## Adaptive Currency

Adaptive Currency ग्राहकों को अपनी पसंदीदा स्थानीय currency में भुगतान करने की सुविधा देता है, जिससे trust और conversion rates बेहतर होते हैं।

### यह कैसे काम करता है

1. **सक्षम करें**: **Settings → Business** से Adaptive Currency सक्षम करें
2. **चुनें**: ग्राहक checkout पर सीधे currencies बदल सकते हैं
3. **PPP लागू करें**: यदि product पर [Purchasing Power Parity](/features/purchasing-power-parity) सक्षम है, तो country percentage base price को कम करता है
4. **Convert करें**: price (या PPP-adjusted price) live FX rates पर customer की currency में convert होती है
5. **Round करें**: यदि [Charm Pricing](/features/charm-pricing) सक्षम है, तो converted amount को 49.99 जैसे साफ़ ending पर round किया जाता है
6. **दिखाएँ**: payment से पहले final payable amount पारदर्शी रूप से दिखाया जाता है

## Automatic Tax Calculation

ग्राहक के billing location के आधार पर taxes automatically calculate किए जाते हैं, जिससे manual setup के बिना GST, VAT और sales tax requirements का compliance सुनिश्चित होता है।

### Tax Calculation कैसे काम करता है

<Steps>
<Step title="Location Detection">
  Tax rules ग्राहक के country (और जहाँ लागू हो, region) के आधार पर लागू किए जाते हैं।
</Step>

<Step title="Dynamic Updates">
  Tax amount automatically update होता है जब:
  - Country बदलता है
  - Address update किया जाता है
</Step>

<Step title="Transparent Display">
  payment से पहले अंतिम tax breakdown स्पष्ट रूप से दिखाया जाता है।
</Step>
</Steps>

<Tip>
Tax calculation पूरी तरह automated है। standard digital goods और SaaS products के लिए किसी manual configuration की आवश्यकता नहीं है।
</Tip>

## Discount Codes

ग्राहक dashboard में आपके द्वारा बनाए गए discount या promo codes सीधे checkout page पर apply कर सकते हैं।

### Checkout Experience

1. Customer discount code दर्ज करता है
2. Discount तुरंत validate किया जाता है
3. Updated price और savings स्पष्ट रूप से दिखाई जाती हैं

जब किसी product पर [Purchasing Power Parity](/features/purchasing-power-parity) सक्षम होता है, तो discount base price पर नहीं, बल्कि PPP-adjusted price पर लागू होता है।

<Frame>
  <img src="/images/checkout/c4.png" alt="Checkout पर discount code entry" style={{ maxHeight: '500px', width: '70%' }}/>

### API Integration

एक या अधिक stacked discount codes को पहले से लागू करें या discount input field सक्षम करें:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Shown by default; set to false to hide the field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`discount_codes` अधिकतम 20 codes की array स्वीकार करता है, जो क्रम से stack होते हैं। Singular `discount_code` field deprecated है, लेकिन अभी भी काम करता है — मौजूदा integrations को तुरंत बदलने की आवश्यकता नहीं है। Stacking और अधिक समृद्ध response shape का उपयोग करने के लिए सुविधानुसार `discount_codes` पर migrate करें।
</Info>

## Smart Address Collection

तेज़ completion के लिए checkout flexible address entry का समर्थन करता है।

### उपलब्ध Options

| Option | Description |
|--------|-------------|
| **Google Address Autofill** | Autocomplete के साथ तेज़ selection |
| **Manual Entry** | Complete addresses के लिए पूरा control |
| **Country Selection** | Tax और compliance logic को निर्धारित करता है |
| **Minimal Address** | केवल country (और जहाँ tax के लिए आवश्यक हो वहाँ ZIP) collect करें — [Minimal Address Mode](#minimal-address-mode) देखें |

<Tip>
Compliance सुनिश्चित करते हुए conversion को अधिकतम करने के लिए address collection speed, accuracy और global coverage के बीच संतुलन बनाता है।
</Tip>

### Minimal Address Mode

अधिकतम conversion के लिए checkout friction कम करने हेतु minimal address collection सक्षम करें। जब `minimal_address` को `true` पर set किया जाता है, तो checkout केवल ये collect करता है:

- **Country** — tax determination के लिए हमेशा आवश्यक
- **ZIP/Postal code** — केवल उन regions में जहाँ sales tax, VAT या GST calculation के लिए यह आवश्यक है

अन्य सभी address fields (street, city, state) छोड़ दिए जाते हैं, जिससे checkout completion काफ़ी तेज़ हो जाता है।

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="Checkout पर केवल country और ZIP/postal code fields दिखाने वाला minimal address mode" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Full address collection default बनी रहती है। Digital products और SaaS flows के लिए `minimal_address` सक्षम करें, जहाँ complete billing details आवश्यक नहीं हैं।
</Info>

## Phone Number Collection

Checkout पर phone number field दिखे या नहीं — और वह required हो या नहीं — इसे checkout session feature flags से नियंत्रित करें।

| Flag | Default | Behavior |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | Checkout form पर phone number field दिखाता है |
| `require_phone_number` | `false` | Phone number field को required बनाता है (form validation non-empty value लागू करती है) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`require_phone_number: true` के लिए `allow_phone_number_collection: true` आवश्यक है। जब phone collection disabled हो और phone number required हो, तो API sessions को reject करता है।
</Warning>

<Tip>
B2B SaaS, regulated industries या ऐसे किसी flow के लिए `require_phone_number` का उपयोग करें जहाँ support, fraud review या compliance के लिए verified contact channel आवश्यक हो।
</Tip>

## Custom Fields

Custom form fields define करके checkout के दौरान customers से अतिरिक्त information collect करें। यह company name, team size, referral source या business-specific अन्य information जैसे data gather करने के लिए उपयोगी है।

### उपलब्ध Field Types

| Type | Description |
|------|-------------|
| `text` | Single-line text input |
| `number` | Numeric input |
| `email` | Validation के साथ email address |
| `url` | Validation के साथ URL |
| `date` | Date picker |
| `dropdown` | Predefined options में से select करें |
| `boolean` | Yes/No toggle |

### उदाहरण

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Customer responses webhook payloads (`payment.succeeded`, `subscription.active`) में और `custom_field_responses` array के माध्यम से API responses में अपने-आप शामिल हो जाते हैं। आप प्रत्येक checkout session के लिए अधिकतम 5 custom fields define कर सकते हैं।
</Info>

## Collection Checkout

Product Collections एक unified checkout experience प्रदान करते हैं, जिसमें customers एक ही checkout में कई संबंधित products (जैसे Starter, Pro, Enterprise plans) देख और select कर सकते हैं।

### यह कैसे काम करता है

1. **सभी products प्रदर्शित**: Customers collection में प्रत्येक active product देखते हैं
2. **पहला product pre-selected**: Collection का पहला product अपने-आप select हो जाता है
3. **Options की तुलना**: चुनने से पहले customers pricing और features की तुलना कर सकते हैं
4. **Single selection**: Product select करने के बाद checkout standard payment flow के साथ आगे बढ़ता है

### Collection Checkout बनाना

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`product_collection_id` का उपयोग करते समय खाली `product_cart` array पास करें। Session creation के समय discount codes को pre-apply नहीं किया जा सकता।
</Warning>

## Checkout Session Configuration

Checkout Sessions API का उपयोग करके checkout behavior नियंत्रित करें:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
Payment के बाद customers को आपके `return_url` पर redirect किया जाता है और query parameters अपने-आप append हो जाते हैं -- इनमें `payment_id` या `subscription_id`, `status`, `email` और `license_key` (यदि लागू हो) शामिल हैं। पूरी list के लिए [Checkout Sessions guide](/developer-resources/checkout-session#request-body) देखें।
</Info>

### Theme Configuration Options

| Property | Description |
|----------|-------------|

| `pay_button_text` | Pay button के लिए custom text (जैसे "Complete Purchase", "Subscribe Now") |
