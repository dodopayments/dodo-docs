## यह कैसे काम करता है

ग्राहकों को payment methods अपने-आप इन आधारों पर दिखाए जाते हैं:

- **Customer Location** — iDEAL (Netherlands) या UPI (India) जैसे regional methods केवल संबंधित region के ग्राहकों को दिखाई देते हैं
- **Transaction Currency** — Payment methods को supported currencies के आधार पर filter किया जाता है
- **Device Type** — Apple Pay केवल compatible Apple devices और browsers पर दिखाई देता है
- **Transaction Type** — कुछ methods subscriptions का समर्थन नहीं करते या उनकी minimum amounts होती हैं

<Info>
**Automatic Activation:** सभी payment methods पहले से configured हैं और उन्हें Dodo Payments द्वारा manage किया जाता है। किसी अतिरिक्त setup की आवश्यकता नहीं है — आपका account verify होने और live mode enabled होने के बाद वे उपलब्ध हो जाते हैं।
</Info>

## Business-Level Payment Method Disabling

आप अपने dashboard से business level पर specific payment methods disable कर सकते हैं। यह आपके business के सभी checkout sessions पर लागू होता है, इसलिए इसे प्रत्येक product या session के लिए configure करने की आवश्यकता नहीं है।

<Steps>
<Step title="Navigate to Settings">
Dodo Payments dashboard में **Settings > Payment Methods** पर जाएँ।
</Step>

<Step title="Disable Payment Methods">
जिन payment methods को आप ग्राहकों को offer नहीं करना चाहते, उन्हें off करने के लिए toggle करें।
</Step>
</Steps>

<Tip>
इसका उपयोग अपने region में high fraud rates वाले payment methods को disable करने या options को केवल उन methods तक सीमित करने के लिए करें जिन्हें आपका business operationally support करता है।
</Tip>

<Info>
Business-level settings global filter की तरह काम करती हैं। `allowed_payment_method_types` के माध्यम से per-checkout restrictions, business level पर enabled methods में उपलब्ध methods को और सीमित करती हैं।
</Info>

## Per-Checkout Payment Method Configuration

Business-level settings के अतिरिक्त, आप `allowed_payment_method_types` का उपयोग करके individual checkout sessions के लिए दिखाए जाने वाले methods को restrict कर सकते हैं:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Best Practices

<AccordionGroup>
<Accordion title="Match methods to your market">
अपने target markets के लिए regional payment methods शामिल करें। Netherlands में iDEAL लगभग 60% online payments प्राप्त करता है; India में UPI का प्रभुत्व है। इन methods को छोड़ने से conversion को काफी नुकसान पहुँचता है।
</Accordion>

<Accordion title="Always provide card fallbacks">
Specific methods को target करते समय भी `credit` और `debit` को fallbacks के रूप में शामिल करें। सभी customers को हर payment method तक access नहीं होता।
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL methods में प्रत्येक provider की minimums होती हैं: Klarna और Afterpay के लिए $50.01 आवश्यक है। इन ranges से बाहर के products के लिए इन्हें शामिल न करें — वे simply दिखाई नहीं देंगे, जो ठीक है।
</Accordion>

<Accordion title="Test across regions and devices">
Live होने से पहले अलग-अलग customer locations, currencies और device types के लिए payment method availability verify करने हेतु test mode का उपयोग करें।
</Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
<Accordion title="Payment method not appearing">
**इन factors की जाँच करें:**
1. क्या method `allowed_payment_method_types` में शामिल है?
2. क्या customer location method के supported region से match करती है?
3. क्या transaction currency method द्वारा supported है?
    4. क्या transaction amount method की supported range में है (जैसे, Klarna/Afterpay min $50.01)?
5. Subscriptions के लिए: क्या method recurring payments को support करता है?

**Solution:** सभी eligible methods देखने के लिए `allowed_payment_method_types` को अस्थायी रूप से remove करें, फिर issue को narrow down करें।
</Accordion>

<Accordion title="Unexpected methods appearing">
**संभावित कारण:**
- `allowed_payment_method_types` सही तरीके से pass नहीं किया जा रहा
- Parameter गलत format में है (यह strings का array होना चाहिए)

**Solution:** अपने API request payload को log करें और parameter structure verify करें।
</Accordion>

<Accordion title="Regional method not available">
**जाँच करें:**
- Customer billing address method के region से match करता है
- Currency सही तरीके से set है (जैसे, iDEAL के लिए EUR)
- यदि customer international है, तो Adaptive Currency enabled है

**Solution:** अपने API request में billing address country code और currency verify करें।
</Accordion>

<Accordion title="Indian payment method issues">
UPI और Rupay subscriptions की unique requirements हैं, जिनमें 48-hour processing delays और RBI mandate limits शामिल हैं।

**See:** पूरी guidance के लिए <a href="/features/payment-methods/india">India Payment Methods</a> देखें।
</Accordion>
</AccordionGroup>
