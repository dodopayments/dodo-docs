<Info>
Credit-Based Billing आपको ग्राहकों को credits का balance देने की सुविधा देता है—जैसे API calls, tokens, compute units या कोई भी custom metric—और आपकी service का उपयोग करने पर उस balance से credits घटाता है। Credits सभी product types के साथ काम करते हैं: subscriptions, one-time purchases और usage-based billing।
</Info>

## Credit-Based Billing क्या है?

Credit-Based Billing आपको अपने products के हिस्से के रूप में ग्राहकों को credit entitlements जारी करने की flexible system देता है। प्रति उपयोग charge करने या feature flags के माध्यम से access सीमित करने के बजाय, आप credits का एक pool allocate करते हैं, जिसका उपयोग ग्राहक आपकी service इस्तेमाल करते समय करते हैं।

Credits इनके लिए आदर्श हैं:

- **AI और LLM platforms**: प्रत्येक plan tier के लिए tokens या generation credits दें
- **API services**: overage pricing के साथ API call credits allocate करें
- **Infrastructure platforms**: compute hours या storage credits जारी करें
- **Communication services**: प्रत्येक subscription के लिए message या minute credits दें
- **Consumption tiers वाले SaaS**: शामिल usage को credit pools में bundle करें

## मुख्य अवधारणाएँ

### Credit Types

Credit बनाते समय, आप दो types में से एक चुनते हैं:

<Tabs>
<Tab title="Custom Unit">
अपनी उत्पाद के लिए सार्थक किसी भी इकाई में क्रेडिट परिभाषित करें - टोकन, API calls, compute hours, या कोई अन्य मेट्रिक। Custom Unit में आपके द्वारा निर्धारित precision (0 से 10 decimal places) का उपयोग होता है।

**इनके लिए सर्वोत्तम**: API calls, AI tokens, compute hours, storage units, messages
</Tab>

<Tab title="Fiat Credits">
Credits वास्तविक currency value (जैसे USD, EUR) दर्शाते हैं। ग्राहकों को monetary credit balance मिलता है, जो आपकी निर्धारित pricing के अनुसार service का उपयोग करने पर कम होता जाता है।

**इनके लिए सर्वोत्तम**: Prepaid balances, promotional credits, service compensation
</Tab>
</Tabs>

### Credit Lifecycle

Credits जारी होने से लेकर उपयोग होने तक एक स्पष्ट lifecycle का पालन करते हैं:

<Steps>
<Step title="Credits Issued">
Credits तब दिए जाते हैं जब कोई ग्राहक attached credit entitlements वाले product (subscription या one-time) को खरीदता है। Subscriptions के लिए credits प्रत्येक billing cycle में फिर से जारी किए जाते हैं।
</Step>

<Step title="Credits Consumed">
ग्राहक आपकी service का उपयोग करने पर credits खर्च करते हैं। Usage-based products के लिए meters real-time events के आधार पर credits अपने-आप घटाते हैं। आप dashboard या API के माध्यम से credits manually भी घटा सकते हैं।
</Step>

<Step title="Credits Expire or Roll Over">
Billing cycle के अंत में (या configured expiry period के बाद), unused credits आपकी settings के आधार पर expire हो जाते हैं या अगले period में rollover हो जाते हैं।
</Step>

<Step title="Overage Handling">
यदि credits cycle के बीच में समाप्त हो जाते हैं, तो आप overage की अनुमति दे सकते हैं (balance से अधिक continued usage) और चुन सकते हैं कि overage को कैसे संभालना है—माफ़ करना, bill करना या deficit को आगे ले जाना।
</Step>
</Steps>

### Grant Sources

Credits कई sources से दिए जा सकते हैं:

| स्रोत | विवरण |
|--------|-------------|
| **Subscription** | Subscription खरीदने पर जारी किए गए Credits, प्रत्येक billing cycle में फिर से जारी किए जाते हैं |
| **One-Time** | One-time payment product के साथ जारी किए गए Credits |
| **Add-on** | Subscription से जुड़े add-on के साथ जारी किए गए Credits |
| **API** | API या dashboard के माध्यम से मैन्युअल रूप से दिए गए Credits |
| **Rollover** | पिछले billing cycle से आगे ले जाए गए Credits |

## Credits बनाना

अपने dashboard के **Products → Credits** section में credit entitlements बनाएं। प्रत्येक credit में unit, precision, expiry rules और lifecycle behavior define होता है।

<Frame caption="The Credits tab under Products shows all your credit entitlements.">
<img src="/images/CBB/Desktop - Entitlements  - Credits.jpg" alt="Credits listing page showing created credit entitlements" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Steps>
<Step title="Navigate to Credits">
अपने dashboard में **Products** पर जाएं और **Credits** tab चुनें। शुरू करने के लिए **Create Credit** पर क्लिक करें।
</Step>

<Step title="Configure Basic Information">
**Credit Name** दर्ज करें—यह credit के लिए आपका internal identifier है।

<Frame caption="The credit creation form with all configuration sections.">
<img src="/images/CBB/Desktop - Create Credit.jpg" alt="Credit creation form showing basic info, general settings, and subscription settings" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Set General Settings">
Credit type और display properties configure करें:

<ParamField path="Credit Type" type="string" required>
**Custom Unit** या **Fiat Credits** चुनें।

- **Custom Unit** - अपना metric (tokens, API calls, compute hours) define करें। इसके लिए **Unit Name** (जैसे "Platform tokens") और **Precision** setting आवश्यक है।
- **Fiat Credits** - Credits वास्तविक currency value दर्शाते हैं। इसके लिए **Unit Currency** selection (USD, EUR, GBP, INR आदि) आवश्यक है।
</ParamField>

<ParamField path="Unit Name" type="string">
केवल Custom Unit credits के लिए। ग्राहक इस credit के लिए जो label देखते हैं (जैसे "AI Tokens", "API Calls")। यह checkout और customer portal में दिखाई देता है।
</ParamField>

<ParamField path="Precision" type="number">
केवल Custom Unit credits के लिए। अनुमत decimal places की संख्या, `0` से `10` तक:

- `0` - पूर्ण संख्याएँ (API calls जैसी गिनी जा सकने वाली वस्तुओं के लिए सर्वोत्तम)
- `1` - एक decimal (0.0)
- `2` - दो decimals (0.00) - **डिफ़ॉल्ट**
- `3` - तीन decimals (0.000)
- अधिकतम `10` तक - उच्च-precision वाली इकाइयों के लिए (जैसे fractional tokens या micro-usage)

<Warning>
Credit बनने के बाद precision बदली नहीं जा सकती।
</Warning>
</ParamField>

<ParamField path="Credit Expiry" type="string">
जारी होने के बाद credits कितने समय तक valid रहते हैं:

- **7 days**, **30 days** (default), **60 days**, **90 days**, **Custom**, या **Never**

Custom दिनों की संख्या (न्यूनतम 1) निर्दिष्ट करने के लिए **Custom** चुनें।
</ParamField>
</Step>

<Step title="Configure Subscription Settings (Optional)">
ये settings recurring subscriptions के भीतर credit behavior नियंत्रित करती हैं:

<ParamField path="Rollover" type="boolean">
Unused credits को अगले billing cycle में carry forward करने की अनुमति दें। सक्षम होने पर configure करें:

- **Max Rollover Percentage** (0–100%) - Carry over होने वाली मात्रा सीमित करें
- **Rollover Timeframe** - Rolled-over credits कितने समय तक valid रहें (जैसे, 1 Month)
- **Max Rollover Count** - Credits forfeited होने से पहले अधिकतम लगातार rollovers
</ParamField>

**जब Credits समाप्त हो जाएं या Subscription expire हो जाए:**

<ParamField path="Allow Overage" type="boolean">
Customers को credit balance शून्य होने के बाद भी आपकी service का उपयोग जारी रखने दें। सक्षम होने पर configure करें:

- **Overage Limit** - Customers अपने balance से अधिकतम कितने credits consume कर सकते हैं
- **Price Per Unit** - Overage enabled होने पर प्रत्येक अतिरिक्त credit की cost (currency selector के साथ)
</ParamField>

<ParamField path="Overage Behavior" type="string" required>
Billing cycle के अंत में overage को कैसे संभालना है, यह नियंत्रित करता है:

- **Forgive overage at reset** (default) - Credit limit से अधिक usage track किया जाता है, लेकिन bill नहीं किया जाता। प्रत्येक cycle में balance reset होता है।
- **Bill overage at billing** - Credit limit से अधिक usage अगले invoice में charge किया जाता है, फिर balance reset होता है।
- **Carry over deficit** - Credit limit से अधिक usage अगले cycle में negative balance के रूप में carry forward होता है।
- **Carry over deficit (auto-repay)** - Deficit carry forward होता है और अगले cycle में नए credits से automatically repay किया जाता है।
</ParamField>
</Step>

<Step title="Create Credit">
Save करने के लिए **Create Credit** पर क्लिक करें। अब यह credit किसी भी product से attach करने के लिए उपलब्ध है।

<Check>
आपका credit entitlement तैयार है। Customers को credits जारी करना शुरू करने के लिए इसे products से attach करें।
</Check>
</Step>
</Steps>

<Tip>
सरल settings से शुरू करें—न rollover, न overage—और customers के credits उपयोग करने के तरीके को समझने के साथ complexity बढ़ाएं। अधिकांश settings को existing grants को प्रभावित किए बिना किसी भी समय update किया जा सकता है। ध्यान दें कि credit बनने के बाद **precision बदली नहीं जा सकती**।
</Tip>

## Products से Credits Attach करना

Product creation या editing flow में credits को **entitlements** के रूप में products से attach किया जाता है। आप प्रत्येक product में अधिकतम **5 credits** attach कर सकते हैं। Credits सभी तीन pricing types के साथ काम करते हैं।

### Subscription Products

Subscriptions के लिए credits **प्रत्येक billing cycle** में जारी किए जाते हैं और proration, trial credits तथा cycle-specific settings के साथ configure किए जा सकते हैं।

<Steps>
<Step title="Create or Edit a Subscription Product">
**Products → Create Product** पर जाएं या किसी existing product को edit करें। Pricing type के रूप में **Subscription** चुनें और अपनी recurring price configure करें।
</Step>

<Step title="Open Entitlements Section">
**Entitlements** section को expand करें और **Credits** के पास मौजूद **Attach** button पर क्लिक करें।

<Frame caption="The Entitlements section in the product form with Credits, License Key, and Digital Product Delivery options.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription.jpg" alt="Product entitlements section showing Credits attach button" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Select Credits to Attach">
एक **Add Credits** panel खुलता है। आप dropdown से existing credit चुन सकते हैं या वहीं नया credit define करने के लिए **Create new credit** पर क्लिक कर सकते हैं।

<Frame caption="The Add Credits panel lets you select existing credits or create new ones.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription-2.jpg" alt="Add Credits panel with credit selection dropdown" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Info>
आप प्रत्येक product में अधिकतम 5 credits attach कर सकते हैं। प्रत्येक credit का अपना configuration हो सकता है।
</Info>
</Step>

<Step title="Configure Credit Settings">
प्रत्येक attached credit के लिए configure करें:

<ParamField path="Credits issued per billing cycle" type="number" required>
प्रत्येक billing period में customer को दिए जाने वाले credits की संख्या।
</ParamField>

<ParamField path="Low Balance Threshold" type="number">
जब credits इस amount से कम हो जाएं तो notify करें। Customers के credits समाप्त होने से पहले alert करने के लिए उपयोगी।
</ParamField>

<ParamField path="Credits During Free Trial" type="number">
Trial periods के लिए अलग credit amount सेट करें। Trial के paid subscription में convert होने पर unused trial credits revoke करने के लिए **Expire trial credits after trial ends** सक्षम करें।
</ParamField>

<ParamField path="Allow Proration" type="boolean">
Customer द्वारा subscription plan upgrade या downgrade करने पर remaining credits को prorate करें।
</ParamField>

<ParamField path="Import Default Credit Settings" type="boolean">
Credit entitlement की default rollover, overage और expiry settings का उपयोग करें। इसे बंद करके विशेष रूप से इस product के लिए settings customize करें।
</ParamField>

<img src="/images/CBB/Desktop - Attach Credit - Subscription-4.jpg" alt="Credit configuration form with billing cycle, trial, and proration settings" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Review and Add">
Attached credit का name, amount और expiration review करें। पुष्टि करने के लिए **Add to Subscription** पर क्लिक करें।

<Frame caption="Review attached credits before adding them to the subscription.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription-5.jpg" alt="Add Credits panel showing selected credit with details" style={{ maxHeight: '500px', width: 'auto' }} />

</Step>
</Steps>

</Info>

## Credit Settings

### Rollover

Rollover unused credits को expire होने के बजाय अगले billing cycle में carry forward करता है।

| Setting | Description |
|---------|-------------|
| **Rollover Enabled** | Unused credits को carry forward करने की अनुमति देने के लिए toggle करें |
| **Max Rollover Percentage** | Carry over होने वाली मात्रा सीमित करें (0–100%)। 50% पर unused credits का केवल आधा rollover होता है |
| **Rollover Timeframe** | Rolled-over credits कितने समय तक valid रहें (day, week, month, year) |
| **Max Rollover Count** | Credits को लगातार rollover किए जाने की अधिकतम संख्या। इस सीमा के बाद remaining credits forfeited हो जाते हैं |

**उदाहरण**: Cycle के अंत में customer के पास 200 unused credits हैं। 75% rollover के साथ 150 credits आगे carry होते हैं और 50 forfeited हो जाते हैं।

### Overage

Overage नियंत्रित करता है कि cycle के बीच में customer का credit balance शून्य होने पर क्या होता है।

| Setting | Description |
|---------|-------------|
| **Allow Overage** | Customers को अपने credit balance से अधिक service का उपयोग जारी रखने देने के लिए toggle करें |
| **Overage Limit** | Customers अपने balance से अधिकतम कितने credits consume कर सकते हैं |
| **Price Per Unit** | Overage के रूप में consume किए गए प्रत्येक अतिरिक्त credit की cost (currency के साथ) |
| **Overage Behavior** | Billing cycle के अंत में overage के साथ क्या होगा, इसे नियंत्रित करता है (नीचे देखें) |

**Overage Behavior options:**

| Behavior | Description |
|----------|-------------|
| **Forgive overage at reset** | Credit limit से अधिक usage track किया जाता है, लेकिन bill नहीं किया जाता। प्रत्येक cycle में balance reset होता है |
| **Bill overage at billing** | Credit limit से अधिक usage अगले invoice में charge किया जाता है, फिर balance reset होता है |
| **Carry over deficit** | Overage अगले cycle में negative balance के रूप में carry forward होता है |
| **Carry over deficit (auto-repay)** | Deficit carry forward होता है और अगले cycle में नए credits से automatically repay किया जाता है |
<Info>
जब overage disabled होता है, तो credit balance शून्य होने के बाद customers service का उपयोग नहीं कर सकते। अपने billing model के अनुरूप overage behavior चुनें—**Forgive at reset** default और सबसे सरल option है।
</Info>

### Expiration

| Setting | Description |
|---------|-------------|
| **Credit Expiry** | Credits expire होने से पहले issuance के बाद की अवधि (7, 30, 60, 90, custom days या never) |
| **Trial Credits Expire After Trial** | Trial period समाप्त होने पर trial-specific credits expire होंगे या नहीं |

<Info>
Expired credits एक `CreditExpired` ledger entry बनाते हैं। यदि rollover enabled है, तो expiration से पहले rollover percentage लागू किया जाता है और केवल शेष amount expire होता है।
</Info>

## Credits के साथ Usage Billing

जब credits usage meters से linked होते हैं, तो system एक powerful consumption-based billing model बनाता है। Customers को credit allocation मिलता है और usage events उनके balance से credits automatically deduct करते हैं।

<Frame caption="The Usage Billing dashboard shows meter events with units consumed, credits consumed, and customer details.">
<img src="/images/CBB/Desktop - Usage Billing.jpg" alt="Usage Billing dashboard showing events table with credits consumed" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### Meter-Based Credit Deduction कैसे काम करता है

1. **आपका application usage events भेजता है** - प्रत्येक event में customer ID, event name और metadata शामिल होते हैं
2. **Meters events aggregate करते हैं** - Count, Sum, Max या Last aggregation का उपयोग करके
3. **Credits automatically deduct होते हैं** - Background worker हर मिनट events process करता है, configured rate से meter units को credits में convert करता है और FIFO ordering (सबसे पुराने grants पहले) का उपयोग करके customer के balance से deduct करता है
4. **Overage track किया जाता है** - यदि credit balance शून्य हो जाता है और overage enabled है, तो system cycle के अंत में billing के लिए overage usage track करता है

### Meters Panel

Usage Billing dashboard में एक **Meters** panel है, जिसमें सभी defined meters और उनके aggregation types सूचीबद्ध हैं:

| Aggregation | Description | Example |
|-------------|-------------|---------|
| **Count** | Events की कुल संख्या | API calls |
| **Sum** | किसी value field का sum | Total bytes transferred |
| **Max** | Record की गई highest value | Peak concurrent users |
| **Last** | सबसे recent value | Current storage used |

### Credit Ledger

प्रत्येक credit operation credit ledger में record होता है, जिससे complete audit trail मिलता है:

| Transaction Type | विवरण |
|-----------------|-------------|
| **Credit Added** | दिए गए Credits (subscription, one-time या API) |
| **Credit Deducted** | usage या manual debit के माध्यम से उपयोग किए गए Credits |
| **Credit Expired** | rollover के बिना समाप्त हुए Credits |
| **Credit Rolled Over** | अगली अवधि में आगे ले जाए गए Credits |
| **Rollover Forfeited** | अधिकतम rollover count पूरा होने के बाद forfeited किए गए rollover Credits |
| **Overage Charged** | overage enabled होने पर credit balance से अधिक usage |
| **Overage Reset** | billing-cycle reset पर tracked overage हटाया गया |
| **Auto Top-Up** | कम balance होने पर Credits की स्वचालित पुनःपूर्ति |
| **Manual Adjustment** | merchant द्वारा मैन्युअल रूप से लागू किया गया credit या debit |
| **Refund** | वापस किए गए Credits |

प्रत्येक ledger entry में transaction से पहले और बाद का balance, पहले और बाद का overage, description और source का reference (payment, subscription आदि) record होता है।

## Webhooks

Credit-Based Billing प्रत्येक credit lifecycle change के लिए webhook events fire करता है। इनका उपयोग अपने application को credit balances के साथ sync रखने, notifications trigger करने या custom billing workflows बनाने के लिए करें।

| Event | विवरण |
|-------|-------------|
| `credit.added` | customer को दिए गए Credits |
| `credit.deducted` | usage या manual debit के माध्यम से उपयोग किए गए Credits |
| `credit.expired` | अप्रयुक्त Credits समाप्त हो गए |
| `credit.rolled_over` | नए grant में आगे ले जाए गए Credits |
| `credit.rollover_forfeited` | अधिकतम rollover count पर Credits forfeited किए गए |
| `credit.overage_charged` | overage charges लागू किए गए |
| `credit.overage_reset` | billing cycle के अंत में tracked overage reset किया गया |
| `credit.manual_adjustment` | मैन्युअल credit/debit adjustment किया गया |
| `credit.balance_low` | balance configured threshold से नीचे चला गया |

सभी ledger events (हर `credit.*` event, सिवाय `credit.balance_low` के) में पूरा `CreditLedgerEntry` payload शामिल होता है, जिसमें balance before/after, overage before/after, source reference और grant के source subscription या payment का `metadata` शामिल होता है (API के माध्यम से सीधे बनाए गए grants के लिए यह खाली होता है)। `credit.balance_low` event में threshold configuration और current balance शामिल होते हैं।

## Best Practices

- **सरल शुरुआत करें**: एक ही credit type और बिना rollover के शुरू करें। Customer feedback और usage patterns के आधार पर complexity बढ़ाएं।
- **स्पष्ट expectations सेट करें**: अपने product pages और customer portal में credit allocations, remaining balances और overage pricing प्रमुखता से दिखाएं।
- **Meaningful units का उपयोग करें**: Generic terms के बजाय credits का नाम उस चीज़ के आधार पर रखें जिसे वे दर्शाते हैं (जैसे, "API Calls", "AI Tokens")। इससे customers को value समझने में मदद मिलती है।
- **Expiry सोच-समझकर configure करें**: छोटी expiry windows (7 days) urgency बढ़ाती हैं, लेकिन customers को निराश कर सकती हैं। अधिकांश SaaS products के लिए लंबी windows (30–90 days) customer-friendly होती हैं।
- **Low balances monitor करें**: Customers के credits समाप्त होने से पहले alert करने के लिए low balance thresholds सेट करें, जिससे unexpected overage charges कम हों।
- **Test mode में test करें**: Live होने से पहले credits बनाएं, उन्हें test products से attach करें और पूरे purchase → usage → deduction → expiration cycle को simulate करें।

Credit-Based Billing अन्य सभी Dodo Payments features के साथ seamlessly काम करता है—trials वाले subscriptions, proration के साथ plan changes और customer portal। Basic setup से शुरू करें और अपने pricing model के विकसित होने के साथ इसे expand करें।
</Info>
