कार्ड भुगतान ऑनलाइन भुगतानों का आधार हैं, जिन्हें दुनिया भर में स्वीकार किया जाता है और ग्राहक इन पर भरोसा करते हैं। Dodo Payments सभी प्रमुख कार्ड नेटवर्क के साथ अंतर्निहित fraud protection और PCI compliance का समर्थन करता है।

## Configuration

इन मानों का उपयोग `allowed_payment_method_types` में करें:

| प्रकार | विवरण |
| :--- | :---------- |
| `credit` | सभी क्रेडिट कार्ड |
| `debit` | सभी डेबिट कार्ड |

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Tip>
`credit` और `debit` दोनों शामिल करें, जब तक कि किसी एक को बाहर रखने का कोई विशेष कारण न हो। कई ग्राहक डेबिट कार्ड पसंद करते हैं और इनकी fees अक्सर कम होती हैं।
</Tip>

## 3D Secure Authentication

3D Secure (3DS) cardholder की पहचान सत्यापित करके एक authentication layer जोड़ता है, जो fraud और chargebacks को कम करती है।

### 3DS कब Trigger होता है

3DS अपने आप trigger होता है जब:
- कार्ड नेटवर्क द्वारा आवश्यक हो
- क्षेत्रीय regulations द्वारा आवश्यक हो (जैसे, यूरोप में PSD2)
- transaction को high-risk के रूप में flag किया गया हो

### 3DS को Force करना

आप सभी transactions पर 3DS आवश्यक कर सकते हैं:

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  force_3ds: true,
  return_url: 'https://example.com/success'
});
```

<Note>
सभी transactions के लिए 3DS सक्षम करने से fraud कम होता है, लेकिन conversion थोड़ी घट सकती है क्योंकि कुछ ग्राहक authentication के दौरान प्रक्रिया छोड़ देते हैं।
</Note>

### Authentication Failures को संभालना

जब किसी payment को 3DS authentication की आवश्यकता होती है, तो उसके सफल या विफल होने से पहले payment intermediate states से गुजरता है:

| Status | अर्थ | क्या करें |
|--------|---------|------------|
| `requires_customer_action` | ग्राहक को 3DS challenge पूरा करना होगा | checkout के दौरान ग्राहक से authentication पूरा करवाएँ |
| `requires_payment_method` | ग्राहक ने कभी payment method प्रदान नहीं किया (विवरण दर्ज नहीं किए या prompt छोड़ दिया) — आमतौर पर यह drop-off है, decline नहीं | checkout पूरा करने के लिए ग्राहक से फिर संपर्क करें; [Abandoned Cart Recovery](/features/recovery/abandoned-cart-recovery) देखें |

यदि authentication पूरा नहीं होता है, तो payment इनमें से किसी एक decline code के साथ विफल हो जाता है:

- `AUTHENTICATION_FAILURE` — ग्राहक authenticate नहीं हो सका।
- `AUTHENTICATION_REQUIRED` — authentication आवश्यक था, लेकिन पूरा नहीं किया गया।
- `AUTHENTICATION_TIMEOUT` — ग्राहक ने समय पर response नहीं दिया।

प्रत्येक के लिए recommended action हेतु [Transaction Failures](/api-reference/transaction-failures) reference देखें।

#### Checkout के समय बनाम Renewal पर

- **Checkout के समय (ग्राहक उपस्थित):** ग्राहक उपस्थित होता है, इसलिए 3DS challenge checkout के दौरान दिखाया जाता है। यदि यह विफल हो, तो उनसे दोबारा प्रयास करने या दूसरा कार्ड इस्तेमाल करने को कहें।
- **Subscription renewal पर (ग्राहक उपस्थित नहीं):** ग्राहक उपस्थित नहीं होता, इसलिए 3DS challenge real time में प्रदर्शित नहीं किया जा सकता। यदि renewal के लिए authentication आवश्यक हो, तो subscription `on_hold` पर चली जाती है। ग्राहक को वापस आने और अपना payment method update करने के लिए prompt करके इसे recover करें — [Handle Payment Failures](/developer-resources/handle-payment-failures) और [Subscription Dunning](/features/recovery/subscription-dunning) देखें।

### Saved Cards सक्षम करें

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  show_saved_payment_methods: true,
  customer: { customer_id: 'cus_existing_123' },
  return_url: 'https://example.com/success'
});
```

### One-Click Purchases

```javascript
// Get customer's saved payment methods
const methods = await client.customers.retrievePaymentMethods('cus_123');

// Use saved card for instant checkout
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  payment_method_id: methods.items[0].payment_method_id,
  confirm: true,
  return_url: 'https://example.com/success'
});
```

## Best Practices

<AccordionGroup>
<Accordion title="Accept all major networks">
जब तक आवश्यक न हो, card types को restrict न करें। ग्राहक अपेक्षा करते हैं कि उनका पसंदीदा कार्ड काम करेगा।
</Accordion>

<Accordion title="Display card logos">
भरोसा बढ़ाने के लिए अपने checkout पर Visa, Mastercard और Amex logos दिखाएँ।
</Accordion>

<Accordion title="Handle declines gracefully">
स्पष्ट error messages दिखाएँ। ग्राहकों को raw error codes न दिखाएँ।
</Accordion>

<Accordion title="Enable saved cards for returning customers">
Saved payment methods repeat purchases के लिए conversion को काफी बढ़ाते हैं।
</Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
<Accordion title="Card declined">
**कारण:** अपर्याप्त funds, कार्ड expired, गलत CVV, bank fraud protection।

**समाधान:** ग्राहक से विवरण verify करने या कोई दूसरा कार्ड आज़माने को कहें। विशिष्ट decline `Error Code` और उसके recommended action को [Transaction Failures](/api-reference/transaction-failures) reference में देखें। Programmatic handling के लिए [Handle Payment Failures](/developer-resources/handle-payment-failures) भी देखें।
</Accordion>

<Accordion title="3DS authentication failed">
**कारण:** ग्राहक ने प्रक्रिया छोड़ दी, bank system unavailable, timeout।

**समाधान:** दोबारा प्रयास करें या ग्राहक से अपने bank से संपर्क करने को कहें। संबंधित payment states और decline codes के लिए [Handling Authentication Failures](#handling-authentication-failures) देखें।
</Accordion>

<Accordion title="Card not supported">
**कारण:** क्षेत्रीय कार्ड supported नहीं है, prepaid restrictions।

**समाधान:** ग्राहक को किसी प्रमुख network का दूसरा कार्ड आज़माना चाहिए।
</Accordion>
</AccordionGroup>
