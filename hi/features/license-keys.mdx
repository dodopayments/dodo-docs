</Info>

## लाइसेंस कुंजियाँ क्या हैं?

लाइसेंस कुंजी अद्वितीय टोकन होते हैं जो आपके उत्पाद तक पहुंच को अधिकृत करते हैं। ये निम्नलिखित के लिए आदर्श हैं:

- **सॉफ़्टवेयर लाइसेंसिंग**: डेस्कटॉप ऐप, प्लगइन्स, और CLI
- **प्रति-सीट नियंत्रण**: प्रति उपयोगकर्ता या डिवाइस सक्रियणों को सीमित करें
- **डिजिटल सामान**: डाउनलोड, अपडेट, या प्रीमियम सुविधाओं को गेट करें

डोडो पेमेंट्स के अंदर, लाइसेंस कुंजियाँ [अधिकार](/features/entitlements/introduction) प्रणाली के माध्यम से प्रबंधित की जाती हैं, जिसका मतलब है कि प्रत्येक कुंजी का जीवन चक्र (निर्माण, समाप्ति, रद्दीकरण, पुनःअनुदान) आपके अन्य वितरणों के समान भुगतान और सदस्यता घटनाओं द्वारा संचालित होता है।

**लाइसेंस कुंजी** को एकीकरण के रूप में चुनें। यह कॉन्फ़िगर करें कि प्रत्येक जारी कुंजी कैसे व्यवहार करती है:
- **सक्रियण सीमा**: प्रति कुंजी अधिकतम वर्तमान सक्रियण (उदाहरण के लिए, एकल-उपयोगकर्ता के लिए `1`, टीम लाइसेंस के लिए `5`, अनलिमिटेड के लिए खाली छोड़ें)।
- **अवधि**: जारी होने के बाद कुंजी कितने समय तक वैध रहती है (उदाहरण के लिए, 30 दिन, 1 वर्ष)। सदस्यता-प्रदत्त कुंजियों के लिए, खाली छोड़ दें; कुंजियाँ तब तक वैध रहती हैं जब तक सदस्यता सक्रिय है।
- **सक्रियण निर्देश**: कुंजी के साथ ईमेल किए गए ग्राहक के सामने के निर्देश। उदाहरण: `Paste the key in Settings → License` या `Run: mycli activate <key>`।

## कुंजियाँ कैसे जारी की जाती हैं

कुंजी का जारी होनासामान्य [अनुदान जीवन चक्र](/features/entitlements/introduction#how-grants-work) का पालन करता है:

| इवेंट | व्यवहार |
|---|---|
| `payment.succeeded` (एक बार) | खरीदे गए `quantity` के लिए एक कुंजी जनरेट करें। कुंजी की समाप्ति अधिकार की अवधि का सम्मान करती है। |
| `subscription.active` | प्रति सदस्यता `quantity` (सीट) के लिए एक कुंजी जनरेट करें। कुंजी की कोई समाप्ति नहीं होती है; वैधता सदस्यता की स्थिति के साथ जुड़ी होती है। |
| `subscription.renewed` | नो-ऑप। मौजूदा कुंजियाँ बनी रहती हैं। |
| `subscription.on_hold` | कुंजियों को निष्क्रिय करें। जब सदस्यता होल्ड से हटती है तो वे पुनः सक्रिय हो जाती हैं। |
| `subscription.cancelled` / `expired` | कुंजियों को स्थायी रूप से निष्क्रिय करें। |
| `subscription.plan_changed` | पुरानी कुंजियों को निष्क्रिय करें; नए प्लान के लिए नई कुंजियाँ जारी करें। |
| `refund.succeeded` (एक बार) | कुंजियों को निष्क्रिय करें। |
| मैनुअल रद्दीकरण API/डैशबोर्ड के माध्यम से | कुंजियों को `revocation_reason: manual` के साथ निष्क्रिय करें। ये सदस्यता के नवीकरण पर स्वचालित रूप से पुनः प्रदान नहीं की जाती हैं। |
| सीधे लाइसेंस कुंजी को निष्क्रिय करना | अनुदान को `revocation_reason: license_key_disabled` के साथ रद्द करें। कुंजी को पुनः सक्षम करना अनुदान को स्वचालित रूप से पुनः सक्रिय करता है। |

### मात्रा व्यवहार

- **सदस्यता उत्पाद** प्रति सीट एक कुंजी जारी करते हैं (`subscriptions.quantity`)।
- **एक बार के उत्पाद** प्रति कार्ट लाइन आइटम एक कुंजी जारी करते हैं (`product_cart.quantity`)।
- **मैनुअल API अनुदान** ठीक एक कुंजी जारी करते हैं।

## सक्रियण, सत्यापन, निष्क्रियता

सक्रियण/सत्यापन/निष्क्रियता API एंडपॉइंट **सार्वजनिक** हैं और इसमें कोई API कुंजी की आवश्यकता नहीं है। इनका उपयोग डेस्कटॉप सॉफ़्टवेयर, CLI, या ब्राउज़र-आधारित क्लाइंट से रनटाइम पर कुंजियों को सत्यापित करने के लिए सीधे करें।

 
<Info>
**सार्वजनिक एंडपॉइंट**: सक्रियण, निष्क्रियता, और लाइसेंस सत्यापन एंडपॉइंट सार्वजनिक हैं और API कुंजी की आवश्यकता नहीं होती है। अपने क्लाइंट एप्लिकेशन से सीधे इन्हें कॉल करें बिना अपने API क्रेडेंशियल्स को उजागर किए हुए।
</Info>

## कुंजियाँ प्रबंधित करें

डैशबोर्ड से अपनी लाइसेंस कुंजी अधिकार खोलें ताकि प्रत्येक अनुदान (प्रत्येक ग्राहक कुंजी के लिए एक पंक्ति) डिलीवरी तिथि, सक्रियण गणना, और एक रद्दीकरण क्रिया के साथ देख सकें। प्रत्येक अनुदान विवरण अंतर्निहित लाइसेंस कुंजी, समाप्ति, उपयोग की गई सक्रियण और सक्रियण सीमा को सामने लाता है।

आप प्रोग्रामेटिक रूप से अनुदान भी सूचीबद्ध कर सकते हैं:

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_license_key_id', {
  status: 'delivered',
});

for (const grant of grants.items) {
  console.log(grant.license_key.key, grant.license_key.activations_used);
}
```

## मौजूदा लाइसेंस कुंजियों का API के द्वारा आयात करें

क्या आपके पास किसी अन्य प्रणाली में लाइसेंस कुंजियाँ पहले से हैं? इन्हें Dodo Payments में आयात करने के लिए [लाइसेंस कुंजी बनाएं](/api-reference/licenses/create-license-key) API का उपयोग करें। यह आपको निर्दोष रूप से मौजूदा कुंजियों को माइग्रेट करने की अनुमति देता है — वे बिना पुनः जारी किए वैसे ही कुंजियों के सक्रियण, सत्यापन, और निष्क्रियता को जारी रखते हैं।

 
{/* LOCKED_PATTERN_4907e9f6f7fbd509120d7a87afc829e9 */}
API के माध्यम से बनाई गई या अपडेट की गई लाइसेंस कुंजियाँ ग्राहकों के लिए ईमेल सूचनाएँ नहीं ट्रिगर करती हैं। यदि आपको किसी आयातित कुंजी की सूचना ग्राहकों को देने की आवश्यकता है, तो इसे अपने अनुप्रयोग में अलग से संभालें।
{/* LOCKED_PATTERN_176d815432e7554ac558e8631b2bc397 */}

```typescript theme={null}
const licenseKey = await client.licenseKeys.create({
  customer_id: 'cus_abc123',
  product_id: 'prod_456',
  key: 'YOUR-EXISTING-LICENSE-KEY',
  activations_limit: 5,
  expires_at: '2026-12-31T23:59:59Z',
});
```

### आयातित कुंजियाँ स्वतः उत्पन्न कुंजियों से कैसे भिन्न होती हैं

| फ़ील्ड | स्वतः उत्पन्न कुंजी | आयातित कुंजी |
|-------|--------------------|--------------|
| `source` | `"auto"` | `"import"` |
| `payment_id` | मूल भुगतान के लिए सेट | `null` (कोई डोडो पेमेंट्स लेनदेन नहीं) |
| `subscription_id` | अगर कुंजी सदस्यता के माध्यम से जारी की गई है तो सेट | `null` जब तक कि विशेष रूप से लिंक न किया गया हो |
| ग्राहक ईमेल अधिसूचना | जारी करने पर भेजा गया | नहीं भेजा गया — अलग से संभालें |

निर्धारित या ऑडिट करते समय आयात की गई इन्वेंट्री को मूल रूप से जारी की गई कुंजियों से भिन्न करने के लिए `source` फ़ील्ड का उपयोग करें।

 
<Tip>
**Polar.sh** या **Lemon Squeezy** से माइग्रेट कर रहे हैं? [`dodo-migrate` CLI](/migrate-to-dodo) उत्पादों, ग्राहकों, छूटों, और लाइसेंस कुंजियों के बड़े पैमाने पर आयात को स्वचालित करता है और बाहरी आईडी को Dodo आईडी से स्वचालित रूप से मैप करता है।
</Tip>

## रिटर्न URL में लाइसेंस कुंजियाँ

जब कोई ग्राहक लाइसेंस कुंजी अधिकार वाले उत्पाद के लिए खरीद पूरी करता है, तो उत्पन्न कुंजी स्वचालित रूप से आपके `return_url` में एक क्वेरी पैरामीटर के रूप में जोड़ दी जाती है। यह आपको अपनी सफलता पृष्ठ पर तुरंत कुंजी प्रदर्शित करने की अनुमति देता है बिना अतिरिक्त API कॉल के।

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com
```

यदि खरीद एकाधिक कुंजियों का उत्पादन करती है (मात्रा > 1), तो वे अल्पविराम से विभाजित होती हैं:

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001,LK-002&email=customer%40example.com
```

सदस्यताओं के लिए, `subscription_id` का उपयोग `payment_id` के बजाय किया जाता है:

```text theme={null}
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001&email=customer%40example.com
```

 
<Tip>
अपने रिटर्न पृष्ठ पर `license_key` पैरामीटर को पार्स करें ताकि कुंजी को तुरंत प्रदर्शित किया जा सके, जिससे बाद-खरीद अनुभव में सुधार होता है।
</Tip>

## वेबहुक

लाइसेंस-कुंजी वितरण और रद्दीकरण चार [`entitlement_grant.*` वेबहुक इवेंट्स](/developer-resources/webhooks/intents/entitlement-grant) को फायर करते हैं। अनुदान पेलोड में एक भरा हुआ `license_key` वस्तु शामिल होती है जिसमें कुंजी, समाप्ति, उपयोग की गई सक्रियण और सीमा होती है।

विरासत `license_key.*` इवेंट्स (`license_key.created`) अंतर्निहित लाइसेंस-कुंजी रिकॉर्ड जीवन चक्र के लिए बार-बार फायर होते हैं; [लाइसेंस कुंजी वेबहुक पेलोड पृष्ठ](/developer-resources/webhooks/intents/license-key) देखें।

 
<Tip>
नई एकीकरणों के लिए, `entitlement_grant.delivered` के बजाय `license_key.created` को सुनें। अधिकार इवेंट आपको सभी एकीकरणों के लिए उत्पाद पर वितरण पूरा होने की जानकारी देता है, न कि केवल लाइसेंस कुंजी।
</Tip>

## पुरानी लाइसेंस कुंजियाँ

 
<Note>
पुराने `license_key_enabled` फ्लैग के साथ बने उत्पादों को **स्वचालित रूप से** लाइसेंस कुंजी अधिकार में माइग्रेट कर दिया गया है। माइग्रेशन पारदर्शी है: मौजूदा ग्राहकों की कुंजियाँ बिना किसी बदलाव के काम करती रहती हैं, सार्वजनिक `/licenses/activate`, `/licenses/validate`, `/licenses/deactivate` एंडपॉइंट सामान्य रूप से काम करते हैं, और `/license_keys/*` API एंडपॉइंट उसी कुंजी स्टोर में पढ़ और लिखते रहते हैं।

स्टैंडअलोन **लाइसेंस कुंजियाँ** डैशबोर्ड खंड जारी की गई प्रत्येक कुंजी की एक सपाट सूची के रूप में उपलब्ध रहता है, जो ऑडिट और खोज के लिए उपयोगी है। नई कॉन्फ़िगरेशन (सक्रियण सीमाएँ, अवधि, या निर्देश बदलना) को **अधिकारों** के अंतर्गत स्थानांतरित लाइसेंस कुंजी अधिकार को संपादित करके किया जाना चाहिए।
</Note>

## सर्वोत्तम प्रथाएँ

- **सक्रियण सीमाओं को स्पष्ट रखें**: उचित डिफॉल्ट्स चुनें (एकल-उपयोगकर्ता एप्लिकेशन के लिए 1, टीम लाइसेंस के लिए 3–5) और उन्हें दस्तावेजित करें।
- **सटीक सक्रियण निर्देश प्रदान करें**: ग्राहक इन्हें अपने ईमेल से पेस्ट करते हैं, इसलिए सटीक पथ और कमांड्स समर्थन टिकट बचाते हैं।
- **सर्वर-साइड कुंजियाँ सत्यापित करें**: नेटवर्क से जुड़े उत्पादों के लिए, स्थानीय रूप से सक्रियण को कैश करने के बजाय `/licenses/validate` के माध्यम से सत्यापित करें।
- **रद्दीकरण के लिए वेबहुक का उपयोग करें**: जब कोई ग्राहक रद्द करता है या रिफंड करता है, तो इन-ऐप फीचर्स को तुरंत निष्क्रिय करने के लिए `entitlement_grant.revoked` को सुनें।
- **सदस्यताओं और एक-बार के साथ परीक्षण करें**: लाइसेंस कुंजी व्यवहार दोनों के बीच सूक्ष्म रूप से भिन्न होता है, इसलिए लाइव होने से पहले दोनों का परीक्षण करें।
