<Tip>

</Tip>

### 2. **Dodo Payments पर Verifi RDR समर्थन**

Dodo Payments अब **विज़ा रैपिड डिस्प्यूट रिज़ॉल्यूशन (RDR)** का समर्थन करता है, जो Verifi द्वारा संचालित है - एक स्वचालित विवाद रोकथाम उपकरण जो योग्य विज़ा विवादों को **औपचारिक चार्जबैक बनने से पहले** हल करता है। जब किसी कार्डधारक एक विवाद शुरू करता है, तो RDR इसे रोकता है और यदि लेन-देन आपकी सेट की गई USD सीमा से कम है तो स्वचालित रूप से धनवापसी करता है।

**यह क्यों महत्वपूर्ण है**

| लाभ | प्रभाव |
|---------|--------|
| **कम विवाद दर** | RDR द्वारा सुलझाए गए विवादों को Visa के 0.9% सीमा में नहीं गिना जाता |
| **कोई विवाद शुल्क नहीं** | प्रति विवाद $15-$25 गैर-निवृत्त शुल्क से बचें |
| **सुनियोजित संचालन वस्त्र** | कोई साक्ष्य इकट्ठा करना या प्रतिक्रिया समय सीमाएँ नहीं |
| **बेहतर ग्राहक अनुभव** | कार्डधारकों को तात्कालिक धनवापसी मिलती है |
| **खाता सुरक्षा** | Visa के विवाद निगरानी कार्यक्रम (VDMP) से बचें |

<Warning>
Visa की 0.9% विवाद दर या 100 विवाद/महीने से अधिक होने पर VDMP सक्रिय होता है, जिसमें $50,000+/महीने के बढ़ते दंड होते हैं। RDR आपको इन सीमाओं से अच्छी तरह नीचे रहने में मदद करता है।
</Warning>

**यह कैसे काम करता है**

1. कार्डधारक अपने बैंक के साथ विवाद शुरू करता है
2. RDR विवाद को औपचारिक चार्जबैक बनने से पहले रोकता है
3. यदि लेन-देन राशि आपकी सीमा के बराबर या उससे कम है, तो धनवापसी स्वचालित रूप से की जाती है
4. विवाद तुरंत हल हो जाता है और **आपकी विवाद दर** के खिलाफ नहीं गिना जाता

<Info>
RDR के माध्यम से स्वचालित रूप से धनवापसी वाली लेन-देन आपके Dodo Payments डैशबोर्ड में **खोया विवाद** के रूप में प्रकट होती हैं। यह अपेक्षित है - धनवापसी औपचारिक चार्जबैक को रोकने के लिए स्वचालित रूप से की गई थी।
</Info>

अपने खाते पर Verifi RDR सक्षम करने के लिए, अपनी सीमा कॉन्फ़िगर करने के लिए **support@dodopayments.com** से संपर्क करें।

और जानें: [विज़ा RDR दस्तावेज़](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

नई **DodoPayments CLI** (`dodopayments-cli`) का परिचय -- अपने पूरे Dodo Payments कार्यप्रवाह को सीधे टर्मिनल से प्रबंधित करें। यह उन डेवलपर्स के लिए बनाई गई है जो कमांड लाइन को प्राथमिकता देते हैं, CLI आपको उत्पादों, भुगतानों, ग्राहकों, छूट, लाइसेंस, एडऑन, धनवापसी प्रबंधित करने और यहां तक कि अपने संपादक को छोड़े बिना चेकआउट सत्र बनाने देता है।

**स्थापना**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**महत्वपूर्ण कमांड**

| आदेश | विवरण |
|---------|-------------|
| `dodo login` | अपने API कुंजी के साथ प्रमाणित करें (ब्राउज़र खोलता है) |
| `dodo products list` | सभी उत्पादों को सूचीबद्ध करें |
| `dodo payments list` | सभी भुगतानों को सूचीबद्ध करें |
| `dodo customers create` | एक नया ग्राहक बनाएँ |
| `dodo checkout new` | एक चेकआउट सत्र बनाएँ और URL प्राप्त करें |
| `dodo wh listen` | अपने स्थानीय सर्वर पर लाइव परीक्षण वेबहुक्स को फॉरवर्ड करें WebSocket के माध्यम से |
| `dodo wh trigger` | किसी भी एंडपॉइंट पर मॉक वेबहुक पेलोड भेजें |

**वेबहुक परीक्षण**

CLI में विकास के लिए दो शक्तिशाली उपकरण शामिल हैं:

- **`dodo wh listen`** -- वास्तविक समय परीक्षण वेबहुक्स को आपके स्थानीय सर्वर पर फॉरवर्ड करने के लिए WebSocket कनेक्शन खोलता है, मूल हेडर को सिग्नेचर सत्यापन परीक्षण के लिए बनाए रखते हुए
- **`dodo wh trigger`** -- इंटरैक्टिव रूप से मॉक वेबहुक पेलोड भेजता है, जो सदस्यताएँ, भुगतान, धनवापसी, विवाद और लाइसेंस के लिए 22 घटना प्रकारों का समर्थन करता है

<Tip>
वेबहुक श्रोता केवल **परीक्षा मोड** API कुंजी के साथ काम करता है। सुनिश्चित करें कि आप `dodo wh listen` का उपयोग करने से पहले परीक्षा मोड कुंजी से लॉग इन हैं।
</Tip>

और जानें: [CLI दस्तावेज़](/developer-resources/sdks/cli)

### 5. **इनलाइन चेकआउट में भुगतान विधि अपडेट करें**

अब [इनलाइन चेकआउट](/developer-resources/inline-checkout) सक्रिय सदस्यताओं के लिए **भुगतान विधि अपडेट** का समर्थन करता है। जब एक ग्राहक को अपनी भुगतान विधि अपडेट करने की आवश्यकता होती है (एक सक्रिय सदस्यता के लिए या एक होल्ड पर रखी गई सदस्यता को फिर से सक्रिय करने के लिए), अपडेट भुगतान विधि प्रवाह अब आपके पृष्ठ लेआउट के भीतर सीधे इनलाइन चेकआउट का उपयोग करके प्रस्तुत किया जा सकता है -- एक निर्बाध, एम्बेडेड अनुभव प्रदान करना।

**यह कैसे काम करता है**

1. अपडेट भुगतान विधि API को कॉल करें ताकि `payment_link` प्राप्त हो:


```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. लौटाई गई `payment_link` का उपयोग करें `checkoutUrl` के रूप में इनलाइन चेकआउट में:


```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

इनलाइन फ़्रेम केवल भुगतान विधि संग्रह फॉर्म को प्रस्तुत करता है, जिससे ग्राहकों को नए कार्ड विवरण दर्ज करने या अपनी पृष्ठ के बिना सहेजी गई भुगतान विधि का चयन करने की अनुमति मिलती है।

<Tip>
होल्ड पर रखने वाली सदस्यताओं के लिए, अपडेट भुगतान विधि प्रवाह बकाया राशि के लिए एक चार्ज स्वचालित रूप से बनाता है। रिएक्टिवेशन की पुष्टि के लिए `payment.succeeded` और `subscription.active` वेबहुक्स की निगरानी करें।
</Tip>

और जानें: [इनलाइन चेकआउट](/developer-resources/inline-checkout) | [सदस्यता भुगतान विधि अपडेट](/features/subscription#update-payment-method-for-active-subscription)

### 6. **चेकआउट सत्रों के लिए टैक्स ID प्रीफिल समर्थन**

अब आप चेकआउट सत्र बनाते समय टैक्स ID (जैसे, VAT संख्या, GST संख्या) को **प्रीफिल** कर सकते हैं, `tax_id` पैरामीटर का उपयोग करके। यह B2B लेन-देन के लिए आदर्श है जहाँ आपको पहले से ही ग्राहक की टैक्स पहचान संख्या पता होती है। जब टैक्स ID प्रीफिल की जाती है, तो फील्ड चेकआउट फ़ॉर्म पर पूर्व-प्रविष्ट और लॉक हो जाती है।

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`tax_id` पैरामीटर को हमेशा `billing_address` के साथ एक `country` फ़ील्ड की आवश्यकता होती है। टैक्स पात्रता वास्तविक समय में सत्यापित की जाती है, और योग्य B2B लेन-देन के लिए रिवर्स-चार्ज नियम स्वचालित रूप से लागू होते हैं।
</Info>

ग्राहकों को प्रीफिल टैक्स ID को संशोधित करने की अनुमति देने के लिए `allow_customer_editing_tax_id` फीचर फ़्लैग का उपयोग करें, और चेकआउट पर टैक्स ID दृश्यता को टॉगल करने के लिए `allow_tax_id`।

और जानें: [चेकआउट सत्र - टैक्स ID](/developer-resources/checkout-session) | [B2B भुगतान](/features/b2b-payments)

### 7. **रिटर्न URL रीडायरेक्ट में लाइसेंस कुंजी और ईमेल**

एक ग्राहक चेकआउट पूरा करने के बाद, Dodo Payments अब `license_key` और `email` को आपके `return_url` रीडायरेक्ट में क्वेरी पैरामीटर्स के रूप में जोड़ता है, इसके अलावा मौजूदा `payment_id`/`subscription_id` और `status` पैरामीटर्स।

**जोड़ने वाले क्वेरी पैरामीटर्स**

| पैरामीटर | प्रकार | स्थिति |
|-----------|------|-----------|
| `payment_id` | `string` | एक बार के भुगतान के लिए हमेशा मौजूद |
| `subscription_id` | `string` | सदस्यता भुगतानों के लिए हमेशा मौजूद |
| `status` | `string` | हमेशा मौजूद |
| `license_key` | `string` | यदि उत्पाद में लाइसेंस कुंजियाँ सक्षम हैं (कई के लिए अल्पविराम से अलग) तो मौजूद |
| `email` | `string` | यदि ग्राहक के पास रिकॉर्ड पर एक ईमेल है तो मौजूद |

**उदाहरण रीडायरेक्ट URL:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
इन क्वेरी पैरामीटर्स का उपयोग अपने रिटर्न पृष्ठ पर लाइसेंस कुंजी प्रदर्शित करने या तुरंत एक पुष्टि ईमेल भेजने के लिए करें, बिना एक अतिरिक्त API कॉल की आवश्यकता के।
</Tip>

और जानें: [चेकआउट सत्र - रिटर्न URL](/developer-resources/checkout-session) | [रिटर्न URL में लाइसेंस कुंजी](/features/license-keys#license-keys-in-return-url)

### 8. **ग्राहक ईमेल अपडेट API**

`PATCH /customers/{customer_id}` एंडपॉइंट अब प्रोग्रामेटिक रूप से ग्राहक ईमेल पतों को अपडेट करने का समर्थन करता है। एकल API कॉल में नाम, फोन नंबर, और मेटाडेटा के साथ ईमेल अपडेट करें।

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**अपडेट करने योग्य फ़ील्ड**

| फ़ील्ड | प्रकार | विवरण |
|-------|------|-------------|
| `email` | `string \| null` | ग्राहक का ईमेल पता |
| `name` | `string \| null` | ग्राहक का प्रदर्शन नाम |
| `phone_number` | `string \| null` | अंतर्राष्ट्रीय प्रारूप में फोन नंबर |
| `metadata` | `object \| null` | कस्टम कुंजी-मूल्य युग्म |

<Info>
ग्राहक ईमेल अपडेट ग्राहक पोर्टल (स्वयं-सेवा), डैशबोर्ड, और CLI के माध्यम से भी उपलब्ध हैं `dodo customers update`।
</Info>

और जानें: [ग्राहक अपडेट API](/api-reference/customers/patch-customer) | [ग्राहक प्रबंधन](/features/customers)

### 9. **Bun अडाप्टर रिलीज़**

`@dodopayments/bun` का परिचय -- [Bun's](https://bun.sh) की स्वदेशी सर्वर (`Bun.serve()`) के लिए एक समर्पित ढांचा अडाप्टर। चेकआउट, ग्राहक पोर्टल, और वेबहुक्स को कुछ पंक्तियों के कोड के साथ Bun के साथ एकीकृत करें।

**स्थापना**

```bash
bun add @dodopayments/bun
```

**त्वरित सेटअप**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Bun अडाप्टर सभी तीन चेकआउट प्रवाह (स्थिर, गतिशील, और सत्र-आधारित), ग्राहक पोर्टल सत्र निर्माण, और 22 घटना प्रकारों के तहत सिग्नेचर सत्यापन और Zod मान्यता के साथ सुरक्षित वेबहुक हैंडलिंग का समर्थन करता है।
