## नई विशेषताएँ

### 1. **थर्ड-पार्टी एनालिटिक्स समर्थन**

Google Analytics 4, Google Tag Manager, और Meta Pixel के साथ Storefront, Checkout, और Customer Portal में ग्राहक व्यवहार ट्रैक करें। ई-कॉमर्स घटनाओं को एकत्र करना शुरू करने के लिए **Settings → Analytics** में अपने ट्रैकिंग आईडी जोड़ें।

**समर्थित प्लेटफार्मों**

| प्लेटफ़ॉर्म | आईडी प्रारूप |
|----------|-----------|
| Google Analytics 4 | `G-XXXXXXXXXX` |
| Google Tag Manager | `GTM-XXXXXXX` |
| Meta Pixel | न्यूमेरिक (10-20 अंक) |

**निगरानी की गई घटनाएँ**

जैसे कि `purchase`, `add_payment_info`, `view_item`, और `view_item_list` जैसी घटनाएँ स्वचालित रूप से आपकी एनालिटिक्स प्लेटफार्मों पर भेजी जाती हैं जैसे ही ग्राहक ब्राउज़ करते हैं और खरीदारी पूरी करते हैं।

</Check>

अधिक जानें: [थर्ड-पार्टी एनालिटिक्स](/features/analytics)

### 2. **चेकआउट थीम अनुकूलन**

चेकआउट सत्र बनाते समय `customization.theme_config` पैरामीटर का उपयोग करके चेकआउट की उपस्थिति को अनुकूलित करें। रंग, फ़ॉन्ट, बॉर्डर रेडियस, और बटन में पाठ को हल्के और गहरे मोड दोनों के लिए विन्यस्त करें।

**कॉन्फ़िगरेशन विकल्प**

| प्रॉपर्टी | विवरण |
|----------|-------------|
| `light` / `dark` | प्रत्येक मोड के लिए रंग योजनाएँ |
| `font_primary_url` | कस्टम फ़ॉन्ट यूआरएल |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius` | बॉर्डर रेडियस (जैसे, `8px`) |
| `pay_button_text` | कस्टम बटन पाठ |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

अधिक जानें: [चेकआउट थीम अनुकूलन](/features/checkout#checkout-theme-customization)

### 3. **भुगतान विफलता पर योजना परिवर्तन रोकें**

नई `on_payment_failure` पैरामीटर ग्राहक योजना परिवर्तनों के व्यवहार को नियंत्रित करता है जब भुगतान विफल होता है।

| मोड | व्यवहार |
|------|----------|
| `prevent_change` | भुगतान सफल होने तक वर्तमान योजना पर सब्सक्रिप्शन बनाए रखें |
| `apply_change` | भुगतान परिणाम के बावजूद योजना परिवर्तन तत्काल लागू करें (डिफ़ॉल्ट) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
महत्वपूर्ण उन्नयनों के लिए `prevent_change` का उपयोग करें जहाँ आप प्रीमियम सुविधाओं तक पहुँच देने से पहले भुगतान सुनिश्चित करना चाहते हैं।
</Tip>

अधिक जानें: [भुगतान विफलताओं को संभालना](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## एपीआई अपडेट

### शेष लेजर एपीआई

आपके खाते के लेजर प्रविष्टियों को फ़िल्टरिंग और पेजिनेशन के साथ पुनर्प्राप्त करने के लिए नया `GET /balances/ledger` अंत बिंदु।

| पैरामीटर | विवरण |
|-----------|-------------|
| `created_at_gte` / `created_at_lte` | तारीख सीमा द्वारा फ़िल्टर करें |
| `event_type` | `payment`, `refund`, `dispute`, `payout`, आदि द्वारा फ़िल्टर करें |
| `currency` | मुद्रा कोड द्वारा फ़िल्टर करें |
| `reference_object_id` | विशिष्ट भुगतान/रिफंड/विवाद आईडी द्वारा फ़िल्टर करें |

अधिक जानें: [शेष लेजर एपीआई](/api-reference/balance-ledger/list-ledger-entries)

### भुगतान प्रतिक्रिया: `refund_status`

`refund_status` क्षेत्र को `GET /payments/{paymentId}` प्रतिक्रिया में जोड़ा गया है ताकि बिना अलग से रिफंड अंत बिंदु को क्वेरी किए यह जल्दी से जांचा जा सके कि क्या भुगतान रिफंड किया गया है।
