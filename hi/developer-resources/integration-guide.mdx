## आवश्यकताएँ

Dodo Payments API को एकीकृत करने के लिए, आपको आवश्यकता होगी:
- एक Dodo Payments merchant account
- dashboard से API Credentials (API key और webhook secret key)

## Dashboard सेटअप

1. [Dodo Payments Dashboard](https://app.dodopayments.com/) पर जाएँ

2. उत्पाद बनाएँ (one-time payment या subscription)। Subscription products की कीमत कम से कम **\$1** (या आपकी चुनी हुई currency में इसके समतुल्य) होनी चाहिए; इससे कम राशि समर्थित नहीं है।

4. अपनी API key जनरेट करें:
   - Developer > API पर जाएँ
   - [विस्तृत मार्गदर्शिका](/api-reference/introduction#api-key-generation)
   - env में DODO_PAYMENTS_API_KEY नाम वाली API key कॉपी करें

5. Webhooks कॉन्फ़िगर करें:
   - Developer > Webhooks पर जाएँ
   - payment notifications के लिए एक webhook URL बनाएँ
   - env में webhook secret key कॉपी करें 

## एकीकरण

### Payment Links

अपने उपयोग-केस के लिए उपयुक्त integration path चुनें:
- **Checkout Sessions (recommended)**: अधिकांश integrations के लिए सर्वोत्तम। अपने server पर एक session बनाएँ और customers को सुरक्षित, hosted checkout पर redirect करें।
- **Overlay Checkout**: जब आपको अपनी site पर in-page अनुभव चाहिए, जो checkout को modal overlay के रूप में खोले।
- **Inline Checkout**: पूरी तरह integrated और branded checkout अनुभवों के लिए checkout को सीधे अपने page layout में embed करें।
- **Static Payment Links**: तेज़ी से payment collection के लिए no-code, तुरंत share किए जा सकने वाले URLs।
- **Dynamic Payment Links**: Programmatically बनाए गए links। हालाँकि, Checkout Sessions recommended हैं और अधिक flexibility प्रदान करते हैं।
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**: native Android, iOS, React Native और Flutter apps के लिए। ऊपर बताए अनुसार अपने server पर session बनाएँ, फिर `checkout_url` को SDK को दें।

<Info>
Overlay और Inline Checkout केवल browser पर काम करते हैं — ये checkout को web
page में embed करते हैं। यदि आप native mobile app बना रहे हैं, तो अपने
server पर checkout session बनाएँ और इसके बजाय उसे
[Mobile Checkout SDKs](/developer-resources/mobile-integration) से खोलें।
</Info>

#### 1. Checkout Sessions

One-time payments या subscriptions के लिए सुरक्षित, hosted checkout अनुभव बनाने हेतु Checkout Sessions का उपयोग करें। अपने server पर एक session बनाएँ, फिर customer को लौटाए गए `checkout_url` पर redirect करें।

<Info>
Checkout sessions डिफ़ॉल्ट रूप से 24 घंटे तक valid रहते हैं। यदि आप <code>confirm=true</code> pass करते हैं, तो sessions 15 मिनट तक valid रहते हैं और सभी आवश्यक fields प्रदान किए जाने चाहिए।
</Info>

#### 2. Overlay Checkout

Seamless in-page checkout अनुभव के लिए हमारा [Overlay Checkout](/developer-resources/overlay-checkout) integration देखें, जो customers को आपकी website छोड़े बिना payments पूरा करने देता है।

#### 3. Inline Checkout

अपने page में सीधे embedded पूरी तरह integrated checkout अनुभवों के लिए हमारा [Inline Checkout](/developer-resources/inline-checkout) integration उपयोग करें। इससे आप custom order summaries बना सकते हैं और checkout layout पर पूरा control रख सकते हैं, जबकि Dodo Payments payment collection को सुरक्षित रूप से संभालता है।

#### 4. Static Payment Links

Static payment links आपको एक सरल URL share करके तेज़ी से payments स्वीकार करने देते हैं। Customer details को pre-fill करने, form fields को नियंत्रित करने और custom metadata जोड़ने के लिए query parameters pass करके checkout अनुभव को customize कर सकते हैं।

<Steps>
<Step title="Construct your payment link">
  Base URL से शुरू करें और अपना product ID जोड़ें:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  आवश्यक query parameters शामिल करें:
  - <ParamField query="quantity" type="integer" default="1">खरीदी जाने वाली items की संख्या।</ParamField>
  - <ParamField query="redirect_url" type="string" required>Payment पूरा होने के बाद redirect करने के लिए URL।</ParamField>
  <Note>
  Redirect URL में query parameters के रूप में payment details शामिल होंगी, उदाहरण के लिए:<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  यदि product में license keys enabled हैं, तो एक `license_key` parameter भी जोड़ा जाता है (multiple keys के लिए comma-separated):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  Checkout को सरल बनाने के लिए customer या billing fields को query parameters के रूप में जोड़ें।
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">Customer का पूरा नाम (यदि firstName या lastName प्रदान किया गया हो तो ignore किया जाता है)।</ParamField>
      - <ParamField query="firstName" type="string">Customer का first name।</ParamField>
      - <ParamField query="lastName" type="string">Customer का last name।</ParamField>
      - <ParamField query="email" type="string">Customer का email address।</ParamField>
      - <ParamField query="country" type="string">Customer का country।</ParamField>
      - <ParamField query="addressLine" type="string">Street address।</ParamField>
      - <ParamField query="city" type="string">City।</ParamField>
      - <ParamField query="state" type="string">State या province।</ParamField>
      - <ParamField query="zipCode" type="string">Postal/ZIP code।</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true या false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  आप specific fields को disable करके उन्हें customer के लिए read-only बना सकते हैं। यह तब उपयोगी है जब आपके पास customer की details पहले से हों (जैसे logged-in users)।
  </Info>
  किसी field को disable करने के लिए उसका value दें और संबंधित <code>disable...</code> flag को <code>true</code> पर set करें:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Field         | Disable Flag         | Required Parameter |
      |---------------|---------------------|-------------------|
      | Full Name     | `disableFullName`   | `fullName`        |
      | First Name    | `disableFirstName`  | `firstName`       |
      | Last Name     | `disableLastName`   | `lastName`        |
      | Email         | `disableEmail`      | `email`           |
      | Country       | `disableCountry`    | `country`         |
      | Address Line  | `disableAddressLine`| `addressLine`     |
      | City          | `disableCity`       | `city`            |
      | State         | `disableState`      | `state`           |
      | ZIP Code      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  Fields को disable करने से accidental changes रोकने और data consistency सुनिश्चित करने में मदद मिलती है।
  </Tip>
  <Note>
  <code>showDiscounts=false</code> set करने से checkout form में discounts section disable और hide हो जाएगा। यदि आप checkout के दौरान customers को coupon या promo codes enter करने से रोकना चाहते हैं, तो इसका उपयोग करें।
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">भुगतान की currency निर्दिष्ट करता है। डिफ़ॉल्ट रूप से billing country की currency का उपयोग होता है।</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">currency selector दिखाएँ या छिपाएँ।</ParamField>
  - <ParamField query="paymentAmount" type="number">चार्ज की जाने वाली राशि को major currency units में निर्धारित करता है (जैसे, $12.50 के लिए <code>12.5</code>)। केवल Pay What You Want products के लिए। यदि value product की minimum price से कम है, तो इसे अनदेखा कर दिया जाता है।</ParamField>
  - <ParamField query="metadata_*" type="string">Custom metadata fields (जैसे, <code>metadata_orderId=123</code>)।</ParamField>

  <Warning>
  Payment link पर `paymentAmount`, Checkout Sessions API में मौजूद **`amount`** field की तरह समान unit नहीं है। Link parameter में major currency units लिए जाते हैं (`12.5` = $12.50), जबकि API का `product_cart[].amount` सबसे छोटी denomination लेता है (`1250` = $12.50)। API field के लिए [Dynamic Pricing](/developer-resources/dynamic-pricing-checkout) देखें।
  </Warning>
</Step>
<Step title="Share the link">
  पूर्ण किए गए payment link को अपने customer को भेजें। उनके इसे खोलने पर, सभी query parameters एकत्र करके session ID के साथ store किए जाते हैं। इसके बाद URL को सरल बनाकर केवल session parameter शामिल किया जाता है (जैसे, <code>?session=sess_1a2b3c4d</code>)। Store की गई जानकारी page refresh होने पर भी बनी रहती है और पूरे checkout process के दौरान accessible रहती है।
  <Check>
  अब customer का checkout experience आपके parameters के आधार पर streamlined और personalized है।
  </Check>
</Step>
</Steps>

### Webhooks लागू करना

Payment notifications प्राप्त करने के लिए एक API endpoint सेट अप करें। यहाँ Next.js का उपयोग करने वाला एक उदाहरण है:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

हमारा webhook implementation [Standard Webhooks](https://standardwebhooks.com/) specification का पालन करता है। Webhook type definitions के लिए हमारी [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide) देखें।

#### सुनने योग्य Events

`payload.type` को enable करें और one-time payment flow से संबंधित events को handle करें। कम से कम, इन events को listen करें:

| Event Type           | यह कब fire होता है                                              | क्या करना है                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | Payment सफलतापूर्वक process हो जाता है।                        | Order fulfill करें — access दें, product provision करें और receipt भेजें। |
| `payment.failed`     | Payment attempt विफल होता है (declined card, error आदि)।       | Customer को notify करें और retry के लिए prompt करें; fulfill न करें।                    |
| `payment.processing` | Payment accept हो जाता है, लेकिन अभी process हो रहा है (async methods)। | Terminal `payment.succeeded`/`payment.failed` का इंतज़ार करें — अभी fulfill न करें। |
| `payment.cancelled`  | Payment पूरा होने से पहले cancel हो जाता है।                   | Held state release करें और order को abandoned mark करें।                       |

<Tip>
Browser redirect पर नहीं, बल्कि **webhook से `payment.succeeded` पर हमेशा fulfill करें** — यदि customer tab बंद कर देता है, तो redirect miss हो सकता है, जबकि webhook को acknowledge किए जाने तक retry किया जाता है।
</Tip>

यदि आप license keys वाले digital products बेचते हैं, तो `license_key.created` को भी handle करें। Events की पूरी सूची — जिसमें subscription, entitlement, credit, recovery और dunning events शामिल हैं — के लिए [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide) देखें।

आप Next.js और TypeScript का उपयोग करने वाले demo implementation वाले इस project को [GitHub](https://github.com/dodopayments/dodo-checkout-demo) पर देख सकते हैं।

Live implementation [यहाँ](https://atlas.dodopayments.com/) देखें।

## Checkout और Currency के बारे में जानने योग्य मुख्य बातें

<Warning>
**Dynamic (Pay-What-You-Want) amounts product की base currency में होते हैं** — किसी arbitrary local currency में नहीं — और base currency केवल **USD, INR, GBP और EUR** तक सीमित है। किसी दूसरी currency (जैसे PHP) में fixed amount collect करने के लिए इसे सीधे pass नहीं किया जा सकता: **Adaptive Pricing** (आपकी base amount को live FX पर convert करता है) या **Localized Pricing** (हर currency के लिए fixed price, लेकिन Pay-What-You-Want के साथ compatible नहीं) का उपयोग करें।
</Warning>

<Tip>
**Currency को explicitly fix करें।** Checkout session पर `billing_currency` और `billing_address.country` pass करें। यदि इन्हें छोड़ दिया जाता है, तो customer के IP से currency और country detect किए जाते हैं (Adaptive Currency), जो उस राशि से मेल नहीं खा सकते जिसे आप charge करना चाहते हैं।
</Tip>

<Info>
**Checkout sessions 24 घंटे में expire हो जाते हैं** (जब `confirm: true` हो, तब 15 मिनट में), और प्रत्येक `checkout_url` **single-use** होता है — link को reuse करने के बजाय प्रत्येक customer और प्रत्येक payment attempt के लिए नया session generate करें।
</Info>

<Info>
**One-click repeat purchase।** Saved payment method वाले returning customer के लिए, तुरंत charge करने और method selection को पूरी तरह skip करने हेतु `payment_method_id` को `confirm: true` के साथ pass करें।
</Info>
