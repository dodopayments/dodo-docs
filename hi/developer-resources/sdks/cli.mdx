अपने Dodo Payments संसाधनों को प्रबंधित करें, चेकआउट सत्र बनाएं, और सीधे टर्मिनल से वेबहुक का परीक्षण करें। उन डेवलपर्स के लिए निर्मित जिन्हें कमांड लाइन पसंद है।

## स्थापना

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### मैनुअल स्थापना

1. अपने सिस्टम के लिए [GitHub Releases](https://github.com/dodopayments/dodopayments-cli/releases) से नवीनतम रिलीज़ डाउनलोड करें
2. बाइनरी को निकाले और `dodo` नाम दें
3. अपने PATH में एक डायरेक्टरी में स्थानांतरित करें:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## प्रमाणीकरण

CLI का उपयोग करने से पहले, अपने API कुंजी द्वारा प्रमाणीकरण करें:

```bash
dodo login
```

यह करेगा:
1. आपके ब्राउज़र में Dodo Payments API कुंजी पृष्ठ खोलेगा
2. आपको अपने API कुंजी दर्ज करने के लिए प्रेरित करेगा
3. आपको वातावरण का चयन करने के लिए कहेगा (**टेस्ट मोड** या **लाइव मोड**)
4. आपकी साख को स्थानीय स्तर पर `~/.dodopayments/api-key` में संग्रहीत करेगा

<Info>
CLI एक वातावरण के लिए एक API कुंजी को संग्रहित करने का समर्थन करता है। यदि दोनों परीक्षण और लाइव मोड कुंजी कॉन्फ़िगर की गई हैं, तो इस सत्र के लिए उपयोग करने के लिए आपको उस वातावरण का चयन करने के लिए प्रेरित किया जाएगा।
</Info>

## उपयोग

सामान्य सिंटैक्स है:

```bash
dodo ‹category› ‹sub-command›
```

कोई तर्क न देने पर `dodo` सभी उपलब्ध श्रेणियों को प्रदर्शित करता है। कोई उप-कमांड न देने पर `dodo <category>` उस श्रेणी के लिए उपलब्ध उप-आदेशों को दिखाता है।

### उत्पाद

अपने उत्पाद सूची का प्रबंधन करें।

| आदेश | विवरण |
|---------|-------------|
| `dodo products list` | सभी उत्पादों को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo products create` | एक उत्पाद बनाने के लिए डैशबोर्ड खोलें |
| `dodo products info` | एक विशिष्ट उत्पाद के विवरण देखें |

### भुगतान

भुगतान लेनदेन को देखें।

| आदेश | विवरण |
|---------|-------------|
| `dodo payments list` | सभी भुगतानों को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo payments info` | एक विशिष्ट भुगतान की जानकारी प्राप्त करें |

### ग्राहक

अपने ग्राहक आधार का प्रबंधन करें।

| आदेश | विवरण |
|---------|-------------|
| `dodo customers list` | सभी ग्राहकों को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo customers create` | एक नया ग्राहक प्रोफ़ाइल बनाएं |
| `dodo customers update` | एक मौजूदा ग्राहक के विवरण को अपडेट करें |

### छूट

कूपन और छूट का प्रबंधन करें।

| आदेश | विवरण |
|---------|-------------|
| `dodo discounts list` | सभी छूटों को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo discounts create` | एक नई प्रतिशत-आधारित छूट बनाएं |
| `dodo discounts delete` | ID द्वारा छूट को हटाएं |

### लाइसेंस

सॉफ्टवेयर लाइसेंस का प्रबंधन करें।

| आदेश | विवरण |
|---------|-------------|
| `dodo licences list` | सभी लाइसेंस कुंजियों को सूचीबद्ध करें (पृष्ठबद्ध) |

### ऐडऑन

उत्पाद ऐडऑन का प्रबंधन करें।

| आदेश | विवरण |
|---------|-------------|
| `dodo addons list` | सभी ऐडऑन को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo addons create` | एक ऐडऑन बनाने के लिए डैशबोर्ड खोलें |
| `dodo addons info` | एक विशिष्ट ऐडऑन के विवरण देखें |

### रिफंड

रिफंड जानकारी देखें।

| आदेश | विवरण |
|---------|-------------|
| `dodo refund list` | सभी रिफंड को सूचीबद्ध करें (पृष्ठबद्ध) |
| `dodo refund info` | एक विशिष्ट रिफंड के विवरण देखें |

### चेकआउट

चेकआउट सत्र बनाएं।

| आदेश | विवरण |
|---------|-------------|
| `dodo checkout new` | एक नया चेकआउट सत्र बनाएं और चेकआउट URL प्राप्त करें |

चेकआउट आदेश उन्नत विकल्पों का समर्थन करता है जिसमें न्यूनतम पते का संग्रहण, वापसी URL, 3D सुरक्षित प्रवर्तन, छूट कोड, और मेटाडेटा शामिल हैं।

## वेबहुक परीक्षण

CLI विकास के दौरान वेबहुक के परीक्षण के लिए दो शक्तिशाली टूल शामिल करता है: एक **लिसनर** जो लाइव परीक्षण वेबहुक को आपके स्थानीय सर्वर पर अग्रेषित करता है, और एक **ट्रिगर** जो किसी भी एंडपॉइंट पर मॉक वेबहुक पेलोड भेजता है।

### वेबहुक के लिए सुनें

Dodo Payments से सीधे अपने स्थानीय विकास सर्वर पर वास्तविक समय में वेबहुक को अग्रेषित करें।

```bash
dodo wh listen
```

<Steps>
<Step title="अपने स्थानीय एंडपॉइंट URL दर्ज करें">
  वह स्थानीय URL प्रदान करें जहाँ आप वेबहुक प्राप्त करना चाहते हैं (जैसे, `http://localhost:3000/webhook`)।
</Step>

<Step title="स्वचालित सेटअप">
  यदि पहले से एक वेबहुक एंडपॉइंट नहीं है तो CLI स्वचालित रूप से आपके Dodo Payments खाते पर एक वेबहुक एंडपॉइंट बनाता है, फिर वास्तविक समय में घटनाओं को प्राप्त करने के लिए एक वेब-सॉकेट कनेक्शन खोलता है।
</Step>

<Step title="प्राप्त करें और अग्रेषित करें">
  जब एक वेबहुक घटना कार्यान्वित होती है (परीक्षण भुगतान, सदस्यता परिवर्तन आदि से), CLI इसे प्राप्त करता है, घटना के प्रकार को लॉग करता है, और आपके स्थानीय एंडपॉइंट को हेडर और बॉडी के साथ पूरी अनुरोध अग्रेषित करता है। आपके एंडपॉइंट से प्रतिक्रिया लॉग की जाती है और वापस भेजी जाती है।
</Step>
</Steps>

<Warning>
वेबहुक लिसनर केवल **टेस्ट मोड** API कुंजी के साथ काम करता है। सुनिश्चित करें कि आप `dodo wh listen` का उपयोग करने से पहले एक टेस्ट मोड कुंजी के साथ लॉग इन हैं।
</Warning>

<Tip>
लिसनर मूल वेबहुक हेडर्स (`webhook-id`, `webhook-signature`, `webhook-timestamp`) को आपके स्थानीय एंडपॉइंट पर अग्रेषित करते समय संरक्षित करता है, ताकि आप अपनी हस्ताक्षर प्रमाणीकरण तर्क का परीक्षण कर सकें।
</Tip>

### परीक्षण वेबहुक को ट्रिगर करें

किसी भी एंडपॉइंट पर त्वरित परीक्षण के लिए मॉक वेबहुक पेलोड भेजें बिना वास्तविक लेनदेन बनाए।

```bash
dodo wh trigger
```

यह आपको मार्गदर्शन करेगा:
1. एक गंतव्य **एंडपॉइंट URL** सेट करना
2. वैकल्पिक रूप से **व्यापार आईडी**, **उत्पाद आईडी**, और **मेटाडेटा** कॉन्फ़िगर करना
3. एक इंटरएक्टिव मेनू से ट्रिगर करने के लिए एक विशिष्ट **घटना** का चयन करना
4. मॉक पेलोड भेजना और प्रतिक्रिया देखना

प्रत्येक घटना के बाद, आप एक और घटना को ट्रिगर करने या बाहर निकलने का चयन कर सकते हैं - जिससे एक सत्र में कई घटना हैंडलरों का परीक्षण करना आसान हो जाता है।

<Warning>
ट्रिगर टूल मॉक पेलोड को वेबहुक हस्ताक्षर के बिना भेजता है। परीक्षण के दौरान वेबहुक हस्ताक्षर प्रमाणीकरण को निष्क्रिय करें `unsafe_unwrap()` का उपयोग करके `unwrap()` के बजाय अपने वेबहुक हैंडलर में।
</Warning>

### समर्थित वेबहुक घटनाएँ

| श्रेणी | घटनाएँ |
|----------|--------|
| **सदस्यता** | `subscription.active`, `subscription.updated`, `subscription.on_hold`, `subscription.renewed`, `subscription.plan_changed`, `subscription.cancelled`, `subscription.failed`, `subscription.expired` |
| **भुगतान** | `payment.success`, `payment.failed`, `payment.processing`, `payment.cancelled` |
| **रिफंड** | `refund.success`, `refund.failed` |
| **विवाद** | `dispute.opened`, `dispute.expired`, `dispute.accepted`, `dispute.cancelled`, `dispute.challenged`, `dispute.won`, `dispute.lost` |
| **लाइसेंस** | `licence.created` |
