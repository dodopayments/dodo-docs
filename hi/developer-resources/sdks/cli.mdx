अपने Dodo Payments संसाधनों को प्रबंधित करें, अपने account पर AI-संचालित queries चलाएँ, checkout sessions बनाएँ और webhooks का परीक्षण करें — यह सब terminal से। CLI में एक interactive TUI, MCP द्वारा संचालित built-in AI assistant और offline webhook testing शामिल हैं।

## सुविधाएँ

- **Interactive TUI** — पूरी interactive interface खोलने के लिए बिना arguments के `dodo` चलाएँ, जिसमें command palette, history और live notifications उपलब्ध हैं।
- **AI assistant built in** — `/ai` के साथ साधारण English में questions पूछें या actions लें। किसी अतिरिक्त setup की आवश्यकता नहीं; यह `dodopayments-mcp` को locally चलाता है।
- **डिफ़ॉल्ट रूप से सुरक्षित** — API keys आपके OS secret store (macOS Keychain, Windows Credential Vault, Linux libsecret) में संग्रहीत की जाती हैं। Disk पर कोई plaintext config नहीं।
- **Auto update** — CLI startup पर नए versions की जाँच करता है और app में आपको सूचित करता है। उसी स्थान पर upgrade करने के लिए `/update` चलाएँ।
- **Webhook tooling** — live webhooks सुनें या local development के लिए payloads को offline trigger करें।

## Installation

macOS या Linux पर CLI को एक line में install करें:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### npm या Bun के साथ install करें

यदि आपके पास पहले से Node या Bun है, तो package-manager installs हमेशा latest version प्राप्त करते हैं:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Manual installation (Node / Bun की आवश्यकता नहीं)

यदि आप किसी remote script को `sh` पर pipe नहीं करना चाहते, तो binary स्वयं download करें।

<Steps>
<Step title="Download the binary">
  अपने platform के लिए binary नवीनतम [GitHub Release](https://github.com/dodopayments/dodopayments-cli/releases) से download करें।

  | Platform | Binary |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  Windows पर `C:\Windows\System32` में move करने के लिए administrator privileges आवश्यक हैं।
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  प्रत्येक release एक `SHA256SUMS.txt` प्रकाशित करता है। अपने download को इससे verify करें:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## Authentication

Authenticated commands का उपयोग करने से पहले अपनी API key से log in करें:

```bash
dodo login
```

या, interactive TUI के अंदर से:

```text
/login
```

Login flow यह करेगा:

1. आपके browser में Dodo Payments API Keys page खोलेगा।
2. आपको अपनी API Key paste करने के लिए prompt करेगा।
3. आपको एक environment चुनने के लिए कहेगा — **Test Mode** या **Live Mode**।
4. Credentials को आपके OS secret store (macOS पर Keychain, Windows पर Credential Vault, Linux पर libsecret) में store करेगा।

<Info>
क्योंकि credentials OS secret store में store किए जाते हैं, इसलिए पहली बार CLI द्वारा credentials पढ़ने या लिखने पर आपसे अपना **device password** माँगा जा सकता है। यदि आप पुराने version से upgrade कर रहे हैं, तो कोई भी मौजूदा plaintext API key अपने-आप **secret store में migrate की जाएगी और legacy file delete कर दी जाएगी**।
</Info>

### Modes बदलना और log out करना

आप एक ही समय में एक **Test Mode** और एक **Live Mode** key को authenticated रख सकते हैं। Credentials clear करने के लिए:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

Logout flow आपको स्वतंत्र रूप से **All accounts**, **Test Mode**, या **Live Mode** में से चुनने देता है।

## उपयोग

आप CLI का उपयोग दो modes में कर सकते हैं।

### 1. Interactive TUI (अनुशंसित)

पूरी interactive interface launch करने के लिए बिना arguments के `dodo` चलाएँ:

```bash
dodo
```

Command palette खोलने के लिए `/` type करें, या बस type करना शुरू करें — slash command के अलावा कोई भी input AI assistant को भेजा जाता है।

| Command | Description |
|---------|-------------|
| `/help` | Command reference दिखाएँ |
| `/update` | CLI update की जाँच करें और उसे install करें |
| `/login` | API key से authenticate करें |
| `/logout` | एक या सभी environments से sign out करें |
| `/clear` | TUI screen clear करें |
| `/exit` | TUI से बाहर निकलें (यह भी: `exit` type करें, या `Esc` को दो बार दबाएँ) |

### 2. Direct subcommands

TUI में प्रवेश किए बिना commands सीधे चलाएँ:

```bash
dodo <category> <sub-command> [args...]
```

उदाहरण के लिए:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

नीचे दी गई reference tables प्रत्येक command दिखाती हैं। TUI में इनके आगे `/` लगाएँ; direct mode में `/` हटा दें।

## AI Assistant

Natural language में questions पूछें या actions लें। Assistant locally चलने वाले `dodopayments-mcp` का उपयोग करता है — किसी अतिरिक्त setup या OAuth flow की आवश्यकता नहीं है, और आपका AI traffic model provider से बात करने के अलावा आपकी machine से बाहर नहीं जाता।

| Command | Description |
|---------|-------------|
| `/ai <query>` | AI assistant से question पूछें या उसे instruction दें |
| _(any non-slash text)_ | TUI में रहते हुए default रूप से AI assistant को भेजा जाता है |

उदाहरण:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
Assistant आपके active environment (Test / Live) का सम्मान करता है, इसलिए यह केवल उस environment के data पर operate करता है जिसमें आप वर्तमान में logged in हैं।
</Tip>

## Project Scaffolding

`dodo init` Dodo Payments billing routes को सीधे किसी मौजूदा project में scaffold करता है। यह boilerplate route files generate करता है, matching `@dodopayments/*` adapter package install करता है, और `DODO_PAYMENTS_*` environment variables को आपके `.env` में सुरक्षित रूप से लिखता है (यह केवल उन variables को append करता है जो पहले से मौजूद नहीं हैं)। यह command **login किए बिना** चलती है।

```bash
dodo init <framework>
```

| Scaffold | Description |
|----------|-------------|
| `dodo init nextjs` | `@dodopayments/nextjs` का उपयोग करके Next.js App Router billing routes (checkout, customer portal और webhook handlers) scaffold करें |
| `dodo init express` | `@dodopayments/express` का उपयोग करके Express server billing routes scaffold करें |
| `dodo init better-auth` | `@dodopayments/better-auth` का उपयोग करके Better-Auth plugin configuration scaffold करें |

Better-Auth scaffold के लिए generate किए जाने वाले plugins की comma-separated list दे सकते हैं (default रूप से सभी): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
Scaffolder स्वतः `src/` directory का पता लगाकर output paths को उसी के अनुसार समायोजित करता है, और आपके package manager (`bun`, `pnpm`, `yarn`, या `npm`) का स्वतः पता लगाकर सही install command चलाता है।
</Info>

## Webhooks

CLI में development के दौरान webhooks का परीक्षण करने के लिए दो powerful tools शामिल हैं: एक **listener**, जो live test webhooks को आपके local server पर forward करता है, और एक **trigger**, जो किसी भी endpoint पर mock webhook payloads भेजता है।

| Command | Description |
|---------|-------------|
| `dodo wh listen` | Webhooks को real time में सुनें और अपने local dev server पर forward करें |
| `dodo wh trigger` | Interactively test webhook event trigger करें — logged out होने पर भी |

### Webhooks सुनें

Dodo Payments से webhooks को real time में सीधे अपने local development server पर forward करें।

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  वह local URL दें जहाँ आप webhooks प्राप्त करना चाहते हैं (उदाहरण के लिए, `http://localhost:3000/webhook`)।
</Step>

<Step title="Automatic setup">
  यदि कोई webhook endpoint पहले से मौजूद नहीं है, तो CLI आपके Dodo Payments account पर उसे स्वतः create करता है, फिर real time में events प्राप्त करने के लिए WebSocket connection खोलता है।
</Step>

<Step title="Receive and forward">
  जब कोई webhook event fire होता है (किसी test payment, subscription change आदि से), CLI उसे receive करता है, event type log करता है और headers तथा body के साथ पूरा request आपके local endpoint पर forward करता है। आपके endpoint का response log करके वापस भेजा जाता है।
</Step>
</Steps>

<Warning>
`dodo wh listen` के लिए **Test Mode** API key आवश्यक है। Listen flow में Live Mode keys समर्थित नहीं हैं।
</Warning>

<Tip>
Listener आपके local endpoint पर forward करते समय मूल webhook headers (`webhook-id`, `webhook-signature`, `webhook-timestamp`) को सुरक्षित रखता है, ताकि आप अपनी signature verification logic का परीक्षण कर सकें।
</Tip>

### Test webhooks trigger करें

Real transactions create किए बिना quick testing के लिए किसी भी endpoint पर mock webhook payloads भेजें।

```bash
dodo wh trigger
```

`/wh trigger` flow आपको इन steps से guide करता है:

1. Destination **endpoint URL** सेट करना
2. Interactive menu से trigger करने के लिए specific **event** चुनना

<Info>
`dodo wh trigger` के लिए login आवश्यक **नहीं** है। यह local/offline webhook payload generator के रूप में काम करता है।
</Info>

<Warning>
Triggered events **signed नहीं होते**। Testing के दौरान अपने endpoint पर webhook signature verification disable करें — उदाहरण के लिए, अपने webhook handler में **केवल testing के दौरान** `unwrap()` के बजाय `unsafe_unwrap()` का उपयोग करें।
</Warning>

### समर्थित webhook events

`dodo wh trigger` इन 22 event types के लिए mock payloads भेज सकता है:

| श्रेणी | Events |
|----------|--------|
| **Subscription** | `active`, `updated`, `on_hold`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired` |
| **Payment** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Refund** | `succeeded`, `failed` |
| **Dispute** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **License** | `created` |

<Note>
यह उन events का एक subset है जिन्हें Dodo Payments deliver करता है। `payout.*`, `credit.*`, `abandoned_checkout.*`, `dunning.*`, `entitlement_grant.*`, `subscription.paused`, और `subscription.update_payment_method` के लिए अभी कोई mock generator नहीं है — इन्हें वास्तविक test-mode activity और `dodo wh listen` के साथ exercise करें। पूरी सूची के लिए [Webhook Events](/developer-resources/webhooks/intents/webhook-events-guide) देखें।
</Note>

### Environment variables

| Variable | Description |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | `dodo wh listen` द्वारा उपयोग किए जाने वाले default webhook relay server URL को override करें |
