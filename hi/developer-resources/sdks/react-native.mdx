<Info>
यह आधिकारिक Dodo Payments React Native checkout SDK है, `@dodopayments/react-native-checkout`। यह Dodo's hosted checkout को native browser view में खोलता है और typed result लौटाता है। ध्यान दें: `dodopayments-react-native-sdk` (unscoped) नाम का एक पुराना, असंबंधित package मौजूद है, जिसका API पूरी तरह अलग है। यह पेज केवल वर्तमान आधिकारिक scoped package का documentation है।
</Info>

<Card title="Checkout Sessions API" icon="cart-shopping" href="/developer-resources/checkout-session">
  अपने backend से वह checkout_url बनाएँ जिसे यह SDK खोलता है।
</Card>
<Card title="Mobile Integration Guide" icon="mobile" href="/developer-resources/mobile-integration">
  देखें कि यह पूरे mobile payment flow में कैसे फिट होता है।
</Card>
</CardGroup>

React Native SDK उसी native Swift और Kotlin cores के ऊपर एक thin Turbo Module wrapper है। यह iOS पर `SFSafariViewController` और Android पर Chrome Custom Tab खोलता है, कोई API key नहीं रखता और Dodo API को सीधे कभी call नहीं करता। Checkout का पूरा logic browser में चलता है; SDK केवल view lifecycle को manage करता है और return URL को capture करता है।

<Warning>
इस SDK के लिए केवल **New Architecture**, React Native 0.76+, iOS 16+ और Android `minSdk` 24 आवश्यक हैं।
</Warning>

## Installation

<Steps>
<Step title="Install the Package">
<Tabs>
<Tab title="Android">
Package autolinked है और Maven से `com.dodopayments.api:checkout-android` प्राप्त करता है।

```sh
npm i @dodopayments/react-native-checkout
```

किसी अतिरिक्त setup की आवश्यकता नहीं है; native dependency अपने-आप resolve हो जाती है।
</Tab>
<Tab title="iOS">

```sh
npm i @dodopayments/react-native-checkout
cd ios && pod install
```

Swift core package में bundled है और CocoaPods के माध्यम से install होता है।
</Tab>
<Tab title="Expo">
केवल development builds के लिए (Expo Go के लिए नहीं)।

```sh
npm i @dodopayments/react-native-checkout
```

इसके बाद अपना `app.json` configure करें (नीचे Register a Callback URL Scheme देखें)।
</Tab>
</Tabs>
</Step>
<Step title="Register a Callback URL Scheme">
आपके app को checkout से return URL प्राप्त करने के लिए एक URL scheme register करनी होगी।

<Tabs>
<Tab title="Android (Gradle)">
`android/app/build.gradle` में:

```kotlin android/app/build.gradle
android {
    defaultConfig {
        manifestPlaceholders["dodoCallbackScheme"] = "myapp"
    }
}
```

`"myapp"` को अपने app की scheme से बदलें।
</Tab>
<Tab title="iOS (Info.plist)">
`ios/YourApp/Info.plist` में:

```xml Info.plist
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLName</key>
    <string>myapp</string>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>myapp</string>
    </array>
  </dict>
</array>
```

आप इसे Xcode के **Info → URL Types** UI के माध्यम से भी जोड़ सकते हैं।
</Tab>
<Tab title="Expo (both platforms)">
पैकेज का अपना config plugin दोनों platforms के लिए scheme को
`prebuild` पर register करता है। इसे `app.json` में एक `scheme` option दें:

```json app.json
{
  "expo": {
    "scheme": "myapp",
    "plugins": [
      [
        "@dodopayments/react-native-checkout",
        { "scheme": "myappcheckout" }
      ]
    ]
  }
}
```

`scheme` का मान आपके द्वारा `returnUrl` में दिए गए मान से मेल खाना चाहिए (उदाहरण के लिए,
`myappcheckout://return`), और यह `expo.scheme` से अलग होना चाहिए। Expo पहले से ही
इसे `MainActivity` पर register करता है, और इसका दोबारा उपयोग checkout
return को गलत screen पर भेज सकता है।

`app.json` में बदलाव करने के बाद native project को
फिर से build करें:

```sh
npx expo prebuild --clean
```

यह केवल development builds के साथ काम करता है, Expo Go के साथ नहीं।

यदि `android/app/build.gradle` को manually maintain किया जाता है और उसमें plugin को खोजने के लिए कोई standard
`defaultConfig { }` block नहीं है, तो इसके बजाय placeholder
स्वयं जोड़ें। ऊपर दिया गया Android tab देखें।
</Tab>
</Tabs>
</Step>
</Steps>

## उपयोग

```typescript
import { Linking } from 'react-native';
import { DodoCheckout } from '@dodopayments/react-native-checkout';

// Required for iOS's return-URL handling.
Linking.addEventListener('url', ({ url }) => DodoCheckout.handleOpenURL(url));

const result = await DodoCheckout.start({
  checkoutUrl,                          // from your backend's checkout session
  returnUrl: 'myapp://checkout/return', // scheme must be registered (see Installation)
  onEvent: (e) => console.log(e.type),  // logging only
});

switch (result.status) {
  case 'succeeded': showSuccess(result.paymentId); break;
  case 'failed':    showFailure(); break;
  case 'cancelled': dismiss(); break;
  case 'pending':   showPending(); break;
  case 'expired':   showExpired(); break;
}
```

## Return URL को forward करना

`Linking` listener iOS के return-URL handling के लिए आवश्यक है। Android पर, `handleOpenURL` एक no-op है जो `false` को resolve करता है, क्योंकि Android core अपने redirect को native रूप से handle करता है। दोनों platforms पर listener को बिना शर्त register करना सुरक्षित है।

```typescript
import { Linking } from 'react-native';
import { DodoCheckout } from '@dodopayments/react-native-checkout';

Linking.addEventListener('url', ({ url }) => {
  DodoCheckout.handleOpenURL(url);
});
```

## Result का अर्थ

<Warning>
`result.status` एक UI hint है, payment का प्रमाण नहीं। प्रत्येक payment की पुष्टि अपने backend से, `payment.succeeded` / `subscription.active` webhook के माध्यम से करें।
</Warning>

<ParamField body="status" type="CheckoutStatus" required>
इनमें से कोई एक: `succeeded`, `failed`, `cancelled`, `pending`, `expired`।
</ParamField>

<ParamField body="paymentId" type="string">
जब return URL में कोई URL शामिल हो, तब set होता है। इसे UI में दिखाएँ, access देने के लिए इसका उपयोग न करें। नीचे Verify the Payment देखें।
</ParamField>

<ParamField body="subscriptionId" type="string">
subscription checkouts के लिए set होता है।
</ParamField>

<ParamField body="licenseKeys" type="string[]">
जब checkout में license key products शामिल होते हैं, तब set होता है।
</ParamField>

<ParamField body="customerEmail" type="string">
जब checkout कोई email capture करता है, तब set होता है।
</ParamField>

<ParamField body="raw" type="Record<string, string>">
return URL का प्रत्येक query parameter, verbatim।
</ParamField>

## Errors

`start` केवल misuse या platform failure के लिए `CheckoutError` के साथ reject करता है। cancelled या declined payment हमेशा एक result होता है, exception नहीं।

- `INVALID_CHECKOUT_URL`: यह `checkout.dodopayments.com` session URL नहीं है।
- `INVALID_RETURN_URL`: यह valid absolute URL नहीं है।
- `ALREADY_IN_PROGRESS`: एक checkout पहले से चल रहा है।
- `PLATFORM_ERROR`: अप्रत्याशित platform failure।

## Abandoned Sessions

यदि checkout के बीच में app या JS bundle बंद हो जाता है, तो promise खो जाता है, लेकिन native layer session को बनाए रखती है। अगले mount पर इसे recover करें और अपने backend के साथ reconcile करें।

```typescript
import { DodoCheckout } from '@dodopayments/react-native-checkout';

const abandoned = await DodoCheckout.getAbandonedSession();
if (abandoned) {
  // reconcile abandoned.sessionId with your backend, then:
  await DodoCheckout.clearAbandonedSession();
}
```
