## छोड़ी गई गाड़ी पुनरुद्धार घटनाएँ

निम्नलिखित वेबहूक घटनाएँ छोड़ी गई गाड़ी पुनरुद्धार जीवनचक्र को ट्रैक करती हैं:

| घटना | विवरण |
|-------|-------------|
| `abandoned_checkout.detected` | एक छोड़ी गई चेकआउट का पता चला है। भेजा जाता है जब कोई भुगतान छोड़ा हुआ (असफल या अधूरा) पहचाना जाता है और पुनरुद्धार कार्यप्रवाह शुरू होता है। |
| `abandoned_checkout.recovered` | ग्राहक ने पुनरुद्धार लिंक के माध्यम से भुगतान पूरा किया। `recovered_payment_id` फ़ील्ड में सफल भुगतान आईडी होती है। |

### छोड़ी गई चेकआउट पेलोड फ़ील्ड्स

<ParamField body="payment_id" type="string" required>
मूल भुगतान जो छोड़ दिया गया था। उत्पाद, राशि और मुद्रा विवरण देखने के लिए इसका उपयोग करें।
</ParamField>

<ParamField body="brand_id" type="string" required>
यह abandoned checkout जिस brand का है।
</ParamField>

<ParamField body="customer_id" type="string" required>
वह customer जिसने checkout छोड़ दिया।
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
checkout छोड़े जाने का कारण। इनमें से एक:
- `payment_failed` — Customer ने payment का प्रयास किया, लेकिन वह विफल रहा
- `checkout_incomplete` — Customer ने checkout देखा, लेकिन payment का प्रयास कभी नहीं किया
</ParamField>

<ParamField body="status" type="string" required>
इस recovery attempt की वर्तमान lifecycle state। इनमें से एक:
- `abandoned` — Detected, अभी तक कोई email नहीं भेजा गया
- `recovering` — कम-से-कम एक recovery email भेजा गया
- `recovered` — Customer ने payment पूरा कर लिया
- `exhausted` — सभी email भेजे जा चुके हैं या नया checkout मिला है
- `opted_out` — Customer ने unsubscribe कर दिया
</ParamField>

<ParamField body="abandoned_at" type="string" required>
checkout को abandoned के रूप में detect किए जाने का ISO 8601 timestamp।
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
successful recovery payment का payment ID। checkout recover होने तक `null`।
</ParamField>

### उदाहरण: ACR Webhooks को संभालना

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Dunning Events

निम्नलिखित webhook events subscription dunning lifecycle को track करते हैं:

| Event | Description |
|-------|-------------|
| `dunning.started` | ऐसी subscription के लिए dunning attempt बनाया गया है जो `on_hold` में चली गई या customer द्वारा cancel कर दी गई। |
| `dunning.recovered` | Customer ने अपना payment method update किया और इसके परिणामस्वरूप payment सफल हुआ। `payment_id` field में successful payment ID होता है। |

### Dunning Attempt Payload Fields

<ParamField body="subscription_id" type="string" required>
वह subscription जिसने dunning attempt को trigger किया।
</ParamField>

<ParamField body="brand_id" type="string" required>
वह brand जिससे यह dunning attempt संबंधित है।
</ParamField>

<ParamField body="customer_id" type="string" required>
वह customer जिसके पास subscription है।
</ParamField>

<ParamField body="trigger_state" type="string" required>
डनिंग को ट्रिगर करने वाली subscription state। इनमें से एक:
- `on_hold` — payment failure के कारण renewals रोक दिए गए
- `cancelled` — Customer Portal से customer ने रद्द किया
</ParamField>

<ParamField body="status" type="string" required>
इस dunning attempt की वर्तमान lifecycle state। इनमें से एक:
- `recovering` — Dunning email भेजे जा रहे हैं
- `recovered` — Customer ने payment method update किया और payment सफल हुआ
- `exhausted` — सभी email भेजे जा चुके हैं या subscription state बदल गई है
</ParamField>

<ParamField body="created_at" type="string" required>
dunning attempt बनाए जाने का ISO 8601 timestamp।
</ParamField>

<ParamField body="payment_id" type="string | null">
successful recovery payment का payment ID। recovery के दौरान `null`।
</ParamField>

### उदाहरण: Dunning Webhooks को संभालना

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
पूरे dunning lifecycle को track करने के लिए `dunning.started` और `dunning.recovered` दोनों को subscribe करें। अपने system में grace periods को pause करने या at-risk subscriptions को flag करने के लिए `dunning.started` का उपयोग करें।
</Tip>
