## Meter बनाना

Meters यह निर्धारित करते हैं कि billing के लिए आपके usage events को कैसे aggregate और measure किया जाता है।

Meter बनाने से पहले अपनी usage tracking strategy की योजना बनाएं:
- तय करें कि आप किन usage events को ट्रैक करना चाहते हैं
- निर्धारित करें कि events को कैसे aggregate किया जाना चाहिए (count, sum आदि)
- विशिष्ट use cases के लिए आवश्यक filtering तय करें

### Meter बनाने की चरण-दर-चरण प्रक्रिया

अपना usage meter सेट अप करने के लिए इस विस्तृत गाइड का पालन करें:

<Steps>
<Step title="Configure Basic Information">
अपने meter की मूलभूत जानकारी सेट अप करें।

<ParamField path="Meter Name" type="string" required>
ऐसा स्पष्ट और वर्णनात्मक नाम चुनें जिससे पता चले कि यह meter क्या ट्रैक करता है।

उदाहरण: "Tokens", "API Calls", "Storage Usage", "Compute Hours"
</ParamField>

<ParamField path="Description" type="string">
यह meter क्या measure करता है, इसका विस्तृत विवरण दें।

उदाहरण: "ग्राहक द्वारा की गई प्रत्येक POST /v1/orders request को गिनता है"
</ParamField>

<ParamField path="Event Name" type="string" required>
वह event identifier निर्दिष्ट करें जो इस meter को trigger करेगा।

उदाहरण: "token", "api.call", "storage.usage", "compute.session"
</ParamField>

<Info>
Event name आपके usage events में भेजे गए नाम से बिल्कुल मेल खाना चाहिए। Event names case-sensitive होते हैं।
</Info>
</Step>

<Step title="Configure Aggregation Settings">
निर्धारित करें कि meter आपके events से usage की गणना कैसे करेगा।

<ParamField path="Aggregation Type" type="string" required>
चुनें कि events को कैसे aggregate किया जाना चाहिए:

<Tabs>
<Tab title="Count">
प्राप्त events की संख्या को सरलता से गिनता है।

Use case: API calls, page views, file uploads

Calculation: events की कुल संख्या
</Tab>

<Tab title="Sum">
आपके events की किसी विशिष्ट property की values को जोड़ता है।

Use case: Data transfer, storage consumption, processing time

Calculation: सभी property values का योग
</Tab>

<Tab title="Max">
Billing period के दौरान किसी विशिष्ट property की सबसे अधिक value रिकॉर्ड करता है।

Use case: Peak concurrent users, maximum storage used, highest bandwidth

Calculation: देखी गई अधिकतम property value
</Tab>

<Tab title="Last">
किसी विशिष्ट property की सबसे हाल की value का उपयोग करता है।

Use case: Current plan tier, latest configuration setting

Calculation: अंतिम रिकॉर्ड की गई property value
</Tab>
</Tabs>
</ParamField>

<ParamField path="Over Property" type="string">
Event metadata से वह property name जिस पर aggregation की जाएगी।

<Warning>
Sum, Max या Last aggregation types का उपयोग करते समय यह field आवश्यक है।
</Warning>
</ParamField>

<ParamField path="Measurement Unit" type="string" required>
Reports और billing में display के लिए unit label निर्धारित करें।

उदाहरण: "calls", "GB", "hours", "tokens"
</ParamField>
</Step>

<Step title="Configure Event Filtering (Optional)">
यह नियंत्रित करने के लिए criteria सेट अप करें कि meter में कौन से events शामिल किए जाएं।

<Info>
Event filtering से आप ऐसे उन्नत rules बना सकते हैं जो तय करते हैं कि आपके usage calculations में कौन से events योगदान देंगे। यह test events को हटाने, user tiers के आधार पर filtering करने या विशिष्ट actions पर ध्यान केंद्रित करने के लिए उपयोगी है।
</Info>

**Enable Event Filtering**

Conditional event processing सक्रिय करने के लिए **Enable Event Filtering** को toggle करें।

**Filter Logic चुनें**

चुनें कि multiple conditions का मूल्यांकन कैसे किया जाएगा:

<Tabs>
<Tab title="AND Logic">
किसी event को count करने के लिए सभी conditions true होनी चाहिए। इसका उपयोग तब करें जब events को एक साथ कई सख्त criteria पूरे करने हों।

**उदाहरण:** उन API calls को गिनें जहां `user_tier = "premium"` AND `endpoint = "/api/v2/users"`
</Tab>

<Tab title="OR Logic">
किसी event को count करने के लिए कम से कम एक condition true होनी चाहिए। इसका उपयोग तब करें जब आप कई criteria में से किसी एक को पूरा करने वाले events शामिल करना चाहते हों।

**उदाहरण:** उन events को गिनें जहां `method = "POST"` OR `method = "PUT"` OR `method = "DELETE"`
</Tab>
</Tabs>

**Filter Conditions सेट अप करना**

<Steps>
<Step title="Add Condition">
नया filter rule बनाने के लिए **Add condition** पर क्लिक करें।
</Step>

<Step title="Configure Property Key">
अपने event metadata से property name निर्दिष्ट करें।
</Step>

<Step title="Select Comparator">
उपलब्ध operators में से चुनें:
- `equals` - सटीक मिलान
- `not_equals` - Exclusion filter
- `greater_than` - Numeric comparison  
- `greater_than_or_equals` - Numeric comparison (inclusive)
- `less_than` - Numeric comparison
- `less_than_or_equals` - Numeric comparison (inclusive)
- `contains` - String में substring शामिल है
- `does_not_contain` - String exclusion filter
</Step>

<Step title="Set Comparison Value">
Comparison के लिए target value सेट करें।
</Step>

<Step title="Add Groups">
Complex logic के लिए अतिरिक्त condition groups बनाने हेतु **Add Group** का उपयोग करें।
</Step>
</Steps>

<Warning>
Conditions के ठीक से काम करने के लिए filtered properties आपके event metadata में शामिल होनी चाहिए। आवश्यक properties के बिना events को counting से बाहर रखा जाएगा।
</Warning>
</Step>

<Step title="Create Meter">
अपने meter configuration की समीक्षा करें और **Create Meter** पर क्लिक करें।

<Check>
आपका meter अब usage events प्राप्त और aggregate करने के लिए तैयार है।
</Check>

</Step>
</Steps>

## Product में Meter लिंक करना

Meter बनाने के बाद Usage-Based Billing सक्षम करने के लिए उसे किसी product से link करना आवश्यक है। यह प्रक्रिया आपके meter के usage data को customer billing के लिए pricing rules से जोड़ती है।

Meters को products से link करने पर usage tracking और billing के बीच connection स्थापित होता है:
- Products pricing rules और billing behavior निर्धारित करते हैं
- Meters billing calculations के लिए usage data प्रदान करते हैं
- Complex billing scenarios के लिए एक product से multiple meters link किए जा सकते हैं

### Product Configuration प्रक्रिया

अपने product settings को सही तरीके से configure करके usage data को billable charges में बदलें:

<Steps>
<Step title="Choose Usage-Based Billing Product Type">
अपने product creation या editing page पर जाएं और product type के रूप में **Usage-Based** चुनें।

</Step>

<Step title="Select Associated Meter">
Side panel से meter selection panel खोलने के लिए **Associated Meter** पर क्लिक करें।

यह panel आपको configure करने देता है कि इस product के लिए usage को कौन से meters track करेंगे।
</Step>

<Step title="Add Your Meter">
Meter selection panel में:

1. उपलब्ध meters देखने के लिए **Add Meters** पर क्लिक करें
2. Dropdown list से आपके द्वारा बनाया गया meter चुनें
3. चुना गया meter आपके product configuration में दिखाई देगा

</Step>

<Step title="Configure Price Per Unit">
अपने meter द्वारा track की गई usage की प्रत्येक unit के लिए pricing सेट करें।

<ParamField path="Price Per Unit" type="number" required>
अपने meter द्वारा measure की गई प्रत्येक unit के लिए charge निर्धारित करें।

**उदाहरण**: प्रति unit `$0.50` सेट करने का अर्थ है:
- 1,000 units consumed = 1,000 × $0.50 = 500.00 charged
- 500 units consumed = 500 × $0.50 = 250.00 charged
- 100 units consumed = 100 × $0.50 = 50.00 charged
</ParamField>

</Step>

<Step title="Set Free Threshold (Optional)">
Billing शुरू होने से पहले free usage allowance configure करें।

<ParamField path="Free Threshold" type="number">
Paid usage calculation शुरू होने से पहले customer द्वारा बिना charge consume की जा सकने वाली units की संख्या।

**यह कैसे काम करता है**:
- Free threshold: 100 units
- Price per unit: $0.50
- Customer usage: 250 units
- **Calculation**: (250 - 100) × $0.50 = **$75.00** charged
</ParamField>

<Info>
Free thresholds freemium models, trial periods या customer के plan में शामिल base allowance देने के लिए आदर्श हैं।
</Info>

<Check>
Free threshold प्रत्येक billing cycle पर लागू होता है, जिससे customers को हर महीने या आपके billing schedule के अनुसार नया allowance मिलता है।
</Check>
</Step>

<Step title="Save Configuration">
अपने meter और pricing configuration की समीक्षा करें, फिर setup पूरा करने के लिए **Save Changes** पर क्लिक करें।

<Check>
आपका product अब Usage-Based Billing के लिए configure है और measured consumption के आधार पर customers से अपने-आप charge करेगा।
</Check>

**इसके बाद क्या होगा**:
- आपके meter को भेजे गए usage events track और aggregate किए जाएंगे
- Billing calculations आपकी pricing rules को automatically लागू करेंगी
- प्रत्येक billing cycle के दौरान actual consumption के आधार पर customers से charge लिया जाएगा
</Step>
</Steps>

<Note>
ध्यान रखें कि आप प्रत्येक product में अधिकतम 10 meters जोड़ सकते हैं। इससे API calls, storage, compute time और custom metrics जैसे कई dimensions में उन्नत usage tracking संभव होती है।
</Note>

## Usage Events भेजना

Meter configure होने के बाद customer usage track करने के लिए आप अपने application से usage events भेजना शुरू कर सकते हैं।

### Event Structure

प्रत्येक usage event में ये required fields शामिल होने चाहिए:

<ParamField body="event_id" type="string" required>
इस specific event के लिए unique identifier। यह सभी events में unique होना चाहिए।
</ParamField>

<ParamField body="customer_id" type="string" required>
यह वह Dodo Payments customer ID है जिससे इस usage को attribute किया जाना चाहिए।
</ParamField>

<ParamField body="event_name" type="string" required>
वह event name जो आपके meter configuration से match करता है। Event names उपयुक्त meter को trigger करते हैं।
</ParamField>

<ParamField body="timestamp" type="string">
घटना के घटित होने का ISO 8601 timestamp। यदि प्रदान नहीं किया गया है, तो यह वर्तमान UTC timestamp पर डिफ़ॉल्ट होता है। यह 1 घंटे अतीत और 5 मिनट भविष्य की सीमा के भीतर होना चाहिए — इस सीमा से बाहर के timestamps अस्वीकार कर दिए जाते हैं।
</ParamField>

<ParamField body="metadata" type="object">
Filtering और aggregation के लिए additional properties। अपने meter की "Over Property" या filtering conditions में referenced values शामिल करें।
</ParamField>

### विश्वसनीय Ingestion के लिए जानने योग्य मुख्य बातें

Production में usage tracking को सटीक और resilient बनाए रखने के लिए इन practices का पालन करें।

<Tip>
**Deterministic, idempotent `event_id`s का उपयोग करें।** `event_id` सभी events में unique होना चाहिए और idempotency key के रूप में काम करता है — दोबारा उपयोग किए गए `event_id` को duplicate माना जाता है और दोबारा count नहीं किया जाता, इसलिए retries से double-billing नहीं होती। ID को random value के बजाय action से derive करें, जैसे `` `${customer_id}_${action}_${timestamp}` ``।
</Tip>

<Tip>
**प्रति request अधिकतम 1,000 events का batch भेजें।** `/events/ingest` endpoint प्रति call अधिकतम **1,000 events** की सीमा लागू करता है; इससे बड़े batches reject हो जाते हैं, इसलिए high volumes को multiple calls में विभाजित करें। High-volume workloads के लिए, प्रत्येक event के लिए एक request भेजने के बजाय events को buffer करके batches में flush करें।
</Tip>

<Warning>
**`5xx` और `429` पर retry करें, `4xx` पर कभी नहीं।** Server errors (`5xx`) और rate limits (`429`) पर exponential backoff के साथ retry करें। **`400`/`422` validation errors पर retry न करें** — payload malformed है और हर बार fail होगा; इसे ठीक करके फिर से भेजें। Retries के बाद भी fail होने वाले events को queue में रखें ताकि कोई event खो न जाए।
</Warning>

<Info>
**Timestamps को सोच-समझकर सेट करें।** रीयल-टाइम events के लिए `timestamp` को छोड़ दें; यह वर्तमान UTC timestamp पर डिफ़ॉल्ट हो जाएगा। विलंबित या बैच किए गए events के लिए इसे स्पष्ट रूप से (ISO 8601) सेट करें, ताकि usage सही billing period में दर्ज हो, लेकिन ध्यान दें कि स्वीकृत विंडो संकीर्ण है: **1 घंटे से अधिक पुराने** या **5 मिनट से अधिक भविष्य के** timestamp वाले events अस्वीकार कर दिए जाते हैं। Historical backfill समर्थित नहीं है — buffered events को एक घंटे के भीतर flush करें।
</Info>

<Warning>
**Aggregated metadata को strings के बजाय numbers के रूप में भेजें।** Meter के **Over Property** (Sum, Max, Last) द्वारा referenced कोई भी property numeric type की होनी चाहिए — `{ "tokens": 150 }`, न कि `{ "tokens": "150" }`। String values aggregate नहीं होंगी।
</Warning>

## Usage-Based Billing Analytics

Comprehensive analytics dashboard के साथ अपने usage-based billing data को monitor और analyze करें। Pricing strategy को optimize करने और usage behaviors को समझने के लिए customer consumption patterns, meter performance और billing trends track करें।

### Overview Analytics

Overview tab आपके usage-based billing performance का व्यापक view प्रदान करता है:

#### Activity Metrics

अलग-अलग time periods में usage के प्रमुख statistics track करें:

<ParamField path="Current Month" type="metric">
यह current billing period की usage activity दिखाता है और monthly consumption patterns समझने में सहायता करता है।
</ParamField>

<ParamField path="All Time" type="metric">
यह tracking शुरू करने के बाद से cumulative usage statistics दिखाता है और long-term growth insights प्रदान करता है।
</ParamField>

<Tip>
अलग-अलग months में usage की तुलना करने और seasonal trends या growth patterns पहचानने के लिए time period selector का उपयोग करें।
</Tip>

### Event Filtering Examples

<Tabs>
<Tab title="Filter by API Endpoint">
केवल specific endpoints पर किए गए API calls को count करें:

Filter Configuration:
- Property: `endpoint`
- Comparator: `equals`
- Value: `/v1/orders`

Sample Event:

```json
{
  "event_id": "call_1",
  "customer_id": "cus_123",
  "event_name": "api.call",
  "metadata": {
    "endpoint": "/v1/orders",
    "method": "POST"
  }
}
```

Result: Filter criteria से match करने वाले events count किए जाएंगे। अलग endpoints वाले events ignore किए जाएंगे।
</Tab>

<Tab title="Filter by Value Range">
केवल बड़ी file uploads को count करें:

Filter Configuration:
- Property: `file_size`
- Comparator: `greater_than`
- Value: `1048576` (bytes में 1MB)

Sample Event:

```json
{
  "event_id": "upload_1",
  "customer_id": "cus_123", 
  "event_name": "file.upload",
  "metadata": {
    "file_size": 5242880,
    "file_type": "image"
  }
}
```

Result: 1MB से बड़ी files count की जाएंगी। छोटी files ignore की जाएंगी।
</Tab>

<Tab title="Complex Multi-Condition Filters">
Business hours के दौरान premium API calls count करें:

Filter Configuration (AND logic का उपयोग करके):
- Property: `plan_type`, Comparator: `equals`, Value: `premium`
- Property: `hour`, Comparator: `greater_than_or_equals`, Value: `9`
- Property: `hour`, Comparator: `less_than`, Value: `17`

Sample Event:

```json
{
  "event_id": "call_1",
  "customer_id": "cus_123",
  "event_name": "api.call",
  "metadata": {
    "plan_type": "premium",
    "hour": 14,
    "endpoint": "/v1/analytics"
  }
}
```

Result: Business hours (9 AM - 5 PM) के दौरान किए गए premium API calls count किए जाएंगे।
</Tab>
</Tabs>

## Troubleshooting

Usage-based billing implementation की common समस्याओं को हल करें और accurate tracking तथा billing सुनिश्चित करें।

### Common Issues

अधिकांश usage-based billing समस्याएं इन categories में आती हैं:
- Event delivery और processing issues
- Meter configuration problems
- Data type और formatting errors
- Customer ID और authentication issues

### Debugging Steps

Usage-based billing की troubleshooting करते समय:
1. Events analytics tab में event delivery verify करें
2. Check करें कि meter configuration आपके event structure से match करती है
3. Customer IDs और API authentication validate करें
4. Filtering conditions और aggregation settings review करें

### Solutions and Fixes

<AccordionGroup>
<Accordion title="Events not showing in meter">
Common causes:
- Event name meter configuration से exactly match नहीं करता
- Event filtering conditions आपके events को exclude कर रही हैं
- Customer ID आपके Dodo Payments account में मौजूद नहीं है
- Event timestamp current billing period से बाहर है

Solutions:
- Event name की spelling और case sensitivity verify करें
- अपनी filtering conditions review और test करें
- Confirm करें कि customer ID valid और active है
- Check करें कि event timestamps recent और properly formatted हैं
</Accordion>

<Accordion title="Aggregation not working as expected">
Common causes:
- Over Property name event metadata keys से match नहीं करता
- Metadata values का data type गलत है (string vs number)
- Required metadata properties missing हैं

Solutions:
- सुनिश्चित करें कि metadata keys आपकी Over Property setting से exactly match करती हैं
- अपने events में string numbers को actual numbers में convert करें
- प्रत्येक event में सभी required properties शामिल करें
</Accordion>

<Accordion title="Filtering not working">
Common causes:
- Filter property names event metadata से match नहीं करते
- Data type के लिए गलत comparator है (string vs number)
- String comparisons में case sensitivity

Solutions:
- दोबारा जांचें कि property names exactly match करते हैं
- अपने data types के लिए appropriate comparators का उपयोग करें
- Strings filter करते समय case sensitivity पर ध्यान दें
</Accordion>
</AccordionGroup>
