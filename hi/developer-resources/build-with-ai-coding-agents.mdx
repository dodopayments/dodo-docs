Dodo Agent Plugin एक ही इंस्टॉल में दो MCP servers और सत्रह integration skills को आपके AI coding agent से जोड़ता है। यह **Claude Code**, **Codex CLI**, **Cursor**, और **OpenCode** के साथ काम करता है — और MCP servers तथा skills CLI किसी भी MCP-compatible client के साथ काम करते हैं।

<Info>
**तीन primitives, एक plugin।** Agent Plugin में आपकी ज़रूरत की सभी चीज़ें शामिल हैं:
- **API MCP server** — payments, subscriptions, customers, products, refunds, licenses और usage का live access। browser OAuth के ज़रिए authenticate होता है (local keys की ज़रूरत नहीं)।
- **Knowledge MCP server** — सभी Dodo Payments documentation में semantic search। credentials की ज़रूरत नहीं।
- **सत्रह agent skills** — cheat sheets जिन्हें आपका agent checkout, subscriptions, webhooks, usage-based और credit-based billing, license keys, product catalog, discounts, localized pricing, mobile checkout, refunds और disputes, customer management, framework adapters, BillingSDK, Better Auth, testing और go-live, तथा best practices के लिए आवश्यकता के अनुसार load करता है।
</Info>

## Plugin install करें

नीचे अपना coding agent चुनें। इंस्टॉल करने पर दोनों MCP servers और सभी सत्रह skills अपने-आप जुड़ जाते हैं।

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Marketplace से install करें:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP server डिफ़ॉल्ट रूप से browser OAuth का उपयोग करता है — install के समय keys की आवश्यकता नहीं होती। पहली बार जब आपका agent किसी Dodo tool को call करेगा, तो आपको sign in करने के लिए कहा जाएगा।

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Source code, configuration options और local development instructions
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex plugins को दो चरणों में install करता है: पहले अपने shell से marketplace register करें, फिर Codex TUI के भीतर plugin install करें।

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Codex खोलें और `/plugins` slash command चलाएँ:

```bash
codex
```

फिर `/plugins` टाइप करें, **Dodo Payments** marketplace पर जाएँ, **dodopayments** plugin चुनें और **Install plugin** चुनें।
</Step>
</Steps>

Plugin इंस्टॉल होने के बाद दोनों MCP servers और सभी सत्रह skills अपने-आप register हो जाते हैं।

<Note>
Codex CLI में `codex plugin install` subcommand नहीं है — plugin installation हमेशा TUI के भीतर `/plugins` flow के माध्यम से होता है। [आधिकारिक Codex plugins docs](https://developers.openai.com/codex/plugins) देखें।
</Note>

यदि आपने पहले marketplace और plugin जोड़ा है, लेकिन वह `/plugins` के अंतर्गत दिखाई नहीं देता, तो उसे refresh करें:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Manual install — repo को Cursor की local plugins directory में clone करें:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Cursor को restart करें। Plugin `.claude/skills/` से skills load करता है (Cursor की Claude Code compatibility layer के माध्यम से) और `.mcp.json` से MCP servers load करता है।

<Info>
Cursor marketplace support जल्द उपलब्ध होगा। तब तक ऊपर दिए गए manual install का उपयोग करें।
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode npm के माध्यम से वितरित होता है। Plugin को अपने `opencode.json` में जोड़ें:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

OpenCode को restart करें। दोनों MCP servers (`dodopayments-api`, `dodo-knowledge`) plugin के config hook के ज़रिए अपने-आप register हो जाते हैं, और सत्रह skills इंस्टॉल किए गए package से auto-discover हो जाती हैं। किसी manual `mcp` block की आवश्यकता नहीं है।
</Accordion>
</AccordionGroup>

<Info>
किसी अलग agent का उपयोग कर रहे हैं? [MCP Server](/developer-resources/mcp-server) और [Agent Skills](/developer-resources/agent-skills) guides में Cursor, Claude Desktop, VS Code, Windsurf, Cline, Zed और किसी भी MCP-compatible client की जानकारी दी गई है।
</Info>

## आपको क्या मिलता है

Plugin इंस्टॉल हो जाने के बाद आपके agent को दो MCP servers और सत्रह skills का access मिल जाता है।

### MCP servers

| Server | Purpose | Auth |
|--------|---------|------|
| `dodopayments-api` | Live API access — payments, subscriptions, customers, products, refunds, licenses, usage | OAuth (browser) |
| `dodo-knowledge` | सभी Dodo Payments documentation में semantic search | None |

दोनों servers को `mcp-remote` के माध्यम से जोड़ा गया है, इसलिए वे किसी भी MCP-compatible client में चलते हैं।

### Agent skills

| Skill | Description |
|-------|-------------|
| `best-practices` | SDK setup, environments, API keys और canonical checkout-to-webhook architecture |
| `framework-adapters` | Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun और Convex के लिए आधिकारिक `@dodopayments/*` route handlers |
| `testing-and-go-live` | Test mode, test payment methods, webhook testing और production launch checklist |
| `checkout-integration` | Checkout Sessions, payment links और overlay या inline checkout |
| `subscription-integration` | Subscription lifecycle, trials, plan changes, proration और on-demand charges |
| `mobile-checkout` | React Native, Flutter, iOS और Android के लिए in-app checkout |
| `webhook-integration` | Standard Webhooks specification का उपयोग करके webhooks प्राप्त करना और verify करना |
| `credit-based-billing` | Credit entitlements, balances, ledger, rollover, overage और meter-based deduction |
| `usage-based-billing` | Meters, event ingestion, aggregation और per-unit pricing |
| `license-keys` | License key activation, validation और instance management |
| `product-catalog-management` | Products, pricing, add-ons, collections, images और digital product delivery |
| `discounts-and-promotions` | Discount codes, eligibility rules, stacking और subscription-cycle limits |
| `localized-pricing` | Localized pricing, Adaptive Currency और purchasing power parity |
| `customer-management` | Customers, self-service portal, saved payment methods और wallets |
| `refunds-and-disputes` | Refunds जारी करना, disputes और chargebacks संभालना, तथा access का reconciliation |
| `billing-sdk` | Pricing tables और billing UI के लिए BillingSDK React components |
| `better-auth-integration` | Customer sync, checkout और portal access के लिए `@dodopayments/better-auth` plugin |

Skills अपने-आप load होती हैं — relevant task का पता चलने पर आपका agent सही skill चुन लेता है। पूरी सूची और individual installation के लिए [Agent Skills documentation](/developer-resources/agent-skills) देखें।

### पहले यह prompt आज़माएँ

Plugin active होने के बाद यह prompt आज़माएँ:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

आपका agent `webhook-integration` skill load करेगा, नवीनतम payload shapes प्राप्त करने के लिए `dodo-knowledge` MCP का उपयोग करेगा और Standard Webhooks spec के अनुसार signature verification वाला handler लिखेगा।

## Security और best practices

<Warning>
**Production API keys को कभी commit न करें।** Development के दौरान [test mode](/miscellaneous/test-mode-vs-live-mode) का उपयोग करें। Agent Plugin डिफ़ॉल्ट रूप से browser OAuth का उपयोग करता है — local API keys पर तभी switch करें जब आपके workflow में इसकी आवश्यकता हो।
</Warning>

- **पहले test mode का उपयोग करें।** Live होने से पहले `dodo_test_...` keys के साथ अपने integration को sandbox करें। [Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode) देखें।
- **OAuth डिफ़ॉल्ट है।** Agent Plugin browser OAuth के माध्यम से authenticate करता है (local secrets नहीं)। API-key mode का उपयोग केवल आवश्यकता होने पर करें — नीचे Configure section देखें।
- **Agent-generated code की समीक्षा करें।** हमेशा सुनिश्चित करें कि webhook handlers में [Standard Webhooks spec](https://standardwebhooks.com/) के अनुसार signature verification शामिल हो।

## API key के साथ Configure करें

डिफ़ॉल्ट रूप से Agent Plugin browser OAuth के साथ remote MCP server का उपयोग करता है — local credentials की आवश्यकता नहीं होती। यदि आपके workflow में local API key की आवश्यकता है (जैसे CI environments या headless servers), तो आप stdio mode पर switch कर सकते हैं।

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Claude Code में `/plugins` खोलें, **Dodo Payments** चुनें और **Configure options** चुनें। ये भरें:

- `dodo_api_key` — आपकी `dodo_test_...` या `dodo_live_...` key
- `dodo_webhook_key` — आपका webhook signing secret
- `dodo_environment` — `test_mode` या `live_mode`

फिर `.mcp.json` को edit करके `dodopayments-api` को local stdio server पर point करें:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

अपने current session में changes लागू करने के लिए `/reload-plugins` चलाएँ।
</Accordion>

<Accordion title="Local API key mode — OpenCode">
`dodopayments-api` को अपने `opencode.json` में स्वयं declare करें — आपकी entry plugin के default remote server पर प्राथमिकता पाएगी:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

लागू करने के लिए OpenCode को restart करें।
</Accordion>
</AccordionGroup>
