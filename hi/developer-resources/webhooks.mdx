Webhooks आपके Dodo Payments account में विशिष्ट घटनाएँ होने पर रीयल-टाइम सूचनाएँ प्रदान करते हैं। वर्कफ़्लो को स्वचालित करने, अपने database को अपडेट करने, सूचनाएँ भेजने और अपने सिस्टम को synchronized रखने के लिए webhooks का उपयोग करें।

<Info>
हमारा webhook implementation [Standard Webhooks](https://standardwebhooks.com/) specification का पालन करता है, जिससे industry best practices और मौजूदा webhook libraries के साथ compatibility सुनिश्चित होती है।
</Info>

    <Tip>
    केवल चुने गए events आपके endpoint पर webhooks trigger करेंगे, जिससे अनावश्यक traffic और processing से बचने में सहायता मिलेगी।
    </Tip>
</Step>

<Step title="Get Secret Key">
    settings page से अपना webhook `Secret Key` प्राप्त करें। प्राप्त webhooks की authenticity verify करने के लिए इसका उपयोग करेंगे।
    
    <Warning>
    अपनी webhook secret key को सुरक्षित रखें और इसे client-side code या public repositories में कभी expose न करें।
    </Warning>
</Step>

<Step title="Rotate Secret (Optional)">
    आवश्यकता होने पर enhanced security के लिए अपनी webhook secret rotate कर सकते हैं। अपनी webhook settings में **Rotate Secret** button पर क्लिक करें।
    
    <Warning>
    Secret rotate करने पर वह **expire** हो जाएगी और नई secret से **replace** हो जाएगी। पुरानी secret केवल अगले 24 घंटों तक valid रहेगी। इसके बाद पुरानी secret से verify करने का प्रयास fail हो जाएगा।
    </Warning>
    
    <Info>
    Secret rotation का समय-समय पर उपयोग करें या तुरंत करें यदि आपको संदेह है कि आपकी वर्तमान secret compromise हो गई है।
    </Info>
</Step>
</Steps>

<Steps>

</Step>

<Step title="Search and Filter">
    event names या keywords टाइप करके विशिष्ट events को जल्दी खोजने के लिए search bar का उपयोग करें।

    - सभी संबंधित sub-events प्राप्त करने के लिए parent events चुन सकते हैं
    - अपनी आवश्यकताओं के आधार पर विशिष्ट events का संयोजन कर सकते हैं

</Step>

</Step>
</Steps>

</Warning>

## Webhook Delivery

### Timeouts

Webhooks में connection और read operations दोनों के लिए **15-second timeout window** होती है। Timeouts से बचने के लिए सुनिश्चित करें कि आपका endpoint तुरंत response दे।

<Tip>
Webhooks को asynchronously process करें: पहले `200` status code के साथ receipt को तुरंत acknowledge करें, फिर actual processing को background में handle करें।
</Tip>

### Automatic Retries

यदि webhook delivery fail होती है, तो Dodo Payments आपके system को overload होने से बचाने के लिए exponential backoff के साथ automatically retry करता है।

| प्रयास | विलंब | विवरण |
|---------|------------------------------|-------------|
| 1 | तुरंत | पहला retry तुरंत होता है |
| 2 | 5 सेकंड | थोड़े विलंब के बाद दूसरा प्रयास |
| 3 | 5 मिनट | बढ़े हुए backoff के साथ तीसरा प्रयास |
| 4 | 30 मिनट | backoff जारी रखते हुए चौथा प्रयास |
| 5 | 2 घंटे | बढ़े हुए विलंब के साथ पाँचवाँ प्रयास |
| 6 | 5 घंटे | अधिक लंबे विलंब के साथ छठा प्रयास |
| 7 | 10 घंटे | अधिकतम विलंब के साथ सातवाँ प्रयास |
| 8 | 10 घंटे | **अंतिम प्रयास** - असफल होने पर webhook को failed mark किया जाता है |

<Info>
प्रत्येक webhook event के लिए **अधिकतम 8 retry attempts**। उदाहरण के लिए, यदि सफल होने से पहले webhook तीन बार fail होता है, तो पहले प्रयास से कुल delivery time लगभग 35 मिनट और 5 सेकंड होता है।
</Info>

<Tip>
किसी भी समय अलग-अलग messages को manually retry करने या सभी failed messages को bulk में recover करने के लिए Dodo Payments dashboard का उपयोग करें।
</Tip>

### Idempotency

प्रत्येक webhook event में एक unique `webhook-id` header शामिल होता है। Idempotency लागू करने और duplicate processing रोकने के लिए इस identifier का उपयोग करें।

```javascript
// Example: Storing webhook IDs to prevent duplicate processing
const processedWebhooks = new Set();

app.post('/webhook', (req, res) => {
  const webhookId = req.headers['webhook-id'];
  
  if (processedWebhooks.has(webhookId)) {
    return res.status(200).json({ received: true });
  }
  
  processedWebhooks.add(webhookId);
  // Process the webhook...
});
```

<Warning>
हमेशा idempotency checks लागू करें। Retries के कारण आपको एक ही event कई बार प्राप्त हो सकता है।
</Warning>

### Event Ordering

Retries या network conditions के कारण webhook events क्रम से बाहर आ सकते हैं। अपने system को किसी भी sequence में events handle करने के लिए design करें।

<Info>
आपको delivery के समय का **latest payload** प्राप्त होगा, चाहे webhook event मूल रूप से कभी भी emit किया गया हो।
</Info>

## Webhooks सुरक्षित करना

अपने webhooks की security सुनिश्चित करने के लिए payloads को हमेशा validate करें और HTTPS का उपयोग करें।

### Signatures verify करना

प्रत्येक webhook request में एक `webhook-signature` header शामिल होता है, जो webhook payload और timestamp का HMAC SHA256 signature है और आपकी secret key से signed है।

#### SDK verification (recommended)

सभी official SDKs incoming webhooks को securely validate और parse करने के लिए built-in helpers शामिल करते हैं। दो methods उपलब्ध हैं:

* `unwrap()`: आपकी webhook secret key का उपयोग करके signatures verify करता है
* `unsafe_unwrap()`: verification के बिना payloads parse करता है

<Tip>
  Dodo Payments client को initialize करते समय अपनी webhook secret `DODO_PAYMENTS_WEBHOOK_KEY` के माध्यम से दें।
</Tip>

<CodeGroup>

```typescript TypeScript/Node.js
import DodoPayments from 'dodopayments';
import express from 'express';

const app = express();
app.use(express.raw({ type: 'application/json' }));

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
});

app.post('/webhook', async (req, res) => {
  try {
    const unwrapped = client.webhooks.unwrap(req.body.toString(), {
      headers: {
        'webhook-id': req.headers['webhook-id'] as string,
        'webhook-signature': req.headers['webhook-signature'] as string,
        'webhook-timestamp': req.headers['webhook-timestamp'] as string,
      },
    });
    res.json({ received: true });
  } catch (error) {
    res.status(401).json({ error: 'Invalid signature' });
  }
});
```

```python Python
from fastapi import FastAPI, Request, HTTPException
from dodopayments import DodoPayments
import os

app = FastAPI()
client = DodoPayments(
    bearer_token=os.getenv("DODO_PAYMENTS_API_KEY"),
    environment=os.getenv("DODO_PAYMENTS_ENVIRONMENT"),
    webhook_key=os.getenv("DODO_PAYMENTS_WEBHOOK_KEY"),
)

@app.post("/webhook")
async def handle_webhook(request: Request):
    try:
        unwrapped = client.webhooks.unwrap(
            await request.body(),
            headers={
                "webhook-id": request.headers.get("webhook-id", ""),
                "webhook-signature": request.headers.get("webhook-signature", ""),
                "webhook-timestamp": request.headers.get("webhook-timestamp", ""),
            },
        )
        return {"received": True}
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid signature")
```

```go Go
import (
	"context"
	"io"
	"net/http"
	"os"
	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func webhookHandler(w http.ResponseWriter, r *http.Request) {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
		option.WithEnvironment(os.Getenv("DODO_PAYMENTS_ENVIRONMENT")),
		option.WithWebhookKey(os.Getenv("DODO_PAYMENTS_WEBHOOK_KEY")),
	)
	rawBody, _ := io.ReadAll(r.Body)
	if _, err := client.Webhooks.Unwrap(context.Background(), rawBody, map[string]string{
		"webhook-id":       r.Header.Get("webhook-id"),
		"webhook-signature": r.Header.Get("webhook-signature"),
		"webhook-timestamp": r.Header.Get("webhook-timestamp"),
	}); err != nil {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}
	w.WriteHeader(http.StatusOK)
}
```

</CodeGroup>

#### Manual verification (alternative)

यदि आप SDK का उपयोग नहीं कर रहे हैं, तो Standard Webhooks spec का पालन करके signatures को स्वयं verify कर सकते हैं:

1. `webhook-id`, `webhook-timestamp` और exact raw stringified `payload` को periods (`.`) से अलग करके concatenate कर signed message बनाएँ।
2. Dashboard से प्राप्त अपनी webhook secret key का उपयोग करके उस string का HMAC SHA256 compute करें।
3. Computed signature की तुलना `webhook-signature` header से करें। यदि वे match करते हैं, तो webhook authentic है।

<Info>
  हम Standard Webhooks specification का पालन करते हैं। Signatures verify करने के लिए आप उनकी libraries का उपयोग कर सकते हैं: [https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries)। Event payload formats के लिए [Webhook Payload](/developer-resources/webhooks/intents/payment) देखें।
</Info>

### Webhooks का response देना

* आपका webhook handler event की receipt acknowledge करने के लिए `2xx status code` return करना चाहिए।
* किसी अन्य response को failure माना जाएगा और webhook retry किया जाएगा।

### सर्वोत्तम practices

<AccordionGroup>
<Accordion title="Use HTTPS endpoints only" icon="lock">
  Webhook endpoints के लिए हमेशा HTTPS URLs का उपयोग करें। HTTP endpoints man-in-the-middle attacks के प्रति vulnerable होते हैं और आपके webhook data को expose करते हैं।
</Accordion>

<Accordion title="Respond immediately" icon="bolt">
  Webhook प्राप्त होते ही तुरंत `200` status code return करें। Timeouts से बचने के लिए event को asynchronously process करें।
  

  ```javascript
  app.post('/webhook', async (req, res) => {
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process asynchronously
    processWebhookAsync(req.body).catch(console.error);
  });
  ```

</Accordion>

<Accordion title="Handle duplicate events" icon="rotate">
  `webhook-id` header का उपयोग करके idempotency लागू करें, ताकि एक ही event को side effects के बिना कई बार safely process किया जा सके।
</Accordion>

<Accordion title="Secure your webhook secret" icon="key">
  Environment variables या secrets manager का उपयोग करके अपनी webhook secret को securely store करें। Secrets को version control में कभी commit न करें।
</Accordion>
</AccordionGroup>

## Webhook Payload Structure

Webhook payload structure को समझने से आपको events को सही ढंग से parse और process करने में सहायता मिलती है।

### Request Format

```http
POST /your-webhook-url
Content-Type: application/json
```

### Headers

<ParamField header="webhook-id" type="string" required>
इस webhook event के लिए unique identifier। Idempotency checks के लिए इसका उपयोग करें।
</ParamField>

<ParamField header="webhook-signature" type="string" required>
Webhook authenticity verify करने के लिए HMAC SHA256 signature।
</ParamField>

<ParamField header="webhook-timestamp" type="string" required>
Webhook भेजे जाने का Unix timestamp (seconds में)।
</ParamField>

### Request Body

<ResponseField name="business_id" type="string" required>
आपका Dodo Payments business identifier।
</ResponseField>

<ResponseField name="type" type="string" required>
इस webhook को trigger करने वाला event type (जैसे, `payment.succeeded`, `subscription.active`)।
</ResponseField>

<ResponseField name="timestamp" type="string" required>
Event होने का ISO 8601 formatted timestamp।
</ResponseField>

<ResponseField name="data" type="object" required>
Event के बारे में detailed information वाला event-specific payload।

<Expandable title="Data object properties">
  <ResponseField name="payload_type" type="string">
  Resource का type। इनमें से एक: `Payment`, `Subscription`, `Refund`, `Dispute`, `LicenseKey`, `CreditLedgerEntry`, `CreditBalanceLow`, `AbandonedCheckout`, `DunningAttempt` या `EntitlementGrant`।
  </ResponseField>
  
  Additional fields event type के अनुसार अलग-अलग होते हैं। Complete schemas के लिए event-specific documentation देखें।
</Expandable>
</ResponseField>

### Example Payload

```json
{
  "business_id": "string",
  "type": "payment.succeeded | payment.failed |...",
  "timestamp": "2024-01-01T12:00:00Z",
  "data": {
    "payload_type": "Payment | Subscription | Refund | Dispute | LicenseKey | CreditLedgerEntry | CreditBalanceLow | AbandonedCheckout | DunningAttempt | EntitlementGrant",
    // ... event-specific fields (see below)
  }
}
```

### Implementation Example

यहाँ webhook verification और handling दिखाने वाला complete Express.js implementation है:

<CodeGroup>

```typescript Express.js Webhook Handler
import { Webhook } from "standardwebhooks";
import express from "express";

const app = express();
app.use(express.json());

const webhook = new Webhook(process.env.DODO_WEBHOOK_SECRET);

app.post('/webhook/dodo-payments', async (req, res) => {
  try {
    // Extract webhook headers
    const webhookHeaders = {
      "webhook-id": req.headers["webhook-id"] as string,
      "webhook-signature": req.headers["webhook-signature"] as string,
      "webhook-timestamp": req.headers["webhook-timestamp"] as string,
    };

    // Verify the webhook signature
    const payload = JSON.stringify(req.body);
    await webhook.verify(payload, webhookHeaders);
    
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process webhook asynchronously
    processWebhookAsync(req.body).catch(console.error);
    
  } catch (error) {
    console.error('Webhook verification failed:', error);
    res.status(400).json({ error: 'Invalid signature' });
  }
});

async function processWebhookAsync(data: any) {
  // Handle the webhook event based on type
  switch (data.type) {
    case 'payment.succeeded':
      await handlePaymentSucceeded(data);
      break;
    case 'subscription.active':
      await handleSubscriptionActive(data);
      break;
    // Add more event handlers...
  }
}
```

```javascript Testing Webhooks Locally
const { Webhook } = require("standardwebhooks");
const axios = require("axios");
const crypto = require("crypto");

// Generate test webhook
const timestamp = new Date();
const webhookId = crypto.randomUUID();
const payload = {
  business_id: "biz_test123",
  type: "payment.succeeded",
  timestamp: timestamp.toISOString(),
  data: {
    payload_type: "Payment",
    payment_id: "pay_test456",
    amount: 2999
  }
};

// Sign the payload
const webhookSecret = process.env.DODO_WEBHOOK_SECRET;
const webhookInstance = new Webhook(webhookSecret);
const payloadString = JSON.stringify(payload);
const signature = webhookInstance.sign(webhookId, timestamp, payloadString);

// Send test webhook
const response = await axios.post('http://localhost:3000/webhook/dodo-payments', payload, {
  headers: {
    "webhook-id": webhookId,
    "webhook-timestamp": Math.floor(timestamp.getTime() / 1000),
    "webhook-signature": signature,
    "Content-Type": "application/json"
  }
});

console.log("Test webhook sent successfully:", response.data);
```

## CLI के साथ Webhooks का परीक्षण

[Dodo Payments CLI](/developer-resources/sdks/cli) local development के दौरान terminal छोड़े बिना webhooks test करने के लिए दो commands प्रदान करता है।

### Locally Live Webhooks सुनना

अपने test mode account से local development server पर real webhook events को real time में forward करें:

```bash
dodo wh listen
```

CLI Dodo Payments से WebSocket connection खोलता है और प्रत्येक webhook event को आपके local endpoint (जैसे, `http://localhost:3000/webhook`) पर forward करता है। यह verification testing के लिए signature headers सहित सभी headers को preserve करता है।

<Info>
Listener केवल **test mode** API keys के साथ काम करता है। इस command का उपयोग करने से पहले `dodo login` चलाएँ और Test Mode चुनें।
</Info>

### Mock Webhook Events Trigger करना

Real transactions create किए बिना किसी भी endpoint पर mock webhook payloads भेजें:

```bash
dodo wh trigger
```

यह interactive tool आपको सभी supported event types में से चुनने और realistic mock payloads अपने endpoint पर भेजने देता है। यह loop करता है, इसलिए आप एक session में कई events का परीक्षण कर सकते हैं।

<Warning>
`dodo wh trigger` से प्राप्त mock webhook payloads signed नहीं होते। केवल testing के दौरान अपने webhook handler में `unwrap()` के बजाय `unsafe_unwrap()` का उपयोग करें।
</Warning>

## Advanced Settings

Advanced Settings tab आपके webhook endpoint के behavior को fine-tune करने के लिए additional configuration options प्रदान करता है।

### Rate Limiting (Throttling)

अपने system को overload होने से बचाने के लिए webhook events की आपके endpoint पर delivery rate नियंत्रित करें।

<Steps>
<Step title="Access Rate Limit Settings">
    **Advanced** tab में "Rate Limit (throttling)" section खोजें।
</Step>

<Step title="Configure Rate Limit">
    Rate limit settings modify करने के लिए **Edit** button पर क्लिक करें।
    
    <Info>
    Default रूप से webhooks पर "No rate limit" लागू होता है, जिसका अर्थ है कि events होने के तुरंत बाद deliver किए जाते हैं।
    </Info>
</Step>

<Step title="Set Limits">
    Webhook delivery frequency नियंत्रित करने और system overload रोकने के लिए इच्छित rate limit configure करें।
</Step>
</Steps>

<Tip>
Rate limiting का उपयोग तब करें जब आपके webhook handler को events process करने के लिए समय चाहिए या जब आप कई events को एक साथ batch करना चाहते हैं।
</Tip>

### Custom Headers

अपने endpoint पर भेजे गए सभी webhook requests में custom HTTP headers जोड़ें। यह authentication, routing या webhook requests में metadata जोड़ने के लिए उपयोगी है।

<Steps>
<Step title="Add Custom Header">
    "Custom Headers" section में अपने custom header के लिए **Key** और **Value** दर्ज करें।
</Step>

<Step title="Add Multiple Headers">
    आवश्यकता के अनुसार additional custom headers जोड़ने के लिए **+** button पर क्लिक करें।
</Step>

<Step title="Save Configuration">
    आपके custom headers इस endpoint पर भेजे जाने वाले सभी webhook requests में शामिल किए जाएँगे।
</Step>
</Steps>

### Transformations

Transformations आपको webhook के payload को modify करके किसी अलग URL पर redirect करने देती हैं। यह powerful feature आपको सक्षम बनाता है:

- Processing से पहले payload structure modify करना
- Content के आधार पर webhooks को अलग-अलग endpoints पर route करना
- Payload से fields add या remove करना
- Data formats transform करना

<Steps>
<Step title="Enable Transformations">
    Transformation feature activate करने के लिए **Enabled** switch को toggle करें।
</Step>

<Step title="Configure Transformation">
    अपने transformation rules define करने के लिए **Edit transformation** पर क्लिक करें।
    
    <Info>
    Webhook payload transform करने और अलग target URL specify करने के लिए JavaScript का उपयोग कर सकते हैं।
    </Info>
</Step>

<Step title="Test Transformation">
    Live होने से पहले यह verify करने के लिए testing interface का उपयोग करें कि आपका transformation सही ढंग से काम कर रहा है।
</Step>
</Steps>

<Warning>
Transformations webhook delivery performance को significantly impact कर सकती हैं। Thoroughly test करें और transformation logic को simple और efficient रखें।
</Warning>

<Tip>
Transformations विशेष रूप से इनके लिए उपयोगी हैं:
- अलग-अलग data formats के बीच convert करना
- Specific criteria के आधार पर events filter करना
- Payload में computed fields जोड़ना
- Events को अलग-अलग microservices पर route करना
</Tip>

## Email Alerts

Automatic email notifications के साथ अपने webhook health से अवगत रहें। जब webhook deliveries fail होने लगें या आपका endpoint response देना बंद कर दे, तो आपको email alerts प्राप्त होंगे, जिससे आप issues को जल्दी address कर सकेंगे और अपने integrations को सुचारु रूप से चला सकेंगे।

### Email Alerts सक्षम करना

<Steps>
<Step title="Navigate to Alerting Settings">
  अपने Dodo Payments Dashboard पर जाएँ और **Dashboard → Webhooks → Alerting** पर जाएँ।
</Step>

<Step title="Enable Email Notifications">
  Webhook delivery issues के बारे में alerts प्राप्त करना शुरू करने के लिए **Email notifications** को on करें।
</Step>

<Step title="Configure Email Address">
  वह email address दर्ज करें जहाँ आप webhook alerts प्राप्त करना चाहते हैं। जब आपके webhook setup से संबंधित कुछ events हों, जैसे delivery issues जो आपके integrations को प्रभावित कर सकते हैं, तो हम इस address पर notifications भेजेंगे।
</Step>
</Steps>

<Tip>
Webhook delivery problems को जल्दी पहचानने और reliable integrations बनाए रखने के लिए email alerts enable करें। Deliveries fail होने या आपका endpoint unresponsive होने पर आपको notification दी जाएगी।
</Tip>
