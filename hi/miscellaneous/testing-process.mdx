## अवलोकन

Test mode आपको वास्तविक transactions process किए बिना payments simulate करने देता है। सभी test credentials केवल test mode में काम करते हैं — production में इनका उपयोग कभी न करें।

<CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
Test transactions वास्तविक payments process नहीं करते और वास्तविक accounts को प्रभावित नहीं करते।
</Card>

<Card title="Full API Access" icon="code">
सभी API endpoints test और live modes में एक जैसे काम करते हैं।
</Card>

<Card title="Webhook Testing" icon="webhook">
Test transactions के लिए production की तरह ही webhooks fire होते हैं।
</Card>
</CardGroup>

<Warning>
Test credentials केवल test mode में काम करते हैं। Live mode में इनका उपयोग करने पर payment failures होंगी।
</Warning>

### Renewal Failure को कैसे Test करें

<Steps>
<Step title="Create a test subscription">
अपने test API keys का उपयोग करके **success** test card (उदाहरण के लिए, `4242 4242 4242 4242`) से subscription बनाएँ। Initial charge सफल होना चाहिए और subscription active हो जानी चाहिए।
</Step>

<Step title="Swap in the failure card via Customer Portal">
[Customer Portal](/features/customer-portal) खोलें, अभी बनाई गई subscription ढूँढें और **Update Payment Method** पर click करें। Failure test card `4000 0000 0000 0341` (Expiry: `12/34`, CVC: `123`) दर्ज करें और इसे subscription की payment method के रूप में save करें।
</Step>

<Step title="Advance the next billing date (optional)">
Natural billing cycle की प्रतीक्षा करने के बजाय renewal तुरंत trigger करने के लिए Update Subscription API का उपयोग करके `next_billing_date` को वर्तमान UTC time पर set करें। यह value ISO 8601 / RFC 3339 UTC timestamp होनी चाहिए (`Z` suffix आवश्यक है)।

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

विवरण के लिए [Update Subscription API reference](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0) देखें।
</Step>

<Step title="Verify the failure">
अगले billing attempt पर:

- Renewal charge failure card पर decline हो जाता है
- Subscription **On-Hold** status में चली जाती है
- एक `payment.failed` webhook event deliver होता है
- Customer payment method update करने और retry करने के लिए Customer Portal पर वापस जा सकता है
</Step>
</Steps>

<Warning>
यह card विशेष रूप से renewal failures test करने के लिए है। अगली billing date पर charge decline हो जाएगा, जिससे आप payment retry logic, customer notifications और failure handling test कर सकते हैं।
</Warning>

## Test UPI

UPI testing में विशेष VPA (Virtual Payment Address) identifiers का उपयोग होता है, जो अलग-अलग payment outcomes simulate करते हैं।

| Status | UPI ID |
| :----- | :----- |
| Success | `success@upi` |
| Failure | `failure@upi` |

### UPI Testing के लिए Requirements

- Billing country को `IN` पर set करना होगा
- Currency `INR` होनी चाहिए
- Non-Indian merchants के लिए: Adaptive Currency enabled होना चाहिए

Subscriptions के लिए RBI mandate testing सहित पूरी UPI documentation के लिए [India Payment Methods](/features/payment-methods/india) page देखें।

### Afterpay Testing

<Steps>
<Step title="Select Afterpay">
Checkout में payment method के रूप में Afterpay चुनें और Pay पर click करें।
</Step>

<Step title="Test successful payment">
Successful payments के लिए किसी भी valid email address और shipping address का उपयोग करें।
</Step>

<Step title="Test failed authentication">
Failure simulate करने के लिए redirect page पर Afterpay modal window बंद करें। Payment `requires_action` से `requires_payment_method` में transition हो जाता है।
</Step>
</Steps>

<Note>
Afterpay को payment option के रूप में दिखाई देने के लिए कम से कम **$50.01** transaction amount आवश्यक है।
</Note>

Billie B2B testing सहित पूरी BNPL documentation के लिए [Buy Now Pay Later](/features/payment-methods/bnpl) page देखें।

## Test Digital Wallets

### Apple Pay

<Steps>
<Step title="Enable test mode">
अपने Dodo Payments test API keys का उपयोग करें।
</Step>

<Step title="Add a card to Apple Wallet">
अपने Apple Wallet में एक वास्तविक card add करें। Test mode में card से charge नहीं लिया जाएगा।
</Step>

<Step title="Complete test purchase">
Apple device पर checkout खोलें और Apple Pay flow पूरा करें।
</Step>
</Steps>

<Warning>
Apple Pay के लिए HTTPS आवश्यक है। उचित SSL setup के बिना यह `localhost` पर दिखाई नहीं देगा। Domain verification भी पूरी होनी चाहिए।
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
Test cards अपने wallet में automatically add करने के लिए [Google Pay test card group में शामिल हों](https://groups.google.com/g/googlepay-test-mode-stub-data)।
</Step>

<Step title="Enable test mode">
अपने Dodo Payments test API keys का उपयोग करें।
</Step>

<Step title="Complete test purchase">
Transaction पूरा करने के लिए Google Pay में मौजूद किसी एक test card को select करें।
</Step>
</Steps>

### Amazon Pay, Cash App Pay और RevolutPay

अपनी test API keys का उपयोग करें और standard checkout flow follow करें। Test transactions को actual charges के बिना simulate किया जाता है।

Apple Pay के लिए domain verification सहित पूरी digital wallet documentation के लिए [Digital Wallets](/features/payment-methods/digital-wallets) page देखें।

## Test European Methods

European payment methods (iDEAL, Bancontact, EPS, Multibanco) को sandbox mode में test किया जा सकता है।

<Steps>
<Step title="Enable test mode">
अपने Dodo Payments test API keys का उपयोग करें।
</Step>

<Step title="Set billing address">
Billing address country को payment method से match करने के लिए set करें:
- `NL` iDEAL के लिए
- `BE` Bancontact के लिए
- `AT` EPS के लिए
- `PT` Multibanco के लिए
</Step>

<Step title="Set currency">
European methods के लिए EUR currency आवश्यक है।
</Step>

<Step title="Complete test flow">
Test environment में simulated bank authentication flow follow करें।
</Step>
</Steps>

पूरी European payment methods documentation के लिए [Europe](/features/payment-methods/europe) page देखें।

## Testing की Best Practices

<AccordionGroup>
<Accordion title="Test all payment scenarios">
केवल successful payments test न करें। Declines, cancellations और insufficient funds जैसे edge cases भी test करें।
</Accordion>

<Accordion title="Verify webhook handling">
सुनिश्चित करें कि आपके webhook endpoints सभी event types को सही ढंग से process करते हैं, विशेष रूप से `payment.succeeded`, `payment.failed` और subscription events।

Webhooks को locally test करने के लिए [Dodo Payments CLI](/developer-resources/sdks/cli#webhook-testing) का उपयोग करें:
- `dodo wh listen` live test webhooks को आपके local server पर forward करता है
- `dodo wh trigger` सभी 22 event types के लिए mock payloads भेजता है
</Accordion>

<Accordion title="Test on real devices">
Apple Pay और Google Pay के लिए वास्तविक iOS और Android devices पर test करें। Simulators wallet behavior को पूरी तरह replicate नहीं करते।
</Accordion>

<Accordion title="Test regional methods with correct addresses">
Regional payment methods (UPI, iDEAL आदि) के लिए matching billing addresses आवश्यक हैं। US billing address होने पर iDEAL दिखाई नहीं देगा।
</Accordion>

<Accordion title="Verify minimum amounts">
BNPL methods के लिए $50.01 minimum आवश्यक है। Test करें कि cart total के आधार पर वे सही ढंग से दिखाई और छिपाई जाती हैं।
</Accordion>
</AccordionGroup>
