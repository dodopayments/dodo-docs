## API Key Management और Authentication

<Steps>
<Step title="Access API Keys">
अपनी keys को manage करने के लिए dashboard में **Developer → API Keys** पर जाएँ।
</Step>

<Step title="Generate a New Key">
**Add API Key** चुनें, एक वर्णनात्मक नाम दें और write access कॉन्फ़िगर करें:

- **Enable write access** (checked): सभी API operations के लिए पूर्ण read और write permissions
- **Enable write access** (unchecked): केवल read-only access - केवल data fetch कर सकता है (payments, subscriptions, customers, products)। resources को create या modify नहीं कर सकता।

<Tip>
Dashboard integrations, analytics tools और ऐसे किसी भी system के लिए "Enable write access" को uncheck करें, जिसे बदलाव किए बिना केवल data देखने की आवश्यकता हो।
</Tip>
</Step>

<Step title="Store Your Key Securely">
Generated key को तुरंत copy करें और सुनिश्चित करें कि इसे सुरक्षित रूप से store किया गया है।
</Step>

<Step title="Authenticate Your API Requests">
सभी requests को authenticate करने के लिए अपनी API keys का उपयोग करें। निम्नलिखित authorization format लागू करें:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
अपनी secret API keys को client-side code या public repositories में कभी expose न करें।
</Warning>
</Step>
</Steps>

## Rate Limits

हमारा API burst protection के साथ dual-window rate limiting system का उपयोग करता है। Limits आपकी authentication method और business tier के आधार पर लागू की जाती हैं।

### Default Limits (Tier 0)

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 40 requests |
| Per Minute (Sustained) | 240 requests |

### Business Tiers

जिन businesses को API की अधिक आवश्यकता होती है, उनके लिए higher rate limits उपलब्ध हैं:

| Tier | Burst (per second) | Sustained (per minute) |
|------|-------------------|------------------------|
| Tier 0 (Default) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
अपने business को higher rate limit tier पर upgrade करने के लिए support से संपर्क करें।
</Tip>

### Unauthenticated Requests

मान्य authentication headers के बिना requests को IP address के आधार पर rate limited किया जाता है:

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 20 requests |
| Per Minute (Sustained) | 100 requests |

### Rate Limit Headers

इन response headers के साथ अपने usage की निगरानी करें:

- `X-RateLimit-Limit` - अनुमत अधिकतम requests
- `X-RateLimit-Remaining` - वर्तमान window में शेष requests
- `X-RateLimit-Reset` - rate limit reset होने का समय

<Note>
जब आप rate limits पार कर जाते हैं, तो API एक `429 Too Many Requests` response लौटाता है। अपनी retry logic में exponential backoff लागू करें।
</Note>
