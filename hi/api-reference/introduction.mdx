## API कुंजी प्रबंधन और प्रमाणीकरण

<Steps>
<Step title="API कुंजी तक पहुँचें">
अपने डैशबोर्ड में **Developer → API Keys** पर जाएँ अपनी कुंजियों का प्रबंधन करने के लिए।
</Step>

<Step title="नई कुंजी उत्पन्न करें">
**Add API Key** का चयन करें, एक वर्णनात्मक नाम प्रदान करें, और लिखने की पहुँच कॉन्फ़िगर करें:

- **लिखने की पहुँच सक्षम करें** (चेक किया गया): सभी API संचालन के लिए पूर्ण पढ़ने और लिखने की अनुमति
- **लिखने की पहुँच सक्षम करें** (अनचेक किया गया): केवल पढ़ने की अनुमति - केवल डेटा (भुगतान, सदस्यताएँ, ग्राहक, उत्पाद) प्राप्त कर सकते हैं। संसाधनों को बनाने या संशोधित नहीं कर सकते।

<Tip>
डैशबोर्ड एकीकरण, विश्लेषण उपकरण, और किसी भी प्रणाली के लिए "लिखने की पहुँच सक्षम करें" को अनचेक करें जिसे केवल डेटा देखने की आवश्यकता है बिना परिवर्तन किए।
</Tip>
</Step>

<Step title="अपनी कुंजी को सुरक्षित रूप से स्टोर करें">
उत्पन्न की गई कुंजी को तुरंत कॉपी करें और सुनिश्चित करें कि इसे सुरक्षित रूप से स्टोर किया गया है।
</Step>

<Step title="अपने API अनुरोधों को प्रमाणित करें">
सभी अनुरोधों को प्रमाणित करने के लिए अपनी API कुंजियों का उपयोग करें। निम्नलिखित प्राधिकरण प्रारूप लागू करें:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
कभी भी अपने गुप्त API कुंजियों को क्लाइंट-साइड कोड या सार्वजनिक रिपॉजिटरी में उजागर न करें।
</Warning>
</Step>
</Steps>

## दर सीमाएँ

हमारा API डुअल-विश Windows दर सीमित प्रणाली का उपयोग करता है जिसमें बर्स्ट सुरक्षा होती है। सीमा आपके प्रमाणीकरण विधि और व्यवसाय स्तर के आधार पर लागू होती है।

### डिफ़ॉल्ट सीमाएँ (स्तरीय 0)

| विंडो | सीमा |
|--------|-------|
| प्रति सेकंड (बर्स्ट) | 40 अनुरोध |
| प्रति मिनट (स्थायी) | 240 अनुरोध |

### व्यापार स्तर

बढ़ी हुई API आवश्यकताओं वाले व्यवसायों के लिए उच्च दर सीमाएं उपलब्ध हैं:

| स्तर | बर्स्ट (प्रति सेकंड) | स्थायी (प्रति मिनट) |
|------|-------------------|------------------------|
| स्तर 0 (डिफ़ॉल्ट) | 40 | 240 |
| स्तर 1 | 100 | 1,000 |
| स्तर 2 | 500 | 5,000 |

<Tip>
अपने व्यवसाय को उच्च दर सीमा स्तर में अपग्रेड करने के लिए समर्थन से संपर्क करें।
</Tip>

### प्रमाणीकरण रहित अनुरोध

मान्य प्रमाणीकरण हेडर के बिना अनुरोधों को IP पते द्वारा दर सीमित किया जाता है:

| विंडो | सीमा |
|--------|-------|
| प्रति सेकंड (बर्स्ट) | 20 अनुरोध |
| प्रति मिनट (स्थायी) | 100 अनुरोध |

### दर सीमा हेडर

इन प्रतिक्रिया हेडरों के साथ अपने उपयोग की निगरानी करें:

- `X-RateLimit-Limit` - अधिकतम अनुरोध जो अनुमति दी जाती है
- `X-RateLimit-Remaining` - वर्तमान विंडो में शेष अनुरोध
- `X-RateLimit-Reset` - वह समय जब दर सीमा रीसेट होती है

<Note>
जब आप दर सीमाओं को पार करते हैं, तो API एक `429 Too Many Requests` प्रतिक्रिया लौटाता है। अपनी पुन: प्रयास लॉजिक में बढ़ती हुई बैकऑफ लागू करें।
</Note>
