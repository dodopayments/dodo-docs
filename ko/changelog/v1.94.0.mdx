## 새로운 기능

### 1. **버려진 장바구니 복구**

완료되지 않거나 실패한 결제를 자동으로 감지하고 고객을 되돌리기 위한 타겟 이메일 시퀀스를 보냅니다. ACR은 60분 후에 성공하지 못한 결제를 모니터링하고 이를 **결제 실패** 또는 **체크아웃 미완료**로 분류한 후, 시퀀스당 최대 3개의 구성 가능한 복구 이메일을 보냅니다.

<Frame>
<img src="/images/recovery/recovery-analytics.png" alt="버려진 체크아웃 수, 복구율, 회수된 수익을 보여주는 복구 분석 대시보드" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

주요 기능:
- **이메일 두 가지 시퀀스** — 결제 실패와 체크아웃 미완료 각각 최대 3개의 이메일
- **복구 할인** — 복구를 유도하기 위한 단일 사용 할인 코드를 자동 생성하는 옵션
- **고객 복구 페이지** — 고유한 복구 링크가 고객을 구매 완료 전용 페이지로 안내
- **복구 분석** — 버려진 체크아웃 수, 복구율, 회수된 수익, 이메일/제품별 분석 추적

<Tip>
기본 이메일 타이밍(1시간, 24시간, 72시간)을 시작으로 하고 복구 분석 데이터를 기반으로 반복합니다.
</Tip>

자세히 알아보기: [버려진 장바구니 복구](/features/recovery/abandoned-cart-recovery)

### 2. **구독 징수**

만료되거나 취소된 구독을 복구하기 위한 이메일 시퀀스를 자동으로 보냅니다. 구독이 **대기 상태**(결제 실패)이거나 고객 포털에서 고객에 의해 **취소**될 때 징수가 시작됩니다.

주요 기능:
- **이메일 두 가지 시퀀스** — 대기 상태와 취소됨 각각 최대 4개의 이메일
- **자동 청구** — 고객이 결제 방식을 업데이트하면 미지급액이 자동으로 청구됨
- **구성 가능한 타이밍** — 기본 간격은 1일, 3일, 5일, 7일이며 이메일당 완전히 맞춤화 가능

자세히 알아보기: [구독 징수](/features/recovery/subscription-dunning)

### 3. **할인 메타데이터**

이제 API를 통해 생성하거나 업데이트할 때 할인에 **메타데이터**(키-값 쌍)를 첨부할 수 있습니다. 메타데이터를 사용하여 캠페인, 소스 또는 내부 참조에 따라 할인을 태그하고 추적 및 조정할 수 있습니다.

```typescript
const discount = await client.discounts.create({
  type: 'percentage',
  amount: 1500, // 15%
  code: 'SUMMER2025',
  metadata: {
    campaign: 'summer_promo',
    source: 'email_blast'
  }
});
```

자세히 알아보기: [할인 코드](/features/discount-codes) | [Metadata Guide](/api-reference/metadata)

### 4. **복구 웹훅**

복구 라이프사이클을 추적하기 위한 새로운 웹훅 이벤트:

| 이벤트 | 설명 |
|-------|-------------|
| `abandoned_checkout.detected` | 버려진 체크아웃이 감지됨 |
| `abandoned_checkout.recovered` | 고객이 복구 링크를 통해 결제를 완료함 |
| `dunning.started` | 구독에 대해 징수 시도가 시작됨 |
| `dunning.recovered` | 고객이 결제 방식을 업데이트하고 결제가 성공함 |

자세히 알아보기: [Recovery Webhooks](/developer-resources/webhooks/intents/recovery)

### 5. **브라질을 위한 Pix 결제**

브라질 중앙은행에서 만든 브라질의 즉시 결제 시스템인 **Pix**를 Dodo Payments 결제에서 수락하세요. Pix는 이제 브라질에서 가장 많이 사용되는 결제 수단으로, 신용카드와 boleto를 제치고 항상 몇 초 만에 확인됩니다.

**커버리지**

| 세부사항 | 값 |
|--------|-------|
| 청구 통화 | BRL |
| 지원 국가 | 브라질 |
| 구독 | 지원되지 않음 (일회성 결제만 가능) |
| 최소 금액 | $0.50 |
| 정산 | 즉시 |

**설정**

`pix`를 `allowed_payment_method_types`에 전달하고 청구 통화를 `BRL`로 설정하세요:

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: ['pix', 'credit', 'debit'],
  billing_currency: 'BRL',
  return_url: 'https://example.com/success'
});
```

고객은 결제 시 Pix QR 코드와 복사-붙여넣기 키를 봅니다. 그들은 은행 앱을 열고, 스캔하거나 붙여넣고, 결제가 즉시 확인됩니다.

<Tip>
Pix QR 코드는 설정된 시간이 지나면 만료됩니다. 필요한 경우 고객이 코드를 재생성할 수 있도록 체크아웃 흐름을 설계하십시오. 카드를 선호하는 고객을 위해 항상 카드 대체 옵션을 포함하십시오.
</Tip>

자세히 알아보기: [Pix Payments](/features/payment-methods/pix)

### 6. **중국 고객을 위한 WeChat Pay**

중국 전역에서 10억 명 이상의 사람들이 사용하는 **WeChat Pay**를 Dodo Payments 결제에서 직접 수락하세요. 고객은 WeChat 앱으로 QR 코드를 스캔하고 WeChat 생태계를 벗어나지 않고 몇 초 만에 결제를 확인합니다.

**커버리지**

| 세부사항 | 값 |
|--------|-------|
| 청구 통화 | USD, CNY |
| 구독 | 지원되지 않음 (일회성 결제만 가능) |
| 최소 금액 | $0.50 / ¥1.00 |
| 정산 | USD |

**설정**

Checkout 세션을 생성할 때 `we_chat_pay`을(를) `allowed_payment_method_types`에 전달합니다:

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: ['we_chat_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

WeChat Pay는 **USD** (중국 고객을 대상으로 하는 해외 상인용) 및 **CNY** (중국 내 거래용)를 모두 지원합니다. 청구 통화에 상관없이 상인에게는 USD로 정산됩니다.

<Tip>
고객이 휴대폰으로 QR 코드를 스캔할 수 있도록 데스크톱이나 태블릿에 체크아웃을 표시하십시오 — 이것이 WeChat Pay 사용자가 가장 익숙한 흐름입니다.
</Tip>

자세히 알아보기: [WeChat Pay](/features/payment-methods/wechat)
