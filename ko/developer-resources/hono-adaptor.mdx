## 설치

<Steps>
<Step title="Install the package">
프로젝트 루트에서 다음 명령을 실행합니다:

```bash
npm install @dodopayments/hono
```

</Step>
<Step title="Set up environment variables">
프로젝트 루트에 <code>.env</code> 파일을 생성합니다:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_RETURN_URL=https://yourapp.com/success
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode""
```

<Warning>
<code>.env</code> 파일이나 secrets를 버전 관리 시스템에 커밋하지 마세요.
</Warning>
</Step>
</Steps>

## Checkout Route Handler

<Info>
Dodo Payments는 결제를 웹사이트에 통합하기 위한 세 가지 payment flow를 지원하며, 이 어댑터는 모든 유형의 payment flow를 지원합니다.
</Info>

- **Static Payment Links:** 빠르고 no-code 결제 수집을 위해 즉시 공유할 수 있는 URL입니다.
- **Dynamic Payment Links:** API 또는 SDK를 사용하여 custom details가 포함된 payment link를 programmatically 생성합니다.
- **Checkout Sessions:** 사전 구성된 product cart 및 customer details를 사용하여 안전하고 custom 가능한 checkout experience를 생성합니다.

<Accordion title="Dynamic Checkout (POST)">
- POST request의 JSON body로 parameters를 전송합니다.
- 일회성 결제와 recurring payment를 모두 지원합니다.
- 지원되는 POST body fields의 전체 목록은 다음을 참조하세요:
  - [One Time Payment Product의 Request body](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Subscription Product의 Request body](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Response Format
Dynamic checkout은 checkout URL이 포함된 JSON response를 반환합니다:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">

자세한 내용과 지원되는 fields의 전체 목록은 [Checkout Sessions Integration Guide](https://docs.dodopayments.com/developer-resources/checkout-session)를 참조하세요.

### Response Format
Checkout sessions는 checkout URL이 포함된 JSON response를 반환합니다:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

## Webhook Route Handler

- **Method:** POST requests만 지원됩니다. 다른 methods는 405를 반환합니다.
- **Signature Verification:** <code>webhookKey</code>를 사용하여 webhook signature를 검증합니다. 검증에 실패하면 401을 반환합니다.
- **Payload Validation:** Zod로 검증합니다. 잘못된 payload에는 400을 반환합니다.
- **Error Handling:**
  - 401: 잘못된 signature
  - 400: 잘못된 payload
  - 500: 검증 중 internal error
- **Event Routing:** payload type에 따라 적절한 event handler를 호출합니다.

**If Checkout Route Handler is selected:**

**Purpose**: This handler redirects users to the Dodo Payments checkout page.

**Integration**:
Create two routes in your Hono app — one for static (GET) and one for dynamic (POST) checkout.

import { Checkout } from '@dodopayments/hono';
import Hono from 'hono'

const app = new Hono()

app.get(
  "/api/checkout",
  Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    type: 'static'
  })
);

app.post(
  "/api/checkout",
  Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    type: 'session' // or 'dynamic' for dynamic link
  })
);

Config Options:

    bearerToken: Your Dodo Payments API key (recommended to be stored in DODO_PAYMENTS_API_KEY env variable).

    returnUrl (optional): URL to redirect the user after successful checkout.

    environment: "test_mode" or "live_mode"

    type: "static" (GET) or "dynamic" (POST) or "session" (POST)

GET (static checkout) expects query parameters:

    productId (required)

    quantity, customer fields (fullName, email, etc.), and metadata (metadata_*) are optional.

POST (dynamic checkout) expects a JSON body with payment details (one-time or subscription). Reference the docs for the full POST schema:

    One-time payments: https://docs.dodopayments.com/api-reference/payments/post-payments

    Subscriptions: https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions

POST (checkout sessions) - (Recommended) A more customizable checkout experience. Returns JSON with checkout_url: Parameters are sent as a JSON body. Supports both one-time and recurring payments. Returns: {"checkout_url": "https://checkout.dodopayments.com/session/..."}. For a complete list of supported fields, refer to:

  Checkout Sessions Integration Guide: https://docs.dodopayments.com/developer-resources/checkout-session

If Webhook Route Handler is selected:

Purpose: Processes incoming webhook events from Dodo Payments to trigger events in your app.

Integration:

import Hono from 'hono'
import { Webhooks } from '@dodopayments/hono'

const app = new Hono()
app.post(
  "/api/webhooks",
  Webhooks({
    webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
    onPayload: async (payload) => {
      // Handle Payload Here
      console.log(payload)
    }
  })
);

Features:

    Only POST method is allowed — others return 405

    Signature verification is performed using webhookKey. Returns 401 if invalid.

    Zod-based payload validation. Returns 400 if invalid schema.

    All handlers are async functions.

You may pass in any of the following handlers:

    onPayload

    onPaymentSucceeded

    onPaymentFailed

    onPaymentProcessing

    onPaymentCancelled

    onRefundSucceeded

    onRefundFailed

    onDisputeOpened, onDisputeExpired, onDisputeAccepted, onDisputeCancelled, onDisputeChallenged, onDisputeWon, onDisputeLost

    onLicenseKeyCreated

    onAbandonedCheckoutDetected, onAbandonedCheckoutRecovered

    onDunningStarted, onDunningRecovered

    onCreditAdded, onCreditDeducted, onCreditExpired, onCreditRolledOver, onCreditRolloverForfeited, onCreditOverageCharged, onCreditManualAdjustment, onCreditBalanceLow
