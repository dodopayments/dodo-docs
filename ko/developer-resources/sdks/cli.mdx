## 기능

- **대화형 TUI** — 인수 없이 `dodo`를 실행하면 command palette, 기록, 실시간 알림을 갖춘 전체 대화형 인터페이스가 열립니다.
- **기본 제공 AI assistant** — `/ai`를 사용해 일반 영어로 질문하거나 작업을 수행할 수 있습니다. 추가 설정이 필요하지 않으며, `dodopayments-mcp`가 로컬에서 실행됩니다.
- **기본적으로 안전함** — API keys는 OS secret store(macOS Keychain, Windows Credential Vault, Linux libsecret)에 저장됩니다. 디스크에 평문 설정이 저장되지 않습니다.
- **자동 업데이트** — CLI는 시작 시 새 버전을 확인하고 앱 내에서 알려줍니다. `/update`를 실행하면 현재 설치 위치에서 업그레이드됩니다.
- **Webhook 도구** — 실시간 webhook을 수신하거나 로컬 개발을 위해 오프라인에서 payload를 트리거할 수 있습니다.

## 설치

macOS 또는 Linux에 CLI를 한 줄로 설치합니다:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### npm 또는 Bun으로 설치

Node 또는 Bun이 이미 설치되어 있다면 package manager 설치는 항상 최신 버전을 가져옵니다:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### 수동 설치(Node / Bun 불필요)

원격 스크립트를 `sh`로 pipe하고 싶지 않다면 바이너리를 직접 다운로드하세요.

<Steps>
<Step title="Download the binary">
  최신 [GitHub Release](https://github.com/dodopayments/dodopayments-cli/releases)에서 플랫폼에 맞는 바이너리를 다운로드하세요.

  | Platform | Binary |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  Windows에서 `C:\Windows\System32`로 이동하려면 administrator 권한이 필요합니다.
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  각 release에는 `SHA256SUMS.txt`가 게시됩니다. 다음 명령으로 다운로드를 확인하세요:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## 인증

인증된 명령을 사용하기 전에 API key로 로그인하세요:

```bash
dodo login
```

또는 대화형 TUI 내부에서 실행하세요:

```text
/login
```

로그인 흐름은 다음과 같이 진행됩니다:

1. 브라우저에서 Dodo Payments API Keys 페이지를 엽니다.
2. API Key를 붙여넣도록 요청합니다.
3. 환경을 선택하도록 요청합니다 — **Test Mode** 또는 **Live Mode**.
4. 자격 증명을 OS secret store(macOS의 Keychain, Windows의 Credential Vault, Linux의 libsecret)에 저장합니다.

<Info>
자격 증명은 OS secret store에 저장되므로 CLI가 처음으로 자격 증명을 읽거나 쓸 때 **device password**를 입력하라는 메시지가 표시될 수 있습니다. 이전 버전에서 업그레이드하는 경우 기존 평문 API key는 자동으로 **secret store로 마이그레이션되고 기존 파일은 삭제**됩니다.
</Info>

### 모드 전환 및 로그아웃

하나의 **Test Mode** key와 하나의 **Live Mode** key를 동시에 인증된 상태로 유지할 수 있습니다. 자격 증명을 삭제하려면:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

로그아웃 흐름에서 **All accounts**, **Test Mode**, **Live Mode** 중 하나를 독립적으로 선택할 수 있습니다.

## 사용법

CLI는 두 가지 모드로 사용할 수 있습니다.

### 1. 대화형 TUI(권장)

인수 없이 `dodo`를 실행하면 전체 대화형 인터페이스가 시작됩니다:

```bash
dodo
```

`/`를 입력하면 command palette가 열립니다. 또는 바로 입력을 시작하세요 — slash command가 아닌 모든 내용은 AI assistant로 전송됩니다.

| Command | Description |
|---------|-------------|
| `/help` | 명령 참조 표시 |
| `/update` | CLI 업데이트 확인 및 설치 |
| `/login` | API key로 인증 |
| `/logout` | 하나 또는 모든 환경에서 로그아웃 |
| `/clear` | TUI 화면 지우기 |
| `/exit` | TUI 종료(또는 `exit` 입력, `Esc` 두 번 누르기) |

### 2. 직접 subcommand 실행

TUI에 들어가지 않고 명령을 직접 실행합니다:

```bash
dodo <category> <sub-command> [args...]
```

예시:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

아래 참조 표에는 모든 명령이 나와 있습니다. TUI에서는 명령 앞에 `/`를 붙이고, 직접 모드에서는 `/`를 생략합니다.

## AI Assistant

자연어로 질문하거나 작업을 수행할 수 있습니다. assistant는 로컬에서 실행되는 `dodopayments-mcp`를 사용합니다. 추가 설정이나 OAuth 흐름이 필요하지 않으며, AI 트래픽은 model provider와 통신하는 경우를 제외하고 컴퓨터 밖으로 나가지 않습니다.

| Command | Description |
|---------|-------------|
| `/ai <query>` | AI assistant에 질문하거나 지시 |
| _(any non-slash text)_ | TUI에서 기본적으로 AI assistant로 전송 |

예시:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
assistant는 활성 환경(Test / Live)을 따르므로 현재 로그인한 환경의 데이터에 대해서만 작업합니다.
</Tip>

## 프로젝트 Scaffolding

`dodo init`는 기존 프로젝트에 Dodo Payments billing route를 직접 scaffold합니다. 기본 route 파일을 생성하고, 일치하는 `@dodopayments/*` adapter package를 설치하며, `DODO_PAYMENTS_*` environment variables를 `.env`에 안전하게 작성합니다(아직 없는 변수만 추가합니다). 이 명령은 **로그인 없이** 실행됩니다.

```bash
dodo init <framework>
```

| Scaffold | Description |
|----------|-------------|
| `dodo init nextjs` | `@dodopayments/nextjs`를 사용해 Next.js App Router billing route(checkout, customer portal, webhook handler)를 scaffold |
| `dodo init express` | `@dodopayments/express`를 사용해 Express server billing route scaffold |
| `dodo init better-auth` | `@dodopayments/better-auth`를 사용해 Better-Auth plugin configuration scaffold |

Better-Auth scaffold에서는 생성할 plugin을 쉼표로 구분해 전달할 수 있습니다(기본값은 모두 생성): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
scaffolder는 `src/` directory를 자동으로 감지하고 그에 따라 output path를 조정합니다. 또한 package manager(`bun`, `pnpm`, `yarn` 또는 `npm`)를 자동으로 감지해 올바른 install command를 실행합니다.
</Info>

## Webhooks

CLI에는 개발 중 webhook을 테스트하기 위한 두 가지 강력한 도구가 포함되어 있습니다. 하나는 실시간 test webhook을 로컬 server로 전달하는 **listener**이고, 다른 하나는 모든 endpoint로 mock webhook payload를 전송하는 **trigger**입니다.

| Command | Description |
|---------|-------------|
| `dodo wh listen` | 실시간으로 webhook을 수신하고 로컬 dev server로 전달 |
| `dodo wh trigger` | 대화형으로 test webhook event 트리거 — 로그아웃 상태에서도 사용 가능 |

### Webhook 수신

Dodo Payments에서 로컬 development server로 webhook을 실시간 전달합니다.

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  webhook을 수신할 로컬 URL을 입력하세요(예: `http://localhost:3000/webhook`).
</Step>

<Step title="Automatic setup">
  CLI는 아직 존재하지 않는 경우 Dodo Payments 계정에 webhook endpoint를 자동으로 생성한 다음, WebSocket connection을 열어 실시간으로 event를 수신합니다.
</Step>

<Step title="Receive and forward">
  webhook event가 발생하면(test payment, subscription 변경 등) CLI가 이를 수신하고 event type을 기록한 뒤, headers와 body를 포함한 전체 request를 로컬 endpoint로 전달합니다. endpoint의 response가 기록되고 다시 전송됩니다.
</Step>
</Steps>

<Warning>
`dodo wh listen`에는 **Test Mode** API key가 필요합니다. listen flow에서는 Live Mode key가 지원되지 않습니다.
</Warning>

<Tip>
listener는 로컬 endpoint로 전달할 때 원본 webhook headers(`webhook-id`, `webhook-signature`, `webhook-timestamp`)를 유지하므로 signature verification logic을 테스트할 수 있습니다.
</Tip>

### Test webhook 트리거

실제 transaction을 생성하지 않고 빠르게 테스트할 수 있도록 모든 endpoint로 mock webhook payload를 전송합니다.

```bash
dodo wh trigger
```

`/wh trigger` flow는 다음 단계를 안내합니다:

1. destination **endpoint URL** 설정
2. 대화형 메뉴에서 트리거할 특정 **event** 선택

<Info>
`dodo wh trigger`에는 **로그인이 필요하지 않습니다**. 로컬/오프라인 webhook payload generator로 작동합니다.
</Info>

<Warning>
트리거된 event에는 **서명이 추가되지 않습니다**. 테스트 중에는 endpoint에서 webhook signature verification을 비활성화하세요. 예를 들어 webhook handler에서는 **테스트 중에만** `unwrap()` 대신 `unsafe_unwrap()`를 사용합니다.
</Warning>

### 지원되는 webhook event

`dodo wh trigger`는 Dodo Payments가 제공하는 모든 46가지 이벤트 유형에 대한 mock payload를 전송할 수 있습니다:

| Category | Events |
|----------|--------|
| **Subscription** | `active`, `updated`, `on_hold`, `paused`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired`, `update_payment_method` |
| **Payment** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Refund** | `succeeded`, `failed` |
| **Dispute** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **License Key** | `created` |
| **Payout** | `created`, `in_progress`, `on_hold`, `failed`, `success` |
| **Credit** | `added`, `deducted`, `expired`, `rolled_over`, `rollover_forfeited`, `overage_charged`, `overage_reset`, `manual_adjustment`, `balance_low` |
| **Abandoned Checkout** | `detected`, `recovered` |
| **Dunning** | `started`, `recovered` |
| **Entitlement Grant** | `created`, `delivered`, `failed`, `revoked` |

<Note>
Mock payload의 형태는 API reference의 해당 스키마를 따릅니다. 각 이벤트의 의미와 프로덕션 환경에서 Dodo Payments가 이벤트를 생성하는 시점은 [Webhook Events](/developer-resources/webhooks/intents/webhook-events-guide)에서 확인하세요.
</Note>

<Tip>
`payout.created`는 payout이 여전히 `not_initiated` 상태로 보고되는 동안 생성되므로 mock payload에도 해당 상태가 반영됩니다. 전체 payout lifecycle은 [Payout Events](/developer-resources/webhooks/intents/payout)에서 확인하세요.
</Tip>
