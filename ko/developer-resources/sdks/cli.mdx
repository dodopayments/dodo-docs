## 기능

- **인터랙티브 TUI** — 인수 없이 ``dodo``을(를) 실행하여 커맨드 팔레트, 기록 및 실시간 알림이 포함된 전체 인터랙티브 인터페이스를 엽니다.
- **내장 AI 어시스턴트** — ``/ai``를 사용하여 간단한 영어로 질문을 하거나 작업을 수행하세요. 추가 설정 없이 ``dodopayments-mcp``가 로컬로 실행됩니다.
- **기본적으로 안전함** — API 키가 OS 비밀 저장소(맥OS 키체인, 윈도우 자격 증명 저장소, 리눅스 libsecret)에 저장됩니다. 플레인텍스트 구성이 디스크에 저장되지 않습니다.
- **자동 업데이트** — CLI는 시작 시 새 버전을 확인하고 앱 내에서 알림을 제공합니다. ``/update``을(를) 실행하여 바로 업그레이드하세요.
- **웹훅 도구** — 라이브 웹훅을 청취하거나 오프라인으로 페이로드를 트리거하여 로컬 개발에 사용하세요.

## 설치

macOS 또는 Linux에서 한 줄로 CLI 설치:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### npm 또는 Bun으로 설치

이미 Node 또는 Bun이 있는 경우, 패키지 매니저 설치는 항상 최신 버전을 가져옵니다:



```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```



### 수동 설치 (Node / Bun 필요 없음)

원격 스크립트를 ``sh``에 파이핑하지 않고 직접 바이너리를 다운로드하려면:

  최신 [GitHub 릴리스](https://github.com/dodopayments/dodopayments-cli/releases)에서 플랫폼에 맞는 바이너리를 다운로드하세요.

  | 플랫폼 | 바이너리 |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |



  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```





  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```



  Windows에서 ``C:\Windows\System32``로 이동하려면 관리자 권한이 필요합니다.

  각 릴리스는 ``SHA256SUMS.txt``을(를) 게시합니다. 다음으로 다운로드를 확인하세요:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```



## 인증

인증된 명령어를 사용하기 전에 API 키로 로그인하세요:

```bash
dodo login
```

또는 인터랙티브 TUI 내부에서:

```text
/login
```

로그인 흐름:

1. Dodo Payments API 키 페이지로 브라우저를 엽니다.
2. API 키를 붙여넣도록 요청받습니다.
3. **테스트 모드** 또는 **라이브 모드** 중 환경을 선택하도록 요청받습니다.
4. 자격 증명을 OS 비밀 저장소에 저장합니다(맥OS 키체인, 윈도우 자격 증명 저장소, 리눅스 libsecret).

자격 증명이 OS 비밀 저장소에 저장되므로, CLI가 자격 증명을 읽거나 쓸 때 처음으로 **디바이스 비밀번호**를 요청받을 수 있습니다. 구버전에서 업그레이드하는 경우, 기존의 모든 플레인텍스트 API 키가 **비밀 저장소로 자동 마이그레이션되고 이전 파일은 삭제됩니다.**

### 모드 전환 및 로그아웃

동시에 하나의 **테스트 모드**와 하나의 **라이브 모드** 키를 인증할 수 있습니다. 자격 증명을 지우려면:



```bash Direct
dodo logout
```

```text TUI
/logout
```



로그아웃 흐름을 통해 **모든 계정**, **테스트 모드** 또는 **라이브 모드**를 독립적으로 선택할 수 있습니다.

## 사용법

CLI는 두 가지 모드에서 사용할 수 있습니다.

### 1. 인터랙티브 TUI (권장)

인수 없이 ``dodo``를 실행하여 전체 인터랙티브 인터페이스를 시작합니다:

```bash
dodo
```

``/``를 입력하여 명령어 팔레트를 열거나 그냥 입력을 시작하세요. 슬래시 명령이 아닌 모든 것은 AI 어시스턴트에게로 전송됩니다.

| 명령어 | 설명 |
|---------|-------------|
| `/help` | 명령어 참조 보기 |
| `/update` | CLI 업데이트 확인 및 설치 |
| `/login` | API 키로 인증 |
| `/logout` | 하나 이상의 환경에서 로그아웃 |
| `/clear` | TUI 화면 지우기 |
| `/exit` | TUI 종료 (또는: ``exit``를 입력하거나 ``Esc``를 두 번 누르기) |

### 2. 직접 하위 명령어

TUI에 들어가지 않고 명령어를 직접 실행하세요:

```bash
dodo <category> <sub-command> [args...]
```

예를 들어:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

아래 참조 표는 모든 명령어를 보여줍니다. TUI에서 그들 앞에 ``/``를 붙이세요; 직접 모드에서는 ``/``를 제거하세요.

## AI 어시스턴트

자연어로 질문을 하거나 작업을 수행하세요. 어시스턴트는 로컬에서 실행되는 ``dodopayments-mcp``을(를) 사용합니다. 추가 설정이나 OAuth 흐름이 필요하지 않으며, AI 트래픽은 모델 공급자와 소통하는 것 외에는 절대 기기를 떠나지 않습니다.

| 명령어 | 설명 |
|---------|-------------|
| `/ai <query>` | AI 어시스턴트에게 질문을 하거나 지시를 내립니다 |
| _(슬래시가 없는 모든 텍스트)_ | TUI에서 기본적으로 AI 어시스턴트로 전송됨 |

예시:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

어시스턴트는 현재 로그인한 환경(테스트/라이브)의 데이터를 기반으로만 작동하므로 활성 환경을 존중합니다.

## 웹훅

CLI에는 개발 중 웹훅을 테스트하기 위한 두 가지 강력한 도구가 포함되어 있습니다: 실시간 테스트 웹훅을 로컬 서버로 전달하는 **리스너**, 그리고 모든 엔드포인트에 모의 웹훅 페이로드를 보내는 **트리거**입니다.

| 명령어 | 설명 |
|---------|-------------|
| `dodo wh listen` | 실시간으로 웹훅을 청취하고 로컬 개발 서버로 전달 |
| `dodo wh trigger` | 테스트 웹훅 이벤트를 인터랙티브하게 트리거 — 로그아웃 상태에서도 |

### 웹훅 청취

Dodo Payments에서 웹훅을 로컬 개발 서버로 실시간 전달.

```bash
dodo wh listen
```

  수신할 웹훅의 로컬 URL을 제공하세요 (예: ``http://localhost:3000/webhook``).

  CLI는 Dodo Payments 계정에 웹훅 엔드포인트가 없으면 자동으로 생성한 후, 실시간으로 이벤트를 수신하기 위해 WebSocket 연결을 엽니다.

  웹훅 이벤트(예: 테스트 결제, 구독 변경 등)가 발생하면, CLI는 이를 수신하고 이벤트 유형을 기록하며, 헤더 및 본문과 함께 전체 요청을 로컬 엔드포인트로 전달합니다. 엔드포인트로부터의 응답은 기록되어 전송됩니다.

``dodo wh listen``은 **테스트 모드** API 키가 필요합니다. 라이브 모드 키는 청취 흐름에서 지원되지 않습니다.

리스너는 로컬 엔드포인트로 전달할 때 원래 웹훅 헤더(``webhook-id``, ``webhook-signature``, ``webhook-timestamp``)를 보존하므로 서명 검증 로직을 테스트할 수 있습니다.

### 테스트 웹훅 트리거

실제 거래를 생성하지 않고 빠르게 테스트하기 위하여 모든 엔드포인트로 모의 웹훅 페이로드를 보냅니다.

```bash
dodo wh trigger
```

``/wh trigger`` 흐름은 여러분을 다음으로 안내합니다:

1. 목적지 **엔드포인트 URL** 설정
2. 인터랙티브 메뉴에서 트리거할 특정 **이벤트** 선택

``dodo wh trigger``는 로그인할 필요가 없습니다. 로컬/오프라인 웹훅 페이로드 생성기로 작동합니다.

트리거된 이벤트는 **서명되지 않습니다**. 테스트하는 동안에는 엔드포인트에서 웹훅 서명 검증을 비활성화하세요 — 예를 들어, 테스트 시에 한하여 여러분의 웹훅 핸들러에서 ``unsafe_unwrap()`` 대신 ``unwrap()``을 사용하세요.

### 지원되는 웹훅 이벤트

| 카테고리 | 이벤트 |
|----------|--------|
| **구독** | `active`, `updated`, `on_hold`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired` |
| **결제** | `succeeded`, `failed`, `processing`, `cancelled` |
| **환불** | `succeeded`, `failed` |
| **분쟁** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **라이선스** | `created` |

### 환경 변수

| 변수 | 설명 |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | ``dodo wh listen``이(가) 사용하는 기본 웹훅 릴레이 서버 URL을 대체합니다 |
