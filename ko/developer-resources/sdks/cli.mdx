Dodo Payments 리소스를 관리하고, 체크아웃 세션을 생성하며, 터미널에서 직접 웹훅을 테스트하세요. 명령줄을 선호하는 개발자를 위해 만들어졌습니다.

## 설치

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### 수동 설치

1. 시스템에 맞는 [GitHub Releases](https://github.com/dodopayments/dodopayments-cli/releases)에서 최신 릴리스를 다운로드하세요.
2. 바이너리를 추출하고 `dodo`로 이름을 변경하세요.
3. PATH에 있는 디렉터리로 이동하세요:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## 인증

CLI를 사용하기 전에 API 키로 인증하세요:

```bash
dodo login
```

이 과정은:
1. 브라우저를 Dodo Payments API 키 페이지로 열기
2. API 키 입력하기
3. 환경 선택하기 (**테스트 모드** 또는 **라이브 모드**)
4. 로컬에 자격증명 저장하기 `~/.dodopayments/api-key`

<Info>
CLI는 환경당 하나의 API 키를 저장하는 것을 지원합니다. 테스트 모드와 라이브 모드 키가 모두 설정되어 있으면, 현재 세션에 사용할 환경을 선택하라는 메시지가 표시됩니다.
</Info>

## 사용법

일반 구문은:

```bash
dodo ‹category› ‹sub-command›
```

인수 없이 `dodo`를 실행하면 모든 사용 가능한 카테고리가 표시됩니다. 서브 커맨드 없이 `dodo <category>`을 실행하면 해당 카테고리의 사용 가능한 서브 커맨드가 표시됩니다.

### 제품

제품 카탈로그를 관리합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo products list` | 모든 제품 나열 (페이지네이션) |
| `dodo products create` | 제품 생성을 위한 대시보드 열기 |
| `dodo products info` | 특정 제품의 세부정보 보기 |

### 결제

결제 거래를 조회합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo payments list` | 모든 결제 나열 (페이지네이션) |
| `dodo payments info` | 특정 결제에 대한 정보 가져오기 |

### 고객

고객 기반을 관리합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo customers list` | 모든 고객 나열 (페이지네이션) |
| `dodo customers create` | 새 고객 프로필 만들기 |
| `dodo customers update` | 기존 고객의 세부정보 업데이트 |

### 할인

쿠폰 및 할인을 관리합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo discounts list` | 모든 할인 나열 (페이지네이션) |
| `dodo discounts create` | 새 비율 기반 할인 만들기 |
| `dodo discounts delete` | ID로 할인 제거 |

### 라이센스

소프트웨어 라이센스를 관리합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo licences list` | 모든 라이센스 키 나열 (페이지네이션) |

### 애드온

제품 애드온을 관리합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo addons list` | 모든 애드온 나열 (페이지네이션) |
| `dodo addons create` | 애드온 생성을 위한 대시보드 열기 |
| `dodo addons info` | 특정 애드온의 세부정보 보기 |

### 환불

환불 정보를 조회합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo refund list` | 모든 환불 나열 (페이지네이션) |
| `dodo refund info` | 특정 환불의 세부정보 보기 |

### 체크아웃

체크아웃 세션을 생성합니다.

| 명령 | 설명 |
|---------|-------------|
| `dodo checkout new` | 새 체크아웃 세션을 생성하고 체크아웃 URL을 가져오기 |

체크아웃 명령은 최소 주소 수집, 반환 URL, 3D 보안 유지, 할인 코드 및 메타데이터를 포함한 고급 옵션을 지원합니다.

## 웹훅 테스트

CLI에는 개발 중 웹훅을 테스트하기 위한 두 가지 강력한 도구가 포함되어 있습니다: 로컬 서버로 실시간으로 테스트 웹훅을 전달하는 **리Listener**와 모든 엔드포인트로 모의 웹훅 페이로드를 보내는 **Trigger**입니다.

### 웹훅 청취

Dodo Payments에서 로컬 개발 서버로 실시간으로 웹훅을 전달합니다.

```bash
dodo wh listen
```

<Steps>
<Step title="로컬 엔드포인트 URL 입력">
  웹훅을 받을 로컬 URL을 제공합니다 (예: `http://localhost:3000/webhook`).
</Step>

<Step title="자동 설정">
  CLI는 Dodo Payments 계정에 웹훅 엔드포인트가 없으면 자동으로 생성한 다음, 실시간으로 이벤트를 수신하기 위해 WebSocket 연결을 엽니다.
</Step>

<Step title="수신 및 전달">
  웹훅 이벤트가 발생하면(테스트 결제, 구독 변경 등) CLI가 이를 수신하고, 이벤트 유형을 로그로 기록하며, 전체 요청과 헤더 및 본문을 로컬 엔드포인트로 전달합니다. 엔드포인트의 응답은 로그에 기록되고 다시 전송됩니다.
</Step>
</Steps>

<Warning>
웹훅 리스너는 **테스트 모드** API 키로만 작동합니다. `dodo wh listen`을 사용하기 전에 테스트 모드 키로 로그인했는지 확인하세요.
</Warning>

<Tip>
리스너는 로컬 엔드포인트로 전달할 때 원래 웹훅 헤더 (`webhook-id`, `webhook-signature`, `webhook-timestamp`)를 보존하므로, 서명 검증 로직을 테스트할 수 있습니다.
</Tip>

### 테스트 웹훅 트리거

모의 웹훅 페이로드를 아무 엔드포인트로 보내 빠르게 테스트합니다.

```bash
dodo wh trigger
```

다음 과정을 안내합니다:
1. 목적지 **엔드포인트 URL** 설정
2. 선택적으로 **비즈니스 ID**, **제품 ID** 및 **메타데이터** 구성
3. 대화형 메뉴에서 트리거할 특정 **이벤트** 선택
4. 모의 페이로드 전송 및 응답 보기

각 이벤트 후에 다른 이벤트를 선택하여 트리거하거나 종료할 수 있어 여러 이벤트 핸들러를 한 세션에서 쉽게 테스트할 수 있습니다.

<Warning>
트리거 도구는 웹훅 서명 없이 모의 페이로드를 전송합니다. 테스트 중에는 웹훅 핸들러에서 `unsafe_unwrap()`를 사용하여 대신 `unwrap()`를 사용하여 웹훅 서명 검증을 비활성화하세요.
</Warning>

### 지원되는 웹훅 이벤트

| 카테고리 | 이벤트 |
|----------|--------|
| **구독** | `subscription.active`, `subscription.updated`, `subscription.on_hold`, `subscription.renewed`, `subscription.plan_changed`, `subscription.cancelled`, `subscription.failed`, `subscription.expired` |
| **결제** | `payment.success`, `payment.failed`, `payment.processing`, `payment.cancelled` |
| **환불** | `refund.success`, `refund.failed` |
| **분쟁** | `dispute.opened`, `dispute.expired`, `dispute.accepted`, `dispute.cancelled`, `dispute.challenged`, `dispute.won`, `dispute.lost` |
| **라이센스** | `licence.created` |

### 환경 변수

| 변수 | 설명 |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | `dodo wh listen`에서 사용되는 기본 웹훅 릴레이 서버 URL을 재정의합니다 |
