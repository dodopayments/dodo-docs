## 미터 생성

미터는 결제를 위해 사용량 이벤트를 집계하고 측정하는 방식을 정의합니다.

미터를 생성하기 전에 사용량 추적 전략을 계획하세요:
- 추적할 사용량 이벤트를 식별합니다
- 이벤트를 집계할 방식을 결정합니다(개수, 합계 등)
- 특정 사용 사례에 필요한 필터링 요구 사항을 정의합니다

### 단계별 미터 생성

다음 종합 가이드에 따라 사용량 미터를 설정하세요:

<Steps>
<Step title="Configure Basic Information">
미터의 기본 정보를 설정합니다.

<ParamField path="Meter Name" type="string" required>
이 미터가 추적하는 대상을 식별할 수 있도록 명확하고 설명적인 이름을 선택합니다.

예: "토큰", "API Calls", "Storage Usage", "Compute Hours"
</ParamField>

<ParamField path="Description" type="string">
이 미터가 측정하는 항목을 자세히 설명합니다.

예: "고객이 보낸 각 POST /v1/orders 요청을 계산합니다"
</ParamField>

<ParamField path="Event Name" type="string" required>
이 미터를 트리거할 이벤트 식별자를 지정합니다.

예: "token", "api.call", "storage.usage", "compute.session"
</ParamField>

<Info>
이벤트 이름은 사용량 이벤트로 전송하는 값과 정확히 일치해야 합니다. 이벤트 이름은 대소문자를 구분합니다.
</Info>
</Step>

<Step title="Configure Aggregation Settings">
미터가 이벤트에서 사용량을 계산하는 방식을 정의합니다.

<ParamField path="Aggregation Type" type="string" required>
이벤트를 집계할 방식을 선택합니다:

<Tabs>
<Tab title="Count">
수신한 이벤트 수를 단순히 계산합니다.

사용 사례: API calls, page views, file uploads

계산: 총 이벤트 수
</Tab>

<Tab title="Sum">
이벤트의 특정 속성에 있는 값을 합산합니다.

사용 사례: 데이터 전송, 스토리지 사용량, 처리 시간

계산: 모든 속성 값의 합계
</Tab>

<Tab title="Max">
결제 기간 동안 특정 속성에서 관찰된 최댓값을 기록합니다.

사용 사례: 최대 동시 사용자 수, 최대 스토리지 사용량, 최고 대역폭

계산: 관찰된 최대 속성 값
</Tab>

<Tab title="Last">
특정 속성의 가장 최근 값을 사용합니다.

사용 사례: 현재 플랜 등급, 최신 구성 설정

계산: 마지막으로 기록된 속성 값
</Tab>
</Tabs>
</ParamField>

<ParamField path="Over Property" type="string">
집계할 이벤트 메타데이터의 속성 이름입니다.

<Warning>
Sum, Max 또는 Last 집계 유형을 사용할 때 이 필드는 필수입니다.
</Warning>
</ParamField>

<ParamField path="Measurement Unit" type="string" required>
보고서와 결제 화면에 표시할 단위 레이블을 정의합니다.

예: "calls", "GB", "hours", "tokens"
</ParamField>
</Step>

<Step title="Configure Event Filtering (Optional)">
미터에 포함할 이벤트를 제어하는 기준을 설정합니다.

<Info>
이벤트 필터링을 사용하면 사용량 계산에 반영할 이벤트를 결정하는 정교한 규칙을 만들 수 있습니다. 테스트 이벤트를 제외하거나, 사용자 등급별로 필터링하거나, 특정 작업에 집중할 때 유용합니다.
</Info>

**이벤트 필터링 활성화**

조건부 이벤트 처리를 활성화하려면 **Enable Event Filtering**을 전환합니다.

**필터 로직 선택**

여러 조건을 평가할 방식을 선택합니다:

<Tabs>
<Tab title="AND Logic">
이벤트가 계산되려면 모든 조건이 true여야 합니다. 여러 엄격한 기준을 동시에 충족하는 이벤트가 필요한 경우 사용합니다.

**예:** `user_tier = "premium"` AND `endpoint = "/api/v2/users"`인 API calls 계산
</Tab>

<Tab title="OR Logic">
이벤트가 계산되려면 하나 이상의 조건이 true여야 합니다. 여러 기준 중 하나라도 충족하는 이벤트를 포함하려는 경우 사용합니다.

**예:** `method = "POST"` OR `method = "PUT"` OR `method = "DELETE"`인 이벤트 계산
</Tab>
</Tabs>

**필터 조건 설정**

<Steps>
<Step title="Add Condition">
새 필터 규칙을 만들려면 **Add condition**을 클릭합니다.
</Step>

<Step title="Configure Property Key">
이벤트 메타데이터의 속성 이름을 지정합니다.
</Step>

<Step title="Select Comparator">
사용 가능한 연산자 중에서 선택합니다:
- `equals` - 정확히 일치
- `not_equals` - 제외 필터
- `greater_than` - 숫자 비교  
- `greater_than_or_equals` - 숫자 비교(포함)
- `less_than` - 숫자 비교
- `less_than_or_equals` - 숫자 비교(포함)
- `contains` - 문자열에 하위 문자열 포함
- `does_not_contain` - 문자열 제외 필터
</Step>

<Step title="Set Comparison Value">
비교할 대상 값을 설정합니다.
</Step>

<Step title="Add Groups">
복잡한 로직을 위해 추가 조건 그룹을 만들려면 **Add Group**을 사용합니다.
</Step>
</Steps>

<Warning>
조건이 정상적으로 작동하려면 필터링된 속성이 이벤트 메타데이터에 포함되어야 합니다. 필수 속성이 없는 이벤트는 계산에서 제외됩니다.
</Warning>
</Step>

<Step title="Create Meter">
미터 구성을 검토하고 **Create Meter**를 클릭합니다.

<Check>
이제 미터가 사용량 이벤트를 수신하고 집계할 준비가 되었습니다.
</Check>

</Step>
</Steps>

## 제품에 미터 연결

미터를 생성한 후에는 사용량 기반 결제를 활성화하기 위해 제품에 연결해야 합니다. 이 과정에서 미터의 사용량 데이터가 고객 결제를 위한 가격 규칙과 연결됩니다.

미터를 제품에 연결하면 사용량 추적과 결제가 연동됩니다:
- 제품은 가격 규칙과 결제 동작을 정의합니다
- 미터는 결제 계산에 사용할 사용량 데이터를 제공합니다
- 복잡한 결제 시나리오에서는 여러 미터를 하나의 제품에 연결할 수 있습니다

### 제품 구성 과정

제품 설정을 올바르게 구성하여 사용량 데이터를 청구 가능한 요금으로 변환하세요:

<Steps>
<Step title="Choose Usage-Based Billing Product Type">
제품 생성 또는 편집 페이지로 이동하여 제품 유형으로 **Usage-Based**를 선택합니다.

</Step>

<Step title="Select Associated Meter">
측면에서 미터 선택 패널을 열려면 **Associated Meter**를 클릭합니다.

이 패널에서 이 제품의 사용량을 추적할 미터를 구성할 수 있습니다.
</Step>

<Step title="Add Your Meter">
미터 선택 패널에서 다음을 수행합니다:

1. 사용 가능한 미터를 보려면 **Add Meters**를 클릭합니다
2. 드롭다운 목록에서 생성한 미터를 선택합니다
3. 선택한 미터가 제품 구성에 표시됩니다

</Step>

<Step title="Configure Price Per Unit">
미터가 추적하는 각 사용량 단위의 가격을 설정합니다.

<ParamField path="Price Per Unit" type="number" required>
미터가 측정하는 각 단위에 부과할 금액을 정의합니다.

**예**: 단위당 `$0.50`로 설정하면 다음과 같습니다:
- 1,000 units consumed = 1,000 × $0.50 = 500.00 charged
- 500 units consumed = 500 × $0.50 = 250.00 charged
- 100 units consumed = 100 × $0.50 = 50.00 charged
</ParamField>

</Step>

<Step title="Set Free Threshold (Optional)">
결제가 시작되기 전에 무료 사용 한도를 설정합니다.

<ParamField path="Free Threshold" type="number">
유료 사용량 계산이 시작되기 전에 고객이 무료로 사용할 수 있는 단위 수입니다.

**작동 방식**:
- 무료 임계값: 100 units
- 단위당 가격: $0.50
- 고객 사용량: 250 units
- **계산**: (250 - 100) × $0.50 = **$75.00** charged
</ParamField>

<Info>
무료 임계값은 프리미엄 모델, 체험 기간 또는 플랜에 포함된 기본 한도를 고객에게 제공할 때 적합합니다.
</Info>

<Check>
무료 임계값은 각 결제 주기에 적용되므로 고객은 매월 또는 설정한 결제 일정에 따라 새로운 무료 한도를 받습니다.
</Check>
</Step>

<Step title="Save Configuration">
미터와 가격 구성을 검토한 다음 **Save Changes**를 클릭하여 설정을 완료합니다.

<Check>
이제 제품이 사용량 기반 결제에 맞게 구성되었으며 측정된 사용량에 따라 고객에게 자동으로 요금이 청구됩니다.
</Check>

**다음 단계**:
- 미터로 전송된 사용량 이벤트가 추적되고 집계됩니다
- 결제 계산에 가격 규칙이 자동으로 적용됩니다
- 각 결제 주기 동안 실제 사용량을 기준으로 고객에게 요금이 청구됩니다
</Step>
</Steps>

<Note>
제품당 최대 10개의 미터를 추가할 수 있습니다. 이를 통해 API calls, 스토리지, 컴퓨팅 시간 및 사용자 지정 지표와 같은 여러 차원에서 정교하게 사용량을 추적할 수 있습니다.
</Note>

## 사용량 이벤트 전송

미터를 구성한 후 애플리케이션에서 사용량 이벤트를 전송하여 고객 사용량을 추적할 수 있습니다.

### 이벤트 구조

각 사용량 이벤트에는 다음 필수 필드가 포함되어야 합니다:

<ParamField body="event_id" type="string" required>
이 특정 이벤트의 고유 식별자입니다. 모든 이벤트에서 고유해야 합니다.
</ParamField>

<ParamField body="customer_id" type="string" required>
이 사용량을 귀속할 Dodo Payments customer ID입니다.
</ParamField>

<ParamField body="event_name" type="string" required>
미터 구성과 일치하는 이벤트 이름입니다. 이벤트 이름이 적절한 미터를 트리거합니다.
</ParamField>

<ParamField body="timestamp" type="string">
이벤트가 발생한 시점의 ISO 8601 timestamp입니다. 제공하지 않으면 현재 시간으로 설정됩니다.
</ParamField>

<ParamField body="metadata" type="object">
필터링과 집계를 위한 추가 속성입니다. 미터의 "Over Property" 또는 필터링 조건에서 참조하는 값을 포함하세요.
</ParamField>

### 사용량 이벤트 API 예시

Events API를 사용하여 구성된 미터로 사용량 이벤트를 전송합니다:

<CodeGroup>

```javascript Node.js
const response = await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.DODO_PAYMENTS_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [
      {
        event_id: "api_call_1234",
        customer_id: "cus_atXa1lklCRRzMicTqfiw2", 
        event_name: "api.call",
        timestamp: new Date().toISOString(),
        metadata: {
          endpoint: "/v1/orders",
          method: "POST",
          response_size: 1024
        }
      }
    ]
  })
});
```

```python Python
import requests
from datetime import datetime

response = requests.post(
    'https://test.dodopayments.com/events/ingest',
    headers={
        'Authorization': f'Bearer {api_key}',
        'Content-Type': 'application/json'
    },
    json={
        'events': [
            {
                'event_id': 'api_call_1234',
                'customer_id': 'cus_atXa1lklCRRzMicTqfiw2',
                'event_name': 'api.call',
                'timestamp': datetime.now().isoformat(),
                'metadata': {
                    'endpoint': '/v1/orders',
                    'method': 'POST',
                    'response_size': 1024
                }
            }
        ]
    }
)
```

```curl cURL
curl -X POST 'https://test.dodopayments.com/events/ingest' \
  -H 'Authorization: Bearer YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "events": [
      {
        "event_id": "api_call_1234",
        "customer_id": "cus_atXa1lklCRRzMicTqfiw2",
        "event_name": "api.call", 
        "timestamp": "2024-01-15T10:30:00Z",
        "metadata": {
          "endpoint": "/v1/orders",
          "method": "POST",
          "response_size": 1024
        }
      }
    ]
  }'
```

</CodeGroup>

## 사용량 기반 결제 분석

종합 분석 대시보드에서 사용량 기반 결제 데이터를 모니터링하고 분석하세요. 고객 소비 패턴, 미터 성능 및 결제 추세를 추적하여 가격 전략을 최적화하고 사용량 패턴을 파악할 수 있습니다.

### 개요 분석

Overview 탭에서는 사용량 기반 결제 성과를 종합적으로 확인할 수 있습니다:

#### 활동 지표

다양한 기간에 걸쳐 주요 사용량 통계를 추적합니다:

<ParamField path="Current Month" type="metric">
현재 결제 기간의 사용량 활동을 표시하여 월별 소비 패턴을 파악할 수 있도록 합니다.
</ParamField>

<ParamField path="All Time" type="metric">
추적을 시작한 이후의 누적 사용량 통계를 표시하여 장기적인 성장 인사이트를 제공합니다.
</ParamField>

<Tip>
기간 선택기를 사용하여 여러 달의 사용량을 비교하고 계절적 추세나 성장 패턴을 식별합니다.
</Tip>

#### 미터 수량 차트

<Frame>
<img src="/images/guides/usage-based-billing/meter-quantities-chart.png" alt="보라색 그라데이션으로 시간에 따른 사용량 추세를 보여주는 미터 수량 차트" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

미터 수량 차트는 다음 기능을 통해 시간에 따른 사용량 추세를 시각화합니다:

- **시계열 시각화**: 일, 주 또는 월별 사용량 패턴 추적
- **여러 미터 지원**: 여러 미터의 데이터를 동시에 확인
- **추세 분석**: 사용량 급증, 패턴 및 성장 추세 식별

<Info>
차트는 사용량과 선택한 기간에 따라 자동으로 크기를 조정하여 작은 변동부터 큰 사용량 변화까지 명확하게 확인할 수 있도록 합니다.
</Info>

Events 탭에서는 개별 사용량 이벤트를 세부적으로 확인할 수 있습니다:

#### 이벤트 정보 표시

이벤트 테이블에는 다음 열을 통해 개별 사용량 이벤트가 명확하게 표시됩니다:

- **Event Name**: 사용량 이벤트를 생성한 특정 작업 또는 트리거
- **Event ID**: 각 이벤트 인스턴스의 고유 식별자
- **Customer ID**: 이벤트와 연결된 고객
- **Timestamp**: 이벤트가 발생한 시점

이 화면에서 고객 전체의 개별 사용량 이벤트를 추적하고 모니터링하여 결제 계산과 사용량 패턴을 투명하게 확인할 수 있습니다.
</Info>

## 집계 예시

다음은 다양한 집계 유형의 작동 방식에 대한 실제 예시입니다:

### 집계 유형 이해

집계 유형마다 적합한 결제 시나리오가 다릅니다. 사용량을 측정하고 요금을 부과하려는 방식에 따라 적절한 유형을 선택하세요.

### 실제 구현 예시

다음 예시는 샘플 이벤트와 예상 결과를 통해 각 집계 유형의 실제 적용 사례를 보여줍니다.

<AccordionGroup>
<Accordion title="Count Aggregation - API Calls">
시나리오: 총 API requests 수 추적

미터 구성:
- Event Name: `api.call`
- Aggregation Type: Count
- Measurement Unit: `calls`

**샘플 이벤트**:

```json
{
  "events": [
    {"event_id": "call_1", "customer_id": "cus_123", "event_name": "api.call"},
    {"event_id": "call_2", "customer_id": "cus_123", "event_name": "api.call"},
    {"event_id": "call_3", "customer_id": "cus_123", "event_name": "api.call"}
  ]
}
```

결과: 고객에게 3 calls가 청구됨
</Accordion>

<Accordion title="Sum Aggregation - Data Transfer">
시나리오: 전송된 총 bytes를 기준으로 청구

미터 구성:
- Event Name: `data.transfer`
- Aggregation Type: Sum
- Over Property: `bytes`
- Measurement Unit: `GB`

**샘플 이벤트**:

```json
{
  "events": [
    {
      "event_id": "transfer_1",
      "customer_id": "cus_123", 
      "event_name": "data.transfer",
      "metadata": {"bytes": 1073741824}
    },
    {
      "event_id": "transfer_2",
      "customer_id": "cus_123",
      "event_name": "data.transfer", 
      "metadata": {"bytes": 536870912}
    }
  ]
}
```

결과: 고객에게 총 1.5 GB 전송량이 청구됨
</Accordion>

<Accordion title="Max Aggregation - Peak Concurrent Users">
시나리오: 최대 동시 사용자 수를 기준으로 청구

미터 구성:
- Event Name: `concurrent.users`
- Aggregation Type: Max
- Over Property: `count`
- Measurement Unit: `users`

**샘플 이벤트**:

```json
{
  "events": [
    {
      "event_id": "peak_1",
      "customer_id": "cus_123",
      "event_name": "concurrent.users", 
      "metadata": {"count": 15}
    },
    {
      "event_id": "peak_2",
      "customer_id": "cus_123",
      "event_name": "concurrent.users",
      "metadata": {"count": 23}
    },
    {
      "event_id": "peak_3",
      "customer_id": "cus_123",
      "event_name": "concurrent.users",
      "metadata": {"count": 18}
    }

}
```

결과: 고객에게 최대 동시 사용자 23명이 청구됨
</Accordion>

### 이벤트 필터링 예시

<Tabs>
<Tab title="Filter by API Endpoint">
특정 endpoint에 대한 API calls만 계산합니다:

필터 구성:
- Property: `endpoint`
- Comparator: `equals`
- Value: `/v1/orders`

샘플 이벤트:

```json
{
  "event_id": "call_1",
  "customer_id": "cus_123",
  "event_name": "api.call",
  "metadata": {
    "endpoint": "/v1/orders",
    "method": "POST"
  }
}
```

결과: 필터 기준과 일치하는 이벤트가 계산됩니다. 다른 endpoint의 이벤트는 무시됩니다.
</Tab>

<Tab title="Filter by Value Range">
대용량 file uploads만 계산합니다:

필터 구성:
- Property: `file_size`
- Comparator: `greater_than`
- Value: `1048576` (bytes 기준 1MB)

샘플 이벤트:

```json
{
  "event_id": "upload_1",
  "customer_id": "cus_123", 
  "event_name": "file.upload",
  "metadata": {
    "file_size": 5242880,
    "file_type": "image"
  }
}
```

결과: 1MB보다 큰 파일이 계산됩니다. 더 작은 파일은 무시됩니다.
</Tab>

<Tab title="Complex Multi-Condition Filters">
영업 시간 동안 premium API calls를 계산합니다:

필터 구성(AND 로직 사용):
- Property: `plan_type`, Comparator: `equals`, Value: `premium`
- Property: `hour`, Comparator: `greater_than_or_equals`, Value: `9`
- Property: `hour`, Comparator: `less_than`, Value: `17`

샘플 이벤트:

```json
{
  "event_id": "call_1",
  "customer_id": "cus_123",
  "event_name": "api.call",
  "metadata": {
    "plan_type": "premium",
    "hour": 14,
    "endpoint": "/v1/analytics"
  }
}
```

결과: 영업 시간(오전 9시~오후 5시) 동안의 premium API calls가 계산됩니다.
</Tab>
</Tabs>

## 문제 해결

사용량 기반 결제 구현에서 발생하는 일반적인 문제를 해결하고 정확한 추적 및 결제를 보장합니다.

### 일반적인 문제

사용량 기반 결제 문제는 대부분 다음 범주에 해당합니다:
- 이벤트 전달 및 처리 문제
- 미터 구성 문제
- 데이터 유형 및 형식 오류
- Customer ID 및 인증 문제

### 디버깅 단계

사용량 기반 결제 문제를 해결할 때:
1. Events 분석 탭에서 이벤트 전달을 확인합니다
2. 미터 구성이 이벤트 구조와 일치하는지 확인합니다
3. Customer ID와 API 인증을 검증합니다
4. 필터링 조건과 집계 설정을 검토합니다

### 해결 방법

<AccordionGroup>
<Accordion title="Events not showing in meter">
일반적인 원인:
- 이벤트 이름이 미터 구성과 정확히 일치하지 않음
- 이벤트 필터링 조건이 이벤트를 제외함
- Customer ID가 Dodo Payments account에 존재하지 않음
- 이벤트 timestamp가 현재 결제 기간을 벗어남

해결 방법:
- 이벤트 이름의 철자와 대소문자 구분을 확인합니다
- 필터링 조건을 검토하고 테스트합니다
- Customer ID가 유효하고 활성 상태인지 확인합니다
- 이벤트 timestamp가 최신이며 올바르게 형식화되었는지 확인합니다
</Accordion>

<Accordion title="Aggregation not working as expected">
일반적인 원인:
- Over Property 이름이 이벤트 메타데이터 키와 일치하지 않음
- 메타데이터 값의 데이터 유형이 잘못됨(string과 number 간 불일치)
- 필수 메타데이터 속성이 누락됨

해결 방법:
- 메타데이터 키가 Over Property 설정과 정확히 일치하는지 확인합니다
- 이벤트에서 문자열 숫자를 실제 숫자로 변환합니다
- 모든 이벤트에 필수 속성을 포함합니다
</Accordion>

<Accordion title="Filtering not working">
일반적인 원인:
- 필터 속성 이름이 이벤트 메타데이터와 일치하지 않음
- 데이터 유형에 맞지 않는 comparator 사용(string과 number 간 불일치)
- 문자열 비교에서 대소문자를 구분함

해결 방법:
- 속성 이름이 정확히 일치하는지 다시 확인합니다
- 데이터 유형에 적합한 comparator를 사용합니다
- 문자열을 필터링할 때 대소문자 구분을 고려합니다
</Accordion>
</AccordionGroup>
