## 사전 요구 사항

Dodo Payments API를 통합하려면 다음이 필요합니다:
- Dodo Payments merchant 계정
- 대시보드의 API Credentials (API key 및 webhook secret key)

## 대시보드 설정

1. [Dodo Payments Dashboard](https://app.dodopayments.com/)로 이동합니다.

2. 제품을 생성합니다(일회성 결제 또는 subscription). Subscription 제품의 가격은 최소 **$1**(또는 선택한 통화로 이에 상응하는 금액)이어야 하며, 이 최소 금액보다 낮은 금액은 지원되지 않습니다.

4. API key를 생성합니다:
   - Developer > API로 이동합니다.
   - [자세한 가이드](/api-reference/introduction#api-key-generation)
   - 환경 변수 DODO_PAYMENTS_API_KEY에 있는 API key를 복사합니다.

5. webhooks를 구성합니다:
   - Developer > Webhooks로 이동합니다.
   - 결제 알림을 위한 webhook URL을 생성합니다.
   - 환경 변수에 있는 webhook secret key를 복사합니다.

## 통합

### Payment Links

사용 사례에 적합한 통합 경로를 선택합니다:
- **Checkout Sessions (권장)**: 대부분의 통합에 가장 적합합니다. 서버에서 session을 생성한 다음 고객을 안전하게 호스팅된 checkout으로 리디렉션합니다.
- **Overlay Checkout**: 사이트에서 modal overlay로 checkout을 열어 페이지 내 경험을 제공해야 할 때 사용합니다.
- **Inline Checkout**: 완전히 통합되고 브랜드에 맞는 checkout 경험을 위해 checkout을 페이지 레이아웃에 직접 삽입합니다.
- **Static Payment Links**: 빠르게 결제를 수집할 수 있는 코드 없는 즉시 공유 가능한 URL입니다.
- **Dynamic Payment Links**: 프로그래밍 방식으로 생성되는 link입니다. 하지만 Checkout Sessions가 더 유연하며 권장됩니다.

#### 1. Checkout Sessions

Checkout Sessions를 사용하면 일회성 결제 또는 subscription을 위한 안전한 호스팅 checkout 경험을 만들 수 있습니다. 서버에서 session을 생성한 다음 고객을 반환된 `checkout_url`로 리디렉션합니다.

<Info>
Checkout sessions는 기본적으로 24시간 동안 유효합니다. <code>confirm=true</code>를 전달하면 session은 15분 동안 유효하며 모든 필수 필드를 제공해야 합니다.
</Info>

<Steps>
<Step title="Create a checkout session">
  원하는 SDK를 선택하거나 REST API를 호출합니다.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'prod_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python

  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "prod_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

<Step title="Redirect customer to checkout">
  session을 생성한 후 `checkout_url`로 리디렉션하여 호스팅된 flow를 시작합니다.


결제를 가장 빠르고 안정적으로 시작하려면 Checkout Sessions를 사용하세요. 고급 사용자 지정을 위해 전체 <a href="/developer-resources/checkout-session">Checkout Sessions 가이드</a>와 <a href="/api-reference/checkout-sessions/create">API Reference</a>를 참조하세요.

#### 2. Overlay Checkout

원활한 페이지 내 checkout 경험을 제공하려면 고객이 웹사이트를 떠나지 않고 결제를 완료할 수 있는 [Overlay Checkout](/developer-resources/overlay-checkout) 통합을 확인하세요.

#### 3. Inline Checkout

페이지에 직접 삽입되는 완전히 통합된 checkout 경험을 제공하려면 [Inline Checkout](/developer-resources/inline-checkout) 통합을 사용하세요. 이를 통해 사용자 지정 주문 요약을 만들고 checkout 레이아웃을 완전히 제어할 수 있으며, Dodo Payments가 결제 수집을 안전하게 처리합니다.

#### 4. Static Payment Links

Static payment links를 사용하면 간단한 URL을 공유하여 빠르게 결제를 받을 수 있습니다. query parameters를 전달하여 고객 정보를 미리 입력하고, form fields를 제어하며, 사용자 지정 metadata를 추가하는 방식으로 checkout 경험을 사용자 지정할 수 있습니다.

<Steps>
<Step title="Construct your payment link">
  기본 URL로 시작하고 product ID를 추가합니다:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  필수 query parameters를 포함합니다:
  - <ParamField query="quantity" type="integer" default="1">구매할 항목 수입니다.</ParamField>
  - <ParamField query="redirect_url" type="string" required>결제 완료 후 리디렉션할 URL입니다.</ParamField>
  <Note>
  리디렉션 URL에는 결제 세부 정보가 query parameters로 포함됩니다. 예:
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  제품에서 license keys가 활성화된 경우 `license_key` parameter도 추가됩니다(여러 key의 경우 쉼표로 구분):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  checkout을 간소화하려면 customer 또는 billing fields를 query parameters로 추가합니다.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">고객의 전체 이름입니다(firstName 또는 lastName이 제공되면 무시됨).</ParamField>
      - <ParamField query="firstName" type="string">고객의 이름입니다.</ParamField>
      - <ParamField query="lastName" type="string">고객의 성입니다.</ParamField>
      - <ParamField query="email" type="string">고객의 이메일 주소입니다.</ParamField>
      - <ParamField query="country" type="string">고객의 국가입니다.</ParamField>
      - <ParamField query="addressLine" type="string">도로명 주소입니다.</ParamField>
      - <ParamField query="city" type="string">도시입니다.</ParamField>
      - <ParamField query="state" type="string">주 또는 도입니다.</ParamField>
      - <ParamField query="zipCode" type="string">우편번호/ZIP 코드입니다.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true 또는 false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  특정 fields를 비활성화하여 고객에게 읽기 전용으로 표시할 수 있습니다. 고객의 세부 정보가 이미 있는 경우(예: 로그인한 사용자) 유용합니다.
  </Info>
  field를 비활성화하려면 해당 값을 제공하고 대응하는 <code>disable...</code> flag를 <code>true</code>로 설정합니다:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Field         | Disable Flag         | Required Parameter |
      |---------------|---------------------|-------------------|
      | Full Name     | `disableFullName`   | `fullName`        |
      | First Name    | `disableFirstName`  | `firstName`       |
      | Last Name     | `disableLastName`   | `lastName`        |
      | Email         | `disableEmail`      | `email`           |
      | Country       | `disableCountry`    | `country`         |
      | Address Line  | `disableAddressLine`| `addressLine`     |
      | City          | `disableCity`       | `city`            |
      | State         | `disableState`      | `state`           |
      | ZIP Code      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  fields를 비활성화하면 실수로 변경되는 것을 방지하고 데이터 일관성을 보장하는 데 도움이 됩니다.
  </Tip>
  <Note>
  <code>showDiscounts=false</code>로 설정하면 checkout form의 discounts section이 비활성화되고 숨겨집니다. checkout 중 고객이 coupon 또는 promo codes를 입력하지 못하게 하려는 경우 사용하세요.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">결제 통화를 지정합니다. 기본값은 billing 국가의 통화입니다.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">통화 선택기를 표시하거나 숨깁니다.</ParamField>
  - <ParamField query="paymentAmount" type="integer">센트 단위 금액입니다(Pay What You Want pricing만 해당).</ParamField>
  - <ParamField query="metadata_*" type="string">사용자 지정 metadata fields입니다(예: <code>metadata_orderId=123</code>).</ParamField>
</Step>
<Step title="Share the link">
  완성된 payment link를 고객에게 보냅니다. 고객이 방문하면 모든 query parameters가 수집되어 session ID와 함께 저장됩니다. 그런 다음 URL은 session parameter만 포함하도록 단순화됩니다(예: <code>?session=sess_1a2b3c4d</code>). 저장된 정보는 페이지를 새로 고쳐도 유지되며 checkout process 전체에서 액세스할 수 있습니다.
  <Check>
  이제 고객의 checkout 경험은 제공한 parameters를 바탕으로 간소화되고 개인화됩니다.
  </Check>
</Step>
</Steps>

#### 4. Dynamic Payment Links
<Tip>

</Tip>

고객 세부 정보와 함께 API call 또는 SDK를 통해 생성합니다. 예시는 다음과 같습니다:

    ```javascript
import { NextRequest, NextResponse } from "next/server";      

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    const { formData, cartItems } = paymentRequestSchema.parse(body);

    const response = await fetch(`${process.env.NEXT_PUBLIC_DODO_TEST_API}/payments`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${process.env.DODO_API_KEY}`, // Replace with your API secret key generated from the Dodo Payments Dashboard
      },
      body: JSON.stringify({
        billing: {
          city: formData.city,
          country: formData.country,
          state: formData.state,
          street: formData.addressLine,
          zipcode: parseInt(formData.zipCode),
        },
        customer: {
          email: formData.email,
          name: `${formData.firstName} ${formData.lastName}`,
          phone_number: formData.phoneNumber || undefined,
        },
        payment_link: true,
        product_cart: cartItems.map((id) => ({
          product_id: id,
          quantity: 1,
        })),
        return_url: process.env.NEXT_PUBLIC_RETURN_URL,
      }),
    });

    if (!response.ok) {
      const errorData = await response.json().catch(() => null);
      return NextResponse.json(
        { error: "Payment link creation failed", details: errorData },
        { status: response.status }
      );
    }

    const data = await response.json();
    return NextResponse.json({ paymentLink: data.payment_link });
  } catch (err) {
    console.error("Payment error:", err);
    return NextResponse.json(
      {
        error: err instanceof Error ? err.message : "An unknown error occurred",
      },
      { status: 500 }
    );
  }
}
```

### Webhooks 구현

결제 알림을 수신할 API endpoint를 설정합니다. 다음은 Next.js를 사용한 예시입니다:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

webhook 구현은 [Standard Webhooks](https://standardwebhooks.com/) specification을 따릅니다. webhook type definitions는 [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide)를 참조하세요.

Next.js와 TypeScript를 사용한 demo implementation이 포함된 이 project를 [GitHub](https://github.com/dodopayments/dodo-checkout-demo)에서 참조할 수 있습니다.

실제 구현은 [여기](https://atlas.dodopayments.com/)에서 확인할 수 있습니다.
