## 사전 요구 사항

Dodo Payments API를 통합하려면 다음이 필요합니다:
- Dodo Payments merchant 계정
- 대시보드의 API Credentials (API key 및 webhook secret key)

## 대시보드 설정

1. [Dodo Payments Dashboard](https://app.dodopayments.com/)로 이동합니다.

2. 제품을 생성합니다(일회성 결제 또는 구독).
구독 제품의 가격은 최소 **\$1**(또는 선택한 통화로 이에 상응하는 금액)이어야 합니다. 이 최소 금액보다 낮은 금액은 지원되지 않습니다.

4. API key를 생성합니다:
   - Developer > API로 이동합니다.
   - [자세한 가이드](/api-reference/introduction#api-key-generation)
   - 환경 변수 DODO_PAYMENTS_API_KEY에 있는 API key를 복사합니다.

5. webhooks를 구성합니다:
   - Developer > Webhooks로 이동합니다.
   - 결제 알림을 위한 webhook URL을 생성합니다.
   - 환경 변수에 있는 webhook secret key를 복사합니다.

## 통합

### Payment Links

사용 사례에 적합한 통합 경로를 선택하세요:
- **Checkout Sessions(권장)**: 대부분의 통합에 가장 적합합니다. 서버에서 세션을 생성한 후 고객을 안전하게 호스팅된 결제 페이지로 리디렉션합니다.
- **Overlay Checkout**: 사이트에서 결제를 모달 오버레이로 열어 페이지 내 환경을 제공해야 할 때 사용합니다.
- **Inline Checkout**: 완전히 통합되고 브랜드가 적용된 결제 환경을 위해 결제 페이지를 레이아웃에 직접 삽입합니다.
- **Static Payment Links**: 빠르게 결제를 수집할 수 있는 코드 없는 즉시 공유 가능한 URL입니다.
- **Dynamic Payment Links**: 프로그래밍 방식으로 생성되는 링크입니다. 하지만 더 높은 유연성을 제공하는 Checkout Sessions 사용을 권장합니다.
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**: 네이티브 Android, iOS, React Native 및 Flutter 앱용입니다. 위와 같이 서버에서 세션을 생성한 다음 `checkout_url`를 SDK에 전달합니다.

<Info>
Overlay 및 Inline Checkout은 브라우저 전용입니다. 웹 페이지에 결제 페이지를 삽입합니다. 네이티브 모바일 앱을 개발하는 경우 서버에서 결제 세션을 생성하고 대신 [Mobile Checkout SDKs](/developer-resources/mobile-integration)를 사용해 엽니다.
</Info>

#### 1. Checkout Sessions

Checkout Sessions를 사용하면 일회성 결제 또는 구독을 위한 안전한 호스팅 결제 환경을 만들 수 있습니다. 서버에서 세션을 생성한 다음 반환된 `checkout_url`로 고객을 리디렉션합니다.

<Info>
Checkout 세션은 기본적으로 24시간 동안 유효합니다. <code>confirm=true</code>를 전달하면 세션은 15분 동안 유효하며 모든 필수 필드를 제공해야 합니다.
</Info>

<Steps>
<Step title="Create a checkout session">

#### 2. Overlay Checkout

원활한 페이지 내 결제 환경을 위해 고객이 웹사이트를 떠나지 않고 결제를 완료할 수 있는 [Overlay Checkout](/developer-resources/overlay-checkout) 통합을 살펴보세요.

#### 3. Inline Checkout

페이지에 직접 삽입되는 완전히 통합된 결제 환경을 제공하려면 [Inline Checkout](/developer-resources/inline-checkout) 통합을 사용하세요. 이를 통해 사용자 지정 주문 요약을 만들고 결제 레이아웃을 완전히 제어할 수 있으며, Dodo Payments가 결제 수집을 안전하게 처리합니다.

#### 4. Static Payment Links

Static payment links를 사용하면 간단한 URL을 공유하여 빠르게 결제를 받을 수 있습니다. query parameters를 전달하여 고객 정보를 미리 입력하고, 양식 필드를 제어하며, 사용자 지정 메타데이터를 추가하는 방식으로 결제 환경을 사용자 지정할 수 있습니다.

<Steps>
<Step title="Construct your payment link">
  기본 URL로 시작한 다음 제품 ID를 추가합니다:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  필수 query parameters를 포함합니다:
  - <ParamField query="quantity" type="integer" default="1">구매할 항목 수입니다.</ParamField>
  - <ParamField query="redirect_url" type="string" required>결제 완료 후 리디렉션할 URL입니다.</ParamField>
  <Note>
  리디렉션 URL에는 query parameters로 결제 세부 정보가 포함됩니다. 예:
  <br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  제품에 라이선스 키가 활성화되어 있으면 `license_key` parameter도 추가됩니다(여러 키의 경우 쉼표로 구분):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  결제를 간소화하려면 고객 또는 청구 필드를 query parameters로 추가합니다.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">고객의 전체 이름입니다(firstName 또는 lastName이 제공되면 무시됨).</ParamField>
      - <ParamField query="firstName" type="string">고객의 이름입니다.</ParamField>
      - <ParamField query="lastName" type="string">고객의 성입니다.</ParamField>
      - <ParamField query="email" type="string">고객의 이메일 주소입니다.</ParamField>
      - <ParamField query="country" type="string">고객의 국가입니다.</ParamField>
      - <ParamField query="addressLine" type="string">도로명 주소입니다.</ParamField>
      - <ParamField query="city" type="string">도시입니다.</ParamField>
      - <ParamField query="state" type="string">주 또는 도입니다.</ParamField>
      - <ParamField query="zipCode" type="string">우편번호/ZIP 코드입니다.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true 또는 false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  특정 필드를 비활성화하여 고객이 읽기 전용으로 사용하도록 설정할 수 있습니다. 이는 이미 고객 정보(예: 로그인한 사용자)를 보유하고 있을 때 유용합니다.
  </Info>
  필드를 비활성화하려면 값을 제공하고 해당 <code>disable...</code> flag를 <code>true</code>로 설정합니다:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | 필드         | 비활성화 Flag         | 필수 Parameter |
      |---------------|---------------------|-------------------|
      | 전체 이름     | `disableFullName`   | `fullName`        |
      | 이름    | `disableFirstName`  | `firstName`       |
      | 성    | `disableLastName`   | `lastName`        |
      | 이메일         | `disableEmail`      | `email`           |
      | 국가       | `disableCountry`    | `country`         |
      | 주소 입력란  | `disableAddressLine`| `addressLine`     |
      | 도시          | `disableCity`       | `city`            |
      | 주/도         | `disableState`      | `state`           |
      | ZIP 코드      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  필드를 비활성화하면 실수로 변경되는 것을 방지하고 데이터 일관성을 유지할 수 있습니다.
  </Tip>
  <Note>
  <code>showDiscounts=false</code>를 설정하면 결제 양식의 할인 섹션이 비활성화되고 숨겨집니다. 결제 중 고객이 coupon 또는 promo code를 입력하지 못하게 하려는 경우 사용하세요.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">결제 통화를 지정합니다. 기본값은 청구 국가의 통화입니다.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">통화 선택기를 표시하거나 숨깁니다.</ParamField>
  - <ParamField query="paymentAmount" type="number">청구 금액을 주요 통화 단위로 고정합니다(예: $12.50의 경우 <code>12.5</code>). Pay What You Want 제품에만 적용됩니다. 제품의 최소 가격보다 낮으면 이 값은 무시됩니다.</ParamField>
  - <ParamField query="metadata_*" type="string">사용자 지정 메타데이터 필드(예: <code>metadata_orderId=123</code>).</ParamField>

  <Warning>
  결제 링크의 `paymentAmount`는 Checkout Sessions API의 `amount` 필드와 동일한 단위가 **아닙니다**. 링크 매개변수는 주요 통화 단위를 사용합니다(`12.5` = $12.50). 반면 API의 `product_cart[].amount`는 가장 작은 액면 단위를 사용합니다(`1250` = $12.50). API 필드에 대한 자세한 내용은 [Dynamic Pricing](/developer-resources/dynamic-pricing-checkout)을 참조하세요.
  </Warning>
</Step>
<Step title="Share the link">
  완성된 결제 링크를 고객에게 전송합니다. 고객이 링크를 방문하면 모든 쿼리 매개변수가 수집되어 세션 ID와 함께 저장됩니다. 그런 다음 URL은 세션 매개변수만 포함하도록 단순화됩니다(예: <code>?session=sess_1a2b3c4d</code>). 저장된 정보는 페이지를 새로 고침해도 유지되며 checkout 전체에서 액세스할 수 있습니다.
  <Check>
  이제 고객의 매개변수에 따라 checkout 환경이 간소화되고 개인화됩니다.
  </Check>
</Step>
</Steps>

      {
        error: err instanceof Error ? err.message : "An unknown error occurred",
      },
      { status: 500 }
    );
  }

### Webhooks 구현

결제 알림을 수신할 API 엔드포인트를 설정합니다. 다음은 Next.js를 사용하는 예시입니다:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

당사의 webhook 구현은 [Standard Webhooks](https://standardwebhooks.com/) 사양을 따릅니다. webhook 유형 정의는 [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide)를 참조하세요.

#### 수신할 이벤트

`payload.type`을 활성화하고 일회성 결제 흐름과 관련된 이벤트를 처리합니다. 최소한 다음 이벤트를 수신해야 합니다:

| Event Type           | When it fires                                              | What to do                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | 결제가 성공적으로 처리됩니다.                        | 주문을 이행합니다 — 액세스 권한을 부여하고, 제품을 프로비저닝하며, 영수증을 전송합니다. |
| `payment.failed`     | 결제 시도가 실패합니다(카드 거절, 오류 등).       | 고객에게 알리고 재시도를 요청합니다. 이행하지 마세요.                    |
| `payment.processing` | 결제가 승인되었지만 아직 처리 중입니다(비동기 방식). | 최종 `payment.succeeded`/`payment.failed`을 기다립니다 — 아직 이행하지 마세요. |
| `payment.cancelled`  | 완료 전에 결제가 취소됩니다.                   | 보류 중인 상태를 해제하고 주문을 abandoned로 표시합니다.                       |

<Tip>
항상 브라우저 리디렉션이 아니라 **webhook의 `payment.succeeded`에서 이행**하세요. 고객이 탭을 닫으면 리디렉션을 놓칠 수 있지만, webhook은 승인될 때까지 재시도됩니다.
</Tip>

라이선스 키가 필요한 디지털 제품을 판매하는 경우 `license_key.created`도 처리하세요. 구독, entitlement, credit, recovery, dunning 이벤트를 포함한 전체 이벤트 목록은 [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide)를 참조하세요.

Next.js와 TypeScript를 사용한 데모 구현이 포함된 이 프로젝트는 [GitHub](https://github.com/dodopayments/dodo-checkout-demo)에서 참조할 수 있습니다.

실제 구현은 [여기](https://atlas.dodopayments.com/)에서 확인할 수 있습니다.

## Checkout 및 통화에 대해 알아야 할 주요 사항

<Warning>
**동적(Pay-What-You-Want) 금액은 임의의 현지 통화가 아니라 제품의 기본 통화로 표시됩니다** — 기본 통화는 **USD, INR, GBP, EUR**로 제한됩니다. 다른 통화(예: PHP)로 고정 금액을 수금하려면 직접 전달할 수 없습니다. **Adaptive Pricing**(실시간 FX로 기본 금액을 변환) 또는 **Localized Pricing**(통화별 고정 가격이지만 Pay-What-You-Want와 호환되지 않음)을 사용하세요.
</Warning>

<Tip>
**통화를 명시적으로 설정하세요.** checkout session에서 `billing_currency` 및 `billing_address.country`을 전달합니다. 생략하면 고객의 IP(Adaptive Currency)를 기준으로 통화와 국가가 감지되므로 의도한 금액과 일치하지 않을 수 있습니다.
</Tip>

<Info>
**Checkout sessions는 24시간 후 만료됩니다**(`confirm: true`인 경우 15분). 또한 각 `checkout_url`은 **한 번만 사용할 수 있으므로**, 링크를 재사용하지 말고 고객별 및 결제 시도별로 새 session을 생성하세요.
</Info>

<Info>
**원클릭 재구매.** 저장된 결제 수단이 있는 기존 고객의 경우 `confirm: true`와 함께 `payment_method_id`을 전달하면 수단 선택을 완전히 건너뛰고 즉시 청구할 수 있습니다.
</Info>
