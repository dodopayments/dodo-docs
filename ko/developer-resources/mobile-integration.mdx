<Info>
Dodo Payments는 **Android, iOS, React Native 및 Flutter**용 공식 checkout SDK를 제공합니다. 각 SDK는 아래에 설명된 패턴(checkout
URL 열기, 반환값 캡처, 결과 파싱)을 단일 타입 지정 `start(...)`
호출 뒤에 래핑하며, abandoned-session recovery가 기본 제공됩니다. 사용 중인 스택에 맞는 SDK가 없는 경우에만 수동 WebView를 사용하세요.
</Info>

## 사전 요구 사항

Dodo Payments를 모바일 앱에 통합하기 전에 다음 항목을 준비했는지 확인하세요:

- **Dodo Payments 계정**: API access가 활성화된 merchant 계정
- **API Credentials**: 대시보드에서 발급한 API key 및 webhook secret key
- **Mobile App Project**: Android, iOS, React Native 또는 Flutter 애플리케이션
- **Backend Server**: checkout session을 안전하게 생성하기 위한 서버

## 통합 워크플로

모바일 통합은 backend에서 API 호출을 처리하고 모바일 앱에서 사용자 경험을 관리하는 안전한 4단계 프로세스를 따릅니다.

<Step title="Mobile: Get Checkout URL">

모바일 앱은 backend를 호출해 checkout URL을 가져옵니다. 이 요청은 로그인한 사용자의 고유 session token으로 인증하세요.

<Tabs>
<Tab title="iOS (Swift)">

```swift
func getCheckoutURL(productId: String, customerEmail: String, customerName: String) async throws -> String {
    let url = URL(string: "https://your-backend.com/api/create-checkout-session")!
    var request = URLRequest(url: url)
    request.httpMethod = "POST"
    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
    request.setValue("Bearer \(userSessionToken)", forHTTPHeaderField: "Authorization")
    
    let requestData: [String: Any] = [
        "productId": productId,
        "customerEmail": customerEmail,
        "customerName": customerName
    ]
    request.httpBody = try JSONSerialization.data(withJSONObject: requestData)
    
    let (data, _) = try await URLSession.shared.data(for: request)
    let response = try JSONDecoder().decode(CheckoutResponse.self, from: data)
    return response.checkout_url
}
```

</Tab>
<Tab title="Android (Kotlin)">

```kotlin
suspend fun getCheckoutURL(productId: String, customerEmail: String, customerName: String): String {
    val client = OkHttpClient()
    val requestBody = JSONObject().apply {
        put("productId", productId)
        put("customerEmail", customerEmail)
        put("customerName", customerName)
    }.toString().toRequestBody("application/json".toMediaType())
    
    val request = Request.Builder()
        .url("https://your-backend.com/api/create-checkout-session")
        .header("Authorization", "Bearer $userSessionToken")
        .post(requestBody)
        .build()
    
    val response = client.newCall(request).execute()
    val responseBody = response.body?.string()
    val jsonResponse = JSONObject(responseBody ?: "")
    return jsonResponse.getString("checkout_url")
}
```

</Tab>
<Tab title="React Native (JavaScript)">

```javascript
const getCheckoutURL = async (productId, customerEmail, customerName) => {
  try {
    const response = await fetch('https://your-backend.com/api/create-checkout-session', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${userSessionToken}`,
      },
      body: JSON.stringify({
        productId,
        customerEmail,
        customerName
      })
    });
    
    const data = await response.json();
    return data.checkout_url;
  } catch (error) {
    console.error('Failed to get checkout URL:', error);
    throw error;
  }
};
```

<Tab title="Flutter (Dart)">

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<String> getCheckoutUrl({
  required String productId,
  required String customerEmail,
  required String customerName,
}) async {
  final response = await http.post(
    Uri.parse('https://your-backend.com/api/create-checkout-session'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $userSessionToken',
    },
    body: jsonEncode({
      'productId': productId,
      'customerEmail': customerEmail,
      'customerName': customerName,
    }),
  );

  if (response.statusCode != 200) {
    throw Exception('Failed to get checkout URL: ${response.statusCode}');
  }
  return jsonDecode(response.body)['checkout_url'] as String;
}
```

## SDK 선택

모든 모바일 SDK는 동일한 contract를 제공합니다. 하나의 `start(...)` 호출로 플랫폼의 native browser surface에서 Dodo의
hosted checkout을 열고, 타입이 지정된 `CheckoutResult`를 반환합니다. 이 값의 `status`는 `succeeded`, `failed`, `cancelled`,
`pending` 또는 `expired`입니다. 어떤 SDK도 API key를 보유하거나 Dodo
Payments API를 호출하지 않으며, 네 SDK 모두 abandoned-session recovery를 지원합니다.

<CardGroup cols={2}>
<Card title="Android" icon="android" href="/developer-resources/sdks/android">
  `com.dodopayments.api:checkout-android`는 Chrome Custom Tab을 엽니다. `minSdk` 23이 필요합니다.
</Card>
<Card title="iOS" icon="apple" href="/developer-resources/sdks/ios">
  `dodopayments-mobile-sdk-ios`는 `SFSafariViewController`를 엽니다. iOS 16 이상이 필요합니다.
</Card>
<Card title="React Native" icon="react" href="/developer-resources/sdks/react-native">
  `@dodopayments/react-native-checkout`는 두 native core 위에서 동작하는 Turbo Module입니다. React Native 0.76 이상이 필요합니다.
</Card>
<Card title="Flutter" icon="layer-group" href="/developer-resources/sdks/flutter">
  `dodopayments_checkout`는 두 native core 위에서 동작하는 Pigeon channel입니다. Flutter 3.44 이상이 필요합니다.
</Card>
</CardGroup>

<Warning>
반환되는 `status`는 결제 증명이 아닌 UI hint입니다. 모든 결제는 backend에서 `payment.succeeded` / `subscription.active`
webhook을 통해 확인하거나 secret key로 payment를 조회해야 합니다.
</Warning>

### Callback URL Scheme 등록

네 SDK 모두 사용자가 선택한 custom URL scheme을 통해 제어권을 앱으로 돌려보냅니다. 예를 들어 `myapp://checkout/return`와 같이 설정할 수 있습니다. 플랫폼별로 한 번씩 등록하세요:

<Tabs>
<Tab title="Android">

```kotlin android/app/build.gradle
android {
    defaultConfig {
        manifestPlaceholders["dodoCallbackScheme"] = "myapp"
    }
}
```

SDK 자체의 manifest에는 redirect activity가 이미 선언되어 있으므로 추가할 manifest XML이 없습니다.
</Tab>
<Tab title="iOS">

```xml Info.plist
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLName</key>
    <string>myapp</string>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>myapp</string>
    </array>
  </dict>
</array>
```

iOS에서는 수신 URL을 SDK로 전달해야 합니다. `SFSafariViewController`가 자체 return URL을 수신할 수 없기 때문입니다. 정확한 핸들러는 [iOS](/developer-resources/sdks/ios) 또는 [React Native](/developer-resources/sdks/react-native) 페이지를 참조하세요.
</Tab>
<Tab title="Expo">
`@dodopayments/react-native-checkout`는 두 플랫폼 모두에 대한 scheme을 `prebuild`에 등록하는 config plugin을 제공합니다. `scheme` 옵션을 전달하세요:

```json app.json
{
  "expo": {
    "scheme": "myapp",
    "plugins": [
      [
        "@dodopayments/react-native-checkout",
        { "scheme": "myappcheckout" }
      ]
    ]
  }
}
```

`scheme`는 `returnUrl`와 일치해야 하며, Expo가 `MainActivity`에 이미 등록하는 `expo.scheme`와는 달라야 합니다. 자세한 내용은 [React Native SDK](/developer-resources/sdks/react-native) 페이지를 참조하세요.

`android/app/build.gradle`가 표준 `defaultConfig { }` 블록 없이 수동으로 관리되는 경우에는 대신 placeholder를 수동으로 설정하세요(Android 탭 참조).

development build에서만 작동하며 Expo Go에서는 작동하지 않습니다. `app.json`를 수정한 후
`npx expo prebuild --clean`를 실행하세요.
</Tab>
</Tabs>

<Note>
직접 구현하고 싶으신가요? `checkout_url`를 WebView에서 열고 `return_url`로의 navigation을 가로챈 다음, `status` 및 `payment_id`
query parameter를 읽으세요. 위 SDK는 플랫폼의 실제 browser surface에서 이 작업을 대신 처리하므로 Apple Pay와 Google Pay가 계속 작동합니다.
</Note>

## 모양 사용자 지정

모든 SDK는 `customization` /
`start(...)`에 선택적 `CheckoutParams` 매개변수를 지원합니다. 이 매개변수는 네이티브 브라우저 표면의 모양과 동작(툴바, 버튼 및 표시 방식)을 제어합니다. 이는 checkout 페이지 자체의 테마와는 별개이며, checkout 세션에서 서버 측으로
[`customization.theme_config`](/developer-resources/checkout-session)을 통해 구성합니다.

옵션은 플랫폼별로 그룹화되어 있습니다. Android의 Custom Tab과 iOS의
`SFSafariViewController`는 서로 다른 네이티브 컨트롤을 제공하기 때문입니다. 모든 필드는 선택 사항이며, `customization`를 완전히 생략하면 각 플랫폼의 기본 모양이 사용됩니다.

## 권장 사항

- **보안**: 앱에 API key를 절대 포함하지 마세요. 백엔드에서 checkout 세션을 생성하고 그 결과인 `checkout_url`만 클라이언트에 전달하세요.
- **권한 확인**: `CheckoutResult.status`를 UI 힌트로 취급하세요. 백엔드에서 결제를 확인한 후에만 액세스 권한을 부여하세요.
- **사용자 경험**: 백엔드에서 세션을 생성하는 동안 로딩 상태를 표시하고, `cancelled`를 오류가 아닌 정상적인 결과로 처리하세요.
- **테스트**: test mode와 test cards를 사용하고, 실제 디바이스와 simulator 모두에서 return-URL 왕복을 확인하세요.

## 문제 해결

### 일반적인 문제

- **Callback이 도착하지 않음**: `returnUrl`의 scheme은 등록한 scheme과 일치해야 합니다. Android에서는 `dodoCallbackScheme` manifest placeholder이고, iOS 및 React Native에서는 `Info.plist` URL type입니다.
- **checkout이 앱 대신 브라우저로 돌아감(iOS)**: 수신한 URL을 전달하지 않았습니다. `.onOpenURL`, `scene(_:openURLContexts:)` 또는 React Native `Linking` listener에서 `DodoCheckout.handleOpenURL(url)`를 호출하세요.
- **Android에서 `PLATFORM_ERROR`**: 대부분 scheme 불일치가 원인입니다. `MainActivity`가 `android:taskAffinity=""`(기본 stock `flutter create`)를 설정하는 경우에도 발생할 수 있으며, 이로 인해 일부 OEM 빌드에서 진행 중인 checkout이 손실될 수 있습니다.
- **`ALREADY_IN_PROGRESS`**: 아직 열려 있는 checkout이 있습니다. 새 checkout을 시작하기 전에 이전 checkout이 완료되거나 닫힐 때까지 기다리세요.
- **해결되지 않은 placeholder로 빌드 실패**: Android SDK를 추가했지만 `manifestPlaceholders["dodoCallbackScheme"]`를 설정하지 않았습니다.
- **결제는 성공했지만 액세스 권한이 부여되지 않음**: mobile result를 기준으로 처리하는 경우 예상되는 동작입니다. 대신 `payment.succeeded` / `subscription.active` webhook에서 액세스 권한을 부여하세요.
