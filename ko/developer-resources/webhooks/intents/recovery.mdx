## 장바구니 복구 이벤트

다음 웹훅 이벤트는 장바구니 복구 수명 주기를 추적합니다:

| Event | Description |
|-------|-------------|
| `abandoned_checkout.detected` | 방치된 결제가 감지되었습니다. 결제가 방치(실패 또는 불완전)로 식별되고 복구 워크플로가 시작되면 전송됩니다. |
| `abandoned_checkout.recovered` | 고객이 복구 링크를 통해 결제를 완료했습니다. `recovered_payment_id` 필드에는 성공적인 결제 ID가 포함되어 있습니다. |

### 방치된 결제 페이로드 필드

<ParamField body="payment_id" type="string" required>
방치된 원래 결제입니다. 이를 사용하여 제품, 금액 및 통화 세부 정보를 조회할 수 있습니다.
</ParamField>

<ParamField body="brand_id" type="string" required>
이 중단된 checkout이 속한 브랜드입니다.
</ParamField>

<ParamField body="customer_id" type="string" required>
checkout을 중단한 고객입니다.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
checkout이 중단된 이유입니다. 다음 중 하나입니다:
- `payment_failed` — 고객이 결제를 시도했지만 실패함
- `checkout_incomplete` — 고객이 checkout을 방문했지만 결제를 시도하지 않음
</ParamField>

<ParamField body="status" type="string" required>
이 복구 시도의 현재 lifecycle 상태입니다. 다음 중 하나입니다:
- `abandoned` — 감지됨, 아직 이메일이 전송되지 않음
- `recovering` — 하나 이상의 복구 이메일이 전송됨
- `recovered` — 고객이 결제를 완료함
- `exhausted` — 모든 이메일이 전송되었거나 더 최근의 checkout이 발견됨
- `opted_out` — 고객이 구독을 취소함
</ParamField>

<ParamField body="abandoned_at" type="string" required>
checkout이 중단된 것으로 감지된 시점의 ISO 8601 timestamp입니다.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
성공한 복구 결제의 payment ID입니다. checkout이 복구될 때까지는 `null`입니다.
</ParamField>

### 예시: ACR Webhook 처리

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Dunning 이벤트

다음 webhook 이벤트는 subscription dunning lifecycle을 추적합니다:

| 이벤트 | 설명 |
|-------|-------------|
| `dunning.started` | `on_hold` 상태가 된 subscription 또는 고객에 의해 취소된 subscription에 대해 dunning 시도가 생성되었습니다. |
| `dunning.recovered` | 고객이 payment method를 업데이트했고 그 결과 결제가 성공했습니다. `payment_id` field에 성공한 payment ID가 포함됩니다. |

### Dunning Attempt Payload Fields

<ParamField body="subscription_id" type="string" required>
dunning 시도를 트리거한 subscription입니다.
</ParamField>

<ParamField body="brand_id" type="string" required>
이 dunning 시도가 속한 브랜드입니다.
</ParamField>

<ParamField body="customer_id" type="string" required>
subscription을 소유한 고객입니다.
</ParamField>

<ParamField body="trigger_state" type="string" required>
Dunning을 트리거한 구독 상태입니다. 다음 중 하나입니다:
- `on_hold` — 결제 실패로 인해 갱신이 중지됨
- `cancelled` — 고객이 Customer Portal에서 취소함
</ParamField>

<ParamField body="status" type="string" required>
이 dunning 시도의 현재 lifecycle 상태입니다. 다음 중 하나입니다:
- `recovering` — dunning 이메일이 전송 중임
- `recovered` — 고객이 payment method를 업데이트했고 결제가 성공함
- `exhausted` — 모든 이메일이 전송되었거나 subscription 상태가 변경됨
</ParamField>

<ParamField body="created_at" type="string" required>
dunning 시도가 생성된 시점의 ISO 8601 timestamp입니다.
</ParamField>

<ParamField body="payment_id" type="string | null">
성공한 복구 결제의 payment ID입니다. 복구 중에는 `null`입니다.
</ParamField>

### 예시: Dunning Webhook 처리

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
전체 dunning lifecycle을 추적하려면 `dunning.started` 및 `dunning.recovered`를 모두 구독하세요. `dunning.started`를 사용하여 grace period를 일시 중지하거나 시스템에서 위험 상태의 subscription을 표시할 수 있습니다.
</Tip>
