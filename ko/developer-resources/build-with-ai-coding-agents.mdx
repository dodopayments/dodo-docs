Dodo Agent Plugin은 두 개의 MCP 서버와 17개의 통합 skills를 한 번의 설치로 AI coding agent에 연결합니다. **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro**, **OpenCode**에서 사용할 수 있습니다. **Gemini CLI**에서는 두 MCP 서버만 사용할 수 있습니다. MCP 서버와 skills CLI는 모든 MCP 호환 client에서 작동합니다.

이 plugin은 [Agent Plugins 1.0.0](https://agent-plugins.org/specification) specification을 따르므로, native support를 제공하는 client는 root의 `plugin.json` 및 `mcp.json`에서 직접 로드합니다. specification보다 먼저 출시된 client는 생성된 compatibility manifest를 통해 동일한 콘텐츠를 로드합니다.

<Info>
**세 가지 기본 구성 요소를 하나의 plugin으로 제공합니다.** Agent Plugin에는 필요한 모든 것이 포함되어 있습니다:
- **API MCP server** — payments, subscriptions, customers, products, refunds, licenses, usage에 실시간으로 액세스합니다. browser OAuth로 인증하므로 local key가 필요하지 않습니다.
- **Knowledge MCP server** — 모든 Dodo Payments documentation에서 semantic search를 수행합니다. credentials가 필요하지 않습니다.
- **17개의 agent skills** — checkout, subscriptions, webhooks, usage-based 및 credit-based billing, license keys, product catalog, discounts, localized pricing, mobile checkout, refunds 및 disputes, customer management, framework adapters, BillingSDK, Better Auth, testing 및 go-live, best practices를 위해 agent가 필요할 때 로드하는 cheat sheet입니다.
</Info>

## plugin 설치

아래에서 사용할 coding agent를 선택하세요. 모든 설치는 두 MCP 서버를 추가하며, Gemini CLI를 제외한 모든 client는 17개의 skills도 추가합니다.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
marketplace에서 설치합니다:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP server는 기본적으로 browser OAuth를 사용하므로 설치 시 key가 필요하지 않습니다. agent가 Dodo tool을 처음 호출하면 로그인하라는 메시지가 표시됩니다.

<Accordion title="Codex CLI">
Codex는 두 단계로 plugin을 설치합니다. 먼저 shell에서 marketplace를 등록한 다음 Codex TUI 내부에서 plugin을 설치합니다.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Codex를 열고 다음 `/plugins` slash command를 실행합니다:

```bash
codex
```

그런 다음 `/plugins`을 입력하고 **Dodo Payments** marketplace로 전환한 뒤 **dodopayments** plugin을 선택하고 **Install plugin**을 선택합니다.
</Step>
</Steps>

plugin이 설치되면 두 MCP 서버와 17개의 skills가 모두 자동으로 등록됩니다.

<Note>
Codex CLI에는 `codex plugin install` subcommand가 없으므로 plugin 설치는 항상 TUI 내부의 `/plugins` flow를 통해 진행됩니다. 자세한 내용은 [Codex 공식 plugins documentation](https://developers.openai.com/codex/plugins)을 참조하세요.
</Note>

이전에 marketplace를 추가했지만 `/plugins` 아래에 plugin이 표시되지 않는다면 새로 고침하세요:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
수동 설치 — repository를 Cursor의 local plugins directory에 clone합니다:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Cursor를 다시 시작합니다. plugin은 `skills/`에서 skills를, `.mcp.json`에서 MCP 서버를 로드하며, 이는 `.cursor-plugin/plugin.json`에 선언되어 있습니다.

<Info>
최근 Cursor build는 Agent Plugins 1.0.0도 직접 인식하며 `.cursor-plugin/marketplace.json` 또는 `.claude-plugin/marketplace.json`를 marketplace source로 사용할 수 있습니다. 이 plugin은 `.claude-plugin/marketplace.json`를 제공하므로 해당 path를 사용하세요. 생성된 `.cursor-plugin/plugin.json`는 이전 build를 위해 유지됩니다.
</Info>

<Warning>
0.5.0 이전 version은 `skills/`를 git submodule에 대한 symlink로 제공했기 때문에 clone 결과 **작동하는 skills가 없는** plugin이 생성되었습니다. 이제 skills는 실제 file로 제공됩니다. 이전 version을 설치했다면 directory를 삭제한 후 다시 clone하세요.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode는 npm을 통해 배포됩니다. `opencode.json`에 plugin을 추가하세요:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

OpenCode를 다시 시작합니다. 두 MCP 서버(`dodopayments-api`, `dodo-knowledge`)는 plugin의 config hook을 통해 자동으로 등록됩니다. 수동 `mcp` block은 필요하지 않습니다.

**Skills에는 한 줄을 추가해야 합니다.** OpenCode는 설치된 package에서 skills를 검색하지 않으므로 package의 `skills/` directory를 직접 지정하세요:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

상대 `skills.paths` 항목은 **project directory**를 기준으로 해석되므로 package가 해당 project의 `node_modules`에 있어야 합니다. OpenCode 자체의 plugin cache는 다른 위치입니다. absolute path를 사용하면 local-install requirement도 피할 수 있습니다.

<Warning>
존재하지 않는 skills path는 **조용히** 무시됩니다. 추측하지 말고 확인하세요:

```bash
opencode run "List every skill available to you by name."
```

17개가 모두 표시되어야 합니다. 0.5.0 이전 version에서는 이러한 skills가 자동 검색된다고 documentation에 명시했지만 실제로는 그렇지 않았습니다. 따라서 OpenCode 사용자는 MCP 서버만 사용하고 skills는 사용할 수 없었습니다.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
repository를 원하는 위치에 clone한 다음 등록합니다:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Chat view를 열고 **Plugins**로 이동한 뒤 clone한 folder를 추가합니다. `settings.json`에서 직접 등록할 수도 있습니다:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

key는 path이고 value는 활성화 여부를 지정합니다. absolute path와 `~/` 모두 사용할 수 있으며, relative path는 각 workspace folder를 기준으로 해석됩니다. 설정은 실시간으로 읽히므로 실행 중인 window에서도 restart 없이 반영됩니다. Skills는 `skills/`에서 로드되고 두 MCP 서버는 `.mcp.json`에서 로드됩니다.

<Note>
`chat.pluginLocations`는 **experimental**이며 *restricted* setting이므로 적용하려면 workspace를 trust해야 합니다. Agent-plugin support 전체는 `chat.plugins.enabled`에 의해 관리되는 preview feature이며 기본적으로 **활성화**되어 있습니다. organization에서 policy로 비활성화한 경우에만 설정하면 됩니다.
</Note>

<Info>
VS Code는 Agent Plugins `$schema`를 기준으로 로드하지 않습니다. loader는 `.plugin/plugin.json`, `.claude-plugin/plugin.json`, root `plugin.json` 순서로 확인하며 MCP의 기본값은 `mcp.json`가 아닌 `.mcp.json`입니다. 이 repository는 생성된 `.claude-plugin/plugin.json`를 제공하므로 VS Code는 compatibility branch를 통해 로드하고, `mcp.json`의 native transports 대신 `mcp-remote` bridge를 사용합니다. 모든 기능은 동일하게 작동하며 path만 다릅니다.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro는 Agent Plugins manifest를 native로 읽고 이를 Power로 로드합니다.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
Kiro에서 Powers panel을 열고 번개 표시가 있는 Ghosty icon을 선택합니다.
</Step>

<Step title="Import the folder">
**Add Custom Power → Import power from a folder**를 선택하고 clone한 directory(`plugin.json`가 포함된 directory)를 지정한 다음 **Install**을 클릭합니다.
</Step>
</Steps>

Skills는 `skills/`에서, MCP 서버는 `mcp.json`에서 로드되며 Kiro 전용 presentation은 `plugin.json`의 `dev.kiro` extension namespace에서 제공됩니다.

<Note>
Agent Plugins format의 plugin에서 Kiro는 MCP 서버를 내부적으로 관리합니다. MCP 서버는 user-level `~/.kiro/settings/mcp.json`에 기록되지 **않으므로** 해당 위치에서 찾을 수 없습니다. Kiro는 GitHub URL에서 직접 Power를 설치할 수도 있습니다. 자세한 내용은 [Kiro 설치 documentation](https://kiro.dev/docs/powers/installation/)을 참조하세요.
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI에는 agent-skill primitive가 없으므로 **두 MCP 서버만 사용할 수 있으며** 17개의 skills는 사용할 수 없습니다. `dodo-knowledge`는 skills가 제공하는 기능의 상당 부분을 여전히 지원하며 자동으로 최신 상태를 유지합니다.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Gemini CLI를 다시 시작합니다. repository root의 `gemini-extension.json`가 manifest입니다.
</Accordion>
</AccordionGroup>

## 제공되는 기능

plugin을 설치하면 agent가 두 MCP 서버와 17개의 skills에 액세스할 수 있습니다.

### MCP servers

| Server | Purpose | Auth |
|--------|---------|------|
| `dodopayments-api` | 실시간 API 액세스 — payments, subscriptions, customers, products, refunds, licenses, usage | OAuth (browser) |
| `dodo-knowledge` | 모든 Dodo Payments documentation에서 semantic search | None |

두 서버 모두 Streamable HTTP를 사용합니다. canonical `mcp.json`는 서버를 native로 선언하며(`type: "streamable-http"`), Codex CLI와 Kiro 같은 spec-native client가 이를 사용합니다. 생성된 compatibility manifest `.mcp.json`는 대신 `mcp-remote`를 통해 동일한 두 endpoint를 연결하므로 Streamable HTTP에 직접 연결할 수 없는 client에서도 실행됩니다. 여기에는 위에서 설명한 git-clone 설치를 통한 Claude Code, VS Code, Cursor가 포함되며, 해당 client의 `.cursor-plugin/plugin.json`는 `.mcp.json`를 가리킵니다.

### Agent skills

| Skill | Description |
|-------|-------------|
| `dodo-best-practices` | SDK 설정, environments, API keys 및 표준 checkout-to-webhook architecture |
| `framework-adapters` | Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun, Convex용 공식 `@dodopayments/*` route handlers |
| `testing-and-go-live` | Test mode, test payment methods, webhook testing 및 production launch checklist |
| `checkout-integration` | Checkout Sessions, payment links 및 overlay 또는 inline checkout |
| `subscription-integration` | Subscription lifecycle, trials, plan changes, proration 및 on-demand charges |
| `mobile-checkout` | React Native, Flutter, iOS 및 Android용 in-app checkout |
| `webhook-integration` | Standard Webhooks specification을 사용한 webhook 수신 및 검증 |
| `credit-based-billing` | Credit entitlements, balances, ledger, rollover, overage 및 meter-based deduction |
| `usage-based-billing` | Meters, event ingestion, aggregation 및 per-unit pricing |
| `license-keys` | License key activation, validation 및 instance management |
| `product-catalog-management` | Products, pricing, add-ons, collections, images 및 digital product delivery |
| `discounts-and-promotions` | Discount codes, eligibility rules, stacking 및 subscription-cycle limits |
| `localized-pricing` | Localized pricing, Adaptive Currency 및 purchasing power parity |
| `customer-management` | Customers, self-service portal, saved payment methods 및 wallets |
| `refunds-and-disputes` | Refund 발행, disputes 및 chargebacks 처리, access 조정 |
| `billing-sdk` | Pricing tables 및 billing UI용 BillingSDK React components |
| `better-auth-integration` | Customer sync, checkout 및 portal access를 위한 `@dodopayments/better-auth` plugin |

Skills는 자동으로 로드되며 agent가 관련 task를 감지하면 적절한 skill을 선택합니다. 전체 목록과 개별 설치 방법은 [Agent Skills documentation](/developer-resources/agent-skills)을 참조하세요.

### 먼저 시도할 prompt

plugin이 활성화되면 다음을 시도해 보세요:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

agent는 `webhook-integration` skill을 로드하고 `dodo-knowledge` MCP를 사용해 최신 payload shape을 가져온 다음 Standard Webhooks spec에 따른 signature verification이 포함된 handler를 작성합니다.

## Security 및 best practices

<Warning>
**production API keys를 절대 commit하지 마세요.** development 중에는 [test mode](/miscellaneous/test-mode-vs-live-mode)를 사용하세요. Agent Plugin은 기본적으로 browser OAuth를 사용합니다. workflow에 필요한 경우에만 local API keys로 전환하세요.
</Warning>

- **먼저 test mode를 사용하세요.** production으로 전환하기 전에 `dodo_test_...` keys로 integration을 sandbox에서 테스트하세요. [Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode)를 참조하세요.
- **OAuth가 기본값입니다.** Agent Plugin은 browser OAuth로 인증하므로 local secrets가 필요하지 않습니다. 필요한 경우에만 API-key mode를 사용하세요. 아래 Configure section을 참조하세요.
- **agent가 생성한 code를 검토하세요.** webhook handlers에 [Standard Webhooks spec](https://standardwebhooks.com/)에 따른 signature verification이 포함되어 있는지 항상 확인하세요.

## API key로 구성

기본적으로 Agent Plugin은 browser OAuth를 사용하는 remote MCP server를 사용하므로 local credentials가 필요하지 않습니다. workflow에 local API key가 필요한 경우(예: CI environments, headless servers) stdio mode로 전환할 수 있습니다.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Claude Code에서 `/plugins`를 열고 **Dodo Payments**를 선택한 다음 **Configure options**를 선택합니다. 다음 값을 입력하세요:

- `dodo_api_key` — `dodo_test_...` 또는 `dodo_live_...` key
- `dodo_webhook_key` — webhook signing secret
- `dodo_environment` — `test_mode` 또는 `live_mode`

그런 다음 `.mcp.json`를 수정하여 `dodopayments-api`가 local stdio server를 가리키도록 합니다:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

현재 session에 변경 사항을 적용하려면 `/reload-plugins`를 실행합니다.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
`dodopayments-api`를 `opencode.json`에서 직접 선언하면 해당 항목이 plugin의 기본 remote server보다 우선합니다:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

적용하려면 OpenCode를 다시 시작합니다.
</Accordion>
