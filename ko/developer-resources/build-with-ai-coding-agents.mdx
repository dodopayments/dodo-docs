Dodo Agent Plugin은 한 번의 설치로 두 개의 MCP 서버와 열일곱 개의 통합 skills를 AI 코딩 에이전트에 연결합니다. **Claude Code**, **Codex CLI**, **Cursor**, **OpenCode**에서 작동하며, MCP 서버와 skills CLI는 모든 MCP 호환 클라이언트에서 사용할 수 있습니다.

<Info>
**세 가지 기본 구성 요소, 하나의 플러그인.** Agent Plugin에는 필요한 모든 기능이 포함되어 있습니다:
- **API MCP server** — payments, subscriptions, customers, products, refunds, licenses, usage에 실시간으로 액세스합니다. 브라우저 OAuth를 통해 인증하므로 로컬 키가 필요하지 않습니다.
- **Knowledge MCP server** — 모든 Dodo Payments 문서에서 semantic search를 수행합니다. 자격 증명이 필요하지 않습니다.
- **열일곱 개의 agent skills** — checkout, subscriptions, webhooks, usage-based 및 credit-based billing, license keys, product catalog, discounts, localized pricing, mobile checkout, refunds and disputes, customer management, framework adapters, BillingSDK, Better Auth, testing and go-live, best practices를 위해 에이전트가 필요할 때 로드하는 치트 시트입니다.
</Info>

## 플러그인 설치

아래에서 사용할 코딩 에이전트를 선택하세요. 설치하면 두 MCP 서버와 열일곱 개의 skills가 모두 자동으로 추가됩니다.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
마켓플레이스에서 설치:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP 서버는 기본적으로 브라우저 OAuth를 사용합니다 — 설치 시 키가 필요하지 않습니다. 에이전트가 처음으로 Dodo 도구를 호출할 때 로그인을 요청받게 됩니다.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  소스 코드, 구성 옵션 및 로컬 개발 지침
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex는 두 단계로 플러그인을 설치합니다: 셸에서 마켓플레이스를 등록한 다음, Codex TUI 내부에서 플러그인을 설치합니다.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Codex를 열고 `/plugins` 슬래시 명령을 실행합니다:

```bash
codex
```

그런 다음 `/plugins`을 입력하고 **Dodo Payments** 마켓플레이스로 전환하며, **dodopayments** 플러그인을 선택하고 **Install plugin**을 선택합니다.
</Step>
</Steps>

플러그인을 설치하면 두 MCP 서버와 열일곱 개의 skills가 모두 자동으로 등록됩니다.

<Note>
Codex CLI에는 `codex plugin install` 서브 명령이 없습니다 — 플러그인 설치는 항상 in-TUI `/plugins` 흐름을 통해 이루어집니다. [공식 Codex 플러그인 문서](https://developers.openai.com/codex/plugins)를 참조하세요.
</Note>

이전에 마켓플레이스를 추가했고 플러그인이 `/plugins` 아래에 나타나지 않으면 새로 고칩니다:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
수동 설치 — Cursor의 로컬 플러그인 디렉토리에 리포를 클론합니다:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Cursor를 재시작합니다. 플러그인은 `.claude/skills/` (Cursor의 Claude Code 호환 레이어 통해)에서 스킬을 로드하고, MCP 서버는 `.mcp.json`에서 로드합니다.

<Info>
Cursor 마켓플레이스 지원이 곧 제공됩니다. 지금은 위의 수동 설치를 사용하세요.
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode는 npm을 통해 배포합니다. 플러그인을 `opencode.json`에 추가하세요:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

OpenCode를 다시 시작하세요. 두 MCP 서버(`dodopayments-api`, `dodo-knowledge`)는 플러그인의 config hook을 통해 자동으로 등록되며, 열일곱 개의 skills는 설치된 package에서 자동으로 검색됩니다. 수동으로 `mcp` block을 추가할 필요가 없습니다.
</Accordion>
</AccordionGroup>

<Info>
다른 에이전트를 사용 중이신가요? [MCP Server](/developer-resources/mcp-server) 및 [Agent Skills](/developer-resources/agent-skills) 가이드에는 Cursor, Claude Desktop, VS Code, Windsurf, Cline, Zed 및 MCP 호환 클라이언트가 다뤄집니다.
</Info>

## 얻을 수 있는 것

플러그인을 설치하면 에이전트가 두 MCP 서버와 열일곱 개의 skills에 액세스할 수 있습니다.

### MCP 서버

| 서버 | 목적 | 인증 |
|--------|---------|------|
| `dodopayments-api` | 라이브 API 접근 — 결제, 구독, 고객, 제품, 환불, 라이선스, 사용량 | OAuth (브라우저) |
| `dodo-knowledge` | 모든 Dodo Payments 문서의 시멘틱 검색 | 없음 |

두 서버는 `mcp-remote`를 통해 연결되어 MCP 호환 클라이언트에서 실행됩니다.

### 에이전트 스킬

| Skill | 설명 |
|-------|-------------|
| `best-practices` | SDK 설정, 환경, API keys, 그리고 checkout부터 webhook까지의 표준 아키텍처 |
| `framework-adapters` | Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun, Convex를 위한 공식 `@dodopayments/*` route handlers |
| `testing-and-go-live` | Test mode, test payment methods, webhook testing, production launch checklist |
| `checkout-integration` | Checkout Sessions, payment links, overlay 또는 inline checkout |
| `subscription-integration` | Subscription lifecycle, trials, plan changes, proration, on-demand charges |
| `mobile-checkout` | React Native, Flutter, iOS, Android를 위한 인앱 checkout |
| `webhook-integration` | Standard Webhooks specification을 사용한 webhook 수신 및 검증 |
| `credit-based-billing` | Credit entitlements, balances, ledger, rollover, overage, meter-based deduction |
| `usage-based-billing` | Meters, event ingestion, aggregation, per-unit pricing |
| `license-keys` | License key activation, validation, instance management |
| `product-catalog-management` | Products, pricing, add-ons, collections, images, digital product delivery |
| `discounts-and-promotions` | Discount codes, eligibility rules, stacking, subscription-cycle limits |
| `localized-pricing` | Localized pricing, Adaptive Currency, purchasing power parity |
| `customer-management` | Customers, self-service portal, saved payment methods, wallets |
| `refunds-and-disputes` | Refunds 발행, disputes 및 chargebacks 처리, access 조정 |
| `billing-sdk` | Pricing tables 및 billing UI를 위한 BillingSDK React components |
| `better-auth-integration` | Customer sync, checkout, portal access를 위한 `@dodopayments/better-auth` plugin |

스킬은 자동으로 로드됩니다 — 에이전트는 관련 작업을 감지할 때 적합한 스킬을 선택합니다. 전체 목록 및 개별 설치에 대한 [Agent Skills 문서](/developer-resources/agent-skills)를 참조하세요.

### 이 프롬프트를 먼저 시도하세요

플러그인이 활성화되면 다음을 시도하세요:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

에이전트는 `webhook-integration` 스킬을 로드하고, 최신 페이로드 형태를 가져오기 위해 `dodo-knowledge` MCP를 사용하고, 표준 웹훅 사양을 따라 서명 검증을 포함한 핸들러를 작성합니다.

## 지원되는 다른 에이전트

에이전트 플러그인은 Claude Code, Codex CLI, Cursor 및 OpenCode를 다룹니다. 다른 에이전트를 사용하는 경우, MCP 서버 및 스킬 CLI를 통해 Dodo Payments에 연결하세요:

| 에이전트 | 가장 빠른 경로 | 추가 지원 |
|-------|-------------|---------------|
| **Claude Code** | 에이전트 플러그인 (한 번의 명령) | MCP 서버, 개별 스킬 |
| **Codex CLI** | 에이전트 플러그인 (한 번의 명령) | MCP 서버 |
| **Cursor** | 에이전트 플러그인 (git clone) | MCP 서버 구성, 스킬 CLI |
| **OpenCode** | 에이전트 플러그인 (npm) | MCP 서버 구성, 스킬 CLI |
| GitHub Copilot (VS Code) | [MCP Server guide](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Claude Desktop | [MCP Server guide](/developer-resources/mcp-server) | — |
| Windsurf | [MCP Server guide](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / 기타 | [MCP Server guide](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

- **Subscription 및 usage-based billing을 처음부터 끝까지 설정** — [Subscriptions](/features/subscription), [Usage-based billing](/features/usage-based-billing/introduction), [Credit-based billing](/features/credit-based-billing)
- **서명 검증을 포함한 Standard Webhooks 호환 handler 생성** — [Webhooks](/developer-resources/webhooks)
- **공식 adapters를 사용해 framework에 route handlers 연결** — [Framework adaptors](/developer-resources/framework-adaptors)
- **Pricing tables 및 subscription management를 위한 BillingSDK React components 연결** — [BillingSDK](/developer-resources/billingsdk)
- **디지털 제품을 위한 license-key flow 작성** — [License keys](/features/license-keys)
- **Entitlements, balances, rollover, overage를 활용한 credit-based billing 구현** — [Credits](/features/credit-based-billing)
- **Add-ons 및 collections를 포함한 product catalog 구축 및 관리** — [Products](/features/products), [Add-ons](/features/addons), [Product collections](/features/product-collections)
- **Discounts 및 localized pricing 추가** — [Discount codes](/features/discount-codes), [Localized pricing](/features/localized-pricing), [Adaptive Currency](/features/adaptive-currency)
- **React Native, Flutter, iOS, Android를 위한 모바일 인앱 checkout 출시** — [Mobile integration](/developer-resources/mobile-integration)
- **Refunds, disputes 및 customer self-service 처리** — [Refunds](/features/transactions/refunds), [Disputes](/features/transactions/disputes), [Customer portal](/features/customer-portal)
- **Integration을 테스트하고 안전하게 출시** — [Test mode vs live mode](/miscellaneous/test-mode-vs-live-mode)

## 보안 및 모범 사례

<Warning>
**운영 API 키를 커밋하지 마세요.** 개발 중에는 [테스트 모드](/miscellaneous/test-mode-vs-live-mode)를 사용하세요. 에이전트 플러그인은 기본적으로 브라우저 OAuth를 사용합니다 — 워크플로우가 필요할 경우에만 로컬 API 키로 전환하세요.
</Warning>

- **먼저 테스트 모드를 사용하세요.** `dodo_test_...` 키로 통합을 샌드박스에서 테스트한 후 라이브로 전환하세요. [Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode)를 참조하세요.
- **OAuth가 기본입니다.** 에이전트 플러그인은 브라우저 OAuth로 인증합니다 (로컬 비밀 없음). 필요하지 않은 경우 API 키 모드를 사용하지 마세요 — 아래 구성 섹션을 참조하세요.
- **에이전트가 생성한 코드를 검토하세요.** 항상 웹훅 핸들러에 표준 웹훅 사양을 따르는 서명 검증이 포함되어 있는지 확인하세요.

## API 키로 구성하기

기본적으로, 에이전트 플러그인은 브라우저 OAuth가 있는 원격 MCP 서버를 사용합니다 — 로컬 자격 증명이 필요 없습니다. 로컬 API 키가 필요한 경우 (예: CI 환경, 헤드리스 서버), stdio 모드로 전환할 수 있습니다.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
`/plugins`를 Claude Code에서 열고, **Dodo Payments**를 선택하고, **구성 옵션**을 선택하세요. 다음을 입력하세요:

- `dodo_api_key` — 당신의 `dodo_test_...` 또는 `dodo_live_...` 키
- `dodo_webhook_key` — 당신의 웹훅 서명 비밀
- `dodo_environment` — `test_mode` 또는 `live_mode`

그런 다음 `.mcp.json`를 편집하여 `dodopayments-api`가 로컬 stdio 서버를 가리키도록 합니다:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

`/reload-plugins`를 실행하여 현재 세션에 변경 사항을 적용합니다.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
`dodopayments-api`를 `opencode.json`에서 직접 선언하세요 — 당신의 항목이 플러그인의 기본 원격 서버에 우선합니다:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

OpenCode를 재시작하여 적용하십시오.
</Accordion>
</AccordionGroup>
