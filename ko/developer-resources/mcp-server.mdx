## 개요

Model Context Protocol(MCP)은 AI 애플리케이션이 외부 데이터 소스 및 API에 안전하게 연결할 수 있도록 하는 개방형 표준입니다. Dodo Payments MCP Server는 Claude, Cursor 및 기타 MCP 호환 클라이언트와 같은 AI 어시스턴트에 결제 인프라에 대한 구조화된 액세스를 제공합니다.

Dodo Payments MCP Server는 **Code Mode** 아키텍처를 사용합니다. 모든 API 엔드포인트에 대해 수백 개의 개별 도구를 노출하는 대신, Code Mode를 사용하면 AI 에이전트가 격리된 샌드박스 환경에서 Dodo Payments SDK를 대상으로 TypeScript 코드를 작성하고 실행할 수 있습니다.

### 주요 기능

- **결제 작업**: 결제 및 환불 생성, 조회, 관리
- **구독 관리**: 반복 결제, 업그레이드, 취소 처리
- **고객 관리**: 고객 데이터 및 포털 액세스 관리
- **제품 카탈로그**: 제품, 가격, 할인 생성 및 업데이트
- **라이선스 관리**: 소프트웨어 라이선스 활성화, 검증 및 관리
- **사용량 기반 결제**: 측정된 사용량 추적 및 청구

## Code Mode 작동 방식

Dodo Payments MCP Server는 AI 에이전트에 정확히 두 가지 도구를 제공합니다:

1. **Docs Search Tool**: 사용 가능한 작업 및 매개변수를 파악하기 위해 Dodo Payments API 및 SDK에 관한 문서를 검색합니다.
2. **Code Execution Tool**: 안전한 샌드박스 환경에서 실행되는 SDK 대상 TypeScript 코드를 작성합니다.

이 아키텍처를 사용하면 에이전트가 한 번의 호출로 복잡한 다단계 작업을 수행할 수 있습니다. 예를 들어 에이전트는 모든 활성 구독을 나열하고, 특정 기준에 따라 필터링한 다음, 각 구독에 할인을 적용할 수 있으며 이 모든 작업이 하나의 스크립트 안에서 이루어집니다.

<Tip>
Code Mode를 사용하면 에이전트가 여러 API 호출을 연결하고, 조건부 로직을 처리하며, LLM에 여러 번 왕복 요청하지 않고도 계산을 수행할 수 있습니다.
</Tip>

## Dodo Knowledge MCP

Dodo Payments MCP Server(API 작업 실행용) 외에도 **Dodo Knowledge MCP**를 제공합니다. 이는 AI 어시스턴트가 Dodo Payments 문서와 지식 베이스에 즉시 액세스할 수 있도록 하는 시맨틱 검색 서버입니다.

<Info>
**[ContextMCP.ai](https://contextmcp.ai)로 구축**: Dodo Knowledge MCP는 ContextMCP를 기반으로 하며, 벡터 임베딩을 사용해 문서 전반에서 빠른 시맨틱 검색을 지원합니다.
</Info>

### Dodo Knowledge MCP란?

Dodo Knowledge MCP는 다음을 제공하는 원격 MCP 서버입니다:

- **시맨틱 문서 검색**: 자연어 쿼리를 사용하여 관련 문서를 찾습니다.
- **컨텍스트 기반 답변**: AI 어시스턴트가 Dodo Payments에 관한 정확하고 최신 정보를 얻습니다.
- **설정 불필요**: API 키나 로컬 설치가 필요하지 않습니다. 연결한 후 바로 쿼리를 시작하면 됩니다.

### 두 MCP 서버 함께 사용하기

AI 지원 개발 환경을 최대한 활용하려면 두 MCP 서버를 모두 사용하는 것이 좋습니다:

| 서버 | 용도 | 사용 사례 |
|--------|---------|----------|
| **Dodo Knowledge MCP** | 문서 검색 | "웹훅은 어떻게 처리하나요?", "지원되는 결제 방법은 무엇인가요?" |
| **Dodo Payments MCP** | API 작업 | 결제 생성, 구독 관리, 환불 처리 |

```json
{
  "mcpServers": {
    "dodo-knowledge": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://knowledge.dodopayments.com/mcp"]
    },
    "dodopayments": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://mcp.dodopayments.com/sse"]
    }
  }
}
```

<Tip>
두 서버를 모두 구성하면 AI 어시스턴트가 먼저 문서를 검색하여 기능 구현 방법을 파악한 다음 실제 API 호출을 실행할 수 있습니다. 이 모든 과정이 하나의 대화에서 이루어집니다.
</Tip>

### Knowledge MCP 문제 해결

연결 문제가 발생하면 다음을 수행하세요:

1. **MCP 인증 캐시 지우기**: `rm -rf ~/.mcp-auth`
2. **클라이언트 애플리케이션 다시 시작**
3. **클라이언트 로그 확인**: 오류 메시지를 확인합니다.
4. **Node.js 버전 확인**: Node.js 18 이상 필요

### NPM 패키지

NPM을 사용하여 MCP 서버를 로컬에서 설치하고 실행합니다.

<Tabs>
<Tab title="NPX (No Installation)">

```bash
# Set your environment variables
export DODO_PAYMENTS_API_KEY="dodo_test_..."
export DODO_PAYMENTS_WEBHOOK_KEY="your_webhook_key"
export DODO_PAYMENTS_ENVIRONMENT="live_mode"

# Run the latest version
npx -y dodopayments-mcp@latest
```

</Tab>

<Tab title="MCP Client Configuration">

```json
{
  "mcpServers": {
    "dodopayments_api": {
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "your_webhook_key",
        "DODO_PAYMENTS_ENVIRONMENT": "live_mode"
      }
    }
  }
}
```

</Tab>
</Tabs>

<Tip>
항상 최신 버전을 가져오려면 `@latest`을 사용하고, 안정성을 위해 `@1.0.0`과 같이 특정 버전에 고정할 수도 있습니다.
</Tip>

### Docker

일관된 배포를 위해 컨테이너화된 환경에서 MCP 서버를 실행합니다.

<CodeGroup>

```bash Docker
# Pull the latest image
docker pull ghcr.io/dodopayments/mcp:latest

# Run the container
docker run -e DODO_PAYMENTS_API_KEY="dodo_test_..." \
  -e DODO_PAYMENTS_WEBHOOK_KEY="your_webhook_key" \
  -e DODO_PAYMENTS_ENVIRONMENT="live_mode" \
  ghcr.io/dodopayments/mcp:latest
```

```yaml Docker Compose
services:
  dodopayments-mcp:
    image: ghcr.io/dodopayments/mcp:latest
    environment:
      - DODO_PAYMENTS_API_KEY=dodo_test_...
      - DODO_PAYMENTS_WEBHOOK_KEY=your_webhook_key
      - DODO_PAYMENTS_ENVIRONMENT=live_mode
    restart: unless-stopped
```

</CodeGroup>

<Note>
Docker 이미지는 [GitHub Container Registry](https://github.com/orgs/dodopayments/packages/container/package/mcp)에서 사용할 수 있습니다.
</Note>

## 환경 변수

환경 변수를 사용하여 MCP 서버 동작을 구성하세요.

| 변수 | 설명 | 필수 |
|----------|-------------|----------|
| `DODO_PAYMENTS_API_KEY` | 사용자의 Dodo Payments API 키 | 예 |
| `DODO_PAYMENTS_WEBHOOK_KEY` | 웹훅 서명 키 | 아니요 |
| `DODO_PAYMENTS_ENVIRONMENT` | 프로덕션의 경우 `live_mode`으로 설정 | 아니요 |

## 원격 실행

웹 기반 클라이언트 또는 에이전트 워크플로를 위해 MCP 서버를 원격 HTTP 서버로 배포하세요.

```bash
# Start as remote server
npx -y dodopayments-mcp --transport=http

# Specify a custom port
npx -y dodopayments-mcp --transport=http --port=3000
```

### 원격 서버 구성

배포가 완료되면 클라이언트는 서버 URL을 사용하여 연결할 수 있습니다:

```json
{
  "mcpServers": {
    "dodopayments_api": {
      "url": "http://localhost:3000",
      "headers": {
        "Authorization": "Bearer your_api_key"
      }
    }
  }
}
```

### Authorization 헤더

원격 서버는 다음 헤더를 통한 인증을 허용합니다:

| 헤더 | 설명 |
|--------|-------------|
| `Authorization` | Bearer token 인증 |
| `x-dodo-payments-api-key` | 직접 API 키 헤더 |

## 보안 모범 사례

Code Mode는 샌드박스 환경에서 코드를 실행하고 서버 측에서 API 키를 주입하여 기본적인 보안을 제공합니다. 자격 증명을 보호하려면 다음 추가 모범 사례를 따르세요.

<AccordionGroup>
<Accordion title="API Key Management">
**자격 증명을 버전 관리 시스템에 절대 커밋하지 마세요**

API 키는 환경 변수 또는 보안 비밀 관리 시스템에 저장하세요.

```bash
# Use environment variables
export DODO_PAYMENTS_API_KEY="dodo_test_..."

# Use a .env file (add to .gitignore)
echo "DODO_PAYMENTS_API_KEY=dodo_test_..." > .env
```

**키를 정기적으로 교체하세요**

주기적으로 새 API 키를 생성하고 Dodo Payments 대시보드를 통해 이전 키를 폐기하세요.

**개발에는 test 키를 사용하세요**

프로덕션 데이터에 영향을 주지 않도록 개발 중에는 항상 test mode API 키를 사용하세요.
</Accordion>

<Accordion title="Access Control">
**원격 서버에 인증을 구현하세요**

원격으로 배포할 때는 항상 `Authorization` 헤더 또는 `x-dodo-payments-api-key` 헤더를 통한 인증을 요구하세요.

**API 사용량을 모니터링하세요**

Dodo Payments 대시보드를 통해 MCP 서버 활동을 추적하고 비정상적인 패턴에 대한 알림을 설정하세요.
</Accordion>

<Accordion title="Network Security">
**원격 서버에 HTTPS를 사용하세요**

항상 HTTPS 엔드포인트 뒤에 원격 MCP 서버를 배포하세요.

**속도 제한을 구현하세요**

MCP 서버 및 API 수준 모두에서 속도 제한을 구현하여 악용을 방지하세요.

**네트워크 액세스를 제한하세요**

MCP 서버에 연결할 수 있는 클라이언트를 제한하도록 방화벽 규칙을 구성하세요.
</Accordion>
</AccordionGroup>

## 문제 해결

<AccordionGroup>
<Accordion title="Connection issues">
**API 키를 확인하세요**

API 키가 올바르게 설정되어 있고 필요한 권한이 있는지 확인하세요.

```bash
# Test your API key
curl -H "Authorization: Bearer dodo_test_..." \
  https://test.dodopayments.com/payments
```

**네트워크 연결을 확인하세요**

Dodo Payments API 엔드포인트에 연결할 수 있는지 확인하세요.

**클라이언트 로그를 검토하세요**

연결 문제를 진단하려면 MCP 클라이언트에서 상세 로깅을 활성화하세요.
</Accordion>

<Accordion title="Authentication errors">
**API 키 환경을 확인하세요**

test 엔드포인트에는 test 키를, 프로덕션 엔드포인트에는 live 키를 사용하고 있는지 확인하세요.

**환경 변수를 확인하세요**

`DODO_PAYMENTS_ENVIRONMENT`이 올바르게 설정되어 있는지 확인하세요(프로덕션의 경우 `live_mode`).

**자격 증명을 다시 생성하세요**

문제가 계속되면 대시보드를 통해 새 API 키를 생성하세요.
</Accordion>

<Accordion title="Tool execution failures">
**입력 매개변수를 검증하세요**

AI 어시스턴트가 각 도구에 올바른 형식의 매개변수를 제공하는지 확인하세요.

**오류 메시지를 검토하세요**

문제의 원인에 관한 구체적인 안내는 API의 오류 응답을 확인하세요.

**API로 직접 테스트하세요**

curl 또는 Postman을 통해 Dodo Payments API를 직접 호출했을 때 작업이 정상적으로 수행되는지 확인하세요.
</Accordion>
</AccordionGroup>

## Code Mode를 사용하는 이유

기존 MCP 구현은 모든 API 엔드포인트를 별도의 도구로 노출하는 "도구 확산" 문제를 자주 겪습니다. Code Mode가 더 뛰어난 접근 방식인 이유는 다음과 같습니다:

### LLM은 도구 호출보다 코드 작성에 더 능숙합니다
LLM은 수백만 줄의 실제 코드로 학습되었기 때문에 본질적으로 스크립트 작성에 능숙합니다. 반면 도구 호출은 합성 예제를 기반으로 하는 경우가 많습니다.

<Info>
"LLM이 도구 호출로 작업을 수행하게 하는 것은 Shakespeare를 한 달 동안 Mandarin 수업에 참여시킨 뒤 그 언어로 희곡을 쓰라고 하는 것과 같습니다." — [Cloudflare](https://blog.cloudflare.com/code-mode/)
</Info>

### 컨텍스트 창의 비대화를 제거합니다
기존 방식에서는 대화가 시작되기도 전에 모든 도구 정의가 토큰을 소비합니다. 50개 이상의 도구를 노출하면 55K~100K 이상의 토큰을 쉽게 사용할 수 있습니다. Anthropic은 최적화 전 도구 정의가 최대 134K 토큰을 소비할 수 있음을 확인했습니다.

Code Mode에서는 2개의 도구 정의만 로드됩니다(약 1K 토큰). 에이전트는 필요에 따라 필요한 문서를 검색합니다. Anthropic의 Tool Search Tool은 컨텍스트 창의 95%를 보존하여 오버헤드를 77K 토큰에서 8.7K 토큰으로 줄였습니다.

### 프로그래밍 방식의 오케스트레이션으로 지연 시간을 줄입니다
기존 도구 호출에서는 각 작업마다 전체 모델 추론 왕복이 필요합니다. 작업에 20번의 API 호출이 필요하다면 왕복도 20번 발생합니다. Code Mode에서는 에이전트가 모든 호출을 실행하는 하나의 스크립트를 작성하고 최종 결과만 반환합니다.

Anthropic은 이 프로그래밍 방식의 접근을 사용했을 때 토큰이 37% 감소하고 정확도가 향상되었음을 관찰했습니다(지식 검색 정확도가 25.6%에서 28.5%로 향상).

### 설계상 더 안전합니다
Code Mode는 다음과 같은 기본 보안 이점을 제공합니다:
- **매개변수에 API 키가 없음**: API 키는 서버 측에서 주입되며 LLM으로 전송되는 도구 매개변수에 노출되지 않습니다.
- **격리된 샌드박스**: 코드는 네트워크 또는 호스트 파일 시스템에 액세스할 수 없는 안전한 환경에서 실행됩니다.
- **제어된 SDK**: 승인된 SDK 메서드만 에이전트가 사용할 수 있습니다.

### 모든 규모의 API로 확장됩니다
API가 성장하면 더 많은 도구를 컨텍스트에 로드해야 하므로 기존 MCP의 성능이 저하됩니다. Code Mode는 API의 표면적 규모와 관계없이 2개의 도구로 일정하게 유지됩니다. Cloudflare는 2,500개가 넘는 API 엔드포인트를 단 2개의 도구와 약 1,000개의 컨텍스트 토큰으로 통합했습니다.

<Info>
이 아키텍처의 이점에 관한 자세한 내용은 [Anthropic](https://www.anthropic.com/engineering/advanced-tool-use) 및 [Cloudflare](https://blog.cloudflare.com/code-mode/)의 엔지니어링 블로그와 Claude의 [Programmatic Tool Calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) 문서를 참조하세요.
</Info>
