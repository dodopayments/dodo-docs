## 개요

테스트 모드를 사용하면 실제 거래를 처리하지 않고 결제를 시뮬레이션할 수 있습니다. 모든 테스트 자격 증명은 테스트 모드에서만 작동하므로 프로덕션에서는 절대 사용하지 마세요.

<CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
테스트 거래는 실제 결제를 처리하지 않으며 실제 계정에 영향을 주지 않습니다.
</Card>

<Card title="Full API Access" icon="code">
모든 API endpoint는 테스트 모드와 live 모드에서 동일하게 작동합니다.
</Card>

<Card title="Webhook Testing" icon="webhook">
테스트 거래에서도 프로덕션과 마찬가지로 웹훅이 발생합니다.
</Card>
</CardGroup>

<Warning>
테스트 자격 증명은 테스트 모드에서만 작동합니다. 이를 live 모드에서 사용하려고 하면 결제가 실패합니다.
</Warning>

## 테스트 카드

이 카드 번호를 사용하여 여러 지역에서 승인 및 거절된 결제를 시뮬레이션하세요.

<Tabs>
<Tab title="Successful Payments">
| 지역 | 브랜드 | 카드 번호 | 만료일 | CVV |
| :----- | :---- | :---------- | :----- | :-- |
| US | Visa | `4242424242424242` | 06/32 | 123 |
| US | Mastercard | `5555555555554444` | 06/32 | 123 |
| 인도 | Visa | `4576238912771450` | 06/32 | 123 |
| 인도 | Mastercard | `5409162669381034` | 06/32 | 123 |
</Tab>

<Tab title="Declined Payments">
| 지역 | 브랜드 | 카드 번호 | 시나리오 | 결과 `error_code` |
| :----- | :---- | :---------- | :------- | :--------------------- |
| US | Visa | `4000000000000002` | 일반적인 거절 | `GENERIC_DECLINE` |
| US | Mastercard | `4000000000009995` | 잔액 부족 | `INSUFFICIENT_FUNDS` |
| 인도 | Visa | `4706131211212123` | 일반적인 거절 | `GENERIC_DECLINE` |
| 인도 | Mastercard | `5105105105105100` | 일반적인 거절 | `GENERIC_DECLINE` |

이 카드 중 하나가 거절되면 결제의 `error_code` 및 `error_message`에 위 시나리오가 반영됩니다. [Transaction Failures](/api-reference/transaction-failures) reference에서 코드를 조회하여 의미와 권장 조치를 확인하고, 통합에서 거절을 처리하는 방법은 [Handle Payment Failures](/developer-resources/handle-payment-failures)를 참조하세요.
</Tab>

<Tab title="Subscription Failure Testing (Renewal/Upgrade/Downgrade)">
| 카드 번호 | 만료일 | CVC |
| :---------- | :----- | :-- |
| `4000 0000 0000 0341` | 12/34 | 123 |

이 카드를 사용하여 subscription Failure 갱신, 업그레이드 및 다운그레이드 시나리오를 테스트하세요.
</Tab>
</Tabs>

<Info>
모든 테스트 카드에는 만료일 **06/32**(또는 **12/34**)와 CVV **123**을 사용하세요.
</Info>

### 갱신 실패 테스트 방법

<Steps>
<Step title="Create a test subscription">
**성공** 테스트 카드(예: `4242 4242 4242 4242`)를 사용하여 테스트 API 키로 subscription을 생성하세요. 초기 청구가 성공하고 subscription이 active 상태가 되어야 합니다.
</Step>

<Step title="Swap in the failure card via Customer Portal">
[Customer Portal](/features/customer-portal)을 열고 방금 생성한 subscription을 찾은 다음 **Update Payment Method**를 클릭하세요. 실패 테스트 카드 `4000 0000 0000 0341`(만료일: `12/34`, CVC: `123`)를 입력하고 subscription의 결제 수단으로 저장하세요.
</Step>

<Step title="Advance the next billing date (optional)">
자연스러운 billing cycle을 기다리는 대신 즉시 갱신을 트리거하려면 Update Subscription API를 사용하여 `next_billing_date`을 현재 UTC 시간으로 설정하세요. 값은 ISO 8601 / RFC 3339 UTC timestamp여야 합니다(`Z` suffix가 필요함).

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

자세한 내용은 [Update Subscription API reference](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0)를 참조하세요.
</Step>

<Step title="Verify the failure">
다음 billing 시도에서:

- 갱신 청구가 실패 카드에서 거절됩니다
- subscription이 **On-Hold** 상태로 전환됩니다
- `payment.failed` 웹훅 event가 전달됩니다
- 고객은 Customer Portal로 돌아가 결제 수단을 업데이트하고 재시도할 수 있습니다
</Step>
</Steps>

<Warning>
이 카드는 갱신 실패를 테스트하기 위한 전용 카드입니다. 다음 billing date에 청구가 거절되므로 결제 retry logic, 고객 알림 및 실패 처리를 테스트할 수 있습니다.
</Warning>

## 테스트 UPI

UPI 테스트에서는 서로 다른 결제 결과를 시뮬레이션하는 특수 VPA(Virtual Payment Address) 식별자를 사용합니다.

| 상태 | UPI ID |
| :----- | :----- |
| 성공 | `success@upi` |
| 실패 | `failure@upi` |

### UPI 테스트 요구 사항

- Billing country는 `IN`로 설정해야 합니다
- Currency는 `INR`여야 합니다
- 인도 외 merchant의 경우: Adaptive Currency을 활성화해야 합니다

subscription의 RBI mandate 테스트를 포함한 전체 UPI 문서는 [India Payment Methods](/features/payment-methods/india) 페이지를 참조하세요.

## 테스트 BNPL

Buy Now Pay Later provider에는 특정 테스트 데이터 요구 사항이 있습니다.

### Klarna 테스트 데이터

테스트 모드에서 Klarna 결제를 시뮬레이션하려면 다음 정보를 사용하세요:

| 필드 | 승인됨 | 거절됨 |
| :---- | :------- | :----- |
| **생년월일** | 07-10-1970 | 07-10-1970 |
| **이름** | Test | Test |
| **성** | Person-us | Person-us |
| **Email** | customer@email.us | customer+denied@email.us |
| **Street** | Amsterdam Ave | Amsterdam Ave |
| **House Number** | 509 | 509 |
| **City** | New York | New York |
| **State** | New York | New York |
| **Postal Code** | 10024-3941 | 10024-3941 |
| **Phone** | +13106683312 | +13106354386 |

<Note>
Klarna가 결제 옵션으로 표시되려면 최소 거래 금액이 **$50.01**이어야 합니다.
</Note>

### Afterpay 테스트

<Steps>
<Step title="Select Afterpay">
checkout에서 Afterpay를 결제 수단으로 선택하고 Pay를 클릭하세요.
</Step>

<Step title="Test successful payment">
성공한 결제에는 유효한 이메일 주소와 배송 주소를 사용하세요.
</Step>

<Step title="Test failed authentication">
실패를 시뮬레이션하려면 redirect page에서 Afterpay modal window를 닫으세요. 결제는 `requires_action`에서 `requires_payment_method`로 전환됩니다.
</Step>
</Steps>

<Note>
Afterpay가 결제 옵션으로 표시되려면 최소 거래 금액이 **$50.01**이어야 합니다.
</Note>

Billie B2B 테스트를 포함한 전체 BNPL 문서는 [Buy Now Pay Later](/features/payment-methods/bnpl) 페이지를 참조하세요.

## Digital Wallet 테스트

### Apple Pay

<Steps>
<Step title="Enable test mode">
Dodo Payments 테스트 API keys를 사용하세요.
</Step>

<Step title="Add a card to Apple Wallet">
실제 카드를 Apple Wallet에 추가하세요. 테스트 모드에서는 카드에 요금이 청구되지 않습니다.
</Step>

<Step title="Complete test purchase">
Apple device에서 checkout을 열고 Apple Pay flow를 완료하세요.
</Step>
</Steps>

<Warning>
Apple Pay에는 HTTPS가 필요합니다. 적절한 SSL 설정 없이는 `localhost`에 표시되지 않습니다. Domain verification도 완료되어야 합니다.
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
테스트 카드가 wallet에 자동으로 추가되도록 [Google Pay 테스트 카드 그룹에 참여](https://groups.google.com/g/googlepay-test-mode-stub-data)하세요.
</Step>

<Step title="Enable test mode">
Dodo Payments 테스트 API keys를 사용하세요.
</Step>

<Step title="Complete test purchase">
거래를 완료하려면 Google Pay에서 테스트 카드 중 하나를 선택하세요.
</Step>
</Steps>

### Amazon Pay, Cash App Pay 및 RevolutPay

테스트 API keys를 사용하고 표준 checkout flow를 따르세요. 테스트 거래는 실제 청구 없이 시뮬레이션됩니다.

Apple Pay의 domain verification을 포함한 전체 digital wallet 문서는 [Digital Wallets](/features/payment-methods/digital-wallets) 페이지를 참조하세요.

## European Methods 테스트

유럽 결제 수단(iDEAL, Bancontact, EPS, Multibanco)은 sandbox mode에서 테스트할 수 있습니다.

<Steps>
<Step title="Enable test mode">
Dodo Payments 테스트 API keys를 사용하세요.
</Step>

<Step title="Set billing address">
청구지 주소의 국가를 결제 수단에 맞게 설정하세요:
- `NL`(iDEAL)
- `BE`(Bancontact)
- `AT`(EPS)
- `PT`(Multibanco)
</Step>

<Step title="Set currency">
유럽 결제 수단에는 EUR currency가 필요합니다.
</Step>

<Step title="Complete test flow">
test environment에서 시뮬레이션된 bank authentication flow를 따르세요.
</Step>
</Steps>

전체 유럽 결제 수단 문서는 [Europe](/features/payment-methods/europe) 페이지를 참조하세요.

## Testing Best Practices

<AccordionGroup>
<Accordion title="Test all payment scenarios">
성공한 결제만 테스트하지 마세요. 결제 거절, 취소, 잔액 부족과 같은 edge case도 테스트하세요.
</Accordion>

<Accordion title="Verify webhook handling">
webhook endpoint가 모든 event type, 특히 `payment.succeeded`, `payment.failed` 및 subscription event를 올바르게 처리하는지 확인하세요.

webhook을 로컬에서 테스트하려면 [Dodo Payments CLI](/developer-resources/sdks/cli#webhook-testing)를 사용하세요:
- `dodo wh listen`는 실제 test webhook을 로컬 서버로 전달합니다.
- `dodo wh trigger`는 22개 event type 모두에 대한 mock payload를 전송합니다.
</Accordion>

<Accordion title="Test on real devices">
Apple Pay와 Google Pay는 실제 iOS 및 Android device에서 테스트하세요. Simulator는 wallet 동작을 완전히 재현하지 못합니다.
</Accordion>

<Accordion title="Test regional methods with correct addresses">
지역 결제 수단(UPI, iDEAL 등)은 일치하는 청구지 주소가 필요합니다. 미국 청구지 주소를 사용하면 iDEAL이 표시되지 않습니다.
</Accordion>

<Accordion title="Verify minimum amounts">
BNPL 결제 수단에는 $50.01의 최소 금액이 필요합니다. cart total에 따라 결제 수단이 올바르게 표시되거나 숨겨지는지 테스트하세요.
</Accordion>
</AccordionGroup>
