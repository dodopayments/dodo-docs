## 고객 포털이란?

포털은 고객이 다음을 수행할 수 있는 신뢰할 수 있는 브랜드의 셀프 서비스 경험을 제공합니다:

- **청구 내역에 접근하기**: 청구서를 보고 영수증을 다운로드합니다.
- **구독 관리**: 구독 세부 정보를 보고, 즉시 또는 다음 청구일에 구독을 취소합니다.
- **결제 수단 업데이트**: 활성 구독의 결제 수단을 변경하거나 보류 중인 구독을 재활성화합니다.
- **라이선스 키 가져오기**: 구매와 연관된 모든 키에 접근합니다.
- **간편한 탐색**: 뒤로 가기 버튼을 사용하여 포털 섹션 간에 쉽게 이동할 수 있습니다.

## 주요 이점

- **지원 요청 감소**: 고객이 일반적인 청구 요청을 스스로 해결합니다.
- **가치 실현 속도 향상**: 청구서와 키에 즉시 접근합니다.
- **이탈 위험 감소**: 갱신 및 요금제 세부정보에 대한 명확한 가시성 제공
- **설계상 안전**: 만료되는 링크로 토큰화된 접근 제공

## 접근 방법

고객은 정적 링크 또는 일회성 동적 링크를 사용하여 포털에 접근할 수 있습니다.

### 정적 링크 (이메일 기반 접근)

고객은 만료되지 않는 정적 링크에 이메일을 입력하여 포털 접근을 요청할 수 있습니다.

정적 포털 링크 형식은 환경에 따라 다릅니다:

**테스트 모드** (테스트 및 개발용):

```bash
https://test.customer.dodopayments.com/login/{business_id}
```

**실제 모드** (실제 거래용):

```bash
https://customer.dodopayments.com/login/{business_id}
```

`{business_id}`을 실제 비즈니스 식별자로 교체한 다음 적절한 링크를 고객과 공유하여 이메일을 입력하고 포털에 안전하게 액세스할 수 있도록 합니다.

### 동적 링크 (매직 링크)

고객을 포털로 직접 보내는 개인화된 일회성 매직 링크입니다. 링크는 24시간 후에 만료됩니다.

<Warning>
동적 링크는 24시간 후에 만료됩니다. 만료되면 새 링크를 생성하여 보내십시오.
</Warning>

## 요금제 변경(업그레이드/다운그레이드)

제품이 **Product Collections**로 구성되어 있을 때 고객은 고객 포털에서 플랜 간 업그레이드 또는 다운그레이드를 직접 수행할 수 있습니다.

<Tip>
**기존 구독에 대해 업그레이드/다운그레이드를 활성화하고 싶으신가요?** 구독 제품을 Product Collection에 추가하세요. 그룹화되면 고객은 고객 포털을 통해 동일한 컬렉션 내에서 플랜을 전환할 수 있습니다.
</Tip>

### 사용 가능한 작업

| 작업 | 설명 | 사용 가능 조건 |
|--------|-------------|----------------|
| **Upgrade** | 동일한 컬렉션의 상위 단계 플랜으로 이동 | 비즈니스에서 구독 업데이트를 활성화한 경우 |
| **Downgrade** | 동일한 컬렉션의 하위 단계 플랜으로 이동 | 비즈니스에서 구독 업데이트를 활성화한 경우 |

### 요금제 변경 작동 방식

1. 고객이 포털에서 현재 구독을 확인합니다.
2. 제품 컬렉션을 기반으로 이용 가능한 업그레이드/다운그레이드 옵션이 표시됩니다.
3. 고객이 새 플랜을 선택합니다.
4. 비례 계산이 수행되고 결제가 즉시 처리됩니다(해당되는 경우).
5. 구독이 새 플랜으로 업데이트됩니다.

<Info>
요금제 변경은 동일한 컬렉션 내의 제품 간에서만 가능합니다. 제품은 구독 또는 사용량 기반 청구 유형이어야 합니다.
</Info>

### 비즈니스 제어

비즈니스는 구독 설정에서 요금제 변경 동작을 구성할 수 있습니다:

- **Allow Subscription Updates**: 고객이 구독을 업그레이드하거나 다운그레이드할 수 있는 기능을 활성화하거나 비활성화합니다

## 구독 세부 정보

고객이 활성 구독에서 "Manage subscription"을 클릭하면 구독 세부 정보 페이지로 이동합니다. 이 페이지는 다음을 보여줍니다:

- **Plan details**: 구독 이름, 가격, 갱신 날짜 및 유효 기간
- **Payment method**: 구독에 연결된 카드 또는 결제 수단과 "Edit" 버튼
- **Billing information**: 이름, 이메일, 전화번호 및 청구 주소와 "Edit" 버튼
- **Billing history**: 이 구독에 대한 모든 결제의 자세한 표
- **Cancel Subscription**: 구독을 취소하는 눈에 띄는 버튼

비즈니스는 Subscription Settings에서 포털 구독 동작을 구성할 수 있습니다:

- **Allow Subscription Updates**: 고객이 구독을 업그레이드하거나 다운그레이드할 수 있는 기능을 활성화하거나 비활성화합니다
- **Allow Subscription Cancellation**: 고객이 직접 구독을 취소할 수 있는 기능을 활성화하거나 비활성화합니다

고객은 구독 세부 정보 페이지에서 구독을 직접 취소할 수 있습니다. "Cancel Subscription"을 클릭하면 두 가지 옵션이 있는 확인 대화 상자가 열립니다:

- **Cancel at next billing date**: 구독은 현재 청구 기간이 끝날 때까지 유지되며, 이후 자동으로 취소됩니다.
- **Cancel now**: 구독이 즉시 취소됩니다.

</Frame>

## 결제 수단 업데이트

고객은 구독 세부 정보 페이지의 결제 수단 옆에 있는 "Edit"을 클릭하여 직접 결제 수단을 업데이트할 수 있습니다. 실패한 결제로 인해 보류된 구독을 다시 활성화할 때 특히 중요합니다.

### 보류된 구독 재활성화

결제 실패로 인해 구독이 `on_hold` 상태로 전환되면 고객은 결제 수단을 업데이트하여 구독을 재활성화해야 합니다. 업데이트 프로세스는 자동으로 다음을 수행합니다:

1. **남은 금액에 대한 청구를 생성합니다**
2. **해당 청구에 대한 청구서를 생성합니다**
3. **새 결제 수단을 사용하여 결제를 처리합니다**
4. **성공적인 결제 후 구독을 `active` 상태로 재활성화합니다**

<Info>
Self-service cancellation은 기본적으로 활성화되어 있는 **Allow Subscription Cancellation** 설정으로 제어되며, **Settings → Subscriptions**에서 관리할 수 있습니다. 이 기능을 끄면 Cancel Subscription 버튼이 비활성화되고 고객에게 판매자에게 문의하라는 tooltip이 표시됩니다. 또한 포털에서 제공되는 두 가지 취소 경로인 즉시 취소와 다음 billing date에 취소가 모두 거부됩니다. 이미 예약된 취소가 있는 고객에게는 취소를 철회할 수 있는 옵션이 계속 표시되므로, 구독을 유지하도록 선택할 수 있습니다. 판매자가 직접 수행하는 취소에는 이 설정이 적용되지 않습니다.
</Info>

### 취소 사유

취소를 확정하기 전에 고객은 **"Why are you cancelling?"**이라는 질문을 받고, 엄선된 목록에서 사유를 선택하도록 안내받습니다. 선택한 사유는 구독에 저장되며 webhook payload와 API에도 표시되므로, 이탈 원인을 분석하고 win-back 플로우를 맞춤 설정할 수 있습니다.

<Frame>
    <img src="/images/customer-portal/cancellation-reasons.png" alt="Cancellation modal with the 'Why are you cancelling?' dropdown showing reasons like Too expensive, Missing features, and Other" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

| Value | Customer-facing label |
|-------|----------------------|
| `too_expensive` | 너무 비쌈 |
| `missing_features` | 기능 부족 |
| `switched_service` | 다른 서비스로 전환함 |
| `unused` | 충분히 사용하지 않음 |
| `customer_service` | 고객 서비스 불만족 |
| `low_quality` | 품질 낮음 |
| `too_complex` | 너무 복잡함 |
| `other` | 기타 |

선택한 값은 구독의 `cancellation_feedback` 필드에 기록됩니다. 선택 사항으로 자유 형식 텍스트 `cancellation_comment`도 수집할 수 있습니다.

```typescript
// Read the captured feedback after a customer cancels
const subscription = await client.subscriptions.retrieve('sub_123');
console.log(subscription.cancellation_feedback); // e.g., "too_expensive"
console.log(subscription.cancellation_comment);  // e.g., "Switching to a competitor"
```

두 필드는 `subscription.cancelled` webhook payload에도 포함되며, API를 통해 취소를 예약하거나 실행할 때 `PATCH /subscriptions/{subscription_id}`에서 프로그래밍 방식으로 값을 입력할 수 있습니다.

<Tip>
`cancellation_feedback`를 [Subscription Dunning](/features/recovery/subscription-dunning)과 함께 사용하여 win-back 이메일을 맞춤 설정할 수 있습니다. 예를 들어 `too_expensive` 취소 고객에게 할인 코드를 보내고, `missing_features` 취소 고객에게 "무엇이 부족했나요?" 설문조사를 보낼 수 있습니다.
</Tip>

## 결제 수단 업데이트

고객은 구독 세부정보 페이지에서 결제 수단 옆의 "Edit"를 클릭하여 결제 수단을 직접 업데이트할 수 있습니다. 이 기능은 결제 실패로 인해 보류된 구독을 재활성화하는 데 특히 중요합니다.

### 보류된 구독 재활성화

결제 실패로 인해 구독이 `on_hold` 상태가 되면 고객은 구독을 재활성화하기 위해 결제 수단을 업데이트해야 합니다. 업데이트 프로세스는 자동으로 다음 작업을 수행합니다:

1. **청구 생성**: 미납 금액에 대한 charge를 생성합니다
2. **invoice 생성**: charge에 대한 invoice를 생성합니다
3. **결제 처리**: 새로운 결제 수단을 사용하여 결제를 처리합니다
4. **구독 재활성화**: 결제가 성공하면 구독을 `active` 상태로 재활성화합니다

<Warning>
`on_hold` 상태의 구독은 자동으로 갱신되지 않습니다. 고객은 미납 금액을 정산하고 구독을 재활성화하기 위해 결제 수단을 업데이트해야 합니다.
</Warning>

<Info>
`on_hold` 구독의 결제 수단을 성공적으로 업데이트하면 고객에게 확인 페이지가 표시되고, 결제 성공 및 구독 재활성화에 대한 이메일 알림이 전송됩니다.
</Info>

### 결제 수단 업데이트 플로우

<Steps>
<Step title="Access subscription details">
포털 홈 페이지에서 활성 구독을 선택한 다음 "Manage subscription"을 클릭합니다.
</Step>

<Step title="Click Edit on payment method">
결제 수단 옆의 "Edit" 버튼을 클릭하여 결제 수단 업데이트 인터페이스를 엽니다.
</Step>

<Step title="Select or add payment method">
기존에 저장된 결제 수단을 선택하거나 카드 정보를 안전하게 입력하여 새 결제 수단을 추가합니다.
</Step>

<Step title="Confirm changes">
업데이트를 확정합니다. `on_hold` 구독의 경우 미납 금액에 대한 charge가 자동으로 생성됩니다.
</Step>

<Step title="Complete payment (if on hold)">
구독이 보류 상태라면 고객은 미납 금액에 대한 결제를 완료하는 화면으로 리디렉션됩니다. 결제가 성공하면 구독이 자동으로 재활성화됩니다.
</Step>

<Step title="Confirmation">
고객에게 결제 수단이 업데이트되었다는 확인 메시지가 표시되며, 해당하는 경우 구독이 재활성화되었다는 안내도 표시됩니다.
</Step>
</Steps>

## 통합 Customer Portal

비즈니스별 고객 포털 외에도 Dodo Payments는 [customer.dodopayments.com](https://customer.dodopayments.com)에서 **Unified Customer Portal**을 제공합니다. 고객은 이 포털에서 Dodo Payments를 사용하는 여러 비즈니스의 모든 구매 내역과 구독을 확인하고 관리할 수 있습니다.

<Frame>
    <img src="/images/changelog/unified-customer-portal.png" alt="Unified Customer Portal" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### 통합 포털 기능

- **비즈니스 간 가시성**: 모든 Dodo Payments merchant의 구매 내역과 구독을 한곳에서 확인합니다
- **중앙 집중식 관리**: 단일 dashboard에서 여러 비즈니스의 구독을 관리합니다
- **통합 billing history**: 모든 구매 내역의 invoice와 결제 기록에 액세스합니다
- **통합 로그인**: 이메일로 한 번 로그인하여 모든 Dodo Payments merchant의 구매 내역에 액세스합니다

<Tip>
Unified Customer Portal은 비즈니스별 포털을 보완합니다. 고객은 선호도에 따라 브랜드가 적용된 merchant 포털 또는 통합 포털을 사용할 수 있습니다.
</Tip>

## 문제 해결

- **링크 만료**: 새 dynamic link를 생성하여 전송합니다.
- **이메일 인식 불가**: 고객에게 구매에 사용한 이메일을 사용하도록 안내합니다
- **구독 보류**: 구독이 보류된 경우 고객은 미납 금액을 정산하고 구독을 재활성화하기 위해 포털에서 결제 수단을 업데이트해야 합니다. 업데이트 프로세스에서 미납 금액이 자동으로 청구됩니다.
- **결제 수단 업데이트 실패**: `on_hold` 구독의 업데이트 과정에서 결제가 실패하면 구독은 보류 상태로 유지됩니다. 고객은 다른 결제 수단으로 다시 시도할 수 있습니다.
