## 하이브리드 결제란 무엇인가요?

하이브리드 결제는 여러 가격 책정 기준을 하나의 제품 상품으로 결합합니다. 정액 구독과 사용량 기반 가격 중 하나만 선택하는 대신 두 방식을 함께 사용할 수 있습니다.

### 하이브리드 결제를 사용하는 이유

| 비즈니스 목표 | 하이브리드 솔루션 |
|--------------|-----------------|
| 예측 가능한 수익 + 성장 가능성 | 기본 구독 + 사용량 초과 요금 |
| 확장 가능한 팀 요금제 | 좌석별 요금 + 기능 추가 기능 |
| 고객을 먼저 확보하고 나중에 확장 | 낮은 기본 요금 + 사용량 요금 |
| 엔터프라이즈 유연성 | 약정 지출 + 주문형 요금 |
| 변동 사용량에 공정한 가격 | 포함된 허용량 + 사용량당 결제 |

### 일반적인 하이브리드 패턴

| 모델 | 설명 | 예시 | 기본 지원 |
|-------|-------------|---------|----------------|
| **1. 구독 + 사용량** | 기본 요금 + 사용량 요금 | \$49/월 + 무료 10K 초과 시 API 호출당 \$0.01 | ✅ 전체 지원 |
| **2. 구독 + 좌석 수** | 플랫폼 요금 + 사용자별 요금 | \$99/월 + 좌석당 \$15 | ✅ 전체 지원 |
| **3. 구독 + 기능 추가 기능** | 핵심 요금제 + 선택적 업그레이드 | \$29/월 + 분석 \$19/월 + API 액세스 \$9/월 | ✅ 전체 지원 |
| **4. 좌석 수 + 사용량** | 사용자별 요금 + 사용량 초과 요금 | \$10/사용자/월 + 사용자당 5GB 초과 시 \$0.05/GB | ⚠️ 우회 방법 필요 |
| **5. 구독 + 좌석 수 + 사용량** | 플랫폼 + 사용자 + 사용량(3중 하이브리드) | \$199/월 + 좌석당 \$20 + 사용량 초과 요금 | ⚠️ 우회 방법 필요 |
| **6. 단계별 기본 요금 + 사용량 초과 요금** | 허용량이 서로 다른 단계별 요금제 | Starter(5K 호출)와 Pro(50K 호출) + 초과 요금 | ✅ 전체 지원 |
| **7. 구독 + 주문형 요금** | 반복 요금 + 변동 수동 요금 | \$99/월 리테이너 + 작업 시간별 청구 | ✅ 전체 지원 |

## 하이브리드 모델 1: 구독 + 사용량

가장 일반적인 하이브리드 모델입니다. 고객은 기본 구독 요금을 지불하고, 포함된 허용량을 초과한 사용량에 대해서는 추가 요금을 지불합니다.

### 작동 방식

**Pro 요금제: 월 $49**

- **포함**: 월 10,000회 API 호출
- **초과 요금**: 10,000회 초과분에 대해 호출당 $0.005

**계산 예시** (이번 달 고객 사용량이 25,000회 호출인 경우):
- 기본 구독: $49.00
- 초과 요금: (25,000 - 10,000) × $0.005 = $75.00
- **합계: $124.00**

### 사용 사례

- **API 플랫폼**: 기본 액세스 + 요청별 요금
- **AI/ML 서비스**: 구독 + 토큰/생성 사용량
- **스토리지 서비스**: 기본 요금제 + GB별 초과 요금
- **커뮤니케이션 플랫폼**: 기본 요금 + 메시지/분당 요금

### 구현

<Steps>
<Step title="Create Usage Meter">
청구 가능한 사용량 기준을 추적하도록 meter를 설정합니다.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
구독 제품을 생성하고 가격 정보가 포함된 사용량 meter를 연결합니다.

```bash
Dashboard: Create Product → Subscription
Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
사용량 meter는 구독 제품에 직접 연결됩니다. 사용량 요금은 자동으로 계산되어 구독 인보이스에 추가됩니다.
</Info>
</Step>

<Step title="Create Checkout Session">
구독 제품으로 checkout session을 생성합니다.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_pro_plan', quantity: 1 }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Send Usage Events">
청구 기간 전체에서 사용량을 추적합니다.

```typescript
await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [{
      event_id: `call_${Date.now()}`,
      customer_id: 'cus_123',
      event_name: 'api.call',
      timestamp: new Date().toISOString(),
      metadata: { endpoint: '/v1/generate' }
    }]
  })
});
```

</Step>
</Steps>

### 가격 책정 방식

<Tabs>
<Tab title="Included Allowance">
무료 임계값은 기본 구독에 포함된 사용량을 충당합니다.

**Pro 요금제: 월 $49**
- 포함: API 호출 10,000회
- 초과 요금: 10,000회 초과 시 호출당 $0.005
- 고객이 8,000회 사용 → $49 지불(초과 요금 없음)
</Tab>

<Tab title="Zero Base + Pure Usage">
기본 요금 없이 첫 사용부터 모든 단위에 요금이 부과됩니다.

**종량제: 기본 요금 월 $0**
- 포함: API 호출 0회
- 사용량: 첫 호출부터 호출당 $0.01
- 고객이 5,000회 사용 → $50 지불
</Tab>

<Tab title="Tiered Allowances">
단계별로 서로 다른 허용량을 포함합니다.

- **Starter**: 월 $19(호출 1,000회 포함)
- **Pro**: 월 $49(호출 10,000회 포함)
- **Enterprise**: 월 $199(호출 100,000회 포함)
- 모든 단계: 호출당 $0.005의 초과 요금
</Tab>
</Tabs>

## 하이브리드 모델 2: 구독 + 좌석 수

플랫폼 요금에 사용자별 요금을 더하는 방식입니다. 팀 협업 도구와 B2B SaaS에 적합합니다.

### 작동 방식

**Team 요금제: 월 $99 + 좌석당 $15**

- **기본 플랫폼 요금**: 월 $99(좌석 3개 포함)
- **추가 좌석**: 좌석당 월 $15

**계산 예시** (사용자 12명으로 구성된 팀):
- 플랫폼 요금: $99.00
- 추가 좌석: (12 - 3) × $15 = $135.00
- **합계: 월 $234.00**

### 사용 사례

- **협업 도구**: 워크스페이스 요금 + 구성원별 요금
- **CRM 시스템**: 플랫폼 라이선스 + 영업 담당자별 요금
- **프로젝트 관리**: 팀 요금제 + 기여자별 요금
- **개발자 도구**: 조직 요금 + 개발자별 요금

### 구현

<Steps>
<Step title="Create Seat Add-on">
추가 좌석용 add-on을 생성합니다.

```bash
Dashboard: Products → Add-ons → Create Add-on
Name: "Additional Seat"
Price: $15/month
Description: "Add another team member"
```

</Step>

<Step title="Create Base Subscription">
플랫폼 요금으로 구독 제품을 생성하고 add-on을 연결합니다.

```bash
Dashboard: Create Product → Subscription
Name: "Team Plan"
Price: $99/month
Description: "Includes 3 team members"

Then in Add-ons section:
- Attach: "Additional Seat" add-on
```

</Step>

<Step title="Create Checkout with Seats">
checkout 중 좌석 수를 지정합니다.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{
    product_id: 'prod_team_plan',
    quantity: 1,
    addons: [{
      addon_id: 'addon_seat',
      quantity: 9  // 9 extra seats (12 total with 3 included)
    }]
  }],
  customer: { email: 'admin@company.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Adjust Seats as Needed">
기존 구독에서 좌석을 추가하거나 제거합니다.

```typescript
// Add 5 more seats
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_team_plan',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  addons: [{
    addon_id: 'addon_seat',
    quantity: 14  // New total: 14 extra seats
  }]
});
```

</Step>
</Steps>

### 가격 책정 방식

<Tabs>
<Tab title="Included Seats">
기본 요금제에 일부 좌석을 포함하고 추가 좌석에는 요금을 부과합니다.

**Team 요금제: 월 $99**
- 포함: 좌석 5개
- 추가 좌석: 좌석당 월 $15
- 사용자 20명 = \$99 + (15 × \$15) = 월 \$324
</Tab>

<Tab title="Pure Per-Seat">
플랫폼 요금 없이 사용자별 요금만 부과합니다.

**사용자별 요금: 사용자당 월 $25**
- 플랫폼 요금 없음
- 사용자 5명 = 월 $125
- 사용자 50명 = 월 $1,250

구현: 기본 구독 가격을 $0으로 설정하고 좌석 add-on만 사용합니다.
</Tab>

<Tab title="Tiered Per-Seat">
상위 단계일수록 좌석별 가격이 낮아집니다.

- **Starter**: 좌석당 $20(좌석 1~10개)
- **Growth**: 좌석당 $15(좌석 11~50개)
- **Enterprise**: 좌석당 $10(좌석 51개 이상)

구현: 각 단계마다 서로 다른 add-on 가격을 적용한 별도의 구독 제품을 생성합니다.
</Tab>
</Tabs>

## 하이브리드 모델 3: 구독 + 기능 추가 기능

고객이 선택적으로 추가할 수 있는 기능 업그레이드가 포함된 핵심 구독입니다.

### 작동 방식

**Core 요금제: 월 $29**

**선택적 add-on:**
- 고급 분석: +월 $19
- API 액세스: +월 $9
- 우선 지원: +월 $29
- 화이트 라벨: +월 $49

**계산 예시** (고객이 Core + 분석 + API 액세스를 선택한 경우):
- Core 요금제: $29.00
- 분석: $19.00
- API 액세스: $9.00
- **합계: 월 $57.00**

### 사용 사례

- **SaaS 플랫폼**: 핵심 기능 + 프리미엄 모듈
- **마케팅 도구**: 기본 도구 + 통합 기능
- **분석 제품**: 대시보드 + 고급 보고서
- **보안 소프트웨어**: 기본 보호 + 고급 기능

### 구현

<Steps>
<Step title="Create Feature Add-ons">
각 선택적 기능에 대한 add-on을 생성합니다.

```bash
# Add-on 1: Advanced Analytics
Dashboard: Products → Add-ons → Create Add-on
Name: "Advanced Analytics"
Price: $19/month

# Add-on 2: API Access
Name: "API Access"
Price: $9/month

# Add-on 3: Priority Support
Name: "Priority Support"
Price: $29/month

# Add-on 4: White-label
Name: "White-label"
Price: $49/month
```

</Step>

<Step title="Create Core Subscription">
기본 구독을 정의하고 모든 기능 add-on을 연결합니다.

```bash
Dashboard: Create Product → Subscription
Name: "Core Plan"
Price: $29/month

Then in Add-ons section:
- Attach all feature add-ons
```

</Step>

<Step title="Let Customers Choose">
선택한 기능으로 checkout합니다.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{
    product_id: 'prod_core_plan',
    quantity: 1,
    addons: [
      { addon_id: 'addon_analytics', quantity: 1 },
      { addon_id: 'addon_api_access', quantity: 1 }
      // Customer didn't select support or white-label
    ]
  }],
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Add Features Later">
고객은 기존 구독에 기능을 추가할 수 있습니다.

```typescript
// Customer wants to add Priority Support
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_core_plan',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  addons: [
    { addon_id: 'addon_analytics', quantity: 1 },
    { addon_id: 'addon_api_access', quantity: 1 },
    { addon_id: 'addon_priority_support', quantity: 1 }  // New!
  ]
});
```

</Step>
</Steps>

## 하이브리드 모델 4: 좌석 수 + 사용량

사용자별 요금과 사용량 기반 요금을 결합합니다. 각 사용자에게 허용량이 제공됩니다.

<Warning>
**제약 사항**: Dodo Payments은(는) 현재 하나의 구독 제품에 사용량 meter와 add-on을 동시에 연결하는 기능을 지원하지 않습니다. 이 모델에는 애플리케이션 수준의 로직을 사용하는 우회 방법이 필요합니다.
</Warning>

<Info>
**곧 출시 예정**: 좌석 수 + 사용량 하이브리드 결제에 대한 기본 지원이 로드맵에 포함되어 있습니다. 이를 통해 하나의 구독 제품에 사용량 meter와 좌석 add-on을 모두 연결할 수 있게 됩니다.
</Info>

### 작동 방식

**Team Analytics: 사용자당 월 $20**

**각 사용자에게 포함되는 항목:**
- 월 5GB 데이터 처리
- 초과 요금: 허용량 초과 시 GB당 $2

**계산 예시** (사용자 10명으로 구성된 팀이 총 80GB를 사용한 경우):
- 좌석 요금: 10 × $20 = $200.00
- 포함 데이터: 10 × 5GB = 50GB
- 초과 요금: (80 - 50) × $2 = $60.00
- **합계: 월 $260.00**

### 사용 사례

- **분석 플랫폼**: 분석가별 요금 + 데이터 처리
- **디자인 도구**: 디자이너별 요금 + 스토리지/내보내기
- **개발 환경**: 개발자별 요금 + 컴퓨팅 시간
- **커뮤니케이션 도구**: 사용자별 요금 + 메시지/통화량

### 구현 옵션

동일한 구독에 사용량 meter와 add-on을 모두 연결할 수 없으므로 다음 방법 중 하나를 선택하세요:

<Tabs>
<Tab title="Option A: Usage Product + App-Managed Seats">
사용량 기반 구독을 사용하고 애플리케이션에서 좌석 결제를 관리합니다.

<Steps>
<Step title="Create Usage Meter">

```bash
Dashboard: Meters → Create Meter
Event Name: "data.processed"
Aggregation: Sum
Property: "bytes"
```

</Step>

<Step title="Create Usage-Based Subscription">

```bash
Dashboard: Create Product → Subscription
Name: "Team Analytics"
Base Price: $0/month

Attach usage pricing:
- Meter: data.processed
- Price per unit: $2/GB
- Free threshold: 0 (managed by your app)
```

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### 사용량 가시성

고객에게 사용량을 실시간으로 보여주세요:

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

## 하이브리드 결제 문제 해결

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**증상**: 사용량이 0으로 표시되거나 잘못된 값으로 표시됩니다.

**해결 방법**:
1. 이벤트 수집이 작동하는지 확인합니다(API 응답 확인).
2. `customer_id`이 구독 고객과 일치하는지 확인합니다.
3. `event_name`이 meter 설정과 일치하는지 확인합니다.
4. 이벤트의 타임스탬프가 올바른지 확인합니다(미래 날짜가 아님).
</Accordion>

<Accordion title="Proration confusion with multiple components">
**증상**: 요금제를 변경할 때 고객에게 예상치 못한 금액이 청구됩니다.

**해결 방법**:
1. 확인 전에 정확한 요금을 표시하려면 `previewChangePlan` API를 사용합니다.
2. 구독과 add-on 모두에 일할 계산이 적용된다는 점을 안내합니다.
3. 업그레이드 결제를 간소화하려면 `difference_immediately` 사용을 고려합니다.
</Accordion>

<Accordion title="Free threshold not applying correctly">
**증상**: 무료여야 하는 사용량에 대해 고객에게 요금이 청구됩니다.

**해결 방법**:
1. 사용량 기반 제품에 무료 임계값이 설정되어 있는지 확인합니다.
2. 임계값 단위가 이벤트 집계 단위와 일치하는지 확인합니다(호출 수와 요청 수 등).
3. 사용량 meter가 구독 제품에 올바르게 연결되어 있는지 확인합니다.
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**증상**: checkout 중 좌석이나 기능을 추가할 수 없습니다.

**해결 방법**:
1. 대시보드에서 add-on이 구독 제품에 연결되어 있는지 확인합니다.
2. API 호출에 사용된 add-on ID가 올바른지 확인합니다.
3. add-on 통화가 구독 제품의 통화와 일치하는지 확인합니다.
</Accordion>
</AccordionGroup>
