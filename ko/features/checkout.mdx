## Adaptive Currency

Adaptive Currency를 사용하면 고객이 선호하는 현지 통화로 결제할 수 있어 신뢰도와 전환율을 높일 수 있습니다.

### 작동 방식

1. **활성화**: **Settings → Business**에서 Adaptive Currency를 활성화합니다
2. **선택**: 고객은 checkout에서 직접 통화를 변경할 수 있습니다
3. **환산**: 실시간 FX rates를 사용해 가격이 동적으로 환산됩니다
4. **표시**: 최종 결제 금액이 결제 전에 투명하게 표시됩니다

## 자동 세금 계산

세금은 고객의 청구지 위치를 기준으로 자동 계산되므로 수동 설정 없이 GST, VAT 및 판매세 요구사항을 준수할 수 있습니다.

### 세금 계산 방식

<Steps>
<Step title="Location Detection">
  세금 규칙은 고객의 국가(해당하는 경우 지역)를 기준으로 적용됩니다.
</Step>

<Step title="Dynamic Updates">
  다음과 같은 경우 세금 금액이 자동으로 업데이트됩니다:
  - 국가가 변경된 경우
  - 주소가 업데이트된 경우
</Step>

<Step title="Transparent Display">
  최종 세금 내역이 결제 전에 명확하게 표시됩니다.
</Step>
</Steps>

<Tip>
세금 계산은 완전히 자동화되어 있습니다. 일반적인 digital goods 및 SaaS products에는 수동 구성이 필요하지 않습니다.
</Tip>

## 할인 코드

고객은 dashboard에서 생성한 discount 또는 promo code를 checkout 페이지에서 직접 적용할 수 있습니다.

### Checkout 경험

1. 고객이 discount code를 입력합니다
2. 할인이 즉시 검증됩니다
3. 업데이트된 가격과 절약 금액이 명확하게 표시됩니다

<Frame>
  <img src="/images/checkout/c4.png" alt="checkout의 할인 코드 입력" style={{ maxHeight: '500px', width: '70%' }}/>
</Frame>

### API 통합

하나 이상의 stacked discount code를 미리 적용하거나 discount input field를 활성화합니다:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Show discount input field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`discount_codes`는 순서대로 누적 적용되는 최대 20개의 code 배열을 허용합니다. 단일 `discount_code` field는 deprecated 상태지만 여전히 작동하므로 기존 integration을 즉시 변경할 필요는 없습니다. stacking과 더 풍부한 response shape를 사용하려면 편리한 시점에 `discount_codes`로 마이그레이션하세요.
</Info>

## 스마트 주소 수집

checkout은 더 빠른 완료를 위해 유연한 주소 입력을 지원합니다.

### 사용 가능한 옵션

| 옵션 | 설명 |
|--------|-------------|
| **Google Address Autofill** | autocomplete를 통한 빠른 선택 |
| **수동 입력** | 완전한 주소를 직접 입력할 수 있는 전체 제어 |
| **국가 선택** | 세금 및 compliance logic을 결정 |
| **최소 주소** | 국가만 수집(세금 계산에 필요한 경우 ZIP 포함) — [Minimal Address Mode](#minimal-address-mode) 참조 |

<Tip>
주소 수집은 compliance를 보장하면서 전환을 극대화할 수 있도록 속도, 정확성 및 전 세계 지원 범위의 균형을 맞춥니다.
</Tip>

### Minimal Address Mode

전환을 극대화하려면 최소 주소 수집을 활성화하여 checkout friction을 줄이세요. `minimal_address`가 `true`로 설정되면 checkout에서 다음 항목만 수집합니다:

- **국가** — 세금 결정을 위해 항상 필요
- **ZIP/우편번호** — 판매세, VAT 또는 GST 계산에 필요한 지역에서만 수집

그 외 모든 주소 필드(거리, 도시, 주)는 생략되어 checkout 완료 속도가 크게 향상됩니다.

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="checkout에서 국가 및 ZIP/우편번호 필드만 표시되는 최소 주소 모드" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
전체 주소 수집이 기본값으로 유지됩니다. 완전한 청구 정보가 필요하지 않은 digital products 및 SaaS flows에서는 `minimal_address`를 활성화하세요.
</Info>

<Card title="Minimal Address Reference" icon="address-card" href="/developer-resources/checkout-session#request-body">
Checkout Sessions API guide에서 전체 `minimal_address` parameter reference를 확인하세요.
</Card>

## 전화번호 수집

checkout session feature flags를 사용하여 checkout에 전화번호 필드가 표시되는지, 그리고 필수인지 여부를 제어할 수 있습니다.

| Flag | 기본값 | 동작 |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | checkout form에 전화번호 필드를 표시합니다 |
| `require_phone_number` | `false` | 전화번호 필드를 필수로 설정합니다(form validation에서 비어 있지 않은 값을 요구) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`require_phone_number: true`는 `allow_phone_number_collection: true`를 요구합니다. phone collection이 비활성화된 상태에서 phone number가 required인 session은 API에서 거부됩니다.
</Warning>

<Tip>
지원, fraud review 또는 compliance를 위해 검증된 연락 채널이 필요한 B2B SaaS, 규제 산업 또는 모든 flow에서 `require_phone_number`를 사용하세요.
</Tip>

## Custom Fields

custom form fields를 정의하여 checkout 중 고객으로부터 추가 정보를 수집할 수 있습니다. 회사명, 팀 규모, 추천 출처 또는 기타 business-specific information을 수집할 때 유용합니다.

### 사용 가능한 필드 유형

| 유형 | 설명 |
|------|-------------|
| `text` | 한 줄 텍스트 입력 |
| `number` | 숫자 입력 |
| `email` | validation이 적용된 email address |
| `url` | validation이 적용된 URL |
| `date` | date picker |
| `dropdown` | 미리 정의된 옵션에서 선택 |
| `boolean` | Yes/No toggle |

### 예시

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
고객 응답은 webhook payload(`payment.succeeded`, `subscription.active`)와 `custom_field_responses` array를 통한 API response에 자동으로 포함됩니다. checkout session당 최대 5개의 custom field를 정의할 수 있습니다.
</Info>

## Collection Checkout

Product Collections는 고객이 하나의 checkout에서 여러 관련 product(예: Starter, Pro, Enterprise plans)를 확인하고 선택할 수 있는 통합 checkout experience를 제공합니다.

### 작동 방식

1. **모든 product 표시**: 고객은 collection의 모든 active product를 확인합니다
2. **첫 번째 product 사전 선택**: collection의 첫 번째 product가 자동으로 선택됩니다
3. **옵션 비교**: 고객은 선택하기 전에 가격과 기능을 비교할 수 있습니다
4. **단일 선택**: product를 선택하면 checkout이 standard payment flow로 진행됩니다

### Collection Checkout 생성

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`product_collection_id`를 사용할 때는 빈 `product_cart` array를 전달하세요. session 생성 시 discount code를 미리 적용할 수 없습니다.
</Warning>

## Checkout Session 구성

Checkout Sessions API를 사용하여 checkout 동작을 제어합니다:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
결제 후 고객은 자동으로 query parameter가 추가된 `return_url`로 redirect됩니다. 여기에는 `payment_id` 또는 `subscription_id`, `status`, `email` 및 `license_key`(해당하는 경우)가 포함됩니다. 전체 목록은 [Checkout Sessions guide](/developer-resources/checkout-session#request-body)를 참조하세요.
</Info>

<Info>
이 섹션에서는 `customization.theme_config`를 사용하는 **server-side API** theme 구성을 다룹니다. **Checkout SDK**(overlay 또는 inline checkout)를 사용하는 경우 camelCase properties를 사용하는 [Overlay Checkout](/developer-resources/overlay-checkout#theme-customization)의 theme customization 섹션을 참조하세요(예: `bg_primary` 대신 `bgPrimary`).
</Info>

### Theme 구성 옵션

| Property | 설명 |
|----------|-------------|
| `light` | light mode의 color 구성 |
| `dark` | dark mode의 color 구성 |
| `font_primary_url` | primary font의 URL |
| `font_secondary_url` | secondary font의 URL |
| `font_size` | Font size: `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `font_weight` | Font weight: `normal`, `medium`, `bold`, `extraBold` |
| `radius` | UI elements의 border radius(예: `4px`, `0.5rem`, `8px`) |
| `pay_button_text` | pay button의 custom text(예: "Complete Purchase", "Subscribe Now") |

### Color 구성(Light/Dark Mode)

각 mode(`light` 및 `dark`)는 다음 color properties를 지원합니다:

| Property | 설명 |
|----------|-------------|
| `bg_primary` | 기본 background color |
| `bg_secondary` | 보조 background color |
| `text_primary` | 기본 text color |
| `text_secondary` | 보조 text color |
| `text_placeholder` | text placeholder color |
| `text_error` | text error color |
| `text_success` | text success color |
| `border_primary` | 기본 border color |
| `border_secondary` | 보조 border color |
| `button_primary` | primary button background color |
| `button_primary_hover` | primary button hover color |
| `button_secondary` | secondary button background color |
| `button_secondary_hover` | secondary button hover color |
| `button_text_primary` | primary button text color |
| `button_text_secondary` | secondary button text color |
| `input_focus_border` | input focus border color |

<Info>
모든 color field는 표준 CSS color format을 허용합니다:
- Hex: `#fff`, `#ffffff`, `#ffffffff`
- RGB/RGBA: `rgb(255, 255, 255)`, `rgba(255, 255, 255, 0.5)`
- HSL/HSLA: `hsl(120, 100%, 50%)`, `hsla(120, 100%, 50%, 0.5)`
- Named colors: `red`, `blue`, `transparent`
</Info>
