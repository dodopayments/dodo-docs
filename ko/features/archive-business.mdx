## 소개

보관 기능은 더 이상 거래하지 않는 비즈니스를 종료합니다. 해당 비즈니스는 대시보드에서 사라지고, API 키는 작동을 멈추며, checkout, payment links, storefront, Customer Portal은 고객에게 더 이상 제공되지 않습니다.

보관은 삭제가 아닙니다. Dodo Payments는 귀사의 [Merchant of Record](/features/mor-introduction)이므로 거래를 중단한 후에도 규정 준수를 위해 결제, 환불, 인보이스 및 세금 기록을 장기간 보관해야 합니다. 보관하면 새로운 활동은 중단되지만 이러한 기록은 그대로 유지됩니다.

<Warning>
보관은 영구적입니다. 보관된 비즈니스를 복원할 방법은 없으며, support에서도 대신 되돌릴 수 없습니다. 하나의 브랜드만 종료하고 다른 브랜드로 계속 거래하려면 비즈니스 대신 해당 브랜드를 보관하세요. [Multi-Brand Setup](/features/multi-brands)을 참조하세요.
</Warning>

## 자격 요건

비즈니스는 모든 정산이 완료된 경우에만 보관할 수 있습니다. 옵션을 사용할 수 있게 되기 전에 Dodo Payments는 7가지 요건을 확인하고 각 요건의 현재 상태를 체크리스트로 표시합니다. 매일 사용하는 동일한 도구를 이용해 미충족 항목을 직접 해결할 수 있습니다.

| 요건 | 다음 경우 충족 | 충족 방법 |
|---|---|---|
| **휴면** | 지난 180일 동안 해당 비즈니스에 결제 활동이 없음 | 기간이 지나기를 기다리세요. 체크리스트에 자격을 갖추게 되는 날짜가 표시됩니다. |
| **Payout Wallet** | 모든 통화 잔액이 정확히 0임 | 남은 자금을 출금하세요. [Account Summary and Payout Wallet](/features/account-summary-payout-wallet)을 참조하세요. |
| **Payouts** | 진행 중이거나 보류 중이거나 시작을 기다리는 payout이 없음 | 각 payout이 정산될 때까지 기다리세요. [Payout Structure](/features/payouts/payout-structure)를 참조하세요. |
| **분쟁** | 열린 dispute나 이의 제기된 dispute가 없음 | 모든 dispute를 해결하거나 수락하세요. [Disputes](/features/transactions/disputes)를 참조하세요. |
| **환불** | 대기 중이거나 검토 중인 refund가 없음 | 각 refund가 완료될 때까지 기다리세요. [Refunds](/features/transactions/refunds)를 참조하세요. |
| **구독** | 대기 중이거나 활성 상태이거나 보류 중이거나 일시중지된 subscription이 없음 | 각 subscription을 취소하세요. [Subscriptions](/features/subscription)을 참조하세요. |
| **고객 잔액** | 어떤 고객도 현금 잔액을 보유하고 있지 않음 | [Customer Wallet](/features/customer-wallet) 원장에서 각 잔액을 0으로 만드세요. |

<Note>
다음 billing date에 취소되도록 예약된 subscription도 실제로 종료될 때까지 보관을 차단합니다. Dodo Payments는 사용자를 대신해 subscription을 취소하지 않으므로 고객에게 청구할 항목을 계속 직접 관리할 수 있습니다.
</Note>

결과와 관계없이 모든 결제는 휴면 기간에 포함됩니다. 실패했거나 중단된 결제 시도도 성공한 결제와 마찬가지로 180일 기간을 다시 시작합니다.

고객 credit 부여는 보관을 차단하지 않습니다. 현금 잔액만 해당됩니다. Credit은 자체 일정에 따라 만료됩니다.

체크리스트는 열 때마다 현재 상태를 기준으로 평가됩니다. 따라서 항목을 해결한 후 새로고침하면 해당 요건이 녹색으로 변경된 것을 확인할 수 있습니다.

## 비즈니스를 보관하는 방법

비즈니스의 **Owner**만 해당 비즈니스를 보관할 수 있습니다. Editors와 Viewers는 체크리스트를 볼 수는 있지만 보관할 수 없습니다. Ownership은 이전할 수 없으므로 소유자가 아니라면 해당 소유자에게 이 절차를 완료해 달라고 요청하세요.

<Steps>
<Step title="Open the Danger Zone">
**Settings → Business**로 이동한 후 **Danger Zone** 패널까지 스크롤하세요. 상태 줄 옆의 **See Details**를 선택해 체크리스트를 펼칩니다.

<Frame>
<img src="/images/archive-business/danger-zone-checklist.png" alt="Archive Business 버튼과 7개 항목의 자격 요건 체크리스트가 모두 충족된 상태를 보여주는 Danger Zone 패널" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>
<Step title="Clear every outstanding requirement">
위 표의 해결 방법 링크를 따라 아직 충족되지 않은 항목을 처리하세요. 진행하면서 패널로 돌아와 체크리스트를 다시 펼치세요. 해결해야 할 항목이 모두 없어지면 체크리스트 위의 상태 줄에 **All conditions met**가 표시됩니다.
</Step>
<Step title="Confirm you want to archive">
**Archive Business**를 선택하고 확인 대화 상자를 읽으세요. **Continue**를 선택하면 소유자의 이메일 주소로 확인 코드가 전송됩니다.

<Frame>
<img src="/images/archive-business/archive-confirmation.png" alt="보관된 비즈니스는 복원할 수 없음을 경고하는 확인 대화 상자" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>
<Step title="Enter the code from your email">
Dodo Payments는 소유자의 등록된 주소로 6자리 코드를 이메일로 보냅니다. 코드는 10분 후 만료되며, 새 코드는 60초마다 요청할 수 있습니다. 새 코드가 필요하기 전까지 3번 시도할 수 있습니다.

<Frame>
<img src="/images/archive-business/otp-prompt.png" alt="재전송 카운트다운과 함께 6자리 코드를 기다리는 인증 대화 상자" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

더 이상 소유자의 mailbox에 액세스할 수 없다면 대화 상자의 **Contact support** 링크를 사용하세요.
</Step>
<Step title="Verify and archive">
코드를 입력하고 **Verify & Archive**를 선택하세요. 이 시점이 되돌릴 수 없는 순간입니다. 코드가 승인되는 즉시 비즈니스가 보관됩니다.

<Frame>
<img src="/images/archive-business/otp-entered.png" alt="6자리 숫자가 모두 입력되고 Verify and Archive 버튼이 활성화된 인증 대화 상자" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>
<Step title="Switch to another business">
Dodo Payments가 보관을 확인하고 다른 비즈니스로 이동합니다. 즉시 이동하려면 **Switch Now**를 선택하세요.

<Frame>
<img src="/images/archive-business/archive-complete.png" alt="비즈니스가 보관되었으며 다른 비즈니스로 전환되는 카운트다운을 보여주는 확인 화면" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>
</Steps>

## 보관 후 발생하는 일

**사용자 측**

- 비즈니스가 대시보드와 business switcher에 더 이상 표시되지 않습니다. Dodo Payments는 보관 직후 다른 비즈니스로 이동합니다.
- live mode와 live payments가 비활성화됩니다.
- 해당 비즈니스의 모든 API 키가 live mode와 test mode 모두에서 작동을 멈춥니다. 캐시된 credentials가 만료되는 데 몇 분이 걸릴 수 있으므로 보관 후에도 integration이 잠시 계속 작동할 수 있습니다.

**고객 측**

- Checkout sessions, payment links 및 static checkout pages에서 결제를 더 이상 받을 수 없습니다.
- storefront에서 제품 제공이 중단됩니다.
- Customer Portal sessions가 종료되고 고객은 더 이상 로그인하여 구매 내역을 관리할 수 없습니다.
- License key activation 및 deactivation이 중단됩니다.

보관하기 전에 고객에게 알려주세요. 비즈니스가 보관되면 고객이 구매 내역으로 돌아갈 수 있는 셀프 서비스 경로가 없으며, Dodo Payments는 재시도 가능한 오류 대신 terminal error를 반환합니다.

**기록**

Payments, refunds, invoices, payouts 및 tax filings는 보관됩니다. 대시보드 액세스는 비즈니스가 보관되는 즉시 종료되므로 보관하기 전에 보관할 invoices와 reports를 다운로드하세요. 이후 기록 사본이 필요하면 [support](/miscellaneous/help-support)에 문의하세요.

## 제한 사항

- **보관은 취소할 수 없습니다.** 이 작업은 merchant와 support 모두에게 영구적입니다.
- **이 방법으로 마지막 비즈니스를 보관할 수는 없습니다.** 소유한 비즈니스가 하나뿐이라면 [support](/miscellaneous/help-support)에 문의하여 대신 계정을 종료하세요.
- **보관은 전부 적용되거나 전혀 적용되지 않습니다.** 카탈로그의 일부를 종료하고 계속 거래하려면 비즈니스가 아니라 브랜드를 보관하세요.
