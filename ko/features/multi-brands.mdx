## 소개

Multi-Brand를 사용하면 각기 다른 로고, 설명자, 웹사이트 URL을 가진 여러 브랜드를 **하나의 인증된 사업체**에 연결할 수 있습니다. 지급 계정, 수수료, KYC는 그대로 유지되며, 모든 제품, 결제 링크, 구독, 송장 및 거래는 이제 특정 브랜드에 따라 분류할 수 있습니다. 추가 비즈니스 계정을 개설할 필요 없이 새로운 틈새 시장을 테스트하거나 사이트를 현지화하거나 B2B와 B2C 라인을 분리하는 데 사용할 수 있습니다.

## 상인 대시보드 흐름

<Steps>
<Step title="Open Settings → Business">
**설정 → 비즈니스**로 이동합니다. 오른쪽의 **[귀하의 비즈니스] 하의 브랜드** 패널에는 기본 브랜드와 보조 브랜드가 나열됩니다.

<Frame>
<img src="/images/multi-brands/brands-section.png" alt="새 브랜드 추가를 위한 플러스 버튼과 함께 기본 및 보조 브랜드를 표시하는 비즈니스 설정의 브랜드 패널" />
</Frame>
</Step>
<Step title="Click the '+' button">
브랜드 패널에서 새로운 브랜드 양식을 열려면 오른쪽 상단의 **+** 버튼을 클릭하세요.
</Step>
<Step title="Fill in the brand details">
다음 필드를 완료하세요:

- **브랜드 이름** (필수): 브랜드 이름을 입력하세요.
- **웹사이트 URL** (필수): 브랜드의 웹사이트, 예를 들어 `https://www.yourcompany.com`.
- **지원 이메일**: 고객이 이 브랜드의 지원을 받을 때 사용할 이메일입니다.
- **브랜드 설명** (필수): 브랜드와 제품을 설명하고 독특한 점을 설명하세요.
- **브랜드 로고**: 체크아웃, 송장 및 결제 링크에서 브랜드를 대표할 로고를 업로드하세요.

양식을 제출하여 브랜드를 생성하세요. 이제 제품에 이 브랜드를 태그할 수 있으며, 결제 링크에 브랜드가 표시됩니다.
</Step>
<Step title="Brand Selector">
제품 생성 시 브랜드 필터가 표시됩니다.
</Step>
<Step title="Brand ID in Transactions">
거래 및 구독에는 거래가 속한 브랜드를 식별할 수 있는 브랜드 ID가 있습니다.
</Step>
</Steps>

## 추가 사항

- **지급금 변경 없음:** 모든 자금, 지급 주기 및 수수료는 계속 비즈니스 수준의 지갑과 판매자 은행 계좌로 처리됩니다.
- **웹훅의 Brand ID:** 결제, 구독, 환불, 분쟁, 라이선스 키, 크레딧 원장 항목, 크레딧 잔액 부족, 권한 부여, 추심 시도 및 미완료 결제 페이로드에는 모두 `brand_id`가 포함되므로, 특정 브랜드에 귀속할 수 있습니다. 엔터티에 자체 브랜드가 없는 경우 `brand_id`는 비즈니스의 기본 브랜드로 대체됩니다. 지급금 페이로드는 비즈니스 수준에서 처리되며 `brand_id`를 포함하지 않습니다.
- **정지:** 브랜드가 정지되면 해당 브랜드의 결제 링크만 중단됩니다. 동일한 비즈니스에 속한 다른 브랜드는 계속 거래할 수 있습니다.
- Storefront, Invoices, License Keys, Discount Codes, Payout Settings 및 기타 모든 비즈니스 수준 기능에는 변경 사항이 없습니다.

## 브랜드 보관

브랜드의 운영이 끝나면 대시보드에 비활성 상태로 남겨 두는 대신 보관하세요. 브랜드를 보관하면 해당 브랜드가 종료되고, 한 번의 단계로 같은 비즈니스의 다른 브랜드에 카탈로그가 이전됩니다.

<Warning>
보관한 브랜드는 영구적으로 처리됩니다. 보관한 브랜드를 복원할 방법은 없습니다.
</Warning>

### 보관하면 어떻게 되나요

보관할 브랜드를 대신할 **대상 브랜드**를 지정합니다. 대시보드에서는 항상 대상 브랜드를 지정하도록 요청하며, API에서는 이를 `move_products_to`로 받습니다. 하나의 원자적 작업에서 Dodo Payments는 다음을 수행합니다.

- 모든 제품을 대상 브랜드로 이전합니다.
- 모든 활성 구독을 대상 브랜드로 이전하므로 갱신 결제가 해당 브랜드로 계속 처리됩니다.
- 모든 제품 컬렉션을 대상 브랜드로 이전합니다.
- 원래 브랜드를 보관하고 비활성화합니다.

기존 기록에는 영향을 주지 않습니다. 결제, 인보이스 및 완료된 구독은 생성 당시의 브랜드를 유지하므로 과거 보고서의 정확성이 유지됩니다.

대상 브랜드는 동일한 비즈니스에 속해야 하며, 대상 브랜드 자체가 보관된 상태여서는 안 됩니다. 기본 브랜드는 유효한 대상이며, 해당 브랜드 ID는 비즈니스 ID입니다. 브랜드에 제품, 활성 구독 및 제품 컬렉션이 하나도 없는 경우에만 대상을 생략할 수 있습니다.

<Note>
기본 브랜드는 보관할 수 없습니다. 기본 브랜드는 비즈니스가 되돌아갈 수 있는 브랜드이므로 항상 하나 이상의 브랜드가 남아 있어야 합니다.
</Note>

### 보관된 브랜드는 읽기 전용입니다

| 작업 | 결과 |
|---|---|
| 브랜드 세부 정보 편집 | `BRAND_ARCHIVED`와 함께 거부됨 |
| 검토를 위해 브랜드 제출 | `BRAND_ARCHIVED`와 함께 거부됨 |
| 브랜드에 제품 또는 컬렉션 생성 | `BRAND_ARCHIVED`와 함께 거부됨 |
| 해당 제품 중 하나에 대한 구독 생성 | `BRAND_ARCHIVED`와 함께 거부됨 |

보관된 브랜드는 브랜드 선택기에서 숨겨지므로 새 레코드에 해당 브랜드를 지정할 수 없습니다. 다만 분석 필터에서는 계속 사용할 수 있으므로 브랜드가 운영되던 기간의 브랜드별 보고서를 완전하게 유지할 수 있습니다. [Analytics](/features/analytics)를 참조하세요.

### API를 통한 보관

종료할 브랜드와 해당 브랜드를 대신할 브랜드를 지정하여 보관 엔드포인트를 호출합니다.

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

응답에는 어떤 항목이 이전되었는지가 표시되므로 결과를 확인할 수 있습니다.

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

보관된 브랜드를 포함하여 브랜드를 나열하려면 목록 엔드포인트에서 `include_archived`를 설정합니다. 보관된 브랜드는 기본적으로 제외됩니다. 모든 브랜드에는 `archived_at` 필드가 있으며, 브랜드가 활성 상태인 동안에는 `null`입니다.

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

전체 요청 및 응답 스키마는 [Archive Brand](/api-reference/brands/archive-brand) API reference를, 이 엔드포인트가 반환하는 오류는 [Error Codes](/api-reference/error-codes)를 참조하세요.
