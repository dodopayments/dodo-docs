<Info>
장바구니 복구(ACR)는 완료되지 않거나 실패한 결제를 감지하고, 고객을 다시 데려오는 자동 이메일 시퀀스를 보냅니다. 선택 할인 인센티브와 결합하여 복구율을 최대화하십시오.
</Info>

## 장바구니 복구란 무엇입니까?

ACR은 결제를 시작했지만 완료하지 않은 고객을 자동으로 식별하여 — 결제가 실패했든 결제 전에 떠났든 상관없이 — 복구 이메일 시퀀스를 보내 다시 데려옵니다.

- **결제 실패**: 고객이 결제를 시도했지만 승인되지 않거나 오류가 발생
- **미완료 결제**: 고객이 결제 페이지를 방문했으나 결제를 시도하지 않음

## ACR의 작동 방식

<Steps>
<Step title="Detection">
60분 이상 경과되었지만 성공하지 않은 결제를 스캔합니다. 여기에는 실패한 결제와 고객이 결제를 시도하지 않은 결제가 포함됩니다.
</Step>

<Step title="Classification">
각 미완료 결제는 이유에 따라 분류됩니다:
- **결제 실패**: 고객이 결제를 시도했지만 실패
- **미완료 결제**: 고객이 결제 페이지를 방문했으나 결제를 시도하지 않음
</Step>

<Step title="Email Sequence">
분류를 기반으로 시스템은 설정된 간격으로 최대 3개의 복구 이메일을 보냅니다. 각 이메일에는 고유한 복구 링크가 포함됩니다.
</Step>

<Step title="Recovery">
고객이 복구 링크를 클릭하면 원래 장바구니가 표시되는 복구 페이지로 이동합니다. 새 결제 세션을 통해 결제를 완료할 수 있습니다.
</Step>
</Steps>

## 상태 라이프사이클

각 미완료 결제는 다음 상태로 진행됩니다:

| 상태 | 설명 |
|--------|-------------|
| `abandoned` | 이탈로 감지된 결제, 아직 이메일이 발송되지 않음 |
| `recovering` | 적어도 하나의 복구 이메일이 발송됨 |
| `recovered` | 고객이 복구 링크를 통해 결제를 완료함 |
| `exhausted` | 모든 이메일이 발송되었으나 복구되지 않음, 또는 더 새로운 결제가 이 결제를 대체함 |
| `opted_out` | 고객이 복구 이메일 수신을 해지함 |

### 전역 설정

| 설정 | 설명 | 기본 |
|---------|-------------|---------|
| **활성화됨** | ACR을 위한 마스터 토글 | Off |
| **할인 활성화됨** | 복구 이메일용 할인 코드를 자동 생성 | Off |
| **할인 비율** | 이 고객을 위한 결제에 적용될 할인 비율 | 0 |
| **할인 유효 일수** | 자동 생성된 할인 코드 유효 일수 | 5 |

### 이메일 시퀀스

ACR은 두 가지 이메일 시퀀스를 지원합니다 — **결제 실패** 및 **미완료 결제** — 각각 최대 3개의 구성 가능한 이메일을 포함합니다.

<Frame caption="ACR email sequence configuration">
<img src="/images/recovery/acr-email-config.png" alt="이메일 시퀀스 편집기: 각 이메일의 제목, 본문, 타이밍, 활성화 토글 표시" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

| 설정 | 설명 |
|---------|-------------|
| **활성화됨** | 개별 이메일 삭제 없이 켜기/끄기 |
| **지연** | 이탈 감지 후 이메일 전송까지의 시간 |
| **제목** | 변수 플레이스홀더가 있는 이메일 제목 |
| **본문** | 변수 플레이스홀더가 있는 HTML 이메일 본문 |
| **답장 받는 사람** | 고객의 답장을 받을 이메일 주소 |

**기본 이메일 타이밍:**

| 이메일 # | 기본 지연 |
|---------|---------------|
| 1 | 1 시간 |
| 2 | 24 시간 |
| 3 | 72 시간 |

## 복구 할인

할인 활성화 시, ACR은 모든 미완료 결제를 위해 고유한 1회용 할인 코드를 자동 생성합니다. 이 할인은:

- 원래 결제의 제품에 제한됨
- 구성이 가능한 만료 기간을 가지고 있음
- 1번만 사용 가능
- 대시보드 할인 목록에는 숨겨져 있음 (내부 사용 전용)

<Tip>
변환 영향을 테스트하기 위해 적당한 할인(5-10%)으로 시작해 보십시오. 작은 인센티브라도 복구율을 크게 개선할 수 있습니다.
</Tip>

## 고객 복구 경험

고객이 이메일의 복구 링크를 클릭하면
원래 결제 세션으로 돌아갑니다. 페이지에는
그들이 남긴 제품과 구성된 할인 코드가 표시됩니다.

## 극단적 사례

| 시나리오 | 동작 |
|----------|----------|
| 고객이 다음 이메일 전 결제를 완료함 | 전송 시점에 복구가 감지됨; 적격한 경우 결제가 복구된 것으로 표시됨 |
| 고객이 새로운 결제를 시작함 | 이전 미완료 결제가 `exhausted`로 표시됨 |
| 고객이 이미 복구된 후 "결제" 클릭 | 복구 페이지가 결제가 이미 완료되었음을 확인함 |
| 고객이 구독 취소 | 미완료 결제가 `opted_out`로 표시되고, 더 이상 이메일이 발송되지 않음 |

## 모범 사례

- **기본값으로 시작**: 기본 이메일 타이밍과 제목은 일반적인 복구 패턴에 최적화되어 있습니다. 기본 데이터를 확보한 후 사용자 정의하십시오.
- **이메일 개인화**: 템플릿 변수를 사용하여 이메일을 고객에게 개인적이고 관련성 있게 만드십시오.
- **분석 모니터링**: 이메일별 복구율을 추적하여 가장 많은 변환을 유도하는 메시지를 식별하십시오. 성과가 저조한 이메일은 비활성화하십시오.
- **전략적으로 할인 사용**: 마진 보호를 위해 소규모(5-10%)로 시작하여 변환 영향을 테스트하십시오.
- **이메일 간결 유지**: 복구 이메일은 짧고 실행 지향적이어야 합니다. 명확한 호출-to-action이 길고 상세한 설명보다 더 나은 결과를 제공합니다.

<Info>
ACR은 활성화되면 자동으로 작동하도록 설계되었습니다. 기본 설정으로 시작하고 분석 결과를 모니터링하며 성과 데이터에 따라 반복하십시오.
</Info>
