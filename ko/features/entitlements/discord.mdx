<Info>
Discord entitlement는 유료 고객의 구독이 활성화되거나 일회성 구매가 승인되는 즉시 고객을 서버에 추가하고(선택적으로 역할도 할당), 취소, 환불 및 플랜 변경이 발생하면 역할을 자동으로 회수합니다.
</Info>

## 제공되는 기능

- 고객은 delivery email 또는 customer portal의 OAuth 링크를 통해 자신의 Discord 계정을 연결합니다.
- 고객이 인증하면 Dodo Payments 고객을 서버에 추가하거나(기존 멤버십이 있으면 이를 찾음) 구성한 역할을 할당합니다.
- 특정 역할을 선택하지 않은 경우에는 서버 멤버십만 부여됩니다.

이 integration은 유료 커뮤니티, supporter 혜택 및 tiered access 채널에 적합합니다.

## 고객 흐름

1. 고객이 checkout을 완료합니다.
2. Dodo Payments가 `Pending` 상태로 grant를 생성합니다. 이 grant의 `oauth_url`는 `null`이며, 고객이 accept flow를 시작하면 Discord authorization URL이 입력됩니다.
3. 고객은 "Join the Discord" 버튼(OAuth 링크)이 포함된 이메일을 받습니다. 이 링크는 고객 포털에서도 확인할 수 있습니다.
4. 고객이 authorization을 완료하면 bot이 고객을 서버에 추가하고 구성된 role을 할당합니다. grant는 `Delivered` 상태로 변경됩니다.
5. subscription이 취소되거나 일시 중지되거나 만료되거나 merchant가 수동으로 revoke하면 bot이 role을 제거하고 grant는 `Revoked` 상태로 변경됩니다.

<Tip>
Dodo Payments bot의 역할이 부여하려는 역할보다 **위에** 배치되어 있는지 확인하세요. Discord에서는 bot이 자신의 역할보다 순위가 높은 역할을 할당할 수 없습니다.
</Tip>

## 필수 구성

| Field | Required | Description |
|---|---|---|
| `guild_id` | Yes | Discord 서버 ID입니다. 대시보드 선택기가 이 값을 자동으로 입력합니다. |
| `role_id` | No | delivery 시 할당할 역할입니다. 서버 멤버십만 액세스하도록 하려면 생략합니다. |

## Webhooks

Discord grant를 추적하려면 [`entitlement_grant.*` webhook events](/developer-resources/webhooks/intents/entitlement-grant)를 구독합니다:

- `entitlement_grant.created`는 `status: "Pending"`와 함께 실행됩니다. 이 시점에서 `oauth_url`는 `null`입니다. 고객이 delivery email 또는 고객 포털에서 accept flow를 시작하면 해당 값이 입력됩니다.
- `entitlement_grant.delivered`는 role이 할당되면 실행됩니다.
- `entitlement_grant.revoked`는 role이 제거되면 실행됩니다.

## 문제 해결

<AccordionGroup>
<Accordion title="Customer never sees the role assigned">
고객이 OAuth flow를 완료할 때까지 grant는 `Pending` 상태입니다. entitlement의 grants 목록을 확인하고 고객이 OAuth 링크를 클릭했는지 확인하세요. 필요한 경우 delivery email을 다시 보내세요.
</Accordion>

<Accordion title="Grant moves to failed with permission errors">
Dodo Payments bot이 서버에 계속 존재하고 `Manage Roles` permission을 보유하며 할당할 역할보다 위에 배치되어 있는지 확인하세요. entitlement를 다시 저장하면 validation이 다시 실행됩니다.
</Accordion>

<Accordion title="Customer cancelled but still has the role">
Discord는 역할 제거를 즉시 전파하지만 고객의 로컬 Discord client에는 캐시가 남아 있을 수 있습니다. 고객이 다시 연결하거나 새로 고침해야 합니다. 서버 측 상태는 올바릅니다.
</Accordion>
</AccordionGroup>
