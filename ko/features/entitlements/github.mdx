<Info>
GitHub 권한은 요금제에 가입한 고객을 비공개 저장소의 협력자로 추가합니다. 권한 수준(`pull`, `push`, `triage`, `maintain`, 또는 `admin`)을 선택하고 Dodo Payments가 초대, 수락 추적 및 취소 시 제거를 처리합니다.
</Info>

## 제공 내역

- 고객은 OAuth 흐름을 통해 GitHub 저장소로 초대되어 GitHub 계정을 구매와 연결합니다.
- 수락 시, GitHub은 설정된 권한 수준으로 협력자 접근을 부여합니다.
- 취소, 환불 또는 수동 해제 시 협력자가 제거됩니다.

일반적인 사용 사례로는 소스 코드 제공 제품, 유료 템플릿, 강좌 코드 저장소 및 클라이언트 SDK 액세스 관리가 포함됩니다.

## 권한 수준

GitHub의 표준 저장소 권한이 적용됩니다:

| Permission | 적합 용도 |
|---|---|
| `pull` | 읽기 전용 접근. 고객이 클론하고, 가져오고, 저장소를 볼 수 있습니다. |
| `triage` | 읽기 접근 및 이슈 및 풀 요청 관리 기능 포함. |
| `push` | 읽기 + 쓰기 접근. 고객이 브랜치를 푸시하고 풀 요청을 열 수 있습니다. |
| `maintain` | 푸시 접근 및 저장소 설정 관리(민감한 설정 제외). |
| `admin` | 저장소의 완전한 제어. 주의해서 사용하세요. |

<Warning>
케이스에 맞는 **최소 권한**을 부여하세요. 대부분의 유료 콘텐츠 시나리오는 `pull`만 필요합니다.
</Warning>

## 고객 흐름

1. 고객이 결제를 완료합니다.
2. Dodo Payments가 고객이 GitHub 계정을 링크할 수 있도록 `pending` 상태의 `oauth_url`를 생성합니다.
3. 고객은 이메일이나 고객 포털의 링크를 통해 승인합니다.
4. Dodo Payments가 고객의 GitHub 계정을 설정된 권한으로 저장소에 초대합니다. 초대가 생성되면 권한이 `delivered`로 이동합니다.
5. 구독이 취소, 환불 또는 해제되면 고객은 협력자로부터 제거됩니다.

## 필수 설정

| 필드 | 필수 | 설명 |
|---|---|---|
| `target_id` | 예 | 고객을 초대할 저장소. 대시보드의 저장소 선택기가 이를 자동으로 입력합니다. |
| `permission` | 예 | `pull`, `push`, `triage`, `maintain`, `admin` 중 하나. |

## API를 통한 생성

<CodeGroup>

```typescript TypeScript theme={null}
const entitlement = await client.entitlements.create({
  name: 'Code Share Repository',
  integration_type: 'github',
  integration_config: {
    target_id: 'acme/private-sdk',
    permission: 'pull',
  },
});
```

```python Python theme={null}
client.entitlements.create(
    name="Code Share Repository",
    integration_type="github",
    integration_config={
        "target_id": "acme/private-sdk",
        "permission": "pull",
    },
)
```

```go Go theme={null}
client.Entitlements.New(ctx, dodopayments.EntitlementNewParams{
  Name:            dodopayments.F("Code Share Repository"),
  IntegrationType: dodopayments.F(dodopayments.EntitlementIntegrationTypeGithub),
  IntegrationConfig: dodopayments.F[dodopayments.IntegrationConfigUnionParam](
    dodopayments.IntegrationConfigGitHubConfigParam{
      TargetID:   dodopayments.F("acme/private-sdk"),
      Permission: dodopayments.F("pull"),
    },
  ),
})
```

</CodeGroup>

## Webhooks

표준 [`entitlement_grant.*` 웹훅 이벤트](/developer-resources/webhooks/intents/entitlement-grant)는 GitHub 흐름을 포함합니다:

- `entitlement_grant.created`는 GitHub 인증을 위한 `oauth_url`를 포함합니다.
- `entitlement_grant.delivered`는 협력자 초대가 생성되면 발송됩니다.
- `entitlement_grant.failed`는 GitHub App이 저장소에 대한 접근을 잃었을 경우 `error_code: "github_permission_denied"`(또는 유사)와 함께 발송됩니다.

## 문제 해결

<AccordionGroup>
<Accordion title="Repository picker is empty">
Dodo Payments GitHub App은 저장소를 소유한 조직 또는 사용자에 설치되어야 합니다. **Entitlements → Integrations → GitHub**로 이동하여 관련 저장소에 접근 권한을 부여하며 앱을 재설치합니다.
</Accordion>

<Accordion title="Grant fails with permission_denied">
GitHub App의 설치가 더 이상 저장소에 접근할 수 없거나 저장소가 이름 변경/이전되었습니다. 앱에 대한 접근을 재허용하고 다음 재부여가 성공할 것입니다.
</Accordion>

<Accordion title="Customer hasn't accepted the invite">
고객은 GitHub 초대를 알림 페이지에서 수락하거나 이메일의 링크를 클릭해야 합니다. 수락하기 전까지 "초대됨" 상태로 남아 있지만 저장소를 클론할 수 없습니다. Dodo Payments 관점에서는 권한이 여전히 `delivered` 상태이며, 초대가 발행됩니다.
</Accordion>
</AccordionGroup>
