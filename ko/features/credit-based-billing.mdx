Credit-Based Billing을 사용하면 고객에게 API 호출, 토큰, 컴퓨팅 단위 또는 사용자 지정 지표와 같은 크레딧 잔액을 부여하고, 고객이 서비스를 사용할 때 해당 잔액에서 차감할 수 있습니다. 크레딧은 구독, 일회성 구매 및 사용량 기반 결제를 포함한 모든 제품 유형에서 작동합니다.
</Info>

## Credit-Based Billing이란 무엇인가요?

Credit-Based Billing은 제품의 일부로 고객에게 크레딧 권한을 발급할 수 있는 유연한 시스템을 제공합니다. 사용량에 따라 요금을 청구하거나 기능 플래그로 액세스를 제한하는 대신, 고객이 서비스를 사용하는 동안 차감할 수 있는 크레딧 풀을 할당합니다.

크레딧은 다음과 같은 경우에 적합합니다:

- **AI 및 LLM 플랫폼**: 요금제 등급별로 토큰 또는 생성 크레딧 부여
- **API 서비스**: 초과 사용 가격이 적용되는 API 호출 크레딧 할당
- **인프라 플랫폼**: 컴퓨팅 시간 또는 스토리지 크레딧 발급
- **커뮤니케이션 서비스**: 구독별 메시지 또는 통화 시간 크레딧 제공
- **사용량 등급이 있는 SaaS**: 포함된 사용량을 크레딧 풀로 묶기

## 핵심 개념

### 크레딧 유형

크레딧을 생성할 때 두 가지 유형 중 하나를 선택합니다:

<Tabs>
<Tab title="Custom Unit">
토큰, API 호출, 컴퓨팅 시간 또는 제품에 의미 있는 모든 지표 등 원하는 단위로 크레딧을 정의할 수 있습니다. Custom Unit은 설정한 정밀도(소수점 이하 0~10자리)를 사용합니다.

**적합한 용도**: API 호출, AI 토큰, 컴퓨팅 시간, 스토리지 단위, 메시지
</Tab>

<Tab title="Fiat Credits">
크레딧은 실제 통화 가치(예: USD, EUR)를 나타냅니다. 고객은 정의한 가격에 따라 서비스를 사용할 때 차감되는 금전적 크레딧 잔액을 받습니다.

**적합한 용도**: 선불 잔액, 프로모션 크레딧, 서비스 보상
</Tab>
</Tabs>

### 크레딧 수명 주기

크레딧은 발급부터 사용까지 명확한 수명 주기를 따릅니다:

<Steps>
<Step title="Credits Issued">
고객이 크레딧 권한이 연결된 제품(구독 또는 일회성 제품)을 구매하면 크레딧이 부여됩니다. 구독의 경우 각 결제 주기마다 크레딧이 다시 발급됩니다.
</Step>

<Step title="Credits Consumed">
고객이 서비스를 사용하면 크레딧이 차감됩니다. 사용량 기반 제품에서는 미터가 실시간 이벤트를 기준으로 크레딧을 자동 차감합니다. 대시보드 또는 API를 통해 크레딧을 수동으로 차감할 수도 있습니다.
</Step>

<Step title="Credits Expire or Roll Over">
결제 주기 종료 시점(또는 설정된 만료 기간 이후)에 사용하지 않은 크레딧은 설정에 따라 만료되거나 다음 기간으로 롤오버됩니다.
</Step>

<Step title="Overage Handling">
주기 중간에 크레딧이 소진되면 초과 사용(잔액을 초과한 계속된 사용)을 허용하고 초과 사용을 처리하는 방법(면제, 청구 또는 부족분 이월)을 선택할 수 있습니다.
</Step>
</Steps>

### 부여 출처

크레딧은 여러 출처에서 부여할 수 있습니다:

| 출처 | 설명 |
|--------|-------------|
| **Subscription** | 구독 구매 시 발급되며 각 결제 주기마다 다시 발급되는 크레딧 |
| **One-Time** | 일회성 결제 제품과 함께 발급되는 크레딧 |
| **API** | API 또는 대시보드를 통해 수동으로 부여되는 크레딧 |
| **Rollover** | 이전 결제 주기에서 이월된 크레딧 |

## 크레딧 생성

대시보드의 **Products → Credits** 섹션에서 크레딧 권한을 생성합니다. 각 크레딧은 단위, 정밀도, 만료 규칙 및 수명 주기 동작을 정의합니다.

<Frame caption="The Credits tab under Products shows all your credit entitlements.">
<img src="/images/CBB/Desktop - Entitlements  - Credits.jpg" alt="생성된 크레딧 권한을 표시하는 크레딧 목록 페이지" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Steps>
<Step title="Navigate to Credits">
대시보드에서 **Products**로 이동하고 **Credits** 탭을 선택합니다. **Create Credit**을 클릭하여 시작합니다.
</Step>

<Step title="Configure Basic Information">
**Credit Name**을 입력합니다. 이는 크레딧의 내부 식별자입니다.

<Frame caption="The credit creation form with all configuration sections.">
<img src="/images/CBB/Desktop - Create Credit.jpg" alt="기본 정보, 일반 설정 및 구독 설정을 표시하는 크레딧 생성 양식" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Set General Settings">
크레딧 유형과 표시 속성을 구성합니다:

<ParamField path="Credit Type" type="string" required>
**Custom Unit** 또는 **Fiat Credits**를 선택합니다.

- **Custom Unit** - 자체 지표(토큰, API 호출, 컴퓨팅 시간)를 정의합니다. **Unit Name**(예: "Platform tokens")과 **Precision** 설정이 필요합니다.
- **Fiat Credits** - 크레딧이 실제 통화 가치를 나타냅니다. **Unit Currency**(USD, EUR, GBP, INR 등)를 선택해야 합니다.
</ParamField>

<ParamField path="Unit Name" type="string">
Custom Unit 크레딧에만 적용됩니다. 고객에게 표시되는 크레딧 라벨(예: "AI Tokens", "API Calls")입니다. Checkout 및 Customer Portal에 표시됩니다.
</ParamField>

<ParamField path="Precision" type="number">
Custom Unit 크레딧에만 해당합니다. 허용되는 소수점 이하 자릿수는 `0`에서 `10`까지입니다:

- `0` - 정수( API 호출처럼 셀 수 있는 항목에 적합)
- `1` - 소수점 이하 1자리(0.0)
- `2` - 소수점 이하 2자리(0.00) - **기본값**
- `3` - 소수점 이하 3자리(0.000)
- 최대 `10` - 높은 정밀도가 필요한 단위(예: 소수 토큰 또는 초소량 사용량)

<Warning>
크레딧을 생성한 후에는 정밀도를 변경할 수 없습니다.
</Warning>
</ParamField>

<ParamField path="Credit Expiry" type="string">
발급 후 크레딧이 유효한 기간입니다:

- **7일**, **30일**(기본값), **60일**, **90일**, **Custom** 또는 **Never**

사용자 지정 일수를 지정하려면 **Custom**을 선택합니다(최소 1일).
</ParamField>
</Step>

<Step title="Configure Subscription Settings (Optional)">
이 설정은 반복 구독 내에서 크레딧 동작을 제어합니다:

<ParamField path="Rollover" type="boolean">
사용하지 않은 크레딧을 다음 결제 주기로 이월합니다. 활성화하면 다음을 구성합니다:

- **Max Rollover Percentage** (0~100%) - 이월되는 크레딧의 비율 제한
- **Rollover Timeframe** - 이월된 크레딧이 유효한 기간(예: 1 Month)
- **Max Rollover Count** - 크레딧이 소멸되기 전 연속 이월 가능한 최대 횟수
</ParamField>

**크레딧이 소진되거나 구독이 만료되는 경우:**

<ParamField path="Allow Overage" type="boolean">
크레딧 잔액이 0이 된 후에도 고객이 서비스를 계속 사용하도록 허용합니다. 활성화하면 다음을 구성합니다:

- **Overage Limit** - 고객이 잔액을 초과하여 사용할 수 있는 최대 크레딧
- **Price Per Unit** - 초과 사용이 활성화된 경우 추가 크레딧당 비용(통화 선택기 포함)
</ParamField>

<ParamField path="Overage Behavior" type="string" required>
결제 주기 종료 시 초과 사용을 처리하는 방법을 제어합니다:

- **Forgive overage at reset** (기본값) - 크레딧 한도를 초과한 사용량을 추적하지만 청구하지 않습니다. 잔액은 매 주기 초기화됩니다.
- **Bill overage at billing** - 크레딧 한도를 초과한 사용량을 다음 인보이스에 청구한 후 잔액을 초기화합니다.
- **Carry over deficit** - 크레딧 한도를 초과한 사용량을 음수 잔액으로 다음 주기에 이월합니다.
- **Carry over deficit (auto-repay)** - 부족분을 이월하고 다음 주기에 새 크레딧에서 자동으로 상환합니다.
</ParamField>
</Step>

<Step title="Create Credit">
**Create Credit**을 클릭하여 저장합니다. 이제 모든 제품에 연결할 수 있는 크레딧이 준비되었습니다.

<Check>
크레딧 권한이 준비되었습니다. 제품에 연결하여 고객에게 크레딧을 발급하세요.
</Check>
</Step>
</Steps>

<Tip>
간단한 설정(롤오버 없음, 초과 사용 없음)으로 시작하고 고객이 크레딧을 사용하는 방식을 파악하면서 복잡성을 추가하세요. 대부분의 설정은 기존 부여에 영향을 주지 않고 언제든지 업데이트할 수 있습니다. 단, 크레딧을 생성한 후에는 **정밀도를 변경할 수 없습니다**.
</Tip>

## 제품에 크레딧 연결

제품 생성 또는 편집 과정에서 크레딧을 **entitlements**로 제품에 연결합니다. 제품당 최대 **5개의 크레딧**을 연결할 수 있습니다. 크레딧은 세 가지 가격 유형 모두에서 작동합니다.

### 구독 제품

구독의 경우 크레딧은 **결제 주기별로** 발급되며 비례 배분, 체험판 크레딧 및 주기별 설정을 구성할 수 있습니다.

<Steps>
<Step title="Create or Edit a Subscription Product">
**Products → Create Product**로 이동하거나 기존 제품을 편집합니다. 가격 유형으로 **Subscription**을 선택하고 반복 가격을 구성합니다.
</Step>

<Step title="Open Entitlements Section">
**Entitlements** 섹션을 펼치고 **Credits** 옆의 **Attach** 버튼을 클릭합니다.

<Frame caption="The Entitlements section in the product form with Credits, License Key, and Digital Product Delivery options.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription.jpg" alt="Credits 연결 버튼을 표시하는 제품 권한 섹션" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Select Credits to Attach">
**Add Credits** 패널이 열립니다. 드롭다운에서 기존 크레딧을 선택하거나 **Create new credit**을 클릭하여 즉시 새 크레딧을 정의할 수 있습니다.

<Frame caption="The Add Credits panel lets you select existing credits or create new ones.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription-2.jpg" alt="크레딧 선택 드롭다운이 있는 Add Credits 패널" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Info>
제품당 최대 5개의 크레딧을 연결할 수 있습니다. 각 크레딧은 자체 구성을 가질 수 있습니다.
</Info>
</Step>

<Step title="Configure Credit Settings">
연결된 각 크레딧에 대해 다음을 구성합니다:

<ParamField path="Credits issued per billing cycle" type="number" required>
각 결제 기간에 고객에게 부여할 크레딧 수입니다.
</ParamField>

<ParamField path="Low Balance Threshold" type="number">
크레딧이 이 금액보다 낮아지면 알림을 보냅니다. 고객이 크레딧을 모두 사용하기 전에 알리는 데 유용합니다.
</ParamField>

<ParamField path="Credits During Free Trial" type="number">
체험 기간에 다른 크레딧 수량을 설정합니다. **Expire trial credits after trial ends**를 활성화하면 체험판이 유료 구독으로 전환될 때 사용하지 않은 체험판 크레딧이 회수됩니다.
</ParamField>

<ParamField path="Allow Proration" type="boolean">
고객이 구독 요금제를 업그레이드하거나 다운그레이드할 때 남은 크레딧을 비례 배분합니다.
</ParamField>

<ParamField path="Import Default Credit Settings" type="boolean">
크레딧 권한의 기본 롤오버, 초과 사용 및 만료 설정을 사용합니다. 이 옵션을 끄면 이 제품에만 적용되는 설정을 사용자 지정할 수 있습니다.
</ParamField>

<Frame caption="Credit configuration showing per-cycle amount, trial credits, proration, and custom settings.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription-4.jpg" alt="결제 주기, 체험판 및 비례 배분 설정이 있는 크레딧 구성 양식" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Review and Add">
이름, 수량 및 만료 정보가 표시된 연결된 크레딧을 검토합니다. **Add to Subscription**을 클릭하여 확인합니다.

<Frame caption="Review attached credits before adding them to the subscription.">
<img src="/images/CBB/Desktop - Attach Credit - Subscription-5.jpg" alt="세부 정보와 함께 선택된 크레딧을 표시하는 Add Credits 패널" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>
</Steps>

### 일회성 결제 제품

일회성 결제의 경우 구매 시점에 크레딧이 **한 번** 발급됩니다.

<Steps>
<Step title="Create a One-Time Product">
가격 유형이 **Single Payment**인 제품을 생성합니다.

<Frame caption="Single Payment pricing selected for a one-time credit product.">
<img src="/images/CBB/Desktop - Attach Credit - OTP.jpg" alt="Single Payment가 선택된 제품 가격 섹션" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Attach Credits">
**Entitlements** 섹션을 열고 크레딧을 연결합니다. 구매 시 발급되는 총 일회성 크레딧인 **number of credits issued**를 구성합니다.
</Step>
</Steps>

<Tip>
일회성 크레딧 제품은 크레딧 충전 팩, 프로모션 번들 또는 선불 크레딧 구매에 적합합니다.
</Tip>

### 사용량 기반 결제 제품

사용량 기반 제품의 경우 크레딧이 **미터에 연결**되고 실시간 사용량 이벤트에 따라 자동으로 차감됩니다.

<Steps>
<Step title="Create a Usage-Based Product">
가격 유형으로 **Usage Based Billing**을 선택합니다. 기본 가격과 결제 주기를 구성합니다.

<Frame caption="Usage Based Billing pricing type with meter configuration.">
<img src="/images/CBB/Desktop - Attach Credit - UBB.jpg" alt="Usage Based Billing 가격 구성" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Add a Meter">

## 크레딧 설정

### 롤오버

롤오버를 사용하면 사용하지 않은 크레딧이 만료되지 않고 다음 결제 주기로 이월됩니다.

| 설정 | 설명 |
|---------|-------------|
| **Rollover Enabled** | 사용하지 않은 크레딧의 이월 허용 여부를 전환합니다 |
| **Max Rollover Percentage** | 이월되는 비율을 제한합니다(0~100%). 50%로 설정하면 사용하지 않은 크레딧의 절반만 이월됩니다 |
| **Rollover Timeframe** | 이월된 크레딧이 유효한 기간(일, 주, 월, 년) |
| **Max Rollover Count** | 크레딧을 연속으로 이월할 수 있는 최대 횟수입니다. 이 한도를 초과하면 남은 크레딧이 소멸됩니다 |

**예시**: 고객에게 주기 종료 시 사용하지 않은 크레딧이 200개 있습니다. 롤오버가 75%이면 150개가 이월되고 50개가 소멸됩니다.

### 초과 사용

초과 사용은 주기 중간에 고객의 크레딧 잔액이 0이 되었을 때 발생하는 일을 제어합니다.

| 설정 | 설명 |
|---------|-------------|
| **Allow Overage** | 고객이 크레딧 잔액을 초과하여 서비스를 계속 사용하도록 허용합니다 |
| **Overage Limit** | 고객이 잔액을 초과하여 사용할 수 있는 최대 크레딧 |
| **Price Per Unit** | 초과 사용으로 소비된 추가 크레딧당 비용(통화 포함) |
| **Overage Behavior** | 결제 주기 종료 시 초과 사용을 처리하는 방법을 제어합니다(아래 참조) |

**초과 사용 동작 옵션:**

| 동작 | 설명 |
|----------|-------------|
| **Forgive overage at reset** | 크레딧 한도를 초과한 사용량을 추적하지만 청구하지 않습니다. 잔액은 매 주기 초기화됩니다 |
| **Bill overage at billing** | 크레딧 한도를 초과한 사용량을 다음 인보이스에 청구한 후 잔액을 초기화합니다 |
| **Carry over deficit** | 초과 사용을 음수 잔액으로 다음 주기에 이월합니다 |
| **Carry over deficit (auto-repay)** | 부족분을 이월하고 다음 주기에 새 크레딧에서 자동으로 상환합니다 |
<Info>
초과 사용이 비활성화되면 고객은 크레딧 잔액이 0이 된 후 서비스를 사용할 수 없습니다. 결제 모델에 맞는 초과 사용 동작을 선택하세요. **Forgive at reset**이 기본값이며 가장 간단한 옵션입니다.
</Info>

### 만료

| 설정 | 설명 |
|---------|-------------|
| **Credit Expiry** | 발급 후 크레딧이 만료되기까지의 기간(7일, 30일, 60일, 90일, 사용자 지정 일수 또는 없음) |
| **Trial Credits Expire After Trial** | 체험 기간 종료 시 체험판 전용 크레딧이 만료되는지 여부 |

<Info>
만료된 크레딧은 `CreditExpired` 원장 항목을 생성합니다. 롤오버가 활성화된 경우 만료 전에 롤오버 비율이 적용되며 나머지만 만료됩니다.
</Info>

## 크레딧을 사용한 사용량 결제

크레딧이 사용량 미터에 연결되면 시스템은 강력한 소비 기반 결제 모델을 생성합니다. 고객은 크레딧을 할당받고 사용량 이벤트에 따라 잔액에서 크레딧이 자동 차감됩니다.

<Frame caption="The Usage Billing dashboard shows meter events with units consumed, credits consumed, and customer details.">
<img src="/images/CBB/Desktop - Usage Billing.jpg" alt="소비된 크레딧이 표시된 이벤트 테이블이 있는 Usage Billing 대시보드" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### 미터 기반 크레딧 차감 방식

1. **애플리케이션에서 사용량 이벤트를 전송합니다** - 각 이벤트에는 고객 ID, 이벤트 이름 및 메타데이터가 포함됩니다
2. **미터가 이벤트를 집계합니다** - Count, Sum, Max 또는 Last 집계를 사용합니다
3. **크레딧이 자동으로 차감됩니다** - 백그라운드 워커가 매분 이벤트를 처리하고, 구성된 비율을 사용해 미터 단위를 크레딧으로 변환한 다음 FIFO 순서(가장 오래된 부여분부터)로 고객 잔액에서 차감합니다
4. **초과 사용량이 추적됩니다** - 크레딧 잔액이 0이 되고 초과 사용이 활성화된 경우 시스템은 주기 종료 시 청구할 초과 사용량을 추적합니다

### 미터 패널

Usage Billing 대시보드에는 정의된 모든 미터와 집계 유형을 나열하는 **Meters** 패널이 포함되어 있습니다:

| 집계 | 설명 | 예시 |
|-------------|-------------|---------|
| **Count** | 전체 이벤트 수 | API 호출 |
| **Sum** | 값 필드의 합계 | 전송된 총 바이트 |
| **Max** | 기록된 가장 높은 값 | 최대 동시 사용자 수 |
| **Last** | 가장 최근 값 | 현재 사용 중인 스토리지 |

## Webhooks

Credit-Based Billing은 모든 크레딧 수명 주기 변경에 대해 webhook 이벤트를 발생시킵니다. 이를 사용하여 애플리케이션을 크레딧 잔액과 동기화하고, 알림을 트리거하거나, 사용자 지정 결제 워크플로를 구축할 수 있습니다.

| 이벤트 | 설명 |
|-------|-------------|
| `credit.added` | 고객에게 크레딧이 부여됨 |
| `credit.deducted` | 사용량 또는 수동 차감으로 크레딧이 소비됨 |
| `credit.expired` | 사용하지 않은 크레딧이 만료됨 |
| `credit.rolled_over` | 크레딧이 새 부여분으로 이월됨 |
| `credit.rollover_forfeited` | 최대 롤오버 횟수에서 크레딧이 소멸됨 |
| `credit.overage_charged` | 초과 사용 요금이 적용됨 |
| `credit.manual_adjustment` | 수동 크레딧/차감 조정이 이루어짐 |
| `credit.balance_low` | 잔액이 구성된 기준보다 낮아짐 |

모든 원장 이벤트(`credit.added`부터 `credit.manual_adjustment`까지)에는 거래 전후 잔액, 거래 전후 초과 사용량, 출처 참조 및 부여분의 출처 구독 또는 결제의 `metadata`를 포함한 전체 `CreditLedgerEntry` 페이로드가 포함됩니다(API를 통해 직접 생성된 부여분의 경우 비어 있음). `credit.balance_low` 이벤트에는 기준 구성과 현재 잔액이 포함됩니다.

</Card>

### 통합 예시

Dodo Payments 클라이언트를 초기화합니다:

```typescript
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env['DODO_PAYMENTS_API_KEY'],
  environment: 'test_mode', // defaults to 'live_mode'
});
```

Checkout 중 구독 제품에 크레딧을 연결합니다:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'prod_ai_pro_plan',
      quantity: 1,
    }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

크레딧을 자동으로 차감하는 사용량 이벤트를 전송합니다:

```typescript
await client.usageEvents.ingest({
  events: [{
    event_id: `gen_${Date.now()}`,
    customer_id: 'cus_abc123',
    event_name: 'ai.generation',
    timestamp: new Date().toISOString(),
    metadata: { model: 'gpt-4', tokens: 1500 }
  }]
});
```

## 모범 사례

- **간단하게 시작하기**: 단일 크레딧 유형과 롤오버 없음으로 시작합니다. 고객 피드백과 사용 패턴에 따라 복잡성을 추가하세요.
- **명확한 기대치 설정**: 제품 페이지와 Customer Portal에 크레딧 할당량, 남은 잔액 및 초과 사용 가격을 눈에 띄게 표시하세요.
- **의미 있는 단위 사용**: 일반적인 용어 대신 크레딧이 나타내는 대상을 기준으로 이름을 지정하세요(예: "API Calls", "AI Tokens"). 고객이 가치를 이해하는 데 도움이 됩니다.
- **신중하게 만료 구성하기**: 짧은 만료 기간(7일)은 긴급성을 높이지만 고객을 불편하게 할 수 있습니다. 대부분의 SaaS 제품에는 더 긴 기간(30~90일)이 고객 친화적입니다.
- **낮은 잔액 모니터링**: 낮은 잔액 기준을 설정하여 고객이 크레딧을 모두 사용하기 전에 알림을 보내면 예상치 못한 초과 사용 요금을 줄일 수 있습니다.
- **테스트 모드에서 테스트하기**: 크레딧을 생성하고 테스트 제품에 연결한 뒤 실제 운영을 시작하기 전에 전체 구매 → 사용량 → 차감 → 만료 주기를 시뮬레이션하세요.
