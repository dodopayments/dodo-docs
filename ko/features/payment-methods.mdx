## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## 비즈니스 수준 결제 수단 비활성화

대시보드에서 비즈니스 수준으로 특정 결제 수단을 비활성화할 수 있습니다. 이는 모든 제품이나 세션별로 구성할 필요 없이 비즈니스의 모든 결제 세션에 적용됩니다.

<Steps>
<Step title="Navigate to Settings">
Dodo Payments 대시보드에서 **설정 > 결제 수단**으로 이동합니다.
</Step>

<Step title="Disable Payment Methods">
고객에게 제공하지 않으려는 결제 수단을 토글하여 끕니다.
</Step>
</Steps>

<Tip>
이것을 사용하여 지역 내 사기 발생률이 높은 결제 수단을 비활성화하거나 운영적으로 지원하는 방법으로 옵션을 제한합니다.
</Tip>

<Info>
비즈니스 수준 설정은 글로벌 필터 역할을 합니다. `allowed_payment_method_types`를 통한 세션별 제한은 비즈니스 수준에서 활성화된 방법 내에서 사용할 수 있는 방법을 더욱 좁힙니다.
</Info>

## 세션별 결제 수단 구성

비즈니스 수준 설정 외에도 `allowed_payment_method_types`를 사용하여 개별 결제 세션에 표시할 방법을 제한할 수 있습니다:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## 모범 사례

<AccordionGroup>
<Accordion title="Match methods to your market">
대상 시장에 대한 지역 결제 수단을 포함하세요. iDEAL은 네덜란드에서 온라인 결제의 약 60%를 차지하며, UPI는 인도에서 우위를 점합니다. 이러한 방법을 생략하면 전환율에 큰 영향을 미칩니다.
</Accordion>

<Accordion title="Always provide card fallbacks">
특정 방법을 타겟팅할 때에도 항상 `credit`와 `debit`를 백업으로 포함하세요. 모든 고객이 모든 결제 수단에 접근할 수 있는 것은 아닙니다.
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL 방법에는 제공자별 최소 요구사항이 있습니다: Klarna와 Afterpay는 $50.01이 필요하고, Sunbit는 $60.00이 필요하며 최대 $19,999까지 가능합니다. 이러한 범위를 벗어난 제품에는 포함하지 마세요. 그렇게 하면 단순히 나타나지 않을 겁니다. 괜찮습니다.
</Accordion>

<Accordion title="Test across regions and devices">
다양한 고객 위치, 통화 및 장치 유형에 대한 결제 수단의 가용성을 라이브 전에 테스트 모드에서 확인하세요.
</Accordion>
</AccordionGroup>

## 문제 해결

<AccordionGroup>
<Accordion title="Payment method not appearing">
**다음 요인을 확인하세요:**
1. `allowed_payment_method_types`에 방법이 포함되었습니까?
2. 고객 위치가 방법이 지원하는 지역과 일치합니까?
3. 거래 통화가 방법으로 지원됩니까?
4. 거래 금액이 방법의 지원 범위 내에 있습니까? (예: Klarna/Afterpay 최소 $50.01; Sunbit $60.00–$19,999)?
5. 구독의 경우: 방법이 반복 결제를 지원합니까?

**해결:** 가능성 있는 모든 방법을 보려면 `allowed_payment_method_types`를 일시적으로 제거한 다음 문제를 좁히세요.
</Accordion>

<Accordion title="Unexpected methods appearing">
**가능한 원인:**
- `allowed_payment_method_types`가 올바르게 전달되지 않음
- 매개변수 형식이 잘못됨 (문자열 배열이어야 함)

**해결:** API 요청 페이로드를 기록하고 매개변수 구조를 확인하세요.
</Accordion>

<Accordion title="Regional method not available">
**확인:**
- 고객 청구 주소가 방법의 지역과 일치합니까?
- 통화가 정확히 설정되었습니까? (예: iDEAL의 경우 EUR)
- 고객이 국제적일 경우 적응형 통화가 활성화되어 있습니까?

**해결:** API 요청에서 청구 주소 국가 코드와 통화를 확인하세요.
</Accordion>

<Accordion title="Indian payment method issues">
UPI 및 Rupay 구독에는 48시간 처리 지연 및 RBI 명령 제약을 포함한 고유한 요구사항이 있습니다.

**참고:** <a href="/features/payment-methods/india">인도 결제 수단</a>을 참조하여 완전한 지침을 확인하세요.
</Accordion>
</AccordionGroup>
