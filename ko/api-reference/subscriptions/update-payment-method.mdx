구독의 결제 방법을 업데이트합니다. 이 엔드포인트는 활성 구독 및 `on_hold` 상태의 구독을 모두 지원합니다.

<Info>
`on_hold` 상태의 구독에 대해 결제 방법을 업데이트하면, 남은 요금에 대한 요금이 자동으로 생성되고, 청구서가 발행되며, 결제가 성공적으로 처리된 후 구독이 `active` 상태로 재활성화됩니다.
</Info>

### 사용 사례

- **활성 구독**: 카드가 만료되거나 고객이 다른 결제 방법을 사용하고 싶을 때 결제 방법 업데이트
- **보류 중인 구독**: 결제 실패로 인해 보류 중인 구독을 결제 방법을 업데이트하여 재활성화
- **결제 방법 관리**: 저장된 결제 방법 간 전환 또는 새 결제 방법 추가

<Info>
고객의 기존 결제 방법 목록을 보려면 [결제 방법 목록 API](/api-reference/customers/get-customer-payment-methods)를 사용하세요. 이것은 `type: "existing"` 를 사용하여 구독의 결제 방법을 업데이트할 때 사용할 수 있는 결제 방법 ID를 검색하는 데 도움을 줍니다.
</Info>

### 활성 구독에 대한 동작

활성 구독의 결제 방법을 업데이트할 때:

- 결제 방법이 즉시 업데이트됩니다
- 청구가 생성되지 않습니다
- 구독은 활성 상태로 유지됩니다
- 향후 갱신은 새 결제 방법을 사용합니다

### 보류 중인 구독에 대한 동작

`on_hold` 상태의 구독에 대한 결제 방법을 업데이트할 때:

1. 남은 요금에 대한 요금이 자동으로 생성됩니다.
2. 요금에 대한 청구서가 생성됩니다.
3. 새 결제 방법을 사용하여 결제가 처리됩니다.
4. 결제가 성공적으로 완료되면 구독이 `active` 상태로 재활성화됩니다.
5. 다음과 같은 웹후크 이벤트를 받게 됩니다: `payment.succeeded` 이후에 `subscription.active`.

<Warning>
결제 방법을 업데이트한 후 `on_hold` 구독에 대한 결제가 실패하면, 구독은 `on_hold` 상태로 유지됩니다. 결제 상태를 추적하기 위해 웹후크 이벤트를 모니터링하세요.
</Warning>

### 웹훅 이벤트

`on_hold` 구독의 결제 방법을 업데이트할 때, 다음 웹후크 이벤트를 받게 됩니다:

1. **`payment.succeeded`** - 남은 요금에 대한 청구가 성공적입니다.
2. **`subscription.active`** - 구독이 재활성화되었습니다.
