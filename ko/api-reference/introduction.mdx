## API Key Management and Authentication

<Steps>
<Step title="Access API Keys">
대시보드에서 **Developer → API Keys**로 이동하여 키를 관리하세요.
</Step>

<Step title="Generate a New Key">
**Add API Key**를 선택하고 설명이 포함된 이름을 입력한 다음 쓰기 액세스를 구성하세요:

- **Enable write access** (선택됨): 모든 API 작업에 대한 전체 읽기 및 쓰기 권한
- **Enable write access** (선택되지 않음): 읽기 전용 액세스 - 데이터(결제, 구독, 고객, 제품)만 가져올 수 있습니다. 리소스를 생성하거나 수정할 수 없습니다.

<Tip>
대시보드 통합, 분석 도구 및 변경 없이 데이터만 확인하면 되는 모든 시스템에서는 "Enable write access"의 선택을 해제하세요.
</Tip>
</Step>

<Step title="Store Your Key Securely">
생성된 키를 즉시 복사하고 안전하게 보관하세요.
</Step>

<Step title="Authenticate Your API Requests">
모든 요청을 인증하려면 API 키를 사용하세요. 다음 authorization 형식을 적용하세요:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
클라이언트 측 코드나 공개 저장소에 비밀 API 키를 절대 노출하지 마세요.
</Warning>
</Step>
</Steps>

## Rate Limits

당사의 API는 버스트 보호 기능이 포함된 이중 윈도우 rate limiting 시스템을 사용합니다. 제한은 인증 방법과 비즈니스 등급에 따라 적용됩니다.

### Default Limits (Tier 0)

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 40 requests |
| Per Minute (Sustained) | 240 requests |

### Business Tiers

API 사용량이 증가한 비즈니스에는 더 높은 rate limit을 사용할 수 있습니다:

| Tier | Burst (per second) | Sustained (per minute) |
|------|-------------------|------------------------|
| Tier 0 (Default) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
비즈니스를 더 높은 rate limit 등급으로 업그레이드하려면 지원팀에 문의하세요.
</Tip>

### Unauthenticated Requests

유효한 인증 헤더가 없는 요청은 IP 주소를 기준으로 rate limit이 적용됩니다:

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 20 requests |
| Per Minute (Sustained) | 100 requests |

### Rate Limit Headers

다음 response headers를 사용하여 사용량을 모니터링하세요:

- `X-RateLimit-Limit` - 허용되는 최대 요청 수
- `X-RateLimit-Remaining` - 현재 윈도우에 남은 요청 수
- `X-RateLimit-Reset` - rate limit이 초기화되는 시간

<Note>
rate limit을 초과하면 API는 `429 Too Many Requests` response를 반환합니다. retry 로직에 exponential backoff를 구현하세요.
</Note>
