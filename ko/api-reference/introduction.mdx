## API Key 관리 및 인증

<Steps>
<Step title="Access API Keys">
대시보드에서 **Developer → API Keys**로 이동하여 key를 관리하세요.
</Step>

<Step title="Generate a New Key">
**Add API Key**를 선택하고 설명이 포함된 이름을 입력한 후 write access를 구성하세요:

- **Enable write access** (선택됨): 모든 API 작업에 대한 전체 read 및 write 권한
- **Enable write access** (선택되지 않음): 읽기 전용 access - 데이터(payments, subscriptions, customers, products)만 가져올 수 있습니다. 리소스를 생성하거나 수정할 수 없습니다.

<Tip>
대시보드 통합, 분석 도구 및 변경 없이 데이터 보기만 필요한 시스템에서는 "Enable write access"를 선택 해제하세요.
</Tip>
</Step>

<Step title="Store Your Key Securely">
생성된 key를 즉시 복사하고 안전하게 보관하세요.
</Step>

<Step title="Authenticate Your API Requests">
모든 요청을 인증하려면 API key를 사용하세요. 다음 authorization 형식을 적용하세요:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
secret API key를 client-side code 또는 public repository에 절대 노출하지 마세요.
</Warning>
</Step>
</Steps>

## Rate Limits

당사의 API는 burst protection을 지원하는 이중 window rate limiting 시스템을 사용합니다. Limit은 authentication method와 business tier에 따라 적용됩니다.

### 기본 Limit (Tier 0)

| Window | Limit |
|--------|-------|
| 초당 (Burst) | 40 requests |
| 분당 (Sustained) | 240 requests |

### Business Tier

API 사용량이 증가한 business에는 더 높은 rate limit을 사용할 수 있습니다:

| Tier | Burst (초당) | Sustained (분당) |
|------|-------------------|------------------------|
| Tier 0 (기본값) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
business를 더 높은 rate limit tier로 업그레이드하려면 support에 문의하세요.
</Tip>

### 인증되지 않은 요청

유효한 authentication header가 없는 요청은 IP address를 기준으로 rate limit이 적용됩니다:

| Window | Limit |
|--------|-------|
| 초당 (Burst) | 20 requests |
| 분당 (Sustained) | 100 requests |

### Rate Limit Header

다음 response header로 사용량을 모니터링하세요:

- `X-RateLimit-Limit` - 허용되는 최대 requests
- `X-RateLimit-Remaining` - 현재 window에서 남은 requests
- `X-RateLimit-Reset` - rate limit이 재설정되는 시간

<Note>
rate limit을 초과하면 API는 `429 Too Many Requests` response를 반환합니다. retry logic에 exponential backoff를 구현하세요.
</Note>
