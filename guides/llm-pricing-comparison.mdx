# LLM Billing Mastery: Strategic Cost Control with Dodo UBB

The core challenge in AI monetization is transforming complex, granular **token usage** into **predictable, compliant revenue**. LLM providers charge based on granular usage metrics (Input vs. Output tokens), which, without proper infrastructure, leads to unpredictable billing. This guide shows how to leverage **Dodo Payments' Usage-Based Billing (UBB)** feature to achieve transparent and profitable monetization for your AI product.

## 1. LLM Token Pricing Comparison (Input vs. Output)

The Dodo UBB system requires accurate calculation of your actual costs. The model separation below is vital for profitability and strategic pricing. *(Note: Costs are illustrative and should be verified.)*

| Model Provider | Model Example        | Input Rate (per 1M tokens) | Output Rate (per 1M tokens) | Strategic UBB Note                                                                                     |
| :------------- | :------------------- | :------------------------- | :-------------------------- | :--------------------------------------------------------------------------------------------------- |
| **OpenAI**     | GPT-4 Turbo          | ~$10.00                   | ~$30.00                    | **Cost Delta:** Highest cost difference; dictates separate input/output metering for profitability.  |
| **Anthropic**  | Claude 3 Opus        | ~$15.00                   | ~$75.00                    | **Premium:** Highest cost; often reserved for high-value reasoning where high output cost is justified by quality. |
| **Google**     | Gemini Pro           | ~$3.50                    | ~$7.00                     | **Volume:** Lower rates; ideal for high-volume chat or search where cost efficiency is critical.      |
| **Open Source**| Llama 3 (via Groq)   | ~$0.10                    | ~$0.20                     | **Cost Floor:** Used for internal metrics or providing a low-cost, predictable baseline tier.         |

## 2. Dodo Payments UBB: The Strategic Advantage

<Tip>
Dodo Payments acts as your Merchant of Record (MoR), handling global taxes and compliance. The UBB system is integrated into this compliant financial layer, solving the difficulty of managing LLM costs and global sales tax simultaneously.
</Tip>

Dodo UBB solves LLM billing complexity by:

* **Automated Metering:** Automatically aggregates token usage data from your application endpoints.
* **Tiered Pricing:** Allows you to define *separate* pricing plans for each LLM model/tier.
* **Simplified Invoicing:** Consolidates complex token usage metrics into **professional, globally compliant invoices** for your end-users.

## 3. Step-by-Step UBB Configuration

You map the LLM's usage (tokens) to a billable metric within the Dodo UBB platform using the following steps.

<Steps>

<Step>
### A. Define the Usage Metrics

1. Access the Dodo **Billing/Products** section in your dashboard.
2. Ensure you have defined two separate **Usage Metrics** in your product configuration:
   * `tokens_in` (for Input Tokens)
   * `tokens_out` (for Output Tokens)

**Verification:**  
You should see both `tokens_in` and `tokens_out` listed under your product’s Usage Metrics.
</Step>

<Step>
### B. Configure Model-Specific Pricing Tiers

1. In your pricing plan, click to add a new **Pricing Tier** for each LLM model you use (e.g., `GPT-4o_Premium_Tier`).
2. Assign per-unit token rates explicitly to each metric:

| Model Tier    | Metric      | Rate (Example)          | **Business Insight**                              |
| :------------ | :---------- | :--------------------- | :------------------------------------------------ |
| **GPT-4-Turbo** | `tokens_in`  | $0.000010 per token    | *Sets the break-even point for developer usage.*  |
| **GPT-4-Turbo** | `tokens_out` | $0.000030 per token    | *Captures the higher cost of the model's generation effort.* |

3. Save your pricing tier configuration.

**Verification:**  
Navigate back to the Pricing Tiers section to confirm your tier and rates are saved and active.
</Step>

<Step>
### C. Implement API Usage Event Submission

Send usage data to Dodo's API with the correct event types and token counts to trigger billing.

<RequestExample
  lang="json"
  title="POST /usage-events"
>
{  
  "product_id": "your_product_id",
  "usage_events": [
    {
      "metric": "tokens_in",
      "quantity": 1500,
      "timestamp": "2025-10-28T12:00:00Z"
    },
    {
      "metric": "tokens_out",
      "quantity": 4500,
      "timestamp": "2025-10-28T12:00:00Z"
    }
  ]
}
</RequestExample>

<ResponseExample
  lang="json"
  title="200 OK"
>
{
  "status": "success",
  "message": "Usage events recorded",
  "events_count": 2
}
</ResponseExample>

**Expected Outcome:**  
You should see these usage events reflected in your Dodo dashboard Usage Metrics section within minutes.

**Retry Logic:**  
If the API returns transient errors (e.g., 500 or 429), implement exponential backoff and retry up to 3 times.

</Step>

</Steps>

### Troubleshooting

- **Events Not Appearing in Dashboard:**  
  Verify your API payload uses exact metric names (`tokens_in` and `tokens_out`). Check API response for errors.
- **Pricing Tier Not Applying:**  
  Confirm that you assigned pricing tiers to the correct metrics and that your product configuration references these tiers.
- **Metric Naming Mismatch Errors:**  
  Always use `tokens_out` (not `tokens_output`) consistently throughout your configuration and API calls.
- **API Authentication Issues:**  
  Ensure API keys are correctly provided in headers and have required permissions.
