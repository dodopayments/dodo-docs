Il Dodo Agent Plugin integra due server MCP e diciassette skill di integrazione nel tuo AI coding agent con una singola installazione. Funziona con **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** e **OpenCode**. **Gemini CLI** riceve solo i due server MCP. I server MCP e la CLI delle skill funzionano con qualsiasi client compatibile con MCP.

Il plugin segue la specifica [Agent Plugins 1.0.0](https://agent-plugins.org/specification), quindi i client con supporto nativo lo caricano direttamente dalla root `plugin.json` e `mcp.json`. I client precedenti alla specifica caricano gli stessi contenuti tramite manifest di compatibilità generati.

<Info>
**Tre primitive, un plugin.** L'Agent Plugin include tutto ciò di cui hai bisogno:
- **Server MCP API** — accesso in tempo reale a pagamenti, abbonamenti, clienti, prodotti, rimborsi, licenze e utilizzo. Esegue l'autenticazione tramite OAuth nel browser (non sono necessarie chiavi locali).
- **Server MCP Knowledge** — ricerca semantica in tutta la documentazione di Dodo Payments. Non sono necessarie credenziali.
- **Diciassette skill per agent** — schede di riferimento che il tuo agent carica su richiesta per checkout, abbonamenti, webhook, fatturazione basata sull'utilizzo e sui crediti, chiavi di licenza, catalogo prodotti, sconti, prezzi localizzati, checkout mobile, rimborsi e contestazioni, gestione dei clienti, adattatori per framework, BillingSDK, Better Auth, testing e go-live, oltre alle best practice.
</Info>

## Installa il plugin

Scegli il tuo coding agent qui sotto. Ogni installazione aggiunge entrambi i server MCP; tutti, tranne Gemini CLI, aggiungono anche le diciassette skill.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installa dal marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Il server MCP API usa OAuth nel browser per impostazione predefinita — non sono necessarie chiavi al momento dell'installazione. La prima volta che il tuo agent chiama uno strumento Dodo, ti verrà richiesto di accedere.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Codice sorgente, opzioni di configurazione e istruzioni per lo sviluppo locale
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installa i plugin in due passaggi: registra il marketplace dalla shell, quindi installa il plugin dall'interno della TUI di Codex.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Apri Codex ed esegui il comando slash `/plugins`:

```bash
codex
```

Digita quindi `/plugins`, passa al marketplace **Dodo Payments**, seleziona il plugin **dodopayments** e scegli **Install plugin**.
</Step>
</Steps>

Entrambi i server MCP e tutte le diciassette skill vengono registrati automaticamente una volta installato il plugin.

<Note>
Codex CLI non dispone di un sottocomando `codex plugin install`: l'installazione del plugin avviene sempre tramite il flusso `/plugins` nella TUI. Consulta la [documentazione ufficiale sui plugin di Codex](https://developers.openai.com/codex/plugins).
</Note>

Se hai già aggiunto il marketplace e il plugin non compare sotto `/plugins`, aggiornalo:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Installazione manuale — clona il repository nella directory dei plugin locali di Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Riavvia Cursor. Il plugin carica le skill da `skills/` e i server MCP da `.mcp.json`, come dichiarato in `.cursor-plugin/plugin.json`.

<Info>
Le build recenti di Cursor riconoscono direttamente anche Agent Plugins 1.0.0 e accettano `.cursor-plugin/marketplace.json` o `.claude-plugin/marketplace.json` come origine del marketplace. Questo plugin include `.claude-plugin/marketplace.json` — usa quel percorso. `.cursor-plugin/plugin.json`, generato automaticamente, viene mantenuto per le build precedenti.
</Info>

<Warning>
Le versioni precedenti alla 0.5.0 includevano `skills/` come symlink verso un git submodule, quindi questo clone produceva un plugin con **skill non funzionanti**. Ora le skill vengono incluse come file reali. Se hai installato una versione precedente, elimina la directory e clona nuovamente.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode viene distribuito tramite npm. Aggiungi il plugin al tuo `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Riavvia OpenCode. Entrambi i server MCP (`dodopayments-api`, `dodo-knowledge`) vengono registrati automaticamente tramite l'hook di configurazione del plugin. Non è necessario alcun blocco `mcp` manuale.

**Le skill richiedono una riga aggiuntiva.** OpenCode non analizza i pacchetti installati alla ricerca delle skill, quindi indica manualmente la directory `skills/` del pacchetto:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

Le voci `skills.paths` relative vengono risolte rispetto alla **directory del progetto**, quindi il pacchetto deve trovarsi nella `node_modules` di quel progetto — la cache dei plugin di OpenCode si trova in una posizione diversa. Funziona anche un percorso assoluto, che evita il requisito dell'installazione locale.

<Warning>
Un percorso delle skill inesistente viene ignorato **silenziosamente**. Verifica invece di dare per scontato:

```bash
opencode run "List every skill available to you by name."
```

Dovresti visualizzarle tutte e diciassette. La documentazione delle versioni precedenti alla 0.5.0 indicava che queste skill venivano rilevate automaticamente — non era così, quindi gli utenti di OpenCode avevano i server MCP ma nessuna skill.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Clona il repository in una posizione qualsiasi, quindi registralo:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Apri la vista Chat, vai su **Plugins** e aggiungi la cartella clonata. Puoi anche registrarla direttamente in `settings.json`:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

La chiave è un percorso, il valore lo abilita. Funzionano sia i percorsi assoluti sia `~/`; un percorso relativo viene risolto rispetto a ogni cartella del workspace. L'impostazione viene letta in tempo reale, quindi una finestra già in esecuzione la acquisisce senza riavvio. Le skill vengono caricate da `skills/`, mentre entrambi i server MCP vengono caricati da `.mcp.json`.

<Note>
`chat.pluginLocations` è contrassegnato come **sperimentale** ed è un'impostazione *limitata*, quindi il workspace deve essere considerato attendibile perché abbia effetto. Il supporto agli agent plugin nel suo complesso è una funzionalità in anteprima regolata da `chat.plugins.enabled`, **attiva per impostazione predefinita** — devi impostarla solo se la tua organizzazione la disabilita tramite policy.
</Note>

<Info>
VS Code non utilizza `$schema` di Agent Plugins come chiave. Il suo loader cerca prima `.plugin/plugin.json`, poi `.claude-plugin/plugin.json` e infine una root `plugin.json`; inoltre imposta MCP su `.mcp.json` invece che su `mcp.json`. Poiché questo repository include un `.claude-plugin/plugin.json` generato, VS Code lo carica tramite quel ramo di compatibilità e utilizza il bridge `mcp-remote` invece dei transport nativi in `mcp.json`. Funziona tutto — cambia il percorso.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro legge nativamente il manifest di Agent Plugins e lo carica come Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
In Kiro, apri il pannello Powers — l'icona Ghosty con il fulmine.
</Step>

<Step title="Import the folder">
Scegli **Add Custom Power → Import power from a folder**, seleziona la directory clonata (quella che contiene `plugin.json`) e fai clic su **Install**.
</Step>
</Steps>

Le skill vengono caricate da `skills/`, i server MCP da `mcp.json` e la presentazione specifica di Kiro proviene dal namespace di estensione `dev.kiro` in `plugin.json`.

<Note>
Per i plugin nel formato Agent Plugins, Kiro gestisce internamente i server MCP — non vengono scritti nel tuo `~/.kiro/settings/mcp.json` a livello utente, quindi non aspettarti di trovarli lì. Kiro può anche installare direttamente una Power da un URL GitHub; consulta la [documentazione di installazione di Kiro](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI non dispone di una primitiva agent-skill, quindi **sono disponibili solo i due server MCP** — le diciassette skill non lo sono. `dodo-knowledge` copre comunque buona parte delle funzionalità offerte dalle skill e rimane aggiornato automaticamente.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Riavvia Gemini CLI. `gemini-extension.json` nella root del repository è il manifest.
</Accordion>
</AccordionGroup>

## Cosa ottieni

Una volta installato il plugin, il tuo agent ha accesso a due server MCP e diciassette skill.

### Server MCP

| Server | Scopo | Autenticazione |
|--------|---------|------|
| `dodopayments-api` | Accesso API in tempo reale — pagamenti, abbonamenti, clienti, prodotti, rimborsi, licenze e utilizzo | OAuth (browser) |
| `dodo-knowledge` | Ricerca semantica in tutta la documentazione di Dodo Payments | Nessuna |

Entrambi i server utilizzano Streamable HTTP. Il `mcp.json` canonico li dichiara nativamente (`type: "streamable-http"`), come utilizzato dai client nativi della specifica, ad esempio Codex CLI e Kiro. Il manifest di compatibilità generato `.mcp.json` collega invece gli stessi due endpoint tramite `mcp-remote`, consentendone l'esecuzione anche nei client che non possono connettersi direttamente a Streamable HTTP — Claude Code, VS Code e Cursor tramite l'installazione con git clone descritta sopra, il cui `.cursor-plugin/plugin.json` punta a `.mcp.json`.

### Skill per agent

| Skill | Descrizione |
|-------|-------------|
| `dodo-best-practices` | Configurazione SDK, ambienti, API keys e architettura canonica da checkout a webhook |
| `framework-adapters` | Handler di route ufficiali `@dodopayments/*` per Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun e Convex |
| `testing-and-go-live` | Test mode, metodi di pagamento di test, testing dei webhook e checklist di lancio in produzione |
| `checkout-integration` | Checkout Sessions, link di pagamento e checkout overlay o inline |
| `subscription-integration` | Ciclo di vita degli abbonamenti, periodi di prova, modifiche ai piani, proration e addebiti on-demand |
| `mobile-checkout` | Checkout in-app per React Native, Flutter, iOS e Android |
| `webhook-integration` | Ricezione e verifica dei webhook usando la specifica Standard Webhooks |
| `credit-based-billing` | Entitlement dei crediti, saldi, ledger, rollover, overage e deduzione basata sui meter |
| `usage-based-billing` | Meter, acquisizione degli eventi, aggregazione e prezzi per unità |
| `license-keys` | Attivazione e convalida delle chiavi di licenza e gestione delle istanze |
| `product-catalog-management` | Prodotti, prezzi, add-on, raccolte, immagini e distribuzione di prodotti digitali |
| `discounts-and-promotions` | Codici sconto, regole di idoneità, combinazione e limiti per ciclo di abbonamento |
| `localized-pricing` | Prezzi localizzati, Adaptive Currency e parità del potere d'acquisto |
| `customer-management` | Clienti, portale self-service, metodi di pagamento salvati e wallet |
| `refunds-and-disputes` | Emissione di rimborsi, gestione di contestazioni e chargeback e riconciliazione degli accessi |
| `billing-sdk` | Componenti React di BillingSDK per tabelle dei prezzi e interfaccia di fatturazione |
| `better-auth-integration` | Plugin `@dodopayments/better-auth` per la sincronizzazione dei clienti, il checkout e l'accesso al portale |

Le skill vengono caricate automaticamente: il tuo agent sceglie quella appropriata quando rileva un'attività pertinente. Consulta la [documentazione Agent Skills](/developer-resources/agent-skills) per l'elenco completo e le istruzioni di installazione individuali.

### Prova prima questo prompt

Una volta attivato il plugin, prova:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Il tuo agent caricherà la skill `webhook-integration`, userà MCP `dodo-knowledge` per recuperare le forme più recenti dei payload e scriverà un handler con verifica della firma conforme alla specifica Standard Webhooks.

## Sicurezza e best practice

<Warning>
**Non eseguire mai il commit delle API keys di produzione.** Usa la [test mode](/miscellaneous/test-mode-vs-live-mode) durante lo sviluppo. L'Agent Plugin usa OAuth nel browser per impostazione predefinita — passa alle API keys locali solo se il tuo flusso di lavoro lo richiede.
</Warning>

- **Usa prima la test mode.** Esegui il sandboxing dell'integrazione con le chiavi `dodo_test_...` prima di andare live. Consulta [Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode).
- **OAuth è l'impostazione predefinita.** L'Agent Plugin esegue l'autenticazione tramite OAuth nel browser (senza secret locali). Usa la modalità con API key solo se necessario — consulta la sezione Configura qui sotto.
- **Esamina il codice generato dall'agent.** Verifica sempre che gli handler webhook includano la verifica della firma secondo la [specifica Standard Webhooks](https://standardwebhooks.com/).

## Configura con una API key

Per impostazione predefinita, l'Agent Plugin usa il server MCP remoto con OAuth nel browser — non sono necessarie credenziali locali. Se il tuo flusso di lavoro richiede una API key locale (ad esempio, ambienti CI o server headless), puoi passare alla modalità stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Apri `/plugins` in Claude Code, seleziona **Dodo Payments** e scegli **Configure options**. Inserisci:

- `dodo_api_key` — la tua chiave `dodo_test_...` o `dodo_live_...`
- `dodo_webhook_key` — il tuo secret di firma dei webhook
- `dodo_environment` — `test_mode` o `live_mode`

Modifica quindi `.mcp.json` in modo che `dodopayments-api` punti al server stdio locale:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Esegui `/reload-plugins` per applicare le modifiche alla sessione corrente.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Dichiara `dodopayments-api` direttamente in `opencode.json` — la tua voce ha la precedenza sul server remoto predefinito del plugin:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Riavvia OpenCode per applicare la modifica.
</Accordion>
</AccordionGroup>
