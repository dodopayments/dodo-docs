Il Dodo Agent Plugin collega due server MCP e diciassette competenze di integrazione al tuo agente di coding basato sull'AI con una sola installazione. Funziona con **Claude Code**, **Codex CLI**, **Cursor** e **OpenCode** — e i server MCP e la CLI delle competenze funzionano con qualsiasi client compatibile con MCP.

<Info>
**Tre primitive, un solo plugin.** Agent Plugin include tutto ciò di cui hai bisogno:
- **Server MCP API** — accesso in tempo reale a pagamenti, abbonamenti, clienti, prodotti, rimborsi, licenze e utilizzo. Esegue l'autenticazione tramite OAuth nel browser (non sono necessarie chiavi locali).
- **Server MCP Knowledge** — ricerca semantica nell'intera documentazione di Dodo Payments. Non sono necessarie credenziali.
- **Diciassette competenze per l'agente** — schede rapide che l'agente carica quando necessario per checkout, abbonamenti, webhook, fatturazione basata sull'utilizzo e sui crediti, chiavi di licenza, catalogo prodotti, sconti, prezzi localizzati, checkout mobile, rimborsi e contestazioni, gestione dei clienti, adapter per framework, BillingSDK, Better Auth, test e go-live, oltre alle best practice.
</Info>

## Installa il plugin

Scegli qui sotto il tuo agente di coding. L'installazione aggiunge automaticamente entrambi i server MCP e tutte le diciassette competenze.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installa dal marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Il server API MCP utilizza di default OAuth del browser — non sono necessarie chiavi al momento dell'installazione. Alla prima chiamata di uno strumento Dodo da parte del tuo agente, ti verrà chiesto di accedere.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Codice sorgente, opzioni di configurazione e istruzioni per lo sviluppo locale
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installa i plugin in due passaggi: registra il marketplace dalla tua shell, poi installa il plugin dall'interno del TUI di Codex.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Apri Codex ed esegui il comando slash `/plugins`:

```bash
codex
```

Poi digita `/plugins`, passa al marketplace **Dodo Payments**, seleziona il plugin **dodopayments** e scegli **Installa plugin**.
</Step>
</Steps>

Entrambi i server MCP e tutte le diciassette competenze vengono registrati automaticamente dopo l'installazione del plugin.

<Note>
Codex CLI non dispone di un sottocomando `codex plugin install` — l'installazione del plugin avviene sempre tramite il flusso in-TUI `/plugins`. Vedi la [documentazione ufficiale dei plugin di Codex](https://developers.openai.com/codex/plugins).
</Note>

Se hai precedentemente aggiunto il marketplace e il plugin non appare sotto `/plugins`, aggiornalo:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Installazione manuale — clona il repository nella directory dei plugin locali di Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Riavvia Cursor. Il plugin carica le competenze da `.claude/skills/` (tramite il layer di compatibilità Claude Code di Cursor) e i server MCP da `.mcp.json`.

<Info>
Il supporto marketplace per Cursor è in arrivo. Per ora, usa l'installazione manuale sopra descritta.
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode distribuisce tramite npm. Aggiungi il plugin al tuo `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Riavvia OpenCode. Entrambi i server MCP (`dodopayments-api`, `dodo-knowledge`) vengono registrati automaticamente tramite l'hook di configurazione del plugin, mentre le diciassette competenze vengono rilevate automaticamente dal pacchetto installato. Non è necessario alcun blocco `mcp` manuale.
</Accordion>
</AccordionGroup>

Usi un agente diverso? Le guide [MCP Server](/developer-resources/mcp-server) e [Agent Skills](/developer-resources/agent-skills) coprono Cursor, Claude Desktop, VS Code, Windsurf, Cline, Zed e qualsiasi client compatibile con MCP.
</Info>

## Cosa ottieni

Dopo l'installazione del plugin, il tuo agente ha accesso a due server MCP e diciassette competenze.

### Server MCP

| Server | Scopo | Autenticazione |
|--------|---------|------|
| `dodopayments-api` | Accesso API live — pagamenti, abbonamenti, clienti, prodotti, rimborsi, licenze, utilizzo | OAuth (browser) |
| `dodo-knowledge` | Ricerca semantica in tutta la documentazione di Dodo Payments | Nessuna |

Entrambi i server sono connessi tramite `mcp-remote` in modo da funzionare con qualsiasi client compatibile con MCP.

### Competenze dell'agente

| Competenza | Descrizione |
|-------|-------------|
| `best-practices` | Configurazione dell'SDK, ambienti, chiavi API e architettura canonica da checkout a webhook |
| `framework-adapters` | Route handler ufficiali di `@dodopayments/*` per Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun e Convex |
| `testing-and-go-live` | Modalità test, metodi di pagamento di test, test dei webhook e checklist per il lancio in produzione |
| `checkout-integration` | Checkout Sessions, link di pagamento e checkout overlay o inline |
| `subscription-integration` | Ciclo di vita degli abbonamenti, periodi di prova, modifiche ai piani, prorata e addebiti su richiesta |
| `mobile-checkout` | Checkout in-app per React Native, Flutter, iOS e Android |
| `webhook-integration` | Ricezione e verifica dei webhook utilizzando la specifica Standard Webhooks |
| `credit-based-billing` | Entitlement dei crediti, saldi, ledger, rollover, overage e detrazione basata sui meter |
| `usage-based-billing` | Meter, acquisizione degli eventi, aggregazione e prezzi per unità |
| `license-keys` | Attivazione e convalida delle chiavi di licenza e gestione delle istanze |
| `product-catalog-management` | Prodotti, prezzi, add-on, raccolte, immagini e distribuzione di prodotti digitali |
| `discounts-and-promotions` | Codici sconto, regole di idoneità, combinazione degli sconti e limiti per ciclo di abbonamento |
| `localized-pricing` | Prezzi localizzati, Adaptive Currency e parità del potere d'acquisto |
| `customer-management` | Clienti, portale self-service, metodi di pagamento salvati e wallet |
| `refunds-and-disputes` | Emissione di rimborsi, gestione di contestazioni e chargeback e riconciliazione degli accessi |
| `billing-sdk` | Componenti React di BillingSDK per tabelle dei prezzi e interfaccia di fatturazione |
| `better-auth-integration` | Il plugin `@dodopayments/better-auth` per la sincronizzazione dei clienti, il checkout e l'accesso al portale |

Le competenze si caricano automaticamente — il tuo agente sceglie quella giusta quando rileva un compito pertinente. Vedi la [documentazione delle competenze dell'agente](/developer-resources/agent-skills) per l'elenco completo e l'installazione individuale.

### Prova questo prompt prima

Una volta che il plugin è attivo, prova:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Il tuo agente caricherà la competenza `webhook-integration`, userà il server MCP `dodo-knowledge` per ottenere le forme di payload più recenti e scriverà un gestore con verifica della firma seguendo la specifica Standard Webhooks.

## Sicurezza e migliori pratiche

<Warning>
**Non commettere mai chiavi API di produzione.** Usa [modalità test](/miscellaneous/test-mode-vs-live-mode) durante lo sviluppo. Il plugin Agent utilizza di default OAuth del browser — passa alle chiavi API locali solo se il tuo flusso di lavoro lo richiede.
</Warning>

- **Usa prima la modalità test.** Sandbox la tua integrazione con chiavi `dodo_test_...` prima di andare live. Vedi [Modalità test vs Modalità live](/miscellaneous/test-mode-vs-live-mode).
- **OAuth è il default.** Il plugin Agent si autentica tramite OAuth del browser (nessun segreto locale). Usa la modalità chiave API solo se necessario — vedi la sezione Configura sotto.
- **Rivedi il codice generato dall'agente.** Verifica sempre che i gestori dei webhook includano la verifica della firma secondo la [standard Webhooks spec](https://standardwebhooks.com/).

## Configurare con una chiave API

Di default, il plugin Agent utilizza il server remoto MCP con OAuth del browser — nessuna credenziale locale necessaria. Se il tuo flusso di lavoro richiede una chiave API locale (es., ambienti CI, server senza testa), puoi passare alla modalità stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Apri `/plugins` in Claude Code, seleziona **Dodo Payments** e scegli **Configura opzioni**. Compila:

- `dodo_api_key` — la tua chiave `dodo_test_...` o `dodo_live_...`
- `dodo_webhook_key` — il tuo segreto di firma del webhook
- `dodo_environment` — `test_mode` o `live_mode`

Poi modifica `.mcp.json` per puntare `dodopayments-api` al server stdio locale:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Esegui `/reload-plugins` per applicare le modifiche alla tua sessione corrente.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Dichiara `dodopayments-api` da solo in `opencode.json` — la tua voce prevarrà sul server remoto predefinito del plugin:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Riavvia OpenCode per applicare.
</Accordion>
</AccordionGroup>
