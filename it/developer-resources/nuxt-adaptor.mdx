## Panoramica

<Info>
Questa guida spiega come integrare Dodo Payments nella tua applicazione Nuxt utilizzando il modulo Nuxt ufficiale. Imparerai a configurare checkout, customer portal e route API per i webhook, oltre a gestire in modo sicuro le variabili d'ambiente.
</Info>

## Installazione

<Steps>
<Step title="Install the Nuxt module">
Esegui il comando seguente nella directory principale del progetto:

```bash
npm install @dodopayments/nuxt
```

</Step>
<Step title="Register the module in nuxt.config.ts">
Aggiungi <code>@dodopayments/nuxt</code> al tuo array <code>modules</code> e configuralo:

```typescript nuxt.config.ts expandable
export default defineNuxtConfig({
  modules: ["@dodopayments/nuxt"],
  devtools: { enabled: true },
  compatibilityDate: "2025-02-25",
  runtimeConfig: {
    private: {
      bearerToken: process.env.NUXT_PRIVATE_BEARER_TOKEN,
      webhookKey: process.env.NUXT_PRIVATE_WEBHOOK_KEY,
      environment: process.env.NUXT_PRIVATE_ENVIRONMENT,
      returnUrl: process.env.NUXT_PRIVATE_RETURNURL
    },
  }
});
```

</Step>
</Steps>

<Warning>
Non eseguire mai il commit del file <code>.env</code> o dei secret nel controllo versione.
</Warning>

## Esempi di gestori di route API

<Info>
Tutte le integrazioni di Dodo Payments in Nuxt vengono gestite tramite route server nella directory <code>server/routes/api/</code>.
</Info>

<Tab title="Checkout API Route">
<Info>
Utilizza questo gestore per integrare il checkout di Dodo Payments nella tua app Nuxt. Supporta i flussi di pagamento statici (GET), dinamici (POST) e basati su sessione (POST).
</Info>

## Gestore della route checkout

<Info>
Dodo Payments supporta tre tipi di flussi di pagamento per integrare i pagamenti nel tuo sito web; questo adaptor supporta tutti i tipi di flussi di pagamento.
</Info>

- **Link di pagamento statici:** URL condivisibili istantaneamente per raccogliere pagamenti rapidamente e senza codice.
- **Link di pagamento dinamici:** genera programmaticamente link di pagamento con dettagli personalizzati utilizzando l'API o gli SDK.
- **Sessioni checkout:** crea esperienze checkout sicure e personalizzabili con carrelli di prodotti e dati dei clienti preconfigurati.

Il checkout statico restituisce una risposta JSON con l'URL del checkout:


<Accordion title="Dynamic Checkout (POST)">
- Invia i parametri come corpo JSON in una richiesta POST.
- Supporta pagamenti una tantum e ricorrenti.
- Per un elenco completo dei campi del corpo POST supportati, consulta:
  - [Corpo della richiesta per un prodotto con pagamento una tantum](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corpo della richiesta per un prodotto in abbonamento](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Formato della risposta
Il checkout dinamico restituisce una risposta JSON con l'URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Le sessioni checkout offrono un'esperienza checkout ospitata più sicura, che gestisce il flusso completo dei pagamenti sia per gli acquisti una tantum sia per gli abbonamenti, con pieno controllo sulla personalizzazione.

Consulta la [Guida all'integrazione delle sessioni checkout](https://docs.dodopayments.com/developer-resources/checkout-session) per maggiori dettagli e un elenco completo dei campi supportati.

### Formato della risposta
Le sessioni checkout restituiscono una risposta JSON con l'URL del checkout:

```json

  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

## Gestore della route webhook

- **Metodo:** sono supportate solo le richieste POST. Gli altri metodi restituiscono 405.
- **Verifica della firma:** verifica la firma del webhook utilizzando <code>webhookKey</code>. Restituisce 401 se la verifica non riesce.
- **Validazione del payload:** viene eseguita con Zod. Restituisce 400 per payload non validi.
- **Gestione degli errori:**
  - 401: firma non valida
  - 400: payload non valido
  - 500: errore interno durante la verifica
- **Instradamento degli eventi:** chiama il gestore dell'evento appropriato in base al tipo di payload.
