Gestisci le risorse di Dodo Payments, esegui query basate sull'AI sul tuo account, crea sessioni di checkout e testa i webhook, tutto dal terminale. La CLI include una TUI interattiva, un assistente AI integrato basato su MCP e il testing offline dei webhook.

## Funzionalità

- **TUI interattiva** — avvia `dodo` senza argomenti per aprire l'intera interfaccia interattiva con tavolozza dei comandi, cronologia e notifiche in tempo reale.
- **Assistente AI integrato** — poni domande o esegui azioni in inglese naturale con `/ai`. Non richiede configurazione aggiuntiva ed esegue `dodopayments-mcp` localmente.
- **Sicura per impostazione predefinita** — le API key vengono archiviate nel gestore dei segreti del tuo sistema operativo (Portachiavi su macOS, Credential Vault su Windows, libsecret su Linux). Nessuna configurazione in testo semplice sul disco.
- **Aggiornamento automatico** — la CLI verifica la disponibilità di nuove versioni all'avvio e mostra una notifica nell'app. Esegui `/update` per effettuare l'aggiornamento in loco.
- **Strumenti per i webhook** — ascolta i webhook in tempo reale o attiva payload offline per lo sviluppo locale.

## Installazione

Installa la CLI con una sola riga su macOS o Linux:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### Installa con npm o Bun

Se hai già Node o Bun, le installazioni tramite package manager scaricano sempre la versione più recente:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Installazione manuale (non richiede Node / Bun)

Se preferisci non inviare uno script remoto tramite pipe a `sh`, scarica tu stesso il binario.

<Steps>
<Step title="Download the binary">
  Scarica il binario per la tua piattaforma dall'ultima [GitHub Release](https://github.com/dodopayments/dodopayments-cli/releases).

  | Piattaforma | Binario |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  Su Windows, spostare in `C:\Windows\System32` richiede privilegi di amministratore.
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  Ogni release pubblica un `SHA256SUMS.txt`. Verifica il download con:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## Autenticazione

Prima di utilizzare i comandi autenticati, accedi con la tua API key:

```bash
dodo login
```

Oppure, dall'interno della TUI interattiva:

```text
/login
```

Il flusso di accesso:

1. Aprirà il browser alla pagina API Keys di Dodo Payments.
2. Ti chiederà di incollare la tua API Key.
3. Ti chiederà di selezionare un ambiente — **Test Mode** o **Live Mode**.
4. Archivierà le credenziali nel gestore dei segreti del sistema operativo (Portachiavi su macOS, Credential Vault su Windows, libsecret su Linux).

<Info>
Poiché le credenziali sono archiviate nel gestore dei segreti del sistema operativo, la prima volta che la CLI legge o scrive le credenziali potrebbe essere richiesta la **password del dispositivo**. Se stai effettuando l'upgrade da una versione precedente, qualsiasi API key esistente in testo semplice verrà **migrata automaticamente nel gestore dei segreti e il file legacy verrà eliminato**.
</Info>

### Cambiare modalità e disconnettersi

Puoi mantenere contemporaneamente autenticata una chiave **Test Mode** e una chiave **Live Mode**. Per cancellare le credenziali:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

Il flusso di disconnessione ti consente di scegliere indipendentemente tra **All accounts**, **Test Mode** o **Live Mode**.

## Utilizzo

Puoi utilizzare la CLI in due modalità.

### 1. TUI interattiva (consigliata)

Esegui `dodo` senza argomenti per avviare l'intera interfaccia interattiva:

```bash
dodo
```

Digita `/` per aprire la tavolozza dei comandi oppure inizia semplicemente a digitare: tutto ciò che non è un comando slash viene inviato all'assistente AI.

| Comando | Descrizione |
|---------|-------------|
| `/help` | Mostra il riferimento dei comandi |
| `/update` | Verifica e installa un aggiornamento della CLI |
| `/login` | Esegue l'autenticazione con una API key |
| `/logout` | Disconnette da uno o tutti gli ambienti |
| `/clear` | Cancella la schermata della TUI |
| `/exit` | Esce dalla TUI (anche digitando `exit` o premendo due volte `Esc`) |

### 2. Sottocomandi diretti

Esegui i comandi direttamente senza accedere alla TUI:

```bash
dodo <category> <sub-command> [args...]
```

Ad esempio:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

Le tabelle di riferimento seguenti mostrano tutti i comandi. Nella TUI, anteponi `/`; in modalità diretta, rimuovi `/`.

## Assistente AI

Poni domande o esegui azioni in linguaggio naturale. L'assistente utilizza `dodopayments-mcp` in esecuzione locale: non richiede configurazione aggiuntiva né un flusso OAuth e il traffico AI non lascia la tua macchina, salvo per comunicare con il provider del modello.

| Comando | Descrizione |
|---------|-------------|
| `/ai <query>` | Poni una domanda all'assistente AI o impartiscigli un'istruzione |
| _(qualsiasi testo non slash)_ | Viene inviato per impostazione predefinita all'assistente AI quando ti trovi nella TUI |

Esempi:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
L'assistente rispetta il tuo ambiente attivo (Test / Live), quindi opera solo sui dati dell'ambiente a cui hai attualmente effettuato l'accesso.
</Tip>

## Scaffolding del progetto

`dodo init` crea le route di fatturazione di Dodo Payments direttamente in un progetto esistente. Genera i file route standard, installa il pacchetto adapter `@dodopayments/*` corrispondente e scrive in modo sicuro le variabili d'ambiente `DODO_PAYMENTS_*` nel tuo `.env` (aggiunge solo le variabili che non sono già presenti). Il comando viene eseguito **senza effettuare l'accesso**.

```bash
dodo init <framework>
```

| Scaffolding | Descrizione |
|----------|-------------|
| `dodo init nextjs` | Crea le route di fatturazione Next.js App Router (checkout, Customer Portal e gestori webhook) utilizzando `@dodopayments/nextjs` |
| `dodo init express` | Crea le route di fatturazione per un server Express utilizzando `@dodopayments/express` |
| `dodo init better-auth` | Crea una configurazione del plugin Better-Auth utilizzando `@dodopayments/better-auth` |

Per lo scaffolding Better-Auth puoi passare un elenco separato da virgole dei plugin da generare (per impostazione predefinita, tutti): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
Lo scaffolder rileva automaticamente una directory `src/` e adatta di conseguenza i percorsi di output; rileva inoltre automaticamente il tuo package manager (`bun`, `pnpm`, `yarn` o `npm`) per eseguire il comando di installazione corretto.
</Info>

## Webhook

La CLI include due potenti strumenti per testare i webhook durante lo sviluppo: un **listener** che inoltra i webhook di test in tempo reale al tuo server locale e un **trigger** che invia payload webhook simulati a qualsiasi endpoint.

| Comando | Descrizione |
|---------|-------------|
| `dodo wh listen` | Ascolta i webhook in tempo reale e li inoltra al server di sviluppo locale |
| `dodo wh trigger` | Attiva interattivamente un evento webhook di test, anche senza aver effettuato l'accesso |

### Ascoltare i webhook

Inoltra i webhook da Dodo Payments direttamente al tuo server di sviluppo locale in tempo reale.

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  Fornisci l'URL locale in cui vuoi ricevere i webhook (ad es. `http://localhost:3000/webhook`).
</Step>

<Step title="Automatic setup">
  La CLI crea automaticamente un endpoint webhook sul tuo account Dodo Payments, se non ne esiste già uno, quindi apre una connessione WebSocket per ricevere gli eventi in tempo reale.
</Step>

<Step title="Receive and forward">
  Quando si attiva un evento webhook (a seguito di un pagamento di test, di una modifica dell'abbonamento e così via), la CLI lo riceve, registra il tipo di evento e inoltra la richiesta completa, con intestazioni e corpo, al tuo endpoint locale. La risposta del tuo endpoint viene registrata e inviata a sua volta.
</Step>
</Steps>

<Warning>
`dodo wh listen` richiede una API key in **Test Mode**. Le chiavi in Live Mode non sono supportate dal flusso di ascolto.
</Warning>

<Tip>
Il listener conserva le intestazioni webhook originali (`webhook-id`, `webhook-signature`, `webhook-timestamp`) quando inoltra la richiesta al tuo endpoint locale, così puoi testare la logica di verifica della firma.
</Tip>

### Attivare webhook di test

Invia payload webhook simulati a qualsiasi endpoint per eseguire test rapidi senza dover creare transazioni reali.

```bash
dodo wh trigger
```

Il flusso `/wh trigger` ti guida attraverso:

1. Impostazione di un **URL dell'endpoint** di destinazione
2. Selezione di un **evento** specifico da attivare tramite un menu interattivo

<Info>
`dodo wh trigger` **non richiede l'accesso**. Funziona come generatore locale/offline di payload webhook.
</Info>

<Warning>
Gli eventi attivati **non sono firmati**. Durante i test, disabilita la verifica della firma webhook sul tuo endpoint: ad esempio, usa `unsafe_unwrap()` invece di `unwrap()` nel gestore webhook **solo durante i test**.
</Warning>

### Eventi webhook supportati

| Categoria | Eventi |
|----------|--------|
| **Subscription** | `active`, `updated`, `on_hold`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired` |
| **Payment** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Refund** | `succeeded`, `failed` |
| **Dispute** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **License** | `created` |

### Variabili d'ambiente

| Variabile | Descrizione |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Sostituisce l'URL predefinito del server relay webhook utilizzato da `dodo wh listen` |
