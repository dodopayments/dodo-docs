## Installazione

<Steps>
<Step title="Install the package">
Esegui il comando seguente nella directory principale del progetto:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
Crea un file <code>.env</code> nella directory principale del progetto:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
Non eseguire mai il commit del file <code>.env</code> o dei segreti nel controllo versione.
</Warning>
</Step>
</Steps>

## Esempi di route handler

<Info>
Tutti gli esempi presuppongono l'uso del server nativo di Bun con <code>Bun.serve()</code>.
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  Usa questo handler per integrare il checkout di Dodo Payments nel tuo server Bun. Supporta i flussi di pagamento statici (GET), dinamici (POST) e di sessione (POST).
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>
  <CodeGroup>

## Route handler per il checkout

<Info>
Dodo Payments supporta tre tipi di flussi di pagamento per integrare i pagamenti nel tuo sito web; questo adattatore supporta tutti i tipi di flussi di pagamento.
</Info>

- **Link di pagamento statici:** URL condivisibili istantaneamente per raccogliere pagamenti in modo rapido e senza codice.
- **Link di pagamento dinamici:** Genera programmaticamente link di pagamento con dettagli personalizzati usando l'API o gli SDK.
- **Sessioni di checkout:** Crea esperienze di checkout sicure e personalizzabili con carrelli di prodotti e dettagli cliente preconfigurati.

<AccordionGroup>
<Accordion title="Static Checkout (GET)">

### Parametri di query supportati
<ParamField query="productId" type="string" required>
Identificatore del prodotto (ad es., <code>?productId=pdt_xxx</code>).
</ParamField>

</ParamField>

</ParamField>

</ParamField>
<ParamField query="addressLine" type="string">

</ParamField>
<ParamField query="city" type="string">
Città del cliente.
</ParamField>
<ParamField query="state" type="string">
Stato o provincia del cliente.
</ParamField>
<ParamField query="zipCode" type="string">
CAP o codice postale del cliente.
</ParamField>
<ParamField query="disableFullName" type="boolean">
Disabilita il campo nome e cognome.
</ParamField>
<ParamField query="disableFirstName" type="boolean">

</ParamField>
<ParamField query="disableLastName" type="boolean">

</ParamField>
<ParamField query="disableEmail" type="boolean">

</ParamField>
<ParamField query="disableCountry" type="boolean">
Disabilita il campo paese.
</ParamField>
<ParamField query="disableAddressLine" type="boolean">
Disabilita la riga dell'indirizzo.
</ParamField>
<ParamField query="disableCity" type="boolean">
Disabilita il campo città.
</ParamField>
<ParamField query="disableState" type="boolean">
Disabilita il campo stato.
</ParamField>
<ParamField query="disableZipCode" type="boolean">
Disabilita il campo CAP.
</ParamField>
<ParamField query="paymentCurrency" type="string">
Specifica la valuta del pagamento (ad es., <code>USD</code>).
</ParamField>
<ParamField query="showCurrencySelector" type="boolean">
Mostra il selettore della valuta.
</ParamField>
<ParamField query="paymentAmount" type="number">
Fissa l'importo addebitato, espresso in unità principali della valuta (ad es., <code>12.5</code> per $12.50). Solo per i prodotti Pay What You Want; viene ignorato se inferiore al prezzo minimo del prodotto.
</ParamField>
<ParamField query="showDiscounts" type="boolean">
Mostra i campi dello sconto.
</ParamField>
<ParamField query="metadata_*" type="string">
Qualsiasi parametro di query che inizi con <code>metadata_</code> verrà passato come metadato.
</ParamField>

<Warning>
Se manca <code>productId</code>, l'handler restituisce una risposta 400. Anche i parametri di query non validi restituiscono una risposta 400.
</Warning>

### Formato della risposta
Il checkout statico restituisce una risposta JSON con l'URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Invia i parametri come corpo JSON in una richiesta POST.
- Supporta sia i pagamenti una tantum sia quelli ricorrenti.
- Per un elenco completo dei campi del corpo POST supportati, consulta:
  - [Corpo della richiesta per un prodotto con pagamento una tantum](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corpo della richiesta per un prodotto in abbonamento](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Formato della risposta
Il checkout dinamico restituisce una risposta JSON con l'URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Le sessioni di checkout offrono un'esperienza di checkout ospitata più sicura, che gestisce l'intero flusso di pagamento sia per gli acquisti una tantum sia per gli abbonamenti, con pieno controllo sulla personalizzazione.

Consulta la [guida all'integrazione delle sessioni di checkout](https://docs.dodopayments.com/developer-resources/checkout-session) per maggiori dettagli e un elenco completo dei campi supportati.

### Formato della risposta
Le sessioni di checkout restituiscono una risposta JSON con l'URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>
</AccordionGroup>

## Customer Portal Route Handler

Il Route Handler Customer Portal consente di integrare facilmente il portale clienti di Dodo Payments nella tua applicazione server Bun.

### Parametri di query
<ParamField query="customer_id" type="string" required>
L'ID cliente per la sessione del portale (ad es. <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Se impostato su <code>true</code>, invia al cliente un'email con il link al portale.
</ParamField>

<Warning>
Restituisce 400 se manca <code>customer_id</code>.
</Warning>

## Route handler webhook

- **Metodo:** Sono supportate solo le richieste POST. Gli altri metodi restituiscono 405.
- **Verifica della firma:** Verifica la firma del webhook usando <code>webhookKey</code>. Restituisce 401 se la verifica non riesce.
- **Convalida del payload:** Convalidato con Zod. Restituisce 400 per i payload non validi.
- **Gestione degli errori:**
  - 401: Firma non valida
  - 400: Payload non valido
  - 500: Errore interno durante la verifica
- **Instradamento degli eventi:** Chiama l'handler dell'evento appropriato in base al tipo di payload.
