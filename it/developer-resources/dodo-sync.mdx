Dodo Payments offre una funzionalità integrata di sincronizzazione del database che sincronizza automaticamente i tuoi dati di pagamento con il tuo database. Puoi sincronizzare **pagamenti**, **clienti**, **abbonamenti** e **licenze** per mantenere una copia locale dei tuoi dati destinata ad analisi, report o integrazioni con altri sistemi.

<Info>
**Implementazione**: disponibile tramite [pacchetto npm](https://www.npmjs.com/package/dodo-sync) | **Codice sorgente**: [GitHub](https://github.com/dodopayments/dodo-sync)
</Info>

## Cosa puoi sincronizzare?

La nostra funzionalità di sincronizzazione del database supporta la sincronizzazione delle seguenti entità Dodo Payments nel tuo database:

<CardGroup cols={2}>
  <Card title="Payments" icon="credit-card">
    Sincronizza tutte le transazioni di pagamento, inclusi i pagamenti una tantum, i rimborsi e gli aggiornamenti dello stato dei pagamenti.
  </Card>
  <Card title="Customers" icon="users">
    Mantieni sincronizzati i dati dei tuoi clienti, inclusi profili, informazioni di contatto e metadati.
  </Card>
  <Card title="Subscriptions" icon="repeat">
    Sincronizza i dati degli abbonamenti, inclusi gli abbonamenti attivi, i cicli di fatturazione e le modifiche allo stato degli abbonamenti.
  </Card>
  <Card title="Licenses" icon="key">
    Sincronizza le informazioni sulle licenze, incluse le chiavi di licenza, le attivazioni e gli aggiornamenti dello stato delle licenze.
  </Card>
</CardGroup>

Puoi sincronizzare qualsiasi combinazione di queste entità specificandole nel parametro `scopes`. Tutte le operazioni di sincronizzazione sono incrementali e trasferiscono solo i record nuovi o aggiornati, per prestazioni ottimali.

## Supporto dei database

Attualmente supportiamo **MongoDB**, **PostgreSQL**, **MySQL** e **ClickHouse**.

Stiamo lavorando attivamente per estendere il supporto a:
- **Database**: Snowflake e altri.
- **Pipeline**: pipeline ETL, sincronizzazione in tempo reale.

<Tip>
Continuiamo ad ampliare il supporto dei database. Se desideri contribuire a una nuova integrazione per database, invia una Pull Request al nostro [repository GitHub](https://github.com/dodopayments/dodo-sync).
</Tip>

## Per iniziare

Puoi utilizzare la nostra funzionalità di sincronizzazione del database tramite la **CLI** o a livello programmatico nel tuo **codice**. Entrambi i metodi offrono le stesse funzionalità: scegli quello più adatto al tuo flusso di lavoro.

### Utilizzo della CLI

Lo strumento CLI offre un modo rapido per configurare ed eseguire la sincronizzazione del database. Installalo globalmente per utilizzarlo da qualsiasi posizione nel terminale:

<CodeGroup>

```bash npm
npm install -g dodo-sync
```

```bash bun
bun add -g dodo-sync
```

</CodeGroup>

#### Esecuzione della CLI

La CLI supporta due modalità: **Modalità interattiva** per una configurazione guidata e **Modalità manuale** per la configurazione diretta.

**Modalità interattiva**: esegui semplicemente il comando senza argomenti per avviare la procedura guidata interattiva.

```bash
dodo-sync
```

**Modalità manuale**: passa direttamente gli argomenti per ignorare la procedura guidata.

```bash
dodo-sync -i [interval] -d [database] -u [database_uri] --scopes [scopes] --api-key [api_key] --env [environment]
```

**Esempi:**

```bash
# MongoDB
dodo-sync -i 600 -d mongodb -u mongodb://mymongodb.url --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# PostgreSQL
dodo-sync -i 600 -d postgres -u postgresql://user:password@localhost:5432/mydb --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# MySQL
dodo-sync -i 600 -d mysql -u mysql://user:password@localhost:3306/mydb --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# ClickHouse
dodo-sync -i 600 -d clickhouse -u http://localhost:8123 --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode
```

#### Argomenti della CLI

<ParamField path="--interval" type="number" alias="-i">
Intervallo di sincronizzazione in secondi. Determina la frequenza di esecuzione dell'operazione di sincronizzazione. Se non viene fornito, la sincronizzazione verrà eseguita una sola volta e terminerà.
</ParamField>

<ParamField path="--database" type="string" alias="-d" required>
Tipo di database da utilizzare. Valori supportati: `"mongodb"`, `"postgres"`, `"mysql"` o `"clickhouse"`.
</ParamField>

<ParamField path="--database-uri" type="string" alias="-u" required>
URI di connessione al database:
- **MongoDB**: `mongodb://localhost:27017` o `mongodb+srv://user:pass@cluster.mongodb.net/`
- **PostgreSQL**: `postgresql://user:password@localhost:5432/mydb`
- **MySQL**: `mysql://user:password@localhost:3306/mydb`
- **ClickHouse**: `http://localhost:8123`
</ParamField>

<ParamField path="--scopes" type="string" required>
Elenco separato da virgole delle entità di dati da sincronizzare. Ambiti disponibili: `licences`, `payments`, `customers`, `subscriptions`. Esempio: `"payments,customers"`.
</ParamField>

<ParamField path="--api-key" type="string" required>
La tua chiave API Dodo Payments. Deve iniziare con `dp_live_` per la modalità live o con `dp_test_` per la modalità di test.
</ParamField>

<ParamField path="--env" type="string" required>
Target dell'ambiente. Deve essere `"live_mode"` o `"test_mode"`. Determina da quale ambiente Dodo Payments sincronizzare.
</ParamField>

<ParamField path="--rate-limit" type="number" alias="--rl">
Limite di richieste al secondo. Controlla la velocità con cui il motore di sincronizzazione effettua le richieste API per evitare di sovraccaricare l'API Dodo Payments.
</ParamField>

### Utilizzo nel codice

Per il controllo a livello programmatico, integra direttamente la funzionalità di sincronizzazione nella tua applicazione. Installala come dipendenza nel tuo progetto:

<CodeGroup>

```bash npm
npm install dodo-sync
```

```bash bun
bun add dodo-sync
```

</CodeGroup>

#### Sincronizzazione automatica (basata su intervallo)

Utilizza la sincronizzazione automatica quando desideri eseguire la sincronizzazione continuamente a intervalli regolari:

```typescript
import { DodoSync } from 'dodo-sync';

const syncDodoPayments = new DodoSync({
  interval: 60, // Sync every 60 seconds
  database: 'mongodb',
  databaseURI: process.env.MONGODB_URI, // e.g., 'mongodb://localhost:27017'
  scopes: ['licences', 'payments', 'customers', 'subscriptions'],
  dodoPaymentsOptions: {
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode' // or 'live_mode'
  }
});

// Initialize connection
await syncDodoPayments.init();

// Start the sync loop
syncDodoPayments.start();
```

<Tip>
L'opzione `interval` è obbligatoria quando si utilizza `.start()` per la sincronizzazione automatica. La sincronizzazione verrà eseguita continuamente all'intervallo specificato finché il processo non verrà arrestato.
</Tip>

#### Sincronizzazione manuale

Utilizza la sincronizzazione manuale quando desideri attivare le operazioni di sincronizzazione su richiesta, ad esempio da un cron job o da un endpoint API:

```typescript
import { DodoSync } from 'dodo-sync';

const syncDodoPayments = new DodoSync({
  database: 'mongodb',
  databaseURI: process.env.MONGODB_URI,
  scopes: ['licences', 'payments', 'customers', 'subscriptions'],
  dodoPaymentsOptions: {
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode'
  }
});

// Initialize connection
await syncDodoPayments.init();

// Trigger a single sync operation
await syncDodoPayments.run();
```

<Tip>
Quando utilizzi la sincronizzazione manuale, l'opzione `interval` non è obbligatoria. Puoi chiamare `.run()` ogni volta che devi eseguire un'operazione di sincronizzazione.
</Tip>

#### Opzioni del costruttore

<ParamField body="database" type="string" required>
Nome del database da utilizzare. Valori supportati: `"mongodb"`, `"postgres"`, `"mysql"` o `"clickhouse"`.

<ParamField body="databaseURI" type="string" required>
Stringa di connessione al database:

## Informazioni importanti

<Warning>
**MongoDB**: un database denominato `dodopayments_sync` verrà creato automaticamente sul server del database. Tutti i dati sincronizzati verranno archiviati al suo interno. Il nome di questo database è attualmente fisso e non può essere modificato.

**PostgreSQL**: le tabelle (`Subscriptions`, `Payments`, `Licenses`, `Customers`) verranno create nel database specificato nell'URI di connessione. I dati vengono archiviati come JSONB.

**MySQL**: le tabelle (`Subscriptions`, `Payments`, `Licenses`, `Customers`) verranno create nel database specificato nell'URI di connessione. I dati vengono archiviati come JSON.

**ClickHouse**: le tabelle (`Subscriptions`, `Payments`, `Licenses`, `Customers`) verranno create utilizzando il motore ReplacingMergeTree. Durante le query, utilizza la parola chiave `FINAL` per garantire risultati deduplicati.
</Warning>

<Info>
Il motore di sincronizzazione tiene traccia delle modifiche e sincronizza solo i record nuovi o aggiornati, rendendo efficienti le sincronizzazioni successive anche con dataset di grandi dimensioni.
</Info>
