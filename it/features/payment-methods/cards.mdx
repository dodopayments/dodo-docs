I pagamenti con carta sono alla base dei pagamenti online: sono accettati in tutto il mondo e considerati affidabili dai clienti. Dodo Payments supporta tutti i principali circuiti di carte, con protezione antifrode integrata e conformità PCI.

## Configurazione

Usa questi valori in `allowed_payment_method_types`:

| Tipo | Descrizione |
| :--- | :---------- |
| `credit` | Tutte le carte di credito |
| `debit` | Tutte le carte di debito |

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Tip>
Includi sia `credit` sia `debit`, a meno che tu non abbia un motivo specifico per escluderne uno. Molti clienti preferiscono le carte di debito, che spesso hanno commissioni più basse.
</Tip>

## Autenticazione 3D Secure

3D Secure (3DS) aggiunge un livello di autenticazione che riduce le frodi e i chargeback verificando l'identità del titolare della carta.

### Quando viene attivato 3DS

3DS viene attivato automaticamente quando:
- È richiesto dal circuito della carta
- È richiesto dalle normative regionali (ad esempio, PSD2 in Europa)
- La transazione viene contrassegnata come ad alto rischio

### Forzare 3DS

Puoi richiedere 3DS per tutte le transazioni:

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  force_3ds: true,
  return_url: 'https://example.com/success'
});
```

<Note>
L'attivazione di 3DS per tutte le transazioni riduce le frodi, ma può diminuire leggermente la conversione, poiché alcuni clienti abbandonano il pagamento durante l'autenticazione.
</Note>

### Gestione degli errori di autenticazione

Quando un pagamento richiede l'autenticazione 3DS, passa attraverso stati intermedi prima di essere completato o rifiutato:

| Stato | Significato | Cosa fare |
|--------|---------|------------|
| `requires_customer_action` | Il cliente deve completare una verifica 3DS | Fai completare al cliente l'autenticazione durante il checkout |
| `requires_payment_method` | Il cliente non ha mai fornito un metodo di pagamento (non ha inserito i dati o ha abbandonato la richiesta) — di solito si tratta di un abbandono, non di un rifiuto | Ricontatta il cliente per completare il checkout; consulta [Recupero dei carrelli abbandonati](/features/recovery/abandoned-cart-recovery) |

Se l'autenticazione non viene completata, il pagamento non va a buon fine con uno di questi codici di rifiuto:

- `AUTHENTICATION_FAILURE` — il cliente non ha potuto essere autenticato.
- `AUTHENTICATION_REQUIRED` — l'autenticazione è richiesta ma non è stata eseguita.
- `AUTHENTICATION_TIMEOUT` — il cliente non ha risposto in tempo.

Consulta il riferimento [Errori delle transazioni](/api-reference/transaction-failures) per l'azione consigliata per ciascun caso.

#### Durante il checkout e al rinnovo

- **Durante il checkout (cliente presente):** Il cliente è presente, quindi la verifica 3DS viene mostrata durante il checkout. Se non va a buon fine, chiedigli di riprovare o di usare un'altra carta.
- **Al rinnovo dell'abbonamento (cliente non presente):** Il cliente non è presente, quindi una verifica 3DS non può essere mostrata in tempo reale. Se un rinnovo richiede l'autenticazione, l'abbonamento passa a `on_hold`. Recuperalo chiedendo al cliente di tornare e aggiornare il metodo di pagamento — consulta [Gestione degli errori di pagamento](/developer-resources/handle-payment-failures) e [Gestione dei mancati pagamenti degli abbonamenti](/features/recovery/subscription-dunning).

I clienti possono salvare le proprie carte per effettuare più rapidamente i checkout futuri.

### Abilitare le carte salvate

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  show_saved_payment_methods: true,
  customer: { customer_id: 'cus_existing_123' },
  return_url: 'https://example.com/success'
});
```

### Acquisti con un clic

```javascript
// Get customer's saved payment methods
const methods = await client.customers.retrievePaymentMethods('cus_123');

// Use saved card for instant checkout
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  payment_method_id: methods.items[0].payment_method_id,
  confirm: true,
  return_url: 'https://example.com/success'
});
```

## Best practice

<AccordionGroup>
<Accordion title="Accept all major networks">
Non limitare i tipi di carta se non è necessario. I clienti si aspettano di poter usare la propria carta preferita.
</Accordion>

<Accordion title="Display card logos">
Mostra i loghi Visa, Mastercard e Amex nel checkout per aumentare la fiducia.
</Accordion>

<Accordion title="Handle declines gracefully">
Mostra messaggi di errore chiari. Non mostrare ai clienti i codici di errore grezzi.
</Accordion>

<Accordion title="Enable saved cards for returning customers">
I metodi di pagamento salvati aumentano significativamente la conversione per gli acquisti ripetuti.
</Accordion>
</AccordionGroup>

## Risoluzione dei problemi

<AccordionGroup>
<Accordion title="Card declined">
**Cause:** Fondi insufficienti, carta scaduta, CVV errato, protezione antifrode della banca.

**Soluzione:** Chiedi al cliente di verificare i dati o di provare un'altra carta. Cerca il codice di rifiuto specifico `Error Code` e l'azione consigliata nel riferimento [Errori delle transazioni](/api-reference/transaction-failures), e consulta [Gestione degli errori di pagamento](/developer-resources/handle-payment-failures) per la gestione programmatica.
</Accordion>

<Accordion title="3DS authentication failed">
**Cause:** Il cliente ha abbandonato il pagamento, il sistema della banca non è disponibile, timeout.

**Soluzione:** Riprova o chiedi al cliente di contattare la propria banca. Consulta [Gestione degli errori di autenticazione](#handling-authentication-failures) per gli stati del pagamento e i codici di rifiuto coinvolti.
</Accordion>

<Accordion title="Card not supported">
**Cause:** La carta regionale non è supportata, restrizioni sulle carte prepagate.

**Soluzione:** Il cliente dovrebbe provare un'altra carta appartenente a un circuito principale.
</Accordion>
</AccordionGroup>
