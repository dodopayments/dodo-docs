<Info>
L'entitlement Discord aggiunge un cliente pagante al tuo server (e, facoltativamente, gli assegna un ruolo) nel momento in cui il suo abbonamento diventa attivo o il suo acquisto una tantum viene completato. Le cancellazioni, i rimborsi e le modifiche al piano revocano automaticamente il ruolo.
</Info>

## Cosa viene fornito

- Il cliente collega il proprio account Discord tramite un link OAuth nell'email di consegna o nel customer portal.
- Dopo l'autorizzazione, Dodo Payments lo aggiunge al tuo server (o trova la sua iscrizione esistente) e assegna il ruolo configurato.
- Se non hai scelto un ruolo specifico, viene concesso il solo accesso al server.

Questa integrazione è ideale per community a pagamento, vantaggi per i sostenitori e canali con accesso a livelli.

## Flusso del cliente

1. Il cliente completa il checkout.
2. Dodo Payments crea un grant con stato `Pending` e con un `oauth_url` che punta a Discord.
3. Il cliente riceve un'email con un pulsante "Join the Discord" (il link OAuth). Il link è visibile anche nel loro portale clienti.
4. Dopo che il cliente ha effettuato l'autorizzazione, il bot lo aggiunge al server e assegna il ruolo configurato. Il grant passa a `Delivered`.
5. Se l'abbonamento viene annullato, messo in pausa o scade, oppure se il merchant revoca manualmente, il bot rimuove il ruolo e il grant passa a `Revoked`.

<Tip>
Assicurati che il ruolo del bot Dodo Payments sia posizionato **sopra** il ruolo che concedi. Discord impedisce ai bot di assegnare ruoli classificati più in alto del proprio.
</Tip>

## Configurazione richiesta

| Campo | Obbligatorio | Descrizione |
|---|---|---|
| `guild_id` | Sì | L'ID del server Discord. Il selettore del dashboard lo compila automaticamente. |
| `role_id` | No | Il ruolo da assegnare al momento della consegna. Omettilo per concedere il solo accesso come membro del server. |

## Crea tramite API

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env['DODO_PAYMENTS_API_KEY'],
  environment: 'test_mode',
});

const entitlement = await client.entitlements.create({
  name: 'Patrons Discord Role',
  integration_type: 'discord',
  integration_config: {
    guild_id: '123456789012345678',
    role_id: '987654321098765432',
  },
});
```

```python Python theme={null}
client.entitlements.create(
    name="Patrons Discord Role",
    integration_type="discord",
    integration_config={
        "guild_id": "123456789012345678",
        "role_id": "987654321098765432",
    },
)
```

```go Go theme={null}
client.Entitlements.New(ctx, dodopayments.EntitlementNewParams{
  Name:            dodopayments.F("Patrons Discord Role"),
  IntegrationType: dodopayments.F(dodopayments.EntitlementIntegrationTypeDiscord),
  IntegrationConfig: dodopayments.F[dodopayments.IntegrationConfigUnionParam](
    dodopayments.IntegrationConfigDiscordConfigParam{
      GuildID: dodopayments.F("123456789012345678"),
      RoleID:  dodopayments.F("987654321098765432"),
    },
  ),
})
```

</CodeGroup>

## Webhook

Iscriviti agli [eventi webhook `entitlement_grant.*`](/developer-resources/webhooks/intents/entitlement-grant) per monitorare i grant Discord:

- `entitlement_grant.created` viene attivato con `status: "Pending"` e un `oauth_url` che il cliente deve autorizzare.
- `entitlement_grant.delivered` viene attivato una volta assegnato il ruolo.
- `entitlement_grant.revoked` viene attivato quando il ruolo viene rimosso.

## Risoluzione dei problemi

<AccordionGroup>
<Accordion title="Customer never sees the role assigned">
Il grant rimane in `Pending` finché il cliente non completa il flusso OAuth. Controlla l'elenco dei grant dell'entitlement e verifica se ha fatto clic sul link OAuth. Se necessario, invia nuovamente l'email di consegna.
</Accordion>

<Accordion title="Grant moves to failed with permission errors">
Assicurati che il bot Dodo Payments sia ancora nel server, disponga del permesso `Manage Roles` e sia posizionato sopra il ruolo assegnato. Salvare nuovamente l'entitlement esegue di nuovo la convalida.
</Accordion>

<Accordion title="Customer cancelled but still has the role">
Discord propaga immediatamente le rimozioni dei ruoli, ma il client Discord locale del cliente potrebbe utilizzare dati memorizzati nella cache. Il cliente dovrebbe riconnettersi o aggiornare la pagina; lo stato lato server è corretto.
</Accordion>
</AccordionGroup>
