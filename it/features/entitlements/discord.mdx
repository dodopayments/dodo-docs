<Info>
L'autorizzazione Discord aggiunge un cliente pagante al tuo server (e opzionalmente assegna loro un ruolo) nel momento in cui il loro abbonamento diventa attivo o il loro acquisto singolo viene effettuato. Cancellazioni, rimborsi e cambi di piano revocano automaticamente il ruolo.
</Info>

## Cosa viene consegnato

- Il cliente collega il proprio account Discord tramite un link OAuth nella loro email di consegna o portale clienti.
- Una volta autorizzati, Dodo Payments li aggiunge al tuo server (o trova la loro adesione esistente) e assegna il ruolo che hai configurato.
- Se non hai scelto un ruolo specifico, viene concessa solo l'adesione al server.

Questa integrazione è ideale per comunità a pagamento, vantaggi di sostenitori e canali di accesso a livelli.

## Flusso del cliente

1. Il cliente completa il checkout.
2. Dodo Payments crea una concessione in stato `pending` con un `oauth_url` che punta a Discord.
3. Il cliente riceve un'email con un pulsante "Unisciti a Discord" (il link OAuth). Il link è visibile anche nel loro portale clienti.
4. Dopo che il cliente autorizza, il bot li aggiunge al server e assegna il ruolo configurato. La concessione si sposta a `delivered`.
5. Se l'abbonamento viene cancellato, messo in pausa o scade, o se il commerciante revoca manualmente, il bot rimuove il ruolo e la concessione si sposta a `revoked`.

Assicurati che il ruolo del bot di Dodo Payments sia posizionato **sopra** il ruolo che concedi. Discord impedisce ai bot di assegnare ruoli classificati più in alto del loro.
</Tip>

## Configurazione richiesta

| Campo | Richiesto | Descrizione |
|---|---|---|
| `guild_id` | Sì | L'ID del server Discord. Il selettore del dashboard lo riempie per te. |
| `role_id` | No | Il ruolo da assegnare alla consegna. Ometti per l'accesso solo all'adesione al server. |

## Creazione tramite API

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env['DODO_PAYMENTS_API_KEY'],
  environment: 'test_mode',
});

const entitlement = await client.entitlements.create({
  name: 'Patrons Discord Role',
  integration_type: 'discord',
  integration_config: {
    guild_id: '123456789012345678',
    role_id: '987654321098765432',
  },
});
```

```python Python theme={null}
client.entitlements.create(
    name="Patrons Discord Role",
    integration_type="discord",
    integration_config={
        "guild_id": "123456789012345678",
        "role_id": "987654321098765432",
    },
)
```

```go Go theme={null}
client.Entitlements.New(ctx, dodopayments.EntitlementNewParams{

```

## Webhooks

Iscriviti agli [eventi webhook `entitlement_grant.*`](/developer-resources/webhooks/intents/entitlement-grant) per tenere traccia delle concessioni Discord:

- `entitlement_grant.created` si attiva con `status: "pending"` e un `oauth_url` per il cliente da autorizzare.
- `entitlement_grant.delivered` si attiva una volta assegnato il ruolo.
- `entitlement_grant.revoked` si attiva quando il ruolo viene rimosso.

## Risoluzione dei problemi

La concessione è in `pending` fino a quando il cliente non completa il flusso OAuth. Controlla l'elenco delle concessioni dell'autorizzazione e conferma se hanno cliccato sul link OAuth. Invia nuovamente l'email di consegna se necessario.
</Accordion>

Assicurati che il bot di Dodo Payments rimanga nel server, abbia il permesso `Manage Roles` e sia posizionato sopra il ruolo che viene assegnato. Salvare nuovamente l'autorizzazione esegue nuovamente la convalida.
</Accordion>

Discord propaga immediatamente la rimozione dei ruoli, ma il client Discord locale del cliente potrebbe memorizzare nella cache. Dovrebbero riconnettersi o aggiornare; lo stato del server è corretto.
</Accordion>
</AccordionGroup>
