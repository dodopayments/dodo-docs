## Che cos'è la fatturazione ibrida?

La fatturazione ibrida combina più dimensioni di prezzo in un'unica offerta di prodotto. Invece di scegliere tra abbonamenti a tariffa fissa O prezzi basati sull'utilizzo, utilizzi entrambi insieme.

### Perché usare la fatturazione ibrida?

| Obiettivo aziendale | Soluzione ibrida |
|--------------|-----------------|
| Ricavi prevedibili + potenziale di crescita | Abbonamento base + eccedenza di utilizzo |
| Prezzi per team scalabili | Per posto + componenti aggiuntivi |
| Acquisire clienti ed espandere in seguito | Commissione base ridotta + addebiti in base al consumo |
| Flessibilità aziendale | Spesa impegnata + addebiti on-demand |
| Prezzi equi per utilizzo variabile | Quantità inclusa + pagamento a consumo |

### Modelli ibridi comuni

| Modello | Descrizione | Esempio | Supporto nativo |
|-------|-------------|---------|----------------|
| **1. Abbonamento + utilizzo** | Commissione base + addebiti in base al consumo | \$49/mese + \$0.01/chiamata API dopo 10.000 gratuite | ✅ Completo |
| **2. Abbonamento + posti** | Commissione della piattaforma + addebiti per utente | \$99/mese + \$15/posto | ✅ Completo |
| **3. Abbonamento + componenti aggiuntivi** | Piano principale + upgrade opzionali | \$29/mese + \$19/mese per analisi + \$9/mese per accesso API | ✅ Completo |
| **4. Posti + utilizzo** | Commissione per utente + eccedenza di consumo | \$10/utente/mese + \$0.05/GB dopo 5 GB/utente | ⚠️ Soluzione alternativa |
| **5. Abbonamento + posti + utilizzo** | Piattaforma + utenti + consumo (ibrido triplo) | \$199/mese + \$20/posto + eccedenza di utilizzo | ⚠️ Soluzione alternativa |
| **6. Base a livelli + eccedenza di utilizzo** | Livelli diversi con quantità incluse diverse | Starter (5.000 chiamate) vs Pro (50.000 chiamate) + eccedenza | ✅ Completo |
| **7. Abbonamento + addebiti on-demand** | Commissione ricorrente + addebiti manuali variabili | Retainer da \$99/mese + fatturazione oraria per il lavoro | ✅ Completo |

## Modello ibrido 1: abbonamento + utilizzo

Il modello ibrido più comune. I clienti pagano una commissione di abbonamento base più gli addebiti per il consumo che supera le quantità incluse.

### Come funziona

**Piano Pro: $49/mese**

- **Incluso**: 10.000 chiamate API/mese
- **Eccedenza**: $0.005 per chiamata dopo 10.000

**Calcolo di esempio** (il cliente utilizza 25.000 chiamate questo mese):
- Abbonamento base: $49.00
- Eccedenza: (25.000 - 10.000) × $0.005 = $75.00
- **Totale: $124.00**

### Casi d'uso

- **Piattaforme API**: accesso base + addebiti per richiesta
- **Servizi AI/ML**: abbonamento + utilizzo di token/generazioni
- **Servizi di archiviazione**: piano base + eccedenza per GB
- **Piattaforme di comunicazione**: base + addebiti per messaggio/minuto

### Implementazione

<Steps>
<Step title="Create Usage Meter">
Configura un meter per monitorare la dimensione di utilizzo fatturabile.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
Crea un prodotto in abbonamento e collega il meter di utilizzo con i prezzi.

```bash
Dashboard: Create Product → Subscription
Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
Il meter di utilizzo viene collegato direttamente al prodotto in abbonamento. Gli addebiti per l'utilizzo vengono calcolati e aggiunti automaticamente alla fattura dell'abbonamento.
</Info>
</Step>

<Step title="Create Checkout Session">
Crea una sessione di checkout con il tuo prodotto in abbonamento.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_pro_plan', quantity: 1 }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Send Usage Events">
Monitora l'utilizzo durante il periodo di fatturazione.

```typescript
await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [{
      event_id: `call_${Date.now()}`,
      customer_id: 'cus_123',
      event_name: 'api.call',
      timestamp: new Date().toISOString(),
      metadata: { endpoint: '/v1/generate' }
    }]
  })
});
```

</Step>
</Steps>

### Varianti di prezzo

<Tabs>
<Tab title="Included Allowance">
La soglia gratuita copre l'utilizzo incluso nell'abbonamento base.

**Piano Pro: $49/mese**
- Include: 10.000 chiamate API
- Eccedenza: $0.005/chiamata dopo 10.000
- Il cliente utilizza 8.000 → paga $49 (nessuna eccedenza)
</Tab>

<Tab title="Zero Base + Pure Usage">
Nessuna commissione base: ogni unità è fatturabile dal primo utilizzo.

**Pay-As-You-Go: base da $0/mese**
- Include: 0 chiamate API
- Utilizzo: $0.01/chiamata dalla prima chiamata
- Il cliente utilizza 5.000 → paga $50
</Tab>

<Tab title="Tiered Allowances">
Livelli diversi includono quantità diverse.

- **Starter**: $19/mese (1.000 chiamate incluse)
- **Pro**: $49/mese (10.000 chiamate incluse)
- **Enterprise**: $199/mese (100.000 chiamate incluse)
- Tutti i livelli: eccedenza di $0.005/chiamata
</Tab>
</Tabs>

## Modello ibrido 2: abbonamento + posti

Commissione della piattaforma più addebiti per utente. Ideale per strumenti di collaborazione tra team e SaaS B2B.

### Come funziona

**Piano Team: $99/mese + $15/posto**

- **Commissione base della piattaforma**: $99/mese (include 3 posti)
- **Posti aggiuntivi**: $15/posto/mese

**Calcolo di esempio** (team di 12 utenti):
- Commissione della piattaforma: $99.00
- Posti aggiuntivi: (12 - 3) × $15 = $135.00
- **Totale: $234.00/mese**

### Casi d'uso

- **Strumenti di collaborazione**: commissione del workspace + quota per membro
- **Sistemi CRM**: licenza della piattaforma + quota per commerciale
- **Gestione dei progetti**: piano team + quota per collaboratore
- **Strumenti per sviluppatori**: commissione dell'organizzazione + quota per sviluppatore

### Implementazione

<Steps>
<Step title="Create Seat Add-on">
Crea un componente aggiuntivo per i posti aggiuntivi.

```bash

Name: "Additional Seat"

Description: "Add another team member"
```

</Step>

<Step title="Create Base Subscription">


</Step>
</Steps>

### Varianti di prezzo

<Tabs>
<Tab title="Included Seats">
Il piano base include alcuni posti; gli extra vengono addebitati.

**Piano Team: $99/mese**
- Include: 5 posti
- Posti aggiuntivi: $15/posto/mese
- 20 utenti = \$99 + (15 × \$15) = \$324/mese
</Tab>

<Tab title="Pure Per-Seat">
Nessuna commissione della piattaforma, solo addebiti per utente.

**Per utente: $25/utente/mese**
- Nessuna commissione della piattaforma
- 5 utenti = $125/mese
- 50 utenti = $1,250/mese

Implementazione: imposta il prezzo dell'abbonamento base a $0 e utilizza solo il componente aggiuntivo per i posti.
</Tab>

<Tab title="Tiered Per-Seat">
Il prezzo per posto diminuisce nei livelli superiori.

- **Starter**: $20/posto (1-10 posti)
- **Growth**: $15/posto (11-50 posti)
- **Enterprise**: $10/posto (51+ posti)

Implementazione: crea prodotti in abbonamento separati per ogni livello con prezzi diversi per i componenti aggiuntivi.
</Tab>
</Tabs>

## Modello ibrido 3: abbonamento + componenti aggiuntivi per funzionalità

Abbonamento principale con upgrade opzionali che i clienti possono aggiungere.

**Componenti aggiuntivi opzionali:**
- Analisi avanzate: +$19/mese
- Accesso API: +$9/mese

- Piano principale: $29.00
- Analisi: $19.00
- Accesso API: $9.00
- **Totale: $57.00/mese**

- **Piattaforme SaaS**: funzionalità principali + moduli premium
- **Strumenti di marketing**: strumento base + integrazioni
- **Prodotti di analisi**: dashboard + report avanzati
- **Software di sicurezza**: protezione di base + funzionalità avanzate

## Modello ibrido 4: posti + utilizzo

Commissione per utente combinata con addebiti basati sul consumo. Ogni utente riceve una quantità inclusa.

<Warning>
**Limitazione**: Dodo Payments attualmente non supporta il collegamento di meter di utilizzo e componenti aggiuntivi allo stesso prodotto in abbonamento. Questo modello richiede una soluzione alternativa che utilizzi la logica a livello di applicazione.
</Warning>

### Come funziona

**Analytics del team: 20 $/utente/mese**

**Ogni utente include:**
- 5 GB di elaborazione dati/mese
- Eccedenza: 2 $/GB dopo la quota inclusa

**Esempio di calcolo** (team di 10 utenti che utilizza 80 GB in totale):
- Costi delle licenze: 10 × 20 $ = 200,00 $
- Dati inclusi: 10 × 5 GB = 50 GB
- Eccedenza: (80 - 50) × 2 $ = 60,00 $
- **Totale: 260,00 $/mese**

### Casi d'uso

- **Piattaforme di analytics**: per analista + elaborazione dati
- **Strumenti di progettazione**: per designer + archiviazione/esportazioni
- **Ambienti di sviluppo**: per sviluppatore + ore di calcolo
- **Strumenti di comunicazione**: per utente + volume di messaggi/chiamate

Poiché non puoi associare sia i contatori di utilizzo sia gli add-on alla stessa subscription, scegli uno dei seguenti approcci:

## Modello ibrido 5: Subscription + licenze + utilizzo (ibrido triplo)

Il modello più completo: tariffa della piattaforma + costo per utente + consumo.

<Warning>
**Limitazione**: Dodo Payments attualmente non supporta l'associazione sia dei contatori di utilizzo sia degli add-on allo stesso prodotto subscription. Questo modello richiede un approccio alternativo.
</Warning>

### Come funziona

**Piattaforma Enterprise**

- **Tariffa della piattaforma**: 199 $/mese
- **Per licenza**: 25 $/utente/mese
- **Utilizzo**: 0,10 $/1.000 chiamate API (50.000 incluse)

**Esempio di calcolo** (azienda con 20 utenti e 150.000 chiamate API):
- Piattaforma: 199,00 $
- Licenze: 20 × 25 $ = 500,00 $
- Utilizzo: (150K - 50K) × \$0.10/1K = \$10.00
- **Totale: 709,00 $/mese**

### Casi d'uso

- **SaaS Enterprise**: piattaforma + team + consumo
- **Piattaforme dati**: workspace + analisti + query
- **Piattaforme di integrazione**: hub + connettori + transazioni
- **Piattaforme AI**: workspace + sviluppatori + inferenza

### Opzioni di implementazione

Scegli uno dei seguenti approcci per implementare la fatturazione ibrida tripla:

</Step>
</Steps>
</Tab>
</Tabs>

<Info>
**Raccomandazione**: l'opzione A (base + licenze + utilizzo on-demand) è generalmente più semplice perché Dodo gestisce automaticamente la fatturazione della piattaforma e delle licenze. Devi solo tenere traccia dell'utilizzo e inviare gli addebiti al termine di ogni ciclo di fatturazione.
</Info>

## Modello ibrido 7: Subscription + on-demand charges

Subscription ricorrente più addebiti manuali variabili per servizi o eccedenze.

### Come funziona

**Piano a forfait: 199 $/mese**

**Include:**
- Accesso alla piattaforma
- 5 ore di consulenza/mese
- Supporto via email

**Addebiti on-demand (secondo necessità):**
- Consulenza aggiuntiva: 150 $/ora
- Sviluppo personalizzato: 200 $/ora
- Supporto di emergenza: 100 $/incidente

**Esempio di calcolo** (questo mese):
- Forfait: 199,00 $
- 3 ore di consulenza aggiuntiva: 450,00 $
- 1 intervento di supporto di emergenza: 100,00 $
- **Totale: 749,00 $**

### Casi d'uso

- **Servizi di consulenza**: forfait + fatturazione oraria
- **Servizi gestiti**: tariffa base + addebiti per incidente
- **Servizi di agenzia**: tariffa mensile + addebiti per progetto
- **Piani di supporto**: tariffa SLA + costo per ticket o per ora

### Implementazione

<Steps>
<Step title="Create On-Demand Subscription">
Configura una subscription con gli addebiti on-demand abilitati.

```typescript
const subscription = await client.subscriptions.create({
  billing: {
    city: 'San Francisco',
    country: 'US',
    state: 'CA',
    street: '123 Main St',
    zipcode: '94105'
  },
  customer: { customer_id: 'cus_123' },
  product_id: 'pdt_retainer',
  quantity: 1,
  payment_link: true,
  return_url: 'https://yourapp.com/success',
  on_demand: {
    mandate_only: false,
    product_price: 19900  // $199 initial charge
  }
});
```

</Step>

<Step title="Charge for Services">
Crea gli addebiti quando i servizi vengono erogati.

```typescript
// Charge for 3 hours of consulting
await client.subscriptions.charge('sub_123', {
  product_price: 45000,  // $450.00 (3 × $150)
  product_description: 'Consulting - 3 hours (March 15)'
});

// Charge for emergency support incident
await client.subscriptions.charge('sub_123', {
  product_price: 10000,  // $100.00
  product_description: 'Emergency support - Server outage (March 18)'
});
```

</Step>

<Step title="Track and Invoice">
Tutti gli addebiti vengono visualizzati nella fattura del cliente.

```typescript
// Retrieve subscription charges
const payments = await client.payments.list({
  subscription_id: 'sub_123'
});

// Show itemized breakdown to customer
payments.items.forEach(payment => {
  console.log(`${payment.payment_id}: $${payment.total_amount / 100}`);
});
```

</Step>
</Steps>

## Esempi reali

<Info>
Questi esempi mostrano strutture di prezzo ideali. A causa della limitazione per cui i contatori di utilizzo e gli add-on non possono essere associati allo stesso prodotto, alcune combinazioni richiedono soluzioni alternative (utilizzando addebiti on-demand per l'utilizzo o gestendo le licenze nell'applicazione).
</Info>

### Esempio 1: piattaforma SaaS AI

**Struttura dei prezzi:**
- **Subscription di base**: 99 $/mese (accesso alla piattaforma, 5 licenze incluse)
- **Add-on per licenze**: 20 $/licenza/mese
- **Add-on per funzionalità**: modelli personalizzati (\$49/mese), accesso API (\$29/mese), coda prioritaria (\$19/mese)
- **Eccedenza di utilizzo**: 0,02 $ per 1.000 token dopo 100K (addebitata tramite on-demand)

**Implementazione**: usa una subscription con add-on per licenze e funzionalità. Tieni traccia dell'utilizzo dei token nella tua applicazione e addebita le eccedenze tramite addebiti on-demand al termine del ciclo di fatturazione.

**Esempio di cliente** (12 utenti, 500K token, modelli personalizzati + accesso API):
| Componente | Calcolo | Importo |
|-----------|-------------|--------|
| Base | Tariffa della piattaforma | 99 $ |
| Licenze aggiuntive | 7 × 20 $ | 140 $ |
| Modelli personalizzati | Add-on | 49 $ |
| Accesso API | Add-on | 29 $ |
| Eccedenza token | 400K × \$0.02/1K (on-demand) | \$8 |
| **Totale** | | **325 $/mese** |

### Esempio 2: piattaforma di strumenti per sviluppatori

**Opzioni di livello:**

| | Free | Pro | Enterprise |
|---|------|-----|------------|
| **Prezzo** | 0 $/mese | 29 $/mese | 199 $/mese |
| **Utenti** | 1 | 5 inclusi | Illimitati |
| **Build** | 100 | 1.000 | 10.000 |
| **Archiviazione** | 1 GB | 10 GB | 100 GB |

**Opzioni di implementazione**:

**Opzione A** (incentrata sull'utilizzo): crea prodotti con contatori di utilizzo per build/archiviazione. Gestisci gli utenti nella tua applicazione.

**Opzione B** (incentrata sulle licenze): crea prodotti con add-on per licenze. Tieni traccia dell'utilizzo di build/archiviazione e addebita le eccedenze tramite on-demand.

**Implementazione**: usa una subscription con add-on per livelli di contatti, funzionalità e licenze. Tieni traccia delle email inviate nella tua applicazione e addebita le eccedenze tramite addebiti on-demand.

## Best practice di implementazione

### Chiarezza della pagina dei prezzi

<Tip>
Rendi i prezzi ibridi facili da comprendere. Mostra in modo evidente nella pagina dei prezzi i costi di base, cosa è incluso e come funzionano le eccedenze.
</Tip>

**Corretto**: "\$49/mese include 10.000 chiamate API. Chiamate aggiuntive: \$0.005 ciascuna"

**Errato**: "\$49/mese + costi di utilizzo"

### Prevedibilità dei costi

Aiuta i clienti a stimare i propri costi:

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### Visibilità sull'utilizzo

Mostra ai clienti il loro utilizzo in tempo reale:

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

## Risoluzione dei problemi della fatturazione ibrida

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**Sintomi**: l'utilizzo mostra valori pari a 0 o non corretti.

**Soluzioni**:
1. Verifica che l'acquisizione degli eventi funzioni (controlla le risposte API)
2. Conferma che `customer_id` corrisponda al cliente della subscription
3. Verifica che `event_name` corrisponda alla configurazione del contatore
4. Verifica che gli eventi abbiano timestamp corretti (non datati nel futuro)
</Accordion>

<Accordion title="Proration confusion with multiple components">
**Sintomi**: al cliente vengono addebitati importi imprevisti quando cambia piano.

**Soluzioni**:
1. Usa l'API `previewChangePlan` per mostrare gli addebiti esatti prima della conferma
2. Comunica che il pro rata si applica alla subscription E agli add-on
3. Valuta l'utilizzo di `difference_immediately` per semplificare la fatturazione degli upgrade
</Accordion>

<Accordion title="Free threshold not applying correctly">
**Sintomi**: al cliente viene addebitato un utilizzo che dovrebbe essere gratuito.

**Soluzioni**:
1. Verifica che la soglia gratuita sia configurata nel prodotto basato sull'utilizzo
2. Controlla che l'unità della soglia corrisponda all'aggregazione degli eventi (chiamate vs. richieste)
3. Conferma che il contatore di utilizzo sia associato correttamente al prodotto subscription
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**Sintomi**: non è possibile aggiungere licenze o funzionalità durante il checkout.

**Soluzioni**:
1. Verifica che gli add-on siano associati al prodotto subscription nella dashboard
2. Controlla che gli ID degli add-on siano corretti nelle chiamate API
3. Assicurati che la valuta dell'add-on corrisponda a quella del prodotto subscription
</Accordion>
</AccordionGroup>
