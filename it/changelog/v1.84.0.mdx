## Nuove funzionalità

### 1. **Analytics a livello di prodotto**

Ogni prodotto ora ha il proprio **dashboard di analytics dedicato**. Vai a **Prodotti > [Seleziona un prodotto]** per accedere ai metriche dettagliate specifiche per quel prodotto, organizzate in cinque schede:

<Frame>
<img src="/images/product-analytics/overview.png" alt="Analytics a livello di prodotto" />
</Frame>

| Scheda | Cosa ottieni |
|-----|-------------|
| **Panoramica** | Fatturato totale, conteggio dei pagamenti riusciti, grafico della tendenza del fatturato di 30 giorni (giornaliero o cumulativo) e una tabella delle transazioni filtrabile |
| **Clienti** | I 3 migliori clienti classificati per spesa con una visualizzazione podio, oltre a una tabella dettagliata sui clienti |
| **Retention** | Tasso di abbandono dei clienti, tasso di abbandono del fatturato e un grafico a linee duali per individuare modelli |
| **Abbonati** | Tutti gli abbonamenti per il prodotto con stato, data di inizio, data della prossima fatturazione e importo |
| **MRR** | Grafico a barre impilato del Fatturato Mensile Ricorrente con suddivisioni di Nuovo MRR, Espansione MRR, MRR Abbandonato e Net New MRR |

Tutte le schede supportano un **filtraggio per data** (impostato su Tutto il tempo per impostazione predefinita) in modo da poter approfondire qualsiasi periodo di tempo.

<Tip>
Usa la scheda Retention per identificare i prodotti con alto tasso di abbandono in anticipo, e la scheda MRR per monitorare se il fatturato da espansione supera il fatturato abbandonato mese dopo mese.
</Tip>

### 2. **Supporto Verifi RDR su Dodo Payments**

Dodo Payments ora supporta il **Visa Rapid Dispute Resolution (RDR)** alimentato da Verifi — uno strumento automatizzato di prevenzione delle controversie che risolve le controversie idonee Visa **prima che diventino chargeback formali**. Quando un titolare di carta avvia una controversia, RDR la intercetta e emette automaticamente un rimborso se la transazione è al di sotto della soglia in USD configurata.

**Perché è importante**

| Vantaggio | Impatto |
|---------|--------|
| **Tasso di controversia inferiore** | Le controversie risolte da RDR non contano per la soglia dello 0,9% di Visa |
| **Nessuna tassa sulle controversie** | Evita spese non rimborsabili di $15-$25 per controversia |
| **Zero carico operativo** | Niente raccolta di prove o scadenze di risposta |
| **Migliore esperienza per il cliente** | I titolari di carta ottengono rimborsi immediati |
| **Protezione dell'account** | Rimani fuori dal programma di monitoraggio delle controversie di Visa (VDMP) |

<Warning>
Superare il tasso di controversia dello 0,9% di Visa o 100 controversie/mese attiva il VDMP, con multe crescenti fino a $50.000+/mese. RDR ti aiuta a rimanere ben sotto queste soglie.
</Warning>

**Come funziona**

1. Il titolare di carta avvia una controversia con la propria banca
2. RDR intercetta la controversia prima che diventi un chargeback formale
3. Se l'importo della transazione è uguale o inferiore alla tua soglia, viene emesso automaticamente un rimborso
4. La controversia viene risolta istantaneamente e **non conta** contro il tuo tasso di controversia

<Info>
Le transazioni rimborsate automaticamente tramite RDR appaiono come una **controversia persa** nel tuo dashboard Dodo Payments. Questo è previsto: il rimborso è stato emesso automaticamente per prevenire un chargeback formale.
</Info>

Per abilitare Verifi RDR sul tuo account, contatta **support@dodopayments.com** per configurare la tua soglia.

Scopri di più: [Documentazione Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

Presentiamo la nuovissima **DodoPayments CLI** (`dodopayments-cli`) -- gestisci l'intero flusso di lavoro di Dodo Payments direttamente dal terminale. Costruita per sviluppatori che preferiscono la riga di comando, la CLI ti permette di gestire prodotti, pagamenti, clienti, sconti, licenze, addon, rimborsi e persino creare sessioni di checkout senza lasciare il tuo editor.

**Installazione**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Comandi principali**

| Comando | Descrizione |
|---------|-------------|
| `dodo login` | Autenticati con la tua chiave API (apre il browser) |
| `dodo products list` | Elenca tutti i prodotti |
| `dodo payments list` | Elenca tutti i pagamenti |
| `dodo customers create` | Crea un nuovo cliente |
| `dodo checkout new` | Crea una sessione di checkout e ottieni l'URL |
| `dodo wh listen` | Inoltra webhook di test in tempo reale al tuo server locale tramite WebSocket |
| `dodo wh trigger` | Invia payload di webhook simulati a qualsiasi endpoint |

**Test dei Webhook**

La CLI include due strumenti potenti per lo sviluppo:

- **`dodo wh listen`** -- Apre una connessione WebSocket per inoltrare webhook di test in tempo reale al tuo server locale, preservando le intestazioni originali per il testing della verifica della firma
- **`dodo wh trigger`** -- Invia payload di webhook simulati in modo interattivo, supportando tutti i 22 tipi di eventi per abbonamenti, pagamenti, rimborsi, controversie e licenze

<Tip>
L'ascoltatore di webhook funziona solo con una chiave API in **modalità test**. Assicurati di essere loggato con una chiave in modalità test prima di utilizzare `dodo wh listen`.
</Tip>

Scopri di più: [Documentazione CLI](/developer-resources/sdks/cli)

### 5. **Aggiornamento del metodo di pagamento nel checkout inline**

Il [checkout inline](/developer-resources/inline-checkout) ora supporta **aggiornamenti del metodo di pagamento** per abbonamenti. Quando un cliente ha bisogno di aggiornare il proprio metodo di pagamento (per un abbonamento attivo o per riattivare un abbonamento sospeso), il flusso di aggiornamento del metodo di pagamento può ora essere visualizzato direttamente all'interno del layout della tua pagina utilizzando il checkout inline -- offrendo un'esperienza integrata senza soluzione di continuità.

**Come funziona**

1. Chiama l'API di Aggiornamento del Metodo di Pagamento per ottenere un `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Utilizza il `payment_link` restituito come `checkoutUrl` nel checkout inline:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

Il frame inline renderizza solo il modulo di raccolta del metodo di pagamento, consentendo ai clienti di inserire nuovi dettagli della carta o di selezionare un metodo di pagamento salvato senza lasciare la tua pagina.

<Tip>
Per abbonamenti sospesi, il flusso di aggiornamento del metodo di pagamento crea automaticamente un addebito per i debiti rimanenti. Monitora i webhook `payment.succeeded` e `subscription.active` per confermare la riattivazione.
</Tip>

Scopri di più: [Checkout Inline](/developer-resources/inline-checkout) | [Aggiornamenti del Metodo di Pagamento per Abbonamenti](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Supporto per la precompilazione dell'ID fiscale per le sessioni di checkout**

Puoi ora **precompilare l'ID fiscale** (ad esempio, numero di VAT, numero di GST) quando crei una sessione di checkout utilizzando il parametro `tax_id`. Questo è ideale per transazioni B2B in cui conosci già il numero identificativo fiscale del cliente. Quando un ID fiscale è precompilato, il campo è pre-popolato e bloccato nel modulo di checkout.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Il parametro `tax_id` richiede un `billing_address` con almeno un campo `country`. L'idoneità fiscale viene convalidata in tempo reale e le regole di inversione dell'onere vengono applicate automaticamente per le transazioni B2B idonee.
</Info>

Utilizza il flag funzione `allow_customer_editing_tax_id` per controllare se i clienti possono modificare l'ID fiscale precompilato, e `allow_tax_id` per alternare la visibilità dell'ID fiscale nel checkout.

Scopri di più: [Sessioni di Checkout - ID Fiscale](/developer-resources/checkout-session) | [Pagamenti B2B](/features/b2b-payments)

### 7. **Chiave di licenza e email nel reindirizzamento dell'URL di ritorno**

Dopo che un cliente completa il checkout, Dodo Payments ora aggiunge `license_key` e `email` come parametri di query al tuo `return_url` di reindirizzamento, oltre ai parametri esistenti `payment_id`/`subscription_id` e `status`.

**Parametri di Query Aggiunti**

| Parametro | Tipo | Condizione |
|-----------|------|-----------|
| `payment_id` | `string` | Sempre presente per pagamenti una tantum |
| `subscription_id` | `string` | Sempre presente per pagamenti di abbonamento |
| `status` | `string` | Sempre presente |
| `license_key` | `string` | Presente se il prodotto ha chiavi di licenza abilitate (separato da virgole per più) |
| `email` | `string` | Presente se il cliente ha un'email registrata |

**Esempi di URL di reindirizzamento:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Utilizza questi parametri di query per visualizzare le chiavi di licenza o inviare immediatamente un'email di conferma sulla tua pagina di ritorno, senza necessità di una chiamata API extra.
</Tip>

Scopri di più: [Sessioni di Checkout - URL di Ritorno](/developer-resources/checkout-session) | [Chiavi di Licenza nell'URL di Ritorno](/features/license-keys#license-keys-in-return-url)

### 8. **API di Aggiornamento dell'Email del Cliente**

L'endpoint `PATCH /customers/{customer_id}` ora supporta l'aggiornamento degli indirizzi email dei clienti in modo programmatico. Aggiorna l'email insieme a nome, numero di telefono e metadata in una sola chiamata API.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Campi Aggiornabili**

| Campo | Tipo | Descrizione |
|-------|------|-------------|
| `email` | `string \| null` | Indirizzo email del cliente |
| `name` | `string \| null` | Nome visualizzato del cliente |
| `phone_number` | `string \| null` | Numero di telefono in formato internazionale |
| `metadata` | `object \| null` | Coppie chiave-valore personalizzate |

<Info>
Gli aggiornamenti dell'email del cliente sono disponibili anche tramite il Portale Clienti (self-service), il dashboard e la CLI tramite `dodo customers update`.
</Info>

Scopri di più: [API di Aggiornamento del Cliente](/api-reference/customers/patch-customer) | [Gestione Clienti](/features/customers)

### 9. **Rilascio dell'Adattatore Bun**

Presentiamo `@dodopayments/bun` -- un adattatore di framework dedicato per il server nativo di [Bun](https://bun.sh) (`Bun.serve()`). Integra checkout, portale clienti e webhook con Bun in poche righe di codice.

**Installazione**

```bash
bun add @dodopayments/bun
```

**Configurazione Rapida**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

L'adattatore Bun supporta tutti e tre i flussi di checkout (statico, dinamico e basato su sessione), generazione di sessioni del portale clienti e gestione sicura dei webhook con verifica della firma e validazione Zod attraverso 22 tipi di eventi.

</Check>
