## Gestione delle API Key e autenticazione

<Steps>
<Step title="Access API Keys">
Vai a **Developer → API Keys** nella dashboard per gestire le tue chiavi.
</Step>

<Step title="Generate a New Key">
Seleziona **Add API Key**, inserisci un nome descrittivo e configura l'accesso in scrittura:

- **Enable write access** (selezionato): autorizzazioni complete di lettura e scrittura per tutte le operazioni API
- **Enable write access** (non selezionato): accesso in sola lettura: puoi solo recuperare dati (pagamenti, abbonamenti, clienti, prodotti). Non puoi creare o modificare risorse.

<Tip>
Deseleziona "Enable write access" per le integrazioni della dashboard, gli strumenti di analisi e qualsiasi sistema che debba solo visualizzare i dati senza apportare modifiche.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Copia immediatamente la chiave generata e assicurati di conservarla in modo sicuro.
</Step>

<Step title="Authenticate Your API Requests">
Usa le tue API keys per autenticare tutte le richieste. Applica il seguente formato di autorizzazione:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Non esporre mai le tue API keys segrete nel codice lato client o nei repository pubblici.
</Warning>
</Step>
</Steps>

## Limiti di frequenza

La nostra API utilizza un sistema di rate limiting a doppia finestra con protezione dai picchi. I limiti vengono applicati in base al tuo metodo di autenticazione e al livello della tua attività.

### Limiti predefiniti (Tier 0)

| Finestra | Limite |
|--------|-------|
| Al secondo (Burst) | 40 richieste |
| Al minuto (Sustained) | 240 richieste |

### Livelli di attività

Sono disponibili limiti di frequenza più elevati per le attività con maggiori esigenze API:

| Livello | Burst (al secondo) | Sustained (al minuto) |
|------|-------------------|------------------------|
| Tier 0 (predefinito) | 40 | 240 |
| Tier 1 | 100 | 1.000 |
| Tier 2 | 500 | 5.000 |

<Tip>
Contatta il supporto per portare la tua attività a un livello di rate limiting superiore.
</Tip>

### Richieste non autenticate

Le richieste senza header di autenticazione validi sono soggette a rate limiting in base all'indirizzo IP:

| Finestra | Limite |
|--------|-------|
| Al secondo (Burst) | 20 richieste |
| Al minuto (Sustained) | 100 richieste |

### Header dei limiti di frequenza

Monitora il tuo utilizzo con questi header di risposta:

- `X-RateLimit-Limit` - Numero massimo di richieste consentite
- `X-RateLimit-Remaining` - Richieste rimanenti nella finestra corrente
- `X-RateLimit-Reset` - Momento in cui il limite di frequenza viene reimpostato

<Note>
Quando superi i limiti di frequenza, l'API restituisce una risposta `429 Too Many Requests`. Implementa un exponential backoff nella logica dei retry.
</Note>
