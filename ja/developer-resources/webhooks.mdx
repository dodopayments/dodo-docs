Webhooksは、Dodo Paymentsアカウントで特定のイベントが発生したときにリアルタイム通知を提供します。Webhooksを使用してワークフローを自動化し、データベースを更新し、通知を送信し、システムを同期させます。

<Info>
私たちのWebhook実装は、[Standard Webhooks](https://standardwebhooks.com/)仕様に従っており、業界のベストプラクティスおよび既存のWebhookライブラリとの互換性を確保しています。
</Info>

## 始めに

<Steps>
<Step title="Webhook設定にアクセス">

</Step>

<Step title="Webhookエンドポイントを作成">
    `Add Webhook`をクリックして、新しいWebhookエンドポイントを作成します。
    </Step>

    <Frame>
        <img src="/images/webhooks/create-endpoint.png" alt="Webhookを追加" />
    </Frame>
</Step>

<Step title="エンドポイントURLを追加する">
    Webhookイベントを受信したいURLを入力します。
    
</Step>

<Step title="受信するイベントを選択する">
    イベントリストからWebhookエンドポイントがリッスンする特定のイベントを選択します。
    
    <Tip>
    選択したイベントのみがエンドポイントにWebhookをトリガーし、不要なトラフィックと処理を回避します。
    </Tip>
</Step>

<Step title="シークレットキーを取得">
    設定ページからWebhookの`Secret Key`を取得します。これを使用して受信したWebhookの正当性を確認します。
    
    <Warning>
    Webhookのシークレットキーを安全に保管し、クライアントサイドのコードや公開リポジトリに公開しないでください。
    </Warning>
</Step>

<Step title="秘密を回転させる（オプション）">
    必要に応じて、セキュリティを強化するためにWebhook秘密を回転させることができます。Webhook設定で**秘密を回転させる**ボタンをクリックします。
    
    <Warning>
    秘密を回転させると、**それが失効し**、**新しいものに置き換えられます**。古い秘密は次の24時間のみ有効です。その後、古い秘密での検証は失敗します。
    </Warning>
    
    <Info>
    現在の秘密が侵害された疑いがある場合は、定期的にまたは直ちに秘密の回転を使用してください。
    </Info>
</Step>
</Steps>

## サブスクライブしたイベントの設定

各Webhookエンドポイントが受信したい特定のイベントを設定できます。

### イベント設定へのアクセス

<Steps>
<Step title="Webhookの詳細に移動">
    Dodo Paymentsダッシュボードに移動し、`Settings > Webhooks`にアクセスします。
</Step>

<Step title="エンドポイントを選択する">
    設定したいWebhookエンドポイントをクリックします。
</Step>

<Step title="イベント設定を開く">
    Webhookの詳細ページで、「サブスクライブしたイベント」セクションが表示されます。**編集**ボタンをクリックしてイベントのサブスクリプションを変更します。
</Step>
</Steps>

### イベントサブスクリプションの管理

<Steps>
<Step title="利用可能なイベントの表示">
    インターフェースは、階層構造で整理されたすべての利用可能なWebhookイベントを表示します。イベントはカテゴリー別にグループ化されています（例：`dispute`、`payment`、`subscription`）。
</Step>

<Step title="検索とフィルタリング">
    検索バーを使用して、イベント名やキーワードを入力して特定のイベントを迅速に見つけます。
</Step>

<Step title="イベントを選択">
    受信したいイベントの横のボックスにチェックを入れます。以下が可能です：
    - 個々のサブイベントを選択する（例：`dispute.accepted`、`dispute.challenged`）
    - 親イベントを選択して、関連するすべてのサブイベントを受信する
    - ニーズに応じて特定のイベントを組み合わせる
</Step>

<Step title="イベントの詳細を確認する">
    各イベントの隣にある情報アイコン（ⓘ）にカーソルを合わせると、そのイベントがトリガーされる条件の説明が表示されます。
</Step>

<Step title="設定を保存する">
    **保存**をクリックして変更を適用するか、**キャンセル**をクリックして変更を破棄します。
</Step>
</Steps>

<Warning>
すべてのイベントの選択を解除すると、Webhookエンドポイントは通知を受け取らなくなります。アプリケーションが正常に機能するために必要なイベントは少なくとも選択してください。
</Warning>

## Webhook配信

### タイムアウト

Webhookには、接続および読み取り操作のための**15秒のタイムアウトウィンドウ**があります。タイムアウトを避けるために、エンドポイントが迅速に応答することを確認してください。

<Tip>
Webhookを非同期で処理し、直ちに`200`ステータスコードで受信を確認し、実際の処理はバックグラウンドで行います。
</Tip>

### 自動再試行

Webhook配信が失敗した場合、Dodo Paymentsはシステムを圧倒しないように指数バックオフで自動的に再試行します。

| 試行 | 遅延 | 説明 |
|---------|------------------------------|-------------|
| 1 | すぐに | 最初の再試行はすぐに行われます |
| 2 | 5秒 | 短い遅延の後に2回目の試行 |
| 3 | 5分 | 増加したバックオフで3回目の試行 |
| 4 | 30分 | バックオフを続けて4回目の試行 |
| 5 | 2時間 | 延長された遅延で5回目の試行 |
| 6 | 5時間 | より長い遅延で6回目の試行 |
| 7 | 10時間 | 最大遅延で7回目の試行 |
| 8 | 10時間 | **最終試行** - 失敗した場合はWebhookが失敗としてマークされます |

<Info>
**Webhookイベントごとに最大8回の再試行**が行われます。たとえば、Webhookが成功する前に3回失敗した場合、最初の試行からの合計配信時間は約35分5秒です。
</Info>

<Tip>
Dodo Paymentsダッシュボードを使用して、個々のメッセージを手動で再試行したり、失敗したすべてのメッセージを一括回復したりできます。
</Tip>

### 冪等性

各Webhookイベントには、一意の`webhook-id`ヘッダーが含まれています。この識別子を使用して冪等性を実装し、重複処理を防ぎます。

```javascript
// Example: Storing webhook IDs to prevent duplicate processing
const processedWebhooks = new Set();

app.post('/webhook', (req, res) => {
  const webhookId = req.headers['webhook-id'];
  
  if (processedWebhooks.has(webhookId)) {
    return res.status(200).json({ received: true });
  }
  
  processedWebhooks.add(webhookId);
  // Process the webhook...
});
```

<Warning>
常に冪等性チェックを実装してください。再試行のため、同じイベントを複数回受信する可能性があります。
</Warning>

### イベントの順序

Webhookイベントは、再試行やネットワーク条件により順不同で到着する場合があります。システムを設計して、任意の順序でイベントを処理できるようにしてください。

<Info>
Webhookイベントが元々発生した時期に関係なく、**配信時の最新のペイロードを受け取ります**。
</Info>

## Webhookのセキュリティ

Webhookのセキュリティを確保するために、常にペイロードを検証し、HTTPSを使用してください。

### 署名の検証

各Webhookリクエストには、`webhook-signature`ヘッダー、WebhookペイロードのHMAC SHA256署名とタイムスタンプが含まれ、あなたのシークレットキーで署名されています。

#### SDK検証（推奨）

すべての公式SDKには、受信したWebhookを安全に検証および解析するための組み込みヘルパーが含まれています。2つのメソッドが利用可能です：

* `unwrap()`: Webhookシークレットキーを使用して署名を検証
* `unsafe_unwrap()`: 検証なしでペイロードを解析

<Tip>
  Dodo Paymentsクライアントを初期化する際に、`DODO_PAYMENTS_WEBHOOK_KEY`を介してWebhookのシークレットを提供してください。
</Tip>

<CodeGroup>

```typescript TypeScript/Node.js
import DodoPayments from 'dodopayments';
import express from 'express';

const app = express();
app.use(express.raw({ type: 'application/json' }));

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
});

app.post('/webhook', async (req, res) => {
  try {
    const unwrapped = client.webhooks.unwrap(req.body.toString(), {
      headers: {
        'webhook-id': req.headers['webhook-id'] as string,
        'webhook-signature': req.headers['webhook-signature'] as string,
        'webhook-timestamp': req.headers['webhook-timestamp'] as string,
      },
    });
    res.json({ received: true });
  } catch (error) {
    res.status(401).json({ error: 'Invalid signature' });
  }
});
```

```python Python
from fastapi import FastAPI, Request, HTTPException
from dodopayments import DodoPayments
import os

app = FastAPI()
client = DodoPayments(
```

```go Go
import (
	"context"
	"io"
	"net/http"
	"os"
	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func webhookHandler(w http.ResponseWriter, r *http.Request) {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
		option.WithEnvironment(os.Getenv("DODO_PAYMENTS_ENVIRONMENT")),
		option.WithWebhookKey(os.Getenv("DODO_PAYMENTS_WEBHOOK_KEY")),
	)
	rawBody, _ := io.ReadAll(r.Body)
	if _, err := client.Webhooks.Unwrap(context.Background(), rawBody, map[string]string{
		"webhook-id":       r.Header.Get("webhook-id"),
		"webhook-signature": r.Header.Get("webhook-signature"),
		"webhook-timestamp": r.Header.Get("webhook-timestamp"),
	}); err != nil {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}
	w.WriteHeader(http.StatusOK)
}
```

</CodeGroup>

#### 手動検証（代替）

SDKを使用していない場合は、Standard Webhooks仕様に従って署名を自分で検証できます：

1. `webhook-id`、`webhook-timestamp`、および正確な生文字列の`payload`をピリオドで区切って連結して署名されたメッセージを構築します（`.`）。
2. ダッシュボードのWebhookシークレットキーを使用してその文字列のHMAC SHA256を計算します。
3. 計算された署名と`webhook-signature`ヘッダーを比較します。一致する場合、Webhookは正当です。

<Info>
  私たちはStandard Webhooks仕様に従っています。署名を検証するために彼らのライブラリを使用できます：[https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries)。イベントペイロード形式については、[Webhookペイロード](/developer-resources/webhooks/intents/payment)を参照してください。
</Info>

### Webhookへの応答

* Webhookハンドラーは、イベントの受信を確認するために`2xx status code`を返す必要があります。
* その他のレスポンスは失敗と見なされ、Webhookは再試行されます。

### ベストプラクティス

<AccordionGroup>
<Accordion title="HTTPSエンドポイントのみを使用" icon="lock">
  Webhookエンドポイントには常にHTTPS URLを使用してください。HTTPエンドポイントは中間者攻撃に対して脆弱であり、Webhookデータを公開します。
</Accordion>

<Accordion title="すぐに応答する" icon="bolt">
  Webhookを受信した時点で、`200`のステータスコードを直ちに返します。タイムアウトを避けるために、イベントを非同期で処理します。
  

  ```javascript
  app.post('/webhook', async (req, res) => {
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process asynchronously
    processWebhookAsync(req.body).catch(console.error);
  });
  ```

</Accordion>

<Accordion title="重複イベントの処理" icon="rotate">
  `webhook-id`ヘッダーを使用して冪等性を実装し、同じイベントを副作用なしで安全に複数回処理します。
</Accordion>

<Accordion title="Webhook秘密を保護する" icon="key">
  環境変数やシークレットマネージャーを使用してWebhook秘密を安全に保管します。決してシークレットをバージョン管理にコミットしないでください。
</Accordion>

## Webhookペイロード構造

Webhookペイロード構造を理解することで、イベントを正しく解析し処理できます。

### リクエスト形式

```http
POST /your-webhook-url
Content-Type: application/json
```

### ヘッダー

<ParamField header="webhook-id" type="string" required>
このWebhookイベントの一意の識別子。冪等性チェックに使用します。
</ParamField>

<ParamField header="webhook-signature" type="string" required>
Webhookの真正性を検証するためのHMAC SHA256署名。
</ParamField>

<ParamField header="webhook-timestamp" type="string" required>
Webhookが送信されたときのUnixタイムスタンプ（秒単位）。
</ParamField>

### リクエストボディ

<ResponseField name="business_id" type="string" required>
あなたのDodo Paymentsビジネス識別子。
</ResponseField>

<ResponseField name="type" type="string" required>
このWebhookをトリガーしたイベントタイプ（例：`payment.succeeded`、`subscription.created`）。
</ResponseField>

<ResponseField name="timestamp" type="string" required>
イベントが発生した時刻のISO 8601形式のタイムスタンプ。
</ResponseField>

<ResponseField name="data" type="object" required>
イベントに特有のペイロードで、イベントに関する詳細情報を含みます。

<Expandable title="データオブジェクトのプロパティ">
  <ResponseField name="payload_type" type="string">
  リソースのタイプ：`Payment`、`Subscription`、`Refund`、`Dispute`、または`LicenseKey`。
  </ResponseField>
  
  追加フィールドはイベントタイプによって異なります。完全なスキーマについては、イベント固有のドキュメントを参照してください。
</Expandable>
</ResponseField>

### 実装例

Webhookの検証と処理を示す完全なExpress.js実装は次のとおりです：

<CodeGroup>

```typescript Express.js Webhook Handler
import { Webhook } from "standardwebhooks";
import express from "express";

const app = express();
app.use(express.json());

const webhook = new Webhook(process.env.DODO_WEBHOOK_SECRET);

app.post('/webhook/dodo-payments', async (req, res) => {
  try {
    // Extract webhook headers
    const webhookHeaders = {
      "webhook-id": req.headers["webhook-id"] as string,
      "webhook-signature": req.headers["webhook-signature"] as string,
      "webhook-timestamp": req.headers["webhook-timestamp"] as string,
    };

    // Verify the webhook signature
    const payload = JSON.stringify(req.body);
    await webhook.verify(payload, webhookHeaders);
    
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process webhook asynchronously
    processWebhookAsync(req.body).catch(console.error);
    
  } catch (error) {
    console.error('Webhook verification failed:', error);
    res.status(400).json({ error: 'Invalid signature' });
  }
});

async function processWebhookAsync(data: any) {
  // Handle the webhook event based on type
  switch (data.type) {
    case 'payment.succeeded':
      await handlePaymentSucceeded(data);
      break;
    case 'subscription.created':
      await handleSubscriptionCreated(data);
      break;
    // Add more event handlers...
  }
}
```

```javascript Testing Webhooks Locally
  }
});

console.log("Test webhook sent successfully:", response.data);
```

</CodeGroup>

<Tip>
Webhookハンドラーを本番イベントを処理する前に、ダッシュボードのテストインターフェースを使用して徹底的にテストしてください。これにより、問題を早期に特定して修正できます。
</Tip>

## WebhooksのCLIによるテスト

[Dodo Payments CLI](/developer-resources/sdks/cli)は、ローカル開発中にWebhookをテストするための2つのコマンドを提供します。ターミナルを離れる必要はありません。

### ライブWebhookをローカルでリッスン

テストモードアカウントからの実際のWebhookイベントをリアルタイムでローカル開発サーバーに転送します：

```bash
dodo wh listen
```

CLIはDodo PaymentsにWebSocket接続を開き、すべてのWebhookイベントをローカルエンドポイント（例：`http://localhost:3000/webhook`）に転送し、検証テストのために署名ヘッダーを含むすべてのヘッダーを保持します。

<Info>
リスナーは**テストモード**APIキーでのみ動作します。`dodo login`を実行し、このコマンドを使用する前にテストモードを選択してください。
</Info>

### モックWebhookイベントをトリガー

実際のトランザクションを作成することなく、任意のエンドポイントにモックWebhookペイロードを送信します：

```bash
dodo wh trigger
```

このインタラクティブなツールを使用すると、サポートされている22のイベントタイプから選択し、リアルなモックペイロードをエンドポイントに送信できます。セッション内で複数のイベントをテストできるようにループします。

<Warning>
`dodo wh trigger`からのモックWebhookペイロードは署名されていません。テスト中は`unwrap()`の代わりに`unsafe_unwrap()`をWebhookハンドラーで使用してください。
</Warning>

<Card title="CLI Webhookテストドキュメント" icon="terminal" href="/developer-resources/sdks/cli#webhook-testing">
  CLIによるWebhookテストに関する完全なドキュメントを確認してください
</Card>

## 高度な設定

高度な設定タブでは、Webhookエンドポイントの動作を細かく調整するための追加の構成オプションが提供されます。

### レート制限（スロットリング）

システムを圧倒しないように、Webhookイベントがエンドポイントに配信されるレートを制御します。

<Steps>
<Step title="レート制限設定にアクセス">
    **高度な**タブで、「レート制限（スロットリング）」セクションを見つけます。
</Step>

<Step title="レート制限を構成">
    **編集**ボタンをクリックして、レート制限設定を変更します。
    
    <Info>
    デフォルトでは、Webhookには「制限なし」が適用され、イベントは発生次第配信されます。
    </Info>
</Step>

<Step title="制限を設定">
    Webhook配信の頻度を制御し、システムの過負荷を防ぐために、希望するレート制限を構成します。
</Step>
</Steps>

<Tip>
Webhookハンドラーがイベントを処理するための時間が必要な場合や、複数のイベントをバッチ処理したい場合はレート制限を使用してください。
</Tip>

### カスタムヘッダー

すべてのWebhookリクエストにカスタムHTTPヘッダーを追加します。これは認証、ルーティング、またはWebhookリクエストにメタデータを追加するのに便利です。

<Steps>
<Step title="カスタムヘッダーを追加">
    「カスタムヘッダー」セクションで、カスタムヘッダーの**キー**と**値**を入力します。
</Step>

<Step title="複数のヘッダーを追加">
    必要に応じて**+**ボタンをクリックして追加のカスタムヘッダーを追加します。
</Step>

<Step title="設定を保存">
    あなたのカスタムヘッダーはこのエンドポイントへのすべてのWebhookリクエストに含まれます。
</Step>
</Steps>

### 変換

変換により、Webhookのペイロードを変更し、別のURLにリダイレクトすることができます。この強力な機能により、次のことが可能になります：

- 処理の前にペイロード構造を変更する
- コンテンツに基づいてWebhookを異なるエンドポイントにルーティングする
- ペイロードからフィールドを追加または削除する
- データフォーマットを変換する

<Steps>
<Step title="変換を有効にする">
    **有効**スイッチを切り替えて変換機能をアクティブにします。
</Step>

<Step title="変換を構成">
    **変換を編集**をクリックして、変換ルールを定義します。
    
    <Info>
    JavaScriptを使用してWebhookペイロードを変換し、別のターゲットURLを指定できます。
    </Info>
</Step>

<Step title="変換をテスト">
    テストインターフェースを使用して、ライブ前に変換が正しく機能するかを確認します。
</Step>
</Steps>

<Warning>
変換はWebhookの配信パフォーマンスに大きな影響を与える可能性があります。徹底的にテストし、変換ロジックをシンプルかつ効率的に保ってください。
</Warning>

<Tip>
変換は特に次の目的に便利です：
- 異なるデータフォーマットへの変換
- 特定の条件に基づいてイベントをフィルタリング
- ペイロードに計算されたフィールドを追加
- イベントを異なるマイクロサービスにルーティング
</Tip>

## メールアラート

Webhookの健康状態について自動メール通知で情報を得ることができます。Webhook配信が失敗し始めたり、エンドポイントが応答しなくなった場合、メールアラートが届くので、問題に迅速に対処し、統合がスムーズに動作するように保てます。

<Frame>
  <img src="/images/webhooks/alerting.png" alt="Webhook Alerting Settings showing email notifications configuration" />
</Frame>

### メールアラートを有効にする

<Steps>
<Step title="アラート設定に移動">
  Dodo Paymentsダッシュボードに移動し、**ダッシュボード → Webhooks → アラート**にアクセスします。
</Step>

<Step title="メール通知を有効にする">
  **メール通知**をオンに切り替えて、Webhook配信の問題に関するアラートを受信し始めます。
</Step>

<Step title="メールアドレスを設定">
  Webhookアラートを受信したいメールアドレスを入力してください。このアドレスに、Webhook設定で特定のイベントが発生した際に通知を送信します。デリバリーの問題が発生した場合など、統合に影響を与える可能性があります。
</Step>
</Steps>

<Tip>
Webhook配信の問題を早期に把握し、信頼性のある統合を維持するためにメールアラートを有効にしてください。配信が失敗したり、エンドポイントが応答しなくなった場合に通知を受け取ります。
</Tip>
