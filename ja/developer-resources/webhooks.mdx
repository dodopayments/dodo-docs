Webhooksは、Dodo Paymentsアカウントで特定のイベントが発生した際に、リアルタイム通知を提供します。Webhooksを使用してワークフローの自動化、データベースの更新、通知の送信、システムの同期を行えます。

<Info>
当社のWebhook実装は[Standard Webhooks](https://standardwebhooks.com/)仕様に準拠しており、業界のベストプラクティスおよび既存のWebhookライブラリとの互換性を確保しています。
</Info>

## 主な機能

## はじめに

<Steps>
<Step title="Access Webhook Settings">
    DodoPayments Dashboardに移動し、`Developer > Webhooks`に進みます。
</Step>

<Step title="Create Webhook Endpoint">
    `Add Webhook`をクリックして、新しいWebhookエンドポイントを作成します。
    

    <Frame>
        <img src="/images/webhooks/create-endpoint.png" alt="Add Webhook" style={{ maxHeight: '500px', width: 'auto' }} />
    </Frame>
</Step>

<Step title="Add Endpoint URL">
    Webhookイベントを受信するURLを入力します。
    
</Step>

<Step title="Select Events to Receive">
    イベントリストから選択して、Webhookエンドポイントがリッスンする特定のイベントを選びます。
    
    <Tip>
    選択したイベントのみがエンドポイントへのWebhookを発火するため、不要なトラフィックや処理を回避できます。
    </Tip>
</Step>

<Step title="Get Secret Key">
    設定ページからWebhookの`Secret Key`を取得します。受信したWebhookの真正性を検証するために使用します。
    
    <Warning>
    Webhook secret keyは安全に保管し、クライアント側のコードや公開リポジトリに決して公開しないでください。
    </Warning>
</Step>

<Step title="Rotate Secret (Optional)">
    必要に応じて、セキュリティを強化するためにWebhook secretをローテーションできます。Webhook設定で**Rotate Secret**ボタンをクリックします。
    
    <Warning>
    Secretをローテーションすると、現在のsecretは**期限切れ**となり、新しいsecretに**置き換えられます**。古いsecretはその後24時間のみ有効です。それ以降、古いsecretで検証すると失敗します。
    </Warning>
    
    <Info>
    Secretのローテーションは定期的に行うか、現在のsecretが漏えいした可能性がある場合は直ちに行ってください。
    </Info>
</Step>
</Steps>

## 購読イベントの設定

各Webhookエンドポイントで受信する特定のイベントを設定できます。

### イベント設定へのアクセス

<Steps>
<Step title="Navigate to Webhook Details">
    Dodo Payments Dashboardに移動し、`Developer > Webhooks`に進みます。
</Step>

<Step title="Select Your Endpoint">
    設定するWebhookエンドポイントをクリックします。
</Step>

<Step title="Open Event Settings">
    Webhook詳細ページに「Subscribed events」セクションがあります。**Edit**ボタンをクリックしてイベント購読を変更します。
</Step>
</Steps>

### イベント購読の管理

<Steps>
<Step title="View Available Events">
    インターフェースには、利用可能なすべてのWebhookイベントが階層構造で表示されます。イベントはカテゴリ（例：`dispute`、`payment`、`subscription`）ごとに分類されます。
</Step>

<Step title="Search and Filter">
    検索バーにイベント名やキーワードを入力して、特定のイベントをすばやく検索します。
</Step>

<Step title="Select Events">
    受信するイベントの横にあるチェックボックスをオンにします。次の操作ができます。
    - 個別のサブイベントを選択（例：`dispute.accepted`、`dispute.challenged`）
    - 親イベントを選択して、関連するすべてのサブイベントを受信
    - 必要に応じて特定のイベントを組み合わせて選択
</Step>

<Step title="Review Event Details">
    各イベントの横にある情報アイコン（ⓘ）にカーソルを合わせると、そのイベントが発火する条件の説明が表示されます。
</Step>

<Step title="Save Configuration">
    **Save**をクリックして変更を適用するか、**Cancel**をクリックして変更を破棄します。
</Step>
</Steps>

<Warning>
すべてのイベントの選択を解除すると、Webhookエンドポイントは通知を受信しません。アプリケーションが正常に動作するために必要なイベントを少なくとも選択してください。
</Warning>

## Webhookの配信

### タイムアウト

Webhooksには、接続操作と読み取り操作の両方に**15秒のタイムアウトウィンドウ**があります。タイムアウトを避けるため、エンドポイントがすばやく応答するようにしてください。

<Tip>
Webhookは、`200` status codeですぐに受信を確認してから、実際の処理をバックグラウンドで行う非同期方式で処理してください。
</Tip>

### 自動再試行

Webhookの配信に失敗すると、Dodo Paymentsは指数バックオフで自動的に再試行し、システムへの過負荷を防ぎます。

| 試行 | 待機時間 | 説明 |
|---------|------------------------------|-------------|
| 1 | Immediately | 最初の再試行は直ちに実行 |
| 2 | 5 seconds | 短い待機後に2回目の試行 |
| 3 | 5 minutes | バックオフを増加させて3回目の試行 |
| 4 | 30 minutes | バックオフを継続して4回目の試行 |
| 5 | 2 hours | 待機時間を延長して5回目の試行 |
| 6 | 5 hours | より長い待機時間で6回目の試行 |
| 7 | 10 hours | 最大待機時間で7回目の試行 |
| 8 | 10 hours | **最後の試行** - 失敗した場合、Webhookは失敗としてマーク |

<Info>
Webhookイベントごとの再試行は**最大8回**です。たとえば、Webhookが成功するまでに3回失敗した場合、最初の試行からの合計配信時間は約35分5秒です。
</Info>

<Tip>
Dodo Payments dashboardを使用すると、個々のメッセージを手動で再試行したり、失敗したすべてのメッセージを一括でいつでも復旧したりできます。
</Tip>

### 冪等性

各Webhookイベントには一意の`webhook-id` headerが含まれます。この識別子を使用して冪等性を実装し、重複処理を防止します。

```javascript
// Example: Storing webhook IDs to prevent duplicate processing
const processedWebhooks = new Set();

app.post('/webhook', (req, res) => {
  const webhookId = req.headers['webhook-id'];
  
  if (processedWebhooks.has(webhookId)) {
    return res.status(200).json({ received: true });
  }
  
  processedWebhooks.add(webhookId);
  // Process the webhook...
});
```

<Warning>
必ず冪等性チェックを実装してください。再試行により、同じイベントを複数回受信する可能性があります。
</Warning>

### イベントの順序

再試行やネットワーク状況により、Webhookイベントが順不同で到着する場合があります。どの順序でもイベントを処理できるようにシステムを設計してください。

<Info>
Webhookイベントが最初に発行された時刻にかかわらず、**配信時点での最新のpayload**を受信します。
</Info>

## Webhooksのセキュリティ保護

Webhooksのセキュリティを確保するため、必ずpayloadを検証し、HTTPSを使用してください。

### 署名の検証

各Webhook requestには`webhook-signature` headerが含まれます。これはWebhook payloadとtimestampのHMAC SHA256 signatureであり、secret keyで署名されています。

#### SDKによる検証（推奨）

すべての公式SDKには、受信したWebhookを安全に検証して解析するための組み込みヘルパーが含まれています。利用できるメソッドは2つです。

* `unwrap()`：Webhook secret keyを使用して署名を検証
* `unsafe_unwrap()`：検証せずにpayloadを解析

<Tip>
  Dodo Payments clientの初期化時に、`DODO_PAYMENTS_WEBHOOK_KEY`でWebhook secretを指定します。
</Tip>

<CodeGroup>

```typescript TypeScript/Node.js
import DodoPayments from 'dodopayments';
import express from 'express';

const app = express();
app.use(express.raw({ type: 'application/json' }));

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
});

app.post('/webhook', async (req, res) => {
  try {
    const unwrapped = client.webhooks.unwrap(req.body.toString(), {
      headers: {
        'webhook-id': req.headers['webhook-id'] as string,
        'webhook-signature': req.headers['webhook-signature'] as string,
        'webhook-timestamp': req.headers['webhook-timestamp'] as string,
      },
    });
    res.json({ received: true });
  } catch (error) {
    res.status(401).json({ error: 'Invalid signature' });
  }
});
```

```python Python
from fastapi import FastAPI, Request, HTTPException
from dodopayments import DodoPayments
import os

app = FastAPI()
client = DodoPayments(
    bearer_token=os.getenv("DODO_PAYMENTS_API_KEY"),
    environment=os.getenv("DODO_PAYMENTS_ENVIRONMENT"),
    webhook_key=os.getenv("DODO_PAYMENTS_WEBHOOK_KEY"),
)

@app.post("/webhook")
async def handle_webhook(request: Request):
    try:
        unwrapped = client.webhooks.unwrap(
            await request.body(),
            headers={
                "webhook-id": request.headers.get("webhook-id", ""),
                "webhook-signature": request.headers.get("webhook-signature", ""),
                "webhook-timestamp": request.headers.get("webhook-timestamp", ""),
            },
        )
        return {"received": True}
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid signature")
```

```go Go
import (
	"context"
	"io"
	"net/http"
	"os"
	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func webhookHandler(w http.ResponseWriter, r *http.Request) {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
		option.WithEnvironment(os.Getenv("DODO_PAYMENTS_ENVIRONMENT")),
		option.WithWebhookKey(os.Getenv("DODO_PAYMENTS_WEBHOOK_KEY")),
	)
	rawBody, _ := io.ReadAll(r.Body)
	if _, err := client.Webhooks.Unwrap(context.Background(), rawBody, map[string]string{
		"webhook-id":       r.Header.Get("webhook-id"),
		"webhook-signature": r.Header.Get("webhook-signature"),
		"webhook-timestamp": r.Header.Get("webhook-timestamp"),
	}); err != nil {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}
	w.WriteHeader(http.StatusOK)
}
```

</CodeGroup>

#### 手動検証（代替方法）

SDKを使用しない場合は、Standard Webhooks仕様に従って署名を自分で検証できます。

1. `webhook-id`、`webhook-timestamp`、正確なraw stringified `payload`をピリオド（`.`）で連結し、署名対象メッセージを作成します。
2. DashboardのWebhook secret keyを使用して、その文字列のHMAC SHA256を計算します。
3. 計算したsignatureと`webhook-signature` headerを比較します。一致すれば、Webhookは正当なものです。

<Info>
  Standard Webhooks仕様に準拠しています。署名の検証には、次のライブラリを使用できます：[https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries)。イベントpayloadの形式については、[Webhook Payload](/developer-resources/webhooks/intents/payment)を参照してください。
</Info>

### Webhooksへの応答

* Webhook handlerは、イベントの受信を確認するために`2xx status code`を返す必要があります。
* その他のresponseは失敗として扱われ、Webhookが再試行されます。

### ベストプラクティス

<AccordionGroup>
<Accordion title="Use HTTPS endpoints only" icon="lock">
  Webhook endpointには必ずHTTPS URLを使用してください。HTTP endpointは中間者攻撃に対して脆弱で、Webhook dataが露出します。
</Accordion>

<Accordion title="Respond immediately" icon="bolt">
  Webhookの受信時に`200` status codeを直ちに返します。タイムアウトを避けるため、イベントを非同期で処理します。
  

  ```javascript
  app.post('/webhook', async (req, res) => {
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process asynchronously
    processWebhookAsync(req.body).catch(console.error);
  });
  ```

</Accordion>

<Accordion title="Handle duplicate events" icon="rotate">
  `webhook-id` headerを使用して冪等性を実装し、同じイベントを副作用なく複数回安全に処理できるようにします。
</Accordion>

<Accordion title="Secure your webhook secret" icon="key">
  環境変数またはsecrets managerを使用してWebhook secretを安全に保管してください。secretをバージョン管理にコミットしないでください。
</Accordion>
</AccordionGroup>

## Webhook Payloadの構造

Webhook payloadの構造を理解すると、イベントを正しく解析して処理できます。

### Request形式

```http
POST /your-webhook-url
Content-Type: application/json
```

### Headers

<ParamField header="webhook-id" type="string" required>
このWebhookイベントの一意な識別子。冪等性チェックに使用します。
</ParamField>

<ParamField header="webhook-signature" type="string" required>
Webhookの真正性を検証するためのHMAC SHA256 signature。
</ParamField>

<ParamField header="webhook-timestamp" type="string" required>
Webhookが送信された時刻を示すUnix timestamp（秒単位）。
</ParamField>

### Request Body

<ResponseField name="business_id" type="string" required>
Dodo Paymentsのbusiness identifier。
</ResponseField>

<ResponseField name="type" type="string" required>
このWebhookを発火させたイベントタイプ（例：`payment.succeeded`、`subscription.active`）。
</ResponseField>

<ResponseField name="timestamp" type="string" required>
イベントが発生した時刻のISO 8601形式のtimestamp。
</ResponseField>

<ResponseField name="data" type="object" required>
イベントの詳細情報を含む、イベント固有のpayload。

<Expandable title="Data object properties">
  <ResponseField name="payload_type" type="string">
  リソースの種類。次のいずれかです: `Payment`、`Subscription`、`Refund`、`Dispute`、`LicenseKey`、`CreditLedgerEntry`、`CreditBalanceLow`、`AbandonedCheckout`、`DunningAttempt`、`EntitlementGrant`、または `Payout`。
  </ResponseField>
  
  追加フィールドはイベントの種類によって異なります。完全なスキーマについては、イベント固有のドキュメントを参照してください。
</Expandable>
</ResponseField>

### Payloadの例

```json
{
  "business_id": "string",
  "type": "payment.succeeded | payment.failed |...",
  "timestamp": "2024-01-01T12:00:00Z",
  "data": {
    "payload_type": "Payment | Subscription | Refund | Dispute | LicenseKey | CreditLedgerEntry | CreditBalanceLow | AbandonedCheckout | DunningAttempt | EntitlementGrant | Payout",
    // ... event-specific fields (see below)
  }
}
```

### 実装例

Webhookの検証と処理を示す、完全なExpress.js実装例です。

<CodeGroup>

```typescript Express.js Webhook Handler
import { Webhook } from "standardwebhooks";
import express from "express";

const app = express();
app.use(express.json());

const webhook = new Webhook(process.env.DODO_WEBHOOK_SECRET);

app.post('/webhook/dodo-payments', async (req, res) => {
  try {
    // Extract webhook headers
    const webhookHeaders = {
      "webhook-id": req.headers["webhook-id"] as string,
      "webhook-signature": req.headers["webhook-signature"] as string,
      "webhook-timestamp": req.headers["webhook-timestamp"] as string,
    };

    // Verify the webhook signature
    const payload = JSON.stringify(req.body);
    await webhook.verify(payload, webhookHeaders);
    
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process webhook asynchronously
    processWebhookAsync(req.body).catch(console.error);
    
  } catch (error) {
    console.error('Webhook verification failed:', error);
    res.status(400).json({ error: 'Invalid signature' });
  }
});

async function processWebhookAsync(data: any) {
  // Handle the webhook event based on type
  switch (data.type) {
    case 'payment.succeeded':
      await handlePaymentSucceeded(data);
      break;
    case 'subscription.active':
      await handleSubscriptionActive(data);
      break;
    // Add more event handlers...
  }
}
```

## CLIでのWebhooksのテスト

[Dodo Payments CLI](/developer-resources/sdks/cli)には、ターミナルを離れずにローカル開発中のWebhooksをテストするための2つのコマンドがあります。

### ローカルでライブWebhookをリッスン

test mode accountから実際のWebhookイベントをローカル開発サーバーへリアルタイムに転送します。

```bash
dodo wh listen
```

CLIはDodo PaymentsへのWebSocket接続を開き、すべてのWebhookイベントをローカルエンドポイント（例：`http://localhost:3000/webhook`）に転送します。検証テスト用にsignature headersを含むすべてのheadersが保持されます。

<Info>
listenerは**test mode** API keysでのみ動作します。このコマンドを使用する前に`dodo login`を実行し、Test Modeを選択してください。
</Info>

### モックWebhookイベントを発火

実際のtransactionを作成せずに、任意のエンドポイントへモックWebhook payloadを送信します。

```bash
dodo wh trigger
```

このインタラクティブツールでは、イベントの種類を選択すると、現実的なモック payload が endpoint に送信されます。ループして動作するため、1回のセッションで複数のイベントをテストできます。

trigger コマンドは subscription、payment、refund、dispute、license key のイベントをサポートします。正確な一覧については、[Supported Webhook Events](/developer-resources/sdks/cli#supported-webhook-events) を参照してください。Payout、credit、abandoned checkout、dunning、entitlement grant のイベントは、モック trigger ではまだ利用できません。これらは `dodo wh listen` を使用し、実際の test-mode トランザクションに対してテストしてください。

<Warning>
`dodo wh trigger` からのモック webhook payload には署名がありません。テスト中に限り、webhook handler では `unwrap()` の代わりに `unsafe_unwrap()` を使用してください。
</Warning>

<Card title="CLI Webhook Testing Docs" icon="terminal" href="/developer-resources/sdks/cli#webhook-testing">
  CLI webhook テストの完全なドキュメントを参照してください
</Card>

## Advanced Settings

Advanced Settings タブには、webhook endpoint の動作を細かく調整するための追加設定オプションがあります。

### Rate Limiting (Throttling)

webhook event が endpoint に配信されるレートを制御し、システムの過負荷を防ぎます。

<Steps>
<Step title="Access Rate Limit Settings">
    **Advanced** タブで、「Rate Limit (throttling)」セクションを見つけます。
</Step>

<Step title="Configure Rate Limit">
    **Edit** ボタンをクリックして、rate limit の設定を変更します。
    
    <Info>
    デフォルトでは、webhook には「No rate limit」が適用され、イベントは発生するとすぐに配信されます。
    </Info>
</Step>

<Step title="Set Limits">
    希望する rate limit を設定して webhook の配信頻度を制御し、システムの過負荷を防ぎます。
</Step>
</Steps>

<Tip>
webhook handler でイベントの処理に時間が必要な場合や、複数のイベントをまとめて処理したい場合に rate limiting を使用します。
</Tip>

### Custom Headers

endpoint に送信されるすべての webhook request に custom HTTP headers を追加します。認証、routing、または webhook request への metadata の追加に便利です。

<Steps>
<Step title="Add Custom Header">
    「Custom Headers」セクションで、custom header の **Key** と **Value** を入力します。
</Step>

<Step title="Add Multiple Headers">
    必要に応じて、**+** ボタンをクリックして custom header を追加します。
</Step>

<Step title="Save Configuration">
    custom header は、この endpoint へのすべての webhook request に含まれます。
</Step>
</Steps>

### Transformations

Transformations を使用すると、webhook の payload を変更して別の URL に redirect できます。この強力な機能により、次のことが可能になります。

- 処理前に payload の構造を変更する
- 内容に基づいて webhook を異なる endpoint に routing する
- payload からフィールドを追加または削除する
- データ形式を変換する

<Steps>
<Step title="Enable Transformations">
    **Enabled** スイッチを切り替えて transformation 機能を有効にします。
</Step>

<Step title="Configure Transformation">
    **Edit transformation** をクリックして、transformation ルールを定義します。
    
    <Info>
    JavaScript を使用して webhook payload を変換し、別の target URL を指定できます。
    </Info>
</Step>

<Step title="Test Transformation">
    本番環境で使用する前に、testing interface を使用して transformation が正しく動作することを確認します。
</Step>
</Steps>

<Warning>
Transformations は webhook の配信パフォーマンスに大きな影響を与える可能性があります。十分にテストし、transformation ロジックはシンプルかつ効率的に保ってください。
</Warning>

<Tip>
Transformations は特に次の用途に便利です。
- 異なるデータ形式間で変換する
- 特定の条件に基づいてイベントをフィルタリングする
- payload に計算済みフィールドを追加する
- イベントを異なる microservice に routing する
</Tip>

## Email Alerts

自動 email notification で webhook の状態を常に把握できます。webhook の配信が失敗し始めたり、endpoint が応答しなくなったりすると、問題にすぐ対処して integration を円滑に維持できるよう、email alert が届きます。

<Frame>
  <img src="/images/webhooks/alerting.png" alt="Webhook Alerting Settings showing email notifications configuration" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### Enable Email Alerts

<Steps>
<Step title="Navigate to Alerting Settings">
  Dodo Payments Dashboard に移動し、**Dashboard → Webhooks → Alerting** を開きます。
</Step>

<Step title="Enable Email Notifications">
  **Email notifications** をオンにして、webhook の配信問題に関する alert の受信を開始します。
</Step>

<Step title="Configure Email Address">
  webhook alert の受信に使用する email address を入力します。webhook setup で特定のイベントが発生したとき、たとえば integration に影響する可能性のある配信問題が発生したときに、このアドレスへ notification を送信します。
</Step>
</Steps>

<Tip>
email alert を有効にして webhook 配信の問題を早期に検知し、信頼性の高い integration を維持しましょう。配信に失敗した場合や endpoint が応答しなくなった場合に notification が届きます。
</Tip>
