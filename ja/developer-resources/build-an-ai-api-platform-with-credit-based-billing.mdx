このチュートリアルでは、各サブスクリプションプランに月次トークンクレジットが付与され、不足時には追加パックを購入でき、バックエンドがOpenAIによるリクエスト処理中に自動控除する階層型AIプラットフォーム**NeuralAPI**を構築します。

このチュートリアルでは、Node.js/Express + OpenAI SDKを使用します。Dodo Paymentsのコンセプト（クレジット、メーター、Webhook）は、どのフレームワークやAIプロバイダーにも適用可能なので、自由に適応してください。

このチュートリアルの終わりまでに以下のことができるようになります:

- カスタムクレジット権利（トークン）と自動控除するメーターを作成する
- サブスクリプションプランにクレジットを付与し（超過なし、あり）、一度限りの追加購入商品を設定する
- OpenAIの完了エンドポイントをDodo Paymentsを通じてトークン請求するよう配線する
- SDKを通じて顧客のライブクレジット残高を照会する
- Webhookシグネチャを確認し、Dodo Paymentsクレジットイベントをルートする

## 建設しているもの

NeuralAPIの価格モデルは以下の通りです:

| 製品 | 価格 | トークン | 超過 |
|---------|-------|--------|---------|
| スタータープラン | 29ドル/月 | 10,000,000トークン/サイクル | ゼロでブロック |
| プロプラン | 99ドル/月 | 40,000,000トークン/サイクル | $0.005 / 1Kトークン |
| トークン追加パック | 19ドル一度限り | +5,000,000トークン | — |

開始する前に、次を確認してください:
- Dodo Paymentsアカウント（テストモードで可）
- OpenAI APIキー
- Node.js 18+
- TypeScript/Node.jsの基本的な知識

## ステップ 1: トークンクレジット権利を作成する

まず、サブスクリプションプランと追加購入パックで共有されるクレジット権利を作成します。これをプラットフォームが使用する「トークン」単位として定義するように考えてください。

<img src="/images/CBB/Desktop - Cookbook - NeuralAPI - Credit.png" alt="クレジット権利が表示されたクレジット一覧ページ" style={{ maxHeight: '500px', width: 'auto' }} />

1. Dodo Payments ダッシュボードにログイン
2. 左のサイドバーで**製品**をクリック
3. **クレジット**タブを選択
4. **クレジット作成**をクリック

トークンクレジットの基本情報を入力してください:

**クレジット名**: `API Tokens`

**クレジットタイプ**: **カスタムユニット**を選択

**単位名**: `token`

**精度**: `0`（トークンは常に整数です）

**クレジット有効期限**: `30 days`（クレジットは各請求サイクルでリセットされます）

精度はクレジット作成後に変更できません。トークンカウントの場合、`0`（整数）がほとんど常に正しいです。

ここでは超過を**無効**のままにします。製品にクレジットを付けるときにプランごとに設定します。これにより、スタータープランではゼロで使用がブロックされ、プロプランでは超過が許可されます。

ここで設定された超過設定は*デフォルト*です。各製品の添付はそれを上書きすることができ、これはステップ3でまさに行うことです。

**クレジット作成**をクリックします。保存後、クレジットを開き、そのIDをコピーします — `cent_xxxxxxxxxxxx`のように見えます。

`API Tokens`のクレジット権利が準備されました。次に、使用イベントが自動的に控除されるようにメーターを作成します。

## ステップ 2: トークン使用のメーターを作成する

メーターは、受信した使用イベントを集計し、クレジット控除に変換します。これをプランの製品を作成する前に作成する必要があります。メーターは製品作成時に取り付けます。

1. ダッシュボードのサイドバーで**製品** → **メーター**に移動
2. **メーター作成**をクリック

以下を入力します:

**メーター名**: `Token Usage Meter`

**イベント名**: `api.tokens_used` *(これはアプリが送信するものと正確に一致する必要があります)*

**集計タイプ**: `Sum` — 各イベントからのトークン数を合計します

**プロパティ**: `tokens` — 各イベントのメタデータキーで合計される値

**測定単位**: `tokens`

イベント名は大文字小文字を区別します。`api.tokens_used` ≠ `Api.Tokens.Used` — 一つを選んでそれに従ってください。

メーターを保存し、そのIDをコピーします — 製品に取り付けるときに参照します。

メーターは作成されました。クレジットを設定する際にこれを結び付けることができます。

## ステップ 3: プラン製品を作成する

両方のプランは**Usage Based Billing**製品でなければなりません。通常のサブスクリプションではありません — メーターはUBB製品のみに取り付けることができ、メーターを使用することで、顧客がAPIを呼び出すたびにクレジットが自動的に控除されます。UBB製品は依然として定期的な基本料金（`$29` / `$99`）をサポートしています。使用量に応じてクレジットで請求されます。

<img src="/images/CBB/Desktop - Attach Credit - UBB.jpg" alt="Usage Based Billingの価格設定構成" style={{ maxHeight: '500px', width: 'auto' }} />

### スタータープラン ($29/月 — 10M トークン、超過なし)

1. **製品 → 製品作成**に移動
2. **Usage Based Billing**を価格タイプとして選択
3. 入力:

**製品名**: `NeuralAPI Starter`

**説明**: `10 million API tokens per month. Perfect for individual developers and small projects.`

**固定価格**: `29.00` (定期的な基本料金 — 使用前に月額で請求)

**請求サイクル**: `Monthly`

**通貨**: `USD`

「メーター選択」セクションで**+**をクリックして`Token Usage Meter`を追加します。その後、メーターで:

1. **Bill usage in Credits**をオンに切り替える
2. **クレジット権利**: `API Tokens`を選択
3. **メーター単位あたりのクレジット**: `1` — イベント内の各トークンが1クレジット控除される
4. **無料閾値**: `0` — クレジット配分自体が顧客の「無料ティア」; 追加の無料バンドは必要ありません

<img src="/images/CBB/Desktop - Attach Credit - UBB-5.jpg" alt="Bill usage in Credits を有効にし、APIトークンを選択したメーター" style={{ maxHeight: '500px', width: 'auto' }} />

これが実際に顧客のバランスを控除するために受信した`api.tokens_used`イベントを作動させる配線です。

製品上で、クレジット請求がメーターに接続されると表示されるクレジット構成セクションにスクロールします。

**請求サイクルごとに発行されたクレジット**: `10000000`

**超過を許可**: **無効** — スターター顧客はトークンが切れたときにブロックされます

**既定のクレジット設定のインポート**: 有効 — クレジット権利の30日間有効期限を使用します

<img src="/images/CBB/Desktop - Attach Credit - UBB-6.jpg" alt="サイクルごとの量と超過設定を含むクレジット構成フォーム" style={{ maxHeight: '500px', width: 'auto' }} />

「保存」をクリックし、製品IDをコピーします。

スタータープラン: 月額$29基本料金、サイクルあたり10Mトークン、ゼロでブロックされ、メーターによって自動的に控除されます。

### プロプラン ($99/月 — 40M トークン、超過有効)

スターターと同じフロー、数値が大きいだけです:

**製品名**: `NeuralAPI Pro`

**説明**: `40 million API tokens per month with overage. Built for production applications.`

**固定価格**: `99.00`

**請求サイクル**: `Monthly`

**通貨**: `USD`

スターターと同じにします: `Token Usage Meter`を追加し、**Bill usage in Credits**をオンに切り替え、`API Tokens`を選択し、**メーター単位あたりのクレジット** `1` を設定し、**無料閾値** `0` を設定します。

クレジット発行を設定します。今回超過を許可します:

**請求サイクルごとに発行されたクレジット**: `40000000`

**既定のクレジット設定のインポート**: **無効** — 製品ごとに超過設定をカスタマイズする必要があります

**超過を許可**: **有効**

**単位あたりの価格**: `0.000005` USD/トークン (すなわち、1Kトークンあたり$0.005、または1Mトークンあたり$5 — プランの有効なトークンあたりの料金より高く、溢れるのを抑制するため)

**超過動作**: `Bill overage at billing` — 超過は次の請求書に請求され、残高がリセットされます

製品を保存し、製品IDをコピーします。

プロプラン: 月額$99基本料金、サイクルあたり40Mトークン、超過は1Kトークンあたり$0.005で、メーターによって自動的に控除されます。

## ステップ 4: トークン追加パックを作成する

トップアップパックは、一度の購入で既存の顧客の残高に5,000,000トークンを提供します。

<img src="/images/CBB/Desktop - Attach Credit - OTP.jpg" alt="単一支払いが選択された製品価格設定セクション" style={{ maxHeight: '500px', width: 'auto' }} />

1. **製品 → 製品作成**に移動
2. **単一支払い(Single Payment)**を価格タイプとして選択
3. 入力:

**製品名**: `Token Top-Up Pack`

**説明**: `Instantly add 5 million tokens to your NeuralAPI balance.`

**価格**: `19.00`

**通貨**: `USD`

1. **権利(Entitlements)**セクションで、**クレジット**の横の**添付(Attach)**をクリック
2. `API Tokens`を選択
3. **発行クレジット**: `5000000`を設定
4. *既定のクレジット設定のインポート*を**無効**にする — デフォルトの30日間有効期限を上書き
5. **クレジット有効期限**を設定: `365 days`
6. 製品を保存

製品IDをコピーします。

なぜトップアップに長い有効期限があるのですか? サブスクリプションクレジットはサイクルだから30 日ごとにリセットされます。トップアップは*前払いの購入*です — 顧客は $19 支払いましたし、そのトークンは1か月以上持続すると合理的に期待されます。365 日は、OpenAI、AWS、Anthropic のリアルな前払いクレジットの動作に合致し、顧客が無期限に貯蓄できないようにしながら、責任を制限します。

トップアップパックの設定完了 — 購入すると 5,000,000 トークンが付与され、365 日間有効です。

`src/server.ts` を作成します:

```typescript src/server.ts expandable
import 'dotenv/config';
import DodoPayments from 'dodopayments';
import OpenAI from 'openai';
import express, { Request, Response } from 'express';

const app = express();

// IMPORTANT: webhook route needs the raw body for signature verification.
// We register the raw parser ONLY on /webhooks/dodo, then JSON for everything else.
app.use('/webhooks/dodo', express.raw({ type: 'application/json' }));
app.use(express.json());
app.use(express.static('public'));

const dodo = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
  environment: (process.env.DODO_ENVIRONMENT as 'test_mode' | 'live_mode') ?? 'test_mode',
});

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY! });

const CREDIT_ENTITLEMENT_ID = process.env.CREDIT_ENTITLEMENT_ID!;
const BASE_URL = process.env.BASE_URL!;
const PLAN_PRODUCTS: Record<string, string> = {
  starter: process.env.STARTER_PLAN_PRODUCT_ID!,
  pro: process.env.PRO_PLAN_PRODUCT_ID!,
};

// ────────────────────────────────────────────────────────────────────────────
// Subscription checkout
// Body: { plan: 'starter' | 'pro', email: string, name: string }
// ────────────────────────────────────────────────────────────────────────────
app.post('/checkout/subscribe', async (req: Request, res: Response) => {
  const { plan, email, name } = req.body;
  if (!PLAN_PRODUCTS[plan]) {
    return res.status(400).json({ error: `Unknown plan: ${plan}` });
  }
  try {
    const session = await dodo.checkoutSessions.create({
      product_cart: [{ product_id: PLAN_PRODUCTS[plan], quantity: 1 }],
      customer: { email, name },
      return_url: `${BASE_URL}/?subscribed=1`,
    });
    res.json({ checkout_url: session.checkout_url, session_id: session.session_id });
  } catch (err) {
    console.error('Subscription checkout error:', err);
    res.status(500).json({ error: 'Failed to create subscription checkout' });
  }
});

// ────────────────────────────────────────────────────────────────────────────
// Top-up checkout — buyer must already be a customer
// Body: { customer_id: string }
// ────────────────────────────────────────────────────────────────────────────
app.post('/checkout/topup', async (req: Request, res: Response) => {
  const { customer_id } = req.body;
  if (!customer_id) return res.status(400).json({ error: 'customer_id required' });
  try {
    const session = await dodo.checkoutSessions.create({
      product_cart: [{ product_id: process.env.TOPUP_PRODUCT_ID!, quantity: 1 }],
      customer: { customer_id },
      return_url: `${BASE_URL}/?topup=1`,
    });
    res.json({ checkout_url: session.checkout_url });
  } catch (err) {
    console.error('Top-up checkout error:', err);
    res.status(500).json({ error: 'Failed to create top-up checkout' });
  }
});

// ────────────────────────────────────────────────────────────────────────────
// Live token balance for a customer
// ────────────────────────────────────────────────────────────────────────────
app.get('/credits/:customerId', async (req: Request, res: Response) => {
  try {
    const result = await dodo.creditEntitlements.balances.retrieve(req.params.customerId, {
      credit_entitlement_id: CREDIT_ENTITLEMENT_ID,
    });
    res.json({
      balance: result.balance,
      overage: result.overage,
      last_transaction_at: result.last_transaction_at,
    });
  } catch (err) {
    console.error('Balance fetch error:', err);
    res.status(500).json({ error: 'Failed to fetch credit balance' });
  }
});

// ────────────────────────────────────────────────────────────────────────────
// AI completion — calls OpenAI, then ingests a usage event with the real
// token count. The meter aggregates these and deducts credits automatically.
// Body: { customer_id: string, prompt: string }
// ────────────────────────────────────────────────────────────────────────────
app.post('/api/generate', async (req: Request, res: Response) => {
  const { customer_id, prompt } = req.body;
  if (!customer_id || !prompt) {
    return res.status(400).json({ error: 'customer_id and prompt required' });
  }

  // Best-effort balance gate for Starter (no overage). Note: balance updates
  // are eventually consistent (~1 min lag from event ingestion), so a Starter
  // customer can technically squeeze through a few extra requests right after
  // running out. Use a stricter rate-limiter on top if you need hard cutoffs.
  try {
    const balance = await dodo.creditEntitlements.balances.retrieve(customer_id, {
      credit_entitlement_id: CREDIT_ENTITLEMENT_ID,
    });
    if (Number(balance.balance) <= 0 && Number(balance.overage) <= 0) {
      return res.status(402).json({
        error: 'Out of tokens. Top up or upgrade to continue.',
      });
    }
  } catch {
    // Fall through — if the balance lookup fails, don't block; rely on metering.
  }

  let completion;
  try {
    completion = await openai.chat.completions.create({
      model: 'gpt-5-mini',
      messages: [{ role: 'user', content: prompt }],
    });
  } catch (err) {
    console.error('OpenAI error:', err);
    return res.status(502).json({ error: 'Upstream AI provider failed' });
  }

  const tokensUsed = completion.usage?.total_tokens ?? 0;

  // Fire-and-forget — don't block the response on metering.
  ingestTokenUsage(customer_id, tokensUsed, completion.model).catch((err) =>
    console.error('Usage ingest failed:', err),
  );

  res.json({
    text: completion.choices[0]?.message?.content ?? '',
    tokens_used: tokensUsed,
    model: completion.model,
  });
});

async function ingestTokenUsage(customerId: string, tokens: number, model: string) {
  await dodo.usageEvents.ingest({
    events: [
      {
        // event_id is the idempotency key. Use a stable, unique value per request.
        event_id: `req_${Date.now()}_${Math.random().toString(36).slice(2, 10)}`,
        customer_id: customerId,
        event_name: 'api.tokens_used',
        timestamp: new Date().toISOString(),
        metadata: { tokens, model },
      },
    ],
  });
}

// ────────────────────────────────────────────────────────────────────────────
// Webhook handler — verifies signature using the SDK, then routes events.
// ────────────────────────────────────────────────────────────────────────────
app.post('/webhooks/dodo', async (req: Request, res: Response) => {
  const rawBody = (req.body as Buffer).toString('utf8');
  const headers = {
    'webhook-id': req.header('webhook-id') ?? '',
    'webhook-signature': req.header('webhook-signature') ?? '',
    'webhook-timestamp': req.header('webhook-timestamp') ?? '',
  };

  let event: { type: string; data: any };
  try {
    event = dodo.webhooks.unwrap(rawBody, { headers }) as any;
  } catch (err) {
    console.error('Webhook verification failed:', err);
    return res.status(401).json({ error: 'Invalid signature' });
  }

  switch (event.type) {
    case 'credit.added':
      console.log(`[credit.added] customer=${event.data.customer_id} amount=${event.data.amount}`);
      break;
    case 'credit.deducted':
      console.log(`[credit.deducted] customer=${event.data.customer_id} amount=${event.data.amount}`);
      break;
    case 'credit.overage_charged':
      console.log(`[credit.overage_charged] customer=${event.data.customer_id}`);
      break;
    default:
      // Ignore other event types
      break;
  }

  res.json({ received: true });
});

app.listen(3000, () => {
  console.log('NeuralAPI billing server running on http://localhost:3000');
});
```

バックエンド完了: サブスクリプションチェックアウト、トップアップチェックアウト、メーター化されたトークン請求を含むOpenAI完了、バランス照会、および検証されたWebhookハンドラー。

[`@dodopayments/ingestion-blueprints`](/features/usage-based-billing/ingestion-blueprints) は、使用イベントを送信する必要なしに自動化するトラッカーを提供します — [LLMブループリント](/developer-resources/ingestion-blueprints/llm)、[APIゲートウェイ](/developer-resources/ingestion-blueprints/api-gateway)、[オブジェクトストレージ](/developer-resources/ingestion-blueprints/object-storage)、[ストリーム](/developer-resources/ingestion-blueprints/stream)、[時間範囲](/developer-resources/ingestion-blueprints/time-range)使用を含めて。

特定の "クレジット N を控除する" 呼び出しがないことに気づいたかもしれません。これは設計上です:

1. ハンドラーが OpenAI を呼び出し、`usage.total_tokens` から戻されたものを受け取ります（例: 1532）。
2. 単一の使用イベントを取り込みます: `event_name: api.tokens_used`, `metadata: { tokens: 1532 }`。
3. `Token Usage Meter`が顧客ごとにイベントを集計します。
4. メーターが `API Tokens` クレジットに**Bill usage in Credits**機能で接続されているため、Dodo Paymentsが顧客の最も古い有効期限切れでない付与から1532クレジットを控除します（FIFO）。
5. 超過が有効で、顧客がゼロを下回った場合、赤字は次の請求書で追跡されて請求されます。

メーターはすべてを処理します。コードはイベントの取り込みのみを行います。

## ステップ 7: Webhookを接続する

Webhookを使用すると、サーバーがバランスの変動に反応できます — 残りが少なくなったときに顧客にメールを送信するのに使用します。

Webhookには公開URLが必要です。ローカル開発では、[ngrok](https://ngrok.com) や任意のトンネルを使用してください:

`https://...ngrok-free.app` のURLをコピーします。

1. ダッシュボードで、**デベロッパー → Webhook → エンドポイント追加**に移動
2. **URL**: `https://your-tunnel.ngrok-free.app/webhooks/dodo`
3. 次に最低限のサブスクリプションを行う:
   - `credit.added`
   - `credit.deducted`
   - `credit.overage_charged`
4. 保存して**署名秘密**をコピー
5. `.env`に貼り付け、`DODO_PAYMENTS_WEBHOOK_KEY`として保存し、`npm run dev`を再起動

SDKの `dodo.webhooks.unwrap()` は、署名秘密を使って`webhook-id`, `webhook-timestamp`、`webhook-signature`ヘッダーを検証します。HMAC 検証を自分で手作業で実行する必要はありません — Dodo Paymentsは[Standard Webhooks](https://www.standardwebhooks.com/)を使用しており、ボディだけでなく、`id.timestamp.body`を署名します。

## トラブルシューティング

**考えられる原因:**
- メーターのイベント名が送信している`event_name` と一致していません（`api.tokens_used`は大文字小文字を区別します）
- メーターが製品の`API Tokens` クレジットにリンクされていません — 製品のメーター設定に進み、**Bill usage in Credits**がオンであることを確認
- `metadata.tokens`キーがメーターの「Over Property」フィールドと一致しません
- 顧客の付与が期限切れ（顧客のクレジット履歴を確認）

**確認すべきこと:**
1. **製品 → メーター**: メーターを開き、保存されているクレジット名が製品のリンクに表示されることを確認
2. メーターの**イベント**タブ — 控除前でも取り込まれたイベントはそこに表示されるべきです
3. **顧客 → \[顧客\] → クレジット**: 1, 2分以内に元帳の記入が表示されるべきです

**考えられる原因:**
- 顧客がまだチェックアウトを完了していません — クレジットは成功した支払い後にのみ発行されます
- 間違った`customer_id`でクエリを実行しています（ダッシュボードの`cus_...` ID を使用してください、自分のDB IDではありません）
- `CREDIT_ENTITLEMENT_ID`が製品に関連付けられたクレジットと一致していません

**確認すべきこと:**
**顧客 → \[顧客\] → クレジット**を開いてください。そこにクレジットが表示されていない場合、製品権限が添付されていないか、支払いが完了していなかった可能性があります。

**考えられる原因:**
- 超過は**プロ製品のクレジット添付**で有効になっていません（クレジットレベル設定はデフォルトです）
- 顧客が実際にスターターにいるのではなく、プロではありません
- 超過制限が0に設定されていました

**確認すべきこと:**
プロ → 権利 → クレジット → **超過を許可** がオンになっていることと、**単位あたりの価格**が `0.000005` (= 1Mトークンあたり $5; 先頭のゼロをダブルチェックしてください — フィールドは1Kあたりの価格ではなく、トークンあたりの価格を取ります)であることを確認してください。

**考えられる原因:**
- ボディパース順序: `express.json()`が`/webhooks/dodo`に適用され、`express.raw()`前に適用されました — SDKはリクエストの**生のバイト**を必要とします、解析されたJSONではありません
- `DODO_PAYMENTS_WEBHOOK_KEY` で間違った署名秘密

**確認すべきこと:**
`app.use('/webhooks/dodo', express.raw(...))`行が`app.use(express.json())`前に`server.ts`であることを確認してください。
