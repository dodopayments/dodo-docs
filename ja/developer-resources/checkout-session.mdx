<Tabs>
<Tab title="Node.js SDK">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'prod_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

import os
from dodopayments import DodoPayments

</Tip>
</Step>

<Step title="戻り処理を行う">

### 必須フィールド

<ParamField body="product_cart" type="array" required>
チェックアウトセッションに含める製品の配列。各製品はあなたのDodo Paymentsダッシュボードからの有効な `product_id` を持っている必要があります。

<Tip>
**ミックスCheckout**: 一度きりの支払い製品とサブスクリプション製品を同じCheckoutセッションで組み合わせることができます。これにより、サブスクリプションに対するセットアップ料金、ハードウェアバンドルとSaaSなどの強力なユースケースが可能になります。
</Tip>

<Expandable title="製品カートアイテムのプロパティ">
<ParamField body="product_id" type="string" required>
Dodo Paymentsダッシュボードからの製品の一意の識別子です。

**例:** `"prod_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
製品の数量です。

**例:** 単一アイテム用 `1`、複数数量用 `3`
</ParamField>

<ParamField body="addons" type="array">
製品に添付するアドオンの配列。製品がサブスクリプションの場合のみ有効です。

<Expandable title="アドオンアイテムのプロパティ">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
pay_what_you_wantが有効な場合、顧客が支払う金額です。無効な場合、このフィールドは無視されます。

**フォーマット**: 通貨の最小単位で表されます (例: USDの場合はセント)。例えば、$1.00を請求するには、`100`を渡します。
</ParamField>
</Expandable>
</ParamField>

<Tip>
**製品IDを見つける**: Dodo Paymentsダッシュボードの製品→詳細表示で製品IDを見つけるか、[製品リストAPI](/api-reference/products/get-products)を使用して見つけることができます。
</Tip>

<Accordion title="支払い設定">

<ParamField body="allowed_payment_method_types" type="array">
Checkout中に顧客が利用できる支払い方法を制御します。これにより、特定の市場やビジネス要件に最適化できます。

**利用可能なオプション**: `credit`、`debit`、`upi_collect`、`apple_pay`、`google_pay`、`amazon_pay`、`klarna`、`affirm`、`afterpay_clearpay`、`cashapp`、`multibanco`、`bancontact_card`、`eps`、`ideal`、`przelewy24`、`paypal`

<Accordion title="セッション管理">

<ParamField body="return_url" type="string">
支払い完了後に顧客をリダイレクトするURL。Dodo Paymentsはリダイレクト時に次のクエリパラメータをあなたのURLに追加します:

| パラメータ | 種類 | 条件 |
|-----------|------|-----------|
| `payment_id` | `string` | 一回限りの支払いに常に存在 |
| `subscription_id` | `string` | サブスクリプション支払いには常に存在 |
| `status` | `string` | 常に存在 |
| `license_key` | `string` | 製品にライセンスキーが有効な場合に存在。複数のキーがある場合はカンマ区切り |
| `email` | `string` | 顧客に記録されたメールがある場合に存在 |

**例のリダイレクトURL:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
`license_key` および `email` クエリパラメータを使用して、ライセンスキーを表示したり、あなたの戻りページでの確認を即座に行ったりできます。追加のAPI呼び出しを必要とせずに。
</Tip>
</ParamField>

<ParamField body="confirm" type="boolean" default="false">
trueの場合、すべてのセッション詳細を即座に確定します。必要なデータが欠けている場合、APIはエラーを返します。
</ParamField>

<ParamField body="discount_code" type="string">
チェックアウトセッションに割引コードを適用します。
</ParamField>

<ParamField body="metadata" type="object">
セッションに関する追加情報を保存するためのカスタムキーと値のペア。
</ParamField>

<ParamField body="force_3ds" type="boolean">
このセッションのために商人のデフォルトの3DS動作をオーバーライドします。
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
最小住所収集モードを有効にします。有効にすると、チェックアウトは次の情報のみを収集します:
- **国**: 課税判断のために常に必要
- **ZIP/郵便番号**: 売上税、VAT、またはGST計算のために必要な地域でのみ


これにより、不必要なフォームフィールドを排除することでチェックアウトの摩擦が大幅に減少します。

<Tip>
迅速なチェックアウト完了のために最小住所を有効にします。完全な住所収集は完全な請求先詳細が必要なビジネスのために依然として利用可能です。
</Tip>
</ParamField>

</ParamField>

<ParamField body="allow_customer_editing_city" type="boolean">
顧客がチェックアウト中に市を編集できるようにします。
</ParamField>

<ParamField body="allow_customer_editing_state" type="boolean">
顧客がチェックアウト中に州を編集できるようにします。
</ParamField>

<ParamField body="allow_customer_editing_country" type="boolean">
顧客がチェックアウト中に国を編集できるようにします。
</ParamField>

<ParamField body="allow_customer_editing_zipcode" type="boolean">
顧客がチェックアウト中に郵便番号を編集できるようにします。
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
最小住所収集モードを有効にします。有効にすると、チェックアウトは次の情報のみを収集します:
- **国**: 課税判断のために常に必要
- **ZIP/郵便番号**: 売上税、VAT、またはGST計算のために必要な地域でのみ


これにより、不必要なフォームフィールドを排除することでチェックアウトの摩擦が大幅に減少します。

<Tip>
迅速なチェックアウト完了のために最小住所を有効にします。完全な住所収集は完全な請求先詳細が必要なビジネスのために依然として利用可能です。
</Tip>
</ParamField>

<ParamField body="redirect_immediately" type="boolean" default="false">

<Tip>
これは、より良いユーザーエクスペリエンスを提供するカスタム成功ページがある場合や、モバイルアプリや埋め込みチェックアウトフローに最適です。

</ParamField>
</Expandable>
</ParamField>

### 11. 即時チェックアウトのための既存の支払い方法の使用

顧客の保存された支払い方法を使用して、即時に処理されるチェックアウトセッションを作成します。支払い方法の収集をスキップします:

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'prod_premium_plan',
      quantity: 1
    }
  ],
  customer: {
    customer_id: 'cus_123'  // Required when using payment_method_id
  },
  payment_method_id: 'pm_abc123',  // Use customer's saved payment method
  confirm: true,  // Required when using payment_method_id
  return_url: 'https://yourapp.com/success'
});
```

<Warning>
`payment_method_id` を使用する場合、`confirm` は `true` に設定され、既存の `customer_id` が提供されなければなりません。支払い方法は、支払いの通貨に対して適格性が確認されます。
</Warning>

<Info>
支払い方法は顧客に属し、支払い通貨と互換性がある必要があります。これにより、再訪顧客のためのワンクリック購入が可能になります。
</Info>

```javascript expandable
const session = await client.checkoutSessions.create({

    {
      product_id: 'prod_monthly_subscription',

    }
  ],

  return_url: 'https://yourapp.com/success',

  }

// The checkout_url will be a shortened, cleaner link
console.log(session.checkout_url);  // e.g., https://checkout.dodopayments.com/buy/abc123
```

<Tip>
短縮リンクはSMS、メール、またはソーシャルメディアの共有に最適です。長いURLよりも覚えやすくなり、顧客の信頼を築きます。
</Tip>

### 13. 支払い成功ページをスキップして即時リダイレクト

</Tip>

<Note>
`redirect_immediately` が有効な場合、支払い完了後に顧客はあなたの `return_url` に即座にリダイレクトされ、デフォルトの成功ページを完全にバイパスします。
</Note>

## ダイナミックリンクからチェックアウトセッションへの移行

### 主要な違い
以前、ダイナミックリンクで支払いリンクを作成するには、顧客の完全な請求先住所を提供する必要がありました。

チェックアウトセッションでは、これがもはや必要ありません。持っている情報だけを渡せば、残りは私たちが処理します。例えば、次のようになります:
- 顧客の請求先国を知っているだけの場合は、それを提供してください。
- チェックアウトフローは自動的に欠けている詳細を収集し、顧客を支払いページに移動します。
- 一方、すでに必要な情報がすべてあって、支払いページに直接進みたい場合は、完全なデータセットを渡し、リクエストボディに `confirm=true` を含めることができます。

</Step>

<Step title="それだけです！">

</Step>

</Step>
</Steps>
