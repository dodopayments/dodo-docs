## インストール

<Steps>
<Step title="パッケージをインストール">
プロジェクトのルートで以下のコマンドを実行します:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="環境変数を設定">
プロジェクトのルートに<code>.env</code>ファイルを作成します:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
<code>.env</code>ファイルや秘密の情報をバージョン管理にコミットしないでください。
</Warning>
</Step>
</Steps>

## ルートハンドラーの例

<Info>
すべての例は、<code>Bun.serve()</code>を使用してBunのネイティブサーバーを使用していることを前提としています。
</Info>

<Tabs>
<Tab title="チェックアウトハンドラー">
  <Info>
  このハンドラーを使用して、Dodo PaymentsのチェックアウトをBunサーバーに統合します。静的（GET）、動的（POST）、およびセッション（POST）支払いフローをサポートします。
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>

## チェックアウトルートハンドラー

<Info>
Dodo Paymentsは、ウェブサイトに支払いを統合するための3種類の支払いフローをサポートしています。このアダプターはすべてのタイプの支払いフローをサポートします。
</Info>

- **静的支払いリンク：** コード不要で即座に共有できるURLによる迅速な支払い収集。
- **動的支払いリンク：** APIまたはSDKを使用してカスタム詳細を持つ支払いリンクをプログラム的に生成します。
- **チェックアウトセッション：** 事前設定された商品カートと顧客詳細を使用して、安全でカスタマイズ可能なチェックアウト体験を提供します。

### レスポンス形式
静的チェックアウトは、チェックアウトURLを含むJSONレスポンスを返します:

```json

}
```

</Accordion>
<Accordion title="動的チェックアウト (POST)">
- パラメータをPOSTリクエストのJSONボディとして送信します。
- 一回限りの支払いと定期的な支払いの両方をサポートします。
- サポートされているすべてのPOSTボディフィールドの完全なリストについては:
  - [一回限りの支払い商品のリクエストボディ](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [サブスクリプション商品のリクエストボディ](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### レスポンス形式
動的チェックアウトは、チェックアウトURLを含むJSONレスポンスを返します:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="チェックアウトセッション (POST)">
チェックアウトセッションは、完全な支払いフローを処理する安全でホストされたチェックアウト体験を提供し、一回限りの購入とサブスクリプションに対して完全なカスタマイズ制御を行います。

詳細な情報やサポートされているフィールドの完全なリストについては、[チェックアウトセッション統合ガイド](https://docs.dodopayments.com/developer-resources/checkout-session)を参照してください。

### レスポンス形式
チェックアウトセッションは、チェックアウトURLを含むJSONレスポンスを返します:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>
</AccordionGroup>

## カスタマーポータルルートハンドラー

カスタマーポータルルートハンドラーを使用すると、Dodo PaymentsのカスタマーポータルをBunサーバーアプリケーションにシームレスに統合できます。

### クエリパラメータ
<ParamField query="customer_id" type="string" required>
ポータルセッションの顧客ID（例：<code>?customer_id=cus_123</code>）。
</ParamField>
<ParamField query="send_email" type="boolean">
<code>true</code>に設定されている場合、ポータルリンクを顧客にメールで送信します。
</ParamField>

<Warning>
<code>customer_id</code>が欠落している場合、400が返されます。
</Warning>

## Webhookルートハンドラー

- **メソッド：** POSTリクエストのみがサポートされています。他のメソッドは405を返します。
- **署名検証：** <code>webhookKey</code>を使用してWebhook署名を検証します。検証に失敗した場合は401を返します。
- **ペイロード検証：** Zodで検証済み。無効なペイロードには400を返します。
- **エラーハンドリング：**
  - 401: 無効な署名
  - 400: 無効なペイロード
  - 500: 検証中の内部エラー
- **イベントルーティング：** ペイロードタイプに基づいて適切なイベントハンドラーを呼び出します。
