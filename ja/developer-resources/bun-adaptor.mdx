## インストール

<Steps>
<Step title="Install the package">
プロジェクトのルートで次のコマンドを実行します:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
プロジェクトのルートに <code>.env</code> ファイルを作成します:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
<code>.env</code> ファイルやシークレットをバージョン管理にコミットしないでください。
</Warning>
</Step>
</Steps>

## Route Handler の例

<Info>
すべての例では、<code>Bun.serve()</code> を使用した Bun のネイティブサーバーを前提としています。
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  この handler を使用して、Bun サーバーに Dodo Payments checkout を統合します。static (GET)、dynamic (POST)、session (POST) の支払いフローに対応しています。
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>

## Checkout Route Handler

<Info>
Dodo Payments は、Web サイトに決済を統合するための3種類の支払いフローに対応しており、この adaptor はすべての支払いフローをサポートします。
</Info>

- **Static Payment Links:** すぐに共有でき、コード不要で迅速に支払いを受け付けられる URL。
- **Dynamic Payment Links:** API または SDKs を使用して、カスタム詳細を含む payment links をプログラムで生成します。
- **Checkout Sessions:** 事前設定された product carts と customer details を使用して、安全でカスタマイズ可能な checkout エクスペリエンスを作成します。

### Response Format
Static checkout は checkout URL を含む JSON response を返します:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- POST request の JSON body として parameters を送信します。
- one-time payments と recurring payments の両方をサポートします。
- サポートされている POST body fields の完全な一覧については、以下を参照してください:
  - [Request body for a One Time Payment Product](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Request body for a Subscription Product](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Response Format
Dynamic checkout は checkout URL を含む JSON response を返します:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Checkout sessions は、より安全な hosted checkout エクスペリエンスを提供します。one-time purchases と subscriptions の両方について、完全な支払いフローを処理し、詳細なカスタマイズ制御が可能です。

詳細およびサポートされている fields の完全な一覧については、[Checkout Sessions Integration Guide](https://docs.dodopayments.com/developer-resources/checkout-session) を参照してください。

### Response Format
Checkout sessions は checkout URL を含む JSON response を返します:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Customer Portal Route Handler

Customer Portal Route Handler を使用すると、Bun サーバーアプリケーションに Dodo Payments customer portal をシームレスに統合できます。

### Query Parameters
<ParamField query="customer_id" type="string" required>
portal session の customer ID (例: <code>?customer_id=cus_123</code>)。
</ParamField>
<ParamField query="send_email" type="boolean">
<code>true</code> に設定すると、customer portal の link を顧客に email で送信します。
</ParamField>

<Warning>
<code>customer_id</code> がない場合は 400 を返します。
</Warning>

## Webhook Route Handler

- **Method:** POST requests のみサポートされます。その他の methods には 405 を返します。
- **Signature Verification:** <code>webhookKey</code> を使用して webhook signature を検証します。検証に失敗した場合は 401 を返します。
- **Payload Validation:** Zod で検証します。無効な payload には 400 を返します。
- **Error Handling:**
  - 401: Invalid signature
  - 400: Invalid payload
  - 500: 検証中の Internal error
- **Event Routing:** payload type に基づいて適切な event handler を呼び出します。
