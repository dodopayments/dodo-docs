## メーターの作成

メーターは、課金目的で使用量イベントを集計・測定する方法を定義します。

メーターを作成する前に、使用量の追跡戦略を計画します。
- 追跡する使用量イベントを特定する
- イベントの集計方法（count、sum など）を決定する
- 特定のユースケースに必要なフィルタリング要件を定義する

### メーター作成の手順

この包括的なガイドに従って、使用量メーターを設定します。

<Steps>
<Step title="Configure Basic Information">
メーターの基本的な詳細を設定します。

<ParamField path="Meter Name" type="string" required>
このメーターが追跡する対象を識別できる、明確で説明的な名前を選択します。

例: "Tokens"、"API Calls"、"Storage Usage"、"Compute Hours"
</ParamField>

<ParamField path="Description" type="string">
このメーターが測定する内容を詳しく説明します。

例: "顧客が実行した各 POST /v1/orders リクエストをカウント"
</ParamField>

<ParamField path="Event Name" type="string" required>
このメーターをトリガーするイベント識別子を指定します。

例: "token"、"api.call"、"storage.usage"、"compute.session"
</ParamField>

<Info>
イベント名は、使用量イベントで送信する値と完全に一致する必要があります。イベント名では大文字と小文字が区別されます。
</Info>
</Step>

<Step title="Configure Aggregation Settings">
メーターがイベントから使用量を計算する方法を定義します。

<ParamField path="Aggregation Type" type="string" required>
イベントの集計方法を選択します。

<Tabs>
<Tab title="Count">
受信したイベント数を単純にカウントします。

ユースケース: API 呼び出し、ページビュー、ファイルアップロード

計算: イベントの総数
</Tab>

<Tab title="Sum">
イベント内の特定のプロパティの値を合計します。

ユースケース: データ転送、ストレージ消費量、処理時間

計算: すべてのプロパティ値の合計
</Tab>

<Tab title="Max">
課金期間中に特定のプロパティで記録された最大値を記録します。

ユースケース: ピーク時の同時接続ユーザー数、最大ストレージ使用量、最大帯域幅

計算: 観測されたプロパティ値の最大値
</Tab>

<Tab title="Last">
特定のプロパティの最新値を使用します。

ユースケース: 現在のプラン tier、最新の設定値

計算: 最後に記録されたプロパティ値
</Tab>
</Tabs>
</ParamField>

<ParamField path="Over Property" type="string">
集計対象となるイベントメタデータのプロパティ名です。

<Warning>
Sum、Max、Last の集計タイプを使用する場合、このフィールドは必須です。
</Warning>
</ParamField>

<ParamField path="Measurement Unit" type="string" required>
レポートと課金画面に表示する単位ラベルを定義します。

例: "calls"、"GB"、"hours"、"tokens"
</ParamField>
</Step>

<Step title="Configure Event Filtering (Optional)">
メーターに含めるイベントを制御する条件を設定します。

<Info>
イベントフィルタリングを使用すると、使用量の計算に含めるイベントを決定する高度なルールを作成できます。テストイベントの除外、ユーザー tier によるフィルタリング、特定のアクションへの絞り込みなどに便利です。
</Info>

**イベントフィルタリングを有効にする**

**イベントフィルタリングを有効にする**を切り替えて、条件付きイベント処理を有効にします。

**フィルターロジックを選択する**

複数の条件を評価する方法を選択します。

<Tabs>
<Tab title="AND Logic">
イベントをカウントするには、すべての条件が true である必要があります。複数の厳密な条件を同時に満たすイベントが必要な場合に使用します。

**例:** `user_tier = "premium"` AND `endpoint = "/api/v2/users"` を満たす API 呼び出しをカウント
</Tab>

<Tab title="OR Logic">
イベントをカウントするには、少なくとも 1 つの条件が true である必要があります。複数の条件のいずれかを満たすイベントを含めたい場合に使用します。

**例:** `method = "POST"` OR `method = "PUT"` OR `method = "DELETE"` を満たすイベントをカウント
</Tab>
</Tabs>

**フィルター条件を設定する**

<Steps>
<Step title="Add Condition">
**Add condition**をクリックして、新しいフィルタールールを作成します。
</Step>

<Step title="Configure Property Key">
イベントメタデータのプロパティ名を指定します。
</Step>

<Step title="Select Comparator">
使用可能な演算子から選択します。
- `equals` - 完全一致
- `not_equals` - 除外フィルター
- `greater_than` - 数値比較  
- `greater_than_or_equals` - 数値比較（指定値を含む）
- `less_than` - 数値比較
- `less_than_or_equals` - 数値比較（指定値を含む）
- `contains` - 文字列に部分文字列を含む
- `does_not_contain` - 文字列除外フィルター
</Step>

<Step title="Set Comparison Value">
比較対象の値を設定します。
</Step>

<Step title="Add Groups">
**Add Group**を使用して、複雑なロジック用の追加の条件グループを作成します。
</Step>
</Steps>

<Warning>
条件を正しく機能させるには、フィルタリングするプロパティをイベントメタデータに含める必要があります。必須プロパティがないイベントはカウントから除外されます。
</Warning>
</Step>

<Step title="Create Meter">
メーター設定を確認し、**Create Meter**をクリックします。

<Check>
これでメーターは使用量イベントを受信し、集計できる状態になりました。
</Check>

</Step>
</Steps>

## 商品でメーターをリンクする

メーターを作成したら、使用量ベースの課金を有効にするため、商品にリンクする必要があります。この処理により、メーターの使用量データが顧客への課金用の価格ルールに接続されます。

メーターを商品にリンクすると、使用量の追跡と課金が接続されます。
- 商品は価格ルールと課金動作を定義する
- メーターは課金計算に使用するデータを提供する
- 複雑な課金シナリオでは、1 つの商品に複数のメーターをリンクできる

### 商品設定の手順

商品設定を適切に構成して、使用量データを請求可能な料金に変換します。

<Steps>
<Step title="Choose Usage-Based Billing Product Type">
商品作成または編集ページに移動し、商品タイプとして**Usage-Based**を選択します。

</Step>

<Step title="Select Associated Meter">
**Associated Meter**をクリックして、側面からメーター選択パネルを開きます。

このパネルで、この商品で使用量を追跡するメーターを設定できます。
</Step>

<Step title="Add Your Meter">
メーター選択パネルで次の操作を行います。

1. **Add Meters**をクリックして、使用可能なメーターを表示する
2. ドロップダウンリストから作成したメーターを選択する
3. 選択したメーターが商品の設定に表示される

</Step>

<Step title="Configure Price Per Unit">
メーターで追跡する使用量の各単位の価格を設定します。

<ParamField path="Price Per Unit" type="number" required>
メーターで測定する各単位に課金する金額を定義します。

**例**: 1 単位あたり `$0.50` に設定すると、次のようになります。
- 1,000 単位を消費 = 1,000 × $0.50 = 500.00 を課金
- 500 単位を消費 = 500 × $0.50 = 250.00 を課金
- 100 単位を消費 = 100 × $0.50 = 50.00 を課金
</ParamField>

</Step>

<Step title="Set Free Threshold (Optional)">
課金開始前の無料使用量を設定します。

<ParamField path="Free Threshold" type="number">
有料使用量の計算が始まる前に、顧客が無料で利用できる単位数です。

**仕組み**:
- 無料しきい値: 100 単位
- 1 単位あたりの価格: $0.50
- 顧客の使用量: 250 単位
- **計算**: (250 - 100) × $0.50 = **$75.00** を課金
</ParamField>

<Info>
無料しきい値は、フリーミアムモデルやトライアル期間、プランに含まれる基本利用量の提供に適しています。
</Info>

<Check>
無料しきい値は各課金サイクルに適用されるため、顧客には毎月、または設定した課金スケジュールに従って新しい無料枠が付与されます。
</Check>
</Step>

<Step title="Save Configuration">
メーターと価格設定を確認し、**Save Changes**をクリックして設定を完了します。

<Check>
これで商品は使用量ベースの課金用に設定され、測定された消費量に基づいて顧客に自動的に課金されます。
</Check>

**次に行われること**:
- メーターに送信された使用量イベントが追跡・集計される
- 価格ルールが課金計算に自動的に適用される
- 各課金サイクル中の実際の消費量に基づいて顧客に課金される
</Step>
</Steps>

<Note>
1 商品あたり最大 10 個のメーターを追加できるため、API 呼び出し、ストレージ、計算時間、カスタムメトリクスなど、複数の軸にわたる高度な使用量追跡が可能です。
</Note>

## 使用量イベントの送信

メーターを設定したら、アプリケーションから使用量イベントを送信して顧客の使用量を追跡できます。

### イベント構造

各使用量イベントには、次の必須フィールドを含める必要があります。

<ParamField body="event_id" type="string" required>
このイベント固有の一意の識別子です。すべてのイベントで一意である必要があります。
</ParamField>

<ParamField body="customer_id" type="string" required>
この使用量を帰属させる Dodo Payments customer ID です。
</ParamField>

<ParamField body="event_name" type="string" required>
メーター設定と一致するイベント名です。イベント名によって適切なメーターがトリガーされます。
</ParamField>

<ParamField body="timestamp" type="string">
イベント発生時刻の ISO 8601 タイムスタンプです。指定しない場合は現在時刻が使用されます。
</ParamField>

<ParamField body="metadata" type="object">
フィルタリングと集計に使用する追加プロパティです。メーターの "Over Property" またはフィルタリング条件で参照する値を含めます。
</ParamField>

### 使用量イベント API の例

Events API を使用して、設定済みのメーターに使用量イベントを送信します。

<CodeGroup>

```javascript Node.js
const response = await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${process.env.DODO_PAYMENTS_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [
      {
        event_id: "api_call_1234",
        customer_id: "cus_atXa1lklCRRzMicTqfiw2", 
        event_name: "api.call",
        timestamp: new Date().toISOString(),
        metadata: {
          endpoint: "/v1/orders",
          method: "POST",
          response_size: 1024
        }
      }
    ]
  })
});
```

```python Python
import requests
from datetime import datetime

response = requests.post(
    'https://test.dodopayments.com/events/ingest',
    headers={
        'Authorization': f'Bearer {api_key}',

    },
    json={
        'events': [
            {
                'event_id': 'api_call_1234',
                'customer_id': 'cus_atXa1lklCRRzMicTqfiw2',
                'event_name': 'api.call',
                'timestamp': datetime.now().isoformat(),
                'metadata': {
                    'endpoint': '/v1/orders',
                    'method': 'POST',
                    'response_size': 1024
                }
            }
        ]
    }
)
```

## 使用量ベースの課金分析

包括的な分析ダッシュボードで、使用量ベースの課金データを監視・分析します。顧客の消費パターン、メーターのパフォーマンス、課金傾向を追跡して、価格戦略を最適化し、使用状況を把握できます。

### 概要分析

Overview タブでは、使用量ベースの課金パフォーマンスを包括的に確認できます。

#### アクティビティメトリクス

さまざまな期間の主要な使用量統計を追跡します。

<ParamField path="Current Month" type="metric">
現在の課金期間の使用状況を表示し、月ごとの消費パターンを把握できます。
</ParamField>

<ParamField path="All Time" type="metric">
追跡を開始してからの累積使用量統計を表示し、長期的な成長を把握できます。
</ParamField>

<Tip>
期間セレクターを使用して月ごとの使用量を比較し、季節的な傾向や成長パターンを特定します。
</Tip>

#### メーター数量チャート

<Frame>
<img src="/images/guides/usage-based-billing/meter-quantities-chart.png" alt="使用量の傾向を紫色のグラデーションで表示するメーター数量チャート" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

メーター数量チャートでは、次の機能によって時間の経過に伴う使用量の傾向を可視化します。

- **時系列の可視化**: 日、週、月ごとの使用量パターンを追跡
- **複数メーターのサポート**: 異なるメーターのデータを同時に表示
- **傾向分析**: 使用量の急増、パターン、成長の推移を特定

<Info>
チャートは使用量と選択した期間に基づいて自動的に拡大縮小され、小さな変動から大きな使用量の変化まで明確に確認できます。
</Info>

### イベント分析

<Frame>
<img src="/images/guides/usage-based-billing/events-table.png" alt="詳細なイベント分析のためにイベント名、ID、ページネーションコントロールを表示するイベントテーブル" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

Events タブでは、個々の使用量イベントを詳細に確認できます。

#### イベント情報の表示

イベントテーブルには、個々の使用量イベントについて次の列が表示されます。

- **イベント名**: 使用量イベントを生成した具体的なアクションまたはトリガー
- **イベント ID**: 各イベントインスタンスの一意の識別子
- **Customer ID**: イベントに関連付けられた顧客
- **タイムスタンプ**: イベントが発生した時刻

<Info>
このビューでは顧客全体の個々の使用量イベントを追跡・監視でき、課金計算と使用量パターンを透明性高く確認できます。
</Info>

### 顧客分析

Customers タブには、次の情報を含む顧客使用量データの詳細なテーブルが表示されます。

#### 使用可能なデータ列

<ParamField path="Customer Email" type="string">
識別に使用する顧客のメールアドレスです。
</ParamField>

<ParamField path="Subscription ID" type="string">
顧客のサブスクリプションの一意の識別子です。
</ParamField>

<ParamField path="Free Threshold" type="number">
課金前に顧客のプランに含まれる無料単位数です。
</ParamField>

<ParamField path="Price Per Unit" type="currency">
無料しきい値を超えた使用量に対する 1 単位あたりの料金です。
</ParamField>

<ParamField path="Last Event" type="timestamp">
顧客の最新の使用量イベントのタイムスタンプです。
</ParamField>

<ParamField path="Total Price" type="currency">
使用量ベースの課金で顧客に請求した合計金額です。
</ParamField>

<ParamField path="Consumed Units" type="number">
顧客が消費した単位数の合計です。
</ParamField>

<ParamField path="Chargeable Units" type="number">
無料しきい値を超え、課金対象となっている単位数です。
</ParamField>

#### テーブルの機能

- **列のフィルタリング**: "Edit Columns" 機能を使用して、特定のデータ列を表示または非表示にする
- **リアルタイム更新**: 使用量データには最新の消費量メトリクスが反映される

## 集計の例

異なる集計タイプの実際の動作例を紹介します。

### 集計タイプについて

集計タイプごとに適した課金シナリオが異なります。使用量の測定方法と課金方法に基づいて、適切なタイプを選択してください。

### 実装例

各集計タイプについて、サンプルイベントと期待される結果を用いた実際の適用例を示します。

<AccordionGroup>
<Accordion title="Count Aggregation - API Calls">
シナリオ: API リクエストの総数を追跡する

メーター設定:
- イベント名: `api.call`
- 集計タイプ: Count
- 測定単位: `calls`

**サンプルイベント**:

```json
{
  "events": [
    {"event_id": "call_1", "customer_id": "cus_123", "event_name": "api.call"},
    {"event_id": "call_2", "customer_id": "cus_123", "event_name": "api.call"},
    {"event_id": "call_3", "customer_id": "cus_123", "event_name": "api.call"}
  ]
}
```

結果: 顧客に 3 calls を課金
</Accordion>

<Accordion title="Sum Aggregation - Data Transfer">
シナリオ: 転送したバイト数の合計に基づいて課金する

メーター設定:
- イベント名: `data.transfer`
- 集計タイプ: Sum
- Over Property: `bytes`
- 測定単位: `GB`

**サンプルイベント**:

```json
{
  "events": [
    {
      "event_id": "transfer_1",
      "customer_id": "cus_123",

    },
    {
      "event_id": "transfer_2",
      "customer_id": "cus_123",
      "event_name": "data.transfer", 
      "metadata": {"bytes": 536870912}
    }
  ]
}
```

結果: 合計 1.5 GB の転送量を顧客に課金
</Accordion>

<Accordion title="Max Aggregation - Peak Concurrent Users">

メーター設定:
- イベント名: `concurrent.users`

</Accordion>

### イベントフィルタリングの例

<Tabs>
<Tab title="Filter by API Endpoint">
特定のエンドポイントへの API 呼び出しのみをカウントします。

フィルター設定:
- プロパティ: `endpoint`
- 比較演算子: `equals`
- 値: `/v1/orders`

サンプルイベント:

```json
{
  "event_id": "call_1",
  "customer_id": "cus_123",
  "event_name": "api.call",
  "metadata": {
    "endpoint": "/v1/orders",
    "method": "POST"
  }
}
```

結果: フィルター条件に一致するイベントがカウントされます。異なるエンドポイントのイベントは無視されます。
</Tab>

<Tab title="Filter by Value Range">
大きなファイルのアップロードのみをカウントします。

フィルター設定:
- プロパティ: `file_size`
- 比較演算子: `greater_than`
- 値: `1048576`（バイト単位で 1MB）

サンプルイベント:

```json
{
  "event_id": "upload_1",
  "customer_id": "cus_123", 
  "event_name": "file.upload",
  "metadata": {
    "file_size": 5242880,
    "file_type": "image"
  }
}
```

結果: 1MB を超えるファイルがカウントされます。小さいファイルは無視されます。
</Tab>

<Tab title="Complex Multi-Condition Filters">

フィルター設定（AND ロジックを使用）:
- プロパティ: `plan_type`、比較演算子: `equals`、値: `premium`

## トラブルシューティング

使用量ベースの課金実装に関する一般的な問題を解決し、正確な追跡と課金を実現します。

### 一般的な問題

使用量ベースの課金に関する問題の多くは、次のカテゴリに分類されます。
- イベントの配信および処理の問題
- メーター設定の問題
- データ型およびフォーマットのエラー
- Customer ID および認証の問題

### デバッグ手順

使用量ベースの課金をトラブルシューティングする場合:
1. Events 分析タブでイベントの配信を確認する
2. メーター設定がイベント構造と一致していることを確認する
3. Customer ID と API 認証を検証する
4. フィルタリング条件と集計設定を確認する

### 解決策と修正方法

<AccordionGroup>
<Accordion title="Events not showing in meter">
一般的な原因:
- イベント名がメーター設定と完全には一致していない
- イベントフィルタリング条件によってイベントが除外されている
- Customer ID が Dodo Payments アカウントに存在しない
- イベントのタイムスタンプが現在の課金期間外である

解決策:
- イベント名のスペルと大文字・小文字を確認する
- フィルタリング条件を確認してテストする
- Customer ID が有効でアクティブであることを確認する
- イベントのタイムスタンプが新しく、正しい形式であることを確認する
</Accordion>

<Accordion title="Aggregation not working as expected">
一般的な原因:
- Over Property 名がイベントメタデータのキーと一致していない
- メタデータ値のデータ型が正しくない（string と number）
- 必須メタデータプロパティがない

解決策:
- メタデータキーが Over Property の設定と完全に一致することを確認する
- イベント内の文字列形式の数値を実際の数値に変換する
- すべてのイベントに必須プロパティを含める
</Accordion>

<Accordion title="Filtering not working">
一般的な原因:
- フィルタープロパティ名がイベントメタデータと一致していない
- データ型に対して誤った比較演算子を使用している（string と number）
- 文字列比較で大文字と小文字が区別されている

解決策:
- プロパティ名が完全に一致することを再確認する
- データ型に適した比較演算子を使用する
- 文字列のフィルタリングでは大文字と小文字の区別を考慮する
</Accordion>
</AccordionGroup>
