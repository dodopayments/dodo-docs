<Info>
Dodo Payments は、**Android、iOS、React Native、
Flutter** 向けの公式 checkout SDK を提供しています。それぞれ、以下で説明するパターン（checkout
URL を開き、戻り値を取得し、結果を解析する処理）を、放棄されたセッションの復旧機能を組み込んだ単一の型付き `start(...)`
呼び出しとしてラップします。手動の WebView は、いずれもご利用の技術スタックに適合しない場合にのみ使用してください。
</Info>

## 前提条件

Dodo Payments をモバイルアプリに統合する前に、以下を準備してください。

- **Dodo Payments アカウント**: API access が有効なアクティブな merchant account
- **API Credentials**: ダッシュボードから取得した API key と webhook secret key
- **Mobile App Project**: Android、iOS、React Native、または Flutter application
- **Backend Server**: checkout session の作成を安全に処理するためのサーバー

## Integration Workflow

モバイル統合では、backend が API calls を処理し、mobile app が user experience を管理する、安全な 4 段階のプロセスに従います。

<Steps>
<Step title="Backend: Create Checkout Session">
<Card title="Checkout Session API Docs" icon="book" href="/developer-resources/checkout-session">
Node.js、Python などを使用して backend で checkout session を作成する方法を説明します。完全な例と parameter references については、専用の <strong>Checkout Sessions API</strong> documentation を参照してください。
</Card>
<Note>
**Security**: checkout sessions は必ず backend server で作成し、mobile app では作成しないでください。これにより API keys が保護され、適切な validation が確実に行われます。
</Note>

</Step>

<Step title="Mobile: Get Checkout URL">

mobile app は backend を呼び出して checkout URL を取得します。この request には、サインイン済みユーザー自身の session token を使用して authenticate してください。

<Tabs>
<Tab title="iOS (Swift)">

```swift
func getCheckoutURL(productId: String, customerEmail: String, customerName: String) async throws -> String {
    let url = URL(string: "https://your-backend.com/api/create-checkout-session")!
    var request = URLRequest(url: url)
    request.httpMethod = "POST"
    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
    request.setValue("Bearer \(userSessionToken)", forHTTPHeaderField: "Authorization")
    
    let requestData: [String: Any] = [
        "productId": productId,
        "customerEmail": customerEmail,
        "customerName": customerName
    ]
    request.httpBody = try JSONSerialization.data(withJSONObject: requestData)
    
    let (data, _) = try await URLSession.shared.data(for: request)
    let response = try JSONDecoder().decode(CheckoutResponse.self, from: data)
    return response.checkout_url
}
```

</Tab>
<Tab title="Android (Kotlin)">

```kotlin
suspend fun getCheckoutURL(productId: String, customerEmail: String, customerName: String): String {
    val client = OkHttpClient()
    val requestBody = JSONObject().apply {
        put("productId", productId)
        put("customerEmail", customerEmail)
        put("customerName", customerName)
    }.toString().toRequestBody("application/json".toMediaType())
    
    val request = Request.Builder()
        .url("https://your-backend.com/api/create-checkout-session")
        .header("Authorization", "Bearer $userSessionToken")
        .post(requestBody)
        .build()
    
    val response = client.newCall(request).execute()
    val responseBody = response.body?.string()
    val jsonResponse = JSONObject(responseBody ?: "")
    return jsonResponse.getString("checkout_url")
}
```

</Tab>
<Tab title="React Native (JavaScript)">

```javascript
const getCheckoutURL = async (productId, customerEmail, customerName) => {
  try {
    const response = await fetch('https://your-backend.com/api/create-checkout-session', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${userSessionToken}`,
      },
      body: JSON.stringify({
        productId,
        customerEmail,
        customerName
      })
    });
    
    const data = await response.json();
    return data.checkout_url;
  } catch (error) {
    console.error('Failed to get checkout URL:', error);
    throw error;
  }
};
```

</Tab>
<Tab title="Flutter (Dart)">

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<String> getCheckoutUrl({
  required String productId,
  required String customerEmail,
  required String customerName,
}) async {
  final response = await http.post(
    Uri.parse('https://your-backend.com/api/create-checkout-session'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $userSessionToken',
    },
    body: jsonEncode({
      'productId': productId,
      'customerEmail': customerEmail,
      'customerName': customerName,
    }),
  );

  if (response.statusCode != 200) {
    throw Exception('Failed to get checkout URL: ${response.statusCode}');
  }
  return jsonDecode(response.body)['checkout_url'] as String;
}
```

## SDK を選択

すべての mobile SDK は同じ contract を公開します。1 回の `start(...)` 呼び出しで、platform の native browser surface にある Dodo の
hosted checkout を開き、`CheckoutResult` を型付きで返します。その `status` は `succeeded`、`failed`、`cancelled`、
`pending`、または `expired` です。いずれも API key を保持したり Dodo
Payments API を呼び出したりすることはなく、4 つすべてが abandoned-session recovery をサポートします。

<CardGroup cols={2}>
<Card title="Android" icon="android" href="/developer-resources/sdks/android">
  `com.dodopayments.api:checkout-android` は Chrome Custom Tab を開きます。`minSdk` 23 以降が必要です。
</Card>
<Card title="iOS" icon="apple" href="/developer-resources/sdks/ios">
  `dodopayments-mobile-sdk-ios` は `SFSafariViewController` を開きます。iOS 16 以降が必要です。
</Card>
<Card title="React Native" icon="react" href="/developer-resources/sdks/react-native">
  `@dodopayments/react-native-checkout` は、両方の native core 上で動作する Turbo Module です。React Native 0.76 以降が必要です。
</Card>
<Card title="Flutter" icon="layer-group" href="/developer-resources/sdks/flutter">
  `dodopayments_checkout` は、両方の native core 上で動作する Pigeon channel です。Flutter 3.44 以降が必要です。
</Card>
</CardGroup>

<Warning>
返される `status` は UI hint であり、payment の証明ではありません。すべての payment は、backend から `payment.succeeded` / `subscription.active`
webhook を通じて確認するか、secret key を使用して payment を取得し、確認してください。
</Warning>

### Callback URL Scheme の登録

4 つの SDK はすべて、指定した custom URL scheme を通じて app に制御を戻します。例: `myapp://checkout/return`。各
platform で 1 回登録してください。

<Tabs>
<Tab title="Android">

```kotlin android/app/build.gradle
android {
    defaultConfig {
        manifestPlaceholders["dodoCallbackScheme"] = "myapp"
    }
}
```

SDK 自体の manifest には redirect activity がすでに宣言されているため、追加する manifest XML はありません。
</Tab>
<Tab title="iOS">

```xml Info.plist
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLName</key>
    <string>myapp</string>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>myapp</string>
    </array>
  </dict>
</array>
```

iOSでは、SDKに受信URLも転送する必要があります。これは
`SFSafariViewController` 自身の戻り先URLを捕捉できないためです。正確な
handlerについては、[iOS](/developer-resources/sdks/ios) または
[React Native](/developer-resources/sdks/react-native) のページを参照してください。
</Tab>
<Tab title="Expo">
`@dodopayments/react-native-checkout` には、両プラットフォームのschemeを
`prebuild` に登録するconfig pluginが含まれています。`scheme` オプションを渡してください:

```json app.json
{
  "expo": {
    "scheme": "myapp",
    "plugins": [
      [
        "@dodopayments/react-native-checkout",
        { "scheme": "myappcheckout" }
      ]
    ]
  }
}
```

`scheme` は `returnUrl` と一致し、Expoが
`MainActivity` にすでに登録している `expo.scheme` とは異なっている必要があります。詳細については、
[React Native SDK](/developer-resources/sdks/react-native) のページを参照してください。

`android/app/build.gradle` を標準の
`defaultConfig { }` ブロックなしで手動管理している場合は、代わりにプレースホルダーを手動で設定してください（Androidタブを参照）。

development builds のみで動作し、Expo Go では動作しません。`app.json` の編集後に
`npx expo prebuild --clean` を実行してください。
</Tab>
</Tabs>

<Note>
自分で構築したい場合は、`checkout_url` を WebView で開き、`return_url` への navigation を intercept してから、`status` と `payment_id`
query parameters を読み取ります。上記の SDK は platform の実際の browser surface でこれを処理するため、Apple Pay と Google Pay が引き続き機能します。
</Note>

## 外観のカスタマイズ

各 SDK は、`customization` /
`start(...)` に、ネイティブブラウザー画面の外観と
動作（ツールバー、ボタン、表示方法）を制御するオプションの `CheckoutParams` パラメーターを受け取ります。これは
チェックアウトページ自体のテーマとは別のもので、チェックアウトセッション上で
サーバー側から [`customization.theme_config`](/developer-resources/checkout-session) を使って
設定します。

オプションはプラットフォームごとに分類されています。これは、Android の Custom Tab と iOS の
`SFSafariViewController` では、利用できるネイティブコントロールが異なるためです。すべてのフィールドは
オプションです。`customization` を完全に省略すると、各プラットフォームのデフォルトの
外観が使用されます。

## ベストプラクティス

- **セキュリティ**: アプリに API key を決して含めないでください。バックエンドで checkout sessions を作成し、生成された `checkout_url` のみをクライアントに渡します。
- **権限の扱い**: `CheckoutResult.status` は UI のヒントとして扱います。バックエンドで支払いを確認した後にのみアクセスを許可してください。
- **ユーザー体験**: バックエンドがセッションを作成している間は読み込み状態を表示し、`cancelled` はエラーではなく通常の結果として処理します。
- **テスト**: test mode と test cards を使用し、実機と simulator の両方で return-URL の往復を確認してください。

## トラブルシューティング

### よくある問題

- **Callback が届かない**: `returnUrl` の scheme は、登録したものと一致している必要があります。Android では `dodoCallbackScheme` の manifest placeholder、iOS と React Native では `Info.plist` の URL type が該当します。
- **チェックアウトがアプリではなくブラウザーに戻る（iOS）**: 受信した URL を転送していません。`.onOpenURL`、`scene(_:openURLContexts:)`、または React Native の `Linking` listener から `DodoCheckout.handleOpenURL(url)` を呼び出してください。
- **Android での `PLATFORM_ERROR`**: ほとんどの場合、scheme の不一致が原因です。また、`MainActivity` が `android:taskAffinity=""`（標準の `flutter create` default）を設定している場合にも発生することがあります。この設定により、一部の OEM ビルドで進行中のチェックアウトが失われる可能性があります。
- **`ALREADY_IN_PROGRESS`**: まだ開いているチェックアウトがあります。別のチェックアウトを開始する前に、前のものを await または dismiss してください。
- **未解決の placeholder でビルドに失敗する**: Android SDK を追加したものの、`manifestPlaceholders["dodoCallbackScheme"]` を設定していません。
- **支払いは成功したがアクセスが許可されない**: モバイルの結果を基準にしている場合は想定される動作です。代わりに `payment.succeeded` / `subscription.active` webhook からアクセスを許可してください。
