Dodo Agent Pluginは、2つのMCPサーバーと8つのインテグレーションスキルを、1回のインストールでAIコーディングエージェントに組み込みます。**Claude Code**、**Codex CLI**、**Cursor**、**OpenCode**で利用でき、MCPサーバーとskills CLIは、MCP互換クライアントであれば利用できます。

<Info>
**3つのプリミティブを1つのプラグインに。** Agent Pluginには、必要なものがすべて含まれています。
- **API MCP server** — payments、subscriptions、customers、products、refunds、licenses、usageへのライブアクセス。ブラウザOAuthで認証されるため、ローカルキーは不要です。
- **Knowledge MCP server** — Dodo Paymentsのドキュメント全体を対象としたセマンティック検索。認証情報は不要です。
- **8つのagent skills** — checkout、subscriptions、webhooks、usage-based billing、credit-based billing、license keys、BillingSDK、ベストプラクティスについて、必要に応じてエージェントが読み込むチートシートです。
</Info>

## プラグインをインストールする

以下から使用するコーディングエージェントを選択してください。インストールすると、2つのMCPサーバーと8つすべてのスキルが自動的に追加されます。

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
マーケットプレイスからインストールします。

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP serverはデフォルトでブラウザOAuthを使用するため、インストール時にキーは不要です。エージェントが初めてDodoのツールを呼び出すと、サインインを求められます。

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  ソースコード、設定オプション、ローカル開発手順
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codexではプラグインを2段階でインストールします。まずシェルからマーケットプレイスを登録し、その後Codex TUI内からプラグインをインストールします。

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Codexを開き、`/plugins`スラッシュコマンドを実行します。

```bash
codex
```

次に`/plugins`と入力し、**Dodo Payments**マーケットプレイスに切り替え、**dodopayments**プラグインを選択して、**Install plugin**を選びます。
</Step>
</Steps>

プラグインをインストールすると、2つのMCPサーバーと8つすべてのスキルが自動的に登録されます。

<Note>
Codex CLIには`codex plugin install`サブコマンドがありません。プラグインのインストールは、常にTUI内の`/plugins`フローで行います。[Codexの公式プラグインドキュメント](https://developers.openai.com/codex/plugins)を参照してください。
</Note>

以前にマーケットプレイスとプラグインを追加したにもかかわらず、`/plugins`の下にプラグインが表示されない場合は、更新してください。

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
手動インストール — リポジトリをCursorのローカルプラグインディレクトリにcloneします。

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Cursorを再起動します。プラグインは`.claude/skills/`（CursorのClaude Code互換レイヤー経由）からスキルを読み込み、`.mcp.json`からMCPサーバーを読み込みます。

<Info>
Cursorのマーケットプレイスサポートは近日提供予定です。現時点では、上記の手動インストールを使用してください。
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCodeはnpm経由で配布されます。プラグインを`opencode.json`に追加します。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

OpenCodeを再起動します。両方のMCPサーバー（`dodopayments-api`、`dodo-knowledge`）はプラグインのconfig hookによって自動的に登録され、8つのスキルはインストール済みパッケージから自動検出されます。手動の`mcp`ブロックは不要です。
</Accordion>
</AccordionGroup>

<Info>
別のエージェントを使用していますか？[MCP Server](/developer-resources/mcp-server)と[Agent Skills](/developer-resources/agent-skills)のガイドでは、Cursor、Claude Desktop、VS Code、Windsurf、Cline、Zed、およびMCP互換クライアントを説明しています。
</Info>

## 利用できるもの

プラグインをインストールすると、エージェントから2つのMCPサーバーと8つのスキルにアクセスできます。

### MCPサーバー

| サーバー | 目的 | 認証 |
|--------|---------|------|
| `dodopayments-api` | ライブAPIアクセス — payments、subscriptions、customers、products、refunds、licenses、usage | OAuth（ブラウザ） |
| `dodo-knowledge` | Dodo Paymentsのドキュメント全体を対象としたセマンティック検索 | なし |

両方のサーバーは`mcp-remote`経由で接続されるため、MCP互換クライアントであれば実行できます。

### エージェントスキル

| スキル | 説明 |
|-------|-------------|
| `best-practices` | Dodo Paymentsとのインテグレーションに関する包括的なガイドとベストプラクティス |
| `checkout-integration` | checkout sessionと支払いフローの作成 |
| `subscription-integration` | subscription billingフローの実装 |
| `webhook-integration` | 支払いイベント用webhooksの設定と処理 |
| `usage-based-billing` | eventsとmetersを使用したmetered billingの実装 |
| `credit-based-billing` | クレジットエンタイトルメント、残高、従量制クレジットの差し引き |
| `license-keys` | デジタル製品のlicense keys管理 |
| `billing-sdk` | BillingSDK Reactコンポーネントの使用 |

スキルは自動的に読み込まれます。関連するタスクを検出すると、エージェントが適切なスキルを選択します。全リストと個別のインストール方法については、[Agent Skillsドキュメント](/developer-resources/agent-skills)を参照してください。

### 最初に試すプロンプト

プラグインが有効になったら、次を試してください。

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

エージェントは`webhook-integration`スキルを読み込み、`dodo-knowledge` MCPを使用して最新のpayload形式を取得し、Standard Webhooks仕様に従った署名検証付きのhandlerを作成します。

| Claude Desktop | [MCP Serverガイド](/developer-resources/mcp-server) | — |

- **完全なドキュメントインデックス**: [`docs.dodopayments.com/llms.txt`](https://docs.dodopayments.com/llms.txt) — コンテキスト取り込み用に完全なドキュメントインデックスを提供します。

- **ソースリポジトリ**: [`github.com/dodopayments/dodo-docs`](https://github.com/dodopayments/dodo-docs) — オフラインでのインデックス作成用にcloneできます。

## エージェントでできること

プラグインをインストールすると、コーディングエージェントは次のことができます。

- **checkout sessionと支払いリンクを作成** — [One-time payments](/features/one-time-payment-products)と[subscriptions](/features/subscription)
- **subscriptionとusage-based billingをエンドツーエンドで構築** — [Subscriptions](/features/subscription)、[Usage-based billing](/features/usage-based-billing/introduction)、[Credit-based billing](/features/credit-based-billing)
- **Standard Webhooks準拠のhandlerを署名検証付きで生成** — [Webhooks](/developer-resources/webhooks)
- **料金表とsubscription管理用のBillingSDK Reactコンポーネントを組み込む** — [BillingSDK](/developer-resources/billingsdk)
- **デジタル製品向けのlicense-keyフローを作成** — [License keys](/features/license-keys)
- **エンタイトルメント、残高、繰り越し、超過分を含むcredit-based billingを実装** — [Credits](/features/credit-based-billing)

## セキュリティとベストプラクティス

<Warning>
**本番環境のAPIキーは決してcommitしないでください。** 開発中は[test mode](/miscellaneous/test-mode-vs-live-mode)を使用してください。Agent PluginはデフォルトでブラウザOAuthを使用します。ローカルAPIキーへの切り替えは、ワークフローで必要な場合にのみ行ってください。
</Warning>

- **まずtest modeを使用する。** `dodo_test_...`キーを使ってインテグレーションをサンドボックス化してから、運用を開始してください。[Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode)を参照してください。
- **OAuthがデフォルトです。** Agent PluginはブラウザOAuth（ローカルシークレット不要）で認証します。必要な場合にのみAPI-key modeを使用してください。詳しくは以下のConfigureセクションを参照してください。
- **エージェントが生成したコードを確認する。** webhook handlerに[Standard Webhooks仕様](https://standardwebhooks.com/)に従った署名検証が含まれていることを必ず確認してください。

## APIキーで設定する

デフォルトでは、Agent PluginはブラウザOAuthを使用するリモートMCPサーバーを使用するため、ローカルの認証情報は不要です。ワークフローでローカルAPIキーが必要な場合（CI環境やヘッドレスサーバーなど）は、stdio modeに切り替えられます。

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Claude Codeで`/plugins`を開き、**Dodo Payments**を選択して、**Configure options**を選びます。次の項目を入力してください。

- `dodo_api_key` — 使用する`dodo_test_...`または`dodo_live_...`キー
- `dodo_webhook_key` — webhook signing secret
- `dodo_environment` — `test_mode`または`live_mode`

次に`.mcp.json`を編集し、`dodopayments-api`がローカルstdio serverを指すようにします。

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

`/reload-plugins`を実行して、現在のセッションに変更を適用します。
</Accordion>

<Accordion title="Local API key mode — OpenCode">
`dodopayments-api`を`opencode.json`で自分で宣言します。このエントリがプラグインのデフォルトのリモートサーバーより優先されます。

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

OpenCodeを再起動して適用します。
</Accordion>
</AccordionGroup>
