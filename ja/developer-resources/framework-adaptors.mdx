Dodo Payments は、payment integration を簡素化する公式の framework adaptor を提供します。各 adaptor は使用する framework の規約にシームレスに対応するよう設計されており、checkout、customer portal、webhook 処理をすぐに利用できます。

<Tip>
Framework adaptor を使えば、10行未満のコードで Dodo Payments を統合できます。認証、request の解析、response の formatting は自動的に処理されます。
</Tip>

## Core Features

すべての framework adaptor に、次の機能が組み込まれています。

| Feature | Description |
|---------|-------------|
| **Checkout Handler** | static、dynamic、session-based checkout flow に対応 |
| **Customer Portal** | subscription と billing management 用の構築済み handler |
| **Webhook Handler** | typed event handler による安全な signature verification |
| **Environment Config** | environment variable による簡単な設定 |
| **Type Safety** | typed payload による完全な TypeScript サポート |

次の3つの手順で、任意の framework adaptor の利用を開始できます。

<Steps>
<Step title="Install the Adaptor">
  package manager を使用して、framework 専用の adaptor をインストールします。

  <Tabs>
  <Tab title="Next.js">

  ```bash
  npm install @dodopayments/nextjs
  ```

  </Tab>
  
  <Tab title="Nuxt">

  ```bash
  npm install @dodopayments/nuxt
  ```

  </Tab>
  
  <Tab title="Express">

  ```bash
  npm install @dodopayments/express
  ```

  </Tab>
  
  <Tab title="Hono">

  ```bash
  npm install @dodopayments/hono
  ```

  </Tab>

  <Tab title="Astro">

  ```bash
  npm install @dodopayments/astro
  ```

  </Tab>

  <Tab title="SvelteKit">

  ```bash
  npm install @dodopayments/sveltekit
  ```

  </Tab>
  </Tabs>
</Step>

<Step title="Configure Environment Variables">
  Dodo Payments の credential を environment に追加します。

  ```env
  DODO_PAYMENTS_API_KEY=your-api-key
  DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
  DODO_PAYMENTS_RETURN_URL=https://yourdomain.com/checkout/success
  DODO_PAYMENTS_ENVIRONMENT="test_mode" # or "live_mode"
  ```

  <Warning>
  `.env` ファイルや secret を version control に commit しないでください。
  </Warning>
</Step>

<Step title="Create Route Handlers">
  checkout、customer portal、webhook の route を設定します。

  <Tabs>
  <Tab title="Next.js">

  ```typescript
  // app/checkout/route.ts
  import { Checkout } from "@dodopayments/nextjs";

  export const GET = Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  });
  ```

  </Tab>
  
  <Tab title="Express">

  ```typescript
  import { checkoutHandler } from '@dodopayments/express';

  app.get('/api/checkout', checkoutHandler({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  
  <Tab title="Hono">

  ```typescript
  import { Checkout } from "@dodopayments/hono";

  app.get('/checkout', Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  </Tabs>

  <Check>
  これで payment を処理する準備が整いました。詳細な guide と利用可能なすべての option については、各 adaptor のページをご覧ください。
  </Check>
</Step>
</Steps>

## Checkout Flow の種類

すべての adaptor は、3種類の checkout flow に対応しています。

<AccordionGroup>
<Accordion title="Static Checkout (GET)">
シンプルで共有可能な payment link には、static checkout を使用します。query parameter として product ID を渡してください。

```
/api/checkout?productId=pdt_xxx&quantity=1
```

query parameter を使用して、customer の事前入力と customization を任意で設定できます。
</Accordion>

<Accordion title="Dynamic Checkout (POST)">
dynamic checkout を使用すると、カスタムの詳細を指定して programmatically に payment を作成できます。

```json
{
  "product_id": "pdt_xxx",
  "customer": {
    "email": "customer@example.com",
    "name": "John Doe"
  },
  "quantity": 1
}
```

one-time payment と subscription の両方に対応しています。
</Accordion>

<Accordion title="Checkout Sessions (POST)">
cart に対応した、柔軟性の高い checkout experience には checkout session を使用します。

```json
{
  "product_cart": [
    { "product_id": "pdt_xxx", "quantity": 1 },
    { "product_id": "pdt_yyy", "quantity": 2 }
  ],
  "customer": {
    "email": "customer@example.com"
  }
}
```

詳しくは [Checkout Sessions Guide](/developer-resources/checkout-session) をご覧ください。
</Accordion>
</AccordionGroup>

## Webhook Event Handling

すべての adaptor は、細かな event callback に対応した type-safe な webhook 処理を提供します。

```typescript
Webhooks({
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
  onPayload: async (payload) => {
    // Handle any webhook event
  },
  onPaymentSucceeded: async (payload) => {
    // Handle successful payments
  },
  onSubscriptionActive: async (payload) => {
    // Handle new subscriptions
  },
  // ... 20+ event types supported
});
```

<Info>
すべての webhook handler は、Zod schema を使用して signature を自動的に検証し、payload を validate します。無効な request は適切な error code で拒否されます。
</Info>

## 適切な Adaptor の選択

| Framework | Best For | Runtime |
|-----------|----------|---------|
| **Next.js** | App Router を使用する full-stack React app | Node.js, Edge |
| **Nuxt** | full-stack Vue.js application | Node.js |
| **Express** | REST API と従来型の Node.js app | Node.js |
| **Fastify** | 高性能 API | Node.js |
| **Hono** | edge deployment、Cloudflare Workers | Edge, Node.js |
| **Astro** | server endpoint を備えた content site | Node.js, Edge |
| **SvelteKit** | full-stack Svelte application | Node.js |
| **Remix** | nested routing に対応した full-stack React | Node.js |
| **TanStack Start** | type-safe な full-stack React | Node.js |
| **Better Auth** | すでに Better Auth を使用している app | Various |
| **Convex** | backend に Convex を使用する app | Convex Runtime |
| **Bun** | ネイティブ Bun server application | Bun |
