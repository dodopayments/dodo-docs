Dodo Paymentsは、支払い統合を簡素化する公式のフレームワークアダプタを提供しています。各アダプタは、フレームワークの慣習にシームレスに対応するように設計されており、チェックアウト、カスタマーポータル、Webhook処理をすぐに利用できます。

<Tip>
フレームワークアダプタを使用すると、10行未満のコードでDodo Paymentsを統合できます。認証、リクエスト解析、レスポンスフォーマットを自動的に処理します。
</Tip>

## コア機能

すべてのフレームワークアダプターは、以下の組み込み機能を提供します：

| 機能 | 説明 |
|---------|-------------|
| **チェックアウトハンドラー** | 静的、動的、セッションベースのチェックアウトフローをサポート |
| **カスタマーポータル** | サブスクリプションと請求管理のための事前構築されたハンドラー |
| **Webhookハンドラー** | タイプ付きイベントハンドラーによるセキュアな署名検証 |
| **環境設定** | 環境変数を使用した簡単なセットアップ |
| **タイプセーフティ** | タイプ付きペイロードを使った完全なTypeScriptサポート |

## クイックスタート

任意のフレームワークアダプターを3つのステップで開始:

<Steps>
<Step title="アダプターのインストール">
  パッケージマネージャーを使用して、フレームワーク固有のアダプターをインストール：

  <Tabs>
  <Tab title="Next.js">

  ```bash
  npm install @dodopayments/nextjs
  ```

  </Tab>
  
  <Tab title="Nuxt">

  ```bash
  npm install @dodopayments/nuxt
  ```

  </Tab>
  
  <Tab title="Express">

  ```bash
  npm install @dodopayments/express
  ```

  </Tab>
  
  <Tab title="Hono">

  ```bash
  npm install @dodopayments/hono
  ```

  </Tab>

  <Tab title="Astro">

  ```bash
  npm install @dodopayments/astro
  ```

  </Tab>

  <Tab title="SvelteKit">

  ```bash
  npm install @dodopayments/sveltekit
  ```

  </Tab>
  </Tabs>
</Step>

<Step title="環境変数の設定">
  Dodo Paymentsの資格情報を環境に追加：

  ```env
  DODO_PAYMENTS_API_KEY=your-api-key
  DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
  DODO_PAYMENTS_RETURN_URL=https://yourdomain.com/checkout/success
  DODO_PAYMENTS_ENVIRONMENT="test_mode" # or "live_mode"
  ```

  <Warning>
  `.env`ファイルやシークレットをバージョン管理にコミットしないでください。
  </Warning>
</Step>

<Step title="ルートハンドラーの作成">
  チェックアウト、カスタマーポータル、およびWebhookルートを設定：

  <Tabs>
  <Tab title="Next.js">

  ```typescript
  // app/checkout/route.ts
  import { Checkout } from "@dodopayments/nextjs";

  export const GET = Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  });
  ```

  </Tab>
  
  <Tab title="Express">

  ```typescript
  import { checkoutHandler } from '@dodopayments/express';

  app.get('/api/checkout', checkoutHandler({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  
  <Tab title="Hono">

  ```typescript
  import { Checkout } from "@dodopayments/hono";

  app.get('/checkout', Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  </Tabs>

  <Check>
  これで支払いを処理する準備が整いました！ 各アダプターのページを訪れて、詳細なガイドと利用可能なすべてのオプションを確認してください。
  </Check>
</Step>
</Steps>

## チェックアウトフローの種類

すべてのアダプターは3つのチェックアウトフローの種類をサポートします：

<AccordionGroup>
<Accordion title="静的チェックアウト (GET)">
シンプルで共有可能な支払いリンクのために静的チェックアウトを使用します。商品IDをクエリパラメーターとして渡します：

```
/api/checkout?productId=pdt_xxx&quantity=1
```

オプションの顧客プリフィルとクエリパラメータを使用したカスタマイズをサポート。
</Accordion>

<Accordion title="動的チェックアウト (POST)">
動的チェックアウトを使用して、カスタム詳細を含む支払いをプログラム的に作成します：

```json
{
  "product_id": "pdt_xxx",
  "customer": {
    "email": "customer@example.com",
    "name": "John Doe"
  },
  "quantity": 1
}
```

一回限りの支払いとサブスクリプションの両方をサポート。
</Accordion>

<Accordion title="チェックアウトセッション (POST)">
カートサポートを備えた最も柔軟なチェックアウト体験のためにチェックアウトセッションを使用します：

```json
{
  "product_cart": [
    { "product_id": "pdt_xxx", "quantity": 1 },
    { "product_id": "pdt_yyy", "quantity": 2 }
  ],
  "customer": {
    "email": "customer@example.com"
  }
}
```

[チェックアウトセッションガイド](/developer-resources/checkout-session)で詳細を学んでください。
</Accordion>
</AccordionGroup>

## Webhookイベント処理

すべてのアダプターは、詳細なイベントコールバックによるタイプセーフなWebhook処理を提供します：

```typescript
Webhooks({
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
  onPayload: async (payload) => {
    // Handle any webhook event
  },
  onPaymentSucceeded: async (payload) => {
    // Handle successful payments
  },
  onSubscriptionActive: async (payload) => {
    // Handle new subscriptions
  },
  // ... 20+ event types supported
});
```

<Info>
すべてのWebhookハンドラーは自動的に署名を検証し、Zodスキーマを使用してペイロードを検証します。無効なリクエストは適切なエラーコードで拒否されます。
</Info>

## 正しいアダプターの選択

| フレームワーク | 最適 | ランタイム |
|-----------|----------|---------|
| **Next.js** | App Routerを持つフルスタックReactアプリ | Node.js, Edge |
| **Nuxt** | フルスタックVue.jsアプリケーション | Node.js |
| **Express** | REST APIおよび従来のNode.jsアプリ | Node.js |
| **Fastify** | 高パフォーマンスAPI | Node.js |
| **Hono** | Edgeデプロイ、Cloudflare Workers | Edge, Node.js |
| **Astro** | サーバーエンドポイントを持つコンテンツサイト | Node.js, Edge |
| **SvelteKit** | フルスタックSvelteアプリケーション | Node.js |
| **Remix** | ネストされたルーティングを持つフルスタックReact | Node.js |
| **TanStack Start** | タイプセーフなフルスタックReact | Node.js |
| **Better Auth** | すでにBetter Authを使用しているアプリ | 様々な |
| **Convex** | Convexをバックエンドとして使用しているアプリ | Convex Runtime |
| **Bun** | ネイティブBunサーバーアプリケーション | Bun |
