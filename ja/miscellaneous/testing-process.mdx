## 概要

テストモードでは、実際の取引を処理せずに支払いをシミュレートできます。テスト用の認証情報はテストモードでのみ機能します。プロダクション環境では絶対に使用しないでください。

<CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
テスト取引では実際の支払いは処理されず、実際のアカウントにも影響しません。
</Card>

<Card title="Full API Access" icon="code">
すべてのAPIエンドポイントは、テストモードとliveモードで同じように動作します。
</Card>

<Card title="Webhook Testing" icon="webhook">
Webhookはプロダクションと同様にテスト取引でも発生します。
</Card>
</CardGroup>

<Warning>
テスト用の認証情報はテストモードでのみ機能します。liveモードで使用しようとすると、支払いが失敗します。
</Warning>

## テストカード

以下のカード番号を使用して、さまざまな地域で成功する支払いと拒否される支払いをシミュレートします。

<Tabs>
<Tab title="Successful Payments">
| 地域 | ブランド | カード番号 | 有効期限 | CVV |
| :----- | :---- | :---------- | :----- | :-- |
| US | Visa | `4242424242424242` | 06/32 | 123 |
| US | Mastercard | `5555555555554444` | 06/32 | 123 |
| India | Visa | `4576238912771450` | 06/32 | 123 |
| India | Mastercard | `5409162669381034` | 06/32 | 123 |
</Tab>

<Tab title="Declined Payments">
| 地域 | ブランド | カード番号 | シナリオ | `error_code` になる結果 |
| :----- | :---- | :---------- | :------- | :--------------------- |
| US | Visa | `4000000000000002` | 一般的な拒否 | `GENERIC_DECLINE` |
| US | Visa | `4000000000009995` | 残高不足 | `INSUFFICIENT_FUNDS` |
| India | Visa | `4706131211212123` | 一般的な拒否 | `GENERIC_DECLINE` |
| India | Mastercard | `5105105105105100` | 一般的な拒否 | `GENERIC_DECLINE` |

これらのカードのいずれかが拒否されると、支払いの`error_code`と`error_message`に上記のシナリオが反映されます。各コードの意味と推奨される対応については、[Transaction Failures](/api-reference/transaction-failures)リファレンスで確認してください。また、統合での拒否への対応については、[Handle Payment Failures](/developer-resources/handle-payment-failures)を参照してください。
</Tab>

<Tab title="Subscription Failure Testing (Renewal/Upgrade/Downgrade)">
| カード番号 | 有効期限 | CVC |
| :---------- | :----- | :-- |
| `4000 0000 0000 0341` | 12/34 | 123 |

このカードを使用して、サブスクリプションのFailure renewal、upgrade、downgradeシナリオをテストします。
</Tab>
</Tabs>

<Info>
すべてのテストカードで、有効期限には**06/32**（または**12/34**）、CVVには**123**を使用してください。
</Info>

### Renewal Failureのテスト方法

<Steps>
<Step title="Create a test subscription">
**success**テストカード（例：`4242 4242 4242 4242`）を使用し、テスト用APIキーでサブスクリプションを作成します。初回の請求は成功し、サブスクリプションはactiveになります。
</Step>

<Step title="Swap in the failure card via Customer Portal">
[Customer Portal](/features/customer-portal)を開き、作成したサブスクリプションを見つけて、**Update Payment Method**をクリックします。Failureテストカード`4000 0000 0000 0341`（有効期限：`12/34`、CVC：`123`）を入力し、サブスクリプションの支払い方法として保存します。
</Step>

<Step title="Advance the next billing date (optional)">
自然な請求サイクルを待たずにすぐ更新をトリガーするには、Update Subscription APIを使用して`next_billing_date`を現在のUTC時刻に設定します。値はISO 8601 / RFC 3339形式のUTCタイムスタンプである必要があります（`Z`サフィックスが必須です）。

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

詳細については、[Update Subscription API reference](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0)を参照してください。
</Step>

<Step title="Verify the failure">
次回の請求時：

- Failureカードで更新請求が拒否される
- サブスクリプションのステータスが**On-Hold**に移行する
- `payment.failed` Webhookイベントが配信される
- 顧客はCustomer Portalに戻り、支払い方法を更新して再試行できる
</Step>
</Steps>

<Warning>
このカードは更新の失敗をテストするための専用カードです。次回の請求日に請求が拒否されるため、支払いの再試行ロジック、顧客通知、失敗処理をテストできます。
</Warning>

## テストUPI

UPIのテストでは、さまざまな支払い結果をシミュレートする特殊なVPA（Virtual Payment Address）識別子を使用します。

| ステータス | UPI ID |
| :----- | :----- |
| Success | `success@upi` |
| Failure | `failure@upi` |

### UPIテストの要件

- 請求先の国は`IN`に設定する必要があります
- 通貨は`INR`である必要があります
- インド以外のMerchantの場合：Adaptive Currencyを有効にする必要があります

サブスクリプションのRBI mandateテストを含むUPIの完全なドキュメントについては、[India Payment Methods](/features/payment-methods/india)ページを参照してください。

## テストBNPL

Buy Now Pay Laterプロバイダーには、特定のテストデータ要件があります。

### Klarnaテストデータ

テストモードでKlarna支払いをシミュレートするには、以下の情報を使用します：

| フィールド | Approved | Denied |
| :---- | :------- | :----- |
| **生年月日** | 07-10-1970 | 07-10-1970 |
| **名** | Test | Test |
| **姓** | Person-us | Person-us |
| **Email** | customer@email.us | customer+denied@email.us |
| **Street** | Amsterdam Ave | Amsterdam Ave |
| **House Number** | 509 | 509 |
| **City** | New York | New York |
| **State** | New York | New York |
| **Postal Code** | 10024-3941 | 10024-3941 |
| **Phone** | +13106683312 | +13106354386 |

<Note>
Klarnaを支払いオプションとして表示するには、最低取引金額**$50.01**が必要です。
</Note>

### Afterpayのテスト

<Steps>
<Step title="Select Afterpay">
Checkoutで支払い方法としてAfterpayを選択し、Payをクリックします。
</Step>

<Step title="Test successful payment">
成功する支払いには、有効なEmailアドレスと配送先住所を使用してください。
</Step>

<Step title="Test failed authentication">
失敗をシミュレートするには、リダイレクトページでAfterpayのモーダルウィンドウを閉じます。支払いは `requires_customer_action` から `requires_payment_method` に遷移します。
</Step>
</Steps>

<Note>
Afterpayを支払いオプションとして表示するには、最低取引金額**$50.01**が必要です。
</Note>

Billie B2B testingを含む完全なBNPLドキュメントについては、[Buy Now Pay Later](/features/payment-methods/bnpl)ページをご覧ください。

## デジタルウォレットのテスト

### Apple Pay

<Steps>
<Step title="Enable test mode">
Dodo PaymentsのテストAPIキーを使用します。
</Step>

<Step title="Add a card to Apple Wallet">
実際のカードをApple Walletに追加します。テストモードではカードに請求されません。
</Step>

<Step title="Complete test purchase">
Appleデバイスでチェックアウトを開き、Apple Payのフローを完了します。
</Step>
</Steps>

<Warning>
Apple PayにはHTTPSが必要です。適切なSSL設定がない場合、`localhost`には表示されません。ドメイン認証も完了している必要があります。
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
テストカードを自動的にウォレットに追加するには、[Google Payのテストカードグループに参加](https://groups.google.com/g/googlepay-test-mode-stub-data)してください。
</Step>

<Step title="Enable test mode">
Dodo PaymentsのテストAPIキーを使用します。
</Step>

<Step title="Complete test purchase">
Google Payでテストカードのいずれかを選択して、取引を完了します。
</Step>
</Steps>

### Amazon Pay、Cash App Pay、RevolutPay

テストAPIキーを使用し、標準のチェックアウトフローに従います。テスト取引は実際の請求なしでシミュレーションされます。

Apple Payのドメイン認証を含む完全なデジタルウォレットのドキュメントについては、[デジタルウォレット](/features/payment-methods/digital-wallets)ページをご覧ください。

## 欧州の決済手段のテスト

欧州の決済手段（iDEAL、Bancontact、EPS、Multibanco）は、サンドボックスモードでテストできます。

<Steps>
<Step title="Enable test mode">
Dodo PaymentsのテストAPIキーを使用します。
</Step>

<Step title="Set billing address">
請求先住所の国を決済手段に合わせて設定します。
- `NL`（iDEALの場合）
- `BE`（Bancontactの場合）
- `AT`（EPSの場合）
- `PT`（Multibancoの場合）
</Step>

<Step title="Set currency">
欧州の決済手段にはEUR通貨が必要です。
</Step>

<Step title="Complete test flow">
テスト環境でシミュレーションされた銀行認証フローに従います。
</Step>
</Steps>

欧州の決済手段に関する完全なドキュメントについては、[Europe](/features/payment-methods/europe)ページをご覧ください。

## テストのベストプラクティス

<AccordionGroup>
<Accordion title="Test all payment scenarios">
成功した支払いだけをテストしないでください。拒否、キャンセル、残高不足などのエッジケースもテストします。
</Accordion>

<Accordion title="Verify webhook handling">
Webhookエンドポイントが、すべてのイベントタイプ、特に`payment.succeeded`、`payment.failed`、サブスクリプションイベントを正しく処理することを確認します。

ローカルでwebhookをテストするには、[Dodo Payments CLI](/developer-resources/sdks/cli#webhooks)を使用します:
- `dodo wh listen` ライブテスト用のwebhookをローカルサーバーに転送します
- `dodo wh trigger` サポートされているすべてのwebhookイベントタイプのモックpayloadを送信します
</Accordion>

<Accordion title="Test on real devices">
Apple PayとGoogle Payでは、実際のiOSおよびAndroidデバイスでテストします。シミュレーターではウォレットの動作を完全には再現できません。
</Accordion>

<Accordion title="Test regional methods with correct addresses">
地域固有の決済手段（UPI、iDEALなど）には、一致する請求先住所が必要です。米国の請求先住所ではiDEALは表示されません。
</Accordion>

<Accordion title="Verify minimum amounts">
BNPLの決済手段には$50.01の最低金額が必要です。カート合計額に応じて正しく表示または非表示になることをテストします。
</Accordion>
</AccordionGroup>
