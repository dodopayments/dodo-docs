## サブスクリプションの移行とは？

サブスクリプションの移行では、既存のサブスクライバーを従来の決済プロセッサーから Dodo Payments に移行し、すべての顧客データを一元管理できる信頼できる唯一の情報源を構築します。移行を行わない場合、これまでに獲得した顧客は従来のシステムに残り、新規顧客のみが Dodo Payments で確認できる状態になります。

移行プロセスにより、顧客は支払い情報を再入力する必要がなく、サブスクリプションが中断されることもない、シームレスな請求エクスペリエンスを実現できます。

<Warning>
現在、移行に対応しているのは **カードトークン** のみです。プロバイダーが定めるトークン化の制限により、Apple Pay、Google Pay、その他のウォレット決済方法は決済プロセッサー間で移行できません。
</Warning>

## 移行プロセスの概要

サブスクリプションの移行プロセスは、次の3つの主要な部分で構成されます。

1. **支払い方法の移行** — 機密性の高いカードデータを現在のプロセッサーから安全に移行
2. **サブスクライバーデータの移行** — 顧客情報、サブスクリプションプラン、請求スケジュールをエクスポート
3. **インポートと検証** — Dodo Payments で支払い方法とサブスクライバーデータを統合

<Note>
サブスクリプションの移行を開始するには、[サポートチーム](mailto:support@dodopayments.com) にお問い合わせください。担当のSolutions Engineerがお客様を担当し、プロセス全体をサポートします。
</Note>

## 要件

移行を開始する前に、次の要件を満たしていることを確認してください。

<AccordionGroup>
<Accordion title="PCI DSS compliance verification">
Dodo Payments はPCI DSS Level 1に準拠しています。コンプライアンス要件を満たすため、カードデータはPCI DSS Level 1に準拠した別の決済プロセッサーからのみ受け取ることができます。

現在のプロセッサーから、次の情報の提供を受ける必要があります。
- 最新のPCI Attestation of Compliance（AOC）、またはVisaのGlobal Registry of Service Providersへの登録情報
- 安全なカードデータのエクスポートに対応していることの確認

現在のプロセッサーと共有するために、当社の[Attestation of Compliance（AOC）](https://pub-2a89184e4c954b599464449d23f506bb.r2.dev/dodo-payments-pci-dss-aoc.pdf)をご確認ください。
</Accordion>

<Accordion title="Dodo Payments integration">
移行を開始する前に、Dodo Payments のintegrationを完了し、すべての新規顧客が Dodo Payments checkoutに誘導されることを確認してください。これにより、移行期間中のデータの不整合を防止できます。
</Accordion>

<Accordion title="Data access authorization">
現在のプロセッサーにデータエクスポートを依頼するために必要な承認を取得していることを確認してください。通常、次の手続きが必要です。
- アカウント所有者の確認
- 機密データへのアクセスに関する書面による承認
- プロセッサーのセキュリティ確認手続きの完了
</Accordion>
</AccordionGroup>

## 移行のステップガイド

<Steps>
<Step title="Request payment method export from your current processor">
現在の決済プロセッサーのサポートチームに連絡し、顧客のカードトークン一式のエクスポートを正式に依頼します。

次の対応が必要です。
- 本人確認および承認の証明を提供する
- エクスポートをDodo Payments のPGP公開鍵（下記に記載）で暗号化するよう依頼する
- 暗号化されたファイルを当社の安全なSFTPサーバーに直接転送するよう依頼する

<Info>
安全な転送は、SFTPを使用してサーバー間で直接行われます。担当のSolutions Engineerが、現在のプロセッサーと共有するSFTP認証情報を提供します。
</Info>

このプロセスには平均で **約2週間** かかりますが、期間は現在のプロセッサーのポリシーや対応時間によって異なります。
</Step>

<Step title="Prepare subscriber data export">
支払い方法の移行中に、従来のシステムからサブスクライバーデータをエクスポートします。担当のSolutions EngineerがCSVテンプレートを提供し、必要なフィールドについてご案内します。

### 必須のサブスクライバーデータ

| Field | Description |
|-------|-------------|
| `customer_id` | 内部で使用している顧客識別子 |
| `email` | 顧客のメールアドレス |
| `name` | 顧客の氏名 |
| `country` | 2文字の国コード（ISO 3166-1 alpha-2） |
| `currency` | 3文字の通貨コード（ISO 4217） |
| `payment_amount` | 最小通貨単位でのサブスクリプション金額 |
| `payment_interval` | 請求頻度（月次、年次など） |
| `next_billing_date` | 次回請求予定日（ISO 8601） |
| `card_token` | 現在のプロセッサーが発行した一意のトークン |

<Warning>
`card_token`フィールドは重要です。インポート時にサブスクライバーレコードと支払い方法を照合するために使用されます。支払い方法のエクスポートに含まれるトークンと完全に一致していることを確認してください。
</Warning>

### データ形式のサンプル

```json
{
  "customers": [
    {
      "customer_id": "cus_abc123",
      "email": "jane.doe@example.com",
      "name": "Jane Doe",
      "country": "US",
      "currency": "USD",
      "payment_amount": 2999,
      "payment_interval": "monthly",
      "next_billing_date": "2025-01-15T00:00:00Z",
      "card_token": "tok_xyz789",
      "metadata": {
        "plan": "pro",
        "signup_source": "website"
      }
    }
  ]
}
```

</Step>

<Step title="Validation and testing">
インポート日までに、当社チームが次の対応を行います。

- 支払い方法データのファイル整合性と暗号化を確認
- サブスクライバーCSVの形式が正しいことを検証
- sandbox環境でテストインポートを実行
- データマッピングの問題を特定して解決

<Check>
本番インポートの準備がすべて整ったことを確認する検証レポートが届きます。
</Check>
</Step>

<Step title="Production import">
合意したインポート日に、当社のengineering teamが次の対応を行います。

1. PCI-compliant Card Vaultに支払い方法データをインポート
2. サブスクライバーデータをインポート
3. カードトークンを使用してサブスクライバーと支払い方法を照合
4. 移行したすべてのサブスクリプションを有効化

<Info>
標準的な移行の処理時間は通常 **2～3営業日** ですが、サブスクライバー数によって異なります。
</Info>
</Step>

<Step title="Post-migration verification">
インポートが完了すると、次のものが提供されます。

- 移行に関する詳細レポート
- 旧サブスクリプションIDと新しいDodo Payments IDの対応表CSV
- Dodo Payments dashboardで移行済みのすべての顧客にアクセス

次の対応を推奨します。
- dashboardで移行済みサブスクリプションのサンプルを確認する
- sandbox modeでいくつかのサブスクリプション更新をテストする
- 新しいIDで内部データベースの参照を更新する
- 最初の請求サイクル中は並行モニタリングを実施する
</Step>
</Steps>

## 移行可能なデータ

サブスクリプションの移行では、次のデータを移行できます。

| Data type | Supported | Notes |
|-----------|-----------|-------|
| クレジットカード／デビットカード番号 | ✅ | PGPで暗号化 |
| カードの有効期限 | ✅ | |
| カード名義人の氏名 | ✅ | |
| 請求先住所 | ✅ | |
| 顧客のメールアドレス | ✅ | |
| 顧客メタデータ | ✅ | カスタムのキーと値のペア |
| サブスクリプションの詳細 | ✅ | プラン、金額、間隔 |
| Apple Payトークン | ❌ | 移行不可 |
| Google Payトークン | ❌ | 移行不可 |
| その他のウォレットトークン | ❌ | 移行不可 |
| 支払い履歴 | ❌ | 現在のプロセッサーからエクスポート |

<Note>
支払い履歴と取引記録は移行できません。移行を完了する前に、記録用として現在のプロセッサーからこれらのデータをエクスポートすることを推奨します。
</Note>

## PGP暗号化

## 予定期間

| Phase | Duration |
|-------|----------|
| 初期設定と計画 | 1～2日 |
| 支払い方法の移行 | 約2週間 |
| サブスクライバーデータの準備 | 3～5日（並行） |
| 検証とテスト | 2～3日 |
| 本番インポート | 2～3営業日 |
| 移行後の確認 | 1～2日 |

<Tip>
移行全体には、開始から完了まで通常 **3～4週間** かかります。支払い方法の移行中にサブスクライバーデータの準備を開始すると、全体の期間を短縮できます。
</Tip>
