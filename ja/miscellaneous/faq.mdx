## はじめに・アカウント設定

<Accordion title="Q1: Dodo Payments ダッシュボードへのログイン方法は？">
  A: ダッシュボードにアクセスし、ウェルカムメールで共有されたログインメールアドレスとパスワードを入力してください。問題がある場合はサポートへご連絡ください。
</Accordion>

<Accordion title="Q2: 本人確認に必要な書類は？">
  A: 政府発行の有効な身分証明書（本人確認）と、事業登録書類（事業確認）が必要です。詳細は [verification process page](/miscellaneous/verification-process) を確認してください。
</Accordion>

<Accordion title="Q3: 審査が拒否された場合は？">
  A: 拒否理由がメールで届きます。サポートに連絡して問題を解消し、書類を修正して再申請してください。必要に応じて再提出オプションが有効化されます。
</Accordion>

<Accordion title="Q4: 審査にはどれくらい時間がかかる？">
  A: 通常 **24〜72 営業時間** ですが、追加書類が必要な場合は長引くことがあります。
</Accordion>

<Accordion title="Q5: まだ自社サイトがありません。LinkedIn ページで代用できますか？">
  A: 販売する商品を把握しライブアクセスを付与するため、ウェブサイトが必要です。サイトが無い場合や作成中の場合は support@dodopayments.com にご連絡ください。
</Accordion>

<Accordion title="Q6: 個人事業で登録なしでも使えますか？">
  A: はい、未登録事業者もサポートします。個人としてオンボーディングし、国際決済を受け取れます。身分証明と事業確認フォームは提出が必要です。
</Accordion>
  
<Accordion title="Q7: 別事業も統合したいです。新規アカウントは必要？">
  A: 不要です。1 つのアカウントで複数事業を管理できます。ダッシュボード左下の + アイコンから Add Business を選択してください。詳細は /miscellaneous/accounts#managing-multiple-businesses を参照。
</Accordion>

<Accordion title="Q8: 審査完了を待ってから連携すべき？">
  A: 待つ必要はありません。Test モードで実装を開始し、審査完了後に本番（Live）決済を開始できます。Test と Live の違いは /miscellaneous/test-mode-vs-live-mode を参照。
</Accordion>

<Accordion title="Q9: Live モードの有効化方法は？">
  A: 設定タブで本人確認・事業確認の書類を提出してください。72 時間以上経過している場合は同ページで保留理由を確認し、サポートへ連絡してください。
</Accordion>

<Accordion title="Q10: アフィリエイトプログラムはありますか？">
  A: はい、提供しています！

  <Card title="アフィリエイトプログラムを見る" icon="users" href="/features/affiliates">
    参加方法、コミッション、開始手順を確認できます。
  </Card>

</Accordion>

<Accordion title="Q11: 作成した商品や顧客を削除できますか？">
  A: 現在は将来のコンプライアンスのため削除できません。アーカイブ機能を開発中で、アクティブ一覧から非表示にできる予定です。
</Accordion>

<Accordion title="Q12: 決済ページの UI をカスタムできますか？">
  A: ビジネスロゴと名称を追加できます。ダッシュボードのビジネスプロフィールでアップロードしてください。
</Accordion>

<Accordion title="Q13: チェックアウトページのブランディング変更は可能？">
  A: 可能です。
  - Dashboard → Settings → Business Setting へ移動
  - ロゴ、ブランド名、サポートメールを更新
  - 静的・動的リンク双方に反映されます
</Accordion>

<Accordion title="Q14: Dodo Checkout を iframe で埋め込めますか？">
  A: いいえ。ホスト型チェックアウトは iframe 埋め込み非対応です。代わりに：
  - ユーザーを Dodo チェックアウト URL にリダイレクト
  - もしくは Overlay Checkout を利用 [Overlay Checkout Docs](/developer-resources/overlay-checkout)
</Accordion>

## 本人確認・税務・コンプライアンス

<Accordion title="Q15: 審査が長いのはなぜ？">
  A: 通常 24–72 営業時間ですが、以下で遅延することがあります:
  - 申請数の増加
  - 週末・祝日
  - 書類不備や不足
  - リスク/コンプライアンスでの手動確認

  <Note>
  72 時間超の場合はメールまたはダッシュボードで追加対応がないか確認してください。Discord で登録メールを DM してフォローアップも可能です。
  </Note>
</Accordion>

<Accordion title="Q16: W-8BEN の署名欄がうまくいきません">
  A: 以下の PDF エディタを使用してください:
  - Adobe Acrobat
  - Mac Preview（多くの場合有効）
  - Smallpdf / PDFescape（オンライン）

  署名にバツ印が出る場合:
  - 署名適用後に保存しているか確認
  - 署名レイヤーをフラット化するツールを使う（対応しないエディタもあり）

  <Tip>
  ブラウザのプレビューで署名するとデジタル署名が正しく埋め込まれないことがあります。
  </Tip>
</Accordion>

<Accordion title="Q17: 登録区分を間違えました（法人/個人）。どう直す？">
  A: 誤った区分を選ぶとオンホールドになる場合があります。

  対応手順:
  1. Intercom か Discord でサポートに連絡し、Payout Compliance 再提出を有効にしてもらう。
  2. 正しい区分を選び、必要書類を再提出する。
</Accordion>

<Accordion title="Q18: 区分不一致で審査が拒否されました。どうすれば？">
  A: 区分不一致（例: 実は個人なのに Organization を選択）なら区分を修正して再提出してください。

  手順:
  1. ダッシュボードまたはメールで却下理由を確認
  2. Intercom または support@dodopayments.com に連絡し再提出権限を依頼
  3. 正しい区分（Individual / Organization）を選び、必要書類をすべて再提出
  4. コンプライアンスチームの再審査を待つ

  <Note>
  サポート連絡後に再提出オプションが有効化されます。再度間違えないようにしてください。
  </Note>
</Accordion>

<Accordion title="Q19: 収益が $100 を超えたら審査は早くなりますか？">
  A: はい。支払い閾値 ($100) を超えると優先的に審査されます。

  <Note>
  即時承認を保証するものではありません。ビジネスモデルと書類の適合が重要です。
  </Note>

  $100 を超えても遅い場合はサポートへ連絡してください。
</Accordion>

<Accordion title="Q20: 親の名義など別名でサインアップできますか？">
  A: できません。登録者は事業の法的所有者と書類が一致する必要があります。もし親が実際の所有者なら:
  - 親のメールと電話番号で登録
  - 書類も親名義で提出

  <Note>
  別名で審査を通そうとするとコンプライアンス拒否の原因になります。
  </Note>
</Accordion>

<Accordion title="Q21: 審査却下の理由はどこで確認できますか？">
  A: 以下で確認できます:
  - ダッシュボードの verification セクション
  - （有効なら）メール通知

  <Tip>
  見つからない場合は compliance@dodopayments.com に連絡、または登録メールをチームに DM してください。
  </Tip>
</Accordion>

<Accordion title="Q22: 過去に却下されたが新しいビジネスで作り直せますか？">
  A: はい、ただし以下が条件です:
  - 拒否理由を解消していること
  - リスク判断の回避目的ではないこと（例: 不正による deboarding の回避）

  <Note>
  問題を解決しないまま複数アカウントを作ると再度拒否される可能性が高いです。
  </Note>
</Accordion>

<Accordion title="Q23: 「以前に deboarded」と表示されました。意味は？">
  A: リスクチームが重大なリスク/コンプライアンス問題を検知しています。
  - 同じ個人/事業情報で新規作成すると再度拒否される可能性が高い

  <Note>
  誤りと思われる場合は compliance@dodopayments.com にエビデンスを添えてレビューを依頼してください。
  </Note>
</Accordion>

<Accordion title="Q24: ペイアウト審査を早めるには？">
  A: 遅延を避けるため:
  - 明瞭で正しい書類を提出
  - Discord での重複メッセージ/タグ付けは避ける（キューが遅くなる）
  - 収益閾値を超えた/急ぎ案件がある旨を伝える
  - 求められたら登録メールを DM する

  <Tip>
  多くは 72 営業時間以内に完了しますが、提出内容に問題があると遅延します。
  </Tip>
</Accordion>

<Accordion title="Q25: W-8BEN と W-8BEN-E を間違えました。どうする？">
  A: これらは区分に紐づきます。
  - W-8BEN: 個人
  - W-8BEN-E: 法人

  間違えた場合:
  - サポートに連絡しフォームをリセット
  - 正しいフォームを作成・アップロード
  - PAN は正しい欄（個人は Line 6a）に記入

  <Tip>
  不明な場合は IRS の公式ガイドを参照してください。
  </Tip>
</Accordion>

<Accordion title="Q26: GST が商号付きであります。法人扱いになりますか？">
  A: いいえ。個人で GST 登録していても個人区分です。
  ✅ W-8BEN を使用
  ✅ 登録区分で "Individual" を選択
  ❌ 法人でない限り W-8BEN-E や "Organization" を選ばない
</Accordion>

<Accordion title="Q27: deboard されたので新規作成すればよい？">
  A: deboard 回避目的の新規作成は不可です。
  - 新規もフラグ・拒否される場合があります
  - リスク判断は同一人物/事業で持ち越されます

  <Tip>
  誤りと思う場合は compliance@dodopayments.com へケースを送ってください。
  </Tip>
</Accordion>

<Accordion title="Q28: インド SaaS の GST はどう処理されますか？">
  A: 顧客所在地に基づき **GST** を自動計算・適用します。
</Accordion>

<Accordion title="Q29: 国際販売も対応しますか？">
  A: はい。国際販売と関連するコンプライアンスをサポートします。
</Accordion>

<Accordion title="Q30: 住所（市/州/郵便番号）は必須ですか？省略できますか？">
  A: 必須です。モーチャント・オブ・レコードとして請求書発行・納税・コンプライアンスを行うため顧客の請求先住所が必要です。API ベースのチェックアウトで事前に収集した情報を埋め込むことは可能ですが、毎回住所が必要です。
</Accordion>

<Accordion title="Q31: 米国で販売する場合、米国で税申告が必要？">
  A: 直接は不要です。Dodo がモーチャント・オブ・レコードとして顧客側税務を処理・納付します。あなたは以下が必要です:
  - 自国の所得税申告（例: インド）
  - W-8BEN(-E) 提出（米国 30% 源泉を回避）
</Accordion>

<Accordion title="Q32: W-8BEN と W-8BEN-E のどちらを出すべきか分かりません">
  A: 次の判断表を使ってください。

  | あなたは... | 提出フォーム | 区分 |
  |------------|-------------|------|
  | 個人事業主・フリーランス・個人 | W-8BEN | Individual |
  | Pvt Ltd, LLP, 登録法人 | W-8BEN-E | Organization |

  追加の目安:
  - **銀行口座が個人口座** → Individual → W-8BEN
  - **銀行口座が法人名義** → Organization → W-8BEN-E
  - **GST があっても個人口座運用なら Individual** → W-8BEN

  <Tip>
  GST を持つ個人事業主でも Individual です。登録法人のみ W-8BEN-E を使用してください。
  </Tip>
</Accordion>

<Accordion title="Q33: 米国市民/米国法人です。どの税フォームが必要？">
  A: すべての米国市民および米国登録法人は W-9 を自社または個人名で提出してください。
</Accordion>

<Accordion title="Q34: 決済を受けるのに PAN または GST は必要ですか？">
  A: 個人は PAN が必須（KYC/税務のため）。法人は Business PAN または GSTIN を提出できます。GST は閾値超過または仕入控除を希望しない限り任意です。
</Accordion>

<Accordion title="Q35: Udyam/MSME 証明があります。W-8BEN と W-8BEN-E どちら？">
  A: Udyam/MSME があっても自動で法人扱いになりません。銀行口座種別で判断します:
  - **個人口座で運用**: Individual → **W-8BEN**
  - **法人名義口座で運用**: Organization → **W-8BEN-E**

  <Note>
  重要なのは銀行口座名義であり、登録証の有無ではありません。
  </Note>
</Accordion>

<Accordion title="Q36: Dodo が税処理するなら、なぜ W-8BEN(-E) が必要？">
  A: Dodo は顧客側の売上税を処理しますが、あなたへの支払いに対する源泉税処理に W-8BEN(-E) が必要です。

  <Note>
  正しく提出すると印米租税条約で二重課税を回避できます。
  </Note>
</Accordion>

## 決済・取引

<Accordion title="Q37: どんな支払い方法を受け付けられますか？">
  A: **クレジットカード**、**デビットカード**、**デジタルウォレット** に対応し、単発決済とサブスクリプション決済をサポートします。
</Accordion>

<Accordion title="Q38: 決済ステータスはどこで確認？">
  A: ダッシュボードの **Payments** セクションで確認できます。各取引のステータスは **In Progress / Failed / Successful** で表示されます。
</Accordion>

<Accordion title="Q39: 決済が失敗したら？">
  A: **Payment Details Page** を確認してください。よくある原因は入力ミス、残高不足、ネットワーク障害です。リンクを再送してリトライできます。
</Accordion>

<Accordion title="Q40: 返金不可ポリシーでもチャージバックは発生しますか？">
  A: はい。カードネットワーク（Visa/Mastercard 等）の規約が優先され、"No refunds" だけでは争議を防げません。争議が発生したら、配送証明・利用ログ・同意取得などの証拠で対応してください。銀行がカード保持者有利と判断すれば手数料と取引は戻されます。明確なコミュニケーションと証跡管理を推奨します。
</Accordion>

<Accordion title="Q41: payment.status が一時的に null になるのはなぜ？">
  A: 以下の短時間で null になることがあります:
  - 作成直後で処理完了前
  - サブスク課金失敗/リトライ中

  最終的に succeeded / failed / cancelled のいずれかになります。

  <Note>
  状態追跡は payment.succeeded / payment.failed などの Webhook を利用してください。
  </Note>
</Accordion>

<Accordion title="Q42: チェックアウトなのに product_cart が null なのは？">
  A: 
  - サブスクリプション決済では一回限りの商品がないため空
  - product_cart は単発決済のみで埋まります
</Accordion>

<Accordion title="Q43: テスト中に本物のカードがブロックされました">
  A: Live モードでテストした可能性があります。

  - Live は実際の資金と銀行を通過
  - 低頻度・不規則だと不審フラグになることがあります

  ✅ テストは以下で行ってください:
  - ダッシュボードの Test モード
  - ドキュメント記載のテストカード番号
</Accordion>

<Accordion title="Q44: 顧客が支払完了と言うのに Webhook が届きません">
  A: チェックリスト:
  - Dashboard > Developers > Webhooks に設定済みか
  - 2xx 以外の応答でサイレント失敗していないか
  - ログで 429 やタイムアウトが無いか
</Accordion>

<Accordion title="Q45: ダッシュボードは成功なのにアプリが更新されない">
  A: redirect_url のクエリパラメータだけに依存している可能性があります。以下を実装してください:
  - Webhook
  - API での決済確認

  ✅ 推奨:
  - 常に payment.succeeded Webhook を受信
  - あるいはリダイレクト後に API で取引を確認
</Accordion>

<Accordion title="Q46: UPI が表示されません">
  A: 以下の理由が考えられます:
  - 請求先国が IN になっていない
  - ビジネスで UPI が有効化されていない

  非インド商人の場合、顧客に UPI は表示されません。
</Accordion>

<Accordion title="Q47: サブスクリプションで UPI は使えますか？">
  A: はい、RBI 準拠のマンデートでサポートします。
  - **マンデート上限**:
    - ₹15,000 未満: ₹15,000 のオンデマンドマンデートを作成
    - ₹15,000 以上: サブスクリプション額のマンデートを作成
  - **48 時間の処理遅延**: 予定日に課金が開始され、実際の引き落としは 48 時間後（＋数時間の遅延もあり）
  - **マンデート取消**: 48 時間内は銀行アプリで取消可能

  <Note>
  UPI サブスクはインドのカードサブスクと同じ RBI 規制に従います。詳細は [Payment Methods](/features/payment-methods#upi-and-rupay-india) を参照。
  </Note>
</Accordion>

<Accordion title="Q48: API で請求先情報を渡さずに集める方法は？">
  A: ユーザー入力で集めたい場合:
  - 請求先を自動収集する静的リンクを使用
  - 動的フローでは手動で収集し API に渡す必要があります

  現状、動的リンク作成時に請求先を入力する UI はありません。
</Accordion>

<Accordion title="Q49: 静的リンクと動的リンクの違いは？">
  A: **静的リンク** はノーコードで即利用:
  - ダッシュボードで設定
  - 請求先を自動収集
  - 顧客/セッション単位のカスタムは不可

  **動的リンク** は API で生成:
  - 請求先情報を明示的に渡す必要
  - 価格/ユーザー ID/リダイレクト URL などをリアルタイムにカスタム可能

  <Tip>
  コードを書きたくないなら静的リンク。柔軟なワークフローが必要なら動的リンク。
  </Tip>
</Accordion>

<Accordion title="Q50: サブスクリプション開始時に Webhook は複数届きますか？">
  A: トライアルなしの場合、初回成功時に通常は以下 3 つを受信します:
  - `subscription.created`
  - `payment.succeeded`
  - `subscription.renewal`
</Accordion>

<Accordion title="Q51: subscription.cancelled_at は何を意味しますか？予約キャンセル？">
  A: Dodo は即時キャンセルと予約キャンセルの両方をサポートします。
  - **即時**: subscription.cancelled_at が直ちに設定され、その時点で終了
  - **予約**: subscription patch API の `cancel_at_next_billing_date` で当期末にキャンセル
</Accordion>

<Accordion title="Q52: サブスクリプションはいつ課金されますか？">
  A: トライアルが無ければ作成時に即課金します。

  <Note>
  インドのカード/UPI サブスクでは RBI 規制により 48 時間の遅延があり、実際の引き落としは開始から 48 時間後（＋最大数時間）となります。
  </Note>
</Accordion>

## ペイアウト・銀行連携

<Accordion title="Q53: ペイアウトの仕組みは？">
  A: ペイアウトは売上を登録銀行口座へ振り込む処理です。複数のサイクルをサポートします:
  - **月 2 回（デフォルト）**:
    - 1〜15 日: 当月 18 日に支払い
    - 16 日〜月末: 翌月 4 日に支払い
  - **週次**: 取引量が多いビジネス向け（サポートへ要請）
  - **月次**:
    - 1〜月末: 翌月 11 日に支払い

  すべての審査が完了し、閾値到達時にのみペイアウトされます。振込後、銀行口座反映まで通常 1〜2 営業日です。

  <Note>
  週末・祝日が支払日にかかると遅延することがあります。デフォルトは月 2 回です。
  </Note>
</Accordion>

<Accordion title="Q54: 手数料・税控除後の最低ペイアウト額は？">
  A: 最低 **$50 USD**（または ₹1,000 INR）です。USD ウォレットはダッシュボードで **$50 以上** にカスタムできます。閾値未満の場合は次サイクルに繰越されます。

  ウォレット残高と閾値は [payouts section](https://app.dodopayments.com/business/payouts) で確認できます。

  <Note>
  柔軟閾値は USD/EUR/GBP で利用可能。INR は固定 ₹1,000 です。
  </Note>
</Accordion>

<Accordion title="Q55: 銀行口座の紐づけ方法は？">
  A: ダッシュボードの **Payout Settings** から **Add Bank Account** をクリックし、口座情報を入力して検証してください。
</Accordion>

<Accordion title="Q56: ペイアウト状況を追跡できますか？">
  A: はい、ダッシュボードの **Payouts** セクションで確認できます。
</Accordion>

<Accordion title="Q57: ペイアウト手数料はいくらですか？">
  A: 顧客から集めた資金を銀行へ振り込む際の手数料です。各国パートナー連携で手数料削減に取り組んでいます。詳細は [pricing and fee structure](/miscellaneous/pricing-and-fee-structure#2-payout-fees) を参照してください。
</Accordion>

<Accordion title="Q58: 「payout processed」メールを受け取りました。いつ着金しますか？">
  A: 通常 1〜2 営業日で口座に反映します。

  <Note>
  週末・祝日は精算されません。金曜処理なら月〜火着金を想定してください。
  </Note>
</Accordion>

<Accordion title="Q59: Payoneer をペイアウト口座に追加する方法は？">
  A: ダッシュボードの Bank Info Form に Payoneer 情報を入力するだけです。専用統合はまだありません。
</Accordion>

<Accordion title="Q60: Payoneer 口座へペイアウトできますか？">
  A: はい。以下を行ってください:
  - ダッシュボードの Bank Info Form に Payoneer 口座を入力
  - 口座が承認済みで USD など出金通貨に対応していることを確認

  専用連携はなく、通常の銀行口座として扱われます。
</Accordion>

<Accordion title="Q61: 銀行情報とコンプライアンスフォームが審査中です。何をすべき？">
  A: そのままお待ちください。通常 1〜2 営業日で審査します。急ぎの場合は support@dodopayments.com へ。
</Accordion>

<Accordion title="Q62: ペイアウト日が金曜・週末の場合は？">
  A: 金曜なら通常同日に処理されますが、祝日/週末が重なると次の営業日（月曜が多い）にずれます。詳細なタイミングは銀行の処理規定に依存します。

  <Note>
  不明な場合はダッシュボードを確認するか、登録メールでサポートに問い合わせてください。
  </Note>
</Accordion>

<Accordion title="Q63: 緊急のローンチや広告がある場合、ペイアウト審査を早められますか？">
  A: 提出済みで審査待ちの場合:
  - 緊急性（ローンチ/有料キャンペーン等）をサポートチャットで明確に伝える
  - ビジネス ID とメールを添える
  - 複数メンバーへのスパム/タグ付けは避ける（遅延の原因）
</Accordion>

<Accordion title="Q64: 銀行口座情報を誤入力しました。更新方法は？">
  A: 誤った場合:
  - Intercom/Discord/メールでサポートに連絡
  - Discord なら登録メールを DM し、Bank Verification セクションのリセットを依頼
  - コンプライアンスチームが再提出を開くまで待つ

  <Note>
  提出後はダッシュボードで直接編集できない場合があります。
  </Note>
</Accordion>

<Accordion title="Q65: 登録法人なのに個人口座を使えますか？">
  A: いいえ。法人登録している場合は法人名義の口座を使用してください。
</Accordion>

<Accordion title="Q66: 自国で SWIFT コードがありません。審査に影響しますか？">
  A: ブロックはされませんが手動レビューが必要です。
  - SWIFT が発行されない旨をサポートに説明
  - 以下の公式書類を提出:
    - 口座番号
    - 口座名義
    - SWIFT が発行されないことの証明
  - 場合によっては国別の汎用 SWIFT を使用することがあります

  <Note>
  このケースは手動審査となります。迅速化には compliance@dodopayments.com へ連絡してください。
  </Note>
</Accordion>

<Accordion title="Q67: SWIFT がない場合の代替書類は？">
  A: SWIFT が無い国では以下を提出してください:
  - 口座情報が記載された公式銀行ステートメント/証明書
  - SWIFT が発行されない旨と口座番号・名義を示す銀行レター
  - その国のルーティング形式を示す政府発行の書類

  <Tip>
  正しい書式のため、提出前に support@dodopayments.com に確認するとスムーズです。
  </Tip>
</Accordion>

## Webhook と統合

<Accordion title="Q77: Webhook に POST が届かず GET だけ来ます">
  A: redirect URL と Webhook URL を混同している可能性があります。redirect は支払い後の遷移先で、`?subscription_id=...&status=active` などの GET が付与されますが Webhook ではありません。

  Dodo から構造化された POST を受け取るには:
  - Dashboard → Developers → Webhooks で設定
  - URL が POST を受け 2xx を返し、署名検証を行うこと

  <Note>
  Webhook と redirect は別用途で併用できます。
  </Note>
</Accordion>

<Accordion title="Q78: Python SDK で 401 Unauthorized が出ます">
  A: クライアント初期化時に環境を渡していない可能性があります。

  <Check>
  **修正例:**
  ```python
  client = DodoPayments(
      bearer_token="your_api_key",
      environment="live_mode"  # or "test_mode"
  )
  ```
  </Check>
</Accordion>

<Accordion title="Q79: テスト用に Webhook イベントを手動送信できますか？">
  A: 可能です。Dashboard -> Developers -> Webhooks から送信できます。
</Accordion>

<Accordion title="Q80: Webhook と redirect URL の違いは？">
  A: 
  - **Webhook URL**: ダッシュボードで設定。イベントの POST ペイロードを受信。
  - **Redirect URL**: 支払い API リクエストで指定。ユーザーをアプリに戻し、`?status=success` などのクエリを付与。

  <Tip>
  DB 更新など自動処理は Webhook、サンクスページ表示は redirect を使い分けてください。
  </Tip>
</Accordion>

<Accordion title="Q81: サブスク商品の payment.succeeded に product_id が無いのはなぜ？">
  A: サブスクの payment.succeeded には product_id は含まれず、関連する `subscription_id` などが含まれます。
</Accordion>

<Accordion title="Q82: 受信 Webhook が本物か検証する方法は？">
  A: 次を実施してください:
    1. **署名確認**: すべての Webhook に `webhook-signature` ヘッダーが付与されます。
    2. **シークレット取得**: ダッシュボードの Webhooks 設定でシークレットを確認。
    3. **署名再計算**: HMAC-SHA256 でペイロードとシークレットから署名を再計算。
    4. **比較**: ヘッダー署名と一致するか検証。不一致なら拒否。
    5. **HTTPS**: 常に HTTPS を使用し改ざんを防止。

  <Tip>StandardWebhooks などのライブラリを利用し、独自実装を避けることを推奨します。</Tip>
</Accordion>

<Accordion title="Q83: 初月支払いでも subscription.renew が届くのはなぜ？">
  A: サブスクでは請求発生のたびに `subscription.renew` が送信されるため、初回でも発生します。
</Accordion>

<Accordion title="Q84: ローカルで Webhook をテストするには？">
  A: 以下を行ってください:
  1. **トンネリングツールを使用**: [ngrok](https://ngrok.com/), [LocalTunnel](https://localtunnel.github.io/www/), [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-apps/) などでローカルを公開 URL 化
  2. **Webhook エンドポイントを用意**: ローカルアプリに POST を受けるエンドポイントを実装
  3. **Dodo 側設定**: ダッシュボードの Webhooks 設定で公開 URL を登録
</Accordion>

<Accordion title="Q85: 支払い後に Webhook が呼ばれません">
  A: 以下を確認してください:
  - Webhook URL と redirect URL を混同していないか
  - Developers > Webhooks に設定済みか
  - URL が POST を受け 2xx を返しているか
  - 署名検証（有効な場合）が正しく実装されているか

  GET の `?status=success` しか見えない場合は redirect をデバッグしており、Webhook ではありません。
</Accordion>

<Accordion title="Q86: URL クエリの status=success を信頼してよい？">
  A: いいえ。クエリは改ざんされ得ます。

  redirect_url?status=success を使う場合は:
  - API で取引を二重確認
  - または payment.succeeded Webhook を待つ

  <Tip>
  リダイレクトは顧客向け確認用であり、支払い確定の根拠にはしないでください。
  </Tip>
</Accordion>

## テスト・ローカル開発

<Accordion title="Q87: Test モードでサブスクリプションはテストできますか？">
  A: はい、サブスクは Test モードでフルにテストできます。実カード番号は使わないでください。
</Accordion>

<Accordion title="Q88: Test と Live の切り替え方法は？">
  A: 
  - ダッシュボードで Test Mode トグルを探し ON/OFF
  - 切替時は対応する API キー/環境を使用

  すべての画面に "Test Mode" ラベルが表示されます。
</Accordion>

<Accordion title="Q89: Test モードで実顧客データを使えますか？">
  A: はい、ただし:
  - 実際の資金移動は発生しない
  - Webhook やフローをシミュレート可能
  - カード情報はテストカードを使用

  金銭リスクなしでエンドツーエンド検証できます。
</Accordion>

<Accordion title="Q90: 「You must provide a mandate for off-session card payments」と出ます">
  A: 以下が原因です:
  - インドのカードで支払い、billing country が IN でない
  - 誤った billing country を渡している
</Accordion>

## セキュリティ・不正対策

<Accordion title="Q93: Dodo Payments は不正からどのように保護しますか？">
  A: **リアルタイム不正検知** で不審取引を監視し、**PCI-DSS 準拠** により決済情報を保護します。
</Accordion>

<Accordion title="Q94: 顧客データは安全ですか？">
  A: はい。**データ暗号化** と **トークン化** を用いて機微情報を保護し、顧客の決済データを直接保存しません。
</Accordion>
