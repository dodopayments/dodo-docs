## はじめに

マルチブランド機能を使用すると、**1つの確認済みビジネス**に、それぞれ独自のロゴ、説明、ウェブサイトURLを持つ複数のブランドを追加できます。支払い口座、手数料、KYCはそのままで、すべての製品、支払いリンク、サブスクリプション、請求書、取引は特定のブランドに基づいて分類できます。新しいニッチをテストしたり、サイトをローカライズしたり、余分なビジネスアカウントを開かずにB2BとB2Cのラインを分けたりするために使用します。

## マーチャントダッシュボードのフロー

<Steps>
<Step title="Open Settings → Business">
**設定 → ビジネス**に移動します。右側の**[Your Business] 下のブランド**パネルに、プライマリブランドとセカンダリブランドが一覧表示されます。

<Frame>
<img src="/images/multi-brands/brands-section.png" alt="ビジネス設定のブランドパネル - プライマリおよびセカンダリブランドを表示し、新しいブランドを追加するためのプラスボタン" />
</Frame>
</Step>
<Step title="Click the '+' button">
ブランドパネルで、右上の**+**ボタンをクリックして、新しいブランドフォームを開きます。
</Step>
<Step title="Fill in the brand details">
次の項目を入力してください：

- **ブランド名**（必須）：ブランド名を入力します。
- **ウェブサイトURL**（必須）：ブランドのウェブサイト、例：`https://www.yourcompany.com`。
- **サポートメール**：このブランドのサポートに使用する顧客用メール。
- **ブランド説明**（必須）：ブランド、製品、そのユニークさを説明します。
- **ブランドロゴ**：チェックアウト、請求書、支払いリンクにブランドを表示するロゴをアップロードします。

フォームを送信してブランドを作成します。製品はこのブランドにタグ付けされ、支払いリンクにはそのブランディングが表示されます。
</Step>
<Step title="Brand Selector">
製品作成時にブランドフィルターが表示されます。
</Step>
<Step title="Brand ID in Transactions">
取引やサブスクリプションにはブランドIDがあり、どのブランドに属する取引かを識別するのに役立ちます。
</Step>
</Steps>

## 追加ポイント

- **支払い変更なし:** すべての資金、支払いサイクル、手数料は、引き続きビジネスレベルのウォレットと加盟店の銀行口座に入金されます。
- **Webhook 上の Brand ID:** 支払い、サブスクリプション、返金、異議申し立て、ライセンスキー、クレジット台帳エントリ、クレジット残高低下、権限付与、督促試行、放棄されたチェックアウトの各ペイロードには、`brand_id` が含まれるため、特定のブランドに関連付けることができます。エンティティに独自のブランドがない場合、`brand_id` はビジネスのプライマリブランドにフォールバックします。支払いペイロードはビジネスレベルであり、`brand_id` は含まれません。
- **停止:** ブランドが停止されても、そのブランドの支払いリンクのみが停止します。同じビジネスに属する他のブランドでは、引き続き取引できます。
- Storefront、Invoices、License Keys、Discount Codes、Payout Settings、およびその他のビジネスレベルの機能に変更はありません。

## ブランドのアーカイブ

ブランドの役割を終えたら、ダッシュボードに休眠状態のまま残すのではなく、アーカイブしてください。アーカイブするとブランドは廃止され、そのカタログが同じビジネスの別のブランドに一度の操作で引き継がれます。

<Warning>
ブランドのアーカイブは永続的です。アーカイブしたブランドを復元する方法はありません。
</Warning>

### アーカイブするとどうなるか

アーカイブするブランドに代わって引き継ぐ **対象ブランド** を指定します。ダッシュボードでは常に対象ブランドの指定が求められ、API では `move_products_to` として受け取ります。Dodo Payments は、1 回のアトミックな操作で次を実行します。

- すべての商品を対象ブランドに移動します。
- すべての稼働中のサブスクリプションを対象ブランドに移動します。これにより、更新時の請求は対象ブランドで継続されます。
- すべての商品コレクションを対象ブランドに移動します。
- 元のブランドをアーカイブして無効化します。

履歴は変更されません。支払い、請求書、完了済みのサブスクリプションには、作成時のブランドが保持されるため、過去のレポートの正確性が維持されます。

対象ブランドは同じビジネスに属し、アーカイブされていない必要があります。プライマリブランドは有効な対象であり、そのブランド ID はビジネス ID です。対象を省略できるのは、そのブランドに商品、稼働中のサブスクリプション、商品コレクションがいずれもない場合だけです。

<Note>
プライマリブランドはアーカイブできません。プライマリブランドはビジネスのフォールバック先となるブランドであるため、常に少なくとも 1 つのブランドが残ります。
</Note>

### アーカイブしたブランドは読み取り専用

| 操作 | 結果 |
|---|---|
| ブランドの詳細を編集する | `BRAND_ARCHIVED` により拒否されます |
| ブランドを検証に提出する | `BRAND_ARCHIVED` により拒否されます |
| ブランドで商品またはコレクションを作成する | `BRAND_ARCHIVED` により拒否されます |
| その商品のサブスクリプションを作成する | `BRAND_ARCHIVED` により拒否されます |

アーカイブしたブランドはブランド選択欄に表示されないため、新しいレコードにタグ付けすることはできません。ただし、分析フィルターでは引き続き利用できるため、そのブランドが営業していた期間のブランド別レポートを完全な状態で維持できます。[分析](/features/analytics) を参照してください。

### API を使用したアーカイブ

廃止するブランドと、そのブランドを引き継ぐブランドを指定して、アーカイブエンドポイントを呼び出します。

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

レスポンスには移動された内容が報告されるため、結果を確認できます。

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

アーカイブしたブランドを含むブランドを一覧表示するには、一覧エンドポイントで `include_archived` を設定します。アーカイブしたブランドはデフォルトで除外されます。すべてのブランドには `archived_at` フィールドがあり、ブランドがアクティブな間は `null` です。

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

リクエストとレスポンスの完全なスキーマについては [ブランドのアーカイブ](/api-reference/brands/archive-brand) API リファレンスを、エンドポイントが返すエラーについては [エラーコード](/api-reference/error-codes) を参照してください。
