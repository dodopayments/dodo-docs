## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## チェックアウトごとの支払い方法の設定

ビジネスレベルの設定に加えて、`allowed_payment_method_types`を使用して、個別のチェックアウトセッションに表示される方法を制限できます。

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## ベストプラクティス

<AccordionGroup>
<Accordion title="Match methods to your market">
ターゲット市場向けに地域の支払い方法を含める。iDEALはオランダのオンライン支払いの約60％を占め、UPIはインドで支配的です。これらの方法を省略すると、コンバージョンに大きな影響があります。
</Accordion>

<Accordion title="Always provide card fallbacks">
特定の方法をターゲットにする場合であっても、`credit`と`debit`をフォールバックとして含めます。すべての顧客がすべての支払い方法にアクセスできるわけではありません。
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL方法（Klarna、Afterpay）は50.01ドル以上が必要です。低価格の商品には含めないでください。これらは表示されないだけで、それで問題ありません。
</Accordion>

<Accordion title="Test across regions and devices">
テストモードを使用して、異なる顧客の場所、通貨、デバイスタイプに対する支払い方法の利用可能性を確認してからライブに移行します。
</Accordion>
</AccordionGroup>

## トラブルシューティング

<AccordionGroup>
<Accordion title="Payment method not appearing">
**これらの要因を確認します：**
1. `allowed_payment_method_types`に方法が含まれていますか？
2. 顧客の所在地が方法の対応地域と一致していますか？
3. トランザクション通貨が方法によってサポートされていますか？
4. トランザクション金額が最低額（例：BNPLには$50.01）が満たされていますか？
5. サブスクリプションの場合：方法が継続的な支払いをサポートしていますか？

**解決策：** 一時的に`allowed_payment_method_types`を削除して、所有している方法をすべて表示し、問題を絞り込みます。
</Accordion>

<Accordion title="Unexpected methods appearing">
**可能性のある原因：**
- `allowed_payment_method_types`が正しく渡されていない
- パラメータのフォーマットが間違っている（文字列配列である必要があります）

**解決策：** APIリクエストペイロードをログし、パラメータ構造を確認します。
</Accordion>

<Accordion title="Regional method not available">
**確認事項：**
- 顧客の請求先住所が方法の地域に一致していること
- 通貨が正しく設定されていること（例：iDEALに対してEUR）
- 顧客が国際的な場合、アダプティブ通貨が有効になっていること

**解決策：** APIリクエストで請求先住所の国コードと通貨を確認します。
</Accordion>

<Accordion title="Indian payment method issues">
UPIおよびRupayのサブスクリプションには、48時間の処理遅延やRBIのマンダート制限など、特有の要件があります。

**参照：** <a href="/features/payment-methods/india">インドの支払い方法</a>の完全なガイダンス。
</Accordion>
</AccordionGroup>
