<Info>
Subscription Dunning は、支払いの失敗や顧客のキャンセルによりサブスクリプションが失効した顧客に対して、支払い方法の更新と再有効化を促すメールのシーケンスを自動的に送信します。
</Info>

## サブスクリプション督促とは？

督促は、サブスクリプションが回復可能な状態に入ると自動的に検出し、顧客に行動を促すメールのシーケンスを送信します：

- **保留中のサブスクリプション**：更新支払いが失敗した（不十分な資金、カードの期限切れ等）
- **キャンセルされたサブスクリプション**：顧客ポータルから顧客がキャンセルした

## 督促の仕組み

<Steps>
<Step title="Trigger">
サブスクリプションが次の2つの状態のいずれかに入ると督促が起動します：
- **保留中**: 更新支払いが失敗した（不十分な資金、カードの期限切れ等）
- **キャンセル**: 顧客が顧客ポータルからサブスクリプションをキャンセルした
</Step>

<Step title="Email Sequence">
トリガー状態に基づいて、システムは設定された間隔で最大4通の督促メールを送信します。各メールには、顧客が支払い方法を更新するかサブスクリプションを再購入できる顧客ポータルへのリンクが含まれています。
</Step>

<Step title="Recovery">
顧客が顧客ポータルを通じて支払い方法を更新すると、残りの支払金額に対して自動的に請求が作成されます。支払いが成功すると、サブスクリプションが再有効化され、督促試行が回復済みとして記録されます。
</Step>
</Steps>

## ステータスライフサイクル

| ステータス | 説明 |
|--------|-------------|
| `recovering` | 督促試行がアクティブです；メールが送信されています |
| `recovered` | 顧客が支払い方法を更新し、支払いに成功しました |
| `exhausted` | すべてのメールを送信しましたが回復せず、またはサブスクリプション状態が予期しない変更を受けました |

<Info>
督促試行が `exhausted` として記録されると、サブスクリプション状態は変更されません。サブスクリプションは現在の状態（保留中またはキャンセル）に留まります。
</Info>

### メールシーケンス

督促は2つのメールシーケンス — **保留中**と**キャンセル** — をサポートしており、それぞれ最大4通のメールを設定可能です。

各メールには以下の設定可能なフィールドがあります：

| 設定 | 説明 |
|---------|-------------|
| **Enabled** | 個々のメールを削除せずにオンまたはオフにするトグル |
| **Delay** | トリガーイベントからこのメールを送信するまでの時間 |
| **Subject** | 変数プレースホルダー付きメール件名 |
| **Body** | 変数プレースホルダー付きHTMLメール本文 |
| **Reply-To** | 顧客からの返信用メールアドレス |

**デフォルトのメールタイミング：**

| シーケンス | メール番号 | デフォルト遅延 |
|----------|---------|---------------|
| 保留中 | 1 | 1日 |
| 保留中 | 2 | 3日 |
| 保留中 | 3 | 5日 |
| 保留中 | 4 | 7日 |
| キャンセル | 1 | 1日 |
| キャンセル | 2 | 3日 |
| キャンセル | 3 | 5日 |
| キャンセル | 4 | 7日 |

## 顧客の回復体験

顧客が督促メール内のリンクをクリックすると、顧客ポータルに移動し、そこでサブスクリプションのステータスを確認し、支払い方法を更新できます。

<Frame caption="Customer portal showing an on-hold subscription with option to update payment method">
<img src="/images/recovery/customer-recovery-page.png" alt="保留中のサブスクリプションを示す顧客ポータル：Pro Plan $95.00/年、支払い方法更新ボタン、支払い失敗に関する警告バナー" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

顧客が支払い方法を更新すると、未払い金に対して自動的に請求が作成されます。支払いが成功すると、サブスクリプションは直ちに再有効化されます。

キャンセルされたサブスクリプションの場合、顧客は既にサブスクリプションが商品として追加されているチェックアウトページに移動します。

## 分析

ダッシュボードの**分析**セクション内の**回復**タブから督促のパフォーマンスを追跡します。

<Frame caption="Recovery analytics dashboard showing ACR and dunning metrics">
<img src="/images/recovery/recovery-analytics.png" alt="督促エントリー数、成功率、回収収益、メールごとのパフォーマンス内訳を示す回復分析ダッシュボード" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

| 指標 | 説明 |
|--------|-------------|
| **督促エントリー** | 作成された督促試行の総数 |
| **成功率** | 回復に至った督促試行の割合 |
| **回収された収益** | 督促を通じて回収された総収益 |
| **試行別の回復** | シーケンス内のどのメールが回復を促進したかの内訳 |

## 特殊ケース

| シナリオ | 挙動 |
|----------|----------|
| メール以前に顧客が支払い方法を更新 | 回復が検出され、督促試行は回復済みとして記録されます |
| 同一事業者から別のサブスクリプションを購入した顧客 | 督促試行は使い果たされたと記録されます |
| すべての督促メールが尽きた | 督促試行は使い果たされたと記録され、サブスクリプション状態は変更されません |

## ベストプラクティス

- **デフォルトで開始**：デフォルトのメールタイミングは、顧客を圧倒せずに緊急性を維持するように合理的な間隔（1、3、5、7日）で設計されています。
- **成功率を監視**：シーケンス内でどのメールが最も回復を促進するかを追跡しましょう。後のメールがほとんど効果を示さない場合、それらを無効にすることを検討してください。
- **サポートと連携**：サポートチームが督促メールが送信されていることを知っておくようにし、顧客が連絡を取ってきた際に支援できるようにしましょう。
- **サブスクリプション状態を確認**：包括的なライフサイクルトラッキングのために `subscription.on_hold` と `subscription.cancelled` のWebhookとペアにしてください。

<Info>
督促は、既存のサブスクリプション保留および再有効化フローと併用され、顧客ポータル内で動作します。一度有効化すると、追加の統合なしで自動的に実行されます。
</Info>
