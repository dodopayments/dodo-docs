<Info>
カート放棄の回復（ACR）は未完了または失敗したチェックアウトを検出し、自動的なメールシーケンスを送信して顧客を誘導します。回復率を最大化するためにオプションの割引インセンティブと組み合わせることができます。
</Info>

## カート放棄の回復とは？

ACRは、支払いが失敗した場合や支払う前に離れた場合など、チェックアウトを開始したが完了しなかった顧客を自動的に特定し、回復メールのシーケンスを送信して顧客を呼び戻します。

- **支払い失敗**: 顧客が支払いを試みたが、拒否またはエラーが発生
- **未完了のチェックアウト**: 顧客がチェックアウトに訪れたが支払いを試みなかった

## ACRの動作方法

<Steps>
<Step title="Detection">
成功していない60分以上経過した支払いをスキャンします。これには支払いが失敗したものや顧客が支払いを試みなかったチェックアウトが含まれます。
</Step>

各放棄されたチェックアウトは理由ごとに分類されます:
- **支払い失敗**: 顧客が支払いを試みたが失敗
- **未完了のチェックアウト**: 顧客がチェックアウトに訪れたが支払いを試みなかった
</Step>

分類に基づいて、システムは設定された間隔で最大3つの回復メールを送信します。各メールには固有の回復リンクが含まれています。
</Step>

顧客が回復リンクをクリックすると、元のカートを表示する回復ページに移動し、 新しいチェックアウトセッションで支払いを完了できます。
</Step>
</Steps>

## ステータスのライフサイクル

各放棄されたチェックアウトは次の状態を進行します:

| ステータス | 説明 |
|--------|-------------|
| `abandoned` | 放棄として検出されたチェックアウトで、まだメールが送信されていない |
| `recovering` | 少なくとも1つの回復メールが送信された |
| `recovered` | 顧客が回復リンクを通じて支払いを完了した |
| `exhausted` | 全てのメールが送信されたが回復されなかった、または新しいチェックアウトがこれより優先された |
| `opted_out` | 顧客が回復メールの購読を解除した |

### グローバル設定

| 設定 | 説明 | デフォルト |
|---------|-------------|---------|
| **有効** | ACRのマスタートグル | オフ |
| **割引有効** | 回復メール用の割引コードを自動生成 | オフ |
| **割引率** | この顧客のチェックアウトに適用される割引率 | 0 |
| **割引有効日数** | 自動生成割引コードの有効期間（日数） | 5 |

### メールシーケンス

ACRは**支払い失敗**と**未完了のチェックアウト**というそれぞれ最大3つの設定可能なメールを持つ2つのメールシーケンスをサポートします。

メールシーケンスエディターに示す件名、本文、タイミング、およびシーケンス内の各メールの有効化トグル
<img src="/images/recovery/acr-email-config.png" alt="Email sequence editor showing subject, body, timing, and enable toggle for each email in the sequence" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

| 設定 | 説明 |
|---------|-------------|
| **有効** | 個々のメールを削除せずにオンまたはオフに切り替え |
| **遅延** | 放棄検出後にこのメールを送信するまでの時間 |
| **件名** | 変数プレースホルダー付きのメール件名 |
| **本文** | 変数プレースホルダー付きのHTMLメール本文 |
| **返信先** | 顧客の返信用メールアドレス |

**デフォルトのメールタイミング:**

| メール # | デフォルトの遅延 |
|---------|---------------|
| 1 | 1時間 |
| 2 | 24時間 |
| 3 | 72時間 |

## 回復割引

割引が有効な場合、ACRは自動的にそれぞれの放棄されたチェックアウト用に一回限りのユニークな割引コードを生成します。この割引は:

- 元のチェックアウトの製品に限定されます
- 設定可能な有効期間があります
- 1回の利用に制限されます
- ダッシュボードの割引リストに表示されません（内部使用のみ）

控えめな割引（5-10％）で始め、影響をテストしてから増やします。小さなインセンティブでさえも回復率を大幅に改善できます。
</Tip>

## 顧客の回復体験

顧客がメール内の回復リンクをクリックすると、元のチェックアウトセッションに戻されます。ページには残された製品が表示され、割引コードが設定されていれば表示されます。

## エッジケース

| シナリオ | 動作 |
|----------|----------|
| 顧客が次のメールの前に購入を完了 | 送信時に回復が検出され、適格であればチェックアウトは回復済みとしてマークされる |
| 顧客が新しいチェックアウトを開始 | 古い放棄されたチェックアウトが`exhausted`としてマークされる |
| 顧客が回復後に再び「支払う」をクリック | 回復ページに支払いが既に完了したことが確認される |
| 顧客が購読を解除 | 放棄されたチェックアウトが`opted_out`としてマークされ、今後のメールは送信されません |

## ベストプラクティス

- **デフォルトで始めます**: デフォルトのメールタイミングと件名は一般的な回復パターンに最適化されています。基礎データを取得してからカスタマイズしてください。
- **メールをパーソナライズします**: テンプレート変数を使用して、メールを個別で関連性のあるものにします。
- **分析の監視**: メール別の回復率を追跡して、最もコンバージョンを促すメッセージを特定します。パフォーマンスの低いメールを無効にします。
- **戦略的に割引を利用**: 影響をテストしながら利益を守るため、控えめ（5-10%）で始めます。
- **メールを簡潔に保持**: 回復メールは短く行動志向であるべきです。クリアな行動呼びかけは、長い説明よりも良い結果をもたらします。

ACRは有効化されると自動的に機能するように設計されています。デフォルト設定で始め、分析結果を監視し、パフォーマンスデータに基づいて反復します。
</Info>
