## 新機能

### 1. **製品レベルの分析**

すべての製品には独自の**専用分析ダッシュボード**があります。**Products > [製品を選択]**に移動して、その製品に特化した詳細なメトリクスにアクセスできます。これらは5つのタブに整理されています:

<Frame>
<img src="/images/product-analytics/overview.png" alt="製品レベルの分析" />
</Frame>

| タブ | 得られるもの |
|-----|-------------|
| **概要** | 総収益、成功した支払い数、30日間の収益トレンドチャート（日別または累積）、フィルタ可能な取引テーブル |
| **顧客** | 支出でランク付けされたトップ3の顧客（表彰台ビュー）、およびフル顧客内訳テーブル |
| **維持** | 顧客の離脱率、収益の離脱率、パターンを特定するための二重線トレンドチャート |
| **サブスクライバー** | ステータス、開始日、次回請求日、金額を含む製品のすべてのサブスクリプション |
| **MRR** | 新しいMRR、拡張MRR、離脱したMRR、純新MRRの内訳を含む毎月の繰り返し収益の積み上げ棒グラフ |

すべてのタブは**日付フィルター**（デフォルトは「すべての時間」）をサポートしており、任意の期間にドリルダウンできます。

<Tip>
離脱が高い製品を早期に特定するには維持タブを使用し、MRRタブを利用して拡張収益が月ごとに離脱収益を上回っているかを追跡してください。
</Tip>

詳細については、[製品レベルの分析](/features/analytics-and-reporting#product-level-analytics)をご覧ください。

### 2. **Dodo PaymentsのVerifi RDRサポート**

Dodo Paymentsは、Verifiによる**Visa Rapid Dispute Resolution (RDR)**をサポートします。これは、適格なVisaの紛争を**正式なチャージバックになる前に解決**する自動化された紛争防止ツールです。カード保有者が紛争を開始すると、RDRはそれをキャッチし、取引が設定されたUSDの閾値以下であれば自動的に返金を発行します。

**重要な理由**

| 利点 | 影響 |
|---------|--------|
| **紛争率の低下** | RDRで解決された紛争は、Visaの0.9%の閾値にカウントされません |
| **紛争手数料なし** | 各紛争につき$15-$25の返金不可の手数料を回避 |
| **運用オーバーヘッドなし** | 証拠収集や応答期限はありません |
| **顧客体験の向上** | カード保有者は即座に返金を受け取ります |
| **アカウント保護** | Visaの紛争監視プログラム（VDMP）にかからないようにする |

<Warning>
Visaの0.9%の紛争率を超えたり、月あたり100件の紛争を超えたりすると、VDMPが発動し、最高$50,000+/月の罰金が課せられます。RDRはこれらの閾値を下回った状態に保つのに役立ちます。
</Warning>

**仕組み**

1. カード保有者が銀行で紛争を開始します
2. RDRが紛争を正式なチャージバックになる前にキャッチします
3. 取引金額が閾値以下であれば、自動的に返金が行われます
4. 紛争は即座に解決され、**紛争率にはカウントされません**

<Info>
RDRを通じて自動返金された取引は、Dodo Paymentsダッシュボードで**失われた紛争**として表示されます。これは予期されたもので、正式なチャージバックを防ぐために返金が自動的に発行されたためです。
</Info>

アカウントでVerifi RDRを有効にするには、**support@dodopayments.com**に連絡して閾値を設定してください。

詳細については、[Visa RDR ドキュメンテーション](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)をご覧ください。

### 3. **DodoPayments CLI**

新しい**DodoPayments CLI** (`dodopayments-cli`)の登場 -- ターミナルから直接Dodo Paymentsのワークフロー全体を管理します。コマンドラインを好む開発者のために構築されたCLIを使用すると、製品、支払い、顧客、割引、ライセンス、アドオン、返金を管理し、エディターを離れることなくチェックアウトセッションを作成できます。

**インストール**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**主要コマンド**

| コマンド | 説明 |
|---------|-------------|
| `dodo login` | APIキーで認証します（ブラウザを開きます） |
| `dodo products list` | すべての製品をリスト表示 |
| `dodo payments list` | すべての支払いをリスト表示 |
| `dodo customers create` | 新しい顧客を作成 |
| `dodo checkout new` | チェックアウトセッションを作成し、URLを取得 |
| `dodo wh listen` | WebSocketを介してローカルサーバーにライブテストWebhookを転送 |
| `dodo wh trigger` | 任意のエンドポイントにモックWebhookペイロードを送信 |

**Webhookテスト**

CLIには開発用の2つの強力なツールが含まれています:

- **`dodo wh listen`** -- リアルタイムテストWebhookをローカルサーバーに転送するためのWebSocket接続を開き、署名検証テストのために元のヘッダーを保持します
- **`dodo wh trigger`** -- インタラクティブにモックWebhookペイロードを送信し、サブスクリプション、支払い、返金、紛争、およびライセンスに関する22のイベントタイプをサポートします

<Tip>
Webhookリスナーは**テストモード**のAPIキーでのみ機能します。`dodo wh listen`を使用する前にテストモードのキーでログインしていることを確認してください。
</Tip>

詳細については、[CLI ドキュメンテーション](/developer-resources/sdks/cli)をご覧ください。

顧客ポータルは完全に再設計され、クリーンで統一されたインターフェースを提供します。改修されたポータルには左側のサイドバーナビゲーションと整理されたセクションがあり、顧客にとってより直感的なセルフサービス体験を提供します。

### 5. **インラインチェックアウトでの支払い方法の更新**

現在、[インラインチェックアウト](/developer-resources/inline-checkout)はサブスクリプションの支払い方法の更新をサポートしています。顧客が支払い方法を更新する必要がある場合（アクティブなサブスクリプション用、または保留中のサブスクリプションの再開のため）、支払い方法の更新フローがインラインチェックアウトを使用してページレイアウト内で直接表示され、シームレスで埋め込まれた体験を提供します。

**仕組み**

1. 更新支払い方法APIを呼び出して `payment_link` を取得します:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. 戻された `payment_link` をインラインチェックアウトの `checkoutUrl` として使用します:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

インラインフレームは、顧客が新しいカードの詳細を入力したり、保存された支払い方法を選択したりするための支払い方法収集フォームのみを表示し、ページを離れることなく行えます。

<Tip>
保留中のサブスクリプションの場合、支払い方法の更新フローは残額の請求を自動的に作成します。再開を確認するには、`payment.succeeded` と `subscription.active` のWebhookを監視してください。
</Tip>

詳細については、[インラインチェックアウト](/developer-resources/inline-checkout) | [サブスクリプションの支払い方法の更新](/features/subscription#update-payment-method-for-active-subscription)をご覧ください。

### 6. **チェックアウトセッションの税ID自動入力サポート**

現在、チェックアウトセッションを作成する際に `tax_id` パラメータを使用して**税ID**（例：VAT番号、GST番号）を自動的に入力できます。これは、顧客の税識別番号が既に分かっているB2B取引に最適です。税IDが自動入力されると、フィールドは事前に入力され、チェックアウトフォームでロックされます。

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`tax_id` パラメータには、少なくとも`country`フィールドを持つ`billing_address`が必要です。税の適格性はリアルタイムで検証され、適格なB2B取引に対してはリバースチャージルールが自動的に適用されます。
</Info>

`allow_customer_editing_tax_id` 機能フラグを使用して、顧客が事前入力された税IDを変更できるかどうかを制御し、`allow_tax_id` を使用してチェックアウト時の税IDの表示を切り替えます。

詳細については、[チェックアウトセッション - 税ID](/developer-resources/checkout-session) | [B2B支払い](/features/b2b-payments)をご覧ください。

### 7. **リターンURLリダイレクトでのライセンスキーおよびメールの追加**

顧客がチェックアウトを完了した後、Dodo Paymentsは、`license_key` および `email` をクエリパラメータとして、既存の `payment_id`/`subscription_id` および `status` パラメータに追加します。

**追加されたクエリパラメータ**

| パラメータ | 種類 | 条件 |
|-----------|------|-----------|
| `payment_id` | `string` | 一度の支払いには常に存在 |
| `subscription_id` | `string` | サブスクリプション支払いには常に存在 |
| `status` | `string` | 常に存在 |
| `license_key` | `string` | 製品にライセンスキーが有効な場合に存在（複数の場合、カンマ区切り） |
| `email` | `string` | 顧客に記録されたメールが存在する場合に存在 |

**リダイレクトURLの例:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
これらのクエリパラメータを使用して、ライセンスキーを表示したり、追加のAPI呼び出しを行うことなく確認メールを即座に送信することができます。
</Tip>

詳細については、[チェックアウトセッション - リターンURL](/developer-resources/checkout-session) | [リターンURLのライセンスキー](/features/license-keys#license-keys-in-return-url)をご覧ください。

### 8. **顧客メール更新API**

`PATCH /customers/{customer_id}` エンドポイントは、プログラム的に顧客のメールアドレスを更新することをサポートしています。メールを、名前、電話番号およびメタデータと共に単一のAPI呼び出しで更新します。

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**更新可能なフィールド**

| フィールド | 種類 | 説明 |
|-------|------|-------------|
| `email` | `string \| null` | 顧客のメールアドレス |
| `name` | `string \| null` | 顧客の表示名 |
| `phone_number` | `string \| null` | 国際フォーマットでの電話番号 |
| `metadata` | `object \| null` | カスタムのキー・バリューのペア |

<Info>
顧客メールの更新は、顧客ポータル（セルフサービス）、ダッシュボード、CLIを介して、`dodo customers update`を使用しても行えます。
</Info>

詳細については、[顧客更新API](/api-reference/customers/patch-customer) | [顧客管理](/features/customers)をご覧ください。

### 9. **Bunアダプタのリリース**

`@dodopayments/bun`の導入 -- [Bun](https://bun.sh) のネイティブサーバー向けの専用フレームワークアダプタです（`Bun.serve()`）。チュートリアルの数行で、チェックアウト、顧客ポータル、およびWebhookをBunに統合します。

**インストール**

```bash
bun add @dodopayments/bun
```

**クイックセットアップ**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Bunアダプタは、すべての3つのチェックアウトフロー（静的、動的、セッションベース）、顧客ポータルのセッション生成、署名検証とZodバリデーションを使用したセキュアなWebhook処理をサポートし、22のイベントタイプにわたります。

<Check>
Bunアダプタは、Next.js、Nuxt、Express、Fastify、Hono、Astro、SvelteKit、Remix、TanStack Start、Better Auth、Convexを含む11のフレームワークアダプタのファミリーに参加します。
</Check>

詳細については、[Bunアダプタのドキュメンテーション](/developer-resources/bun-adaptor) | [フレームワークアダプタの概要](/developer-resources/framework-adaptors)
