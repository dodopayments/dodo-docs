## API Key の管理と認証

<Steps>
<Step title="Access API Keys">
ダッシュボードで **Developer → API Keys** に移動して、key を管理します。
</Step>

<Step title="Generate a New Key">
**Add API Key** を選択し、説明的な名前を入力して、write access を設定します。

- **Enable write access**（チェックあり）：すべての API 操作に対する完全な読み取りおよび書き込み権限
- **Enable write access**（チェックなし）：読み取り専用アクセス。データ（payments、subscriptions、customers、products）の取得のみ可能。リソースの作成や変更はできません。

<Tip>
ダッシュボード連携、分析ツール、変更を行わずデータの閲覧のみを必要とするシステムでは、「Enable write access」のチェックを外します。
</Tip>
</Step>

<Step title="Store Your Key Securely">
生成された key をすぐにコピーし、安全に保存されていることを確認します。
</Step>

<Step title="Authenticate Your API Requests">
すべてのリクエストの認証には API keys を使用します。次の authorization 形式を適用してください。

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
secret API keys を client-side code や public repositories に公開しないでください。
</Warning>
</Step>
</Steps>

## Rate Limits

当社の API は、burst protection を備えた dual-window rate limiting system を使用します。制限は、認証方式と business tier に基づいて適用されます。

### Default Limits（Tier 0）

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 40 requests |
| Per Minute (Sustained) | 240 requests |

### Business Tiers

API の利用ニーズが高い business には、より高い rate limits を利用できます。

| Tier | Burst (per second) | Sustained (per minute) |
|------|-------------------|------------------------|
| Tier 0 (Default) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
business をより高い rate limit tier にアップグレードするには、support にお問い合わせください。
</Tip>

### Unauthenticated Requests

有効な認証 headers のないリクエストは、IP address に基づいて rate limited されます。

| Window | Limit |
|--------|-------|
| Per Second (Burst) | 20 requests |
| Per Minute (Sustained) | 100 requests |

### Rate Limit Headers

次の response headers で利用状況を監視できます。

- `X-RateLimit-Limit` - 許可される最大リクエスト数
- `X-RateLimit-Remaining` - 現在の window で残っているリクエスト数
- `X-RateLimit-Reset` - rate limit がリセットされる時刻

<Note>
rate limits を超過すると、API は `429 Too Many Requests` response を返します。retry logic には exponential backoff を実装してください。
</Note>
