サブスクリプションの支払い方法を更新します。このエンドポイントは、アクティブなサブスクリプションと `on_hold` 状態のサブスクリプションの両方をサポートしています。

<Info>
`on_hold` 状態のサブスクリプションの場合、支払い方法を更新すると、未払い残高の請求が自動的に作成され、請求書が生成され、支払いが成功するとサブスクリプションが `active` 状態に再活性化されます。
</Info>

### 使用例

- **アクティブなサブスクリプション**: カードが期限切れになったときや、顧客が別の支払い方法を使用したいときに支払い方法を更新
- **保留中のサブスクリプション**: 支払い失敗により保留になったサブスクリプションを支払い方法を更新することで再活性化
- **支払い方法の管理**: 保存された支払い方法の間で切り替えたり、新しいものを追加したりする

<Info>
顧客の既存の支払い方法を一覧表示するには、[List Payment Methods API](/api-reference/customers/get-customer-payment-methods) を使用します。これは、サブスクリプションの支払い方法を更新する際に `type: "existing"` を使用して利用可能な支払い方法IDを取得するのに役立ちます。
</Info>

### アクティブなサブスクリプションの動作

アクティブなサブスクリプションの支払い方法を更新する場合:

- 支払い方法は即座に更新されます
- 請求は作成されません
- サブスクリプションはアクティブのままです
- 今後の更新は新しい支払い方法を使用します

### 保留中のサブスクリプションの動作

`on_hold` 状態のサブスクリプションの支払い方法を更新する際には、

1. 未払いの請求が自動的に作成されます
2. 請求書が請求のために生成されます
3. 新しい支払い方法を使用して支払いが処理されます
4. 支払いが成功すると、サブスクリプションが `active` 状態に再活性化されます
5. 次のWebhookイベントを受け取ります： `payment.succeeded` の後に `subscription.active`

<Warning>
`on_hold` サブスクリプションの支払い方法を更新した後に支払いが失敗した場合、サブスクリプションは `on_hold` 状態のままになります。支払い状況を追跡するためにWebhookイベントを監視してください。
</Warning>

### Webhookイベント

`on_hold` サブスクリプションの支払い方法を更新すると、次のWebhookイベントが受信されます：

1. **`payment.succeeded`** - 残りの請求の請求が成功しました
2. **`subscription.active`** - サブスクリプションが再活性化されました
