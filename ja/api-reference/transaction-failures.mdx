## 概要

Dodo Payments は、支払いの試行が失敗するたびに詳細な失敗理由を返します。これらの理由は決済手段やプロバイダーを問わず標準化されているため、アプリケーションで一貫した処理を実装できます。

支払いが失敗すると、`payment.failed` webhook と payment object には次の情報が公開されます。

- `error_code` — 以下の表に記載された標準化された失敗理由。
- `error_message` — 人間が読める説明。
- `retry_attempt` — 元の charge では `0`、スケジュールされた subscription renewal の各リトライでは `1` 以上。

これらの失敗理由を理解すると、顧客に明確なフィードバックを提供し、リトライする価値があるかを判断し、より多くの収益を回収できます。

<Card title="Handle Payment Failures" icon="screwdriver-wrench" href="/developer-resources/handle-payment-failures">
webhook と API からこれらのコードを読み取り、顧客に表示し、リトライするタイミングを判断するための、ステップごとの開発者向けガイドです。
</Card>

## ソフトディクラインとハードディクライン

すべての失敗コードは、2つのカテゴリーのいずれかに分類されます。この区別によって、同じ決済手段でリトライするか、顧客に新しい決済手段を求めるかが決まります。

| ディクラインの種類 | 意味 | 対応 | 例 |
|--------------|---------------|------------|----------|
| **ソフトディクライン** | 一時的または修正可能 — 後の試行で同じカードが利用できるようになるか、顧客が入力内容を修正すると成功します。 | 安全にリトライできます（一定時間待つか、顧客が詳細を修正した後）。 | `INSUFFICIENT_FUNDS`、`GENERIC_DECLINE`、`CARD_VELOCITY_EXCEEDED`、`PROCESSING_ERROR`、`NETWORK_ERROR`、`NETWORK_TIMEOUT`、`TRY_AGAIN_LATER` |
| **ハードディクライン** | 終端的 — 同じカードでリトライしても結果は変わりません。 | 同じカードで**リトライしないでください**。顧客に別の決済手段を使うか、銀行に問い合わせるよう依頼します。 | `STOLEN_CARD`、`LOST_CARD`、`PICKUP_CARD`、`DO_NOT_HONOR`、`FRAUDULENT`、`INVALID_ACCOUNT` |

subscription renewal では、Dodo Payments がこの区別を自動的に適用します。ソフトディクラインは [Subscription Payment Retries](/features/recovery/payment-retries) によって再試行され、ハードディクラインはリトライチェーンを直ちに終了します。ハードディクラインには [Subscription Dunning](/features/recovery/subscription-dunning) による対応が適しています。

<Warning>
**`STOLEN_CARD`、`LOST_CARD`、`PICKUP_CARD`、または `FRAUDULENT` の実際の理由を顧客に決して明かさないでください。** これらを表示すると、不正行為者に手がかりを与える可能性があります。顧客には常に一般的なディクラインメッセージ（例：*「カードが拒否されました。銀行に問い合わせるか、別のカードを使用してください。」*）を表示し、具体的なコードは内部でのみ記録してください。
</Warning>

## トランザクション失敗の理由

次の表には、すべての失敗コード、ディクラインの種類、顧客が解決できるかどうか、説明、および推奨アクションを記載しています。

| 失敗コード | 種類 | ユーザーエラー | 説明 | 推奨アクション |
|--------------|------|------------|-------------|--------------------|
| `AUTHENTICATION_FAILURE` | Soft | Yes | トランザクション中の認証に失敗しました | 顧客にリトライして3DS認証を完了するか、別のカードを使用するよう依頼します |
| `AUTHENTICATION_REQUIRED` | Soft | Yes | トランザクションを完了するには追加認証が必要です | 顧客に3DS認証の完了を促します。subscription renewal の場合は、顧客に戻って認証するよう依頼します |
| `AUTHENTICATION_TIMEOUT` | Soft | Yes | 認証プロセスがタイムアウトしました | 顧客にリトライして、速やかに認証を完了するよう依頼します |
| `CARD_DECLINED` | Soft | No | 発行銀行が具体的な理由なしにカードを拒否しました（一般的なディクライン） | 顧客にリトライするか、銀行に問い合わせるか、別のカードを使用するよう依頼します |
| `CARD_NOT_ACTIVATED` | Soft | Yes | カード会員によってカードが有効化されていません | 顧客に銀行でカードを有効化してからリトライするよう依頼します |
| `CARD_VELOCITY_EXCEEDED` | Soft | Yes | 短時間に試行されたトランザクションが多すぎます | 顧客に待ってから後でリトライするか、利用限度額について銀行に問い合わせるよう依頼します |
| `CUSTOMER_CANCELLED` | Soft | Yes | 顧客がトランザクションをキャンセルしました | 顧客の準備ができたらチェックアウトを再開できるよう案内します |
| `DO_NOT_HONOR` | Hard | No | 発行銀行がトランザクションを明示的に拒否しました（ISO 8583 code 05 — honor しない）；network ではこれを終端的なものとして扱います | 顧客に銀行へ問い合わせるよう依頼します。同じカードでリトライしないでください |
| `EXPIRED_CARD` | Hard | Yes | カードの有効期限が切れています | 顧客に有効期限内のカードを使用するよう依頼します |
| `FRAUDULENT` | Hard | Yes | トランザクションが不正の可能性ありとしてフラグ付けされました | 顧客には一般的なディクラインメッセージを表示し、理由は明かさないでください。別のカードを使用するよう依頼します |
| `GENERIC_DECLINE` | Soft | No | トランザクションが不明な理由で拒否されました | 顧客に銀行へ問い合わせるか、別のカードを試すよう依頼します |
| `INCORRECT_CVC` | Soft | Yes | 入力されたCVC codeが正しくありません | 顧客に正しいCVCを再入力するよう依頼します |
| `INCORRECT_NUMBER` | Soft | Yes | カード番号が正しく入力されていません | 顧客に正しいカード番号を再入力するよう依頼します |
| `INSUFFICIENT_FUNDS` | Soft | Yes | 口座残高が不足しているためトランザクションを完了できません | 顧客に別の決済手段を使用するか、残高が利用可能になってからリトライするよう依頼します |
| `INVALID_ACCOUNT` | Hard | Yes | 提供された口座情報が無効です | 顧客に銀行へ問い合わせるか、別のカードを使用するよう依頼します |
| `INVALID_AMOUNT` | Soft | Yes | トランザクション金額が無効です | 顧客と金額および購入限度額を確認します |
| `INVALID_CARD_NUMBER` | Soft | Yes | カード番号の形式が無効です | 顧客に有効なカード番号を再入力するよう依頼します |
| `INVALID_CARD_OWNER` | Soft | Yes | カード所有者情報が無効です | 顧客にカード名義人の氏名を修正するよう依頼します |
| `INVALID_CVC` | Soft | Yes | CVCの形式が無効です | 顧客に有効なCVCを再入力するよう依頼します |
| `INVALID_EXPIRY_YEAR` | Soft | Yes | カード有効期限の年が無効です | 顧客に有効な有効期限を入力するよう依頼します |
| `INVALID_PIN` | Soft | Yes | 入力されたPINが正しくありません | 顧客に正しいPINを再入力するよう依頼します |
| `INVALID_REQUEST` | Soft | Yes | トランザクションリクエストに無効なデータが含まれています | payment request fields を確認し、有効なデータで再送信します |
| `INVALID_UPI_ID` | Soft | Yes | 入力されたUPI IDが無効です | 顧客に有効なUPI IDを入力するよう依頼します |
| `LIMIT_EXCEEDED` | Soft | Yes | トランザクションがカードまたは口座の限度額を超えています | 顧客に限度額について銀行に問い合わせるか、別の方法を使用するよう依頼します |
| `LIVE_MODE_TEST_CARD` | Hard | Yes | live modeでtest cardが使用されました | 実際のカードを使用します。live modeではtest cardでのリトライは常に失敗します |
| `LOST_CARD` | Hard | Yes | カードが紛失したものとして報告されています | 顧客には一般的なディクラインメッセージを表示し、理由は明かさないでください。別のカードを使用するよう依頼します |
| `MANDATE_INVALID` | Soft | Yes | payment mandateが無効です | 顧客にpayment mandateを再設定するよう依頼します |
| `MANDATE_REQUIRED` | Soft | Yes | このトランザクションにはmandateが必要です | mandateを設定し、chargeする前に顧客に承認を依頼します |
| `MANDATE_REQUIRED_SYSTEM` | Hard | No | システムがこの種類のトランザクションにmandateを必要としています | chargeする前にmandate setup flowが完了していることを確認します |
| `NETWORK_ERROR` | Soft | No | トランザクション中にnetwork errorが発生しました | 一時的なエラーです。短時間待ってから支払いをリトライします |
| `NETWORK_TIMEOUT` | Soft | No | network requestがタイムアウトしました | 一時的なエラーです。短時間待ってから支払いをリトライします |
| `ORDER_ALREADY_EXISTS` | Soft | No | このトランザクションのorderはすでに存在します（orderの重複作成） | リトライする前に既存のorderのステータスを確認します。解消しない場合はサポートに連絡します |
| `ORDER_CREATION_FAILED` | Soft | No | トランザクションのorder作成に失敗しました | 一時的なシステムエラーです。支払いをリトライし、解消しない場合はサポートに連絡します |
| `PAYMENT_METHOD_PROVIDER_DECLINED` | Hard | Yes | payment method providerがトランザクションを拒否しました | 顧客にproviderへ問い合わせるか、別のpayment methodを使用するよう依頼します |
| `PAYMENT_METHOD_UNSUPPORTED` | Hard | Yes | このトランザクションではpayment methodがサポートされていません | 顧客にサポート対象のpayment methodを使用するよう依頼します |
| `PICKUP_CARD` | Hard | Yes | カードが紛失または盗難されたものとして報告され、回収対象としてフラグ付けされています | 顧客には一般的なディクラインメッセージを表示し、理由は明かさないでください。別のカードを使用するよう依頼します |
| `PROCESSING_ERROR` | Soft | No | トランザクションの処理中にエラーが発生しました | 一時的なエラーです。支払いをリトライし、解消しない場合は顧客に銀行へ問い合わせるよう依頼します |
| `PROVIDER_UNSUPPORTED` | Hard | No | payment providerがこの種類のトランザクションをサポートしていません | 顧客に別のpayment methodを使用するよう依頼します |
| `REENTER_TRANSACTION` | Soft | Yes | トランザクションを再入力する必要があります | 顧客に支払いをリトライするよう依頼します |
| `REVOCATION_OF_AUTHORIZATION` | Hard | Yes | トランザクションのauthorizationが取り消されました | 顧客に別のpayment methodを使用するよう依頼します |
| `STOLEN_CARD` | Hard | Yes | カードが盗難されたものとして報告されています | 顧客には一般的なディクラインメッセージを表示し、理由は明かさないでください。別のカードを使用するよう依頼します |
| `SUBSCRIPTION_NOT_ACTIVE` | Hard | No | subscriptionが有効でないため、recurring chargeを処理できませんでした | chargeを再試行する前に、payment methodの更新などによってsubscriptionを再有効化します |
| `TRANSACTION_NOT_ALLOWED` | Hard | Yes | このカードまたは口座ではトランザクションが許可されていません | 顧客にこの種類のトランザクションを許可するよう銀行に問い合わせるか、別のカードを使用するよう依頼します |
| `TRANSACTION_NOT_APPROVED` | Hard | Yes | トランザクションが承認されませんでした | 顧客に銀行へ問い合わせるか、別のカードを試すよう依頼します |
| `TRY_AGAIN_LATER` | Soft | No | トランザクションは後で再試行する必要があります | 一時的なエラーです。後で支払いをリトライします |
| `UNKNOWN_ERROR` | Soft | No | 不明なエラーが発生しました | 支払いをリトライし、解消しない場合はサポートに連絡します |

<Note>
**User Error** は、顧客が支払いのディクラインを解決できるかどうかを示します。`Yes` の場合、顧客は問題を解決するためのアクションを実行できます（例：正しいカード情報を入力する）。`No` の場合、ディクラインの原因はシステムレベルの問題または銀行側の制限であり、顧客が直接解決することはできません。
</Note>

<Info>
発行銀行独自のrisk engineが、merchantやトランザクションの詳細とは無関係に、カード名義人を高リスク顧客としてフラグ付けした場合にも、カードは拒否されることがあります。通常、このようなディクラインには `DO_NOT_HONOR`、`GENERIC_DECLINE`、`CARD_DECLINED`、`TRANSACTION_NOT_APPROVED`、または `FRAUDULENT` のような一般的なコードが表示されます。この場合、銀行は具体的な理由を共有せず、Dodo Payments もmerchantも決定を覆すことはできません。顧客に銀行へ問い合わせてフラグを解消するか、別のカードまたはpayment methodを使用するよう依頼します。
</Info>

## プログラムによる失敗処理

`payment.failed` webhookまたはpayment objectから `error_code` を読み取り、上記の推奨アクションに対応付けて、リトライするかどうかを判断します。subscription renewalでは、ソフトディクラインは自動的にリトライされます。[Subscription Payment Retries](/features/recovery/payment-retries)を参照してください。

カードのディクラインではないAPIレベルおよびビジネスロジックのエラー（`PAYMENT_NOT_SUCCEEDED` や `REFUND_WINDOW_EXPIRED` など）については、[Error Codes](/api-reference/error-codes) リファレンスを参照してください。
