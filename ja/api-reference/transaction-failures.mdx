## 概要

Dodo Payments は、支払いの試行が失敗するたびに詳細な失敗理由を返します。これらの理由は決済手段やプロバイダーを問わず標準化されているため、アプリケーションで一貫した処理を実装できます。

支払いが失敗すると、`payment.failed` webhook と payment object には次の情報が公開されます。

- `error_code` — 以下の表に記載されている標準化された失敗理由。
- `error_message` — マーチャントである**あなた**向けに書かれた、人が読める説明。`error_code` が以下の標準化コードのいずれかである場合、決済プロセッサからの生のテキストではなく、見出しと推奨アクションが表示されます。
- `retry_attempt` — 元の請求に対する `0`、スケジュールされたサブスクリプション更新の各再試行に対する `1` 以上。

これらの失敗理由を理解すると、顧客に明確なフィードバックを提供し、リトライする価値があるかを判断し、より多くの収益を回収できます。

### マーチャント向けの文言と顧客向けの文言

すべての標準化された失敗コードは2種類の異なるメッセージに対応しており、適切な対象者に適切な詳細レベルが表示されます。

| 対象者 | 表示場所 | 内容 |
|----------|------------------|--------------|
| **あなた** | 決済上の `error_message`、ダッシュボードの決済詳細ページ、マーチャント向け決済失敗メール | 実際の理由と推奨アクション。例：*「カード所有者によってカードが有効化されていません。顧客に銀行でカードを有効化してもらい、その後再試行してください。」* |
| **顧客** | チェックアウトの失敗画面、[Customer Portal](/features/customer-portal)、[督促](/features/recovery/subscription-dunning)メール | 顧客が対応できる、短く平易な説明。例：*「カードがまだ有効化されていません。銀行でカードを有効化してから、もう一度お試しください。」* |

<Note>
Customer Portal は `error_message` に顧客向けの文言を返します。一方、マーチャント API は同じ決済についてマーチャント向けの文言を返します。`error_code` はどちらでも同一です。
</Note>

## ソフトディクラインとハードディクライン

すべての失敗コードは、2つのカテゴリのいずれかに分類されます。この区別によって、同じ決済手段で再試行するか、顧客に新しい決済手段を求めるかが決まります。

| ディクラインの種類 | 意味 | 対応 | 例 |
|--------------|---------------|------------|----------|
| **ソフトディクライン** | 一時的、または修正可能な状態。同じカードでも、後で再試行するか、顧客が入力を修正すれば成功する可能性があります。 | 再試行して問題ありません（遅延後、または顧客が詳細を修正した後）。 | `INSUFFICIENT_FUNDS`、`GENERIC_DECLINE`、`CARD_VELOCITY_EXCEEDED`、`PROCESSING_ERROR`、`NETWORK_ERROR`、`NETWORK_TIMEOUT`、`TRY_AGAIN_LATER` |
| **ハードディクライン** | 終了状態。同じカードで再試行しても結果は変わりません。 | 同じカードで**再試行しないでください**。顧客に別の決済手段を使うか、銀行に問い合わせるよう依頼してください。 | `STOLEN_CARD`、`LOST_CARD`、`PICKUP_CARD`、`DO_NOT_HONOR`、`FRAUDULENT`、`INVALID_ACCOUNT` |

サブスクリプションの更新では、Dodo Payments がこの区別を自動的に適用します。ソフトディクラインは[Subscription Payment Retries](/features/recovery/payment-retries)によって再試行され、ハードディクラインは再試行チェーンを直ちに終了するため、[Subscription Dunning](/features/recovery/subscription-dunning)で対応するのが最適です。

<Warning>
**`STOLEN_CARD`、`LOST_CARD`、`PICKUP_CARD`、または `FRAUDULENT` の実際の理由を顧客に決して明かさないでください。** これらを表示すると、不正行為者に手がかりを与える可能性があります。顧客には必ず一般的なディクラインメッセージ（例：*「カードが拒否されました。銀行に問い合わせるか、別のカードをお使いください。」*）を表示し、具体的なコードは内部でのみ記録してください。

Dodo Payments は、管理対象の画面ですでにこのルールを適用しています。これら4つのコードについて、チェックアウト、Customer Portal、督促メールでは常に一般的なディクラインメッセージに置き換えられます。一方、マーチャント向けの文言には実際の理由が保持されます。マーチャント API から `error_message` を顧客に表示する場合は、どこでも同じルールを適用してください。
</Warning>

## 取引の失敗理由

以下の表には、すべての失敗コード、ディクラインの種類、顧客が解決できるかどうか、説明、および推奨アクションを記載しています。

| 失敗コード | 種類 | ユーザーエラー | 説明 | 推奨アクション |
|--------------|------|------------|-------------|--------------------|
| `AUTHENTICATION_FAILURE` | ソフト | はい | 取引中の認証に失敗しました | 顧客に再試行して3DS認証を完了するか、別のカードを使うよう依頼してください |
| `AUTHENTICATION_REQUIRED` | ソフト | はい | 取引を完了するには追加の認証が必要です | 顧客に3DS認証を完了するよう促してください。サブスクリプションの更新では、顧客に戻って認証するよう依頼してください |
| `AUTHENTICATION_TIMEOUT` | ソフト | はい | 認証プロセスがタイムアウトしました | 顧客に再試行し、速やかに認証を完了するよう依頼してください |
| `CARD_DECLINED` | ソフト | いいえ | 発行銀行が具体的な理由なしにカードを拒否しました（一般的なディクライン） | 顧客に再試行するか、銀行に問い合わせるか、別のカードを使うよう依頼してください |
| `CARD_NOT_ACTIVATED` | ソフト | はい | カード所有者によってカードが有効化されていません | 顧客に銀行でカードを有効化してから、再試行するよう依頼してください |
| `CARD_VELOCITY_EXCEEDED` | ソフト | はい | 短時間に試行された取引が多すぎます | 顧客に待ってから後で再試行するか、利用限度額について銀行に問い合わせるよう依頼してください |
| `CUSTOMER_CANCELLED` | ソフト | はい | 顧客が取引をキャンセルしました | 顧客の準備ができたら、チェックアウトを再開してもらってください |
| `DO_NOT_HONOR` | ハード | いいえ | 発行銀行が取引を明示的に拒否しました（ISO 8583 code 05 — do not honor）。ネットワークでは終了状態として扱われます | 顧客に銀行へ問い合わせるよう依頼し、同じカードで再試行しないでください |
| `EXPIRED_CARD` | ハード | はい | カードの有効期限が切れています | 顧客に有効期限内のカードを使うよう依頼してください |
| `FRAUDULENT` | ハード | はい | 取引が不正の可能性ありとしてフラグ付けされました | 顧客には一般的なディクラインメッセージを表示し、理由を明かさないでください。別のカードを使うよう依頼してください |
| `GENERIC_DECLINE` | ソフト | いいえ | 取引が不明な理由で拒否されました | 顧客に銀行へ問い合わせるか、別のカードを試すよう依頼してください |
| `INCORRECT_CVC` | ソフト | はい | 入力された CVC code が正しくありません | 顧客に正しい CVC を再入力するよう依頼してください |
| `INCORRECT_NUMBER` | ソフト | はい | カード番号が正しく入力されていません | 顧客に正しいカード番号を再入力するよう依頼してください |
| `INSUFFICIENT_FUNDS` | ソフト | はい | 取引を完了するための残高が不足しています | 顧客に別の決済手段を使うか、残高が利用可能になってから再試行するよう依頼してください |
| `INVALID_ACCOUNT` | ハード | はい | 入力されたアカウント情報が無効です | 顧客に銀行へ問い合わせるか、別のカードを使うよう依頼してください |
| `INVALID_AMOUNT` | ソフト | はい | 取引金額が無効です | 顧客と金額および購入限度額を確認してください |
| `INVALID_CARD_NUMBER` | ソフト | はい | カード番号の形式が無効です | 顧客に有効なカード番号を再入力するよう依頼してください |
| `INVALID_CARD_OWNER` | ソフト | はい | カード所有者情報が無効です | 顧客にカード所有者名を修正するよう依頼してください |
| `INVALID_CVC` | ソフト | はい | CVC の形式が無効です | 顧客に有効な CVC を再入力するよう依頼してください |
| `INVALID_EXPIRY_YEAR` | ソフト | はい | カードの有効期限の年が無効です | 顧客に有効な有効期限を入力するよう依頼してください |
| `INVALID_PIN` | ソフト | はい | 入力された PIN が正しくありません | 顧客に正しい PIN を再入力するよう依頼してください |
| `INVALID_REQUEST` | ソフト | はい | 取引リクエストに無効なデータが含まれています | 決済リクエストのフィールドを確認し、有効なデータで再送信してください |
| `INVALID_UPI_ID` | ソフト | はい | 入力された UPI ID が無効です | 顧客に有効な UPI ID を入力するよう依頼してください |
| `LIMIT_EXCEEDED` | ソフト | はい | 取引がカードまたはアカウントの限度額を超えています | 顧客に限度額について銀行へ問い合わせるか、別の方法を使うよう依頼してください |
| `LIVE_MODE_TEST_CARD` | ハード | はい | ライブモードでテストカードが使われました | 実際のカードを使ってください。ライブモードではテストカードを再試行しても必ず失敗します |
| `LOST_CARD` | ハード | はい | カードが紛失したと報告されています | 顧客には一般的なディクラインメッセージを表示し、理由を明かさないでください。別のカードを使うよう依頼してください |
| `MANDATE_INVALID` | ソフト | はい | 決済 mandate が無効です | 顧客に決済 mandate を再設定するよう依頼してください |
| `MANDATE_REQUIRED` | ソフト | はい | この取引には mandate が必要です | mandate を設定し、請求前に顧客に承認してもらってください |
| `MANDATE_REQUIRED_SYSTEM` | ハード | いいえ | この種類の取引には mandate が必要です | 請求前に mandate の設定フローが完了していることを確認してください |
| `NETWORK_ERROR` | ソフト | いいえ | 取引中にネットワークエラーが発生しました | 一時的なエラーです。短時間待ってから決済を再試行してください |
| `NETWORK_TIMEOUT` | ソフト | いいえ | ネットワークリクエストがタイムアウトしました | 一時的なエラーです。短時間待ってから決済を再試行してください |
| `ORDER_ALREADY_EXISTS` | ソフト | いいえ | この取引の注文はすでに存在します（注文の重複作成） | 再試行する前に既存の注文のステータスを確認してください。解決しない場合はサポートに問い合わせてください |
| `ORDER_CREATION_FAILED` | ソフト | いいえ | 取引の注文作成に失敗しました | 一時的なシステムエラーです。決済を再試行し、解決しない場合はサポートに問い合わせてください |
| `PAYMENT_METHOD_PROVIDER_DECLINED` | ハード | はい | 決済手段プロバイダーが取引を拒否しました | 顧客にプロバイダーへ問い合わせるか、別の決済手段を使うよう依頼してください |
| `PAYMENT_METHOD_UNSUPPORTED` | ハード | はい | この取引では決済手段がサポートされていません | 顧客にサポートされている決済手段を使うよう依頼してください |
| `PICKUP_CARD` | ハード | はい | カードが紛失または盗難に遭ったと報告され、回収対象としてフラグ付けされています | 顧客には一般的なディクラインメッセージを表示し、理由を明かさないでください。別のカードを使うよう依頼してください |
| `PROCESSING_ERROR` | ソフト | いいえ | 取引の処理中にエラーが発生しました | 一時的なエラーです。決済を再試行し、解決しない場合は顧客に銀行へ問い合わせるよう依頼してください |
| `PROVIDER_UNSUPPORTED` | ハード | いいえ | 決済プロバイダーがこの種類の取引をサポートしていません | 顧客に別の決済手段を使うよう依頼してください |
| `REENTER_TRANSACTION` | ソフト | はい | 取引を再入力する必要があります | 顧客に決済を再試行するよう依頼してください |
| `REVOCATION_OF_AUTHORIZATION` | ハード | はい | 取引の承認が取り消されました | 顧客に別の決済手段を使うよう依頼してください |
| `STOLEN_CARD` | ハード | はい | カードが盗難されたと報告されています | 顧客には一般的なディクラインメッセージを表示し、理由を明かさないでください。別のカードを使うよう依頼してください |
| `SUBSCRIPTION_NOT_ACTIVE` | ハード | いいえ | サブスクリプションが有効ではないため、継続請求を処理できませんでした | 再度請求する前に、サブスクリプションを再有効化してください（例：決済手段を更新する） |
| `TRANSACTION_NOT_ALLOWED` | ハード | はい | このカードまたはアカウントでは取引が許可されていません | 顧客にこの種類の取引を許可するよう銀行へ問い合わせるか、別のカードを使うよう依頼してください |
| `TRANSACTION_NOT_APPROVED` | ハード | はい | 取引が承認されませんでした | 顧客に銀行へ問い合わせるか、別のカードを試すよう依頼してください |
| `TRY_AGAIN_LATER` | ソフト | いいえ | 取引は後で再試行する必要があります | 一時的なエラーです。後で決済を再試行してください |
| `UNKNOWN_ERROR` | ソフト | いいえ | 不明なエラーが発生しました | 決済を再試行し、解決しない場合はサポートに問い合わせてください |

<Note>
**「ユーザーエラー」は、決済のディクラインを顧客が解決できるかどうかを示します。** `Yes` の場合、顧客は問題を解決するための対応（例：正しいカード情報を入力する）ができます。`No` の場合、ディクラインの原因はシステムレベルの問題または銀行の制限であり、顧客が直接解決することはできません。
</Note>

<Info>
発行銀行独自のリスクエンジンが、マーチャントや取引の詳細とは無関係に、カード所有者を高リスク顧客と判断した場合にも、カードは拒否されることがあります。通常、このようなディクラインは `DO_NOT_HONOR`、`GENERIC_DECLINE`、`CARD_DECLINED`、`TRANSACTION_NOT_APPROVED`、または `FRAUDULENT` のような一般的なコードとして返されます。この場合、銀行は具体的な理由を共有せず、Dodo Payments もマーチャントも判断を覆すことはできません。顧客に銀行へ問い合わせてフラグを解消するか、別のカードまたは決済手段を使うよう依頼してください。
</Info>

## プログラムでの失敗処理

`payment.failed` webhook または payment object から `error_code` を読み取り、上記の推奨アクションに対応付けて、再試行するかどうかを判断してください。サブスクリプションの更新では、ソフトディクラインが自動的に再試行されます。詳しくは[Subscription Payment Retries](/features/recovery/payment-retries)を参照してください。

カードのディクラインではない API レベルおよびビジネスロジックのエラー（`PAYMENT_NOT_SUCCEEDED` や `REFUND_WINDOW_EXPIRED` など）については、[Error Codes](/api-reference/error-codes)リファレンスを参照してください。
