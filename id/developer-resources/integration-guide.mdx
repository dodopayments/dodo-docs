## Prerequisites

To integrate the Dodo Payments API, you'll need:
- A Dodo Payments merchant account
- API Credentials (API key and webhook secret key) from dashboard

## Dashboard Setup

1. Navigate to the [Dodo Payments Dashboard](https://app.dodopayments.com/)

2. Buat produk (pembayaran satu kali atau subscription). Produk subscription harus diberi harga minimal **\$1** (atau nilai setara dalam mata uang yang Anda pilih); jumlah di bawah minimum ini tidak didukung.

4. Generate your API key:
   - Go to Developer > API
   - [Detailed Guide](/api-reference/introduction#api-key-generation)
   - Copy the API key the in env named DODO_PAYMENTS_API_KEY

5. Configure webhooks:
   - Go to Developer > Webhooks
   - Create a webhook URL for payment notifications
   - Copy the webhook secret key in env 

## Integration

### Payment Links

Pilih jalur integrasi yang sesuai dengan kasus penggunaan Anda:
- **Checkout Sessions (direkomendasikan)**: Terbaik untuk sebagian besar integrasi. Buat session di server Anda lalu arahkan pelanggan ke checkout yang aman dan di-host.
- **Overlay Checkout**: Gunakan jika Anda memerlukan pengalaman dalam halaman yang membuka checkout sebagai overlay modal di situs Anda.
- **Inline Checkout**: Sematkan checkout langsung ke tata letak halaman Anda untuk pengalaman checkout yang sepenuhnya terintegrasi dan bermerek.
- **Static Payment Links**: URL yang dapat langsung dibagikan tanpa kode untuk mengumpulkan pembayaran dengan cepat.
- **Dynamic Payment Links**: Link yang dibuat secara terprogram. Namun, Checkout Sessions direkomendasikan karena menyediakan fleksibilitas yang lebih besar.
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**: Untuk aplikasi Android, iOS, React Native, dan Flutter native. Buat session di server Anda seperti di atas, lalu teruskan `checkout_url` ke SDK.

<Info>
Overlay dan Inline Checkout hanya tersedia di browser — keduanya menyematkan checkout ke dalam halaman
web. Jika Anda sedang membuat aplikasi mobile native, buat checkout session di
server Anda dan buka dengan
[Mobile Checkout SDKs](/developer-resources/mobile-integration).
</Info>

#### 1. Checkout Sessions

Gunakan Checkout Sessions untuk membuat pengalaman checkout yang aman dan di-host untuk pembayaran satu kali atau subscription. Anda membuat session di server, lalu mengarahkan pelanggan ke `checkout_url` yang dikembalikan.

<Info>
Checkout sessions berlaku selama 24 jam secara default. Jika Anda meneruskan <code>confirm=true</code>, sessions berlaku selama 15 menit dan semua field wajib harus disediakan.
</Info>

<Steps>
<Step title="Create a checkout session">
  Pilih SDK pilihan Anda atau panggil REST API.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'prod_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python
  import os
  from dodopayments import DodoPayments

  client = DodoPayments(
      bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
      environment="test_mode",  # defaults to "live_mode"
  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "prod_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

  </Tab>

  <Tab title="REST API">

  ```javascript
  const response = await fetch('https://test.dodopayments.com/checkouts', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.DODO_PAYMENTS_API_KEY}`,
    },
    body: JSON.stringify({
      product_cart: [{ product_id: 'prod_123', quantity: 1 }],
      customer: { email: 'customer@example.com', name: 'John Doe' },
      return_url: 'https://yourapp.com/checkout/success',
    }),
  });
  const session = await response.json();
  ```

  </Tab>
  </Tabs>
</Step>

<Step title="Redirect customer to checkout">
  Setelah session dibuat, arahkan ke `checkout_url` untuk memulai alur yang di-host.

  ```javascript
  // Example in a browser context
  window.location.href = session.checkout_url;
  ```

</Step>
</Steps>

<Tip>
Gunakan Checkout Sessions untuk cara tercepat dan paling andal dalam mulai menerima pembayaran. Untuk kustomisasi lanjutan, lihat <a href="/developer-resources/checkout-session">panduan Checkout Sessions lengkap</a> dan <a href="/api-reference/checkout-sessions/create">API Reference</a>.
</Tip>

#### 2. Overlay Checkout

Untuk pengalaman checkout dalam halaman yang mulus, lihat integrasi [Overlay Checkout](/developer-resources/overlay-checkout) kami yang memungkinkan pelanggan menyelesaikan pembayaran tanpa meninggalkan situs Anda.

#### 3. Inline Checkout

Untuk pengalaman checkout yang sepenuhnya terintegrasi dan disematkan langsung di halaman Anda, gunakan integrasi [Inline Checkout](/developer-resources/inline-checkout) kami. Dengan ini, Anda dapat membuat ringkasan pesanan kustom dan mengendalikan sepenuhnya tata letak checkout, sementara Dodo Payments menangani pengumpulan pembayaran dengan aman.

#### 4. Static Payment Links

Static payment links memungkinkan Anda menerima pembayaran dengan cepat melalui URL sederhana. Anda dapat menyesuaikan pengalaman checkout dengan meneruskan query parameters untuk mengisi detail pelanggan terlebih dahulu, mengontrol field formulir, dan menambahkan metadata kustom.

<Steps>
<Step title="Construct your payment link">
  Mulai dengan base URL dan tambahkan ID produk:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  Sertakan query parameters penting:
  - <ParamField query="quantity" type="integer" default="1">Jumlah item yang dibeli.</ParamField>
  - <ParamField query="redirect_url" type="string" required>URL untuk mengarahkan pengguna setelah pembayaran selesai.</ParamField>
  <Note>
  URL pengalihan akan menyertakan detail pembayaran sebagai query parameters, misalnya:<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  Jika produk mengaktifkan license keys, parameter `license_key` juga ditambahkan (dipisahkan koma untuk beberapa key):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  Tambahkan field pelanggan atau billing sebagai query parameters untuk menyederhanakan checkout.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">Nama lengkap pelanggan (diabaikan jika firstName atau lastName diberikan).</ParamField>
      - <ParamField query="firstName" type="string">Nama depan pelanggan.</ParamField>
      - <ParamField query="lastName" type="string">Nama belakang pelanggan.</ParamField>
      - <ParamField query="email" type="string">Alamat email pelanggan.</ParamField>
      - <ParamField query="country" type="string">Negara pelanggan.</ParamField>
      - <ParamField query="addressLine" type="string">Alamat jalan.</ParamField>
      - <ParamField query="city" type="string">Kota.</ParamField>
      - <ParamField query="state" type="string">Provinsi atau negara bagian.</ParamField>
      - <ParamField query="zipCode" type="string">Kode pos/ZIP.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true atau false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  Anda dapat menonaktifkan field tertentu agar menjadi hanya-baca bagi pelanggan. Ini berguna jika Anda sudah memiliki detail pelanggan, misalnya untuk pengguna yang sudah login.
  </Info>
  Untuk menonaktifkan field, berikan nilainya dan atur flag <code>disable...</code> yang sesuai ke <code>true</code>:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Field         | Disable Flag         | Required Parameter |
      |---------------|---------------------|-------------------|
      | Full Name     | `disableFullName`   | `fullName`        |
      | First Name    | `disableFirstName`  | `firstName`       |
      | Last Name     | `disableLastName`   | `lastName`        |
      | Email         | `disableEmail`      | `email`           |
      | Country       | `disableCountry`    | `country`         |
      | Address Line  | `disableAddressLine`| `addressLine`     |
      | City          | `disableCity`       | `city`            |
      | State         | `disableState`      | `state`           |
      | ZIP Code      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  Menonaktifkan field membantu mencegah perubahan yang tidak disengaja dan memastikan konsistensi data.
  </Tip>
  <Note>
  Mengatur <code>showDiscounts=false</code> akan menonaktifkan dan menyembunyikan bagian diskon dalam formulir checkout. Gunakan ini jika Anda ingin mencegah pelanggan memasukkan kode kupon atau promosi selama checkout.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">Menentukan mata uang pembayaran. Secara default menggunakan mata uang negara billing.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">Menampilkan atau menyembunyikan pemilih mata uang.</ParamField>
  - <ParamField query="paymentAmount" type="integer">Jumlah dalam sen (hanya untuk penetapan harga Pay What You Want).</ParamField>
  - <ParamField query="metadata_*" type="string">Field metadata kustom (misalnya, <code>metadata_orderId=123</code>).</ParamField>
</Step>
<Step title="Share the link">
  Kirim payment link yang telah selesai kepada pelanggan Anda. Saat mereka membukanya, semua query parameters dikumpulkan dan disimpan bersama session ID. URL kemudian disederhanakan agar hanya menyertakan parameter session, misalnya <code>?session=sess_1a2b3c4d</code>. Informasi yang disimpan tetap ada setelah halaman dimuat ulang dan dapat diakses sepanjang proses checkout.
  <Check>
  Pengalaman checkout pelanggan kini lebih sederhana dan dipersonalisasi berdasarkan parameter Anda.
  </Check>
</Step>
</Steps>

#### 4. Dynamic Payment Links
<Tip>
Checkout Sessions lebih disarankan untuk sebagian besar kasus penggunaan karena menawarkan fleksibilitas dan kontrol yang lebih besar.
</Tip>

Dibuat melalui panggilan API atau SDK kami dengan detail pelanggan. Berikut contohnya:

Ada dua API untuk membuat dynamic payment links:

- One-time Payment Link API [API reference](/api-reference/payments/post-payments)
- Subscription Payment Link API [API reference](/api-reference/subscriptions/post-subscriptions)

Untuk petunjuk terperinci tentang integrasi subscription, lihat [Subscription Integration Guide](/developer-resources/subscription-integration-guide) ini.

### Menerapkan Webhooks

Siapkan endpoint API untuk menerima notifikasi pembayaran. Berikut contoh menggunakan Next.js:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

Implementasi webhook kami mengikuti spesifikasi [Standard Webhooks](https://standardwebhooks.com/). Untuk definisi tipe webhook, lihat [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide) kami.

#### Event yang Perlu Didengarkan

Aktifkan `payload.type` dan tangani event yang relevan dengan alur pembayaran satu kali. Minimal, dengarkan event berikut:

| Event Type           | When it fires                                              | What to do                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | Pembayaran berhasil diproses.                        | Penuhi pesanan — berikan akses, sediakan produk, dan kirim tanda terima. |
| `payment.failed`     | Upaya pembayaran gagal (kartu ditolak, error, dan sebagainya).       | Beri tahu pelanggan dan minta mereka mencoba lagi; jangan penuhi pesanan.                    |
| `payment.processing` | Pembayaran diterima tetapi masih diproses (metode async). | Tunggu hingga `payment.succeeded`/`payment.failed` terminal — jangan penuhi pesanan terlebih dahulu. |
| `payment.cancelled`  | Pembayaran dibatalkan sebelum selesai.                   | Lepaskan state yang ditahan dan tandai pesanan sebagai ditinggalkan.                       |

<Tip>
Selalu **penuhi pesanan berdasarkan `payment.succeeded` dari webhook**, bukan berdasarkan pengalihan browser — pengalihan dapat terlewat jika pelanggan menutup tab, sedangkan webhook akan dicoba ulang hingga diakui.
</Tip>

Jika Anda menjual produk digital dengan license keys, tangani juga `license_key.created`. Untuk daftar lengkap event — termasuk event subscription, entitlement, credit, recovery, dan dunning — lihat [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide).

Anda dapat melihat project ini dengan implementasi demo di [GitHub](https://github.com/dodopayments/dodo-checkout-demo) menggunakan Next.js dan TypeScript.

Anda dapat melihat implementasi live [di sini](https://atlas.dodopayments.com/).

## Hal Penting yang Perlu Diketahui tentang Checkout & Mata Uang

<Warning>
**Jumlah Dynamic (Pay-What-You-Want) menggunakan mata uang dasar produk** — bukan mata uang lokal sembarang — dan mata uang dasar dibatasi pada **USD, INR, GBP, dan EUR**. Untuk mengumpulkan jumlah tetap dalam mata uang lain, misalnya PHP, Anda tidak dapat meneruskannya secara langsung: gunakan **Adaptive Pricing** (mengonversi jumlah dasar berdasarkan FX live) atau **Localized Pricing** (harga tetap per mata uang, tetapi tidak kompatibel dengan Pay-What-You-Want).
</Warning>

<Tip>
**Tetapkan mata uang secara eksplisit.** Teruskan `billing_currency` dan `billing_address.country` pada checkout session. Jika tidak disertakan, mata uang dan negara akan dideteksi dari IP pelanggan (Adaptive Currency) dan mungkin tidak sesuai dengan yang ingin Anda kenakan.
</Tip>

<Info>
**Checkout sessions kedaluwarsa dalam 24 jam** (15 menit jika `confirm: true`), dan setiap `checkout_url` hanya dapat digunakan **satu kali** — buat session baru untuk setiap pelanggan dan setiap upaya pembayaran, bukan menggunakan kembali link.
</Info>

<Info>
**Pembelian ulang sekali klik.** Untuk pelanggan yang kembali dengan metode pembayaran tersimpan, teruskan `payment_method_id` bersama `confirm: true` untuk menagih secara instan tanpa memilih metode.
</Info>
