## Apa itu Penagihan Hibrida?

Penagihan hibrida menggabungkan beberapa dimensi harga ke dalam satu penawaran produk. Alih-alih memilih antara langganan tarif tetap ATAU harga berbasis penggunaan, Anda menggunakan keduanya secara bersamaan.

### Mengapa Menggunakan Penagihan Hibrida?

| Tujuan Bisnis | Solusi Hibrida |
|--------------|-----------------|
| Pendapatan yang dapat diprediksi + peluang pertumbuhan | Langganan dasar + kelebihan penggunaan |
| Harga tim yang dapat diskalakan | Per kursi + add-on fitur |
| Mendapatkan pelanggan, memperluas layanan kemudian | Biaya dasar rendah + biaya konsumsi |
| Fleksibilitas perusahaan | Pengeluaran berkomitmen + biaya sesuai permintaan |
| Harga yang adil untuk penggunaan variabel | Kuota yang disertakan + bayar sesuai penggunaan |

### Pola Hibrida Umum

| Model | Deskripsi | Contoh | Dukungan Native |
|-------|-------------|---------|----------------|
| **1. Langganan + Penggunaan** | Biaya dasar + biaya konsumsi | \$49/bln + \$0.01/panggilan API setelah 10K gratis | ✅ Penuh |
| **2. Langganan + Kursi** | Biaya platform + biaya per pengguna | \$99/bln + \$15/kursi | ✅ Penuh |
| **3. Langganan + Add-on Fitur** | Paket inti + upgrade opsional | \$29/bln + \$19/bln analitik + \$9/bln akses API | ✅ Penuh |
| **4. Kursi + Penggunaan** | Biaya per pengguna + kelebihan konsumsi | \$10/pengguna/bln + \$0.05/GB setelah 5GB/pengguna | ⚠️ Solusi alternatif |
| **5. Langganan + Kursi + Penggunaan** | Platform + pengguna + konsumsi (hibrida tiga komponen) | \$199/bln + \$20/kursi + kelebihan penggunaan | ⚠️ Solusi alternatif |
| **6. Dasar Bertingkat + Kelebihan Penggunaan** | Tingkatan berbeda dengan kuota berbeda | Starter (5K panggilan) vs Pro (50K panggilan) + kelebihan penggunaan | ✅ Penuh |
| **7. Langganan + Biaya Sesuai Permintaan** | Biaya berulang + biaya manual variabel | Retainer \$99/bln + penagihan per jam untuk pekerjaan | ✅ Penuh |

## Model Hibrida 1: Langganan + Penggunaan

Model hibrida yang paling umum. Pelanggan membayar biaya langganan dasar ditambah biaya untuk konsumsi yang melebihi kuota yang disertakan.

### Cara Kerjanya

**Paket Pro: $49/bulan**

- **Termasuk**: 10.000 panggilan API/bulan
- **Kelebihan penggunaan**: $0.005 per panggilan setelah 10.000

**Contoh perhitungan** (pelanggan menggunakan 25.000 panggilan bulan ini):
- Langganan dasar: $49.00
- Kelebihan penggunaan: (25.000 - 10.000) × $0.005 = $75.00
- **Total: $124.00**

### Kasus Penggunaan

- **Platform API**: Akses dasar + biaya per permintaan
- **Layanan AI/ML**: Langganan + penggunaan token/generasi
- **Layanan penyimpanan**: Paket dasar + kelebihan penggunaan per GB
- **Platform komunikasi**: Biaya dasar + biaya per pesan/menit

### Implementasi

<Steps>
<Step title="Create Usage Meter">
Siapkan meter untuk melacak dimensi penggunaan yang dapat ditagihkan.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
Buat produk langganan dan lampirkan meter penggunaan beserta harganya.

```bash

Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
Meter penggunaan dilampirkan langsung ke produk langganan. Biaya penggunaan dihitung dan ditambahkan ke invoice langganan secara otomatis.
</Info>
</Step>

<Step title="Create Checkout Session">
Buat sesi checkout dengan produk langganan Anda.

```typescript

  ],
```

</Step>

<Step title="Send Usage Events">
Lacak penggunaan selama periode penagihan.

</Step>
</Steps>

### Variasi Harga

<Tabs>
<Tab title="Included Allowance">
Ambang batas gratis mencakup penggunaan yang disertakan dalam langganan dasar.

**Paket Pro: $49/bulan**
- Termasuk: 10.000 panggilan API
- Kelebihan penggunaan: $0.005/panggilan setelah 10.000
- Pelanggan menggunakan 8.000 → Membayar $49 (tanpa kelebihan penggunaan)
</Tab>

<Tab title="Zero Base + Pure Usage">

**Bayar Sesuai Penggunaan: dasar $0/bulan**
- Termasuk: 0 panggilan API
- Penggunaan: $0.01/panggilan sejak panggilan pertama
- Pelanggan menggunakan 5.000 → Membayar $50
</Tab>

<Tab title="Tiered Allowances">
Tingkatan yang berbeda mencakup kuota yang berbeda.

- **Pro**: $49/bulan (termasuk 10.000 panggilan)
- **Enterprise**: $199/bulan (termasuk 100.000 panggilan)
- Semua tingkatan: kelebihan penggunaan $0.005/panggilan
</Tab>

## Model Hibrida 2: Langganan + Kursi

Biaya platform ditambah biaya per pengguna. Ideal untuk alat kolaborasi tim dan SaaS B2B.

### Cara Kerjanya

**Paket Tim: $99/bulan + $15/kursi**

- **Biaya platform dasar**: $99/bulan (termasuk 3 kursi)
- **Kursi tambahan**: $15/kursi/bulan

**Contoh perhitungan** (tim yang terdiri dari 12 pengguna):
- Biaya platform: $99.00
- Kursi tambahan: (12 - 3) × $15 = $135.00
- **Total: $234.00/bulan**

### Kasus Penggunaan

- **Alat kolaborasi**: Biaya ruang kerja + per anggota
- **Sistem CRM**: Lisensi platform + per perwakilan penjualan
- **Manajemen proyek**: Paket tim + per kontributor
- **Alat developer**: Biaya organisasi + per developer

### Variasi Harga

<Tabs>
<Tab title="Included Seats">
Paket dasar mencakup beberapa kursi; kenakan biaya untuk kursi tambahan.

**Paket Tim: $99/bulan**
- Termasuk: 5 kursi
- Kursi tambahan: $15/kursi/bulan
- 20 pengguna = \$99 + (15 × \$15) = \$324/bulan
</Tab>

<Tab title="Pure Per-Seat">
Tidak ada biaya platform, hanya biaya per pengguna.

**Per Pengguna: $25/pengguna/bulan**
- Tidak ada biaya platform
- 5 pengguna = $125/bulan
- 50 pengguna = $1.250/bulan

Implementasi: Tetapkan harga langganan dasar sebesar $0, lalu gunakan add-on kursi saja.

<Tab title="Tiered Per-Seat">
Harga per kursi menurun pada tingkatan yang lebih tinggi.

- **Starter**: $20/kursi (1-10 kursi)

Implementasi: Buat produk langganan terpisah untuk setiap tingkatan dengan harga add-on yang berbeda.

## Model Hibrida 4: Kursi + Penggunaan

Biaya per pengguna yang digabungkan dengan biaya berbasis konsumsi. Setiap pengguna mendapatkan kuota.

<Warning>
**Batasan**: Dodo Payments saat ini tidak mendukung pelampiran meter penggunaan dan add-on secara bersamaan ke produk langganan yang sama. Model ini memerlukan solusi alternatif menggunakan logika tingkat aplikasi.
</Warning>

### Cara Kerjanya

**Team Analytics: $20/user/month**

**Setiap pengguna mencakup:**
- Pemrosesan data 5 GB/bulan
- Kelebihan penggunaan: $2/GB setelah kuota

**Contoh perhitungan** (tim dengan 10 pengguna menggunakan total 80 GB):
- Biaya seat: 10 × $20 = $200.00
- Data yang disertakan: 10 × 5 GB = 50 GB
- Kelebihan penggunaan: (80 - 50) × $2 = $60.00
- **Total: $260.00/bulan**

### Kasus Penggunaan

- **Platform analytics**: Per-analyst + pemrosesan data
- **Alat desain**: Per-designer + penyimpanan/ekspor
- **Lingkungan pengembangan**: Per-developer + jam komputasi
- **Alat komunikasi**: Per-user + volume pesan/panggilan

### Opsi Implementasi

Karena Anda tidak dapat melampirkan usage meters dan add-ons sekaligus ke subscription yang sama, pilih salah satu pendekatan berikut:

## Model Hybrid 5: Subscription + Seats + Usage (Triple Hybrid)

Model paling komprehensif: biaya platform + per-user + konsumsi.

<Warning>
**Batasan**: Dodo Payments saat ini tidak mendukung pelampiran usage meters dan add-ons sekaligus ke subscription product yang sama. Model ini memerlukan pendekatan workaround.
</Warning>

### Cara Kerjanya

**Enterprise Platform**

- **Platform Fee**: $199/bulan
- **Per Seat**: $25/user/bulan
- **Usage**: $0.10/1000 API calls (50K disertakan)

**Contoh perhitungan** (perusahaan dengan 20 pengguna, 150.000 API calls):
- Platform: $199.00
- Seat: 20 × $25 = $500.00
- Usage: (150K - 50K) × \$0.10/1K = \$10.00
- **Total: $709.00/bulan**

### Kasus Penggunaan

- **Enterprise SaaS**: Platform + tim + konsumsi
- **Platform data**: Workspace + analyst + query
- **Platform integrasi**: Hub + connector + transaksi
- **Platform AI**: Workspace + developer + inference

</Step>
</Steps>
</Tab>
</Tabs>

## Model Hybrid 7: Subscription + On-Demand Charges

Subscription berulang ditambah charges manual variabel untuk layanan atau kelebihan penggunaan.

### Cara Kerjanya

**Paket Retainer: $199/bulan**

**Mencakup:**
- Akses platform
- 5 jam konsultasi/bulan
- Dukungan email

**On-Demand Charges (sesuai kebutuhan):**
- Konsultasi tambahan: $150/jam
- Pengembangan khusus: $200/jam
- Dukungan darurat: $100/insiden

**Contoh perhitungan** (bulan ini):
- Retainer: $199.00
- 3 jam konsultasi tambahan: $450.00
- 1 dukungan darurat: $100.00
- **Total: $749.00**

### Kasus Penggunaan

- **Layanan konsultasi**: Retainer + penagihan per jam
- **Layanan terkelola**: Biaya dasar + biaya insiden
- **Layanan agensi**: Biaya bulanan + biaya proyek
- **Paket dukungan**: Biaya SLA + per-tiket atau per-jam

## Praktik Terbaik Implementasi

### Kejelasan Halaman Harga

<Tip>
Buat harga hybrid mudah dipahami. Tampilkan biaya dasar, hal-hal yang disertakan, dan cara kerja kelebihan penggunaan secara jelas di halaman harga Anda.
</Tip>

**Baik**: "\$49/bulan mencakup 10.000 API calls. Panggilan tambahan: \$0.005 per panggilan"

**Buruk**: "\$49/bulan + biaya penggunaan"

### Prediktabilitas Biaya

Bantu pelanggan memperkirakan biaya mereka:

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### Visibilitas Penggunaan

Tampilkan penggunaan pelanggan secara real-time:

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

## Pemecahan Masalah Penagihan Hybrid

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**Gejala**: Penggunaan menampilkan nilai 0 atau nilai yang salah.

**Solusi**:
1. Verifikasi bahwa event ingestion berfungsi (periksa respons API)
2. Pastikan `customer_id` sesuai dengan customer subscription
3. Periksa bahwa `event_name` sesuai dengan konfigurasi meter
4. Verifikasi bahwa event memiliki timestamp yang benar (bukan bertanggal di masa depan)
</Accordion>

<Accordion title="Proration confusion with multiple components">
**Gejala**: Pelanggan dikenai jumlah yang tidak terduga saat mengubah plan.

**Solusi**:
1. Gunakan API `previewChangePlan` untuk menampilkan biaya yang tepat sebelum konfirmasi
2. Sampaikan bahwa proration berlaku untuk subscription DAN add-ons
3. Pertimbangkan menggunakan `difference_immediately` untuk penagihan upgrade yang lebih sederhana
</Accordion>

<Accordion title="Free threshold not applying correctly">
**Gejala**: Pelanggan dikenai biaya untuk penggunaan yang seharusnya gratis.

**Solusi**:
1. Verifikasi bahwa free threshold dikonfigurasi pada product berbasis penggunaan
2. Periksa bahwa unit threshold sesuai dengan agregasi event (calls vs. requests)
3. Pastikan usage meter terlampir dengan benar pada subscription product
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**Gejala**: Tidak dapat menambahkan seat atau fitur selama checkout.

**Solusi**:
1. Verifikasi bahwa add-ons terlampir pada subscription product di dashboard
2. Periksa bahwa add-on IDs sudah benar dalam API calls
3. Pastikan mata uang add-on sesuai dengan mata uang subscription product
</Accordion>
</AccordionGroup>
