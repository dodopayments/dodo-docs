## Cara Kerjanya

Metode pembayaran secara otomatis ditampilkan kepada pelanggan berdasarkan:

- **Lokasi Pelanggan** — Metode regional seperti iDEAL (Belanda) atau UPI (India) hanya muncul untuk pelanggan di wilayah tersebut
- **Mata Uang Transaksi** — Metode pembayaran difilter berdasarkan mata uang yang didukung
- **Tipe Perangkat** — Apple Pay hanya muncul pada perangkat dan browser Apple yang kompatibel
- **Tipe Transaksi** — Beberapa metode tidak mendukung langganan atau memiliki jumlah minimum

<Info>
**Aktivasi Otomatis:** Semua metode pembayaran telah dikonfigurasi sebelumnya dan dikelola oleh Dodo Payments. Tidak perlu pengaturan tambahan — mereka tersedia setelah akun Anda diverifikasi dan mode langsung diaktifkan.
</Info>

## Mengonfigurasi Metode Pembayaran

Secara default, semua metode pembayaran yang memenuhi syarat muncul secara otomatis. Gunakan `allowed_payment_method_types` untuk membatasi metode yang ditampilkan:

<Tab title="Python">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="cURL">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>
</Tabs>

  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \

## Praktik Terbaik

Sertakan metode pembayaran regional untuk pasar target Anda. iDEAL menangkap ~60% pembayaran online di Belanda; UPI mendominasi di India. Menghilangkan metode ini secara signifikan mengurangi konversi.

Bahkan ketika menargetkan metode tertentu, sertakan `credit` dan `debit` sebagai pengganti. Tidak semua pelanggan memiliki akses ke setiap metode pembayaran.

Metode BNPL (Klarna, Afterpay) memerlukan minimal $50.01. Jangan sertakan untuk produk berharga rendah — metode ini tidak akan muncul, yang baik-baik saja.

Gunakan mode tes untuk memverifikasi ketersediaan metode pembayaran untuk lokasi pelanggan yang berbeda, mata uang, dan jenis perangkat sebelum diluncurkan.

## Pemecahan Masalah

**Periksa faktor-faktor ini:**
1. Apakah metode termasuk dalam `allowed_payment_method_types`?
2. Apakah lokasi pelanggan cocok dengan wilayah yang didukung metode?
3. Apakah mata uang transaksi didukung oleh metode?
4. Apakah jumlah transaksi memenuhi minimum (misalnya, $50.01 untuk BNPL)?
5. Untuk langganan: apakah metode mendukung pembayaran berulang?

**Solusi:** Hapus `allowed_payment_method_types` sementara untuk melihat semua metode yang memenuhi syarat, lalu sesuaikan masalahnya.

**Kemungkinan penyebab:**
- `allowed_payment_method_types` tidak diteruskan dengan benar
- Parameter diformat dengan salah (harus berupa array string)

**Solusi:** Catat payload permintaan API Anda dan verifikasi struktur parameter.

**Periksa:**
- Apakah alamat tagihan pelanggan sesuai dengan wilayah metode
- Apakah mata uang diatur dengan benar (misalnya, EUR untuk iDEAL)
- Apakah Adaptive Currency diaktifkan jika pelanggan bersifat internasional

**Solusi:** Verifikasi kode negara alamat tagihan dan mata uang dalam permintaan API Anda.

Langganan UPI dan Rupay memiliki persyaratan unik termasuk penundaan proses 48 jam dan batas mandat RBI.
