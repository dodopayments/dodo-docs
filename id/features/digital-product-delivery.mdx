## Overview

Pengiriman Produk Digital adalah jenis hak **File Digital**. Anda unggah file Anda sekali ke hak File Digital, lampirkan hak tersebut ke produk, dan Dodo Payments mengantarkan tautan unduhan presigned ke setiap pelanggan yang membayar melalui email dan portal pelanggan.

Hak mendukung:

- **Unggahan file yang di-hosted**: menyimpan file di Dodo Payments dan melayani mereka melalui URL presigned jangka pendek.
- **Tautan unduhan eksternal**: tautkan ke file yang di-hosting di Dropbox, Google Drive, S3, atau URL lainnya.
- **Instruksi unduhan**: teks berbentuk bebas yang ditampilkan kepada pelanggan pada halaman pesanan mereka dan dalam email pengiriman.

Anda dapat mencampur ketiganya dalam satu hak.

## Mengatur Pengiriman Produk Digital

<Steps>
<Step title="Open Entitlements">
Buka **Hak** di dasbor Dodo Payments Anda dan klik **+** untuk membuat hak baru.
</Step>

<Step title="Choose Digital Files">
Pilih **Pengiriman Produk Digital** sebagai integrasi.
</Step>

<Step title="Add files, links, and instructions">
Konfigurasikan kombinasi apa pun dari:

- **File**: unggah satu atau lebih file. Setiap unggahan mengembalikan `file_id` yang ditambahkan ke hak.
- **URL Eksternal**: tautan HTTPS yang dapat diakses publik yang dikirimkan bersama file yang di-hosting.
- **Instruksi**: teks berbentuk bebas yang ditampilkan kepada pelanggan (misalnya, "Unzip dan jalankan setup.sh").

Simpan. Hak sekarang tersedia untuk dilampirkan ke produk mana pun.

## Cara Kerja Pengiriman

Pengiriman File Digital mengikuti standar [siklus grant](/features/entitlements/introduction#how-grants-work):

| Peristiwa | Perilaku |
|---|---|
| `payment.succeeded` (sekali pakai) | Terbitkan grant. Grant menyertakan presigned download URLs yang valid selama ~15 menit; pelanggan dapat memperbaruinya dengan membuka kembali tautan email atau halaman Customer Portal. |
| `subscription.active` | Terbitkan grant. File tetap dapat diakses selama langganan aktif. |
| `subscription.renewed` | No-op. Grant yang sama tetap digunakan; presigned URLs baru dibuat pada setiap fetch. |
| `subscription.on_hold` / `cancelled` / `expired` | Cabut grant. Presigned URLs baru tidak lagi diterbitkan. |
| `subscription.paused` | Cabut grant. Presigned URLs baru tidak lagi diterbitkan hingga langganan dilanjutkan. |
| `subscription.plan_changed` | Cabut grant lama; terbitkan grant baru untuk hak akses paket baru. |
| `refund.succeeded` (sekali pakai) | Cabut grant. |
| Pencabutan manual | Cabut dengan `revocation_reason: manual`. |

<Warning>
Pencabutan menghentikan Dodo Payments dari penerbitan URL unduhan baru, tetapi tidak membatalkan salinan yang sudah diunduh oleh pelanggan. Perlakukan unduhan file yang di-hosting sebagai "dikirim sekali dibaca."
</Warning>

## Mengelola File Secara Program

### Unggah file ke hak

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';
import fs from 'node:fs';

const client = new DodoPayments({
  bearerToken: process.env['DODO_PAYMENTS_API_KEY'],
  environment: 'test_mode',
});

await client.entitlements.files.upload('ent_files_abc', {
  file: fs.createReadStream('./pro-bundle.zip'),
  filename: 'pro-bundle.zip',
});
```

```bash cURL theme={null}
curl -X POST "https://test.dodopayments.com/entitlements/ent_files_abc/files" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@./pro-bundle.zip" \
  -F "filename=pro-bundle.zip"
```

</CodeGroup>

### Daftar basis dan selesaikan URL unduhan

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_files_abc', {
  customer_id: 'cus_abc123',
});

for (const grant of grants.items) {
  for (const file of grant.digital_product_delivery.files) {
    console.log(file.filename, file.download_url, `expires in ${file.expires_in}s`);
  }
}
```

### Hapus file dari hak

```typescript theme={null}
await client.entitlements.files.delete('df_a4f6c1de', { id: 'ent_files_abc' });
```

## Pertimbangan Penting

- **URL presigned cepat habis masa berlakunya.** URL unduhan yang dikembalikan dalam payload basis atau acara webhook berlaku selama ~15 menit. Jangan menyimpannya; ambil kembali ketika pelanggan perlu mengunduh lagi.
- **Memperbarui file hanya memengaruhi pembelian di masa mendatang.** Mengganti atau menghapus file tidak mengubah unduhan yang telah diterbitkan secara retroaktif. Pelanggan di masa lalu masih dapat mengambil versi yang berlaku saat basis mereka dibuat.
- **Pengembalian dana tidak membatalkan salinan yang diunduh.** Pelanggan yang sudah mengunduh file tetap memiliki salinannya. Untuk konten yang dapat dicabut (media dengan batasan lisensi, akses terbatas waktu), gabungkan File Digital dengan [Kunci Lisensi](/features/license-keys) dan validasi saat runtime.
- **Untuk konten sensitif, lebih baik gunakan URL eksternal dengan autentikasi sendiri.** URL presigned Dodo Payments adalah jangka pendek tetapi tidak terautentikasi dalam jendela waktu mereka; siapa pun dengan URL dapat mengunduh dalam jendela tersebut. Konten yang di-hosting secara eksternal dan dibatasi akun memberikan jaminan yang lebih kuat.

## Webhook

Pengiriman file digital dan pencabutan memicu empat [acara webhook `entitlement_grant.*`](/developer-resources/webhooks/intents/entitlement-grant). Untuk grant File Digital, payload mencakup objek `digital_product_delivery` dengan daftar file yang diselesaikan (URL presigned, nama file, ukuran), `instructions` opsional, dan `external_url` opsional.

```json theme={null}
"digital_product_delivery": {
  "files": [
    {
      "file_id": "df_a4f6c1de",
      "download_url": "https://files.dodopayments.com/.../pro-bundle.zip?Signature=...",
      "filename": "pro-bundle.zip",
      "content_type": "application/zip",
      "file_size": 18742390,
      "expires_in": 900
    }
  ],
  "instructions": "Unzip and run setup.sh from the project root.",
  "external_url": null
}
```

## Pengiriman Produk Digital Lama

<Note>
Produk yang dikonfigurasi dengan blok `digital_product_delivery` lama pada produk itu sendiri telah **dimigrasikan secara otomatis** ke entitlement Digital Files. File yang sudah ada dan diunggah melalui product file API lama tetap dipertahankan; file tersebut tetap dapat diunduh dan muncul dalam grant payload bersama file yang baru diunggah. Pada konfigurasi `digital_files` entitlement, file tersebut dicatat dalam daftar `legacy_file_ids`. Pembaruan selanjutnya (menambahkan file, mengubah instruksi, mengganti URL eksternal) harus dilakukan dengan mengedit entitlement Digital Files yang telah dimigrasikan di bawah **Entitlements**.

Bidang level produk lama (`digital_product_delivery.external_url`, `digital_product_delivery.instructions`) terus terisi pada respons produk untuk kompatibilitas mundur, tetapi hak adalah sumber kebenaran ke depan.
</Note>

## Praktik Terbaik

- **Anggap unduhan sebagai satu kali.** Pelanggan akan berbagi atau kehilangan tautan, jadi desain produk Anda dengan asumsi bahwa apa pun yang mereka unduh menjadi milik mereka.
- **Gunakan instruksi untuk menetapkan harapan.** Untuk paket multi-berkas, tambahkan baris `instructions` yang menjelaskan apa yang harus diinstal terlebih dahulu atau cara menggabungkan berkas.
- **Perhatikan batas 500 MiB.** Artefak yang lebih besar (dataset multi-GB, kursus video) sebaiknya dihosting secara eksternal dan ditautkan melalui `external_url` daripada diunggah.
- **Gabungkan dengan License Keys untuk akses yang bisa dicabut.** Jika Anda perlu mencabut akses ke fitur dalam produk setelah pengembalian dana, gabungkan hak akses Berkas Digital dengan hak akses License Key dan validasi kunci saat runtime.
- **Uji alur penyegaran portal pelanggan.** Pastikan pelanggan dapat kembali ke portal seminggu kemudian dan masih mendapatkan tautan unduhan yang berfungsi. Ini adalah jalur pemulihan utama ketika tautan email kedaluwarsa.
