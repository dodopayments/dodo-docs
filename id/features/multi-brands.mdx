## Pendahuluan

Multi-Brand memungkinkan Anda melampirkan beberapa merek, masing-masing dengan logo, deskriptor, dan URL situs web sendiri, ke **satu bisnis terverifikasi**. Akun pembayaran Anda, biaya, dan KYC tetap sama persis, sementara setiap Produk, Tautan Pembayaran, Langganan, Faktur, dan Transaksi kini dapat diajukan di bawah merek tertentu. Gunakan untuk menguji ceruk baru, melokalkan situs, atau memisahkan lini B2B dan B2C tanpa membuka akun bisnis tambahan.

## Alur Dasbor Merchant

<Steps>
<Step title="Open Settings → Business">
Navigasikan ke **Pengaturan → Bisnis**. Panel **Merek Di Bawah [Bisnis Anda]** di sebelah kanan mencantumkan merek Utama Anda dan merek Sekunder apa pun.

<Frame>
<img src="/images/multi-brands/brands-section.png" alt="Panel Merek dalam Pengaturan Bisnis menampilkan merek utama dan sekunder dengan tombol tambah untuk menambahkan merek baru" />
</Frame>
</Step>
<Step title="Click the '+' button">
Di panel Merek, klik tombol **+** di pojok kanan atas untuk membuka formulir merek baru.
</Step>
<Step title="Fill in the brand details">
Lengkapi kolom berikut:

- **Nama Merek** (wajib): Masukkan nama merek Anda.
- **URL Situs Web** (wajib): Situs web merek Anda, contohnya `https://www.yourcompany.com`.
- **Email Dukungan**: Email yang dapat digunakan pelanggan untuk menghubungi dukungan untuk merek ini.
- **Deskripsi Merek** (wajib): Jelaskan merek Anda, produk, dan apa yang membuatnya unik.
- **Logo Merek**: Unggah logo untuk mewakili merek pada pembayaran, faktur, dan tautan pembayaran.

Kirim formulir untuk membuat merek. Produk sekarang dapat diberi tag ke merek ini dan tautan pembayaran akan menampilkan branding-nya.
</Step>
<Step title="Brand Selector">
Filter Merek sekarang terlihat pada pembuatan Produk.
</Step>
<Step title="Brand ID in Transactions">
Transaksi dan Langganan memiliki ID Merek untuk membantu Anda mengidentifikasi transaksi mana yang milik merek mana.
</Step>
</Steps>

## Poin Tambahan

- **Tidak ada perubahan payout:** Semua dana, siklus payout, dan biaya tetap mengalir ke dompet tingkat bisnis dan rekening bank merchant.
- **Brand ID pada webhook:** Semua payload pembayaran, langganan, refund, sengketa, kunci lisensi, entri ledger kredit, saldo kredit rendah, pemberian entitlement, upaya penagihan, dan checkout yang ditinggalkan menyertakan `brand_id`, sehingga Anda dapat mengaitkannya dengan brand tertentu. Jika suatu entitas tidak memiliki brand sendiri, `brand_id` akan menggunakan brand utama bisnis tersebut. Payload payout berada di tingkat bisnis dan tidak menyertakan `brand_id`.
- **Penangguhan:** Jika sebuah brand ditangguhkan, hanya payment link miliknya yang berhenti. Brand lain di bawah bisnis yang sama tetap dapat bertransaksi.
- Tidak ada perubahan pada Storefront, Invoices, License Keys, Discount Codes, Payout Settings, maupun fitur tingkat bisnis lainnya.

## Mengarsipkan Brand

Ketika sebuah brand sudah tidak digunakan lagi, arsipkan brand tersebut daripada membiarkannya tidak aktif di dashboard Anda. Pengarsipan menonaktifkan brand dan menyerahkan katalognya kepada brand lain dari bisnis yang sama dalam satu langkah.

<Warning>
Mengarsipkan brand bersifat permanen. Tidak ada cara untuk memulihkan brand yang telah diarsipkan.
</Warning>

### Yang Terjadi Saat Anda Mengarsipkan Brand

Anda menentukan **brand target** untuk mengambil alih dari brand yang Anda arsipkan. Dashboard selalu meminta satu brand target, dan API menerimanya sebagai `move_products_to`. Dalam satu tindakan atomik, Dodo Payments:

- Memindahkan setiap produk ke brand target.
- Memindahkan setiap langganan aktif ke brand target, sehingga perpanjangan tetap ditagihkan atas nama brand tersebut.
- Memindahkan setiap koleksi produk ke brand target.
- Mengarsipkan dan menonaktifkan brand asli.

Riwayat Anda tidak berubah. Pembayaran, invoice, dan langganan yang telah selesai tetap menggunakan brand tempat data tersebut dibuat, sehingga pelaporan sebelumnya tetap akurat.

Brand target harus berasal dari bisnis yang sama dan tidak boleh diarsipkan. Brand utama Anda adalah target yang valid, dan ID brand-nya adalah ID bisnis Anda. Anda dapat mengosongkan target hanya jika brand tersebut tidak memiliki produk, langganan aktif, atau koleksi produk.

<Note>
Brand utama tidak dapat diarsipkan. Brand ini menjadi fallback bisnis Anda, sehingga selalu ada setidaknya satu brand yang tersisa.
</Note>

### Brand yang Diarsipkan Bersifat Read-Only

| Tindakan | Hasil |
|---|---|
| Mengedit detail brand | Ditolak dengan `BRAND_ARCHIVED` |
| Mengirimkan brand untuk verifikasi | Ditolak dengan `BRAND_ARCHIVED` |
| Membuat produk atau koleksi di bawah brand | Ditolak dengan `BRAND_ARCHIVED` |
| Membuat langganan untuk salah satu produknya | Ditolak dengan `BRAND_ARCHIVED` |

Brand yang diarsipkan disembunyikan dari pemilih brand, sehingga Anda tidak dapat menandai data baru dengan brand tersebut. Brand tetap tersedia sebagai filter analytics, sehingga pelaporan per brand Anda tetap lengkap untuk periode saat brand tersebut beroperasi. Lihat [Analytics](/features/analytics).

### Mengarsipkan Melalui API

Panggil endpoint arsip dengan brand yang Anda nonaktifkan dan brand yang mengambil alih:

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

Respons tersebut melaporkan data yang dipindahkan, sehingga Anda dapat mengonfirmasi hasilnya:

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

Untuk mencantumkan brand termasuk yang telah diarsipkan, tetapkan `include_archived` pada list endpoint. Brand yang diarsipkan dikecualikan secara default. Setiap brand memiliki field `archived_at`, yang bernilai `null` saat brand masih aktif.

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

Lihat referensi API [Archive Brand](/api-reference/brands/archive-brand) untuk skema request dan response lengkap, serta [Error Codes](/api-reference/error-codes) untuk error yang dikembalikan endpoint ini.
