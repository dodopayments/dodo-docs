## Pengelolaan API Key dan Autentikasi

<Steps>
<Step title="Access API Keys">
Buka **Developer → API Keys** di dashboard Anda untuk mengelola key.
</Step>

<Step title="Generate a New Key">
Pilih **Add API Key**, berikan nama yang deskriptif, dan konfigurasikan akses tulis:

- **Enable write access** (dicentang): Izin baca dan tulis penuh untuk semua operasi API
- **Enable write access** (tidak dicentang): Akses hanya baca - hanya dapat mengambil data (pembayaran, subscription, customer, produk). Tidak dapat membuat atau mengubah resource.

<Tip>
Hapus centang "Enable write access" untuk integrasi dashboard, alat analitik, dan sistem apa pun yang hanya perlu melihat data tanpa melakukan perubahan.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Salin key yang dibuat segera dan pastikan key tersebut disimpan dengan aman.
</Step>

<Step title="Authenticate Your API Requests">
Gunakan API key Anda untuk mengautentikasi semua request. Terapkan format authorization berikut:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Jangan pernah mengekspos secret API key Anda dalam kode sisi klien atau repository publik.
</Warning>
</Step>
</Steps>

## Rate Limit

API kami menggunakan sistem rate limiting dengan dua jendela dan perlindungan burst. Limit diterapkan berdasarkan metode autentikasi dan tier bisnis Anda.

### Limit Default (Tier 0)

| Jendela | Limit |
|--------|-------|
| Per Detik (Burst) | 40 request |
| Per Menit (Berkelanjutan) | 240 request |

### Tier Bisnis

Rate limit yang lebih tinggi tersedia untuk bisnis dengan kebutuhan API yang lebih besar:

| Tier | Burst (per detik) | Berkelanjutan (per menit) |
|------|-------------------|------------------------|
| Tier 0 (Default) | 40 | 240 |
| Tier 1 | 100 | 1.000 |
| Tier 2 | 500 | 5.000 |

<Tip>
Hubungi support untuk meningkatkan bisnis Anda ke tier rate limit yang lebih tinggi.
</Tip>

### Request Tanpa Autentikasi

Request tanpa header autentikasi yang valid dibatasi berdasarkan alamat IP:

| Jendela | Limit |
|--------|-------|
| Per Detik (Burst) | 20 request |
| Per Menit (Berkelanjutan) | 100 request |

### Header Rate Limit

Pantau penggunaan Anda dengan response header berikut:

- `X-RateLimit-Limit` - Jumlah maksimum request yang diizinkan
- `X-RateLimit-Remaining` - Jumlah request yang tersisa pada jendela saat ini
- `X-RateLimit-Reset` - Waktu saat rate limit direset

<Note>
Saat Anda melampaui rate limit, API mengembalikan response `429 Too Many Requests`. Terapkan exponential backoff dalam logika retry Anda.
</Note>
