## Overview

Test mode lets you simulate payments without processing real transactions. All test credentials only work in test mode — never use them in production.

<CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
Test transactions don't process actual payments or affect real accounts.
</Card>

<Card title="Full API Access" icon="code">
All API endpoints work identically in test and live modes.
</Card>

<Card title="Webhook Testing" icon="webhook">
Webhooks fire for test transactions just like production.
</Card>
</CardGroup>

<Warning>
Test credentials only work in test mode. Attempting to use them in live mode will result in payment failures.
</Warning>

### Cara Menguji Kegagalan Pembaruan

<Steps>
<Step title="Create a test subscription">
Buat langganan dengan kunci API uji Anda menggunakan kartu uji **sukses** (misalnya, `4242 4242 4242 4242`). Biaya awal harus berhasil dan langganan harus menjadi aktif.
</Step>

<Step title="Swap in the failure card via Customer Portal">
Buka [Customer Portal](/features/customer-portal), temukan langganan yang baru saja Anda buat, dan klik **Update Payment Method**. Masukkan kartu uji kegagalan `4000 0000 0000 0341` (Kedaluarsa: `12/34`, CVC: `123`) dan simpan sebagai metode pembayaran langganan.
</Step>

<Step title="Advance the next billing date (optional)">
Untuk memicu pembaruan segera daripada menunggu siklus penagihan alami, gunakan API Pembaruan Langganan untuk mengatur `next_billing_date` ke waktu UTC saat ini. Nilai tersebut harus berupa stempel waktu UTC ISO 8601 / RFC 3339 (sufiks `Z` diperlukan).

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

Lihat detailnya di [Update Subscription API reference](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0).
</Step>

<Step title="Verify the failure">
Pada percobaan penagihan berikutnya:

- Biaya pembaruan ditolak pada kartu kegagalan
- Langganan berpindah ke status **On-Hold**
- Sebuah acara webhook `payment.failed` dikirimkan
- Pelanggan dapat kembali ke Customer Portal untuk memperbarui metode pembayaran dan mencoba lagi
</Step>
</Steps>

<Warning>
Kartu ini khusus untuk menguji kegagalan pembaruan. Biaya akan ditolak pada tanggal penagihan berikutnya, memungkinkan Anda untuk menguji logika pengulangan pembayaran, pemberitahuan pelanggan, dan penanganan kegagalan.
</Warning>

## Uji UPI

Pengujian UPI menggunakan identifier VPA (Virtual Payment Address) khusus yang mensimulasikan berbagai hasil pembayaran.

| Status | UPI ID |
| :----- | :----- |
| Success | `success@upi` |
| Failure | `failure@upi` |

### Persyaratan untuk Pengujian UPI

- Negara penagihan harus diatur ke `IN`
- Mata uang harus `INR`
- Untuk pedagang non-India: Adaptive Currency harus diaktifkan

Untuk dokumentasi UPI lengkap termasuk pengujian mandat RBI untuk langganan, lihat halaman [India Payment Methods](/features/payment-methods/india).

### Afterpay Testing

<Steps>
<Step title="Select Afterpay">
Pilih Afterpay sebagai metode pembayaran di checkout dan klik Pay.
</Step>

<Step title="Test successful payment">
Gunakan alamat email dan alamat pengiriman yang valid untuk pembayaran yang sukses.
</Step>

<Step title="Test failed authentication">
Untuk menyimulasikan kegagalan, tutup jendela modal Afterpay di halaman pengalihan. Pembayaran beralih dari `requires_customer_action` ke `requires_payment_method`.
</Step>
</Steps>

<Note>
Afterpay membutuhkan jumlah transaksi minimal **$50.01** agar muncul sebagai opsi pembayaran.
</Note>

Untuk dokumentasi BNPL lengkap termasuk pengujian Billie B2B, lihat halaman [Buy Now Pay Later](/features/payment-methods/bnpl).

## Menguji Digital Wallet

### Apple Pay

<Steps>
<Step title="Enable test mode">
Gunakan test API keys Dodo Payments Anda.
</Step>

<Step title="Add a card to Apple Wallet">
Tambahkan kartu sungguhan ke Apple Wallet Anda. Dalam test mode, kartu tidak akan dikenai biaya.
</Step>

<Step title="Complete test purchase">
Buka checkout di perangkat Apple dan selesaikan alur Apple Pay.
</Step>
</Steps>

<Warning>
Apple Pay memerlukan HTTPS. Apple Pay tidak akan muncul di `localhost` tanpa konfigurasi SSL yang tepat. Verifikasi domain juga harus selesai.
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
[Gabung ke grup kartu pengujian Google Pay](https://groups.google.com/g/googlepay-test-mode-stub-data) untuk mendapatkan kartu pengujian yang otomatis ditambahkan ke wallet Anda.
</Step>

<Step title="Enable test mode">
Gunakan test API keys Dodo Payments Anda.
</Step>

<Step title="Complete test purchase">
Pilih salah satu kartu pengujian di Google Pay untuk menyelesaikan transaksi.
</Step>
</Steps>

### Amazon Pay, Cash App Pay & RevolutPay

Gunakan test API keys Anda dan ikuti alur checkout standar. Transaksi pengujian disimulasikan tanpa biaya aktual.

Untuk dokumentasi digital wallet lengkap termasuk verifikasi domain untuk Apple Pay, lihat halaman [Digital Wallets](/features/payment-methods/digital-wallets).

## Uji ACH Direct Debit

ACH Direct Debit dapat diuji dalam Test Mode dengan memasukkan detail bank pengujian saat checkout.

<Steps>
<Step title="Enable test mode">
Gunakan test API keys Dodo Payments Anda.
</Step>

<Step title="Set currency and billing address">
Atur mata uang penagihan ke `USD` dan negara alamat penagihan ke `US`. ACH tidak ditawarkan di luar kombinasi ini.
</Step>

<Step title="Use a one-time payment">
ACH tidak tersedia pada checkout langganan, jadi uji dengan pembayaran satu kali.
</Step>

<Step title="Enter the test bank details">
Masukkan salah satu pasangan routing number dan account number pengujian di bawah, lalu pastikan webhook handler Anda menerima status pembayaran final — pembayaran ACH dikonfirmasi secara asinkron, bukan saat checkout.
</Step>
</Steps>

### Rekening Bank Pengujian

Gunakan routing number `110000000` dengan salah satu account number berikut:

| Account Number | Perilaku |
| :------------- | :------- |
| `000123456789` | Pembayaran berhasil. |
| `000222222227` | Pembayaran gagal karena dana tidak mencukupi. |
| `000111111113` | Pembayaran gagal karena rekening ditutup. |
| `000555555559` | Pembayaran berhasil, lalu memicu sengketa. |
| `000000000009` | Pembayaran terus diproses tanpa batas waktu. |

Untuk daftar lengkap rekening pengujian, lihat halaman [ACH Direct Debit](/features/payment-methods/ach#testing).

## Uji Metode Eropa

Metode pembayaran Eropa (iDEAL, Bancontact, EPS, Multibanco) dapat diuji dalam Test Mode.

<Steps>
<Step title="Enable test mode">
Gunakan API key pengujian Dodo Payments Anda.
</Step>

<Step title="Set billing address">
Atur negara alamat penagihan agar sesuai dengan metode pembayaran:
- `NL` untuk iDEAL
- `BE` untuk Bancontact
- `AT` untuk EPS
- `PT` untuk Multibanco
</Step>

<Step title="Set currency">
Metode Eropa memerlukan mata uang EUR.
</Step>

<Step title="Complete test flow">
Ikuti alur autentikasi bank yang disimulasikan di lingkungan pengujian.
</Step>
</Steps>

### IBAN SEPA Direct Debit Pengujian

SEPA Direct Debit memerlukan EUR dan alamat penagihan di Zona Euro. Gunakan IBAN pengujian berikut untuk memaksa hasil tertentu:

| IBAN Pengujian | Perilaku |
| :-------- | :------- |
| `DE89370400440532013000` | Pembayaran berhasil. |
| `DE62370400440532013001` | Pembayaran gagal. |
| `DE35370400440532013002` | Pembayaran berhasil, lalu langsung disengketakan. |
| `DE65370400440002222227` | Pembayaran gagal karena dana tidak mencukupi. |

Untuk daftar lengkap IBAN pengujian, termasuk nilai per negara, lihat halaman [Europe](/features/payment-methods/europe#sepa-test-ibans).

Untuk dokumentasi lengkap metode pembayaran Eropa, lihat halaman [Europe](/features/payment-methods/europe).

## Praktik Terbaik Pengujian

<AccordionGroup>
<Accordion title="Test all payment scenarios">
Jangan hanya menguji pembayaran yang berhasil. Uji penolakan, pembatalan, dan kasus khusus seperti dana yang tidak mencukupi.
</Accordion>

<Accordion title="Verify webhook handling">
Pastikan endpoint webhook Anda memproses semua jenis event dengan benar, terutama `payment.succeeded`, `payment.failed`, dan event langganan.

Gunakan [Dodo Payments CLI](/developer-resources/sdks/cli#webhooks) untuk menguji webhook secara lokal:
- `dodo wh listen` meneruskan webhook pengujian langsung ke server lokal Anda
- `dodo wh trigger` mengirim payload mock untuk semua jenis event webhook yang didukung
</Accordion>

<Accordion title="Test on real devices">
Untuk Apple Pay dan Google Pay, lakukan pengujian di perangkat iOS dan Android yang sebenarnya. Simulator tidak sepenuhnya mereplikasi perilaku wallet.
</Accordion>

<Accordion title="Test regional methods with correct addresses">
Metode pembayaran regional (UPI, iDEAL, dan lainnya) memerlukan alamat penagihan yang sesuai. Alamat penagihan AS tidak akan menampilkan iDEAL.
</Accordion>

<Accordion title="Verify minimum amounts">
Metode BNPL memerlukan minimum $50.01. Uji apakah metode tersebut muncul atau disembunyikan dengan benar berdasarkan total keranjang.
</Accordion>
</AccordionGroup>
