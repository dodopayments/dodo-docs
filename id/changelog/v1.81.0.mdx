## Fitur Baru

### 1. **Dukungan Analitik Pihak Ketiga**

Lacak perilaku pelanggan di Storefront, Checkout, dan Customer Portal dengan Google Analytics 4, Google Tag Manager, dan Meta Pixel. Tambahkan ID pelacakan Anda di **Pengaturan → Analitik** untuk mulai mengumpulkan acara e-commerce.

**Platform yang Didukung**

| Platform                | Format ID                             |
|-------------------------|--------------------------------------|
| Google Analytics 4      | `G-XXXXXXXXXX` |
| Google Tag Manager      | `GTM-XXXXXXX` |
| Meta Pixel             | Numerik (10-20 digit)                |

**Acara yang Dilacak**

Acara seperti `purchase`, `add_payment_info`, `view_item`, dan `view_item_list` secara otomatis dikirim ke platform analitik Anda saat pelanggan menjelajah dan menyelesaikan pembelian.

<Check>
Didukung di Storefront, Checkout yang dihosting, Checkout overlay/in-line, dan Customer Portal.
</Check>

Pelajari lebih lanjut: [Analitik Pihak Ketiga](/features/analytics)

### 2. **Kustomisasi Tema Checkout**

Sesuaikan tampilan checkout melalui parameter `customization.theme_config` saat membuat sesi checkout. Konfigurasikan warna, font, radius tepi, dan teks tombol untuk mode terang dan gelap.

**Opsi Konfigurasi**

| Properti                                        | Deskripsi                            |
|-------------------------------------------------|--------------------------------------|
| `light` / `dark` | Skema warna untuk setiap mode        |
| `font_primary_url`                | URL font kustom                  |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius`         | Radius tepi (misalnya, `8px`)   |
| `pay_button_text`                | Teks tombol kustom                 |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

Pelajari lebih lanjut: [Kustomisasi Tema Checkout](/features/checkout#checkout-theme-customization)

### 3. **Cegah Perubahan Rencana saat Pembayaran Gagal**

Parameter baru `on_payment_failure` untuk perubahan rencana langganan mengontrol perilaku saat pembayaran gagal.

| Mode                                         | Perilaku                                               |
|-----------------------------------------------|-----------------------------------------------------|
| `prevent_change` | Pertahankan langganan pada rencana saat ini hingga pembayaran berhasil |
| `apply_change` | Terapkan perubahan rencana segera terlepas dari hasil pembayaran (default) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
Gunakan `prevent_change` untuk upgrade kritis di mana Anda ingin memastikan pembayaran sebelum memberikan akses ke fitur premium.
</Tip>

Pelajari lebih lanjut: [Menangani Kegagalan Pembayaran](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## Pembaruan API

### API Buku Besar Saldo

Endpoint baru `GET /balances/ledger` untuk mengambil entri buku besar akun Anda dengan penyaringan dan pagination.

| Parameter                                      | Deskripsi                            |
|------------------------------------------------|------------------------------------|
| `created_at_gte` / `created_at_lte` | Saring berdasarkan rentang tanggal |
| `event_type` | Saring berdasarkan `payment`, `refund`, `dispute`, `payout`, dll. |
| `currency` | Saring berdasarkan kode mata uang |
| `reference_object_id` | Saring berdasarkan ID pembayaran/refund/perselisihan tertentu |

Pelajari lebih lanjut: [API Buku Besar Saldo](/api-reference/balance-ledger/list-ledger-entries)

### Respon Pembayaran: `refund_status`

Menambahkan field `refund_status` ke respon `GET /payments/{paymentId}` untuk dengan cepat memeriksa apakah pembayaran telah dikembalikan tanpa mengquery endpoint pengembalian terpisah.
