Setiap produk kini memiliki **dasbor analitik khusus** masing-masing. Akses ke **Produk > [Pilih Produk]** untuk melihat metrik terperinci yang spesifik untuk produk tersebut, yang disusun dalam lima tab:

</Frame>

| Tab | Apa yang Anda Dapatkan |
|-----|-------------|
| **Ikhtisar** | Total pendapatan, jumlah pembayaran yang berhasil, grafik tren pendapatan 30 hari (harian atau kumulatif), dan tabel transaksi yang dapat difilter |

### 2. **Dukungan Verifi RDR pada Dodo Payments**

Dodo Payments sekarang mendukung **Visa Rapid Dispute Resolution (RDR)** yang didukung oleh Verifi -- alat pencegahan sengketa otomatis yang menyelesaikan sengketa Visa yang layak **sebelum menjadi pengembalian dana formal**. Ketika pemegang kartu memulai sengketa, RDR mengintersepsi dan secara otomatis mengeluarkan pengembalian dana jika transaksi berada di bawah ambang batas USD yang Anda konfigurasi.

**Mengapa Ini Penting**

| Manfaat | Dampak |
|---------|--------|
| **Tingkat sengketa lebih rendah** | Sengketa yang diselesaikan oleh RDR tidak dihitung dalam ambang batas 0,9% Visa |
| **Tanpa biaya sengketa** | Hindari biaya tidak dapat dikembalikan sebesar $15-$25 per sengketa |
| **Tanpa overhead operasional** | Tidak ada pengumpulan bukti atau batas waktu respons |
| **Pengalaman pelanggan yang lebih baik** | Pemegang kartu mendapatkan pengembalian dana instan |
| **Lindungi akun** | Jauh dari Program Pemantauan Sengketa Visa (VDMP) |

<Warning>
Melampaui tingkat sengketa 0,9% Visa atau 100 sengketa/bulan akan memicu VDMP, dengan denda yang meningkat hingga $50,000+/bulan. RDR membantu Anda tetap jauh di bawah ambang batas ini.
</Warning>

**Bagaimana Ini Bekerja**

1. Pemegang kartu memulai sengketa dengan bank mereka
2. RDR mengintersepsi sengketa sebelum menjadi pengembalian dana formal
3. Jika jumlah transaksi berada di ambang batas Anda, pengembalian dana dikeluarkan secara otomatis
4. Sengketa selesai secara instan dan **tidak dihitung** terhadap tingkat sengketa Anda

<Info>
Transaksi yang secara otomatis dikembalikan melalui RDR muncul sebagai **sengketa hilang** di dasbor Dodo Payments Anda. Ini diharapkan -- pengembalian dana dikeluarkan secara otomatis untuk mencegah pengembalian dana formal.
</Info>

Untuk mengaktifkan Verifi RDR di akun Anda, hubungi **support@dodopayments.com** untuk mengonfigurasi ambang batas Anda.

Pelajari lebih lanjut: [Dokumentasi Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

Memperkenalkan **DodoPayments CLI** yang baru -- kelola seluruh alur kerja Dodo Payments Anda langsung dari terminal. Dibangun untuk pengembang yang lebih memilih baris perintah, CLI memungkinkan Anda mengelola produk, pembayaran, pelanggan, diskon, lisensi, addon, pengembalian dana, dan bahkan membuat sesi checkout tanpa meninggalkan editor Anda.

**Instalasi**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Perintah Utama**

| Perintah | Deskripsi |
|---------|-------------|
| `dodo login` | Autentikasi dengan kunci API Anda (membuka browser) |
| `dodo products list` | Daftar semua produk |
| `dodo payments list` | Daftar semua pembayaran |
| `dodo customers create` | Buat pelanggan baru |
| `dodo checkout new` | Buat sesi checkout dan dapatkan URL |
| `dodo wh listen` | Teruskan webhook pengujian langsung ke server lokal Anda melalui WebSocket |
| `dodo wh trigger` | Kirim payload webhook tiruan ke titik akhir mana pun |

**Pengujian Webhook**

CLI mencakup dua alat kuat untuk pengembangan:

- **`dodo wh listen`** -- Membuka koneksi WebSocket untuk meneruskan webhook pengujian waktu nyata ke server lokal Anda, mempertahankan header asli untuk pengujian verifikasi tanda tangan
- **`dodo wh trigger`** -- Mengirimkan payload webhook tiruan secara interaktif, mendukung semua 22 jenis acara di seluruh langganan, pembayaran, pengembalian dana, sengketa, dan lisensi

<Tip>
Pendengar webhook hanya berfungsi dengan kunci API **mode uji**. Pastikan Anda masuk dengan kunci mode uji sebelum menggunakan `dodo wh listen`.
</Tip>

Pelajari lebih lanjut: [Dokumentasi CLI](/developer-resources/sdks/cli)

### 5. **Perbarui Metode Pembayaran dalam Checkout Inline**

Checkout [inline](/developer-resources/inline-checkout) kini mendukung **pembaruan metode pembayaran** untuk langganan. Ketika seorang pelanggan perlu memperbarui metode pembayarannya (untuk langganan aktif atau untuk mengaktifkan kembali langganan yang ditangguhkan), alur pembaruan metode pembayaran kini dapat dirender langsung di dalam tata letak halaman Anda menggunakan checkout inline -- memberikan pengalaman yang mulus dan tertanam.

**Cara Kerjanya**

1. Panggil API Pembaruan Metode Pembayaran untuk mendapatkan `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Gunakan `payment_link` yang dikembalikan sebagai `checkoutUrl` dalam checkout inline:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

Frame inline hanya merender formulir pengumpulan metode pembayaran, memungkinkan pelanggan untuk memasukkan rincian kartu baru atau memilih metode pembayaran yang disimpan tanpa meninggalkan halaman Anda.

<Tip>
Untuk langganan yang ditangguhkan, alur pembaruan metode pembayaran secara otomatis membuat biaya untuk tunggakan yang tersisa. Pantau webhook `payment.succeeded` dan `subscription.active` untuk mengonfirmasi reaktivasi.
</Tip>

Pelajari lebih lanjut: [Checkout Inline](/developer-resources/inline-checkout) | [Pembaruan Metode Pembayaran Langganan](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Dukungan Prefill ID Pajak untuk Sesi Checkout**

Anda sekarang dapat **mengisi otomatis ID Pajak** (misalnya, nomor PPN, nomor GST) saat membuat sesi checkout menggunakan parameter `tax_id`. Ini ideal untuk transaksi B2B di mana Anda sudah mengetahui nomor identifikasi pajak pelanggan. Ketika ID Pajak diisi otomatis, kolom akan terisi dan terkunci di formulir checkout.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Parameter `tax_id` memerlukan `billing_address` dengan setidaknya satu kolom `country`. Kelayakan pajak divalidasi secara real-time, dan aturan reverse-charge diterapkan secara otomatis untuk transaksi B2B yang memenuhi syarat.
</Info>

Gunakan fitur flag `allow_customer_editing_tax_id` untuk mengontrol apakah pelanggan dapat mengubah ID Pajak yang diisi otomatis, dan `allow_tax_id` untuk mengubah visibilitas ID Pajak di checkout.

Pelajari lebih lanjut: [Sesi Checkout - ID Pajak](/developer-resources/checkout-session) | [Pembayaran B2B](/features/b2b-payments)

### 7. **Kunci Lisensi dan Email di Pengalihan URL Kembali**

Setelah pelanggan menyelesaikan checkout, Dodo Payments kini melampirkan `license_key` dan `email` sebagai parameter kueri ke pengalihan `return_url` Anda, selain dari parameter `payment_id`/`subscription_id` dan `status` yang ada.

**Parameter Kueri yang Dilampirkan**

| Parameter | Tipe | Kondisi |
|-----------|------|-----------|
| `payment_id` | `string` | Selalu ada untuk pembayaran satu kali |
| `subscription_id` | `string` | Selalu ada untuk pembayaran langganan |
| `status` | `string` | Selalu ada |
| `license_key` | `string` | Ada jika produk memiliki kunci lisensi diaktifkan (dipisahkan koma untuk beberapa) |
| `email` | `string` | Ada jika pelanggan memiliki email yang tercatat |

**Contoh URL Pengalihan:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Gunakan parameter kueri ini untuk menampilkan kunci lisensi atau mengirim email konfirmasi segera di halaman kembali Anda, tanpa perlu panggilan API tambahan.
</Tip>

Pelajari lebih lanjut: [Sesi Checkout - URL Kembali](/developer-resources/checkout-session) | [Kunci Lisensi di URL Kembali](/features/license-keys#license-keys-in-return-url)

### 8. **API Pembaruan Email Pelanggan**

Endpoint `PATCH /customers/{customer_id}` kini mendukung pembaruan alamat email pelanggan secara programatik. Perbarui email bersamaan dengan nama, nomor telepon, dan metadata dalam satu panggilan API.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Bidang yang Dapat Diperbarui**

| Bidang | Tipe | Deskripsi |
|-------|------|-------------|
| `email` | `string \| null` | Alamat email pelanggan |
| `name` | `string \| null` | Nama tampilan pelanggan |
| `phone_number` | `string \| null` | Nomor telepon dalam format internasional |
| `metadata` | `object \| null` | Pasangan kunci-nilai kustom |

<Info>
Pembaruan email pelanggan juga tersedia melalui Portal Pelanggan (layanan mandiri), dasbor, dan CLI melalui `dodo customers update`.
</Info>

Pelajari lebih lanjut: [API Pembaruan Pelanggan](/api-reference/customers/patch-customer) | [Manajemen Pelanggan](/features/customers)

### 9. **Rilis Adaptor Bun**

Memperkenalkan `@dodopayments/bun` -- adaptor framework khusus untuk server native [Bun](https://bun.sh) (`Bun.serve()`). Integrasikan checkout, portal pelanggan, dan webhook dengan Bun hanya dalam beberapa baris kode.

**Instalasi**

```bash
bun add @dodopayments/bun
```

**Pengaturan Cepat**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Adaptor Bun mendukung semua tiga alur checkout (statis, dinamis, dan berbasis sesi), pembuatan sesi portal pelanggan, dan penanganan webhook aman dengan verifikasi tanda tangan dan validasi Zod di seluruh 22 jenis acara.

<Check>
Adaptor Bun bergabung dengan keluarga 11 adaptor framework kami termasuk Next.js, Nuxt, Express, Fastify, Hono, Astro, SvelteKit, Remix, TanStack Start, Better Auth, dan Convex.
</Check>
