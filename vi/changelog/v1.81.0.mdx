## Tính Năng Mới

### 1. **Hỗ Trợ Phân Tích Từ Bên Thứ Ba**

Theo dõi hành vi của khách hàng trên Storefront, Checkout và Customer Portal với Google Analytics 4, Google Tag Manager, và Meta Pixel. Thêm ID theo dõi của bạn trong **Cài đặt → Phân Tích** để bắt đầu thu thập các sự kiện thương mại điện tử.

**Nền Tảng Hỗ Trợ**

| Nền Tảng | Định Dạng ID |
|----------|-----------|
| Google Analytics 4 | `G-XXXXXXXXXX` |
| Google Tag Manager | `GTM-XXXXXXX` |
| Meta Pixel | Số (10-20 chữ số) |

**Sự Kiện Được Theo Dõi**

Các sự kiện như `purchase`, `add_payment_info`, `view_item`, và `view_item_list` sẽ được tự động gửi đến các nền tảng phân tích của bạn khi khách hàng duyệt và hoàn tất mua hàng.

<Check>
Hỗ trợ trên Storefront, Checkout được lưu trữ, Checkout theo overlay/inline, và Customer Portal.
</Check>

Tìm hiểu thêm: [Phân Tích Từ Bên Thứ Ba](/features/analytics)

### 2. **Tùy Chỉnh Giao Diện Thanh Toán**

Tùy chỉnh giao diện của thanh toán thông qua tham số `customization.theme_config` khi tạo phiên thanh toán. Cấu hình màu sắc, phông chữ, bán kính viền, và văn bản nút cho cả chế độ sáng và tối.

**Tùy Chọn Cấu Hình**

| Thuộc Tính | Mô Tả |
|----------|-------------|
| `light` / `dark` | Sơ đồ màu cho mỗi chế độ |
| `font_primary_url` | URL phông chữ tùy chỉnh |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius` | Bán kính viền (ví dụ: `8px`) |
| `pay_button_text` | Văn bản nút tùy chỉnh |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

Tìm hiểu thêm: [Tùy Chỉnh Giao Diện Thanh Toán](/features/checkout#checkout-theme-customization)

### 3. **Ngăn Chặn Thay Đổi Gói Khi Thanh Toán Thất Bại**

Tham số `on_payment_failure` mới cho việc thay đổi gói đăng ký kiểm soát hành vi khi thanh toán thất bại.

| Chế Độ | Hành Vi |
|------|----------|
| `prevent_change` | Giữ gói đăng ký trên gói hiện tại cho đến khi thanh toán thành công |
| `apply_change` | Áp dụng thay đổi gói ngay lập tức bất kể kết quả thanh toán (mặc định) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
Sử dụng `prevent_change` cho những nâng cấp quan trọng mà bạn muốn đảm bảo thanh toán trước khi cấp quyền truy cập vào các tính năng cao cấp.
</Tip>

Tìm hiểu thêm: [Xử Lý Thanh Toán Thất Bại](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## Cập Nhật API

### API Sổ Kế Toán

Điểm cuối `GET /balances/ledger` mới để lấy các mục sổ kế toán của tài khoản của bạn với bộ lọc và phân trang.

| Tham Số | Mô Tả |
|-----------|-------------|
| `created_at_gte` / `created_at_lte` | Lọc theo khoảng thời gian |
| `event_type` | Lọc theo `payment`, `refund`, `dispute`, `payout`, v.v. |
| `currency` | Lọc theo mã tiền tệ |
| `reference_object_id` | Lọc theo ID thanh toán/rembourse/dispute cụ thể |

Tìm hiểu thêm: [API Sổ Kế Toán](/api-reference/balance-ledger/list-ledger-entries)

### Phản Hồi Thanh Toán: `refund_status`

Đã thêm trường `refund_status` vào phản hồi `GET /payments/{paymentId}` để nhanh chóng kiểm tra xem một khoản thanh toán đã được hoàn lại hay chưa mà không cần truy vấn riêng điểm cuối hoàn lại.
