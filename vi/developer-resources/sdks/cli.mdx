Quản lý tài nguyên Dodo Payments của bạn, tạo các phiên thanh toán và thử nghiệm webhook trực tiếp từ terminal. Được xây dựng cho các lập trình viên thích sử dụng dòng lệnh.

## Cài đặt

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Cài đặt thủ công

1. Tải xuống bản phát hành mới nhất từ [GitHub Releases](https://github.com/dodopayments/dodopayments-cli/releases) cho hệ thống của bạn
2. Giải nén và đổi tên file nhị phân thành `dodo`
3. Chuyển đến một thư mục có trong PATH của bạn:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## Xác thực

Trước khi sử dụng CLI, hãy xác thực với API key của bạn:

```bash
dodo login
```

Điều này sẽ:
1. Mở trình duyệt của bạn đến trang API Keys của Dodo Payments
2. Nhắc bạn nhập API Key của bạn
3. Yêu cầu bạn chọn môi trường (**Chế độ thử nghiệm** hoặc **Chế độ trực tiếp**)
4. Lưu thông tin xác thực của bạn cục bộ tại `~/.dodopayments/api-key`

<Info>
CLI hỗ trợ lưu một API key cho mỗi môi trường. Nếu cả hai key chế độ thử nghiệm và trực tiếp được cấu hình, bạn sẽ được nhắc chọn môi trường nào để sử dụng cho phiên hiện tại.
</Info>

## Cách sử dụng

Cú pháp chung là:

```bash
dodo ‹category› ‹sub-command›
```

Chạy `dodo` mà không có tham số sẽ hiển thị tất cả các danh mục có sẵn. Chạy `dodo <category>` mà không có subcommand sẽ hiển thị các subcommands có sẵn cho danh mục đó.

### Sản phẩm

Quản lý danh mục sản phẩm của bạn.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo products list` | Liệt kê tất cả sản phẩm (phân trang) |
| `dodo products create` | Mở bảng điều khiển để tạo sản phẩm |
| `dodo products info` | Xem chi tiết cho một sản phẩm cụ thể |

### Thanh toán

Xem thông tin giao dịch thanh toán.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo payments list` | Liệt kê tất cả thanh toán (phân trang) |
| `dodo payments info` | Lấy thông tin về một thanh toán cụ thể |

### Khách hàng

Quản lý cơ sở khách hàng của bạn.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo customers list` | Liệt kê tất cả khách hàng (phân trang) |
| `dodo customers create` | Tạo một hồ sơ khách hàng mới |
| `dodo customers update` | Cập nhật thông tin một khách hàng hiện có |

### Giảm giá

Quản lý coupon và giảm giá.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo discounts list` | Liệt kê tất cả giảm giá (phân trang) |
| `dodo discounts create` | Tạo một giảm giá theo tỷ lệ phần trăm mới |
| `dodo discounts delete` | Xóa một giảm giá theo ID |

### Giấy phép

Quản lý giấy phép phần mềm.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo licences list` | Liệt kê tất cả các khóa giấy phép (phân trang) |

### Phụ kiện

Quản lý các phụ kiện sản phẩm.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo addons list` | Liệt kê tất cả các phụ kiện (phân trang) |
| `dodo addons create` | Mở bảng điều khiển để tạo một phụ kiện |
| `dodo addons info` | Xem chi tiết cho một phụ kiện cụ thể |

### Hoàn tiền

Xem thông tin hoàn tiền.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo refund list` | Liệt kê tất cả hoàn tiền (phân trang) |
| `dodo refund info` | Xem chi tiết cho một hoàn tiền cụ thể |

### Thanh toán

Tạo các phiên thanh toán.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo checkout new` | Tạo một phiên thanh toán mới và nhận URL thanh toán |

Lệnh thanh toán hỗ trợ các tùy chọn nâng cao bao gồm thu thập địa chỉ tối thiểu, URL trả về, yêu cầu bảo mật 3D, mã giảm giá, và metadata.

## Kiểm tra Webhook

CLI bao gồm hai công cụ mạnh mẽ để kiểm tra webhook trong quá trình phát triển: một **listener** mà chuyển tiếp webhook thử nghiệm trực tiếp đến server cục bộ của bạn, và một **trigger** mà gửi payload webhook giả đến bất kỳ endpoint nào.

### Lắng nghe các Webhook

Chuyển tiếp webhook từ Dodo Payments trực tiếp đến server phát triển cục bộ của bạn theo thời gian thực.

```bash
dodo wh listen
```

<Steps>
<Step title="Nhập URL endpoint cục bộ của bạn">
  Cung cấp URL cục bộ nơi bạn muốn nhận webhook (ví dụ: `http://localhost:3000/webhook`).
</Step>

<Step title="Thiết lập tự động">
  CLI sẽ tự động tạo một endpoint webhook trên tài khoản Dodo Payments của bạn nếu nó chưa tồn tại, sau đó mở một kết nối WebSocket để nhận sự kiện theo thời gian thực.
</Step>

<Step title="Nhận và chuyển tiếp">
  Khi một sự kiện webhook xảy ra (từ một thanh toán thử nghiệm, thay đổi đăng ký, v.v.), CLI sẽ nhận sự kiện đó, ghi lại loại sự kiện và chuyển tiếp toàn bộ yêu cầu cùng với các headers và body đến endpoint cục bộ của bạn. Phản hồi từ endpoint của bạn sẽ được ghi lại và gửi lại.
</Step>
</Steps>

<Warning>
Listener webhook chỉ hoạt động với một API key **chế độ thử nghiệm**. Đảm bảo rằng bạn đã đăng nhập với một key chế độ thử nghiệm trước khi sử dụng `dodo wh listen`.
</Warning>

<Tip>
Listener bảo tồn các headers webhook gốc (`webhook-id`, `webhook-signature`, `webhook-timestamp`) khi chuyển tiếp đến endpoint cục bộ của bạn, vì vậy bạn có thể thử nghiệm logic xác thực chữ ký của mình.
</Tip>

### Kích hoạt các Webhook Thử nghiệm

Gửi payload webhook giả đến bất kỳ endpoint nào để thử nghiệm nhanh mà không cần tạo các giao dịch thực tế.

```bash
dodo wh trigger
```

Điều này hướng dẫn bạn qua:
1. Đặt một **endpoint URL** đích
2. Tùy chọn cấu hình **Business ID**, **Product ID**, và **Metadata**
3. Chọn một **sự kiện** cụ thể để kích hoạt từ một menu tương tác
4. Gửi payload giả và xem phản hồi

Sau mỗi sự kiện, bạn có thể chọn một sự kiện khác để kích hoạt hoặc thoát -- việc này làm cho việc thử nghiệm nhiều trình xử lý sự kiện trong một phiên trở nên dễ dàng.

<Warning>
Công cụ kích hoạt gửi các payload giả mà không có chữ ký webhook. Vô hiệu hóa xác thực chữ ký webhook trong quá trình thử nghiệm bằng cách sử dụng `unsafe_unwrap()` thay vì `unwrap()` trong trình xử lý webhook của bạn.
</Warning>

### Các Sự kiện Webhook Hỗ trợ

| Danh mục | Sự kiện |
|----------|--------|
| **Đăng ký** | `subscription.active`, `subscription.updated`, `subscription.on_hold`, `subscription.renewed`, `subscription.plan_changed`, `subscription.cancelled`, `subscription.failed`, `subscription.expired` |
| **Thanh toán** | `payment.success`, `payment.failed`, `payment.processing`, `payment.cancelled` |
| **Hoàn tiền** | `refund.success`, `refund.failed` |
| **Tranh chấp** | `dispute.opened`, `dispute.expired`, `dispute.accepted`, `dispute.cancelled`, `dispute.challenged`, `dispute.won`, `dispute.lost` |
| **Giấy phép** | `licence.created` |

### Biến Môi Trường

| Biến | Mô tả |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Ghi đè URL máy chủ chuyển tiếp webhook mặc định được sử dụng bởi `dodo wh listen` |
