Quản lý tài nguyên Dodo Payments, chạy truy vấn hỗ trợ AI trên tài khoản, tạo phiên checkout và kiểm thử webhook — tất cả ngay từ terminal. CLI đi kèm TUI tương tác, trợ lý AI tích hợp được hỗ trợ bởi MCP và tính năng kiểm thử webhook ngoại tuyến.

## Tính năng

- **TUI tương tác** — chạy `dodo` không có đối số để mở giao diện tương tác đầy đủ với bảng lệnh, lịch sử và thông báo trực tiếp.
- **Tích hợp sẵn trợ lý AI** — đặt câu hỏi hoặc thực hiện thao tác bằng tiếng Anh thông thường với `/ai`. Không cần thiết lập thêm, chạy `dodopayments-mcp` cục bộ.
- **Bảo mật theo mặc định** — API keys được lưu trong kho bí mật của hệ điều hành (macOS Keychain, Windows Credential Vault, Linux libsecret). Không lưu cấu hình dạng văn bản thuần trên đĩa.
- **Tự động cập nhật** — CLI kiểm tra phiên bản mới khi khởi động và thông báo trong ứng dụng. Chạy `/update` để nâng cấp ngay tại chỗ.
- **Công cụ webhook** — lắng nghe webhook trực tiếp hoặc kích hoạt payload ngoại tuyến cho việc phát triển cục bộ.

## Cài đặt

Cài đặt CLI bằng một dòng lệnh trên macOS hoặc Linux:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### Cài đặt bằng npm hoặc Bun

Nếu bạn đã có Node hoặc Bun, các lệnh cài đặt bằng package manager luôn tải phiên bản mới nhất:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Cài đặt thủ công (không yêu cầu Node / Bun)

Nếu bạn không muốn pipe một script từ xa vào `sh`, hãy tự tải binary xuống.

<Steps>
<Step title="Download the binary">
  Tải binary dành cho nền tảng của bạn từ [GitHub Release](https://github.com/dodopayments/dodopayments-cli/releases) mới nhất.

  | Nền tảng | Binary |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  Trên Windows, việc di chuyển đến `C:\Windows\System32` yêu cầu quyền quản trị viên.
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  Mỗi bản phát hành đều công bố một `SHA256SUMS.txt`. Xác minh bản tải xuống bằng:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## Xác thực

Trước khi sử dụng các lệnh yêu cầu xác thực, hãy đăng nhập bằng API key của bạn:

```bash
dodo login
```

Hoặc từ bên trong TUI tương tác:

```text
/login
```

Quy trình đăng nhập sẽ:

1. Mở trình duyệt đến trang API Keys của Dodo Payments.
2. Yêu cầu bạn dán API Key.
3. Yêu cầu bạn chọn môi trường — **Test Mode** hoặc **Live Mode**.
4. Lưu thông tin xác thực trong kho bí mật của hệ điều hành (Keychain trên macOS, Credential Vault trên Windows, libsecret trên Linux).

<Info>
Vì thông tin xác thực được lưu trong kho bí mật của hệ điều hành, bạn có thể được yêu cầu nhập **mật khẩu thiết bị** lần đầu CLI đọc hoặc ghi thông tin xác thực. Nếu bạn nâng cấp từ phiên bản cũ, mọi API key dạng văn bản thuần hiện có sẽ được **di chuyển sang kho bí mật và tự động xóa tệp cũ**.
</Info>

### Chuyển đổi chế độ và đăng xuất

Bạn có thể xác thực đồng thời một key **Test Mode** và một key **Live Mode**. Để xóa thông tin xác thực:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

Quy trình đăng xuất cho phép bạn chọn độc lập giữa **Tất cả tài khoản**, **Test Mode** hoặc **Live Mode**.

## Cách sử dụng

Bạn có thể sử dụng CLI ở hai chế độ.

### 1. TUI tương tác (khuyến nghị)

Chạy `dodo` không có đối số để khởi chạy giao diện tương tác đầy đủ:

```bash
dodo
```

Nhập `/` để mở bảng lệnh, hoặc chỉ cần bắt đầu nhập — mọi nội dung không phải slash command sẽ được gửi đến trợ lý AI.

| Lệnh | Mô tả |
|---------|-------------|
| `/help` | Hiển thị tài liệu tham khảo lệnh |
| `/update` | Kiểm tra và cài đặt bản cập nhật CLI |
| `/login` | Xác thực bằng API key |
| `/logout` | Đăng xuất khỏi một hoặc tất cả môi trường |
| `/clear` | Xóa màn hình TUI |
| `/exit` | Thoát TUI (cũng có thể nhập `exit` hoặc nhấn `Esc` hai lần) |

### 2. Subcommand trực tiếp

Chạy lệnh trực tiếp mà không vào TUI:

```bash
dodo <category> <sub-command> [args...]
```

Ví dụ:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

Các bảng tham khảo bên dưới hiển thị mọi lệnh. Trong TUI, thêm tiền tố `/`; ở chế độ trực tiếp, bỏ tiền tố `/`.

## Trợ lý AI

Đặt câu hỏi hoặc thực hiện thao tác bằng ngôn ngữ tự nhiên. Trợ lý sử dụng `dodopayments-mcp` chạy cục bộ — không cần thiết lập bổ sung hoặc quy trình OAuth, và lưu lượng AI của bạn không rời khỏi máy ngoại trừ khi giao tiếp với nhà cung cấp model.

| Lệnh | Mô tả |
|---------|-------------|
| `/ai <query>` | Đặt câu hỏi hoặc đưa chỉ dẫn cho trợ lý AI |
| _(bất kỳ nội dung nào không bắt đầu bằng slash)_ | Theo mặc định được gửi đến trợ lý AI khi đang ở TUI |

Ví dụ:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
Trợ lý tuân theo môi trường đang hoạt động của bạn (Test / Live), vì vậy chỉ thao tác trên dữ liệu của môi trường bạn đang đăng nhập.
</Tip>

## Dựng khung dự án

`dodo init` dựng các route billing của Dodo Payments trực tiếp vào một dự án hiện có. Lệnh này tạo các tệp route boilerplate, cài đặt package adapter `@dodopayments/*` tương ứng và ghi an toàn các biến môi trường `DODO_PAYMENTS_*` vào `.env` (chỉ nối thêm các biến chưa tồn tại). Lệnh chạy **mà không cần đăng nhập**.

```bash
dodo init <framework>
```

| Scaffold | Mô tả |
|----------|-------------|
| `dodo init nextjs` | Dựng các route billing cho Next.js App Router (checkout, Customer Portal và webhook handlers) bằng `@dodopayments/nextjs` |
| `dodo init express` | Dựng các route billing cho server Express bằng `@dodopayments/express` |
| `dodo init better-auth` | Dựng cấu hình plugin Better-Auth bằng `@dodopayments/better-auth` |

Đối với scaffold Better-Auth, bạn có thể truyền danh sách plugin phân tách bằng dấu phẩy để tạo (mặc định là tất cả): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
Scaffolder tự động phát hiện thư mục `src/` và điều chỉnh các đường dẫn đầu ra tương ứng, đồng thời tự động phát hiện package manager của bạn (`bun`, `pnpm`, `yarn` hoặc `npm`) để chạy lệnh cài đặt phù hợp.
</Info>

## Webhook

CLI bao gồm hai công cụ mạnh để kiểm thử webhook trong quá trình phát triển: **listener** chuyển tiếp webhook kiểm thử trực tiếp đến server cục bộ của bạn và **trigger** gửi payload webhook giả lập đến bất kỳ endpoint nào.

| Lệnh | Mô tả |
|---------|-------------|
| `dodo wh listen` | Lắng nghe webhook theo thời gian thực và chuyển tiếp đến dev server cục bộ |
| `dodo wh trigger` | Kích hoạt tương tác một sự kiện webhook kiểm thử — ngay cả khi đã đăng xuất |

### Lắng nghe webhook

Chuyển tiếp webhook từ Dodo Payments trực tiếp đến development server cục bộ của bạn theo thời gian thực.

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  Cung cấp URL cục bộ nơi bạn muốn nhận webhook (ví dụ: `http://localhost:3000/webhook`).
</Step>

<Step title="Automatic setup">
  CLI tự động tạo webhook endpoint trên tài khoản Dodo Payments nếu endpoint chưa tồn tại, sau đó mở kết nối WebSocket để nhận sự kiện theo thời gian thực.
</Step>

<Step title="Receive and forward">
  Khi một sự kiện webhook được kích hoạt (từ giao dịch thanh toán kiểm thử, thay đổi subscription, v.v.), CLI tiếp nhận sự kiện, ghi lại loại sự kiện và chuyển tiếp toàn bộ request cùng headers và body đến endpoint cục bộ của bạn. Response từ endpoint của bạn được ghi lại và gửi ngược lại.
</Step>
</Steps>

<Warning>
`dodo wh listen` yêu cầu API key **Test Mode**. Key Live Mode không được hỗ trợ bởi quy trình listen.
</Warning>

<Tip>
Listener giữ nguyên các webhook headers ban đầu (`webhook-id`, `webhook-signature`, `webhook-timestamp`) khi chuyển tiếp đến endpoint cục bộ, để bạn có thể kiểm thử logic xác minh chữ ký.
</Tip>

### Kích hoạt webhook kiểm thử

Gửi payload webhook giả lập đến bất kỳ endpoint nào để kiểm thử nhanh mà không cần tạo giao dịch thực.

```bash
dodo wh trigger
```

Quy trình `/wh trigger` hướng dẫn bạn:

1. Thiết lập **endpoint URL** đích
2. Chọn một **event** cụ thể để kích hoạt từ menu tương tác

<Info>
`dodo wh trigger` **không yêu cầu đăng nhập**. Đây là trình tạo payload webhook cục bộ/ngoại tuyến.
</Info>

<Warning>
Các sự kiện được kích hoạt **không được ký**. Khi kiểm thử, hãy tắt tính năng xác minh chữ ký webhook trên endpoint — ví dụ, chỉ sử dụng `unsafe_unwrap()` thay cho `unwrap()` trong webhook handler **trong quá trình kiểm thử בלבד**.
</Warning>

### Các sự kiện webhook được hỗ trợ

`dodo wh trigger` có thể gửi payload giả lập cho tất cả 46 loại sự kiện mà Dodo Payments cung cấp:

| Danh mục | Sự kiện |
|----------|--------|
| **Gói đăng ký** | `active`, `updated`, `on_hold`, `paused`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired`, `update_payment_method` |
| **Thanh toán** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Hoàn tiền** | `succeeded`, `failed` |
| **Tranh chấp** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **Khóa cấp phép** | `created` |
| **Chi trả** | `created`, `in_progress`, `on_hold`, `failed`, `success` |
| **Tín dụng** | `added`, `deducted`, `expired`, `rolled_over`, `rollover_forfeited`, `overage_charged`, `overage_reset`, `manual_adjustment`, `balance_low` |
| **Thanh toán dang dở** | `detected`, `recovered` |
| **Thu hồi công nợ** | `started`, `recovered` |
| **Cấp quyền lợi** | `created`, `delivered`, `failed`, `revoked` |

<Note>
Hình dạng payload giả lập tuân theo các schema tương ứng trong tài liệu tham chiếu API. Xem [Sự kiện Webhook](/developer-resources/webhooks/intents/webhook-events-guide) để biết ý nghĩa của từng sự kiện và thời điểm Dodo Payments phát sự kiện đó trong môi trường production.
</Note>

<Tip>
`payout.created` được phát trong khi khoản chi trả vẫn báo cáo trạng thái `not_initiated`, vì vậy payload giả lập cũng phản ánh điều đó. Xem [Sự kiện chi trả](/developer-resources/webhooks/intents/payout) để biết toàn bộ vòng đời của khoản chi trả.
</Tip>
