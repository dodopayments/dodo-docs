## Overview

Test mode lets you simulate payments without processing real transactions. All test credentials only work in test mode — never use them in production.

<CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
Test transactions don't process actual payments or affect real accounts.
</Card>

<Card title="Full API Access" icon="code">
All API endpoints work identically in test and live modes.
</Card>

<Card title="Webhook Testing" icon="webhook">
Webhooks fire for test transactions just like production.
</Card>
</CardGroup>

<Warning>
Test credentials only work in test mode. Attempting to use them in live mode will result in payment failures.
</Warning>

### How to Test Renewal Failure

<Steps>
<Step title="Create a test subscription">
Create a subscription with your test API keys using a **success** test card (for example, `4242 4242 4242 4242`). The initial charge should succeed and the subscription should become active.
</Step>

<Step title="Swap in the failure card via Customer Portal">
Open the [Customer Portal](/features/customer-portal), find the subscription you just created, and click **Update Payment Method**. Enter the failure test card `4000 0000 0000 0341` (Expiry: `12/34`, CVC: `123`) and save it as the subscription's payment method.
</Step>

<Step title="Advance the next billing date (optional)">
To trigger renewal immediately instead of waiting for the natural billing cycle, use the Update Subscription API to set `next_billing_date` to the current UTC time. The value must be an ISO 8601 / RFC 3339 UTC timestamp (the `Z` suffix is required).

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

See the [Update Subscription API reference](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0) for details.
</Step>

<Step title="Verify the failure">
On the next billing attempt:

- The renewal charge declines on the failure card
- The subscription moves to **On-Hold** status
- A `payment.failed` webhook event is delivered
- The customer can return to the Customer Portal to update the payment method and retry
</Step>
</Steps>

<Warning>
This card is specifically for testing renewal failures. The charge will decline on the next billing date, allowing you to test payment retry logic, customer notifications, and failure handling.
</Warning>

## Test UPI

UPI testing uses special VPA (Virtual Payment Address) identifiers that simulate different payment outcomes.

| Status | UPI ID |
| :----- | :----- |
| Success | `success@upi` |
| Failure | `failure@upi` |

### Requirements for UPI Testing

- Billing country must be set to `IN`
- Currency must be `INR`
- For non-Indian merchants: Adaptive Currency must be enabled

For complete UPI documentation including RBI mandate testing for subscriptions, see the [India Payment Methods](/features/payment-methods/india) page.

### Afterpay Testing

<Steps>
<Step title="Select Afterpay">
Choose Afterpay as the payment method in checkout and click Pay.
</Step>

<Step title="Test successful payment">
Use any valid email address and shipping address for successful payments.
</Step>

<Step title="Test failed authentication">
Để mô phỏng lỗi, hãy đóng cửa sổ modal Afterpay trên trang chuyển hướng. Thanh toán chuyển từ `requires_customer_action` sang `requires_payment_method`.
</Step>
</Steps>

<Note>
Afterpay requires a minimum transaction amount of **$50.01** to appear as a payment option.
</Note>

Để xem tài liệu BNPL đầy đủ, bao gồm cả việc kiểm thử Billie B2B, hãy xem trang [Buy Now Pay Later](/features/payment-methods/bnpl).

## Kiểm thử Digital Wallets

### Apple Pay

<Steps>
<Step title="Enable test mode">
Sử dụng test API keys của Dodo Payments.
</Step>

<Step title="Add a card to Apple Wallet">
Thêm một thẻ thật vào Apple Wallet. Trong test mode, thẻ sẽ không bị tính phí.
</Step>

<Step title="Complete test purchase">
Mở checkout trên thiết bị Apple và hoàn tất quy trình Apple Pay.
</Step>
</Steps>

<Warning>
Apple Pay yêu cầu HTTPS. Tính năng này sẽ không xuất hiện trên `localhost` nếu chưa thiết lập SSL đúng cách. Việc xác minh domain cũng phải được hoàn tất.
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
[Tham gia nhóm thẻ kiểm thử Google Pay](https://groups.google.com/g/googlepay-test-mode-stub-data) để tự động thêm test cards vào wallet của bạn.
</Step>

<Step title="Enable test mode">
Sử dụng test API keys của Dodo Payments.
</Step>

<Step title="Complete test purchase">
Chọn một trong các test cards trong Google Pay để hoàn tất giao dịch.
</Step>
</Steps>

### Amazon Pay, Cash App Pay & RevolutPay

Sử dụng test API keys và làm theo quy trình checkout tiêu chuẩn. Các giao dịch kiểm thử được mô phỏng mà không phát sinh khoản phí thực tế.

Để xem tài liệu Digital Wallets đầy đủ, bao gồm việc xác minh domain cho Apple Pay, hãy xem trang [Digital Wallets](/features/payment-methods/digital-wallets).

## Kiểm thử ACH Direct Debit

Có thể kiểm thử ACH Direct Debit trong Test Mode bằng cách nhập thông tin ngân hàng kiểm thử tại bước thanh toán.

<Steps>
<Step title="Enable test mode">
Sử dụng test API keys của Dodo Payments.
</Step>

<Step title="Set currency and billing address">
Đặt đơn vị tiền tệ thanh toán thành `USD` và quốc gia của địa chỉ thanh toán thành `US`. ACH không được cung cấp ngoài tổ hợp này.
</Step>

<Step title="Use a one-time payment">
ACH không khả dụng trên các trang thanh toán cho subscription, vì vậy hãy kiểm thử với một khoản thanh toán one-time.
</Step>

<Step title="Enter the test bank details">
Nhập một trong các cặp routing number và account number kiểm thử bên dưới, sau đó xác nhận webhook handler của bạn nhận được trạng thái thanh toán cuối cùng — các khoản thanh toán ACH được xác nhận bất đồng bộ thay vì tại bước thanh toán.
</Step>
</Steps>

### Tài khoản ngân hàng kiểm thử

Sử dụng routing number `110000000` với bất kỳ account number nào sau đây:

| Account Number | Hành vi |
| :------------- | :------- |
| `000123456789` | Khoản thanh toán thành công. |
| `000222222227` | Khoản thanh toán thất bại do không đủ tiền. |
| `000111111113` | Khoản thanh toán thất bại vì tài khoản đã bị đóng. |
| `000555555559` | Khoản thanh toán thành công, sau đó phát sinh dispute. |
| `000000000009` | Khoản thanh toán tiếp tục ở trạng thái processing vô thời hạn. |

Để xem danh sách đầy đủ các tài khoản kiểm thử, hãy tham khảo trang [ACH Direct Debit](/features/payment-methods/ach#testing).

## Kiểm thử các phương thức châu Âu

Có thể kiểm thử các phương thức thanh toán châu Âu (iDEAL, Bancontact, EPS, Multibanco) trong Test Mode.

<Steps>
<Step title="Enable test mode">
Sử dụng test API keys của Dodo Payments.
</Step>

<Step title="Set billing address">
Đặt quốc gia của địa chỉ thanh toán tương ứng với phương thức thanh toán:
- `NL` cho iDEAL
- `BE` cho Bancontact
- `AT` cho EPS
- `PT` cho Multibanco
</Step>

<Step title="Set currency">
Các phương thức châu Âu yêu cầu đơn vị tiền tệ EUR.
</Step>

<Step title="Complete test flow">
Thực hiện quy trình xác thực ngân hàng mô phỏng trong môi trường kiểm thử.
</Step>
</Steps>

### IBAN kiểm thử cho SEPA Direct Debit

SEPA Direct Debit yêu cầu EUR và địa chỉ thanh toán thuộc Eurozone. Sử dụng các IBAN kiểm thử này để buộc một kết quả cụ thể:

| Test IBAN | Hành vi |
| :-------- | :------- |
| `DE89370400440532013000` | Khoản thanh toán thành công. |
| `DE62370400440532013001` | Khoản thanh toán thất bại. |
| `DE35370400440532013002` | Khoản thanh toán thành công, sau đó ngay lập tức phát sinh dispute. |
| `DE65370400440002222227` | Khoản thanh toán thất bại do không đủ tiền. |

Để xem danh sách đầy đủ các IBAN kiểm thử, bao gồm giá trị theo từng quốc gia, hãy tham khảo trang [Europe](/features/payment-methods/europe#sepa-test-ibans).

Để xem tài liệu đầy đủ về các phương thức thanh toán châu Âu, hãy tham khảo trang [Europe](/features/payment-methods/europe).

## Phương pháp kiểm thử tốt nhất

<AccordionGroup>
<Accordion title="Test all payment scenarios">
Đừng chỉ kiểm thử các khoản thanh toán thành công. Hãy kiểm thử cả trường hợp bị từ chối, hủy và các tình huống đặc biệt như không đủ tiền.
</Accordion>

<Accordion title="Verify webhook handling">
Đảm bảo các webhook endpoints của bạn xử lý chính xác mọi event types, đặc biệt là `payment.succeeded`, `payment.failed` và các subscription events.

Sử dụng [Dodo Payments CLI](/developer-resources/sdks/cli#webhooks) để kiểm thử webhooks trên máy local:
- `dodo wh listen` chuyển tiếp live test webhooks đến local server của bạn
- `dodo wh trigger` gửi mock payload cho tất cả webhook event types được hỗ trợ
</Accordion>

<Accordion title="Test on real devices">
Đối với Apple Pay và Google Pay, hãy kiểm thử trên thiết bị iOS và Android thực tế. Simulator không mô phỏng đầy đủ hành vi của wallet.
</Accordion>

<Accordion title="Test regional methods with correct addresses">
Các phương thức thanh toán theo khu vực (UPI, iDEAL, v.v.) yêu cầu địa chỉ thanh toán tương ứng. Địa chỉ thanh toán tại Hoa Kỳ sẽ không hiển thị iDEAL.
</Accordion>

<Accordion title="Verify minimum amounts">
Các phương thức BNPL yêu cầu giá trị tối thiểu $50.01. Hãy kiểm thử để đảm bảo chúng hiển thị/ẩn chính xác dựa trên tổng giá trị giỏ hàng.
</Accordion>
</AccordionGroup>
