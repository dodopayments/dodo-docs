## Quản lý API Key và xác thực

<Steps>
<Step title="Access API Keys">
Đi tới **Developer → API Keys** trong dashboard để quản lý các key của bạn.
</Step>

<Step title="Generate a New Key">
Chọn **Add API Key**, nhập tên mô tả và cấu hình quyền ghi:

- **Enable write access** (đã chọn): Toàn quyền đọc và ghi cho tất cả thao tác API
- **Enable write access** (chưa chọn): Quyền chỉ đọc - chỉ có thể truy xuất dữ liệu (payments, subscriptions, customers, products). Không thể tạo hoặc sửa đổi tài nguyên.

<Tip>
Bỏ chọn "Enable write access" cho các tích hợp dashboard, công cụ phân tích và mọi hệ thống chỉ cần xem dữ liệu mà không thực hiện thay đổi.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Sao chép key đã tạo ngay lập tức và đảm bảo key được lưu trữ an toàn.
</Step>

<Step title="Authenticate Your API Requests">
Sử dụng API key để xác thực tất cả yêu cầu. Áp dụng định dạng authorization sau:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Không bao giờ để lộ secret API key trong code phía client hoặc repository công khai.
</Warning>
</Step>
</Steps>

## Giới hạn tốc độ

API của chúng tôi sử dụng hệ thống giới hạn tốc độ hai cửa sổ kèm cơ chế bảo vệ burst. Các giới hạn được áp dụng dựa trên phương thức xác thực và cấp độ doanh nghiệp của bạn.

### Giới hạn mặc định (Tier 0)

| Cửa sổ | Giới hạn |
|--------|-------|
| Mỗi giây (Burst) | 40 requests |
| Mỗi phút (Duy trì) | 240 requests |

### Cấp độ doanh nghiệp

Các giới hạn tốc độ cao hơn dành cho những doanh nghiệp có nhu cầu API tăng cao:

| Cấp độ | Burst (mỗi giây) | Duy trì (mỗi phút) |
|------|-------------------|------------------------|
| Tier 0 (Mặc định) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
Liên hệ bộ phận hỗ trợ để nâng cấp doanh nghiệp lên cấp độ giới hạn tốc độ cao hơn.
</Tip>

### Requests không xác thực

Các request không có header xác thực hợp lệ sẽ bị giới hạn theo địa chỉ IP:

| Cửa sổ | Giới hạn |
|--------|-------|
| Mỗi giây (Burst) | 20 requests |
| Mỗi phút (Duy trì) | 100 requests |

### Header giới hạn tốc độ

Theo dõi mức sử dụng của bạn bằng các response header sau:

- `X-RateLimit-Limit` - Số request tối đa được phép
- `X-RateLimit-Remaining` - Số request còn lại trong cửa sổ hiện tại
- `X-RateLimit-Reset` - Thời điểm giới hạn tốc độ được đặt lại

<Note>
Khi vượt quá giới hạn tốc độ, API sẽ trả về response `429 Too Many Requests`. Hãy triển khai exponential backoff trong logic retry.
</Note>
