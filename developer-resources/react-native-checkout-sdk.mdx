`@dodopayments/react-native-checkout` opens Dodo's hosted checkout in
`SFSafariViewController` on iOS and a Chrome Custom Tab on Android, the same
native cores as the standalone [Swift](/developer-resources/ios-checkout-sdk)
and [Kotlin](/developer-resources/android-checkout-sdk) SDKs. It carries no
checkout logic of its own, just a Turbo Module bridge.

Requires the New Architecture, React Native 0.76+, iOS 16+, and Android
`minSdk` 24.

## Installation

<Steps>
<Step title="Install the package">
```sh
npm i @dodopayments/react-native-checkout
```
</Step>
<Step title="Platform setup">
<Tabs>
<Tab title="Android">
Autolinked. Pulls `com.dodopayments:checkout-android` from Maven Central,
no extra step.
</Tab>
<Tab title="iOS">
```sh
cd ios && pod install
```
</Tab>
<Tab title="Expo">
Works with development builds only, not Expo Go. Add the config plugin:

```json app.json
{ "expo": { "plugins": ["@dodopayments/react-native-checkout"] } }
```
</Tab>
</Tabs>
</Step>
<Step title="Register a callback URL scheme">
<Tabs>
<Tab title="Android">
Set your callback scheme as a Gradle manifest placeholder:

```kotlin android/app/build.gradle
android {
    defaultConfig {
        manifestPlaceholders["dodoCallbackScheme"] = "myapp"
    }
}
```
</Tab>
<Tab title="iOS">
Add a URL type for your scheme in `Info.plist`, then forward incoming URLs
from `Linking` into the SDK:

```ts
import { Linking } from 'react-native';
import { DodoCheckout } from '@dodopayments/react-native-checkout';

Linking.addEventListener('url', ({ url }) => DodoCheckout.handleOpenURL(url));
```

<Note>
It's safe to forward every URL here. `handleOpenURL` only acts on URLs
matching your registered `returnUrl` and resolves `false` for anything
else.
</Note>
</Tab>
</Tabs>
</Step>
</Steps>

## Usage

```ts
import { Linking } from 'react-native';
import { DodoCheckout } from '@dodopayments/react-native-checkout';

Linking.addEventListener('url', ({ url }) => DodoCheckout.handleOpenURL(url));

const result = await DodoCheckout.start({
  checkoutUrl,                          // from your backend's checkout session
  returnUrl: 'myapp://checkout/return', // scheme must be registered (see Setup)
  onEvent: (e) => console.log(e.type),  // logging only
});

switch (result.status) {
  case 'succeeded': break;
  case 'failed':    break;
  case 'cancelled': break;
  case 'pending':   break;
  case 'expired':   break;
}
```

## What the Result Means

<Warning>
`result.status` is a UI hint, not proof of payment. Confirm every payment
from your backend, via the `payment.succeeded` / `subscription.active`
webhook.
</Warning>

<ParamField body="status" type="string" required>
One of `succeeded`, `failed`, `cancelled`, `pending`, `expired`.
</ParamField>

<ParamField body="paymentId" type="string | undefined">
Set when the return URL included one. Display it in the UI, don't use it
to grant access. See Verify the Payment below.
</ParamField>

## Errors

`start` rejects with a `CheckoutError` only for misuse or a platform
failure. A cancelled or declined payment is always a result, never a
rejection.

- `INVALID_CHECKOUT_URL`: not a `checkout.dodopayments.com` session URL.
- `INVALID_RETURN_URL`: not a valid absolute URL.
- `ALREADY_IN_PROGRESS`: a checkout is already running.
- `PLATFORM_ERROR`: unexpected platform failure.

## Abandoned Sessions

<Info>
If the app or JS bundle is killed mid-checkout, the JS promise is lost but
the native layer keeps the session. Recover it on next mount.
</Info>

```ts
import { DodoCheckout } from '@dodopayments/react-native-checkout';

const abandoned = await DodoCheckout.getAbandonedSession();
if (abandoned) {
  // reconcile abandoned.sessionId with your backend, then:
  await DodoCheckout.clearAbandonedSession();
}
```
