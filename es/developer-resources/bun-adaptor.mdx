## Instalación

<Steps>
<Step title="Install the package">
Ejecuta el siguiente comando en la raíz de tu proyecto:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
Crea un archivo <code>.env</code> en la raíz de tu proyecto:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
Nunca confirmes tu archivo <code>.env</code> ni tus secretos en el control de versiones.
</Warning>
</Step>
</Steps>

## Ejemplos de controladores de rutas

<Info>
Todos los ejemplos asumen que utilizas el servidor nativo de Bun con <code>Bun.serve()</code>.
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  Utiliza este controlador para integrar el checkout de Dodo Payments en tu servidor Bun. Admite flujos de pago estáticos (GET), dinámicos (POST) y de sesión (POST).
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>
  <CodeGroup>


## Controlador de rutas de checkout

<Info>
Dodo Payments admite tres tipos de flujos de pago para integrar pagos en tu sitio web; este adaptador admite todos los tipos de flujos de pago.
</Info>

- **Enlaces de pago estáticos:** URLs que se pueden compartir al instante para cobrar pagos rápidamente y sin código.
- **Enlaces de pago dinámicos:** Genera enlaces de pago mediante programación con datos personalizados usando la API o los SDK.
- **Sesiones de checkout:** Crea experiencias de checkout seguras y personalizables con carritos de productos preconfigurados y datos del cliente.

### Formato de respuesta
El checkout estático devuelve una respuesta JSON con la URL de checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envía los parámetros como un cuerpo JSON en una solicitud POST.
- Admite pagos únicos y recurrentes.
- Para consultar la lista completa de campos compatibles del cuerpo POST, consulta:
  - [Cuerpo de la solicitud para un producto de pago único](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Cuerpo de la solicitud para un producto de suscripción](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Formato de respuesta
El checkout dinámico devuelve una respuesta JSON con la URL de checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Las sesiones de checkout proporcionan una experiencia de checkout alojada más segura que gestiona el flujo de pago completo, tanto para compras únicas como para suscripciones, con control total de personalización.

Consulta la [guía de integración de Checkout Sessions](https://docs.dodopayments.com/developer-resources/checkout-session) para obtener más información y consultar la lista completa de campos compatibles.

### Formato de respuesta
Las sesiones de checkout devuelven una respuesta JSON con la URL de checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Controlador de rutas de Customer Portal

El controlador de rutas de Customer Portal te permite integrar sin problemas el Customer Portal de Dodo Payments en tu aplicación de servidor Bun.

### Query Parameters
<ParamField query="customer_id" type="string" required>
ID del cliente para la sesión del portal (por ejemplo, <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Si se establece en <code>true</code>, envía al cliente un correo electrónico con el enlace al portal.
</ParamField>

<Warning>
Devuelve 400 si falta <code>customer_id</code>.
</Warning>

## Controlador de rutas de Webhook

- **Método:** Solo se admiten solicitudes POST. Los demás métodos devuelven 405.
- **Verificación de firma:** Verifica la firma del webhook mediante <code>webhookKey</code>. Devuelve 401 si la verificación falla.
- **Validación del payload:** Se valida con Zod. Devuelve 400 para payloads no válidos.
- **Gestión de errores:**
  - 401: Firma no válida
  - 400: Payload no válido
  - 500: Error interno durante la verificación
- **Enrutamiento de eventos:** Llama al controlador de eventos adecuado según el tipo de payload.

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

  returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
```
