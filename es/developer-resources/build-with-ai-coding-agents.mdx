El Dodo Agent Plugin conecta dos servidores MCP y diecisiete skills de integración con tu agente de programación basado en IA en una sola instalación. Funciona con **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** y **OpenCode**. **Gemini CLI** obtiene únicamente los dos servidores MCP. Los servidores MCP y la CLI de skills funcionan con cualquier cliente compatible con MCP.

El plugin sigue la especificación [Agent Plugins 1.0.0](https://agent-plugins.org/specification), por lo que los clientes con compatibilidad nativa lo cargan directamente desde la raíz `plugin.json` y `mcp.json`. Los clientes anteriores a la especificación cargan el mismo contenido mediante manifiestos de compatibilidad generados.

<Info>
**Tres primitivas, un plugin.** El Agent Plugin incluye todo lo que necesitas:
- **Servidor MCP de API**: acceso en tiempo real a pagos, suscripciones, clientes, productos, reembolsos, licencias y uso. Se autentica mediante OAuth del navegador (no se necesitan claves locales).
- **Servidor MCP de conocimiento**: búsqueda semántica en toda la documentación de Dodo Payments. No se necesitan credenciales.
- **Diecisiete skills de agente**: hojas de referencia que tu agente carga bajo demanda para checkout, suscripciones, webhooks, facturación basada en uso y en créditos, claves de licencia, catálogo de productos, descuentos, precios localizados, checkout móvil, reembolsos y disputas, gestión de clientes, adaptadores de frameworks, BillingSDK, Better Auth, pruebas y puesta en producción, y buenas prácticas.
</Info>

## Instalar el plugin

Elige tu agente de programación a continuación. Cada instalación añade ambos servidores MCP; todos, excepto Gemini CLI, también añaden las diecisiete skills.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Instálalo desde el marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

El servidor MCP de API usa OAuth del navegador de forma predeterminada; no se necesitan claves durante la instalación. La primera vez que tu agente llame a una herramienta de Dodo, se te pedirá que inicies sesión.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Código fuente, opciones de configuración e instrucciones para el desarrollo local
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex instala plugins en dos pasos: registra el marketplace desde tu shell y, después, instala el plugin desde la TUI de Codex.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Abre Codex y ejecuta el comando slash `/plugins`:

```bash
codex
```

Después, escribe `/plugins`, cambia al marketplace de **Dodo Payments**, selecciona el plugin **dodopayments** y elige **Install plugin**.
</Step>
</Steps>

Ambos servidores MCP y las diecisiete skills se registran automáticamente una vez instalado el plugin.

<Note>
Codex CLI no tiene un subcomando `codex plugin install`; la instalación del plugin siempre se realiza mediante el flujo `/plugins` dentro de la TUI. Consulta la [documentación oficial de plugins de Codex](https://developers.openai.com/codex/plugins).
</Note>

Si ya habías añadido el marketplace y el plugin no aparece en `/plugins`, actualízalo:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Instalación manual: clona el repositorio en el directorio de plugins local de Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Reinicia Cursor. El plugin carga las skills desde `skills/` y los servidores MCP desde `.mcp.json`, según lo declarado en `.cursor-plugin/plugin.json`.

<Info>
Las versiones recientes de Cursor también reconocen directamente Agent Plugins 1.0.0 y aceptan `.cursor-plugin/marketplace.json` o `.claude-plugin/marketplace.json` como fuente del marketplace. Este plugin incluye `.claude-plugin/marketplace.json`; usa esa ruta. El `.cursor-plugin/plugin.json` generado se conserva para versiones anteriores.
</Info>

<Warning>
Las versiones anteriores a la 0.5.0 incluían `skills/` como enlaces simbólicos a un submódulo de git, por lo que este clon producía un plugin **sin skills funcionales**. Ahora las skills se incluyen como archivos reales. Si instalaste una versión anterior, elimina el directorio y vuelve a clonar.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode se distribuye mediante npm. Añade el plugin a tu `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Reinicia OpenCode. Ambos servidores MCP (`dodopayments-api`, `dodo-knowledge`) se registran automáticamente mediante el hook de configuración del plugin. No se necesita ningún bloque `mcp` manual.

**Las skills necesitan una línea adicional.** OpenCode no busca skills en los paquetes instalados, así que debes indicarle el directorio `skills/` del paquete:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

Las entradas relativas de `skills.paths` se resuelven respecto al **directorio del proyecto**, por lo que el paquete debe existir en el `node_modules` de ese proyecto; la caché de plugins propia de OpenCode se encuentra en otra ubicación. También funciona una ruta absoluta y evita el requisito de instalación local.

<Warning>
Una ruta de skills inexistente se ignora **silenciosamente**. Verifica en lugar de darlo por hecho:

```bash
opencode run "List every skill available to you by name."
```

Deberías ver las diecisiete. Las versiones anteriores a la 0.5.0 documentaban estas skills como detectadas automáticamente; no era así, por lo que los usuarios de OpenCode tenían servidores MCP, pero no skills.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Clona el repositorio en cualquier ubicación y regístralo:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Abre la vista Chat, ve a **Plugins** y añade la carpeta clonada. También puedes registrarla directamente en `settings.json`:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

La clave es una ruta y el valor la habilita. Funcionan tanto las rutas absolutas como `~/`; una ruta relativa se resuelve respecto a cada carpeta del workspace. La configuración se lee en tiempo real, por lo que una ventana en ejecución la adopta sin reiniciarse. Las skills se cargan desde `skills/` y ambos servidores MCP desde `.mcp.json`.

<Note>
`chat.pluginLocations` está marcado como **experimental** y es una configuración *restringida*, por lo que el workspace debe ser de confianza para que se aplique. La compatibilidad general con plugins de agentes es una función preliminar controlada por `chat.plugins.enabled`, que está **activada de forma predeterminada**; solo tienes que establecerla si tu organización la deshabilita mediante una política.
</Note>

<Info>
VS Code no utiliza `$schema` de Agent Plugins como clave. Su cargador busca primero `.plugin/plugin.json`, después `.claude-plugin/plugin.json` y luego una raíz `plugin.json`; además, establece MCP en `.mcp.json` en lugar de `mcp.json`. Como este repositorio incluye un `.claude-plugin/plugin.json` generado, VS Code lo carga mediante esa rama de compatibilidad y obtiene el puente `mcp-remote` en lugar de los transportes nativos de `mcp.json`. Todo funciona; la ruta es diferente.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro lee el manifiesto de Agent Plugins de forma nativa y lo carga como un Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
En Kiro, abre el panel Powers: el icono de Ghosty con el rayo.
</Step>

<Step title="Import the folder">
Elige **Add Custom Power → Import power from a folder**, selecciona el directorio clonado (el que contiene `plugin.json`) y haz clic en **Install**.
</Step>
</Steps>

Las skills se cargan desde `skills/`, los servidores MCP desde `mcp.json` y la presentación específica de Kiro procede del espacio de nombres de extensión `dev.kiro` en `plugin.json`.

<Note>
En los plugins con formato Agent Plugins, Kiro gestiona internamente los servidores MCP; **no** se escriben en tu `~/.kiro/settings/mcp.json` de nivel de usuario, así que no esperes encontrarlos allí. Kiro también puede instalar un Power directamente desde una URL de GitHub; consulta la [documentación de instalación de Kiro](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI no tiene una primitiva de agent-skill, por lo que **solo están disponibles los dos servidores MCP**; las diecisiete skills no lo están. `dodo-knowledge` sigue cubriendo buena parte de lo que ofrecen las skills y se mantiene actualizado automáticamente.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Reinicia Gemini CLI. `gemini-extension.json` en la raíz del repositorio es el manifiesto.
</Accordion>
</AccordionGroup>

¿Usas otro agente? Las guías de [MCP Server](/developer-resources/mcp-server) y [Agent Skills](/developer-resources/agent-skills) abarcan Claude Desktop, Windsurf, Cline, Zed y cualquier cliente compatible con MCP.
</Info>

## Qué obtienes

Una vez instalado el plugin, tu agente tiene acceso a dos servidores MCP y diecisiete skills.

### Servidores MCP

| Servidor | Propósito | Autenticación |
|--------|---------|------|
| `dodopayments-api` | Acceso a la API en tiempo real: pagos, suscripciones, clientes, productos, reembolsos, licencias y uso | OAuth (navegador) |
| `dodo-knowledge` | Búsqueda semántica en toda la documentación de Dodo Payments | Ninguna |

Ambos servidores utilizan Streamable HTTP. El `mcp.json` canónico los declara de forma nativa (`type: "streamable-http"`), que es lo que usan clientes nativos de la especificación como Codex CLI y Kiro. El manifiesto de compatibilidad generado `.mcp.json` conecta los mismos dos endpoints mediante `mcp-remote`, de modo que también se ejecutan en clientes que no pueden conectarse directamente a Streamable HTTP: Claude Code, VS Code y Cursor mediante la instalación por clonación de git documentada anteriormente, cuyo `.cursor-plugin/plugin.json` apunta a `.mcp.json`.

### Skills de agente

| Skill | Descripción |
|-------|-------------|
| `dodo-best-practices` | Configuración del SDK, entornos, claves de API y la arquitectura canónica de checkout a webhook |
| `framework-adapters` | Handlers de rutas oficiales de `@dodopayments/*` para Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun y Convex |
| `testing-and-go-live` | Modo de prueba, métodos de pago de prueba, pruebas de webhooks y checklist de lanzamiento a producción |
| `checkout-integration` | Checkout Sessions, enlaces de pago y checkout superpuesto o integrado |
| `subscription-integration` | Ciclo de vida de suscripciones, pruebas, cambios de plan, prorrateo y cargos bajo demanda |
| `mobile-checkout` | Checkout integrado en la aplicación para React Native, Flutter, iOS y Android |
| `webhook-integration` | Recepción y verificación de webhooks mediante la especificación Standard Webhooks |
| `credit-based-billing` | Entitlements de crédito, saldos, ledger, rollover, exceso de uso y deducción basada en medidores |
| `usage-based-billing` | Medidores, ingesta de eventos, agregación y precios por unidad |
| `license-keys` | Activación y validación de claves de licencia y gestión de instancias |
| `product-catalog-management` | Productos, precios, add-ons, colecciones, imágenes y entrega de productos digitales |
| `discounts-and-promotions` | Códigos de descuento, reglas de elegibilidad, acumulación y límites por ciclo de suscripción |
| `localized-pricing` | Precios localizados, Adaptive Currency y paridad del poder adquisitivo |
| `customer-management` | Clientes, portal de autoservicio, métodos de pago guardados y wallets |
| `refunds-and-disputes` | Emisión de reembolsos, gestión de disputas y contracargos, y conciliación del acceso |
| `billing-sdk` | Componentes React de BillingSDK para tablas de precios y UI de facturación |
| `better-auth-integration` | Plugin `@dodopayments/better-auth` para sincronización de clientes, checkout y acceso al portal |

Las skills se cargan automáticamente: tu agente elige la adecuada cuando detecta una tarea relevante. Consulta la [documentación de Agent Skills](/developer-resources/agent-skills) para ver la lista completa y la instalación individual.

### Prueba primero este prompt

Una vez activo el plugin, prueba:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Tu agente cargará la skill `webhook-integration`, usará el MCP `dodo-knowledge` para obtener las formas de payload más recientes y escribirá un handler con verificación de firma siguiendo la especificación Standard Webhooks.

## Compatibilidad con clientes

### Clientes con instalación de Agent Plugin

Una instalación conecta ambos servidores MCP, además de las skills en todos los clientes que cuentan con una primitiva de skills.

| Agente | Instalación | Skills | Servidores MCP |
|-------|---------|-------:|------------:|
| **Claude Code** | comando del marketplace | 17 | 2 |
| **Codex CLI** | comando del marketplace | 17 | 2 |
| **Cursor** | clonación de git | 17 | 2 |
| **VS Code / GitHub Copilot** | clonación de git | 17 | 2 |
| **Kiro** | clonación de git | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | clonación de git | 0 | 2 |

- **OpenCode** necesita una entrada `skills.paths` adicional antes de cargar sus diecisiete skills; consulta la sección de instalación anterior.
- **Gemini CLI** no tiene una primitiva de agent-skill, por lo que las skills no están disponibles allí por diseño.

### Otros clientes compatibles con MCP

Estos no tienen instalación de Agent Plugin. Configura manualmente los dos servidores MCP y añade skills mediante la Skills CLI cuando sea compatible.

| Agente | Servidores MCP | Skills |
|-------|-------------|--------|
| Claude Desktop | [Guía de MCP Server](/developer-resources/mcp-server) | no compatible |
| Windsurf | [Guía de MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / otros | [Guía de MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## Seguridad y buenas prácticas

<Warning>
**Nunca hagas commit de claves de API de producción.** Usa el [modo de prueba](/miscellaneous/test-mode-vs-live-mode) durante el desarrollo. El Agent Plugin usa OAuth del navegador de forma predeterminada; cambia a claves de API locales únicamente si tu flujo de trabajo lo requiere.
</Warning>

- **Usa primero el modo de prueba.** Pon tu integración en sandbox con claves `dodo_test_...` antes de pasar a producción. Consulta [Modo de prueba frente a modo activo](/miscellaneous/test-mode-vs-live-mode).
- **OAuth es el valor predeterminado.** El Agent Plugin se autentica mediante OAuth del navegador (sin secretos locales). Usa el modo de clave de API solo si lo necesitas; consulta la sección Configurar más abajo.
- **Revisa el código generado por el agente.** Verifica siempre que los handlers de webhooks incluyan verificación de firma conforme a la [especificación Standard Webhooks](https://standardwebhooks.com/).

## Configurar con una clave de API

De forma predeterminada, el Agent Plugin usa el servidor MCP remoto con OAuth del navegador; no se necesitan credenciales locales. Si tu flujo de trabajo requiere una clave de API local (por ejemplo, entornos de CI o servidores sin interfaz), puedes cambiar al modo stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Abre `/plugins` en Claude Code, selecciona **Dodo Payments** y elige **Configure options**. Completa lo siguiente:

- `dodo_api_key`: tu clave `dodo_test_...` o `dodo_live_...`
- `dodo_webhook_key`: tu secreto de firma de webhook
- `dodo_environment`: `test_mode` o `live_mode`

Después, edita `.mcp.json` para apuntar `dodopayments-api` al servidor stdio local:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Ejecuta `/reload-plugins` para aplicar los cambios a tu sesión actual.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Declara `dodopayments-api` tú mismo en `opencode.json`; tu entrada prevalece sobre el servidor remoto predeterminado del plugin:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Reinicia OpenCode para aplicar los cambios.
</Accordion>
</AccordionGroup>
