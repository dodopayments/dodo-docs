<Info>
**Session Validity**: Checkout sessions are valid for 24 hours by default. If you pass `confirm=true` in your request, the session will only be valid for 15 minutes.
</Info>

<Warning>
**Single-Use Links**: The `checkout_url` returned by the API is not reusable and expires within 24 hours (or 15 minutes when `confirm=true`). It is intended for a single customer to complete one payment. Generate a fresh checkout session for each customer and each payment attempt rather than sharing or reusing a link.
</Warning>

## Creating Your First Checkout Session

<Tabs>
<Tab title="Node.js SDK">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'pdt_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

### API Response

All methods above return the same response structure:

```json
{
  "session_id": "cks_Gi6KGJ2zFJo9rq9Ukifwa",
  "checkout_url": "https://test.checkout.dodopayments.com/session/cks_Gi6KGJ2zFJo9rq9Ukifwa"
}
```

Solo se garantiza que esté presente `session_id`. En dos casos se devuelven campos adicionales o menos campos:

- **Se proporcionó `payment_method_id`**: el cargo se procesa de inmediato y `checkout_url` es `null`. Usa en su lugar el `payment_id` devuelto.
- **`confirm: true` creó el pago al crear la sesión**: la respuesta también incluye `payment_id`, `client_secret` e `publishable_key` para usarlos con el SDK de checkout de Dodo Payments.

<Note>
El `checkout_url` generado es de un solo uso y caduca en un plazo de 24 horas. No lo guardes en caché ni lo reutilices entre clientes o intentos de pago; crea una nueva sesión de checkout cada vez que necesites un enlace nuevo.
</Note>

<Steps>
<Step title="Get the checkout URL">
Extrae `checkout_url` de la respuesta de la API.
</Step>

<Step title="Redirect your customer">
Dirige al cliente a la URL de checkout para completar su compra.

```javascript
// Redirect immediately
window.location.href = session.checkout_url;

// Or open in new window
window.open(session.checkout_url, '_blank');
```

<Tip>
**Opciones de integración alternativas**: En lugar de redirigir, puedes insertar el checkout directamente en tu página mediante [Overlay Checkout](/developer-resources/overlay-checkout) (superposición modal) o [Inline Checkout](/developer-resources/inline-checkout) (completamente integrado). En una aplicación móvil nativa, proporciona la misma URL a los [SDK de Mobile Checkout](/developer-resources/mobile-integration) para Android, iOS, React Native o Flutter. Todos consumen la misma URL de sesión de checkout.
</Tip>
</Step>

<Step title="Handle the return">
Después del pago, los clientes son redirigidos a tu `return_url` con parámetros de consulta que incluyen el ID del pago o la suscripción, el estado, el correo electrónico del cliente y cualquier clave de licencia. Consulta la [documentación de parámetros de `return_url`](#request-body) para ver la lista completa.
</Step>
</Steps>

### Campos obligatorios

<ParamField body="product_cart" type="array" required>
Matriz de productos que se incluirán en la sesión de checkout. Cada producto debe tener un `product_id` válido de tu panel de Dodo Payments.

<Tip>
**Checkout mixto**: Puedes combinar productos de pago único y productos de suscripción en la misma sesión de checkout. Esto permite casos de uso como tarifas de configuración con suscripciones, paquetes de hardware con SaaS y mucho más.
</Tip>

<Expandable title="Product Cart Item Properties">
<ParamField body="product_id" type="string" required>
El identificador único del producto de tu panel de Dodo Payments.

**Ejemplo:** `"pdt_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
Cantidad del producto.

**Ejemplo:** `1` para un solo artículo, `3` para varias unidades
</ParamField>

<ParamField body="addons" type="array">
Matriz de complementos que se adjuntarán al producto. Solo es válido si el producto es una suscripción.

<Expandable title="Addon item properties">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
Importe que paga el cliente si pay_what_you_want está habilitado. Si está deshabilitado, este campo se ignorará.

**Formato**: Se representa en la denominación más pequeña de la moneda (por ejemplo, centavos para USD). Para cobrar $1.00, pasa `100`.
</ParamField>

<ParamField body="credit_entitlements" type="array">
Anulaciones por sesión de checkout para los derechos de crédito ya asociados a este producto. Úsalo para conceder una cantidad diferente de créditos en esta sesión; por ejemplo, un paquete promocional que concede 1.000 créditos de API en lugar de los 500 predeterminados del producto, sin crear un producto independiente.

<Info>
Cada `credit_entitlement_id` ya debe estar asociado al producto. Este campo solo anula el `credits_amount` concedido cuando se completa esta sesión; la configuración de derechos de crédito a nivel de producto (caducidad, renovación, etc.) sigue aplicándose.
</Info>

<Expandable title="Credit entitlement override properties">

ID del derecho de crédito que se anulará. Ya debe estar asociado al producto.
</ParamField>

<ParamField body="credits_amount" type="string" required>
Cantidad de créditos que se concederán para esta sesión de checkout, anulando el `credits_amount` a nivel de producto. Debe ser mayor que cero.
</ParamField>

<Accordion title="Session Management">

<ParamField body="return_url" type="string">
URL a la que se redirigirá a los clientes después de completar el pago. Dodo Payments añade los siguientes parámetros de consulta a tu URL durante la redirección:

| Parámetro | Tipo | Condición |
|-----------|------|-----------|
| `payment_id` | `string` | Siempre presente para pagos únicos |
| `subscription_id` | `string` | Siempre presente para pagos de suscripción |
| `status` | `string` | Siempre presente |
| `license_key` | `string` | Presente si el producto tiene habilitadas las claves de licencia. Separado por comas si hay varias claves |
| `email` | `string` | Presente si el cliente tiene un correo electrónico registrado |

**URL de redirección de ejemplo:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
Usa los parámetros de consulta `license_key` y `email` para mostrar las claves de licencia o enviar inmediatamente una confirmación en tu página de retorno, sin necesidad de realizar otra llamada a la API.
</Tip>
</ParamField>

<ParamField body="cancel_url" type="string">
URL a la que se redirigirá a los clientes cuando hagan clic en el botón de volver o cancelen la sesión de checkout. Si no se proporciona, el botón de volver no se mostrará.

<Tip>
Establece un `cancel_url` para ofrecer a los clientes una forma clara de volver a tu sitio sin completar la compra. Esto mejora la experiencia de checkout y reduce la fricción.
</Tip>
</ParamField>

<ParamField body="confirm" type="boolean" default="false">
Si es true, finaliza inmediatamente todos los detalles de la sesión. La API generará un error si faltan datos obligatorios.
</ParamField>

<ParamField body="discount_codes" type="array">
Aplica uno o más códigos de descuento acumulables a la sesión de checkout. Los códigos se aplican **en el orden del array** (el primer código reduce el precio inicial, el segundo reduce el precio ya rebajado, y así sucesivamente), hasta un máximo de **20** códigos por sesión. Cuando [Purchasing Power Parity](/features/purchasing-power-parity) está habilitado, el precio inicial es el importe ajustado por PPP, no el precio base.

```typescript
discount_codes: ['WELCOME10', 'BLACKFRIDAY20']
```

<Info>
El campo singular `discount_code` que aparece a continuación está **obsoleto**, pero sigue siendo totalmente compatible; las integraciones existentes continúan funcionando sin cambios. No se puede combinar con `discount_codes` en la misma solicitud. Migra a `discount_codes` cuando te resulte conveniente para aprovechar la acumulación.
</Info>
</ParamField>

<ParamField body="discount_code" type="string" deprecated>
**Obsoleto**; usa `discount_codes` para las integraciones nuevas. Este campo sigue funcionando por compatibilidad con versiones anteriores, pero no se puede combinar con `discount_codes` en la misma solicitud.
</ParamField>

<ParamField body="metadata" type="object">
Pares clave-valor personalizados para almacenar información adicional sobre la sesión.
</ParamField>

<ParamField body="force_3ds" type="boolean">
Anula el comportamiento de 3DS predeterminado del merchant para esta sesión.
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
Habilita el modo de recopilación mínima de direcciones. Cuando está habilitado, el checkout solo recopila:
- **País**: Siempre obligatorio para determinar los impuestos
- **Código ZIP o postal**: Solo en regiones donde sea necesario para calcular el impuesto sobre las ventas, el IVA o el GST

Esto reduce considerablemente la fricción del checkout al eliminar campos de formulario innecesarios.

<Tip>
Habilita la dirección mínima para completar el checkout más rápido. La recopilación de la dirección completa sigue disponible para las empresas que necesitan todos los datos de facturación.
</Tip>
</ParamField>

<ParamField body="payment_method_id" type="string">
Método de pago guardado perteneciente al cliente asociado. Requiere `confirm: true` y un `customer.customer_id` existente. Cuando se establece, el cargo se procesa de inmediato y `checkout_url` se devuelve como `null`; usa en su lugar el `payment_id` devuelto.
</ParamField>

<ParamField body="short_link" type="boolean" default="false">
Si es true, devuelve una URL de checkout abreviada en lugar de la URL de sesión completa.
</ParamField>

<ParamField body="product_collection_id" type="string">
ID de la colección de productos para el flujo de checkout basado en colecciones.
</ParamField>

<ParamField body="tax_id" type="string">
ID fiscal del cliente (por ejemplo, un número de IVA). Requiere `billing_address` con un `country`.
</ParamField>

<ParamField body="customer_business_name" type="string">
Nombre comercial o legal opcional asociado al ID fiscal. Cuando se proporciona junto con un `tax_id` válido, se muestra en la factura en lugar del nombre personal del cliente.
</ParamField>

<ParamField body="mandate_min_amount_inr_paise" type="integer">
Anula el límite mínimo del mandato a nivel de merchant (en paise de INR) para los mandatos electrónicos en INR de tarjetas indias.
</ParamField>

### 11. Uso de métodos de pago existentes para checkout instantáneo

Usa el método de pago guardado de un cliente para crear una sesión de checkout que se procese de inmediato, omitiendo la recopilación del método de pago:

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'pdt_premium_plan',
      quantity: 1
    }
  ],
  customer: {
    customer_id: 'cus_123'  // Required when using payment_method_id
  },
  payment_method_id: 'pm_abc123',  // Use customer's saved payment method
  confirm: true,  // Required when using payment_method_id
  return_url: 'https://yourapp.com/success'
});
```

<Warning>
Al usar `payment_method_id`, `confirm` debe establecerse en `true` y debe proporcionarse un `customer_id` existente. El método de pago se validará para comprobar su elegibilidad con la moneda del pago. Como el cargo se procesa de inmediato, `checkout_url` se devuelve como `null`; usa en su lugar el `payment_id` devuelto.
</Warning>

<Info>
El método de pago debe pertenecer al cliente y ser compatible con la moneda del pago. Esto permite realizar compras con un solo clic para los clientes recurrentes.
</Info>

## Previsualizar sesiones de checkout

Antes de crear una sesión de checkout, puedes previsualizar el desglose de precios, incluidos impuestos, descuentos y totales. Esto resulta útil para mostrar precios precisos a los clientes antes de que procedan al checkout.

<Note>
El `current_breakup.subtotal` mostrado en la vista previa ya refleja [Purchasing Power Parity](/features/purchasing-power-parity) y [Charm Pricing](/features/charm-pricing) cuando se aplican al producto.
</Note>

<Note>
Cuando el carrito contiene un producto de suscripción, la respuesta de vista previa también devuelve un `next_billing_date`: una vista previa de la próxima fecha de facturación, para que puedas mostrarla antes de crear la suscripción. Se calcula en relación con el momento actual: `now + trial period` cuando se aplica un período de prueba; de lo contrario, `now + one payment frequency`. El campo se omite en los carritos que solo contienen compras únicas. Se trata de una estimación basada en el momento de la vista previa; el `next_billing_date` definitivo se establece cuando se activa la suscripción.
</Note>

<Note>

Usa `current_breakup` para consultar el total con impuestos que se debe pagar hoy.
</Note>

## Migración de Dynamic Links a las sesiones de checkout

### Diferencias principales
Anteriormente, al crear un enlace de pago con Dynamic Links, era obligatorio proporcionar la dirección de facturación completa del cliente.

Con las sesiones de checkout, esto ya no es necesario. Puedes enviar simplemente la información de la que dispongas y nosotros nos encargaremos del resto. Por ejemplo:

- Si solo conoces el país de facturación del cliente, proporciona únicamente ese dato.
- El flujo de checkout recopilará automáticamente la información que falte antes de dirigir al cliente a la página de pago.
- Por otro lado, si ya tienes toda la información necesaria y quieres ir directamente a la página de pago, puedes enviar el conjunto de datos completo e incluir `confirm=true` en el cuerpo de la solicitud.

### Proceso de migración

Migrar de Dynamic Links a las sesiones de checkout es sencillo:

<Steps>
<Step title="Update your integration">
Actualiza tu integración para usar el nuevo método de API o SDK.
</Step>

<Step title="Adjust request payload">
Ajusta el payload de la solicitud según el formato de las sesiones de checkout.
</Step>

<Step title="That's it!">
Sí. No necesitas realizar ningún procesamiento adicional ni pasos especiales de migración.
</Step>
</Steps>
