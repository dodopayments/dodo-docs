## Eventos de Recuperación de Carritos Abandonados

Los siguientes eventos de webhook rastrean el ciclo de vida de la recuperación de carritos abandonados:

| Evento | Descripción |
|-------|-------------|
| `abandoned_checkout.detected` | Se ha detectado un pago abandonado. Enviado cuando un pago se identifica como abandonado (fallido o incompleto) y comienza el flujo de trabajo de recuperación. |
| `abandoned_checkout.recovered` | El cliente completó el pago a través del enlace de recuperación. El campo `recovered_payment_id` contiene el ID de pago exitoso. |

### Campos de Carga Útil de Pago Abandonado

<ParamField body="payment_id" type="string" required>
El pago original que fue abandonado. Úselo para buscar detalles de producto, cantidad y moneda.
</ParamField>

<ParamField body="brand_id" type="string" required>
La marca a la que pertenece este checkout abandonado.
</ParamField>

<ParamField body="customer_id" type="string" required>
El cliente que abandonó el checkout.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
Por qué se abandonó el checkout. Uno de los siguientes:
- `payment_failed` — El cliente intentó realizar el pago, pero falló
- `checkout_incomplete` — El cliente visitó el checkout, pero nunca intentó realizar el pago
</ParamField>

<ParamField body="status" type="string" required>
Estado actual del ciclo de vida de este intento de recuperación. Uno de los siguientes:
- `abandoned` — Detectado; aún no se han enviado emails
- `recovering` — Se ha enviado al menos un email de recuperación
- `recovered` — El cliente completó el pago
- `exhausted` — Se enviaron todos los emails o se encontró un checkout más reciente
- `opted_out` — El cliente canceló su suscripción
</ParamField>

<ParamField body="abandoned_at" type="string" required>
Marca de tiempo ISO 8601 de cuándo se detectó que el checkout había sido abandonado.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
El ID del pago de recuperación exitoso. `null` hasta que se recupere el checkout.
</ParamField>

### Ejemplo: gestión de webhooks de ACR

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Eventos de dunning

Los siguientes eventos de webhook realizan un seguimiento del ciclo de vida de dunning de la suscripción:

| Evento | Descripción |
|-------|-------------|
| `dunning.started` | Se creó un intento de dunning para una suscripción que pasó a `on_hold` o que el cliente canceló. |
| `dunning.recovered` | El cliente actualizó su método de pago y el pago resultante se realizó correctamente. El campo `payment_id` contiene el ID del pago exitoso. |

### Campos del payload del intento de dunning

<ParamField body="subscription_id" type="string" required>
La suscripción que activó el intento de dunning.
</ParamField>

<ParamField body="brand_id" type="string" required>
La marca a la que pertenece este intento de dunning.
</ParamField>

<ParamField body="customer_id" type="string" required>
El cliente propietario de la suscripción.
</ParamField>

<ParamField body="trigger_state" type="string" required>
El estado de la suscripción que desencadenó el proceso de dunning. Uno de:
- `on_hold` — Renovaciones detenidas debido a un fallo en el pago
- `cancelled` — El cliente canceló desde el portal del cliente
</ParamField>

<ParamField body="status" type="string" required>
Estado actual del ciclo de vida de este intento de dunning. Uno de los siguientes:
- `recovering` — Se están enviando emails de dunning
- `recovered` — El cliente actualizó el método de pago y el pago se realizó correctamente
- `exhausted` — Se enviaron todos los emails o cambió el estado de la suscripción
</ParamField>

<ParamField body="created_at" type="string" required>
Marca de tiempo ISO 8601 de cuándo se creó el intento de dunning.
</ParamField>

<ParamField body="payment_id" type="string | null">
El ID del pago de recuperación exitoso. `null` mientras se realiza la recuperación.
</ParamField>

### Ejemplo: gestión de webhooks de dunning

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
Suscríbete a `dunning.started` y `dunning.recovered` para realizar un seguimiento de todo el ciclo de vida de dunning. Usa `dunning.started` para pausar los periodos de gracia o marcar las suscripciones en riesgo en tu sistema.
</Tip>
