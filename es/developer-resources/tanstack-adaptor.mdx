## Instalación

<Steps>
<Step title="Install the package">
Ejecuta el siguiente comando en la raíz de tu proyecto:

```bash
npm install @dodopayments/tanstack
```

</Step>
<Step title="Set up environment variables">
Crea un archivo <code>.env</code> en la raíz de tu proyecto:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_RETURN_URL=your-return-url
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
```

<Warning>
Nunca confirmes tu archivo <code>.env</code> ni tus secretos en el control de versiones.
</Warning>
</Step>
</Steps>

    ```typescript Tanstack Route Handler expandable
    // src/routes/api/checkout.ts
    import { Checkout } from "@dodopayments/tanstack";
    import { createServerFileRoute } from "@tanstack/react-start/server";

    export const ServerRoute = createServerFileRoute("/api/checkout")
    .methods({
        GET: async ({ request }) => {
        return Checkout({
            bearerToken: process.env.DODO_PAYMENTS_API_KEY,
            returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
            environment: process.env.DODO_PAYMENTS_ENVIRONMENT,

            bearerToken: process.env.DODO_PAYMENTS_API_KEY,

            environment: process.env.DODO_PAYMENTS_ENVIRONMENT,

        }
    })
  
    ```

## Route Handler de checkout

<Info>
Dodo Payments admite tres tipos de flujos de pago para integrar pagos en tu sitio web; este adaptor admite todos los tipos de flujos de pago.
</Info>

- **Enlaces de pago estáticos:** URLs que se pueden compartir al instante para recopilar pagos rápidamente y sin código.
- **Enlaces de pago dinámicos:** Genera enlaces de pago mediante programación con datos personalizados usando la API o los SDK.
- **Sesiones de checkout:** Crea experiencias de checkout seguras y personalizables con carritos de productos y datos del cliente preconfigurados.

### Formato de respuesta
El checkout estático devuelve una respuesta JSON con la URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envía los parámetros como un cuerpo JSON en una solicitud POST.
- Admite pagos únicos y recurrentes.
- Para consultar la lista completa de campos compatibles del cuerpo POST, consulta:
  - [Cuerpo de la solicitud para un producto de pago único](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Cuerpo de la solicitud para un producto de suscripción](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Formato de respuesta
El checkout dinámico devuelve una respuesta JSON con la URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Las sesiones de checkout ofrecen una experiencia de checkout alojada más segura que gestiona el flujo de pago completo, tanto para compras únicas como para suscripciones, con control total de personalización.

Consulta la [guía de integración de Checkout Sessions](https://docs.dodopayments.com/developer-resources/checkout-session) para obtener más información y consultar la lista completa de campos compatibles.

### Formato de respuesta
Las sesiones de checkout devuelven una respuesta JSON con la URL del checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Customer Portal Route Handler

El Route Handler de Customer Portal te permite integrar sin problemas el Customer Portal de Dodo Payments en tu aplicación Tanstack.

### Query Parameters
<ParamField query="customer_id" type="string" required>
El ID del cliente para la sesión del portal (por ejemplo, <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Si se establece en <code>true</code>, envía un correo electrónico al cliente con el enlace al portal.
</ParamField>

<Warning>
Devuelve 400 si falta <code>customer_id</code>.
</Warning>

## Webhook Route Handler

- **Método:** Solo se admiten solicitudes POST. Los demás métodos devuelven 405.
- **Verificación de firma:** Verifica la firma del webhook usando <code>webhookKey</code>. Devuelve 401 si la verificación falla.
- **Validación del payload:** Se valida con Zod. Devuelve 400 para payloads no válidos.
- **Gestión de errores:**
  - 401: Firma no válida
  - 400: Payload no válido
  - 500: Error interno durante la verificación
- **Enrutamiento de eventos:** Llama al event handler correspondiente según el tipo de payload.
