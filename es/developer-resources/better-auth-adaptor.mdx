# Descripción general

El <b>Adaptador Better Auth</b> para Dodo Payments proporciona:

- Creación automática de clientes al registrarse
- Sesiones de pago (preferido) con mapeo de slug de producto
- Portal de clientes de autoservicio
- Procesamiento de eventos de webhook en tiempo real con verificación de firma
- Soporte completo para TypeScript

<Note>
  Necesitas una cuenta de Dodo Payments y claves API para usar esta integración.
</Note>

# Requisitos previos

- Node.js 20+
- Acceso a tu panel de control de Dodo Payments
- Proyecto existente utilizando [better-auth](https://www.npmjs.com/package/better-auth)

# Instalación

<Steps>
<Step title="Instalar dependencias">
Ejecuta el siguiente comando en la raíz de tu proyecto:

```bash
npm install @dodopayments/better-auth dodopayments better-auth zod
```

<Check>
Todos los paquetes requeridos están ahora instalados.
</Check>
</Step>
</Steps>

# Configuración

<Steps>
<Step title="Configurar variables de entorno">
Agrega esto a tu archivo <code>.env</code>:

```env expandable
DODO_PAYMENTS_API_KEY=your_api_key_here
DODO_PAYMENTS_WEBHOOK_SECRET=your_webhook_secret_here
BETTER_AUTH_URL=http://localhost:3000
BETTER_AUTH_SECRET=your_better_auth_secret_here
```

<Warning>
Nunca cometas claves API o secretos en el control de versiones.
</Warning>
</Step>

<Step title="Configurar integración del lado del servidor">
Crea o actualiza <code>src/lib/auth.ts</code>:

```typescript expandable
import { betterAuth } from "better-auth";
import {
  dodopayments,
  checkout,
  portal,
  webhooks,
} from "@dodopayments/better-auth";
import DodoPayments from "dodopayments";

export const dodoPayments = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
  environment: "test_mode", // or "live_mode" for production
});

export const { auth, endpoints, client } = BetterAuth({
  plugins: [
    dodopayments({
      client: dodoPayments,
      createCustomerOnSignUp: true,
      use: [
        checkout({
          products: [
            {
              productId: "pdt_xxxxxxxxxxxxxxxxxxxxx",
              slug: "premium-plan",
            },
          ],
          successUrl: "/dashboard/success",
          authenticatedUsersOnly: true,
        }),
        portal(),
        webhooks({
          webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_SECRET!,
          onPayload: async (payload) => {
            console.log("Received webhook:", payload.event_type);
          },
        }),
      ],
    }),
  ],
});
```

<Tip>
Establece <code>environment</code> a <code>live_mode</code> para producción.
</Tip>
</Step>

<Step title="Configurar integración del lado del cliente">
Crea o actualiza <code>src/lib/auth-client.ts</code>:

```typescript expandable
import { createAuthClient } from "better-auth/react";
import { dodopaymentsClient } from "@dodopayments/better-auth";

export const authClient = createAuthClient({
  baseURL: process.env.BETTER_AUTH_URL || "http://localhost:3000",
  plugins: [dodopaymentsClient()],
});
```

</Step>
</Steps>

# Ejemplos de uso

<Info>
  Prefiere <code>authClient.dodopayments.checkoutSession</code> para nuevas
  integraciones. El método legado <code>checkout</code> está en desuso y se mantiene
  solo por compatibilidad hacia atrás.
</Info>

## Creando una Sesión de Pago (Preferido)

<CodeGroup>

```typescript Using a slug
const { data: session, error } = await authClient.dodopayments.checkoutSession({
  // Option A: use a configured slug
  slug: "premium-plan",

// Your internal id for reference
referenceId: "order_123",
});

if (session) {
window.location.href = session.url;
}

```

`

```typescript Using product cart
const { data: session, error } = await authClient.dodopayments.checkoutSession({
  // Option B: pass a product cart/product id directly
  product_cart: [
    {
      product_id: "pdt_xxxxxxxxxxxxxxxxxxxxx",
      quantity: 1,
    }
  ],

  // Your internal id for reference
  referenceId: "order_123",
});

if (session) {
  window.location.href = session.url;
}
```

`

</CodeGroup>

<Info>
  A diferencia del método legado <code>checkout</code>, <code>checkoutSession</code>
  no requiere información de facturación por adelantado, ya que se tomará del usuario
  en la página de pago. Aún puedes anularlo pasando la
  clave <code>billing</code> en el argumento.
</Info>

<Info>
  Similar al método legado <code>checkout</code>,
  <code>checkoutSession</code> toma el correo electrónico y el nombre del cliente de su
  sesión de better-auth, sin embargo, puedes anularlo pasando el
  objeto <code>customer</code> con correo electrónico y nombre.
</Info>

<Info>
  Puedes pasar las mismas opciones en el argumento como el cuerpo de la solicitud para [Crear
  Sesión de Pago](https://docs.dodopayments.com/api-reference/checkout-sessions/create)
  endpoint.
</Info>

<Note>
  La URL de retorno se toma de la <code>successUrl</code> configurada en el
  plugin del servidor. No necesitas incluir <code>return_url</code> en la
  carga útil del cliente.
</Note>

# Webhooks

<Info>
  El plugin de webhooks procesa eventos de pago en tiempo real de Dodo Payments con
  verificación de firma segura. El endpoint predeterminado es <code>/api/auth/dodopayments/webhooks</code>.
</Info>

<Steps>
<Step title="Generar y establecer secreto de webhook">
Genera un secreto de webhook para tu URL de endpoint (por ejemplo, <code>https://&lt;tu-dominio&gt;/api/auth/dodopayments/webhooks</code>) en el panel de Dodo Payments y configúralo en tu archivo <code>.env</code>:

```env
DODO_PAYMENTS_WEBHOOK_SECRET=your_webhook_secret_here
```

</Step>

<Step title="Manejar eventos de webhook">
Ejemplo de manejador:

```typescript expandable
webhooks({
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_SECRET!,
  onPayload: async (payload) => {
    console.log("Received webhook:", payload.event_type);
  },
});
```

</Step>
</Steps>

# Referencia de Configuración

<AccordionGroup>
  <Accordion title="Opciones del Plugin">
    - <b>client</b> (requerido): Instancia del cliente DodoPayments -{" "}
    <b>createCustomerOnSignUp</b> (opcional): Crear clientes automáticamente al registrarse - <b>use</b> (requerido): Array de plugins a habilitar (checkout,
    portal, webhooks)
  </Accordion>
  <Accordion title="Opciones del Plugin de Pago">
    - <b>products</b>: Array de productos o función asíncrona que devuelve productos -{" "}
    <b>successUrl</b>: URL a redirigir después de un pago exitoso -{" "}
    <b>authenticatedUsersOnly</b>: Requiere autenticación de usuario (predeterminado: false)
  </Accordion>
</AccordionGroup>

# Solución de Problemas y Consejos

<AccordionGroup>
  <Accordion title="Problemas Comunes">
    - <b>Clave API inválida</b>: Verifica tu <code>DODO_PAYMENTS_API_KEY</code> en <code>.env</code>. -{" "}
    <b>Desajuste de firma de webhook</b>: Asegúrate de que el secreto de webhook coincida con el que
    se estableció en el panel de Dodo Payments. - <b>Cliente no creado</b>: Confirma que <code>createCustomerOnSignUp</code> esté configurado como <code>true</code>.
  </Accordion>
  <Accordion title="Mejores Prácticas">
    - Usa variables de entorno para todos los secretos y claves. - Prueba en <code>test_mode</code> antes de cambiar a <code>live_mode</code>. - Registra
    eventos de webhook para depuración y auditoría.
  </Accordion>
</AccordionGroup>
