## Create a product

You can create products from the dashboard or via API. Choose the pricing model up‑front, One‑Time, Subscription, or Usage‑Based and then configure details. The pricing model can’t be changed later; create a new product if you need a different model.

<Steps>
<Step title="Name & description">
Provide a clear title and a concise value‑oriented description. Markdown is supported in descriptions.

<Tip>
Keep the first sentence customer‑facing and outcome‑oriented; it appears prominently in checkout.
</Tip>

<Frame>
  <img src="/images/products.png" alt="Productos" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

</Step>

<Step title="Pricing model & price">
Select the pricing model:

- **One‑Time**: Fixed price paid once.
- **Subscription**: Recurring price with interval and optional trial.
- **Usage‑Based**: Price derived from metered events.

Then set pricing:

- **Precio**: Importe base y moneda.
- **Descuento (%)**: Descuento opcional en línea mostrado en el pago y facturas.
- Para suscripciones, establece **Repetir cada** (por ejemplo, 1 mes o 1 año) y **Días de prueba** si es necesario. El precio de la suscripción debe ser al menos **$1** (o el equivalente en la moneda elegida); los importes por debajo de este mínimo no son compatibles y la suscripción no funcionará.

<Tip>
¿Quieres un precio fijo por moneda o país en lugar de una conversión de FX en vivo? Establece un `pricing_mode` en el producto y aplica reglas de [Precios Localizados](/features/localized-pricing) — por ejemplo, €9.99 en EUR o ₹999 en India.
</Tip>

<Warning>
Cambiar el precio afecta solo a nuevas compras. Las suscripciones existentes siguen las reglas de cambio de plan.
</Warning>
</Step>

<Step title="Product media">
Sube imágenes para mostrar el producto durante el pago y en las facturas. Se admiten PNG/JPG/WebP de hasta 3 MB. Reordena o reemplaza en cualquier momento.
</Step>

<Step title="Automated entitlements (Under Advanced Settings)">
Adjunta cumplimiento que se activa automáticamente después del pago:

- **Claves de Licencia**: Emitir y validar claves únicas
- **Descarga de Archivos**: Otorgar acceso seguro a archivos
- **Personalizado**: Activar tu lógica de derechos mediante webhooks

Agrega o quita beneficios a medida que tu oferta evoluciona. Los suscriptores existentes ganan o pierden acceso según corresponda.
</Step>
</Steps>

## Variantes y opciones de precios

En lugar de variantes bajo un solo producto, crea productos separados para cada opción de precio (por ejemplo, Mensual y Anual). Luego, agrúpalos en una **Colección de Productos** para presentar todas las opciones en un solo pago y permitir el cambio de plan en el Portal del Cliente.

<Frame>
  <img src="/images/product-collection/checkout-page.png" alt="Colecciones de Productos" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### ¿Por qué este enfoque?

- **Modelos de precios claros**: Cada producto tiene un modelo de precios único y bien definido (único, suscripción, o basado en uso)
- **APIs predecibles**: Integraciones más simples sin la lógica de variantes anidadas
- **Informes más fáciles**: Seguimiento de ingresos y métricas por producto sin agregación de variantes
- **Pago flexible**: Mostrar múltiples productos uno al lado del otro, permitiendo a los clientes comparar y elegir

### Cómo funcionan las Colecciones de Productos

1. **Crear productos**: Configura productos individuales para cada plan (por ejemplo, Inicio Mensual, Inicio Anual, Pro Mensual, Pro Anual)
2. **Agrupar en una colección**: Añadir productos relacionados a una Colección de Productos
3. **Pago unificado**: Los clientes ven todas las opciones en un solo pago y seleccionan su plan preferido
4. **Cambio de plan**: Los clientes pueden mejorar o degradar entre productos en la misma colección a través del Portal del Cliente

## Gestión de productos

Puedes gestionar los productos a través del panel de control o programáticamente mediante la API. La API proporciona control total sobre la creación, actualizaciones, recuperación, carga de imágenes, y archivado de productos.

### Gestión mediante el Panel de Control

- **Actualización**: Edita el nombre, descripción, imágenes, precio, campos, y beneficios en cualquier momento (el modelo de precios es inmutable).
- **Archivado**: Oculta un producto de nuevas compras sin interrumpir a los clientes existentes. Puedes desarchivarlo más tarde.

### Gestión mediante la API

Las siguientes instrucciones te permiten crear, actualizar, gestionar y recuperar productos, incluyendo la carga de imágenes.

<AccordionGroup>
<Accordion title="Creating a Product">
Un producto puede ser un artículo único o un servicio basado en suscripción. Para crear un nuevo producto, envía una solicitud `POST` al endpoint `/products` con detalles como nombre, descripción, precio, moneda, y si es un producto recurrente.

Para productos recurrentes, establece el objeto `price` a un precio recurrente (`type: recurring_price`) y especifica `payment_frequency_interval` e `subscription_period_interval` (`Day`, `Week`, `Month`, o `Year`) junto con sus cuentas correspondientes.

<Card title="Create Product API" icon="code" href="/api-reference/products/post-products">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Crear Producto.
</Card>
</Accordion>

<Accordion title="Updating a Product">
Para modificar un producto existente, envía una solicitud `PATCH` al endpoint `/products/{product_id}`. Puedes actualizar propiedades como nombre, precio, y descripción mientras mantienes otros detalles sin cambios.

Asegúrate de que el `product_id` en el endpoint coincida con un producto existente.

<Card title="Update Product API" icon="code" href="/api-reference/products/patch-products">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Actualización de Producto.
</Card>
</Accordion>

<Accordion title="Retrieving Products">
Puedes obtener una lista de productos almacenados en tu cuenta usando una solicitud `GET` al endpoint `/products`. Esto te permite recuperar detalles del producto, incluyendo productos activos y archivados.

<Card title="Retrieve Products API" icon="code" href="/api-reference/products/get-products">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Recuperación de Productos.
</Card>
</Accordion>

<Accordion title="Uploading Product Images">
Puedes asociar una imagen a un producto subiéndola a AWS S3 usando una URL prefirmada proporcionada por la API. Primero, solicita una URL de carga de imagen desde el endpoint `/products/{product_id}/images`, luego usa la URL proporcionada para subir la imagen dentro de 60 segundos.

<Warning>
La URL prefirmada expira en 60 segundos, por lo que la imagen debe ser subida dentro de ese plazo.
</Warning>

Una vez recibida la URL prefirmada de la API, sube la imagen usando el método `PUT`. Esto asegura acceso seguro y temporal a AWS S3 para subir la imagen.

**Librerías soportadas para subir a S3:**
- **Node.js**: `axios`, `node-fetch`
- **Python**: `requests`, `boto3`
- **Go**: `net/http`
- **PHP**: `GuzzleHttp`
- **Ruby**: `rest-client`

Si la carga es exitosa, AWS S3 devolverá un estatus `200 OK`, indicando que la imagen se ha almacenado correctamente.

<Card title="Upload Product Image API" icon="code" href="/api-reference/products/put-products-images">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Carga de Imagen de Producto.
</Card>
</Accordion>

<Accordion title="Archiving a Product">
Si ya no deseas mostrar o usar un producto, puedes archivarlo usando una solicitud `DELETE` al endpoint `/products/{id}`. Esta acción oculta el producto pero no lo elimina permanentemente.

<Card title="Archive Product API" icon="code" href="/api-reference/products/archive-product">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Archivado de Producto.
</Card>
</Accordion>

<Accordion title="Unarchiving a Product">
Si necesitas restaurar un producto archivado, envía una solicitud `POST` al endpoint `/products/{product_id}/unarchive`. Esto reactivará el producto y lo pondrá nuevamente disponible para su uso.

<Card title="Unarchive Product API" icon="code" href="/api-reference/products/unarchive-product">
  Ve la estructura detallada de solicitud y respuesta en la documentación de la API de Desarchivado de Producto.
</Card>
</Accordion>

## Mejores prácticas

- **Empieza con claridad**: Separa los productos para cada opción de precio (Mensual vs Anual)
- **Usa pruebas de manera juiciosa**: Combina pruebas con onboarding para impulsar la activación
- **Automatiza el cumplimiento**: Usa beneficios y webhooks para entregar instantáneamente
- **Etiquetar con metadatos**: Guarda los IDs de tu sistema para la conciliación
