## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## Desactivación de Métodos de Pago a Nivel Empresarial

Puedes desactivar métodos de pago específicos a nivel empresarial desde tu panel de control. Esto se aplica a todas las sesiones de pago de tu negocio, sin necesidad de configurarlo por producto o sesión.

<Steps>
<Step title="Navigate to Settings">
Ve a **Configuración > Métodos de Pago** en el panel de control de Dodo Payments.
</Step>

<Step title="Disable Payment Methods">
Desactiva cualquier método de pago que no quieras ofrecer a los clientes.
</Step>
</Steps>

<Tip>
Usa esto para desactivar métodos de pago que tengan altas tasas de fraude en tu región, o para limitar opciones solo a los métodos que tu empresa soporta operativamente.
</Tip>

<Info>
Las configuraciones a nivel empresarial actúan como un filtro global. Las restricciones por pago a través de `allowed_payment_method_types` afinan aún más los métodos disponibles dentro de lo habilitado a nivel empresarial.
</Info>

## Configuración de Métodos de Pago por Checkout

Además de las configuraciones a nivel empresarial, puedes restringir los métodos que se muestran para sesiones de pago individuales usando `allowed_payment_method_types`:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Mejores Prácticas

<AccordionGroup>
<Accordion title="Match methods to your market">
Incluye métodos de pago regionales para tus mercados objetivo. iDEAL captura alrededor del 60% de los pagos en línea en los Países Bajos; UPI domina en India. Omitir estos métodos afecta significativamente la conversión.
</Accordion>

<Accordion title="Always provide card fallbacks">
Incluso cuando se dirigen a métodos específicos, incluye `credit` y `debit` como alternativas. No todos los clientes tienen acceso a cada método de pago.
</Accordion>

<Accordion title="Consider transaction minimums">
Los métodos BNPL (Klarna, Afterpay) requieren un mínimo de $50.01. No los incluyas para productos de bajo valor: simplemente no aparecerán, lo cual está bien.
</Accordion>

<Accordion title="Test across regions and devices">
Usa el modo de prueba para verificar la disponibilidad de métodos de pago para diferentes ubicaciones de clientes, monedas y tipos de dispositivos antes de lanzarlo.
</Accordion>
</AccordionGroup>

## Solución de Problemas

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Verifica estos factores:**
1. ¿Método incluido en `allowed_payment_method_types`?
2. ¿Ubicación del cliente coincide con la región del método?
3. ¿Moneda de transacción soportada por el método?
4. ¿Monto de transacción cumple con el mínimo (por ejemplo, $50.01 para BNPL)?
5. Para suscripciones: ¿el método soporta pagos recurrentes?

**Solución:** Elimina `allowed_payment_method_types` temporalmente para ver todos los métodos elegibles, luego reduce el problema.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Causas posibles:**
- `allowed_payment_method_types` no se está pasando correctamente
- Parámetro formateado incorrectamente (debe ser arreglo de cadenas)

**Solución:** Registra la carga útil de tu solicitud API y verifica la estructura del parámetro.
</Accordion>

<Accordion title="Regional method not available">
**Verifica:**
- La dirección de facturación del cliente coincide con la región del método
- La moneda está configurada correctamente (por ejemplo, EUR para iDEAL)
- Moneda Adaptativa está habilitada si el cliente es internacional

**Solución:** Verifica el código de país de la dirección de facturación y la moneda en tu solicitud API.
</Accordion>

<Accordion title="Indian payment method issues">
Las suscripciones UPI y Rupay tienen requisitos únicos incluyendo retrasos de procesamiento de 48 horas y límites de mandato RBI.

**Ver:** <a href="/features/payment-methods/india">Métodos de Pago en India</a> para una guía completa.
</Accordion>
</AccordionGroup>
