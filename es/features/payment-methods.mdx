## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## Desactivación de métodos de pago a nivel empresarial

Puedes desactivar métodos de pago específicos a nivel empresarial desde tu dashboard. Esto se aplica a todas las sesiones de checkout de tu empresa, sin necesidad de configurarlo por producto o sesión.

<Steps>
<Step title="Navigate to Settings">
Ve a **Settings > Payment Methods** en el dashboard de Dodo Payments.
</Step>

<Step title="Disable Payment Methods">
Desactiva cualquier método de pago que no quieras ofrecer a tus clientes.
</Step>
</Steps>

<Tip>
Utiliza esta opción para desactivar métodos de pago con altos índices de fraude en tu región o para limitar las opciones únicamente a los métodos que tu empresa admite operativamente.
</Tip>

<Info>
La configuración a nivel empresarial actúa como un filtro global. Las restricciones por checkout mediante `allowed_payment_method_types` reducen aún más los métodos disponibles dentro de los habilitados a nivel empresarial.
</Info>

## Configuración de métodos de pago por checkout

Además de la configuración a nivel empresarial, puedes restringir qué métodos se muestran para sesiones de checkout individuales mediante `allowed_payment_method_types`:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "pdt_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "pdt_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Prácticas recomendadas

<AccordionGroup>
<Accordion title="Match methods to your market">
Incluye métodos de pago regionales para tus mercados objetivo. iDEAL procesa aproximadamente el 60 % de los pagos en línea en los Países Bajos; UPI domina en India. Omitir estos métodos perjudica significativamente la conversión.
</Accordion>

<Accordion title="Always provide card fallbacks">
Incluso cuando te dirijas a métodos específicos, incluye `credit` y `debit` como alternativas de respaldo. No todos los clientes tienen acceso a todos los métodos de pago.
</Accordion>

<Accordion title="Consider transaction minimums">
Los métodos BNPL tienen mínimos por proveedor: Klarna y Afterpay requieren $50.01. No los incluyas para productos fuera de estos rangos; simplemente no aparecerán, lo cual está bien.
</Accordion>

<Accordion title="Test across regions and devices">
Usa el modo de prueba para verificar la disponibilidad de los métodos de pago según las distintas ubicaciones de los clientes, monedas y tipos de dispositivo antes de entrar en producción.
</Accordion>
</AccordionGroup>

## Solución de problemas

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Comprueba estos factores:**
1. ¿El método está incluido en `allowed_payment_method_types`?
2. ¿La ubicación del cliente coincide con la región compatible con el método?
3. ¿La moneda de la transacción es compatible con el método?
    4. ¿El importe de la transacción está dentro del rango compatible con el método (por ejemplo, mínimo de $50.01 para Klarna/Afterpay)?
5. Para suscripciones: ¿el método admite pagos recurrentes?

**Solución:** Elimina temporalmente `allowed_payment_method_types` para ver todos los métodos aptos y, a continuación, delimita el problema.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Posibles causas:**
- `allowed_payment_method_types` no se está enviando correctamente
- El parámetro tiene un formato incorrecto (debe ser un array de strings)

**Solución:** Registra el payload de tu solicitud de API y verifica la estructura del parámetro.
</Accordion>

<Accordion title="Regional method not available">
**Comprueba:**
- La dirección de facturación del cliente coincide con la región del método
- La moneda está configurada correctamente (por ejemplo, EUR para iDEAL)
- Adaptive Currency está habilitado si el cliente es internacional

**Solución:** Verifica el código de país de la dirección de facturación y la moneda en tu solicitud de API.
</Accordion>

<Accordion title="Indian payment method issues">
Las suscripciones UPI y Rupay tienen requisitos específicos, incluidos retrasos de procesamiento de 48 horas y límites de mandatos del RBI.

**Consulta:** <a href="/features/payment-methods/india">Métodos de pago de India</a> para obtener instrucciones completas.
</Accordion>
</AccordionGroup>
