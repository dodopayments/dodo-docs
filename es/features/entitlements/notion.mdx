<Info>
La asignación de Notion duplica una plantilla que has preparado en el espacio de trabajo del cliente que paga. El cliente se autoriza a través de OAuth, elige el espacio de trabajo en el que desea que se copie la plantilla, y Dodo Payments maneja la duplicación.
</Info>

## Qué se entrega

- Se solicita al cliente que conecte su espacio de trabajo de Notion mediante OAuth.
- Una vez autorizado, Dodo Payments duplica la plantilla configurada en el espacio de trabajo que haya elegido.
- Al cancelar, la plantilla duplicada permanece en el espacio de trabajo del cliente (Notion no admite la eliminación remota). El grant se marca como `Revoked` para fines de registro.

Los usos comunes incluyen plantillas de Notion de pago, sistemas de productividad y plantillas de OS/CRM.

## Flujo del cliente

1. El cliente completa el checkout.
2. Dodo Payments crea un grant con el estado `Pending`. Su `oauth_url` es `null` hasta que el cliente inicia el flujo de aceptación; en ese momento, se completa con una URL de autorización de Notion.
3. El cliente autoriza mediante el enlace incluido en su correo electrónico o en el Customer Portal y selecciona el workspace en el que desea duplicar la plantilla.
4. Dodo Payments duplica la plantilla. El grant pasa a `Delivered`.
5. Tras la revocación, el grant se marca como `Revoked`; la copia duplicada permanece en el workspace del cliente.

<Note>
Notion trata intencionalmente una página duplicada como contenido propio del destinatario. Dodo Payments no puede eliminar la copia al revocar.
</Note>

## Configuración requerida

| Campo | Requerido | Descripción |
|---|---|---|
| `notion_template_id` | Sí | El ID de la plantilla. El selector del panel llena este campo. |

## Crear mediante API

<CodeGroup>

```typescript TypeScript theme={null}
const entitlement = await client.entitlements.create({
  name: 'Study Notes',
  integration_type: 'notion',
  integration_config: {
    notion_template_id: 'tmpl_abc123',
  },
});
```

```python Python theme={null}
client.entitlements.create(
    name="Study Notes",
    integration_type="notion",
    integration_config={"notion_template_id": "tmpl_abc123"},
)
```

```go Go theme={null}
client.Entitlements.New(ctx, dodopayments.EntitlementNewParams{
  Name:            dodopayments.F("Study Notes"),
  IntegrationType: dodopayments.F(dodopayments.EntitlementIntegrationTypeNotion),
  IntegrationConfig: dodopayments.F[dodopayments.IntegrationConfigUnionParam](
    dodopayments.IntegrationConfigNotionConfigParam{
      NotionTemplateID: dodopayments.F("tmpl_abc123"),
    },
  ),
})
```

</CodeGroup>

## Webhooks

Ver [eventos webhook `entitlement_grant.*`](/developer-resources/webhooks/intents/entitlement-grant):

- `entitlement_grant.created` se activa con `status: "Pending"` y `oauth_url` aún en `null`; la URL de autorización de Notion se completa una vez que el cliente inicia el flujo de aceptación desde el correo electrónico de entrega o el Customer Portal.
- `entitlement_grant.delivered` se activa una vez que se duplica la plantilla.
- `entitlement_grant.revoked` se activa al cancelar; la copia del cliente no se modifica.

## Resolución de problemas

<AccordionGroup>
<Accordion title="Customer didn't get the template">
El grant permanece en `Pending` hasta que el cliente completa el flujo de OAuth de Notion. Reenvía el correo electrónico de entrega; el enlace de OAuth caduca después de una semana, tras lo cual puedes revocar y volver a crear el grant.
</Accordion>

<Accordion title="Template picker is empty">
Reconectar Notion desde **Asignaciones → Integraciones → Notion** con el espacio de trabajo que posee las plantillas de origen.
</Accordion>

<Accordion title="Customer wants the template removed after refund">
Notion no permite la eliminación remota de páginas duplicadas. El cliente debe eliminar la copia de su propio espacio de trabajo.
</Accordion>
</AccordionGroup>
