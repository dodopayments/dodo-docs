## Introducción

Multi-Brand te permite adjuntar varias marcas, cada una con su propio logo, descriptor y URL de sitio web, a **un negocio verificado**. Tu cuenta de pagos, tarifas y KYC se mantienen exactamente igual, mientras que cada Producto, Enlace de Pago, Suscripción, Factura y Transacción ahora pueden archivarse bajo una marca específica. Úsalo para probar nuevos nichos, localizar un sitio o separar líneas B2B y B2C sin abrir cuentas comerciales adicionales.

## Flujo del Panel del Comerciante

<Steps>
<Step title="Open Settings → Business">
Navega a **Configuración → Negocio**. El panel **Marcas bajo [Tu Negocio]** a la derecha lista tu marca Principal y cualquier marca Secundaria.

<Frame>
<img src="/images/multi-brands/brands-section.png" alt="Panel de Marcas en Configuración de Negocio mostrando marcas primarias y secundarias con un botón de más para agregar una nueva marca" />
</Frame>
</Step>
<Step title="Click the '+' button">
En el panel de Marcas, haz clic en el botón **+** en la esquina superior derecha para abrir el formulario de nueva marca.
</Step>
<Step title="Fill in the brand details">
Completa los siguientes campos:

- **Nombre de la Marca** (obligatorio): Ingresa el nombre de tu marca.
- **URL del Sitio Web** (obligatorio): El sitio web de tu marca, por ejemplo `https://www.yourcompany.com`.
- **Correo Electrónico de Soporte**: El correo electrónico que los clientes pueden usar para contactar soporte para esta marca.
- **Descripción de la Marca** (obligatorio): Describe tu marca, productos y lo que la hace única.
- **Logo de la Marca**: Sube un logo para representar la marca en el pago, facturas y enlaces de pago.

Envía el formulario para crear la marca. Los productos ahora pueden etiquetarse con esta marca y los enlaces de pago mostrarán su imagen de marca.
</Step>
<Step title="Brand Selector">
Ahora se ve un filtro de Marca en la creación de Productos.
</Step>
<Step title="Brand ID in Transactions">
Las transacciones y suscripciones tienen un ID de Marca para ayudarte a identificar a qué marca pertenece la transacción.
</Step>
</Steps>

## Puntos Adicionales

- **Sin cambios en los pagos:** Todos los fondos, ciclos de pago y comisiones siguen gestionándose a través de la billetera de nivel empresarial y la cuenta bancaria del merchant.
- **ID de marca en los webhooks:** Las cargas útiles de pagos, suscripciones, reembolsos, disputas, claves de licencia, entradas del libro mayor de créditos, saldos de crédito bajos, concesiones de permisos, intentos de cobro y checkouts abandonados incluyen un `brand_id`, para que puedas atribuirlas a una marca específica. Cuando una entidad no tiene una marca propia, `brand_id` recurre a la marca principal de la empresa. Las cargas útiles de pagos son de nivel empresarial y no incluyen un `brand_id`.
- **Suspensiones:** Si se suspende una marca, solo se detienen sus enlaces de pago. Las demás marcas de la misma empresa siguen procesando transacciones.
- No hay cambios en Storefront, Invoices, License Keys, Discount Codes, Payout Settings ni en ninguna otra funcionalidad de nivel empresarial.

## Archivar una marca

Cuando una marca ha cumplido su ciclo, archívela en lugar de dejarla inactiva en su dashboard. Archivar retira la marca y transfiere su catálogo a otra marca del mismo negocio en un solo paso.

<Warning>
Archivar una marca es permanente. No hay forma de restaurar una marca archivada.
</Warning>

### Qué ocurre al archivar

Debe designar una **marca objetivo** que tome el control de la marca que está archivando. El dashboard siempre solicita una, y la API la recibe como `move_products_to`. En una única acción atómica, Dodo Payments:

- Traslada todos los productos a la marca objetivo.
- Traslada todas las suscripciones activas a la marca objetivo, de modo que las renovaciones continúen facturándose bajo ella.
- Traslada todas las colecciones de productos a la marca objetivo.
- Archiva y deshabilita la marca original.

Su historial no se modifica. Los pagos, las facturas y las suscripciones finalizadas conservan la marca con la que se crearon, por lo que los informes históricos siguen siendo precisos.

La marca objetivo debe pertenecer al mismo negocio y no debe estar archivada. Su marca principal es un objetivo válido, y su ID de marca es el ID de su negocio. Puede omitir el objetivo solo cuando la marca no contiene productos, suscripciones activas ni colecciones de productos.

<Note>
La marca principal nunca se puede archivar. Es la marca a la que recurre su negocio, por lo que siempre queda al menos una marca.
</Note>

### Una marca archivada es de solo lectura

| Acción | Resultado |
|---|---|
| Editar los detalles de la marca | Rechazado con `BRAND_ARCHIVED` |
| Enviar la marca para su verificación | Rechazado con `BRAND_ARCHIVED` |
| Crear un producto o una colección bajo la marca | Rechazado con `BRAND_ARCHIVED` |
| Crear una suscripción para uno de sus productos | Rechazado con `BRAND_ARCHIVED` |

Las marcas archivadas se ocultan de los selectores de marcas, por lo que no puede asignarles nuevos registros. Siguen disponibles como filtros de análisis, lo que mantiene completos sus informes por marca durante el período en que la marca estuvo operativa. Consulte [Analytics](/features/analytics).

### Archivar mediante la API

Llame al endpoint de archivo con la marca que está retirando y la marca que asumirá el control:

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

La respuesta informa qué elementos se trasladaron, para que pueda confirmar el resultado:

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

Para mostrar las marcas, incluidas las archivadas, establezca `include_archived` en el endpoint de listado. Las marcas archivadas se excluyen de forma predeterminada. Cada marca incluye un campo `archived_at`, cuyo valor es `null` mientras la marca está activa.

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

Consulte la referencia de la API de [Archive Brand](/api-reference/brands/archive-brand) para ver el esquema completo de la solicitud y la respuesta, y [Error Codes](/api-reference/error-codes) para consultar los errores que devuelve este endpoint.
