## Nuevas Funciones

### 1. **Analíticas a Nivel de Producto**

Cada producto ahora tiene su propio **panel de analíticas dedicado**. Navega a **Productos > [Seleccionar un Producto]** para acceder a métricas detalladas específicas para ese producto, organizadas en cinco pestañas:

<Frame>
<img src="/images/product-analytics/overview.png" alt="Analíticas a Nivel de Producto" />
</Frame>

| Pestaña | Lo Que Obtienes |
|-----|-------------|
| **Descripción General** | Ingresos totales, recuento de pagos exitosos, gráfico de tendencias de ingresos de 30 días (diario o acumulativo), y una tabla de transacciones filtrable |
| **Clientes** | Los 3 principales clientes clasificados por gasto con vista de podio, además de una tabla de desglose de clientes completa |
| **Retención** | Tasa de cancelación de clientes, tasa de cancelación de ingresos, y un gráfico de tendencias de doble línea para detectar patrones |
| **Suscriptores** | Todas las suscripciones para el producto con estado, fecha de inicio, próxima fecha de facturación y monto |
| **MRR** | Gráfico de barras apiladas de Ingresos Recurrentes Mensuales con desglose de Nuevo MRR, Expansión MRR, Churned MRR y Net New MRR |

Todas las pestañas soportan un **filtro de fecha** (por defecto a Todo el Tiempo) para que puedas navegar por cualquier período de tiempo.

<Tip>
Usa la pestaña de Retención para identificar productos con alta cancelación temprana, y la pestaña de MRR para rastrear si los ingresos por expansión superan los ingresos cancelados mes a mes.
</Tip>

### 2. **Soporte de Verifi RDR en Dodo Payments**

Dodo Payments ahora soporta **Visa Rapid Dispute Resolution (RDR)** impulsado por Verifi -- una herramienta automática de prevención de disputas que resuelve disputas de Visa elegibles **antes de que se conviertan en contracargos formales**. Cuando un titular de tarjeta inicia una disputa, RDR la intercepta y emite automáticamente un reembolso si la transacción está por debajo de tu umbral configurado en USD.

**Por Qué Es Importante**

| Beneficio | Impacto |
|---------|--------|
| **Menor tasa de disputa** | Las disputas resueltas por RDR no cuentan para el umbral del 0.9% de Visa |
| **Sin tarifas de disputa** | Evita tarifas no reembolsables de $15-$25 por disputa |
| **Cero carga operativa** | Sin recolección de evidencia o plazos de respuesta |
| **Mejor experiencia del cliente** | Los titulares de tarjetas obtienen reembolsos instantáneos |
| **Protección de cuentas** | Mantente fuera del Programa de Monitoreo de Disputas de Visa (VDMP) |

<Warning>
Exceder la tasa de disputa del 0.9% de Visa o 100 disputas/mes activa el VDMP, con multas que aumentan hasta $50,000+/mes. RDR te ayuda a mantenerte muy por debajo de estos umbrales.
</Warning>

**Cómo Funciona**

1. El titular de la tarjeta inicia una disputa con su banco
2. RDR intercepta la disputa antes de que se convierta en un contracargo formal
3. Si el monto de la transacción está en o por debajo de tu umbral, se emite automáticamente un reembolso
4. La disputa se resuelve instantáneamente y **no cuenta** contra tu tasa de disputa

<Info>
Las transacciones reembolsadas automáticamente a través de RDR aparecen como una **disputa perdida** en tu panel de Dodo Payments. Esto es esperado; el reembolso fue emitido automáticamente para prevenir un contracargo formal.
</Info>

Para habilitar Verifi RDR en tu cuenta, contacta a **support@dodopayments.com** para configurar tu umbral.

Más información: [Documentación de Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **CLI de DodoPayments**

Presentamos el nuevo **CLI de DodoPayments** (`dodopayments-cli`) -- gestiona todo tu flujo de trabajo de Dodo Payments directamente desde la terminal. Diseñado para desarrolladores que prefieren la línea de comandos, el CLI te permite gestionar productos, pagos, clientes, descuentos, licencias, complementos, reembolsos, e incluso crear sesiones de pago sin salir de tu editor.

**Instalación**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Comandos Clave**

| Comando | Descripción |
|---------|-------------|
| `dodo login` | Autenticarse con tu clave API (abre el navegador) |
| `dodo products list` | Listar todos los productos |
| `dodo payments list` | Listar todos los pagos |
| `dodo customers create` | Crear un nuevo cliente |
| `dodo checkout new` | Crear una sesión de compra y obtener la URL |
| `dodo wh listen` | Redirigir webhooks de prueba en vivo a tu servidor local a través de WebSocket |
| `dodo wh trigger` | Enviar cargas útiles de webhook simulado a cualquier endpoint |

**Pruebas de Webhook**

El CLI incluye dos herramientas poderosas para el desarrollo:

- **`dodo wh listen`** -- Abre una conexión WebSocket para redirigir webhooks de prueba en tiempo real a tu servidor local, preservando encabezados originales para pruebas de verificación de firma
- **`dodo wh trigger`** -- Envía cargas útiles de webhook simuladas interactivamente, soportando todos los 22 tipos de eventos a través de suscripciones, pagos, reembolsos, disputas y licencias

<Tip>
El oyente de webhook solo funciona con una clave API de **modo de prueba**. Asegúrate de estar conectado con una clave de modo de prueba antes de usar `dodo wh listen`.
</Tip>

Más información: [Documentación del CLI](/developer-resources/sdks/cli)

### 5. **Actualizar Método de Pago en la Compra Integrada**

El [pago integrado](/developer-resources/inline-checkout) ahora soporta **actualizaciones del método de pago** para suscripciones. Cuando un cliente necesita actualizar su método de pago (para una suscripción activa o para reactivar una suscripción en espera), el flujo de actualización del método de pago ahora puede ser renderizado directamente en el diseño de tu página usando la compra integrada -- proporcionando una experiencia embebida y sin interrupciones.

**Cómo Funciona**

1. Llama a la API de Actualización del Método de Pago para obtener un `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Usa el `payment_link` devuelto como el `checkoutUrl` en la compra integrada:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

El marco integrado renderiza solo el formulario de recopilación del método de pago, permitiendo a los clientes ingresar nuevos detalles de tarjeta o seleccionar un método de pago guardado sin salir de tu página.

<Tip>
Para suscripciones en espera, el flujo de actualización del método de pago crea automáticamente un cargo por los saldos pendientes. Monitorea los webhooks `payment.succeeded` y `subscription.active` para confirmar la reactivación.
</Tip>

Más información: [Compra Integrada](/developer-resources/inline-checkout) | [Actualizaciones del Método de Pago de Suscripción](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Soporte de Autocompletado del ID Fiscal para Sesiones de Compra**

Ahora puedes **autocompletar el ID Fiscal** (por ejemplo, número de IVA, número GST) al crear una sesión de compra usando el parámetro `tax_id`. Esto es ideal para transacciones B2B donde ya conoces el número de identificación fiscal del cliente. Cuando se completa el ID Fiscal, el campo se pre-puebla y se bloquea en el formulario de compra.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
El parámetro `tax_id` requiere un `billing_address` con al menos un campo `country`. La elegibilidad fiscal se valida en tiempo real, y las reglas de inversión de carga se aplican automáticamente para transacciones B2B que califiquen.
</Info>

Usa la bandera de función `allow_customer_editing_tax_id` para controlar si los clientes pueden modificar el ID Fiscal precompletado, y `allow_tax_id` para alternar la visibilidad del ID Fiscal en la compra.

Más información: [Sesiones de Compra - ID Fiscal](/developer-resources/checkout-session) | [Pagos B2B](/features/b2b-payments)

### 7. **Clave de Licencia y Correo Electrónico en la Redirección de URL de Retorno**

Después de que un cliente complete la compra, Dodo Payments ahora añade `license_key` e `email` como parámetros de consulta a tu redirección `return_url`, además de los parámetros existentes `payment_id`/`subscription_id` e `status`.

**Parámetros de Consulta Añadidos**

| Parámetro | Tipo | Condición |
|-----------|------|-----------|
| `payment_id` | `string` | Siempre presente para pagos únicos |
| `subscription_id` | `string` | Siempre presente para pagos de suscripción |
| `status` | `string` | Siempre presente |
| `license_key` | `string` | Presente si el producto tiene claves de licencia habilitadas (separadas por comas para múltiples) |
| `email` | `string` | Presente si el cliente tiene un correo electrónico registrado |

**Ejemplos de URLs de redirección:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Usa estos parámetros de consulta para mostrar claves de licencia o enviar un correo electrónico de confirmación inmediatamente en tu página de retorno, sin necesidad de una llamada API adicional.
</Tip>

Más información: [Sesiones de Compra - URL de Retorno](/developer-resources/checkout-session) | [Claves de Licencia en la URL de Retorno](/features/license-keys#license-keys-in-return-url)

### 8. **API de Actualización de Correo Electrónico del Cliente**

El endpoint `PATCH /customers/{customer_id}` ahora soporta la actualización de direcciones de correo electrónico de clientes programáticamente. Actualiza el correo electrónico junto con el nombre, número de teléfono y metadatos en una única llamada a la API.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Campos Actualizables**

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `email` | `string \| null` | Dirección de correo electrónico del cliente |
| `name` | `string \| null` | Nombre de visualización del cliente |
| `phone_number` | `string \| null` | Número de teléfono en formato internacional |
| `metadata` | `object \| null` | Pares clave-valor personalizados |

<Info>
Las actualizaciones de correo electrónico de los clientes también están disponibles a través del Portal del Cliente (autoservicio), el panel, y el CLI a través de `dodo customers update`.
</Info>

Más información: [API de Actualización de Cliente](/api-reference/customers/patch-customer) | [Gestión de Clientes](/features/customers)

### 9. **Lanzamiento del Adaptador de Bun**

Presentamos `@dodopayments/bun` -- un adaptador de marco dedicado para el servidor nativo de [Bun](https://bun.sh) (`Bun.serve()`). Integra la compra, el portal del cliente y los webhooks con Bun en solo unas pocas líneas de código.

**Instalación**

```bash
bun add @dodopayments/bun
```

**Configuración Rápida**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

El adaptador de Bun soporta todos los tres flujos de compra (estático, dinámico y basado en sesión), generación de sesiones del portal del cliente, y manejo seguro de webhooks con verificación de firma y validación de Zod en 22 tipos de eventos.

El adaptador de Bun se une a nuestra familia de 11 adaptadores de marco que incluyen Next.js, Nuxt, Express, Fastify, Hono, Astro, SvelteKit, Remix, TanStack Start, Better Auth y Convex.
</Check>
