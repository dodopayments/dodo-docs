### 2. **Verifi RDR 在 Dodo Payments 上的支持**

Dodo Payments 现在支持 **Visa 快速争议解决（RDR）**，由 Verifi 提供支持 -- 一种自动化的争议预防工具，可以在符合条件的 Visa 争议 **正式变为拒付之前解决它们**。当持卡人发起争议时，RDR 会拦截并自动如果交易低于您配置的 USD 阈值则发出退款。

**为什么这很重要**

| 好处 | 影响 |
|---------|--------|
| **降低争议率** | RDR解决的争议不计入Visa的0.9%阈值 |
| **无争议费用** | 避免每个争议15至25美元的不可退还费用 |
| **零操作开销** | 无需收集证据或响应截止日期 |
| **更好的客户体验** | 持卡人可获得即时退款 |
| **账户保护** | 避免进入Visa争议监控程序（VDMP） |

<Warning>
超过 Visa 的 0.9% 争议率或每月 100 次争议将触发 VDMP，可能导致逐步罚款高达 50,000 美元/月以上。RDR 有助于您在这些阈值下保持良好状态。
</Warning>

**它是如何工作的**

1. 持卡人与其银行发起争议
2. RDR 在争议成为正式拒付之前拦截该争议
3. 如果交易金额在或低于您的阈值，则自动发出退款
4. 争议即刻解决，并且 **不计入** 争议率

<Info>
通过 RDR 自动退还的交易在您的 Dodo Payments 仪表板中显示为 **失去的争议**。这是预期的 -- 退款是自动发出以防止正式拒付。
</Info>

要在您的账户上启用 Verifi RDR，请联系 **support@dodopayments.com** 以配置您的阈值。

了解更多：[Visa RDR 文档](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

推出全新的 **DodoPayments CLI** (`dodopayments-cli`) -- 直接从终端管理整个 Dodo Payments 工作流。该 CLI 为更喜欢命令行的开发人员构建，允许您管理产品、支付、客户、折扣、许可证、附加组件、退款，甚至创建结账会话，而无需离开编辑器。

**安装**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**关键命令**

| 命令 | 描述 |
|---------|-------------|
| `dodo login` | 使用您的 API 密钥进行身份验证（打开浏览器） |
| `dodo products list` | 列出所有产品 |
| `dodo payments list` | 列出所有支付 |
| `dodo customers create` | 创建新客户 |
| `dodo checkout new` | 创建结账会话并获取 URL |
| `dodo wh listen` | 通过 WebSocket 将实时测试 webhook 转发到您的本地服务器 |
| `dodo wh trigger` | 发送模拟 webhook 有效负载到任何端点 |

**Webhook 测试**

该 CLI 包含两个强大的开发工具：

- **`dodo wh listen`** -- 打开 WebSocket 连接，将实时测试 webhook 转发到您的本地服务器，保留原始头部以进行签名验证测试
- **`dodo wh trigger`** -- 以交互方式发送模拟 webhook 有效负载，支持所有 22 种事件类型，包括订阅、支付、退款、争议和许可证

<Tip>
Webhook 监听器仅适用于 **测试模式** API 密钥。在使用 `dodo wh listen` 之前，请确保您已使用测试模式密钥登录。
</Tip>

### 5. **在内联结账中更新支付方式**

现在的 [内联结账](/developer-resources/inline-checkout) 支持对订阅的 **支付方式更新**。当客户需要更新其支付方式（针对活跃订阅或重新激活已暂停的订阅）时，更新支付方式流程现在可以直接在您的页面布局中使用内联结账呈现，从而提供无缝的嵌入体验。

**工作原理**

1. 调用更新支付方式 API 以获取 `payment_link`：

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. 将返回的 `payment_link` 用作内联结账中的 `checkoutUrl`：

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

内联框仅呈现支付方式收集表单，允许客户输入新卡详细信息或选择已保存的支付方式，而无需离开您的页面。

<Tip>
对于已暂停的订阅，更新支付方式流程将自动创建剩余欠款的收费。监控 `payment.succeeded` 和 `subscription.active` webhook 以确认重新激活。
</Tip>

了解更多：[内联结账](/developer-resources/inline-checkout) | [订阅支付方式更新](/features/subscription#update-payment-method-for-active-subscription)

### 6. **结账会话的税号预填支持**

现在，在创建结账会话时，可以使用 `tax_id` 参数 **预填税号**（例如，增值税号码、商品服务税号码）。这非常适合已经知道客户税务识别号的 B2B 交易。当税号被预填时，该字段在结账表单上预填并锁定。

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`tax_id` 参数需要至少有 `country` 字段的 `billing_address`。税务资格会实时验证，并且自动应用逆向收费规则，以便符合条件的 B2B 交易。
</Info>

使用 `allow_customer_editing_tax_id` 特性标志控制客户是否可以修改预填的税号，以及 `allow_tax_id` 切换结账时税号的可见性。

了解更多：[结账会话 - 税号](/developer-resources/checkout-session) | [B2B 付款](/features/b2b-payments)

### 7. **返回 URL 重定向中的许可证密钥和电子邮件**

在客户完成结账后，Dodo Payments 现在将 `license_key` 和 `email` 作为查询参数附加到您的 `return_url` 重定向中，此外还有现有的 `payment_id`/`subscription_id` 和 `status` 参数。

**附加查询参数**

| 参数 | 类型 | 条件 |
|-----------|------|-----------|
| `payment_id` | `string` | 对于一次性付款始终存在 |
| `subscription_id` | `string` | 对于订阅付款始终存在 |
| `status` | `string` | 始终存在 |
| `license_key` | `string` | 如果产品启用许可证密钥（多个以逗号分隔）则存在 |
| `email` | `string` | 如果客户记录有电子邮件则存在 |

**示例重定向 URL：**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
使用这些查询参数在您的返回页面上显示许可证密钥或立即发送确认电子邮件，而无需额外的 API 调用。
</Tip>

了解更多：[结账会话 - 返回 URL](/developer-resources/checkout-session) | [返回 URL 中的许可证密钥](/features/license-keys#license-keys-in-return-url)

### 8. **客户电子邮件更新 API**

`PATCH /customers/{customer_id}` 端点现在支持以编程方式更新客户电子邮件地址。可以在一次 API 调用中更新电子邮件及姓名、电话号码和元数据。

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**可更新字段**

| 字段 | 类型 | 描述 |
|-------|------|-------------|
| `email` | `string \| null` | 客户的电子邮件地址 |
| `name` | `string \| null` | 客户的显示名称 |
| `phone_number` | `string \| null` | 符合国际格式的电话号码 |
| `metadata` | `object \| null` | 自定义键值对 |

<Info>
客户电子邮件更新也可以通过客户门户（自助服务），仪表板，以及通过 `dodo customers update` 的 CLI 获得。
</Info>

### 9. **Bun 适配器发布**

推出 `@dodopayments/bun` -- 专为 [Bun](https://bun.sh) 的原生服务器 (`Bun.serve()`) 设计的专用框架适配器。用几行代码将结账、客户门户和 webhook 与 Bun 集成。

**安装**

```bash
bun add @dodopayments/bun
```

**快速设置**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Bun 适配器支持所有三种结账流程（静态、动态和基于会话），客户门户会话生成，以及通过签名验证和 Zod 验证处理的安全 webhook，涵盖 22 种事件类型。
