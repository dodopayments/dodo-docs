Dodo Agent Plugin 可在一次安装中将两个 MCP servers 和十七项集成 skills 接入您的 AI coding agent。它支持 **Claude Code**、**Codex CLI**、**Cursor** 和 **OpenCode** — 并且 MCP servers 和 skills CLI 可与任何兼容 MCP 的客户端配合使用。

<Info>
**三大基础组件，一个 plugin。** Agent Plugin 打包了您所需的一切：
- **API MCP server** — 实时访问 payments、subscriptions、customers、products、refunds、licenses 和 usage。通过 browser OAuth 进行身份验证（无需本地 keys）。
- **Knowledge MCP server** — 对所有 Dodo Payments 文档进行语义搜索。无需 credentials。
- **十七项 agent skills** — 您的 agent 可按需加载的速查表，涵盖 checkout、subscriptions、webhooks、usage-based 和 credit-based billing、license keys、product catalog、discounts、localized pricing、mobile checkout、refunds 和 disputes、customer management、framework adapters、BillingSDK、Better Auth、testing 和 go-live，以及最佳实践。
</Info>

## 安装插件

在下方选择您的 coding agent。安装过程会自动添加两个 MCP servers 和全部十七项 skills。

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
从市场安装：

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP 服务器默认使用浏览器 OAuth —— 安装时不需要密钥。您的代理首次调用 Dodo 工具时，会提示您登录。

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  源码、配置选项和本地开发说明
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex 通过两个步骤安装插件：从您的 shell 注册市场，然后从 Codex TUI 内安装插件。

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
打开 Codex 并运行 `/plugins` 斜杠命令：

```bash
codex
```

然后输入 `/plugins`，切换到 **Dodo Payments** 市场，选择 **dodopayments** 插件，并选择 **安装插件**。
</Step>
</Steps>

安装 plugin 后，两个 MCP servers 和全部十七项 skills 都会自动注册。

<Note>
Codex CLI 没有 `codex plugin install` 子命令 —— 插件安装总是通过 in-TUI `/plugins` 流程进行。查看 [官方 Codex 插件文档](https://developers.openai.com/codex/plugins)。
</Note>

如果您之前添加了市场且插件未显示在 `/plugins`，下拉刷新：

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
手动安装 —— 将 repo 克隆到 Cursor 的本地插件目录：

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

重启 Cursor。插件从 `.claude/skills/` 加载技能（通过 Cursor 的 Claude Code 兼容层），从 `.mcp.json` 加载 MCP 服务器。

<Info>
Cursor 市场支持即将推出。暂时，请使用上述手动安装。
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode 通过 npm 分发。将插件添加到您的 `opencode.json`：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

重启 OpenCode。两个 MCP servers（`dodopayments-api`、`dodo-knowledge`）会通过 plugin 的 config hook 自动注册，十七项 skills 则会从已安装的 package 中自动发现。无需手动添加 `mcp` block。
</Accordion>
</AccordionGroup>

<Info>
使用不同的代理？[MCP 服务器](/developer-resources/mcp-server) 和 [代理技能](/developer-resources/agent-skills) 指南涵盖 Cursor、Claude Desktop、VS Code、Windsurf、Cline、Zed 和任何 MCP 兼容的客户端。
</Info>

## 您将获得的内容

安装 plugin 后，您的 agent 即可访问两个 MCP servers 和十七项 skills。

### MCP 服务器

| 服务器 | 目的 | 认证 |
|--------|---------|------|
| `dodopayments-api` | 实时 API 访问 —— 支付、订阅、客户、产品、退款、许可证、使用情况 | OAuth（浏览器） |
| `dodo-knowledge` | 在所有 Dodo Payments 文档中进行语义搜索 | 无 |

两个服务器通过 `mcp-remote` 连接，因此它们可以在任何 MCP 兼容的客户端中运行。

### 代理技能

| Skill | Description |
|-------|-------------|
| `best-practices` | SDK 设置、environments、API keys，以及从 checkout 到 webhook 的标准架构 |
| `framework-adapters` | 适用于 Next.js、Express、Hono、Astro、Remix、SvelteKit、Nuxt、Fastify、TanStack、Bun 和 Convex 的官方 `@dodopayments/*` route handlers |
| `testing-and-go-live` | Test mode、test payment methods、webhook testing，以及 production launch checklist |
| `checkout-integration` | Checkout Sessions、payment links，以及 overlay 或 inline checkout |
| `subscription-integration` | Subscription lifecycle、trials、plan changes、proration 和 on-demand charges |
| `mobile-checkout` | 适用于 React Native、Flutter、iOS 和 Android 的 in-app checkout |
| `webhook-integration` | 使用 Standard Webhooks specification 接收并验证 webhooks |
| `credit-based-billing` | Credit entitlements、balances、ledger、rollover、overage 和基于 meter 的 deduction |
| `usage-based-billing` | Meters、event ingestion、aggregation 和 per-unit pricing |
| `license-keys` | License key activation、validation 和 instance management |
| `product-catalog-management` | Products、pricing、add-ons、collections、images 和 digital product delivery |
| `discounts-and-promotions` | Discount codes、eligibility rules、stacking 和 subscription-cycle limits |
| `localized-pricing` | Localized pricing、Adaptive Currency 和 purchasing power parity |
| `customer-management` | Customers、self-service portal、saved payment methods 和 wallets |
| `refunds-and-disputes` | Issuing refunds、handling disputes 和 chargebacks，以及 reconciling access |
| `billing-sdk` | 用于 pricing tables 和 billing UI 的 BillingSDK React components |
| `better-auth-integration` | 用于 customer sync、checkout 和 portal access 的 `@dodopayments/better-auth` plugin |

技能自动加载——您的代理在检测到相关任务时选择合适的技能。查看 [代理技能文档](/developer-resources/agent-skills) 获取完整列表和单独安装信息。

### 首先尝试此提示

插件激活后，请尝试：

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

您的代理将加载 `webhook-integration` 技能，使用 `dodo-knowledge` MCP 提取最新的负载形状，并按照标准 Webhooks 规范编写带签名验证的处理程序。

## 安全性和最佳实践

<Warning>
**永远不要提交生产 API 密钥。** 在开发过程中使用 [测试模式](/miscellaneous/test-mode-vs-live-mode)。Agent 插件默认使用浏览器 OAuth — 只有当您的工作流程需要时才切换到本地 API 密钥。
</Warning>

- **先使用测试模式。** 在上线前用 `dodo_test_...` 密钥对您的集成进行沙箱测试。参见 [测试模式与实时模式](/miscellaneous/test-mode-vs-live-mode)。
- **OAuth 是默认。** Agent 插件通过浏览器 OAuth 进行身份验证（没有本地秘密）。只有在需要时才使用 API 密钥模式 —— 见下面的配置部分。
- **审查代理生成的代码。** 始终验证 webhook 处理程序是否包含按 [标准 Webhooks 规范](https://standardwebhooks.com/) 进行的签名验证。

## 使用 API 密钥进行配置

默认情况下，Agent 插件使用远程 MCP 服务器与浏览器 OAuth —— 不需要本地凭证。如果您的工作流程需要本地 API 密钥（例如，CI 环境、无头服务器），可以切换到 stdio 模式。

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
在 Claude Code 中打开 `/plugins`，选择 **Dodo Payments**，并选择 **配置选项**。填写：

- `dodo_api_key` — 您的 `dodo_test_...` 或 `dodo_live_...` 密钥
- `dodo_webhook_key` — 您的 webhook 签名秘密
- `dodo_environment` — `test_mode` 或 `live_mode`

然后编辑 `.mcp.json` 以将 `dodopayments-api` 指向本地 stdio 服务器：

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

运行 `/reload-plugins` 以应用更改到当前会话。
</Accordion>

<Accordion title="Local API key mode — OpenCode">
根据您的需要在 `opencode.json` 中声明 `dodopayments-api` —— 您的入口将取代插件的默认远程服务器：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

重新启动 OpenCode 以应用。
</Accordion>
</AccordionGroup>
