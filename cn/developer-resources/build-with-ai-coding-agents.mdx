Dodo Agent Plugin 一次安装即可将两个 MCP servers 和十七个 integration skills 接入你的 AI coding agent。它支持 **Claude Code**、**Codex CLI**、**Cursor**、**VS Code / GitHub Copilot**、**Kiro** 和 **OpenCode**。**Gemini CLI** 仅支持两个 MCP servers。MCP servers 和 skills CLI 适用于任何兼容 MCP 的客户端。

该 plugin 遵循 [Agent Plugins 1.0.0](https://agent-plugins.org/specification) 规范，因此具备原生支持的客户端可以直接从根目录 `plugin.json` 和 `mcp.json` 加载它。不支持该规范的旧客户端则通过生成的兼容性 manifests 加载相同内容。

<Info>
**三种基础能力，一个 plugin。** Agent Plugin 包含你所需的一切：
- **API MCP server** — 实时访问 payments、subscriptions、customers、products、refunds、licenses 和 usage。通过浏览器 OAuth 进行身份验证（无需本地 keys）。
- **Knowledge MCP server** — 跨所有 Dodo Payments 文档进行语义搜索。无需 credentials。
- **十七个 agent skills** — agent 按需加载的速查表，涵盖 checkout、subscriptions、webhooks、usage-based 和 credit-based billing、license keys、product catalog、discounts、localized pricing、mobile checkout、refunds 和 disputes、customer management、framework adapters、BillingSDK、Better Auth、testing 和 go-live，以及 best practices。
</Info>

## 安装 plugin

在下方选择你的 coding agent。每种安装方式都会添加两个 MCP servers；除 Gemini CLI 外，其他客户端还会添加十七个 skills。

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
从 marketplace 安装：

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP server 默认使用浏览器 OAuth——安装时无需 keys。agent 首次调用 Dodo tool 时，系统会提示你登录。

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  源代码、配置选项和本地开发说明
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex 分两步安装 plugins：先从 shell 注册 marketplace，再在 Codex TUI 内安装 plugin。

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
打开 Codex 并运行 `/plugins` slash command：

```bash
codex
```

然后输入 `/plugins`，切换到 **Dodo Payments** marketplace，选择 **dodopayments** plugin，并选择 **Install plugin**。
</Step>
</Steps>

安装 plugin 后，两个 MCP servers 和全部十七个 skills 都会自动注册。

<Note>
Codex CLI 没有 `codex plugin install` subcommand——plugin 安装始终通过 TUI 内的 `/plugins` 流程完成。请参阅 [Codex 官方 plugins 文档](https://developers.openai.com/codex/plugins)。
</Note>

如果你之前已添加 marketplace，但 plugin 没有显示在 `/plugins` 下方，请刷新它：

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
手动安装——将 repo clone 到 Cursor 的本地 plugins 目录：

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

重启 Cursor。plugin 会从 `skills/` 加载 skills，并从 `.mcp.json` 加载 MCP servers，这些内容在 `.cursor-plugin/plugin.json` 中声明。

<Info>
新版 Cursor 也能直接识别 Agent Plugins 1.0.0，并接受 `.cursor-plugin/marketplace.json` 或 `.claude-plugin/marketplace.json` 作为 marketplace source。该 plugin 提供 `.claude-plugin/marketplace.json`——请使用该路径。生成的 `.cursor-plugin/plugin.json` 会保留给旧版本使用。
</Info>

<Warning>
0.5.0 之前的版本将 `skills/` 作为指向 git submodule 的 symlinks 提供，因此这种 clone 得到的 plugin **没有可用的 skills**。现在 skills 以真实文件形式提供。如果你安装过早期版本，请删除该目录后重新 clone。
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode 通过 npm 分发。将 plugin 添加到你的 `opencode.json`：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

重启 OpenCode。两个 MCP servers（`dodopayments-api`、`dodo-knowledge`）会通过 plugin 的 config hook 自动注册。无需手动添加 `mcp` block。

**Skills 还需要额外添加一行。** OpenCode 不会扫描已安装的 packages 来查找 skills，因此请自行将其指向 package 的 `skills/` 目录：

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

相对 `skills.paths` 条目会相对于 **project directory** 解析，因此 package 必须存在于该项目的 `node_modules` 中——OpenCode 自己的 plugin cache 位于其他位置。绝对路径同样有效，并且可以避免本地安装要求。

<Warning>
不存在的 skills path 会被**静默**忽略。请验证而不要想当然：

```bash
opencode run "List every skill available to you by name."
```

你应该能看到全部十七个 skills。0.5.0 之前的版本文档称这些 skills 会自动发现——实际上并不会，因此 OpenCode 用户只有 MCP servers，没有 skills。
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
将 repo clone 到任意位置，然后注册它：

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

打开 Chat view，进入 **Plugins**，然后添加 clone 的文件夹。你也可以直接在 `settings.json` 中注册它：

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

key 是路径，value 用于启用它。绝对路径和 `~/` 都有效；相对路径会相对于每个 workspace folder 解析。该设置会实时读取，因此运行中的窗口无需重启即可应用。Skills 从 `skills/` 加载，两个 MCP servers 都从 `.mcp.json` 加载。

<Note>
`chat.pluginLocations` 标记为**实验性**，并且属于*受限*设置，因此 workspace 必须受信任才能应用。Agent-plugin 支持整体上仍是 preview feature，由 `chat.plugins.enabled` 控制，该功能**默认开启**——只有在组织通过 policy 禁用它时，才需要设置此项。
</Note>

<Info>
VS Code 不会根据 Agent Plugins `$schema` 进行识别。其 loader 会依次检查 `.plugin/plugin.json`、`.claude-plugin/plugin.json`，然后检查根目录 `plugin.json`，并将 MCP 默认设置为 `.mcp.json`，而不是 `mcp.json`。由于此 repo 提供了生成的 `.claude-plugin/plugin.json`，VS Code 会通过该兼容分支加载它，并获得 `mcp-remote` bridge，而不是 `mcp.json` 中的原生 transports。一切都能正常工作——只是路径不同。
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro 原生读取 Agent Plugins manifest，并将其加载为 Power。

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
在 Kiro 中，打开 Powers panel——即带闪电图标的 Ghosty 图标。
</Step>

<Step title="Import the folder">
选择 **Add Custom Power → Import power from a folder**，选择 clone 的目录（包含 `plugin.json` 的目录），然后点击 **Install**。
</Step>
</Steps>

Skills 从 `skills/` 加载，MCP servers 从 `mcp.json` 加载，Kiro 专属 presentation 则来自 `plugin.json` 中的 `dev.kiro` extension namespace。

<Note>
对于 Agent Plugins 格式的 plugins，Kiro 会在内部管理 MCP servers——它们**不会**写入用户级别的 `~/.kiro/settings/mcp.json`，因此不要期待在那里找到它们。Kiro 也可以直接从 GitHub URL 安装 Power；请参阅 [Kiro 安装文档](https://kiro.dev/docs/powers/installation/)。
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI 没有 agent-skill primitive，因此**只能使用两个 MCP servers**——十七个 skills 不可用。`dodo-knowledge` 仍然覆盖 skills 所提供功能中的很大一部分，并且会自动保持最新。

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

重启 Gemini CLI。repo 根目录中的 `gemini-extension.json` 就是 manifest。
</Accordion>
</AccordionGroup>

<Info>
使用其他 agent？[MCP Server](/developer-resources/mcp-server) 和 [Agent Skills](/developer-resources/agent-skills) 指南涵盖 Claude Desktop、Windsurf、Cline、Zed 以及任何兼容 MCP 的客户端。
</Info>

## 你将获得什么

安装 plugin 后，你的 agent 就可以访问两个 MCP servers 和十七个 skills。

### MCP servers

| Server | Purpose | Auth |
|--------|---------|------|
| `dodopayments-api` | 实时 API 访问——payments、subscriptions、customers、products、refunds、licenses、usage | OAuth（浏览器） |
| `dodo-knowledge` | 跨所有 Dodo Payments 文档进行语义搜索 | None |

两个 servers 都使用 Streamable HTTP。规范的 `mcp.json` 以原生方式声明它们（`type: "streamable-http"`），Codex CLI 和 Kiro 等原生支持该规范的客户端会使用这种方式。生成的兼容性 manifest `.mcp.json` 则通过 `mcp-remote` 连接同样的两个 endpoints，因此也能在无法直接连接 Streamable HTTP 的客户端中运行——Claude Code、VS Code，以及通过上文记录的 git-clone 安装方式安装的 Cursor，其 `.cursor-plugin/plugin.json` 会指向 `.mcp.json`。

### Agent skills

| Skill | Description |
|-------|-------------|
| `dodo-best-practices` | SDK 设置、environments、API keys，以及标准的 checkout-to-webhook 架构 |
| `framework-adapters` | Next.js、Express、Hono、Astro、Remix、SvelteKit、Nuxt、Fastify、TanStack、Bun 和 Convex 的官方 `@dodopayments/*` route handlers |
| `testing-and-go-live` | Test mode、test payment methods、webhook testing 和 production launch checklist |
| `checkout-integration` | Checkout Sessions、payment links，以及 overlay 或 inline checkout |
| `subscription-integration` | Subscription 生命周期、trials、plan changes、proration 和 on-demand charges |
| `mobile-checkout` | React Native、Flutter、iOS 和 Android 的 in-app checkout |
| `webhook-integration` | 使用 Standard Webhooks 规范接收和验证 webhooks |
| `credit-based-billing` | Credit entitlements、balances、ledger、rollover、overage 和基于 meter 的 deduction |
| `usage-based-billing` | Meters、event ingestion、aggregation 和按单位定价 |
| `license-keys` | License key activation、validation 和 instance management |
| `product-catalog-management` | Products、pricing、add-ons、collections、images 和 digital product delivery |
| `discounts-and-promotions` | Discount codes、eligibility rules、stacking 和 subscription-cycle limits |
| `localized-pricing` | Localized pricing、Adaptive Currency 和 purchasing power parity |
| `customer-management` | Customers、self-service portal、saved payment methods 和 wallets |
| `refunds-and-disputes` | Issuing refunds、处理 disputes 和 chargebacks，以及 reconciliating access |
| `billing-sdk` | 用于 pricing tables 和 billing UI 的 BillingSDK React components |
| `better-auth-integration` | 用于 customer sync、checkout 和 portal access 的 `@dodopayments/better-auth` plugin |

Skills 会自动加载——agent 检测到相关任务后会选择正确的 skill。完整列表和单独的安装说明请参阅 [Agent Skills 文档](/developer-resources/agent-skills)。

### 首先尝试此 prompt

plugin 激活后，请尝试：

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

你的 agent 会加载 `webhook-integration` skill，使用 `dodo-knowledge` MCP 获取最新的 payload shapes，并按照 Standard Webhooks spec 编写包含 signature verification 的 handler。

## 客户端支持

### 支持 Agent Plugin 安装的客户端

一次安装即可连接两个 MCP servers，并在具备 skill primitive 的每个客户端上启用 skills。

| Agent | Install | Skills | MCP servers |
|-------|---------|-------:|------------:|
| **Claude Code** | marketplace command | 17 | 2 |
| **Codex CLI** | marketplace command | 17 | 2 |
| **Cursor** | git clone | 17 | 2 |
| **VS Code / GitHub Copilot** | git clone | 17 | 2 |
| **Kiro** | git clone | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | git clone | 0 | 2 |

- **OpenCode** 需要额外添加一个 `skills.paths` 条目，之后十七个 skills 才会加载——请参阅上方的安装部分。
- **Gemini CLI** 没有 agent-skill primitive，因此 skills 按设计在其中不可用。

### 其他兼容 MCP 的客户端

这些客户端不支持 Agent Plugin 安装。请手动配置两个 MCP servers，并在支持的情况下通过 Skills CLI 添加 skills。

| Agent | MCP servers | Skills |
|-------|-------------|--------|
| Claude Desktop | [MCP Server 指南](/developer-resources/mcp-server) | 不支持 |
| Windsurf | [MCP Server 指南](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / others | [MCP Server 指南](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## 安全与最佳实践

<Warning>
**绝不要提交 production API keys。** 开发期间请使用 [test mode](/miscellaneous/test-mode-vs-live-mode)。Agent Plugin 默认使用浏览器 OAuth——只有在 workflow 需要时才切换到本地 API keys。
</Warning>

- **先使用 test mode。** 上线前使用 `dodo_test_...` keys 在 sandbox 中测试 integration。请参阅 [Test Mode vs Live Mode](/miscellaneous/test-mode-vs-live-mode)。
- **OAuth 是默认方式。** Agent Plugin 通过浏览器 OAuth 进行身份验证（无需本地 secrets）。只有在确有需要时才使用 API-key mode——请参阅下方的 Configure 部分。
- **审查 agent 生成的代码。** 始终确认 webhook handlers 按照 [Standard Webhooks spec](https://standardwebhooks.com/) 包含 signature verification。

## 使用 API key 配置

默认情况下，Agent Plugin 使用带浏览器 OAuth 的远程 MCP server——无需本地 credentials。如果你的 workflow 需要本地 API key（例如 CI environments、headless servers），可以切换到 stdio mode。

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
在 Claude Code 中打开 `/plugins`，选择 **Dodo Payments**，然后选择 **Configure options**。填写：

- `dodo_api_key`——你的 `dodo_test_...` 或 `dodo_live_...` key
- `dodo_webhook_key`——你的 webhook signing secret
- `dodo_environment`——`test_mode` 或 `live_mode`

然后编辑 `.mcp.json`，将 `dodopayments-api` 指向本地 stdio server：

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

运行 `/reload-plugins`，将更改应用到当前 session。
</Accordion>

<Accordion title="Local API key mode — OpenCode">
在 `opencode.json` 中自行声明 `dodopayments-api`——你的 entry 会覆盖 plugin 的默认 remote server：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

重启 OpenCode 以应用更改。
</Accordion>
</AccordionGroup>
