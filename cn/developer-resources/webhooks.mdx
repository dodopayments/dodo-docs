Webhooks 在 Dodo Payments 账户中发生特定事件时提供实时通知。使用 webhooks 来自动化工作流程、更新数据库、发送通知，并保持系统同步。

<Info>
我们的 webhook 实现遵循 [Standard Webhooks](https://standardwebhooks.com/) 规范，确保与行业最佳实践和现有 webhook 库兼容。
</Info>

<Step title="Select Events to Receive">
    通过从事件列表中选择特定事件来选择您的 webhook 端点应监听的事件。

    只有选定的事件会触发发送到您的端点的 webhooks，帮助您避免不必要的流量和处理。

<Step title="Get Secret Key">

    <Warning>
    确保您的 webhook 秘密密钥安全，绝不要在客户端代码或公共存储库中公开。
    </Warning>

<Step title="Rotate Secret (Optional)">

    <Warning>
    旋转密钥将 **过期它** 并用新的替换它。旧密钥在接下来的 24 小时内有效。之后，尝试用旧密钥验证将失败。
    </Warning>
    
    <Info>
    定期使用密钥旋转或在怀疑当前密钥已被泄露时立即使用。
    </Info>
</Step>
</Steps>

## Webhook 传递

### 超时

Webhooks 对连接和读取操作有一个 **15 秒的超时窗口**。确保您的端点快速响应以避免超时。

<Tip>
通过立即用 `200` 状态码确认接收来异步处理 webhooks，然后在后台处理实际处理。
</Tip>

### 自动重试

如果 webhook 传递失败，Dodo Payments 会自动重试并进行指数退避，以防止系统超负荷。

| 尝试次数 | 延迟 | 描述 |
|---------|------------------------------|-------------|
| 1 | 立即 | 第一次重试立刻发生 |
| 2 | 5 秒 | 第二次尝试在短暂延迟后进行 |
| 3 | 5 分钟 | 第三次尝试，增加退避 |
| 4 | 30 分钟 | 第四次尝试，继续退避 |
| 5 | 2 小时 | 第五次尝试，延长延迟 |
| 6 | 5 小时 | 第六次尝试，较长延迟 |
| 7 | 10 小时 | 第七次尝试，最大延迟 |
| 8 | 10 小时 | **最后一次尝试** - 如果不成功，webhook 标记为失败 |

<Info>
每个 webhook 事件最多 **8 次重试**。例如，如果一个 webhook 在成功之前失败了三次，那么从第一次尝试到最终成功的总传递时间大约是 35 分钟 5 秒。
</Info>

<Tip>
使用 Dodo Payments 仪表板手动重试个别消息或在任何时候批量恢复所有失败的消息。
</Tip>

### 幂等性

每个 webhook 事件都包含一个唯一的 `webhook-id` 头。使用此标识符实现幂等性以防止重复处理。

```javascript
// Example: Storing webhook IDs to prevent duplicate processing
const processedWebhooks = new Set();

app.post('/webhook', (req, res) => {
  const webhookId = req.headers['webhook-id'];
  
  if (processedWebhooks.has(webhookId)) {
    return res.status(200).json({ received: true });
  }
  
  processedWebhooks.add(webhookId);
  // Process the webhook...
});
```

<Warning>
始终实现幂等性检查。由于重试，您可能会多次收到相同事件。
</Warning>

### 事件排序

Webhook 事件可能由于重试或网络条件而无序到达。设计您的系统将能够处理任何顺序的事件。

<Info>
无论 webhook 事件最初何时发出，您都会在交付时收到**最新的有效负载**。
</Info>

## 保护 Webhooks

为了确保您的 webhooks 的安全性，请始终验证有效负载并使用 HTTPS。

### 验证签名

每个 webhook 请求都包含一个 `webhook-signature` 头，即 webhook 有效负载和时间戳的 HMAC SHA256 签名，使用您的密钥签名。

#### SDK 验证（推荐）

所有官方 SDK 都包括内置助手，用于安全验证和解析传入的 webhooks。提供两种方法：

* `unwrap()`: 使用您的 webhook 秘密密钥验证签名
* `unsafe_unwrap()`: 解析有效负载而不进行验证

<Tip>
  在初始化 Dodo Payments 客户端时，通过 `DODO_PAYMENTS_WEBHOOK_KEY` 提供您的 webhook 密钥。
</Tip>

<CodeGroup>

```typescript TypeScript/Node.js
import DodoPayments from 'dodopayments';
import express from 'express';

const app = express();
app.use(express.raw({ type: 'application/json' }));

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
});

app.post('/webhook', async (req, res) => {
  try {
    const unwrapped = client.webhooks.unwrap(req.body.toString(), {
      headers: {
        'webhook-id': req.headers['webhook-id'] as string,
        'webhook-signature': req.headers['webhook-signature'] as string,
        'webhook-timestamp': req.headers['webhook-timestamp'] as string,
      },
    });
    res.json({ received: true });
  } catch (error) {
    res.status(401).json({ error: 'Invalid signature' });
  }
});
```

```python Python
from fastapi import FastAPI, Request, HTTPException
from dodopayments import DodoPayments
import os

app = FastAPI()
client = DodoPayments(
    bearer_token=os.getenv("DODO_PAYMENTS_API_KEY"),
    environment=os.getenv("DODO_PAYMENTS_ENVIRONMENT"),
    webhook_key=os.getenv("DODO_PAYMENTS_WEBHOOK_KEY"),
)

@app.post("/webhook")
async def handle_webhook(request: Request):
    try:
        unwrapped = client.webhooks.unwrap(
            await request.body(),
            headers={
                "webhook-id": request.headers.get("webhook-id", ""),
                "webhook-signature": request.headers.get("webhook-signature", ""),
                "webhook-timestamp": request.headers.get("webhook-timestamp", ""),
            },
        )
        return {"received": True}
    except Exception:
        raise HTTPException(status_code=401, detail="Invalid signature")
```

```go Go
import (
	"context"
	"io"
	"net/http"
	"os"
	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func webhookHandler(w http.ResponseWriter, r *http.Request) {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
		option.WithEnvironment(os.Getenv("DODO_PAYMENTS_ENVIRONMENT")),
		option.WithWebhookKey(os.Getenv("DODO_PAYMENTS_WEBHOOK_KEY")),
	)
	rawBody, _ := io.ReadAll(r.Body)
	if _, err := client.Webhooks.Unwrap(context.Background(), rawBody, map[string]string{
		"webhook-id":       r.Header.Get("webhook-id"),
		"webhook-signature": r.Header.Get("webhook-signature"),
		"webhook-timestamp": r.Header.Get("webhook-timestamp"),
	}); err != nil {
		http.Error(w, "Invalid signature", http.StatusUnauthorized)
		return
	}
	w.WriteHeader(http.StatusOK)
}
```

#### 手动验证（替代方案）

如果您不使用 SDK，您可以按照 Standard Webhooks 规范自行验证签名：

1. 通过用点（`.`）分隔 `webhook-id`、`webhook-timestamp` 和准确的原始字符串化 `payload` 来构建签名消息。
2. 使用仪表板中的 webhook 秘密密钥计算该字符串的 HMAC SHA256。
3. 将计算出的签名与 `webhook-signature` 头进行比较。如果它们匹配，webhook 是可信的。

<Info>
  我们遵循 Standard Webhooks 规范。您可以使用他们的库来验证签名：[https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries](https://github.com/standard-webhooks/standard-webhooks/tree/main/libraries)。对于事件有效负载格式，请参见 [Webhook Payload](/developer-resources/webhooks/intents/payment)。
</Info>

### 响应 Webhooks

* 您的 webhook 处理程序必须返回一个 `2xx status code` 以确认收到事件。
* 任何其他响应将被视为失败，webhook 将被重试。

### 最佳实践

<AccordionGroup>
<Accordion title="Use HTTPS endpoints only" icon="lock">

</Accordion>

<Accordion title="Respond immediately" icon="bolt">

</Accordion>

<Accordion title="Handle duplicate events" icon="rotate">

</Accordion>

<Accordion title="Secure your webhook secret" icon="key">

</Accordion>

## Webhook 有效负载结构

了解 webhook 有效负载结构有助于您正确解析和处理事件。

### 请求格式

```http
POST /your-webhook-url
Content-Type: application/json
```

### 头

<ParamField header="webhook-id" type="string" required>
此 webhook 事件的唯一标识符。用于幂等性检查。
</ParamField>

<ParamField header="webhook-signature" type="string" required>
用于验证 webhook 真实性的 HMAC SHA256 签名。
</ParamField>

<ParamField header="webhook-timestamp" type="string" required>
发送 webhook 时的 Unix 时间戳（以秒为单位）。
</ParamField>

### 请求正文

<ResponseField name="business_id" type="string" required>
您的 Dodo Payments 业务标识符。
</ResponseField>

<ResponseField name="type" type="string" required>
触发此 webhook 的事件类型（例如，`payment.succeeded`，`subscription.active`）。
</ResponseField>

<ResponseField name="timestamp" type="string" required>
事件发生时的 ISO 8601 格式时间戳。
</ResponseField>

<ResponseField name="data" type="object" required>
事件特定有效负载，包含有关事件的详细信息。

<Expandable title="Data object properties">
  <ResponseField name="payload_type" type="string">
  资源类型。以下类型之一：`Payment`、`Subscription`、`Refund`、`Dispute`、`LicenseKey`、`CreditLedgerEntry`、`CreditBalanceLow`、`AbandonedCheckout`、`DunningAttempt`、`EntitlementGrant` 或 `Payout`。
  </ResponseField>
  
  其他字段因事件类型而异。有关完整 schema，请参阅特定事件的文档。
</Expandable>
</ResponseField>

```json
  "timestamp": "2024-01-01T12:00:00Z",

  }
}
```

### 实现示例

以下是展示 webhook 验证和处理的完整 Express.js 实现：

<CodeGroup>

```typescript Express.js Webhook Handler
import { Webhook } from "standardwebhooks";
import express from "express";

const app = express();
app.use(express.json());

const webhook = new Webhook(process.env.DODO_WEBHOOK_SECRET);

app.post('/webhook/dodo-payments', async (req, res) => {
  try {
    // Extract webhook headers
    const webhookHeaders = {
      "webhook-id": req.headers["webhook-id"] as string,
      "webhook-signature": req.headers["webhook-signature"] as string,
      "webhook-timestamp": req.headers["webhook-timestamp"] as string,
    };

    // Verify the webhook signature
    const payload = JSON.stringify(req.body);
    await webhook.verify(payload, webhookHeaders);
    
    // Acknowledge receipt immediately
    res.status(200).json({ received: true });
    
    // Process webhook asynchronously
    processWebhookAsync(req.body).catch(console.error);
    
  } catch (error) {
    console.error('Webhook verification failed:', error);
    res.status(400).json({ error: 'Invalid signature' });
  }
});

async function processWebhookAsync(data: any) {
  // Handle the webhook event based on type
  switch (data.type) {
    case 'payment.succeeded':
      await handlePaymentSucceeded(data);
      break;
    case 'subscription.active':
      await handleSubscriptionActive(data);
      break;
    // Add more event handlers...
  }
}
```

## 使用 CLI 测试 Webhooks

[Dodo Payments CLI](/developer-resources/sdks/cli) 提供了两条命令，用于在本地开发期间测试 webhooks，而无需离开您的终端。

### 本地监听实时 Webhooks

将实际 webhook 事件从您的测试模式帐户实时转发到您的本地开发服务器：

```bash
dodo wh listen
```

CLI 打开一个与 Dodo Payments 的 WebSocket 连接，并将每个 webhook 事件转发到您的本地端点（例如，`http://localhost:3000/webhook`），保留包括签名头在内的所有头部以用于验证测试。

<Info>
监听器仅适用于 **测试模式** API 密钥。运行 `dodo login` 并选择测试模式，然后使用此命令。
</Info>

### 触发模拟 Webhook 事件

将模拟 webhook 负载发送到任何端点，而无需创建实际交易：

```bash
dodo wh trigger
```

此交互式工具允许你选择事件类型，并向你的端点发送逼真的模拟 payload。它会循环运行，因此你可以在一次会话中测试多个事件。

触发命令涵盖订阅、支付、退款、争议和许可证密钥事件——有关确切列表，请参阅[支持的 Webhook 事件](/developer-resources/sdks/cli#supported-webhook-events)。目前，支付结算、余额抵扣、已放弃结账、催收和权益授予事件尚无法通过模拟触发器使用；请使用 `dodo wh listen`，针对真实的测试模式交易进行测试。

<Warning>
来自 `dodo wh trigger` 的模拟 Webhook payload 未签名。仅在测试期间，在 Webhook handler 中使用 `unsafe_unwrap()`，而不是 `unwrap()`。
</Warning>

## 高级设置

高级设置选项卡提供了额外的配置选项，用于微调 Webhook 端点的行为。

### 速率限制（节流）

控制 Webhook 事件发送到端点的速率，避免系统过载。

<Steps>
<Step title="Access Rate Limit Settings">
    在 **Advanced** 选项卡中，找到“Rate Limit (throttling)”部分。
</Step>

<Step title="Configure Rate Limit">
    点击 **Edit** 按钮以修改速率限制设置。
    
    <Info>
    默认情况下，Webhook 应用“No rate limit”，这意味着事件会在发生后立即发送。
    </Info>
</Step>

<Step title="Set Limits">
    配置所需的速率限制，以控制 Webhook 的发送频率并防止系统过载。
</Step>
</Steps>

<Tip>
当 Webhook handler 需要时间处理事件，或你希望将多个事件批量处理时，可以使用速率限制。
</Tip>

### 自定义 Headers

向发送到端点的所有 Webhook 请求添加自定义 HTTP headers。这对于身份验证、路由或向 Webhook 请求添加元数据非常有用。

<Steps>
<Step title="Add Custom Header">
    在“Custom Headers”部分中，为自定义 header 输入 **Key** 和 **Value**。
</Step>

<Step title="Add Multiple Headers">
    根据需要点击 **+** 按钮添加其他自定义 headers。
</Step>

<Step title="Save Configuration">
    你的自定义 headers 将包含在发送到此端点的所有 Webhook 请求中。
</Step>
</Steps>

### 转换

转换功能允许你修改 Webhook 的 payload，并将其重定向到其他 URL。此强大功能可让你：

- 在处理前修改 payload 结构
- 根据内容将 Webhook 路由到不同端点
- 从 payload 中添加或移除字段
- 转换数据格式

<Steps>
<Step title="Enable Transformations">
    切换 **Enabled** 开关以启用转换功能。
</Step>

<Step title="Configure Transformation">
    点击 **Edit transformation** 以定义转换规则。
    
    <Info>
    你可以使用 JavaScript 转换 Webhook payload，并指定其他目标 URL。
    </Info>
</Step>

<Step title="Test Transformation">
    使用测试界面验证转换在上线前是否正常运行。
</Step>
</Steps>

<Warning>
转换可能会显著影响 Webhook 的发送性能。请充分测试，并保持转换逻辑简单高效。
</Warning>

<Tip>
转换尤其适用于：
- 在不同数据格式之间进行转换
- 根据特定条件筛选事件
- 向 payload 添加计算字段
- 将事件路由到不同的微服务
</Tip>

## Email Alerts

通过自动 Email 通知了解 Webhook 的运行状况。当 Webhook 发送开始失败或端点停止响应时，你会收到 Email alerts，从而可以快速解决问题，确保集成顺畅运行。

<Frame>
  <img src="/images/webhooks/alerting.png" alt="Webhook Alerting Settings showing email notifications configuration" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### 启用 Email Alerts

<Steps>
<Step title="Navigate to Alerting Settings">
  前往 Dodo Payments Dashboard，然后导航至 **Dashboard → Webhooks → Alerting**。
</Step>

<Step title="Enable Email Notifications">
  开启 **Email notifications**，开始接收有关 Webhook 发送问题的 alerts。
</Step>

<Step title="Configure Email Address">
  输入你希望接收 Webhook alerts 的 Email 地址。当 Webhook 设置发生某些事件（例如可能影响集成的发送问题）时，我们会向该地址发送通知。
</Step>
</Steps>

<Tip>
启用 Email alerts，以便及早发现 Webhook 发送问题并保持可靠的集成。当发送失败或端点无响应时，你会收到通知。
</Tip>
