## 前提条件

要集成 Dodo Payments API，您需要：
- 一个 Dodo Payments 商户账户
- 从仪表板获取的 API 凭证（API 密钥和 webhook 密钥）

## 仪表板设置

1. 访问 [Dodo Payments 仪表板](https://app.dodopayments.com/)

2. 创建产品（一次性付款或订阅）。订阅产品的定价必须至少为 **\$1**（或您所选货币的等值金额）；不支持低于此最低金额的定价。

4. 生成您的 API 密钥：
   - 前往开发者 > API
   - [详细指南](/api-reference/introduction#api-key-generation)
   - 将 API 密钥复制到名为 DODO_PAYMENTS_API_KEY 的环境变量中

5. 配置 webhooks：
   - 前往开发者 > Webhooks
   - 创建用于支付通知的 webhook URL
   - 将 webhook 密钥复制到环境变量中

## 集成

### 支付链接

选择适合您使用场景的集成路径：
- **Checkout Sessions（推荐）**：适用于大多数集成。在您的服务器上创建 session，然后将客户重定向到安全的托管结账页面。
- **Overlay Checkout**：当您需要在页面内以模态叠加层形式打开结账页面时使用。
- **Inline Checkout**：将结账页面直接嵌入页面布局，以实现完全集成且带有品牌样式的结账体验。
- **Static Payment Links**：无需代码、可立即分享的 URL，适用于快速收款。
- **Dynamic Payment Links**：以编程方式创建的链接。不过，我们推荐使用 Checkout Sessions，因为它提供更大的灵活性。
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**：适用于原生 Android、iOS、React Native 和 Flutter 应用。按照上述方式在服务器上创建 session，然后将 `checkout_url` 交给 SDK。

<Info>
Overlay Checkout 和 Inline Checkout 仅适用于浏览器——它们会将结账页面嵌入网页中。如果您正在构建原生移动应用，请在服务器上创建 checkout session，然后改用 [Mobile Checkout SDKs](/developer-resources/mobile-integration) 打开它。
</Info>

#### 1. Checkout Sessions

使用 Checkout Sessions 为一次性付款或订阅创建安全的托管结账体验。在您的服务器上创建 session，然后将客户重定向到返回的 `checkout_url`。

<Info>
Checkout sessions 默认有效期为 24 小时。如果传入 <code>confirm=true</code>，session 的有效期为 15 分钟，并且必须提供所有必填字段。
</Info>

<Steps>
<Step title="Create a checkout session">
  选择您偏好的 SDK，或调用 REST API。

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'prod_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python
  import os
  from dodopayments import DodoPayments

  client = DodoPayments(
      bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
      environment="test_mode",  # defaults to "live_mode"
  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "prod_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

  </Tab>

  <Tab title="REST API">

  ```javascript
  const response = await fetch('https://test.dodopayments.com/checkouts', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${process.env.DODO_PAYMENTS_API_KEY}`,
    },
    body: JSON.stringify({
      product_cart: [{ product_id: 'prod_123', quantity: 1 }],
      customer: { email: 'customer@example.com', name: 'John Doe' },
      return_url: 'https://yourapp.com/checkout/success',
    }),
  });
  const session = await response.json();
  ```

  </Tab>
  </Tabs>
</Step>

<Step title="Redirect customer to checkout">
  创建 session 后，将客户重定向到 `checkout_url` 以启动托管流程。

  ```javascript
  // Example in a browser context
  window.location.href = session.checkout_url;
  ```

</Step>
</Steps>

<Tip>
优先使用 Checkout Sessions，这是开始收款最快、最可靠的方式。如需高级自定义，请参阅完整的 <a href="/developer-resources/checkout-session">Checkout Sessions 指南</a>和 <a href="/api-reference/checkout-sessions/create">API Reference</a>。
</Tip>

#### 2. Overlay Checkout

如需无缝的页面内结账体验，请了解我们的 [Overlay Checkout](/developer-resources/overlay-checkout) 集成。客户无需离开您的网站即可完成付款。

#### 3. Inline Checkout

如需将结账页面直接嵌入页面，以实现完全集成的结账体验，请使用我们的 [Inline Checkout](/developer-resources/inline-checkout) 集成。您可以据此构建自定义订单摘要，并完全控制结账布局，同时由 Dodo Payments 安全地处理收款。

#### 4. Static Payment Links

Static payment links 允许您通过分享简单的 URL 快速收款。您可以通过传递 query parameters 预填客户信息、控制表单字段并添加自定义 metadata，从而自定义结账体验。

<Steps>
<Step title="Construct your payment link">
  从基础 URL 开始，并附加您的产品 ID：

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  包含必要的 query parameters：
  - <ParamField query="quantity" type="integer" default="1">要购买的商品数量。</ParamField>
  - <ParamField query="redirect_url" type="string" required>付款完成后用于重定向的 URL。</ParamField>
  <Note>
  重定向 URL 将以 query parameters 的形式包含付款详情，例如：<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  如果产品启用了 license keys，还会附加 `license_key` 参数（多个 key 以逗号分隔）：<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  将客户或账单字段作为 query parameters 添加，以简化结账流程。
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">客户的全名（如果提供了 firstName 或 lastName，则忽略此字段）。</ParamField>
      - <ParamField query="firstName" type="string">客户的名字。</ParamField>
      - <ParamField query="lastName" type="string">客户的姓氏。</ParamField>
      - <ParamField query="email" type="string">客户的电子邮件地址。</ParamField>
      - <ParamField query="country" type="string">客户所在国家/地区。</ParamField>
      - <ParamField query="addressLine" type="string">街道地址。</ParamField>
      - <ParamField query="city" type="string">城市。</ParamField>
      - <ParamField query="state" type="string">州或省。</ParamField>
      - <ParamField query="zipCode" type="string">邮政编码/ZIP code。</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true 或 false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  您可以禁用特定字段，使其对客户只读。当您已经拥有客户信息（例如已登录用户的信息）时，这非常有用。
  </Info>
  要禁用字段，请提供其值，并将相应的 <code>disable...</code> flag 设置为 <code>true</code>：
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Field         | Disable Flag         | Required Parameter |
      |---------------|---------------------|-------------------|
      | Full Name     | `disableFullName`   | `fullName`        |
      | First Name    | `disableFirstName`  | `firstName`       |
      | Last Name     | `disableLastName`   | `lastName`        |
      | Email         | `disableEmail`      | `email`           |
      | Country       | `disableCountry`    | `country`         |
      | Address Line  | `disableAddressLine`| `addressLine`     |
      | City          | `disableCity`       | `city`            |
      | State         | `disableState`      | `state`           |
      | ZIP Code      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  禁用字段有助于防止意外更改并确保数据一致性。
  </Tip>
  <Note>
  设置 <code>showDiscounts=false</code> 将禁用并隐藏结账表单中的折扣部分。如果您不希望客户在结账时输入 coupon 或 promo code，请使用此设置。
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">指定付款货币。默认为账单国家/地区的货币。</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">显示或隐藏货币选择器。</ParamField>
  - <ParamField query="paymentAmount" type="integer">金额，以分为单位（仅适用于 Pay What You Want 定价）。</ParamField>
  - <ParamField query="metadata_*" type="string">自定义 metadata 字段（例如 <code>metadata_orderId=123</code>）。</ParamField>
</Step>
<Step title="Share the link">
  将完整的 payment link 发送给客户。当客户访问该链接时，所有 query parameters 都会被收集并与 session ID 一起存储。随后，URL 会被简化为仅包含 session parameter（例如 <code>?session=sess_1a2b3c4d</code>）。存储的信息会在页面刷新后保留，并可在整个结账过程中访问。
  <Check>
  现在，客户的结账体验会根据您的参数实现简化和个性化。
  </Check>
</Step>
</Steps>

### 实现 Webhooks

设置 API endpoint 以接收付款通知。以下是使用 Next.js 的示例：

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

我们的 webhook 实现遵循 [Standard Webhooks](https://standardwebhooks.com/) 规范。有关 webhook type definitions，请参阅我们的 [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide)。

#### 要监听的 Events

启用 `payload.type`，并处理与一次性付款流程相关的 events。至少应监听：

| Event Type           | When it fires                                              | What to do                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | 付款已成功处理。                        | 完成订单履约——授予访问权限、配置产品、发送收据。 |
| `payment.failed`     | 付款尝试失败（卡被拒绝、发生错误等）。       | 通知客户并提示重试；不要履约。                    |
| `payment.processing` | 付款已接受但仍在处理（异步方式）。 | 等待最终的 `payment.succeeded`/`payment.failed` ——暂时不要履约。 |
| `payment.cancelled`  | 付款在完成前被取消。                   | 释放所有保留状态，并将订单标记为已放弃。                       |

<Tip>
始终**根据 webhook 中的 `payment.succeeded` 履约**，而不是根据浏览器重定向履约——如果客户关闭标签页，重定向可能会被错过；而 webhook 会持续重试，直到收到确认。
</Tip>

如果您销售带有 license keys 的数字产品，还应处理 `license_key.created`。有关完整的 events 列表（包括订阅、entitlement、credit、recovery 和 dunning events），请参阅 [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide)。

您可以在 [GitHub](https://github.com/dodopayments/dodo-checkout-demo) 上参考这个使用 Next.js 和 TypeScript 实现 demo 的项目。

您可以[在此处](https://atlas.dodopayments.com/)查看在线实现。

## Checkout 与 Currency 的重要须知

<Warning>
**Dynamic（Pay-What-You-Want）金额使用产品的基础货币**，而不是任意的本地货币；基础货币仅限 **USD、INR、GBP 和 EUR**。要在其他货币（例如 PHP）中收取固定金额，不能直接传入该金额：请使用 **Adaptive Pricing**（按实时 FX 将基础金额转换）或 **Localized Pricing**（按货币设置固定价格，但与 Pay-What-You-Want 不兼容）。
</Warning>

<Tip>
**明确设置货币。**在 checkout session 中传入 `billing_currency` 和 `billing_address.country`。如果省略，系统会根据客户的 IP 检测货币和国家/地区（Adaptive Currency），结果可能与您计划收取的货币不一致。
</Tip>

<Info>
**Checkout sessions 将在 24 小时后过期**（设置 `confirm: true` 时为 15 分钟），并且每个 `checkout_url` 都是**一次性使用**——请为每位客户和每次付款尝试生成新的 session，而不要重复使用链接。
</Info>

<Info>
**一键重复购买。**对于保存了 payment method 的回头客，同时传入 `payment_method_id` 和 `confirm: true` 即可立即扣款，完全跳过 payment method 选择步骤。
</Info>
