## 安装

<Steps>
<Step title="Install the package">
在您的项目根目录运行以下命令：

```bash
npm install @dodopayments/hono
```

</Step>
<Step title="Set up environment variables">
在您的项目根目录创建一个<code>.env</code>文件：

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_RETURN_URL=https://yourapp.com/success
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode""
```

<Warning>
切勿将<code>.env</code>文件或密钥提交到版本控制中。
</Warning>
</Step>
</Steps>

## 结账路由处理器

<Info>
Dodo Payments 支持三种类型的支付流程以将支付集成到您的网站中，此适配器支持所有类型的支付流程。
</Info>

- **静态支付链接：** 可即时共享的 URL，用于快速、无代码的支付收集。
- **动态支付链接：** 使用 API 或 SDK 以编程方式生成具有自定义详细信息的支付链接。
- **结账会话：** 创建具有预配置产品购物车和客户详细信息的安全、可自定义结账体验。

## 客户门户路由处理器

客户门户路由处理器使您能够将 Dodo Payments 客户门户无缝集成到您的 Hono 应用程序中。

### 查询参数
<ParamField query="customer_id" type="string" required>
门户会话的客户 ID（例如，<code>?customer_id=cus_123</code>）。
</ParamField>
<ParamField query="send_email" type="boolean">
如果设置为<code>true</code>，则向客户发送带有门户链接的电子邮件。
</ParamField>

<Warning>
如果缺少<code>customer_id</code>，则返回 400。
</Warning>

## Webhook 路由处理器

- **方法：** 仅支持 POST 请求。其他方法返回 405。
- **签名验证：** 使用<code>webhookKey</code>验证 webhook 签名。如果验证失败，则返回 401。
- **有效负载验证：** 由 Zod 验证。无效的有效负载返回 400。
- **错误处理：**
  - 401：无效签名
  - 400：无效有效负载
  - 500：验证过程中内部错误
- **事件路由：** 基于有效负载类型调用相应的事件处理器。

**如果选择了结账路由处理器：**

**目的**：此处理器将用户重定向到 Dodo Payments 结账页面。

**集成**：
在您的 Hono 应用中创建两个路由 —— 一个用于静态（GET），另一个用于动态（POST）结账。

import { Checkout } from '@dodopayments/hono';
import Hono from 'hono'

const app = new Hono()

app.get(
  "/api/checkout",
  Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    type: 'static'
  })
);

app.post(
  "/api/checkout",
  Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    type: 'session' // or 'dynamic' for dynamic link
  })
);

配置选项：

    bearerToken：您的 Dodo Payments API 键（建议存储在 DODO_PAYMENTS_API_KEY 环境变量中）。

    returnUrl（可选）：用户结账成功后要重定向的 URL。

    environment："test_mode" 或 "live_mode"

    type："static"（GET）或 "dynamic"（POST）或 "session"（POST）

GET（静态结账）预期查询参数：

    productId（必需）

    数量、客户字段（fullName、email 等）以及元数据（metadata_*）可选。

POST（动态结账）预期包含支付详细信息的 JSON 正文（一次性或订阅）。参考文档获取完整 POST 架构：

    一次性支付：https://docs.dodopayments.com/api-reference/payments/post-payments

    订阅：https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions

POST（结账会话） - （推荐）更可定制的结账体验。返回带有 checkout_url 的 JSON：参数作为 JSON 正文发送。支持一次性和定期支付。返回：{"checkout_url": "https://checkout.dodopayments.com/session/..."}。有关支持字段的完整列表，请参阅：

  结账会话集成指南：https://docs.dodopayments.com/developer-resources/checkout-session

如果选择了客户门户路由处理器：

目的：此路由允许客户通过 Dodo Payments 门户管理其订阅。

集成：

import { Checkout } from '@dodopayments/hono';

查询参数：

    customer_id（必需）：例如，?customer_id=cus_123

    send_email（可选）：如果为 true，客户会收到带有门户链接的电子邮件

如果缺少 customer_id，则返回 400。

如果选择了 Webhook 路由处理器：

目的：处理来自 Dodo Payments 的传入 webhook 事件以触发应用中的事件。

集成：

import Hono from 'hono'
import { Webhooks } from '@dodopayments/hono'

const app = new Hono()
app.post(
  "/api/webhooks",
  Webhooks({
    webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
    onPayload: async (payload) => {
      // 处理负载
      console.log(payload)
    }
  })
);

特性：

    仅允许 POST 方法 — 其他方法返回 405

    使用 webhookKey 进行签名验证。如果无效，则返回 401。

    基于 Zod 的负载验证。如果无效架构，则返回 400。

    所有处理器都是异步函数。

支持的 Webhook 事件处理器：

您可以传入以下任何处理器：

    onPayload

    onPaymentSucceeded

    onPaymentFailed

    onPaymentProcessing

    onPaymentCancelled

    onRefundSucceeded

    onRefundFailed

    onDisputeOpened, onDisputeExpired, onDisputeAccepted, onDisputeCancelled, onDisputeChallenged, onDisputeWon, onDisputeLost

    onSubscriptionActive, onSubscriptionOnHold, onSubscriptionRenewed, onSubscriptionPlanChanged, onSubscriptionCancelled, onSubscriptionFailed, onSubscriptionExpired, onSubscriptionUpdated
