## 前提条件  

要集成 Dodo Payments API，您需要：  
- 一个 Dodo Payments 商户账户  
- 来自仪表板的 API 凭证（API 密钥和 webhook 密钥）  

有关前提条件的更详细指南，请查看此 [部分](/developer-resources/integration-guide#dashboard-setup)。  

## API 集成  

### 结账会话  

使用结账会话以安全的托管结账方式销售订阅产品。在 `product_cart` 中传递你的订阅产品，并将客户重定向到返回的 `checkout_url`。

<Tip>
**混合结账**：您可以在同一结账会话中将订阅产品与一次性产品结合使用。这使得像订阅的设置费用、与SaaS捆绑的硬件等用例成为可能。请参阅[结账会话指南](/developer-resources/checkout-session)以获取示例。
</Tip>

<Tabs>
<Tab title="Node.js SDK">

```javascript
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function main() {
  const session = await client.checkoutSessions.create({
    product_cart: [
      { product_id: 'prod_subscription_monthly', quantity: 1 }
    ],
    // Optional: configure trials for subscription products
    subscription_data: { trial_period_days: 14 },
    customer: {
      email: 'subscriber@example.com',
      name: 'Jane Doe',
    },
    return_url: 'https://example.com/success',
  });

  console.log(session.checkout_url);
}

main();
```

### Webhooks

在集成订阅时，您将收到 webhooks 以跟踪订阅生命周期。这些 webhooks 帮助您有效管理订阅状态和支付场景。

要设置您的 webhook 端点，请遵循我们的 [详细集成指南](/developer-resources/integration-guide#implementing-webhooks)。

#### 订阅事件类型

以下 webhook 事件跟踪订阅状态更改：

1. **`subscription.active`** - 订阅已成功激活。
2. **`subscription.updated`** - 订阅对象已更新（在任何字段更改时触发）。
3. **`subscription.on_hold`** - 由于续费失败，订阅已暂停。
4. **`subscription.failed`** - 在创建授权时订阅创建失败。
5. **`subscription.renewed`** - 订阅已续费到下一个账单周期。

为了可靠地管理订阅生命周期，我们建议跟踪这些订阅事件。

<Tip>
使用 `subscription.updated` 获取有关任何订阅更改的实时通知，保持你的应用状态同步，无需轮询 API。
</Tip>

#### 支付场景

**成功支付流程**

当支付成功时，您将收到以下 webhooks：

1. `subscription.active` - 表示订阅激活。  
2. `payment.succeeded` - 确认初始支付：
    - 对于即时计费（0试用天数）：预计在 2-10分钟内。
    - 对于试用天数：在试用结束时。
3. `subscription.renewed` - 表示付款扣除及续费下一个周期。（基本上，无论何时订阅产品的付款被扣除，你都会收到 `subscription.renewed` 的 webhook，以及 `payment.succeeded`）

**支付失败场景**

1. 订阅失败
  - `subscription.failed` - 由于创建授权失败，订阅创建失败。
  - `payment.failed` - 表示付款失败。

2. 订阅暂停
  - `subscription.on_hold` - 由于续费付款失败或更改计划收费失败，订阅已暂停。
  - 当订阅被暂停时，除非更新付款方式，否则不会自动续费。

<Info>**最佳实践**：为了简化实现，我们建议主要跟踪订阅事件以管理订阅生命周期。</Info>

### 处理订阅搁置

当订阅进入 `on_hold` 状态时，你需要更新付款方式以重新激活它。本节解释了订阅何时暂停以及如何处理它们。

#### 何时订阅被搁置

当以下情况发生时，订阅会被搁置：

- **续订支付失败**：由于资金不足、卡过期或银行拒绝，自动续订费用失败
- **计划变更费用失败**：在计划升级/降级期间，立即收费失败
- **支付方式授权失败**：支付方式无法授权进行定期收费

<Warning>
处于 `on_hold` 状态的订阅不会自动续费。你必须更新付款方式以重新激活订阅。
</Warning>

#### 从搁置状态重新激活订阅

要从 `on_hold` 状态重新激活订阅，请使用更新付款方式 API。这将自动：

1. 创建未付费用的收费
2. 生成收费的发票
3. 使用新付款方式处理付款
4. 在成功付款后再次激活订阅到 `active` 状态

<Steps>
<Step title="处理 subscription.on_hold webhook">
当你收到 `subscription.on_hold` 的 webhook 时，更新你的应用状态并通知客户：

```javascript
// Webhook handler
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;
  
  if (event.type === 'subscription.on_hold') {
    const subscription = event.data;
    
    // Update subscription status in your database
    await updateSubscriptionStatus(subscription.subscription_id, 'on_hold');
    
    // Notify customer to update payment method
    await sendEmailToCustomer(subscription.customer_id, {
      subject: 'Payment Required - Subscription On Hold',
      message: 'Your subscription is on hold. Please update your payment method to continue service.'
    });
  }
  
  res.json({ received: true });
});
```

## 更改订阅计划

您可以使用更改计划 API 端点升级或降级订阅计划。这允许您修改订阅的产品、数量，并处理按比例分配。

<Card title="更改计划 API 参考" icon="arrows-rotate" href="/api-reference/subscriptions/change-plan">
  有关更改订阅计划的详细信息，请参阅我们的更改计划 API 文档。
</Card>

### 按比例分配选项

在更改订阅计划时，您有两个选项来处理立即收费：

#### 1. `prorated_immediately`
- 根据当前账单周期剩余的时间计算按比例分配的金额
- 只向客户收取旧计划和新计划之间的差额
- 在试用期间，这将立即将用户切换到新计划，并立即向客户收费

#### 2. `full_immediately`
- 向客户收取新计划的全额订阅费用
- 忽略之前计划的任何剩余时间或余额
- 当你希望重置账单周期或无论如何收取全额费用时很有用

#### 3. `difference_immediately`
- 在升级时，客户会立即被收取两个计划金额之间的差价。
- 例如，如果当前计划是 30 美元，而客户升级到 80 美元，他们会立即被收取 50 美元。 
- 在降级时，当前计划中未使用的金额作为内部信用添加，并自动应用于未来的订阅续费。
- 例如，如果当前计划是 50 美元，而客户切换到 20 美元计划，那么剩余的 30 美元将被计入信用，并用于下一个账单周期。

### 行为

- 当你调用此 API 时，Dodo Payments 会立即根据你选择的按比例分配选项发起收费。
- 如果计划变更是降级，并且你使用 `prorated_immediately`，信用将被自动计算并添加到订阅的信用余额中。这些信用特定于该订阅，并且仅用于抵消同一订阅的未来定期付款。
- `full_immediately` 选项会绕过信用计算，并收取完整的新计划金额。

<Tip>
**仔细选择你的按比例分配选项**：使用 `prorated_immediately` 进行公平计费，考虑未使用的时间，或在你希望无论当前账单周期如何收取全额新计划费用时使用 `full_immediately`。
</Tip>

### 收费处理

- 在计划更改时发起的立即收费通常在 2 分钟内完成处理
- 如果此立即收费因任何原因失败，订阅将自动被搁置，直到问题解决

## 按需订阅

<Info>
  按需订阅让您灵活地向客户收费，而不仅仅是按照固定的时间表。此功能适用于所有账户。
</Info>

**要创建按需订阅：**

要创建按需订阅，请使用 [POST /subscriptions](/api-reference/subscriptions/post-subscriptions) API 端点，并在请求主体中包含 `on_demand` 字段。这允许你在不立即收费的情况下授权付款方式，或设置自定义初始价格。

**要收费按需订阅：**

对于后续收费，请使用 [POST /subscriptions/charge](/api-reference/subscriptions/create-charge) 端点，并指定要向客户收费的金额。

有关完整的逐步指南，包括请求/响应示例、安全重试策略和 webhook 处理，请参见 <a href="/developer-resources/ondemand-subscriptions">按需订阅指南</a>。
</Note>
