## API 密钥管理和身份验证

<Steps>
<Step title="Access API Keys">
在控制面板中依次进入 **Developer → API Keys** 以管理您的密钥。
</Step>

<Step title="Generate a New Key">
选择 **Add API Key**，提供描述性名称，并配置写入权限：

- **Enable write access**（已选中）：对所有 API 操作拥有完整的读取和写入权限
- **Enable write access**（未选中）：只读访问权限——只能获取数据（支付、订阅、客户、产品）。无法创建或修改资源。

<Tip>
对于控制面板集成、分析工具以及任何只需查看数据而无需进行更改的系统，请取消选中“Enable write access”。
</Tip>
</Step>

<Step title="Store Your Key Securely">
请立即复制生成的密钥，并确保将其安全存储。
</Step>

<Step title="Authenticate Your API Requests">
使用 API 密钥对所有请求进行身份验证。应用以下授权格式：

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
切勿在客户端代码或公共代码仓库中暴露您的秘密 API 密钥。
</Warning>
</Step>
</Steps>

## 速率限制

我们的 API 使用带有突发保护的双窗口速率限制系统。限制取决于您的身份验证方式和业务层级。

### 默认限制（Tier 0）

| 窗口 | 限制 |
|--------|-------|
| 每秒（突发） | 40 个请求 |
| 每分钟（持续） | 240 个请求 |

### 业务层级

对于 API 需求量较高的企业，我们提供更高的速率限制：

| 层级 | 突发（每秒） | 持续（每分钟） |
|------|-------------------|------------------------|
| Tier 0（默认） | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
请联系支持团队，将您的业务升级到更高的速率限制层级。
</Tip>

### 未经身份验证的请求

没有有效身份验证标头的请求将按 IP 地址进行速率限制：

| 窗口 | 限制 |
|--------|-------|
| 每秒（突发） | 20 个请求 |
| 每分钟（持续） | 100 个请求 |

### 速率限制标头

通过以下响应标头监控您的使用情况：

- `X-RateLimit-Limit` - 允许的最大请求数
- `X-RateLimit-Remaining` - 当前窗口中的剩余请求数
- `X-RateLimit-Reset` - 速率限制重置时间

<Note>
当您超出速率限制时，API 会返回 `429 Too Many Requests` 响应。在重试逻辑中实现指数退避。
</Note>
