## 什么是附加组件？

附加组件是在主要订阅之外，客户可以额外购买的补充产品。它们非常适合：

- **Seat-based billing**：额外的团队成员、用户许可或并发用户
- **Feature upgrades**：高级功能、进阶分析或优先支持
- **Usage extensions**：额外的存储、API 调用或带宽额度
- **Service add-ons**：专业服务、培训或咨询小时

## 主要优势

- **Flexible Pricing Models**：提供基础方案并配备可选附加组件，以构建复杂的定价结构。您可以通过随着客户需求变化而增长的升级功能来满足不同的客户群体。
- **Revenue Optimization**：展示相关附加组件以提升每位用户的平均收入（ARPU），从而在客户逐步添加功能时创造自然的追加销售机会。
- **Simplified Management**：从一个仪表板管理所有定价组件。附加组件会自动包含在结账会话和订阅管理中。
- **Customer Choice**：允许客户通过仅选择所需的附加组件来自定义订阅，从而提升满意度并减少流失。

## 创建附加组件

附加组件作为独立产品在 Dodo Payments 仪表板中创建，然后附加到您的主要订阅产品。这种分离使您能够：

- 在多个订阅产品中重用附加组件
- 独立管理定价
- 单独跟踪附加组件的表现
- 更新附加组件而不影响基础订阅

### 附加组件配置

创建附加组件时可以配置：

- **定价**：为附加项设置一次性或 recurring 定价
- **货币**：使用 Dodo Payments 可以收取的任意货币设置基础价格。可搜索的货币选择器会将 **USD、GBP、EUR 和 INR** 固定在顶部；基础货币以外的客户将通过 [Adaptive Currency](/features/adaptive-currency) 结算
- **计费周期**：必须与您的订阅计费周期匹配
- **数量限制**：设置每位客户的最小和最大数量
- **可用性**：控制哪些订阅产品可以使用该附加项
- **税务设置**：配置适用的税务类别

## 集成示例

### 带附加组件的结账会话
创建结账会话时，可按需包含附加组件及自定义数量：

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'your_subscription_id',
      quantity: 1,
      addons: [
        {
          addon_id: 'your_addon_id',
          quantity: 3 // 3 additional seats
        }
      ]
    }
  ],
  // ... other checkout options
});
```

<Tip>
要让客户在结账页面自行添加或移除附加组件，请在创建会话时，将 [`allow_editing_addons`](/developer-resources/checkout-session#optional-fields) 功能标志设置为 `true`。默认情况下为 `false`，并仅适用于订阅产品。

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'your_subscription_id', quantity: 1 }],
  feature_flags: {
    allow_editing_addons: true // customers can edit add-ons at checkout
  },
});
```

</Tip>

### 计划更改与附加组件
修改现有订阅以添加、移除或更新附加组件：

```typescript
// Add add-ons to existing subscription
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_new',
  quantity: 1,
  proration_billing_mode: 'difference_immediately',
  addons: [
    { addon_id: 'addon_123', quantity: 2 }
  ]
});

// Remove all existing add-ons
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_new',
  quantity: 1,
  proration_billing_mode: 'difference_immediately',
  addons: [] // Empty array removes all existing add-ons
});
```

### 动态定价
根据附加组件的选择动态计算总成本：

```typescript
function calculateTotalCost(basePrice: number, addons: AddonSelection[]) {
  const addonTotal = addons.reduce((sum, addon) => 
    sum + (addon.price * addon.quantity), 0
  );
  return basePrice + addonTotal;
}
```

## 最佳实践

- **从简开始**：推出 2-3 个核心附加组件，并根据客户反馈和使用情况扩展选项。
- **保持价格清晰**：明确传达附加组件的定价和价值，让客户了解他们所支付的额外费用所获得的内容。
- **彻底测试**：验证附加组件组合，确保价格计算准确无误，结账流程顺畅。

### 设计考量

- **明确的价值主张**：每个附加组件应具备客户易于理解的明确优势
- **逻辑分组**：在结账流程中将相关的附加组件进行分组
- **灵活的数量**：允许客户根据需要调整附加组件的数量
- **透明的定价**：在整个结账过程中清楚显示总成本

<Info>
附加组件是创建随客户增长的灵活、可扩展定价模型的强大方法。从简单的用例开始，随着了解哪些对您的业务和客户最有效，逐步扩展。
</Info>
