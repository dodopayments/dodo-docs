## 什么是本地化定价？

每个产品都有一个基础货币的基础价格。本地化定价允许您通过**为每种货币或国家设置的固定价格**来覆盖该基础价格。通过在产品上设置 `pricing_mode` 来开启此功能，然后为每个市场附加一条规则。

这是国际定价所采用的几个相互独立的调节手段之一，每个手段解决不同的问题：

| 机制 | 作用 | 客户看到的数字 |
| :--- | :--- | :--- |
| **本地化定价** | 为每种货币或每个国家设置固定价格 | 完全按照您设置的金额 |
| [**Adaptive Currency**](/features/adaptive-currency) | 按实时 FX 汇率自动转换基础价格 | 按当前汇率转换后的基础价格 |
| [**购买力平价**](/features/purchasing-power-parity) | 按国家自动收取您价格的一定比例 | 基础价格的一定百分比 |
| [**魅力定价**](/features/charm-pricing) | 将转换后的价格自动舍入为简洁的尾数 | 例如 49.99 这样的整洁数字 |
| [**折扣代码**](/features/discount-codes) | 在基础价格上按百分比减免 | 基础价格减去折扣 |

<Info>
本地化定价和自适应货币共同运作。当没有匹配的本地化规则时，产品会回落到其基础价格——如果客户已经使用您的基础货币，会直接收费，否则通过自适应货币转换。
</Info>

## 核心概念

- **定价模式** — 产品在同一时间只能处于一种模式，由其 `pricing_mode` 设置：
  - `by_currency`：每种货币对应一个价格，不受国家/地区影响。所有使用 EUR 付款的人都会看到 €9.99。
  - `by_country`：针对某个国家/地区设置的价格（印度为 ₹999），即使多个国家/地区使用同一种货币也不例外。
- **固定金额，以最小货币单位表示** — 规则的 `amount` 是以该货币最小单位表示的整数，与 API 中其他地方的规则相同：`99900` 表示 ₹999.00，`999` 表示 €9.99。这是您设置的价格，绝不会是转换后的金额。
- **匹配的规则优先于自动定价** — 当本地化规则应用于某个明细项时，[购买力平价](/features/purchasing-power-parity)和[魅力定价](/features/charm-pricing)都会跳过该明细项。客户支付的是您设置的金额，不做任何更改。
- **没有匹配规则时** — 产品会保留现有行为：使用您基础货币的客户直接支付基础价格；其他所有客户的价格都会通过 [Adaptive Currency](/features/adaptive-currency) 进行转换。
- **匹配规则时费用包含在内** — 客户支付的就是您设置的**确切金额**。[Adaptive Currency](/features/adaptive-currency#choose-who-bears-the-fee) 的 FX 费用由您承担（该笔交易按含费用处理），而不会额外加收，因此您声明的本地价格始终就是实际收取的价格。

## 通过API管理

本地化定价完全可通过API使用。首先设置产品的定价模式，然后附加规则。

### 设置定价模式

设置 `pricing_mode` 当您创建产品（或更新现有产品）时。`null` 意味着仅基础的现有行为。

<CodeGroup>

```typescript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode',
});

const product = await client.products.update('pdt_premium_plan', {
  pricing_mode: 'by_country',
});
```

```python theme={null}
import os
from dodopayments import DodoPayments

client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
    environment="test_mode",
)

product = client.products.update(
    "pdt_premium_plan",
    pricing_mode="by_country",
)
```

```go theme={null}
package main

import (
	"context"
	"os"

	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func main() {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
	)

	_, err := client.Products.Update(
		context.TODO(),
		"pdt_premium_plan",
		dodopayments.ProductUpdateParams{
			PricingMode: dodopayments.F(dodopayments.PricingModeByCountry),
		},
	)
	if err != nil {
		panic(err)
	}
}
```

</CodeGroup>

### 添加本地化价格

给产品附加一条规则。在 `by_country` 模式下，需要 `country_code`；在 `by_currency` 模式下则必须省略此项。

<CodeGroup>

```typescript theme={null}
// ₹999.00 for customers in India
const localizedPrice = await client.products.localizedPrices.create('pdt_premium_plan', {
  currency: 'INR',
  country_code: 'IN',
  amount: 99900,
});
```

```python theme={null}
# ₹999.00 for customers in India
localized_price = client.products.localized_prices.create(
    "pdt_premium_plan",
    currency="INR",
    country_code="IN",
    amount=99900,
)
```

```go theme={null}
// ₹999.00 for customers in India
localizedPrice, err := client.Products.LocalizedPrices.New(
	context.TODO(),
	"pdt_premium_plan",
	dodopayments.ProductLocalizedPriceNewParams{
		Currency:    dodopayments.F(dodopayments.CurrencyInr),
		CountryCode: dodopayments.F(dodopayments.CountryCodeIn),
		Amount:      dodopayments.F(int64(99900)),
	},
)
```

</CodeGroup>

对于 `by_currency` 产品，省略 `country_code`。例如，对所有使用EUR支付的人实行固定 `€9.99` （`currency: 'EUR'`，`amount: 999`）。

### 列出、更新和存档

您只能更新规则的`amount`；货币和国家一旦创建就固定。存档是一个幂等软删除，因此规则停止匹配但留在您的记录中。

<CodeGroup>

```typescript theme={null}
// List all active rules on a product
const rules = await client.products.localizedPrices.list('pdt_premium_plan');

// Change the amount (e.g. end a promo)
await client.products.localizedPrices.update('lcp_india_price', {
  product_id: 'pdt_premium_plan',
  amount: 119900,
});

// Archive a rule
await client.products.localizedPrices.archive('lcp_india_price', {
  product_id: 'pdt_premium_plan',
});
```

```python theme={null}
# List all active rules on a product
rules = client.products.localized_prices.list("pdt_premium_plan")

# Change the amount (e.g. end a promo)
client.products.localized_prices.update(

    product_id="pdt_premium_plan",
    amount=119900,
)

# Archive a rule
client.products.localized_prices.archive(
    "lcp_india_price",
    product_id="pdt_premium_plan",
)
```


## 结账时如何应用

本地化定价会根据每个购物车行项目进行解析，仅适用于设置了`pricing_mode` 的产品。Dodo Payments从请求中读取两个信号：客户的**计费国家**，以及可选的**`billing_currency`**（如果省略，则根据计费国家推导出货币）。

- **按国家**：查找与计费国家匹配的规则。如果存在，该客户会按规则的货币收取该规则的金额。
- **按货币**：查找与客户货币匹配的规则（`billing_currency`，或根据其国家推导出的货币）。如果存在，该客户会按该货币收取规则的金额。
- **无匹配或无`pricing_mode`**：适用基础价格，当客户的货币等于基础货币时直接收费，否则通过[自适应货币](/features/adaptive-currency)转换。

每个购物车项目都会单独解析，因此您可以在同一次结账中将一个产品本地化，而将其他产品保持基础定价。如果任何项目匹配本地化规则，整个交易都将强制费用包含（见[核心概念](#core-concepts)）。

## 订阅计划变更时的应用方式

本地化定价会在订阅者切换计划时随之生效。当现有订阅[变更计划](/features/subscription#subscription-plan-changes)并切换到包含 `pricing_mode` 的产品时，新计划的价格会按照与结账相同的规则确定，并使用订阅中已经锁定的账单国家/地区和货币：

- **按国家/地区**：应用与订阅账单国家/地区匹配的规则。如果规则的货币与订阅计费所用的货币不同，则按照实时 FX 汇率转换规则金额——规则会被应用，而不是跳过。
- **按货币**：应用与客户计费货币匹配的规则，并向客户收取与规则金额完全一致的金额。
- **无匹配项或无 `pricing_mode`**：应用新计划的基础价格，并在需要时通过 [Adaptive Currency](/features/adaptive-currency) 进行转换——这与结账时使用的回退机制相同。

无论计划变更从何处发起，均遵循此规则：[Change Plan API](/api-reference/subscriptions/change-plan)、[Customer Portal](/features/customer-portal) 中的自助计划变更，以及安排在计费周期结束时生效的变更。

- **预览结果准确无误。** [Preview Change Plan](/api-reference/subscriptions/preview-change-plan) 会返回实际变更收费时使用的相同本地化金额。
- **续订会保留本地化价格。** 变更后，新计划会以其本地化金额续订，并继续包含费用——与以该价格创建的订阅完全一致。
- **按实际金额计算按比例分摊。** 升级时，未使用时间的抵扣金额基于客户实际支付的旧计划金额；新计划则根据其本地化规则定价。
- **安排的变更会在安排时锁定价格。** 安排在计费周期结束时生效的变更，会收取安排时计算的金额，即使你在此期间编辑了规则也是如此。
- **计费货币不会改变。** 计划变更不会切换订阅结算所使用的货币；其他货币的规则会通过 FX 转换为该货币。
- **附加项不会本地化。** 新计划中的附加项价格始终使用其基础定价。

## 重要行为

| 行为 | 详情 |
| :--- | :--- |
| **税前金额** | 本地化金额是*税前*价格。对于不含税产品，结账时会在此基础上加收税费，因此本地化金额并不是最终总额。请参阅[含税定价](/features/tax-inclusive-pricing)。 |
| **不适用于 Pay What You Want** | 本地化规则不适用于 [Pay What You Want](/features/pay-what-you-want) 产品，因为客户可以自行选择金额。 |
| **按货币定价不同于基础价格** | `by_currency` 规则必须使用与产品基础货币不同的货币。 |
| **每个市场一个规则** | 一个产品针对每种货币（按货币）或每个国家/地区（按国家/地区）最多只能有一个有效规则。 |
| **所有产品类型** | 适用于一次性、订阅和按用量计费的产品——包括现有订阅者[变更计划](#how-it-applies-on-subscription-plan-changes)的情况。 |

<Info>
本地化规则变更不会触发专属 webhooks。解析后的金额会像其他任何价格一样，出现在生成的付款或订阅中。
</Info>

## 最佳实践

- **设置合理的基础价格。** 对于没有规则的所有市场，它都是通过 Adaptive Currency 转换后的备用价格。
- **输入整洁的数字。** 固定金额的意义就在于设置 ₹999、€9.99 或 ¥1000 这样整洁的价格，而不是得到 FX 结果。若要在所有货币中自动舍入价格，请参阅[魅力定价](/features/charm-pricing)。
- **根据需求选择模式。** 使用 `by_country` 进行购买力定价；当每个货币区域设置一个价格就足够时，使用 `by_currency`。
- **促销期间进行归档，而不是重新创建。** 归档规则会在保留历史记录的同时，将市场恢复为基础/自适应定价；之后可根据需要重新创建规则或重新定价。
- **宣传总价前注意税费。** 对于不含税产品，客户支付的是本地化金额*加上*税费，因此不要在广告中将其标为最终价格。
