## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## 在业务级别停用支付方式

你可以在控制面板中从业务级别停用特定支付方式。这会应用于你业务的所有结账会话，无需针对每个产品或会话单独配置。

<Steps>
<Step title="Navigate to Settings">
在 Dodo Payments 控制面板中前往 **Settings > Payment Methods**。
</Step>

<Step title="Disable Payment Methods">
关闭你不希望向客户提供的任何支付方式。
</Step>
</Steps>

<Tip>
使用此设置可以停用你所在地区欺诈率较高的支付方式，或仅保留业务在运营层面支持的支付方式。
</Tip>

<Info>
业务级别设置充当全局筛选器。通过 `allowed_payment_method_types` 设置的单次结账限制，会在业务级别已启用的支付方式范围内进一步缩小可用方式。
</Info>

## 配置单次结账的支付方式

除了业务级别设置外，你还可以使用 `allowed_payment_method_types` 限制单个结账会话中显示的支付方式：

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "pdt_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "pdt_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## 最佳实践

<AccordionGroup>
<Accordion title="Match methods to your market">
为你的目标市场提供区域性支付方式。iDEAL 覆盖了荷兰约 60% 的在线付款；UPI 在印度占据主导地位。省略这些支付方式会严重降低转化率。
</Accordion>

<Accordion title="Always provide card fallbacks">
即使针对特定支付方式，也应将 `credit` 和 `debit` 作为备用方式。并非所有客户都能使用每一种支付方式。
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL 方式有各自提供商规定的最低金额：Klarna 和 Afterpay 要求最低金额为 $50.01。对于不在这些金额范围内的产品，不要包含这些方式——它们不会显示，这没有问题。
</Accordion>

<Accordion title="Test across regions and devices">
上线前使用测试模式，验证不同客户所在地、货币和设备类型下的支付方式可用性。
</Accordion>
</AccordionGroup>

## 故障排除

<AccordionGroup>
<Accordion title="Payment method not appearing">
**检查以下因素：**
1. 是否在 `allowed_payment_method_types` 中包含了该支付方式？
2. 客户所在地是否与该支付方式支持的区域匹配？
3. 该支付方式是否支持交易货币？
    4. 交易金额是否在该支付方式支持的范围内（例如，Klarna/Afterpay 的最低金额为 $50.01）？
5. 对于订阅：该支付方式是否支持周期性付款？

**解决方案：** 临时移除 `allowed_payment_method_types`，以查看所有符合条件的支付方式，然后逐步缩小问题范围。
</Accordion>

<Accordion title="Unexpected methods appearing">
**可能的原因：**
- 未正确传递 `allowed_payment_method_types`
- 参数格式不正确（必须是字符串数组）

**解决方案：** 记录你的 API 请求负载，并验证参数结构。
</Accordion>

<Accordion title="Regional method not available">
**检查：**
- 客户账单地址是否与支付方式的区域匹配
- 货币是否设置正确（例如，iDEAL 使用 EUR）
- 如果客户来自国际地区，是否已启用 Adaptive Currency

**解决方案：** 在 API 请求中验证账单地址国家/地区代码和货币。
</Accordion>

<Accordion title="Indian payment method issues">
UPI 和 Rupay 订阅有独特的要求，包括 48 小时处理延迟和 RBI 授权限额。

**参见：** <a href="/features/payment-methods/india">印度支付方式</a>，获取完整指南。
</Accordion>
</AccordionGroup>
