## 工作原理

支付方式会根据以下内容自动向客户展示：

- **客户位置** — iDEAL（荷兰）或 UPI（印度）等区域性支付方式仅在客户位于这些地区时出现
- **交易货币** — 支付方式按支持的货币进行过滤
- **设备类型** — Apple Pay 仅在兼容的 Apple 设备和浏览器上显示
- **交易类型** — 一些支付方式不支持订阅或有最低金额要求

<Info>
**自动激活：**所有支付方式由 Dodo Payments 预配置并管理。无需额外设置——一旦账户通过验证并启用实时模式，即会可用。
</Info>

## 配置支付方式

默认情况下，所有符合条件的支付方式都会自动显示。使用`allowed_payment_method_types`来限制显示的方法：

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## 最佳实践

<AccordionGroup>
<Accordion title="Match methods to your market">
包含目标市场的区域支付方式。在荷兰，iDEAL占线上支付的约60%；在印度，UPI占主导地位。省略这些方法会显著影响转化率。
</Accordion>

<Accordion title="Always provide card fallbacks">
即便针对特定方法，亦包括`credit`和`debit`作为备选。并非所有客户都能访问每种支付方式。
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL方法（Klarna, Afterpay）需要最低$50.01。不要为低价商品纳入它们 — 它们不会出现，这没问题。
</Accordion>

<Accordion title="Test across regions and devices">
使用测试模式验证不同客户位置、货币和设备类型的支付方式可用性，然后上线。
</Accordion>
</AccordionGroup>

## 故障排除

<AccordionGroup>
<Accordion title="Payment method not appearing">
**检查以下因素：**
1. 是否在`allowed_payment_method_types`中包含了方法？
2. 客户位置是否符合方法支持的区域？
3. 交易货币是否为方法支持的币种？
4. 交易金额是否达到最低要求（例如，BNPL的$50.01）？
5. 对于订阅：方法是否支持定期付款？

**解决方案：** 暂时移除`allowed_payment_method_types`以查看所有符合条件的方法，然后缩小问题范围。
</Accordion>

<Accordion title="Unexpected methods appearing">
**可能原因：**
- `allowed_payment_method_types`未正确传递
- 参数格式错误（必须是字符串数组）

**解决方案：** 记录API请求负载并验证参数结构。
</Accordion>

<Accordion title="Regional method not available">
**检查：**
- 客户账单地址是否与方法地区一致
- 货币设置是否正确（例如，iDEAL使用EUR）
- 如果客户是国际的，是否启用了适应性货币

**解决方案：** 验证API请求中的账单地址国家代码和货币。
</Accordion>

<Accordion title="Indian payment method issues">
UPI和Rupay订阅有特定要求，包括48小时处理延迟和RBI授权限制。

**参见：** <a href="/features/payment-methods/india">印度支付方式</a> 以获取完整指导。
</Accordion>
</AccordionGroup>
