数字钱包让客户可以通过保存在设备上的支付方式进行一次性支付。它们提供更高的转化率，通过令牌化提供更强的安全性，并提供简化的结账体验。

## 支持的钱包

| 钱包 | 可用性 | 货币 | 订阅 | 需要设置 |
| :----- | :----------- | :--------- | :-----------: | :------------- |
| **Apple Pay** | 全球（印度除外） | 所有 | 是 | 域名验证 |
| **Google Pay** | 全球（印度除外） | 所有 | 是 | 无 |
| **Amazon Pay** | 全球（印度除外） | 美元 | 否 | 无 |
| **Cash App Pay** | 仅限美国 | 美元 | 否 | 无 |
| **RevolutPay** | 全球 | 英镑 | 否 | 无 |

<Warning>
**PayPal 支持暂停：** PayPal 暂时无法进行新的交易。
</Warning>

## Apple Pay

Apple Pay 允许客户使用保存在 Apple Wallet 中的卡片进行支付，支持 Face ID 或 Touch ID 身份验证。

### 需求
- **设备：** iOS 17+，iPadOS 17+，macOS 上的 Safari 17+
- **协议：** 需要 HTTPS
- **域名：** 必须经过 Apple 验证

### 域名验证

<Steps>
<Step title="下载域名关联文件">
下载 [Apple Pay 域名关联文件](http://checkout.dodopayments.com/.well-known/apple-developer-merchantid-domain-association)。
</Step>

<Step title="将文件托管在您的域名上">
上传到您的服务器：

```
https://yourdomain.com/.well-known/apple-developer-merchantid-domain-association
```

该文件必须在没有重定向的情况下可访问，并使用 `Content-Type: application/octet-stream` 或 `text/plain` 提供。
</Step>

<Step title="请求激活">
发送电子邮件到 **support@dodopayments.com**，内容包括：
- 您的生产域名（例如： `https://yourdomain.com`）
- 确认文件已托管

我们将在 1-2 个工作日内验证并启用 Apple Pay。
</Step>

<Step title="测试集成">
确认后：
1. 在 Apple 设备上打开结账
2. 验证 Apple Pay 按钮是否出现
3. 完成一次测试交易
</Step>
</Steps>

<Warning>
在域名验证完成之前，Apple Pay 不会出现在结账中。请在推出时考虑这一点。
</Warning>

### 配置

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['apple_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## Google Pay

Google Pay 允许客户使用保存在 Google 帐户中的卡片进行支付，具备内置的欺诈保护。

### 需求
- **浏览器：** Chrome（桌面/移动），Safari，Firefox
- **设备：** 带有 Google Pay 应用的 Android 设备
- **设置：** 在 Chrome 中启用“允许网站检查您是否有支付方式”

### 配置

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['google_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Info>
Google Pay 不需要进行域名验证——一旦您的账户上线，它会自动工作。
</Info>

## Amazon Pay

Amazon Pay 允许客户使用其 Amazon 帐户凭证和保存的支付方式，提供熟悉的结账体验。

### 限制
- **货币：** 仅支持美元
- **订阅：** 不支持
- **地区：** 在印度不可用

### 配置

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['amazon_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## Cash App Pay

Cash App Pay 允许来自 Cash App 的支付，这在美国消费者中仍然很受欢迎。

### 限制
- **地区：** 仅限美国
- **货币：** 仅支持美元
- **订阅：** 不支持

### 配置

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['cashapp', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## RevolutPay

RevolutPay 为全球的 Revolut 用户提供快速、无缝的支付，利用他们现有的 Revolut 账户余额或关联的卡片。

### 限制
- **货币：** 仅支持英镑
- **订阅：** 不支持

### 配置

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['revolut_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## 测试

### Apple Pay 测试

<Steps>
<Step title="使用测试模式">
在您的 Dodo Payments 控制面板中启用测试模式。
</Step>

<Step title="添加卡片到 Apple Wallet">
向您的 Apple Wallet 添加一张真实的卡片。在测试模式下，该卡片不会被收费。
</Step>

<Step title="完成测试购买">
在 Apple 设备上打开结账并完成 Apple Pay 流程。
</Step>
</Steps>

<Warning>
Apple Pay 需要 HTTPS。没有正确的 SSL 设置，无法在 `localhost` 显示。
</Warning>

### Google Pay 测试

<Steps>
<Step title="加入测试卡组">
[加入 Google Pay 测试卡组](https://groups.google.com/g/googlepay-test-mode-stub-data)，以便自动将测试卡添加到您的钱包。
</Step>

<Step title="启用测试模式">
使用您的 Dodo Payments 测试 API 密钥。
</Step>

<Step title="完成测试购买">
在 Google Pay 中选择一张测试卡完成交易。
</Step>
</Steps>

### Amazon Pay 和 Cash App Pay

使用您的测试 API 密钥并按照标准结账流程进行测试。测试交易将被模拟，不会发生实际费用。

## SDK 支持

### Web SDK
所有数字钱包在以下方面均完全支持：
- 覆盖结账
- 内嵌结账
- 直接 API 集成

### 移动 SDK

<Warning>
**React Native 限制：** Apple Pay、Google Pay、Cash App Pay 和 UPI 目前在 React Native SDK 中**不支持**。对于需要这些方法的移动应用，使用基于 Web 的结账覆盖。
</Warning>

对于原生移动支持，考虑：
- 在 WebView 中打开结账
- 在 Web 上使用 [Overlay Checkout](/developer-resources/overlay-checkout)
- 单独实现 플랫폼 原生的 Apple Pay / Google Pay SDK

## 最佳实践

<AccordionGroup>
<Accordion title="优先考虑移动设备上的钱包">
移动用户期望使用 Apple Pay 和 Google Pay。请在移动结账中显著显示这些选项。
</Accordion>

<Accordion title="尽早完成域名验证">
Apple Pay 需要域名验证。不要等到推出日——在开发期间开始该过程。
</Accordion>

<Accordion title="始终包含卡片后备选项">
并不是所有客户都有数字钱包。始终在您的允许方法中包含 `credit` 和 `debit`。
</Accordion>

<Accordion title="在真实设备上测试">
模拟器无法完全复现钱包行为。在推出前请在真实的 iOS 和 Android 设备上进行测试。
</Accordion>

<Accordion title="优雅地处理钱包不可用情况">
如果钱包不可用（设备不兼容，未保存卡片），请确保其他支付选项可见。
</Accordion>
</AccordionGroup>

## 故障排除

<AccordionGroup>
<Accordion title="Apple Pay 按钮未出现">
**检查：**
1. 域名已与 Dodo Payments 验证？
2. 使用 HTTPS 吗？
3. 设备是 iOS 17+ / Safari 17+ / iPadOS 17+ 吗？
4. 客户在 Apple Wallet 中有卡片吗？
5. `apple_pay` 是否包含在 `allowed_payment_method_types` 中？

**解决方案：** 完成域名验证并确保使用 HTTPS。在真实的 Apple 设备上进行测试。
</Accordion>

<Accordion title="Google Pay 按钮未出现">
**检查：**
1. 使用 Chrome 或兼容的浏览器吗？
2. 客户在 Google Pay 中有卡片吗？
3. Chrome 设置“允许网站检查支付方式”已启用吗？
4. `google_pay` 是否包含在 `allowed_payment_method_types` 中？

**解决方案：** 验证浏览器兼容性和客户的 Google Pay 设置。
</Accordion>

<Accordion title="钱包支付失败">
**常见原因：**
- 钱包中的卡片过期或无效
- 银行拒绝交易
- 网络连接问题

**解决方案：** 客户应检查钱包中的卡片或尝试使用其他支付方式。
</Accordion>

<Accordion title="错误的设备类型">
数字钱包仅在兼容设备上显示：
- Apple Pay：仅适用于 Apple 设备
- Google Pay：Chrome 浏览器或 Android 设备

**解决方案：** 这是预期的行为。确保可用的卡片后备选项.
</Accordion>
</AccordionGroup>
