## **B2B 交易的税号验证**

- 如果在结账时提供了 **有效的税号**，发票将包括：
    - **客户的税号**。
- 税收扣除将根据客户所在国家的适用法规确定。
- 发票将包括 **Dodo Payments 的税务详情**，以及适用于该交易的税收。

## 收集B2B发票的企业名称

对于B2B采购，您可以在发票上显示客户的**法定企业名称**，而不是个人姓名。这与税号一起通过`customer_business_name`字段收集。

当客户在结账时选择**作为企业购买**时，会提示他们输入**企业名称**和**税号**。

当客户输入时，税号会实时验证。对于欧盟成员国、英国和澳大利亚，结账时不仅执行格式/校验和验证，还会进行实时注册查询（分别为 VIES、HMRC 和 ABR），并在找到匹配时自动填充注册的法定企业名称。对于其他所有国家，只执行格式/校验和验证。

只有当**以下三个**条件全部满足时，企业名称才会出现在发票上：

1. 交易为 B2B（`b2b = true`）
2. 存在一个 `tax_id`
3. 提供了一个非空的 `customer_business_name`

如果任何条件不满足，将使用客户的个人姓名。

### 在结账时设置

直接传递 `customer_business_name`，和/或启用 `allow_customer_editing_business_name` 让客户在结账页面上输入或编辑它，位于税号旁边：

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_abc', quantity: 1 }],
  customer: { email: 'buyer@acme.com' },
  tax_id: 'GB123456789',
  customer_business_name: 'Acme Corp Ltd',
  feature_flags: {
    allow_tax_id: true,
    allow_customer_editing_business_name: true // optional: let the customer edit it
  },
  return_url: 'https://yoursite.com/return'
});
```

| 表面 | 字段 | 备注 |
|---------|-------|-------|
| 结账会话 | `customer_business_name`, `feature_flags.allow_customer_editing_business_name` | 最大250字符；标志默认为 `false` |
| 支付 | `customer_business_name` | 最大250字符 |
| 订阅 | `customer_business_name` | 通过 `PATCH /subscriptions/{id}` 设置或清除 |

<Warning>
`customer_business_name` 不能在没有 `tax_id` 的情况下设置 —— 请求将被拒绝。清除 `tax_id` 也会清除企业名称，因为两者在发票上是关联的。周围的空白被修剪，只有空白的值被视为明确的清除。
</Warning>

## **B2C 交易的税务处理**

- 未提供有效税号的交易将被视为**B2C 交易**，并根据客户所在国家的适用税收法规扣除税款。
- 发票将包括**Dodo Payments 的税务详情**，以及应用于交易的税款。

## 反向收费机制

通常，商品或服务的供应商有责任支付增值税/服务税/GST。然而，在进口和其他指定供应等特定情况下，责任在接收方（客户）一方，根据反向收费机制。反向收费意味着税款支付责任在接收商品或服务的接收方，而不是供应方，适用于通知的供应类别。

## **反向收费的适用性**

- 在法律适用的某些情况下，结账时**不会扣除税款**，交易将受**反向收费机制**约束。
- 发票将根据法规要求清楚地表明何时适用反向收费。
