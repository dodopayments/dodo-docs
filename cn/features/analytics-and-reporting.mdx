## Home

**Home** 是侧边栏中的登录页，包含两个部分：**Today** 和 **Your overview**。

### Today

<Frame caption="Today: your day's pulse, hour by hour">
  <img src="/images/analytics/home-today.png" alt="Home Today view with an hourly volume chart, cash position, and next payout tiles" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

按小时显示当天的业务脉搏。

- **Headline chart:** 在 **Net volume** 和 **Gross volume** 之间切换（默认显示 Net volume），按小时绘制，并与昨天同一时间的曲线进行对比。
- **Cash Position:** 当前钱包余额和下一次 payout 日期。

<Note>
两张卡片都会显示信息提示框（ⓘ）和“Updated Xs ago”时间戳，让您始终了解数据的新鲜程度。
</Note>

### Your Overview

<Frame caption="Your overview: a fully customizable set of metric cards">
  <img src="/images/analytics/home-overview.png" alt="Home Your overview view with customizable cards for revenue by country, payouts received, top customers by spend, and refunds" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

完全可自定义——使用 **Customize** 选择、重新排列和移除卡片。

- **Default cards:** Net volume、Gross volume、Payments、Top customers by spend、New customers、Revenue by country 和 Refunds；此外，一次性/按用量计费商户还包括 **Average order value**，订阅商户则包括 **MRR** 和 **Net New MRR**。
- **Controls:**
  - **Period:** Daily/Weekly 或自定义范围。
  - **Compare:** Previous period 或 previous month（默认开启）。
  - **Product:** 单个产品或产品组。

### Filtering & Customization

每个选项卡都有自己的筛选栏：

- **Time Period:** 预设范围或自定义日期范围，以及 **Daily/Weekly** 分组。

### Revenue Tab

<Frame caption="Revenue tab: gross/net volume, payouts, and refunds">
  <img src="/images/analytics/revenue-tab.png" alt="Revenue tab showing gross volume, net volume, payouts received, and refunds cards with trend charts" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

跟踪收入、payout 和争议活动，以了解收入趋势并识别表现最佳的市场。使用 **Gross/Net** 下拉菜单，在总额和净额之间切换标题数值、图表及国家排名。

| Metric | Description |
|--------|-------------|
| **Gross volume** | 期间所有成功支付收取的总金额，未扣除费用、退款或争议损失。 |
| **Net volume** | Net volume = gross volume − fees − refunds − lost disputes。 |
| **Payouts received** | Payout = eligible sales − taxes − fees − refunds − chargebacks。 |
| **Refund rate** | Refund rate = refunded amount ÷ gross volume。 |
| **Disputes** | 标题指标是按总额计算的 chargeback rate：每笔收到的 chargeback 都会计入，因此之后获胜或被撤销的 chargeback 不会降低该指标（这是 card networks 评估风险的方式）。Won / lost / pending 以数量显示，用于提供上下文，并在两个期间之间进行比较。Chargeback rate = chargebacks received ÷ payments。 |
| **Payments count** | 状态为 Successful 的支付数量。不包括进行中、失败和未发起的尝试。 |
| **Average order value** | AOV = revenue ÷ number of orders，涵盖一次性和按用量计费的产品。 |
| **Revenue by product** | 归因于各产品的总收入，按从高到低排列。 |
| **Revenue by country** | 根据客户账单国家/地区，归因于各国家/地区的收入。 |
| **Revenue by geography** | 以地图显示国家/地区级别的收入，颜色越深表示金额越高。 |

### Customers Tab

<Frame caption="Customers tab: active and new customers, ARPU, and top customers">
  <img src="/images/analytics/customers-tab.png" alt="Customers tab showing active customers, new customers, ARPU, and top customers by spend" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

分析客户获取、留存和消费模式，以优化您的客户策略。

| Metric | Description |
|--------|-------------|
| **Active customers** | 在该期间内任何时间进行过支付或持有有效订阅的客户。 |
| **New customers** | 首次成功向您支付发生在该期间内的客户。 |
| **ARPU** | ARPU = revenue ÷ active customers。 |
| **Top customers** | 按该期间的收入对客户排名，从高到低排列。 |
| **New vs. returning** | New = 在该期间内首次购买。Returning = 在更早期间曾向您购买。 |
| **Modeled LTV** | 估算客户流失前产生的收入。 |

### Subscriptions Tab

监控经常性收入，了解 Monthly Recurring Revenue (MRR) 如何随时间变化。

| Metric | Description |
|--------|-------------|
| **MRR** | 预计一个月内产生的经常性收入，每个方案都会转换为月度金额（年度方案按 1/12 计算）。不包括一次性支付。 |
| **Projected ARR** | Projected ARR = current MRR × 12。 |
| **Net New MRR** | Net New MRR = New + Expansion − Contraction − Churned。 |
| **Active subscriptions** | 正在计费的订阅，包括仍处于试用期的订阅。 |
| **New MRR** | 该期间全新订阅增加的 MRR。 |
| **Expansion MRR** | 现有客户升级或购买附加项所产生的额外 MRR。 |
| **Contraction MRR** | 现有客户转用更低价方案但仍保持订阅时损失的 MRR。 |
| **Churned MRR** | 客户在该期间取消订阅时损失的 MRR。 |

<Note>
MRR 会计算**并行订阅**（按客户求和），并根据每个订阅的已付费有效期按比例计算。
</Note>

### Retention Tab

<Frame caption="Retention tab: churn rates, retention matrix, and NRR/GRR">
  <img src="/images/analytics/retention-tab.png" alt="Retention tab showing the user retention cohort matrix, customer churn rate, revenue churn rate, and net revenue retention" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

监控客户留存和流失模式。

| Metric | Description |
|--------|-------------|
| **User retention matrix** | 按注册月份（cohort）对客户分组，然后显示每个 cohort 在之后每个月仍处于活跃状态的客户比例。Retention (month k) = cohort customers active in month k ÷ cohort size。 |
| **Customer churn rate** | 期间内取消的起始订阅者占比，旁边显示流失客户数量。Customer churn rate = churned subscribers ÷ subscribers at start of period。 |
| **Revenue churn rate** | Revenue churn rate = churned MRR ÷ starting MRR，其中 starting MRR 是该期间开始时现有客户产生的经常性收入（即上一期间结束时的收入）。 |
| **Net Revenue Retention (NRR)** | 包括升级，因此可能超过 100%。NRR = (starting MRR + Expansion − Contraction − Churned) ÷ starting MRR。 |
| **Gross Revenue Retention (GRR)** | 不包括升级，因此最高为 100%。GRR = (starting MRR − Contraction − Churned) ÷ starting MRR。 |
| **Trial conversion** | Trial conversion = trials converted ÷ trials that ended in the period。仅当您提供试用时显示。 |

### Success Rate Tab

<Frame caption="Success Rate tab: payment and refund success rates with failure analysis">
  <img src="/images/analytics/success-rate-tab.png" alt="Success Rate tab showing payment success rate, payments breakdown, payment failure reasons, and success by payment method" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

监控支付和退款成功率，以快速识别并解决交易问题。

| Metric | Description |
|--------|-------------|
| **Payment success rate** | 只有 processor/network failures 会计入失败；客户可修复的问题（如卡号错误或卡片过期）不会计入分母。Payment success rate = succeeded ÷ (attempts − customer-fixable failures)。 |
| **Payments breakdown** | 将尝试拆分为总数、成功、失败（network）、失败（customer）和未发起。 |
| **Payment failure reason** | 按原因细分支付失败情况。 |
| **By payment method** | 按方式（card、wallet、UPI、BNPL）显示：success rate = succeeded ÷ attempts；volume = succeeded amount。 |
| **Checkouts count** | 客户开始的 checkout session 数量，无论是否完成。 |
| **Refund success rate** | 已发起退款中成功处理的比例。 |

<Card title="Transaction Failure Reference" icon="circle-exclamation" href="/api-reference/transaction-failures">
获取所有可能的交易失败代码及其原因。
</Card>

<Warning>
如果您发现成功率下降或失败次数激增，请查看失败原因并及时处理，以最大限度减少收入损失。
</Warning>

### Recovery Tab

<Frame caption="Recovery tab: retries, dunning, and abandoned cart recovery">
  <img src="/images/analytics/recovery-tab.png" alt="Recovery tab showing recovery overview, recovery by flow, payment retries, and dunning metrics" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

跟踪 Dodo Payments 通过自动重试、催收邮件和弃购恢复代表您挽回的收入金额。

| Metric | Description |
|--------|-------------|
| **Recovery overview** | 期间内恢复的收入及整体恢复率。Recovery rate = recovered ÷ recoverable failed amount；硬拒绝（账户已关闭）不计入可恢复金额。 |
| **Recovery by flow** | 按重试、催收和弃购分别显示恢复的收入。 |
| **Payment retries** | 重试次数、成功重试次数、重试成功率和挽救的订阅数量。 |
| **Dunning** | 催收条目、已发送邮件、恢复收入、恢复率和平均恢复时间。 |
| **Abandoned cart** | 弃购 checkout、恢复收入、恢复率和平均恢复时间。 |

<Card title="Recovery Features" icon="life-ring" href="/features/recovery/overview">
详细了解如何配置支付重试、催收和弃购恢复。
</Card>

## Reports

每份 report 在其对应页面都有 **Build Report** 按钮。前往相关部分即可访问并下载所需的 report。

每份 report 都可以按适用条件进行筛选（payment method、status、product type、failure type、dispute status 或 currency），并下载为 CSV。

| Report Type | Description | Where to find it |
|-------------|-------------|------------------|
| **Payment Report** | 所有已处理支付的详细记录，包括账单地址、卡片详情、USD 等值金额、结算详情、费用和失败代码。 | **Transactions → Payments** |
| **Refund Report** | 所有退款活动的完整记录及详细退款信息。 | **Transactions → Refunds** |
| **Disputes Report** | 支付争议摘要，包括解决状态和证据详情。 | **Transactions → Disputes** |
| **Customer Report** | 按客户整理的支付、退款和争议摘要。 | **Sales → Customers** |
| **Payout Report** | 支付到您账户的 payout 摘要，并按 ledger event 拆分费用。 | **Payouts** |
| **Account Summary Report** | 详细的 balance-ledger 条目，包括事件类型、金额和引用信息。 | **Payouts → Balances** |

## Downloading Reports

<Steps>
<Step title="Navigate to the relevant page">
使用上表前往所需 report 所在的页面。
</Step>
<Step title="Select a time period">
点击 <strong>Build Report</strong>，然后选择预设范围（Today、Last 7 days、Last 30 days、This month 等），或使用日历选择自定义日期范围。
</Step>
<Step title="Download">
点击 <strong>Download Report</strong>。report 将导出为 CSV 并保存到您的设备。
</Step>
</Steps>

<Note>
费用数据不提供独立 report。您可以在 **Payouts → Balances** 下的 **Account Summary Report** 中，通过筛选选项查看费用明细（payment fees、refund fees 和 payout fees）。
</Note>
