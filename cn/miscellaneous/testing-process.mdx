## 概述

测试模式允许您模拟支付而不处理真实交易。所有测试凭据仅在测试模式下使用——请勿在生产中使用。

 <CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
测试交易不会处理实际支付或影响真实账户。
</Card>

 <Card title="Full API Access" icon="code">
所有API端点在测试和实时模式下的工作方式相同。
</Card>

 <Card title="Webhook Testing" icon="webhook">
Webhooks在测试交易中触发的方式与生产中相同。
</Card>
</CardGroup>

 <Warning>
测试凭据仅在测试模式下有效。在实时模式下尝试使用会导致支付失败。
</Warning>

当这些卡中的一张被拒绝时，支付的 `error_code` 和 `error_message` 反映了上述场景。在[Transaction Failures](/api-reference/transaction-failures)参考中查找任何代码以了解其含义和推荐的操作，并参阅[Handle Payment Failures](/developer-resources/handle-payment-failures)以处理集成中的拒绝。

### 如何测试续订失败

 <Steps>
<Step title="Create a test subscription">
使用您的测试API密钥创建一个订阅，使用一个**成功**测试卡（例如，`4242 4242 4242 4242`）。初始费用应成功，并且订阅应激活。
</Step>

 <Step title="Swap in the failure card via Customer Portal">
打开[客户门户](/features/customer-portal)，找到您刚刚创建的订阅，然后点击**更新支付方式**。输入失败测试卡 `4000 0000 0000 0341`（到期：`12/34`，CVC：`123`）并将其保存为订阅的支付方式。
</Step>

 <Step title="Advance the next billing date (optional)">
要立即触发续订而不是等待自然计费周期，请使用更新订阅API将 `next_billing_date` 设置为当前UTC时间。值必须是ISO 8601 / RFC 3339 UTC时间戳（需要 `Z` 后缀）。

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

有关详细信息，请参阅[更新订阅API参考](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0)。
</Step>

 <Step title="Verify the failure">
在下一个计费尝试中：

- 续订费用在失败卡上被拒
- 订阅移至**等待中**状态
- 发送 `payment.failed` webhook事件
- 客户可以返回客户门户以更新支付方式并重试
</Step>
</Steps>

 <Warning>
此卡专用于测试续订失败。费用将在下一个计费日期被拒绝，使您能够测试支付重试逻辑、客户通知和失败处理。
</Warning>

## 测试UPI

UPI测试使用特殊的VPA（虚拟支付地址）标识符来模拟不同的付款结果。

| 状态   | UPI ID |
| :----- | :----- |
| 成功   | `success@upi` |
| 失败   | `failure@upi` |

### UPI测试要求

- 结算国家必须设置为`IN`
- 货币必须为`INR`
- 对于非印度商户：必须启用自适应货币

有关完整的UPI文档，包括订阅的RBI授权测试，请参阅[India Payment Methods](/features/payment-methods/india)页面。

| **街道**     | Amsterdam Ave | Amsterdam Ave |

 <Note>
Klarna 需要最低交易金额为 **$50.01** 才能显示为付款选项。
</Note>

### Afterpay测试

 <Steps>
<Step title="Select Afterpay">
在结账时选择Afterpay作为支付方式，然后点击支付。
</Step>

 <Step title="Test successful payment">
使用任何有效的电子邮件地址和送货地址以获取成功的付款。
</Step>

 <Step title="Test failed authentication">
要模拟失败，请在重定向页面上关闭Afterpay模式窗口。付款从 `requires_action` 转到 `requires_payment_method`。
</Step>
</Steps>

 <Note>
Afterpay 需要最低交易金额为 **$50.01** 才能显示为付款选项。
</Note>

有关完整的BNPL文档，包括Billie B2B测试，请参阅[Buy Now Pay Later](/features/payment-methods/bnpl)页面。

## 测试数字钱包

### Apple Pay

 <Steps>
<Step title="Enable test mode">
使用您的Dodo Payments测试API密钥。
</Step>

 <Step title="Add a card to Apple Wallet">
将真实卡添加到您的Apple Wallet。在测试模式下，卡不会被扣费。
</Step>

 <Step title="Complete test purchase">
在苹果设备上打开结账并完成Apple Pay流程。
</Step>
</Steps>

 <Warning>
Apple Pay 需要 HTTPS。如果没有正确的SSL设置，它将在 `localhost` 上不会显示。还须完成域验证。
</Warning>

### Google Pay

 <Steps>
<Step title="Join the test card group">
[加入Google Pay测试卡组](https://groups.google.com/g/googlepay-test-mode-stub-data)以自动将测试卡添加到您的钱包中。
</Step>

 <Step title="Enable test mode">
使用您的Dodo Payments测试API密钥。
</Step>

 <Step title="Complete test purchase">
在Google Pay中选择一张测试卡以完成交易。
</Step>
</Steps>

### Amazon Pay, Cash App Pay & RevolutPay

使用您的测试API密钥并按照标准结账流程进行操作。测试交易是模拟的，不会产生实际费用。

有关完整的数字钱包文档，包括Apple Pay的域验证，请参阅[Digital Wallets](/features/payment-methods/digital-wallets)页面。

## 测试欧洲支付方式

欧洲支付方式（iDEAL, Bancontact, EPS, Multibanco）可在沙盒模式下进行测试。

 <Steps>
<Step title="Enable test mode">
使用您的Dodo Payments测试API密钥。
</Step>

 <Step title="Set billing address">
将结算地址国家与支付方式匹配：
- iDEAL为`NL`
- Bancontact为`BE`
- EPS为`AT`
- Multibanco为`PT`
</Step>

 <Step title="Set currency">
欧洲支付方式需要使用欧元(EUR)货币。
</Step>

 <Step title="Complete test flow">
在测试环境中按照模拟银行认证流程进行操作。
</Step>
</Steps>

有关完整的欧洲支付方式文档，请参阅[Europe](/features/payment-methods/europe)页面。

## 测试最佳实践

 <AccordionGroup>
<Accordion title="Test all payment scenarios">
不只是测试成功的付款。测试拒绝、取消和类似资金不足的边缘情况。
</Accordion>

 <Accordion title="Verify webhook handling">
确保您的webhook端点正确处理所有事件类型，特别是`payment.succeeded`、`payment.failed`和订阅事件。

使用[Dodo Payments CLI](/developer-resources/sdks/cli#webhook-testing)本地测试webhooks：
- `dodo wh listen` 将实时测试webhooks转发到您的本地服务器
- `dodo wh trigger` 发送模拟的所有22种事件类型的负载
</Accordion>

 <Accordion title="Test on real devices">
对于Apple Pay和Google Pay，请在实际的iOS和Android设备上进行测试。模拟器无法完全复制钱包行为。
</Accordion>

 <Accordion title="Test regional methods with correct addresses">
区域支付方式（UPI，iDEAL等）需要匹配的结算地址。美国结算地址不会显示iDEAL。
</Accordion>

 <Accordion title="Verify minimum amounts">
BNPL方法需要最低$50.01。测试他们是否根据购物车总额正确显示/隐藏。
</Accordion>
</AccordionGroup>
