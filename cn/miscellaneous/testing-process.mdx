## 概述

测试模式允许您模拟支付而不处理真实交易。所有测试凭据仅在测试模式下使用——请勿在生产中使用。

 <CardGroup cols={3}>
<Card title="No Real Charges" icon="shield-check">
测试交易不会处理实际支付或影响真实账户。
</Card>

 <Card title="Full API Access" icon="code">
所有API端点在测试和实时模式下的工作方式相同。
</Card>

 <Card title="Webhook Testing" icon="webhook">
Webhooks在测试交易中触发的方式与生产中相同。
</Card>
</CardGroup>

 <Warning>
测试凭据仅在测试模式下有效。在实时模式下尝试使用会导致支付失败。
</Warning>

### 如何测试续订失败

 <Steps>
<Step title="Create a test subscription">
使用您的测试API密钥创建一个订阅，使用一个**成功**测试卡（例如，`4242 4242 4242 4242`）。初始费用应成功，并且订阅应激活。
</Step>

 <Step title="Swap in the failure card via Customer Portal">
打开[客户门户](/features/customer-portal)，找到您刚刚创建的订阅，然后点击**更新支付方式**。输入失败测试卡 `4000 0000 0000 0341`（到期：`12/34`，CVC：`123`）并将其保存为订阅的支付方式。
</Step>

 <Step title="Advance the next billing date (optional)">
要立即触发续订而不是等待自然计费周期，请使用更新订阅API将 `next_billing_date` 设置为当前UTC时间。值必须是ISO 8601 / RFC 3339 UTC时间戳（需要 `Z` 后缀）。

```http
PATCH /subscriptions/{subscription_id}
{
  "next_billing_date": "2026-05-03T00:00:00Z"
}
```

有关详细信息，请参阅[更新订阅API参考](/api-reference/subscriptions/patch-subscriptions#body-next-billing-date-one-of-0)。
</Step>

 <Step title="Verify the failure">
在下一个计费尝试中：

- 续订费用在失败卡上被拒
- 订阅移至**等待中**状态
- 发送 `payment.failed` webhook事件
- 客户可以返回客户门户以更新支付方式并重试
</Step>
</Steps>

 <Warning>
此卡专用于测试续订失败。费用将在下一个计费日期被拒绝，使您能够测试支付重试逻辑、客户通知和失败处理。
</Warning>

## 测试UPI

UPI测试使用特殊的VPA（虚拟支付地址）标识符来模拟不同的付款结果。

| 状态   | UPI ID |
| :----- | :----- |
| 成功   | `success@upi` |
| 失败   | `failure@upi` |

### UPI测试要求

- 结算国家必须设置为`IN`
- 货币必须为`INR`
- 对于非印度商户：必须启用自适应货币

有关完整的UPI文档，包括订阅的RBI授权测试，请参阅[India Payment Methods](/features/payment-methods/india)页面。

### Afterpay测试

 <Steps>
<Step title="Select Afterpay">
在结账时选择Afterpay作为支付方式，然后点击支付。
</Step>

 <Step title="Test successful payment">
使用任何有效的电子邮件地址和送货地址以获取成功的付款。
</Step>

 <Step title="Test failed authentication">
要模拟失败，请在重定向页面上关闭Afterpay模式窗口。付款从 `requires_action` 转到 `requires_payment_method`。
</Step>
</Steps>

 <Note>
Afterpay 需要最低交易金额为 **$50.01** 才能显示为付款选项。
</Note>

如需完整的 BNPL 文档（包括 Billie B2B 测试），请参阅 [Buy Now Pay Later](/features/payment-methods/bnpl) 页面。

## 测试数字钱包

### Apple Pay

<Steps>
<Step title="Enable test mode">
使用您的 Dodo Payments 测试 API 密钥。
</Step>

<Step title="Add a card to Apple Wallet">
将真实银行卡添加到您的 Apple Wallet。在测试模式下不会扣款。
</Step>

<Step title="Complete test purchase">
在 Apple 设备上打开结账页面并完成 Apple Pay 流程。
</Step>
</Steps>

<Warning>
Apple Pay 要求使用 HTTPS。未正确配置 SSL 时，它不会显示在 `localhost` 上。域名验证也必须完成。
</Warning>

### Google Pay

<Steps>
<Step title="Join the test card group">
[加入 Google Pay 测试卡组](https://groups.google.com/g/googlepay-test-mode-stub-data)，即可自动将测试卡添加到您的钱包。
</Step>

<Step title="Enable test mode">
使用您的 Dodo Payments 测试 API 密钥。
</Step>

<Step title="Complete test purchase">
在 Google Pay 中选择一张测试卡以完成交易。
</Step>
</Steps>

### Amazon Pay、Cash App Pay 和 RevolutPay

使用您的测试 API 密钥，并按照标准结账流程操作。测试交易会进行模拟，不会实际扣款。

如需完整的数字钱包文档（包括 Apple Pay 的域名验证），请参阅 [Digital Wallets](/features/payment-methods/digital-wallets) 页面。

## 测试欧洲支付方式

欧洲支付方式（iDEAL、Bancontact、EPS、Multibanco）可以在沙盒模式下进行测试。

<Steps>
<Step title="Enable test mode">
使用您的 Dodo Payments 测试 API 密钥。
</Step>

<Step title="Set billing address">
将账单地址所在国家/地区设置为与支付方式匹配：
- `NL` 用于 iDEAL
- `BE` 用于 Bancontact
- `AT` 用于 EPS
- `PT` 用于 Multibanco
</Step>

<Step title="Set currency">
欧洲支付方式要求使用 EUR 货币。
</Step>

<Step title="Complete test flow">
在测试环境中按照模拟的银行身份验证流程操作。
</Step>
</Steps>

如需完整的欧洲支付方式文档，请参阅 [Europe](/features/payment-methods/europe) 页面。

## 测试最佳实践

<AccordionGroup>
<Accordion title="Test all payment scenarios">
不要只测试成功支付。还要测试拒付、取消，以及余额不足等边界情况。
</Accordion>

<Accordion title="Verify webhook handling">
确保您的 webhook 端点能够正确处理所有事件类型，尤其是 `payment.succeeded`、`payment.failed` 和订阅事件。

使用 [Dodo Payments CLI](/developer-resources/sdks/cli#webhook-testing) 在本地测试 webhook：
- `dodo wh listen` 将实时测试 webhook 转发到您的本地服务器
- `dodo wh trigger` 为全部 22 种事件类型发送模拟 payload
</Accordion>

<Accordion title="Test on real devices">
对于 Apple Pay 和 Google Pay，请在实际的 iOS 和 Android 设备上进行测试。模拟器无法完全复现钱包行为。
</Accordion>

<Accordion title="Test regional methods with correct addresses">
区域性支付方式（UPI、iDEAL 等）要求账单地址匹配。使用美国账单地址时不会显示 iDEAL。
</Accordion>

<Accordion title="Verify minimum amounts">
BNPL 支付方式要求最低金额为 $50.01。请测试它们是否会根据购物车总额正确显示或隐藏。
</Accordion>
</AccordionGroup>
