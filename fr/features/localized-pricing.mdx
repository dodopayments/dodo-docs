## Qu'est-ce que la Tarification Localisée ?

Chaque produit a un prix de base dans une devise de base. La Tarification Localisée vous permet de remplacer cette base par des **prix fixes que vous définissez par devise ou par pays**. Activez-la en définissant un `pricing_mode` sur le produit, puis attachez une règle par marché.

Il s'agit de l'un des nombreux leviers indépendants de la tarification internationale, chacun répondant à un problème différent :

| Mécanisme | Fonctionnement | Le nombre affiché au client |
| :--- | :--- | :--- |
| **Tarification localisée** | Un prix fixe que vous définissez par devise ou par pays | Exactement le montant que vous avez défini |
| [**Adaptive Currency**](/features/adaptive-currency) | Convertit automatiquement votre prix de base selon les taux de change en temps réel | Le prix de base converti au taux de change actuel |
| [**Parité de pouvoir d'achat**](/features/purchasing-power-parity) | Facture automatiquement une part de votre prix, selon le pays | Un pourcentage du prix de base |
| [**Tarification psychologique**](/features/charm-pricing) | Arrondit automatiquement le prix converti pour obtenir une terminaison nette | Un montant arrondi, tel que 49,99 |
| [**Codes de réduction**](/features/discount-codes) | Une réduction en pourcentage appliquée au prix de base | Le prix de base moins la réduction |

<Info>
La Tarification Localisée et la Devise Adaptative fonctionnent ensemble. Lorsqu'aucune règle localisée ne correspond, le produit revient à son prix de base — facturé directement si le client est déjà dans votre devise de base, ou converti via Devise Adaptative sinon.
</Info>

## Concepts de Base

- **Modes de tarification** — Un produit utilise exactement un mode à la fois, défini par son `pricing_mode`:
  - `by_currency` : un prix par devise, quel que soit le pays. Toute personne payant en EUR voit 9,99 €.
  - `by_country` : un prix spécifique à un pays (₹999 en Inde), même lorsque plusieurs pays partagent la même devise.
- **Montants fixes, dans la plus petite unité** — Le `amount` d'une règle est un entier exprimé dans la plus petite unité de la devise, comme partout ailleurs dans l'API : `99900` correspond à 999,00 ₹, `999` correspond à 9,99 €. Il s'agit d'un prix que vous définissez, jamais d'une valeur convertie.
- **Une règle correspondante est prioritaire sur la tarification automatique** — Lorsqu'une règle localisée s'applique à une ligne, la [Parité de pouvoir d'achat](/features/purchasing-power-parity) et la [Tarification psychologique](/features/charm-pricing) sont toutes deux ignorées pour cette ligne. Le client paie le montant que vous avez défini, sans modification.
- **Lorsqu'aucune règle ne correspond** — Le produit conserve son comportement existant : les clients dans votre devise de base paient directement le prix de base ; tous les autres bénéficient d'une conversion via [Adaptive Currency](/features/adaptive-currency).
- **Les frais sont inclus lorsqu'une règle correspond** — Le client paie **exactement** le montant que vous avez défini. Les frais de change de [Adaptive Currency](/features/adaptive-currency#choose-who-bears-the-fee) sont pris en charge par vous (ils sont considérés comme inclus dans les frais pour cette transaction) plutôt qu'ajoutés au montant. Ainsi, le prix local indiqué est toujours le prix facturé.

## Configurer dans le Tableau de Bord

<Steps>
<Step title="Open the product form">
Dans votre Tableau de Bord Marchand, allez à **Produits** et créez un produit (ou ouvrez un existant pour le modifier). Définissez le **Prix** de base et la devise comme d'habitude.
</Step>

<Step title="Enable Localized Pricing and choose a mode">
Dans la section **Tarification**, cochez **Tarification Localisée**, puis choisissez **Par Pays** ou **Par Devise**.

<Frame>
  <img src="/images/localized-pricing/pricing-section.png" alt="Tarification Localisée activée sur le formulaire produit avec Par Pays sélectionné" style={{ maxHeight: '450px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Add a price for each market">
Cliquez sur **Ajouter un Prix par Pays** ou **Ajouter un Prix par Devise**, remplissez le panneau **Tarification localisée** et cliquez sur **Ajouter**. Chaque marché que vous ajoutez apparaît dans le tableau des exceptions, où vous pouvez le modifier ou le supprimer plus tard.

<Tabs>
<Tab title="By Country">
Choisissez un pays, sélectionnez la devise et entrez le montant (par exemple ₹999 pour l'Inde), puis cliquez sur **Ajouter**.

<Tab title="By Currency">

## Gérer via l'API

La Tarification Localisée est entièrement disponible via l'API. Commencez par définir le mode de tarification du produit, puis attachez des règles.

### Définir le mode de tarification

Définissez `pricing_mode` lorsque vous créez le produit (ou mettez à jour un existant). `null` signifie uniquement de base, le comportement existant.

<CodeGroup>

```typescript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode',
});

const product = await client.products.update('pdt_premium_plan', {
  pricing_mode: 'by_country',
});
```

```python theme={null}
import os
from dodopayments import DodoPayments

client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
    environment="test_mode",
)

product = client.products.update(
    "pdt_premium_plan",
    pricing_mode="by_country",
)
```

```go theme={null}
package main

import (
	"context"
	"os"

	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func main() {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
	)

	_, err := client.Products.Update(
		context.TODO(),
		"pdt_premium_plan",
		dodopayments.ProductUpdateParams{
			PricingMode: dodopayments.F(dodopayments.PricingModeByCountry),
		},
	)
	if err != nil {
		panic(err)
	}
}
```

</CodeGroup>

### Ajouter un prix localisé

Attachez une règle au produit. En mode `by_country` `country_code` est requis ; en mode `by_currency` il doit être omis.

<CodeGroup>

```typescript theme={null}
// ₹999.00 for customers in India
const localizedPrice = await client.products.localizedPrices.create('pdt_premium_plan', {
  currency: 'INR',
  country_code: 'IN',
  amount: 99900,
});
```

```python theme={null}
# ₹999.00 for customers in India
localized_price = client.products.localized_prices.create(
    "pdt_premium_plan",
    currency="INR",
    country_code="IN",
    amount=99900,
)
```

```go theme={null}
// ₹999.00 for customers in India
localizedPrice, err := client.Products.LocalizedPrices.New(
	context.TODO(),
	"pdt_premium_plan",
	dodopayments.ProductLocalizedPriceNewParams{
		Currency:    dodopayments.F(dodopayments.CurrencyInr),
		CountryCode: dodopayments.F(dodopayments.CountryCodeIn),
		Amount:      dodopayments.F(int64(99900)),
	},
)
```

</CodeGroup>

Pour un produit `by_currency`, omettez `country_code`. Par exemple, un prix forfaitaire `€9.99` pour tous ceux qui paient en EUR (`currency: 'EUR'`, `amount: 999`).

### Lister, mettre à jour et archiver

Vous ne pouvez mettre à jour que le `amount` d'une règle ; la devise et le pays sont fixés une fois créés. L'archivage est une suppression douce idempotente, donc la règle cesse de correspondre mais reste dans votre historique.

<CodeGroup>

```typescript theme={null}
// List all active rules on a product
const rules = await client.products.localizedPrices.list('pdt_premium_plan');

// Change the amount (e.g. end a promo)
await client.products.localizedPrices.update('lcp_india_price', {
  product_id: 'pdt_premium_plan',
  amount: 119900,
});

// Archive a rule
await client.products.localizedPrices.archive('lcp_india_price', {
  product_id: 'pdt_premium_plan',
});
```

```python theme={null}
# List all active rules on a product
rules = client.products.localized_prices.list("pdt_premium_plan")

# Change the amount (e.g. end a promo)
client.products.localized_prices.update(
    "lcp_india_price",
    product_id="pdt_premium_plan",
    amount=119900,
)

# Archive a rule
client.products.localized_prices.archive(
    "lcp_india_price",
    product_id="pdt_premium_plan",
)
```


</CodeGroup>

## Comment cela s'applique lors du paiement

La tarification localisée est résolue par ligne de panier, et seulement pour les produits qui ont un `pricing_mode` défini. Dodo Payments lit deux signaux de la demande : le **pays de facturation** du client, et un **`billing_currency`** facultatif (lorsqu'il est omis, une devise est dérivée du pays de facturation).

- **Par Pays** : cherche une règle correspondant au pays de facturation. Si elle existe, le client est facturé du montant de la règle dans la devise de la règle.
- **Par Devise** : cherche une règle correspondant à la devise du client (le `billing_currency`, ou la devise dérivée de son pays). Si elle existe, le client est facturé du montant de la règle dans cette devise.
- **Aucune correspondance, ou pas de `pricing_mode`** : le prix de base s'applique, facturé directement lorsque la devise du client est égale à la devise de base, sinon converti via [Devise Adaptative](/features/adaptive-currency).

Chaque ligne de panier est résolue indépendamment, donc vous pouvez localiser un produit et laisser les autres sur la tarification de base dans le même paiement. Si une ligne correspond à une règle localisée, l'ensemble de la transaction est forcé à frais inclusifs (voir [Concepts de Base](#core-concepts)).

## Fonctionnement lors des changements de plan d’abonnement

La tarification localisée suit vos abonnés lorsqu’ils changent de plan. Lorsqu’un abonnement existant [change de plan](/features/subscription#subscription-plan-changes) vers un produit qui possède un `pricing_mode`, le prix du nouveau plan est déterminé selon les mêmes règles qu’au checkout, en utilisant le pays et la devise de facturation déjà définis sur l’abonnement :

- **Par pays** : une règle correspondant au pays de facturation de l’abonnement s’applique. Si la devise de la règle diffère de celle dans laquelle l’abonnement est facturé, le montant de la règle est converti selon les taux de change en temps réel — la règle est appliquée, et non ignorée.
- **Par devise** : une règle correspondant à la devise dans laquelle le client est facturé s’applique, et le client est facturé exactement du montant de la règle.
- **Aucune correspondance ou aucun `pricing_mode`** : le prix de base du nouveau plan s’applique, avec conversion via [Adaptive Currency](/features/adaptive-currency) si nécessaire — le même mécanisme de repli qu’au checkout.

Cela s’applique à toutes les situations dans lesquelles un changement de plan peut être initié : la [Change Plan API](/api-reference/subscriptions/change-plan), les changements de plan en libre-service du [Customer Portal](/features/customer-portal) et les changements planifiés à la fin de la période de facturation.

- **Les aperçus sont exacts.** [Preview Change Plan](/api-reference/subscriptions/preview-change-plan) renvoie le même montant localisé que celui facturé lors du changement réel.
- **Les renouvellements conservent le prix localisé.** Après le changement, le nouveau plan est renouvelé à son montant localisé — et reste frais inclus — exactement comme un abonnement créé à ce prix.
- **La proratisation utilise les montants réels.** Lors d’une mise à niveau, le crédit correspondant à la période inutilisée est calculé à partir de ce que le client a réellement payé pour l’ancien plan, tandis que le nouveau plan est tarifé selon sa règle localisée.
- **Les changements planifiés bloquent le prix au moment de la planification.** Un changement planifié à la fin de la période de facturation facture le montant calculé au moment de la planification, même si vous modifiez la règle entre-temps.
- **La devise de facturation ne change jamais.** Un changement de plan ne modifie jamais la devise dans laquelle un abonnement est réglé ; une règle dans une autre devise est convertie dans celle-ci selon le taux de change.
- **Les modules complémentaires ne sont pas localisés.** Les prix des modules complémentaires du nouveau plan utilisent toujours leur tarification de base.

## Comportements importants

| Comportement | Détail |
| :--- | :--- |
| **Montants avant taxes** | Un montant localisé est le prix *avant* taxes. Pour les produits dont les taxes sont exclues, celles-ci sont ajoutées au checkout ; le montant localisé ne correspond donc pas au total final. Consultez [Tax-Inclusive Pricing](/features/tax-inclusive-pricing). |
| **Non disponible pour Pay What You Want** | Les règles localisées ne s’appliquent jamais aux produits [Pay What You Want](/features/pay-what-you-want), pour lesquels le client choisit le montant. |
| **La tarification par devise diffère de la tarification de base** | Une règle `by_currency` doit utiliser une devise différente de la devise de base du produit. |
| **Une règle par marché** | Un produit peut avoir au maximum une règle active par devise (par devise) ou par pays (par pays). |
| **Tous les types de produits** | S’applique aux produits ponctuels, aux abonnements et aux produits basés sur l’utilisation — y compris lorsqu’un abonné existant [change de plan](#how-it-applies-on-subscription-plan-changes). |

<Info>
Les changements de règles localisées n’émettent pas leurs propres webhooks. Le montant déterminé apparaît sur le paiement ou l’abonnement qui en résulte, exactement comme pour tout autre prix.
</Info>

## Bonnes pratiques

- **Conservez un prix de base cohérent.** Il sert de solution de repli pour tout marché sans règle, avec une conversion via Adaptive Currency.
- **Saisissez des montants nets.** Tout l'intérêt d'un montant fixe est d'obtenir un prix net comme ₹999, 9,99 € ou ¥1000, et non un résultat de conversion. Pour un arrondi automatique dans toutes les devises, consultez la [Tarification psychologique](/features/charm-pricing).
- **Choisissez le mode adapté à votre besoin.** Utilisez `by_country` pour une tarification fondée sur le pouvoir d'achat ; utilisez `by_currency` lorsqu'un prix par zone monétaire suffit.
- **Archivez plutôt que de recréer pour les promotions.** L'archivage d'une règle fait revenir le marché à la tarification de base/adaptive tout en préservant l'historique ; recréez ou modifiez le prix ultérieurement si nécessaire.
- **Vérifiez la fiscalité avant d'annoncer un prix total.** Pour les produits hors taxes, le client paie le montant localisé *plus* les taxes. Ne le présentez donc pas comme le prix final dans vos publicités.
