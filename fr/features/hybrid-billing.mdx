## Qu’est-ce que la facturation hybride ?

La facturation hybride combine plusieurs dimensions tarifaires au sein d’une seule offre. Au lieu de choisir entre des abonnements à tarif fixe OU une tarification basée sur l’utilisation, vous utilisez les deux simultanément.

### Pourquoi utiliser la facturation hybride ?

| Objectif commercial | Solution hybride |
|--------------|-----------------|
| Revenus prévisibles + potentiel de croissance | Abonnement de base + dépassement lié à l’utilisation |
| Tarification d’équipe évolutive | Par utilisateur + modules complémentaires |
| Acquérir des clients, puis élargir l’offre | Frais de base réduits + frais de consommation |
| Flexibilité pour les entreprises | Dépenses engagées + frais à la demande |
| Tarification équitable pour une utilisation variable | Quota inclus + paiement à l’utilisation |

### Modèles hybrides courants

| Modèle | Description | Exemple | Prise en charge native |
|-------|-------------|---------|----------------|
| **1. Abonnement + utilisation** | Frais de base + frais de consommation | \$49/mois + \$0.01/appel API après 10K appels gratuits | ✅ Complète |
| **2. Abonnement + utilisateurs** | Frais de plateforme + frais par utilisateur | \$99/mois + \$15/utilisateur | ✅ Complète |
| **3. Abonnement + modules complémentaires** | Offre principale + mises à niveau facultatives | \$29/mois + \$19/mois pour les analytics + \$9/mois pour l’accès API | ✅ Complète |
| **4. Utilisateurs + utilisation** | Frais par utilisateur + dépassement lié à la consommation | \$10/utilisateur/mois + \$0.05/GB après 5GB/utilisateur | ⚠️ Contournement nécessaire |
| **5. Abonnement + utilisateurs + utilisation** | Plateforme + utilisateurs + consommation (triple hybride) | \$199/mois + \$20/utilisateur + dépassement d’utilisation | ⚠️ Contournement nécessaire |
| **6. Base par niveaux + dépassement d’utilisation** | Différents niveaux avec différents quotas | Starter (5K appels) contre Pro (50K appels) + dépassement | ✅ Complète |
| **7. Abonnement + frais à la demande** | Frais récurrents + frais manuels variables | Retainer de \$99/mois + facturation horaire des prestations | ✅ Complète |

## Modèle hybride 1 : abonnement + utilisation

Le modèle hybride le plus courant. Les clients paient des frais d’abonnement de base, auxquels s’ajoutent les frais de consommation dépassant les quotas inclus.

### Fonctionnement

**Offre Pro : $49/mois**

- **Inclus** : 10,000 appels API/mois
- **Dépassement** : $0.005 par appel au-delà de 10,000

**Exemple de calcul** (le client utilise 25,000 appels ce mois-ci) :
- Abonnement de base : $49.00
- Dépassement : (25,000 - 10,000) × $0.005 = $75.00
- **Total : $124.00**

### Cas d’utilisation

- **Plateformes API** : accès de base + frais par requête
- **Services AI/ML** : abonnement + utilisation de tokens/générations
- **Services de stockage** : offre de base + dépassement par GB
- **Plateformes de communication** : base + frais par message/minute

### Mise en œuvre

<Steps>
<Step title="Create Usage Meter">
Configurez un meter pour suivre la dimension d’utilisation facturable.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
Créez un subscription product et associez-lui le meter d’utilisation avec sa tarification.

```bash
Dashboard: Create Product → Subscription
Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
Le meter d’utilisation est directement associé au subscription product. Les frais d’utilisation sont calculés et ajoutés automatiquement à la facture de l’abonnement.
</Info>
</Step>

<Step title="Create Checkout Session">
Créez une checkout session avec votre subscription product.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_pro_plan', quantity: 1 }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Send Usage Events">
Suivez l’utilisation pendant toute la période de facturation.

```typescript
await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [{
      event_id: `call_${Date.now()}`,
      customer_id: 'cus_123',
      event_name: 'api.call',
      timestamp: new Date().toISOString(),
      metadata: { endpoint: '/v1/generate' }
    }]
  })
});
```

</Step>
</Steps>

### Variantes tarifaires

<Tabs>
<Tab title="Included Allowance">
Le seuil gratuit couvre l’utilisation incluse dans l’abonnement de base.

**Offre Pro : $49/mois**
- Inclut : 10,000 appels API
- Dépassement : $0.005/appel après 10,000
- Le client utilise 8,000 appels → paie $49 (aucun dépassement)
</Tab>

<Tab title="Zero Base + Pure Usage">
Aucun frais de base : chaque unité est facturable dès la première utilisation.

**Paiement à l’utilisation : base à $0/mois**
- Inclut : 0 appel API
- Utilisation : $0.01/appel dès le premier appel
- Le client utilise 5,000 appels → paie $50
</Tab>

<Tab title="Tiered Allowances">
Différents niveaux incluent différents quotas.

- **Starter** : $19/mois (1,000 appels inclus)
- **Pro** : $49/mois (10,000 appels inclus)
- **Enterprise** : $199/mois (100,000 appels inclus)
- Tous les niveaux : dépassement de $0.005/appel
</Tab>
</Tabs>

## Modèle hybride 2 : abonnement + utilisateurs

Frais de plateforme auxquels s’ajoutent des frais par utilisateur. Idéal pour les outils de collaboration d’équipe et les solutions B2B SaaS.

### Fonctionnement

**Offre Team : $99/mois + $15/utilisateur**

- **Frais de plateforme de base** : $99/mois (inclut 3 utilisateurs)
- **Utilisateurs supplémentaires** : $15/utilisateur/mois

**Exemple de calcul** (équipe de 12 utilisateurs) :
- Frais de plateforme : $99.00
- Utilisateurs supplémentaires : (12 - 3) × $15 = $135.00
- **Total : $234.00/mois**

### Cas d’utilisation

- **Outils de collaboration** : frais d’espace de travail + frais par membre
- **Systèmes CRM** : licence de plateforme + frais par commercial
- **Gestion de projets** : offre d’équipe + frais par contributeur
- **Outils pour développeurs** : frais d’organisation + frais par développeur

### Mise en œuvre

<Steps>
<Step title="Create Seat Add-on">
Créez un add-on pour les utilisateurs supplémentaires.

```bash
Dashboard: Products → Add-ons → Create Add-on
Name: "Additional Seat"
Price: $15/month
Description: "Add another team member"
```

</Step>

<Step title="Create Base Subscription">
Créez le subscription product avec les frais de plateforme et associez l’add-on.

```bash
Dashboard: Create Product → Subscription
Name: "Team Plan"
Price: $99/month
Description: "Includes 3 team members"

Then in Add-ons section:
- Attach: "Additional Seat" add-on
```

</Step>

<Step title="Create Checkout with Seats">
Indiquez la quantité d’utilisateurs lors du checkout.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{
    product_id: 'prod_team_plan',
    quantity: 1,
    addons: [{
      addon_id: 'addon_seat',
      quantity: 9  // 9 extra seats (12 total with 3 included)
    }]
  }],
  customer: { email: 'admin@company.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Adjust Seats as Needed">
Ajoutez ou supprimez des utilisateurs sur les abonnements existants.

```typescript
// Add 5 more seats
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_team_plan',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  addons: [{
    addon_id: 'addon_seat',
    quantity: 14  // New total: 14 extra seats
  }]
});
```

</Step>
</Steps>

### Variantes tarifaires

<Tabs>
<Tab title="Included Seats">
L’offre de base inclut certains utilisateurs ; les utilisateurs supplémentaires sont facturés.

**Offre Team : $99/mois**
- Inclut : 5 utilisateurs
- Utilisateurs supplémentaires : $15/utilisateur/mois
- 20 utilisateurs = \$99 + (15 × \$15) = \$324/mois
</Tab>

<Tab title="Pure Per-Seat">
Aucun frais de plateforme, uniquement des frais par utilisateur.

**Par utilisateur : $25/utilisateur/mois**
- Aucun frais de plateforme
- 5 utilisateurs = $125/mois
- 50 utilisateurs = $1,250/mois

Mise en œuvre : définissez le prix de l’abonnement de base à $0 et utilisez uniquement l’add-on d’utilisateurs.
</Tab>

<Tab title="Tiered Per-Seat">
Le prix par utilisateur diminue pour les niveaux supérieurs.

- **Starter** : $20/utilisateur (1 à 10 utilisateurs)
- **Growth** : $15/utilisateur (11 à 50 utilisateurs)
- **Enterprise** : $10/utilisateur (51 utilisateurs et plus)

Mise en œuvre : créez des subscription products distincts pour chaque niveau, avec des prix d’add-on différents.
</Tab>
</Tabs>

## Modèle hybride 3 : abonnement + modules complémentaires de fonctionnalités

Abonnement principal auquel les clients peuvent ajouter des mises à niveau de fonctionnalités facultatives.

### Fonctionnement

**Offre principale : $29/mois**

**Modules complémentaires facultatifs :**
- Analytics avancés : +$19/mois
- Accès API : +$9/mois
- Support prioritaire : +$29/mois
- White-label : +$49/mois

**Exemple de calcul** (le client choisit l’offre principale + Analytics + accès API) :
- Offre principale : $29.00
- Analytics : $19.00
- Accès API : $9.00
- **Total : $57.00/mois**

### Cas d’utilisation

- **Plateformes SaaS** : fonctionnalités principales + modules premium
- **Outils marketing** : outil de base + intégrations
- **Produits d’analytics** : tableau de bord + rapports avancés
- **Logiciels de sécurité** : protection de base + fonctionnalités avancées

### Mise en œuvre

<Steps>
<Step title="Create Feature Add-ons">
Créez un add-on pour chaque fonctionnalité facultative.

</Step>

```bash

Price: $29/month

Then in Add-ons section:
- Attach all feature add-ons
```

## Modèle hybride 4 : utilisateurs + utilisation

Frais par utilisateur combinés à des frais basés sur la consommation. Chaque utilisateur bénéficie d’un quota.

<Warning>
**Limitation** : Dodo Payments ne prend actuellement pas en charge l’association simultanée de meters d’utilisation et d’add-ons au même subscription product. Ce modèle nécessite un contournement à l’aide d’une logique au niveau de l’application.
</Warning>

<Info>
**Bientôt disponible** : la prise en charge native de la facturation hybride Utilisateurs + Utilisation figure sur notre feuille de route. Elle vous permettra d’associer à un même subscription product des meters d’utilisation et des add-ons d’utilisateurs.
</Info>

### Fonctionnement

**Analytics d’équipe : $20/utilisateur/mois**

**Chaque utilisateur inclut :**
- 5 GB de traitement de données/mois
- Dépassement : $2/GB après le quota

**Exemple de calcul** (équipe de 10 utilisateurs utilisant 80 GB au total) :
- Frais utilisateurs : 10 × $20 = $200.00
- Données incluses : 10 × 5 GB = 50 GB
- Dépassement : (80 - 50) × $2 = $60.00
- **Total : $260.00/mois**

### Cas d’utilisation

- **Plateformes d’analytics** : par analyste + traitement des données
- **Outils de design** : par designer + stockage/exports
- **Environnements de développement** : par développeur + heures de calcul
- **Outils de communication** : par utilisateur + volume de messages/appels

### Options de mise en œuvre

Comme vous ne pouvez pas associer simultanément des meters d’utilisation et des add-ons au même abonnement, choisissez l’une des approches suivantes :

<Tabs>
<Tab title="Option A: Usage Product + App-Managed Seats">
Utilisez un abonnement basé sur l’utilisation et gérez la facturation des utilisateurs dans votre application.

<Steps>
<Step title="Create Usage Meter">

```bash

```

</Step>

<Step title="Create Usage-Based Subscription">

```bash

Base Price: $0/month

Attach usage pricing:
- Meter: data.processed
- Price per unit: $2/GB
- Free threshold: 0 (managed by your app)
```

</Step>

<Step title="Manage Seats in Your Application">
Suivez le nombre d’utilisateurs et calculez séparément les frais correspondants.

```typescript
// Your application tracks seats and calculates total cost
async function calculateMonthlyBill(customerId: string) {
  const seatCount = await getSeatCount(customerId);
  const seatFee = seatCount * 20; // $20/seat

  // Usage is billed by Dodo automatically
  // You invoice/charge seat fees separately or include in base price

  // Alternatively, adjust base subscription price when seats change
  const totalBasePrice = seatCount * 2000; // $20/seat in cents
  await client.subscriptions.update('sub_123', {
    // Update subscription to reflect seat-based pricing
  });
}
```

</Step>

<Step title="Calculate Dynamic Free Threshold">
Ajustez l’utilisation incluse en fonction du nombre d’utilisateurs.

```typescript
// When checking usage, apply per-seat allowance
async function checkUsageOverage(customerId: string) {
  const seatCount = await getSeatCount(customerId);
  const includedGB = seatCount * 5; // 5 GB per user

  const currentUsage = await getUsageFromDodo(customerId);
  const overage = Math.max(0, currentUsage - includedGB);

  // Overage is billed by Dodo at $2/GB
  return { included: includedGB, used: currentUsage, overage };
}
```

</Step>
</Steps>
</Tab>

<Tab title="Option B: Seat Add-on + On-Demand Usage Charges">

Calculez et facturez manuellement les dépassements d’utilisation.

```typescript
async function billUsageOverage(subscriptionId: string) {
  const subscription = await getSubscription(subscriptionId);
  const seatCount = subscription.addons.find(a => a.id === 'addon_seat')?.quantity || 0;

  const includedGB = seatCount * 5;
  const usedGB = await calculatePeriodUsage(subscription.customer_id);
  const overageGB = Math.max(0, usedGB - includedGB);

  if (overageGB > 0) {
    const overageCharge = overageGB * 200; // $2/GB in cents

      product_price: overageCharge,

}
```

</Step>

</Info>

## Modèle hybride 5 : abonnement + utilisateurs + utilisation (triple hybride)

Le modèle le plus complet : frais de plateforme + frais par utilisateur + consommation.

<Warning>
**Limitation** : Dodo Payments ne prend actuellement pas en charge l’association simultanée de meters d’utilisation et d’add-ons au même subscription product. Ce modèle nécessite un contournement.
</Warning>

<Info>
**Bientôt disponible** : la prise en charge native de la facturation triple hybride (base + utilisateurs + utilisation) figure sur notre feuille de route. Elle permettra d’associer à un même subscription product des meters d’utilisation et des add-ons d’utilisateurs.
</Info>

### Fonctionnement

**Plateforme Enterprise**

- **Frais de plateforme** : $199/mois
- **Par utilisateur** : $25/utilisateur/mois
- **Utilisation** : $0.10/1,000 appels API (50K inclus)

**Exemple de calcul** (entreprise de 20 utilisateurs effectuant 150,000 appels API) :
- Plateforme : $199.00
- Utilisateurs : 20 × $25 = $500.00
- Utilisation : (150K - 50K) × \$0.10/1K = \$10.00
- **Total : $709.00/mois**

### Cas d’utilisation

- **SaaS Enterprise** : plateforme + équipe + consommation
- **Plateformes de données** : espace de travail + analystes + requêtes
- **Plateformes d’intégration** : hub + connecteurs + transactions
- **Plateformes AI** : espace de travail + développeurs + inférence

### Options de mise en œuvre

Choisissez l’une des approches suivantes pour mettre en œuvre la facturation triple hybride :

<Tabs>
<Tab title="Option A: Base + Seats (Add-on) + On-Demand Usage">
Utilisez un abonnement avec des add-ons d’utilisateurs et facturez manuellement l’utilisation au moyen de frais à la demande.

**Il s’agit de l’approche recommandée**, car Dodo gère automatiquement les frais de plateforme et la facturation des utilisateurs.

```bash
Price: $25/month
```

</Step>

<Step title="Create Subscription Product">

```bash
Name: "Enterprise Platform"
Base Price: $199/month

Attach add-on:
- "User Seat" add-on

Enable on-demand charging
```

<Step title="Create Checkout with Seats">

### Clarté de la page tarifaire

<Tip>
Rendez la tarification hybride facile à comprendre. Présentez clairement les coûts de base, ce qui est inclus et le fonctionnement des dépassements sur votre page tarifaire.
</Tip>

**Bon** : "\$49/mois inclut 10,000 appels API. Appels supplémentaires : \$0.005 chacun"

**Mauvais** : "\$49/mois + frais d’utilisation"

### Prévisibilité des coûts

Aidez les clients à estimer leurs coûts :

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### Visibilité de l’utilisation

Montrez aux clients leur utilisation en temps réel :

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

## Résolution des problèmes de facturation hybride

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**Symptômes** : l’utilisation affiche 0 ou des valeurs incorrectes.

**Solutions** :
1. Vérifiez que l’ingestion des événements fonctionne (contrôlez les réponses API)
2. Vérifiez que `customer_id` correspond au client de l’abonnement
3. Vérifiez que `event_name` correspond à la configuration du meter
4. Vérifiez que les événements possèdent des timestamps corrects (et ne sont pas datés dans le futur)
</Accordion>

<Accordion title="Proration confusion with multiple components">
**Symptômes** : le client est facturé des montants inattendus lors d’un changement d’offre.

**Solutions** :
1. Utilisez l’API `previewChangePlan` pour afficher les frais exacts avant confirmation
2. Indiquez que le prorata s’applique à l’abonnement ET aux add-ons
3. Envisagez d’utiliser `difference_immediately` pour simplifier la facturation des mises à niveau
</Accordion>

<Accordion title="Free threshold not applying correctly">
**Symptômes** : le client est facturé pour une utilisation qui devrait être gratuite.

**Solutions** :
1. Vérifiez que le seuil gratuit est configuré sur le produit basé sur l’utilisation
2. Vérifiez que l’unité du seuil correspond à l’agrégation des événements (appels contre requêtes)
3. Confirmez que le meter d’utilisation est correctement associé au subscription product
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**Symptômes** : impossible d’ajouter des utilisateurs ou des fonctionnalités lors du checkout.

**Solutions** :
1. Vérifiez que les add-ons sont associés au subscription product dans le dashboard
2. Vérifiez que les identifiants des add-ons sont corrects dans les appels API
3. Assurez-vous que la devise de l’add-on correspond à celle du subscription product
</Accordion>
</AccordionGroup>
