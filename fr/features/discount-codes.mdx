## Qu'est-ce que les codes de rabais ?

Les codes de rabais sont des jetons promotionnels qui réduisent les totaux de commande au moment du paiement. Ils sont idéaux pour :

- **Campagnes saisonnières** : Black Friday, lancements de produits ou anniversaires
- **Offres d'acquisition** : Incitations à la première achat ou récompenses de parrainage
- **Fidélisation** : Récompenses de reconquête ou de fidélité pour les clients existants
- **Offres B2B** : Tarification contractée ou négociée via des codes privés

## Avantages clés

- **Rabais flexibles** : Pourcentage ou montant fixe de réduction
- **Contrôle ciblé** : Restriction par produit et cycles d'abonnement
- **Gouvernance des campagnes** : Dates d'expiration et limites d'utilisation
- **Paiement sans friction** : Champ UI et support API via des sessions de paiement

- **Remises flexibles** : remises en pourcentage ou d'un montant fixe
- **Codes cumulables** : appliquez jusqu'à 20 codes par commande, paiement ou abonnement — combinez des campagnes (par ex. `WELCOME10` + `BLACKFRIDAY20`) sans créer de codes personnalisés
- **Contrôle ciblé** : restreignez l'utilisation par produit, cycles d'abonnement et éligibilité du client
- **Gouvernance des campagnes** : dates de début planifiées, dates d'expiration, limites d'utilisation globales et par client
- **Tarification par devise** : définissez la déduction fixe, le plafond du montant et le sous-total minimum pour chaque devise
- **Checkout fluide** : prise en charge du champ dans l'interface et de l'API via les sessions de checkout

Créez des codes de rabais dans votre tableau de bord Dodo Payments, puis appliquez-les dans le paiement hébergé ou via l'API.

### Configuration dans le tableau de bord

- **Nom de la remise** (obligatoire) : nom interne et nom affiché dans le tableau de bord
- **Code** (obligatoire) : chaîne saisie par les clients lors du checkout, ou générez un code aléatoire à l'aide du bouton prévu à cet effet
- **Type** (obligatoire) : choisissez **Pourcentage** (réduction en pourcentage) ou **Montant** (déduction fixe)
- **Montant** (obligatoire) : valeur en pourcentage ou montant fixe pour une remise de type Montant
- **Date de début** (facultative) : planifiez l'activation ultérieure du code ; laissez ce champ vide pour l'activer immédiatement
- **Date d'expiration** (facultative) : date après laquelle le code devient invalide
- **Limite d'utilisation** (facultative) : nombre maximal total d'utilisations pour tous les clients
- **Limite d'utilisation par client** (facultative) : nombre maximal d'utilisations par un même client. Cette valeur doit être inférieure ou égale à la limite d'utilisation globale lorsque les deux sont définies
- **Éligibilité du client** (facultative) : limitez les personnes autorisées à utiliser le code — tous les clients, les nouveaux clients, les clients existants ou une liste sélectionnée manuellement
- **Options de devise** (facultatives) : valeurs par devise — consultez [Options par devise](#per-currency-options)
- **Restriction de produit** (facultative) : limitez l'applicabilité à certains produits
- **Limite de cycles d'abonnement** (facultative) : nombre de cycles de facturation pendant lesquels la remise s'applique
- **Conserver lors d'un changement de plan** (facultatif) : conservez la remise active lorsque le plan de l'abonnement change (`preserve_on_plan_change`)
- **Métadonnées** (facultatives) : ajoutez des paires clé-valeur personnalisées pour le suivi interne ou les intégrations

## Types de remise

| Type | Valeur API | Comportement |
|------|-----------|-----------|
| Pourcentage | `percentage` | Réduit le prix d'un pourcentage. Peut être plafonné par devise avec une remise maximale. |
| Montant | `flat` | Déduit un montant fixe. La déduction est répartie sur l'ensemble du panier plutôt qu'appliquée à chaque ligne. |

Les deux types peuvent être combinés dans le même tableau `discount_codes` et sont appliqués dans l'ordre du tableau.

## Éligibilité du client

Définissez `customer_eligibility` pour contrôler les personnes autorisées à utiliser un code :

| Valeur | Personnes autorisées à utiliser le code |
|-------|----------------|
| `any` | Tout client. Il s'agit de la valeur par défaut. |
| `first_time` | Clients n'ayant encore rien acheté auprès de vous. |
| `existing` | Clients ayant déjà acheté auprès de vous. |
| `specific` | Uniquement les clients que vous ajoutez à la liste d'autorisation du code. |

<Frame>
    <img src="/images/discount-codes/discount-restriction.png" alt="Menu déroulant d'éligibilité du client affichant les options Tout, Première commande, Existant et Client spécifique" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Warning>
Un code `specific` commence avec **zéro** client éligible et rejette toute utilisation jusqu'à ce que vous y ajoutiez des clients. Ajoutez-les dans le tableau de bord ou avec l'API des clients de remise.
</Warning>

Associez l'éligibilité à la **Limite d'utilisation par client** pour limiter le nombre de fois que chaque client peut utiliser le code, indépendamment de la limite d'utilisation globale.

## Options par devise

Les options de devise permettent à un même code de fonctionner correctement dans toutes les devises que vous vendez. Chaque entrée définit, pour une seule devise :

- **Montant** — pour une remise de type Montant, il s'agit de la déduction elle-même ; pour une remise en Pourcentage, il plafonne le montant que le code peut déduire. Correspond à `max_amount_possible` via l'API.
- **Sous-total minimum** — le code s'applique uniquement lorsque le panier atteint ce sous-total. `0` signifie qu'il n'y a aucun minimum.
- **Par défaut** — une entrée peut être marquée comme valeur par défaut à partir de laquelle les autres devises non configurées sont converties.

<Frame>
    <img src="/images/discount-codes/discount-currency-options.png" alt="Panneau des options de devise avec le montant et le sous-total minimum par devise pour INR et USD" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

Une remise de type Montant nécessite au moins une option de devise avec une valeur par défaut résolvable, car une déduction fixe n'a aucun sens sans devise. Les options de devise sont facultatives pour les remises en Pourcentage.

<Info>
Le sous-total minimum est toujours calculé à partir des prix d'origine du panier, jamais à partir du total intermédiaire au cours d'un cumul. L'ordre de cumul ne modifie donc jamais le respect du minimum.
</Info>

## Expérience de checkout

1. Les acheteurs saisissent le code dans le champ du checkout.
2. Les remises éligibles sont appliquées et les totaux sont mis à jour immédiatement.

<Info>
Dans les sessions de checkout, transmettez `discount_codes` (un tableau) pour préappliquer un ou plusieurs codes, et définissez `feature_flags.allow_discount_code` pour afficher le champ de saisie. Les codes sont appliqués dans l'ordre du tableau, jusqu'à un maximum de 20.
</Info>

## Cumul des codes de remise

Les sessions de checkout, les paiements et les abonnements acceptent jusqu'à **20 codes cumulés** via le tableau `discount_codes` (20 entrées maximum). Les codes sont appliqués **dans l'ordre du tableau** : le premier code éligible réduit d'abord le prix de base, le suivant réduit le prix déjà remisé, et ainsi de suite. L'ensemble des remises appliquées est renvoyé dans la réponse sous `discount_ids` (pour les paiements/abonnements) et `discounts` (détails plus complets par remise, notamment la position et le nombre de cycles d'abonnement restants).

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_abc', quantity: 1 }],
  discount_codes: ['WELCOME10', 'BLACKFRIDAY20'], // applied in this order
  customer: { email: 'user@example.com' },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Le champ singulier `discount_code` est **obsolète**, mais reste entièrement pris en charge pour assurer la rétrocompatibilité — les intégrations existantes continuent de fonctionner sans modification. Il ne peut pas être combiné avec `discount_codes` dans la même requête. Nous vous recommandons de migrer vers `discount_codes` (la forme tableau) lorsque cela vous convient, même pour un seul code, afin de profiter du cumul et d'une structure de réponse plus riche.
</Info>

## Cas d'utilisation courants

- **Offres de lancement** : promotions limitées dans le temps pour de nouveaux produits
- **Achats en volume ou B2B** : remises contractuelles pour certains ensembles de produits
- **Fidélisation** : codes de reconquête dans les processus de prévention du churn
- **Campagnes saisonnières** : promotions liées aux fêtes ou à des événements

## Exemples d'intégration

### Créer une remise avec des métadonnées
Ajoutez des paires clé-valeur personnalisées pour le suivi interne.

```typescript
const discount = await client.discounts.create({
  type: 'percentage',
  amount: 1500, // 15%
  code: 'SUMMER2025',
  metadata: {
    campaign: 'summer_promo',
    source: 'email_blast'
  }
});
```

<Tip>
Utilisez les métadonnées pour associer les remises à une campagne, une source ou un ID de référence interne afin de rapprocher ultérieurement les utilisations et de mesurer le ROI.
</Tip>

### Appliquer des remises dans les sessions de checkout
Préappliquez une ou plusieurs remises cumulées et affichez l'interface de saisie du code.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  discount_codes: ['BLACKFRIDAY2024', 'NEWUSER5'], // stacked in array order
  customer: { email: 'user@example.com', name: 'Jane Doe' },
  return_url: 'https://yoursite.com/return'
});
```

### Appliquer des remises lors d'un changement de plan
Proposez une tarification promotionnelle lorsque les clients passent à un plan supérieur ou inférieur.

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  discount_codes: ['UPGRADE20']
});
```

| Valeur de `discount_codes` | Comportement lors d'un changement de plan |
|------------------------|-------------------------|
| `undefined` / `null` (non fourni) | Les remises existantes avec `preserve_on_plan_change=true` sont conservées si elles s'appliquent au nouveau produit. |
| `[]` (tableau vide) | **Toutes** les remises existantes sont supprimées de l'abonnement. |
| `['CODE_A', 'CODE_B', ...]` | Remplace toutes les remises existantes par cet ensemble cumulé, appliqué dans l'ordre du tableau. |

<Info>
Consultez toutes les remises appliquées à l'abonnement via le nouveau tableau `discounts` dans la réponse de l'abonnement. Chaque entrée comprend `discount_id`, `position`, `cycles_remaining` (pour les abonnements) et le code d'origine.
</Info>

### Activer la saisie d'une remise sans préapplication
Permettez aux clients de saisir un code lors du checkout sans en transmettre un au préalable.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return'
});
```

## Bonnes pratiques

- **Nommez clairement** : utilisez des codes reconnaissables correspondant aux noms des campagnes
- **Limitez dans le temps** : ajoutez des dates d'expiration pour créer un sentiment d'urgence et éviter les abus
- **Définissez judicieusement le périmètre** : limitez les remises à certains produits afin d'éviter une érosion des marges
- **Validez en amont** : vérifiez l'applicabilité du code avant de confirmer le checkout
- **Suivez l'impact** : mesurez l'utilisation et la conversion par campagne

<Info>
Les codes de remise sont de puissants leviers d'acquisition et de fidélisation. Commencez par des offres simples et clairement nommées, validez-les rigoureusement, puis ajustez-les en fonction de leurs performances.
</Info>
