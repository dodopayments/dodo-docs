<Info>
Les clés de licence sont le type de droit de licence. Créez un droit de clé de licence une fois avec la limite d'activation, l'expiration et les instructions souhaitées, attachez-le à n'importe quel produit, et Dodo Payments génère et délivre une clé par achat ou siège d'abonnement, automatiquement.
</Info>

## Que sont les clés de licence ?

Les clés de licence sont des jetons uniques qui autorisent l'accès à votre produit. Elles sont idéales pour :

- **Licences de logiciel** : Applications de bureau, plugins et CLIs
- **Contrôles par utilisateur** : Limitez les activations par utilisateur ou appareil
- **Biens numériques** : Restreindre les téléchargements, mises à jour ou fonctionnalités premium

Dans Dodo Payments, les clés de licence sont gérées via le système de [Droits](/features/entitlements/introduction), ce qui signifie que le cycle de vie de chaque clé (création, expiration, révocation, réattribution) est piloté par les mêmes événements de paiement et d'abonnement que vos autres livrables.

## Créer un droit de clé de licence

<Steps>
{/* LOCKED_PATTERN_f16e14811ca298b21da18fc853f7ddb4 */}
Accédez à **Droits** dans votre tableau de bord Dodo Payments et cliquez sur **+** pour créer un nouveau droit.
</Step>

{/* LOCKED_PATTERN_5d767446a528196b6d908f9c763c6dfe */}
Sélectionnez **Clé de licence** comme intégration. Configurez le comportement de chaque clé émise :

- **Limite d'activations** : Maximum d'activations simultanées par clé (par exemple, `1` pour utilisateur unique, `5` pour licences d'équipe, laissez vide pour illimité).
- **Durée** : Durée de validité de la clé après émission (par exemple, 30 jours, 1 an). Pour les clés émises par abonnement, laissez vide ; les clés restent valides tant que l'abonnement est actif.
- **Instructions d'activation** : Instructions destinées aux clients envoyées par email avec la clé. Exemples : `Paste the key in Settings → License` ou `Run: mycli activate <key>`.

## Attacher aux produits

Ouvrez un produit, développez **Paramètres avancés → Droits & Crédits**, et sélectionnez votre droit de clé de licence. Un seul produit peut délivrer une clé de licence ainsi que d'autres droits (accès Discord, téléchargements de fichiers, accès aux dépôts GitHub, etc.) lors du même achat.

## Comment les clés sont-elles émises

L'émission des clés suit le [cycle de vie des droits](/features/entitlements/introduction#how-grants-work) standard :

| Événement | Comportement |
|---|---|
| `payment.succeeded` (unique) | Générer une clé par `quantity` acheté. L'expiration de la clé respecte la durée du droit. |
| `subscription.active` | Générer une clé par abonnement `quantity` (siège). La clé n'a pas d'expiration ; la validité est liée au statut de l'abonnement. |
| `subscription.renewed` | Aucune opération. Les clés existantes persistent. |
| `subscription.on_hold` | Désactiver les clés. Elles se réactivent lorsque l'abonnement est réactivé. |
| `subscription.cancelled` / `expired` | Désactiver définitivement les clés. |
| `subscription.plan_changed` | Désactiver les anciennes clés ; émettre de nouvelles pour le nouveau plan. |
| `refund.succeeded` (unique) | Désactiver les clés. |
| Révocation manuelle via API/tableau de bord | Désactiver les clés avec `revocation_reason: manual`. Elles ne sont pas réattribuées automatiquement lors du renouvellement de l'abonnement. |
| Clé de licence désactivée directement | Révoquer le droit avec `revocation_reason: license_key_disabled`. La réactivation de la clé réactive automatiquement le droit. |

### Comportement des quantités

- **Produits d'abonnement** émettent une clé par siège (`subscriptions.quantity`).
- **Produits uniques** émettent une clé par article de la ligne de panier (`product_cart.quantity`).
- **Attributions manuelles par API** émettent exactement une clé.

## Activation, Validation, Désactivation

Les extrémités de l'API d'activation/validation/désactivation sont **publiques** et ne nécessitent aucune clé API. Utilisez-les directement depuis les logiciels de bureau, les CLI ou les clients basés sur navigateur pour vérifier les clés à l'exécution.

<Info>
**Endpoints Publics** : Les endpoints d'activation, de désactivation et de validation de licence sont publics et ne nécessitent pas de clé API. Appelez-les directement depuis vos applications clientes sans exposer vos identifiants API.
</Info>

### Activer une licence

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';

// No API key needed for public license endpoints
const client = new DodoPayments();

const response = await client.licenses.activate({
  license_key: 'PRO-AAAA-BBBB-CCCC-DDDD',
  name: 'Device Name',
});

console.log(response.id);
```

```python Python theme={null}
client.licenses.activate(
    license_key="PRO-AAAA-BBBB-CCCC-DDDD",
    name="Device Name",
)
```

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/licenses/activate \
  -H "Content-Type: application/json" \
  -d '{
    "license_key": "PRO-AAAA-BBBB-CCCC-DDDD",
    "name": "Device Name"
  }'
```

</CodeGroup>

### Valider une licence

<CodeGroup>

```typescript TypeScript theme={null}
const response = await client.licenses.validate({
  license_key: 'PRO-AAAA-BBBB-CCCC-DDDD',
});

console.log(response.valid);
```

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/licenses/validate \
  -H "Content-Type: application/json" \
  -d '{ "license_key": "PRO-AAAA-BBBB-CCCC-DDDD" }'
```

</CodeGroup>

### Désactiver une instance d'activation

```typescript theme={null}
await client.licenses.deactivate({
  license_key: 'PRO-AAAA-BBBB-CCCC-DDDD',
  license_key_instance_id: 'instance_abc123',
});
```

## Gérer les clés

Ouvrez le droit de clé de licence depuis votre tableau de bord pour voir chaque droit (une ligne par clé client) avec la date de livraison, le nombre d'activations et une action de révocation. Chaque détail de droit révèle la clé de licence sous-jacente, l'expiration, les activations utilisées et la limite d'activations.

Vous pouvez également lister les droits de manière programmatique :

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_license_key_id', {
  status: 'delivered',
});

for (const grant of grants.items) {
  console.log(grant.license_key.key, grant.license_key.activations_used);
}
```

## Importer des clés de licence existantes via l'API

Avez-vous déjà des clés de licence dans un autre système ? Utilisez l'API [Créer une clé de licence](/api-reference/licenses/create-license-key) pour les importer dans Dodo Payments. Cela vous permet de migrer des clés existantes sans perturber vos clients — ils continuent d'activer, de valider et de désactiver avec les mêmes chaînes de clés sans réémission.

{/* LOCKED_PATTERN_4907e9f6f7bdb37_END */}
Les clés de licence créées ou mises à jour via l'API ne déclenchent pas de notifications par email aux clients. Si vous avez besoin de notifier vos clients à propos d'une clé importée, gérez-le séparément dans votre application.
{/* LOCKED_PATTERN_176d815432e7554ac558e8631b2bc397 */}

```typescript theme={null}
const licenseKey = await client.licenseKeys.create({
  customer_id: 'cus_abc123',
  product_id: 'prod_456',
  key: 'YOUR-EXISTING-LICENSE-KEY',
  activations_limit: 5,
  expires_at: '2026-12-31T23:59:59Z',
});
```

### Comment les clés importées diffèrent des clés générées automatiquement

| Champ | Clé générée automatiquement | Clé importée |
|-------|----------------------------|-------------|
| `source` | `"auto"` | `"import"` |
| `payment_id` | Défini sur le paiement d'origine | `null` (aucune transaction Dodo Payments) |
| `subscription_id` | Défini si la clé a été émise via un abonnement | `null` à moins d'être explicitement lié |
| Notification par email au client | Envoyée lors de l'émission | Non envoyée — à gérer séparément |

Utilisez le champ `source` sur les réponses `GET /license_keys` pour distinguer l'inventaire migré des clés émises organiquement lors de la réconciliation ou de l'audit.

<Tip>
Migration depuis **Polar.sh** ou **Lemon Squeezy** ? Le [`dodo-migrate` CLI](/migrate-to-dodo) automatise les importations en masse de produits, de clients, de remises et de clés de licence en une seule commande et mappe automatiquement les ID externes aux ID Dodo.
</Tip>

## Clés de licence dans l'URL de retour

Lorsqu'un client effectue un achat pour un produit avec un droit de clé de licence, la clé générée est automatiquement ajoutée à votre `return_url` en tant que paramètre de requête. Cela vous permet d'afficher la clé immédiatement sur votre page de succès sans effectuer un appel API supplémentaire.

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com
```

Si l'achat génère plusieurs clés (quantité > 1), elles sont séparées par des virgules :

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001,LK-002&email=customer%40example.com
```

Pour les abonnements, `subscription_id` est utilisé à la place de `payment_id` :

```text theme={null}
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001&email=customer%40example.com
```

<Tip>
Analysez le paramètre `license_key` sur votre page de retour pour afficher la clé immédiatement, améliorant ainsi l'expérience post-achat.
</Tip>

## Clés de licence dans l'URL de retour

Lorsqu'un client termine un achat pour un produit avec des clés de licence activées, la clé de licence est automatiquement ajoutée à votre `return_url` comme paramètre de requête. Cela vous permet d'afficher la clé immédiatement sur votre page de réussite sans faire un appel API supplémentaire.

```text
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com
```

Si l'achat génère plusieurs clés de licence (par exemple, quantité > 1), elles sont séparées par des virgules :

```text
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001,LK-002&email=customer%40example.com
```

Pour les abonnements, `subscription_id` est utilisé au lieu de `payment_id` :

```text
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001&email=customer%40example.com
```

<Tip>
Analysez le paramètre `license_key` sur votre page de retour pour afficher immédiatement la clé aux clients, améliorant ainsi l'expérience après achat.
</Tip>

## Meilleures pratiques

- **Gardez des limites claires** : Choisissez des valeurs par défaut sensées pour l'expiration et les activations
- **Guide des utilisateurs** : Fournissez des instructions d'activation précises et une documentation en libre-service
- **Automatisation des vérifications** : Validez les clés côté serveur avant d'accorder l'accès
- **Surveillez les événements** : Utilisez des webhooks pour détecter les abus et automatiser les révocations

The legacy `license_key.*` events (`license_key.created`) continue to fire for the underlying license-key record lifecycle; see the [License Key webhook payload page](/developer-resources/webhooks/intents/license-key).

<Tip>
For new integrations, listen to `entitlement_grant.delivered` rather than `license_key.created`. The entitlement event tells you delivery is complete across all integrations on the product, not just the license key.
</Tip>

## Legacy License Keys

<Note>
Products created with the older `license_key_enabled` flag have been **automatically migrated** to a License Key entitlement. The migration is transparent: existing customers' keys continue to work unchanged, the public `/licenses/activate`, `/licenses/validate`, `/licenses/deactivate` endpoints continue to function, and the `/license_keys/*` API endpoints continue to read and write to the same key store.

The standalone **License Keys** dashboard section remains available as a flat list of every key issued, useful for audit and search. New configuration (changing activation limits, durations, or instructions) should be done by editing the migrated License Key entitlement under **Entitlements**.
</Note>

## Best Practices

- **Keep activation limits clear**: Choose sensible defaults (1 for single-user apps, 3–5 for team licenses) and document them.
- **Provide precise activation instructions**: Customers paste these from their email, so exact paths and commands save support tickets.
- **Validate keys server-side**: For network-connected products, validate via `/licenses/validate` rather than caching activation locally.
- **Use webhooks for revocation**: Listen to `entitlement_grant.revoked` to disable in-app features immediately when a customer cancels or refunds.
- **Test with subscriptions and one-times**: License key behavior differs subtly between the two, so test both before going live.
