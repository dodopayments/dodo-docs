## Adaptive Currency

Adaptive Currency permet aux clients de payer dans leur devise locale préférée, ce qui renforce la confiance et améliore les taux de conversion.

### Fonctionnement

1. **Activer** : activez Adaptive Currency depuis **Settings → Business**
2. **Sélectionner** : les clients peuvent changer de devise directement lors du checkout
3. **Appliquer la PPP** : si la [Purchasing Power Parity](/features/purchasing-power-parity) est activée pour le produit, le pourcentage associé au pays réduit le prix de base
4. **Convertir** : le prix (ou le prix ajusté selon la PPP) est converti dans la devise du client aux taux de change en temps réel
5. **Arrondir** : si la [Charm Pricing](/features/charm-pricing) est activée, le montant converti est arrondi à une valeur de terminaison standard comme 49.99
6. **Afficher** : le montant final à payer est affiché de manière transparente avant le paiement

## Calcul automatique des taxes

Les taxes sont calculées automatiquement en fonction de l'adresse de facturation du client, ce qui garantit la conformité aux exigences relatives à la GST, à la VAT et aux taxes sur les ventes, sans configuration manuelle.

### Fonctionnement du calcul des taxes

<Steps>
<Step title="Location Detection">
  Les règles fiscales sont appliquées en fonction du pays du client (et de la région, le cas échéant).
</Step>

<Step title="Dynamic Updates">
  Le montant des taxes est mis à jour automatiquement lorsque :
  - Le pays change
  - L'adresse est mise à jour
</Step>

<Step title="Transparent Display">
  Le détail final des taxes est clairement affiché avant le paiement.
</Step>
</Steps>

<Tip>
Le calcul des taxes est entièrement automatisé. Aucune configuration manuelle n'est requise pour les produits numériques et les produits SaaS standard.
</Tip>

## Prise en charge du numéro fiscal de l'entreprise

Pour les entreprises enregistrées, le paiement permet aux clients de saisir leur numéro fiscal d'entreprise (par exemple, un numéro de VAT/GST).

### Que se passe-t-il lorsqu'un numéro fiscal est saisi ?

- L'éligibilité fiscale est validée en temps réel
- Les exonérations fiscales applicables ou les règles d'autoliquidation sont appliquées
- Le montant des taxes est mis à jour instantanément lors du paiement

## Codes de réduction

Les clients peuvent appliquer directement sur la page de paiement les codes de réduction ou promotionnels que vous avez créés dans le tableau de bord.

### Expérience de paiement

1. Le client saisit le code de réduction
2. La réduction est validée instantanément
3. Le prix mis à jour et les économies réalisées sont clairement affichés

Lorsque la [Purchasing Power Parity](/features/purchasing-power-parity) est activée pour un produit, la remise s'applique au prix ajusté selon la PPP, et non au prix de base.

<Frame>
  <img src="/images/checkout/c4.png" alt="Saisie d'un code de remise lors du checkout" style={{ maxHeight: '500px', width: '70%' }}/>
</Frame>

### Intégration API

Préappliquez un ou plusieurs codes de remise cumulés ou activez le champ de saisie des remises :

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Shown by default; set to false to hide the field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`discount_codes` accepte un tableau contenant jusqu'à 20 codes, cumulés dans l'ordre. Le champ singulier `discount_code` est obsolète, mais fonctionne toujours — les intégrations existantes n'ont pas besoin d'être modifiées immédiatement. Migrez vers `discount_codes` lorsque cela vous conviendra afin d'utiliser le cumul et une structure de réponse plus riche.
</Info>

## Collecte intelligente des adresses

Le checkout prend en charge la saisie flexible des adresses pour accélérer le parcours.

### Options disponibles

| Option | Description |
|--------|-------------|
| **Google Address Autofill** | Sélection rapide avec saisie semi-automatique |
| **Saisie manuelle** | Contrôle total pour les adresses complètes |
| **Sélection du pays** | Détermine la logique fiscale et de conformité |
| **Adresse minimale** | Collecte uniquement le pays (et le code postal lorsqu'il est requis pour la fiscalité) — consultez le [mode Adresse minimale](#minimal-address-mode) |

<Tip>
La collecte des adresses équilibre rapidité, précision et couverture mondiale afin de maximiser la conversion tout en garantissant la conformité.
</Tip>

### Mode Adresse minimale

Pour maximiser la conversion, activez la collecte d'adresses minimale afin de réduire les frictions lors du checkout. Lorsque `minimal_address` est défini sur `true`, le checkout collecte uniquement :

- **Pays** — toujours requis pour déterminer les taxes
- **Code ZIP/postal** — uniquement dans les régions où il est nécessaire pour calculer la sales tax, la TVA ou la GST

Tous les autres champs d'adresse (rue, ville, État ou région) sont ignorés, ce qui accélère considérablement la finalisation du checkout.

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="Mode Adresse minimale affichant uniquement les champs du pays et du code ZIP/postal lors du checkout" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
La collecte complète des adresses reste le comportement par défaut. Activez `minimal_address` pour les produits numériques et les parcours SaaS qui ne nécessitent pas de coordonnées de facturation complètes.
</Info>

## Collecte du numéro de téléphone

Contrôlez l'affichage du champ du numéro de téléphone lors du checkout — et déterminez s'il est requis — à l'aide des indicateurs de fonctionnalité de la session de checkout.

| Indicateur | Par défaut | Comportement |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | Affiche le champ du numéro de téléphone dans le formulaire de checkout |
| `require_phone_number` | `false` | Rend le champ du numéro de téléphone obligatoire (la validation du formulaire impose une valeur non vide) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`require_phone_number: true` nécessite `allow_phone_number_collection: true`. L'API rejette les sessions lorsque la collecte du téléphone est désactivée alors que le numéro de téléphone est obligatoire.
</Warning>

<Tip>
Utilisez `require_phone_number` pour les SaaS B2B, les secteurs réglementés ou tout parcours nécessitant un canal de contact vérifié pour l'assistance, l'analyse des fraudes ou la conformité.
</Tip>

## Champs personnalisés

Collectez des informations supplémentaires auprès des clients lors du checkout en définissant des champs de formulaire personnalisés. Cette fonctionnalité est utile pour recueillir des données telles que le nom de l'entreprise, la taille de l'équipe, la source de recommandation ou toute autre information propre à votre activité.

### Types de champs disponibles

| Type | Description |
|------|-------------|
| `text` | Champ de texte sur une ligne |
| `number` | Saisie numérique |
| `email` | Adresse e-mail avec validation |
| `url` | URL avec validation |
| `date` | Sélecteur de date |
| `dropdown` | Sélection parmi des options prédéfinies |
| `boolean` | Interrupteur Oui/Non |

### Exemple

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Les réponses des clients sont automatiquement incluses dans les charges utiles des webhooks (`payment.succeeded`, `subscription.active`) et dans les réponses de l'API via le tableau `custom_field_responses`. Vous pouvez définir jusqu'à 5 champs personnalisés par session de checkout.
</Info>

## Acceptation de la politique de confidentialité et des conditions

Pour garantir la transparence juridique et en matière de conformité :

- Les liens vers la [Politique de confidentialité](https://dodopayments.com/privacy-policy) et les [Conditions applicables aux acheteurs](https://dodopayments.com/buyer-terms) sont clairement affichés lors du checkout

## Checkout de collection

Les collections de produits permettent une expérience de checkout unifiée, où les clients peuvent consulter et sélectionner plusieurs produits associés (par exemple, les formules Starter, Pro et Enterprise) lors d'un même checkout.

### Fonctionnement

1. **Tous les produits sont affichés** : les clients voient tous les produits actifs de la collection
2. **Le premier produit est présélectionné** : le premier produit de la collection est automatiquement sélectionné
3. **Comparer les options** : les clients peuvent comparer les prix et les fonctionnalités avant de choisir
4. **Sélection unique** : après avoir sélectionné un produit, le checkout se poursuit avec le parcours de paiement standard

### Création d'un checkout de collection

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
Lorsque vous utilisez `product_collection_id`, transmettez un tableau `product_cart` vide. Les codes de remise ne peuvent pas être préappliqués lors de la création de la session.
</Warning>

## Configuration de la session de checkout

Contrôlez le comportement du checkout à l'aide de l'API Checkout Sessions :

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
Après le paiement, les clients sont redirigés vers votre `return_url`, auquel des paramètres de requête sont automatiquement ajoutés — notamment `payment_id` ou `subscription_id`, `status`, `email` et `license_key` (le cas échéant). Consultez le [guide Checkout Sessions](/developer-resources/checkout-session#request-body) pour obtenir la liste complète.
</Info>

## Personnalisation du thème du checkout

Personnalisez l'apparence de la page de checkout pour l'adapter à votre marque à l'aide du paramètre `customization.theme_config` lors de la création d'une session de checkout via l'API. Configurez les couleurs, les polices, le rayon des bordures et le texte des boutons pour les modes clair et sombre.

<Card title="Design & Theme Customization" icon="palette" href="/features/design">
  Configurez visuellement les thèmes depuis le tableau de bord avec des thèmes prédéfinis, la typographie, les couleurs et un aperçu en temps réel.

<Info>
Cette section traite de la configuration du thème via l'**API côté serveur** à l'aide de `customization.theme_config`. Si vous utilisez le **Checkout SDK** (checkout en superposition ou intégré), consultez la section de personnalisation du thème dans [Overlay Checkout](/developer-resources/overlay-checkout#theme-customization), qui utilise des propriétés camelCase (par exemple, `bgPrimary` au lieu de `bg_primary`).
</Info>

### Options de configuration du thème

| Propriété | Description |
|----------|-------------|
| `light` | Configuration des couleurs pour le mode clair |
| `dark` | Configuration des couleurs pour le mode sombre |
| `font_primary_url` | URL de la police principale |
| `font_secondary_url` | URL de la police secondaire |
| `font_size` | Taille de police : `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `font_weight` | Graisse de police : `normal`, `medium`, `bold`, `extraBold` |
| `radius` | Rayon des bordures des éléments d'interface (par exemple, `4px`, `0.5rem`, `8px`) |
| `pay_button_text` | Texte personnalisé du bouton de paiement (par exemple, "Complete Purchase", "Subscribe Now") |

### Configuration des couleurs (mode clair/sombre)

Chaque mode (`light` et `dark`) prend en charge les propriétés de couleur suivantes :

| Propriété | Description |
|----------|-------------|
| `bg_primary` | Couleur d'arrière-plan principale |
| `bg_secondary` | Couleur d'arrière-plan secondaire |
| `text_primary` | Couleur principale du texte |
| `text_secondary` | Couleur secondaire du texte |
| `text_placeholder` | Couleur du texte d'espace réservé |
| `text_error` | Couleur du texte d'erreur |
| `text_success` | Couleur du texte de réussite |
| `border_primary` | Couleur principale des bordures |
| `border_secondary` | Couleur secondaire des bordures |
| `button_primary` | Couleur d'arrière-plan du bouton principal |
| `button_primary_hover` | Couleur au survol du bouton principal |
| `button_secondary` | Couleur d'arrière-plan du bouton secondaire |
| `button_secondary_hover` | Couleur au survol du bouton secondaire |
| `button_text_primary` | Couleur du texte du bouton principal |
| `button_text_secondary` | Couleur du texte du bouton secondaire |
| `input_focus_border` | Couleur de la bordure lors du focus d'un champ |

<Info>
Tous les champs de couleur acceptent les formats de couleur CSS standard :
- Hexadécimal : `#fff`, `#ffffff`, `#ffffffff`
- RGB/RGBA : `rgb(255, 255, 255)`, `rgba(255, 255, 255, 0.5)`
- HSL/HSLA : `hsl(120, 100%, 50%)`, `hsla(120, 100%, 50%, 0.5)`
- Couleurs nommées : `red`, `blue`, `transparent`
</Info>

### Exemple

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  customization: {
    theme_config: {
      // Custom fonts
      font_primary_url: 'https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&display=swap',
      font_size: 'md',
      font_weight: 'medium',
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      
      // Light mode colors
      light: {
        bg_primary: '#ffffff',
        bg_secondary: '#f5f5f5',
        text_primary: '#1a1a1a',
        text_secondary: '#666666',
        button_primary: '#0066ff',
        button_primary_hover: '#0052cc',
        button_text_primary: '#ffffff',
        border_primary: '#e0e0e0'
      },
      
      // Dark mode colors
      dark: {
        bg_primary: '#1a1a1a',
        bg_secondary: '#2d2d2d',
        text_primary: '#ffffff',
        text_secondary: '#a0a0a0',
        button_primary: '#3385ff',
        button_primary_hover: '#4d99ff',
        button_text_primary: '#ffffff',
        border_primary: '#404040'
      }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

<Tip>
Vous n'avez pas besoin de spécifier toutes les propriétés de couleur. Les propriétés non spécifiées utiliseront les valeurs du thème par défaut.
</Tip>
