Les portefeuilles numériques permettent aux clients de payer en un seul clic avec les moyens de paiement enregistrés sur leurs appareils. Ils offrent de meilleurs taux de conversion, une sécurité renforcée grâce à la tokenisation et une expérience de paiement simplifiée.

## Portefeuilles pris en charge

| Portefeuille | Disponibilité | Devises | Abonnements | Configuration requise |
| :----- | :----------- | :--------- | :-----------: | :------------- |
| **Apple Pay** | Mondial (hors Inde) | Toutes | Oui | Vérification du domaine |
| **Google Pay** | Mondial (hors Inde) | Toutes | Oui | Aucune |
| **Amazon Pay** | Mondial (hors Inde) | USD | Non | Aucune |
| **Cash App Pay** | États-Unis uniquement | USD | Oui | Aucune |
| **RevolutPay** | Mondial | GBP | Non | Aucune |

<Warning>
**Prise en charge de PayPal suspendue :** PayPal est temporairement indisponible pour les nouvelles transactions.
</Warning>

## Apple Pay

Apple Pay permet aux clients de payer avec les cartes enregistrées dans leur Apple Wallet, avec une authentification Face ID ou Touch ID.

<Info>
Apple Pay est proposé pour les abonnements même lorsque le premier prélèvement est de **0 $** (par exemple, pendant les essais gratuits), afin que le mandat de paiement puisse être configuré lors de l'inscription. Pour les paiements ponctuels, Apple Pay est affiché uniquement lorsque le montant est supérieur à 0 $.
</Info>

### Exigences
- **Appareils :** iOS 17+, iPadOS 17+, Safari 17+ sur macOS
- **Protocole :** HTTPS requis
- **Domaine :** Doit être vérifié auprès d'Apple

### Vérification du domaine

<Info>
La vérification du domaine est requise uniquement pour le paiement **intégré (embedded)**. Le paiement en overlay, le paiement hébergé et les liens de paiement n'en ont pas besoin.
</Info>

<Steps>
<Step title="Open Wallet domains">
Dans votre dashboard, accédez à **Settings → Payment Methods** puis, sur la ligne **Apple Pay**, cliquez sur **Manage domains**.

<Frame caption="Open Wallet domains from the Apple Pay row">
  <img src="/images/apple-pay-domains/manage-domains.png" alt="Bouton Manage domains sur la ligne Apple Pay dans les paramètres Payment Methods" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Download the domain association file">
Depuis le panneau des domaines de portefeuille, téléchargez le fichier d'association.

<Frame caption="Download the Apple Pay domain association file">
  <img src="/images/apple-pay-domains/wallet-domains-panel.png" alt="Panneau des domaines de portefeuille avec le bouton Download file" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Register your domain">
Cliquez sur **Register domain** et saisissez le domaine où vous intégrez le paiement (par exemple, `shop.example.com`), puis cliquez sur **Continue**.

<Frame caption="Register the domain where you embed checkout">
  <img src="/images/apple-pay-domains/register-domain.png" alt="Formulaire d'enregistrement d'un domaine avec un domaine saisi" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Host the file on your domain">
Téléversez-le sur votre serveur à l'adresse suivante :

```
https://shop.example.com/.well-known/apple-developer-merchantid-domain-association
```

Le fichier doit être servi via HTTPS, être accessible sans redirection et être servi avec `Content-Type: application/octet-stream` ou `text/plain`.
</Step>

<Step title="Verify the domain">
Cliquez sur **Verify domain**. Dodo Payments vérifie le fichier hébergé et envoie votre domaine à Apple.

<Frame caption="Verify the hosted association file">
  <img src="/images/apple-pay-domains/verify-domain.png" alt="Écran de vérification du domaine avec le chemin d'hébergement du fichier d'association et le bouton Verify domain" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Confirm it's active">
Lorsque le statut indique **Active**, Apple Pay est actif pour ce domaine. Utilisez le bouton bascule **Enabled** pour l'activer ou le désactiver pour chaque domaine.

<Frame caption="Verified domains show an Active status">
  <img src="/images/apple-pay-domains/domains-active.png" alt="Liste des domaines de portefeuille affichant des domaines avec le statut Apple Pay Active et les boutons bascule Enabled" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>
</Step>

<Step title="Test the integration">
1. Ouvrez le paiement sur un appareil Apple
2. Vérifiez que le bouton Apple Pay s'affiche
3. Effectuez une transaction de test
</Step>
</Steps>

### Configuration

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['apple_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## Google Pay

Google Pay permet aux clients de payer avec les cartes enregistrées dans leur compte Google, grâce à une protection intégrée contre la fraude.

### Exigences
- **Navigateurs :** Chrome (ordinateur/mobile), Safari, Firefox
- **Appareils :** appareils Android équipés de l'application Google Pay
- **Paramètres :** l'option "Allow sites to check if you have payment methods" doit être activée dans Chrome

### Configuration

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['google_pay', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Info>
Aucune vérification du domaine n'est nécessaire pour Google Pay : le service fonctionne automatiquement une fois votre compte actif.
</Info>

## Amazon Pay

Amazon Pay permet aux clients d'utiliser les identifiants de leur compte Amazon et leurs moyens de paiement enregistrés pour une expérience de paiement familière.

### Disponibilité
- **Région :** Mondial, hors Inde
- **Devise :** USD uniquement
- **Abonnements :** Non pris en charge

### Configuration

```javascript
const session = await client.checkoutSessions.create({

  allowed_payment_method_types: ['amazon_pay', 'credit', 'debit'],
```

## Cash App Pay

Cash App Pay permet d'effectuer des paiements depuis Cash App, très populaire auprès des consommateurs américains pour les paiements entre particuliers.

### Disponibilité
- **Région :** États-Unis uniquement
- **Devise :** USD uniquement
- **Abonnements :** Pris en charge

### Configuration

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: ['cashapp', 'credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

## RevolutPay

RevolutPay permet aux utilisateurs de Revolut du monde entier d'effectuer des paiements rapides et fluides, en utilisant le solde existant de leur compte Revolut ou leurs cartes associées.

### Disponibilité
- **Région :** Mondial
- **Devise :** GBP uniquement
- **Abonnements :** Non pris en charge

### Configuration

## Tests

### Tests avec Apple Pay

<Steps>
<Step title="Use test mode">
Activez le mode test dans votre dashboard Dodo Payments.
</Step>

<Step title="Add a card to Apple Wallet">
Ajoutez une carte réelle à votre Apple Wallet. En mode test, la carte ne sera pas débitée.
</Step>

<Step title="Complete test purchase">
Ouvrez le paiement sur un appareil Apple et terminez le parcours Apple Pay.
</Step>
</Steps>

<Warning>
Apple Pay nécessite HTTPS. Il ne s'affichera pas sur `localhost` sans configuration SSL appropriée.
</Warning>

### Tests avec Google Pay

<Steps>
<Step title="Join the test card group">
[Rejoignez le groupe de cartes de test Google Pay](https://groups.google.com/g/googlepay-test-mode-stub-data) pour ajouter automatiquement des cartes de test à votre portefeuille.
</Step>

<Step title="Enable test mode">
Utilisez vos clés API de test Dodo Payments.
</Step>

<Step title="Complete test purchase">
Sélectionnez l'une des cartes de test dans Google Pay pour terminer la transaction.
</Step>
</Steps>

### Amazon Pay et Cash App Pay

Utilisez vos clés API de test et suivez le parcours de paiement standard. Les transactions de test seront simulées sans débit réel.

## Prise en charge des SDK

### SDK Web
Tous les portefeuilles numériques sont entièrement pris en charge dans :
- Overlay Checkout
- Inline Checkout
- intégration API directe

### SDK mobiles (Checkout)

Les SDK Checkout [Android](/developer-resources/sdks/android), [iOS](/developer-resources/sdks/ios),
[React Native](/developer-resources/sdks/react-native) et
[Flutter](/developer-resources/sdks/flutter) ouvrent le
checkout hébergé de Dodo dans la véritable surface de navigateur de la plateforme (`SFSafariViewController` /
Chrome Custom Tabs), et non dans une WebView, de sorte qu'Apple Pay et Google Pay fonctionnent de la
même manière que sur le web. Consultez le [Guide d'intégration mobile](/developer-resources/mobile-integration) pour la configuration.

## Bonnes pratiques

<AccordionGroup>
<Accordion title="Prioritize wallets on mobile">
Les utilisateurs mobiles s'attendent à pouvoir utiliser Apple Pay et Google Pay. Affichez ces options bien en évidence dans les checkouts mobiles.
</Accordion>

<Accordion title="Complete domain verification early">
Apple Pay nécessite la vérification du domaine. N'attendez pas le jour du lancement — commencez le processus pendant le développement.
</Accordion>

<Accordion title="Always include card fallbacks">
Tous les clients ne disposent pas de portefeuilles numériques. Incluez toujours `credit` et `debit` dans vos méthodes autorisées.
</Accordion>

<Accordion title="Test on real devices">
Les simulateurs ne reproduisent pas entièrement le comportement des portefeuilles. Effectuez des tests sur de véritables appareils iOS et Android avant le lancement.
</Accordion>

<Accordion title="Handle wallet unavailability gracefully">
Si un portefeuille n'est pas disponible (appareil inadéquat, aucune carte enregistrée), assurez-vous que les autres options de paiement sont visibles.
</Accordion>
</AccordionGroup>

## Dépannage

<AccordionGroup>
<Accordion title="Apple Pay button not appearing">
**Vérifications :**
1. Domaine vérifié avec Dodo Payments ?
2. Utilisation de HTTPS ?
3. L'appareil est-il sous iOS 17+ / Safari 17+ / iPadOS 17+ ?
4. Le client possède-t-il des cartes dans Apple Wallet ?
5. `apple_pay` est-il inclus dans `allowed_payment_method_types` ?

**Solution :** Terminez la vérification du domaine et assurez-vous d'utiliser HTTPS. Effectuez des tests sur un véritable appareil Apple.
</Accordion>

<Accordion title="Google Pay button not appearing">
**Vérifications :**
1. Utilisation de Chrome ou d'un navigateur compatible ?
2. Le client possède-t-il des cartes dans Google Pay ?
3. Le paramètre Chrome « Autoriser les sites à vérifier les méthodes de paiement » est-il activé ?
4. `google_pay` est-il inclus dans `allowed_payment_method_types` ?

**Solution :** Vérifiez la compatibilité du navigateur et la configuration Google Pay du client.
</Accordion>

<Accordion title="Wallet payment failed">
**Causes courantes :**
- Carte du portefeuille expirée ou invalide
- Transaction refusée par la banque
- Problème de connectivité réseau

**Solution :** Le client doit vérifier la carte dans son portefeuille ou essayer une autre méthode de paiement.
</Accordion>

<Accordion title="Wrong device type">
Les portefeuilles numériques apparaissent uniquement sur les appareils compatibles :
- Apple Pay : appareils Apple uniquement
- Google Pay : navigateur Chrome ou appareils Android

**Solution :** Ce comportement est attendu. Assurez-vous que des solutions de repli pour les cartes sont disponibles.
</Accordion>
</AccordionGroup>
