Les paiements par carte constituent la base des paiements en ligne. Ils sont acceptés dans le monde entier et bénéficient de la confiance des clients partout dans le monde. Dodo Payments prend en charge tous les principaux réseaux de cartes, avec une protection intégrée contre la fraude et la conformité PCI.

## Réseaux de cartes pris en charge

### Réseaux mondiaux

| Réseau | Couverture |
| :------ | :------- |
| **Visa** | Leader mondial, plus de 4 milliards de cartes dans le monde |
| **Mastercard** | Présence mondiale, fonctionnalités de sécurité avancées |
| **American Express** | Titulaires de cartes premium, dépenses plus élevées |
| **Discover** | Principalement axé sur les États-Unis, en expansion mondiale |

## Configuration

Utilisez ces valeurs dans `allowed_payment_method_types` :

| Type | Description |
| :--- | :---------- |
| `credit` | Toutes les cartes de crédit |
| `debit` | Toutes les cartes de débit |

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: ['credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Tip>
Incluez à la fois `credit` et `debit`, sauf si vous avez une raison précise d’en exclure un. De nombreux clients préfèrent les cartes de débit, qui présentent souvent des frais moins élevés.
</Tip>

## Authentification 3D Secure

3D Secure (3DS) ajoute une couche d’authentification qui réduit la fraude et les contestations de paiement en vérifiant l’identité du titulaire de la carte.

### Déclenchement de 3DS

3DS est automatiquement déclenché lorsque :
- Le réseau de cartes l’exige
- Les réglementations régionales l’exigent (par exemple, PSD2 en Europe)
- La transaction est identifiée comme présentant un risque élevé

### Forcer 3DS

Vous pouvez exiger 3DS pour toutes les transactions :

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  force_3ds: true,
  return_url: 'https://example.com/success'
});
```

<Note>
Activer 3DS pour toutes les transactions réduit la fraude, mais peut légèrement diminuer le taux de conversion, car certains clients abandonnent pendant l’authentification.
</Note>

### Gestion des échecs d’authentification

Lorsqu’un paiement nécessite une authentification 3DS, il passe par des états intermédiaires avant de réussir ou d’échouer :

| Statut | Signification | Action à effectuer |
|--------|---------|------------|
| `requires_customer_action` | Le client doit terminer un challenge 3DS | Faites terminer l’authentification au client pendant le checkout |
| `requires_payment_method` | Le client n’a jamais fourni de moyen de paiement (il n’a pas saisi ses informations ou a abandonné l’invite) — il s’agit généralement d’un abandon, et non d’un refus | Relancez le client pour qu’il termine le checkout ; consultez [Récupération des paniers abandonnés](/features/recovery/abandoned-cart-recovery) |

Si l’authentification n’aboutit pas, le paiement échoue avec l’un de ces codes de refus :

- `AUTHENTICATION_FAILURE` — le client n’a pas pu être authentifié.
- `AUTHENTICATION_REQUIRED` — l’authentification est requise, mais n’a pas été effectuée.
- `AUTHENTICATION_TIMEOUT` — le client n’a pas répondu à temps.

Consultez la référence [Échecs de transaction](/api-reference/transaction-failures) pour connaître l’action recommandée pour chacun d’eux.

#### Lors du checkout ou lors d’un renouvellement

- **Lors du checkout (client présent) :** Le client est présent, le challenge 3DS s’affiche donc pendant le checkout. En cas d’échec, demandez-lui de réessayer ou d’utiliser une autre carte.
- **Lors du renouvellement d’un abonnement (client absent) :** Le client n’est pas présent, un challenge 3DS ne peut donc pas être affiché en temps réel. Si un renouvellement nécessite une authentification, l’abonnement passe à `on_hold`. Récupérez-le en invitant le client à revenir et à mettre à jour son moyen de paiement — consultez [Gérer les échecs de paiement](/developer-resources/handle-payment-failures) et [Relances d’abonnement](/features/recovery/subscription-dunning).

### Activer les cartes enregistrées

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  show_saved_payment_methods: true,
  customer: { customer_id: 'cus_existing_123' },
  return_url: 'https://example.com/success'
});
```

### Achats en un clic

```javascript
// Get customer's saved payment methods
const methods = await client.customers.retrievePaymentMethods('cus_123');

// Use saved card for instant checkout
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  payment_method_id: methods.items[0].payment_method_id,
  confirm: true,
  return_url: 'https://example.com/success'
});
```

## Sécurité et conformité

| Fonctionnalité | Description |
| :------ | :---------- |
| **PCI DSS niveau 1** | Niveau de certification le plus élevé |
| **Tokenisation** | Les numéros de carte sont immédiatement tokenisés |
| **Évaluation de la fraude** | Évaluation des risques en temps réel |

## Bonnes pratiques

<AccordionGroup>
<Accordion title="Accept all major networks">
Ne limitez pas les types de cartes, sauf si cela est nécessaire. Les clients s’attendent à pouvoir utiliser leur carte préférée.
</Accordion>

<Accordion title="Display card logos">
Affichez les logos Visa, Mastercard et Amex lors du checkout pour renforcer la confiance.
</Accordion>

<Accordion title="Handle declines gracefully">
Affichez des messages d’erreur clairs. N’exposez pas les codes d’erreur bruts aux clients.
</Accordion>

<Accordion title="Enable saved cards for returning customers">
Les moyens de paiement enregistrés augmentent considérablement le taux de conversion pour les achats répétés.
</Accordion>
</AccordionGroup>

## Dépannage

<AccordionGroup>
<Accordion title="Card declined">
**Causes :** Fonds insuffisants, carte expirée, CVV incorrect, protection antifraude de la banque.

**Solution :** Demandez au client de vérifier ses informations ou d’essayer une autre carte. Recherchez le code de refus `Error Code` spécifique et l’action recommandée correspondante dans la référence [Échecs de transaction](/api-reference/transaction-failures), et consultez [Gérer les échecs de paiement](/developer-resources/handle-payment-failures) pour la gestion programmatique.
</Accordion>

<Accordion title="3DS authentication failed">
**Causes :** Client ayant abandonné, système bancaire indisponible, délai d’attente dépassé.

**Solution :** Réessayez ou demandez au client de contacter sa banque. Consultez [Gestion des échecs d’authentification](#handling-authentication-failures) pour connaître les états de paiement et les codes de refus concernés.
</Accordion>

<Accordion title="Card not supported">
**Causes :** Carte régionale non prise en charge, restrictions concernant les cartes prépayées.

**Solution :** Le client doit essayer une autre carte appartenant à un réseau majeur.
</Accordion>
</AccordionGroup>
