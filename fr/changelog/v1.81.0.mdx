## Nouvelles Fonctionnalités

### 1. **Support des Analyses Tiers**

Suivez le comportement des clients sur la vitrine, le paiement et le portail client avec Google Analytics 4, Google Tag Manager et Meta Pixel. Ajoutez vos IDs de suivi dans **Paramètres → Analytique** pour commencer à collecter des événements de commerce électronique.

**Plateformes Supportées**

| Plateforme | Format ID |
|----------|-----------|
| Google Analytics 4 | `G-XXXXXXXXXX` |
| Google Tag Manager | `GTM-XXXXXXX` |
| Meta Pixel | Numérique (10-20 chiffres) |

**Événements Suivis**

Des événements comme `purchase`, `add_payment_info`, `view_item`, et `view_item_list` sont automatiquement envoyés à vos plateformes d'analytique lorsque les clients naviguent et complètent des achats.

<Check>
Supporté sur la vitrine, le paiement hébergé, le paiement superposé/en ligne et le portail client.
</Check>

En savoir plus : [Analyses Tiers](/features/analytics)

### 2. **Personnalisation du Thème de Paiement**

Personnalisez l'apparence du paiement via le paramètre `customization.theme_config` lors de la création de sessions de paiement. Configurez les couleurs, les polices, le rayon de bordure et le texte des boutons pour les modes clair et sombre.

**Options de Configuration**

| Propriété | Description |
|----------|-------------|
| `light` / `dark` | Schémas de couleurs pour chaque mode |
| `font_primary_url` | URL de police personnalisée |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius` | Rayon de bordure (ex. : `8px`) |
| `pay_button_text` | Texte de bouton personnalisé |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

En savoir plus : [Personnalisation du Thème de Paiement](/features/checkout#checkout-theme-customization)

### 3. **Prévenir le Changement de Plan en cas d'Échec de Paiement**

Nouveau paramètre `on_payment_failure` pour les changements de plan d'abonnement qui contrôle le comportement en cas d'échec de paiement.

| Mode | Comportement |
|------|----------|
| `prevent_change` | Conserver l'abonnement sur le plan actuel jusqu'à ce que le paiement réussisse |
| `apply_change` | Appliquer le changement de plan immédiatement, indépendamment du résultat du paiement (par défaut) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
Utilisez `prevent_change` pour des mises à jour critiques où vous souhaitez vous assurer que le paiement est effectué avant de donner accès à des fonctionnalités premium.
</Tip>

En savoir plus : [Gestion des Échecs de Paiement](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## Mises à jour de l'API

### API de Livre de Compte

Nouveau point de terminaison `GET /balances/ledger` pour récupérer les entrées de livre de compte de votre compte avec filtrage et pagination.

| Paramètre | Description |
|-----------|-------------|
| `created_at_gte` / `created_at_lte` | Filtrer par plage de dates |
| `event_type` | Filtrer par `payment`, `refund`, `dispute`, `payout`, etc. |
| `currency` | Filtrer par code de devise |
| `reference_object_id` | Filtrer par ID de paiement/remboursement/dépôt spécifique |

En savoir plus : [API de Livre de Compte](/api-reference/balance-ledger/list-ledger-entries)

### Réponse de Paiement : `refund_status`

Ajout du champ `refund_status` à la réponse `GET /payments/{paymentId}` pour vérifier rapidement si un paiement a été remboursé sans interroger séparément le point de terminaison des remboursements.
