## Nouvelles Fonctionnalités

### 1. **Analyse au Niveau des Produits**

Chaque produit dispose désormais de son propre **tableau de bord d'analyse dédié**. Accédez à **Produits > [Sélectionner un produit]** pour accéder à des métriques détaillées spécifiques à ce produit, organisées sur cinq onglets :

<Frame>
<img src="/images/product-analytics/overview.png" alt="Analyse au Niveau des Produits" />
</Frame>

| Onglet | Ce que vous obtenez |
|-----|-------------|
| **Aperçu** | Chiffre d'affaires total, nombre de paiements réussis, graphique de tendance des revenus sur 30 jours (journalier ou cumulé), et tableau de transactions filtrables |
| **Clients** | Top 3 clients classés par dépense avec une vue podium, plus un tableau complet de répartition des clients |
| **Rétention** | Taux de désabonnement client, taux de désabonnement des revenus, et un graphique de tendance à deux lignes pour repérer les modèles |
| **Abonnés** | Tous les abonnements pour le produit avec statut, date de début, date de prochaine facturation, et montant |
| **MRR** | Graphique à barres empilées des Revenus Mensuels Récurrents avec des décomptes de Nouveaux MRR, d'Expansion MRR, de Churned MRR, et de Net New MRR |

Tous les onglets supportent un **filtre de date** (par défaut sur Tout le Temps) afin que vous puissiez explorer n'importe quelle période.

<Tip>
Utilisez l'onglet Rétention pour identifier rapidement les produits avec un fort taux de désabonnement, et l'onglet MRR pour suivre si les revenus d'expansion dépassent les revenus désabonnés d'un mois à l'autre.
</Tip>

### 2. **Support Verifi RDR sur Dodo Payments**

Dodo Payments prend désormais en charge la **Résolution Rapide des Litiges Visa (RDR)** alimentée par Verifi -- un outil de prévention des litiges automatisé qui résout les litiges Visa éligibles **avant qu'ils ne deviennent des rétrofacturations formelles**. Lorsqu'un titulaire de carte initie un litige, RDR l'intercepte et émet automatiquement un remboursement si la transaction est inférieure à votre seuil en USD configuré.

**Pourquoi c'est important**

| Avantage | Impact |
|---------|--------|
| **Taux de litige inférieur** | Les litiges résolus par RDR ne comptent pas dans le seuil de 0,9 % de Visa |
| **Pas de frais de litige** | Évitez des frais non remboursables de 15 à 25 $ par litige |
| **Zero charge opérationnelle** | Pas de collecte de preuves ni de délais de réponse |
| **Meilleure expérience client** | Les titulaires de carte obtiennent des remboursements instantanés |
| **Protection du compte** | Restez en dehors du Programme de Surveillance des Litiges de Visa (VDMP) |

<Warning>
Dépasser le taux de litige de 0,9 % de Visa ou 100 litiges par mois déclenche le VDMP, avec des amendes escaladantes allant jusqu'à 50 000 $+/mois. RDR vous aide à rester bien en dessous de ces seuils.
</Warning>

**Comment ça fonctionne**

1. Le titulaire de carte initie un litige auprès de sa banque
2. RDR intercepte le litige avant qu'il ne devienne une rétrofacturation formelle
3. Si le montant de la transaction est à ou en dessous de votre seuil, un remboursement est émis automatiquement
4. Le litige est résolu instantanément et **ne compte pas** contre votre taux de litige

<Info>
Les transactions remboursées automatiquement via RDR apparaissent comme un **litige perdu** dans votre tableau de bord Dodo Payments. Cela est attendu -- le remboursement a été émis automatiquement pour éviter une rétrofacturation formelle.
</Info>

Pour activer Verifi RDR sur votre compte, contactez **support@dodopayments.com** pour configurer votre seuil.

En savoir plus : [Documentation Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

Présentation de la toute nouvelle **DodoPayments CLI** (`dodopayments-cli`) -- gérez tout votre flux de travail Dodo Payments directement depuis le terminal. Conçue pour les développeurs qui préfèrent la ligne de commande, la CLI vous permet de gérer les produits, paiements, clients, remises, licences, addons, remboursements, et même de créer des sessions de paiement sans quitter votre éditeur.

**Installation**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Commandes Clés**

| Commande | Description |
|---------|-------------|
| `dodo login` | Authentifiez-vous avec votre clé API (ouvre le navigateur) |
| `dodo products list` | Listez tous les produits |
| `dodo payments list` | Listez tous les paiements |
| `dodo customers create` | Créez un nouveau client |
| `dodo checkout new` | Créez une session de paiement et obtenez l'URL |
| `dodo wh listen` | Transférez des webhooks de test en direct vers votre serveur local via WebSocket |
| `dodo wh trigger` | Envoyez des charges utiles de webhook simulées à n'importe quel point de terminaison |

**Test de Webhook**

La CLI comprend deux outils puissants pour le développement :

- **`dodo wh listen`** -- Ouvre une connexion WebSocket pour transférer des webhooks de test en temps réel vers votre serveur local, tout en préservant les en-têtes d'origine pour les tests de vérification de signature
- **`dodo wh trigger`** -- Envoie des charges utiles de webhook simulées de manière interactive, prenant en charge tous les 22 types d'événements à travers abonnements, paiements, remboursements, litiges et licences

<Tip>
Le listener de webhook fonctionne uniquement avec une clé API en **mode test**. Assurez-vous d'être connecté avec une clé en mode test avant d'utiliser `dodo wh listen`.
</Tip>

En savoir plus : [Documentation CLI](/developer-resources/sdks/cli)

### 5. **Mise à Jour de la Méthode de Paiement dans le Paiement en Ligne**

Le [paiement en ligne](/developer-resources/inline-checkout) prend désormais en charge les **mises à jour de la méthode de paiement** pour les abonnements. Lorsqu'un client doit mettre à jour sa méthode de paiement (pour un abonnement actif ou pour réactiver un abonnement en attente), le flux de mise à jour de la méthode de paiement peut désormais être rendu directement dans la mise en page de votre page via le paiement en ligne -- fournissant une expérience intégrée et fluide.

**Comment ça fonctionne**

1. Appelez l'API de mise à jour de la méthode de paiement pour obtenir un `payment_link` :

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Utilisez le `payment_link` retourné comme le `checkoutUrl` dans le paiement en ligne :

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

Le cadre intégré rend uniquement le formulaire de collecte des méthodes de paiement, permettant aux clients d'entrer de nouveaux détails de carte ou de sélectionner une méthode de paiement enregistrée sans quitter votre page.

<Tip>
Pour les abonnements en attente, le flux de mise à jour de la méthode de paiement crée automatiquement un prélèvement pour les montants dus restants. Surveillez les webhooks `payment.succeeded` et `subscription.active` pour confirmer la réactivation.
</Tip>

En savoir plus : [Paiement en Ligne](/developer-resources/inline-checkout) | [Mises à Jour des Méthodes de Paiement d'Abonnement](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Support de Préremplissage de l'ID Fiscal pour les Sessions de Paiement**

Vous pouvez désormais **pré-remplir l'ID Fiscal** (par exemple, numéro de TVA, numéro de GST) lors de la création d'une session de paiement en utilisant le paramètre `tax_id`. Ceci est idéal pour les transactions B2B où vous connaissez déjà le numéro d'identification fiscale du client. Lorsqu'un ID Fiscal est prérempli, le champ est pré-rempli et verrouillé dans le formulaire de paiement.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Le paramètre `tax_id` nécessite un `billing_address` avec au moins un champ `country`. L'éligibilité fiscale est validée en temps réel, et les règles d'auto-liquidation sont appliquées automatiquement pour les transactions B2B qualifiées.
</Info>

Utilisez le drapeau de fonctionnalité `allow_customer_editing_tax_id` pour contrôler si les clients peuvent modifier l'ID Fiscal pré-rempli, et `allow_tax_id` pour basculer la visibilité de l'ID Fiscal lors du paiement.

En savoir plus : [Sessions de Paiement - ID Fiscal](/developer-resources/checkout-session) | [Paiements B2B](/features/b2b-payments)

### 7. **Clé de Licence et Email dans la Redirection URL de Retour**

Après qu'un client ait complété le paiement, Dodo Payments ajoute désormais `license_key` et `email` comme paramètres de requête à votre redirection `return_url`, en plus des paramètres existants `payment_id`/`subscription_id` et `status`.

**Paramètres de Requête Ajoutés**

| Paramètre | Type | Condition |
|-----------|------|-----------|
| `payment_id` | `string` | Toujours présent pour les paiements uniques |
| `subscription_id` | `string` | Toujours présent pour les paiements d'abonnement |
| `status` | `string` | Toujours présent |
| `license_key` | `string` | Présent si le produit a des clés de licence activées (séparées par des virgules pour plusieurs) |
| `email` | `string` | Présent si le client a un email enregistré |

**Exemples d'URLs de redirection :**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Utilisez ces paramètres de requête pour afficher des clés de licence ou envoyer un email de confirmation immédiatement sur votre page de retour, sans nécessiter un appel API supplémentaire.
</Tip>

En savoir plus : [Sessions de Paiement - URL de Retour](/developer-resources/checkout-session) | [Clés de Licence dans l'URL de Retour](/features/license-keys#license-keys-in-return-url)

### 8. **API de Mise à Jour de l'Email Client**

Le point de terminaison `PATCH /customers/{customer_id}` prend désormais en charge la mise à jour des adresses email des clients de manière programmatique. Mettez à jour l'email ainsi que le nom, le numéro de téléphone et les métadonnées en un seul appel API.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Champs Modifiables**

| Champ | Type | Description |
|-------|------|-------------|
| `email` | `string \| null` | Adresse email du client |
| `name` | `string \| null` | Nom d'affichage du client |
| `phone_number` | `string \| null` | Numéro de téléphone au format international |
| `metadata` | `object \| null` | Paires clé-valeur personnalisées |

<Info>
Les mises à jour des emails clients sont également disponibles via le Portail Client (libre-service), le tableau de bord et la CLI via `dodo customers update`.
</Info>

En savoir plus : [API de Mise à Jour des Clients](/api-reference/customers/patch-customer) | [Gestion des Clients](/features/customers)

### 9. **Publication de l'Adaptateur Bun**

Présentation de `@dodopayments/bun` -- un adaptateur de framework dédié pour le serveur natif de [Bun](https://bun.sh) (`Bun.serve()`). Intégrez le paiement, le portail client et les webhooks avec Bun en seulement quelques lignes de code.

**Installation**

```bash
bun add @dodopayments/bun
```

**Configuration Rapide**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

L'adaptateur Bun prend en charge les trois flux de paiement (statique, dynamique et basé sur les sessions), la génération de sessions de portail client, et le traitement sécurisé des webhooks avec vérification de signature et validation Zod à travers 22 types d'événements.

L'adaptateur Bun rejoint notre famille de 11 adaptateurs de frameworks, y compris Next.js, Nuxt, Express, Fastify, Hono, Astro, SvelteKit, Remix, TanStack Start, Better Auth et Convex.
</Check>
