## Prerequisites

To integrate the Dodo Payments API, you'll need:
- A Dodo Payments merchant account
- API Credentials (API key and webhook secret key) from dashboard

## Dashboard Setup

1. Navigate to the [Dodo Payments Dashboard](https://app.dodopayments.com/)

2. Créez un produit (paiement unique ou abonnement). Les produits par abonnement doivent être tarifés à au moins **\$1** (ou l'équivalent dans la devise choisie) ; les montants inférieurs à ce minimum ne sont pas pris en charge.

4. Generate your API key:
   - Go to Developer > API
   - [Detailed Guide](/api-reference/introduction#api-key-generation)
   - Copy the API key the in env named DODO_PAYMENTS_API_KEY

5. Configure webhooks:
   - Go to Developer > Webhooks
   - Create a webhook URL for payment notifications
   - Copy the webhook secret key in env 

## Integration

### Payment Links

Choisissez le parcours d'intégration adapté à votre cas d'utilisation :
- **Checkout Sessions (recommandé)** : idéal pour la plupart des intégrations. Créez une session sur votre serveur, puis redirigez les clients vers une page de paiement sécurisée et hébergée.
- **Overlay Checkout** : à utiliser lorsque vous avez besoin d'une expérience dans la page qui ouvre le paiement sous forme de fenêtre modale superposée à votre site.
- **Inline Checkout** : intégrez directement le paiement dans la mise en page de votre page pour une expérience entièrement intégrée et personnalisée.
- **Static Payment Links** : des URL sans code, immédiatement partageables, pour collecter rapidement des paiements.
- **Dynamic Payment Links** : des liens créés par programmation. Toutefois, Checkout Sessions est recommandé et offre davantage de flexibilité.
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)** : pour les applications natives Android, iOS, React Native et Flutter. Créez la session sur votre serveur comme indiqué ci-dessus, puis transmettez `checkout_url` au SDK.

<Info>
Overlay Checkout et Inline Checkout sont réservés aux navigateurs : ils intègrent le paiement dans une
page web. Si vous développez une application mobile native, créez la session de paiement sur
votre serveur et ouvrez-la avec les
[Mobile Checkout SDKs](/developer-resources/mobile-integration) à la place.
</Info>

#### 1. Checkout Sessions

Utilisez Checkout Sessions pour créer une expérience de paiement sécurisée, hébergée, pour les paiements uniques ou les abonnements. Vous créez une session sur votre serveur, puis redirigez le client vers `checkout_url` renvoyé.

<Info>
Les Checkout Sessions sont valides pendant 24 heures par défaut. Si vous transmettez <code>confirm=true</code>, les sessions sont valides pendant 15 minutes et tous les champs obligatoires doivent être fournis.
</Info>

<Steps>
<Step title="Create a checkout session">
  Choisissez votre SDK préféré ou appelez l'API REST.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  )

      product_cart=[{"product_id": "pdt_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},

#### 2. Overlay Checkout

Pour une expérience de paiement fluide dans la page, découvrez notre intégration [Overlay Checkout](/developer-resources/overlay-checkout), qui permet aux clients de finaliser leurs paiements sans quitter votre site.

#### 3. Inline Checkout

Pour des expériences de paiement entièrement intégrées directement dans votre page, utilisez notre intégration [Inline Checkout](/developer-resources/inline-checkout). Elle vous permet de créer des récapitulatifs de commande personnalisés et de contrôler entièrement la mise en page du paiement, tandis que Dodo Payments gère la collecte des paiements en toute sécurité.

#### 4. Static Payment Links

Les Static Payment Links vous permettent d'accepter rapidement des paiements en partageant une URL simple. Vous pouvez personnaliser l'expérience de paiement en transmettant des paramètres de requête pour préremplir les informations client, contrôler les champs du formulaire et ajouter des métadonnées personnalisées.

<Steps>
<Step title="Construct your payment link">
  Commencez par l'URL de base et ajoutez votre identifiant de produit :

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  Incluez les paramètres de requête essentiels :
  - <ParamField query="quantity" type="integer" default="1">Nombre d'articles à acheter.</ParamField>
  - <ParamField query="redirect_url" type="string" required>URL de redirection après la finalisation du paiement.</ParamField>
  <Note>
  L'URL de redirection inclura les détails du paiement sous forme de paramètres de requête, par exemple :<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  Si les clés de licence sont activées pour le produit, un paramètre `license_key` est également ajouté (séparé par des virgules pour plusieurs clés) :<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  Ajoutez les champs client ou de facturation comme paramètres de requête pour simplifier le paiement.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">Nom complet du client (ignoré si firstName ou lastName est fourni).</ParamField>
      - <ParamField query="firstName" type="string">Prénom du client.</ParamField>
      - <ParamField query="lastName" type="string">Nom du client.</ParamField>
      - <ParamField query="email" type="string">Adresse e-mail du client.</ParamField>
      - <ParamField query="country" type="string">Pays du client.</ParamField>
      - <ParamField query="addressLine" type="string">Adresse postale.</ParamField>
      - <ParamField query="city" type="string">Ville.</ParamField>
      - <ParamField query="state" type="string">État ou province.</ParamField>
      - <ParamField query="zipCode" type="string">Code postal/ZIP.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true ou false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  Vous pouvez désactiver certains champs afin de les rendre accessibles en lecture seule pour le client. Cette option est utile lorsque vous disposez déjà des informations du client (par exemple, pour les utilisateurs connectés).
  </Info>
  Pour désactiver un champ, fournissez sa valeur et définissez l'indicateur <code>disable...</code> correspondant sur <code>true</code> :
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Champ         | Indicateur de désactivation         | Paramètre obligatoire |
      |---------------|---------------------|-------------------|
      | Nom complet     | `disableFullName`   | `fullName`        |
      | Prénom    | `disableFirstName`  | `firstName`       |
      | Nom    | `disableLastName`   | `lastName`        |
      | E-mail         | `disableEmail`      | `email`           |
      | Pays       | `disableCountry`    | `country`         |
      | Adresse          | `disableAddressLine`| `addressLine`     |
      | Ville          | `disableCity`       | `city`            |
      | État         | `disableState`      | `state`           |
      | Code ZIP      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  La désactivation des champs contribue à empêcher les modifications accidentelles et garantit la cohérence des données.
  </Tip>
  <Note>
  La définition de <code>showDiscounts=false</code> désactive et masque la section des remises dans le formulaire de paiement. Utilisez cette option si vous souhaitez empêcher les clients de saisir des codes de réduction ou promotionnels lors du paiement.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">Spécifie la devise du paiement. Par défaut, il s’agit de la devise du pays de facturation.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">Affiche ou masque le sélecteur de devise.</ParamField>
  - <ParamField query="paymentAmount" type="number">Fixe le montant facturé, en unités principales de la devise (par exemple, <code>12.5</code> pour 12,50 $). Uniquement pour les produits Pay What You Want. La valeur est ignorée si elle est inférieure au prix minimum du produit.</ParamField>
  - <ParamField query="metadata_*" type="string">Champs de métadonnées personnalisés (par exemple, <code>metadata_orderId=123</code>).</ParamField>

  <Warning>
  `paymentAmount` sur un lien de paiement ne correspond pas à la même unité que le champ `amount` dans l’API Checkout Sessions. Le paramètre du lien utilise les unités principales de la devise (`12.5` = 12,50 $), tandis que `product_cart[].amount` de l’API utilise la plus petite dénomination (`1250` = 12,50 $). Consultez [Dynamic Pricing](/developer-resources/dynamic-pricing-checkout) pour découvrir le champ de l’API.
  </Warning>
</Step>
<Step title="Share the link">
  Envoyez le lien de paiement complété à votre client. Lorsqu’il le consulte, tous les paramètres de requête sont collectés et enregistrés avec un identifiant de session. L’URL est ensuite simplifiée pour n’inclure que le paramètre de session (par exemple, <code>?session=sess_1a2b3c4d</code>). Les informations enregistrées persistent après l’actualisation de la page et restent accessibles pendant tout le processus de paiement.
  <Check>
  L’expérience de paiement de votre client est désormais simplifiée et personnalisée en fonction de vos paramètres.
  </Check>
</Step>
</Steps>

### Implémentation des webhooks

Configurez un point de terminaison d’API pour recevoir les notifications de paiement. Voici un exemple utilisant Next.js :

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

Notre implémentation des webhooks respecte la spécification [Standard Webhooks](https://standardwebhooks.com/). Pour les définitions des types de webhooks, consultez notre [Guide des événements de webhook](/developer-resources/webhooks/intents/webhook-events-guide).

#### Événements à écouter

Activez `payload.type` et gérez les événements pertinents pour un flux de paiement unique. Au minimum, écoutez les événements suivants :

| Type d’événement           | Déclenchement                                              | Action à effectuer                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | Le paiement est traité avec succès.                        | Exécutez la commande — accordez l’accès, provisionnez le produit et envoyez le reçu. |
| `payment.failed`     | La tentative de paiement échoue (carte refusée, erreur, etc.).       | Informez le client et invitez-le à réessayer ; n’exécutez pas la commande.                    |
| `payment.processing` | Le paiement est accepté, mais son traitement est toujours en cours (méthodes asynchrones). | Attendez `payment.succeeded`/`payment.failed`, l’événement final — n’exécutez pas encore la commande. |
| `payment.cancelled`  | Le paiement est annulé avant son achèvement.                   | Libérez tout état conservé et marquez la commande comme abandonnée.                       |

<Tip>
Exécutez toujours la commande sur `payment.succeeded` **à partir du webhook**, et non lors de la redirection du navigateur — la redirection peut être manquée si le client ferme l’onglet, tandis que le webhook est réessayé jusqu’à réception d’un accusé de réception.
</Tip>

Si vous vendez des produits numériques avec des clés de licence, gérez également `license_key.created`. Pour consulter la liste complète des événements — notamment ceux liés aux abonnements, aux droits, aux crédits, à la récupération et au recouvrement — consultez le [Guide des événements de webhook](/developer-resources/webhooks/intents/webhook-events-guide).

Vous pouvez consulter ce projet avec une implémentation de démonstration sur [GitHub](https://github.com/dodopayments/dodo-checkout-demo) utilisant Next.js et TypeScript.

Vous pouvez consulter l’implémentation en ligne [ici](https://atlas.dodopayments.com/).

## Points essentiels à connaître sur Checkout et les devises

<Warning>
Les **montants dynamiques (Pay-What-You-Want) sont exprimés dans la devise de base du produit**, et non dans une devise locale arbitraire. La devise de base est limitée à **USD, INR, GBP et EUR**. Pour percevoir un montant fixe dans une autre devise (par exemple, PHP), vous ne pouvez pas le transmettre directement : utilisez **Adaptive Pricing** (qui convertit votre montant de base selon le taux de change en temps réel) ou **Localized Pricing** (prix fixe par devise, mais incompatible avec Pay-What-You-Want).
</Warning>

<Tip>
**Définissez explicitement la devise.** Transmettez `billing_currency` et `billing_address.country` lors de la session de paiement. Si vous les omettez, la devise et le pays sont détectés à partir de l’adresse IP du client (Adaptive Currency) et peuvent ne pas correspondre à ce que vous souhaitez facturer.
</Tip>

<Info>
**Les sessions de paiement expirent au bout de 24 heures** (15 minutes lorsque `confirm: true`), et chaque `checkout_url` est **à usage unique** — générez une nouvelle session pour chaque client et chaque tentative de paiement au lieu de réutiliser un lien.
</Info>

<Info>
**Achat répété en un clic.** Pour un client existant disposant d’un moyen de paiement enregistré, transmettez `payment_method_id` avec `confirm: true` afin de débiter instantanément le client, sans aucune sélection de moyen de paiement.
</Info>
