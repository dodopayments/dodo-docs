## Aperçu

Un boilerplate prêt pour la production pour intégrer Dodo Payments dans des applications Expo/React Native. Ce modèle inclut la création de sessions de caisse, le traitement des paiements et une configuration TypeScript appropriée pour vous aider à commencer à accepter des paiements dans votre application mobile rapidement.

<Info>
Ce boilerplate utilise Expo SDK avec TypeScript et inclut des exemples d'implémentations pour les sessions de checkout et le traitement des paiements.
</Info>

## Prérequis

- Node.js 18+
- Expo CLI ou EAS CLI
- Compte Dodo Payments (clé API depuis le tableau de bord)
- Simulateur iOS ou Émulateur Android (ou appareil physique)

## Démarrage Rapide

<Steps>
<Step title="Clone the Repository">
Clonez le dépôt du boilerplate et placez-vous dans le répertoire du projet :

```bash
git clone https://github.com/dodopayments/expo-boilerplate.git
cd expo-boilerplate
```

</Step>

<Step title="Get Your API Credentials">
Obtenez vos identifiants depuis le tableau de bord Dodo Payments en mode Test :

- **Clé API** : Allez à **Développeur → Clés API** dans votre [tableau de bord](https://app.dodopayments.com)

<Tip>
Commencez en mode Test pour pouvoir tester votre intégration en toute sécurité sans traiter de paiements réels.
</Tip>
</Step>

<Step title="Configure Environment Variables">
Créez un fichier `.env` à la racine du projet :

```bash
touch .env
```

Ajoutez vos identifiants Dodo Payments :

```bash .env
EXPO_PUBLIC_DODO_API_KEY=your_test_api_key_here
```

<Warning>
Ne committez jamais votre fichier `.env` dans le contrôle de version. Il est déjà inclus dans `.gitignore`.
</Warning>

<Warning>
Les variables `EXPO_PUBLIC_*` sont intégrées au bundle JavaScript distribué et peuvent être lues par toute personne qui télécharge votre application. Les clés API Dodo Payments sont des secrets bearer ; utilisez-les donc uniquement avec une clé Test Mode pendant le développement. Pour la production, créez les sessions de checkout sur votre backend et transmettez uniquement le `checkout_url` obtenu à l'application — consultez [Mobile Integration](/developer-resources/mobile-integration).
</Warning>
</Step>

<Step title="Install Dependencies">
Installez les packages npm requis :

```bash
npm install
```

</Step>

<Step title="Start the Development Server">
Démarrez le serveur de développement Expo :

```bash
npx expo start
```

Scannez le code QR avec l'application Expo Go sur votre appareil, ou appuyez sur `i` pour le simulateur iOS ou sur `a` pour l'émulateur Android.

<Check>
Vous êtes prêt à commencer le développement ! Le modèle de base inclut des écrans et des composants d'exemple pour vous aider à comprendre l'intégration.
</Check>
</Step>
</Steps>

## Structure du projet

```
expo-boilerplate/
├── app/
│   ├── (tabs)/
│   │   └── index.tsx          # Home screen with examples
│   └── checkout.tsx           # Checkout screen
├── components/
│   └── PaymentButton.tsx      # Payment button component
├── lib/
│   └── dodo.ts                # Dodo Payments client setup
├── .env.example               # Environment variables template
└── package.json
```

## Étapes suivantes

Une fois le modèle de base opérationnel :

<Steps>
<Step title="Create Your Products">
Ajoutez des produits dans votre [tableau de bord Dodo Payments](https://app.dodopayments.com) pour activer la fonctionnalité de checkout.
</Step>

<Step title="Customize the Integration">
Adaptez le code d'exemple aux besoins et au design de votre application.
</Step>

<Step title="Test on Real Devices">
Testez le flux de paiement sur des appareils physiques afin de vous assurer que tout fonctionne correctement.
</Step>

<Step title="Go Live">
Lorsque vous êtes prêt, passez aux clés API Live Mode et générez votre application pour la production.
</Step>
</Steps>

## Génération pour la production

<Steps>
<Step title="Install EAS CLI">

```bash
npm install -g eas-cli
```

</Step>

<Step title="Configure EAS">

```bash
eas build:configure
```

</Step>

<Step title="Build Your App">
Pour iOS :

```bash
eas build --platform ios
```

Pour Android :

```bash
eas build --platform android
```

</Step>
</Steps>
