## Installation

<Steps>
<Step title="Install the package">
Exécutez la commande suivante à la racine de votre projet :

```bash
npm install @dodopayments/tanstack
```

</Step>
<Step title="Set up environment variables">
Créez un fichier <code>.env</code> à la racine de votre projet :

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_RETURN_URL=your-return-url
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
```

<Warning>
Ne validez jamais votre fichier <code>.env</code> ni vos secrets dans le contrôle de version.
</Warning>
</Step>
</Steps>

    ```typescript Tanstack Route Handler expandable
    // src/routes/api/checkout.ts
    import { Checkout } from "@dodopayments/tanstack";
    import { createServerFileRoute } from "@tanstack/react-start/server";

    export const ServerRoute = createServerFileRoute("/api/checkout")
    .methods({
        GET: async ({ request }) => {
        return Checkout({
            bearerToken: process.env.DODO_PAYMENTS_API_KEY,
            returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
            environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
            type: "static", // optional, defaults to 'static'
        })(request)
        },
        POST: async ({ request }) => {
        return Checkout({
            bearerToken: process.env.DODO_PAYMENTS_API_KEY,
            returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
            environment: process.env.DODO_PAYMENTS_ENVIRONMENT,

        })(request)
        }
    })
  
    ```

## Gestionnaire de route Checkout

<Info>
Dodo Payments prend en charge trois types de flux de paiement pour intégrer les paiements à votre site web ; cet adaptateur prend en charge tous les types de flux de paiement.
</Info>

- **Payment Links statiques :** des URL partageables instantanément pour collecter rapidement des paiements, sans code.
- **Payment Links dynamiques :** générez des liens de paiement par programmation avec des informations personnalisées à l’aide de l’API ou des SDK.
- **Sessions Checkout :** créez des expériences de checkout sécurisées et personnalisables avec des paniers de produits préconfigurés et les informations des clients.

<AccordionGroup>

</Warning>

### Format de la réponse
Le checkout statique renvoie une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envoyez les paramètres dans le corps JSON d’une requête POST.
- Prend en charge les paiements uniques et récurrents.
- Pour obtenir la liste complète des champs pris en charge dans le corps POST, consultez :
  - [Corps de la requête pour un produit avec paiement unique](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corps de la requête pour un produit par abonnement](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Format de la réponse
Le checkout dynamique renvoie une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Les sessions Checkout offrent une expérience de checkout hébergée et plus sécurisée qui gère l’intégralité du flux de paiement, aussi bien pour les achats uniques que pour les abonnements, avec un contrôle total de la personnalisation.

Consultez le [guide d’intégration des sessions Checkout](https://docs.dodopayments.com/developer-resources/checkout-session) pour plus de détails et la liste complète des champs pris en charge.

### Format de la réponse
Les sessions Checkout renvoient une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>
</AccordionGroup>

## Gestionnaire de route Customer Portal

Le gestionnaire de route Customer Portal vous permet d’intégrer facilement le Customer Portal de Dodo Payments à votre application Tanstack.

### Query Parameters
<ParamField query="customer_id" type="string" required>
Identifiant du client pour la session du portail (par exemple, <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Si ce paramètre est défini sur <code>true</code>, un e-mail contenant le lien du portail est envoyé au client.
</ParamField>

<Warning>
Renvoie 400 si <code>customer_id</code> est manquant.
</Warning>

## Gestionnaire de route Webhook

- **Method :** seules les requêtes POST sont prises en charge. Les autres méthodes renvoient 405.
- **Vérification de la signature :** vérifie la signature du webhook à l’aide de <code>webhookKey</code>. Renvoie 401 si la vérification échoue.
- **Validation du payload :** validé avec Zod. Renvoie 400 si le payload n’est pas valide.
- **Gestion des erreurs :**
  - 401 : signature non valide
  - 400 : payload non valide
  - 500 : erreur interne lors de la vérification
- **Routage des événements :** appelle le gestionnaire d’événements approprié selon le type de payload.
