Le Dodo Agent Plugin connecte deux serveurs MCP et dix-sept compétences d’intégration à votre agent de codage IA en une seule installation. Il fonctionne avec **Claude Code**, **Codex CLI**, **Cursor** et **OpenCode** — et les serveurs MCP ainsi que la CLI des compétences fonctionnent avec tout client compatible avec MCP.

<Info>
**Trois primitives, un seul plugin.** L’Agent Plugin regroupe tout ce dont vous avez besoin :
- **Serveur MCP API** — accès en temps réel aux paiements, abonnements, clients, produits, remboursements, licences et données d’utilisation. Authentification via OAuth dans le navigateur (aucune clé locale requise).
- **Serveur MCP Knowledge** — recherche sémantique dans toute la documentation de Dodo Payments. Aucune information d’identification requise.
- **Dix-sept compétences pour agents** — fiches pratiques que votre agent charge à la demande pour le checkout, les abonnements, les webhooks, la facturation basée sur l’utilisation et sur les crédits, les clés de licence, le catalogue de produits, les remises, la tarification localisée, le checkout mobile, les remboursements et litiges, la gestion des clients, les adaptateurs de framework, BillingSDK, Better Auth, les tests et la mise en production, ainsi que les bonnes pratiques.
</Info>

## Installer le plugin

Choisissez votre agent de codage ci-dessous. L’installation ajoute automatiquement les deux serveurs MCP et les dix-sept compétences.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installez depuis le marché :

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Le serveur API MCP utilise OAuth du navigateur par défaut — pas de clés requises lors de l'installation. La première fois que votre agent appelle un outil Dodo, vous serez invité à vous connecter.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Code source, options de configuration, et instructions de développement local
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installe des plugins en deux étapes : enregistrez le marketplace depuis votre terminal, puis installez le plugin depuis l'intérieur de l'interface Codex TUI.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Ouvrez Codex et exécutez la commande slash `/plugins` :

```bash
codex
```

Ensuite, tapez `/plugins`, passez au marketplace **Dodo Payments**, sélectionnez le plugin **dodopayments** et choisissez **Installer le plugin**.
</Step>
</Steps>

Les deux serveurs MCP et les dix-sept compétences sont automatiquement enregistrés une fois le plugin installé.

<Note>
Codex CLI n'a pas de sous-commande `codex plugin install` — l'installation de plugins se fait toujours via le flux in-TUI `/plugins`. Voir la [documentation officielle des plugins Codex](https://developers.openai.com/codex/plugins).
</Note>

Si vous avez déjà ajouté le marketplace et que le plugin n'apparaît pas sous `/plugins`, actualisez-le :

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Installation manuelle — clonez le dépôt dans le répertoire local des plugins de Cursor :

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Redémarrez Cursor. Le plugin charge les compétences de `.claude/skills/` (via la couche de compatibilité Claude Code de Cursor) et les serveurs MCP de `.mcp.json`.

<Info>
Le support du marketplace Cursor arrive bientôt. Pour l'instant, utilisez l'installation manuelle ci-dessus.
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode distribue via npm. Ajoutez le plugin à votre `opencode.json` :

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Redémarrez OpenCode. Les deux serveurs MCP (`dodopayments-api`, `dodo-knowledge`) sont automatiquement enregistrés via le hook de configuration du plugin, et les dix-sept compétences sont automatiquement découvertes dans le package installé. Aucun bloc `mcp` manuel n’est requis.
</Accordion>
</AccordionGroup>

<Info>
Vous utilisez un autre agent ? Les guides [Serveur MCP](/developer-resources/mcp-server) et [Compétences d'agent](/developer-resources/agent-skills) couvrent Cursor, Claude Desktop, VS Code, Windsurf, Cline, Zed et tout client compatible MCP.
</Info>

## Ce que vous obtenez

Une fois le plugin installé, votre agent a accès à deux serveurs MCP et dix-sept compétences.

### Serveurs MCP

| Serveur | Objectif | Auth |
|--------|---------|------|
| `dodopayments-api` | Accès API en direct — paiements, abonnements, clients, produits, remboursements, licences, utilisation | OAuth (navigateur) |
| `dodo-knowledge` | Recherche sémantique dans toute la documentation Dodo Payments | Aucun |

Les deux serveurs sont connectés via `mcp-remote` afin qu'ils fonctionnent dans tout client compatible MCP.

### Compétences d'agent

| Compétence | Description |
|-------|-------------|
| `best-practices` | Configuration du SDK, environnements, clés API et architecture canonique du checkout au webhook |
| `framework-adapters` | Gestionnaires de routes `@dodopayments/*` officiels pour Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun et Convex |
| `testing-and-go-live` | Mode test, moyens de paiement de test, tests de webhooks et checklist de mise en production |
| `checkout-integration` | Checkout Sessions, liens de paiement et checkout superposé ou intégré |
| `subscription-integration` | Cycle de vie des abonnements, périodes d’essai, changements de forfait, proratisation et frais à la demande |
| `mobile-checkout` | Checkout intégré à l’application pour React Native, Flutter, iOS et Android |
| `webhook-integration` | Réception et vérification des webhooks à l’aide de la spécification Standard Webhooks |
| `credit-based-billing` | Droits liés aux crédits, soldes, registre, report, dépassement et déduction basée sur les compteurs |
| `usage-based-billing` | Compteurs, ingestion des événements, agrégation et tarification à l’unité |
| `license-keys` | Activation et validation des clés de licence, ainsi que gestion des instances |
| `product-catalog-management` | Produits, tarification, modules complémentaires, collections, images et livraison de produits numériques |
| `discounts-and-promotions` | Codes de remise, règles d’éligibilité, cumul et limites par cycle d’abonnement |
| `localized-pricing` | Tarification localisée, Adaptive Currency et parité de pouvoir d’achat |
| `customer-management` | Clients, portail en libre-service, moyens de paiement enregistrés et wallets |
| `refunds-and-disputes` | Émission de remboursements, gestion des litiges et rétrofacturations, et rapprochement des accès |
| `billing-sdk` | Composants React BillingSDK pour les tableaux de tarification et l’interface de facturation |
| `better-auth-integration` | Le plugin `@dodopayments/better-auth` pour la synchronisation des clients, le checkout et l’accès au portail |

Les compétences se chargent automatiquement — votre agent choisit la bonne lorsqu'il détecte une tâche pertinente. Voir la [documentation des compétences d'agent](/developer-resources/agent-skills) pour la liste complète et l'installation individuelle.

### Essayez ce prompt en premier

Une fois le plugin actif, essayez :

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Votre agent chargera la compétence `webhook-integration`, utilisera le MCP `dodo-knowledge` pour récupérer les dernières formes de charge utile, et écrira un gestionnaire avec vérification de signature suivant la spécification des Standard Webhooks.

## Sécurité et meilleures pratiques

<Warning>
**Ne vous engagez jamais avec des clés API de production.** Utilisez le [mode test](/miscellaneous/test-mode-vs-live-mode) pendant le développement. Le plugin d'agent utilise par défaut OAuth du navigateur — ne passez à des clés API locales que si votre flux de travail l'exige.
</Warning>

- **Utilisez d'abord le mode test.** Testez votre intégration avec les clés `dodo_test_...` avant de passer en production. Voir [Mode test vs Mode live](/miscellaneous/test-mode-vs-live-mode).
- **OAuth est par défaut.** Le plugin d'agent s'authentifie via OAuth du navigateur (aucun secret local). Utilisez le mode clé API uniquement si nécessaire — voir la section Configuration ci-dessous.
- **Relisez le code généré par l'agent.** Vérifiez toujours que les gestionnaires de webhooks incluent la vérification de signature suivant la [spécification des Standard Webhooks](https://standardwebhooks.com/).

## Configurer avec une clé API

Par défaut, le plugin d'agent utilise le serveur MCP distant avec OAuth du navigateur — pas besoin d'identifiants locaux. Si votre flux de travail nécessite une clé API locale (par exemple, environnements CI, serveurs sans interface), vous pouvez passer au mode stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Ouvrez `/plugins` dans Claude Code, sélectionnez **Dodo Payments** et choisissez **Configurer les options**. Remplissez :

- `dodo_api_key` — votre clé `dodo_test_...` ou `dodo_live_...`
- `dodo_webhook_key` — votre secret de signature de webhook
- `dodo_environment` — `test_mode` ou `live_mode`

Puis éditez `.mcp.json` pour pointer `dodopayments-api` vers le serveur stdio local :

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Exécutez `/reload-plugins` pour appliquer les changements à votre session actuelle.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Déclarez `dodopayments-api` vous-même dans `opencode.json` — votre entrée prévaut sur le serveur distant par défaut du plugin :

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Redémarrez OpenCode pour appliquer.
</Accordion>
</AccordionGroup>
