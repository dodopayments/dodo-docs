Le Dodo Agent Plugin intègre deux serveurs MCP et dix-sept skills d’intégration à votre agent de programmation IA en une seule installation. Il fonctionne avec **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** et **OpenCode**. **Gemini CLI** ne bénéficie que des deux serveurs MCP. Les serveurs MCP et la CLI des skills fonctionnent avec tout client compatible avec MCP.

Le plugin suit la spécification [Agent Plugins 1.0.0](https://agent-plugins.org/specification), ce qui permet aux clients disposant d’une prise en charge native de le charger directement depuis la racine `plugin.json` et `mcp.json`. Les clients antérieurs à la spécification chargent le même contenu via des manifestes de compatibilité générés.

<Info>
**Trois primitives, un seul plugin.** Le Agent Plugin regroupe tout ce dont vous avez besoin :
- **Serveur MCP API** — accès en temps réel aux paiements, abonnements, clients, produits, remboursements, licences et données d’utilisation. Authentification via OAuth dans le navigateur (aucune clé locale requise).
- **Serveur MCP Knowledge** — recherche sémantique dans toute la documentation Dodo Payments. Aucun identifiant requis.
- **Dix-sept skills d’agent** — fiches pratiques que votre agent charge à la demande pour le checkout, les abonnements, les webhooks, la facturation basée sur l’utilisation et les crédits, les clés de licence, le catalogue de produits, les remises, la tarification localisée, le checkout mobile, les remboursements et litiges, la gestion des clients, les adaptateurs de framework, BillingSDK, Better Auth, les tests et la mise en production, ainsi que les bonnes pratiques.
</Info>

## Installer le plugin

Choisissez votre agent de programmation ci-dessous. Chaque installation ajoute les deux serveurs MCP ; toutes, à l’exception de Gemini CLI, ajoutent également les dix-sept skills.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installez depuis la marketplace :

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Le serveur MCP API utilise OAuth dans le navigateur par défaut — aucune clé n’est requise au moment de l’installation. La première fois que votre agent appelle un outil Dodo, il vous sera demandé de vous connecter.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Code source, options de configuration et instructions de développement local
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installe les plugins en deux étapes : enregistrez la marketplace depuis votre shell, puis installez le plugin depuis l’interface TUI de Codex.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Ouvrez Codex et exécutez la commande slash `/plugins` :

```bash
codex
```

Saisissez ensuite `/plugins`, sélectionnez la marketplace **Dodo Payments**, choisissez le plugin **dodopayments**, puis sélectionnez **Install plugin**.
</Step>
</Steps>

Les deux serveurs MCP et les dix-sept skills sont automatiquement enregistrés une fois le plugin installé.

<Note>
Codex CLI ne possède pas de sous-commande `codex plugin install` — l’installation du plugin s’effectue toujours via le flux `/plugins` dans la TUI. Consultez la [documentation officielle des plugins Codex](https://developers.openai.com/codex/plugins).
</Note>

Si vous avez déjà ajouté la marketplace et que le plugin n’apparaît pas sous `/plugins`, actualisez-la :

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Installation manuelle — clonez le dépôt dans le répertoire de plugins local de Cursor :

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Redémarrez Cursor. Le plugin charge les skills depuis `skills/` et les serveurs MCP depuis `.mcp.json`, comme indiqué dans `.cursor-plugin/plugin.json`.

<Info>
Les versions récentes de Cursor reconnaissent également directement Agent Plugins 1.0.0 et acceptent `.cursor-plugin/marketplace.json` ou `.claude-plugin/marketplace.json` comme source de marketplace. Ce plugin fournit `.claude-plugin/marketplace.json` — utilisez ce chemin. Le fichier `.cursor-plugin/plugin.json` généré est conservé pour les versions plus anciennes.
</Info>

<Warning>
Les versions antérieures à 0.5.0 fournissaient `skills/` sous forme de liens symboliques vers un sous-module git ; ce clone produisait donc un plugin avec **aucun skill fonctionnel**. Les skills sont désormais fournis sous forme de vrais fichiers. Si vous avez installé une version antérieure, supprimez le répertoire et clonez à nouveau.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode est distribué via npm. Ajoutez le plugin à votre `opencode.json` :

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Redémarrez OpenCode. Les deux serveurs MCP (`dodopayments-api`, `dodo-knowledge`) sont automatiquement enregistrés via le hook de configuration du plugin. Aucun bloc `mcp` manuel n’est requis.

**Les skills nécessitent une ligne supplémentaire.** OpenCode ne recherche pas les skills dans les packages installés ; indiquez-lui donc vous-même le répertoire `skills/` du package :

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

Les entrées `skills.paths` relatives sont résolues par rapport au **répertoire du projet** ; le package doit donc exister dans le `node_modules` de ce projet — le cache de plugins d’OpenCode se trouve à un autre emplacement. Un chemin absolu fonctionne également et évite l’exigence d’une installation locale.

<Warning>
Un chemin de skills qui n’existe pas est ignoré **silencieusement**. Vérifiez plutôt que de supposer :

```bash
opencode run "List every skill available to you by name."
```

Vous devriez en voir dix-sept. Les versions antérieures à 0.5.0 indiquaient que ces skills étaient détectés automatiquement — ce n’était pas le cas ; les utilisateurs d’OpenCode disposaient donc des serveurs MCP, mais d’aucun skill.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Clonez le dépôt où vous le souhaitez, puis enregistrez-le :

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Ouvrez la vue Chat, accédez à **Plugins**, puis ajoutez le dossier cloné. Vous pouvez également l’enregistrer directement dans `settings.json` :

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

La clé est un chemin et la valeur l’active. Les chemins absolus et `~/` fonctionnent également ; un chemin relatif est résolu par rapport à chaque dossier de workspace. Le paramètre est lu en direct : une fenêtre ouverte le prend en compte sans redémarrage. Les skills sont chargés depuis `skills/` et les deux serveurs MCP depuis `.mcp.json`.

<Note>
`chat.pluginLocations` est marqué comme **expérimental** et constitue un paramètre *restreint* ; le workspace doit donc être approuvé pour qu’il soit appliqué. La prise en charge globale des plugins d’agent est une fonctionnalité en préversion régie par `chat.plugins.enabled`, qui est **activée par défaut** — vous ne devez la définir que si votre organisation la désactive par politique.
</Note>

<Info>
VS Code ne se base pas sur `$schema` d’Agent Plugins. Son chargeur examine `.plugin/plugin.json`, puis `.claude-plugin/plugin.json`, puis une racine `plugin.json`, et utilise par défaut `.mcp.json` pour MCP plutôt que `mcp.json`. Comme ce dépôt fournit un `.claude-plugin/plugin.json` généré, VS Code le charge via cette branche de compatibilité et obtient le pont `mcp-remote` plutôt que les transports natifs de `mcp.json`. Tout fonctionne — seul le chemin diffère.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro lit nativement le manifeste Agent Plugins et charge celui-ci comme un Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
Dans Kiro, ouvrez le panneau Powers — l’icône Ghosty avec l’éclair.
</Step>

<Step title="Import the folder">
Choisissez **Add Custom Power → Import power from a folder**, sélectionnez le répertoire cloné (celui qui contient `plugin.json`), puis cliquez sur **Install**.
</Step>
</Steps>

Les skills sont chargés depuis `skills/`, les serveurs MCP depuis `mcp.json`, et la présentation propre à Kiro provient de l’espace de noms d’extension `dev.kiro` dans `plugin.json`.

<Note>
Pour les plugins au format Agent Plugins, Kiro gère les serveurs MCP en interne — ils ne sont **pas** écrits dans votre `~/.kiro/settings/mcp.json` utilisateur ; ne vous attendez donc pas à les y trouver. Kiro peut également installer directement un Power depuis une URL GitHub ; consultez la [documentation d’installation de Kiro](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI ne possède pas de primitive agent-skill ; **seuls les deux serveurs MCP sont donc disponibles** — les dix-sept skills ne le sont pas. `dodo-knowledge` couvre néanmoins une grande partie de ce que fournissent les skills et reste automatiquement à jour.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Redémarrez Gemini CLI. `gemini-extension.json` à la racine du dépôt est le manifeste.
</Accordion>
</AccordionGroup>

Vous utilisez un autre agent ? Les guides [MCP Server](/developer-resources/mcp-server) et [Agent Skills](/developer-resources/agent-skills) couvrent Claude Desktop, Windsurf, Cline, Zed et tout client compatible avec MCP.
</Info>

## Ce que vous obtenez

Une fois le plugin installé, votre agent a accès à deux serveurs MCP et dix-sept skills.

### Serveurs MCP

| Serveur | Fonction | Auth |
|--------|---------|------|
| `dodopayments-api` | Accès API en temps réel — paiements, abonnements, clients, produits, remboursements, licences et utilisation | OAuth (navigateur) |
| `dodo-knowledge` | Recherche sémantique dans toute la documentation Dodo Payments | Aucune |

Les deux serveurs utilisent Streamable HTTP. Le `mcp.json` canonique les déclare nativement (`type: "streamable-http"`), ce qu’utilisent les clients compatibles nativement avec la spécification, tels que Codex CLI et Kiro. Le manifeste de compatibilité généré `.mcp.json` relie à la place les mêmes endpoints via `mcp-remote` ; ils peuvent ainsi également fonctionner dans les clients qui ne peuvent pas établir directement une connexion Streamable HTTP — Claude Code, VS Code et Cursor via l’installation par git clone décrite ci-dessus, dont `.cursor-plugin/plugin.json` pointe vers `.mcp.json`.

### Skills d’agent

| Skill | Description |
|-------|-------------|
| `dodo-best-practices` | Configuration du SDK, environnements, clés API et architecture canonique du checkout au webhook |
| `framework-adapters` | Gestionnaires de routes officiels `@dodopayments/*` pour Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun et Convex |
| `testing-and-go-live` | Mode test, moyens de paiement de test, tests de webhooks et checklist de lancement en production |
| `checkout-integration` | Checkout Sessions, liens de paiement et checkout superposé ou intégré |
| `subscription-integration` | Cycle de vie des abonnements, périodes d’essai, changements de plans, proratisation et frais à la demande |
| `mobile-checkout` | Checkout intégré à l’application pour React Native, Flutter, iOS et Android |
| `webhook-integration` | Réception et vérification des webhooks selon la spécification Standard Webhooks |
| `credit-based-billing` | Droits aux crédits, soldes, ledger, report, dépassement et déduction basée sur un meter |
| `usage-based-billing` | Meters, ingestion d’événements, agrégation et tarification à l’unité |
| `license-keys` | Activation et validation des clés de licence, et gestion des instances |
| `product-catalog-management` | Produits, tarification, modules complémentaires, collections, images et distribution de produits numériques |
| `discounts-and-promotions` | Codes de remise, règles d’éligibilité, cumul et limites par cycle d’abonnement |
| `localized-pricing` | Tarification localisée, Adaptive Currency et parité de pouvoir d’achat |
| `customer-management` | Clients, portail en libre-service, moyens de paiement enregistrés et wallets |
| `refunds-and-disputes` | Émission de remboursements, gestion des litiges et rétrofacturations, et rapprochement des accès |
| `billing-sdk` | Composants React BillingSDK pour les tableaux de tarification et l’interface de facturation |
| `better-auth-integration` | Plugin `@dodopayments/better-auth` pour la synchronisation des clients, le checkout et l’accès au portail |

Les skills sont chargés automatiquement — votre agent sélectionne le bon lorsqu’il détecte une tâche pertinente. Consultez la [documentation Agent Skills](/developer-resources/agent-skills) pour obtenir la liste complète et les instructions d’installation individuelles.

### Essayez d’abord cette invite

Une fois le plugin actif, essayez :

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Votre agent chargera le skill `webhook-integration`, utilisera le MCP `dodo-knowledge` pour récupérer les dernières structures de payload et écrira un handler avec vérification de signature conformément à la spécification Standard Webhooks.

## Prise en charge des clients

### Clients avec installation d’un Agent Plugin

Une seule installation configure les deux serveurs MCP, ainsi que les skills sur chaque client qui possède une primitive de skills.

| Agent | Installation | Skills | Serveurs MCP |
|-------|---------|-------:|------------:|
| **Claude Code** | commande marketplace | 17 | 2 |
| **Codex CLI** | commande marketplace | 17 | 2 |
| **Cursor** | git clone | 17 | 2 |
| **VS Code / GitHub Copilot** | git clone | 17 | 2 |
| **Kiro** | git clone | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | git clone | 0 | 2 |

- **OpenCode** nécessite une entrée `skills.paths` supplémentaire avant le chargement de ses dix-sept skills — consultez la section d’installation ci-dessus.
- **Gemini CLI** ne possède pas de primitive agent-skill ; les skills n’y sont donc pas disponibles par conception.

### Autres clients compatibles avec MCP

Ces clients ne disposent pas d’installation d’Agent Plugin. Configurez manuellement les deux serveurs MCP et ajoutez les skills via la Skills CLI lorsqu’elle est prise en charge.

| Agent | Serveurs MCP | Skills |
|-------|-------------|--------|
| Claude Desktop | [Guide MCP Server](/developer-resources/mcp-server) | non pris en charge |
| Windsurf | [Guide MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / autres | [Guide MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## Sécurité et bonnes pratiques

<Warning>
**Ne validez jamais de clés API de production dans votre dépôt.** Utilisez le [mode test](/miscellaneous/test-mode-vs-live-mode) pendant le développement. Le Agent Plugin utilise OAuth dans le navigateur par défaut — ne passez aux clés API locales que si votre workflow l’exige.
</Warning>

- **Commencez par le mode test.** Isolez votre intégration avec les clés `dodo_test_...` avant le passage en production. Consultez [Mode test et mode live](/miscellaneous/test-mode-vs-live-mode).
- **OAuth est le mode par défaut.** Le Agent Plugin s’authentifie via OAuth dans le navigateur (aucun secret local). N’utilisez le mode avec clé API que si nécessaire — consultez la section Configuration ci-dessous.
- **Examinez le code généré par l’agent.** Vérifiez toujours que les handlers de webhook incluent une vérification de signature conformément à la [spécification Standard Webhooks](https://standardwebhooks.com/).

## Configurer avec une clé API

Par défaut, le Agent Plugin utilise le serveur MCP distant avec OAuth dans le navigateur — aucun identifiant local n’est nécessaire. Si votre workflow requiert une clé API locale (par exemple, dans des environnements CI ou sur des serveurs sans interface), vous pouvez passer en mode stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Ouvrez `/plugins` dans Claude Code, sélectionnez **Dodo Payments**, puis choisissez **Configure options**. Renseignez :

- `dodo_api_key` — votre clé `dodo_test_...` ou `dodo_live_...`
- `dodo_webhook_key` — votre secret de signature des webhooks
- `dodo_environment` — `test_mode` ou `live_mode`

Modifiez ensuite `.mcp.json` afin de faire pointer `dodopayments-api` vers le serveur stdio local :

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Exécutez `/reload-plugins` pour appliquer les modifications à votre session actuelle.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Déclarez vous-même `dodopayments-api` dans `opencode.json` — votre entrée prend le dessus sur le serveur distant par défaut du plugin :

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Redémarrez OpenCode pour appliquer les modifications.
</Accordion>
</AccordionGroup>
