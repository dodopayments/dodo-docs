<Info>
**Session Validity**: Checkout sessions are valid for 24 hours by default. If you pass `confirm=true` in your request, the session will only be valid for 15 minutes.
</Info>

<Warning>
**Liens à usage unique** : le `checkout_url` renvoyé par l'API n'est pas réutilisable et expire dans les 24 heures (ou après 15 minutes lorsque `confirm=true`). Il est destiné à un seul client pour effectuer un paiement. Générez une nouvelle session de paiement pour chaque client et chaque tentative de paiement au lieu de partager ou de réutiliser un lien.
</Warning>

## Créer votre première session de paiement

<Tabs>
<Tab title="Node.js SDK">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'pdt_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

### Réponse de l'API

Toutes les méthodes ci-dessus renvoient la même structure de réponse :

```json
{
  "session_id": "cks_Gi6KGJ2zFJo9rq9Ukifwa",
  "checkout_url": "https://test.checkout.dodopayments.com/session/cks_Gi6KGJ2zFJo9rq9Ukifwa"
}
```

Seul `session_id` est garanti d'être présent. Deux cas renvoient des champs supplémentaires ou en omettent certains :

- **`payment_method_id` a été fourni** — la charge est traitée immédiatement et `checkout_url` est `null`. Utilisez plutôt le `payment_id` renvoyé.
- **`confirm: true` a créé le paiement lors de la création de la session** — la réponse inclut également `payment_id`, `client_secret` et `publishable_key` à utiliser avec le SDK de paiement Dodo Payments.

<Note>
Le `checkout_url` généré est à usage unique et expire dans les 24 heures. Ne le mettez pas en cache et ne le réutilisez pas pour plusieurs clients ou tentatives de paiement — créez une nouvelle session de paiement chaque fois que vous avez besoin d'un lien actualisé.
</Note>

<Steps>
<Step title="Get the checkout URL">
Extrayez le `checkout_url` de la réponse de l'API.
</Step>

<Step title="Redirect your customer">
Dirigez votre client vers l'URL de paiement pour finaliser son achat.

```javascript
// Redirect immediately
window.location.href = session.checkout_url;

// Or open in new window
window.open(session.checkout_url, '_blank');
```

<Tip>
**Options d'intégration alternatives** : Au lieu d'effectuer une redirection, vous pouvez intégrer directement le paiement dans votre page à l'aide de [Overlay Checkout](/developer-resources/overlay-checkout) (fenêtre modale) ou d'[Inline Checkout](/developer-resources/inline-checkout) (entièrement intégré). Dans une application mobile native, transmettez la même URL aux [SDK Mobile Checkout](/developer-resources/mobile-integration) pour Android, iOS, React Native ou Flutter. Toutes ces options utilisent la même URL de session de paiement.
</Tip>
</Step>

<Step title="Handle the return">
Après le paiement, les clients sont redirigés vers votre `return_url` avec des paramètres de requête incluant l'ID du paiement ou de l'abonnement, le statut, l'adresse e-mail du client et les éventuelles clés de licence. Consultez la [documentation des paramètres `return_url`](#request-body) pour obtenir la liste complète.
</Step>

### Champs requis

<ParamField body="product_cart" type="array" required>
Tableau de produits à inclure dans la session de paiement. Chaque produit doit posséder un `product_id` valide provenant de votre tableau de bord Dodo Payments.

<Tip>
**Paiement mixte** : Vous pouvez combiner des produits à paiement unique et des produits par abonnement dans une même session de paiement. Cela permet des cas d'utilisation avancés tels que des frais de mise en place avec des abonnements, des offres groupées de matériel et de SaaS, et bien plus encore.
</Tip>

<Expandable title="Product Cart Item Properties">
<ParamField body="product_id" type="string" required>
Identifiant unique du produit provenant de votre tableau de bord Dodo Payments.

**Exemple :** `"pdt_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
Quantité du produit.

**Exemple :** `1` pour un article, `3` pour plusieurs articles
</ParamField>

<ParamField body="addons" type="array">
Tableau d'addons à associer au produit. Valide uniquement si le produit est un abonnement.

<Expandable title="Addon item properties">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
Montant payé par le client lorsque pay_what_you_want est activé. S'il est désactivé, ce champ est ignoré.

**Format** : Représenté dans la plus petite unité de la devise (par exemple, les centimes pour USD). Pour facturer 1,00 $, transmettez `100`.
</ParamField>

<ParamField body="credit_entitlements" type="array">
Remplacements propres à la session de paiement pour les droits de crédits déjà associés à ce produit. Utilisez ce champ pour accorder un nombre de crédits différent lors de cette session uniquement — par exemple, une offre promotionnelle accordant 1 000 crédits API au lieu des 500 crédits par défaut du produit — sans créer de produit distinct.

<Info>
Chaque `credit_entitlement_id` doit déjà être associé au produit. Ce champ remplace uniquement le `credits_amount` accordé lorsque cette session est exécutée ; les paramètres des droits de crédits au niveau du produit (expiration, report, etc.) continuent de s'appliquer.
</Info>

<Expandable title="Credit entitlement override properties">
<ParamField body="credit_entitlement_id" type="string" required>
ID du droit de crédit à remplacer. Il doit déjà être associé au produit.
</ParamField>

<ParamField body="credits_amount" type="string" required>
Nombre de crédits à accorder pour cette session de paiement, remplaçant le `credits_amount` au niveau du produit. Doit être supérieur à zéro.
</ParamField>

<Accordion title="Session Management">

<ParamField body="return_url" type="string">
URL vers laquelle rediriger les clients une fois le paiement terminé. Dodo Payments ajoute les paramètres de requête suivants à votre URL lors de la redirection :

| Paramètre | Type | Condition |
|-----------|------|-----------|
| `payment_id` | `string` | Toujours présent pour les paiements uniques |
| `subscription_id` | `string` | Toujours présent pour les paiements par abonnement |
| `status` | `string` | Toujours présent |
| `license_key` | `string` | Présent si le produit dispose de clés de licence activées. Séparé par des virgules en cas de clés multiples |
| `email` | `string` | Présent si l'adresse e-mail du client est enregistrée |

**Exemples d'URL de redirection :**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
Utilisez les paramètres de requête `license_key` et `email` pour afficher les clés de licence ou envoyer immédiatement une confirmation sur votre page de retour, sans appel API supplémentaire.
</Tip>
</ParamField>

<ParamField body="cancel_url" type="string">
URL vers laquelle rediriger les clients lorsqu'ils cliquent sur le bouton de retour ou annulent la session de paiement. Si elle n'est pas fournie, le bouton de retour ne sera pas affiché.

<Tip>
Définissez un `cancel_url` pour permettre aux clients de retourner clairement sur votre site sans finaliser l'achat. Cela améliore l'expérience de paiement et réduit les frictions.
</Tip>
</ParamField>

<ParamField body="confirm" type="boolean" default="false">
Si la valeur est true, finalise immédiatement tous les détails de la session. L'API renvoie une erreur si des données obligatoires sont manquantes.
</ParamField>

<ParamField body="discount_codes" type="array">
Appliquez un ou plusieurs codes de réduction empilés à la session de paiement. Les codes sont appliqués **dans l'ordre du tableau** (le premier code réduit le prix initial, le deuxième réduit le prix déjà remisé, et ainsi de suite), dans la limite de **20** codes par session. Lorsque la [parité de pouvoir d'achat](/features/purchasing-power-parity) est activée, le prix initial correspond au montant ajusté selon la PPP, et non au prix de base.

```typescript
discount_codes: ['WELCOME10', 'BLACKFRIDAY20']
```

<Info>
Le champ `discount_code` ci-dessous, au singulier, est **obsolète**, mais reste entièrement pris en charge — les intégrations existantes continuent de fonctionner sans modification. Il ne peut pas être combiné avec `discount_codes` dans la même requête. Migrez vers `discount_codes` lorsque cela vous convient pour bénéficier du cumul.
</Info>
</ParamField>

<ParamField body="discount_code" type="string" deprecated>
**Obsolète** — préférez `discount_codes` pour les nouvelles intégrations. Ce champ fonctionne toujours pour assurer la rétrocompatibilité, mais ne peut pas être combiné avec `discount_codes` dans la même requête.
</ParamField>

<ParamField body="metadata" type="object">
Paires clé-valeur personnalisées permettant de stocker des informations supplémentaires sur la session.
</ParamField>

<ParamField body="force_3ds" type="boolean">
Remplacez le comportement 3DS par défaut du marchand pour cette session.
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
Activez le mode de collecte d'adresse minimale. Lorsqu'il est activé, le paiement collecte uniquement :
- **Pays** : Toujours requis pour déterminer les taxes
- **Code ZIP/postal** : Uniquement dans les régions où il est nécessaire au calcul de la taxe de vente, de la TVA ou de la GST

Cela réduit considérablement les frictions lors du paiement en supprimant les champs de formulaire inutiles.

<Tip>
Activez l'adresse minimale pour finaliser le paiement plus rapidement. La collecte de l'adresse complète reste disponible pour les entreprises qui ont besoin de détails de facturation complets.
</Tip>
</ParamField>

<ParamField body="payment_method_id" type="string">
Un moyen de paiement enregistré appartenant au client associé. Nécessite `confirm: true` et un `customer.customer_id` existant. Lorsqu'il est défini, la charge est traitée immédiatement et `checkout_url` est renvoyé comme `null` — utilisez plutôt le `payment_id` renvoyé.
</ParamField>

<ParamField body="short_link" type="boolean" default="false">
Si la valeur est true, renvoie une URL de paiement raccourcie au lieu de l'URL complète de la session.
</ParamField>

<ParamField body="product_collection_id" type="string">
ID de la collection de produits pour le flux de paiement fondé sur une collection.
</ParamField>

<ParamField body="tax_id" type="string">
ID fiscal du client (par exemple, un numéro de TVA). Nécessite `billing_address` avec un `country`.
</ParamField>

<ParamField body="customer_business_name" type="string">
Nom commercial ou légal facultatif associé à l'ID fiscal. Lorsqu'il est fourni avec un `tax_id` valide, il est affiché sur la facture à la place du nom personnel du client.
</ParamField>

<ParamField body="mandate_min_amount_inr_paise" type="integer">
Remplacez le seuil de mandat défini au niveau du marchand (en paises INR) pour les mandats électroniques INR sur les cartes indiennes.
</ParamField>

### 11. Utilisation de moyens de paiement existants pour un paiement instantané

Utilisez le moyen de paiement enregistré d'un client pour créer une session de paiement traitée immédiatement, sans collecte du moyen de paiement :

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'pdt_premium_plan',
      quantity: 1
    }
  ],
  customer: {
    customer_id: 'cus_123'  // Required when using payment_method_id
  },
  payment_method_id: 'pm_abc123',  // Use customer's saved payment method
  confirm: true,  // Required when using payment_method_id
  return_url: 'https://yourapp.com/success'
});
```

<Warning>
Lors de l'utilisation de `payment_method_id`, `confirm` doit être défini sur `true` et un `customer_id` existant doit être fourni. Le moyen de paiement est validé pour vérifier sa compatibilité avec la devise du paiement. Comme la charge est traitée immédiatement, `checkout_url` est renvoyé comme `null` — utilisez plutôt le `payment_id` renvoyé.
</Warning>

<Info>
Le moyen de paiement doit appartenir au client et être compatible avec la devise du paiement. Cela permet les achats en un clic pour les clients existants.
</Info>

**Types de champs disponibles :** `text`, `number`, `email`, `url`, `date`, `dropdown`, `boolean`

## Prévisualiser les sessions de paiement

Avant de créer une session de paiement, vous pouvez prévisualiser le détail des prix, notamment les taxes, les remises et les totaux. Cela est utile pour afficher des prix précis aux clients avant qu'ils ne passent au paiement.

<Note>
L'`current_breakup.subtotal` prévisualisé tient déjà compte de la [parité de pouvoir d'achat](/features/purchasing-power-parity) et de la [tarification psychologique](/features/charm-pricing) lorsqu'elles s'appliquent au produit.
</Note>

<Note>
Lorsque le panier contient un produit avec abonnement, la réponse de prévisualisation renvoie également un `next_billing_date` — un aperçu de la prochaine date de facturation, afin que vous puissiez l'afficher avant la création de l'abonnement. Cette date est calculée par rapport à maintenant : `now + trial period` lorsqu'une période d'essai s'applique, sinon `now + one payment frequency`. Le champ est omis pour les paniers contenant uniquement des achats ponctuels. Il s'agit d'une estimation basée sur l'heure de la prévisualisation ; l'`next_billing_date` faisant foi est défini lors de l'activation de l'abonnement.
</Note>

<Note>
La prévisualisation renvoie également `trial_period_days` (la durée effective de la période d'essai, gratuite ou payante) et `trial_amount` (le montant de l'essai par unité après réductions, dans les unités mineures de la devise du prix). `trial_amount` est présent uniquement pour un [essai payant](/features/subscription#paid-trials) et vaut `null` pour un essai gratuit ou en l'absence d'essai. Utilisez `current_breakup` pour connaître le total taxé effectivement dû aujourd'hui.
</Note>

## Passer des Dynamic Links aux Checkout Sessions

### Principales différences
Auparavant, lors de la création d'un lien de paiement avec Dynamic Links, vous deviez fournir l'adresse de facturation complète du client.

Avec les Checkout Sessions, cela n'est plus nécessaire. Vous pouvez simplement transmettre les informations dont vous disposez, et nous nous chargeons du reste. Par exemple :

- Si vous connaissez uniquement le pays de facturation du client, fournissez simplement cette information.
- Le parcours de paiement recueillera automatiquement les informations manquantes avant de rediriger le client vers la page de paiement.
- En revanche, si vous disposez déjà de toutes les informations requises et souhaitez accéder directement à la page de paiement, vous pouvez transmettre l'ensemble des données et inclure `confirm=true` dans le corps de votre requête.

### Processus de migration

La migration de Dynamic Links vers les Checkout Sessions est simple :

<Steps>
<Step title="Update your integration">
Mettez à jour votre intégration pour utiliser la nouvelle méthode de l'API ou du SDK.
</Step>

<Step title="Adjust request payload">
Ajustez la charge utile de la requête selon le format des Checkout Sessions.
</Step>

<Step title="That's it!">
Oui. Aucune gestion supplémentaire ni étape de migration particulière n'est nécessaire de votre côté.
</Step>
</Steps>
