## Création de Votre Première Session de Paiement

<Tabs>
<Tab title="SDK Node.js">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'prod_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

```python expandable
import os
from dodopayments import DodoPayments

# Initialize the Dodo Payments client
client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),  # This is the default and can be omitted
    environment="test_mode",  # defaults to "live_mode"
)

def create_checkout_session():
    """
    Create a checkout session for a single product with customer data pre-filled.
    Returns the session object containing checkout_url for customer redirection.
    """
    try:
        session = client.checkout_sessions.create(
            # Products to sell - use IDs from your Dodo Payments dashboard
            product_cart=[
                {
                    "product_id": "prod_123",  # Replace with your actual product ID
                    "quantity": 1
                }
            ],
            
            # Pre-fill customer information to reduce checkout friction
            customer={
                "email": "customer@example.com",
                "name": "John Doe",
                "phone_number": "+1234567890"
            },
            
            # Billing address for tax calculation and compliance
            billing_address={
                "street": "123 Main St",
                "city": "San Francisco", 
                "state": "CA",
                "country": "US",  # Required: ISO 3166-1 alpha-2 country code
                "zipcode": "94102"
            },
            
            # Where to redirect after successful payment
            return_url="https://yoursite.com/checkout/success",
            
            # Custom data for your internal tracking
            metadata={
                "order_id": "order_123",
                "source": "web_app"
            }
        )
        
        # Redirect your customer to this URL to complete payment
        print(f"Checkout URL: {session.checkout_url}")
        print(f"Session ID: {session.session_id}")
        
        return session
        
    except Exception as error:
        print(f"Failed to create checkout session: {error}")

# Example usage in a Flask route
from flask import Flask, jsonify, request

app = Flask(__name__)

@app.route('/create-checkout', methods=['POST'])
```

### Réponse de l'API

Tous les méthodes ci-dessus retournent la même structure de réponse :

```json
{
  "session_id": "cks_Gi6KGJ2zFJo9rq9Ukifwa",
  "checkout_url": "https://test.checkout.dodopayments.com/session/cks_Gi6KGJ2zFJo9rq9Ukifwa"
}
```

<Steps>
<Step title="Obtenez l'URL de paiement">
Extrayez `checkout_url` de la réponse API.
</Step>

<Step title="Redirigez votre client">
Dirigez votre client vers l'URL de paiement pour finaliser son achat.

```javascript
// Redirect immediately
window.location.href = session.checkout_url;

// Or open in new window
window.open(session.checkout_url, '_blank');
```

<Tip>
**Options d'Intégration Alternatives** : Au lieu de rediriger, vous pouvez intégrer le paiement directement dans votre page en utilisant [Overlay Checkout](/developer-resources/overlay-checkout) (superposition modale) ou [Inline Checkout](/developer-resources/inline-checkout) (entièrement intégré). Les deux options utilisent la même URL de session de paiement.
</Tip>
</Step>

<Step title="Gérer le retour">
Après le paiement, les clients sont redirigés vers votre `return_url` avec des paramètres de requête incluant l'ID de paiement/abonnement, le statut, l'email du client, et toutes les clés de licence. Voir la [documentation des paramètres `return_url`](#request-body) pour la liste complète.
</Step>
</Steps>

### Champs Obligatoires

<ParamField body="product_cart" type="array" required>
Tableau de produits à inclure dans la session de paiement. Chaque produit doit avoir un `product_id` valide de votre tableau de bord Dodo Payments.

<Tip>
**Paiement Mixte** : Vous pouvez combiner des produits de paiement unique et des produits d'abonnement dans la même session de paiement. Cela permet des cas d'utilisation puissants comme des frais d'installation avec des abonnements, des bundles matériels avec des SaaS, et plus encore.
</Tip>

<Expandable title="Propriétés de l'Article du Panier de Produits">
<ParamField body="product_id" type="string" required>
L'identifiant unique du produit de votre tableau de bord Dodo Payments.

**Exemple :** `"prod_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
Quantité du produit.

**Exemple :** `1` pour un article unique, `3` pour plusieurs quantités
</ParamField>

<ParamField body="addons" type="array">
Tableau d'addons à attacher au produit. Valide uniquement si le produit est un abonnement.

<Expandable title="Propriétés de l'article Addon">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
Montant que le client paie si pay_what_you_want est activé. Si désactivé, ce champ sera ignoré.

**Format** : Représenté dans la plus petite dénomination de la devise (par exemple, cents pour USD). Par exemple, pour facturer 1,00 $, passez `100`.
</ParamField>

<Tip>

<Accordion title="Gestion de Session">

<ParamField body="return_url" type="string">
URL pour rediriger les clients après la fin du paiement. Dodo Payments ajoute les paramètres de requête suivants à votre URL lors de la redirection :

| Paramètre | Type | Condition |
|-----------|------|-----------|
| `payment_id` | `string` | Toujours présent pour les paiements ponctuels |
| `subscription_id` | `string` | Toujours présent pour les paiements par abonnement |
| `status` | `string` | Toujours présent |
| `license_key` | `string` | Présent si le produit a des clés de licence activées. Séparé par des virgules si plusieurs clés |
| `email` | `string` | Présent si le client a un email enregistré |

**Exemples d'URL de redirection :**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
Utilisez les paramètres de requête `license_key` et `email` pour afficher des clés de licence ou envoyer une confirmation immédiatement sur votre page de retour, sans avoir besoin d'un appel API supplémentaire.
</Tip>
</ParamField>

<Accordion title="Champs personnalisés">

<ParamField body="custom_fields" type="array">
Collectez des informations supplémentaires auprès des clients lors du paiement avec des champs de formulaire personnalisés. Vous pouvez définir jusqu'à 5 champs personnalisés par session de paiement. Les réponses des clients sont incluses dans les charges de webhook et disponibles via l'API.

<Expandable title="Propriétés de l'objet de champ personnalisé">
<ParamField body="key" type="string" required>
Identifiant unique pour ce champ. Utilisé comme clé dans les charges de webhook et les réponses API.

**Exemple** : `"company_name"`, `"referral_source"`, `"team_size"`
</ParamField>

<ParamField body="label" type="string" required>
Étiquette d'affichage montrée au client sur le formulaire de paiement.

**Exemple** : `"Company Name"`, `"How did you hear about us?"`, `"Team Size"`
</ParamField>

<ParamField body="field_type" type="string" required>
Type de champ déterminant les règles de validation d'entrée.

**Types disponibles** :
- `text` - Saisie de texte sur une seule ligne
- `number` - Saisie numérique
- `email` - Adresse email avec validation
- `url` - URL avec validation
- `date` - Sélecteur de date
- `dropdown` - Sélectionner parmi des options prédéfinies
- `boolean` - Bascule Oui/Non
</ParamField>

<ParamField body="required" type="boolean" default="false">
Indique si ce champ doit être rempli avant que le paiement puisse se terminer.
</ParamField>

<ParamField body="placeholder" type="string">

</ParamField>

<ParamField body="options" type="array">
Liste d'options pour le type de champ `dropdown`. Requis lorsque `field_type` est `dropdown`, ignoré pour d'autres types.

**Exemple** : `["Google", "Twitter", "Friend referral", "Other"]`
</ParamField>
</Expandable>
</ParamField>

<Info>
Les réponses des clients aux champs personnalisés sont incluses dans :
- **Webhooks** : `payment.succeeded`, `subscription.created`, et d'autres charges d'événements pertinents contiennent le tableau `custom_field_responses`
- **Réponses API** : Les objets de paiement et d'abonnement incluent `custom_field_responses`
</Info>

</Accordion>

</ParamField>

</Warning>

<Info>
La méthode de paiement doit appartenir au client et être compatible avec la devise de paiement. Cela permet des achats en un clic pour les clients revenants.
</Info>

## Passer de liens dynamiques à des sessions de paiement

### Différences clés
Auparavant, lors de la création d'un lien de paiement avec des liens dynamiques, vous deviez fournir l'adresse de facturation complète du client.

Avec les sessions de paiement, cela n'est plus nécessaire. Vous pouvez simplement transmettre les informations dont vous disposez, et nous nous occuperons du reste. Par exemple :

- Si vous ne connaissez que le pays de facturation du client, fournissez uniquement cela.
- Le flux de paiement collectera automatiquement les détails manquants avant de déplacer le client vers la page de paiement.
- En revanche, si vous avez déjà toutes les informations requises et que vous souhaitez passer directement à la page de paiement, vous pouvez transmettre l'ensemble des données et inclure `confirm=true` dans le corps de votre demande.

### Processus de migration

La migration de liens dynamiques vers des sessions de paiement est simple :

<Steps>
<Step title="Mettez à jour votre intégration">
Mettez à jour votre intégration pour utiliser la nouvelle méthode API ou SDK.
</Step>

<Step title="Ajustez la charge de la demande">
Ajustez la charge de la demande selon le format des sessions de paiement.
</Step>

<Step title="C'est tout !">
Oui. Il n'est pas nécessaire d'autres manipulations ou étapes spéciales de migration de votre côté.
</Step>
</Steps>
