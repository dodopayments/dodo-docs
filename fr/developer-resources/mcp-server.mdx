## Aperçu

Le Protocole de Contexte de Modèle (MCP) est une norme ouverte qui permet aux applications IA de se connecter de manière sécurisée à des sources de données et des API externes. Le Serveur MCP Dodo Payments fournit aux assistants IA comme Claude, Cursor et d'autres clients compatibles MCP un accès structuré à votre infrastructure de paiement.

Le serveur MCP de Dodo Payments utilise l’architecture **Code Mode**. Plutôt que d’exposer des centaines d’outils individuels pour chaque point de terminaison d’API, le Code Mode permet aux agents IA d’écrire et d’exécuter du code TypeScript avec le SDK Dodo Payments dans un environnement isolé de bac à sable.

### Capacités clés

- **Opérations de paiement** : Créer, récupérer et gérer les paiements et les remboursements
- **Gestion des abonnements** : Gérer la facturation récurrente, les mises à niveau et les annulations
- **Administration des clients** : Gérer les données des clients et l'accès au portail
- **Catalogue de produits** : Créer et mettre à jour des produits, des prix et des remises
- **Gestion des licences** : Activer, valider et gérer les licences logicielles
- **Facturation basée sur l'utilisation** : Suivre et facturer l'utilisation mesurée

## Comment fonctionne le Code Mode

Le serveur MCP de Dodo Payments fournit exactement deux outils à votre agent IA :

1. **Outil de recherche dans la documentation** : interroge la documentation sur l’API et le SDK Dodo Payments pour comprendre les opérations et paramètres disponibles.
2. **Outil d’exécution de code** : écrit du code TypeScript contre le SDK qui s’exécute dans un environnement sécurisé de bac à sable.

Cette architecture permet aux agents d’effectuer des opérations complexes en plusieurs étapes dans un seul appel. Par exemple, un agent peut lister tous les abonnements actifs, les filtrer selon des critères spécifiques et appliquer une remise à chacun — tout cela dans un seul script.

<Tip>
Grâce au Code Mode, les agents peuvent chaîner plusieurs appels API, gérer des logiques conditionnelles et effectuer des calculs sans avoir besoin de multiples allers-retours vers la LLM.
</Tip>

### Configuration rapide

Connectez-vous au serveur MCP de Dodo Payments depuis votre client IA :

Le [Dodo Agent Plugin](/developer-resources/build-with-ai-coding-agents) installe à la fois les serveurs MCP et les huit compétences en une seule étape pour Claude Code, Codex CLI, Cursor, et OpenCode. Consultez le [guide sur les AI Coding Agents](/developer-resources/build-with-ai-coding-agents) pour les commandes d'installation par agent.

Si votre agent n'est pas dans cette liste, utilisez les onglets ci-dessous pour configurer directement le serveur MCP.

Ajoutez à `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "dodopayments": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://mcp.dodopayments.com/sse"]
    }
  }
}
```

```json
{
  "mcpServers": {
    "dodopayments": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://mcp.dodopayments.com/sse"]
    }
  }
}
```

```json
{

      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://mcp.dodopayments.com/sse"]
```

## Dodo Knowledge MCP

En plus du Dodo Payments MCP Server (pour l'exécution des opérations API), nous proposons **Dodo Knowledge MCP**—un serveur de recherche sémantique qui fournit aux assistants IA un accès instantané à la documentation de Dodo Payments et à la base de connaissances.

**Construit avec [ContextMCP.ai](https://contextmcp.ai)** : Dodo Knowledge MCP est alimenté par ContextMCP, permettant une recherche sémantique rapide dans notre documentation en utilisant des embeddings vectoriels.

### Qu'est-ce que Dodo Knowledge MCP ?

Dodo Knowledge MCP est un serveur MCP distant qui fournit :

- **Recherche de Documentation Sémantique** : Trouvez la documentation pertinente en utilisant des requêtes en langage naturel.
- **Réponses Contextuelles** : Les assistants IA obtiennent des informations précises et à jour sur Dodo Payments.
- **Installation Zéro** : Pas de clés API ou d'installation locale requises — connectez-vous simplement et commencez à interroger.

### Utilisation Conjointe des Deux Serveurs MCP

Pour la meilleure expérience de développement assistée par IA, nous recommandons d'utiliser les deux serveurs MCP :

| Serveur | Objectif | Cas d'utilisation |
|--------|---------|----------|
| **Dodo Knowledge MCP** | Recherche de documentation | "Comment gérer les webhooks ?", "Quels modes de paiement sont pris en charge ?" |
| **Dodo Payments MCP** | Opérations API | Créer des paiements, gérer des abonnements, traiter des remboursements |

```json
{
  "mcpServers": {
    "dodo-knowledge": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://knowledge.dodopayments.com/mcp"]
    },
    "dodopayments": {
      "command": "npx",
      "args": ["-y", "mcp-remote@latest", "https://mcp.dodopayments.com/sse"]
    }
  }
}
```

Avec les deux serveurs configurés, votre assistant IA peut d'abord rechercher la documentation pour comprendre comment implémenter une fonctionnalité, puis exécuter les appels API réels — tout cela dans une seule conversation.

### Dépannage du Knowledge MCP

Si vous rencontrez des problèmes de connexion :

1. **Effacez le cache d'authentification MCP** : `rm -rf ~/.mcp-auth`
2. **Redémarrez votre application cliente**
3. **Vérifiez les journaux clients** pour les messages d'erreur
4. **Vérifiez la version de Node.js** : nécessite Node.js 18+

Accédez à la page de configuration Dodo Knowledge MCP

### Docker

Exécutez le serveur MCP dans un environnement conteneurisé pour un déploiement cohérent.

```yaml Docker Compose
services:
  dodopayments-mcp:
    image: ghcr.io/dodopayments/mcp:latest
    environment:
      - DODO_PAYMENTS_API_KEY=dodo_test_...
      - DODO_PAYMENTS_WEBHOOK_KEY=your_webhook_key
      - DODO_PAYMENTS_ENVIRONMENT=live_mode
    restart: unless-stopped
```

```bash Docker
# Pull the latest image
docker pull ghcr.io/dodopayments/mcp:latest

# Run the container
docker run -e DODO_PAYMENTS_API_KEY="dodo_test_..." \
  -e DODO_PAYMENTS_WEBHOOK_KEY="your_webhook_key" \
  -e DODO_PAYMENTS_ENVIRONMENT="live_mode" \
  ghcr.io/dodopayments/mcp:latest
```

```yaml Docker Compose
services:
  dodopayments-mcp:
    image: ghcr.io/dodopayments/mcp:latest
```

| `DODO_PAYMENTS_WEBHOOK_KEY` | Votre clé de signature de webhook | Non |
| `DODO_PAYMENTS_ENVIRONMENT` | Définir sur `live_mode` pour la production | Non |

## Meilleures Pratiques de Sécurité

Le mode Code fournit une sécurité inhérente en exécutant le code dans un environnement sandboxes et en injectant les clés API côté serveur. Suivez ces meilleures pratiques supplémentaires pour protéger vos identifiants.

**Ne jamais commettre les identifiants dans le contrôle de version**

Stockez les clés API dans des variables d'environnement ou des systèmes de gestion de secrets sécurisés.

```bash
# Use environment variables
export DODO_PAYMENTS_API_KEY="dodo_test_..."

# Use a .env file (add to .gitignore)
echo "DODO_PAYMENTS_API_KEY=dodo_test_..." > .env
```

**Changez régulièrement les clés**

Générez de nouvelles clés API périodiquement et révoquez les anciennes via votre tableau de bord Dodo Payments.

**Utilisez des clés de test pour le développement**

Utilisez toujours des clés API en mode test pendant le développement pour éviter d'affecter les données de production.

**Implémentez l'authentification pour les serveurs distants**

Lors du déploiement à distance, exigez toujours l'authentification via l'en-tête `Authorization` ou `x-dodo-payments-api-key`.

**Surveillez l'utilisation de l'API**

Suivez l'activité du serveur MCP via votre tableau de bord Dodo Payments et configurez des alertes pour des motifs inhabituels.

**Utilisez HTTPS pour les serveurs distants**

Déployez toujours les serveurs MCP distants derrière des points de terminaison HTTPS.

**Implementez des limites de fréquence**

Protégez-vous contre les abus en mettant en œuvre des limites de fréquence au niveau du serveur MCP et de l'API.

**Restreignez l'accès réseau**

Configurez des règles de pare-feu pour limiter quels clients peuvent se connecter à votre serveur MCP.

## Dépannage

**Vérifiez votre clé API**

Assurez-vous que votre clé API est correctement définie et dispose des autorisations nécessaires.

```bash
# Test your API key
curl -H "Authorization: Bearer dodo_test_..." \
  https://test.dodopayments.com/payments
```

**Vérifiez votre connexion réseau**

Assurez-vous de pouvoir atteindre les points de terminaison de l'API Dodo Payments.

**Examinez les journaux clients**

Activez la journalisation verbale dans votre client MCP pour diagnostiquer les problèmes de connexion.

**Confirmez l'environnement de la clé API**

Assurez-vous d'utiliser des clés de test avec des points de terminaison de test et des clés live avec des points de terminaison de production.

**Vérifiez la variable d'environnement**

Assurez-vous que `DODO_PAYMENTS_ENVIRONMENT` est correctement définie (`live_mode` pour la production).

**Régénérez les identifiants**

Si le problème persiste, générez une nouvelle clé API via votre tableau de bord.

**Validez les paramètres d'entrée**

Assurez-vous que l'assistant IA fournit des paramètres correctement formatés pour chaque outil.

**Examinez les messages d'erreur**

Vérifiez la réponse d'erreur de l'API pour des conseils spécifiques sur ce qui a échoué.

**Testez directement avec l'API**

Vérifiez que l'opération fonctionne en appelant directement l'API Dodo Payments via curl ou Postman.

## Pourquoi le mode Code

Les implémentations MCP traditionnelles souffrent souvent de la "prolifération d'outils", où chaque point de terminaison de l'API est exposé comme un outil distinct. Le mode Code est une approche supérieure pour plusieurs raisons :

### Les LLMs sont meilleurs pour écrire du code que pour appeler des outils
Les LLMs ont été formés sur des millions de lignes de code réel, ce qui les rend naturellement compétents pour écrire des scripts. En revanche, l'appel d'outils est souvent basé sur des exemples synthétiques.

"Faire effectuer des tâches à un LLM avec l'appel d'outils, c'est comme faire suivre à Shakespeare un cours intensif en mandarin pendant un mois, puis lui demander d'écrire une pièce en chinois." — [Cloudflare](https://blog.cloudflare.com/code-mode/)

### Élimine le gonflement de la fenêtre de contexte
Dans une approche traditionnelle, chaque définition d'outil consomme des tokens avant même que la conversation ne commence. Exposer plus de 50 outils peut facilement utiliser entre 55K et 100K+ tokens. Anthropic a constaté que les définitions d'outils pouvaient consommer jusqu'à 134K tokens avant optimisation.

Avec le mode Code, seules 2 définitions d'outils sont chargées (~1K tokens). L'agent recherche la documentation dont il a besoin à la demande. L'outil de recherche d'Anthropic a préservé 95% de la fenêtre de contexte, réduisant les dépenses de 77K à 8,7K tokens.

### Réduit la latence via l'orchestration programmatique
L'appel d'outils traditionnel nécessite un aller-retour complet du modèle pour chaque opération. Si une tâche nécessite 20 appels d'API, cela nécessite 20 aller-retours. En mode Code, l'agent écrit un script qui exécute tous les appels et retourne uniquement le résultat final.

Anthropic a observé une réduction de 37% des tokens et une amélioration de la précision (le taux de récupération des connaissances est passé de 25,6% à 28,5%) en utilisant cette approche programmatique.

### Plus sûr par conception
Le mode Code offre des avantages de sécurité inhérents :
- **Pas de clés API dans les paramètres** : Les clés API sont injectées côté serveur et jamais exposées dans les paramètres des outils envoyés au LLM.
- **Environnement isolé** : Le code s'exécute dans un environnement sécurisé sans accès au réseau ou au système de fichiers de l'hôte.
- **SDK contrôlé** : Seules les méthodes de SDK autorisées sont disponibles pour l'agent.

### S'adapte à n'importe quelle taille d'API
À mesure qu'une API se développe, les performances MCP traditionnelles se dégradent car plus d'outils doivent être chargés dans le contexte. Le mode Code reste constant avec 2 outils, quelle que soit la surface de l'API. Cloudflare a réussi à réduire plus de 2,500 points de terminaison d'API en seulement 2 outils et environ 1,000 tokens de contexte.

Pour plus de détails sur les avantages de cette architecture, consultez les blogs d'ingénierie de [Anthropic](https://www.anthropic.com/engineering/advanced-tool-use) et [Cloudflare](https://blog.cloudflare.com/code-mode/), et la documentation [Programmatic Tool Calling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) de Claude.
