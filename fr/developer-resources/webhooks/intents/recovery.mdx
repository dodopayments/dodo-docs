## Événements de récupération de panier abandonné

Les événements webhook suivants suivent le cycle de vie de la récupération de panier abandonné :

| Événement | Description |
|-------|-------------|
| `abandoned_checkout.detected` | Un paiement abandonné a été détecté. Envoyé lorsqu'un paiement est identifié comme abandonné (échoué ou incomplet) et que le flux de travail de récupération commence. |
| `abandoned_checkout.recovered` | Le client a complété le paiement via le lien de récupération. Le champ `recovered_payment_id` contient l'ID de paiement réussi. |

### Champs de la charge utile du paiement abandonné

<ParamField body="payment_id" type="string" required>
Le paiement original qui a été abandonné. Utilisez ceci pour rechercher les détails du produit, le montant et la devise.
</ParamField>

<ParamField body="brand_id" type="string" required>
La marque à laquelle appartient ce checkout abandonné.
</ParamField>

<ParamField body="customer_id" type="string" required>
Le client qui a abandonné le checkout.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
La raison pour laquelle le checkout a été abandonné. L’une des suivantes :
- `payment_failed` — Le client a tenté d’effectuer le paiement, mais celui-ci a échoué
- `checkout_incomplete` — Le client a consulté le checkout, mais n’a jamais tenté d’effectuer le paiement
</ParamField>

<ParamField body="status" type="string" required>
État actuel du cycle de vie de cette tentative de récupération. L’un des suivants :
- `abandoned` — Détectée, aucun e-mail n’a encore été envoyé
- `recovering` — Au moins un e-mail de récupération a été envoyé
- `recovered` — Le client a effectué le paiement
- `exhausted` — Tous les e-mails ont été envoyés ou un checkout plus récent a été trouvé
- `opted_out` — Le client s’est désabonné
</ParamField>

<ParamField body="abandoned_at" type="string" required>
Horodatage ISO 8601 correspondant au moment où le checkout a été identifié comme abandonné.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
L’identifiant du paiement réussi ayant permis la récupération. `null` jusqu’à la récupération du checkout.
</ParamField>

### Exemple : gestion des Webhooks ACR

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Événements de dunning

Les événements Webhook suivants suivent le cycle de vie du dunning d’un abonnement :

| Événement | Description |
|-------|-------------|
| `dunning.started` | Une tentative de dunning a été créée pour un abonnement passé à l’état `on_hold` ou annulé par le client. |
| `dunning.recovered` | Le client a mis à jour son mode de paiement et le paiement qui en a résulté a été effectué avec succès. Le champ `payment_id` contient l’identifiant du paiement réussi. |

### Champs de la charge utile d’une tentative de dunning

<ParamField body="subscription_id" type="string" required>
L’abonnement à l’origine de la tentative de dunning.
</ParamField>

<ParamField body="brand_id" type="string" required>
La marque à laquelle appartient cette tentative de dunning.
</ParamField>

<ParamField body="customer_id" type="string" required>
Le client auquel appartient l’abonnement.
</ParamField>

<ParamField body="trigger_state" type="string" required>
L’état de l’abonnement à l’origine du dunning. L’un des suivants :
- `on_hold` — Abonnement suspendu en raison d’un échec de paiement
- `cancelled` — Le client a annulé depuis le portail client
</ParamField>

<ParamField body="status" type="string" required>
État actuel du cycle de vie de cette tentative de dunning. L’un des suivants :
- `recovering` — Les e-mails de dunning sont en cours d’envoi
- `recovered` — Le client a mis à jour son mode de paiement et le paiement a été effectué avec succès
- `exhausted` — Tous les e-mails ont été envoyés ou l’état de l’abonnement a changé
</ParamField>

<ParamField body="created_at" type="string" required>
Horodatage ISO 8601 correspondant au moment où la tentative de dunning a été créée.
</ParamField>

<ParamField body="payment_id" type="string | null">
L’identifiant du paiement réussi ayant permis la récupération. `null` pendant la récupération.
</ParamField>

### Exemple : gestion des Webhooks de dunning

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
Abonnez-vous à `dunning.started` et `dunning.recovered` pour suivre l’intégralité du cycle de vie du dunning. Utilisez `dunning.started` pour suspendre les périodes de grâce ou signaler les abonnements à risque dans votre système.
</Tip>
