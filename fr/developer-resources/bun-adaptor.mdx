## Installation

<Steps>
<Step title="Install the package">
Exécutez la commande suivante à la racine de votre projet :

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
Créez un fichier <code>.env</code> à la racine de votre projet :

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
Ne validez jamais votre fichier <code>.env</code> ni vos secrets dans le contrôle de version.
</Warning>
</Step>
</Steps>

## Exemples de gestionnaires de routes

<Info>
Tous les exemples supposent que vous utilisez le serveur natif de Bun avec <code>Bun.serve()</code>.
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  Utilisez ce gestionnaire pour intégrer le checkout de Dodo Payments à votre serveur Bun. Il prend en charge les flux de paiement statique (GET), dynamique (POST) et par session (POST).
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>

## Gestionnaire de route Checkout

<Info>
Dodo Payments prend en charge trois types de flux de paiement pour intégrer les paiements à votre site web ; cet adaptateur les prend tous en charge.
</Info>

- **Liens de paiement statiques :** URLs partageables instantanément pour collecter rapidement des paiements, sans code.
- **Liens de paiement dynamiques :** Générez des liens de paiement par programmation avec des informations personnalisées à l’aide de l’API ou des SDK.
- **Sessions Checkout :** Créez des expériences de checkout sécurisées et personnalisables avec des paniers de produits et des informations client préconfigurés.

</Warning>

### Format de la réponse
Le checkout statique renvoie une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envoyez les paramètres dans le corps JSON d’une requête POST.
- Prend en charge les paiements ponctuels et récurrents.
- Pour obtenir la liste complète des champs pris en charge dans le corps POST, consultez :
  - [Corps de la requête pour un produit à paiement unique](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corps de la requête pour un produit par abonnement](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Format de la réponse
Le checkout dynamique renvoie une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Les sessions Checkout offrent une expérience de checkout hébergée plus sécurisée qui gère l’intégralité du flux de paiement pour les achats ponctuels comme pour les abonnements, avec un contrôle total de la personnalisation.

Consultez le [Guide d’intégration des sessions Checkout](https://docs.dodopayments.com/developer-resources/checkout-session) pour plus d’informations et la liste complète des champs pris en charge.

### Format de la réponse
Les sessions Checkout renvoient une réponse JSON contenant l’URL du checkout :

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>
</AccordionGroup>

## Customer Portal Gestionnaire de route

Le gestionnaire de route Customer Portal vous permet d’intégrer facilement le portail client de Dodo Payments à votre application serveur Bun.

### Paramètres de requête
<ParamField query="customer_id" type="string" required>
Identifiant client pour la session du portail (par exemple, <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Si la valeur est <code>true</code>, un e-mail contenant le lien du portail est envoyé au client.
</ParamField>

<Warning>
Renvoie 400 si <code>customer_id</code> est absent.
</Warning>

## Gestionnaire de route Webhook

- **Méthode :** Seules les requêtes POST sont prises en charge. Les autres méthodes renvoient 405.
- **Vérification de la signature :** Vérifie la signature du webhook à l’aide de <code>webhookKey</code>. Renvoie 401 si la vérification échoue.
- **Validation de la charge utile :** Validée avec Zod. Renvoie 400 si la charge utile n’est pas valide.
- **Gestion des erreurs :**
  - 401 : Signature non valide
  - 400 : Charge utile non valide
  - 500 : Erreur interne lors de la vérification
- **Routage des événements :** Appelle le gestionnaire d’événements approprié en fonction du type de charge utile.
