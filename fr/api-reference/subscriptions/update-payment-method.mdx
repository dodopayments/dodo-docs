---
openapi: post /subscriptions/{subscription_id}/update-payment-method
title: Mettre à jour le mode de paiement
description: Mettez à jour le mode de paiement pour un abonnement existant. Vous
  pouvez soit ajouter un nouveau mode de paiement, soit utiliser un mode de
  paiement existant parmi les modes de paiement enregistrés du client.
---

Mettez à jour le moyen de paiement pour un abonnement. Ce point de terminaison prend en charge à la fois les abonnements actifs et les abonnements dans l'état `on_hold`.

<Info>
Pour les abonnements dans l'état `on_hold`, la mise à jour du moyen de paiement crée automatiquement une charge pour les sommes dues restantes, génère une facture et réactive l'abonnement à l'état `active` après un paiement réussi.
</Info>

### Cas d'utilisation

- **Abonnements actifs** : Mettez à jour le mode de paiement lorsque la carte expire ou que le client souhaite utiliser un mode de paiement différent
- **Abonnements en attente** : Réactivez les abonnements qui ont été mis en attente en raison de paiements échoués en mettant à jour le mode de paiement
- **Gestion des modes de paiement** : Alternez entre les modes de paiement enregistrés ou ajoutez-en de nouveaux

<Info>
Pour lister les moyens de paiement existants pour un client, utilisez l'[API Liste des Moyens de Paiement](/api-reference/customers/get-customer-payment-methods). Cela vous aide à récupérer les ID des moyens de paiement disponibles lors de l'utilisation de `type: "existing"` pour mettre à jour le moyen de paiement d'un abonnement.
</Info>

### Comportement pour les abonnements actifs

Lors de la mise à jour du mode de paiement pour un abonnement actif :

- Le mode de paiement est mis à jour immédiatement
- Aucun prélèvement n'est créé
- L'abonnement reste actif
- Les renouvellements futurs utiliseront le nouveau mode de paiement

### Comportement pour les abonnements en attente

Lors de la mise à jour du moyen de paiement pour un abonnement dans l'état `on_hold` :

1. Une charge est automatiquement créée pour les sommes dues restantes
2. Une facture est générée pour la charge
3. Le paiement est traité en utilisant le nouveau moyen de paiement
4. Après un paiement réussi, l'abonnement est réactivé à l'état `active`
5. Vous recevrez des événements webhook : `payment.succeeded` suivis de `subscription.active`

<Warning>
Si le paiement échoue après la mise à jour du moyen de paiement pour un abonnement `on_hold`, l'abonnement restera dans l'état `on_hold`. Surveillez les événements webhook pour suivre l'état du paiement.
</Warning>

### Événements Webhook

Lors de la mise à jour d'un moyen de paiement pour un abonnement `on_hold`, vous recevrez les événements webhook suivants :

1. **`payment.succeeded`** - La charge pour les sommes dues restantes a réussi
2. **`subscription.active`** - L'abonnement a été réactivé
