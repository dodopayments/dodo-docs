## API-Key-Verwaltung und Authentifizierung

<Steps>
<Step title="Access API Keys">
Navigieren Sie in Ihrem Dashboard zu **Developer → API Keys**, um Ihre Schlüssel zu verwalten.
</Step>

<Step title="Generate a New Key">
Wählen Sie **Add API Key**, geben Sie einen aussagekräftigen Namen ein und konfigurieren Sie den Schreibzugriff:

- **Enable write access** (aktiviert): Vollständige Lese- und Schreibberechtigungen für alle API-Vorgänge
- **Enable write access** (deaktiviert): Nur-Lese-Zugriff – es können ausschließlich Daten abgerufen werden (Zahlungen, Abonnements, Kunden, Produkte). Ressourcen können nicht erstellt oder geändert werden.

<Tip>
Deaktivieren Sie "Enable write access" für Dashboard-Integrationen, Analysetools und alle Systeme, die Daten nur anzeigen müssen, ohne Änderungen vorzunehmen.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Kopieren Sie den generierten Schlüssel sofort und stellen Sie sicher, dass er sicher gespeichert wird.
</Step>

<Step title="Authenticate Your API Requests">
Verwenden Sie Ihre API-Schlüssel zur Authentifizierung aller Anfragen. Verwenden Sie das folgende Autorisierungsformat:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Geben Sie Ihre geheimen API-Schlüssel niemals in clientseitigem Code oder öffentlichen Repositories preis.
</Warning>
</Step>
</Steps>

## Rate Limits

Unsere API verwendet ein Rate-Limiting-System mit zwei Zeitfenstern und Burst-Schutz. Die Limits richten sich nach Ihrer Authentifizierungsmethode und Ihrer Business-Stufe.

### Standardlimits (Tier 0)

| Zeitfenster | Limit |
|--------|-------|
| Pro Sekunde (Burst) | 40 Anfragen |
| Pro Minute (anhaltend) | 240 Anfragen |

### Business-Stufen

Höhere Rate Limits sind für Unternehmen mit erhöhtem API-Bedarf verfügbar:

| Stufe | Burst (pro Sekunde) | Anhaltend (pro Minute) |
|------|-------------------|------------------------|
| Tier 0 (Standard) | 40 | 240 |
| Tier 1 | 100 | 1.000 |
| Tier 2 | 500 | 5.000 |

<Tip>
Kontaktieren Sie den Support, um Ihr Unternehmen auf eine höhere Rate-Limit-Stufe hochzustufen.
</Tip>

### Nicht authentifizierte Anfragen

Anfragen ohne gültige Authentifizierungs-Header werden nach IP-Adresse begrenzt:

| Zeitfenster | Limit |
|--------|-------|
| Pro Sekunde (Burst) | 20 Anfragen |
| Pro Minute (anhaltend) | 100 Anfragen |

### Rate-Limit-Header

Überwachen Sie Ihre Nutzung mit diesen Response-Headern:

- `X-RateLimit-Limit` – Maximale Anzahl zulässiger Anfragen
- `X-RateLimit-Remaining` – Verbleibende Anfragen im aktuellen Zeitfenster
- `X-RateLimit-Reset` – Zeitpunkt, zu dem das Rate Limit zurückgesetzt wird

<Note>
Wenn Sie die Rate Limits überschreiten, gibt die API eine `429 Too Many Requests` Response zurück. Implementieren Sie in Ihrer Retry-Logik ein exponentielles Backoff.
</Note>
