## API-Key-Verwaltung und authentication

<Steps>
<Step title="Access API Keys">
Navigiere in deinem Dashboard zu **Developer → API Keys**, um deine keys zu verwalten.
</Step>

<Step title="Generate a New Key">
Wähle **Add API Key**, gib einen aussagekräftigen Namen ein und konfiguriere den Schreibzugriff:

- **Enable write access** (aktiviert): Vollständige Lese- und Schreibberechtigungen für alle API operations
- **Enable write access** (deaktiviert): Read-only-Zugriff – Daten können nur abgerufen werden (payments, subscriptions, customers, products). Ressourcen können nicht erstellt oder geändert werden.

<Tip>
Deaktiviere "Enable write access" für Dashboard-Integrationen, analytics tools und jedes System, das Daten nur anzeigen und keine Änderungen vornehmen muss.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Kopiere den generierten key sofort und stelle sicher, dass er sicher gespeichert wird.
</Step>

<Step title="Authenticate Your API Requests">
Verwende deine API keys, um alle requests zu authentifizieren. Nutze das folgende authorization-Format:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Gib deine geheimen API keys niemals in clientseitigem code oder öffentlichen repositories preis.
</Warning>
</Step>
</Steps>

## Ratenlimits

Unsere API verwendet ein Ratenbegrenzungssystem mit zwei Zeitfenstern und Burst-Schutz. Die Limits richten sich nach deiner authentication-Methode und deinem business tier.

### Standardlimits (Tier 0)

| Zeitfenster | Limit |
|--------|-------|
| Pro Sekunde (Burst) | 40 requests |
| Pro Minute (anhaltend) | 240 requests |

### Business-Tiers

Höhere Ratenlimits sind für Unternehmen mit erhöhtem API-Bedarf verfügbar:

| Tier | Burst (pro Sekunde) | Anhaltend (pro Minute) |
|------|-------------------|------------------------|
| Tier 0 (Standard) | 40 | 240 |
| Tier 1 | 100 | 1.000 |
| Tier 2 | 500 | 5.000 |

<Tip>
Kontaktiere den Support, um dein Unternehmen auf ein höheres Ratenlimit-Tier hochzustufen.
</Tip>

### Nicht authentifizierte requests

Requests ohne gültige authentication headers werden nach IP-Adresse begrenzt:

| Zeitfenster | Limit |
|--------|-------|
| Pro Sekunde (Burst) | 20 requests |
| Pro Minute (anhaltend) | 100 requests |

### Ratenlimit-Header

Überwache deine Nutzung mit diesen response headers:

- `X-RateLimit-Limit` – Maximale Anzahl zulässiger requests
- `X-RateLimit-Remaining` – Verbleibende requests im aktuellen Zeitfenster
- `X-RateLimit-Reset` – Zeitpunkt, an dem das Ratenlimit zurückgesetzt wird

<Note>
Wenn du die Ratenlimits überschreitest, gibt die API eine `429 Too Many Requests` response zurück. Implementiere exponentielles Backoff in deiner retry logic.
</Note>
