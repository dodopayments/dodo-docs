## Umgang mit Zahlungsfehlern

Verwenden Sie den `on_payment_failure`-Parameter, um zu steuern, was passiert, wenn die Zahlung für die Planänderung fehlschlägt:

| Value | Verhalten |
|-------|-----------|
| `prevent_change` | Behalten Sie das Abonnement im aktuellen Plan, bis die Zahlung erfolgreich ist. Die Planänderung bleibt ausstehend. |
| `apply_change` | Wenden Sie die Planänderung sofort an, unabhängig vom Zahlungsergebnis. Dies ist die Standardeinstellung. |

<Info>
Wenn `on_payment_failure` nicht angegeben ist, gilt das auf Unternehmensebene konfigurierte Verhalten im Dashboard.
</Info>

## Rabattcodes

Sie können einen Rabattcode anwenden, wenn Sie den Plan ändern, indem Sie den Parameter `discount_code` übergeben.

| Szenario | Verhalten |
|----------|-----------|
| `discount_code` bereitgestellt | Validiert und wendet den Rabatt auf den neuen Plan an. |
| `discount_code` nicht bereitgestellt, bestehender Rabatt mit `preserve_on_plan_change=true` | Bestehender Rabatt wird beibehalten, wenn er auf das neue Produkt anwendbar ist. |
| `discount_code` nicht bereitgestellt, kein beibehaltbarer Rabatt | Kein Rabatt angewendet. |

<Tip>
Verwenden Sie Rabattcodes während Planänderungen, um bei Upgrades Aktionspreise anzubieten, oder übergeben Sie einen Code, wenn Sie Kunden auf eine neue Tarifstufe migrieren.
</Tip>

<Tip>
Verwenden Sie `prevent_change` für kritische Upgrades, bei denen Sie die Zahlung sicherstellen wollen, bevor Sie Zugang zu Premiumfunktionen gewähren.
</Tip>
