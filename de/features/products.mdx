## Erstellen Sie ein Produkt

Sie können Produkte über das Dashboard oder über die API erstellen. Wählen Sie das Preismodell im Voraus: Einmalig, Abonnement oder Nutzungsbasiert und konfigurieren Sie dann die Details. Das Preismodell kann später nicht geändert werden; erstellen Sie ein neues Produkt, wenn Sie ein anderes Modell benötigen.

<Steps>
<Step title="Name & description">
Geben Sie einen klaren Titel und eine prägnante, wertorientierte Beschreibung an. Markdown wird in Beschreibungen unterstützt.

<Tip>
Halten Sie den ersten Satz kundenorientiert und ergebnisfokussiert; dieser erscheint prominent im Checkout.
</Tip>

<Frame>
  <img src="/images/products.png" alt="Produkte" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

</Step>

<Step title="Pricing model & price">
Wählen Sie das Preismodell:

- **Einmalig**: Festpreis, der einmal bezahlt wird.
- **Abonnement**: Wiederkehrender Preis mit Intervall und optionaler Testphase.
- **Nutzungsbasiert**: Preis, der aus gemessenen Ereignissen abgeleitet wird.

Legen Sie dann die Preise fest:

- **Preis**: Basisbetrag und Währung. Sie können den Basispreis in **jeder Währung festlegen, die Dodo Payments berechnen kann**, nicht nur in USD. Verwenden Sie die durchsuchbare Währungsauswahl, um eine Währung zu finden; **USD, GBP, EUR und INR** sind oben in der Liste angeheftet.
- **Rabatt (%)**: Optionaler Inline-Rabatt, der im Checkout und auf Rechnungen angezeigt wird.
- Legen Sie bei Abonnements **Wiederholen alle** (z. B. 1 Monat oder 1 Jahr), **Testtage** und einen optionalen **Testbetrag** für einen [kostenpflichtigen Testzeitraum](/features/subscription#paid-trials) fest. Der Abonnementpreis muss mindestens **1 $** (oder dem Gegenwert in der gewählten Währung) entsprechen; Beträge unter diesem Mindestwert werden nicht unterstützt, und das Abonnement funktioniert nicht.

<Info>
Kunden außerhalb Ihrer Basiswährung werden weiterhin über [Adaptive Currency](/features/adaptive-currency) abgerechnet. So können Sie Preise in der Währung festlegen, die am besten zu Ihrem Markt passt, ohne die Abrechnung für Käufer zu ändern.
</Info>

<Tip>
Möchten Sie statt einer Live-FX-Umrechnung einen festen Preis pro Währung oder Land? Legen Sie für das Produkt ein `pricing_mode` fest und fügen Sie Regeln für [Localized Pricing](/features/localized-pricing) hinzu – zum Beispiel 9,99 € in EUR oder ₹999 in Indien.
</Tip>

<Warning>
Eine Preisänderung wirkt sich nur auf neue Käufe aus. Für bestehende Abonnements gelten die Regeln für Planänderungen.
</Warning>
</Step>

<Step title="Product media">
Laden Sie Bilder hoch, um das Produkt im Checkout und auf Rechnungen zu präsentieren. Unterstützt werden PNG/JPG/WebP bis zu 3 MB. Sie können die Reihenfolge jederzeit ändern oder Bilder ersetzen.
</Step>

<Step title="Automated entitlements (Under Advanced Settings)">
Fügen Sie eine Fulfillment-Option hinzu, die nach der Zahlung automatisch aktiviert wird:

- **Lizenzschlüssel**: Eindeutige Schlüssel ausstellen und validieren
- **Dateidownloads**: Sicheren Dateizugriff gewähren
- **Benutzerdefiniert**: Lösen Sie Ihre eigene Berechtigungslogik über Webhooks aus

Fügen oder entfernen Sie Vorteile, wenn sich Ihr Angebot weiterentwickelt. Bestehende Abonnenten erhalten oder verlieren entsprechend den Zugriff.
</Step>
</Steps>

## Varianten und Preisoptionen

Erstellen Sie statt Varianten unter einem Produkt separate Produkte für jede Preisoption (zum Beispiel monatlich und jährlich). Gruppieren Sie diese anschließend in einer **Product Collection**, um alle Optionen in einem einzigen Checkout anzuzeigen und den Planwechsel im Customer Portal zu ermöglichen.

<Frame>
  <img src="/images/product-collection/checkout-page.png" alt="Product Collections" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

### Warum dieser Ansatz?

- **Klare Preismodelle**: Jedes Produkt verfügt über ein einzelnes, klar definiertes Preismodell (einmalig, Abonnement oder nutzungsbasiert)
- **Vorhersehbare APIs**: Einfachere Integrationen ohne verschachtelte Variantenlogik
- **Einfachere Berichte**: Verfolgen Sie Umsatz und Kennzahlen pro Produkt, ohne Varianten aggregieren zu müssen
- **Flexibler Checkout**: Zeigen Sie mehrere Produkte nebeneinander an, damit Kunden sie vergleichen und auswählen können

### So funktionieren Product Collections

1. **Produkte erstellen**: Richten Sie einzelne Produkte für jeden Plan ein (z. B. Starter Monthly, Starter Annual, Pro Monthly, Pro Annual)
2. **In einer Collection gruppieren**: Fügen Sie verwandte Produkte zu einer Product Collection hinzu
3. **Einheitlicher Checkout**: Kunden sehen alle Optionen in einem Checkout und wählen ihren bevorzugten Plan aus
4. **Planwechsel**: Kunden können über das Customer Portal zwischen Produkten derselben Collection upgraden oder downgraden

## Produkte verwalten

Sie können Produkte über das Dashboard oder programmgesteuert über die API verwalten. Die API bietet vollständige Kontrolle über das Erstellen, Aktualisieren und Abrufen von Produkten, das Hochladen von Bildern sowie das Archivieren.

### Verwaltung über das Dashboard

- **Aktualisieren**: Bearbeiten Sie Name, Beschreibung, Bilder, Preis, Felder und Vorteile jederzeit (das Preismodell ist unveränderlich).
- **Archivieren**: Blenden Sie ein Produkt für neue Käufe aus, ohne bestehende Kunden zu beeinträchtigen. Sie können es später wieder aus dem Archiv holen.
- **Entwürfe**: Ein Produkt in Bearbeitung wird als Entwurf gespeichert, damit Sie später darauf zurückkommen können. Entwürfe werden **separat für den Testmodus und den Live-Modus** gespeichert, sodass ein unfertiges Produkt in einem Modus niemals in den anderen übergeht. Verwenden Sie **Entwurf löschen**, um ihn zu verwerfen und neu zu beginnen.

<Tip>
Produkt- und Collection-Formularseiten enthalten Aktionsschaltflächen im Header, sodass Sie speichern können, ohne zum Ende eines langen Formulars zu scrollen.
</Tip>

### Verwaltung über die API

Mit den folgenden Anweisungen können Sie Produkte erstellen, aktualisieren, verwalten und abrufen, einschließlich des Hochladens von Bildern.

<AccordionGroup>
<Accordion title="Creating a Product">
Ein Produkt kann ein einmaliger Artikel oder ein abonnementbasierter Dienst sein. Um ein neues Produkt zu erstellen, senden Sie eine `POST`-Anfrage an den Endpunkt `/products` mit Angaben wie Name, Beschreibung, Preis, Währung und der Information, ob es sich um ein wiederkehrendes Produkt handelt.

Legen Sie bei wiederkehrenden Produkten das Objekt `price` auf einen wiederkehrenden Preis (`type: recurring_price`) fest und geben Sie `payment_frequency_interval` sowie `subscription_period_interval` (`Day`, `Week`, `Month` oder `Year`) zusammen mit den entsprechenden Anzahlen an.

<Card title="Create Product API" icon="code" href="/api-reference/products/post-products">
  Eine detaillierte Struktur von Anfrage und Antwort finden Sie in der API-Dokumentation zu Create Product.
</Card>
</Accordion>

<Accordion title="Updating a Product">
Um ein bestehendes Produkt zu ändern, senden Sie eine `PATCH`-Anfrage an den Endpunkt `/products/{product_id}`. Sie können Eigenschaften wie Name, Preis und Beschreibung aktualisieren, während andere Details unverändert bleiben.

Stellen Sie sicher, dass `product_id` im Endpunkt mit einem bestehenden Produkt übereinstimmt.

<Card title="Update Product API" icon="code" href="/api-reference/products/patch-products">
  Eine detaillierte Struktur von Anfrage und Antwort finden Sie in der API-Dokumentation zu Update Product.
</Card>
</Accordion>

<Accordion title="Retrieving Products">
Sie können eine Liste der in Ihrem Konto gespeicherten Produkte mit einer `GET`-Anfrage an den Endpunkt `/products` abrufen. So können Sie Produktdetails einschließlich aktiver und archivierter Produkte abrufen.

<Card title="Retrieve Products API" icon="code" href="/api-reference/products/get-products">
  Eine detaillierte Struktur von Anfrage und Antwort finden Sie in der API-Dokumentation zu Retrieve Products.
</Card>
</Accordion>

<Accordion title="Uploading Product Images">
Sie können ein Bild mit einem Produkt verknüpfen, indem Sie es mithilfe einer von der API bereitgestellten vorab signierten URL in AWS S3 hochladen. Fordern Sie zunächst eine URL zum Hochladen eines Bildes über den Endpunkt `/products/{product_id}/images` an und verwenden Sie anschließend die bereitgestellte URL, um das Bild innerhalb von 60 Sekunden hochzuladen.

<Warning>
Die vorab signierte URL läuft nach 60 Sekunden ab. Das Bild muss daher innerhalb dieses Zeitraums hochgeladen werden.
</Warning>

Sobald Sie die vorab signierte URL von der API erhalten haben, laden Sie das Bild mit der `PUT`-Methode hoch. Dadurch wird ein sicherer und zeitlich begrenzter Zugriff auf AWS S3 zum Hochladen des Bildes gewährleistet.

**Unterstützte Bibliotheken für das Hochladen in S3:**
- **Node.js**: `axios`, `node-fetch`
- **Python**: `requests`, `boto3`
- **Go**: `net/http`
- **PHP**: `GuzzleHttp`
- **Ruby**: `rest-client`

Wenn der Upload erfolgreich ist, gibt AWS S3 den Status `200 OK` zurück. Dies bedeutet, dass das Bild erfolgreich gespeichert wurde.

<Card title="Upload Product Image API" icon="code" href="/api-reference/products/put-products-images">

</Accordion>

<Accordion title="Archiving a Product">
Wenn Sie ein Produkt nicht mehr anzeigen oder verwenden möchten, können Sie es mit einer `DELETE`-Anfrage an den Endpunkt `/products/{id}` archivieren. Dadurch wird das Produkt ausgeblendet, aber nicht dauerhaft gelöscht.

<Accordion title="Unarchiving a Product">

## Best Practices

- **Mit Klarheit beginnen**: Separate Produkte für jede Preisoption (monatlich gegenüber jährlich)
- **Testzeiträume sinnvoll einsetzen**: Kombinieren Sie Testzeiträume mit Onboarding, um die Aktivierung zu fördern
- **Fulfillment automatisieren**: Verwenden Sie Vorteile und Webhooks, um Leistungen sofort bereitzustellen
- **Metadaten verwenden**: Speichern Sie die IDs Ihres Systems zur Abstimmung
