## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## Deaktivierung von Zahlungsmethoden auf Geschäftsebene

Sie können spezifische Zahlungsmethoden auf Geschäftsebene von Ihrem Dashboard aus deaktivieren. Dies gilt für alle Checkout-Sitzungen Ihres Unternehmens, ohne dass eine Konfiguration pro Produkt oder Sitzung erforderlich ist.

<Steps>
<Step title="Navigate to Settings">
Gehen Sie zu **Einstellungen > Zahlungsmethoden** im Dodo Payments-Dashboard.
</Step>

<Step title="Disable Payment Methods">
Schalten Sie alle Zahlungsmethoden aus, die Sie Kunden nicht anbieten möchten.
</Step>
</Steps>

<Tip>
Verwenden Sie dies, um Zahlungsmethoden zu deaktivieren, die in Ihrer Region hohe Betrugsraten aufweisen, oder um die Optionen nur auf die Methoden zu beschränken, die Ihr Unternehmen operativ unterstützt.
</Tip>

<Info>
Einstellungen auf Geschäftsebene wirken als globaler Filter. Einschränkungen pro Checkout über `allowed_payment_method_types` schränken die verfügbaren Methoden weiter ein innerhalb dessen, was auf Geschäftsebene aktiviert ist.
</Info>

## Konfiguration von Zahlungsmethoden pro Checkout

Zusätzlich zu den Einstellungen auf Geschäftsebene können Sie einschränken, welche Methoden für einzelne Checkout-Sitzungen angezeigt werden, indem Sie `allowed_payment_method_types` verwenden:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Best Practices

<AccordionGroup>
<Accordion title="Match methods to your market">
Integrieren Sie regionale Zahlungsmethoden für Ihre Zielmärkte. iDEAL erfasst ~60% der Online-Zahlungen in den Niederlanden; UPI dominiert in Indien. Das Auslassen dieser Methoden verringert die Konversionsrate erheblich.
</Accordion>

<Accordion title="Always provide card fallbacks">
Auch wenn Sie spezifische Methoden anvisieren, integrieren Sie `credit` und `debit` als Fallbacks. Nicht alle Kunden haben Zugang zu jeder Zahlungsmethode.
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL-Methoden (Klarna, Afterpay) erfordern mindestens $50,01. Nehmen Sie sie nicht für Produkte mit geringem Wert auf — sie werden einfach nicht erscheinen, was in Ordnung ist.
</Accordion>

<Accordion title="Test across regions and devices">
Verwenden Sie den Testmodus, um die Verfügbarkeit von Zahlungsmethoden für verschiedene Kundenstandorte, Währungen und Gerätetypen zu überprüfen, bevor Sie live gehen.
</Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Überprüfen Sie diese Faktoren:**
1. Methode in `allowed_payment_method_types` enthalten?
2. Kundenstandort stimmt mit der unterstützten Region der Methode überein?
3. Transaktionswährung von der Methode unterstützt?
4. Transaktionsbetrag erfüllt Mindestanforderungen (z.B. $50,01 für BNPL)?
5. Für Abonnements: Methode unterstützt wiederkehrende Zahlungen?

**Lösung:** Entfernen Sie TEMPORÄR `allowed_payment_method_types`, um alle berechtigten Methoden anzuzeigen, und reduzieren Sie dann das Problem.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Mögliche Ursachen:**
- `allowed_payment_method_types` wird nicht korrekt übergeben
- Parameter falsch formatiert (muss ein Array von Strings sein)

**Lösung:** Protokollieren Sie Ihre API-Anforderungsnutzlast und überprüfen Sie die Parameterstruktur.
</Accordion>

<Accordion title="Regional method not available">
**Überprüfen:**
- Rechnungsadresse des Kunden stimmt mit Region der Methode überein
- Währung ist korrekt eingestellt (z.B. EUR für iDEAL)
- Adaptive Currency ist aktiviert, wenn der Kunde international ist

**Lösung:** Überprüfen Sie den Ländercode der Rechnungsadresse und die Währung in Ihrer API-Anforderung.
</Accordion>

<Accordion title="Indian payment method issues">
UPI- und Rupay-Abonnements haben einzigartige Anforderungen, einschließlich 48-stündiger Bearbeitungsverzögerungen und RBI-Mandatsbeschränkungen.

**Siehe:** <a href="/features/payment-methods/india">India Payment Methods</a> für vollständige Richtlinien.
</Accordion>
</AccordionGroup>
