## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## Deaktivieren von Zahlungsmethoden auf Geschäftsebene

Sie können bestimmte Zahlungsmethoden auf Geschäftsebene über Ihr Dashboard deaktivieren. Dies gilt für alle Checkout-Sitzungen Ihres Geschäfts, ohne dass eine Konfiguration pro Produkt oder Sitzung erforderlich ist.

<Steps>
<Step title="Navigate to Settings">
Gehen Sie im Dashboard von Dodo Payments zu **Settings > Payment Methods**.
</Step>

<Step title="Disable Payment Methods">
Deaktivieren Sie alle Zahlungsmethoden, die Sie Ihren Kunden nicht anbieten möchten.
</Step>
</Steps>

<Tip>
Verwenden Sie diese Option, um Zahlungsmethoden mit hohen Betrugsraten in Ihrer Region zu deaktivieren oder die Auswahl auf die Methoden zu beschränken, die Ihr Unternehmen operativ unterstützt.
</Tip>

<Info>
Einstellungen auf Geschäftsebene fungieren als globaler Filter. Einschränkungen pro Checkout über `allowed_payment_method_types` schränken die verfügbaren Methoden innerhalb der auf Geschäftsebene aktivierten Methoden weiter ein.
</Info>

## Konfiguration von Zahlungsmethoden pro Checkout

Zusätzlich zu den Einstellungen auf Geschäftsebene können Sie mit `allowed_payment_method_types` einschränken, welche Methoden für einzelne Checkout-Sitzungen angezeigt werden:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "pdt_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkouts \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "pdt_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Best Practices

<AccordionGroup>
<Accordion title="Match methods to your market">
Binden Sie regionale Zahlungsmethoden für Ihre Zielmärkte ein. iDEAL wickelt etwa 60 % der Onlinezahlungen in den Niederlanden ab; UPI dominiert in Indien. Das Weglassen dieser Methoden beeinträchtigt die Conversion erheblich.
</Accordion>

<Accordion title="Always provide card fallbacks">
Fügen Sie auch bei der Ausrichtung auf bestimmte Methoden `credit` und `debit` als Fallbacks hinzu. Nicht alle Kunden haben Zugriff auf jede Zahlungsmethode.
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL-Methoden haben anbieterspezifische Mindestbeträge: Für Klarna und Afterpay sind $50.01 erforderlich. Binden Sie sie nicht für Produkte außerhalb dieser Bereiche ein – sie werden einfach nicht angezeigt, was unproblematisch ist.
</Accordion>

<Accordion title="Test across regions and devices">
Verwenden Sie den Testmodus, um die Verfügbarkeit von Zahlungsmethoden für verschiedene Kundenstandorte, Währungen und Gerätetypen zu überprüfen, bevor Sie live gehen.
</Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Prüfen Sie diese Faktoren:**
1. Ist die Methode in `allowed_payment_method_types` enthalten?
2. Entspricht der Standort des Kunden der von der Methode unterstützten Region?
3. Wird die Transaktionswährung von der Methode unterstützt?
    4. Liegt der Transaktionsbetrag innerhalb des von der Methode unterstützten Bereichs (z. B. Mindestbetrag von $50.01 bei Klarna/Afterpay)?
5. Für Abonnements: Unterstützt die Methode wiederkehrende Zahlungen?

**Lösung:** Entfernen Sie `allowed_payment_method_types` vorübergehend, um alle geeigneten Methoden anzuzeigen, und grenzen Sie das Problem anschließend ein.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Mögliche Ursachen:**
- `allowed_payment_method_types` wird nicht korrekt übergeben
- Parameter ist falsch formatiert (muss ein Array von Strings sein)

**Lösung:** Protokollieren Sie den Payload Ihrer API-Anfrage und überprüfen Sie die Parameterstruktur.
</Accordion>

<Accordion title="Regional method not available">
**Prüfen Sie:**
- Die Rechnungsadresse des Kunden entspricht der Region der Methode
- Die Währung ist korrekt festgelegt (z. B. EUR für iDEAL)
- Adaptive Currency ist aktiviert, wenn der Kunde international ist

**Lösung:** Überprüfen Sie den Ländercode der Rechnungsadresse und die Währung in Ihrer API-Anfrage.
</Accordion>

<Accordion title="Indian payment method issues">
UPI- und Rupay-Abonnements haben besondere Anforderungen, darunter Verarbeitungsverzögerungen von 48 Stunden und RBI-Mandatslimits.

**Siehe:** <a href="/features/payment-methods/india">Zahlungsmethoden in Indien</a> für eine vollständige Anleitung.
</Accordion>
</AccordionGroup>
