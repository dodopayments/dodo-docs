Dodo Payments unterstützt eine Vielzahl von Zahlungsmethoden, um Ihnen zu helfen, Kunden weltweit zu bedienen. Aktivieren Sie neue Zahlungsmethoden sofort – keine zusätzlichen Verträge, Integrationen oder Händlerkonten erforderlich.

## Warum mehrere Zahlungsmethoden anbieten?

<CardGroup cols={3}>
<Card title="Boost Conversion" icon="chart-line">

</Card>

<Card title="One Platform" icon="layer-group">

</Card>

<Card title="Smart Routing" icon="route">

</Card>

## So funktioniert es

Zahlungsmethoden werden automatisch basierend auf Folgendem angezeigt:

- **Standort des Kunden** — Regionale Methoden wie iDEAL (Niederlande) oder UPI (Indien) erscheinen nur für Kunden in diesen Regionen
- **Transaktionswährung** — Zahlungsmethoden werden nach unterstützten Währungen gefiltert
- **Gerätetyp** — Apple Pay erscheint nur auf kompatiblen Apple-Geräten und -Browserversionen
- **Transaktionstyp** — Einige Methoden unterstützen keine Abonnements oder haben Mindestbeträge

<Info>
**Automatische Aktivierung:** Alle Zahlungsmethoden sind vorkonfiguriert und werden von Dodo Payments verwaltet. Es ist keine zusätzliche Einrichtung erforderlich – sie stehen zur Verfügung, sobald dein Konto verifiziert ist und der Live-Modus aktiviert wurde.
</Info>

## Konfigurieren von Zahlungsmethoden

Standardmäßig werden alle berechtigten Zahlungsmethoden automatisch angezeigt. Verwende `allowed_payment_method_types`, um einzuschränken, welche Methoden angezeigt werden:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Best Practices

<AccordionGroup>
<Accordion title="Match methods to your market">
Inklusive regionaler Zahlungsmethoden für Ihre Zielmärkte. iDEAL erfasst ~60 % der Online-Zahlungen in den Niederlanden; UPI dominiert in Indien. Das Weglassen dieser Methoden schwächt die Konversion erheblich.
</Accordion>

<Accordion title="Always provide card fallbacks">
Selbst wenn bestimmte Methoden gezielt werden, immer `credit` und `debit` als Fallbacks einbeziehen. Nicht alle Kunden haben Zugang zu jeder Zahlungsmethode.
</Accordion>

<Accordion title="Consider transaction minimums">
BNPL-Methoden (Klarna, Afterpay) erfordern 50,01 $ Mindestbetrag. Nehmen Sie sie nicht für Produkte mit geringem Wert auf – sie werden einfach nicht angezeigt, was in Ordnung ist.
</Accordion>

<Accordion title="Test across regions and devices">
Testmodus verwenden, um die Verfügbarkeit der Zahlungsmethode für verschiedene Kundenstandorte, Währungen und Gerätetypen zu überprüfen, bevor sie live geschaltet werden.
</Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Überprüfen Sie folgende Faktoren:**
1. Methode in `allowed_payment_method_types` enthalten?
2. Kundenstandort entspricht der unterstützten Region der Methode?
3. Transaktionswährung wird von Methode unterstützt?
4. Transaktionsbetrag erfüllt Mindestanforderung (z. B. $50.01 für BNPL)?
5. Für Abonnements: Methode unterstützt wiederkehrende Zahlungen?

**Lösung:** Entfernen Sie `allowed_payment_method_types` vorübergehend, um alle berechtigten Methoden zu sehen, und grenzen Sie das Problem dann ein.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Mögliche Ursachen:**
- `allowed_payment_method_types` wird nicht korrekt übermittelt
- Parameter falsch formatiert (muss ein Array von Strings sein)

**Lösung:** Protokollieren Sie Ihre API-Anforderungsnutzlast und überprüfen Sie die Parameterstruktur.
</Accordion>

<Accordion title="Regional method not available">
**Überprüfen:**
- Kundenrechnungsadresse stimmt mit der Region der Methode überein
- Währung ist korrekt eingestellt (z. B. EUR für iDEAL)
- Adaptive Currency ist aktiviert, falls der Kunde international ist

**Lösung:** Überprüfen Sie das Ländercode und die Währung der Rechnungsadresse in Ihrer API-Anfrage.
</Accordion>

<Accordion title="Indian payment method issues">
UPI- und Rupay-Abonnements haben einzigartige Anforderungen, einschließlich 48-Stunden-Verarbeitungsverzögerungen und RBI-Mandatsbeschränkungen.

**Siehe:** <a href="/features/payment-methods/india">Indien Zahlungsmethoden</a> für vollständige Anleitung.
</Accordion>
</AccordionGroup>
