## Was ist lokalisierte Preisgestaltung?

Jedes Produkt hat einen Basispreis in einer Basiswährung. Mit der lokalisierten Preisgestaltung können Sie diesen Basispreis durch **feste Preise, die Sie pro Währung oder pro Land festlegen**, überschreiben. Aktivieren Sie es, indem Sie eine `pricing_mode` für das Produkt festlegen und dann eine Regel pro Markt anhängen.

Sie ist einer von mehreren unabhängigen Stellhebeln für die internationale Preisgestaltung, wobei jeder ein anderes Problem löst:

| Mechanismus | Was er bewirkt | Die Zahl, die der Kunde sieht |
| :--- | :--- | :--- |
| **Lokalisierte Preisgestaltung** | Ein fester Preis, den Sie pro Währung oder Land festlegen | Genau der von Ihnen festgelegte Betrag |
| [**Adaptive Currency**](/features/adaptive-currency) | Wandelt Ihren Basispreis automatisch zu aktuellen FX-Kursen um | Zum aktuellen Wechselkurs umgerechneter Basispreis |
| [**Purchasing Power Parity**](/features/purchasing-power-parity) | Berechnet automatisch je nach Land einen Anteil Ihres Preises | Ein Prozentsatz des Basispreises |
| [**Charm Pricing**](/features/charm-pricing) | Rundet den umgerechneten Preis automatisch auf ein passendes Endergebnis | Eine aufgeräumte Zahl wie 49.99 |
| [**Rabattcodes**](/features/discount-codes) | Eine prozentuale Reduzierung des Basispreises | Basispreis abzüglich des Rabatts |

<Info>
Lokalisierte Preisgestaltung und Adaptive Currency arbeiten zusammen. Wenn keine lokalisierte Regel übereinstimmt, fällt das Produkt auf seinen Basispreis zurück — bei Kunden, die sich bereits in Ihrer Basiswährung befinden, direkt abgerechnet oder durch Adaptive Currency umgerechnet.
</Info>

## Kernkonzepte

- **Preismodi** — Ein Produkt befindet sich zu jedem Zeitpunkt genau in einem Modus, der durch seinen `pricing_mode` festgelegt wird:
  - `by_currency`: ein Preis pro Währung, unabhängig vom Land. Jeder, der in EUR bezahlt, sieht €9.99.
  - `by_country`: ein länderspezifischer Preis (₹999 in Indien), auch wenn mehrere Länder dieselbe Währung verwenden.
- **Feste Beträge in der kleinsten Einheit** — Das `amount` einer Regel ist eine Ganzzahl in der kleinsten Einheit der Währung, genauso wie überall sonst in der API: `99900` entspricht ₹999.00, `999` entspricht €9.99. Es handelt sich um einen von Ihnen festgelegten Preis, niemals um einen umgerechneten Wert.
- **Eine passende Regel hat Vorrang vor der automatischen Preisgestaltung** — Wenn eine lokalisierte Regel auf eine Position zutrifft, werden [Purchasing Power Parity](/features/purchasing-power-parity) und [Charm Pricing](/features/charm-pricing) für diese Position übersprungen. Der Kunde zahlt den von Ihnen festgelegten Betrag unverändert.
- **Wenn keine Regel zutrifft** — Das Produkt behält sein bestehendes Verhalten bei: Kunden in Ihrer Basiswährung zahlen den Basispreis direkt; alle anderen erhalten den über [Adaptive Currency](/features/adaptive-currency) umgerechneten Preis.
- **Gebühren sind bei einer passenden Regel inklusive** — Der Kunde zahlt **genau** den von Ihnen festgelegten Betrag. Die FX-Gebühr von [Adaptive Currency](/features/adaptive-currency#choose-who-bears-the-fee) wird von Ihnen übernommen (für diese Transaktion als gebühreninklusive behandelt), statt zusätzlich berechnet zu werden. Dadurch entspricht Ihr angegebener lokaler Preis immer dem berechneten Preis.

## Verwaltung über die API

Lokalisierte Preisgestaltung ist vollständig über die API verfügbar. Setzen Sie zuerst den Preisgestaltungsmodus des Produkts und fügen Sie dann Regeln an.

### Setzen Sie den Preisgestaltungsmodus

Setzen Sie `pricing_mode`, wenn Sie das Produkt erstellen (oder ein bestehendes aktualisieren). `null` bedeutet nur Basis, das bestehende Verhalten.

<CodeGroup>

```typescript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode',
});

const product = await client.products.update('pdt_premium_plan', {
  pricing_mode: 'by_country',
});
```

```python theme={null}
import os
from dodopayments import DodoPayments

client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
    environment="test_mode",
)

product = client.products.update(
    "pdt_premium_plan",
    pricing_mode="by_country",
)
```

```go theme={null}
package main

import (
	"context"
	"os"

	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func main() {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
	)

	_, err := client.Products.Update(
		context.TODO(),
		"pdt_premium_plan",
		dodopayments.ProductUpdateParams{
			PricingMode: dodopayments.F(dodopayments.PricingModeByCountry),
		},
	)
	if err != nil {
		panic(err)
	}
}
```

</CodeGroup>

### Fügen Sie einen lokalisierten Preis hinzu

Fügen Sie dem Produkt eine Regel hinzu. Im `by_country` Modus ist `country_code` erforderlich; im `by_currency` Modus muss er weggelassen werden.

<CodeGroup>

```typescript theme={null}
// ₹999.00 for customers in India
const localizedPrice = await client.products.localizedPrices.create('pdt_premium_plan', {
  currency: 'INR',
  country_code: 'IN',
  amount: 99900,
});
```

```python theme={null}
# ₹999.00 for customers in India
localized_price = client.products.localized_prices.create(
    "pdt_premium_plan",
    currency="INR",
    country_code="IN",
    amount=99900,
)
```

```go theme={null}
// ₹999.00 for customers in India
localizedPrice, err := client.Products.LocalizedPrices.New(
	context.TODO(),
	"pdt_premium_plan",
	dodopayments.ProductLocalizedPriceNewParams{
		Currency:    dodopayments.F(dodopayments.CurrencyInr),
		CountryCode: dodopayments.F(dodopayments.CountryCodeIn),
		Amount:      dodopayments.F(int64(99900)),
	},
)
```

</CodeGroup>

Für ein `by_currency` Produkt, weglassen `country_code`. Zum Beispiel, ein fester `€9.99` für alle, die in EUR bezahlen (`currency: 'EUR'`, `amount: 999`).

### Auflisten, aktualisieren und archivieren

Sie können nur das `amount` einer Regel aktualisieren; Währung und Land sind einmal erstellt festgelegt. Archivierung ist ein idempotentes Soft-Delete, damit die Regel nicht mehr übereinstimmt, aber in Ihrem Verlauf bleibt.

<CodeGroup>

```typescript theme={null}
// List all active rules on a product
const rules = await client.products.localizedPrices.list('pdt_premium_plan');

// Change the amount (e.g. end a promo)
await client.products.localizedPrices.update('lcp_india_price', {
  product_id: 'pdt_premium_plan',
  amount: 119900,
});

// Archive a rule
await client.products.localizedPrices.archive('lcp_india_price', {
  product_id: 'pdt_premium_plan',
});
```

```python theme={null}
# List all active rules on a product
rules = client.products.localized_prices.list("pdt_premium_plan")

# Change the amount (e.g. end a promo)
client.products.localized_prices.update(

    product_id="pdt_premium_plan",
    amount=119900,

# Archive a rule
client.products.localized_prices.archive(
    "lcp_india_price",
    product_id="pdt_premium_plan",
)
```

## Anwendung im Checkout

Lokalisierte Preisgestaltung wird pro Warenkorbposition gelöst und nur für Produkte, die ein `pricing_mode` gesetzt haben. Dodo Payments liest zwei Signale aus der Anfrage: das **Abrechnungsland** des Kunden und eine optionale **`billing_currency`** (wenn nicht angegeben, wird eine Währung aus dem Abrechnungsland abgeleitet).

- **Nach Land**: sucht nach einer Regel, die mit dem Abrechnungsland übereinstimmt. Wenn dies der Fall ist, wird beim Kunden die Betragsregel in der Währung der Regel berechnet.
- **Nach Währung**: sucht nach einer Regel, die mit der Währung des Kunden übereinstimmt (die `billing_currency`, oder die Währung, die aus ihrem Land abgeleitet wird). Wenn dies der Fall ist, wird der Kunde in dieser Währung zum Regelbetrag belastet.
- **Keine Übereinstimmung oder kein `pricing_mode`**: Der Basispreis gilt, der direkt berechnet wird, wenn die Währung des Kunden der Basiswährung entspricht, andernfalls umgerechnet durch [Adaptive Currency](/features/adaptive-currency).

Jede Warenkorbposition wird für sich gelöst, sodass Sie ein Produkt lokalisieren und andere beim Basispreis im selben Checkout belassen können. Wenn eine Position mit einer lokalisierten Regel übereinstimmt, wird die gesamte Transaktion zwangsweise gebühreninklusive durchgeführt (siehe [Kernkonzepte](#core-concepts)).

## Anwendung bei Änderungen des Abonnementplans

Die lokalisierten Preise folgen Ihren Abonnenten, wenn sie den Plan wechseln. Wenn ein bestehendes Abonnement den [Plan ändert](/features/subscription#subscription-plan-changes) und zu einem Produkt wechselt, das über einen `pricing_mode` verfügt, wird der Preis des neuen Plans anhand derselben Regeln wie beim Checkout ermittelt. Dabei werden das Abrechnungsland und die Währung verwendet, die bereits im Abonnement festgelegt sind:

- **Nach Land**: Es gilt eine Regel, die dem Abrechnungsland des Abonnements entspricht. Wenn sich die Währung der Regel von der Abrechnungswährung des Abonnements unterscheidet, wird der Betrag der Regel zum aktuellen FX-Kurs umgerechnet — die Regel wird angewendet und nicht übersprungen.
- **Nach Währung**: Es gilt eine Regel, die der Währung entspricht, in der der Kunde abgerechnet wird, und dem Kunden wird exakt der Betrag der Regel berechnet.
- **Keine Übereinstimmung oder kein `pricing_mode`**: Es gilt der Grundpreis des neuen Plans, der bei Bedarf über [Adaptive Currency](/features/adaptive-currency) umgerechnet wird — derselbe Fallback wie beim Checkout.

Dies gilt überall dort, wo eine Planänderung ausgelöst werden kann: über die [Change Plan API](/api-reference/subscriptions/change-plan), die selbst durchführbaren Planänderungen im [Customer Portal](/features/customer-portal) und für Änderungen, die zum Ende des Abrechnungszeitraums geplant sind.

- **Vorschauen sind exakt.** [Preview Change Plan](/api-reference/subscriptions/preview-change-plan) gibt denselben lokalisierten Betrag zurück, der bei der tatsächlichen Änderung berechnet wird.
- **Verlängerungen behalten den lokalisierten Preis bei.** Nach der Änderung wird der neue Plan zu seinem lokalisierten Betrag verlängert — und bleibt gebühreninklusiv — genau wie ein Abonnement, das zu diesem Preis erstellt wurde.
- **Proration verwendet tatsächliche Beträge.** Bei einem Upgrade basiert das Guthaben für die ungenutzte Zeit auf dem Betrag, den der Kunde tatsächlich für den alten Plan bezahlt hat, während der neue Plan anhand seiner lokalisierten Regel bepreist wird.
- **Geplante Änderungen legen den Preis zum Zeitpunkt der Planung fest.** Bei einer für das Ende des Abrechnungszeitraums geplanten Änderung wird der zum Zeitpunkt der Planung berechnete Betrag berechnet, selbst wenn Sie die Regel zwischenzeitlich bearbeiten.
- **Die Abrechnungswährung ändert sich nie.** Eine Planänderung wechselt niemals die Währung, in der ein Abonnement abgerechnet wird; eine Regel in einer anderen Währung wird per FX in diese Währung umgerechnet.
- **Add-ons werden nicht lokalisiert.** Add-on-Preise im neuen Plan verwenden immer ihre Grundpreise.

## Wichtige Verhaltensweisen

| Verhalten | Details |
| :--- | :--- |
| **Beträge vor Steuern** | Ein lokalisierter Betrag ist der Preis *vor* Steuern. Bei Produkten ohne enthaltene Steuern werden diese beim Checkout zusätzlich berechnet, sodass der lokalisierte Betrag nicht dem Endbetrag entspricht. Siehe [Tax-Inclusive Pricing](/features/tax-inclusive-pricing). |
| **Nicht für Pay What You Want** | Lokalisierte Regeln gelten nie für [Pay What You Want](/features/pay-what-you-want)-Produkte, bei denen der Kunde den Betrag auswählt. |
| **Nach Währung unterscheidet sich vom Grundpreis** | Eine `by_currency`-Regel muss eine andere Währung als die Basiswährung des Produkts verwenden. |
| **Eine Regel pro Markt** | Ein Produkt kann höchstens eine aktive Regel pro Währung (nach Währung) oder pro Land (nach Land) haben. |
| **Alle Produkttypen** | Gilt für Einmalzahlungen, Abonnements und nutzungsbasierte Produkte — auch wenn ein bestehender Abonnent [den Plan ändert](#how-it-applies-on-subscription-plan-changes). |

<Info>
Änderungen an lokalisierten Regeln lösen keine eigenen Webhooks aus. Der ermittelte Betrag erscheint in der daraus resultierenden Zahlung oder dem Abonnement genau wie jeder andere Preis.
</Info>

## Best Practices

- **Legen Sie einen sinnvollen Basispreis fest.** Er dient als Fallback für jeden Markt ohne Regel und wird über Adaptive Currency umgerechnet.
- **Geben Sie übersichtliche Zahlen ein.** Der Zweck eines festen Betrags ist ein aufgeräumter Preis wie ₹999, €9.99 oder ¥1000, kein FX-Ergebnis. Informationen zum automatischen Runden in jeder Währung finden Sie unter [Charm Pricing](/features/charm-pricing).
- **Wählen Sie den passenden Modus.** Verwenden Sie `by_country` für eine an der Kaufkraft orientierte Preisgestaltung; verwenden Sie `by_currency`, wenn ein Preis pro Währungszone ausreicht.
- **Archivieren Sie Regeln für Aktionen, statt sie neu zu erstellen.** Durch das Archivieren einer Regel wird der Markt auf die Basis-/Adaptive-Preisgestaltung zurückgesetzt, während der Verlauf erhalten bleibt. Erstellen Sie später bei Bedarf eine neue Regel oder legen Sie den Preis neu fest.
- **Beachten Sie die Steuerzeile, bevor Sie einen Gesamtbetrag bewerben.** Bei Produkten ohne enthaltene Steuern zahlt der Kunde den lokalisierten Betrag *zuzüglich* Steuern. Geben Sie ihn daher in Anzeigen nicht als Endpreis an.
