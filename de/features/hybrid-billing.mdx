## Was ist hybride Abrechnung?

Hybride Abrechnung kombiniert mehrere Preisd imensionen zu einem einzigen Produktangebot. Statt zwischen Festpreis-Abonnements ODER nutzungsbasierter Preisgestaltung zu wählen, verwenden Sie beides gemeinsam.

### Warum hybride Abrechnung nutzen?

| Geschäftsziel | Hybride Lösung |
|--------------|-----------------|
| Planbare Einnahmen + Wachstumspotenzial | Basisabonnement + Mehrverbrauch |
| Skalierbare Team-Preisgestaltung | Pro Sitz + Feature-Add-ons |
| Kunden gewinnen, später erweitern | Niedrige Grundgebühr + Verbrauchsgebühren |
| Flexibilität für Unternehmen | Vereinbarte Ausgaben + On-Demand-Gebühren |
| Faire Preise bei variabler Nutzung | Inklusivkontingent + nutzungsabhängige Zahlung |

### Gängige hybride Muster

| Modell | Beschreibung | Beispiel | Native Unterstützung |
|-------|-------------|---------|----------------|
| **1. Abonnement + Nutzung** | Grundgebühr + Verbrauchsgebühren | \$49/Monat + \$0.01/API-Aufruf nach 10K kostenlosen Aufrufen | ✅ Vollständig |
| **2. Abonnement + Sitze** | Plattformgebühr + Gebühren pro Benutzer | \$99/Monat + \$15/Sitz | ✅ Vollständig |
| **3. Abonnement + Feature-Add-ons** | Kernplan + optionale Upgrades | \$29/Monat + \$19/Monat Analytics + \$9/Monat API-Zugriff | ✅ Vollständig |
| **4. Sitze + Nutzung** | Gebühr pro Benutzer + verbrauchsabhängiger Mehrverbrauch | \$10/Benutzer/Monat + \$0.05/GB nach 5 GB/Benutzer | ⚠️ Workaround |
| **5. Abonnement + Sitze + Nutzung** | Plattform + Benutzer + Verbrauch (dreifach hybrid) | \$199/Monat + \$20/Sitz + Mehrverbrauch | ⚠️ Workaround |
| **6. Gestaffelte Basis + Mehrverbrauch** | Verschiedene Stufen mit unterschiedlichen Kontingenten | Starter (5K Aufrufe) vs. Pro (50K Aufrufe) + Mehrverbrauch | ✅ Vollständig |
| **7. Abonnement + On-Demand-Gebühren** | Wiederkehrende Gebühr + variable manuelle Gebühren | \$99/Monat Retainer + stundenbasierte Abrechnung für Leistungen | ✅ Vollständig |

## Hybrides Modell 1: Abonnement + Nutzung

Das häufigste hybride Modell. Kunden zahlen eine Grundgebühr für das Abonnement sowie Gebühren für den Verbrauch, der die enthaltenen Kontingente überschreitet.

### Funktionsweise

**Pro-Plan: $49/Monat**

- **Enthalten**: 10.000 API-Aufrufe/Monat
- **Mehrverbrauch**: $0.005 pro Aufruf nach 10.000

**Beispielrechnung** (der Kunde verwendet diesen Monat 25.000 Aufrufe):
- Basisabonnement: $49.00
- Mehrverbrauch: (25.000 - 10.000) × $0.005 = $75.00
- **Gesamt: $124.00**

### Anwendungsfälle

- **API-Plattformen**: Basiszugriff + Gebühren pro Anfrage
- **KI/ML-Dienste**: Abonnement + Token-/Generierungsnutzung
- **Speicherdienste**: Basistarif + Mehrverbrauch pro GB
- **Kommunikationsplattformen**: Basis + Gebühren pro Nachricht/Minute

### Implementierung

<Steps>
<Step title="Create Usage Meter">
Richten Sie einen Meter ein, um die abrechenbare Nutzungsdimension zu erfassen.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
Erstellen Sie ein Abonnementprodukt und verknüpfen Sie den Usage Meter mit der Preisgestaltung.

```bash
Dashboard: Create Product → Subscription
Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
Der Usage Meter wird direkt mit dem Abonnementprodukt verknüpft. Nutzungsgebühren werden automatisch berechnet und zur Abonnementrechnung hinzugefügt.
</Info>
</Step>

<Step title="Create Checkout Session">
Erstellen Sie eine Checkout-Session mit Ihrem Abonnementprodukt.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_pro_plan', quantity: 1 }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Send Usage Events">
Erfassen Sie die Nutzung während des Abrechnungszeitraums.

```typescript
await fetch('https://test.dodopayments.com/events/ingest', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    events: [{
      event_id: `call_${Date.now()}`,
      customer_id: 'cus_123',
      event_name: 'api.call',
      timestamp: new Date().toISOString(),
      metadata: { endpoint: '/v1/generate' }
    }]
  })
});
```

</Step>
</Steps>

### Preisvarianten

<Tabs>
<Tab title="Included Allowance">
Das kostenlose Kontingent deckt die im Basisabonnement enthaltene Nutzung ab.

**Pro-Plan: $49/Monat**
- Enthalten: 10.000 API-Aufrufe
- Mehrverbrauch: $0.005/Aufruf nach 10.000
- Der Kunde verwendet 8.000 → Zahlt $49 (kein Mehrverbrauch)
</Tab>

<Tab title="Zero Base + Pure Usage">
Keine Grundgebühr; jede Einheit ist ab der ersten Nutzung abrechenbar.

**Pay-As-You-Go: $0/Monat Grundgebühr**
- Enthalten: 0 API-Aufrufe
- Nutzung: $0.01/Aufruf ab dem ersten Aufruf
- Der Kunde verwendet 5.000 → Zahlt $50
</Tab>

<Tab title="Tiered Allowances">
Verschiedene Stufen enthalten unterschiedliche Kontingente.

- **Starter**: $19/Monat (1.000 Aufrufe enthalten)
- **Pro**: $49/Monat (10.000 Aufrufe enthalten)
- **Enterprise**: $199/Monat (100.000 Aufrufe enthalten)
- Alle Stufen: $0.005/Aufruf Mehrverbrauch
</Tab>
</Tabs>

## Hybrides Modell 2: Abonnement + Sitze

Plattformgebühr plus Gebühren pro Benutzer. Ideal für Tools zur Teamzusammenarbeit und B2B-SaaS.

### Funktionsweise

**Team-Plan: $99/Monat + $15/Sitz**

- **Plattformgrundgebühr**: $99/Monat (inklusive 3 Sitze)
- **Zusätzliche Sitze**: $15/Sitz/Monat

**Beispielrechnung** (Team mit 12 Benutzern):
- Plattformgebühr: $99.00
- Zusätzliche Sitze: (12 - 3) × $15 = $135.00
- **Gesamt: $234.00/Monat**

### Anwendungsfälle

- **Tools zur Zusammenarbeit**: Arbeitsbereichsgebühr + pro Mitglied
- **CRM-Systeme**: Plattformlizenz + pro Vertriebsmitarbeiter
- **Projektmanagement**: Team-Plan + pro Mitwirkendem
- **Entwicklertools**: Organisationsgebühr + pro Entwickler

### Implementierung

<Steps>
<Step title="Create Seat Add-on">
Erstellen Sie ein Add-on für zusätzliche Sitze.

```bash
Dashboard: Products → Add-ons → Create Add-on
Name: "Additional Seat"
Price: $15/month
Description: "Add another team member"
```

</Step>

<Step title="Create Base Subscription">
Erstellen Sie das Abonnementprodukt mit Plattformgebühr und verknüpfen Sie das Add-on.

```bash
Dashboard: Create Product → Subscription
Name: "Team Plan"
Price: $99/month
Description: "Includes 3 team members"

Then in Add-ons section:
- Attach: "Additional Seat" add-on
```

</Step>

<Step title="Create Checkout with Seats">
Geben Sie die Sitzanzahl während des Checkouts an.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{
    product_id: 'prod_team_plan',
    quantity: 1,
    addons: [{
      addon_id: 'addon_seat',
      quantity: 9  // 9 extra seats (12 total with 3 included)
    }]
  }],
  customer: { email: 'admin@company.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Adjust Seats as Needed">
Fügen Sie Sitze zu bestehenden Abonnements hinzu oder entfernen Sie sie.

```typescript
// Add 5 more seats
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_team_plan',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  addons: [{
    addon_id: 'addon_seat',
    quantity: 14  // New total: 14 extra seats
  }]
});
```

</Step>
</Steps>

### Preisvarianten

<Tabs>
<Tab title="Included Seats">
Der Basistarif enthält einige Sitze; zusätzliche Sitze werden berechnet.

**Team-Plan: $99/Monat**
- Enthalten: 5 Sitze
- Zusätzliche Sitze: $15/Sitz/Monat
- 20 Benutzer = \$99 + (15 × \$15) = \$324/Monat
</Tab>

<Tab title="Pure Per-Seat">
Keine Plattformgebühr, nur Gebühren pro Benutzer.

**Pro Benutzer: $25/Benutzer/Monat**
- Keine Plattformgebühr
- 5 Benutzer = $125/Monat
- 50 Benutzer = $1,250/Monat

Implementierung: Setzen Sie den Abonnementgrundpreis auf $0 und verwenden Sie ausschließlich das Sitz-Add-on.
</Tab>

<Tab title="Tiered Per-Seat">
Der Preis pro Sitz sinkt in höheren Stufen.

- **Starter**: $20/Sitz (1–10 Sitze)
- **Growth**: $15/Sitz (11–50 Sitze)
- **Enterprise**: $10/Sitz (51+ Sitze)

Implementierung: Erstellen Sie für jede Stufe separate Abonnementprodukte mit unterschiedlichen Add-on-Preisen.
</Tab>
</Tabs>

## Hybrides Modell 3: Abonnement + Feature-Add-ons

Kernabonnement mit optionalen Funktionserweiterungen, die Kunden hinzufügen können.

### Funktionsweise

**Kernplan: $29/Monat**

**Optionale Add-ons:**
- Erweiterte Analytics: +$19/Monat
- API-Zugriff: +$9/Monat
- Priorisierter Support: +$29/Monat
- White-Label: +$49/Monat

**Beispielrechnung** (der Kunde wählt Core + Analytics + API-Zugriff):
- Kernplan: $29.00
- Analytics: $19.00
- API-Zugriff: $9.00
- **Gesamt: $57.00/Monat**

### Anwendungsfälle

- **SaaS-Plattformen**: Kernfunktionen + Premium-Module
- **Marketingtools**: Basistool + Integrationen
- **Analytics-Produkte**: Dashboard + erweiterte Berichte
- **Sicherheitssoftware**: Basisschutz + erweiterte Funktionen

### Implementierung

<Steps>
<Step title="Create Feature Add-ons">
Erstellen Sie für jede optionale Funktion ein Add-on.

```bash
# Add-on 1: Advanced Analytics
Dashboard: Products → Add-ons → Create Add-on
Name: "Advanced Analytics"
Price: $19/month

# Add-on 2: API Access
Name: "API Access"
Price: $9/month

# Add-on 3: Priority Support
Name: "Priority Support"
Price: $29/month

# Add-on 4: White-label
Name: "White-label"
Price: $49/month
```

</Step>

<Step title="Create Core Subscription">
Definieren Sie Ihr Basisabonnement und verknüpfen Sie alle Feature-Add-ons.

```bash
Dashboard: Create Product → Subscription
Name: "Core Plan"
Price: $29/month

Then in Add-ons section:
- Attach all feature add-ons
```

</Step>

<Step title="Let Customers Choose">
Führen Sie den Checkout mit den ausgewählten Funktionen durch.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{
    product_id: 'prod_core_plan',
    quantity: 1,
    addons: [
      { addon_id: 'addon_analytics', quantity: 1 },
      { addon_id: 'addon_api_access', quantity: 1 }
      // Customer didn't select support or white-label
    ]
  }],
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Add Features Later">
Kunden können Funktionen zu bestehenden Abonnements hinzufügen.

```typescript
// Customer wants to add Priority Support
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_core_plan',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  addons: [
    { addon_id: 'addon_analytics', quantity: 1 },
    { addon_id: 'addon_api_access', quantity: 1 },
    { addon_id: 'addon_priority_support', quantity: 1 }  // New!
  ]
});
```

</Step>
</Steps>

## Hybrides Modell 4: Sitze + Nutzung

Gebühr pro Benutzer kombiniert mit verbrauchsabhängigen Gebühren. Jeder Benutzer erhält ein Kontingent.

<Warning>
**Einschränkung**: Dodo Payments unterstützt derzeit nicht die gleichzeitige Verknüpfung von Usage Meters und Add-ons mit demselben Abonnementprodukt. Dieses Modell erfordert einen Workaround mit Logik auf Anwendungsebene.
</Warning>

<Info>
**Demnächst verfügbar**: Native Unterstützung für hybride Abrechnung mit Sitzen + Nutzung steht auf unserer Roadmap. Damit können Sie sowohl Usage Meters als auch Sitz-Add-ons mit demselben Abonnementprodukt verknüpfen.
</Info>

### Funktionsweise

**Team Analytics: $20/Benutzer/Monat**

**Jeder Benutzer umfasst:**
- 5 GB Datenverarbeitung/Monat
- Mehrverbrauch: $2/GB nach dem Kontingent

**Beispielrechnung** (Team mit 10 Benutzern und insgesamt 80 GB Nutzung):
- Sitzgebühren: 10 × $20 = $200.00
- Enthaltene Daten: 10 × 5 GB = 50 GB
- Mehrverbrauch: (80 - 50) × $2 = $60.00
- **Gesamt: $260.00/Monat**

### Anwendungsfälle

- **Analytics-Plattformen**: Pro Analyst + Datenverarbeitung
- **Designtools**: Pro Designer + Speicher/Exporte
- **Entwicklungsumgebungen**: Pro Entwickler + Compute-Stunden
- **Kommunikationstools**: Pro Benutzer + Nachrichten-/Anrufvolumen

### Implementierungsoptionen

Da Sie nicht gleichzeitig Usage Meters und Add-ons mit demselben Abonnement verknüpfen können, wählen Sie einen der folgenden Ansätze:

<Tabs>
<Tab title="Option A: Usage Product + App-Managed Seats">
Verwenden Sie ein nutzungsbasiertes Abonnement und verwalten Sie die Sitzabrechnung in Ihrer Anwendung.

<Steps>
<Step title="Create Usage Meter">

```bash
Dashboard: Meters → Create Meter
Event Name: "data.processed"
Aggregation: Sum
Property: "bytes"
```

</Step>

<Step title="Create Usage-Based Subscription">

```bash
Dashboard: Create Product → Subscription
Name: "Team Analytics"
Base Price: $0/month

Attach usage pricing:
- Meter: data.processed
- Price per unit: $2/GB
- Free threshold: 0 (managed by your app)
```

</Step>

<Step title="Manage Seats in Your Application">
Erfassen Sie die Sitzanzahl und berechnen Sie die Sitzgebühren separat.

```typescript
// Your application tracks seats and calculates total cost
async function calculateMonthlyBill(customerId: string) {
  const seatCount = await getSeatCount(customerId);
  const seatFee = seatCount * 20; // $20/seat

  // Usage is billed by Dodo automatically
  // You invoice/charge seat fees separately or include in base price

  // Alternatively, adjust base subscription price when seats change
  const totalBasePrice = seatCount * 2000; // $20/seat in cents
  await client.subscriptions.update('sub_123', {
    // Update subscription to reflect seat-based pricing
  });
}
```

</Step>

<Step title="Calculate Dynamic Free Threshold">
Passen Sie die enthaltene Nutzung anhand der Sitzanzahl an.

```typescript
// When checking usage, apply per-seat allowance
async function checkUsageOverage(customerId: string) {
  const seatCount = await getSeatCount(customerId);
  const includedGB = seatCount * 5; // 5 GB per user

  const currentUsage = await getUsageFromDodo(customerId);
  const overage = Math.max(0, currentUsage - includedGB);

  // Overage is billed by Dodo at $2/GB
  return { included: includedGB, used: currentUsage, overage };
}
```

</Step>
</Steps>
</Tab>

<Tab title="Option B: Seat Add-on + On-Demand Usage Charges">
Verwenden Sie Sitz-Add-ons und berechnen Sie die Nutzung manuell über On-Demand-Gebühren.

<Steps>

```bash

```

</Step>

<Step title="Create Subscription with Add-on">

```bash

- "Team Member" add-on
```

<Step title="Track Usage in Your Application">

<Step title="Charge Usage at End of Cycle">
Berechnen und berechnen Sie Mehrverbrauch manuell.

```typescript
async function billUsageOverage(subscriptionId: string) {
  const subscription = await getSubscription(subscriptionId);
  const seatCount = subscription.addons.find(a => a.id === 'addon_seat')?.quantity || 0;

  const includedGB = seatCount * 5;
  const usedGB = await calculatePeriodUsage(subscription.customer_id);
  const overageGB = Math.max(0, usedGB - includedGB);

  if (overageGB > 0) {
    const overageCharge = overageGB * 200; // $2/GB in cents
    await client.subscriptions.charge(subscriptionId, {
      product_price: overageCharge,
      product_description: `Data overage: ${overageGB} GB × $2/GB`
    });
  }
}
```

</Step>
</Steps>
</Tab>
</Tabs>

</Info>

## Hybrides Modell 5: Abonnement + Sitze + Nutzung (dreifach hybrid)

Das umfassendste Modell: Plattformgebühr + pro Benutzer + Verbrauch.

<Warning>
**Einschränkung**: Dodo Payments unterstützt derzeit nicht die gleichzeitige Verknüpfung von Usage Meters und Add-ons mit demselben Abonnementprodukt. Dieses Modell erfordert einen Workaround.
</Warning>

<Info>
**Demnächst verfügbar**: Native Unterstützung für die dreifach hybride Abrechnung (Basis + Sitze + Nutzung) steht auf unserer Roadmap. Damit können Sie sowohl Usage Meters als auch Sitz-Add-ons mit demselben Abonnementprodukt verknüpfen.
</Info>

### Funktionsweise

**Enterprise-Plattform**

- **Plattformgebühr**: $199/Monat
- **Pro Sitz**: $25/Benutzer/Monat
- **Nutzung**: $0.10/1.000 API-Aufrufe (50K enthalten)

**Beispielrechnung** (Unternehmen mit 20 Benutzern und 150.000 API-Aufrufen):
- Plattform: $199.00
- Sitze: 20 × $25 = $500.00
- Nutzung: (150K - 50K) × \$0.10/1K = \$10.00
- **Gesamt: $709.00/Monat**

### Anwendungsfälle

- **Enterprise-SaaS**: Plattform + Team + Verbrauch
- **Datenplattformen**: Arbeitsbereich + Analysten + Abfragen
- **Integrationsplattformen**: Hub + Konnektoren + Transaktionen
- **KI-Plattformen**: Arbeitsbereich + Entwickler + Inferenz

### Implementierungsoptionen

Wählen Sie einen der folgenden Ansätze zur Implementierung der dreifach hybriden Abrechnung:

<Tabs>

## Hybrides Modell 7: Abonnement + On-Demand-Gebühren

Wiederkehrendes Abonnement plus variable manuelle Gebühren für Leistungen oder Mehrverbrauch.

### Funktionsweise

**Retainer-Plan: $199/Monat**

**Enthalten:**
- Plattformzugriff
- 5 Beratungsstunden/Monat
- E-Mail-Support

**On-Demand-Gebühren (nach Bedarf):**
- Zusätzliche Beratung: $150/Stunde
- Individuelle Entwicklung: $200/Stunde
- Notfall-Support: $100/Vorfall

**Beispielrechnung** (diesen Monat):
- Retainer: $199.00
- 3 zusätzliche Beratungsstunden: $450.00
- 1 Notfall-Supportleistung: $100.00
- **Gesamt: $749.00**

### Anwendungsfälle

- **Beratungsleistungen**: Retainer + stundenbasierte Abrechnung
- **Managed Services**: Grundgebühr + Gebühren pro Vorfall
- **Agenturleistungen**: Monatsgebühr + Projektgebühren
- **Supportpläne**: SLA-Gebühr + pro Ticket oder Stunde

</Info>

### Beispiel 1: KI-SaaS-Plattform

**Preisstruktur:**
- **Basisabonnement**: $99/Monat (Plattformzugriff, 5 Sitze enthalten)

**Implementierung**: Verwenden Sie ein Abonnement mit Sitz- und Feature-Add-ons. Erfassen Sie die Tokennutzung in Ihrer Anwendung und berechnen Sie den Mehrverbrauch am Ende des Abrechnungszyklus über On-Demand-Gebühren.

**Beispielkunde** (12 Benutzer, 500K Token, individuelle Modelle + API-Zugriff):
| Komponente | Berechnung | Betrag |
|-----------|-------------|--------|
| Basis | Plattformgebühr | $99 |
| Zusätzliche Sitze | 7 × $20 | $140 |
| Individuelle Modelle | Add-on | $49 |
| API-Zugriff | Add-on | $29 |
| Token-Mehrverbrauch | 400K × \$0.02/1K (On-Demand) | \$8 |
| **Gesamt** | | **$325/Monat** |

### Beispiel 2: Plattform für Entwicklertools

**Stufenoptionen:**

| | Kostenlos | Pro | Enterprise |
|---|------|-----|------------|
| **Preis** | $0/Monat | $29/Monat | $199/Monat |
| **Benutzer** | 1 | 5 enthalten | Unbegrenzt |
| **Builds** | 100 | 1.000 | 10.000 |
| **Speicher** | 1 GB | 10 GB | 100 GB |

**Implementierungsoptionen:**

**Option A** (Nutzungsorientiert): Erstellen Sie Produkte mit Usage Meters für Builds/Speicher. Verwalten Sie die Benutzer in Ihrer Anwendung.

**Option B** (Sitzorientiert): Erstellen Sie Produkte mit Sitz-Add-ons. Erfassen Sie die Nutzung von Builds/Speicher und berechnen Sie den Mehrverbrauch über On-Demand-Gebühren.

**Add-ons (bei Verwendung von Option B):**

## Best Practices für die Implementierung

### Verständlichkeit der Preisseite

<Tip>
Machen Sie hybride Preise leicht verständlich. Zeigen Sie auf Ihrer Preisseite deutlich die Basiskosten, die enthaltenen Leistungen und die Funktionsweise des Mehrverbrauchs.
</Tip>

**Gut**: "\$49/Monat beinhaltet 10.000 API-Aufrufe. Zusätzliche Aufrufe: jeweils \$0.005"

**Schlecht**: "\$49/Monat + Nutzungsgebühren"

### Kostenplanbarkeit

Helfen Sie Kunden, ihre Kosten zu schätzen:

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### Sichtbarkeit der Nutzung

Zeigen Sie Kunden ihre Nutzung in Echtzeit:

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

### Transparenz der Abrechnung

Stellen Sie detaillierte Rechnungen aus, die alle Komponenten anzeigen:

| Rechnungsposten | Betrag |
|-----------|--------|
| Pro-Plan (monatlich) | $49.00 |
| Zusätzliche Sitze (7 × $15.00) | $105.00 |
| API-Nutzung – enthalten (10.000 Aufrufe) | $0.00 |
| API-Nutzung – Mehrverbrauch (15.420 Aufrufe × $0.005) | $77.10 |
| Add-on für erweiterte Analytics | $19.00 |
| **Zwischensumme** | **$250.10** |
| Steuer (8.5%) | $21.26 |
| **Gesamtbetrag** | **$271.36** |

## Fehlerbehebung bei hybrider Abrechnung

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**Symptome**: Die Nutzung wird mit 0 oder falschen Werten angezeigt.

**Lösungen**:
1. Überprüfen Sie, ob die Ereignisaufnahme funktioniert (API-Antworten prüfen)
2. Bestätigen Sie, dass `customer_id` mit dem Abonnementkunden übereinstimmt
3. Prüfen Sie, ob `event_name` mit der Meter-Konfiguration übereinstimmt
4. Überprüfen Sie, ob die Ereignisse korrekte Zeitstempel besitzen (nicht in der Zukunft liegen)
</Accordion>

<Accordion title="Proration confusion with multiple components">
**Symptome**: Kunden werden beim Wechsel des Plans unerwartete Beträge berechnet.

**Lösungen**:
1. Verwenden Sie die `previewChangePlan` API, um vor der Bestätigung die exakten Gebühren anzuzeigen
2. Kommunizieren Sie, dass die zeitanteilige Abrechnung sowohl für das Abonnement ALS AUCH für Add-ons gilt
3. Erwägen Sie die Verwendung von `difference_immediately` für eine einfachere Upgrade-Abrechnung
</Accordion>

<Accordion title="Free threshold not applying correctly">
**Symptome**: Kunden werden Nutzung berechnet, die kostenlos sein sollte.

**Lösungen**:
1. Überprüfen Sie, ob das kostenlose Kontingent beim nutzungsbasierten Produkt konfiguriert ist
2. Prüfen Sie, ob die Einheit des Kontingents mit der Ereignisaggregation übereinstimmt (Aufrufe vs. Anfragen)
3. Bestätigen Sie, dass der Usage Meter korrekt mit dem Abonnementprodukt verknüpft ist
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**Symptome**: Sitze oder Funktionen können während des Checkouts nicht hinzugefügt werden.

**Lösungen**:
1. Überprüfen Sie, ob Add-ons im Dashboard mit dem Abonnementprodukt verknüpft sind
2. Prüfen Sie, ob die Add-on-IDs in den API-Aufrufen korrekt sind
3. Stellen Sie sicher, dass die Währung des Add-ons mit der Währung des Abonnementprodukts übereinstimmt
</Accordion>
</AccordionGroup>
