## Adaptive Currency

Adaptive Currency ermöglicht es Kunden, in ihrer bevorzugten lokalen Währung zu bezahlen, und verbessert dadurch das Vertrauen sowie die Conversion-Raten.

### Funktionsweise

1. **Aktivieren**: Aktiviere Adaptive Currency unter **Settings → Business**
2. **Auswählen**: Kunden können die Währung direkt im checkout wechseln
3. **PPP anwenden**: Wenn [Purchasing Power Parity](/features/purchasing-power-parity) für das Produkt aktiviert ist, reduziert der Länderprozentsatz den Basispreis
4. **Umrechnen**: Der Preis (oder der durch PPP angepasste Preis) wird zum aktuellen FX-Kurs in die Währung des Kunden umgerechnet
5. **Runden**: Wenn [Charm Pricing](/features/charm-pricing) aktiviert ist, wird der umgerechnete Betrag auf ein prägnantes Ende wie 49.99 gerundet
6. **Anzeigen**: Der endgültige zu zahlende Betrag wird vor der Zahlung transparent angezeigt

## Automatische Steuerberechnung

Steuern werden automatisch anhand des Abrechnungsstandorts des Kunden berechnet. Dadurch wird die Einhaltung der Anforderungen für GST, VAT und sales tax ohne manuelle Einrichtung gewährleistet.

### Funktionsweise der Steuerberechnung

<Steps>
<Step title="Location Detection">
  Steuerregeln werden anhand des Landes des Kunden angewendet (und gegebenenfalls anhand der Region).
</Step>

<Step title="Dynamic Updates">
  Der Steuerbetrag wird automatisch aktualisiert, wenn:
  - das Land geändert wird
  - die Adresse aktualisiert wird
</Step>

<Step title="Transparent Display">
  Die endgültige Steueraufschlüsselung wird vor der Zahlung übersichtlich angezeigt.
</Step>
</Steps>

<Tip>
Die Steuerberechnung ist vollständig automatisiert. Für standardmäßige digitale Produkte und SaaS-Produkte ist keine manuelle Konfiguration erforderlich.
</Tip>

## Unterstützung der Business Tax ID

Für registrierte Unternehmen ermöglicht der Checkout Kunden, ihre Business Tax ID (z. B. VAT/GST-Nummer) einzugeben.

### Was geschieht bei der Eingabe einer Tax ID?

- Die Steuerberechtigung wird in Echtzeit validiert
- Anwendbare Steuerbefreiungen oder Reverse-Charge-Regeln werden angewendet
- Der Steuerbetrag wird im Checkout sofort aktualisiert

## Rabattcodes

Kunden können Rabatt- oder Promo-Codes, die Sie im Dashboard erstellt haben, direkt auf der Checkout-Seite anwenden.

### Checkout-Erlebnis

1. Der Kunde gibt den Rabattcode ein
2. Der Rabatt wird sofort validiert
3. Der aktualisierte Preis und die Ersparnis werden übersichtlich angezeigt

Wenn [Purchasing Power Parity](/features/purchasing-power-parity) für ein Produkt aktiviert ist, wird der Rabatt auf den durch PPP angepassten Preis angewendet, nicht auf den Basispreis.

<Frame>
  <img src="/images/checkout/c4.png" alt="Eingabe eines Rabattcodes im checkout" style={{ maxHeight: '500px', width: '70%' }}/>
</Frame>

### API-Integration

Wende einen oder mehrere kombinierte Rabattcodes vorab an oder aktiviere das Eingabefeld für Rabatte:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Shown by default; set to false to hide the field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`discount_codes` akzeptiert ein Array mit bis zu 20 Codes, die in der angegebenen Reihenfolge kombiniert werden. Das einzelne Feld `discount_code` ist veraltet, funktioniert aber weiterhin — bestehende Integrationen müssen nicht sofort geändert werden. Migriere bei Gelegenheit zu `discount_codes`, um Kombinationen und die umfangreichere Antwortstruktur zu nutzen.
</Info>

## Intelligente Adresserfassung

Der checkout unterstützt eine flexible Adresseingabe für einen schnelleren Abschluss.

### Verfügbare Optionen

| Option | Beschreibung |
|--------|-------------|
| **Automatische Adressvervollständigung von Google** | Schnelle Auswahl mit Autovervollständigung |
| **Manuelle Eingabe** | Vollständige Kontrolle über vollständige Adressen |
| **Länderauswahl** | Steuert die Steuer- und Compliance-Logik |
| **Minimale Adresse** | Erfasst nur das Land (und, sofern für die Steuer erforderlich, die Postleitzahl) — siehe [Modus für minimale Adressen](#minimal-address-mode) |

<Tip>
Die Adresserfassung schafft ein ausgewogenes Verhältnis zwischen Geschwindigkeit, Genauigkeit und globaler Abdeckung, um die Conversion zu maximieren und gleichzeitig Compliance sicherzustellen.
</Tip>

### Modus für minimale Adressen

Für eine maximale Conversion kannst du die Erfassung minimaler Adressen aktivieren, um Reibungsverluste im checkout zu reduzieren. Wenn `minimal_address` auf `true` gesetzt ist, erfasst der checkout nur:

- **Land** — für die Steuerbestimmung immer erforderlich
- **ZIP/Postleitzahl** — nur in Regionen, in denen sie für die Berechnung von sales tax, VAT oder GST erforderlich ist

Alle anderen Adressfelder (Straße, Ort, Bundesland) werden übersprungen, wodurch der Abschluss des checkout erheblich beschleunigt wird.

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="Modus für minimale Adressen mit nur den Feldern für Land und ZIP/Postleitzahl im checkout" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Die vollständige Adresserfassung bleibt der Standard. Aktiviere `minimal_address` für digitale Produkte und SaaS-Abläufe, bei denen keine vollständigen Rechnungsdaten erforderlich sind.
</Info>

  Siehe die vollständige Referenz des Parameters `minimal_address` im Leitfaden zur Checkout Sessions API.
</Card>

## Erfassung von Telefonnummern

Steuere mithilfe von Feature Flags der Checkout Session, ob das Telefonnummernfeld im checkout angezeigt wird und ob es erforderlich ist.

| Flag | Standard | Verhalten |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | Zeigt das Telefonnummernfeld im checkout-Formular an |
| `require_phone_number` | `false` | Macht das Telefonnummernfeld erforderlich (die Formularvalidierung erzwingt einen nicht leeren Wert) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`require_phone_number: true` erfordert `allow_phone_number_collection: true`. Die API lehnt Sessions ab, bei denen die Erfassung der Telefonnummer deaktiviert ist, obwohl die Telefonnummer erforderlich ist.
</Warning>

<Tip>
Verwende `require_phone_number` für B2B-SaaS, regulierte Branchen oder Abläufe, bei denen du einen verifizierten Kontaktkanal für Support, Betrugsprüfung oder Compliance benötigst.
</Tip>

## Benutzerdefinierte Felder

Erfasse während des checkout zusätzliche Informationen von Kunden, indem du benutzerdefinierte Formularfelder definierst. Dies ist nützlich, um Daten wie den Firmennamen, die Teamgröße, die Quelle der Empfehlung oder andere geschäftsspezifische Informationen zu erfassen.

### Verfügbare Feldtypen

| Typ | Beschreibung |
|------|-------------|
| `text` | Texteingabe in einer Zeile |
| `number` | Numerische Eingabe |
| `email` | E-Mail-Adresse mit Validierung |
| `url` | URL mit Validierung |
| `date` | Datumsauswahl |
| `dropdown` | Auswahl aus vordefinierten Optionen |
| `boolean` | Umschalter für Ja/Nein |

### Beispiel

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Die Antworten der Kunden werden automatisch in Webhook-Payloads (`payment.succeeded`, `subscription.active`) und API-Antworten über das Array `custom_field_responses` aufgenommen. Du kannst bis zu 5 benutzerdefinierte Felder pro Checkout Session definieren.
</Info>

## Collection Checkout

Product Collections ermöglichen eine einheitliche checkout-Erfahrung, bei der Kunden mehrere verwandte Produkte (z. B. Starter-, Pro- und Enterprise-Tarife) in einem einzigen checkout anzeigen und auswählen können.

### Funktionsweise

1. **Alle Produkte werden angezeigt**: Kunden sehen jedes aktive Produkt in der Collection
2. **Erstes Produkt vorausgewählt**: Das erste Produkt in der Collection wird automatisch ausgewählt
3. **Optionen vergleichen**: Kunden können Preise und Funktionen vor der Auswahl vergleichen
4. **Einzelauswahl**: Nach der Auswahl eines Produkts wird der checkout mit dem standardmäßigen Zahlungsablauf fortgesetzt

### Collection Checkout erstellen

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
Wenn du `product_collection_id` verwendest, übergib ein leeres `product_cart`-Array. Rabattcodes können bei der Erstellung der Session nicht vorab angewendet werden.
</Warning>

## Konfiguration der Checkout Session

Steuere das checkout-Verhalten mithilfe der Checkout Sessions API:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
Nach der Zahlung werden Kunden zu deinem `return_url` weitergeleitet, wobei automatisch Query-Parameter angehängt werden — darunter `payment_id` oder `subscription_id`, `status`, `email` und `license_key` (falls zutreffend). Eine vollständige Liste findest du im [Checkout Sessions-Leitfaden](/developer-resources/checkout-session#request-body).
</Info>

Passe das Erscheinungsbild der checkout-Seite mithilfe des Parameters `customization.theme_config` bei der Erstellung einer Checkout Session über die API an deine Marke an. Konfiguriere Farben, Schriftarten, Rahmenradius und Schaltflächentext für den hellen und dunklen Modus.

<Frame>
  <img src="/images/checkout/theme-example.png" alt="Checkout-Seite mit benutzerdefiniertem Theme" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Card title="Design & Theme Customization" icon="palette" href="/features/design">
  Konfiguriere Themes visuell im Dashboard mit vorgefertigten Themes, Typografie, Farben und einer Live-Vorschau.
</Card>

<Info>
Dieser Abschnitt behandelt die **serverseitige API**-Konfiguration des Themes mithilfe von `customization.theme_config`. Wenn du das **Checkout SDK** (Overlay- oder Inline-checkout) verwendest, findest du im Abschnitt zur Theme-Anpassung unter [Overlay Checkout](/developer-resources/overlay-checkout#theme-customization) weitere Informationen. Dort werden camelCase-Eigenschaften verwendet (z. B. `bgPrimary` statt `bg_primary`).
</Info>

### Optionen der Theme-Konfiguration

| Property | Beschreibung |
|----------|-------------|
| `light` | Farbkonfiguration für den hellen Modus |
| `dark` | Farbkonfiguration für den dunklen Modus |
| `font_primary_url` | URL für die primäre Schriftart |
| `font_secondary_url` | URL für die sekundäre Schriftart |
| `font_size` | Schriftgröße: `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `font_weight` | Schriftstärke: `normal`, `medium`, `bold`, `extraBold` |
| `radius` | Rahmenradius für UI-Elemente (z. B. `4px`, `0.5rem`, `8px`) |
| `pay_button_text` | Benutzerdefinierter Text für die Zahlungsschaltfläche (z. B. "Complete Purchase", "Subscribe Now") |

### Farbkonfiguration (heller/dunkler Modus)

Jeder Modus (`light` und `dark`) unterstützt die folgenden Farbeigenschaften:

| Property | Beschreibung |
|----------|-------------|
| `bg_primary` | Primäre Hintergrundfarbe |
| `bg_secondary` | Sekundäre Hintergrundfarbe |
| `text_primary` | Primäre Textfarbe |
| `text_secondary` | Sekundäre Textfarbe |
| `text_placeholder` | Platzhalterfarbe des Textes |
| `text_error` | Fehlerfarbe des Textes |
| `text_success` | Erfolgsfarbe des Textes |
| `border_primary` | Primäre Rahmenfarbe |
| `border_secondary` | Sekundäre Rahmenfarbe |
| `button_primary` | Hintergrundfarbe der primären Schaltfläche |
| `button_primary_hover` | Hover-Farbe der primären Schaltfläche |
| `button_secondary` | Hintergrundfarbe der sekundären Schaltfläche |
| `button_secondary_hover` | Hover-Farbe der sekundären Schaltfläche |
| `button_text_primary` | Textfarbe der primären Schaltfläche |
| `button_text_secondary` | Textfarbe der sekundären Schaltfläche |
| `input_focus_border` | Rahmenfarbe bei Eingabefokus |

<Info>
Alle Farbfelder akzeptieren standardmäßige CSS-Farbformate:
- Hex: `#fff`, `#ffffff`, `#ffffffff`
- RGB/RGBA: `rgb(255, 255, 255)`, `rgba(255, 255, 255, 0.5)`
- HSL/HSLA: `hsl(120, 100%, 50%)`, `hsla(120, 100%, 50%, 0.5)`
- Benannte Farben: `red`, `blue`, `transparent`
</Info>

### Beispiel

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  customization: {
    theme_config: {
      // Custom fonts
      font_primary_url: 'https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&display=swap',
      font_size: 'md',
      font_weight: 'medium',
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      
      // Light mode colors
      light: {
        bg_primary: '#ffffff',
        bg_secondary: '#f5f5f5',
        text_primary: '#1a1a1a',
        text_secondary: '#666666',
        button_primary: '#0066ff',
        button_primary_hover: '#0052cc',
        button_text_primary: '#ffffff',
        border_primary: '#e0e0e0'
      },
      
      // Dark mode colors
      dark: {
        bg_primary: '#1a1a1a',
        bg_secondary: '#2d2d2d',
        text_primary: '#ffffff',
        text_secondary: '#a0a0a0',
        button_primary: '#3385ff',
        button_primary_hover: '#4d99ff',
        button_text_primary: '#ffffff',
        border_primary: '#404040'
      }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

<Tip>
Du musst nicht alle Farbeigenschaften angeben. Nicht angegebene Eigenschaften verwenden die Standardwerte des Themes.
</Tip>
