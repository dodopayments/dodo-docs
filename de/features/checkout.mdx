## Adaptive Currency

Adaptive Currency ermöglicht es Kunden, in ihrer bevorzugten lokalen Währung zu bezahlen, und verbessert dadurch das Vertrauen sowie die Conversion-Raten.

### Funktionsweise

1. **Aktivieren**: Aktivieren Sie Adaptive Currency unter **Settings → Business**
2. **Auswählen**: Kunden können die Währung direkt im Checkout wechseln
3. **Umrechnen**: Preise werden mithilfe von FX-Raten in Echtzeit dynamisch umgerechnet
4. **Anzeigen**: Der endgültige zu zahlende Betrag wird vor der Zahlung transparent angezeigt

## Automatische Steuerberechnung

Steuern werden automatisch anhand des Abrechnungsstandorts des Kunden berechnet. Dadurch wird die Einhaltung der Anforderungen für GST, VAT und sales tax ohne manuelle Einrichtung gewährleistet.

### Funktionsweise der Steuerberechnung

<Steps>
<Step title="Location Detection">
  Steuerregeln werden anhand des Landes des Kunden angewendet (und gegebenenfalls anhand der Region).
</Step>

<Step title="Dynamic Updates">
  Der Steuerbetrag wird automatisch aktualisiert, wenn:
  - das Land geändert wird
  - die Adresse aktualisiert wird
</Step>

<Step title="Transparent Display">
  Die endgültige Steueraufschlüsselung wird vor der Zahlung übersichtlich angezeigt.
</Step>
</Steps>

<Tip>
Die Steuerberechnung ist vollständig automatisiert. Für standardmäßige digitale Produkte und SaaS-Produkte ist keine manuelle Konfiguration erforderlich.
</Tip>

## Unterstützung der Business Tax ID

Für registrierte Unternehmen ermöglicht der Checkout Kunden, ihre Business Tax ID (z. B. VAT/GST-Nummer) einzugeben.

### Was geschieht bei der Eingabe einer Tax ID?

- Die Steuerberechtigung wird in Echtzeit validiert
- Anwendbare Steuerbefreiungen oder Reverse-Charge-Regeln werden angewendet
- Der Steuerbetrag wird im Checkout sofort aktualisiert

<Info>

</Info>

## Rabattcodes

Kunden können Rabatt- oder Promo-Codes, die Sie im Dashboard erstellt haben, direkt auf der Checkout-Seite anwenden.

### Checkout-Erlebnis

1. Der Kunde gibt den Rabattcode ein
2. Der Rabatt wird sofort validiert
3. Der aktualisierte Preis und die Ersparnis werden übersichtlich angezeigt

<Frame>
  <img src="/images/checkout/c4.png" alt="Eingabe eines Rabattcodes im Checkout" style={{ maxHeight: '500px', width: '70%' }}/>
</Frame>

### API-Integration

Wenden Sie einen oder mehrere kombinierbare Rabattcodes vorab an oder aktivieren Sie das Eingabefeld für Rabatte:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Show discount input field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
`discount_codes` akzeptiert ein Array mit bis zu 20 Codes, die in der angegebenen Reihenfolge kombiniert werden. Das einzelne Feld `discount_code` ist veraltet, funktioniert aber weiterhin – bestehende Integrationen müssen nicht sofort geändert werden. Migrieren Sie bei Gelegenheit zu `discount_codes`, um die Kombination von Codes und die umfangreichere Antwortstruktur zu nutzen.
</Info>

## Intelligente Adresserfassung

Der Checkout unterstützt eine flexible Adresseingabe für einen schnelleren Abschluss.

### Verfügbare Optionen

| Option | Beschreibung |
|--------|-------------|
| **Google Address Autofill** | Schnelle Auswahl mit Autovervollständigung |
| **Manuelle Eingabe** | Vollständige Kontrolle über komplette Adressen |
| **Länderauswahl** | Steuert die Steuer- und Compliance-Logik |
| **Minimale Adresse** | Erfasst nur das Land (und, falls für die Steuer erforderlich, die Postleitzahl) – siehe [Modus für minimale Adressen](#minimal-address-mode) |

<Tip>
Die Adresserfassung vereint Geschwindigkeit, Genauigkeit und globale Abdeckung, um die Conversion zu maximieren und gleichzeitig Compliance sicherzustellen.
</Tip>

### Modus für minimale Adressen

Für eine maximale Conversion können Sie die Erfassung minimaler Adressen aktivieren, um Reibung im Checkout zu reduzieren. Wenn `minimal_address` auf `true` gesetzt ist, erfasst der Checkout nur:

- **Land** – für die Steuerbestimmung immer erforderlich
- **Postleitzahl** – nur in Regionen, in denen sie für die Berechnung von sales tax, VAT oder GST erforderlich ist

Alle anderen Adressfelder (Straße, Ort, Bundesland) werden übersprungen, wodurch der Abschluss des Checkouts deutlich beschleunigt wird.

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="Modus für minimale Adressen mit nur den Feldern für Land und Postleitzahl im Checkout" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Die vollständige Adresserfassung bleibt der Standard. Aktivieren Sie `minimal_address` für digitale Produkte und SaaS-Abläufe, bei denen keine vollständigen Rechnungsdetails erforderlich sind.
</Info>

  Eine vollständige Referenz des Parameters `minimal_address` finden Sie im Leitfaden zur Checkout Sessions API.
</Card>

## Erfassung der Telefonnummer

Steuern Sie mithilfe von Feature-Flags der Checkout-Session, ob das Telefonnummernfeld im Checkout angezeigt wird und ob es erforderlich ist.

| Flag | Standard | Verhalten |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | Zeigt das Telefonnummernfeld im Checkout-Formular an |
| `require_phone_number` | `false` | Macht das Telefonnummernfeld erforderlich (die Formularvalidierung verlangt einen nicht leeren Wert) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
`require_phone_number: true` erfordert `allow_phone_number_collection: true`. Die API lehnt Sessions ab, bei denen die Erfassung der Telefonnummer deaktiviert ist, während die Telefonnummer erforderlich ist.
</Warning>

<Tip>
Verwenden Sie `require_phone_number` für B2B-SaaS, regulierte Branchen oder Abläufe, bei denen Sie einen verifizierten Kontaktkanal für Support, Betrugsprüfung oder Compliance benötigen.
</Tip>

## Benutzerdefinierte Felder

Erfassen Sie während des Checkouts zusätzliche Informationen von Kunden, indem Sie benutzerdefinierte Formularfelder definieren. Dies ist nützlich, um Daten wie den Firmennamen, die Teamgröße, die Empfehlungsquelle oder andere geschäftsspezifische Informationen zu erfassen.

### Verfügbare Feldtypen

| Typ | Beschreibung |
|------|-------------|
| `text` | Texteingabe in einer Zeile |
| `number` | Numerische Eingabe |
| `email` | E-Mail-Adresse mit Validierung |
| `url` | URL mit Validierung |
| `date` | Datumsauswahl |
| `dropdown` | Auswahl aus vordefinierten Optionen |
| `boolean` | Umschalter für Ja/Nein |

### Beispiel

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Kundenantworten werden automatisch in Webhook-Payloads (`payment.succeeded`, `subscription.active`) sowie in API-Antworten über das Array `custom_field_responses` aufgenommen. Sie können bis zu 5 benutzerdefinierte Felder pro Checkout-Session definieren.
</Info>

## Collection Checkout

Product Collections ermöglichen ein einheitliches Checkout-Erlebnis, bei dem Kunden mehrere verwandte Produkte (z. B. Starter-, Pro- und Enterprise-Tarife) in einem einzigen Checkout anzeigen und auswählen können.

### Funktionsweise

1. **Alle Produkte werden angezeigt**: Kunden sehen jedes aktive Produkt in der Collection
2. **Erstes Produkt vorausgewählt**: Das erste Produkt der Collection wird automatisch ausgewählt
3. **Optionen vergleichen**: Kunden können Preise und Funktionen vor der Auswahl vergleichen
4. **Einzelauswahl**: Nach der Auswahl eines Produkts wird der Checkout mit dem standardmäßigen Zahlungsablauf fortgesetzt

### Erstellen eines Collection Checkouts

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
Bei Verwendung von `product_collection_id` übergeben Sie ein leeres `product_cart`-Array. Rabattcodes können bei der Erstellung der Session nicht vorab angewendet werden.
</Warning>

## Konfiguration der Checkout-Session

Steuern Sie das Verhalten des Checkouts mithilfe der Checkout Sessions API:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
Nach der Zahlung werden Kunden zu Ihrer `return_url` weitergeleitet. Query-Parameter werden automatisch angehängt – darunter `payment_id` oder `subscription_id`, `status`, `email` und `license_key` (falls zutreffend). Die vollständige Liste finden Sie im [Leitfaden zu Checkout-Sessions](/developer-resources/checkout-session#request-body).
</Info>

  Konfigurieren Sie Themes visuell im Dashboard mit vorgefertigten Themes, Typografie, Farben und einer Live-Vorschau.

<Info>
Dieser Abschnitt behandelt die serverseitige Theme-Konfiguration über die API mithilfe von `customization.theme_config`. Wenn Sie das **Checkout SDK** (Overlay- oder Inline-Checkout) verwenden, finden Sie im Abschnitt zur Theme-Anpassung von [Overlay Checkout](/developer-resources/overlay-checkout#theme-customization) weitere Informationen. Dort werden camelCase-Eigenschaften verwendet (z. B. `bgPrimary` anstelle von `bg_primary`).
</Info>

### Optionen der Theme-Konfiguration

| Eigenschaft | Beschreibung |
|----------|-------------|
| `light` | Farbkonfiguration für den hellen Modus |
| `dark` | Farbkonfiguration für den dunklen Modus |
| `font_primary_url` | URL der primären Schriftart |
| `font_secondary_url` | URL der sekundären Schriftart |
| `font_size` | Schriftgröße: `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `font_weight` | Schriftstärke: `normal`, `medium`, `bold`, `extraBold` |
| `radius` | Eckenradius für UI-Elemente (z. B. `4px`, `0.5rem`, `8px`) |
| `pay_button_text` | Benutzerdefinierter Text für den Zahlungsbutton (z. B. "Complete Purchase", "Subscribe Now") |

### Farbkonfiguration (heller/dunkler Modus)

Jeder Modus (`light` und `dark`) unterstützt die folgenden Farbeigenschaften:

| Eigenschaft | Beschreibung |
|----------|-------------|
| `bg_primary` | Primäre Hintergrundfarbe |
| `bg_secondary` | Sekundäre Hintergrundfarbe |
| `text_primary` | Primäre Textfarbe |
| `text_secondary` | Sekundäre Textfarbe |
| `text_placeholder` | Farbe des Platzhaltertexts |
| `text_error` | Fehlertextfarbe |
| `text_success` | Erfolgstextfarbe |
| `border_primary` | Primäre Rahmenfarbe |
| `border_secondary` | Sekundäre Rahmenfarbe |
| `button_primary` | Hintergrundfarbe des primären Buttons |
| `button_primary_hover` | Hover-Farbe des primären Buttons |
| `button_secondary` | Hintergrundfarbe des sekundären Buttons |
| `button_secondary_hover` | Hover-Farbe des sekundären Buttons |
| `button_text_primary` | Textfarbe des primären Buttons |
| `button_text_secondary` | Textfarbe des sekundären Buttons |
| `input_focus_border` | Rahmenfarbe bei Eingabefokus |

<Info>
Alle Farbfelder akzeptieren standardmäßige CSS-Farbformate:
- Hex: `#fff`, `#ffffff`, `#ffffffff`
- RGB/RGBA: `rgb(255, 255, 255)`, `rgba(255, 255, 255, 0.5)`
- HSL/HSLA: `hsl(120, 100%, 50%)`, `hsla(120, 100%, 50%, 0.5)`
- Benannte Farben: `red`, `blue`, `transparent`
</Info>

### Beispiel

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  customization: {
    theme_config: {
      // Custom fonts
      font_primary_url: 'https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600&display=swap',
      font_size: 'md',
      font_weight: 'medium',
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      
      // Light mode colors
      light: {
        bg_primary: '#ffffff',
        bg_secondary: '#f5f5f5',
        text_primary: '#1a1a1a',
        text_secondary: '#666666',
        button_primary: '#0066ff',
        button_primary_hover: '#0052cc',
        button_text_primary: '#ffffff',
        border_primary: '#e0e0e0'
      },
      
      // Dark mode colors
      dark: {
        bg_primary: '#1a1a1a',
        bg_secondary: '#2d2d2d',
        text_primary: '#ffffff',
        text_secondary: '#a0a0a0',
        button_primary: '#3385ff',
        button_primary_hover: '#4d99ff',
        button_text_primary: '#ffffff',
        border_primary: '#404040'
      }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

<Tip>
Sie müssen nicht alle Farbeigenschaften angeben. Nicht festgelegte Eigenschaften verwenden die Standardwerte des Themes.
</Tip>
