## Was sind Rabattcodes?

Rabattcodes sind Promotionstoken, die die Bestellsumme an der Kasse reduzieren. Sie eignen sich ideal für:

- **Saisonale Kampagnen**: Black Friday, Produkteinführungen oder Jubiläen
- **Akquisitionsangebote**: Anreize für Ersterwerb oder Empfehlungsbelohnungen
- **Bindung**: Rückgewinnungs- oder Treuebelohnungen für bestehende Kunden
- **B2B-Deals**: Vereinbarte oder ausgehandelte Preise über private Codes

## Hauptvorteile

- **Flexible Rabatte**: Prozentbasierte oder feste Rabatte
- **Kombinierbare Codes**: Wende bis zu 20 Codes pro Checkout, Zahlung oder Abonnement an — kombiniere Kampagnen (z. B. `WELCOME10` + `BLACKFRIDAY20`), ohne individuelle Codes erstellen zu müssen
- **Gezielte Kontrolle**: Beschränke die Verwendung nach Produkt, Abonnementzyklen und Kundenberechtigung
- **Kampagnenverwaltung**: Geplante Startdaten, Ablaufdaten sowie allgemeine und kundenbezogene Nutzungslimits
- **Preise je Währung**: Lege den festen Abzugsbetrag, das Betragslimit und den Mindestzwischensumme je Währung fest
- **Nahtloser Checkout**: UI-Feld und API-Unterstützung über Checkout Sessions

## Rabattcodes erstellen

Erstellen Sie Rabattcodes in Ihrem Dodo Payments-Dashboard und wenden Sie diese im gehosteten Checkout oder über API an.

### Dashboard-Einrichtung

- **Discount Name** (erforderlich): Interner Name und im Dashboard angezeigter Name
- **Code** (erforderlich): Die Zeichenfolge, die Kunden beim Checkout eingeben, oder generiere über die bereitgestellte Schaltfläche einen zufälligen Code
- **Type** (erforderlich): Wähle **Percentage** (prozentualer Rabatt) oder **Amount** (fester Abzug)
- **Amount** (erforderlich): Der Prozentwert oder der feste Betrag für einen Amount-Rabatt
- **Start Date** (optional): Plane die Aktivierung des Codes für einen späteren Zeitpunkt; lasse das Feld leer, um ihn sofort zu aktivieren
- **Expiration Date** (optional): Datum, nach dem der Code ungültig wird
- **Usage Limit** (optional): Maximale Gesamtzahl der Einlösungen über alle Kunden hinweg
- **Per-Customer Usage Limit** (optional): Maximale Anzahl der Einlösungen durch einen einzelnen Kunden. Wenn beide Limits festgelegt sind, muss dieses kleiner oder gleich dem allgemeinen Nutzungslimit sein
- **Customer Eligibility** (optional): Beschränke, wer den Code einlösen darf — alle Kunden, Erstkunden, bestehende Kunden oder eine manuell ausgewählte Liste
- **Currency Options** (optional): Werte je Währung — siehe [Optionen je Währung](#per-currency-options)
- **Product Restriction** (optional): Beschränke die Gültigkeit auf ausgewählte Produkte
- **Subscription Cycle Limit** (optional): Anzahl der Abrechnungszyklen, für die der Rabatt gilt
- **Preserve on Plan Change** (optional): Rabatt aktiv halten, wenn sich der Plan des Abonnements ändert (`preserve_on_plan_change`)
- **Metadata** (optional): Füge benutzerdefinierte Schlüssel-Wert-Paare für internes Tracking oder Integrationen hinzu

## Rabattarten

| Typ | API-Wert | Verhalten |
|------|-----------|-----------|
| Prozentual | `percentage` | Reduziert den Preis um einen Prozentsatz. Optional kann der Rabatt je Währung durch einen maximalen Rabatt begrenzt werden. |
| Betrag | `flat` | Zieht einen festen Betrag ab. Der Abzug wird über den gesamten Warenkorb verteilt und nicht pro Position angewendet. |

Beide Typen können im selben `discount_codes`-Array kombiniert werden und werden in der Reihenfolge des Arrays angewendet.

## Kundenberechtigung

Lege `customer_eligibility` fest, um zu steuern, wer einen Code einlösen darf:

| Wert | Wer kann ihn einlösen? |
|-------|----------------|
| `any` | Jeder Kunde. Dies ist die Standardeinstellung. |
| `first_time` | Kunden, die zuvor noch nichts bei dir gekauft haben. |
| `existing` | Kunden, die zuvor bei dir gekauft haben. |
| `specific` | Nur Kunden, die du der Allowlist des Codes hinzufügst. |

<Frame>
    <img src="/images/discount-codes/discount-restriction.png" alt="Dropdown für Kundenberechtigungen mit den Optionen Jeder, Erstkunde, Bestehender Kunde und Bestimmter Kunde" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Warning>
Ein `specific`-Code beginnt mit **null** berechtigten Kunden und lehnt jede Einlösung ab, bis du Kunden hinzufügst. Füge sie im Dashboard oder über die Discount Customers API hinzu.
</Warning>

Kombiniere die Berechtigung mit dem **Per-Customer Usage Limit**, um unabhängig vom allgemeinen Nutzungslimit festzulegen, wie oft jeder einzelne Kunde den Code einlösen darf.

## Optionen je Währung

Mit Währungsoptionen kann sich ein Code über alle von dir angebotenen Währungen hinweg korrekt verhalten. Jeder Eintrag legt für eine einzelne Währung Folgendes fest:

- **Amount** — Bei einem Amount-Rabatt ist dies der Abzug selbst; bei einem Percentage-Rabatt begrenzt er den maximalen Abzugsbetrag des Codes. Wird über die API auf `max_amount_possible` abgebildet.
- **Minimum subtotal** — Der Code gilt nur, wenn der Warenkorb diese Zwischensumme erreicht. `0` bedeutet, dass kein Mindestbetrag gilt.
- **Default** — Ein Eintrag kann als Standard markiert werden, aus dem andere, nicht konfigurierte Währungen umgerechnet werden.

<Frame>
    <img src="/images/discount-codes/discount-currency-options.png" alt="Bereich für Währungsoptionen mit Betrag und Mindestzwischensumme je Währung für INR und USD" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

Ein Amount-Rabatt erfordert mindestens eine Währungsoption mit einem auflösbaren Standardwert, da ein fester Abzug ohne Währung keine Bedeutung hat. Währungsoptionen sind für Percentage-Rabatte optional.

<Info>
Die Mindestzwischensumme wird immer anhand der ursprünglichen Preise des Warenkorbs berechnet, niemals anhand der Zwischensumme während der Anwendung einer Rabattkette. Die Reihenfolge der Rabatte ändert daher nie, ob ein Mindestbetrag erreicht ist.
</Info>

## Checkout-Erlebnis

1. Käufer geben den Code in das Checkout-Feld ein.
2. Berechtigte Rabatte werden angewendet und die Summen sofort aktualisiert.

<Frame>
    <img src="/images/discount-codes/discount-on-checkout.png" alt="Checkout-Seite mit einem auf die Bestellsumme angewendeten Rabatt" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Info>
Übergeben Sie in Checkout Sessions `discount_codes` (ein Array), um einen oder mehrere Codes vorab anzuwenden. Das Eingabefeld für Rabattcodes wird standardmäßig angezeigt – `feature_flags.allow_discount_code` ist standardmäßig auf `true` gesetzt. Setzen Sie es nur dann auf `false`, wenn Sie das Feld ausblenden möchten. Codes werden in der Reihenfolge des Arrays angewendet, bis zu einem Maximum von 20.
</Info>

## Rabattcodes kombinieren

Checkout Sessions, Zahlungen und Abonnements akzeptieren über das `discount_codes`-Array bis zu **20 kombinierte Codes** (maximal 20 Einträge). Codes werden **in der Reihenfolge des Arrays** angewendet: Der erste berechtigte Code reduziert zuerst den Basispreis, der nächste Code reduziert den bereits rabattierten Preis usw. Die vollständige Liste der angewendeten Rabatte wird in der Antwort unter `discount_ids` (bei Zahlungen/Abonnements) und `discounts` (detailliertere Angaben je Rabatt, einschließlich Position und verbleibender Abonnementzyklen) zurückgegeben.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_abc', quantity: 1 }],
  discount_codes: ['WELCOME10', 'BLACKFRIDAY20'], // applied in this order
  customer: { email: 'user@example.com' },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Das einzelne Feld `discount_code` ist **veraltet**, wird aus Gründen der Abwärtskompatibilität aber weiterhin vollständig unterstützt — bestehende Integrationen funktionieren ohne Änderungen. Es kann nicht zusammen mit `discount_codes` in derselben Anfrage verwendet werden. Wir empfehlen, bei Gelegenheit auf `discount_codes` (die Array-Form) zu migrieren, auch bei einzelnen Codes, um von der Kombination mehrerer Codes und der umfangreicheren Antwortstruktur zu profitieren.
</Info>

## Häufige Anwendungsfälle

- **Einführungsangebote**: Zeitlich begrenzte Launch-Aktionen für neue Produkte
- **Großkunden oder B2B**: Vertraglich vereinbarte Rabatte für ausgewählte Produktgruppen
- **Kundenbindung**: Rückgewinnungscodes in Abläufen zur Vermeidung von Abwanderung
- **Saisonale Kampagnen**: Feiertags- oder veranstaltungsbezogene Aktionen

## Integrationsbeispiele

### Einen Rabatt mit Metadaten erstellen
Füge benutzerdefinierte Schlüssel-Wert-Paare für internes Tracking hinzu.

```typescript
const discount = await client.discounts.create({
  type: 'percentage',
  amount: 1500, // 15%
  code: 'SUMMER2025',
  metadata: {
    campaign: 'summer_promo',
    source: 'email_blast'
  }
});
```

<Tip>
Verwende Metadaten, um Rabatte nach Kampagne, Quelle oder interner Referenz-ID zu kennzeichnen, damit du die Nutzung später abgleichen und den ROI messen kannst.
</Tip>

### Rabatte in Checkout Sessions anwenden
Wende einen oder mehrere kombinierte Rabatte vorab an und zeige die Codeeingabe-UI an.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  discount_codes: ['BLACKFRIDAY2024', 'NEWUSER5'], // stacked in array order
  customer: { email: 'user@example.com', name: 'Jane Doe' },
  return_url: 'https://yoursite.com/return'
});
```

### Rabatte bei Planänderungen anwenden
Biete Aktionspreise an, wenn Kunden ihr Abonnement upgraden oder downgraden.

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'pdt_pro',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  discount_codes: ['UPGRADE20']
});
```

| Wert von `discount_codes` | Verhalten bei Planänderung |
|------------------------|-------------------------|
| `undefined` / `null` (nicht angegeben) | Bestehende Rabatte mit `preserve_on_plan_change=true` bleiben erhalten, sofern sie auf das neue Produkt anwendbar sind. |
| `[]` (leeres Array) | **Alle** bestehenden Rabatte werden aus dem Abonnement entfernt. |
| `['CODE_A', 'CODE_B', ...]` | Ersetzt alle bestehenden Rabatte durch diese kombinierte Gruppe, die in der Reihenfolge des Arrays angewendet wird. |

<Info>
Lese alle angewendeten Rabatte über das neue `discounts`-Array in der Abonnementantwort aus dem Abonnement aus. Jeder Eintrag enthält `discount_id`, `position`, `cycles_remaining` (für Abonnements) und den ursprünglichen Code.
</Info>

### Rabattcodefeld ausblenden
Das Eingabefeld für Rabattcodes wird standardmäßig angezeigt, sodass Kunden jederzeit einen Code eingeben können, ohne dass Sie vorab einen übergeben müssen. Setzen Sie `allow_discount_code` auf `false`, um das Feld vollständig auszublenden.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  feature_flags: {
    allow_discount_code: false
  },
  return_url: 'https://yoursite.com/return'
});
```

## Best Practices

- **Klar benennen**: Verwende erkennbare Codes, die zu den Kampagnennamen passen
- **Zeitlich begrenzen**: Füge Ablaufdaten hinzu, um Dringlichkeit zu erzeugen und Missbrauch zu verhindern
- **Gezielt einsetzen**: Beschränke die Gültigkeit auf bestimmte Produkte, um Margenverluste zu vermeiden
- **Früh validieren**: Prüfe die Anwendbarkeit des Codes, bevor du den Checkout bestätigst
- **Auswirkungen überwachen**: Verfolge Nutzung und Conversion nach Kampagne

<Info>
Rabattcodes sind wirkungsvolle Instrumente für Kundengewinnung und -bindung. Beginne mit einfachen, aussagekräftig benannten Angeboten, validiere sie gründlich und optimiere sie anhand ihrer Leistung.
</Info>
