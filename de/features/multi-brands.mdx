## Einführung

Multi-Brand ermöglicht es Ihnen, mehrere Marken mit jeweils eigenem Logo, Descriptor und Website-URL an **ein verifiziertes Unternehmen** anzuhängen. Ihr Auszahlungskonto, Gebühren und KYC bleiben genau gleich, während jedes Produkt, Zahlungslink, Abonnement, jede Rechnung und Transaktion nun unter einer bestimmten Marke erfasst werden kann. Verwenden Sie es, um neue Nischen zu testen, eine Website zu lokalisieren oder B2B- und B2C-Linien zu trennen, ohne zusätzliche Geschäftskonten zu eröffnen.

## Merchant Dashboard Ablauf

<Steps>
<Step title="Open Settings → Business">
Navigieren Sie zu **Einstellungen → Unternehmen**. Das **Marken unter [Ihr Unternehmen]**-Panel rechts listet Ihre Primärmarke und alle Sekundärmarken auf.

<Frame>
<img src="/images/multi-brands/brands-section.png" alt="Marken-Panel in den Unternehmenseinstellungen, das primäre und sekundäre Marken mit einer Plus-Taste zum Hinzufügen einer neuen Marke zeigt" />
</Frame>
</Step>
<Step title="Click the '+' button">
Klicken Sie im Marken-Panel auf die **+**-Taste in der oberen rechten Ecke, um das Formular für die neue Marke zu öffnen.
</Step>
<Step title="Fill in the brand details">
Füllen Sie die folgenden Felder aus:

- **Markenname** (erforderlich): Geben Sie Ihren Markennamen ein.
- **Website-URL** (erforderlich): Die Website Ihrer Marke, zum Beispiel `https://www.yourcompany.com`.
- **Support-E-Mail**: Die E-Mail, die Kunden verwenden können, um Support für diese Marke zu erreichen.
- **Markenbeschreibung** (erforderlich): Beschreiben Sie Ihre Marke, Produkte und was sie einzigartig macht.
- **Markenlogo**: Laden Sie ein Logo hoch, um die Marke beim Checkout, auf Rechnungen und Zahlungslinks darzustellen.

Reichen Sie das Formular ein, um die Marke zu erstellen. Produkte können nun dieser Marke zugeordnet werden und Zahlungslinks zeigen deren Branding an.
</Step>
<Step title="Brand Selector">
Ein Markenfilter ist jetzt bei der Produkterstellung sichtbar.
</Step>
<Step title="Brand ID in Transactions">
Transaktionen und Abonnements haben eine Marken-ID, um Ihnen zu helfen, festzustellen, zu welcher Marke die Transaktion gehört.
</Step>
</Steps>

## Zusätzliche Punkte

- **Keine Änderungen bei Auszahlungen:** Alle Gelder, Auszahlungszyklen und Gebühren fließen weiterhin in das Wallet auf Geschäftsebene und auf das Bankkonto des Händlers.
- **Marken-ID in Webhooks:** Die Payloads für Zahlungen, Abonnements, Rückerstattungen, Streitfälle, Lizenzschlüssel, Einträge im Kreditbuch, niedrige Kreditguthaben, Berechtigungsvergabe, Mahnversuche und abgebrochene Checkouts enthalten alle eine `brand_id`, sodass du sie einer bestimmten Marke zuordnen kannst. Wenn eine Entität keine eigene Marke hat, greift `brand_id` auf die primäre Marke des Geschäfts zurück. Auszahlungs-Payloads gelten auf Geschäftsebene und enthalten keine `brand_id`.
- **Sperrungen:** Wenn eine Marke gesperrt wird, werden nur ihre Zahlungslinks deaktiviert. Andere Marken unter demselben Geschäft können weiterhin Transaktionen durchführen.
- Keine Änderungen an Storefront, Rechnungen, Lizenzschlüsseln, Rabattcodes, Auszahlungseinstellungen oder anderen Funktionen auf Geschäftsebene.

## Eine Brand archivieren

Wenn eine Brand ihren Zweck erfüllt hat, archivieren Sie sie, anstatt sie ungenutzt in Ihrem Dashboard zu belassen. Durch das Archivieren wird die Brand stillgelegt und ihr Katalog in einem einzigen Schritt an eine andere Brand desselben Unternehmens übertragen.

<Warning>
Das Archivieren einer Brand ist dauerhaft. Es gibt keine Möglichkeit, eine archivierte Brand wiederherzustellen.
</Warning>

### Was beim Archivieren geschieht

Sie bestimmen eine **Ziel-Brand**, die die zu archivierende Brand übernimmt. Das Dashboard fordert immer eine Ziel-Brand an, und die API übernimmt sie als `move_products_to`. In einer atomaren Aktion führt Dodo Payments Folgendes aus:

- Verschiebt jedes Produkt in die Ziel-Brand.
- Verschiebt jedes laufende Abonnement in die Ziel-Brand, sodass Verlängerungen weiterhin unter dieser Brand abgerechnet werden.
- Verschiebt jede Produktkollektion in die Ziel-Brand.
- Archiviert und deaktiviert die ursprüngliche Brand.

Ihre Historie bleibt unverändert. Zahlungen, Rechnungen und abgeschlossene Abonnements behalten die Brand, unter der sie erstellt wurden, sodass die bisherige Berichterstattung korrekt bleibt.

Die Ziel-Brand muss demselben Unternehmen angehören und darf selbst nicht archiviert sein. Ihre primäre Brand ist eine gültige Ziel-Brand, und ihre Brand-ID entspricht Ihrer Business-ID. Sie können die Ziel-Brand nur weglassen, wenn die Brand keine Produkte, laufenden Abonnements und Produktkollektionen enthält.

<Note>
Die primäre Brand kann niemals archiviert werden. Sie ist die Brand, auf die Ihr Unternehmen zurückgreift, sodass immer mindestens eine Brand bestehen bleibt.
</Note>

### Eine archivierte Brand ist schreibgeschützt

| Aktion | Ergebnis |
|---|---|
| Details der Brand bearbeiten | Mit `BRAND_ARCHIVED` abgelehnt |
| Brand zur Verifizierung einreichen | Mit `BRAND_ARCHIVED` abgelehnt |
| Produkt oder Kollektion unter der Brand erstellen | Mit `BRAND_ARCHIVED` abgelehnt |
| Abonnement für eines ihrer Produkte erstellen | Mit `BRAND_ARCHIVED` abgelehnt |

Archivierte Brands werden in Brand-Auswahllisten ausgeblendet, sodass Sie ihnen keine neuen Datensätze zuweisen können. Sie bleiben als Filter in Analytics verfügbar, damit Ihre Berichterstattung pro Brand für den Zeitraum, in dem die Brand aktiv war, vollständig bleibt. Siehe [Analytics](/features/analytics).

### Über die API archivieren

Rufen Sie den Archivierungsendpunkt mit der Brand, die Sie stilllegen, und der Brand, die sie übernimmt, auf:

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

Die Antwort gibt an, was verschoben wurde, sodass Sie das Ergebnis bestätigen können:

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

Um Brands einschließlich der archivierten Brands aufzulisten, setzen Sie `include_archived` im List-Endpunkt. Archivierte Brands werden standardmäßig ausgeschlossen. Jede Brand enthält ein Feld `archived_at`, das `null` lautet, solange die Brand aktiv ist.

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

Weitere Informationen zum vollständigen Request- und Response-Schema finden Sie in der API-Referenz zu [Archive Brand](/api-reference/brands/archive-brand) sowie unter [Error Codes](/api-reference/error-codes) zu den Fehlern, die dieser Endpunkt zurückgibt.
