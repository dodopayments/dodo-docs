## Neue Funktionen

### 1. **Unterstützung für Drittanbieter-Analysen**

Verfolge das Kundenverhalten im Storefront, Checkout und im Kundenportal mit Google Analytics 4, Google Tag Manager und Meta Pixel. Füge deine Tracking-IDs in **Einstellungen → Analysen** hinzu, um E-Commerce-Ereignisse zu sammeln.

**Unterstützte Plattformen**

| Plattform | ID-Format |
|----------|-----------|
| Google Analytics 4 | `G-XXXXXXXXXX` |
| Google Tag Manager | `GTM-XXXXXXX` |
| Meta Pixel | Numerisch (10-20 Ziffern) |

**Verfolgte Ereignisse**

Ereignisse wie `purchase`, `add_payment_info`, `view_item` und `view_item_list` werden automatisch an deine Analyseplattformen gesendet, während Kunden browsen und Einkäufe abschließen.

<Check>
Unterstützt auf Storefront, gehostetem Checkout, Overlay/Inline-Checkout und Kundenportal.
</Check>

Erfahre mehr: [Drittanbieter-Analysen](/features/analytics)

### 2. **Anpassung des Checkout-Themes**

Passe das Erscheinungsbild des Checkouts über den `customization.theme_config`-Parameter bei der Erstellung von Checkout-Sitzungen an. Konfiguriere Farben, Schriftarten, Randradius und Schaltflächentext für hellen und dunklen Modus.

**Konfigurationsoptionen**

| Eigenschaft | Beschreibung |
|----------|-------------|
| `light` / `dark` | Farbschemata für jeden Modus |
| `font_primary_url` | Benutzerdefinierte Schriftarten-URL |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius` | Randradius (z.B. `8px`) |
| `pay_button_text` | Benutzerdefinierter Schaltflächentext |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

Erfahre mehr: [Anpassung des Checkout-Themes](/features/checkout#checkout-theme-customization)

### 3. **Verhinderung von Planänderungen bei Zahlungsfehlern**

Neuer `on_payment_failure`-Parameter für Änderungen am Abonnementplan steuert das Verhalten, wenn eine Zahlung fehlschlägt.

| Modus | Verhalten |
|------|----------|
| `prevent_change` | Abonnement im aktuellen Plan behalten, bis die Zahlung erfolgreich ist |
| `apply_change` | Planänderung sofort anwenden, unabhängig vom Zahlungsergebnis (Standard) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
Verwende `prevent_change` für kritische Upgrades, bei denen du sicherstellen möchtest, dass die Zahlung erfolgt, bevor der Zugriff auf Premium-Funktionen gewährt wird.
</Tip>

Erfahre mehr: [Umgang mit Zahlungsfehlern](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## API-Updates

### Bilanz-Ledger-API

Neuer `GET /balances/ledger`-Endpunkt, um die Ledger-Einträge deines Kontos mit Filterung und Seitenzahlen abzurufen.

| Parameter | Beschreibung |
|-----------|-------------|
| `created_at_gte` / `created_at_lte` | Nach Datumsbereich filtern |
| `event_type` | Filtern nach `payment`, `refund`, `dispute`, `payout`, etc. |
| `currency` | Filtern nach Währungs-Code |
| `reference_object_id` | Filtern nach spezifischer Zahlungs-/Rückerstattungs-/Streit-ID |

Erfahre mehr: [Bilanz-Ledger-API](/api-reference/balance-ledger/list-ledger-entries)

### Zahlungsantwort: `refund_status`

Neues `refund_status`-Feld in der `GET /payments/{paymentId}`-Antwort hinzugefügt, um schnell zu überprüfen, ob eine Zahlung zurückerstattet wurde, ohne den Rückerstattungs-Endpunkt separat abzufragen.
