## Neue Funktionen

### 1. **Produktanalysen auf Produktebene**

Jedes Produkt hat jetzt sein eigenes **dediziertes Analyse-Dashboard**. Navigiere zu **Produkte > [Produkt auswählen]**, um detaillierte Kennzahlen zu diesem Produkt abzurufen, die über fünf Registerkarten organisiert sind:

<Frame>
<img src="/images/product-analytics/overview.png" alt="Produktanalysen auf Produktebene" />
</Frame>

| Registerkarte | Was Sie erhalten |
|---------------|----------------|
| **Überblick** | Gesamteinnahmen, Anzahl erfolgreicher Zahlungen, 30-Tage-Einnahmetrenddiagramm (täglich oder kumulativ) und eine filterbare Transaktionstabelle |
| **Kunden** | Die 3 besten Kunden nach Ausgaben mit einer Podiumsansicht sowie einer vollständigen Kundenaufstellungstabelle |
| **Retention** | Kundenabwanderungsrate, Umsatzabwanderungsrate und ein doppellinien Trenddiagramm, um Muster zu erkennen |
| **Abonnenten** | Alle Abonnements für das Produkt mit Status, Startdatum, nächstem Abrechnungsdatum und Betrag |
| **MRR** | Diagramm der monatlich wiederkehrenden Einnahmen mit Aufschlüsselung nach Neuem MRR, Erweiterungs-MRR, Abwanderungs-MRR und Net New MRR |

Alle Registerkarten unterstützen einen **Datumsfilter** (standardmäßig auf Alle Zeit eingestellt), damit Sie in jeden beliebigen Zeitraum eintauchen können.

<Tip>
Verwenden Sie die Registerkarte Retention, um Produkte mit hoher Abwanderung frühzeitig zu identifizieren, und die MRR-Registerkarte, um zu verfolgen, ob der Erweiterungsumsatz die abgewanderten Einnahmen von Monat zu Monat übersteigt.
</Tip>

### 2. **Verifi RDR Unterstützung bei Dodo Payments**

Dodo Payments unterstützt jetzt **Visa Rapid Dispute Resolution (RDR)**, das von Verifi unterstützt wird – ein automatisiertes Streitbeilegungstool, das berechtigte Visa-Streitigkeiten **bevor sie formelle Rückbuchungen werden** löst. Wenn ein Karteninhaber einen Streit eröffnet, wird dieser von RDR abgefangen und automatisch eine Rückerstattung ausgestellt, wenn die Transaktion unter Ihrem konfigurierten USD-Schwellenwert liegt.

**Warum es wichtig ist**

| Vorteil | Auswirkung |
|---------|-----------|
| **Niedrigere Streitquote** | RDR-gelöste Streitigkeiten zählen nicht zur Visa-Schwelle von 0,9 % |
| **Keine Streitgebühren** | Vermeiden Sie nicht erstattungsfähige Gebühren von 15 bis 25 USD pro Streitigkeit |
| **Null betrieblicher Aufwand** | Keine Beweisbeschaffung oder Fristen für Antworten |
| **Besseres Kundenerlebnis** | Karteninhaber erhalten sofortige Rückerstattungen |
| **Kontoschutz** | Halten Sie sich aus dem Visa-Streitüberwachungsprogramm (VDMP) heraus |

<Warning>
Das Überschreiten der Visa-Streitquote von 0,9 % oder 100 Streitigkeiten/Monat löst das VDMP aus, mit steigenden Strafen von bis zu 50.000 USD+/Monat. RDR hilft Ihnen, gut unter diesen Schwellenwerten zu bleiben.
</Warning>

**So funktioniert es**

1. Karteninhaber eröffnet einen Streit bei seiner Bank
2. RDR fängt den Streit ab, bevor er eine formelle Rückbuchung wird
3. Wenn der Transaktionsbetrag bei oder unter Ihrem Schwellenwert liegt, wird automatisch eine Rückerstattung ausgestellt
4. Der Streit wird sofort gelöst und **zählt nicht** gegen Ihre Streitquote

<Info>
Durch RDR automatisch rückerstattete Transaktionen erscheinen als **verlorene Streitigkeit** in Ihrem Dodo Payments-Dashboard. Das ist zu erwarten – die Rückerstattung wurde automatisch ausgestellt, um eine formelle Rückbuchung zu verhindern.
</Info>

Um Verifi RDR für Ihr Konto zu aktivieren, kontaktieren Sie **support@dodopayments.com** zur Konfiguration Ihres Schwellenwerts.

Erfahren Sie mehr: [Visa RDR Dokumentation](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

Einführung des brandneuen **DodoPayments CLI** (`dodopayments-cli`) – verwalten Sie Ihren gesamten Dodo Payments Workflow direkt vom Terminal. Entwickelt für Entwickler, die die Befehlszeile bevorzugen, ermöglicht das CLI die Verwaltung von Produkten, Zahlungen, Kunden, Rabatten, Lizenzen, Add-Ons, Rückerstattungen und sogar die Erstellung von Checkout-Sitzungen, ohne Ihren Editor zu verlassen.

**Installation**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Wichtige Befehle**

| Befehl | Beschreibung |
|---------|-------------|
| `dodo login` | Mit Ihrem API-Schlüssel authentifizieren (öffnet den Browser) |
| `dodo products list` | Alle Produkte auflisten |
| `dodo payments list` | Alle Zahlungen auflisten |
| `dodo customers create` | Neuen Kunden erstellen |
| `dodo checkout new` | Eine Checkout-Sitzung erstellen und die URL abrufen |
| `dodo wh listen` | Live-Test-Webhooks an Ihren lokalen Server über WebSocket weiterleiten |
| `dodo wh trigger` | Mock-Webhooks payloads an einen beliebigen Endpunkt senden |

**Webhook-Testing**

Das CLI enthält zwei leistungsstarke Tools zur Entwicklung:

- **`dodo wh listen`** – Öffnet eine WebSocket-Verbindung, um Echtzeit-Test-Webhooks an Ihren lokalen Server weiterzuleiten und dabei die ursprünglichen Header für Tests zur Signaturprüfung zu bewahren.
- **`dodo wh trigger`** – Sendet Mock-Webhooks-Payloads interaktiv, unterstützt alle 22 Ereignistypen über Abonnements, Zahlungen, Rückerstattungen, Streitigkeiten und Lizenzen.

<Tip>
Der Webhook-Listener funktioniert nur mit einem **Testmodus** API-Schlüssel. Stellen Sie sicher, dass Sie mit einem Testmodus-Schlüssel angemeldet sind, bevor Sie `dodo wh listen` verwenden.
</Tip>

Erfahren Sie mehr: [CLI Dokumentation](/developer-resources/sdks/cli)

### 5. **Zahlungsmethode im Inline-Checkout aktualisieren**

Der [Inline-Checkout](/developer-resources/inline-checkout) unterstützt jetzt **Zahlungsmethode-Updates** für Abonnements. Wenn ein Kunde seine Zahlungsmethode aktualisieren muss (für ein aktives Abonnement oder um ein auf halt gesetztes Abonnement zu reaktivieren), kann der Update-Zahlungsmethoden-Workflow jetzt direkt innerhalb Ihres Seitendesigns mit Inline-Checkout angezeigt werden – und bietet ein nahtloses, eingebettetes Erlebnis.

**So funktioniert es**

1. Rufen Sie die Update-Zahlungsmethoden-API auf, um ein `payment_link` zu erhalten:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Verwenden Sie das zurückgegebene `payment_link` als `checkoutUrl` im Inline-Checkout:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

Der Inline-Rahmen rendert nur das Formular zur Erfassung der Zahlungsmethode, sodass Kunden neue Kartendaten eingeben oder eine gespeicherte Zahlungsmethode auswählen können, ohne Ihre Seite zu verlassen.

<Tip>
Bei auf Halt gesetzten Abonnements erstellt der Update-Zahlungsmethoden-Workflow automatisch eine Belastung für ausstehende Zahlungen. Überwachen Sie die `payment.succeeded` und `subscription.active`-Webhooks, um die Reaktivierung zu bestätigen.
</Tip>

Erfahren Sie mehr: [Inline-Checkout](/developer-resources/inline-checkout) | [Zahlungsmethoden-Updates für Abonnements](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Unterstützung der Vorbefüllung der Steuer-ID für Checkout-Sitzungen**

Sie können jetzt die **Steuer-ID** (z.B. USt-Nummer, GST-Nummer) vorbefüllen, wenn Sie eine Checkout-Sitzung unter Verwendung des `tax_id`-Parameters erstellen. Dies ist ideal für B2B-Transaktionen, bei denen Sie die Steueridentifikationsnummer des Kunden bereits kennen. Wenn eine Steuer-ID vorbefüllt ist, wird das Feld im Checkout-Formular vorausgefüllt und gesperrt.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Das `tax_id`-Parameter erfordert ein `billing_address` mit mindestens einem `country`-Feld. Die Steuerberechtigung wird in Echtzeit validiert, und die Umkehrsteuerregeln werden automatisch auf qualifizierte B2B-Transaktionen angewendet.
</Info>

Verwenden Sie das `allow_customer_editing_tax_id`-Feature-Flag, um zu steuern, ob Kunden die vorbefüllte Steuer-ID bearbeiten können, und `allow_tax_id`, um die Sichtbarkeit der Steuer-ID beim Checkout umzuschalten.

Erfahren Sie mehr: [Checkout-Sitzungen - Steuer-ID](/developer-resources/checkout-session) | [B2B-Zahlungen](/features/b2b-payments)

### 7. **Lizenzschlüssel und E-Mail in der Rückkehr-URL-Weiterleitung**

Nachdem ein Kunde den Checkout abgeschlossen hat, fügt Dodo Payments jetzt `license_key` und `email` als Abfrageparameter zu Ihrer `return_url`-Weiterleitung hinzu, zusätzlich zu den vorhandenen `payment_id`/`subscription_id` und `status`-Parametern.

**Hinzugefügte Abfrageparameter**

| Parameter | Typ | Bedingung |
|-----------|-----|-----------|
| `payment_id` | `string` | Immer vorhanden bei Einmalzahlungen |
| `subscription_id` | `string` | Immer vorhanden bei Abonnementzahlungen |
| `status` | `string` | Immer vorhanden |
| `license_key` | `string` | Vorhanden, wenn das Produkt Lizenzschlüssel aktiviert hat (durch Kommas getrennt für mehrere) |
| `email` | `string` | Vorhanden, wenn der Kunde eine E-Mail im System hat |

**Beispiel-Redirect-URLs:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Verwenden Sie diese Abfrageparameter, um Lizenzschlüssel anzuzeigen oder eine Bestätigungs-E-Mail sofort auf Ihrer Rückkehrseite zu senden, ohne einen zusätzlichen API-Aufruf zu benötigen.
</Tip>

Erfahren Sie mehr: [Checkout-Sitzungen - Rückkehr-URL](/developer-resources/checkout-session) | [Lizenzschlüssel in der Rückkehr-URL](/features/license-keys#license-keys-in-return-url)

### 8. **API zur Aktualisierung der Kunden-Email**

Der `PATCH /customers/{customer_id}`-Endpunkt unterstützt jetzt das programmgesteuerte Aktualisieren von Kunden-E-Mail-Adressen. Aktualisieren Sie die E-Mail zusammen mit Namen, Telefonnummer und Metadaten in einem einzigen API-Aufruf.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Aktualisierbare Felder**

| Feld | Typ | Beschreibung |
|------|------|-------------|
| `email` | `string \| null` | E-Mail-Adresse des Kunden |
| `name` | `string \| null` | Anzeige-Name des Kunden |
| `phone_number` | `string \| null` | Telefonnummer im internationalen Format |
| `metadata` | `object \| null` | Benutzerdefinierte Schlüssel-Wert-Paare |

<Info>
Aktualisierungen der Kunden-E-Mail sind auch über das Kundenportal (Self-Service), das Dashboard und das CLI über `dodo customers update` verfügbar.
</Info>

Erfahren Sie mehr: [Kundenaktualisierungs-API](/api-reference/customers/patch-customer) | [Kundenmanagement](/features/customers)

### 9. **Bun Adapter Veröffentlichung**

Einführung von `@dodopayments/bun` – einem speziellen Framework-Adapter für [Bun's](https://bun.sh) native Server (`Bun.serve()`). Integrieren Sie Checkout, Kundenportal und Webhooks mit Bun in nur wenigen Zeilen Code.

**Installation**

```bash
bun add @dodopayments/bun
```

**Schnelleinrichtung**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Der Bun-Adapter unterstützt alle drei Checkout-Methoden (statisch, dynamisch und sitzungsbasiert), die Erstellung von Kundenportal-Sitzungen und eine sichere Webhook-Verwaltung mit Signaturprüfung und Zod-Validierung über 22 Ereignistypen.

</Check>
