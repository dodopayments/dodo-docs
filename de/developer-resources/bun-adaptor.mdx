## Installation

<Steps>
<Step title="Install the package">
Führen Sie den folgenden Befehl im Stammverzeichnis Ihres Projekts aus:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
Erstellen Sie eine <code>.env</code>-Datei im Stammverzeichnis Ihres Projekts:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
Committen Sie Ihre <code>.env</code>-Datei oder Geheimnisse niemals in die Versionsverwaltung.
</Warning>
</Step>
</Steps>

## Beispiele für Route-Handler

<Info>
Alle Beispiele setzen voraus, dass Sie den nativen Server von Bun mit <code>Bun.serve()</code> verwenden.
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  Verwenden Sie diesen Handler, um den Checkout von Dodo Payments in Ihren Bun-Server zu integrieren. Unterstützt statische (GET), dynamische (POST) und sitzungsbasierte (POST) Zahlungsabläufe.
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>

## Checkout-Route-Handler

<Info>
Dodo Payments unterstützt drei Arten von Zahlungsabläufen zur Integration von Zahlungen in Ihre Website. Dieser Adapter unterstützt alle Arten von Zahlungsabläufen.
</Info>

- **Statische Payment Links:** Sofort teilbare URLs für die schnelle Zahlungserfassung ohne Code.
- **Dynamische Payment Links:** Generieren Sie programmgesteuert Payment Links mit benutzerdefinierten Details über die API oder SDKs.
- **Checkout Sessions:** Erstellen Sie sichere, anpassbare Checkout-Erlebnisse mit vorkonfigurierten Produktwarenkörben und Kundendaten.

### Antwortformat
Der statische Checkout gibt eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Übergeben Sie die Parameter als JSON-Body in einer POST-Anfrage.
- Unterstützt sowohl einmalige als auch wiederkehrende Zahlungen.
- Eine vollständige Liste der unterstützten Felder im POST-Body finden Sie unter:
  - [Request body for a One Time Payment Product](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Request body for a Subscription Product](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Antwortformat
Der dynamische Checkout gibt eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Checkout Sessions bieten ein sichereres, gehostetes Checkout-Erlebnis, das den vollständigen Zahlungsablauf sowohl für einmalige Käufe als auch für Abonnements abwickelt und dabei umfassende Anpassungsmöglichkeiten bietet.

Weitere Informationen und eine vollständige Liste der unterstützten Felder finden Sie im [Checkout Sessions Integration Guide](https://docs.dodopayments.com/developer-resources/checkout-session).

### Antwortformat
Checkout Sessions geben eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Customer Portal-Route-Handler

Der Customer Portal-Route-Handler ermöglicht die nahtlose Integration des Customer Portals von Dodo Payments in Ihre Bun-Serveranwendung.

### Query-Parameter
<ParamField query="customer_id" type="string" required>
Die Kunden-ID für die Portalsitzung (z. B. <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Bei Einstellung auf <code>true</code> wird dem Kunden eine E-Mail mit dem Portal-Link gesendet.
</ParamField>

<Warning>
Gibt 400 zurück, wenn <code>customer_id</code> fehlt.
</Warning>

## Webhook-Route-Handler

- **Methode:** Nur POST-Anfragen werden unterstützt. Andere Methoden geben 405 zurück.
- **Signaturüberprüfung:** Überprüft die Webhook-Signatur mithilfe von <code>webhookKey</code>. Gibt 401 zurück, wenn die Überprüfung fehlschlägt.
- **Payload-Validierung:** Wird mit Zod validiert. Gibt 400 für ungültige Payloads zurück.
- **Fehlerbehandlung:**
  - 401: Ungültige Signatur
  - 400: Ungültige Payload
  - 500: Interner Fehler bei der Überprüfung
- **Ereignis-Routing:** Ruft den entsprechenden Event-Handler basierend auf dem Payload-Typ auf.
