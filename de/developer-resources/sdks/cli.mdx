Verwalten Sie Ihre Dodo Payments-Ressourcen, erstellen Sie Checkout-Sitzungen und testen Sie Webhooks direkt über das Terminal. Entwickelt für Entwickler, die die Befehlszeile bevorzugen.

## Installation

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Manuelle Installation

1. Laden Sie die neueste Version von [GitHub Releases](https://github.com/dodopayments/dodopayments-cli/releases) für Ihr System herunter
2. Extrahieren und benennen Sie die Binärdatei in `dodo` um
3. Verschieben Sie sie in ein Verzeichnis in Ihrem PATH:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## Authentifizierung

Bevor Sie die CLI verwenden, authentifizieren Sie sich mit Ihrem API-Schlüssel:

```bash
dodo login
```

Dies wird:
1. Ihren Browser zur Seite Dodo Payments API-Schlüssel öffnen
2. Sie auffordern, Ihren API-Schlüssel einzugeben
3. Sie fragen, welche Umgebung (**Testmodus** oder **Live-Modus**) Sie auswählen möchten
4. Ihre Anmeldeinformationen lokal in `~/.dodopayments/api-key` speichern

<Info>
Die CLI unterstützt das Speichern eines API-Schlüssels pro Umgebung. Wenn sowohl Test- als auch Live-Modusschlüssel konfiguriert sind, werden Sie aufgefordert, auszuwählen, welche Umgebung für die aktuelle Sitzung verwendet werden soll.
</Info>

## Verwendung

Die allgemeine Syntax ist:

```bash
dodo ‹category› ‹sub-command›
```

Das Ausführen von `dodo` ohne Argumente zeigt alle verfügbaren Kategorien an. Das Ausführen von `dodo <category>` ohne Unterbefehl zeigt die verfügbaren Unterbefehle für diese Kategorie an.

### Produkte

Verwalten Sie Ihren Produktkatalog.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo products list` | Listet alle Produkte auf (paginiert) |
| `dodo products create` | Dashboard öffnen, um ein Produkt zu erstellen |
| `dodo products info` | Details zu einem bestimmten Produkt anzeigen |

### Zahlungen

Zahlungstransaktionen anzeigen.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo payments list` | Listet alle Zahlungen auf (paginiert) |
| `dodo payments info` | Informationen zu einer bestimmten Zahlung abrufen |

### Kunden

Verwalten Sie Ihre Kundenbasis.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo customers list` | Listet alle Kunden auf (paginiert) |
| `dodo customers create` | Erstellt ein neues Kundenprofil |
| `dodo customers update` | Aktualisiert die Daten eines bestehenden Kunden |

### Rabatte

Verwalten Sie Gutscheine und Rabatte.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo discounts list` | Listet alle Rabatte auf (paginiert) |
| `dodo discounts create` | Erstellt einen neuen prozentualen Rabatt |
| `dodo discounts delete` | Entfernt einen Rabatt nach ID |

### Lizenzen

Verwalten Sie Softwarelizenzen.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo licences list` | Listet alle Lizenzschlüssel auf (paginiert) |

### Addons

Verwalten Sie Produkt-Addons.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo addons list` | Listet alle Addons auf (paginiert) |
| `dodo addons create` | Dashboard öffnen, um ein Addon zu erstellen |
| `dodo addons info` | Details zu einem bestimmten Addon anzeigen |

### Rückerstattungen

Rückerstattungsinformationen anzeigen.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo refund list` | Listet alle Rückerstattungen auf (paginiert) |
| `dodo refund info` | Details zu einer bestimmten Rückerstattung anzeigen |

### Checkout

Erstellen Sie Checkout-Sitzungen.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo checkout new` | Erstellt eine neue Checkout-Sitzung und erhält die Checkout-URL |

Der Checkout-Befehl unterstützt erweiterte Optionen, einschließlich minimaler Adresssammlung, Rück-URL, Durchsetzung von 3D Secure, Rabattcodes und Metadaten.

## Webhook-Tests

Die CLI enthält zwei leistungsstarke Tools zum Testen von Webhooks während der Entwicklung: einen **Listener**, der Live-Test-Webhooks an Ihren lokalen Server weiterleitet, und einen **Trigger**, der gefälschte Webhook-Payloads an einen beliebigen Endpunkt sendet.

### Webhooks abhören

Leiten Sie Webhooks von Dodo Payments direkt an Ihren lokalen Entwicklungsserver in Echtzeit weiter.

```bash
dodo wh listen
```

<Steps>
<Step title="Geben Sie Ihre lokale Endpunkt-URL ein">
  Geben Sie die lokale URL an, an der Sie Webhooks empfangen möchten (z.B. `http://localhost:3000/webhook`).
</Step>

<Step title="Automatische Einrichtung">
  Die CLI erstellt automatisch einen Webhook-Endpunkt auf Ihrem Dodo Payments-Konto, falls noch keiner vorhanden ist, und öffnet dann eine WebSocket-Verbindung, um Ereignisse in Echtzeit zu empfangen.
</Step>

<Step title="Empfangen und weiterleiten">
  Wenn ein Webhook-Ereignis auftritt (z.B. bei einer Testzahlung, einer Änderung des Abonnements usw.), empfängt die CLI es, protokolliert den Ereignistyp und leitet die vollständige Anfrage mit Headern und Body an Ihren lokalen Endpunkt weiter. Die Antwort von Ihrem Endpunkt wird protokolliert und zurückgesendet.
</Step>
</Steps>

<Warning>
Der Webhook-Listener funktioniert nur mit einem **Testmodus** API-Schlüssel. Stellen Sie sicher, dass Sie mit einem Testmodus-Schlüssel angemeldet sind, bevor Sie `dodo wh listen` verwenden.
</Warning>

<Tip>
Der Listener bewahrt die originalen Webhook-Header (`webhook-id`, `webhook-signature`, `webhook-timestamp`) beim Weiterleiten an Ihren lokalen Endpunkt, sodass Sie Ihre Logik zur Signaturverifizierung testen können.
</Tip>

### Trigger-Test-Webhooks

Senden Sie gefälschte Webhook-Payloads an einen beliebigen Endpunkt für schnelle Tests, ohne echte Transaktionen erstellen zu müssen.

```bash
dodo wh trigger
```

Dies führt Sie durch:
1. Festlegen einer Ziel-**Endpunkt-URL**
2. Optional Konfiguration von **Business-ID**, **Produkt-ID** und **Metadaten**
3. Auswahl eines bestimmten **Ereignisses** aus einem interaktiven Menü
4. Senden der gefälschten Payload und Anzeige der Antwort

Nach jedem Ereignis können Sie ein weiteres Ereignis auslösen oder beenden – sodass es einfach ist, mehrere Ereignishandler in einer Sitzung zu testen.

<Warning>
Das Trigger-Tool sendet gefälschte Payloads ohne Webhook-Signaturen. Deaktivieren Sie die Überprüfung der Webhook-Signatur während des Tests, indem Sie `unsafe_unwrap()` anstelle von `unwrap()` in Ihrem Webhook-Handler verwenden.
</Warning>

### Unterstützte Webhook-Ereignisse

| Kategorie | Ereignisse |
|----------|--------|
| **Abonnement** | `subscription.active`, `subscription.updated`, `subscription.on_hold`, `subscription.renewed`, `subscription.plan_changed`, `subscription.cancelled`, `subscription.failed`, `subscription.expired` |
| **Zahlung** | `payment.success`, `payment.failed`, `payment.processing`, `payment.cancelled` |
| **Rückerstattung** | `refund.success`, `refund.failed` |
| **Streitfall** | `dispute.opened`, `dispute.expired`, `dispute.accepted`, `dispute.cancelled`, `dispute.challenged`, `dispute.won`, `dispute.lost` |
| **Lizenz** | `licence.created` |

### Umgebungsvariablen

| Variable | Beschreibung |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Überschreibt die Standard-Webhook-Relay-Server-URL, die von `dodo wh listen` verwendet wird |
