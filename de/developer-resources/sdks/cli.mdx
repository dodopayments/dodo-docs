Verwalte deine Dodo Payments-Ressourcen, führe KI-gestützte Abfragen für dein Konto aus, erstelle Checkout-Sitzungen und teste Webhooks — alles über das Terminal. Die CLI verfügt über eine interaktive TUI, einen integrierten KI-Assistenten powered by MCP sowie Offline-Webhook-Tests.

## Funktionen

- **Interaktive TUI** — starte `dodo` ohne Argumente, um die vollständige interaktive Oberfläche mit Befehlspalette, Verlauf und Live-Benachrichtigungen zu öffnen.
- **Integrierter KI-Assistent** — stelle Fragen oder führe Aktionen in natürlicher Sprache mit `/ai` aus. Keine zusätzliche Einrichtung erforderlich, läuft lokal mit `dodopayments-mcp`.
- **Standardmäßig sicher** — API keys werden im Geheimnisspeicher deines Betriebssystems abgelegt (macOS Keychain, Windows Credential Vault, Linux libsecret). Keine Klartextkonfiguration auf der Festplatte.
- **Automatische Aktualisierung** — die CLI sucht beim Start nach neuen Versionen und benachrichtigt dich in der App. Führe `/update` aus, um direkt zu aktualisieren.
- **Webhook-Tools** — empfange Live-Webhooks oder löse Payloads für die lokale Entwicklung offline aus.

## Installation

Installiere die CLI mit einer einzigen Zeile unter macOS oder Linux:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### Mit npm oder Bun installieren

Wenn du bereits Node oder Bun verwendest, installieren die Paketmanager immer die neueste Version:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Manuelle Installation (keine Node-/Bun-Installation erforderlich)

Wenn du lieber kein entferntes Skript an `sh` weiterleiten möchtest, lade die Binärdatei selbst herunter.

<Steps>
<Step title="Download the binary">
  Lade die Binärdatei für deine Plattform aus dem neuesten [GitHub Release](https://github.com/dodopayments/dodopayments-cli/releases) herunter.

  | Plattform | Binärdatei |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  Unter Windows erfordert das Verschieben nach `C:\Windows\System32` Administratorrechte.
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  Jede Version veröffentlicht einen `SHA256SUMS.txt`. Überprüfe deinen Download mit:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## Authentifizierung

Melde dich vor der Verwendung authentifizierter Befehle mit deinem API key an:

```bash
dodo login
```

Oder innerhalb der interaktiven TUI:

```text
/login
```

Der Anmeldevorgang:

1. Öffnet deinen Browser auf der Seite für Dodo Payments API Keys.
2. Fordert dich auf, deinen API Key einzufügen.
3. Bittet dich, eine Umgebung auszuwählen — **Test Mode** oder **Live Mode**.
4. Speichert die Zugangsdaten im Geheimnisspeicher deines Betriebssystems (Keychain unter macOS, Credential Vault unter Windows, libsecret unter Linux).

<Info>
Da die Zugangsdaten im Geheimnisspeicher des Betriebssystems gespeichert werden, wirst du möglicherweise beim ersten Lesen oder Schreiben von Zugangsdaten durch die CLI nach deinem **Gerätepasswort** gefragt. Wenn du von einer älteren Version aktualisierst, wird ein vorhandener API key automatisch **in den Geheimnisspeicher migriert und die alte Datei gelöscht**.
</Info>

### Modi wechseln und abmelden

Du kannst gleichzeitig jeweils einen authentifizierten Schlüssel für **Test Mode** und **Live Mode** speichern. So löschst du Zugangsdaten:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

Beim Abmeldevorgang kannst du unabhängig zwischen **All accounts**, **Test Mode** und **Live Mode** wählen.

## Verwendung

Du kannst die CLI in zwei Modi verwenden.

### 1. Interaktive TUI (empfohlen)

Führe `dodo` ohne Argumente aus, um die vollständige interaktive Oberfläche zu starten:

```bash
dodo
```

Gib `/` ein, um die Befehlspalette zu öffnen, oder beginne einfach zu tippen — alles, was kein Slash-Befehl ist, wird an den KI-Assistenten gesendet.

| Befehl | Beschreibung |
|---------|-------------|
| `/help` | Befehlsreferenz anzeigen |
| `/update` | Nach einem CLI-Update suchen und es installieren |
| `/login` | Mit einem API key authentifizieren |
| `/logout` | Von einer oder allen Umgebungen abmelden |
| `/clear` | TUI-Bildschirm leeren |
| `/exit` | TUI beenden (auch: `exit` eingeben oder `Esc` zweimal drücken) |

### 2. Direkte Unterbefehle

Führe Befehle direkt aus, ohne die TUI zu öffnen:

```bash
dodo <category> <sub-command> [args...]
```

Beispiel:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

Die folgenden Referenztabellen zeigen alle Befehle. Setze ihnen in der TUI `/` voran; lasse `/` im direkten Modus weg.

## KI-Assistent

Stelle Fragen oder führe Aktionen in natürlicher Sprache aus. Der Assistent verwendet `dodopayments-mcp`, das lokal ausgeführt wird — keine zusätzliche Einrichtung oder OAuth-Ablauf erforderlich. Dein KI-Datenverkehr verlässt dein Gerät nur zur Kommunikation mit dem Modellanbieter.

| Befehl | Beschreibung |
|---------|-------------|
| `/ai <query>` | Dem KI-Assistenten eine Frage stellen oder eine Anweisung geben |
| _(beliebiger Text ohne Slash)_ | Wird in der TUI standardmäßig an den KI-Assistenten gesendet |

Beispiele:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
Der Assistent berücksichtigt deine aktive Umgebung (Test / Live) und arbeitet daher nur mit Daten aus der Umgebung, in der du aktuell angemeldet bist.
</Tip>

## Projektgerüst

`dodo init` erstellt Dodo Payments-Abrechnungsrouten direkt in einem vorhandenen Projekt. Der Befehl generiert die erforderlichen Route-Dateien, installiert das passende `@dodopayments/*`-Adapterpaket und schreibt die `DODO_PAYMENTS_*`-Umgebungsvariablen sicher in deine `.env` (es werden nur Variablen angehängt, die noch nicht vorhanden sind). Der Befehl läuft **ohne Anmeldung**.

```bash
dodo init <framework>
```

| Gerüst | Beschreibung |
|----------|-------------|
| `dodo init nextjs` | Erstellt Abrechnungsrouten für den Next.js App Router (Checkout, Kundenportal und Webhook-Handler) mit `@dodopayments/nextjs` |
| `dodo init express` | Erstellt Abrechnungsrouten für einen Express-Server mit `@dodopayments/express` |
| `dodo init better-auth` | Erstellt eine Better-Auth-Pluginkonfiguration mit `@dodopayments/better-auth` |

Für das Better-Auth-Gerüst kannst du eine durch Kommas getrennte Liste von Plugins übergeben, die generiert werden sollen (standardmäßig alle): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
Das Gerüst erkennt automatisch ein `src/`-Verzeichnis und passt die Ausgabepfade entsprechend an. Außerdem wird dein Paketmanager automatisch erkannt (`bun`, `pnpm`, `yarn` oder `npm`), um den richtigen Installationsbefehl auszuführen.
</Info>

## Webhooks

Die CLI enthält zwei leistungsstarke Tools zum Testen von Webhooks während der Entwicklung: einen **Listener**, der Live-Test-Webhooks an deinen lokalen Server weiterleitet, und einen **Trigger**, der simulierte Webhook-Payloads an jeden Endpunkt sendet.

| Befehl | Beschreibung |
|---------|-------------|
| `dodo wh listen` | Webhooks in Echtzeit empfangen und an deinen lokalen Entwicklungsserver weiterleiten |
| `dodo wh trigger` | Interaktiv ein Test-Webhook-Ereignis auslösen — auch ohne Anmeldung |

### Webhooks empfangen

Leite Webhooks von Dodo Payments in Echtzeit direkt an deinen lokalen Entwicklungsserver weiter.

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  Gib die lokale URL an, unter der du Webhooks empfangen möchtest (z. B. `http://localhost:3000/webhook`).
</Step>

<Step title="Automatic setup">
  Die CLI erstellt automatisch einen Webhook-Endpunkt in deinem Dodo Payments-Konto, falls noch keiner vorhanden ist, und öffnet anschließend eine WebSocket-Verbindung, um Ereignisse in Echtzeit zu empfangen.
</Step>

<Step title="Receive and forward">
  Wenn ein Webhook-Ereignis ausgelöst wird (etwa durch eine Testzahlung oder eine Abonnementänderung), empfängt die CLI es, protokolliert den Ereignistyp und leitet die vollständige Anfrage mit Headern und Body an deinen lokalen Endpunkt weiter. Die Antwort deines Endpunkts wird protokolliert und zurückgesendet.
</Step>
</Steps>

<Warning>
`dodo wh listen` erfordert einen **Test Mode** API key. Live Mode-Schlüssel werden vom Listener nicht unterstützt.
</Warning>

<Tip>
Der Listener bewahrt beim Weiterleiten an deinen lokalen Endpunkt die ursprünglichen Webhook-Header (`webhook-id`, `webhook-signature`, `webhook-timestamp`), damit du deine Logik zur Signaturüberprüfung testen kannst.
</Tip>

### Test-Webhooks auslösen

Sende simulierte Webhook-Payloads für schnelle Tests an einen beliebigen Endpunkt, ohne echte Transaktionen erstellen zu müssen.

```bash
dodo wh trigger
```

Der Ablauf von `/wh trigger` führt dich durch folgende Schritte:

1. Festlegen einer **Endpunkt-URL** als Ziel
2. Auswählen eines bestimmten **Ereignisses**, das über ein interaktives Menü ausgelöst werden soll

<Info>
`dodo wh trigger` erfordert keine Anmeldung. Es funktioniert als lokaler/offline Webhook-Payload-Generator.
</Info>

<Warning>
Ausgelöste Ereignisse sind **nicht signiert**. Deaktiviere während des Testens die Webhook-Signaturüberprüfung an deinem Endpunkt — verwende beispielsweise in deinem Webhook-Handler **nur während des Testens** `unsafe_unwrap()` anstelle von `unwrap()`.
</Warning>

### Unterstützte Webhook-Ereignisse

`dodo wh trigger` kann Mock-Payloads für diese 22 Ereignistypen senden:

| Kategorie | Ereignisse |
|----------|--------|
| **Subscription** | `active`, `updated`, `on_hold`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired` |
| **Payment** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Refund** | `succeeded`, `failed` |
| **Dispute** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **License** | `created` |

<Note>
Dies ist eine Teilmenge der von Dodo Payments bereitgestellten Ereignisse. `payout.*`, `credit.*`, `abandoned_checkout.*`, `dunning.*`, `entitlement_grant.*`, `subscription.paused` und `subscription.update_payment_method` verfügen noch über keinen Mock-Generator – teste sie mit echten Aktivitäten im Testmodus und `dodo wh listen`. Die vollständige Liste findest du unter [Webhook-Ereignisse](/developer-resources/webhooks/intents/webhook-events-guide).
</Note>

### Umgebungsvariablen

| Variable | Beschreibung |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Überschreibt die standardmäßige URL des Webhook-Relay-Servers, die von `dodo wh listen` verwendet wird |

## Aktualisierungen

Die CLI sucht beim Start nach einer neueren Version und zeigt eine Benachrichtigung in der Statusleiste an, wenn eine verfügbar ist. So führst du ein Upgrade durch:

```text
/update
```

Alternativ kannst du das Installationsprogramm erneut ausführen, um das Upgrade direkt durchzuführen:

<CodeGroup>

```bash install.sh
curl -fsSL https://dodopayments.com/install.sh | sh
```

```bash npm
npm install -g dodopayments-cli
```

