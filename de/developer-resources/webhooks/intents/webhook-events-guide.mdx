Dodo Payments bietet Echtzeit-Webhooks-Benachrichtigungen, um Sie über kritische Ereignisse im Zusammenhang mit Transaktionen, Abonnements, Rückerstattungen, Streitigkeiten und der Verwaltung von Lizenzschlüsseln zu informieren. Im Folgenden finden Sie einen detaillierten Leitfaden zu diesen Ereignissen, die zur Klarheit kategorisiert sind, sowie Implementierungstipps und -überlegungen.

## **Zahlungsevents**

| **Ereignisname**        | **Ereignistyp**          | **Beschreibung**                                                                |
|--------------------------|--------------------------|---------------------------------------------------------------------------------|
| **Zahlung Erfolgreich**  | `payment.succeeded`      | Ausgelöst, wenn eine Zahlung erfolgreich verarbeitet wird.                        |
| **Zahlung Fehlgeschlagen**| `payment.failed`         | Tritt auf, wenn ein Zahlungsversuch aufgrund von Fehlern, abgelehnten Karten oder anderen Problemen fehlschlägt. |
| **Zahlung wird verarbeitet** | `payment.processing`     | Gibt an, dass eine Zahlung gerade verarbeitet wird.                               |
| **Zahlung Abgebrochen**  | `payment.cancelled`      | Ausgelöst, wenn eine Zahlung vor Abschluss abgebrochen wird.                    |

## **Rückerstattungsevents**

| **Ereignisname**        | **Ereignistyp**          | **Beschreibung**                                                                |
|--------------------------|--------------------------|---------------------------------------------------------------------------------|
| **Rückerstattung Erfolgreich** | `refund.succeeded`       | Ausgelöst, wenn eine Rückerstattung erfolgreich verarbeitet wird.                 |
| **Rückerstattung Fehlgeschlagen** | `refund.failed`          | Tritt auf, wenn ein Rückerstattungsversuch aufgrund von Verarbeitungsfehlern oder anderen Problemen fehlschlägt. |

## **Streitigkeitsevents**

| **Ereignisname**        | **Ereignistyp**          | **Beschreibung**                                                                |
|--------------------------|--------------------------|---------------------------------------------------------------------------------|
| **Streitfall Eröffnet**  | `dispute.opened`         | Ausgelöst, wenn ein Kunde einen Streitfall initiiert.                            |
| **Streitfall Abgelaufen** | `dispute.expired`        | Gibt an, dass ein Streitfall ohne Lösung abgelaufen ist.                        |
| **Streitfall Akzeptiert**| `dispute.accepted`       | Ausgelöst, wenn ein Händler den Streitfall akzeptiert.                          |
| **Streitfall Abgebrochen** | `dispute.cancelled`      | Tritt auf, wenn ein Streitfall vom Kunden oder System abgebrochen wird.         |
| **Streitfall Angefochten** | `dispute.challenged`     | Ausgelöst, wenn ein Händler einen Streitfall anficht.                           |
| **Streitfall Gewonnen**   | `dispute.won`            | Gibt an, dass der Händler einen Streitfall erfolgreich gewonnen hat.            |
| **Streitfall Verloren**   | `dispute.lost`           | Tritt auf, wenn der Händler einen Streitfall verliert.                         |

## **Abonnementsevents**

| **Ereignisname**        | **Ereignistyp**          | **Beschreibung**                                                                |
|--------------------------|--------------------------|---------------------------------------------------------------------------------|
| **Abonnement Aktiv**     | `subscription.active`    | Gibt an, dass ein Abonnement jetzt aktiv ist und wiederkehrende Gebühren geplant sind. |
| **Abonnement Aktualisiert** | `subscription.updated`   | Ausgelöst, wenn ein beliebiges Feld des Abonnements aktualisiert wird (Echtzeitsynchronisation ohne Abfragen). |
| **Abonnement Ausgesetzt** | `subscription.on_hold`   | Ausgelöst, wenn ein Abonnement vorübergehend aufgrund gescheiterter Erneuerung ausgesetzt wird. |
| **Abonnement Erneuert**  | `subscription.renewed`   | Tritt auf, wenn ein Abonnement erfolgreich erneuert wird.                       |
| **Abonnement Plan Geändert** | `subscription.plan_changed` | Ausgelöst, wenn ein Abonnement aufgewertet, herabgestuft oder mit unterschiedlichen Zusatzleistungen geändert wird. |
| **Abonnement Abgebrochen** | `subscription.cancelled` | Ausgelöst, wenn ein Abonnement vom Händler oder Kunden abgebrochen wird.        |
| **Abonnement Fehlgeschlagen** | `subscription.failed`    | Gibt an, dass ein Abonnement fehlgeschlagen ist. Das bedeutet, dass wir keinen Mandat erstellen konnten. |
| **Abonnement Abgelaufen** | `subscription.expired`   | Ausgelöst, wenn ein Abonnement das Ende seiner Laufzeit erreicht und abläuft.    |

## **Lizenzschlüsselereignisse**

| **Ereignisname**        | **Ereignistyp**          | **Beschreibung**                                                                |
|--------------------------|--------------------------|---------------------------------------------------------------------------------|
| **Lizenzschlüssel Erstellt** | `license_key.created`    | Ausgelöst, wenn ein neuer Lizenzschlüssel für ein Produkt erstellt wird.        |

Diese Webhook-Ereignisse sind darauf ausgelegt, Händlern kritische Updates zu bieten, um ihre Abläufe effektiv zu verwalten. Implementieren Sie robuste Handler für jedes relevante Ereignis in Ihrer Webhook-Integration, um eine reibungslose und zuverlässige Funktionalität sicherzustellen.
