## Ereignisse zur Wiederherstellung verlassener Warenkörbe

Die folgenden Webhook-Ereignisse verfolgen den Lebenszyklus der Wiederherstellung von verlassenen Warenkörben:

| Ereignis | Beschreibung |
|-------|-------------|
| `abandoned_checkout.detected` | Ein verlassener Checkout wurde erkannt. Gesendet, wenn eine Zahlung als verlassen (fehlgeschlagen oder unvollständig) identifiziert wird und der Wiederherstellungs-Workflow beginnt. |
| `abandoned_checkout.recovered` | Der Kunde hat die Zahlung über den Wiederherstellungslink abgeschlossen. Das Feld `recovered_payment_id` enthält die erfolgreiche Zahlungs-ID. |

### Felder des Payloads für verlassene Checkouts

<ParamField body="payment_id" type="string" required>
Die ursprüngliche Zahlung, die verlassen wurde. Verwenden Sie dies, um Produkt-, Betrags- und Währungsdetails nachzuschlagen.
</ParamField>

<ParamField body="brand_id" type="string" required>
Die Marke, zu der dieser abgebrochene Checkout gehört.
</ParamField>

<ParamField body="customer_id" type="string" required>
Der Kunde, der den Checkout abgebrochen hat.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
Warum der Checkout abgebrochen wurde. Einer der folgenden Werte:
- `payment_failed` — Der Kunde hat eine Zahlung versucht, aber sie ist fehlgeschlagen
- `checkout_incomplete` — Der Kunde hat den Checkout besucht, aber nie eine Zahlung versucht
</ParamField>

<ParamField body="status" type="string" required>
Aktueller Lebenszyklusstatus dieses Wiederherstellungsversuchs. Einer der folgenden Werte:
- `abandoned` — Erkannt, noch keine E-Mails versendet
- `recovering` — Mindestens eine Wiederherstellungs-E-Mail versendet
- `recovered` — Der Kunde hat die Zahlung abgeschlossen
- `exhausted` — Alle E-Mails versendet oder ein neuerer Checkout gefunden
- `opted_out` — Der Kunde hat sich abgemeldet
</ParamField>

<ParamField body="abandoned_at" type="string" required>
ISO-8601-Zeitstempel des Zeitpunkts, zu dem der Checkout als abgebrochen erkannt wurde.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
Die Zahlungs-ID der erfolgreichen Wiederherstellungszahlung. `null`, bis der Checkout wiederhergestellt wurde.
</ParamField>

### Beispiel: Verarbeitung von ACR-Webhooks

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Dunning-Ereignisse

Die folgenden Webhook-Ereignisse verfolgen den Dunning-Lebenszyklus eines Abonnements:

| Ereignis | Beschreibung |
|-------|-------------|
| `dunning.started` | Ein Dunning-Versuch wurde für ein Abonnement erstellt, das den Status `on_hold` erreicht hat oder vom Kunden gekündigt wurde. |
| `dunning.recovered` | Der Kunde hat seine Zahlungsmethode aktualisiert und die daraus resultierende Zahlung war erfolgreich. Das Feld `payment_id` enthält die ID der erfolgreichen Zahlung. |

### Felder der Dunning-Versuch-Payload

<ParamField body="subscription_id" type="string" required>
Das Abonnement, das den Dunning-Versuch ausgelöst hat.
</ParamField>

<ParamField body="brand_id" type="string" required>
Die Marke, zu der dieser Dunning-Versuch gehört.
</ParamField>

<ParamField body="customer_id" type="string" required>
Der Kunde, dem das Abonnement gehört.
</ParamField>

<ParamField body="trigger_state" type="string" required>
Der Abonnementstatus, der das Dunning ausgelöst hat. Einer von:
- `on_hold` — Verlängerungen aufgrund eines fehlgeschlagenen Zahlungsvorgangs gestoppt
- `cancelled` — Der Kunde hat über das Customer Portal gekündigt
</ParamField>

<ParamField body="status" type="string" required>
Aktueller Lebenszyklusstatus dieses Dunning-Versuchs. Einer der folgenden Werte:
- `recovering` — Dunning-E-Mails werden versendet
- `recovered` — Der Kunde hat die Zahlungsmethode aktualisiert und die Zahlung war erfolgreich
- `exhausted` — Alle E-Mails versendet oder der Abonnementstatus hat sich geändert
</ParamField>

<ParamField body="created_at" type="string" required>
ISO-8601-Zeitstempel des Zeitpunkts, zu dem der Dunning-Versuch erstellt wurde.
</ParamField>

<ParamField body="payment_id" type="string | null">
Die Zahlungs-ID der erfolgreichen Wiederherstellungszahlung. `null` während der Wiederherstellung.
</ParamField>

### Beispiel: Verarbeitung von Dunning-Webhooks

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
Abonniere sowohl `dunning.started` als auch `dunning.recovered`, um den vollständigen Dunning-Lebenszyklus zu verfolgen. Verwende `dunning.started`, um Kulanzzeiträume zu pausieren oder in deinem System abonnierten Kunden mit erhöhtem Risiko zu kennzeichnen.
</Tip>
