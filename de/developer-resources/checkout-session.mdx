<Info>
**Session Validity**: Checkout sessions are valid for 24 hours by default. If you pass `confirm=true` in your request, the session will only be valid for 15 minutes.
</Info>

<Warning>
**Single-Use Links**: The `checkout_url` returned by the API is not reusable and expires within 24 hours (or 15 minutes when `confirm=true`). It is intended for a single customer to complete one payment. Generate a fresh checkout session for each customer and each payment attempt rather than sharing or reusing a link.
</Warning>

## Creating Your First Checkout Session

<Tabs>
<Tab title="Node.js SDK">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'pdt_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

### API Response

All methods above return the same response structure:

```json
{
  "session_id": "cks_Gi6KGJ2zFJo9rq9Ukifwa",
  "checkout_url": "https://test.checkout.dodopayments.com/session/cks_Gi6KGJ2zFJo9rq9Ukifwa"
}
```

Nur `session_id` ist garantiert vorhanden. In zwei Fällen werden zusätzliche oder weniger Felder zurückgegeben:

- **`payment_method_id` wurde angegeben** — die Zahlung wird sofort verarbeitet und `checkout_url` ist `null`. Verwende stattdessen das zurückgegebene `payment_id`.
- **`confirm: true` hat die Zahlung zum Zeitpunkt der Sitzungserstellung erstellt** — die Antwort enthält außerdem `payment_id`, `client_secret` und `publishable_key` zur Verwendung mit dem Dodo Payments Checkout SDK.

<Note>
Das generierte `checkout_url` kann nur einmal verwendet werden und läuft innerhalb von 24 Stunden ab. Speichere es nicht zwischen und verwende es nicht für andere Kunden oder Zahlungsversuche erneut — erstelle jedes Mal eine neue Checkout-Sitzung, wenn du einen neuen Link benötigst.
</Note>

<Steps>
<Step title="Get the checkout URL">
Extrahiere `checkout_url` aus der API-Antwort.
</Step>

<Step title="Redirect your customer">
Leite deinen Kunden zur Checkout-URL weiter, um den Kauf abzuschließen.

```javascript
// Redirect immediately
window.location.href = session.checkout_url;

// Or open in new window
window.open(session.checkout_url, '_blank');
```

<Tip>
**Alternative Integrationsoptionen**: Anstatt weiterzuleiten, kannst du den Checkout mit [Overlay Checkout](/developer-resources/overlay-checkout) (modal als Overlay) oder [Inline Checkout](/developer-resources/inline-checkout) (vollständig eingebettet) direkt in deine Seite einbetten. Übergebe in einer nativen mobilen App dieselbe URL an die [Mobile Checkout SDKs](/developer-resources/mobile-integration) für Android, iOS, React Native oder Flutter. Alle diese Optionen verwenden dieselbe Checkout-Sitzungs-URL.
</Tip>
</Step>

Die Query-Parameter enthalten unter anderem die Zahlungs-/Abonnement-ID, den Status, die E-Mail-Adresse des Kunden und alle Lizenzschlüssel. Eine vollständige Liste findest du in der [Dokumentation zu den `return_url`-Parametern](#request-body).

### Erforderliche Felder

<ParamField body="product_cart" type="array" required>
Array der Produkte, die in die Checkout-Sitzung aufgenommen werden sollen. Jedes Produkt muss über eine gültige `product_id` aus deinem Dodo Payments-Dashboard verfügen.

<Tip>
**Gemischter Checkout**: Du kannst Einmalzahlungsprodukte und Abonnementprodukte in derselben Checkout-Sitzung kombinieren. Dadurch werden leistungsstarke Anwendungsfälle wie Einrichtungsgebühren mit Abonnements, Hardwarepakete mit SaaS und vieles mehr ermöglicht.
</Tip>

<Expandable title="Product Cart Item Properties">
<ParamField body="product_id" type="string" required>
Die eindeutige Kennung des Produkts aus deinem Dodo Payments-Dashboard.

**Beispiel:** `"pdt_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
Menge des Produkts.

**Beispiel:** `1` für ein einzelnes Element, `3` für mehrere Einheiten
</ParamField>

<ParamField body="addons" type="array">
Array der Add-ons, die dem Produkt hinzugefügt werden sollen. Nur gültig, wenn das Produkt ein Abonnement ist.

<Expandable title="Addon item properties">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
Betrag, den der Kunde zahlt, wenn pay_what_you_want aktiviert ist. Wenn die Option deaktiviert ist, wird dieses Feld ignoriert.

**Format**: Wird in der kleinsten Einheit der Währung angegeben (z. B. Cent für USD). Um beispielsweise 1,00 $ zu berechnen, übergib `100`.
</ParamField>

<ParamField body="credit_entitlements" type="array">
Überschreibungen pro Checkout-Sitzung für bereits an dieses Produkt angehängte Credit-Berechtigungen. Damit kannst du für diese einzelne Sitzung eine andere Anzahl an Credits gewähren — etwa ein Werbepaket mit 1.000 API-Credits anstelle der standardmäßigen 500 des Produkts — ohne ein separates Produkt zu erstellen.

<Info>
Jede `credit_entitlement_id` muss bereits an das Produkt angehängt sein. Dieses Feld überschreibt nur die `credits_amount`, die bei der Erfüllung dieser Sitzung gewährt wird. Einstellungen auf Produktebene für Credit-Berechtigungen (Ablauf, Übertragung usw.) gelten weiterhin.
</Info>

<Expandable title="Credit entitlement override properties">
<ParamField body="credit_entitlement_id" type="string" required>
ID der zu überschreibenden Credit-Berechtigung. Muss bereits an das Produkt angehängt sein.
</ParamField>

<ParamField body="credits_amount" type="string" required>
Anzahl der Credits, die für diese Checkout-Sitzung gewährt werden sollen und damit die `credits_amount` auf Produktebene überschreiben. Muss größer als null sein.
</ParamField>
</Expandable>
</ParamField>
</Expandable>
</ParamField>

<Tip>
**Produkt-IDs finden**: Produkt-IDs findest du in deinem Dodo Payments-Dashboard unter Products → View Details oder über die [List Products API](/api-reference/products/get-products).
</Tip>

<Accordion title="Session Management">

<ParamField body="return_url" type="string">
URL, zu der Kunden nach Abschluss der Zahlung weitergeleitet werden. Dodo Payments hängt bei der Weiterleitung die folgenden Query-Parameter an deine URL an:

| Parameter | Typ | Bedingung |
|-----------|------|-----------|
| `payment_id` | `string` | Bei Einmalzahlungen immer vorhanden |
| `subscription_id` | `string` | Bei Abonnementzahlungen immer vorhanden |
| `status` | `string` | Immer vorhanden |
| `license_key` | `string` | Vorhanden, wenn für das Produkt Lizenzschlüssel aktiviert sind. Bei mehreren Schlüsseln durch Kommas getrennt |
| `email` | `string` | Vorhanden, wenn für den Kunden eine E-Mail-Adresse gespeichert ist |

**Beispiel-Weiterleitungs-URLs:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
Verwende die Query-Parameter `license_key` und `email`, um Lizenzschlüssel anzuzeigen oder sofort eine Bestätigung auf deiner Rückgabeseite zu senden, ohne einen zusätzlichen API-Aufruf zu benötigen.
</Tip>
</ParamField>

<ParamField body="cancel_url" type="string">
URL, zu der Kunden weitergeleitet werden, wenn sie auf die Zurück-Schaltfläche klicken oder die Checkout-Sitzung abbrechen. Wenn sie nicht angegeben ist, wird die Zurück-Schaltfläche nicht angezeigt.

<Tip>
Lege eine `cancel_url` fest, damit Kunden eindeutig zu deiner Website zurückkehren können, ohne den Kauf abzuschließen. Dies verbessert das Checkout-Erlebnis und reduziert Reibung.
</Tip>
</ParamField>

<ParamField body="confirm" type="boolean" default="false">
Wenn true, werden alle Sitzungsdetails sofort finalisiert. Die API gibt einen Fehler aus, wenn erforderliche Daten fehlen.
</ParamField>

<ParamField body="discount_codes" type="array">
Wende einen oder mehrere aufeinanderfolgende Rabattcodes auf die Checkout-Sitzung an. Codes werden **in Array-Reihenfolge** angewendet (der erste Code reduziert den Grundpreis, der zweite den bereits rabattierten Preis usw.), bis zu maximal **20** Codes pro Sitzung.

```typescript
discount_codes: ['WELCOME10', 'BLACKFRIDAY20']
```

<Info>
Das einzelne Feld `discount_code` unten ist **veraltet**, wird aber weiterhin vollständig unterstützt — bestehende Integrationen funktionieren unverändert. Es kann in derselben Anfrage nicht mit `discount_codes` kombiniert werden. Migriere bei Gelegenheit zu `discount_codes`, um von der Verkettung zu profitieren.
</Info>
</ParamField>

<ParamField body="discount_code" type="string" deprecated>
**Veraltet** — verwende für neue Integrationen bevorzugt `discount_codes`. Dieses Feld funktioniert aus Gründen der Abwärtskompatibilität weiterhin, kann aber in derselben Anfrage nicht mit `discount_codes` kombiniert werden.
</ParamField>

<ParamField body="metadata" type="object">
Benutzerdefinierte Schlüssel-Wert-Paare zum Speichern zusätzlicher Informationen zur Sitzung.
</ParamField>

<ParamField body="force_3ds" type="boolean">
Überschreibe das standardmäßige 3DS-Verhalten des Händlers für diese Sitzung.
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
Aktiviere den Modus zur Erfassung einer minimalen Adresse. Wenn aktiviert, erfasst der Checkout nur:
- **Land**: Für die Steuerbestimmung immer erforderlich
- **ZIP-/Postleitzahl**: Nur in Regionen, in denen sie für die Berechnung von sales tax, VAT oder GST erforderlich ist

Dies reduziert Reibung beim Checkout erheblich, da unnötige Formularfelder entfallen.

<Tip>
Aktiviere die minimale Adresse für einen schnelleren Checkout-Abschluss. Die vollständige Adresserfassung bleibt für Unternehmen verfügbar, die vollständige Rechnungsdaten benötigen.
</Tip>
</ParamField>

<ParamField body="payment_method_id" type="string">
Eine gespeicherte Zahlungsmethode des angehängten Kunden. Erfordert `confirm: true` und eine vorhandene `customer.customer_id`. Wenn gesetzt, wird die Zahlung sofort verarbeitet und `checkout_url` als `null` zurückgegeben — verwende stattdessen das zurückgegebene `payment_id`.
</ParamField>

<ParamField body="short_link" type="boolean" default="false">
Wenn true, wird eine verkürzte Checkout-URL anstelle der vollständigen Sitzungs-URL zurückgegeben.
</ParamField>

<ParamField body="product_collection_id" type="string">
Produktkollektions-ID für den sammlungsbasierten Checkout-Ablauf.
</ParamField>

<ParamField body="tax_id" type="string">
Steuer-ID des Kunden (z. B. eine Umsatzsteuer-ID). Erfordert `billing_address` mit einer `country`.
</ParamField>

<ParamField body="customer_business_name" type="string">
Optionaler geschäftlicher oder rechtlicher Name, der mit der Steuer-ID verknüpft ist. Zusammen mit einer gültigen `tax_id` wird er auf der Rechnung anstelle des persönlichen Namens des Kunden angezeigt.
</ParamField>

<ParamField body="mandate_min_amount_inr_paise" type="integer">
Überschreibe den Mandatsmindestbetrag auf Händlerebene (in INR-Paise) für INR-E-Mandate auf indischen Karten.
</ParamField>

### 11. Vorhandene Zahlungsmethoden für einen sofortigen Checkout verwenden

Verwende die gespeicherte Zahlungsmethode eines Kunden, um eine Checkout-Sitzung zu erstellen, die sofort verarbeitet wird und die Erfassung der Zahlungsmethode überspringt:

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'pdt_premium_plan',
      quantity: 1
    }
  ],
  customer: {
    customer_id: 'cus_123'  // Required when using payment_method_id
  },
  payment_method_id: 'pm_abc123',  // Use customer's saved payment method
  confirm: true,  // Required when using payment_method_id
  return_url: 'https://yourapp.com/success'
});
```

<Warning>
Bei Verwendung von `payment_method_id` muss `confirm` auf `true` gesetzt und eine vorhandene `customer_id` angegeben werden. Die Zahlungsmethode wird auf ihre Eignung für die Währung der Zahlung geprüft. Da die Zahlung sofort verarbeitet wird, wird `checkout_url` als `null` zurückgegeben — verwende stattdessen das zurückgegebene `payment_id`.
</Warning>

<Info>
Die Zahlungsmethode muss dem Kunden gehören und mit der Zahlungswährung kompatibel sein. Dadurch werden Käufe mit einem Klick für wiederkehrende Kunden ermöglicht.
</Info>

```javascript expandable
      options: ['Google', 'Twitter', 'Friend referral', 'Blog post', 'Other']
    },
    {
      key: 'website',
      label: 'Company Website',
      field_type: 'url',
      required: false,
      placeholder: 'https://example.com'
    }
  ],
  customer: {
    email: 'buyer@company.com',
    name: 'Jane Doe'
  },
  return_url: 'https://yourapp.com/success'

```

## Checkout-Sitzungen in der Vorschau anzeigen

Vor dem Erstellen einer Checkout-Sitzung kannst du die Preisaufschlüsselung einschließlich Steuern, Rabatten und Gesamtsummen in einer Vorschau anzeigen. Dies ist nützlich, um Kunden genaue Preise anzuzeigen, bevor sie zum Checkout fortfahren.

<Note>
Wenn der Warenkorb ein Abonnementprodukt enthält, gibt die Vorschauantwort außerdem eine `next_billing_date` zurück — eine Vorschau des bevorstehenden Abrechnungsdatums, damit du es vor der Erstellung des Abonnements anzeigen kannst. Sie wird relativ zum aktuellen Zeitpunkt berechnet: `now + trial period`, wenn ein Testzeitraum gilt, andernfalls `now + one payment frequency`. Bei Warenkörben, die nur Einmalprodukte enthalten, wird das Feld weggelassen. Es handelt sich um eine auf den Vorschauzeitpunkt bezogene Schätzung; die maßgebliche `next_billing_date` wird beim Aktivieren des Abonnements festgelegt.
</Note>

<Note>
Die Vorschau gibt außerdem `trial_period_days` (die effektive Dauer des kostenlosen oder kostenpflichtigen Testzeitraums) und `trial_amount` (die Testgebühr pro Einheit nach Rabatten in den kleinsten Einheiten der Preiswährung) zurück. `trial_amount` ist nur bei einem [kostenpflichtigen Testzeitraum](/features/subscription#paid-trials) vorhanden und bei einem kostenlosen oder fehlenden Testzeitraum `null`. Verwende `current_breakup` für die tatsächlich heute fällige, versteuerte Gesamtsumme.
</Note>

## Von Dynamic Links zu Checkout-Sitzungen wechseln

### Wesentliche Unterschiede
Bisher musstest du beim Erstellen eines Zahlungslinks mit Dynamic Links die vollständige Rechnungsadresse des Kunden angeben.

Mit Checkout-Sitzungen ist das nicht mehr erforderlich. Du kannst einfach alle Informationen übergeben, die dir vorliegen, und wir kümmern uns um den Rest. Zum Beispiel:

- Wenn du nur das Rechnungsland des Kunden kennst, gib einfach dieses an.
- Der Checkout-Ablauf erfasst die fehlenden Daten automatisch, bevor der Kunde zur Zahlungsseite weitergeleitet wird.
- Wenn du hingegen bereits alle erforderlichen Informationen hast und direkt zur Zahlungsseite wechseln möchtest, kannst du den vollständigen Datensatz übergeben und `confirm=true` in deinen Request Body aufnehmen.

### Migrationsprozess

Die Migration von Dynamic Links zu Checkout-Sitzungen ist unkompliziert:

<Steps>
<Step title="Update your integration">
Aktualisiere deine Integration, damit sie die neue API- oder SDK-Methode verwendet.
</Step>

<Step title="Adjust request payload">
Passe die Request-Payload an das Format der Checkout-Sitzungen an.
</Step>

<Step title="That's it!">
Ja. Auf deiner Seite sind keine zusätzlichen Maßnahmen oder besonderen Migrationsschritte erforderlich.
</Step>
</Steps>
