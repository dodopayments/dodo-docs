## Erstellen Ihrer ersten Checkout-Sitzung

<Tabs>
<Tab title="Node.js SDK">

```javascript expandable
import DodoPayments from 'dodopayments';

// Initialize the Dodo Payments client
const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode', // defaults to 'live_mode'
});

async function createCheckoutSession() {
  try {
    const session = await client.checkoutSessions.create({
      // Products to sell - use IDs from your Dodo Payments dashboard
      product_cart: [
        {
          product_id: 'prod_123', // Replace with your actual product ID
          quantity: 1
        }
      ],
      
      // Pre-fill customer information to reduce friction
      customer: {
        email: 'customer@example.com',
        name: 'John Doe',
        phone_number: '+1234567890'
      },
      
      // Billing address for tax calculation and compliance
      billing_address: {
        street: '123 Main St',
        city: 'San Francisco',
        state: 'CA',
        country: 'US', // Required: ISO 3166-1 alpha-2 country code
        zipcode: '94102'
      },
      
      // Where to redirect after successful payment
      return_url: 'https://yoursite.com/checkout/success',
      
      // Custom data for your internal tracking
      metadata: {
        order_id: 'order_123',
        source: 'web_app'
      }
    });

    // Redirect your customer to this URL to complete payment
    console.log('Checkout URL:', session.checkout_url);
    console.log('Session ID:', session.session_id);
    
    return session;
    
  } catch (error) {
    console.error('Failed to create checkout session:', error);
    throw error;
  }
}

// Example usage in an Express.js route
app.post('/create-checkout', async (req, res) => {
  try {
    const session = await createCheckoutSession();
    res.json({ checkout_url: session.checkout_url });
  } catch (error) {
    res.status(500).json({ error: 'Failed to create checkout session' });
  }
});
```

```python expandable
import os
from dodopayments import DodoPayments

# Initialize the Dodo Payments client
client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),  # This is the default and can be omitted
    environment="test_mode",  # defaults to "live_mode"
)

def create_checkout_session():
    """
    Create a checkout session for a single product with customer data pre-filled.
    Returns the session object containing checkout_url for customer redirection.
    """
    try:
        session = client.checkout_sessions.create(
            # Products to sell - use IDs from your Dodo Payments dashboard
            product_cart=[
                {
                    "product_id": "prod_123",  # Replace with your actual product ID
                    "quantity": 1
                }
            ],
            
            # Pre-fill customer information to reduce checkout friction
            customer={
                "email": "customer@example.com",
                "name": "John Doe",
                "phone_number": "+1234567890"
            },
            
            # Billing address for tax calculation and compliance
            billing_address={
                "street": "123 Main St",
                "city": "San Francisco", 
                "state": "CA",
                "country": "US",  # Required: ISO 3166-1 alpha-2 country code
                "zipcode": "94102"
            },
            
            # Where to redirect after successful payment
            return_url="https://yoursite.com/checkout/success",
            
            # Custom data for your internal tracking
            metadata={
                "order_id": "order_123",
                "source": "web_app"
            }
        )
        
        # Redirect your customer to this URL to complete payment
        print(f"Checkout URL: {session.checkout_url}")
        print(f"Session ID: {session.session_id}")
        
        return session

# Example usage in a Flask route
from flask import Flask, jsonify, request

app = Flask(__name__)

@app.route('/create-checkout', methods=['POST'])
```

### API-Antwort

Alle oben genannten Methoden geben die gleiche Antwortstruktur zurück:

```json
{
  "session_id": "cks_Gi6KGJ2zFJo9rq9Ukifwa",
  "checkout_url": "https://test.checkout.dodopayments.com/session/cks_Gi6KGJ2zFJo9rq9Ukifwa"
}
```

<Steps>
<Step title="Holen Sie sich die Checkout-URL">
Extrahieren Sie das `checkout_url` aus der API-Antwort.
</Step>

<Step title="Leiten Sie Ihren Kunden weiter">
Leiten Sie Ihren Kunden zur Checkout-URL, um den Kauf abzuschließen.

```javascript
// Redirect immediately
window.location.href = session.checkout_url;

// Or open in new window
window.open(session.checkout_url, '_blank');
```

<Tip>
**Alternative Integrationsoptionen**: Anstatt weiterzuleiten, können Sie den Checkout direkt auf Ihrer Seite einbetten, indem Sie [Overlay Checkout](/developer-resources/overlay-checkout) (Modal-Overlay) oder [Inline Checkout](/developer-resources/inline-checkout) (vollständig eingebettet) verwenden. Beide Optionen verwenden dieselbe Checkout-Sitzungs-URL.
</Tip>
</Step>

<Step title="Behandeln Sie die Rückkehr">
Nach der Zahlung werden die Kunden mit Query-Parametern, die ID der Zahlung/Abonnement, Status, Kunden-E-Mail und Lizenzschlüssel enthalten, an Ihre `return_url` umgeleitet. Siehe die [`return_url` Parameterdokumentation](#request-body) für die vollständige Liste.
</Step>
</Steps>

### Erforderliche Felder

<ParamField body="product_cart" type="array" required>
Array von Produkten, die in der Checkout-Sitzung enthalten sein sollen. Jedes Produkt muss eine gültige `product_id` aus Ihrem Dodo Payments Dashboard haben.

<Tip>
**Gemischter Checkout**: Sie können einmalige Zahlungsprodukte und Abonnementprodukte in derselben Checkout-Sitzung kombinieren. Dies ermöglicht leistungsstarke Anwendungsfälle wie Einrichtungsgebühren mit Abonnements, Hardware-Bundles mit SaaS und mehr.
</Tip>

<Expandable title="Eigenschaften des Produkt-Warenkorbartikels">
<ParamField body="product_id" type="string" required>
Die eindeutige Kennung des Produkts aus Ihrem Dodo Payments-Dashboard.

**Beispiel:** `"prod_123abc456def"`
</ParamField>

<ParamField body="quantity" type="integer" required>
Menge des Produkts.

**Beispiel:** `1` für einen einzelnen Artikel, `3` für mehrere Mengen
</ParamField>

<ParamField body="addons" type="array">
Array von Add-Ons, die dem Produkt angehängt werden sollen. Nur gültig, wenn das Produkt ein Abonnement ist.

<Expandable title="Eigenschaften des Add-On-Artikels">
<ParamField body="addon_id" type="string" required />

<ParamField body="quantity" type="integer" required />
</Expandable>
</ParamField>

<ParamField body="amount" type="integer">
Betrag, den der Kunde zahlt, wenn pay_what_you_want aktiviert ist. Wenn deaktiviert, wird dieses Feld ignoriert.

**Format**: Dargestellt in der niedrigsten Währungseinheit (z. B. Cent für USD). Zum Beispiel, um $1,00 zu berechnen, übergeben Sie `100`.
</ParamField>
</Expandable>
</ParamField>

<Tip>
**Finden Sie Ihre Produkt-IDs**: Sie können Produkt-IDs in Ihrem Dodo Payments-Dashboard unter Produkte → Details anzeigen finden oder die [List Products API](/api-reference/products/get-products) verwenden.
</Tip>

<Accordion title="Sitzungsverwaltung">

<ParamField body="return_url" type="string">
URL zur Umleitung der Kunden nach Abschluss der Zahlung. Dodo Payments fügt die folgenden Query-Parameter zu Ihrer URL bei der Umleitung hinzu:

| Parameter | Typ | Bedingung |
|-----------|------|-----------|
| `payment_id` | `string` | Immer vorhanden für einmalige Zahlungen |
| `subscription_id` | `string` | Immer vorhanden für Abonnementzahlungen |
| `status` | `string` | Immer vorhanden |
| `license_key` | `string` | Vorhanden, wenn das Produkt Lizenzschlüssel aktiviert hat. Komma-getrennt, wenn mehrere Schlüssel vorhanden sind |
| `email` | `string` | Vorhanden, wenn der Kunde eine E-Mail im System hat |

**Beispiel-Redirect-URLs:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription payment with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com

# Payment without license keys
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&email=customer%40example.com
```

<Tip>
Verwenden Sie die `license_key` und `email` Query-Parameter, um Lizenzschlüssel anzuzeigen oder umgehend eine Bestätigung auf Ihrer Rückgabeseite zu senden, ohne einen zusätzlichen API-Aufruf zu benötigen.
</Tip>
</ParamField>

<ParamField body="confirm" type="boolean" default="false">
Wenn wahr, werden alle Sitzungsdetails sofort finalisiert. API gibt einen Fehler zurück, wenn erforderliche Daten fehlen.
</ParamField>

<ParamField body="discount_code" type="string">
Wenden Sie einen Rabattcode auf die Checkout-Sitzung an.
</ParamField>

<ParamField body="metadata" type="object">
Benutzerdefinierte Schlüssel-Wert-Paare zum Speichern zusätzlicher Informationen über die Sitzung.
</ParamField>

<ParamField body="force_3ds" type="boolean">
Überschreiben Sie das Standard-3DS-Verhalten des Händlers für diese Sitzung.
</ParamField>

<ParamField body="minimal_address" type="boolean" default="false">
Aktivieren Sie den minimalen Adresssammlungsmodus. Wenn aktiviert, sammelt die Kasse nur:
- **Land**: Immer erforderlich zur Steuerbestimmung
- **Postleitzahl**: Nur in Regionen, in denen es für die Berechnung von Verkaufssteuer, VAT oder GST erforderlich ist.

Dies reduziert erheblich die Reibung beim Checkout, indem unnötige Formularfelder eliminiert werden.

<Tip>
Aktivieren Sie die minimale Adresse für eine schnellere Checkout-Abwicklung. Die vollständige Adresssammlung bleibt für Unternehmen verfügbar, die vollständige Rechnungsdetails benötigen.
</Tip>
</ParamField>

Sammeln Sie zusätzliche Informationen von Kunden während des Checkouts mit benutzerdefinierten Formularfeldern. Sie können bis zu 5 benutzerdefinierte Felder pro Checkout-Sitzung definieren. Die Antworten der Kunden sind in den Webhook-Nutzlasten enthalten und über die API verfügbar.

<Expandable title="Eigenschaften des benutzerdefinierten Feldobjekts">
<ParamField body="key" type="string" required>
Eindeutiger Identifikator für dieses Feld. Wird als Schlüssel in Webhook-Nutzlasten und API-Antworten verwendet.

**Beispiel**: `"company_name"`, `"referral_source"`, `"team_size"`
</ParamField>

<ParamField body="label" type="string" required>
Anzeigetext, der dem Kunden im Checkout-Formular angezeigt wird.

**Beispiel**: `"Company Name"`, `"How did you hear about us?"`, `"Team Size"`
</ParamField>

<ParamField body="field_type" type="string" required>
Art des Feldes, die die Validierungsregeln für die Eingabe bestimmt.

**Verfügbare Typen**:
- `text` - Eingabe für einzeilige Texte
- `number` - Numerische Eingabe
- `email` - E-Mail-Adresse mit Validierung
- `url` - URL mit Validierung
- `date` - Datumswähler
- `dropdown` - Auswahl aus vordefinierten Optionen
- `boolean` - Ja/Nein-Umschalter
</ParamField>

<ParamField body="required" type="boolean" default="false">
Ob dieses Feld ausgefüllt werden muss, bevor der Checkout abgeschlossen werden kann.
</ParamField>

<ParamField body="placeholder" type="string">
Platzhaltertext, der im Eingabefeld angezeigt wird.
</ParamField>

<ParamField body="options" type="array">
Liste der Optionen für `dropdown`-Feldtyp. Erforderlich, wenn `field_type` `dropdown` ist, ignoriert für andere Typen.

**Beispiel**: `["Google", "Twitter", "Friend referral", "Other"]`
</ParamField>
</Expandable>
</ParamField>

<Info>
Die Antworten der Kunden auf benutzerdefinierte Felder sind enthalten in:
- **Webhooks**: `payment.succeeded`, `subscription.created` und andere relevante Ereignis-Nutzlasten enthalten das `custom_field_responses`-Array
- **API-Antworten**: Zahlungs- und Abonnementobjekte beinhalten `custom_field_responses`
</Info>

### 11. Verwendung vorhandener Zahlungsmethoden für sofortigen Checkout

Verwenden Sie die gespeicherte Zahlungsmethode eines Kunden, um eine Checkout-Sitzung zu erstellen, die sofort verarbeitet wird, und überspringen Sie die Erfassung der Zahlungsmethode:

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'prod_premium_plan',
      quantity: 1
    }
  ],
  customer: {
    customer_id: 'cus_123'  // Required when using payment_method_id
  },
  payment_method_id: 'pm_abc123',  // Use customer's saved payment method
  confirm: true,  // Required when using payment_method_id
  return_url: 'https://yourapp.com/success'
});
```

<Warning>
Wenn `payment_method_id` verwendet wird, muss `confirm` auf `true` gesetzt werden und eine vorhandene `customer_id` muss bereitgestellt werden. Die Zahlungsmethode wird auf Berechtigung mit der Währungszahlung validiert.
</Warning>

<Info>
Die Zahlungsmethode muss dem Kunden gehören und mit der Zahlungsmethode kompatibel sein. Dies ermöglicht einen Kauf mit einem Klick für wiederkehrende Kunden.
</Info>

</Tip>

### 13. Zahlungserfolgsseite überspringen mit sofortiger Umleitung

Leiten Sie die Kunden unmittelbar nach Abschluss der Zahlung um und umgehen Sie die Standardseite für den Zahlungserfolg:

```javascript expandable
const session = await client.checkoutSessions.create({
  product_cart: [
    {
      product_id: 'prod_digital_product',
      quantity: 1
    }
  ],
  feature_flags: {
    redirect_immediately: true  // Skip success page, redirect immediately
  },
  return_url: 'https://yourapp.com/success',
  customer: {
    email: 'customer@example.com',
    name: 'Jane Smith'
  }
});
```

<Tip>
Verwenden Sie `redirect_immediately: true`, wenn Sie eine benutzerdefinierte Erfolgseite haben, die ein besseres Benutzererlebnis als die Standardseite für den Zahlungserfolg bietet. Dies ist besonders nützlich für mobile Apps und eingebettete Checkout-Flows.
</Tip>

<Note>
Wenn `redirect_immediately` aktiviert ist, werden die Kunden unmittelbar nach Abschluss der Zahlung an Ihre `return_url` weitergeleitet, wodurch die Standardseite für den Zahlungserfolg vollständig übersprungen wird.
</Note>

## Umstellung von dynamischen Links auf Checkout-Sitzungen

### Wichtige Unterschiede
Früher, bei der Erstellung eines Zahlungslinks mit dynamischen Links, mussten Sie die vollständige Rechnungsadresse des Kunden angeben.

Bei Checkout-Sitzungen ist dies nicht mehr erforderlich. Sie können einfach die Informationen übergeben, die Sie haben, und wir kümmern uns um den Rest. Zum Beispiel:

- Wenn Sie nur das Rechnungsland des Kunden kennen, geben Sie nur das an.
- Der Checkout-Flow sammelt automatisch die fehlenden Details, bevor der Kunde zur Zahlungsseite weitergeleitet wird.
- Andererseits, wenn Sie bereits alle erforderlichen Informationen haben und direkt zur Zahlungsseite überspringen möchten, können Sie den vollständigen Datensatz übergeben und `confirm=true` in Ihrem Anfragekörper einschließen.

### Migrationsprozess
Die Migration von dynamischen Links zu Checkout-Sitzungen ist unkompliziert:

<Steps>
<Step title="Aktualisieren Sie Ihre Integration">
Aktualisieren Sie Ihre Integration auf die neue API- oder SDK-Methode.
</Step>

<Step title="Anpassen der Anfragedaten">
Passen Sie die Anfragedaten gemäß dem Format der Checkout-Sitzungen an.
</Step>

<Step title="Das war's!">
Ja. Es sind keine zusätzlichen Handlungen oder speziellen Migrationsschritte Ihrerseits erforderlich.
</Step>
</Steps>

<Step title="That's it!">
Yes. No additional handling or special migration steps are needed on your side.
</Step>
</Steps>
