<Info>
Dodo Payments stellt ein offizielles Checkout-SDK für **Android, iOS, React Native,
und Flutter** bereit. Jedes SDK kapselt das unten dokumentierte Muster (Checkout-
URL öffnen, Rückgabe erfassen, Ergebnis analysieren) hinter einem einzigen typisierten `start(...)`-
Aufruf, einschließlich integrierter Wiederherstellung abgebrochener Sitzungen. Verwende nur dann eine manuelle WebView,
wenn keines davon zu deinem Stack passt.
</Info>

## Voraussetzungen

Bevor du Dodo Payments in deine mobile App integrierst, stelle sicher, dass du Folgendes hast:

- **Dodo Payments-Konto**: Aktives Händlerkonto mit API-Zugriff
- **API-Zugangsdaten**: API-Schlüssel und Webhook-Secret-Key aus deinem Dashboard
- **Projekt der mobilen App**: Android-, iOS-, React-Native- oder Flutter-Anwendung
- **Backend-Server**: Zur sicheren Verarbeitung der Erstellung von Checkout-Sitzungen

## Integrationsablauf

Die mobile Integration folgt einem sicheren Prozess in vier Schritten: Dein Backend verarbeitet die API-Aufrufe und deine mobile App verwaltet die Benutzererfahrung.

<Steps>
<Step title="Backend: Create Checkout Session">
<Card title="Checkout Session API Docs" icon="book" href="/developer-resources/checkout-session">

<Note>
**Sicherheit**: Checkout-Sitzungen müssen auf deinem Backend-Server erstellt werden, niemals in der mobilen App. Dadurch werden deine API-Schlüssel geschützt und eine ordnungsgemäße Validierung sichergestellt.
</Note>

<Step title="Mobile: Get Checkout URL">

Deine mobile App ruft dein Backend auf, um die Checkout-URL abzurufen. Authentifiziere
diese Anfrage mit dem Sitzungstoken des angemeldeten Benutzers.

<Tabs>
<Tab title="iOS (Swift)">

```swift
func getCheckoutURL(productId: String, customerEmail: String, customerName: String) async throws -> String {
    let url = URL(string: "https://your-backend.com/api/create-checkout-session")!
    var request = URLRequest(url: url)
    request.httpMethod = "POST"
    request.setValue("application/json", forHTTPHeaderField: "Content-Type")
    request.setValue("Bearer \(userSessionToken)", forHTTPHeaderField: "Authorization")
    
    let requestData: [String: Any] = [
        "productId": productId,
        "customerEmail": customerEmail,
        "customerName": customerName
    ]
    request.httpBody = try JSONSerialization.data(withJSONObject: requestData)
    
    let (data, _) = try await URLSession.shared.data(for: request)
    let response = try JSONDecoder().decode(CheckoutResponse.self, from: data)
    return response.checkout_url
}
```

</Tab>
<Tab title="Android (Kotlin)">

```kotlin
suspend fun getCheckoutURL(productId: String, customerEmail: String, customerName: String): String {
    val client = OkHttpClient()
    val requestBody = JSONObject().apply {
        put("productId", productId)
        put("customerEmail", customerEmail)
        put("customerName", customerName)
    }.toString().toRequestBody("application/json".toMediaType())
    
    val request = Request.Builder()
        .url("https://your-backend.com/api/create-checkout-session")
        .header("Authorization", "Bearer $userSessionToken")
        .post(requestBody)
        .build()
    
    val response = client.newCall(request).execute()
    val responseBody = response.body?.string()
    val jsonResponse = JSONObject(responseBody ?: "")
    return jsonResponse.getString("checkout_url")
}
```

</Tab>
<Tab title="React Native (JavaScript)">

```javascript
const getCheckoutURL = async (productId, customerEmail, customerName) => {
  try {
    const response = await fetch('https://your-backend.com/api/create-checkout-session', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${userSessionToken}`,
      },
      body: JSON.stringify({
        productId,
        customerEmail,
        customerName
      })
    });
    
    const data = await response.json();
    return data.checkout_url;
  } catch (error) {
    console.error('Failed to get checkout URL:', error);
    throw error;
  }
};
```

</Tab>
<Tab title="Flutter (Dart)">

```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<String> getCheckoutUrl({
  required String productId,
  required String customerEmail,
  required String customerName,
}) async {
  final response = await http.post(
    Uri.parse('https://your-backend.com/api/create-checkout-session'),
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer $userSessionToken',
    },
    body: jsonEncode({
      'productId': productId,
      'customerEmail': customerEmail,
      'customerName': customerName,
    }),
  );

  if (response.statusCode != 200) {
    throw Exception('Failed to get checkout URL: ${response.statusCode}');
  }
  return jsonDecode(response.body)['checkout_url'] as String;
}
```

## Wähle dein SDK

Jedes mobile SDK stellt denselben Vertrag bereit: Ein einziger `start(...)`-Aufruf öffnet den
gehosteten Checkout von Dodo in der nativen Browser-Oberfläche der Plattform und gibt ein typisiertes
`CheckoutResult` zurück, dessen `status` `succeeded`, `failed`, `cancelled`,
`pending` oder `expired` ist. Keines davon enthält einen API-Schlüssel oder ruft die Dodo
Payments API auf, und alle vier unterstützen die Wiederherstellung abgebrochener Sitzungen.

<CardGroup cols={2}>
<Card title="Android" icon="android" href="/developer-resources/sdks/android">
  `com.dodopayments.api:checkout-android` öffnet einen Chrome Custom Tab. Erfordert `minSdk` 23.
</Card>
<Card title="iOS" icon="apple" href="/developer-resources/sdks/ios">
  `dodopayments-mobile-sdk-ios` öffnet `SFSafariViewController`. Erfordert iOS 16+.
</Card>
<Card title="React Native" icon="react" href="/developer-resources/sdks/react-native">
  `@dodopayments/react-native-checkout`, ein Turbo Module über beide nativen Kerne. Erfordert React Native 0.76+.
</Card>
<Card title="Flutter" icon="layer-group" href="/developer-resources/sdks/flutter">
  `dodopayments_checkout`, ein Pigeon-Kanal über beide nativen Kerne. Erfordert Flutter 3.44+.
</Card>
</CardGroup>

<Warning>
Das zurückgegebene `status` ist ein UI-Hinweis, kein Zahlungsnachweis. Bestätige jede
Zahlung von deinem Backend aus über den `payment.succeeded`-/`subscription.active`-
Webhook oder rufe die Zahlung mit deinem Secret-Key ab.
</Warning>

### Ein Callback-URL-Schema registrieren

Alle vier SDKs geben die Kontrolle über ein benutzerdefiniertes URL-Schema, das
du auswählst, an deine App zurück, zum Beispiel `myapp://checkout/return`. Registriere es einmal pro
Plattform:

<Tabs>
<Tab title="Android">

```kotlin android/app/build.gradle
android {
    defaultConfig {
        manifestPlaceholders["dodoCallbackScheme"] = "myapp"
    }
}
```

Das Manifest des SDKs deklariert die Redirect-Aktivität bereits selbst, daher musst du kein
Manifest-XML hinzufügen.
</Tab>
<Tab title="iOS">

```xml Info.plist
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleURLName</key>
    <string>myapp</string>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>myapp</string>
    </array>
  </dict>
</array>
```

Unter iOS musst du eingehende URLs ebenfalls an das SDK weiterleiten, da
`SFSafariViewController` seine eigene Rückgabe-URL nicht abfangen kann. Siehe die
[iOS](/developer-resources/sdks/ios)- oder
[React Native](/developer-resources/sdks/react-native)-Seite für den genauen
Handler.
</Tab>
<Tab title="Expo">
`@dodopayments/react-native-checkout` enthält ein Config-Plugin, das das
Schema für beide Plattformen unter `prebuild` registriert. Übergib ihm eine
`scheme`-Option:

```json app.json
{
  "expo": {
    "scheme": "myapp",
    "plugins": [
      [
        "@dodopayments/react-native-checkout",
        { "scheme": "myappcheckout" }
      ]
    ]
  }
}
```

`scheme` muss mit `returnUrl` übereinstimmen und sich von `expo.scheme` unterscheiden, das Expo
bereits unter `MainActivity` registriert. Weitere Informationen findest du auf der
[React Native SDK](/developer-resources/sdks/react-native)-Seite.

Wenn `android/app/build.gradle` manuell gepflegt wird und keinen standardmäßigen
`defaultConfig { }`-Block enthält, setze den Platzhalter stattdessen manuell (siehe den
Android-Tab).

Funktioniert nur mit Development Builds, nicht mit Expo Go. Führe
`npx expo prebuild --clean` nach der Bearbeitung von `app.json` aus.
</Tab>
</Tabs>

<Note>
Möchtest du es selbst erstellen? Öffne die `checkout_url` in einer WebView und fange
die Navigation zu deiner `return_url` ab. Lies anschließend die `status`- und `payment_id`-
Query-Parameter aus. Die obigen SDKs übernehmen dies für dich in der echten Browser-Oberfläche der Plattform,
daher funktionieren Apple Pay und Google Pay weiterhin.
</Note>

## Best Practices

- **Sicherheit**: Liefere niemals einen API-Schlüssel in deiner App aus. Erstelle Checkout-Sitzungen in deinem Backend und übergib dem Client nur die resultierende `checkout_url`.
- **Maßgeblichkeit**: Behandle `CheckoutResult.status` als UI-Hinweis. Gewähre Zugriff erst, nachdem dein Backend die Zahlung bestätigt hat.
- **Benutzererfahrung**: Zeige einen Ladezustand an, während dein Backend die Sitzung erstellt, und behandle `cancelled` als normales Ergebnis und nicht als Fehler.
- **Tests**: Verwende den Testmodus und Testkarten und überprüfe den Roundtrip der Rückgabe-URL sowohl auf einem echten Gerät als auch in einem Simulator.

## Fehlerbehebung

### Häufige Probleme

- **Callback trifft nie ein**: Das Schema in `returnUrl` muss mit dem registrierten Schema übereinstimmen. Unter Android ist dies der `dodoCallbackScheme`-Manifest-Platzhalter, unter iOS und React Native der `Info.plist`-URL-Typ.
- **Checkout kehrt unter iOS zum Browser statt zu deiner App zurück**: Du hast die eingehende URL nicht weitergeleitet. Rufe `DodoCheckout.handleOpenURL(url)` aus `.onOpenURL`, `scene(_:openURLContexts:)` oder einem React-Native- `Linking`-Listener auf.
- **`PLATFORM_ERROR` unter Android**: Meist liegt ein Schema-Konflikt vor. Dies kann auch auftreten, wenn dein `MainActivity` `android:taskAffinity=""` setzt (der standardmäßige `flutter create`-Wert), wodurch einige OEM-Builds den laufenden Checkout verlieren können.
- **`ALREADY_IN_PROGRESS`**: Ein Checkout ist noch geöffnet. Warte, bis der vorherige abgeschlossen ist, oder schließe ihn, bevor du einen weiteren startest.
- **Build schlägt wegen eines nicht aufgelösten Platzhalters fehl**: Du hast das Android-SDK hinzugefügt, aber `manifestPlaceholders["dodoCallbackScheme"]` nie gesetzt.
- **Zahlung erfolgreich, aber kein Zugriff gewährt**: Dies ist zu erwarten, wenn du dich am mobilen Ergebnis orientierst. Gewähre den Zugriff stattdessen über den `payment.succeeded`-/`subscription.active`-Webhook.
