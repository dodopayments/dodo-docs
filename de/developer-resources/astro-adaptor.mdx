## Installation

<Steps>
<Step title="Install the package">
Führen Sie den folgenden Befehl im Stammverzeichnis Ihres Projekts aus:

```bash
npm install @dodopayments/astro
```

</Step>
<Step title="Set up environment variables">
Erstellen Sie eine <code>.env</code>-Datei im Stammverzeichnis Ihres Projekts:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=https://yourdomain.com/checkout/success
```

<Warning>
Übertragen Sie Ihre <code>.env</code>-Datei oder Secrets niemals in die Versionsverwaltung.
</Warning>
</Step>
</Steps>

## Checkout Route Handler

<Info>
Dodo Payments unterstützt drei Arten von Zahlungsabläufen zur Integration von Zahlungen in Ihre Website; dieser Adapter unterstützt alle Arten von Zahlungsabläufen.
</Info>

- **Statische Payment Links:** Sofort teilbare URLs für die schnelle Zahlungserfassung ohne Code.
- **Dynamische Payment Links:** Generieren Sie mithilfe der API oder SDKs programmgesteuert Payment Links mit benutzerdefinierten Details.
- **Checkout Sessions:** Erstellen Sie sichere, anpassbare Checkout-Erlebnisse mit vorkonfigurierten Produkt-Warenkörben und Kundendaten.

<AccordionGroup>
<Accordion title="Static Checkout (GET)">

</ParamField>

<Warning>
Wenn <code>productId</code> fehlt, gibt der Handler eine 400-Antwort zurück. Ungültige Query-Parameter führen ebenfalls zu einer 400-Antwort.
</Warning>

### Antwortformat
Der statische Checkout gibt eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Senden Sie die Parameter als JSON-Body in einer POST-Anfrage.
- Unterstützt sowohl einmalige als auch wiederkehrende Zahlungen.
- Eine vollständige Liste der unterstützten Felder im POST-Body finden Sie unter:
  - [Request body for a One Time Payment Product](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Request body for a Subscription Product](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Antwortformat
Der dynamische Checkout gibt eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Checkout Sessions bieten ein sichereres, gehostetes Checkout-Erlebnis, das den vollständigen Zahlungsablauf sowohl für einmalige Käufe als auch für Abonnements abwickelt und umfassende Anpassungsmöglichkeiten bietet.

Weitere Informationen und eine vollständige Liste der unterstützten Felder finden Sie im [Checkout Sessions Integration Guide](https://docs.dodopayments.com/developer-resources/checkout-session).

### Antwortformat
Checkout Sessions geben eine JSON-Antwort mit der Checkout-URL zurück:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>
</AccordionGroup>

## Customer Portal Route Handler

Der Customer Portal Route Handler ermöglicht Ihnen die nahtlose Integration des Customer Portal von Dodo Payments in Ihre Astro-Anwendung.

### Query-Parameter
<ParamField query="customer_id" type="string" required>
Die Kunden-ID für die Portal-Sitzung (z. B. <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Wenn auf <code>true</code> gesetzt, wird dem Kunden eine E-Mail mit dem Portal-Link gesendet.
</ParamField>

<Warning>
Gibt 400 zurück, wenn <code>customer_id</code> fehlt.
</Warning>

## Webhook Route Handler

- **Methode:** Es werden nur POST-Anfragen unterstützt. Andere Methoden geben 405 zurück.
- **Signaturüberprüfung:** Überprüft die Webhook-Signatur mithilfe von <code>webhookKey</code>. Gibt 401 zurück, wenn die Überprüfung fehlschlägt.
- **Payload-Validierung:** Wird mit Zod validiert. Gibt 400 für ungültige Payloads zurück.
- **Fehlerbehandlung:**
  - 401: Ungültige Signatur
  - 400: Ungültige Payload
  - 500: Interner Fehler während der Überprüfung
- **Event-Routing:** Ruft den passenden Event-Handler basierend auf dem Payload-Typ auf.
