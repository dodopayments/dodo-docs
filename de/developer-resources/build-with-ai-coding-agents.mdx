Das Dodo Agent Plugin integriert zwei MCP-Server und siebzehn Integrations-Skills mit deinem AI-Coding-Agent in einer einzigen Installation. Es funktioniert mit **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** und **OpenCode**. **Gemini CLI** erhält nur die beiden MCP-Server. Die MCP-Server und die Skills CLI funktionieren mit jedem MCP-kompatiblen Client.

Das Plugin folgt der Spezifikation [Agent Plugins 1.0.0](https://agent-plugins.org/specification), sodass Clients mit nativer Unterstützung es direkt aus dem Root `plugin.json` und `mcp.json` laden. Clients, die älter als die Spezifikation sind, laden denselben Inhalt über generierte Kompatibilitätsmanifeste.

<Info>
**Drei Grundlagen, ein Plugin.** Das Agent Plugin enthält alles, was du benötigst:
- **API-MCP-Server** — Live-Zugriff auf Zahlungen, Abonnements, Kunden, Produkte, Rückerstattungen, Lizenzen und Nutzung. Die Authentifizierung erfolgt über Browser-OAuth (keine lokalen Schlüssel erforderlich).
- **Knowledge-MCP-Server** — Semantische Suche in der gesamten Dokumentation von Dodo Payments. Keine Zugangsdaten erforderlich.
- **Siebzehn Agent-Skills** — Kurzreferenzen, die dein Agent bei Bedarf für Checkout, Abonnements, Webhooks, nutzungsbasierte und kreditbasierte Abrechnung, Lizenzschlüssel, Produktkatalog, Rabatte, lokalisierte Preise, Mobile Checkout, Rückerstattungen und Streitfälle, Kundenverwaltung, Framework-Adapter, BillingSDK, Better Auth, Tests und Go-Live sowie Best Practices lädt.
</Info>

## Plugin installieren

Wähle unten deinen Coding-Agent aus. Jede Installation fügt beide MCP-Server hinzu; alle Agents außer Gemini CLI fügen außerdem die siebzehn Skills hinzu.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installiere über den Marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Der API-MCP-Server verwendet standardmäßig Browser-OAuth — zur Installation sind keine Schlüssel erforderlich. Wenn dein Agent zum ersten Mal ein Dodo-Tool aufruft, wirst du aufgefordert, dich anzumelden.

  Quellcode, Konfigurationsoptionen und Anweisungen für die lokale Entwicklung
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installiert Plugins in zwei Schritten: Registriere den Marketplace über deine Shell und installiere anschließend das Plugin innerhalb der Codex-TUI.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Öffne Codex und führe den `/plugins`-Slash-Befehl aus:

```bash
codex
```

Gib anschließend `/plugins` ein, wechsle zum Marketplace **Dodo Payments**, wähle das Plugin **dodopayments** aus und klicke auf **Install plugin**.
</Step>
</Steps>

Beide MCP-Server und alle siebzehn Skills werden automatisch registriert, sobald das Plugin installiert ist.

<Note>
Codex CLI verfügt über keinen `codex plugin install`-Subcommand — die Plugin-Installation erfolgt immer über den `/plugins`-Ablauf innerhalb der TUI. Weitere Informationen findest du in der [offiziellen Codex-Plugin-Dokumentation](https://developers.openai.com/codex/plugins).
</Note>

Wenn du den Marketplace und das Plugin bereits hinzugefügt hast, das Plugin aber nicht unter `/plugins` angezeigt wird, aktualisiere ihn:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Manuelle Installation — klone das Repository in das lokale Plugin-Verzeichnis von Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Starte Cursor neu. Das Plugin lädt Skills aus `skills/` und MCP-Server aus `.mcp.json`, wie in `.cursor-plugin/plugin.json` festgelegt.

<Info>
Aktuelle Cursor-Builds erkennen Agent Plugins 1.0.0 außerdem direkt und akzeptieren `.cursor-plugin/marketplace.json` oder `.claude-plugin/marketplace.json` als Marketplace-Quelle. Dieses Plugin liefert `.claude-plugin/marketplace.json` — verwende diesen Pfad. Das generierte `.cursor-plugin/plugin.json` bleibt für ältere Builds erhalten.
</Info>

<Warning>
Versionen vor 0.5.0 lieferten `skills/` als Symlinks in ein Git-Submodul. Daher erzeugte dieser Clone ein Plugin mit **keinen funktionierenden Skills**. Skills werden jetzt als echte Dateien bereitgestellt. Wenn du eine frühere Version installiert hast, lösche das Verzeichnis und klone das Repository erneut.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode wird über npm verteilt. Füge das Plugin zu deiner `opencode.json` hinzu:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Starte OpenCode neu. Beide MCP-Server (`dodopayments-api`, `dodo-knowledge`) werden automatisch über den Config-Hook des Plugins registriert. Es ist kein manueller `mcp`-Block erforderlich.

**Skills benötigen eine zusätzliche Zeile.** OpenCode durchsucht installierte Pakete nicht nach Skills. Verweise daher selbst auf das `skills/`-Verzeichnis des Pakets:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

Relative `skills.paths`-Einträge werden relativ zum **Projektverzeichnis** aufgelöst. Das Paket muss daher im `node_modules` dieses Projekts vorhanden sein — der eigene Plugin-Cache von OpenCode befindet sich an einem anderen Ort. Ein absoluter Pfad funktioniert ebenfalls und vermeidet die Voraussetzung einer lokalen Installation.

<Warning>
Ein nicht vorhandener Skill-Pfad wird **still** ignoriert. Überprüfe ihn, statt ihn vorauszusetzen:

```bash
opencode run "List every skill available to you by name."
```

Du solltest alle siebzehn sehen. In der Dokumentation für Versionen vor 0.5.0 wurden diese Skills als automatisch erkannt beschrieben — das war nicht der Fall. OpenCode-Benutzer hatten daher MCP-Server, aber keine Skills.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Klone das Repository an einen beliebigen Ort und registriere es anschließend:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Öffne die Chat-Ansicht, gehe zu **Plugins** und füge den geklonten Ordner hinzu. Du kannst es auch direkt in `settings.json` registrieren:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

Der Schlüssel ist ein Pfad, der Wert aktiviert ihn. Absolute Pfade und `~/` funktionieren ebenfalls; ein relativer Pfad wird relativ zu jedem Workspace-Ordner aufgelöst. Die Einstellung wird live eingelesen, sodass ein geöffnetes Fenster sie ohne Neustart übernimmt. Skills werden aus `skills/` geladen, beide MCP-Server aus `.mcp.json`.

<Note>
`chat.pluginLocations` ist als **experimentell** und als *eingeschränkte* Einstellung gekennzeichnet. Daher muss der Workspace vertrauenswürdig sein, damit sie angewendet wird. Die Unterstützung für Agent Plugins insgesamt ist eine Vorschaufunktion und wird durch `chat.plugins.enabled` gesteuert. Diese Option ist **standardmäßig aktiviert** — du musst sie nur setzen, wenn deine Organisation sie per Richtlinie deaktiviert.
</Note>

<Info>
VS Code verwendet nicht den Agent Plugins `$schema`. Sein Loader prüft `.plugin/plugin.json`, anschließend `.claude-plugin/plugin.json` und danach ein Root-`plugin.json`. MCP wird standardmäßig auf `.mcp.json` statt auf `mcp.json` gesetzt. Da dieses Repository ein generiertes `.claude-plugin/plugin.json` enthält, lädt VS Code es über diesen Kompatibilitätszweig und verwendet die `mcp-remote`-Bridge statt der nativen Transports in `mcp.json`. Alles funktioniert — nur der Pfad ist anders.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro liest das Agent-Plugins-Manifest nativ und lädt es als Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
Öffne in Kiro das Powers-Panel — das Ghosty-Symbol mit dem Blitz.
</Step>

<Step title="Import the folder">
Wähle **Add Custom Power → Import power from a folder**, wähle das geklonte Verzeichnis aus (das Verzeichnis, das `plugin.json` enthält) und klicke auf **Install**.
</Step>
</Steps>

Skills werden aus `skills/` geladen, MCP-Server aus `mcp.json`. Die Kiro-spezifische Darstellung stammt aus dem `dev.kiro`-Erweiterungsnamespace in `plugin.json`.

<Note>
Bei Plugins im Agent-Plugins-Format verwaltet Kiro MCP-Server intern — sie werden **nicht** in deine benutzereigene `~/.kiro/settings/mcp.json` geschrieben. Erwarte sie daher nicht dort. Kiro kann eine Power auch direkt über eine GitHub-URL installieren. Weitere Informationen findest du in der [Kiro-Installationsdokumentation](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI verfügt über keine Agent-Skill-Grundlage. Daher sind **nur die beiden MCP-Server verfügbar** — die siebzehn Skills nicht. `dodo-knowledge` deckt dennoch einen großen Teil der Funktionen der Skills ab und bleibt automatisch aktuell.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Starte Gemini CLI neu. `gemini-extension.json` im Root des Repositorys ist das Manifest.
</Accordion>
</AccordionGroup>

</Info>

## Das erhältst du

Sobald das Plugin installiert ist, hat dein Agent Zugriff auf zwei MCP-Server und siebzehn Skills.

### MCP-Server

| Server | Zweck | Auth |
|--------|---------|------|
| `dodopayments-api` | Live-API-Zugriff — Zahlungen, Abonnements, Kunden, Produkte, Rückerstattungen, Lizenzen und Nutzung | OAuth (Browser) |
| `dodo-knowledge` | Semantische Suche in der gesamten Dokumentation von Dodo Payments | Keine |

Beide Server verwenden Streamable HTTP. Das kanonische `mcp.json` deklariert sie nativ (`type: "streamable-http"`), wie es spezifikationskonforme Clients wie Codex CLI und Kiro verwenden. Das generierte Kompatibilitätsmanifest `.mcp.json` verbindet stattdessen dieselben beiden Endpunkte über `mcp-remote`. Dadurch funktionieren sie auch in Clients, die Streamable HTTP nicht direkt ansprechen können — Claude Code, VS Code und Cursor über die oben dokumentierte Git-Clone-Installation, deren `.cursor-plugin/plugin.json` auf `.mcp.json` verweist.

### Agent-Skills

| Skill | Beschreibung |
|-------|-------------|
| `dodo-best-practices` | SDK-Einrichtung, Umgebungen, API-Schlüssel und die kanonische Checkout-bis-Webhook-Architektur |
| `framework-adapters` | Offizielle `@dodopayments/*`-Route-Handler für Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun und Convex |
| `testing-and-go-live` | Testmodus, Testzahlungsmethoden, Webhook-Tests und Checkliste für den Produktionsstart |
| `checkout-integration` | Checkout Sessions, Zahlungslinks sowie Overlay- oder Inline-Checkout |
| `subscription-integration` | Lebenszyklus von Abonnements, Testphasen, Planänderungen, anteilige Abrechnung und bedarfsgesteuerte Gebühren |
| `mobile-checkout` | In-App-Checkout für React Native, Flutter, iOS und Android |
| `webhook-integration` | Empfangen und Überprüfen von Webhooks gemäß der Standard-Webhooks-Spezifikation |
| `credit-based-billing` | Kreditansprüche, Guthaben, Ledger, Übertrag, Überschreitung und meterbasierter Abzug |
| `usage-based-billing` | Meter, Eventaufnahme, Aggregation und Preis pro Einheit |
| `license-keys` | Aktivierung und Validierung von Lizenzschlüsseln sowie Verwaltung von Instanzen |
| `product-catalog-management` | Produkte, Preise, Add-ons, Sammlungen, Bilder und Bereitstellung digitaler Produkte |
| `discounts-and-promotions` | Rabattcodes, Berechtigungsregeln, Kombinationen und Limits für Abonnementzyklen |
| `localized-pricing` | Lokalisierte Preise, Adaptive Currency und Kaufkraftparität |
| `customer-management` | Kunden, Self-Service-Portal, gespeicherte Zahlungsmethoden und Wallets |
| `refunds-and-disputes` | Ausstellen von Rückerstattungen, Bearbeiten von Streitfällen und Chargebacks sowie Abgleich des Zugriffs |
| `billing-sdk` | BillingSDK-React-Komponenten für Preistabellen und Billing-UI |
| `better-auth-integration` | Das `@dodopayments/better-auth`-Plugin für Kundensynchronisierung, Checkout und Portalzugriff |

Skills werden automatisch geladen — dein Agent wählt den passenden Skill, sobald er eine relevante Aufgabe erkennt. Die vollständige Liste und individuelle Installationsanweisungen findest du in der [Agent-Skills-Dokumentation](/developer-resources/agent-skills).

### Probiere zuerst diesen Prompt aus

Sobald das Plugin aktiv ist, probiere Folgendes:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Dein Agent lädt den Skill `webhook-integration`, verwendet den `dodo-knowledge`-MCP, um die neuesten Payload-Strukturen abzurufen, und schreibt einen Handler mit Signaturüberprüfung gemäß der Standard-Webhooks-Spezifikation.

## Client-Unterstützung

### Clients mit Agent-Plugin-Installation

Eine Installation verbindet beide MCP-Server sowie die Skills mit jedem Client, der eine Skill-Grundlage besitzt.

| Agent | Installation | Skills | MCP-Server |
|-------|---------|-------:|------------:|
| **Claude Code** | Marketplace-Befehl | 17 | 2 |
| **Codex CLI** | Marketplace-Befehl | 17 | 2 |
| **Cursor** | Git-Clone | 17 | 2 |
| **VS Code / GitHub Copilot** | Git-Clone | 17 | 2 |
| **Kiro** | Git-Clone | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | Git-Clone | 0 | 2 |

- **OpenCode** benötigt einen zusätzlichen `skills.paths`-Eintrag, bevor seine siebzehn Skills geladen werden — siehe den Installationsabschnitt oben.
- **Gemini CLI** verfügt über keine Agent-Skill-Grundlage. Daher sind Skills dort absichtlich nicht verfügbar.

### Andere MCP-kompatible Clients

Diese Clients verfügen über keine Agent-Plugin-Installation. Konfiguriere die beiden MCP-Server manuell und füge Skills über die Skills CLI hinzu, sofern dies unterstützt wird.

| Agent | MCP-Server | Skills |
|-------|-------------|--------|
| Claude Desktop | [MCP-Server-Anleitung](/developer-resources/mcp-server) | nicht unterstützt |
| Windsurf | [MCP-Server-Anleitung](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / andere | [MCP-Server-Anleitung](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## Sicherheit und Best Practices

<Warning>
**Veröffentliche niemals API-Schlüssel für die Produktion.** Verwende während der Entwicklung den [Testmodus](/miscellaneous/test-mode-vs-live-mode). Das Agent Plugin verwendet standardmäßig Browser-OAuth — wechsle nur dann zu lokalen API-Schlüsseln, wenn dein Workflow dies erfordert.
</Warning>

- **Verwende zuerst den Testmodus.** Isoliere deine Integration mit `dodo_test_...`-Schlüsseln, bevor du live gehst. Siehe [Testmodus vs. Livemodus](/miscellaneous/test-mode-vs-live-mode).
- **OAuth ist der Standard.** Das Agent Plugin authentifiziert sich über Browser-OAuth (keine lokalen Secrets). Verwende den API-Key-Modus nur, wenn du ihn benötigst — siehe den Abschnitt „Konfigurieren“ weiter unten.
- **Überprüfe von Agents generierten Code.** Stelle immer sicher, dass Webhook-Handler eine Signaturüberprüfung gemäß der [Standard-Webhooks-Spezifikation](https://standardwebhooks.com/) enthalten.

## Mit einem API-Schlüssel konfigurieren

Standardmäßig verwendet das Agent Plugin den Remote-MCP-Server mit Browser-OAuth — lokale Zugangsdaten sind nicht erforderlich. Wenn dein Workflow einen lokalen API-Schlüssel erfordert (z. B. CI-Umgebungen oder Headless-Server), kannst du in den stdio-Modus wechseln.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Öffne `/plugins` in Claude Code, wähle **Dodo Payments** aus und klicke auf **Configure options**. Fülle Folgendes aus:

- `dodo_api_key` — dein `dodo_test_...`- oder `dodo_live_...`-Schlüssel
- `dodo_webhook_key` — dein Webhook-Signatur-Secret
- `dodo_environment` — `test_mode` oder `live_mode`

Bearbeite anschließend `.mcp.json`, sodass `dodopayments-api` auf den lokalen stdio-Server verweist:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Führe `/reload-plugins` aus, um die Änderungen auf deine aktuelle Sitzung anzuwenden.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Deklariere `dodopayments-api` selbst in `opencode.json` — dein Eintrag hat Vorrang vor dem standardmäßigen Remote-Server des Plugins:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Starte OpenCode neu, um die Änderungen anzuwenden.
</Accordion>
</AccordionGroup>
