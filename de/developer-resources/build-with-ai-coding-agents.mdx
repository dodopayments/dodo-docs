Das Dodo Agent Plugin bindet zwei MCP server und siebzehn Integrations-Skills mit einer einzigen Installation in deinen KI-Coding-Agent ein. Es funktioniert mit **Claude Code**, **Codex CLI**, **Cursor** und **OpenCode** — und die MCP server sowie die Skills CLI funktionieren mit jedem MCP-kompatiblen Client.

<Info>
**Drei Grundbausteine, ein Plugin.** Das Agent Plugin bündelt alles, was du brauchst:
- **API MCP server** — Live-Zugriff auf Zahlungen, Abonnements, Kunden, Produkte, Rückerstattungen, Lizenzen und Nutzung. Die Authentifizierung erfolgt über Browser-OAuth (keine lokalen Schlüssel erforderlich).
- **Knowledge MCP server** — Semantische Suche in der gesamten Dokumentation von Dodo Payments. Keine Zugangsdaten erforderlich.
- **Siebzehn Agent-Skills** — Spickzettel, die dein Agent bei Bedarf für Checkout, Abonnements, Webhooks, nutzungsbasierte und kreditbasierte Abrechnung, Lizenzschlüssel, Produktkatalog, Rabatte, lokalisierte Preise, mobilen Checkout, Rückerstattungen und Disputes, Kundenverwaltung, Framework-Adapter, BillingSDK, Better Auth, Tests und Go-live sowie Best Practices lädt.
</Info>

## Plugin installieren

Wähle unten deinen Coding-Agent aus. Die Installation fügt automatisch beide MCP server und alle siebzehn Skills hinzu.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installation aus dem Marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

Der API MCP Server verwendet standardmäßig Browser-OAuth — keine Schlüssel erforderlich zur Installationszeit. Beim ersten Aufruf eines Dodo-Tools durch Ihren Agenten werden Sie aufgefordert, sich anzumelden.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Quellcode, Konfigurationsoptionen und Anweisungen zur lokalen Entwicklung
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installiert Plugins in zwei Schritten: Zuerst den Marktplatz über Ihr Terminal registrieren, dann das Plugin innerhalb der Codex TUI installieren.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Öffnen Sie Codex und führen Sie den `/plugins` Slash-Befehl aus:

```bash
codex
```

Geben Sie dann `/plugins` ein, wechseln Sie zum **Dodo Payments** Marktplatz, wählen Sie das Plugin **dodopayments** und wählen Sie **Plugin installieren**.
</Step>
</Steps>

Beide MCP server und alle siebzehn Skills werden automatisch registriert, sobald das Plugin installiert ist.

<Note>
Codex CLI hat keinen `codex plugin install` Unterbefehl — die Plugin-Installation erfolgt immer über den in-TUI `/plugins` Flow. Siehe die [offiziellen Codex Plugins-Dokumentation](https://developers.openai.com/codex/plugins).
</Note>

Wenn Sie den Marktplatz zuvor hinzugefügt haben und das Plugin nicht unter `/plugins` erscheint, aktualisieren Sie es:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Manuelle Installation — klonen Sie das Repository in das lokale Plugins-Verzeichnis von Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Starten Sie Cursor neu. Das Plugin lädt Skills von `.claude/skills/` (über die Claude Code-Kompatibilitätsschicht von Cursor) und MCP-Server von `.mcp.json`.

<Info>
Cursor-Marktplatz-Unterstützung ist in Arbeit. Vorerst verwenden Sie die oben beschriebene manuelle Installation.
</Info>
</Accordion>

<Accordion title="OpenCode">
OpenCode wird über npm verteilt. Fügen Sie das Plugin zu Ihrem `opencode.json` hinzu:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Starte OpenCode neu. Beide MCP server (`dodopayments-api`, `dodo-knowledge`) werden über den Config-Hook des Plugins automatisch registriert, und die siebzehn Skills werden automatisch aus dem installierten Paket erkannt. Kein manueller `mcp`-Block erforderlich.
</Accordion>
</AccordionGroup>

<Info>
Verwenden Sie einen anderen Agenten? Die [MCP Server](/developer-resources/mcp-server) und [Agent Skills](/developer-resources/agent-skills) Anleitungen behandeln Cursor, Claude Desktop, VS Code, Windsurf, Cline, Zed und jeden MCP-kompatiblen Client.
</Info>

## Was Sie erhalten

Sobald das Plugin installiert ist, hat dein Agent Zugriff auf zwei MCP server und siebzehn Skills.

### MCP-Server

| Server | Zweck | Auth |
|--------|-------|------|
| `dodopayments-api` | Live-API-Zugriff — Zahlungen, Abonnements, Kunden, Produkte, Rückerstattungen, Lizenzen, Nutzung | OAuth (Browser) |
| `dodo-knowledge` | Semantische Suche in der gesamten Dodo Payments-Dokumentation | Keine |

Beide Server sind durch `mcp-remote` verbunden, sodass sie in jedem MCP-kompatiblen Client laufen.

### Agent-Skills

| Skill | Beschreibung |
|-------|-------------|
| `best-practices` | SDK-Einrichtung, Umgebungen, API keys und die kanonische Checkout-to-Webhook-Architektur |
| `framework-adapters` | Offizielle `@dodopayments/*` Route-Handler für Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun und Convex |
| `testing-and-go-live` | Testmodus, Testzahlungsmethoden, Webhook-Tests und die Checkliste für den Produktivstart |
| `checkout-integration` | Checkout Sessions, Zahlungslinks sowie Overlay- oder Inline-Checkout |
| `subscription-integration` | Lebenszyklus von Abonnements, Testzeiträume, Planänderungen, anteilige Abrechnung und On-Demand-Gebühren |
| `mobile-checkout` | In-App-Checkout für React Native, Flutter, iOS und Android |
| `webhook-integration` | Empfangen und Verifizieren von Webhooks mithilfe der Standard-Webhooks-Spezifikation |
| `credit-based-billing` | Kreditansprüche, Salden, Ledger, Übertrag, Übernutzung und zählerbasierter Abzug |
| `usage-based-billing` | Zähler, Event-Ingestion, Aggregation und Preise pro Einheit |
| `license-keys` | Aktivierung und Validierung von Lizenzschlüsseln sowie Verwaltung von Instanzen |
| `product-catalog-management` | Produkte, Preise, Add-ons, Sammlungen, Bilder und die Bereitstellung digitaler Produkte |
| `discounts-and-promotions` | Rabattcodes, Berechtigungsregeln, Kombinationen und Limits für Abonnementzyklen |
| `localized-pricing` | Lokalisierte Preise, adaptive Währung und Kaufkraftparität |
| `customer-management` | Kunden, das Self-Service-Portal, gespeicherte Zahlungsmethoden und Wallets |
| `refunds-and-disputes` | Rückerstattungen ausstellen, Disputes und Chargebacks bearbeiten sowie den Zugriff abgleichen |
| `billing-sdk` | BillingSDK React-Komponenten für Preistabellen und Billing-Oberflächen |
| `better-auth-integration` | Das `@dodopayments/better-auth` Plugin für Kundensynchronisierung, Checkout und Portalzugriff |

Skills werden automatisch geladen — Ihr Agent wählt den richtigen aus, wenn er eine relevante Aufgabe erkennt. Siehe die [Agent Skills Dokumentation](/developer-resources/agent-skills) für die vollständige Liste und individuelle Installation.

### Probieren Sie diesen Prompt zuerst aus

Sobald das Plugin aktiv ist, versuchen Sie:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Ihr Agent lädt den `webhook-integration` Skill, verwendet den `dodo-knowledge` MCP, um die neuesten Payload-Strukturen abzurufen, und schreibt einen Handler mit Signaturprüfung nach dem Standard Webhooks-Spezifikation.

## Speziell für Agenten erstellte Dokumente

Jede Dodo Payments-Dokumentationsseite ist in einem für den KI-Verbrauch optimierten Format verfügbar:

- **Vollständiges Dokumentenindex**: [`docs.dodopayments.com/llms.txt`](https://docs.dodopayments.com/llms.txt) — dient als vollständiger Dokumentenindex für die Kontextaufnahme.
- **Reines Markdown**: Fügen Sie `.md` zu jeder Dokumentations-URL hinzu, um die rohe Markdown-Version zu erhalten (z. B. `/api-reference/introduction.md`).
- **Quellrepository**: [`github.com/dodopayments/dodo-docs`](https://github.com/dodopayments/dodo-docs) — klonen Sie für die Offline-Indexierung.

## Sicherheit und Best Practices

<Warning>
**Veröffentlichen Sie niemals Produktions-API-Schlüssel.** Verwenden Sie während der Entwicklung den [Testmodus](/miscellaneous/test-mode-vs-live-mode). Das Agent Plugin verwendet standardmäßig Browser-OAuth — wechseln Sie nur zu lokalen API-Schlüsseln, wenn Ihr Arbeitsablauf dies erfordert.
</Warning>

- **Verwenden Sie zuerst den Testmodus.** Testen Sie Ihre Integration mit `dodo_test_...` Schlüsseln, bevor Sie live gehen. Siehe [Testmodus vs Livemodus](/miscellaneous/test-mode-vs-live-mode).
- **OAuth ist der Standard.** Das Agent Plugin authentifiziert über Browser-OAuth (keine lokalen Geheimnisse). Verwenden Sie den API-Schlüsselmodus nur, wenn Sie ihn benötigen — siehe den Abschnitt Konfiguration unten.
- **Überprüfen Sie agentengenerierten Code.** Stellen Sie sicher, dass Webhook-Handler die Signaturverifizierung gemäß der [Standard Webhooks-Spezifikation](https://standardwebhooks.com/) enthalten.

## Mit einem API-Schlüssel konfigurieren

Standardmäßig verwendet das Agent Plugin den entfernten MCP-Server mit Browser-OAuth — keine lokalen Anmeldedaten erforderlich. Wenn Ihr Arbeitsablauf einen lokalen API-Schlüssel erfordert (z.B. CI-Umgebungen, headless Server), können Sie in den Stdio-Modus wechseln.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Öffnen Sie `/plugins` in Claude Code, wählen Sie **Dodo Payments** und wählen Sie **Konfigurationsoptionen**. Füllen Sie ein:

- `dodo_api_key` — Ihr `dodo_test_...` oder `dodo_live_...` Schlüssel
- `dodo_webhook_key` — Ihr Webhook-Signatur-Geheimnis
- `dodo_environment` — `test_mode` oder `live_mode`

Bearbeiten Sie dann `.mcp.json`, um `dodopayments-api` auf den lokalen Stdio-Server zu verweisen:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Führen Sie `/reload-plugins` aus, um Änderungen in Ihrer aktuellen Sitzung anzuwenden.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Deklarieren Sie `dodopayments-api` selbst in `opencode.json` — Ihr Eintrag gewinnt über den Standard-Remote-Server des Plugins:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Starten Sie OpenCode neu, um anzuwenden.
</Accordion>
</AccordionGroup>
