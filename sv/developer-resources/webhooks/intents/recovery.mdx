## Övergivna varukorgsåterställningshändelser

Följande webhook-händelser spårar livscykeln för övergiven varukorgsåterställning:

| Händelse | Beskrivning |
|-------|-------------|
| `abandoned_checkout.detected` | En övergiven utcheckning har upptäckts. Skickas när en betalning identifieras som övergiven (misslyckad eller ofullständig) och återställningsarbetsflödet börjar. |
| `abandoned_checkout.recovered` | Kunden slutförde betalningen via återställningslänken. Fältet `recovered_payment_id` innehåller det lyckade betalnings-ID:t. |

### Fält för övergiven utcheckningsnyttolast

<ParamField body="payment_id" type="string" required>
Den ursprungliga betalningen som övergavs. Använd denna för att leta upp produkt-, belopps- och valutainformation.
</ParamField>

<ParamField body="brand_id" type="string" required>
Varumärket som denna övergivna checkout tillhör.
</ParamField>

<ParamField body="customer_id" type="string" required>
Kunden som övergav checkouten.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
Varför checkouten övergavs. Ett av följande:
- `payment_failed` — Kunden försökte genomföra betalningen, men den misslyckades
- `checkout_incomplete` — Kunden besökte checkouten men försökte aldrig genomföra betalningen
</ParamField>

<ParamField body="status" type="string" required>
Aktuellt livscykeltillstånd för detta återställningsförsök. Ett av följande:
- `abandoned` — Identifierad, inga e-postmeddelanden har skickats ännu
- `recovering` — Minst ett återställningsmeddelande har skickats
- `recovered` — Kunden har slutfört betalningen
- `exhausted` — Alla e-postmeddelanden har skickats eller en nyare checkout har hittats
- `opted_out` — Kunden har avslutat prenumerationen
</ParamField>

<ParamField body="abandoned_at" type="string" required>
ISO 8601-tidsstämpel för när checkouten identifierades som övergiven.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
Betalnings-ID:t för den lyckade återställningsbetalningen. `null` tills checkouten har återställts.
</ParamField>

### Exempel: Hantera ACR-webhooks

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## Dunning-händelser

Följande webhook-händelser spårar prenumerationens Dunning-livscykel:

| Händelse | Beskrivning |
|-------|-------------|
| `dunning.started` | Ett Dunning-försök har skapats för en prenumeration som övergick till `on_hold` eller avslutades av kunden. |
| `dunning.recovered` | Kunden uppdaterade sin betalningsmetod och den resulterande betalningen lyckades. Fältet `payment_id` innehåller ID:t för den lyckade betalningen. |

### Fält i nyttolasten för Dunning-försök

<ParamField body="subscription_id" type="string" required>
Prenumerationen som utlöste Dunning-försöket.
</ParamField>

<ParamField body="brand_id" type="string" required>
Varumärket som detta Dunning-försök tillhör.
</ParamField>

<ParamField body="customer_id" type="string" required>
Kunden som äger prenumerationen.
</ParamField>

<ParamField body="trigger_state" type="string" required>
Prenumerationstillståndet som utlöste Dunning. Ett av följande:
- `on_hold` — Prenumerationen pausades på grund av ett betalningsfel
- `cancelled` — Kunden avslutade prenumerationen från kundportalen
</ParamField>

<ParamField body="status" type="string" required>
Aktuellt livscykeltillstånd för detta Dunning-försök. Ett av följande:
- `recovering` — Dunning-e-postmeddelanden skickas
- `recovered` — Kunden uppdaterade betalningsmetoden och betalningen lyckades
- `exhausted` — Alla e-postmeddelanden har skickats eller prenumerationens tillstånd har ändrats
</ParamField>

<ParamField body="created_at" type="string" required>
ISO 8601-tidsstämpel för när Dunning-försöket skapades.
</ParamField>

<ParamField body="payment_id" type="string | null">
Betalnings-ID:t för den lyckade återställningsbetalningen. `null` under återställningen.
</ParamField>

### Exempel: Hantera Dunning-webhooks

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
Prenumerera på både `dunning.started` och `dunning.recovered` för att spåra hela Dunning-livscykeln. Använd `dunning.started` för att pausa respitperioder eller markera prenumerationer i riskzonen i ditt system.
</Tip>
