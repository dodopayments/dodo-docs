Dodo Payments har en inbyggd funktion för databassynkronisering som automatiskt synkroniserar dina betalningsdata med din egen databas. Du kan synkronisera **betalningar**, **kunder**, **prenumerationer** och **licenser** för att upprätthålla en lokal kopia av dina data för analys, rapportering eller integration med andra system.

<Info>
**Implementering**: Tillgänglig via [npm-paket](https://www.npmjs.com/package/dodo-sync) | **Källkod**: [GitHub](https://github.com/dodopayments/dodo-sync)
</Info>

## Vad kan du synkronisera?

Vår funktion för databassynkronisering stöder synkronisering av följande Dodo Payments-entiteter till din databas:

<CardGroup cols={2}>
  <Card title="Payments" icon="credit-card">
    Synkronisera alla betalningstransaktioner, inklusive engångsbetalningar, återbetalningar och uppdateringar av betalningsstatus.
  </Card>
  <Card title="Customers" icon="users">
    Håll dina kunddata synkroniserade, inklusive kundprofiler, kontaktuppgifter och metadata.
  </Card>
  <Card title="Subscriptions" icon="repeat">
    Synkronisera prenumerationsdata, inklusive aktiva prenumerationer, faktureringscykler och ändringar av prenumerationsstatus.
  </Card>
  <Card title="Licenses" icon="key">
    Synkronisera licensinformation, inklusive licensnycklar, aktiveringar och uppdateringar av licensstatus.
  </Card>
</CardGroup>

Du kan synkronisera valfri kombination av dessa entiteter genom att ange dem i parametern `scopes`. Alla synkroniseringsåtgärder är inkrementella och överför endast nya eller uppdaterade poster för optimal prestanda.

## Databasstöd

Vi stöder för närvarande **MongoDB**, **PostgreSQL**, **MySQL** och **ClickHouse**.

Vi arbetar aktivt med att utöka stödet för:
- **Databaser**: Snowflake och andra.
- **Pipelines**: ETL-pipelines, Realtime-synkronisering.

<Tip>
Vi utökar kontinuerligt databasstödet. Om du vill bidra med en ny datasintegration kan du skicka en Pull Request till vårt [GitHub-arkiv](https://github.com/dodopayments/dodo-sync).
</Tip>

## Kom igång

Du kan använda vår funktion för databassynkronisering via **CLI** eller programmatiskt i din **kod**. Båda metoderna erbjuder samma funktionalitet – välj den som passar ditt arbetsflöde bäst.

### Använda CLI

CLI-verktyget erbjuder ett snabbt sätt att konfigurera och köra databassynkronisering. Installera det globalt för att kunna använda det från valfri plats i terminalen:

<CodeGroup>

```bash npm
npm install -g dodo-sync
```

```bash bun
bun add -g dodo-sync
```

</CodeGroup>

#### Köra CLI

CLI stöder två lägen: **Interaktivt läge** för guidad konfiguration och **Manuellt läge** för direkt konfiguration.

**Interaktivt läge**: Kör kommandot utan argument för att starta den interaktiva konfigurationsguiden.

```bash
dodo-sync
```

**Manuellt läge**: Skicka argument direkt för att hoppa över guiden.

```bash
dodo-sync -i [interval] -d [database] -u [database_uri] --scopes [scopes] --api-key [api_key] --env [environment]
```

**Exempel:**

```bash
# MongoDB
dodo-sync -i 600 -d mongodb -u mongodb://mymongodb.url --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# PostgreSQL
dodo-sync -i 600 -d postgres -u postgresql://user:password@localhost:5432/mydb --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# MySQL
dodo-sync -i 600 -d mysql -u mysql://user:password@localhost:3306/mydb --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode

# ClickHouse
dodo-sync -i 600 -d clickhouse -u http://localhost:8123 --scopes "licences,payments,customers,subscriptions" --api-key YOUR_API_KEY --env test_mode
```

#### CLI-argument

<ParamField path="--interval" type="number" alias="-i">
Synkroniseringsintervall i sekunder. Anger hur ofta synkroniseringsåtgärden körs. Om det inte anges körs synkroniseringen en gång och avslutas sedan.
</ParamField>

<ParamField path="--database" type="string" alias="-d" required>
Databastyp som ska användas. Tillåtna värden: `"mongodb"`, `"postgres"`, `"mysql"` eller `"clickhouse"`.
</ParamField>

<ParamField path="--database-uri" type="string" alias="-u" required>
Anslutnings-URI för din databas:
- **MongoDB**: `mongodb://localhost:27017` eller `mongodb+srv://user:pass@cluster.mongodb.net/`
- **PostgreSQL**: `postgresql://user:password@localhost:5432/mydb`
- **MySQL**: `mysql://user:password@localhost:3306/mydb`
- **ClickHouse**: `http://localhost:8123`
</ParamField>

<ParamField path="--scopes" type="string" required>
Kommaseparerad lista över dataentiteter som ska synkroniseras. Tillgängliga scopes: `licences`, `payments`, `customers`, `subscriptions`. Exempel: `"payments,customers"`.
</ParamField>

<ParamField path="--api-key" type="string" required>
Din Dodo Payments API-nyckel. Ska börja med `dp_live_` för live-läge eller `dp_test_` för testläge.
</ParamField>

<ParamField path="--env" type="string" required>
Miljömål. Måste vara antingen `"live_mode"` eller `"test_mode"`. Detta avgör vilken Dodo Payments-miljö som ska synkroniseras.
</ParamField>

<ParamField path="--rate-limit" type="number" alias="--rl">
Hastighetsbegränsning i requests per sekund. Styr hur snabbt synkroniseringsmotorn gör API-requests för att undvika att överbelasta Dodo Payments API.
</ParamField>

### Använda i din kod

För programmatisk kontroll kan du integrera synkroniseringsfunktionen direkt i din applikation. Installera den som ett beroende i ditt projekt:

<CodeGroup>

```bash npm
npm install dodo-sync
```

```bash bun
bun add dodo-sync
```

</CodeGroup>

#### Automatisk synkronisering (intervallbaserad)

Använd automatisk synkronisering när du vill att synkroniseringen ska köras kontinuerligt med regelbundna intervall:

```typescript
import { DodoSync } from 'dodo-sync';

const syncDodoPayments = new DodoSync({
  interval: 60, // Sync every 60 seconds
  database: 'mongodb',
  databaseURI: process.env.MONGODB_URI, // e.g., 'mongodb://localhost:27017'
  scopes: ['licences', 'payments', 'customers', 'subscriptions'],
  dodoPaymentsOptions: {
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode' // or 'live_mode'
  }
});

// Initialize connection
await syncDodoPayments.init();

// Start the sync loop
syncDodoPayments.start();
```

<Tip>
Alternativet `interval` krävs när `.start()` används för automatisk synkronisering. Synkroniseringen körs kontinuerligt med det angivna intervallet tills processen stoppas.
</Tip>

#### Manuell synkronisering

Använd manuell synkronisering när du vill utlösa synkroniseringsåtgärder vid behov, till exempel från ett cron-jobb eller en API-endpoint:

```typescript
import { DodoSync } from 'dodo-sync';

const syncDodoPayments = new DodoSync({
  database: 'mongodb',
  databaseURI: process.env.MONGODB_URI,
  scopes: ['licences', 'payments', 'customers', 'subscriptions'],
  dodoPaymentsOptions: {
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode'
  }
});

// Initialize connection
await syncDodoPayments.init();

// Trigger a single sync operation
await syncDodoPayments.run();
```

<Tip>
När du använder manuell synkronisering krävs inte alternativet `interval`. Du kan anropa `.run()` när du behöver utföra en synkroniseringsåtgärd.
</Tip>

<ParamField body="databaseURI" type="string" required>

## Viktig information

<Warning>
**MongoDB**: En databas med namnet `dodopayments_sync` skapas automatiskt på din databasserver. Alla synkroniserade data lagras där. Databasnamnet är för närvarande fast och kan inte ändras.

**PostgreSQL**: Tabeller (`Subscriptions`, `Payments`, `Licenses`, `Customers`) skapas i den databas som anges i din anslutnings-URI. Data lagras som JSONB.

**MySQL**: Tabeller (`Subscriptions`, `Payments`, `Licenses`, `Customers`) skapas i den databas som anges i din anslutnings-URI. Data lagras som JSON.

**ClickHouse**: Tabeller (`Subscriptions`, `Payments`, `Licenses`, `Customers`) skapas med motorn ReplacingMergeTree. Använd nyckelordet `FINAL` vid frågor för att säkerställa deduplicerade resultat.
</Warning>

<Info>
Synkroniseringsmotorn spårar ändringar och synkroniserar endast nya eller uppdaterade poster, vilket gör efterföljande synkroniseringar effektiva även med stora datamängder.
</Info>
