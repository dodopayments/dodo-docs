## Prerequisites

To integrate the Dodo Payments API, you'll need:
- A Dodo Payments merchant account
- API Credentials (API key and webhook secret key) from dashboard

## Dashboard Setup

1. Navigate to the [Dodo Payments Dashboard](https://app.dodopayments.com/)

2. Skapa en produkt (engångsbetalning eller prenumeration). Prenumerationsprodukter måste ha ett pris på minst **\$1** (eller motsvarande i den valda valutan); belopp under denna miniminivå stöds inte.

4. Generera din API-nyckel:
   - Gå till Developer > API
   - [Detaljerad guide](/api-reference/introduction#api-key-management-and-authentication)
   - Kopiera API-nyckeln i env med namnet DODO_PAYMENTS_API_KEY

5. Configure webhooks:
   - Go to Developer > Webhooks
   - Create a webhook URL for payment notifications
   - Copy the webhook secret key in env 

## Integration

### Payment Links

Välj den integrationsväg som passar ditt användningsfall:
- **Checkout Sessions (rekommenderas)**: Bäst för de flesta integrationer. Skapa en session på din server och omdirigera kunder till en säker, värdbaserad checkout.
- **Overlay Checkout**: Använd detta när du behöver en upplevelse på sidan där checkout öppnas som ett modalt överlägg på din webbplats.
- **Inline Checkout**: Bädda in checkout direkt i sidans layout för en helt integrerad och varumärkesanpassad checkout-upplevelse.
- **Static Payment Links**: Kodfria, direkt delbara URL:er för snabb insamling av betalningar.
- **Dynamic Payment Links**: Länkar som skapas programmatiskt. Checkout Sessions rekommenderas dock eftersom de ger större flexibilitet.
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**: För inbyggda Android-, iOS-, React Native- och Flutter-appar. Skapa sessionen på din server enligt ovan och skicka sedan `checkout_url` till SDK:t.

<Info>
Overlay och Inline Checkout är endast för webbläsare — de bäddar in checkout på en webbsida. Om du bygger en inbyggd mobilapp ska du skapa checkout-sessionen på din server och öppna den med [Mobile Checkout SDKs](/developer-resources/mobile-integration) i stället.
</Info>

#### 1. Checkout Sessions

Använd Checkout Sessions för att skapa en säker, värdbaserad checkout-upplevelse för engångsbetalningar eller prenumerationer. Du skapar en session på din server och omdirigerar sedan kunden till den returnerade `checkout_url`.

<Info>
Checkout-sessioner är som standard giltiga i 24 timmar. Om du skickar <code>confirm=true</code> är sessionerna giltiga i 15 minuter och alla obligatoriska fält måste anges.
</Info>

<Steps>
<Step title="Create a checkout session">
  Välj önskat SDK eller anropa REST API.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python

  from dodopayments import DodoPayments

  client = DodoPayments(
      bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
      environment="test_mode",  # defaults to "live_mode"
  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "pdt_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

  </Tab>

  ```javascript
      product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  ```

<Step title="Redirect customer to checkout">
  Efter att sessionen har skapats omdirigerar du till `checkout_url` för att starta det värdbaserade flödet.


#### 2. Overlay Checkout

För en smidig checkout-upplevelse på sidan kan du utforska vår integration för [Overlay Checkout](/developer-resources/overlay-checkout), som gör det möjligt för kunder att slutföra betalningar utan att lämna din webbplats.

#### 3. Inline Checkout

För helt integrerade checkout-upplevelser som bäddas in direkt på sidan använder du vår integration för [Inline Checkout](/developer-resources/inline-checkout). Då kan du skapa anpassade ordersammanfattningar och ha full kontroll över checkout-layouten, medan Dodo Payments hanterar betalningsinsamlingen på ett säkert sätt.

#### 4. Static Payment Links

Med statiska betalningslänkar kan du snabbt ta emot betalningar genom att dela en enkel URL. Du kan anpassa checkout-upplevelsen genom att skicka query-parametrar för att förifylla kunduppgifter, styra formulärfält och lägga till anpassade metadata.

<Steps>
<Step title="Construct your payment link">
  Börja med bas-URL:en och lägg till ditt produkt-ID:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  Inkludera viktiga query-parametrar:
  - <ParamField query="quantity" type="integer" default="1">Antal artiklar som ska köpas.</ParamField>
  - <ParamField query="redirect_url" type="string" required>URL dit kunden ska omdirigeras efter att betalningen har slutförts.</ParamField>
  <Note>
  Omdirigerings-URL:en innehåller betalningsuppgifter som query-parametrar, till exempel:<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  Om produkten har licensnycklar aktiverade läggs även en `license_key`-parameter till (kommaseparerad för flera nycklar):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  Lägg till kund- eller faktureringsfält som query-parametrar för att förenkla checkout.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">Kundens fullständiga namn (ignoreras om firstName eller lastName anges).</ParamField>
      - <ParamField query="firstName" type="string">Kundens förnamn.</ParamField>
      - <ParamField query="lastName" type="string">Kundens efternamn.</ParamField>
      - <ParamField query="email" type="string">Kundens e-postadress.</ParamField>
      - <ParamField query="country" type="string">Kundens land.</ParamField>
      - <ParamField query="addressLine" type="string">Gatuadress.</ParamField>
      - <ParamField query="city" type="string">Ort.</ParamField>
      - <ParamField query="state" type="string">Delstat eller provins.</ParamField>
      - <ParamField query="zipCode" type="string">Postnummer/ZIP-kod.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true eller false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  Du kan inaktivera specifika fält så att de blir skrivskyddade för kunden. Detta är användbart när du redan har kundens uppgifter (t.ex. för inloggade användare).
  </Info>
  Om du vill inaktivera ett fält anger du dess värde och ställer in motsvarande <code>disable...</code>-flagga på <code>true</code>:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Field         | Disable Flag         | Required Parameter |
      |---------------|---------------------|-------------------|
      | Full Name     | `disableFullName`   | `fullName`        |
      | First Name    | `disableFirstName`  | `firstName`       |
      | Last Name     | `disableLastName`   | `lastName`        |
      | Email         | `disableEmail`      | `email`           |
      | Country       | `disableCountry`    | `country`         |
      | Address Line  | `disableAddressLine`| `addressLine`     |
      | City          | `disableCity`       | `city`            |
      | State         | `disableState`      | `state`           |
      | ZIP Code      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  Att inaktivera fält bidrar till att förhindra oavsiktliga ändringar och säkerställer datakonsistens.
  </Tip>
  <Note>
  Om du ställer in <code>showDiscounts=false</code> inaktiveras och döljs rabattsektionen i checkout-formuläret. Använd detta om du vill förhindra att kunder anger kupong- eller kampanjkoder under checkout.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">Anger betalningsvalutan. Standardvärdet är faktureringslandets valuta.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">Visa eller dölj valutaväljaren.</ParamField>
  - <ParamField query="paymentAmount" type="number">Fastställer det debiterade beloppet i större valutaenheter (t.ex. <code>12.5</code> för 12,50 USD). Gäller endast Pay What You Want-produkter. Värdet ignoreras om det understiger produktens minimipris.</ParamField>
  - <ParamField query="metadata_*" type="string">Anpassade metadatafält (t.ex. <code>metadata_orderId=123</code>).</ParamField>

  <Warning>
  `paymentAmount` på en betalningslänk är **inte samma enhet som fältet `amount` i Checkout Sessions API**. Länkparametern använder större valutaenheter (`12.5` = 12,50 USD), medan API:ets `product_cart[].amount` använder den minsta valören (`1250` = 12,50 USD). Se [Dynamic Pricing](/developer-resources/dynamic-pricing-checkout) för API-fältet.
  </Warning>
</Step>
<Step title="Share the link">
  Skicka den färdiga betalningslänken till din kund. När kunden besöker länken samlas alla frågeparametrar in och lagras med ett sessions-ID. URL:en förenklas sedan till att endast innehålla sessionsparametern (t.ex. <code>?session=sess_1a2b3c4d</code>). Den lagrade informationen finns kvar vid siduppdateringar och är tillgänglig under hela checkoutprocessen.
  <Check>
  Kundens checkoutupplevelse är nu smidigare och personanpassad utifrån dina parametrar.
  </Check>
</Step>
</Steps>

#### 4. Dynamiska betalningslänkar
<Tip>
Välj Checkout Sessions för de flesta användningsområden; de ger större flexibilitet och kontroll.
</Tip>

Skapas via ett API-anrop eller vårt SDK med kunduppgifter. Här är ett exempel:

Det finns två API:er för att skapa dynamiska betalningslänkar:

- One-time Payment Link API [API-referens](/api-reference/payments/post-payments)
- Subscription Payment Link API [API-referens](/api-reference/subscriptions/post-subscriptions)

<Warning>
Båda slutpunkterna för att skapa länkar är **föråldrade**. `POST /payments` och `POST /subscriptions` fortsätter att fungera för befintliga integrationer, men nya integrationer bör använda [Checkout Sessions](/developer-resources/checkout-session) (`POST /checkouts`) i stället.

### Implementera webhooks

Konfigurera en API-slutpunkt för att ta emot betalningsaviseringar. Här är ett exempel med Next.js:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

Vår webhook-implementation följer specifikationen [Standard Webhooks](https://standardwebhooks.com/). Definitioner av webhook-typer finns i vår [guide till webhookhändelser](/developer-resources/webhooks/intents/webhook-events-guide).

#### Händelser att lyssna efter

Aktivera `payload.type` och hantera de händelser som är relevanta för ett engångsbetalningsflöde. Lyssna som minst efter:

| Händelsetyp           | När den utlöses                                              | Vad du ska göra                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | Betalningen har behandlats utan problem.                        | Slutför ordern — ge åtkomst, tillhandahåll produkten och skicka kvittot. |
| `payment.failed`     | Betalningsförsöket misslyckas (nekat kort, fel osv.).       | Meddela kunden och be hen försöka igen; slutför inte ordern.                    |
| `payment.processing` | Betalningen har godkänts men behandlas fortfarande (asynkrona metoder). | Vänta på den slutliga `payment.succeeded`/`payment.failed` — slutför inte ordern ännu. |
| `payment.cancelled`  | Betalningen avbryts innan den slutförs.                   | Frigör eventuell reserverad status och markera ordern som övergiven.                       |

<Tip>
Slutför alltid ordern vid `payment.succeeded` från webhooken**, inte vid webbläsarens omdirigering — omdirigeringen kan missas om kunden stänger fliken, medan webhooken försöks igen tills den har bekräftats.
</Tip>

Om du säljer digitala produkter med licensnycklar ska du även hantera `license_key.created`. En fullständig lista över händelser — inklusive händelser för prenumerationer, rättigheter, krediter, återställning och kravhantering — finns i [guide till webhookhändelser](/developer-resources/webhooks/intents/webhook-events-guide).

Du kan hänvisa till detta projekt med en demoimplementation på [GitHub](https://github.com/dodopayments/dodo-checkout-demo) som använder Next.js och TypeScript.

Du kan se den aktiva implementationen [här](https://atlas.dodopayments.com/).

## Viktigt att känna till om Checkout och valutor

<Warning>
**Dynamiska belopp (Pay-What-You-Want) anges i produktens basvaluta** — inte i en valfri lokal valuta — och basvalutan är begränsad till **USD, INR, GBP och EUR**. Om du vill ta ut ett fast belopp i en annan valuta (t.ex. PHP) kan du inte skicka det direkt: använd **Adaptive Pricing** (omvandlar ditt basbelopp med aktuell växelkurs) eller **Localized Pricing** (fast pris per valuta, men är inte kompatibelt med Pay-What-You-Want).
</Warning>

<Tip>
**Ange valutan uttryckligen.** Skicka `billing_currency` och `billing_address.country` i checkoutsessionen. Om de utelämnas identifieras valuta och land från kundens IP (Adaptive Currency), vilket kanske inte motsvarar det du avser att debitera.
</Tip>

<Info>
**Checkoutsessioner upphör efter 24 timmar** (15 minuter när `confirm: true`), och varje `checkout_url` är **avsett att användas en gång** — skapa en ny session för varje kund och betalningsförsök i stället för att återanvända en länk.
</Info>

<Info>
**Återkommande köp med ett klick.** För en återkommande kund med en sparad betalningsmetod skickar du `payment_method_id` tillsammans med `confirm: true` för att debitera direkt och helt hoppa över valet av metod.
</Info>
