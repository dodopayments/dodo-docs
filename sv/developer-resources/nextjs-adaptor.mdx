## Installation

<Steps>
<Step title="Install the package">
Kör följande kommando i projektets rotkatalog:

```bash
npm install @dodopayments/nextjs
```

</Step>
<Step title="Set up environment variables">
Skapa en <code>.env</code>-fil i projektets rotkatalog:

```env
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_RETURN_URL=https://yourdomain.com/checkout/success
DODO_PAYMENTS_ENVIRONMENT="test_mode"or"live_mode"
```

<Warning>
Checka aldrig in din <code>.env</code>-fil eller hemligheter i versionshanteringen.
</Warning>
</Step>
</Steps>

  import { Checkout } from "@dodopayments/nextjs";

  export const GET = Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
    type: "static", // optional, defaults to 'static'
  });

    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,

## Checkout route handler

<Info>
Dodo Payments stöder tre typer av betalningsflöden för att integrera betalningar på din webbplats; denna adapter stöder alla typer av betalningsflöden.
</Info>

- **Statiska betalningslänkar:** Omedelbart delningsbara URL:er för snabb betalningsinsamling utan kod.
- **Dynamiska betalningslänkar:** Skapa programmatiskt betalningslänkar med anpassade uppgifter via API:t eller SDK:er.
- **Checkout-sessioner:** Skapa säkra, anpassningsbara checkout-upplevelser med förkonfigurerade produktvarukorgar och kunduppgifter.

### Svarsformat
Statisk checkout returnerar ett JSON-svar med checkout-URL:en:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Skicka parametrar som en JSON-body i en POST-begäran.
- Stöder både engångsbetalningar och återkommande betalningar.
- En fullständig lista över fält som stöds i POST-body finns i:
  - [Request body for a One Time Payment Product](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Request body for a Subscription Product](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

<Warning>
Dynamic Checkout proxar de utfasade `POST /payments`- och `POST /subscriptions`-endpointarna. Det fortsätter att fungera för befintliga integrationer, men nya integrationer bör använda **Checkout Sessions** nedan.
</Warning>

### Svarsformat
Dynamic checkout returnerar ett JSON-svar med checkout-URL:en:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
Checkout sessions erbjuder en säkrare, hostad checkout-upplevelse som hanterar hela betalningsflödet för både engångsköp och prenumerationer, med full kontroll över anpassningen.

Se [integrationsguiden för Checkout Sessions](https://docs.dodopayments.com/developer-resources/checkout-session) för mer information och en fullständig lista över fält som stöds.

### Svarsformat
Checkout sessions returnerar ett JSON-svar med checkout-URL:en:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Customer Portal Route Handler

Customer Portal Route Handler gör det möjligt att sömlöst integrera Dodo Payments kundportal i din Next.js-applikation.

### Query Parameters
<ParamField query="customer_id" type="string" required>
Kund-ID:t för portalsessionen (t.ex. <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Om detta anges som <code>true</code> skickas ett e-postmeddelande till kunden med portallänken.
</ParamField>

<Warning>
Returnerar 400 om <code>customer_id</code> saknas.
</Warning>

## Webhook Route Handler

- **Metod:** Endast POST-förfrågningar stöds. Andra metoder returnerar 405.
- **Signaturverifiering:** Verifierar webhook-signaturen med <code>webhookKey</code>. Returnerar 401 om verifieringen misslyckas.
- **Validering av payload:** Valideras med Zod. Returnerar 400 för ogiltiga payloads.
- **Felhantering:**
  - 401: Ogiltig signatur
  - 400: Ogiltig payload
  - 500: Internt fel under verifieringen
- **Event routing:** Anropar rätt event handler baserat på payload-typen.
