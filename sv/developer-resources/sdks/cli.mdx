Hantera dina Dodo Payments-resurser, kör AI-drivna frågor mot ditt konto, skapa checkout-sessioner och testa webhooks — allt från terminalen. CLI levereras med ett interaktivt TUI, en inbyggd AI-assistent som drivs av MCP samt offline-testning av webhooks.

## Funktioner

- **Interaktivt TUI** — starta `dodo` utan argument för att öppna hela det interaktiva gränssnittet med kommandopalett, historik och liveaviseringar.
- **Inbyggd AI-assistent** — ställ frågor eller utför åtgärder på vanlig engelska med `/ai`. Ingen extra konfiguration krävs; den körs `dodopayments-mcp` lokalt.
- **Säkert som standard** — API-nycklar lagras i operativsystemets hemliga lagring (macOS Keychain, Windows Credential Vault, Linux libsecret). Ingen klartextkonfiguration sparas på disken.
- **Automatiska uppdateringar** — CLI kontrollerar om det finns nya versioner vid start och meddelar dig i appen. Kör `/update` för att uppgradera på plats.
- **Webhook-verktyg** — lyssna efter live-webhooks eller utlös payloads offline för lokal utveckling.

## Installation

Installera CLI med en enda rad på macOS eller Linux:

```bash
curl -fsSL https://dodopayments.com/install.sh | sh
```

### Installera med npm eller Bun

Om du redan har Node eller Bun installerar pakethanterarna alltid den senaste versionen:

<CodeGroup>

```bash npm
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Manuell installation (Node / Bun krävs inte)

Om du helst inte vill skicka ett fjärrskript till `sh` kan du ladda ned binärfilen själv.

<Steps>
<Step title="Download the binary">
  Ladda ned binärfilen för din plattform från den senaste [GitHub-versionen](https://github.com/dodopayments/dodopayments-cli/releases).

  | Plattform | Binärfil |
  |----------|--------|
  | macOS (Apple Silicon) | `dodo-cli-darwin-arm64` |
  | macOS (Intel) | `dodo-cli-darwin-x64` |
  | Linux (x86_64) | `dodo-cli-linux-x64` |
  | Linux (arm64) | `dodo-cli-linux-arm64` |
  | Windows (x86_64) | `dodo-cli-windows-x64.exe` |
</Step>

<Step title="Rename the binary to `dodo`">
  <CodeGroup>

  ```bash Linux / macOS
  mv ./dodo-cli-* ./dodo && chmod +x ./dodo
  ```

  ```powershell Windows
  ren .\dodo-cli-windows-x64.exe .\dodo.exe
  ```

  </CodeGroup>
</Step>

<Step title="Move it to a directory on your PATH">
  <CodeGroup>

  ```bash Linux / macOS
  sudo mv ./dodo /usr/local/bin/
  ```

  ```powershell Windows
  move .\dodo.exe C:\Windows\System32\dodo.exe
  ```

  </CodeGroup>

  <Info>
  På Windows kräver flyttning till `C:\Windows\System32` administratörsbehörighet.
  </Info>
</Step>

<Step title="(Optional) Verify the download">
  Varje version publicerar en `SHA256SUMS.txt`. Verifiera nedladdningen med:

  ```bash
  shasum -a 256 -c SHA256SUMS.txt
  ```

</Step>
</Steps>

## Autentisering

Innan du använder autentiserade kommandon loggar du in med din API-nyckel:

```bash
dodo login
```

Eller från det interaktiva TUI:t:

```text
/login
```

Inloggningsflödet kommer att:

1. Öppna webbläsaren på sidan för Dodo Payments API Keys.
2. Be dig klistra in din API Key.
3. Be dig välja en miljö — **Test Mode** eller **Live Mode**.
4. Lagra autentiseringsuppgifterna i operativsystemets hemliga lagring (Keychain på macOS, Credential Vault på Windows, libsecret på Linux).

<Info>
Eftersom autentiseringsuppgifterna lagras i operativsystemets hemliga lagring kan du behöva ange ditt **enhetslösenord** första gången CLI läser eller skriver autentiseringsuppgifter. Om du uppgraderar från en äldre version kommer en befintlig API-nyckel i klartext automatiskt att **flyttas till den hemliga lagringen och den äldre filen att raderas**.
</Info>

### Byta läge och logga ut

Du kan ha en autentiserad nyckel för **Test Mode** och en för **Live Mode** samtidigt. Rensa autentiseringsuppgifter så här:

<CodeGroup>

```bash Direct
dodo logout
```

```text TUI
/logout
```

</CodeGroup>

Utloggningsflödet låter dig välja mellan **All accounts**, **Test Mode** eller **Live Mode** separat.

## Användning

Du kan använda CLI i två lägen.

### 1. Interaktivt TUI (rekommenderas)

Kör `dodo` utan argument för att starta hela det interaktiva gränssnittet:

```bash
dodo
```

Skriv `/` för att öppna kommandopaletten, eller börja bara skriva — allt som inte är ett snedstreckskommando skickas till AI-assistenten.

| Kommando | Beskrivning |
|---------|-------------|
| `/help` | Visa kommandoöversikten |
| `/update` | Sök efter och installera en CLI-uppdatering |
| `/login` | Autentisera med en API-nyckel |
| `/logout` | Logga ut från en eller alla miljöer |
| `/clear` | Rensa TUI-skärmen |
| `/exit` | Avsluta TUI:t (även: skriv `exit` eller tryck två gånger på `Esc`) |

### 2. Direkta underkommandon

Kör kommandon direkt utan att gå in i TUI:t:

```bash
dodo <category> <sub-command> [args...]
```

Exempel:

```bash
dodo payments list 1
dodo customers create
dodo wh trigger
```

Referenstabellerna nedan visar alla kommandon. I TUI:t lägger du till `/` före dem; i direktläge tar du bort `/`.

## AI-assistent

Ställ frågor eller utför åtgärder på naturligt språk. Assistenten använder `dodopayments-mcp` som körs lokalt — ingen ytterligare konfiguration eller OAuth-flow krävs, och din AI-trafik lämnar inte din dator förutom kommunikationen med modellleverantören.

| Kommando | Beskrivning |
|---------|-------------|
| `/ai <query>` | Ställ en fråga till AI-assistenten eller ge den en instruktion |
| _(valfri text som inte börjar med snedstreck)_ | Skickas som standard till AI-assistenten när du är i TUI:t |

Exempel:

```text
how much revenue did I make this week?
/ai create a new customer named Acme Inc.
/ai find my last failed payment
```

<Tip>
Assistenten respekterar din aktiva miljö (Test / Live), så den arbetar endast med data från den miljö du är inloggad i.
</Tip>

## Projektstrukturering

`dodo init` skapar Dodo Payments-betalningsroutes direkt i ett befintligt projekt. Den genererar route-filer med standardkod, installerar det matchande `@dodopayments/*`-adapterpaketet och skriver säkert `DODO_PAYMENTS_*`-miljövariablerna till din `.env` (endast variabler som inte redan finns läggs till). Kommandot körs **utan inloggning**.

```bash
dodo init <framework>
```

| Struktur | Beskrivning |
|----------|-------------|
| `dodo init nextjs` | Skapa betalningsroutes för Next.js App Router (checkout, Customer Portal och webhook-hanterare) med `@dodopayments/nextjs` |
| `dodo init express` | Skapa betalningsroutes för en Express-server med `@dodopayments/express` |
| `dodo init better-auth` | Skapa en Better-Auth-plugin-konfiguration med `@dodopayments/better-auth` |

För Better-Auth-strukturen kan du skicka en kommaseparerad lista över plugins som ska genereras (alla används som standard): `checkout`, `portal`, `usage`, `webhooks`.

```bash
# Scaffold every Better-Auth plugin (default)
dodo init better-auth

# Scaffold only specific plugins
dodo init better-auth checkout,portal
```

<Info>
Strukturverktyget identifierar automatiskt en `src/`-katalog och anpassar sökvägarna för utdata. Det identifierar även automatiskt din pakethanterare (`bun`, `pnpm`, `yarn` eller `npm`) för att köra rätt installationskommando.
</Info>

## Webhooks

CLI innehåller två kraftfulla verktyg för att testa webhooks under utveckling: en **lyssnare** som vidarebefordrar live-testwebhooks till din lokala server och en **utlösare** som skickar simulerade webhook-payloads till valfri endpoint.

| Kommando | Beskrivning |
|---------|-------------|
| `dodo wh listen` | Lyssna efter webhooks i realtid och vidarebefordra dem till din lokala utvecklingsserver |
| `dodo wh trigger` | Utlös en test-webhook-händelse interaktivt — även när du är utloggad |

### Lyssna efter webhooks

Vidarebefordra webhooks från Dodo Payments direkt till din lokala utvecklingsserver i realtid.

```bash
dodo wh listen
```

<Steps>
<Step title="Enter your local endpoint URL">
  Ange den lokala URL där du vill ta emot webhooks (t.ex. `http://localhost:3000/webhook`).
</Step>

<Step title="Automatic setup">
  CLI skapar automatiskt en webhook-endpoint på ditt Dodo Payments-konto om det inte redan finns en, och öppnar sedan en WebSocket-anslutning för att ta emot händelser i realtid.
</Step>

<Step title="Receive and forward">
  När en webhook-händelse utlöses (från en testbetalning, ändring av en prenumeration osv.) tar CLI emot den, loggar händelsetypen och vidarebefordrar hela begäran med headers och body till din lokala endpoint. Svaret från din endpoint loggas och skickas tillbaka.
</Step>
</Steps>

<Warning>
`dodo wh listen` kräver en API-nyckel för **Test Mode**. Nycklar för Live Mode stöds inte av lyssnarflödet.
</Warning>

<Tip>
Lyssnaren bevarar de ursprungliga webhook-headers (`webhook-id`, `webhook-signature`, `webhook-timestamp`) när de vidarebefordras till din lokala endpoint, så att du kan testa din logik för signaturverifiering.
</Tip>

### Utlös test-webhooks

Skicka simulerade webhook-payloads till valfri endpoint för snabb testning utan att behöva skapa riktiga transaktioner.

```bash
dodo wh trigger
```

Flödet för `/wh trigger` guidar dig genom följande:

1. Ange en destination för **endpoint-URL**
2. Välj en specifik **händelse** att utlösa från en interaktiv meny

<Info>
`dodo wh trigger` kräver **inte** inloggning. Det fungerar som en lokal/offline-generator för webhook-payloads.
</Info>

<Warning>
Utlösta händelser är **inte signerade**. Inaktivera verifiering av webhook-signaturer på din endpoint under testningen — använd exempelvis `unsafe_unwrap()` i stället för `unwrap()` i din webhook-hanterare **endast under testning**.
</Warning>

### Webhook-händelser som stöds

`dodo wh trigger` kan skicka mock-payloads för alla 46 händelsetyper som Dodo Payments levererar:

| Kategori | Händelser |
|----------|--------|
| **Prenumeration** | `active`, `updated`, `on_hold`, `paused`, `renewed`, `plan_changed`, `cancelled`, `failed`, `expired`, `update_payment_method` |
| **Betalning** | `succeeded`, `failed`, `processing`, `cancelled` |
| **Återbetalning** | `succeeded`, `failed` |
| **Tvist** | `opened`, `expired`, `accepted`, `cancelled`, `challenged`, `won`, `lost` |
| **Licensnyckel** | `created` |
| **Utbetalning** | `created`, `in_progress`, `on_hold`, `failed`, `success` |
| **Kredit** | `added`, `deducted`, `expired`, `rolled_over`, `rollover_forfeited`, `overage_charged`, `overage_reset`, `manual_adjustment`, `balance_low` |
| **Övergiven kassa** | `detected`, `recovered` |
| **Påminnelsehantering** | `started`, `recovered` |
| **Tilldelning av behörighet** | `created`, `delivered`, `failed`, `revoked` |

<Note>
Formerna för mock-payloads följer motsvarande scheman i API-referensen. Se [Webhook Events](/developer-resources/webhooks/intents/webhook-events-guide) för vad varje händelse betyder och när Dodo Payments skickar den i produktion.
</Note>

<Tip>
`payout.created` skickas medan utbetalningen fortfarande rapporterar statusen `not_initiated`, så mock-payloaden återspeglar även detta. Se [Payout Events](/developer-resources/webhooks/intents/payout) för hela utbetalningens livscykel.
</Tip>

### Miljövariabler

| Variabel | Beskrivning |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Åsidosätt standard-URL:en för webhook-relayservern som används av `dodo wh listen` |
