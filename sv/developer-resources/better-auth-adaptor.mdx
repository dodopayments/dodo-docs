# Översikt

Den <b>Better Auth Adapter</b> för Dodo Payments erbjuder:

- Automatisk kundskapande vid registrering
- Checkout Sessions (föredraget) med produkt-slug-mappning
- Självbetjäningsportal för kunder
- Metered usage-ingestion och rapporteringsändpunkter för användningsbaserad fakturering
- Realtids-webhook-händelsebehandling med signaturverifiering
- Full TypeScript-stöd

<Note>
  Du behöver ett Dodo Payments-konto och API-nycklar för att använda denna integration.
</Note>

# Förutsättningar

- Node.js 20+
- Tillgång till din Dodo Payments Dashboard
- Befintligt projekt som använder [better-auth](https://www.npmjs.com/package/better-auth)

# Installation

<Steps>

# Konfiguration

<Steps>
<Step title="Configure environment variables">
Lägg till dessa i din <code>.env</code>-fil:

```env expandable
DODO_PAYMENTS_API_KEY=your_api_key_here
DODO_PAYMENTS_WEBHOOK_SECRET=your_webhook_secret_here
BETTER_AUTH_URL=http://localhost:3000
BETTER_AUTH_SECRET=your_better_auth_secret_here
```

<Warning>
Förekom aldrig att commita API-nycklar eller hemligheter till versionskontrollen.
</Warning>
</Step>

<Step title="Set up server-side integration">
Skapa eller uppdatera <code>src/lib/auth.ts</code>:

```typescript expandable
import { betterAuth } from "better-auth";
import {
  dodopayments,
  checkout,
  portal,
  webhooks,
  usage,
} from "@dodopayments/better-auth";
import DodoPayments from "dodopayments";

export const dodoPayments = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
  environment: "test_mode", // or "live_mode" for production
});

export const { auth, endpoints, client } = BetterAuth({
  plugins: [
    dodopayments({
      client: dodoPayments,
      createCustomerOnSignUp: true,
      use: [
        checkout({
          products: [
            {
              productId: "pdt_xxxxxxxxxxxxxxxxxxxxx",
              slug: "premium-plan",
            },
          ],
          successUrl: "/dashboard/success",
          authenticatedUsersOnly: true,
        }),
        portal(),
        webhooks({
          webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_SECRET!,
          onPayload: async (payload) => {
            console.log("Received webhook:", payload.event_type);
          },
        }),
        usage(),
      ],
    }),
  ],
});
```

<Tip>
Ange <code>environment</code> till <code>live_mode</code> för produktion.
</Tip>
</Step>

<Step title="Set up client-side integration">
Skapa eller uppdatera <code>src/lib/auth-client.ts</code>:

```typescript expandable
import { createAuthClient } from "better-auth/react";
import { dodopaymentsClient } from "@dodopayments/better-auth/client";

export const authClient = createAuthClient({
  baseURL: process.env.BETTER_AUTH_URL || "http://localhost:3000",
  plugins: [dodopaymentsClient()],
});
```

</Step>
</Steps>

# Användningsexempel

<Info>
  Föredra <code>authClient.dodopayments.checkoutSession</code> för nya
  integrationer. Den äldre <code>checkout</code>-metoden är avskriven och finns kvar
  endast för bakåtkompatibilitet.
</Info>

## Skapa en Checkout Session (Föredraget)

<CodeGroup>

```typescript Using a slug
const { data: session, error } = await authClient.dodopayments.checkoutSession({
  // Option A: use a configured slug
  slug: "premium-plan",

// Your internal id for reference
referenceId: "order_123",
});

if (session) {
window.location.href = session.url;
}

```

`

```typescript Using product cart
const { data: session, error } = await authClient.dodopayments.checkoutSession({
  // Option B: pass a product cart/product id directly
  product_cart: [
    {
      product_id: "pdt_xxxxxxxxxxxxxxxxxxxxx",
      quantity: 1,
    }
  ],

  // Your internal id for reference
  referenceId: "order_123",
});

if (session) {
  window.location.href = session.url;
}
```

`

</CodeGroup>

<Info>
  Till skillnad från den äldre <code>checkout</code>-metoden kräver <code>checkoutSession</code>
  inte faktureringsinformation i förväg eftersom detta tas från användaren
  på kassasidan. Du kan fortfarande åsidosätta detta genom att skicka
  <code>billing</code>-nyckeln i argumentet.
</Info>

<Info>
  Precis som den äldre <code>checkout</code>-metoden hämtar
  <code>checkoutSession</code> kundens e-post och namn från deras
  better-auth-session, men du kan åsidosätta det genom att skicka
  <code>customer</code>-objektet med e-post och namn.
</Info>

<Info>
  Du kan skicka samma alternativ i argumentet som i begäran till [Create
  Checkout
  Session](https://docs.dodopayments.com/api-reference/checkout-sessions/create)
  slutpunkt.
</Info>

<Note>
  Returneringsadressen tas från <code>successUrl</code> som konfigurerats i
  server-pluginet. Du behöver inte inkludera <code>return_url</code> i
  klientens payload.
</Note>

## Äldre Checkout (Avvecklad)

<Warning>
  Metoden <code>authClient.dodopayments.checkout</code> är avskriven. Använd
  <code>checkoutSession</code> istället för nya implementationer.
</Warning>

```typescript expandable
const { data: checkout, error } = await authClient.dodopayments.checkout({
  slug: "premium-plan",
  customer: {
    email: "customer@example.com",
    name: "John Doe",
  },
  billing: {
    city: "San Francisco",
    country: "US",
    state: "CA",
    street: "123 Market St",
    zipcode: "94103",
  },
  referenceId: "order_123",
});

if (checkout) {
  window.location.href = checkout.url;
}
```

## Spåra mätanvändning

Aktivera <code>usage()</code>-pluginet på servern för att fånga mätade händelser och låta kunder inspektera sin användningsbaserade fakturering.

- <code>authClient.dodopayments.usage.ingest</code> tar emot händelser för den inloggade, e-postverifierade användaren.
- <code>authClient.dodopayments.usage.meters.list</code> listar senaste användningen för de mätare som är kopplade till den kundens prenumerationer.

```typescript expandable
// Record a metered event (e.g., an API request)
const { error: ingestError } = await authClient.dodopayments.usage.ingest({
  event_id: crypto.randomUUID(),
  event_name: "api_request",
  metadata: {
    route: "/reports",
    method: "GET",
  },
  // Optional Date; defaults to now if omitted
  timestamp: new Date(),
});

if (ingestError) {
  console.error("Failed to record usage", ingestError);
}

// List recent usage for the current customer
const { data: usage, error: usageError } =
  await authClient.dodopayments.usage.meters.list({
    query: {
      page_size: 20,
      meter_id: "mtr_yourMeterId", // optional
    },
  });

if (usage?.items) {
  usage.items.forEach((event) => {
    console.log(event.event_name, event.timestamp, event.metadata);
  });
}
```

<Tip>
  Tidsstämplar äldre än en timme eller mer än fem minuter framåt i tiden
  avvisas när användning registreras.
</Tip>
<Tip>
  Om du utelämnar <code>meter_id</code> när du listar användningsmätare
  returneras alla mätare som är kopplade till kundens prenumerationer.
</Tip>

# Webhooks

<Info>
  Webhooks-pluginen bearbetar realtidsbetalningshändelser från Dodo Payments med
  säker signaturverifiering. Standard-slutpunkten är{" "}
  <code>/api/auth/dodopayments/webhooks</code>.
</Info>

<Steps>
<Step title="Generate and set webhook secret">
Generera en webhook-hemlighet för din slutpunkt (t.ex. <code>https://&lt;your-domain&gt;/api/auth/dodopayments/webhooks</code>) i Dodo Payments Dashboard och ange den i din <code>.env</code>-fil:

```env
DODO_PAYMENTS_WEBHOOK_SECRET=your_webhook_secret_here
```

</Step>

<Step title="Handle webhook events">
Exempelhanterare:

```typescript expandable
webhooks({
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_SECRET!,
  onPayload: async (payload) => {
    console.log("Received webhook:", payload.event_type);
  },
});
```

</Step>
</Steps>

# Konfigurationsreferens

<AccordionGroup>
  <Accordion title="Plugin Options">
    - <b>client</b> (obligatorisk): DodoPayments klientinstans
    - <b>createCustomerOnSignUp</b> (valfri): Skapa automatiskt kunder vid användarregistrering
    - <b>use</b> (obligatorisk): Lista med plugins att aktivera (checkout, portal, användning, webhooks)
    - <b>getCustomerParams</b> (valfri): Funktion som tar emot BetterAuth `User` och returnerar extra fält som ska bifogas DodoPayments-kunden vid skapande och uppdatering (t.ex. `metadata`, `phone_number`)

    ```typescript
    dodopayments({
      client: dodoPayments,
      createCustomerOnSignUp: true,
      use: [portal()],
      getCustomerParams: (user) => ({
        metadata: { userId: user.id },
        phone_number: user.phoneNumber ?? null,
      }),
    })
    ```

  </Accordion>
  <Accordion title="Checkout Plugin Options">
    - <b>products</b>: Lista med produkter eller asynkron funktion som returnerar produkter -{" "}
    <b>successUrl</b>: URL att omdirigera till efter lyckad betalning -{" "}
    <b>authenticatedUsersOnly</b>: Kräver användarautentisering (standard: false)
  </Accordion>
</AccordionGroup>

# Felsökning och tips

<AccordionGroup>
  <Accordion title="Common Issues">
    - <b>Ogiltig API-nyckel</b>: Kontrollera din{" "}
    <code>DODO_PAYMENTS_API_KEY</code> i <code>.env</code>. -{" "}
    <b>Webhook-signaturfel</b>: Se till att webhook-hemligheten matchar den som
    är inställd i Dodo Payments Dashboard. - <b>Kund inte skapad</b>: Bekräfta{" "}
    <code>createCustomerOnSignUp</code> är satt till <code>true</code>.
  </Accordion>
  <Accordion title="Best Practices">
    - Använd miljövariabler för alla hemligheter och nycklar. - Testa i{" "}
    <code>test_mode</code> innan du byter till <code>live_mode</code>. - Logga
    webhook-händelser för felsökning och revision.
  </Accordion>
</AccordionGroup>
