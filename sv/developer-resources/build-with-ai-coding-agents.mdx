Dodo Agent Plugin kopplar in två MCP-servrar och sjutton integrationsskills i din AI-kodningsagent med en enda installation. Den fungerar med **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** och **OpenCode**. **Gemini CLI** får endast de två MCP-servrarna. MCP-servrarna och skills CLI fungerar med alla MCP-kompatibla klienter.

Pluginet följer specifikationen [Agent Plugins 1.0.0](https://agent-plugins.org/specification), så klienter med inbyggt stöd läser in det direkt från roten `plugin.json` och `mcp.json`. Klienter som är äldre än specifikationen läser in samma innehåll via genererade kompatibilitetsmanifest.

<Info>
**Tre grundkomponenter, ett plugin.** Agent Plugin innehåller allt du behöver:
- **API MCP-server** — direktåtkomst till betalningar, prenumerationer, kunder, produkter, återbetalningar, licenser och användning. Autentiserar via webbläsarbaserad OAuth (inga lokala nycklar krävs).
- **Knowledge MCP-server** — semantisk sökning i all Dodo Payments-dokumentation. Inga autentiseringsuppgifter krävs.
- **Sjutton agent skills** — fusklappar som agenten läser in vid behov för checkout, prenumerationer, webhooks, användningsbaserad och kreditbaserad fakturering, licensnycklar, produktkatalog, rabatter, lokaliserad prissättning, mobil checkout, återbetalningar och tvister, kundhantering, ramverksadaptrar, BillingSDK, Better Auth, testning och produktionslansering samt bästa praxis.
</Info>

## Installera pluginet

Välj din kodningsagent nedan. Varje installation lägger till båda MCP-servrarna; alla utom Gemini CLI lägger även till de sjutton skillsen.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Installera från marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

API MCP-servern använder webbläsarbaserad OAuth som standard — inga nycklar krävs vid installationen. Första gången agenten anropar ett Dodo-verktyg uppmanas du att logga in.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  Källkod, konfigurationsalternativ och instruktioner för lokal utveckling
</Card>
</Accordion>

<Accordion title="Codex CLI">
Codex installerar plugins i två steg: registrera marketplace från ditt skal och installera sedan pluginet inifrån Codex TUI.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Öppna Codex och kör `/plugins` slash-kommandot:

```bash
codex
```

Skriv sedan `/plugins`, växla till marketplace **Dodo Payments**, välj pluginet **dodopayments** och välj **Install plugin**.
</Step>
</Steps>

Båda MCP-servrarna och alla sjutton skills registreras automatiskt när pluginet har installerats.

<Note>
Codex CLI har inget underkommando `codex plugin install` — plugininstallation sker alltid via `/plugins`-flödet i TUI. Se [den officiella dokumentationen för Codex-plugins](https://developers.openai.com/codex/plugins).
</Note>

Om du redan har lagt till marketplace och pluginet inte visas under `/plugins` kan du uppdatera det:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Manuell installation — klona repot till Cursors lokala plugin-katalog:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Starta om Cursor. Pluginet läser in skills från `skills/` och MCP-servrar från `.mcp.json`, enligt deklarationen i `.cursor-plugin/plugin.json`.

<Info>
Nyare Cursor-versioner känner också igen Agent Plugins 1.0.0 direkt och accepterar antingen `.cursor-plugin/marketplace.json` eller `.claude-plugin/marketplace.json` som marketplace-källa. Detta plugin levereras med `.claude-plugin/marketplace.json` — använd den sökvägen. Det genererade `.cursor-plugin/plugin.json` finns kvar för äldre versioner.
</Info>

<Warning>
Versioner före 0.5.0 levererade `skills/` som symlänkar till en git-submodul, vilket innebar att denna klon skapade ett plugin med **inga fungerande skills**. Skills levereras nu som riktiga filer. Om du installerade en tidigare version ska du ta bort katalogen och klona om.
</Warning>
</Accordion>

<Accordion title="OpenCode">
OpenCode distribueras via npm. Lägg till pluginet i din `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Starta om OpenCode. Båda MCP-servrarna (`dodopayments-api`, `dodo-knowledge`) registreras automatiskt via pluginets config hook. Inget manuellt `mcp`-block krävs.

**Skills kräver en extra rad.** OpenCode söker inte igenom installerade paket efter skills, så ange själv sökvägen till paketets `skills/`-katalog:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

Relativa `skills.paths`-poster löses mot **projektkatalogen**, så paketet måste finnas i det projektets `node_modules` — OpenCodes eget plugin-cache ligger på en annan plats. En absolut sökväg fungerar också och undviker kravet på lokal installation.

<Warning>
En skills-sökväg som inte finns ignoreras **tyst**. Kontrollera i stället för att anta:

```bash
opencode run "List every skill available to you by name."
```

Du bör se alla sjutton. Versioner före 0.5.0 dokumenterade dessa skills som automatiskt upptäckta — det stämde inte, så OpenCode-användare hade MCP-servrar men inga skills.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Klona repot var som helst och registrera det sedan:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Öppna Chat-vyn, gå till **Plugins** och lägg till den klonade mappen. Du kan också registrera den direkt i `settings.json`:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

Nyckeln är en sökväg och värdet aktiverar den. Absoluta sökvägar och `~/` fungerar båda; en relativ sökväg löses mot varje arbetsytemapp. Inställningen läses in dynamiskt, så ett fönster som redan körs tar upp den utan omstart. Skills läses in från `skills/` och båda MCP-servrarna från `.mcp.json`.

<Note>
`chat.pluginLocations` är markerad som **experimentell** och är en *begränsad* inställning, så arbetsytan måste vara betrodd för att den ska tillämpas. Stödet för agent-plugin i stort är en förhandsfunktion som styrs av `chat.plugins.enabled`, vilket är **aktiverat som standard** — du behöver bara ange det om din organisation inaktiverar det via policy.
</Note>

<Info>
VS Code använder inte Agent Plugins `$schema` som nyckel. Inläsaren söker först efter `.plugin/plugin.json`, sedan `.claude-plugin/plugin.json` och därefter en rot-`plugin.json`, och använder `.mcp.json` som standard för MCP i stället för `mcp.json`. Eftersom detta repo levereras med ett genererat `.claude-plugin/plugin.json` läser VS Code in det via denna kompatibilitetsgren och får bryggan `mcp-remote` i stället för de inbyggda transporterna i `mcp.json`. Allt fungerar — sökvägen skiljer sig.
</Info>
</Accordion>

<Accordion title="Kiro">
Kiro läser in Agent Plugins-manifestet inbyggt och laddar detta som en Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
I Kiro öppnar du Powers-panelen — Ghosty-ikonen med blixten.
</Step>

<Step title="Import the folder">
Välj **Add Custom Power → Import power from a folder**, välj den klonade katalogen (den som innehåller `plugin.json`) och klicka på **Install**.
</Step>
</Steps>

Skills läses in från `skills/`, MCP-servrar från `mcp.json` och Kiro-specifik presentation kommer från tilläggsnamnrymden `dev.kiro` i `plugin.json`.

<Note>
För plugins i Agent Plugins-formatet hanterar Kiro MCP-servrar internt — de skrivs **inte** till din användarnivå-`~/.kiro/settings/mcp.json`, så förvänta dig inte att hitta dem där. Kiro kan också installera en Power direkt från en GitHub-URL; se [Kiros installationsdokumentation](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
Gemini CLI har ingen agent-skill-primitiv, så **endast de två MCP-servrarna är tillgängliga** — de sjutton skillsen är inte tillgängliga. `dodo-knowledge` täcker fortfarande en stor del av det som skillsen tillhandahåller och hålls automatiskt uppdaterad.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Starta om Gemini CLI. `gemini-extension.json` i repots rot är manifestet.
</Accordion>
</AccordionGroup>

## Det här får du

När pluginet har installerats har agenten tillgång till två MCP-servrar och sjutton skills.

### MCP-servrar

| Server | Syfte | Auth |
|--------|---------|------|
| `dodopayments-api` | Direkt API-åtkomst — betalningar, prenumerationer, kunder, produkter, återbetalningar, licenser och användning | OAuth (webbläsare) |
| `dodo-knowledge` | Semantisk sökning i all Dodo Payments-dokumentation | Ingen |

Båda servrarna använder Streamable HTTP. Det kanoniska `mcp.json` deklarerar dem inbyggt (`type: "streamable-http"`), vilket är vad specifikationskompatibla klienter som Codex CLI och Kiro använder. Det genererade kompatibilitetsmanifestet `.mcp.json` kopplar i stället samma två endpoints via `mcp-remote`, så de även körs i klienter som inte kan ansluta direkt till Streamable HTTP — Claude Code, VS Code och Cursor via git-kloninstallationen som dokumenteras ovan, där `.cursor-plugin/plugin.json` pekar på `.mcp.json`.

### Agent skills

| Skill | Beskrivning |
|-------|-------------|
| `dodo-best-practices` | SDK-konfiguration, miljöer, API-nycklar och den kanoniska checkout-till-webhook-arkitekturen |
| `framework-adapters` | Officiella `@dodopayments/*`-route handlers för Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun och Convex |
| `testing-and-go-live` | Testläge, testbetalningsmetoder, webhook-testning och checklistan för produktionslansering |
| `checkout-integration` | Checkout Sessions, betalningslänkar samt overlay- eller inline-checkout |
| `subscription-integration` | Prenumerationens livscykel, provperioder, planändringar, proratering och on-demand-avgifter |
| `mobile-checkout` | Checkout i appen för React Native, Flutter, iOS och Android |
| `webhook-integration` | Ta emot och verifiera webhooks med specifikationen Standard Webhooks |
| `credit-based-billing` | Kreditförmåner, saldon, huvudbok, överföring, överutnyttjande och mätarbaserat avdrag |
| `usage-based-billing` | Mätare, händelseinläsning, aggregering och prissättning per enhet |
| `license-keys` | Aktivering och validering av licensnycklar samt hantering av instanser |
| `product-catalog-management` | Produkter, prissättning, tillägg, samlingar, bilder och leverans av digitala produkter |
| `discounts-and-promotions` | Rabattkoder, behörighetsregler, kombinationer och begränsningar per prenumerationscykel |
| `localized-pricing` | Lokaliserad prissättning, Adaptive Currency och köpkraftsparitet |
| `customer-management` | Kunder, självbetjäningsportalen, sparade betalningsmetoder och wallets |
| `refunds-and-disputes` | Utfärdande av återbetalningar, hantering av tvister och chargebacks samt åtkomstavstämning |
| `billing-sdk` | BillingSDK React-komponenter för pristabeller och faktureringsgränssnitt |
| `better-auth-integration` | `@dodopayments/better-auth`-pluginet för kundsynkronisering, checkout och portalåtkomst |

Skills läses in automatiskt — agenten väljer rätt skill när den upptäcker en relevant uppgift. Se [dokumentationen för Agent Skills](/developer-resources/agent-skills) för hela listan och individuell installation.

### Prova denna prompt först

När pluginet är aktivt kan du prova:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Agenten läser in skillen `webhook-integration`, använder `dodo-knowledge` MCP för att hämta de senaste payload-strukturerna och skriver en handler med signaturverifiering enligt specifikationen Standard Webhooks.

## Klientstöd

### Klienter med Agent Plugin-installation

En installation kopplar in båda MCP-servrarna samt skillsen på alla klienter som har en skill-primitiv.

| Agent | Installation | Skills | MCP-servrar |
|-------|---------|-------:|------------:|
| **Claude Code** | marketplace-kommando | 17 | 2 |
| **Codex CLI** | marketplace-kommando | 17 | 2 |
| **Cursor** | git-klon | 17 | 2 |
| **VS Code / GitHub Copilot** | git-klon | 17 | 2 |
| **Kiro** | git-klon | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | git-klon | 0 | 2 |

- **OpenCode** behöver en extra `skills.paths`-post innan de sjutton skillsen läses in — se installationsavsnittet ovan.
- **Gemini CLI** har ingen agent-skill-primitiv, så skills är avsiktligt inte tillgängliga där.

### Övriga MCP-kompatibla klienter

Dessa har ingen Agent Plugin-installation. Konfigurera de två MCP-servrarna manuellt och lägg till skills via Skills CLI där det stöds.

| Agent | MCP-servrar | Skills |
|-------|-------------|--------|
| Claude Desktop | [MCP Server-guiden](/developer-resources/mcp-server) | stöds inte |
| Windsurf | [MCP Server-guiden](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / övriga | [MCP Server-guiden](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## Dokumentation byggd för agenter

Varje Dodo Payments-dokumentationssida finns tillgänglig i ett format optimerat för AI-användning:

- **Fullständigt dokumentationsindex**: [`docs.dodopayments.com/llms.txt`](https://docs.dodopayments.com/llms.txt) — tillhandahåller hela dokumentationsindexet för kontextinläsning.
- **Vanlig markdown**: Lägg till `.md` i valfri dokumentations-URL för att få markdown-versionen i råformat (t.ex. `/api-reference/introduction.md`).
- **Källkodsförråd**: [`github.com/dodopayments/dodo-docs`](https://github.com/dodopayments/dodo-docs) — klona för offlineindexering.

## Säkerhet och bästa praxis

<Warning>
**Checka aldrig in API-nycklar för produktion.** Använd [testläge](/miscellaneous/test-mode-vs-live-mode) under utvecklingen. Agent Plugin använder webbläsarbaserad OAuth som standard — växla endast till lokala API-nycklar om ditt arbetsflöde kräver det.
</Warning>

- **Använd testläge först.** Testa din integration i en sandbox med nycklarna `dodo_test_...` innan du går live. Se [Testläge kontra liveläge](/miscellaneous/test-mode-vs-live-mode).
- **OAuth är standard.** Agent Plugin autentiserar via webbläsarbaserad OAuth (inga lokala hemligheter). Använd endast API-key-läge om du behöver det — se avsnittet Konfigurera nedan.
- **Granska kod som genererats av agenten.** Kontrollera alltid att webhook-handlers innehåller signaturverifiering enligt [specifikationen Standard Webhooks](https://standardwebhooks.com/).

## Konfigurera med en API-nyckel

Som standard använder Agent Plugin den fjärranslutna MCP-servern med webbläsarbaserad OAuth — inga lokala autentiseringsuppgifter behövs. Om ditt arbetsflöde kräver en lokal API-nyckel (t.ex. CI-miljöer eller huvudlösa servrar) kan du växla till stdio-läge.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Öppna `/plugins` i Claude Code, välj **Dodo Payments** och välj **Configure options**. Fyll i:

- `dodo_api_key` — din `dodo_test_...`- eller `dodo_live_...`-nyckel
- `dodo_webhook_key` — din hemlighet för webhook-signering
- `dodo_environment` — `test_mode` eller `live_mode`

Redigera sedan `.mcp.json` så att `dodopayments-api` pekar på den lokala stdio-servern:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Kör `/reload-plugins` för att tillämpa ändringarna i din aktuella session.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Deklarera `dodopayments-api` själv i `opencode.json` — din post åsidosätter pluginets förvalda fjärrserver:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Starta om OpenCode för att tillämpa ändringen.
</Accordion>
</AccordionGroup>
