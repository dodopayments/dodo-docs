## Hantering av API-nycklar och autentisering

<Steps>
<Step title="Access API Keys">
Gå till **Developer → API Keys** i din dashboard för att hantera dina nycklar.
</Step>

<Step title="Generate a New Key">
Välj **Add API Key**, ange ett beskrivande namn och konfigurera skrivåtkomst:

- **Enable write access** (markerat): Fullständiga läs- och skrivbehörigheter för alla API-operationer
- **Enable write access** (avmarkerat): Skrivskyddad åtkomst – kan endast hämta data (betalningar, prenumerationer, kunder, produkter). Kan inte skapa eller ändra resurser.

<Tip>
Avmarkera "Enable write access" för dashboard-integrationer, analysverktyg och alla system som endast behöver visa data utan att göra ändringar.
</Tip>
</Step>

<Step title="Store Your Key Securely">
Kopiera den genererade nyckeln omedelbart och se till att den lagras säkert.
</Step>

<Step title="Authenticate Your API Requests">
Använd dina API-nycklar för att autentisera alla anrop. Använd följande auktoriseringsformat:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
Exponera aldrig dina hemliga API-nycklar i kod på klientsidan eller i offentliga repositories.
</Warning>
</Step>
</Steps>

## Anropsbegränsningar

Vårt API använder ett system för anropsbegränsning med två tidsfönster och skydd mot toppar. Begränsningarna tillämpas baserat på din autentiseringsmetod och företagsnivå.

### Standardbegränsningar (nivå 0)

| Fönster | Begränsning |
|--------|-------|
| Per sekund (topp) | 40 anrop |
| Per minut (varaktig) | 240 anrop |

### Företagsnivåer

Högre anropsbegränsningar är tillgängliga för företag med större API-behov:

| Nivå | Topp (per sekund) | Varaktig (per minut) |
|------|-------------------|------------------------|
| Nivå 0 (standard) | 40 | 240 |
| Nivå 1 | 100 | 1 000 |
| Nivå 2 | 500 | 5 000 |

<Tip>
Kontakta supporten för att uppgradera ditt företag till en högre nivå för anropsbegränsning.
</Tip>

### Oautentiserade anrop

Anrop utan giltiga autentiseringsheaders begränsas baserat på IP-adress:

| Fönster | Begränsning |
|--------|-------|
| Per sekund (topp) | 20 anrop |
| Per minut (varaktig) | 100 anrop |

### Headers för anropsbegränsning

Övervaka din användning med dessa svarheaders:

- `X-RateLimit-Limit` – Maximalt tillåtna anrop
- `X-RateLimit-Remaining` – Återstående anrop i det aktuella fönstret
- `X-RateLimit-Reset` – Tidpunkt då anropsbegränsningen återställs

<Note>
När du överskrider anropsbegränsningarna returnerar API:et ett svar med `429 Too Many Requests`. Implementera exponentiell backoff i din retry-logik.
</Note>
