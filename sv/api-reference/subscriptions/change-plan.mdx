## Hantering av betalningsfel

Använd `on_payment_failure`-parametern för att styra vad som händer när betalning för planändring misslyckas:

| Value | Behavior |
|-------|----------|
| `prevent_change` | Behåll prenumerationen på nuvarande plan tills betalningen lyckas. Planändringen förblir väntande. |
| `apply_change` | Tillämpa planändringen omedelbart oavsett betalningsresultat. Detta är standard. |

<Info>
Om `on_payment_failure` inte anges, återgår beteendet till din företagsinställning som konfigurerats i instrumentpanelen.
</Info>

## Rabattkoder

Du kan tillämpa en rabattkod när du ändrar planer genom att skicka parametern `discount_code`.

| Scenario | Beteende |
|----------|----------|
| `discount_code` tillhandahölls | Validerar och tillämpar rabatten på den nya planen. |
| `discount_code` inte tillhandahölls, befintlig rabatt med `preserve_on_plan_change=true` | Befintlig rabatt bevaras om tillämplig på den nya produkten. |
| `discount_code` inte tillhandahölls, ingen bevaringsbar rabatt | Ingen rabatt tillämpad. |

<Tip>
Använd rabattkoder vid planändringar för att erbjuda kampanjpriser vid uppgraderingar, eller skicka en kod när du migrerar kunder till en ny plantyp.
</Tip>

<Tip>
Använd `prevent_change` för kritiska uppgraderingar där du vill säkerställa betalning innan du beviljar åtkomst till premiumfunktioner.
</Tip>
