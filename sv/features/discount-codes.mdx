## Vad är Rabattkoder?

Rabattkoder är kampanjtoken som minskar ordersummorna i kassan. De är idealiska för:

- **Säsongskampanjer**: Black Friday, produktlanseringar eller jubileer
- **Förvärvserbjudanden**: Första-köp incitament eller belöningar vid hänvisningar
- **Behållande**: Återvinnings- eller lojalitetsbelöningar för befintliga kunder
- **B2B-erbjudanden**: Avtalade eller förhandlade priser via privata koder

## Viktiga Fördelar

- **Flexibla rabatter**: Procentbaserade rabatter eller rabatter med fast belopp
- **Kombinerbara koder**: Tillämpa upp till 20 koder per checkout, betalning eller prenumeration — kombinera kampanjer (t.ex. `WELCOME10` + `BLACKFRIDAY20`) utan att skapa specialanpassade koder
- **Målinriktad kontroll**: Begränsa efter produkt, prenumerationscykler och kundberättigande
- **Kampanjstyrning**: Schemalagda startdatum, utgångsdatum samt användningsgränser totalt och per kund
- **Prissättning per valuta**: Ange det fasta avdraget, beloppsgränsen och minsta delsumma per valuta
- **Smidig checkout**: UI-fält och API-stöd via checkout sessions

## Skapa Rabattkoder

Skapa rabattkoder i din Dodo Payments-instrumentpanel och tillämpa dem sedan i värdad kassa eller via API.

### Konfigurera i dashboarden

- **Discount Name** (obligatoriskt): Internt namn och visningsnamn i dashboarden
- **Code** (obligatoriskt): Strängen som kunder anger i checkout, eller generera en slumpmässig kod med den angivna knappen
- **Type** (obligatoriskt): Välj **Percentage** (procentuell rabatt) eller **Amount** (fast avdrag)
- **Amount** (obligatoriskt): Procentvärdet eller det fasta beloppet för en Amount-rabatt
- **Start Date** (valfritt): Schemalägg när koden ska aktiveras; lämna tomt för att aktivera den omedelbart
- **Expiration Date** (valfritt): Datum efter vilket koden blir ogiltig
- **Usage Limit** (valfritt): Maximalt totalt antal inlösningar för alla kunder
- **Per-Customer Usage Limit** (valfritt): Maximalt antal inlösningar för en enskild kund. Måste vara mindre än eller lika med den totala användningsgränsen när båda anges
- **Customer Eligibility** (valfritt): Begränsa vilka som får lösa in koden — alla kunder, förstagångskunder, befintliga kunder eller en manuellt vald lista
- **Currency Options** (valfritt): Värden per valuta — se [Alternativ per valuta](#per-currency-options)
- **Product Restriction** (valfritt): Begränsa giltigheten till valda produkter
- **Subscription Cycle Limit** (valfritt): Antalet faktureringscykler som rabatten gäller för
- **Preserve on Plan Change** (valfritt): Behåll rabatten aktiv när prenumerationens plan ändras (`preserve_on_plan_change`)
- **Metadata** (valfritt): Lägg till anpassade nyckel–värde-par för intern spårning eller integrationer

## Rabattmetoder

| Typ | API-värde | Beteende |
|------|-----------|-----------|
| Percentage | `percentage` | Sänker priset med en procentsats. Kan valfritt begränsas per valuta med en maximal rabatt. |
| Amount | `flat` | Drar av ett fast belopp. Avdraget samordnas över hela varukorgen i stället för att tillämpas per radartikel. |

Båda typerna kan kombineras i samma `discount_codes`-array och tillämpas i arrayens ordning.

## Kundberättigande

Ange `customer_eligibility` för att styra vilka som får lösa in en kod:

| Värde | Vem kan lösa in |
|-------|----------------|
| `any` | Alla kunder. Detta är standardinställningen. |
| `first_time` | Kunder som inte har handlat av dig tidigare. |
| `existing` | Kunder som har handlat av dig tidigare. |
| `specific` | Endast kunder som du lägger till i kodens allow-list. |

<Frame>
    <img src="/images/discount-codes/discount-restriction.png" alt="Rullgardinsmeny för kundberättigande som visar alternativen Any, First-time, Existing och Specific customer" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

<Warning>
En kod med `specific` börjar med **noll** berättigade kunder och avvisar alla inlösningar tills du lägger till kunder. Lägg till dem i dashboarden eller med discount customers API.
</Warning>

Kombinera berättigande med **Per-Customer Usage Limit** för att begränsa hur ofta varje enskild kund kan lösa in koden, oberoende av den totala användningsgränsen.

## Alternativ per valuta

Med valutaalternativ kan en kod fungera korrekt för alla valutor du säljer i. Varje post anger följande för en enskild valuta:

- **Amount** — för en Amount-rabatt är detta själva avdraget; för en Percentage-rabatt anger det hur mycket koden maximalt kan dra av. Mappas till `max_amount_possible` via API:t.
- **Minimum subtotal** — koden tillämpas endast när varukorgen når denna delsumma. `0` betyder att det inte finns något minimum.
- **Default** — en post kan markeras som standard, så att andra, ej konfigurerade valutor konverteras från den.

<Frame>
    <img src="/images/discount-codes/discount-currency-options.png" alt="Panel med valutaalternativ och belopp per valuta samt minsta delsumma för INR och USD" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

En Amount-rabatt kräver minst ett valutaalternativ med en lösbar standard, eftersom ett fast avdrag saknar betydelse utan en valuta. Valutaalternativ är valfria för Percentage-rabatter.

<Info>
Minsta delsumma beräknas alltid utifrån varukorgens ursprungliga priser, aldrig utifrån den löpande totalsumman mitt i en kombination. Ordningen för kombinationen påverkar därför aldrig om ett minimum uppnås.
</Info>

## Kombinera rabattkoder

Checkout sessions, betalningar och prenumerationer accepterar upp till **20 kombinerade koder** via `discount_codes`-arrayen (högst 20 poster). Koder tillämpas **i arrayens ordning**, så att den första berättigade koden först sänker grundpriset, nästa kod sänker det redan rabatterade priset och så vidare. Den fullständiga uppsättningen tillämpade rabatter returneras i svaret under `discount_ids` (för betalningar/prenumerationer) och `discounts` (rikare information per rabatt, inklusive position och återstående prenumerationscykler).

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_abc', quantity: 1 }],
  discount_codes: ['WELCOME10', 'BLACKFRIDAY20'], // applied in this order
  customer: { email: 'user@example.com' },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Det singulara `discount_code`-fältet är **föråldrat** men har fortfarande fullt stöd för bakåtkompatibilitet — befintliga integrationer fortsätter att fungera utan ändringar. Det kan inte kombineras med `discount_codes` i samma begäran. Vi rekommenderar att du migrerar till `discount_codes` (array-formatet) när det passar, även för enstaka koder, för att dra nytta av kombinationer och den rikare svarsstrukturen.
</Info>

## Vanliga användningsområden

- **Introduktionserbjudanden**: Tidsbegränsade lanseringskampanjer för nya produkter
- **Bulk eller B2B**: Avtalsbaserade rabatter för utvalda produktuppsättningar
- **Kundbevarande**: Win-back-koder i arbetsflöden för att förebygga kundbortfall
- **Säsongskampanjer**: Högtids- eller evenemangsbaserade kampanjer

## Integrationsexempel

### Skapa en rabatt med metadata
Lägg till anpassade nyckel–värde-par för intern spårning.

```typescript
const discount = await client.discounts.create({
  type: 'percentage',
  amount: 1500, // 15%
  code: 'SUMMER2025',
  metadata: {
    campaign: 'summer_promo',
    source: 'email_blast'
  }
});
```

<Tip>
Använd metadata för att märka rabatter efter kampanj, källa eller internt referens-ID, så att du senare kan stämma av användningen och mäta ROI.
</Tip>

### Tillämpa rabatter i Checkout Sessions
Förtillämpa en eller flera kombinerade rabatter och visa UI:t för kodinmatning.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  discount_codes: ['BLACKFRIDAY2024', 'NEWUSER5'], // stacked in array order
  customer: { email: 'user@example.com', name: 'Jane Doe' },
  return_url: 'https://yoursite.com/return'
});
```

### Tillämpa rabatter vid planändringar
Erbjud kampanjpriser när kunder uppgraderar eller nedgraderar sin prenumeration.

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'pdt_pro',
  quantity: 1,
  proration_billing_mode: 'prorated_immediately',
  discount_codes: ['UPGRADE20']
});
```

| `discount_codes`-värde | Beteende vid planändring |
|------------------------|-------------------------|
| `undefined` / `null` (anges inte) | Befintliga rabatter med `preserve_on_plan_change=true` bevaras om de gäller för den nya produkten. |
| `[]` (tom array) | **Alla** befintliga rabatter tas bort från prenumerationen. |
| `['CODE_A', 'CODE_B', ...]` | Ersätter alla befintliga rabatter med denna kombinerade uppsättning, tillämpad i arrayens ordning. |

<Info>
Läs alla tillämpade rabatter från prenumerationen via den nya `discounts`-arrayen i prenumerationssvaret. Varje post innehåller `discount_id`, `position`, `cycles_remaining` (för prenumerationer) och den ursprungliga koden.
</Info>

### Dölj fältet för rabattkod
Fältet för rabattinmatning visas som standard, så kunder kan alltid ange en kod utan att du skickar med en i förväg. Ange `allow_discount_code` till `false` för att dölja fältet helt.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'pdt_abc', quantity: 1 }
  ],
  feature_flags: {
    allow_discount_code: false
  },
  return_url: 'https://yoursite.com/return'
});
```

## Bästa praxis

- **Namnge tydligt**: Använd igenkännbara koder som överensstämmer med kampanjnamnen
- **Tidsbegränsa**: Lägg till utgångsdatum för att skapa brådska och förhindra missbruk
- **Avgränsa klokt**: Begränsa till specifika produkter för att undvika marginalförluster
- **Validera tidigt**: Kontrollera kodens giltighet innan checkout bekräftas
- **Övervaka effekten**: Följ användning och konvertering per kampanj

<Info>
Rabattkoder är kraftfulla verktyg för kundanskaffning och kundbevarande. Börja med enkla erbjudanden med tydliga namn, validera noggrant och iterera utifrån resultatet.
</Info>
