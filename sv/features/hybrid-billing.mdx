## Vad är hybrid fakturering?

Hybrid fakturering kombinerar flera prisdimensioner i ett enda produkterbjudande. I stället för att välja mellan prenumeration med fast pris ELLER användningsbaserad prissättning använder du båda tillsammans.

### Varför använda hybrid fakturering?

| Affärsmål | Hybridlösning |
|--------------|-----------------|
| Förutsägbara intäkter + tillväxtpotential | Basprenumeration + överskridande av användning |
| Teamprissättning som kan skalas | Per plats + funktionstillägg |
| Vinn kunder, utöka senare | Låg basavgift + förbrukningsavgifter |
| Flexibilitet för företag | Avtalad spend + avgifter på begäran |
| Rättvis prissättning vid varierande användning | Inkluderad kvot + betala per användning |

### Vanliga hybridmönster

| Modell | Beskrivning | Exempel | Inbyggt stöd |
|-------|-------------|---------|----------------|
| **1. Prenumeration + användning** | Basavgift + förbrukningsavgifter | \$49/mån + \$0.01/API-anrop efter 10K gratis | ✅ Fullständigt |
| **2. Prenumeration + platser** | Plattformavgift + avgifter per användare | \$99/mån + \$15/plats | ✅ Fullständigt |
| **3. Prenumeration + funktionstillägg** | Grundplan + valfria uppgraderingar | \$29/mån + \$19/mån analys + \$9/mån API-åtkomst | ✅ Fullständigt |
| **4. Platser + användning** | Avgift per användare + förbrukningsöverskridande | \$10/användare/mån + \$0.05/GB efter 5 GB/användare | ⚠️ Lösning krävs |
| **5. Prenumeration + platser + användning** | Plattform + användare + förbrukning (trippelhybrid) | \$199/mån + \$20/plats + överskridande användning | ⚠️ Lösning krävs |
| **6. Nivåindelad bas + överskridande användning** | Olika nivåer med olika kvoter | Starter (5K anrop) kontra Pro (50K anrop) + överskridande | ✅ Fullständigt |
| **7. Prenumeration + avgifter på begäran** | Återkommande avgift + varierande manuella avgifter | \$99/mån retainer + timdebitering för arbete | ✅ Fullständigt |

## Hybridmodell 1: Prenumeration + användning

Den vanligaste hybridmodellen. Kunder betalar en basavgift för prenumerationen samt avgifter för förbrukning som överstiger de inkluderade kvoterna.

### Så fungerar det

**Pro-plan: $49/månad**

- **Inkluderat**: 10 000 API-anrop/månad
- **Överskridande**: $0.005 per anrop efter 10 000

**Exempelberäkning** (kunden använder 25 000 anrop den här månaden):
- Basprenumeration: $49.00
- Överskridande: (25 000 - 10 000) × $0.005 = $75.00
- **Totalt: $124.00**

### Användningsområden

- **API-plattformar**: Basåtkomst + avgifter per begäran
- **AI/ML-tjänster**: Prenumeration + användning av token/generering
- **Lagringstjänster**: Basplan + överskridande per GB
- **Kommunikationsplattformar**: Bas + avgifter per meddelande/minut

### Implementering

<Steps>
<Step title="Create Usage Meter">
Konfigurera en mätare för att spåra den debiterbara användningsdimensionen.

```bash
Dashboard: Meters → Create Meter
Event Name: "api.call"
Aggregation: Count
This tracks API calls per customer
```

</Step>

<Step title="Create Subscription Product with Usage Pricing">
Skapa en prenumerationsprodukt och koppla användningsmätaren med prissättning.

```bash
Dashboard: Create Product → Subscription
Name: "Pro Plan"
Base Price: $49/month

Then attach usage pricing:
- Meter: api.call
- Price per unit: $0.005
- Free threshold: 10,000 (included in subscription)
```

<Info>
Användningsmätaren kopplas direkt till prenumerationsprodukten. Användningsavgifter beräknas och läggs automatiskt till på prenumerationsfakturan.
</Info>
</Step>

<Step title="Create Checkout Session">
Skapa en checkout-session med din prenumerationsprodukt.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_pro_plan', quantity: 1 }
  ],
  customer: { email: 'customer@example.com' },
  return_url: 'https://yourapp.com/success'
});
```

</Step>

<Step title="Send Usage Events">
Spåra användningen under hela faktureringsperioden.

```typescript

  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json'
  },

    events: [{
      event_id: `call_${Date.now()}`,
      customer_id: 'cus_123',
      event_name: 'api.call',
      timestamp: new Date().toISOString(),
      metadata: { endpoint: '/v1/generate' }
    }]
  })
});
```

</Step>
</Steps>

### Prisvariationer

<Tabs>
<Tab title="Included Allowance">
Den kostnadsfria tröskeln täcker användning som ingår i basprenumerationen.

**Pro-plan: $49/månad**
- Inkluderar: 10 000 API-anrop
- Överskridande: $0.005/anrop efter 10 000
- Kunden använder 8 000 → Betalar $49 (inget överskridande)
</Tab>

<Tab title="Zero Base + Pure Usage">
Ingen basavgift – varje enhet är debiterbar från första användningen.

**Betala efter användning: $0/månad i basavgift**
- Inkluderar: 0 API-anrop
- Användning: $0.01/anrop från första anropet
- Kunden använder 5 000 → Betalar $50
</Tab>

<Tab title="Tiered Allowances">
Olika nivåer inkluderar olika kvoter.

- **Starter**: $19/månad (1 000 anrop inkluderade)
- **Pro**: $49/månad (10 000 anrop inkluderade)
- **Enterprise**: $199/månad (100 000 anrop inkluderade)
- Alla nivåer: $0.005/anrop i överskridande
</Tab>
</Tabs>

## Hybrid Model 2: Subscription + Seats

Platform fee plus per-user charges. Ideal for team collaboration tools and B2B SaaS.

### How It Works

**Team Plan: $99/month + $15/seat**

- **Base platform fee**: $99/month (includes 3 seats)
- **Additional seats**: $15/seat/month

**Example calculation** (team of 12 users):
- Platform fee: $99.00
- Extra seats: (12 - 3) × $15 = $135.00
- **Total: $234.00/month**

### Use Cases

- **Collaboration tools**: Workspace fee + per-member
- **CRM systems**: Platform license + per-sales-rep
- **Project management**: Team plan + per-contributor
- **Developer tools**: Organization fee + per-developer

### Implementation

<Steps>
<Step title="Create Seat Add-on">
Create an add-on for additional seats.

```bash
Dashboard: Products → Add-ons → Create Add-on
Name: "Additional Seat"
Price: $15/month
Description: "Add another team member"
```

</Step>

<Step title="Create Base Subscription">
Create the subscription product with platform fee and attach the add-on.

```bash
Dashboard: Create Product → Subscription
Name: "Team Plan"
Price: $99/month
Description: "Includes 3 team members"

Then in Add-ons section:
- Attach: "Additional Seat" add-on
```

</Step>

<Step title="Create Checkout with Seats">
Specify seat quantity during checkout.

```typescript
    product_id: 'prod_team_plan',
```

</Step>

<Step title="Adjust Seats as Needed">
Add or remove seats on existing subscriptions.

```typescript
    addon_id: 'addon_seat',
    quantity: 14  // New total: 14 extra seats
  }]
});
```

</Step>
</Steps>

### Pricing Variations

<Tabs>
<Tab title="Included Seats">
Base plan includes some seats, charge for extras.

**Team Plan: $99/month**
- Includes: 5 seats
- Extra seats: $15/seat/month
- 20 users = \$99 + (15 × \$15) = \$324/month
</Tab>

<Tab title="Pure Per-Seat">
No platform fee, only per-user charges.

**Per User: $25/user/month**
- No platform fee
- 5 users = $125/month
- 50 users = $1,250/month

Implementation: Set base subscription price to $0, use seat add-on only.
</Tab>

<Tab title="Tiered Per-Seat">
Per-seat price decreases at higher tiers.

- **Starter**: $20/seat (1-10 seats)
- **Growth**: $15/seat (11-50 seats)
- **Enterprise**: $10/seat (51+ seats)

Implementation: Create separate subscription products for each tier with different add-on prices.
</Tab>
</Tabs>

## Hybrid Model 3: Subscription + Feature Add-ons

Core subscription with optional feature upgrades customers can add.

**Core Plan: $29/month**

**Optional Add-ons:**
- Advanced Analytics: +$19/month
- API Access: +$9/month

- Core plan: $29.00

## Hybrid Model 4: Seats + Usage

Per-user fee combined with consumption-based charges. Each user gets an allowance.

<Warning>
**Constraint**: Dodo Payments does not currently support attaching both usage meters and add-ons to the same subscription product. This model requires a workaround using application-level logic.
</Warning>

### Så fungerar det

**Team Analytics: 20 $/användare/månad**

**Varje användare inkluderar:**
- 5 GB databehandling/månad
- Överstigande användning: 2 $/GB efter inkluderad mängd

**Exempelberäkning** (team med 10 användare som använder totalt 80 GB):
- Platsavgifter: 10 × 20 $ = 200,00 $
- Inkluderad data: 10 × 5 GB = 50 GB
- Överstigande användning: (80 - 50) × 2 $ = 60,00 $
- **Totalt: 260,00 $/månad**

### Användningsområden

- **Analytics-plattformar**: Per analytiker + databehandling
- **Designverktyg**: Per designer + lagring/exporter
- **Utvecklingsmiljöer**: Per utvecklare + beräkningstimmar
- **Kommunikationsverktyg**: Per användare + meddelande-/samtalsvolym

### Implementeringsalternativ

Eftersom du inte kan koppla både usage meters och add-ons till samma subscription väljer du ett av följande tillvägagångssätt:

</Step>

```typescript
  const includedGB = seatCount * 5; // 5 GB per user

  const currentUsage = await getUsageFromDodo(customerId);

  return { included: includedGB, used: currentUsage, overage };
```

Beräkna och debitera överstigande användning manuellt.

```typescript
async function billUsageOverage(subscriptionId: string) {
  const subscription = await getSubscription(subscriptionId);
  const seatCount = subscription.addons.find(a => a.id === 'addon_seat')?.quantity || 0;

  const includedGB = seatCount * 5;
  const usedGB = await calculatePeriodUsage(subscription.customer_id);
  const overageGB = Math.max(0, usedGB - includedGB);

  if (overageGB > 0) {
    const overageCharge = overageGB * 200; // $2/GB in cents
    await client.subscriptions.charge(subscriptionId, {
      product_price: overageCharge,
      product_description: `Data overage: ${overageGB} GB × $2/GB`
    });
  }
}
```

</Step>

</Tab>

## Hybridmodell 5: Subscription + Seats + Usage (Triple Hybrid)

**Enterprise Platform**

## Hybridmodell 6: Tiered Base + Usage Overage

Olika subscription tiers med olika inkluderade mängder och priser för överstigande användning.

### Så fungerar det

| Tier | Pris | Inkluderade anrop | Pris för överstigande användning |
|------|-------|------------------|--------------|
| **Starter** | 19 $/månad | 1 000 | 0,02 $/anrop |
| **Pro** | 79 $/månad | 25 000 | 0,01 $/anrop |
| **Business** | 199 $/månad | 100 000 | 0,005 $/anrop |
| **Enterprise** | 499 $/månad | 500 000 | 0,002 $/anrop |

### Implementering

Skapa separata subscription products för varje tier, där varje produkt har sin egen usage configuration:

```bash
# For each tier, create a subscription product:
```

## Hybridmodell 7: Subscription + On-Demand Charges

Återkommande subscription plus varierande manuella charges för tjänster eller överstigande användning.

### Så fungerar det

**Retainer Plan: 199 $/månad**

**Inkluderar:**
- Plattformsåtkomst
- 5 konsulttimmar/månad
- E-postsupport

**On-Demand Charges (vid behov):**
- Extra konsultation: 150 $/timme
- Anpassad utveckling: 200 $/timme
- Akutsupport: 100 $/incident

**Exempelberäkning** (den här månaden):
- Retainer: 199,00 $
- 3 extra konsulttimmar: 450,00 $
- 1 akutsupport: 100,00 $
- **Totalt: 749,00 $**

### Användningsområden

- **Konsulttjänster**: Retainer + timdebitering
- **Managed services**: Basavgift + incidentavgifter
- **Byråtjänster**: Månadsavgift + projektavgifter
- **Supportplaner**: SLA-avgift + per ärende eller timme

### Implementering

<Steps>
<Step title="Create On-Demand Subscription">
Konfigurera en subscription med on-demand charging aktiverat.

```typescript
const subscription = await client.subscriptions.create({
  billing: {
    city: 'San Francisco',
    country: 'US',
    state: 'CA',
    street: '123 Main St',
    zipcode: '94105'
  },
  customer: { customer_id: 'cus_123' },
  product_id: 'prod_retainer',
  quantity: 1,
  payment_link: true,
  return_url: 'https://yourapp.com/success',
  on_demand: {
    mandate_only: false,
    product_price: 19900  // $199 initial charge
  }
});
```

</Step>

<Step title="Charge for Services">
Skapa charges när tjänsterna levereras.

```typescript
// Charge for 3 hours of consulting
await client.subscriptions.charge('sub_123', {
  product_price: 45000,  // $450.00 (3 × $150)
  product_description: 'Consulting - 3 hours (March 15)'
});

// Charge for emergency support incident
await client.subscriptions.charge('sub_123', {
  product_price: 10000,  // $100.00
  product_description: 'Emergency support - Server outage (March 18)'
});
```

</Step>

<Step title="Track and Invoice">
Alla charges visas på kundens invoice.

```typescript
// Retrieve subscription charges
const payments = await client.payments.list({
  subscription_id: 'sub_123'
});

// Show itemized breakdown to customer
payments.items.forEach(payment => {
  console.log(`${payment.payment_id}: $${payment.total_amount / 100}`);
});
```

</Step>
</Steps>

## Bästa praxis för implementering

### Tydlighet på prissidan

<Tip>
Gör hybridprissättning lätt att förstå. Visa baskostnader, vad som ingår och hur överstigande användning fungerar tydligt på prissidan.
</Tip>

**Bra**: "\$49/månad inkluderar 10 000 API-anrop. Ytterligare anrop: \$0.005 styck"

**Dåligt**: "\$49/månad + användningsavgifter"

### Förutsägbara kostnader

Hjälp kunderna att uppskatta sina kostnader:

```typescript
// Provide a cost calculator
function estimateMonthlyCost({
  plan,
  seats,
  expectedUsage,
  addons
}: EstimateParams): number {
  let total = plan.basePrice;

  // Add seat costs
  const extraSeats = Math.max(0, seats - plan.includedSeats);
  total += extraSeats * plan.seatPrice;

  // Add usage overage
  const overage = Math.max(0, expectedUsage - plan.includedUsage);
  total += overage * plan.overageRate;

  // Add feature add-ons
  total += addons.reduce((sum, addon) => sum + addon.price, 0);

  return total;
}
```

### Synlighet för användning

Visa kunderna deras användning i realtid:

```typescript
// Display usage dashboard
async function getUsageSummary(subscriptionId: string) {
  const usage = await client.subscriptions.retrieveUsageHistory(subscriptionId);

  // Each item is a billing period; each meter reports its usage for that period.
  const latestPeriod = usage.items[0];

  return latestPeriod.meters.map((meter) => {
    const consumed = Number(meter.consumed_units);
    const chargeable = Number(meter.chargeable_units);
    return {
      meter: meter.name,
      current: consumed,
      included: meter.free_threshold,
      remaining: Math.max(0, meter.free_threshold - consumed),
      overage: chargeable,
      cost: meter.total_price
    };
  });
}
```

## Felsökning av hybriddebitering

<AccordionGroup>
<Accordion title="Usage not being tracked correctly">
**Symptom**: Användningen visas som 0 eller med felaktiga värden.

**Lösningar**:
1. Kontrollera att event ingestion fungerar (kontrollera API-svar)
2. Bekräfta att `customer_id` matchar subscription-kunden
3. Kontrollera att `event_name` matchar meter-konfigurationen
4. Kontrollera att events har korrekta tidsstämplar (inte framtidsdaterade)
</Accordion>

<Accordion title="Proration confusion with multiple components">
**Symptom**: Kunden debiteras oväntade belopp när planer ändras.

**Lösningar**:
1. Använd `previewChangePlan` API för att visa exakta charges innan du bekräftar
2. Informera om att proratering gäller för subscription OCH add-ons
3. Överväg att använda `difference_immediately` för enklare uppgraderingsdebitering
</Accordion>

<Accordion title="Free threshold not applying correctly">
**Symptom**: Kunden debiteras för användning som borde vara kostnadsfri.

**Lösningar**:
1. Kontrollera att den kostnadsfria gränsen är konfigurerad på den usage-based produkten
2. Kontrollera att gränsenheten matchar händelseaggregeringen (anrop kontra requests)
3. Bekräfta att usage meter är korrekt kopplad till subscription product
</Accordion>

<Accordion title="Add-ons not appearing in checkout">
**Symptom**: Det går inte att lägga till platser eller funktioner under checkout.

**Lösningar**:
1. Kontrollera att add-ons är kopplade till subscription product i dashboard
2. Kontrollera att add-on IDs är korrekta i API-anrop
3. Säkerställ att add-on-valutan matchar subscription product-valutan
</Accordion>
</AccordionGroup>
