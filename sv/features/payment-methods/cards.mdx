Kortbetalningar är grunden för onlinebetalningar, accepteras globalt och åtnjuter kundernas förtroende världen över. Dodo Payments har stöd för alla större kortnätverk med inbyggt bedrägeriskydd och PCI-efterlevnad.

## Kortnätverk som stöds

### Globala nätverk

| Nätverk | Täckning |
| :------ | :------- |
| **Visa** | Global ledare, över 4 miljarder kort världen över |
| **Mastercard** | Global räckvidd, starka säkerhetsfunktioner |
| **American Express** | Premiumkortsinnehavare, högre spendering |
| **Discover** | USA-fokuserat, växer globalt |
| **JCB** | Ledande i Japan, expanderar i Asien |
| **UnionPay** | Dominerande i Kina, över 8 miljarder kort |

## Konfiguration

Använd dessa värden i `allowed_payment_method_types`:

| Typ | Beskrivning |
| :--- | :---------- |
| `credit` | Alla kreditkort |
| `debit` | Alla betalkort |

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  allowed_payment_method_types: ['credit', 'debit'],
  return_url: 'https://example.com/success'
});
```

<Tip>
Inkludera både `credit` och `debit` om du inte har ett specifikt skäl att utesluta något av dem. Betalkort föredras av många kunder och har ofta lägre avgifter.
</Tip>

## 3D Secure-autentisering

3D Secure (3DS) lägger till ett autentiseringslager som minskar bedrägerier och chargebacks genom att verifiera kortinnehavarens identitet.

### När 3DS aktiveras

3DS aktiveras automatiskt när:
- Det krävs av kortnätverket
- Det krävs enligt regionala bestämmelser (t.ex. PSD2 i Europa)
- Transaktionen flaggas som högrisk

### Tvinga 3DS

Du kan kräva 3DS för alla transaktioner:

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  force_3ds: true,
  return_url: 'https://example.com/success'
});
```

<Note>
Att aktivera 3DS för alla transaktioner minskar bedrägerier, men kan minska konverteringen något eftersom vissa kunder avbryter under autentiseringen.
</Note>

### Hantera autentiseringsfel

När en betalning behöver 3DS-autentisering passerar betalningen genom mellanliggande statusar innan den lyckas eller misslyckas:

| Status | Betydelse | Åtgärd |
|--------|---------|------------|
| `requires_customer_action` | Kunden måste slutföra en 3DS-utmaning | Be kunden slutföra autentiseringen under checkout |
| `requires_payment_method` | Kunden angav aldrig en betalningsmetod (angav inte sina uppgifter eller avbröt uppmaningen) — vanligtvis ett avhopp, inte ett avslag | Kontakta kunden igen så att hen kan slutföra checkout; se [Återställ övergivna kundvagnar](/features/recovery/abandoned-cart-recovery) |

Om autentiseringen inte slutförs misslyckas betalningen med någon av dessa decline codes:

- `AUTHENTICATION_FAILURE` — kunden kunde inte autentiseras.
- `AUTHENTICATION_REQUIRED` — autentisering krävs men utfördes inte.
- `AUTHENTICATION_TIMEOUT` — kunden svarade inte i tid.

Se referensen [Transaktionsfel](/api-reference/transaction-failures) för rekommenderad åtgärd för varje kod.

#### Vid checkout jämfört med vid förnyelse

- **Vid checkout (kunden närvarande):** Kunden är närvarande, så 3DS-utmaningen visas under checkout. Om den misslyckas ber du kunden försöka igen eller använda ett annat kort.
- **Vid förnyelse av prenumeration (kunden inte närvarande):** Kunden är inte närvarande, så en 3DS-utmaning kan inte visas i realtid. Om en förnyelse kräver autentisering flyttas prenumerationen till `on_hold`. Återställ den genom att be kunden återkomma och uppdatera sin betalningsmetod — se [Hantera betalningsfel](/developer-resources/handle-payment-failures) och [Påminnelser om prenumerationsbetalningar](/features/recovery/subscription-dunning).

## Sparade betalningsmetoder

Kunder kan spara sina kort för snabbare framtida checkouts.

</Card>
</CardGroup>

### Aktivera sparade kort

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  show_saved_payment_methods: true,
  customer: { customer_id: 'cus_existing_123' },
  return_url: 'https://example.com/success'
});
```

### Köp med ett klick

```javascript
// Get customer's saved payment methods
const methods = await client.customers.retrievePaymentMethods('cus_123');

// Use saved card for instant checkout
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'pdt_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  payment_method_id: methods.items[0].payment_method_id,
  confirm: true,
  return_url: 'https://example.com/success'
});
```

## Felsökning

<AccordionGroup>
<Accordion title="Card declined">
**Orsaker:** Otillräckliga medel, kortet har löpt ut, felaktig CVV, bankens bedrägeriskydd.

**Lösning:** Be kunden verifiera uppgifterna eller försöka med ett annat kort. Slå upp den specifika decline `Error Code` och dess rekommenderade åtgärd i referensen [Transaktionsfel](/api-reference/transaction-failures), och se [Hantera betalningsfel](/developer-resources/handle-payment-failures) för programmatisk hantering.
</Accordion>

<Accordion title="3DS authentication failed">
**Orsaker:** Kunden avbröt, banksystemet är inte tillgängligt, timeout.

**Lösning:** Försök igen eller be kunden kontakta sin bank. Se [Hantera autentiseringsfel](#handling-authentication-failures) för de betalningsstatusar och decline codes som berörs.
</Accordion>

<Accordion title="Card not supported">
**Orsaker:** Regionalt kort stöds inte, begränsningar för förbetalda kort.

**Lösning:** Kunden bör försöka med ett annat kort från ett större nätverk.
</Accordion>
</AccordionGroup>
