## Vad är Lokala Priser?

Varje produkt har ett baspris i en basvaluta. Lokala Priser låter dig åsidosätta det baspriset med **fasta priser du ställer in per valuta eller per land**. Aktivera det genom att ställa in en `pricing_mode` på produkten, och bifoga sedan en regel per marknad.

Det är en av flera oberoende reglage för internationell prissättning, där varje reglage löser ett annat problem:

| Mekanism | Vad den gör | Beloppet kunden ser |
| :--- | :--- | :--- |
| **Lokaliserad prissättning** | Ett fast pris som du anger per valuta eller land | Exakt det belopp du anger |
| [**Adaptive Currency**](/features/adaptive-currency) | Omvandlar automatiskt ditt baspris enligt aktuella FX-kurser | Baspris omvandlat enligt den aktuella växelkursen |
| [**Purchasing Power Parity**](/features/purchasing-power-parity) | Debiterar automatiskt en andel av ditt pris baserat på land | En procentandel av baspriset |
| [**Charm Pricing**](/features/charm-pricing) | Avrundar automatiskt det omvandlade priset till ett snyggt slut | Ett jämnt belopp, till exempel 49.99 |
| [**Discount codes**](/features/discount-codes) | En procentuell rabatt från baspriset | Baspris minus rabatten |

<Info>
Lokala Priser och Adaptiv Valuta fungerar tillsammans. När ingen lokal regel matchar faller produkten tillbaka till sitt baspris — debiteras direkt om kunden redan är i din basvaluta, eller konverteras via Adaptiv Valuta om inte.
</Info>

## Kärnkoncept

- **Prissättningslägen** — En produkt är alltid i exakt ett läge, vilket anges av dess `pricing_mode`:
  - `by_currency`: ett pris per valuta, oavsett land. Alla som betalar i EUR ser €9.99.
  - `by_country`: ett landsspecifikt pris (₹999 i Indien), även när flera länder delar valuta.
- **Fasta belopp i den minsta enheten** — En regels `amount` är ett heltal i valutans minsta enhet, precis som överallt annars i API:t: `99900` är ₹999.00 och `999` är €9.99. Det är ett pris du anger, aldrig ett omvandlat värde.
- **En matchande regel vinner över automatisk prissättning** — När en lokaliserad regel gäller för en rad hoppas [Purchasing Power Parity](/features/purchasing-power-parity) och [Charm Pricing](/features/charm-pricing) båda över för den raden. Kunden betalar det belopp du anger, oförändrat.
- **När ingen regel matchar** — Produkten behåller sitt befintliga beteende: kunder i din basvaluta betalar baspriset direkt, medan alla andra får det omvandlat genom [Adaptive Currency](/features/adaptive-currency).
- **Avgifter inkluderas när en regel matchar** — Kunden betalar **exakt** det belopp du anger. FX-avgiften för [Adaptive Currency](/features/adaptive-currency#choose-who-bears-the-fee) betalas av dig (hanteras som avgiftsinkluderad för den transaktionen) i stället för att läggas ovanpå, så ditt angivna lokala pris alltid är det pris som debiteras.

## Hantera via API

Lokala Priser är fullt tillgängliga via API. Ställ först in produktens prissättningsläge, sedan bifogar du regler.

### Ställ in prissättningsläget

Ställ in `pricing_mode` när du skapar produkten (eller uppdaterar en befintlig). `null` betyder bas-endast, det befintliga beteendet.

<CodeGroup>

```typescript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode',
});

const product = await client.products.update('pdt_premium_plan', {
  pricing_mode: 'by_country',
});
```

```python theme={null}
import os
from dodopayments import DodoPayments

client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
    environment="test_mode",
)

product = client.products.update(
    "pdt_premium_plan",
    pricing_mode="by_country",
)
```

```go theme={null}
package main

import (
	"context"
	"os"

	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func main() {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
	)

	_, err := client.Products.Update(
		context.TODO(),
		"pdt_premium_plan",
		dodopayments.ProductUpdateParams{
			PricingMode: dodopayments.F(dodopayments.PricingModeByCountry),
		},
	)
	if err != nil {
		panic(err)
	}
}
```

</CodeGroup>

### Lägg till ett lokaliserat pris

Bifoga en regel till produkten. I `by_country` läge är `country_code` obligatorisk; i `by_currency` läge måste den utelämnas.

<CodeGroup>

```typescript theme={null}
// ₹999.00 for customers in India
const localizedPrice = await client.products.localizedPrices.create('pdt_premium_plan', {
  currency: 'INR',
  country_code: 'IN',
  amount: 99900,
});
```

```python theme={null}
# ₹999.00 for customers in India
localized_price = client.products.localized_prices.create(
    "pdt_premium_plan",
    currency="INR",
    country_code="IN",
    amount=99900,
)
```

```go theme={null}
// ₹999.00 for customers in India
localizedPrice, err := client.Products.LocalizedPrices.New(
	context.TODO(),
	"pdt_premium_plan",
	dodopayments.ProductLocalizedPriceNewParams{
		Currency:    dodopayments.F(dodopayments.CurrencyInr),
		CountryCode: dodopayments.F(dodopayments.CountryCodeIn),
		Amount:      dodopayments.F(int64(99900)),
	},
)
```

</CodeGroup>

För en `by_currency` produkt, utelämna `country_code`. Till exempel, ett platt `€9.99` för alla som betalar i EUR (`currency: 'EUR'`, `amount: 999`).

### Lista, uppdatera och arkivera

Du kan endast uppdatera en regels `amount`; valuta och land är fasta när de skapats. Arkivering är en idempotent mjuk-radering, så regeln slutar att matcha men stannar i din historik.

<CodeGroup>

```typescript theme={null}
// List all active rules on a product
const rules = await client.products.localizedPrices.list('pdt_premium_plan');

// Change the amount (e.g. end a promo)
await client.products.localizedPrices.update('lcp_india_price', {
  product_id: 'pdt_premium_plan',
  amount: 119900,
});

// Archive a rule
await client.products.localizedPrices.archive('lcp_india_price', {
  product_id: 'pdt_premium_plan',
});
```

```python theme={null}
# List all active rules on a product
rules = client.products.localized_prices.list("pdt_premium_plan")

# Change the amount (e.g. end a promo)
client.products.localized_prices.update(

    product_id="pdt_premium_plan",
    amount=119900,

# Archive a rule
client.products.localized_prices.archive(
    "lcp_india_price",
    product_id="pdt_premium_plan",

```

## Hur det tillämpas vid Kassa

Lokala priser löses per varurad, och endast för produkter som har en `pricing_mode` satt. Dodo Payments läser två signaler från förfrågan: kundens **faktureringsland** samt en valfri **`billing_currency`** (när den utelämnas härleds en valuta från faktureringslandet).

- **Per Land**: söker efter en regel som matchar faktureringslandet. Om en sådan finns debiteras kunden regelns belopp i regelns valuta.
- **Per Valuta**: söker efter en regel som matchar kundens valuta (`billing_currency`, eller valutan härledd från deras land). Om en sådan finns debiteras kunden regelns belopp i den valutan.
- **Ingen match, eller ingen `pricing_mode`**: baspriset gäller, debiteras direkt när kundens valuta motsvarar basvalutan, annars konverteras via [Adaptiv Valuta](/features/adaptive-currency).

Varje varurad löses på egen hand, så du kan lokalisera en produkt och lämna andra på basprissättning inom samma kassa. Om någon rad matchar en lokaliserad regel, tvingas hela transaktionen till avgifter inklusive (se [Kärnkoncept](#core-concepts)).

## Så fungerar det vid ändringar av prenumerationsplaner

Lokaliserad prissättning följer dina prenumeranter när de byter plan. När en befintlig prenumeration [byter plan](/features/subscription#subscription-plan-changes) till en produkt som har en `pricing_mode` fastställs priset för den nya planen enligt samma regler som vid checkout, med hjälp av det faktureringsland och den valuta som redan är låsta på prenumerationen:

- **Per land**: en regel som matchar prenumerationens faktureringsland tillämpas. Om regelns valuta skiljer sig från valutan som prenumerationen faktureras i, konverteras regelns belopp enligt aktuella FX-kurser — regeln tillämpas, den hoppas inte över.
- **Per valuta**: en regel som matchar valutan som kunden faktureras i tillämpas, och kunden debiteras exakt regelns belopp.
- **Ingen matchning eller ingen `pricing_mode`**: den nya planens grundpris tillämpas och konverteras via [Adaptive Currency](/features/adaptive-currency) vid behov — samma reservlösning som vid checkout.

Detta gäller överallt där ett planbyte kan initieras: [Change Plan API](/api-reference/subscriptions/change-plan), självbetjäningsbyten av plan i [Customer Portal](/features/customer-portal) och ändringar som schemalagts till slutet av faktureringsperioden.

- **Förhandsvisningar är exakta.** [Preview Change Plan](/api-reference/subscriptions/preview-change-plan) returnerar samma lokaliserade belopp som den faktiska ändringen debiterar.
- **Förnyelser behåller det lokaliserade priset.** Efter ändringen förnyas den nya planen till sitt lokaliserade belopp — och förblir inklusive avgifter — precis som en prenumeration som skapats till det priset.
- **Proportionell debitering använder verkliga belopp.** Vid en uppgradering baseras krediteringen för outnyttjad tid på vad kunden faktiskt betalade för den gamla planen, medan den nya planen prissätts enligt sin lokaliserade regel.
- **Schemalagda ändringar låser priset när de schemaläggs.** En ändring som schemalagts till slutet av faktureringsperioden debiterar det belopp som beräknades när den schemalades, även om du redigerar regeln däremellan.
- **Faktureringsvalutan ändras aldrig.** Ett planbyte byter aldrig den valuta som en prenumeration regleras i; en regel i en annan valuta konverteras till den med FX.
- **Tillägg lokaliseras inte.** Tilläggspriser på den nya planen använder alltid sin grundprissättning.

## Viktiga beteenden

| Beteende | Detalj |
| :--- | :--- |
| **Belopp före skatt** | Ett lokaliserat belopp är priset *före* skatt. För produkter där skatt inte ingår läggs skatten ovanpå vid checkout, så det lokaliserade beloppet är inte slutsumman. Se [Tax-Inclusive Pricing](/features/tax-inclusive-pricing). |
| **Gäller inte Pay What You Want** | Lokaliserade regler tillämpas aldrig på produkter med [Pay What You Want](/features/pay-what-you-want), där kunden väljer beloppet. |
| **Per valuta skiljer sig från grundpriset** | En `by_currency`-regel måste använda en annan valuta än produktens basvaluta. |
| **En regel per marknad** | En produkt kan ha högst en aktiv regel per valuta (per valuta) eller per land (per land). |
| **Alla produkttyper** | Gäller engångsprodukter, prenumerationsprodukter och användningsbaserade produkter — även när en befintlig prenumerant [byter plan](#how-it-applies-on-subscription-plan-changes). |

<Info>
Ändringar av lokaliserade regler genererar inga egna webhooks. Det fastställda beloppet visas på den resulterande betalningen eller prenumerationen precis som vilket annat pris som helst.
</Info>

## Bästa praxis

- **Håll ett rimligt baspris.** Det används som reservpris på alla marknader utan regel och omvandlas genom Adaptive Currency.
- **Ange tydliga belopp.** Hela poängen med ett fast belopp är ett snyggt pris som ₹999, €9.99 eller ¥1000, inte ett FX-resultat. För automatisk avrundning i alla valutor, se [Charm Pricing](/features/charm-pricing).
- **Välj rätt läge för ändamålet.** Använd `by_country` för köpkraftsbaserad prissättning och `by_currency` när ett pris per valutaområde räcker.
- **Arkivera i stället för att skapa om vid kampanjer.** När du arkiverar en regel återgår marknaden till bas-/Adaptive Currency-prissättning samtidigt som historiken bevaras. Skapa om eller prissätt på nytt senare efter behov.
- **Tänk på skatteraden innan du annonserar ett totalpris.** För produkter där skatt inte ingår betalar kunden det lokaliserade beloppet *plus* skatt, så ange inte detta som slutpris i annonser.
