## Nya Funktioner

### 1. **Produktanalys på Nivå**

Varje produkt har nu sin egen **dedikerade analysdashboard**. Navigera till **Produkter > [Välj en Produkt]** för att få tillgång till detaljerade mätvärden specifika för den produkten, organiserade i fem flikar:

<Frame>
<img src="/images/product-analytics/overview.png" alt="Produktanalys på Nivå" />
</Frame>

| Flik | Vad Du Får |
|-----|-------------|
| **Översikt** | Totala intäkter, antal lyckade betalningar, trenddiagram för intäkter över 30 dagar (daglig eller kumulativ), och en filtrerbar transaktionstabell |
| **Kunder** | Topp 3 kunder rankade efter utgifter med en podiumvy, plus en fullständig kundnedbrytningstabel |
| **Retention** | Kunder som slutar, intäktsbortfall, och ett diagram med två linjer för att upptäcka mönster |
| **Prenumeranter** | Alla prenumerationer för produkten med status, startdatum, nästa betalningsdatum, och belopp |
| **MRR** | Månatlig återkommande intäkt staplad stapeldiagram med nedbrutna New MRR, Expansion MRR, Churned MRR, och Net New MRR |

Alla flikar stödjer ett **datumfilter** (som standard all tid) så att du kan gräva ner i vilken tidsperiod som helst.

<Tip>
Använd retention-fliken för att identifiera produkter med hög churn tidigt, och MRR-fliken för att spåra om expansionsintäkter överstiger churned-intäkter månad efter månad.
</Tip>

### 2. **Verifi RDR Stöd på Dodo Payments**

Dodo Payments stödjer nu **Visa Rapid Dispute Resolution (RDR)** som drivs av Verifi -- ett automatiserat tvistförebyggande verktyg som löser berättigade Visa-tvister **innan de blir formella chargebacks**. När en kortinnehavare påbörjar en tvist, kan RDR fånga den och automatiskt utfärda en återbetalning om transaktionens belopp ligger under din konfigurerade USD-tröskel.

**Varför Det Är Viktigt**

| Fördel | Påverkan |
|---------|--------|
| **Lägre tvistnivå** | RDR-lösta tvister räknas inte mot Visas 0,9% tröskel |
| **Inga tvistavgifter** | Undvik $15-$25 icke-återbetalningsbara avgifter per tvist |
| **Ingen operationell overhead** | Ingen insamlingsbevisning eller svarstider |
| **Bättre kundupplevelse** | Kortinnehavare får omedelbara återbetalningar |
| **Kontoskydd** | Håll dig utanför Visas Dispute Monitoring Program (VDMP) |

<Warning>
Överskridande av Visas 0,9% tvistnivå eller 100 tvister/månad utlöser VDMP, med trappande böter upp till $50,000+/månad. RDR hjälper dig att hålla dig väl under dessa trösklar.
</Warning>

**Hur Det Fungerar**

1. Kortinnehavaren påbörjar en tvist med sin bank
2. RDR fångar tvisten innan den blir en formell chargeback
3. Om transaktionsbeloppet är vid eller under din tröskel, utfärdas en återbetalning automatiskt
4. Tvisten löses omedelbart och **räknas inte** mot din tvistnivå

<Info>
Transaktioner som automatiskt återbetalas genom RDR visas som en **förlorad tvist** i din Dodo Payments dashboard. Detta är förväntat -- återbetalningen utfärdades automatiskt för att förhindra en formell chargeback.
</Info>

För att aktivera Verifi RDR på ditt konto, kontakta **support@dodopayments.com** för att konfigurera din tröskel.

Läs mer: [Visa RDR Dokumentation](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **DodoPayments CLI**

Introducerar den helt nya **DodoPayments CLI** (`dodopayments-cli`) -- hantera hela din Dodo Payments arbetsflöde direkt från terminalen. Byggd för utvecklare som föredrar kommandoraden, låter CLI dig hantera produkter, betalningar, kunder, rabatter, licenser, tillägg, återbetalningar, och till och med skapa checkout-sessioner utan att lämna din editor.

**Installation**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Nyckelkommandon**

| Kommando | Beskrivning |
|---------|-------------|
| `dodo login` | Autentisera med din API-nyckel (öppnar webbläsaren) |
| `dodo products list` | Lista alla produkter |
| `dodo payments list` | Lista alla betalningar |
| `dodo customers create` | Skapa en ny kund |
| `dodo checkout new` | Skapa en checkout-session och få URL:en |
| `dodo wh listen` | Vidarebefordra live-testwebhooks till din lokala server via WebSocket |
| `dodo wh trigger` | Skicka mock-webhook payload till valfri slutpunkt |

**Webhook-testning**

CLI:n inkluderar två kraftfulla verktyg för utveckling:

- **`dodo wh listen`** -- Öppnar en WebSocket-anslutning för att vidarebefordra realtids-testwebhooks till din lokala server, vilket bevarar originalhuvuden för signaturverifieringstestning
- **`dodo wh trigger`** -- Skickar mock-webhook payload interaktivt, och stöder alla 22 händelsetyper över prenumerationer, betalningar, återbetalningar, tvister, och licenser

<Tip>
Webhook-lyssnaren fungerar endast med en **testläges** API-nyckel. Se till att du är inloggad med en nyckel för testläge innan du använder `dodo wh listen`.
</Tip>

### 5. **Uppdatera Betalningsmetod i Inline Checkout**

Den [inline checkout](/developer-resources/inline-checkout) stöder nu **uppdateringar av betalningsmetoder** för prenumerationer. När en kund behöver uppdatera sin betalningsmetod (för en aktiv prenumeration eller för att återaktivera en prenumeration som har gått på håll), kan flödet för att uppdatera betalningsmetoden nu renderas direkt inom din sidlayout med hjälp av inline checkout -- vilket ger en sömlös, inbäddad upplevelse.

**Hur Det Fungerar**

1. Anropa API:et för att Uppdatera Betalningsmetoden för att få en `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Använd den återlämnade `payment_link` som `checkoutUrl` i inline checkout:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

Inline-ramen renderar endast formuläret för insamling av betalningsmetoder, vilket gör att kunder kan ange nya kortdetaljer eller välja en sparad betalningsmetod utan att lämna din sida.

<Tip>
För prenumerationer som har pausats, skapar flödet för att uppdatera betalningsmetoden automatiskt en avgift för kvarvarande skulder. Övervaka `payment.succeeded` och `subscription.active` webhooks för att bekräfta återaktiveringen.
</Tip>

Läs mer: [Inline Checkout](/developer-resources/inline-checkout) | [Uppdateringar av Prenumerationsbetalningsmetoder](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Stöd för Förifyllning av Skatte-ID för Checkout-sessioner**

Du kan nu **förfylla skatte-ID** (t.ex. momsnummer, GST-nummer) när du skapar en checkout-session med parametern `tax_id`. Detta är perfekt för B2B-transaktioner där du redan känner till kundens skatteidentifieringsnummer. När ett skatte-ID är förfyllt, låses fältet på checkout-formuläret.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
Parametern `tax_id` kräver en `billing_address` med minst ett `country`-fält. Skatteberättigande valideras i realtid, och omvänd avgift tillämpas automatiskt för kvalificerade B2B-transaktioner.
</Info>

Använd funktionsflaggan `allow_customer_editing_tax_id` för att kontrollera om kunder kan ändra det förifyllda skatte-ID:t, och `allow_tax_id` för att växla synligheten för skatte-ID på checkout.

Läs mer: [Checkout-sessioner - Skatte-ID](/developer-resources/checkout-session) | [B2B Betalningar](/features/b2b-payments)

### 7. **Licensnyckel och E-post i Return URL Omdirigering**

Efter att en kund har slutfört checkout, lägger Dodo Payments nu till `license_key` och `email` som frågeparametrar till din `return_url`-omdirigering, utöver de befintliga `payment_id`/`subscription_id` och `status`-parametrarna.

**Tillagda frågeparametrar**

| Parameter | Typ | Villkor |
|-----------|------|-----------|
| `payment_id` | `string` | Alltid närvarande för engångsbetalningar |
| `subscription_id` | `string` | Alltid närvarande för prenumerationsbetalningar |
| `status` | `string` | Alltid närvarande |
| `license_key` | `string` | Närvarande om produkten har licensnycklar aktiverade (komma-separerad för flera) |
| `email` | `string` | Närvarande om kunden har en e-postadress i registret |

**Exempel på omdirigerings-URL:er:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Använd dessa frågeparametrar för att visa licensnycklar eller skicka ett bekräftelsemail omedelbart på din retursida, utan att behöva en extra API-anrop.
</Tip>

Läs mer: [Checkout-sessioner - Return URL](/developer-resources/checkout-session) | [Licensnycklar i Return URL](/features/license-keys#license-keys-in-return-url)

### 8. **API för Uppdatering av Kund-E-post**

Endpointen `PATCH /customers/{customer_id}` stöder nu programmatisk uppdatering av kundernas e-postadresser. Uppdatera e-post tillsammans med namn, telefonnummer, och metadata i ett enda API-anrop.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Uppdateringsbara Fält**

| Fält | Typ | Beskrivning |
|-------|------|-------------|
| `email` | `string \| null` | Kundens e-postadress |
| `name` | `string \| null` | Kundens visningsnamn |
| `phone_number` | `string \| null` | Telefonnummer i internationellt format |
| `metadata` | `object \| null` | Anpassade nyckel-värde-par |

<Info>
Uppdateringar av kundens e-post finns även tillgängliga genom Kundportalen (självbetjäning), dashboarden, och CLI via `dodo customers update`.
</Info>

### 9. **Bun-adapterutgåvan**

Introducerar `@dodopayments/bun` -- en dedikerad ramverksadapter för [Bun's](https://bun.sh) native server (`Bun.serve()`). Integrera checkout, kundportal, och webhooks med Bun på bara några rader kod.

**Installation**

```bash
bun add @dodopayments/bun
```

**Snabbinstallation**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

Bun-adaptern stöder alla tre checkout-flöden (statisk, dynamisk, och sessionbaserad), generering av kundportalsessioner, och säker hantering av webhooks med signaturverifiering och Zod-validering över 22 händelsetyper.

<Check>
Bun-adaptern går med i vår familj av 11 ramverksadaptrar inklusive Next.js, Nuxt, Express, Fastify, Hono, Astro, SvelteKit, Remix, TanStack Start, Better Auth, och Convex.
</Check>

Läs mer: [Bun Adapter Dokumentation](/developer-resources/bun-adaptor) | [Ramverksadaptrar Översikt](/developer-resources/framework-adaptors)
