### 1. **تحليلات على مستوى المنتج**

كل منتج أصبح لديه **لوحة تحليلات مخصصة** خاصة به. انتقل إلى **المنتجات > [اختر منتجًا]** للوصول إلى مقاييس مفصلة مرتبطة بذلك المنتج، منظمة عبر خمس علامات:

<Frame>
<img src="/images/product-analytics/overview.png" alt="تحليلات على مستوى المنتج" />
</Frame>

| العلامة | ما ستحصل عليه |
|---------|--------------|
| **نظرة عامة** | إجمالي الإيرادات، عدد المدفوعات الناجحة، مخطط اتجاه الإيرادات لمدة 30 يومًا (يومي أو تراكمي)، وجدول معاملات قابل للتصفية |
| **العملاء** | أفضل 3 عملاء مرتبين حسب الإنفاق مع عرض المنصة، بالإضافة إلى جدول تفصيلي كامل للعملاء |
| **الاحتفاظ** | معدل دوران العملاء، معدل دوران الإيرادات، ومخطط اتجاه بخط مزدوج لاكتشاف الأنماط |
| **المشتركين** | جميع الاشتراكات المرتبطة بالمنتج مع الحالة، تاريخ البدء، تاريخ الفوترة التالي، والمبلغ |
| **MRR** | مخطط الأعمدة المكدسة للإيرادات المتكررة شهريًا مع تفصيلات الإيرادات الجديدة، توسعات الإيرادات، الإيرادات المتراجعة، والإيرادات الصافية الجديدة |

جميع العلامات تدعم **مرشح تاريخي** (افتراضي على جميع الأوقات) حتى تتمكن من التعمق في أي فترة زمنية.

<Tip>
استخدم علامة الاحتفاظ لتحديد المنتجات ذات معدل الدوران العالي مبكرًا، وعلامة MRR لتتبع ما إذا كانت إيرادات التوسع تتجاوز الإيرادات المتراجعة شهراً بعد شهر.
</Tip>

### 2. **دعم Verifi RDR على Dodo Payments**

يدعم Dodo Payments الآن **حل النزاعات السريعة من Visa (RDR)** المدعوم من Verifi - أداة تلقائية لمنع المنازعات تحل النزاعات المؤهلة من Visa **قبل أن تصبح استردادًا رسميًا**. عندما يبدأ حامل البطاقة نزاعًا، تتدخل RDR وتصدر تلقائيًا استردادًا إذا كانت المعاملة أقل من حدك المحدد بالدولار الأمريكي.

**لماذا هذا مهم**

| الفائدة | التأثير |
|---------|--------|
| **معدل نزاعات أقل** | النزاعات التي تم حلها بواسطة RDR لا تُحتسب ضمن حد 0.9% الخاص بـ Visa |
| **لا رسوم نزاع** | تجنب الرسوم غير القابلة للاسترداد التي تتراوح بين 15-25 دولارًا لكل نزاع |
| **عدم وجود عبء تشغيلي** | لا حاجة لجمع الأدلة أو مواعيد استجابة |
| **تجربة عملاء أفضل** | يحصل حاملو البطاقات على استردادات فورية |
| **حماية الحساب** | ابق بعيدًا عن برنامج مراقبة المنازعات من Visa (VDMP) |

<Warning>
تجاوز معدل النزاع 0.9% الخاص بـ Visa أو 100 نزاعًا في الشهر يؤدي إلى تفعيل VDMP، مع غرامات تصاعدية تصل إلى أكثر من 50000 دولار شهريًا. يساعدك RDR على البقاء بعيدًا عن هذه الحدود.
</Warning>

**كيف يعمل**

1. يبدأ حامل البطاقة نزاعًا مع بنكه
2. تتدخل RDR في النزاع قبل أن يصبح استردادًا رسميًا
3. إذا كانت قيمة المعاملة أقل من أو تساوي حدك، يتم إصدار استرداد تلقائي
4. يتم حل النزاع على الفور ولا يُحتسب ضد معدل النزاع لديك

<Info>
المعاملات التي تم استردادها تلقائيًا عبر RDR تظهر كنزاع مفقود في لوحة معلومات Dodo Payments الخاصة بك. هذه هي الحالة المتوقعة - تم إصدار الاسترداد تلقائيًا لمنع استرداد رسمي.
</Info>

لتفعيل Verifi RDR على حسابك، اتصل بـ **support@dodopayments.com** لتكوين حدك.

تعلم المزيد: [وثائق Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **سطر أوامر DodoPayments**

نقدم لك سطر الأوامر الجديد **DodoPayments CLI** (`dodopayments-cli`) -- إدارة سير عمل Dodo Payments بالكامل مباشرة من الطرفية. مصمم للمطورين الذين يفضلون سطر الأوامر، يتيح لك CLI إدارة المنتجات، المدفوعات، العملاء، الخصومات، التراخيص، الملحقات، الاستردادات، وحتى إنشاء جلسات الشراء دون مغادرة محررك.

**التثبيت**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**الأوامر الرئيسية**

| الأمر | الوصف |
|---------|-------------|
| `dodo login` | المصادقة باستخدام مفتاح API الخاص بك (يفتح المتصفح) |
| `dodo products list` | قائمة بجميع المنتجات |
| `dodo payments list` | قائمة بجميع المدفوعات |
| `dodo customers create` | إنشاء عميل جديد |
| `dodo checkout new` | إنشاء جلسة شراء والحصول على عنوان URL |
| `dodo wh listen` | توجيه الويب الحية الاختبارية إلى الخادم المحلي الخاص بك عبر WebSocket |
| `dodo wh trigger` | إرسال حمولات الويب الاختبارية إلى أي نقطة نهاية |

**اختبار الويب**

يتضمن CLI أداتين قويتين للتطوير:

- **`dodo wh listen`** -- يفتح اتصال WebSocket لتوجيه اختبارات الويب الحية إلى الخادم المحلي الخاص بك، مع الحفاظ على الرؤوس الأصلية لاختبار التحقق من التوقيع
- **`dodo wh trigger`** -- يرسل حمولات الويب الاختبارية تفاعليًا، مع دعم جميع أنواع الأحداث الـ 22 عبر الاشتراكات والمدفوعات والاستردادات والمنازعات والتراخيص

<Tip>
تعمل مستمعات الويب فقط مع مفتاح API بوضع **اختباري**. تأكد من أنك قمت بتسجيل الدخول باستخدام مفتاح وضع الاختبار قبل استخدام `dodo wh listen`.
</Tip>

تعلم المزيد: [وثائق CLI](/developer-resources/sdks/cli)

### 5. **تحديث طريقة الدفع في عملية الشراء المدمجة**

يدعم [عمليات الشراء المدمجة](/developer-resources/inline-checkout) الآن **تحديثات طرق الدفع** للاشتراكات. عندما يحتاج عميل إلى تحديث طريقة دفعه (للاشتراك النشط أو لإعادة تنشيط اشتراك كانت حالته موقوفة)، يمكن الآن عرض تدفق تحديث طريقة الدفع مباشرة داخل تخطيط صفحتك باستخدام عملية الشراء المدمجة -- مما يوفر تجربة سلسة ومدمجة.

**كيف يعمل**

1. استدعِ واجهة برمجة تطبيقات تحديث طريقة الدفع للحصول على `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. استخدم `payment_link` المعاد كـ `checkoutUrl` في عملية الشراء المدمجة:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

تقوم الإطار المدمج بعرض نموذج جمع طريقة الدفع فقط، مما يسمح للعملاء بإدخال تفاصيل بطاقة جديدة أو اختيار طريقة دفع محفوظة دون مغادرة صفحتك.

<Tip>
بالنسبة للاشتراكات الموقوفة، يقوم تدفق تحديث طريقة الدفع تلقائيًا بإنشاء شحنة للديون المتبقية.راقب `payment.succeeded` و `subscription.active` لاكتمال إعادة التنشيط.
</Tip>

تعرف على المزيد: [العمليات المدمجة](/developer-resources/inline-checkout) | [تحديثات طريقة الدفع للاشتراك](/features/subscription#update-payment-method-for-active-subscription)

### 6. **دعم تعبئة مسبقة لرقم التعريف الضريبي لجلسات الشراء**

يمكنك الآن **تعبئة رقم التعريف الضريبي** (مثل رقم VAT، رقم GST) عند إنشاء جلسة شراء باستخدام المعامل `tax_id`. هذا مثالي للمعاملات من B2B حيث تعرف بالفعل رقم التعريف الضريبي للعميل. عند تعبئة رقم التعريف الضريبي، يتم تعبئة الحقل مسبقًا وإغلاقه في نموذج عملية الشراء.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
المعاملة `tax_id` تتطلب `billing_address` مع حقل واحد على الأقل من `country`. يتم التحقق من الأهلية الضريبية في الوقت الفعلي، وتطبق قواعد الرسوم العكسية تلقائيًا للمعاملات المؤهلة من B2B.
</Info>

استخدم علم الميزة `allow_customer_editing_tax_id` للتحكم فيما إذا كان يمكن للعملاء تعديل رقم التعريف الضريبي المعبأ مسبقًا، و `allow_tax_id` لتبديل رؤية رقم التعريف الضريبي عند الشراء.

تعلم المزيد: [جلسات الشراء - رقم التعريف الضريبي](/developer-resources/checkout-session) | [المدفوعات B2B](/features/b2b-payments)

### 7. **مفتاح الترخيص والبريد الإلكتروني في إعادة توجيه عنوان URL**

بعد إكمال العميل لعملية الشراء، يضيف Dodo Payments الآن `license_key` و `email` كمعاملات استعلام إلى إعادة توجيه `return_url` الخاصة بك، بالإضافة إلى المعاملات الحالية `payment_id`/`subscription_id` و `status`.

**المعاملات المرفقة**

| المعامل | النوع | الشرط |
|-----------|------|-----------|
| `payment_id` | `string` | دائمًا موجودة للمدفوعات لمرة واحدة |
| `subscription_id` | `string` | دائمًا موجودة لمدفوعات الاشتراك |
| `status` | `string` | دائمًا موجودة |
| `license_key` | `string` | موجود إذا كان لدى المنتج مفاتيح ترخيص ممكّنة (مفصولة بفواصل لأكثر من مفتاح) |
| `email` | `string` | موجود إذا كان لدى العميل بريد إلكتروني مسجل |

**مثال على روابط إعادة التوجيه:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
استخدم هذه المعاملات لإظهار مفاتيح الترخيص أو إرسال بريد تأكيد فورًا على صفحتك عند العودة، دون الحاجة إلى استدعاء API إضافية.
</Tip>

تعلم المزيد: [جلسات الشراء - عنوان URL لإعادة التوجيه](/developer-resources/checkout-session) | [مفاتيح الترخيص في عنوان URL للإعادة](/features/license-keys#license-keys-in-return-url)

### 8. **واجهة برمجة تطبيقات تحديث بريد العملاء**

نقطة النهاية `PATCH /customers/{customer_id}` الآن تدعم تحديث عناوين البريد الإلكتروني للعملاء برمجيًا. تحديث البريد الإلكتروني جنبًا إلى جنب مع الاسم، رقم الهاتف، والبيانات الوصفية في استدعاء API واحد.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**حقول قابلة للتحديث**

| الحقل | النوع | الوصف |
|-------|------|-------------|
| `email` | `string \| null` | عنوان البريد الإلكتروني للعميل |
| `name` | `string \| null` | الاسم المعروض للعميل |
| `phone_number` | `string \| null` | رقم الهاتف بتنسيق دولي |
| `metadata` | `object \| null` | أزواج مفتاح-قيمة مخصصة |

<Info>
تحديثات البريد الإلكتروني للعملاء متاحة أيضًا من خلال بوابة العملاء (خدمة ذاتية)، لوحة المعلومات، وCLI عبر `dodo customers update`.
</Info>

تعلم المزيد: [واجهة برمجة تطبيقات تحديث العملاء](/api-reference/customers/patch-customer) | [إدارة العملاء](/features/customers)

### 9. **إطلاق موصل Bun**

نقدم لكم `@dodopayments/bun` -- موصل إطار مخصص لـ [Bun](https://bun.sh) الخادم الأصلي (`Bun.serve()`). دمج عمليات الشراء، بوابة العملاء، والويب هوكس مع Bun في بضعة أسطر من الكود.

**التثبيت**

```bash
bun add @dodopayments/bun
```

**إعداد سريع**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

يدعم موصل Bun جميع تدفقات الشراء الثلاثة (ثابتة، ديناميكية، ومعتمدة على الجلسة)، ون生成 جلسات بوابة العملاء، ومعالجة ويب هوكس بشكل آمن مع التحقق من التوقيع والتحقق من صحة Zod عبر 22 نوعًا مختلفًا من الأحداث.

</Check>
