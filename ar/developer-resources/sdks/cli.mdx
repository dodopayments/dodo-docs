إدارة موارد مدفوعات Dodo، إنشاء جلسات الخروج، واختبار الويب هوكس مباشرة من الطرفية. مصمم للمطورين الذين يفضلون سطر الأوامر.

## التثبيت

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### التثبيت اليدوي

1. قم بتنزيل الإصدار الأخير من [إصدارات GitHub](https://github.com/dodopayments/dodopayments-cli/releases) لنظامك
2. قم بفك ضغط الملف وإعادة تسمية الثنائي إلى `dodo`
3. انتقل إلى دليل في PATH الخاص بك:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## المصادقة

قبل استخدام CLI، قم بالمصادقة باستخدام مفتاح API الخاص بك:

```bash
dodo login
```

سيؤدي ذلك إلى:
1. فتح متصفحك على صفحة مفاتيح API لموقع Dodo Payments
2. مطالبتك بإدخال مفتاح API الخاص بك
3. سؤالك لاختيار البيئة (**وضع الاختبار** أو **وضع البث المباشر**)
4. تخزين بيانات اعتمادك محليًا في `~/.dodopayments/api-key`

<Info>
يدعم CLI تخزين مفتاح API واحد لكل بيئة. إذا تم تكوين مفاتيح لكل من وضع الاختبار ووضع البث المباشر، سيتم مطالبتك باختيار أي بيئة لاستخدامها للجلسة الحالية.
</Info>

## الاستخدام

الصيغة العامة هي:

```bash
dodo ‹category› ‹sub-command›
```

تشغيل `dodo` بدون أي معلمات يعرض جميع الفئات المتاحة. تشغيل `dodo <category>` بدون أمر فرعي يعرض الأوامر الفرعية المتاحة لتلك الفئة.

### المنتجات

إدارة كتالوج المنتجات الخاص بك.

| الأمر | الوصف |
|---------|-------------|
| `dodo products list` | قائمة بجميع المنتجات (مقيدة) |
| `dodo products create` | فتح لوحة المعلومات لإنشاء منتج |
| `dodo products info` | عرض التفاصيل لمنتج معين |

### المدفوعات

عرض معاملات الدفع.

| الأمر | الوصف |
|---------|-------------|
| `dodo payments list` | قائمة بجميع المدفوعات (مقيدة) |
| `dodo payments info` | الحصول على معلومات حول دفع معين |

### العملاء

إدارة قاعدة عملائك.

| الأمر | الوصف |
|---------|-------------|
| `dodo customers list` | قائمة بجميع العملاء (مقيدة) |
| `dodo customers create` | إنشاء ملف تعريف عميل جديد |
| `dodo customers update` | تحديث تفاصيل عميل موجود |

### الخصومات

إدارة القسائم والخصومات.

| الأمر | الوصف |
|---------|-------------|
| `dodo discounts list` | قائمة بجميع الخصومات (مقيدة) |
| `dodo discounts create` | إنشاء خصم جديد يعتمد على النسبة المئوية |
| `dodo discounts delete` | إزالة خصم باستخدام ID |

### التراخيص

إدارة تراخيص البرمجيات.

| الأمر | الوصف |
|---------|-------------|
| `dodo licences list` | قائمة بجميع مفاتيح الترخيص (مقيدة) |

### الإضافات

إدارة إضافات المنتجات.

| الأمر | الوصف |
|---------|-------------|
| `dodo addons list` | قائمة بجميع الإضافات (مقيدة) |
| `dodo addons create` | فتح لوحة المعلومات لإنشاء إضافة |
| `dodo addons info` | عرض التفاصيل لإضافة معينة |

### المبالغ المستردة

عرض معلومات المبالغ المستردة.

| الأمر | الوصف |
|---------|-------------|
| `dodo refund list` | قائمة بجميع المبالغ المستردة (مقيدة) |
| `dodo refund info` | عرض تفاصيل مبلغ مسترد معين |

### الخروج

إنشاء جلسات الخروج.

| الأمر | الوصف |
|---------|-------------|
| `dodo checkout new` | إنشاء جلسة خروج جديدة والحصول على رابط الخروج |

يدعم أمر الخروج خيارات متقدمة بما في ذلك جمع العنوان القليل، رابط العودة، فرض 3D Secure، رموز الخصم، وبيانات التعريف.

## اختبار الويب هوكس

يتضمن CLI أداتين قويتين لاختبار الويب هوكس أثناء التطوير: **مستمع** يقوم بتحويل الويب هوكس التجريبية حية إلى خادمك المحلي، و**محفز** يرسل حمولات ويب هوكس مزيفة إلى أي نقطة نهاية.

### الاستماع للويب هوكس

تحويل الويب هوكس من Dodo Payments مباشرة إلى خادم تطويرك المحلي في الوقت الحقيقي.

```bash
dodo wh listen
```

<Steps>
<Step title="أدخل عنوان endpoint المحلي الخاص بك">
  قدم عنوان URL المحلي حيث تريد تلقي الويب هوكس (على سبيل المثال، `http://localhost:3000/webhook`).
</Step>

<Step title="الإعداد التلقائي">
  يقوم CLI تلقائيًا بإنشاء نقطة نهاية ويب هوك على حسابك في Dodo Payments إذا لم تكن موجودة بالفعل، ثم يفتح اتصال WebSocket لاستقبال الأحداث في الوقت الحقيقي.
</Step>

<Step title="تلقي وتحويل">
  عند حدوث حدث ويب هوك (من دفع تجريبي، تغيير اشتراك، إلخ)، يتلقاه CLI، ويسجل نوع الحدث، ثم يحول الطلب الكامل مع الرؤوس والجسد إلى نقطة النهاية المحلية الخاصة بك. يتم تسجيل استجابة نقطة النهاية الخاصة بك وإرسالها مرة أخرى.
</Step>
</Steps>

<Warning>
لا يعمل مستمع الويب هوك إلا مع مفتاح API **وضع الاختبار**. تأكد من أنك قد سجلت الدخول باستخدام مفتاح وضع الاختبار قبل استخدام `dodo wh listen`.
</Warning>

<Tip>
يحافظ المستمع على رؤوس الويب هوك الأصلية (`webhook-id`، `webhook-signature`، `webhook-timestamp`) عند تحويلها إلى نقطة النهاية المحلية الخاصة بك، لذا يمكنك اختبار منطق التحقق من التوقيع الخاص بك.
</Tip>

### حفز اختبارات الويب هوك

أرسل حمولات ويب هوكس مزيفة إلى أي نقطة نهاية لاختبار سريع بدون الحاجة إلى إنشاء معاملات حقيقية.

```bash
dodo wh trigger
```

هذا يرشدك خلال:
1. تعيين **عنوان URL** الوجهة
2. تكوين **معرّف العمل**، **معرّف المنتج**، و**البيانات التعريفية** اختياريًا
3. اختيار **حدث** محدد للتفعيل من قائمة تفاعلية
4. إرسال الحمولة المزيفة وعرض الاستجابة

بعد كل حدث، يمكنك اختيار حدث آخر للتفعيل أو الخروج - مما يسهل اختبار معالجات الأحداث المتعددة في جلسة واحدة.

<Warning>
تقوم أداة التحفيز بإرسال حمولات مزيفة بدون توقيعات ويب هوك. قم بتعطيل التحقق من توقيع ويب هوك أثناء الاختبار باستخدام `unsafe_unwrap()` بدلاً من `unwrap()` في معالج الويب هوك الخاص بك.
</Warning>

### أحداث ويب هوك المدعومة

| الفئة | الأحداث |
|----------|--------|
| **الاشتراك** | `subscription.active`، `subscription.updated`، `subscription.on_hold`، `subscription.renewed`، `subscription.plan_changed`، `subscription.cancelled`، `subscription.failed`، `subscription.expired` |
| **الدفع** | `payment.success`، `payment.failed`، `payment.processing`، `payment.cancelled` |
| **الاسترداد** | `refund.success`، `refund.failed` |
| **النزاع** | `dispute.opened`، `dispute.expired`، `dispute.accepted`، `dispute.cancelled`، `dispute.challenged`، `dispute.won`، `dispute.lost` |
| **الرخصة** | `licence.created` |

### متغيرات البيئة

| المتغير | الوصف |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | تجاوز عنوان URL الافتراضي لخادم نقل الويب هوك المستخدم بواسطة `dodo wh listen` |
