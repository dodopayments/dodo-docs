تقدم مدفوعات دودي موصلات رسمية للإطار تسهل دمج المدفوعات. تم تصميم كل موصل للعمل بسلاسة مع تقاليد إطارك، مما يوفر معالجة الدفع، وبوابة العملاء، والتعامل مع الويب هوك بشكل مباشر.

<Tip>
تتيح لك موصلات الإطار دمج مدفوعات دودي في أقل من 10 أسطر من التعليمات البرمجية. إنها تتعامل مع المصادقة، وتحليل الطلبات، وتنسيق الاستجابات تلقائيًا.
</Tip>

## الميزات الأساسية

توفر جميع محولات الإطار هذه الإمكانيات المدمجة:

| الميزة | الوصف |
|---------|-------------|
| **معالج الدفع** | دعم لمجاري الدفع الثابتة والديناميكية والمبنية على الجلسات |
| **بوابة العملاء** | معالج مسبق البناء لإدارة الاشتراكات والفوترة |
| **معالج Webhook** | التحقق من توقيع آمن مع معالجات أحداث معينة |
| **تكوين البيئة** | إعداد بسيط عبر متغيرات البيئة |
| **أمان النوع** | دعم كامل لـ TypeScript مع حمولة محددة |

## البدء السريع

ابدأ مع أي محول إطار في ثلاث خطوات:

<Steps>
<Step title="تثبيت المحول">
  استخدم مدير الحزم الخاص بك لتثبيت المحول المحدد للإطار:

  <Tabs>
  <Tab title="Next.js">

  ```bash
  npm install @dodopayments/nextjs
  ```

  </Tab>
  
  <Tab title="Nuxt">

  ```bash
  npm install @dodopayments/nuxt
  ```

  </Tab>
  
  <Tab title="Express">

  ```bash
  npm install @dodopayments/express
  ```

  </Tab>
  
  <Tab title="Hono">

  ```bash
  npm install @dodopayments/hono
  ```

  </Tab>

  <Tab title="Astro">

  ```bash
  npm install @dodopayments/astro
  ```

  </Tab>

  <Tab title="SvelteKit">

  ```bash
  npm install @dodopayments/sveltekit
  ```

  </Tab>
  </Tabs>
</Step>

<Step title="تكوين متغيرات البيئة">
  أضف بيانات اعتماد Dodo Payments الخاصة بك إلى بيئتك:

  ```env
  DODO_PAYMENTS_API_KEY=your-api-key
  DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
  DODO_PAYMENTS_RETURN_URL=https://yourdomain.com/checkout/success
  DODO_PAYMENTS_ENVIRONMENT="test_mode" # or "live_mode"
  ```

  <Warning>
  لا تقم أبداً بإيداع ملف `.env` أو الأسرار في التحكم في الإصدار.
  </Warning>
</Step>

<Step title="إنشاء معالجات الطريق">
  قم بإعداد مسارات الدفع، بوابة العملاء، وWebhook:

  <Tabs>
  <Tab title="Next.js">

  ```typescript
  // app/checkout/route.ts
  import { Checkout } from "@dodopayments/nextjs";

  export const GET = Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  });
  ```

  </Tab>
  
  <Tab title="Express">

  ```typescript
  import { checkoutHandler } from '@dodopayments/express';

  app.get('/api/checkout', checkoutHandler({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  
  <Tab title="Hono">

  ```typescript
  import { Checkout } from "@dodopayments/hono";

  app.get('/checkout', Checkout({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
    environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
  }));
  ```

  </Tab>
  </Tabs>

  <Check>
  أنت الآن جاهز لمعالجة المدفوعات! قم بزيارة صفحات المحول الفردية للحصول على أدلة تفصيلية وجميع الخيارات المتاحة.
  </Check>
</Step>
</Steps>

## أنواع تدفق الدفع

تدعم جميع المحولات ثلاث أنواع من تدفقات الدفع:

<AccordionGroup>
<Accordion title="الدفع الثابت (GET)">
استخدم الدفع الثابت لروابط الدفع البسيطة، القابلة للمشاركة. مرر معرّف المنتج كمعامل استعلام:

```
/api/checkout?productId=pdt_xxx&quantity=1
```

يدعم تعبئة مسبقة اختيارية للعملاء وتخصيص عبر معاملات استعلام.
</Accordion>

<Accordion title="الدفع الديناميكي (POST)">
استخدم الدفع الديناميكي لإنشاء مدفوعات برمجيًا مع تفاصيل مخصصة:

```json
{
  "product_id": "pdt_xxx",
  "customer": {
    "email": "customer@example.com",
    "name": "John Doe"
  },
  "quantity": 1
}
```

يدعم كل من المدفوعات لمرة واحدة والاشتراكات.
</Accordion>

<Accordion title="جلسات الدفع (POST)">
استخدم جلسات الدفع لتجربة الدفع الأكثر مرونة مع دعم السلة:

```json
{
  "product_cart": [
    { "product_id": "pdt_xxx", "quantity": 1 },
    { "product_id": "pdt_yyy", "quantity": 2 }
  ],
  "customer": {
    "email": "customer@example.com"
  }
}
```

تعرّف على المزيد في [دليل جلسات الدفع](/developer-resources/checkout-session).
</Accordion>
</AccordionGroup>

## معالجة أحداث Webhook

توفر جميع المحولات معالجة آمنة من حيث النوع لـ Webhook مع ردود أحداث دقيقة:

```typescript
Webhooks({
  webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY,
  onPayload: async (payload) => {
    // Handle any webhook event
  },
  onPaymentSucceeded: async (payload) => {
    // Handle successful payments
  },
  onSubscriptionActive: async (payload) => {
    // Handle new subscriptions
  },
  // ... 20+ event types supported
});
```

<Info>
تتحقق جميع معالجات Webhook تلقائيًا من التوقيعات وتتحقق من صحة الحمولة باستخدام مخططات Zod. تتمReject الطلبات غير الصالحة مع رموز خطأ مناسبة.
</Info>

## اختيار المحول المناسب

| إطار العمل | الأفضل ل | وقت التشغيل |
|-----------|----------|---------|
| **Next.js** | تطبيقات React كاملة المكدس مع App Router | Node.js، Edge |
| **Nuxt** | تطبيقات Vue.js كاملة المكدس | Node.js |
| **Express** | واجهات برمجة التطبيقات REST والتطبيقات Node.js التقليدية | Node.js |
| **Fastify** | واجهات برمجة التطبيقات عالية الأداء | Node.js |
| **Hono** | نشرات Edge، عمال Cloudflare | Edge، Node.js |
| **Astro** | مواقع المحتوى مع نقاط نهاية للخادم | Node.js، Edge |
| **SvelteKit** | تطبيقات Svelte كاملة المكدس | Node.js |
| **Remix** | تطبيقات React كاملة المكدس مع توجيه متداخل | Node.js |
| **TanStack Start** | React كاملة المكدس بأمان النوع | Node.js |
| **Better Auth** | التطبيقات المستخدمة بالفعل Better Auth | متعددة |
| **Convex** | التطبيقات التي تستخدم Convex كخلفية | Convex Runtime |
| **Bun** | تطبيقات خادم Bun الأصلية | Bun |
