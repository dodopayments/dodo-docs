## نظرة عامة

يوفر قالب Go الجاهز نقطة بداية جاهزة للاستخدام في بيئة الإنتاج لدمج Dodo Payments مع الواجهة الخلفية المبنية بـ Go. يتضمن هذا القالب معالجة جلسات الدفع، والتحقق من Webhook، ودمج Customer Portal، ويتبع أفضل ممارسات Go لمساعدتك على بدء قبول المدفوعات بسرعة.

<Info>
يستخدم هذا القالب Go 1.21+ مع أنماط البنية النظيفة (`cmd`، `internal`، `templates`)، وقوالب HTML، وSDK ‏`dodopayments-go` لتكامل سلس مع API.
</Info>

### الميزات

- **إعداد سريع** - ابدأ في أقل من 5 دقائق
- **تكامل الدفع** - تدفق Checkout مُعد مسبقًا باستخدام SDK ‏`dodopayments-go`
- **واجهة مستخدم عصرية** - صفحة أسعار بسيطة ذات مظهر داكن باستخدام قوالب HTML
- **معالجة Webhook** - التحقق الآمن من أحداث الدفع ومعالجتها
- **Customer Portal** - إدارة الاشتراكات ذاتية الخدمة
- **أفضل ممارسات Go** - بنية نظيفة باستخدام `cmd` و`internal` و`templates`
- **Checkout مُعبأ مسبقًا** - يوضح تمرير بيانات العميل لتحسين تجربة المستخدم

## المتطلبات الأساسية

قبل البدء، تأكد من توفر ما يلي:

- **Go 1.21+**
- **حساب Dodo Payments** (للوصول إلى مفاتيح API وWebhook من لوحة التحكم)

## البدء السريع

<Steps>
<Step title="Clone the Repository">

```bash
git clone https://github.com/dodopayments/go-boilerplate.git
cd go-boilerplate
```

</Step>

<Step title="Install Dependencies">

```bash
make install
```

أو يدويًا:

```bash
go mod download
```

</Step>

<Step title="Get API Credentials">
سجّل حسابًا على [Dodo Payments](https://dodopayments.com/) واحصل على بيانات الاعتماد من لوحة التحكم:

- **مفتاح API:** [لوحة التحكم ← المطور ← مفاتيح API](https://app.dodopayments.com/developer/api-keys)
- **مفتاح Webhook:** [لوحة التحكم ← المطور ← Webhooks](https://app.dodopayments.com/developer/webhooks)

<Tip>
تأكد من أنك تستخدم **الوضع التجريبي** أثناء التطوير!
</Tip>
</Step>

<Step title="Configure Environment Variables">
أنشئ ملف `.env` في الدليل الجذر:

```bash
cp .env.example .env
```

حدّث القيم باستخدام بيانات اعتماد Dodo Payments:

```bash .env
DODO_PAYMENTS_API_KEY=your_api_key_here
DODO_PAYMENTS_WEBHOOK_KEY=your_webhook_signing_key_here
DODO_PAYMENTS_RETURN_URL=http://localhost:8000
DODO_PAYMENTS_ENVIRONMENT=test_mode
```

<Warning>
لا ترفع ملف `.env` إلى نظام التحكم في الإصدارات مطلقًا. وهو مضمن بالفعل في `.gitignore`.
</Warning>
</Step>

<Step title="Add Your Products">
حدّث `internal/lib/products.go` باستخدام معرّفات المنتجات الفعلية من Dodo Payments:

```go
var Products = []Product{
    {
        ProductID:   "pdt_001", // Replace with your product ID
        Name:        "Basic Plan",
        Description: "Get access to basic features and support",
        Price:       9999, // in cents
        Features: []string{
            "Access to basic features",
            "Email support",
            "1 Team member",
            "Basic analytics",
        },
    },
    // ... add more products
}
```

</Step>

<Step title="Run the Development Server">

```bash
make run
```

أو يدويًا:

```bash
go run cmd/server/main.go
```

افتح [http://localhost:8000](http://localhost:8000) لعرض صفحة الأسعار!

<Check>
سترى صفحة أسعار ذات مظهر داكن، مع منتجاتك جاهزة للشراء.
</Check>
</Step>
</Steps>

## بنية المشروع

```text
go-boilerplate/
├── cmd/
│   └── server/             # Application entry point
├── internal/
│   ├── api/                # API handlers (Checkout, Portal, Webhook)
│   ├── core/               # Configuration and system core
│   └── lib/                # Shared logic (Products, Customer utils)
├── templates/              # HTML templates
├── Makefile                # Build and run commands
├── go.mod                  # Go module definition
├── go.sum                  # Dependency checksums
├── .env.example            # Environment template
└── README.md
```

## نقاط نهاية API

يتضمن القالب نقاط النهاية المُعدة مسبقًا التالية:

| نقطة النهاية | الطريقة | الوصف |
|----------|--------|-------------|
| `/` | GET | صفحة الأسعار مع قائمة المنتجات |
| `/api/checkout` | POST | إنشاء جلسة Checkout جديدة |
| `/api/webhook` | POST | معالجة Webhooks الخاصة بـ Dodo Payments |
| `/api/customer-portal` | POST | إنشاء عنوان URL لـ Customer Portal |

## التخصيص

### تحديث معلومات المنتج

عدّل `internal/lib/products.go` لتعديل:
- معرّفات المنتجات (من لوحة تحكم Dodo)
- الأسعار
- الميزات
- الأوصاف

```go
var Products = []Product{
    {
        ProductID:   "pdt_001", // Replace with your product ID
        Name:        "Basic Plan",
        Description: "Get access to basic features and support",
        Price:       9999,
        Features: []string{
            "Access to basic features",
            "Email support",
            "1 Team member",
            "Basic analytics",
        },
    },
}
```

### تعبئة بيانات العميل مسبقًا

في `templates/index.html`، استبدل بيانات العميل المضمّنة في الشيفرة ببيانات المستخدم الفعلية لديك:

```javascript
const customerData = {
    name: "John Doe",       // Replace with actual logged-in user's name
    email: "john@example.com"  // Replace with actual logged-in user's email
};
```

في تطبيق الإنتاج، يمكنك حقن هذه القيم ديناميكيًا من نظام المصادقة لديك.

## أحداث Webhook

يوضح القالب معالجة أحداث Webhook في `internal/api/webhook.go`. تشمل الأحداث المدعومة ما يلي:

| الحدث | الوصف |
|-------|-------------|
| `subscription.active` | يتم تشغيله عند تنشيط الاشتراك |
| `payment.succeeded` | يتم تشغيله عند نجاح الدفع |

أضف منطق عملك داخل معالج Webhook من أجل:
- تحديث أذونات المستخدمين في قاعدة بياناتك
- إرسال رسائل بريد إلكتروني للتأكيد
- توفير الوصول إلى المنتجات الرقمية
- تتبع التحليلات والمقاييس

## اختبار Webhooks محليًا

للتطوير المحلي، استخدم أدوات مثل [ngrok](https://ngrok.com/) لإتاحة خادمك المحلي عبر الإنترنت:

```bash
ngrok http 8000
```

حدّث عنوان URL الخاص بـ Webhook في [لوحة تحكم Dodo Payments](https://app.dodopayments.com/developer/webhooks):

```
https://your-ngrok-url.ngrok.io/api/webhook
```

## النشر

### البناء لبيئة الإنتاج

```bash
make build
```

أو يدويًا:

```bash
go build -o bin/server cmd/server/main.go
./bin/server
```

### النشر إلى Vercel

[

![النشر باستخدام Vercel](https://vercel.com/button)

](https://vercel.com/new/clone?repository-url=https://github.com/dodopayments/go-boilerplate)

### Docker

أنشئ ملف `Dockerfile`:

```dockerfile
FROM golang:1.21-alpine AS builder

WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN go build -o bin/server cmd/server/main.go

FROM alpine:latest
WORKDIR /app
COPY --from=builder /app/bin/server .
COPY --from=builder /app/templates ./templates

EXPOSE 8000
CMD ["./server"]
```

أنشئ وشغّل:

```bash
docker build -t go-dodo .
docker run -p 8000:8000 --env-file .env go-dodo
```

### اعتبارات الإنتاج

<Warning>
قبل النشر إلى بيئة الإنتاج:
- بدّل `DODO_PAYMENTS_ENVIRONMENT` إلى `live_mode`
- استخدم مفاتيح API الخاصة ببيئة الإنتاج من لوحة التحكم
- حدّث عنوان URL الخاص بـ Webhook إلى نطاق الإنتاج لديك
- فعّل HTTPS لجميع نقاط النهاية
</Warning>

## استكشاف الأخطاء وإصلاحها

<AccordionGroup>
<Accordion title="Build errors or missing dependencies">
تأكد من تنزيل وحدات Go بشكل صحيح:

```bash
go mod tidy
go mod download
```

</Accordion>

<Accordion title="Checkout session creation fails">
**الأسباب الشائعة:**
- معرّف منتج غير صالح - تحقق من وجوده في لوحة تحكم Dodo
- مفتاح API أو إعداد بيئة غير صحيح في `.env`
- راجع سجلات الخادم للاطلاع على رسائل الخطأ التفصيلية
</Accordion>

<Accordion title="Webhooks not receiving events">
للاختبار المحلي، استخدم [ngrok](https://ngrok.com) لإتاحة خادمك عبر الإنترنت:

```bash
ngrok http 8000
```

حدّث عنوان URL الخاص بـ Webhook في [لوحة تحكم Dodo](https://app.dodopayments.com/developer/webhooks) إلى عنوان URL الخاص بـ ngrok. احرص على تحديث ملف `.env` بمفتاح التحقق الصحيح الخاص بـ Webhook.
</Accordion>

<Accordion title="Templates not loading">
تأكد من تشغيل الخادم من الدليل الجذر للمشروع، أو من تهيئة مسار القوالب بشكل صحيح في شيفرتك.
</Accordion>
</AccordionGroup>
