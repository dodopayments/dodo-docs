## المتطلبات الأساسية

لدمج واجهة برمجة تطبيقات Dodo Payments، ستحتاج إلى:
- حساب تاجر على Dodo Payments
- بيانات اعتماد API (مفتاح API ومفتاح سر webhook) من لوحة التحكم

## إعداد لوحة التحكم

1. انتقل إلى [لوحة تحكم Dodo Payments](https://app.dodopayments.com/)

2. أنشئ منتجًا (دفعة لمرة واحدة أو اشتراك). يجب ألا يقل سعر منتجات الاشتراك عن **$1** (أو ما يعادله بالعملة التي اخترتها)؛ ولا تُدعم المبالغ الأقل من هذا الحد الأدنى.

4. أنشئ مفتاح API:
   - انتقل إلى Developer > API
   - [دليل تفصيلي](/api-reference/introduction#api-key-generation)
   - انسخ مفتاح API إلى البيئة المسماة DODO_PAYMENTS_API_KEY

5. اضبط webhooks:
   - انتقل إلى Developer > Webhooks
   - أنشئ عنوان URL لـ webhook لإشعارات الدفع
   - انسخ مفتاح webhook السري إلى البيئة 

## التكامل

### Payment Links

اختر مسار التكامل الذي يناسب حالة استخدامك:
- **Checkout Sessions (موصى به)**: الخيار الأفضل لمعظم عمليات التكامل. أنشئ جلسة على خادمك ثم أعد توجيه العملاء إلى صفحة دفع آمنة ومستضافة.
- **Overlay Checkout**: استخدمه عندما تحتاج إلى تجربة داخل الصفحة تفتح صفحة الدفع كتراكب modal على موقعك.
- **Inline Checkout**: ضمّن صفحة الدفع مباشرةً في تخطيط صفحتك للحصول على تجربة دفع متكاملة تحمل علامتك التجارية.
- **Static Payment Links**: عناوين URL قابلة للمشاركة فورًا ومن دون برمجة لجمع المدفوعات بسرعة.
- **Dynamic Payment Links**: روابط تُنشأ برمجيًا. ومع ذلك، يُوصى باستخدام Checkout Sessions لأنها توفر مرونة أكبر.

#### 1. Checkout Sessions

استخدم Checkout Sessions لإنشاء تجربة دفع آمنة ومستضافة للدفعات لمرة واحدة أو الاشتراكات. تنشئ جلسة على خادمك، ثم تعيد توجيه العميل إلى `checkout_url` المُعاد.

<Info>
تكون Checkout Sessions صالحة لمدة 24 ساعة افتراضيًا. إذا مررت <code>confirm=true</code>، فستكون الجلسات صالحة لمدة 15 دقيقة، ويجب توفير جميع الحقول المطلوبة.
</Info>

<Steps>
<Step title="Create a checkout session">
  اختر SDK المفضل لديك أو استدعِ REST API.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'prod_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python
  import os
  from dodopayments import DodoPayments

  client = DodoPayments(
      bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
      environment="test_mode",  # defaults to "live_mode"
  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "prod_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

  </Tab>

  <Tab title="REST API">

  ```javascript

    }),
  });
  const session = await response.json();
  ```

</Step>

<Step title="Redirect customer to checkout">
  بعد إنشاء الجلسة، أعد التوجيه إلى `checkout_url` لبدء التدفق المستضاف.


<Tip>
فضّل Checkout Sessions باعتبارها الطريقة الأسرع والأكثر موثوقية لبدء قبول المدفوعات. لمزيد من التخصيص المتقدم، راجع <a href="/developer-resources/checkout-session">دليل Checkout Sessions الكامل</a> و<a href="/api-reference/checkout-sessions/create">مرجع API</a>.
</Tip>

#### 2. Overlay Checkout

لتوفير تجربة دفع سلسة داخل الصفحة، استكشف تكامل [Overlay Checkout](/developer-resources/overlay-checkout) الذي يتيح للعملاء إكمال المدفوعات دون مغادرة موقعك الإلكتروني.

#### 3. Inline Checkout

لتوفير تجارب دفع متكاملة مضمّنة مباشرةً في صفحتك، استخدم تكامل [Inline Checkout](/developer-resources/inline-checkout). يتيح لك ذلك إنشاء ملخصات طلبات مخصصة والتحكم الكامل في تخطيط صفحة الدفع، بينما يتولى Dodo Payments جمع المدفوعات بأمان.

#### 4. Static Payment Links

تتيح لك روابط الدفع الثابتة قبول المدفوعات بسرعة من خلال مشاركة عنوان URL بسيط. يمكنك تخصيص تجربة الدفع عبر تمرير query parameters لملء بيانات العميل مسبقًا، والتحكم في حقول النموذج، وإضافة metadata مخصصة.

<Steps>
<Step title="Construct your payment link">
  ابدأ بعنوان URL الأساسي وأضف معرّف منتجك:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  أدرج query parameters الأساسية:
  - <ParamField query="quantity" type="integer" default="1">عدد العناصر المراد شراؤها.</ParamField>
  - <ParamField query="redirect_url" type="string" required>عنوان URL لإعادة التوجيه بعد إتمام الدفع.</ParamField>
  <Note>
  سيتضمن عنوان URL لإعادة التوجيه تفاصيل الدفع باعتبارها query parameters، مثل:<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  إذا كانت مفاتيح الترخيص مفعّلة للمنتج، فستتم أيضًا إضافة parameter باسم `license_key` (مفصولة بفواصل عند وجود عدة مفاتيح):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  أضف حقول العميل أو الفوترة باعتبارها query parameters لتبسيط عملية الدفع.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">الاسم الكامل للعميل (يُتجاهل إذا تم توفير firstName أو lastName).</ParamField>
      - <ParamField query="firstName" type="string">الاسم الأول للعميل.</ParamField>
      - <ParamField query="lastName" type="string">اسم العائلة للعميل.</ParamField>
      - <ParamField query="email" type="string">عنوان البريد الإلكتروني للعميل.</ParamField>
      - <ParamField query="country" type="string">بلد العميل.</ParamField>
      - <ParamField query="addressLine" type="string">عنوان الشارع.</ParamField>
      - <ParamField query="city" type="string">المدينة.</ParamField>
      - <ParamField query="state" type="string">الولاية أو المقاطعة.</ParamField>
      - <ParamField query="zipCode" type="string">الرمز البريدي/ZIP.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true أو false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  يمكنك تعطيل حقول محددة لجعلها للقراءة فقط بالنسبة إلى العميل. يفيد ذلك عندما تكون لديك تفاصيل العميل مسبقًا (مثل المستخدمين الذين سجّلوا الدخول).
  </Info>
  لتعطيل حقل، وفّر قيمته واضبط العلامة <code>disable...</code> المقابلة على <code>true</code>:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | الحقل         | علامة التعطيل         | Parameter المطلوب |
      |---------------|---------------------|-------------------|
      | الاسم الكامل     | `disableFullName`   | `fullName`        |
      | الاسم الأول    | `disableFirstName`  | `firstName`       |
      | اسم العائلة     | `disableLastName`   | `lastName`        |
      | البريد الإلكتروني         | `disableEmail`      | `email`           |
      | البلد       | `disableCountry`    | `country`         |
      | سطر العنوان  | `disableAddressLine`| `addressLine`     |
      | المدينة          | `disableCity`       | `city`            |
      | الولاية         | `disableState`      | `state`           |
      | الرمز البريدي      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  يساعد تعطيل الحقول على منع التغييرات غير المقصودة وضمان اتساق البيانات.
  </Tip>
  <Note>
  سيؤدي ضبط <code>showDiscounts=false</code> إلى تعطيل قسم الخصومات وإخفائه في نموذج الدفع. استخدم ذلك إذا كنت تريد منع العملاء من إدخال رموز القسائم أو الرموز الترويجية أثناء الدفع.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">يحدد عملة الدفع. تكون العملة الافتراضية هي عملة بلد الفوترة.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">إظهار محدد العملة أو إخفاؤه.</ParamField>
  - <ParamField query="paymentAmount" type="integer">المبلغ بالسنتات (لتسعير Pay What You Want فقط).</ParamField>
  - <ParamField query="metadata_*" type="string">حقول metadata مخصصة (مثل <code>metadata_orderId=123</code>).</ParamField>
</Step>
<Step title="Share the link">
  أرسل رابط الدفع المكتمل إلى عميلك. عند زيارته، يتم جمع جميع query parameters وتخزينها مع معرّف جلسة. ثم يُبسّط عنوان URL ليشمل parameter الجلسة فقط (مثل <code>?session=sess_1a2b3c4d</code>). تستمر المعلومات المخزنة عبر عمليات تحديث الصفحة، ويمكن الوصول إليها طوال عملية الدفع.
  <Check>
  أصبحت تجربة الدفع لدى العميل الآن مبسطة ومخصصة بناءً على parameters التي مررتها.
  </Check>
</Step>
</Steps>

#### 4. Dynamic Payment Links
<Tip>
فضّل Checkout Sessions لمعظم حالات الاستخدام، إذ توفر مرونة وتحكمًا أكبر.
</Tip>

يتم إنشاؤها عبر استدعاء API أو SDK الخاص بنا مع تفاصيل العميل. إليك مثال:

هناك واجهتا API لإنشاء Dynamic Payment Links:

- One-time Payment Link API [مرجع API](/api-reference/payments/post-payments)
- Subscription Payment Link API [مرجع API](/api-reference/subscriptions/post-subscriptions)

الدليل أدناه مخصص لإنشاء رابط دفع لمرة واحدة.

للحصول على تعليمات تفصيلية حول دمج الاشتراكات، راجع [دليل تكامل الاشتراكات](/developer-resources/subscription-integration-guide).

<Info>تأكد من تمرير `payment_link = true` للحصول على رابط الدفع </Info>

    ```javascript
export async function POST(request: NextRequest) {
  try {
    const body = await request.json();
    const { formData, cartItems } = paymentRequestSchema.parse(body);

    const response = await fetch(`${process.env.NEXT_PUBLIC_DODO_TEST_API}/payments`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${process.env.DODO_API_KEY}`, // Replace with your API secret key generated from the Dodo Payments Dashboard
      },
      body: JSON.stringify({
        billing: {
          city: formData.city,
          country: formData.country,
          state: formData.state,
          street: formData.addressLine,
          zipcode: parseInt(formData.zipCode),
        },
        customer: {
          email: formData.email,
          name: `${formData.firstName} ${formData.lastName}`,
          phone_number: formData.phoneNumber || undefined,
        },
        payment_link: true,
        product_cart: cartItems.map((id) => ({
          product_id: id,
          quantity: 1,
        })),
        return_url: process.env.NEXT_PUBLIC_RETURN_URL,
      }),
    });

    if (!response.ok) {
      const errorData = await response.json().catch(() => null);
      return NextResponse.json(
        { error: "Payment link creation failed", details: errorData },
        { status: response.status }
      );
    }

    const data = await response.json();
    return NextResponse.json({ paymentLink: data.payment_link });
  } catch (err) {
    console.error("Payment error:", err);
    return NextResponse.json(
      {
        error: err instanceof Error ? err.message : "An unknown error occurred",
      },
      { status: 500 }
    );
  }
}
```

### تنفيذ Webhooks

أنشئ نقطة نهاية API لاستقبال إشعارات الدفع. إليك مثال باستخدام Next.js:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

يتبع تنفيذ webhook لدينا مواصفات [Standard Webhooks](https://standardwebhooks.com/). للحصول على تعريفات أنواع webhook، راجع [دليل أحداث Webhook](/developer-resources/webhooks/intents/webhook-events-guide).

يمكنك الرجوع إلى هذا المشروع الذي يتضمن تنفيذًا تجريبيًا على [GitHub](https://github.com/dodopayments/dodo-checkout-demo) باستخدام Next.js وTypeScript.
