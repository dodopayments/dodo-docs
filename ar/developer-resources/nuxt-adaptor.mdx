## نظرة عامة

<Info>
يشرح هذا الدليل كيفية دمج Dodo Payments في تطبيق Nuxt لديك باستخدام وحدة Nuxt الرسمية. ستتعلّم كيفية إعداد مسارات API الخاصة بصفحة الدفع وبوابة العملاء وwebhooks، وكيفية إدارة متغيرات البيئة بأمان.
</Info>

## التثبيت

<Steps>
<Step title="Install the Nuxt module">
شغّل الأمر التالي في جذر مشروعك:

```bash
npm install @dodopayments/nuxt
```

</Step>
<Step title="Register the module in nuxt.config.ts">
أضف <code>@dodopayments/nuxt</code> إلى مصفوفة <code>modules</code> واضبط إعداداتها:

```typescript nuxt.config.ts expandable
export default defineNuxtConfig({
  modules: ["@dodopayments/nuxt"],
  devtools: { enabled: true },
  compatibilityDate: "2025-02-25",
  runtimeConfig: {
    private: {
      bearerToken: process.env.NUXT_PRIVATE_BEARER_TOKEN,
      webhookKey: process.env.NUXT_PRIVATE_WEBHOOK_KEY,
      environment: process.env.NUXT_PRIVATE_ENVIRONMENT,
      returnUrl: process.env.NUXT_PRIVATE_RETURNURL
    },
  }
});
```

</Step>
</Steps>

<Warning>
لا تلتزم بملف <code>.env</code> أو الأسرار في نظام التحكم بالإصدارات.
</Warning>

## معالج مسار الدفع

يدعم Dodo Payments ثلاثة أنواع من تدفقات الدفع لدمج المدفوعات في موقعك الإلكتروني، ويدعم هذا المحوّل جميع أنواع تدفقات الدفع.

- **روابط الدفع الثابتة:** عناوين URL قابلة للمشاركة فورًا لتحصيل المدفوعات بسرعة ومن دون كتابة تعليمات برمجية.
- **روابط الدفع الديناميكية:** أنشئ روابط دفع برمجيًا مع تفاصيل مخصصة باستخدام API أو SDKs.
- **جلسات الدفع:** أنشئ تجارب دفع آمنة وقابلة للتخصيص، مع سلال منتجات وتفاصيل عملاء مُعدّة مسبقًا.

## معالج مسار Webhook

- **الطريقة:** لا يُدعم سوى طلبات POST. وتُرجع الطرق الأخرى 405.
- **التحقق من التوقيع:** يتم التحقق من توقيع webhook باستخدام <code>webhookKey</code>. وتُرجع العملية 401 إذا فشل التحقق.
- **التحقق من الحمولة:** يتم التحقق منها باستخدام Zod. وتُرجع العملية 400 للحمولات غير الصالحة.
- **معالجة الأخطاء:**
  - 401: توقيع غير صالح
  - 400: حمولة غير صالحة
  - 500: خطأ داخلي أثناء التحقق
- **توجيه الأحداث:** يستدعي معالج الأحداث المناسب بناءً على نوع الحمولة.

// server/routes/api/webhook.post.ts

export default defineEventHandler((event) => {
  const {
    private: { webhookKey },
  } = useRuntimeConfig();

  const handler = Webhooks({
    webhookKey: webhookKey,
    onPayload: async (payload) => {
      // handle the payload
    },
    // ... other event handlers for granular control
  });

  return handler(event);
});

Handler Details:
- Method: Only POST requests are supported. Other methods return 405.
- Signature Verification: The handler verifies the webhook signature using webhookKey and returns 401 if verification fails.
- Payload Validation: The payload is validated with Zod. Returns 400 for invalid payloads.
