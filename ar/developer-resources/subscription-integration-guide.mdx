## المتطلبات الأساسية  

لدمج واجهة برمجة تطبيقات مدفوعات دودو، ستحتاج إلى:  
- حساب تاجر مدفوعات دودو  
- بيانات اعتماد واجهة برمجة التطبيقات (مفتاح API ومفتاح سرية webhook) من لوحة التحكم  

للحصول على دليل أكثر تفصيلاً حول المتطلبات الأساسية، تحقق من [هذا القسم](/developer-resources/integration-guide#dashboard-setup).  

## تكامل واجهة برمجة التطبيقات  

### جلسات الدفع  

استخدم جلسات الخروج لبيع منتجات الاشتراك من خلال عملية شراء آمنة ومُستضافة. قم بتمرير منتج الاشتراك الخاص بك في `product_cart` وقم بتحويل العملاء إلى `checkout_url` التي تم إرجاعها.

<Tip>
**الدفع المختلط**: يمكنك دمج منتجات الاشتراك مع المنتجات ذات الدفع لمرة واحدة في نفس جلسة الدفع. يتيح ذلك حالات استخدام مثل رسوم الإعداد مع الاشتراكات، وحزم الأجهزة مع SaaS، والمزيد. راجع [دليل جلسات الدفع](/developer-resources/checkout-session) للحصول على أمثلة.
</Tip>

import DodoPayments from 'dodopayments';

const client = new DodoPayments({

    product_cart: [
      { product_id: 'prod_subscription_monthly', quantity: 1 }

    customer: {

    },

  });

}

### الويب هوكس

عند دمج الاشتراكات، ستتلقى ويب هوكس لتتبع دورة حياة الاشتراك. تساعدك هذه الويب هوكس في إدارة حالات الاشتراك وسيناريوهات الدفع بشكل فعال.

لإعداد نقطة نهاية الويب هوك الخاصة بك، يرجى اتباع [دليل التكامل التفصيلي](/developer-resources/integration-guide#implementing-webhooks).

#### أنواع أحداث الاشتراك

تتبع أحداث الويب هوك التالية تغييرات حالة الاشتراك:

1. **`subscription.active`** - تم تفعيل الاشتراك بنجاح.
2. **`subscription.updated`** - تم تحديث كائن الاشتراك (يتم تفعيله عند تغيير أي حقل).
3. **`subscription.on_hold`** - تم تعليق الاشتراك بسبب فشل التجديد.
4. **`subscription.failed`** - فشل إنشاء الاشتراك أثناء إنشاء التفويض.
5. **`subscription.renewed`** - تم تجديد الاشتراك للفترة البنكية التالية.

لإدارة دورة حياة الاشتراك بشكل موثوق، نوصي بتتبع هذه الأحداث الخاصة بالاشتراك.

<Tip>
استخدم `subscription.updated` للحصول على إشعارات في الوقت الحقيقي حول أي تغييرات في الاشتراك، مما يحافظ على توافق حالة تطبيقك بدون الحاجة لاستدعاء API بشكل دوري.
</Tip>

#### سيناريوهات الدفع

**تدفق الدفع الناجح**

عندما ينجح الدفع، ستتلقى الويب هوكس التالية:

1. `subscription.active` - يشير إلى تفعيل الاشتراك
2. `payment.succeeded` - يؤكد الدفعة الأولية:
    - بالنسبة للمدفوعات الفورية (0 يوم تجريبي): توقع خلال 2-10 دقائق
    - بالنسبة للأيام التجريبية: متىما انتهت
3. `subscription.renewed` - يشير إلى خصم الدفعة وتجديد الدورة التالية. (بشكل أساسي، كلما تم خصم المدفوعات لمنتجات الاشتراك، ستحصل على إشعار `subscription.renewed` جنبًا إلى جنب مع `payment.succeeded`)

**سيناريوهات فشل الدفع**

1. فشل الاشتراك
  - `subscription.failed` - فشل إنشاء الاشتراك بسبب الفشل في إنشاء تفويض.
  - `payment.failed` - يشير إلى فشل في الدفع.

2. الاشتراك مُعلق
  - `subscription.on_hold` - تم تعليق الاشتراك بسبب فشل دفع التجديد أو رسوم تغيير الخطة.
  - عندما يكون الاشتراك مُعلقًا، فلن يتم تجديده تلقائيًا حتى يتم تحديث وسيلة الدفع.

<Info>**أفضل ممارسة**: لتبسيط التنفيذ، نوصي بتتبع أحداث الاشتراك بشكل أساسي لإدارة دورة حياة الاشتراك.</Info>

### التعامل مع الاشتراك المعلق

عندما يدخل الاشتراك في حالة `on_hold`، تحتاج إلى تحديث وسيلة الدفع لإعادة تنشيطه. يوضح هذا القسم متى يتم تعليق الاشتراكات وكيفية التعامل معها.

#### متى يتم تعليق الاشتراكات

يتم تعليق الاشتراك عندما:

- **يفشل دفع التجديد**: تفشل رسوم التجديد التلقائية بسبب عدم كفاية الأموال، أو انتهاء صلاحية البطاقة، أو رفض البنك
- **يفشل رسوم تغيير الخطة**: تفشل الرسوم الفورية أثناء ترقية/تخفيض الخطة
- **يفشل تفويض طريقة الدفع**: لا يمكن تفويض طريقة الدفع للرسوم المتكررة

<Warning>
لا تجدد الاشتراكات في حالة `on_hold` تلقائيًا. يجب عليك تحديث وسيلة الدفع لإعادة تفعيل الاشتراك.
</Warning>

#### إعادة تفعيل الاشتراكات من حالة المعلق

لإعادة تنشيط اشتراك من حالة `on_hold`، استخدم واجهة برمجة تطبيقات تحديث وسيلة الدفع. هذا يقوم تلقائيًا بما يلي:

1. إنشاء رسم للديون المتبقية
2. إنشاء فاتورة للرسم
3. معالجة الدفع باستخدام وسيلة الدفع الجديدة
4. إعادة تنشيط الاشتراك إلى حالة `active` عند الدفع الناجح

<Steps>
<Step title="تعامل مع Webhook الاشتراك.on_hold">
عند تلقيك لـ `subscription.on_hold` Webhook، قم بتحديث حالة تطبيقك وأبلغ العميل:

```javascript
// Webhook handler
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;
  
  if (event.type === 'subscription.on_hold') {
    const subscription = event.data;
    
    // Update subscription status in your database
    await updateSubscriptionStatus(subscription.subscription_id, 'on_hold');
    
    // Notify customer to update payment method
    await sendEmailToCustomer(subscription.customer_id, {
      subject: 'Payment Required - Subscription On Hold',
      message: 'Your subscription is on hold. Please update your payment method to continue service.'
    });
  }
  
  res.json({ received: true });
});
```

</Step>

<Step title="تحديث طريقة الدفع">
عندما يكون العميل جاهزًا لتحديث طريقة الدفع الخاصة به، اتصل بواجهة برمجة التطبيقات لتحديث طريقة الدفع:

<CodeGroup>

```javascript Node.js
// Update with new payment method
const response = await client.subscriptions.updatePaymentMethod(subscriptionId, {
  type: 'new',
  return_url: 'https://example.com/return'
});

// For on_hold subscriptions, a charge is automatically created
if (response.payment_id) {
  console.log('Charge created for remaining dues:', response.payment_id);
  // Redirect customer to response.payment_link to complete payment
}
```

```python Python
# Update with new payment method
response = client.subscriptions.update_payment_method(
    subscription_id=subscription_id,
    type="new",
    return_url="https://example.com/return"
)

# For on_hold subscriptions, a charge is automatically created
if response.payment_id:
    print("Charge created for remaining dues:", response.payment_id)
    # Redirect customer to response.payment_link to complete payment
```

</CodeGroup>

<Info>
يمكنك أيضًا استخدام معرف طريقة الدفع الموجودة إذا كان لدى العميل طرق دفع محفوظة:

```javascript
await client.subscriptions.updatePaymentMethod(subscriptionId, {
  type: 'existing',
  payment_method_id: 'pm_abc123'
});
```

</Info>
</Step>

<Step title="مراقبة أحداث الويب هوك">
بعد تحديث طريقة الدفع، راقب هذه أحداث الويب هوك:

1. **`payment.succeeded`** - كانت الدفعة للديون المتبقية ناجحة
2. **`subscription.active`** - تمت إعادة تفعيل الاشتراك

```javascript
if (event.type === 'payment.succeeded') {
  const payment = event.data;
  
  // Check if this payment is for an on_hold subscription
  if (payment.subscription_id) {
    // Wait for subscription.active webhook to confirm reactivation
  }
}

if (event.type === 'subscription.active') {
  const subscription = event.data;
  
  // Update subscription status in your database
  await updateSubscriptionStatus(subscription.subscription_id, 'active');
  
  // Restore customer access
  await restoreCustomerAccess(subscription.customer_id);
  
  // Notify customer of successful reactivation
  await sendEmailToCustomer(subscription.customer_id, {
    subject: 'Subscription Reactivated',
    message: 'Your subscription has been reactivated successfully.'
  });
}
```

</Step>
</Steps>

## تغيير خطط الاشتراك

يمكنك ترقية أو تخفيض خطة الاشتراك باستخدام نقطة نهاية واجهة برمجة التطبيقات لتغيير الخطة. يتيح لك ذلك تعديل منتج الاشتراك، والكمية، والتعامل مع النسبة المئوية.

<Card title="مرجع واجهة برمجة التطبيقات لتغيير الخطة" icon="arrows-rotate" href="/api-reference/subscriptions/change-plan">
  لمزيد من المعلومات التفصيلية حول تغيير خطط الاشتراك، يرجى الرجوع إلى وثائق واجهة برمجة التطبيقات لتغيير الخطة.
</Card>

### خيارات النسبة المئوية

عند تغيير خطط الاشتراك، لديك خياران للتعامل مع الرسوم الفورية:

#### 1. `prorated_immediately`
- يحسب المبلغ النسبي بناءً على الوقت المتبقي في دورة الفواتير الحالية
- يقوم بخصم الفرق فقط بين الخطة القديمة والجديدة من العميل
- خلال فترة التجربة، سيتم تحويل المستخدم إلى الخطة الجديدة على الفور، وتحصيل المبلغ من العميل على الفور

#### 2. `full_immediately`
- يقوم بخصم المبلغ الكامل للاشتراك للخطة الجديدة من العميل
- يتجاهل أي وقت متبقي أو أرصدة من الخطة السابقة
- مفيد عندما تريد إعادة تعيين دورة الفواتير أو خصم المبلغ الكامل بغض النظر عن النسبي

#### 3. `difference_immediately`
- عند الترقية، يتم خصم الفرق بين مبلغ الخطتين من العميل مباشرة.
- على سبيل المثال، إذا كانت الخطة الحالية تبلغ 30 دولارًا وارتقى العميل إلى 80 دولارًا، يتم خصم 50 دولارًا على الفور.
- عند التخفيض، يتم إضافة المبلغ غير المستخدم من الخطة الحالية كرصيد داخلي ويتم استخدامه تلقائيًا في تجديد الاشتراكات المستقبلية.
- على سبيل المثال، إذا كانت الخطة الحالية تبلغ 50 دولارًا وقام العميل بالتبديل إلى خطة بقيمة 20 دولارًا، يتم ائتمان 30 دولارًا وتستخدم للدورة الفوترة التالية.

### السلوك

- عند استدعاء هذه الواجهة البرمجية، يبدأ Dodo Payments مباشرة في خصم بناءً على خيار النسبية الذي اخترته.
- إذا كانت تغيير الخطة تخفيضًا وتستخدم `prorated_immediately`، سيتم حساب الأرصدة تلقائيًا وإضافتها إلى رصيد الاشتراك. هذه الأرصدة مخصصة لذلك الاشتراك فقط وستستخدم فقط لتعويض المدفوعات المتكررة المستقبلية لنفس الاشتراك.
- خيار `full_immediately` يتجاوز حسابات الائتمان ويخصم المبلغ الكامل للخطة الجديدة.

<Tip>
**اختر خيار النسبية بعناية**: استخدم `prorated_immediately` للفوترة العادلة التي تأخذ في الاعتبار الوقت غير المستخدم، أو `full_immediately` عندما ترغب في خصم المبلغ الكامل للخطة الجديدة بغض النظر عن دورة الفواتير الحالية.
</Tip>

### معالجة الرسوم

- عادةً ما تكتمل معالجة الرسوم الفورية التي تبدأ عند تغيير الخطة في أقل من دقيقتين
- إذا فشلت هذه الرسوم الفورية لأي سبب، يتم تلقائيًا وضع الاشتراك في حالة تعليق حتى يتم حل المشكلة

## الاشتراكات عند الطلب

<Info>
  تتيح لك الاشتراكات عند الطلب فرض رسوم على العملاء بمرونة، وليس فقط وفق جدول زمني ثابت. هذه الميزة متاحة لجميع الحسابات.
</Info>

**لإنشاء اشتراك عند الطلب:**

لإنشاء اشتراك عند الطلب، استخدم واجهة برمجة التطبيقات [POST /subscriptions](/api-reference/subscriptions/post-subscriptions) وأدرج حقل `on_demand` في نص طلبك. يتيح لك ذلك تفويض وسيلة الدفع دون خصم فوري، أو تعيين سعر أولي مخصص.

**لتحصيل رسوم اشتراك عند الطلب:**

لتحصيل الرسوم اللاحقة، استخدم نقطة النهاية [POST /subscriptions/charge](/api-reference/subscriptions/create-charge) وحدد المبلغ الذي سيتم فرضه على العميل لتلك المعاملة.

<Note>
للحصول على دليل كامل خطوة بخطوة—بما في ذلك أمثلة الطلب/الاستجابة، وسياسات إعادة المحاولة الآمنة، والتعامل مع الويب هوكس—راجع <a href="/developer-resources/ondemand-subscriptions">دليل الاشتراكات عند الطلب</a>.
</Note>
