يعمل مكون دودة الربط على توصيل خادمَي MCP وثماني مهارات تكامل في وكيل الترميز بالذكاء الاصطناعي الخاص بك في عملية تثبيت واحدة. يعمل مع **Claude Code** و**Codex CLI** و**Cursor** و**OpenCode** — وتعمل خوادم MCP وواجهة الأوامر CLI للمهارات مع أي عميل متوافق مع MCP.

/* LOCKED_PATTERN_6fa96040307d68e9fa44436559d63ee8 */
**ثلاث أساسيات، مكوّن واحد.** يجمع مكون الوكيل كل ما تحتاجه:
 - **خادم API MCP** — الوصول المباشر إلى المدفوعات، الاشتراكات، العملاء، المنتجات، الاستردادات، التراخيص، والاستخدام. يتحقق عبر OAuth المتصفح (لا حاجة لمفاتيح محلية).
 - **خادم المعرفة MCP** — البحث الدلالي عبر جميع وثائق Dodo Payments. لا حاجة إلى بيانات اعتماد.
 - **ثماني مهارات وكيل** — أوراق الغش التي يقوم وكيلك بتحميلها عند الطلب للخروج، الاشتراكات، webhooks، الفوترة المعتمدة على الاستخدام، الفوترة المعتمدة على الرصيد، مفاتيح الترخيص، BillingSDK، وأفضل الممارسات.

## ما تحصل عليه

بمجرد تثبيت المكون، يكون لدى وكيلك وصول إلى خادمي MCP وثماني مهارات.

### خوادم MCP

| الخادم | الغرض | التوثيق |
|--------|---------|------|
| `dodopayments-api` | الوصول المباشر إلى API — المدفوعات، الاشتراكات، العملاء، المنتجات، الاستردادات، التراخيص، الاستخدام | OAuth (المتصفح) |
| `dodo-knowledge` | البحث الدلالي عبر جميع وثائق Dodo Payments | لا شيء |

يتم توصيل كلا الخادمين عبر `mcp-remote` بحيث يمكن تشغيلهما في أي عميل متوافق مع MCP.

### مهارات الوكيل

| المهارة | الوصف |
|-------|-------------|
| `best-practices` | دليل شامل لتكامل Dodo Payments مع أفضل الممارسات |
| `checkout-integration` | إنشاء جلسات الخروج وتدفقات الدفع |
| `subscription-integration` | تنفيذ تدفقات فوترة الاشتراكات |
| `webhook-integration` | إعداد ومعالجة webhooks لأحداث الدفع |
| `usage-based-billing` | تنفيذ الفوترة باستخدام الأحداث والعدادات |
| `credit-based-billing` | استحقاقات الرصيد، الأرصدة، وخصم الائتمان مُقاسًا |
| `license-keys` | إدارة مفاتيح الترخيص للمنتجات الرقمية |
| `billing-sdk` | استخدام مكونات BillingSDK React |

تتحمل المهارات تلقائيًا — يختار وكيلك المهارة الصحيحة عندما يكتشف مهمة ذات صلة. راجع [وثائق مهارات الوكيل](/developer-resources/agent-skills) للحصول على القائمة الكاملة والتثبيت الفردي.

### جرب هذا الموجه أولاً

بمجرد تنشيط المكون، جرب:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

سيقوم وكيلك بتحميل مهارة `webhook-integration`، استخدام MCP لتنزيل أحدث أشكال الحمولة، وكتابة معالج مع التحقق من التوقيع وفقًا لمواصفات Standard Webhooks.

## وثائق مبنية للوكلاء

كل صفحة من صفحات وثائق Dodo Payments متاحة بتنسيق مُحسَّن لاستهلاك الذكاء الصناعي:

- **كامل فهرس الوثائق**: [`docs.dodopayments.com/llms.txt`](https://docs.dodopayments.com/llms.txt) — يخدم فهرس الوثائق الكامل لابتلاع السياق.
- **تنسيق markdown الخام**: أضف `.md` لأي عنوان URL للوثائق للحصول على نسخة markdown الخام (مثل، `/api-reference/introduction.md`).
- **المستودع المصدر**: [`github.com/dodopayments/dodo-docs`](https://github.com/dodopayments/dodo-docs) — نسخ للتحميل دون اتصال.

## ما يمكن لوكيلك القيام به

مع تثبيت المكون، يمكن لوكيل الترميز الخاص بك:

- **إنشاء جلسات الدفع وروابط الدفع** — [الدفعات لمرة واحدة](/features/one-time-payment-products) و[الاشتراكات](/features/subscription)
- **تكوين الفوترة المعتمدة على الاشتراك والاستخدام بالكامل** — [الاشتراكات](/features/subscription)، [الفوترة المعتمدة على الاستخدام](/features/usage-based-billing)، [الفوترة المعتمدة على الرصيد](/features/credit-based-billing)
- **تكوين معالجة متوافقة مع Standard Webhooks لتحديد التوقيع** — [Webhooks](/developer-resources/webhooks)
- **توصيل مكونات BillingSDK React** لجدول الأسعار وإدارة الاشتراك — [BillingSDK](/developer-resources/billingsdk)
- **كتابة تدفقات مفاتيح الترخيص** للمنتجات الرقمية — [مفاتيح الترخيص](/features/license-keys)
- **تنفيذ الفوترة المعتمدة على الرصيد** من خلال الاستحقاقات، الأرصدة، والانتقال والشحن الزائد — [الائتمانات](/features/credit-based-billing)

## الأمان وأفضل الممارسات

/* LOCKED_PATTERN_4907e9f6f7fbd509120d7a87afc829e9 */
**لا تقم أبدًا بوضع مفاتيح API الخاصة بالإنتاج.** استخدم [وضع الاختبار](/miscellaneous/test-mode-vs-live-mode) أثناء التطوير. يستخدم مكون الوكيل بشكل افتراضي OAuth المتصفح — قم بالتبديل فقط إلى مفاتيح API المحلية إذا تطلبت سير العمل لديك ذلك.
/* LOCKED_PATTERN_176d815432e7554ac558e8631b2bc397 */

- **استخدم وضع الاختبار أولاً.** قلل من تكاملاتك باستخدام مفاتيح `dodo_test_...` قبل التفعيل. راجع [وضع الاختبار مقابل الوضع المباشر](/miscellaneous/test-mode-vs-live-mode).
- **OAuth هو الافتراضي.** يتحقق مكون الوكيل عبر OAuth المتصفح (لا أسرار محلية). استخدم وضع API-key فقط إذا احتجت لذلك — راجع قسم الإعدادات أدناه.
- **راجع الكود الذي يولده الوكيل.** تحقق دائمًا من أن عملية معالجة webhooks تتضمن التحقق من التوقيع وفقًا لـ [مواصفات Standard Webhooks](https://standardwebhooks.com/).

## التكوين باستخدام مفتاح API

بشكل افتراضي، يستخدم مكون الوكيل الخادم MCP البعيد مع OAuth المتصفح — لا حاجة إلى بيانات اعتماد محلية. إذا كان سير العمل لديك يتطلب مفتاح API محلي (مثل بيئات CI، الخوادم غير الرئيسية)، يمكنك التحول إلى وضع stdio.

/* LOCKED_PATTERN_3a00efd457b01f610250031fcbf16962 */
/* LOCKED_PATTERN_f22e427153b199e505630b6831e2b3fb */
افتح `/plugins` في Claude Code، حدد **Dodo Payments**، واختر **تكوين الخيارات**. املأ:

- `dodo_api_key` — المفتاح الخاص بك `dodo_test_...` أو `dodo_live_...`
- `dodo_webhook_key` — سر توقيع webhook الخاص بك
- `dodo_environment` — `test_mode` أو `live_mode`

ثم قم بتحرير `.mcp.json` لتوجيه `dodopayments-api` إلى الخادم المحلي stdio:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

قم بتشغيل `/reload-plugins` لتطبيق التغييرات على جلستك الحالية.
