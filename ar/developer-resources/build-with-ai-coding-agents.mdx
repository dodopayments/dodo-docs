يربط Dodo Agent Plugin خادمي MCP وسبع عشرة مهارة تكامل بوكيل البرمجة بالذكاء الاصطناعي لديك في عملية تثبيت واحدة. وهو يعمل مع **Claude Code** و**Codex CLI** و**Cursor** و**VS Code / GitHub Copilot** و**Kiro** و**OpenCode**. يحصل **Gemini CLI** على خادمي MCP فقط. تعمل خوادم MCP وواجهة CLI الخاصة بالمهارات مع أي عميل متوافق مع MCP.

يتبع المكوّن الإضافي مواصفة [Agent Plugins 1.0.0](https://agent-plugins.org/specification)، لذلك تحمّله العملاء الذين يدعمونه أصلاً مباشرةً من الجذر `plugin.json` و`mcp.json`. أما العملاء الأقدم من المواصفة، فيحمّلون المحتوى نفسه عبر ملفات توافق تم إنشاؤها تلقائياً.

<Info>
**ثلاثة عناصر أساسية، ومكوّن إضافي واحد.** يجمع Agent Plugin كل ما تحتاج إليه:
- **خادم API MCP** — وصول مباشر إلى المدفوعات والاشتراكات والعملاء والمنتجات والمبالغ المستردة والتراخيص والاستخدام. تتم المصادقة عبر OAuth في المتصفح (ولا حاجة إلى مفاتيح محلية).
- **خادم Knowledge MCP** — بحث دلالي عبر وثائق Dodo Payments كاملةً. لا يحتاج إلى بيانات اعتماد.
- **سبع عشرة مهارة للوكيل** — أوراق مرجعية مختصرة يحمّلها وكيلك عند الطلب للدفع والاشتراكات وwebhooks والفوترة القائمة على الاستخدام والائتمانات ومفاتيح التراخيص وكتالوج المنتجات والخصومات والتسعير المحلي والدفع عبر الأجهزة المحمولة والمبالغ المستردة والنزاعات وإدارة العملاء ومحوّلات الأطر وBillingSDK وBetter Auth والاختبار والإطلاق وأفضل الممارسات.
</Info>

## تثبيت المكوّن الإضافي

اختر وكيل البرمجة أدناه. يضيف كل تثبيت خادمي MCP؛ كما يضيف سبع عشرة مهارة في جميع الحالات باستثناء Gemini CLI.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
ثبّته من marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

يستخدم خادم API MCP المصادقة عبر OAuth في المتصفح افتراضياً — ولا حاجة إلى مفاتيح وقت التثبيت. في المرة الأولى التي يستدعي فيها وكيلك أداة من Dodo، سيُطلب منك تسجيل الدخول.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  الشيفرة المصدرية وخيارات الإعدادات وتعليمات التطوير المحلي
</Card>
</Accordion>

<Accordion title="Codex CLI">
يثبّت Codex المكوّنات الإضافية على خطوتين: سجّل marketplace من shell، ثم ثبّت المكوّن الإضافي من داخل Codex TUI.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
افتح Codex ونفّذ أمر slash `/plugins`:

```bash
codex
```

ثم اكتب `/plugins`، وانتقل إلى marketplace الخاص بـ **Dodo Payments**، وحدد المكوّن الإضافي **dodopayments**، ثم اختر **Install plugin**.
</Step>
</Steps>

يُسجَّل خادما MCP وجميع المهارات السبع عشرة تلقائياً بعد تثبيت المكوّن الإضافي.

<Note>
لا يحتوي Codex CLI على أمر فرعي `codex plugin install` — لذلك يتم تثبيت المكوّن الإضافي دائماً من خلال تدفق `/plugins` داخل TUI. راجع [وثائق Codex الرسمية للمكوّنات الإضافية](https://developers.openai.com/codex/plugins).
</Note>

إذا أضفت marketplace والمكوّن الإضافي سابقاً ولم يظهر ضمن `/plugins`، فحدّثه:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
التثبيت اليدوي — استنسخ المستودع إلى مجلد المكوّنات الإضافية المحلي في Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

أعد تشغيل Cursor. يحمّل المكوّن الإضافي المهارات من `skills/` وخوادم MCP من `.mcp.json`، وفقاً لما هو مُعلن في `.cursor-plugin/plugin.json`.

<Info>
تتعرف إصدارات Cursor الحديثة أيضاً على Agent Plugins 1.0.0 مباشرةً، وتقبل `.cursor-plugin/marketplace.json` أو `.claude-plugin/marketplace.json` كمصدر marketplace. يوفّر هذا المكوّن الإضافي `.claude-plugin/marketplace.json` — استخدم هذا المسار. ويُحتفظ بالملف المُنشأ `.cursor-plugin/plugin.json` للإصدارات الأقدم.
</Info>

<Warning>
كانت الإصدارات السابقة لـ 0.5.0 توفّر `skills/` كروابط رمزية إلى وحدة git فرعية، لذلك كان هذا الاستنساخ ينتج مكوّناً إضافياً **من دون مهارات عاملة**. تُوفَّر المهارات الآن كملفات فعلية. إذا ثبّت إصداراً أقدم، فاحذف المجلد وأعد الاستنساخ.
</Warning>
</Accordion>

<Accordion title="OpenCode">
يوزّع OpenCode المكوّن الإضافي عبر npm. أضف المكوّن الإضافي إلى `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

أعد تشغيل OpenCode. يُسجَّل خادما MCP (`dodopayments-api` و`dodo-knowledge`) تلقائياً عبر hook إعدادات المكوّن الإضافي. لا حاجة إلى كتلة `mcp` يدوية.

**تحتاج المهارات إلى سطر إضافي واحد.** لا يفحص OpenCode الحزم المثبتة بحثاً عن المهارات، لذا وجّهه يدوياً إلى مجلد `skills/` الخاص بالحزمة:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

تُحلّ إدخالات `skills.paths` النسبية بالنسبة إلى **مجلد المشروع**، لذلك يجب أن تكون الحزمة موجودة في `node_modules` الخاص بذلك المشروع — إذ إن ذاكرة التخزين المؤقت للمكوّنات الإضافية في OpenCode تقع في مكان مختلف. يعمل المسار المطلق أيضاً، ويتجنب متطلب التثبيت المحلي.

<Warning>
يُتجاهل مسار المهارات غير الموجود **بصمت**. تحقّق بدلاً من الافتراض:

```bash
opencode run "List every skill available to you by name."
```

ينبغي أن ترى المهارات السبع عشرة جميعها. كانت الإصدارات السابقة لـ 0.5.0 توثّق هذه المهارات على أنها تُكتشف تلقائياً — لكنها لم تكن كذلك، لذا كان مستخدمو OpenCode يحصلون على خوادم MCP من دون مهارات.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
استنسخ المستودع إلى أي مكان، ثم سجّله:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

افتح عرض Chat، وانتقل إلى **Plugins**، وأضف المجلد المستنسخ. يمكنك أيضاً تسجيله مباشرةً في `settings.json`:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

المفتاح هو مسار، والقيمة تفعّله. تعمل المسارات المطلقة و`~/` أيضاً؛ ويُحلّ المسار النسبي بالنسبة إلى كل مجلد مساحة عمل. يُقرأ الإعداد مباشرةً، لذا تلتقطه النافذة قيد التشغيل من دون إعادة تشغيل. تُحمّل المهارات من `skills/`، ويُحمّل خادما MCP من `.mcp.json`.

<Note>
تم وضع علامة **تجريبية** على `chat.pluginLocations`، وهو إعداد *مقيّد*، لذلك يجب الوثوق بمساحة العمل حتى يُطبَّق. ويُعد دعم agent-plugin عموماً ميزة معاينة تتحكم فيها `chat.plugins.enabled`، وهي **مفعّلة افتراضياً** — ولا تحتاج إلى ضبطها إلا إذا عطلتها مؤسستك وفقاً للسياسة.
</Note>

<Info>
لا يعتمد VS Code على `$schema` الخاص بـ Agent Plugins. يبحث محمّله في `.plugin/plugin.json`، ثم `.claude-plugin/plugin.json`، ثم في `plugin.json` الجذري، ويضبط MCP افتراضياً على `.mcp.json` بدلاً من `mcp.json`. ولأن هذا المستودع يوفّر `.claude-plugin/plugin.json` مُنشأً، يحمّله VS Code عبر فرع التوافق هذا ويحصل على جسر `mcp-remote` بدلاً من وسائل النقل الأصلية في `mcp.json`. كل شيء يعمل — لكن المسار مختلف.
</Info>
</Accordion>

<Accordion title="Kiro">
يقرأ Kiro بيان Agent Plugins بشكل أصلي ويحمّله باعتباره Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
في Kiro، افتح لوحة Powers — أيقونة Ghosty التي تحمل صاعقة.
</Step>

<Step title="Import the folder">
اختر **Add Custom Power → Import power from a folder**، وحدد المجلد المستنسخ (الذي يحتوي على `plugin.json`)، ثم انقر **Install**.
</Step>
</Steps>

تُحمّل المهارات من `skills/`، وخوادم MCP من `mcp.json`، بينما يأتي العرض الخاص بـ Kiro من مساحة أسماء الامتداد `dev.kiro` في `plugin.json`.

<Note>
بالنسبة إلى المكوّنات الإضافية بتنسيق Agent Plugins، يدير Kiro خوادم MCP داخلياً — ولا تُكتب في `~/.kiro/settings/mcp.json` على مستوى المستخدم، لذلك لا تتوقع العثور عليها هناك. يمكن لـ Kiro أيضاً تثبيت Power مباشرةً من عنوان URL في GitHub؛ راجع [وثائق تثبيت Kiro](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
لا يحتوي Gemini CLI على primitive للمهارات، لذا **يتوفر خادما MCP فقط** — ولا تتوفر المهارات السبع عشرة. يغطي `dodo-knowledge` مع ذلك جزءاً كبيراً مما توفره المهارات، ويظل محدثاً تلقائياً.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

أعد تشغيل Gemini CLI. يُعد `gemini-extension.json` في جذر المستودع هو البيان.
</Accordion>
</AccordionGroup>

<Info>
هل تستخدم وكيلاً مختلفاً؟ يغطي دليلا [MCP Server](/developer-resources/mcp-server) و[Agent Skills](/developer-resources/agent-skills) Claude Desktop وWindsurf وCline وZed وأي عميل متوافق مع MCP.
</Info>

## ما تحصل عليه

بعد تثبيت المكوّن الإضافي، يتمتع وكيلك بإمكانية الوصول إلى خادمي MCP وسبع عشرة مهارة.

### خوادم MCP

| الخادم | الغرض | المصادقة |
|--------|---------|------|
| `dodopayments-api` | وصول مباشر إلى API — المدفوعات والاشتراكات والعملاء والمنتجات والمبالغ المستردة والتراخيص والاستخدام | OAuth (المتصفح) |
| `dodo-knowledge` | بحث دلالي عبر وثائق Dodo Payments كاملةً | لا شيء |

يتحدث الخادمان عبر Streamable HTTP. يعلن `mcp.json` الأساسي عنهما بشكل أصلي (`type: "streamable-http"`)، وهذا ما تستخدمه العملاء التي تدعم المواصفة أصلاً مثل Codex CLI وKiro. أما بيان التوافق المُنشأ `.mcp.json`، فيربط نقطتي النهاية نفسيهما عبر `mcp-remote` بدلاً من ذلك، ولذلك يعملان أيضاً مع العملاء التي لا تستطيع الاتصال بـ Streamable HTTP مباشرةً — مثل Claude Code وVS Code وCursor عبر تثبيت استنساخ git الموثق أعلاه، حيث يشير `.cursor-plugin/plugin.json` إلى `.mcp.json`.

### مهارات الوكيل

| المهارة | الوصف |
|-------|-------------|
| `dodo-best-practices` | إعداد SDK والبيئات ومفاتيح API وبنية checkout-to-webhook الأساسية |
| `framework-adapters` | معالجات مسارات `@dodopayments/*` الرسمية لـ Next.js وExpress وHono وAstro وRemix وSvelteKit وNuxt وFastify وTanStack وBun وConvex |
| `testing-and-go-live` | وضع الاختبار وطرق الدفع الاختبارية واختبار webhook وقائمة التحقق من الإطلاق إلى الإنتاج |
| `checkout-integration` | Checkout Sessions وروابط الدفع وcheckout المتراكب أو المضمّن |
| `subscription-integration` | دورة حياة الاشتراك والتجارب وتغييرات الخطط والتوزيع النسبي والرسوم عند الطلب |
| `mobile-checkout` | checkout داخل التطبيق لـ React Native وFlutter وiOS وAndroid |
| `webhook-integration` | استقبال webhooks والتحقق منها باستخدام مواصفة Standard Webhooks |
| `credit-based-billing` | استحقاقات الائتمان والأرصدة ودفتر الأستاذ والترحيل والتجاوز والخصم القائم على العداد |
| `usage-based-billing` | العدادات واستيعاب الأحداث وتجميعها والتسعير لكل وحدة |
| `license-keys` | تفعيل مفتاح الترخيص والتحقق منه وإدارة المثيلات |
| `product-catalog-management` | المنتجات والتسعير والإضافات والمجموعات والصور وتسليم المنتجات الرقمية |
| `discounts-and-promotions` | رموز الخصم وقواعد الأهلية والتكديس وحدود دورة الاشتراك |
| `localized-pricing` | التسعير المحلي وAdaptive Currency وتكافؤ القوة الشرائية |
| `customer-management` | العملاء والبوابة ذاتية الخدمة وطرق الدفع المحفوظة والمحافظ |
| `refunds-and-disputes` | إصدار المبالغ المستردة ومعالجة النزاعات وchargebacks وتسوية الوصول |
| `billing-sdk` | مكوّنات BillingSDK React لجداول التسعير وواجهة الفوترة |
| `better-auth-integration` | المكوّن الإضافي `@dodopayments/better-auth` لمزامنة العملاء وcheckout والوصول إلى Customer Portal |

تُحمّل المهارات تلقائياً — يختار وكيلك المهارة المناسبة عند اكتشاف مهمة ذات صلة. راجع [وثائق Agent Skills](/developer-resources/agent-skills) للقائمة الكاملة وتعليمات التثبيت الفردية.

### جرّب هذا الطلب أولاً

بعد تفعيل المكوّن الإضافي، جرّب ما يلي:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

سيحمّل وكيلك مهارة `webhook-integration`، ويستخدم MCP `dodo-knowledge` لجلب أحدث أشكال payload، ثم يكتب معالجاً مع التحقق من التوقيع وفقاً لمواصفة Standard Webhooks.

## دعم العملاء

### العملاء الذين يدعمون تثبيت Agent Plugin

يربط تثبيت واحد خادمي MCP، إضافةً إلى المهارات في كل عميل يملك primitive للمهارات.

| الوكيل | التثبيت | المهارات | خوادم MCP |
|-------|---------|-------:|------------:|
| **Claude Code** | أمر marketplace | 17 | 2 |
| **Codex CLI** | أمر marketplace | 17 | 2 |
| **Cursor** | استنساخ git | 17 | 2 |
| **VS Code / GitHub Copilot** | استنساخ git | 17 | 2 |
| **Kiro** | استنساخ git | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | استنساخ git | 0 | 2 |

- يحتاج **OpenCode** إلى إدخال `skills.paths` إضافي واحد قبل تحميل مهاراته السبع عشرة — راجع قسم التثبيت أعلاه.
- لا يملك **Gemini CLI** primitive لمهارات الوكيل، لذا لا تتوفر المهارات فيه حسب التصميم.

### عملاء آخرون متوافقون مع MCP

لا يملكون تثبيت Agent Plugin. اضبط خادمي MCP يدوياً، وأضف المهارات عبر Skills CLI حيثما كان ذلك مدعوماً.

| الوكيل | خوادم MCP | المهارات |
|-------|-------------|--------|
| Claude Desktop | [دليل MCP Server](/developer-resources/mcp-server) | غير مدعومة |
| Windsurf | [دليل MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / غيرهما | [دليل MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## وثائق مصممة للوكلاء

تتوفر كل صفحة من وثائق Dodo Payments بتنسيق محسّن للاستهلاك بواسطة الذكاء الاصطناعي:

- **فهرس الوثائق الكامل**: [`docs.dodopayments.com/llms.txt`](https://docs.dodopayments.com/llms.txt) — يوفّر فهرس الوثائق الكامل لإدخاله في السياق.
- **Markdown عادي**: أضف `.md` إلى أي عنوان URL للوثائق للحصول على إصدار Markdown الخام (مثل `/api-reference/introduction.md`).
- **المستودع المصدر**: [`github.com/dodopayments/dodo-docs`](https://github.com/dodopayments/dodo-docs) — استنسخه للفهرسة دون اتصال.

## ما يستطيع وكيلك فعله

بعد تثبيت المكوّن الإضافي، يستطيع وكيل البرمجة لديك:

- **إنشاء جلسات checkout وروابط الدفع** — [المدفوعات لمرة واحدة](/features/one-time-payment-products) و[الاشتراكات](/features/subscription)
- **إعداد الفوترة القائمة على الاشتراكات والاستخدام من البداية إلى النهاية** — [الاشتراكات](/features/subscription)، [الفوترة القائمة على الاستخدام](/features/usage-based-billing/introduction)، [الفوترة القائمة على الائتمان](/features/credit-based-billing)
- **إنشاء معالجات متوافقة مع Standard Webhooks** مع التحقق من التوقيع — [Webhooks](/developer-resources/webhooks)

- **ربط مكوّنات BillingSDK React** بجداول التسعير وإدارة الاشتراكات — [BillingSDK](/developer-resources/billingsdk)

## الأمان وأفضل الممارسات

<Warning>
**لا تلتزم أبداً بمفاتيح API الخاصة بالإنتاج.** استخدم [وضع الاختبار](/miscellaneous/test-mode-vs-live-mode) أثناء التطوير. يستخدم Agent Plugin المصادقة عبر OAuth في المتصفح افتراضياً — ولا تنتقل إلى مفاتيح API المحلية إلا إذا تطلب سير عملك ذلك.
</Warning>

- **استخدم وضع الاختبار أولاً.** اختبر تكاملك في بيئة معزولة باستخدام مفاتيح `dodo_test_...` قبل الانتقال إلى الإنتاج. راجع [وضع الاختبار مقابل وضع الإنتاج](/miscellaneous/test-mode-vs-live-mode).
- **OAuth هو الإعداد الافتراضي.** يصادق Agent Plugin عبر OAuth في المتصفح (من دون أسرار محلية). استخدم وضع API-key فقط عند الحاجة — راجع قسم Configure أدناه.
- **راجع الشيفرة التي ينشئها الوكيل.** تحقّق دائماً من أن معالجات webhook تتضمن التحقق من التوقيع وفقاً لـ [مواصفة Standard Webhooks](https://standardwebhooks.com/).

## الإعداد باستخدام مفتاح API

يستخدم Agent Plugin افتراضياً خادم MCP البعيد مع OAuth في المتصفح — ولا يحتاج إلى بيانات اعتماد محلية. إذا تطلب سير عملك مفتاح API محلياً (مثل بيئات CI والخوادم التي تعمل دون واجهة)، يمكنك التبديل إلى وضع stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
افتح `/plugins` في Claude Code، وحدد **Dodo Payments**، ثم اختر **Configure options**. أدخل ما يلي:

- `dodo_api_key` — مفتاح `dodo_test_...` أو `dodo_live_...` الخاص بك
- `dodo_webhook_key` — السر الخاص بتوقيع webhook
- `dodo_environment` — `test_mode` أو `live_mode`

ثم عدّل `.mcp.json` لتوجيه `dodopayments-api` إلى خادم stdio المحلي:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

شغّل `/reload-plugins` لتطبيق التغييرات على جلستك الحالية.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
أعلن عن `dodopayments-api` بنفسك في `opencode.json` — إذ إن إدخالك يتغلب على الخادم البعيد الافتراضي للمكوّن الإضافي:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

أعد تشغيل OpenCode للتطبيق.
</Accordion>
</AccordionGroup>
