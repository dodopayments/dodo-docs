يعمل مكون دودة الربط على توصيل خادمَي MCP وثماني مهارات تكامل في وكيل الترميز بالذكاء الاصطناعي الخاص بك في عملية تثبيت واحدة. يعمل مع **Claude Code** و**Codex CLI** و**Cursor** و**OpenCode** — وتعمل خوادم MCP وواجهة الأوامر CLI للمهارات مع أي عميل متوافق مع MCP.

<Info>
**ثلاث أساسيات، مكوّن واحد.** يجمع مكون الوكيل كل ما تحتاجه:
 - **خادم API MCP** — الوصول المباشر إلى المدفوعات، الاشتراكات، العملاء، المنتجات، الاستردادات، التراخيص، والاستخدام. يتحقق عبر OAuth المتصفح (لا حاجة لمفاتيح محلية).
 - **خادم المعرفة MCP** — البحث الدلالي عبر جميع وثائق Dodo Payments. لا حاجة إلى بيانات اعتماد.
 - **ثماني مهارات وكيل** — أوراق الغش التي يقوم وكيلك بتحميلها عند الطلب للخروج، الاشتراكات، webhooks، الفوترة المعتمدة على الاستخدام، الفوترة المعتمدة على الرصيد، مفاتيح الترخيص، BillingSDK، وأفضل الممارسات.
</Info>

## تثبيت المكون

اختر وكيل الترميز الخاص بك أدناه. يتم إضافة خادمي MCP وجميع المهارات الثمانية تلقائيًا.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
التثبيت من السوق:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

يستخدم خادم API MCP بشكل افتراضي OAuth عبر المتصفح — لا حاجة إلى مفاتيح عند وقت التثبيت. في المرة الأولى التي يتصل فيها وكيلك بأداة من دودة الربط، سيُطلب منك تسجيل الدخول.

<Card title="Dodo Agent Plugin on GitHub" icon="github" href="https://github.com/dodopayments/dodo-agent-plugin">
  الشيفرة المصدرية، خيارات التكوين، وتعليمات التطوير المحلي
</Card>
</Accordion>

<Accordion title="Codex CLI">
يقوم Codex بتثبيت المكونات الإضافية على مرحلتين: تسجيل السوق من صدفتك، ثم تثبيت المكون الإضافي من داخل واجهة Codex TUI.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
افتح Codex وشغّل الأمر المائل `/plugins`:

```bash
codex
```

ثم اكتب `/plugins`، وقم بالتبديل إلى سوق **Dodo Payments**، واختر المكون الإضافي **dodopayments**، واختر **Install plugin**.
</Step>
</Steps>

يتم تسجيل كل من خوادم MCP وجميع المهارات الثمانية تلقائيًا بمجرد تثبيت المكون الإضافي.

<Note>
لا تحتوي Codex CLI على أمر فرعي `codex plugin install` — يحدث تثبيت المكونات الإضافية دائمًا من خلال التدفق `/plugins` في الواجهة النصية TUI. راجع [المستندات الرسمية لمكونات Codex الإضافية](https://developers.openai.com/codex/plugins).
</Note>

إذا قمت بإضافة السوق سابقًا ولم يظهر المكون الإضافي تحت `/plugins`، قم بتحديثه:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
التثبيت اليدوي — استنساخ المخزن إلى دليل المكونات الإضافية المحلي الخاص بـ Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

أعد تشغيل Cursor. يقوم المكون الإضافي بتحميل المهارات من `.claude/skills/` (عبر طبقة توافق Claude Code) وخوادم MCP من `.mcp.json`.

<Info>
دعم سوق Cursor قادم. في الوقت الحالي، استخدم التثبيت اليدوي أعلاه.
</Info>
</Accordion>

<Accordion title="OpenCode">
توزع OpenCode عبر npm. أضف المكون الإضافي إلى `opencode.json` الخاص بك:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

أعد تشغيل OpenCode. يتم تسجيل كل من خوادم MCP (`dodopayments-api`، `dodo-knowledge`) تلقائيًا عبر خطاف تكوين المكون الإضافي، ويتم اكتشاف المهارات الثمانية تلقائيًا من الحزمة المثبتة. لا حاجة إلى كتلة `mcp` يدوية.
</Accordion>
</AccordionGroup>

<Info>
تستخدم عميل مختلف؟ تغطي أدلة [خادم MCP](/developer-resources/mcp-server) و[مهارات الوكيل](/developer-resources/agent-skills) Cursor، Claude Desktop، VS Code، Windsurf، Cline، Zed، وأي عميل متوافق مع MCP.
</Info>

## ما ستحصل عليه

بمجرد تثبيت المكون الإضافي، يكون لدى وكيلك الوصول إلى خادمين من نوع MCP وثمانية مهارات.

### خوادم MCP

| الخادم | الغرض | التحقق |
|--------|-------|--------|
| `dodopayments-api` | الوصول إلى واجهة برمجة التطبيقات المباشرة — المدفوعات، الاشتراكات، العملاء، المنتجات، المبالغ المستردة، التراخيص، الاستخدام | OAuth (المتصفح) |
| `dodo-knowledge` | البحث الدلالي في كل وثائق Dodo Payments | لا يوجد |

يتم توصيل كلا الخادمين عبر `mcp-remote` بحيث تعمل في أي عميل متوافق مع MCP.

### مهارات الوكيل

| المهارة | الوصف |
|---------|--------|
| `best-practices` | دليل شامل لتكامل Dodo Payments مع أفضل الممارسات |
| `checkout-integration` | إنشاء جلسات دفع وتدفقات الدفع |
| `subscription-integration` | تنفيذ تدفقات الفوترة القائمة على الاشتراك |
| `webhook-integration` | إعداد والتعامل مع webhooks لأحداث الدفع |
| `usage-based-billing` | تنفيذ الفوترة بالقياس مع الأحداث والمقاييس |
| `credit-based-billing` | الاعتمادات والرصيد وخصم الاعتمادات المقاسة |
| `license-keys` | إدارة مفاتيح التراخيص للمنتجات الرقمية |
| `billing-sdk` | استخدام مكونات BillingSDK React |

يتم تحميل المهارات تلقائيًا — يختار وكيلك المناسب عند تحديد مهمة ذات صلة. راجع [مستندات مهارات الوكيل](/developer-resources/agent-skills) للقائمة الكاملة والتثبيت الفردي.

### جرب هذه المطالبة أولاً

بمجرد تنشيط المكون الإضافي، جرب:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

سيقوم وكيلك بتحميل المهارة `webhook-integration`، واستخدام MCP الخاص بـ `dodo-knowledge` لاستخراج أحدث أشكال الحمولة، وكتابة معالج بعمليات تحقق التوقيع وفقًا لمواصفات Standard Webhooks.

## عوامل أخرى مدعومة

يغطي المكون الإضافي للوكيل Claude Code، Codex CLI، Cursor، وOpenCode. إذا كنت تستخدم وكيلًا مختلفًا، قم بالاتصال بـ Dodo Payments عبر خوادم MCP وCLI للمهارات:

| الوكيل | أسرع مسار | يدعم أيضًا |
|--------|-----------|------------|
| **Claude Code** | المكون الإضافي للوكيل (أمر واحد) | خادم MCP، مهارات فردية |
| **Codex CLI** | المكون الإضافي للوكيل (أمر واحد) | خادم MCP |
| **Cursor** | المكون الإضافي للوكيل (git clone) | تكوين خادم MCP، CLI للمهارات |
| **OpenCode** | المكون الإضافي للوكيل (npm) | تكوين خادم MCP، CLI للمهارات |
| GitHub Copilot (VS Code) | [دليل خادم MCP](/developer-resources/mcp-server) | [مهارات CLI](/developer-resources/agent-skills) |
| Claude Desktop | [دليل خادم MCP](/developer-resources/mcp-server) | — |
| Windsurf | [دليل خادم MCP](/developer-resources/mcp-server) | [مهارات CLI](/developer-resources/agent-skills) |
| Cline / Zed / الآخرين | [دليل خادم MCP](/developer-resources/mcp-server) | [مهارات CLI](/developer-resources/agent-skills) |

## ما يمكن لوكيلك أن يفعله

مع تثبيت المكون الإضافي، يمكن لوكيل التشفير الخاص بك أن:

- **إنشاء جلسات دفع وروابط دفع** — [مدفوعات مرة واحدة](/features/one-time-payment-products) و[اشتراكات](/features/subscription)
- **إعداد الفوترة القائمة على الاشتراك والاستخدام بشكل كامل** — [اشتراكات](/features/subscription)، [الفوترة القائمة على الاستخدام](/features/usage-based-billing)، [الفوترة القائمة على الاعتمادات](/features/credit-based-billing)
- **توليد معالجات متوافقة مع Standard Webhooks** مع تحقق من التوقيعات — [Webhooks](/developer-resources/webhooks)
- **ربط مكونات BillingSDK React** لجدول الأسعار وإدارة الاشتراك — [BillingSDK](/developer-resources/billingsdk)
- **كتابة تدفقات مفاتيح التراخيص** للمنتجات الرقمية — [مفاتيح التراخيص](/features/license-keys)
- **تنفيذ الفوترة القائمة على الاعتمادات** مع الاستحقاقات، الأرصدة، الترحيل، والاستخدام الزائد — [الاعتمادات](/features/credit-based-billing)

## الأمان وأفضل الممارسات

<Warning>
**لا تُضمِّن أبدًا مفاتيح API الإنتاجية.** استخدم [وضع الاختبار](/miscellaneous/test-mode-vs-live-mode) أثناء التطوير. يستخدم المكون الإضافي للوكيل OAuth عبر المتصفح بشكل افتراضي — لا تتحول إلى مفاتيح API المحلية إلا إذا كانت سير عملك تتطلبها.
</Warning>

- **استخدم وضع الاختبار أولاً.** قم بعزل التكامل الخاص بك باستخدام مفاتيح `dodo_test_...` قبل الانتقال إلى الإنتاج. راجع [وضع الاختبار مقابل وضع الإنتاج](/miscellaneous/test-mode-vs-live-mode).
- **OAuth هو الوضع الافتراضي.** يقوم المكون الإضافي للوكيل بالتحقق عبر OAuth للمتصفح (لا أسرار محلية). استخدم وضع مفتاح API إذا كنت تحتاجه فقط — راجع قسم التكوين أدناه.
- **راجع الكود الذي يولده الوكيل.** تحقق دائمًا من أن معالجات Webhooks تتضمن تحققًا من التوقيع وفقًا لمواصفات [Standard Webhooks](https://standardwebhooks.com/).

## التكوين باستخدام مفتاح API

بشكل افتراضي، يستخدم المكون الإضافي للوكيل خادم MCP البعيد مع OAuth للمتصفح — لا توجد أسرار محلية مطلوبة. إذا كانت سير عملك تتطلب مفتاح API محلي (مثل بيئات CI، الخوادم دون واجهة)، يمكنك التبديل إلى وضع stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
افتح `/plugins` في Claude Code، حدد **Dodo Payments**، واختر **Configure options**. املأ الآتي:

- `dodo_api_key` — مفتاح `dodo_test_...` الخاص بك أو مفتاح `dodo_live_...`
- `dodo_webhook_key` — سر توقيع webhook الخاص بك
- `dodo_environment` — `test_mode` أو `live_mode`

ثم حرر `.mcp.json` لتوجيه `dodopayments-api` نحو خادم stdio المحلي:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

شغل `/reload-plugins` لتطبيق التغييرات على جلستك الحالية.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
أعلن عن `dodopayments-api` بنفسك في `opencode.json` — إدخالك يفوز على خادم البعيد الافتراضي للمكون الإضافي:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

أعد تشغيل OpenCode لتطبيق التغييرات.
</Accordion>
</AccordionGroup>
