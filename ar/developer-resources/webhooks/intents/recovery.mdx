## أحداث استرداد سلة التسوق المتروكة

تتبع أحداث الويب هوك التالية دورة حياة استرداد سلة التسوق المتروكة:

| الحدث | الوصف |
|-------|-------------|
| `abandoned_checkout.detected` | تم اكتشاف خروج مهجور. يتم الإرسال عندما يتم تحديد الدفع باعتباره مهجورًا (فشل أو غير مكتمل) ويبدأ سير عمل الاسترداد. |
| `abandoned_checkout.recovered` | أكمل العميل الدفع من خلال رابط الاسترداد. يحتوي حقل `recovered_payment_id` على معرف الدفع الناجح. |

### حقول حمولات استرداد الخروج المهجور

<ParamField body="payment_id" type="string" required>
الدفع الأصلي الذي تم التخلي عنه. استخدم هذا للبحث عن تفاصيل المنتج والمبلغ والعملة.
</ParamField>

<ParamField body="brand_id" type="string" required>
العلامة التجارية التي ينتمي إليها هذا checkout المتروك.
</ParamField>

<ParamField body="customer_id" type="string" required>
العميل الذي ترك checkout.
</ParamField>

<ParamField body="abandonment_reason" type="string" required>
سبب ترك checkout. أحد الخيارات التالية:
- `payment_failed` — حاول العميل الدفع، لكنه فشل
- `checkout_incomplete` — زار العميل checkout، لكنه لم يحاول الدفع
</ParamField>

<ParamField body="status" type="string" required>
الحالة الحالية لدورة حياة محاولة الاسترداد هذه. أحد الخيارات التالية:
- `abandoned` — تم الاكتشاف، ولم تُرسل أي رسائل بريد إلكتروني بعد
- `recovering` — تم إرسال رسالة بريد إلكتروني واحدة على الأقل للاسترداد
- `recovered` — أكمل العميل الدفع
- `exhausted` — أُرسلت جميع رسائل البريد الإلكتروني أو تم العثور على checkout أحدث
- `opted_out` — ألغى العميل الاشتراك
</ParamField>

<ParamField body="abandoned_at" type="string" required>
طابع زمني بتنسيق ISO 8601 يحدد وقت اكتشاف أن checkout متروك.
</ParamField>

<ParamField body="recovered_payment_id" type="string | null">
معرّف الدفع لعملية الدفع الناجحة للاسترداد. `null` حتى تتم استعادة checkout.
</ParamField>

### مثال: معالجة Webhooks الخاصة بـ ACR

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'abandoned_checkout.detected':
      console.log(`Checkout abandoned: ${event.data.payment_id}`);
      console.log(`Reason: ${event.data.abandonment_reason}`);
      // Track abandonment in your analytics
      await trackAbandonment(event.data);
      break;

    case 'abandoned_checkout.recovered':
      console.log(`Checkout recovered: ${event.data.payment_id}`);
      console.log(`Recovery payment: ${event.data.recovered_payment_id}`);
      // Grant access, update records
      await handleRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

## أحداث Dunning

تتتبّع أحداث Webhook التالية دورة حياة Dunning للاشتراك:

| الحدث | الوصف |
|-------|-------------|
| `dunning.started` | تم إنشاء محاولة Dunning لاشتراك دخل في الحالة `on_hold` أو ألغاه العميل. |
| `dunning.recovered` | حدّث العميل طريقة الدفع الخاصة به ونجحت عملية الدفع الناتجة. يحتوي الحقل `payment_id` على معرّف عملية الدفع الناجحة. |

### حقول حمولة محاولة Dunning

<ParamField body="subscription_id" type="string" required>
الاشتراك الذي أدّى إلى تشغيل محاولة Dunning.
</ParamField>

<ParamField body="brand_id" type="string" required>
العلامة التجارية التي تنتمي إليها محاولة Dunning هذه.
</ParamField>

<ParamField body="customer_id" type="string" required>
العميل الذي يملك الاشتراك.
</ParamField>

<ParamField body="trigger_state" type="string" required>
حالة الاشتراك التي أدّت إلى بدء dunning. إحدى القيم التالية:
- `on_hold` — توقفت عمليات التجديد بسبب فشل الدفع
- `cancelled` — ألغى العميل الاشتراك من Customer Portal
</ParamField>

<ParamField body="status" type="string" required>
الحالة الحالية لدورة حياة محاولة Dunning هذه. أحد الخيارات التالية:
- `recovering` — جارٍ إرسال رسائل Dunning الإلكترونية
- `recovered` — حدّث العميل طريقة الدفع ونجحت عملية الدفع
- `exhausted` — أُرسلت جميع رسائل البريد الإلكتروني أو تغيّرت حالة الاشتراك
</ParamField>

<ParamField body="created_at" type="string" required>
طابع زمني بتنسيق ISO 8601 يحدد وقت إنشاء محاولة Dunning.
</ParamField>

<ParamField body="payment_id" type="string | null">
معرّف الدفع لعملية الدفع الناجحة للاسترداد. `null` أثناء الاسترداد.
</ParamField>

### مثال: معالجة Webhooks الخاصة بـ Dunning

```javascript
app.post('/webhooks/dodo', async (req, res) => {
  const event = req.body;

  switch (event.type) {
    case 'dunning.started':
      console.log(`Dunning started for subscription: ${event.data.subscription_id}`);
      console.log(`Trigger: ${event.data.trigger_state}`);
      // Track dunning in your system
      await trackDunning(event.data);
      break;

    case 'dunning.recovered':
      console.log(`Subscription recovered: ${event.data.subscription_id}`);
      console.log(`Recovery payment: ${event.data.payment_id}`);
      // Reactivate access, update records
      await handleDunningRecovery(event.data);
      break;
  }

  res.json({ received: true });
});
```

<Tip>
اشترك في كلٍّ من `dunning.started` و`dunning.recovered` لتتبّع دورة حياة Dunning الكاملة. استخدم `dunning.started` لإيقاف فترات السماح مؤقتًا أو وضع علامة على الاشتراكات المعرّضة للخطر في نظامك.
</Tip>
