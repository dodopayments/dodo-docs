## ما هو التسعير المحلي؟

كل منتج له سعر أساسي بعملة أساسية. يتيح لك التسعير المحلي تجاوز هذا الأساس باستخدام **أسعار ثابتة تقوم بتحديدها لكل عملة أو لكل بلد**. قم بتفعيله عن طريق تعيين `pricing_mode` على المنتج، ثم قم بإرفاق قاعدة واحدة لكل سوق.

إنها إحدى ثلاث وسائل مستقلة لتسعير الدولي، كل منها يحل مشكلة مختلفة:

| الآلية | ما تقوم به | الرقم الذي يراه العميل |
| :--- | :--- | :--- |
| **التسعير المحلي** | سعر ثابت تحدده لكل عملة أو دولة | بالضبط المبلغ الذي تحدده |
| [**العملة التكيفية**](/features/adaptive-currency) | تحويل تلقائي لسعرك الأساسي بأسعار الصرف الحية | السعر الأساسي محول بسعر الصرف الحالي |
| [**رموز الخصم**](/features/discount-codes) | تخفيض بنسبة مئوية من السعر الأساسي | السعر الأساسي ناقص الخصم |

<Info>
يعمل التسعير المحلي وتكييف العملة معاً. عندما لا تتطابق أي قاعدة محلية، يرجع المنتج إلى سعره الأساسي - يتم تحصيله مباشرة إذا كان العميل بالفعل في عملتك الأساسية، أو يتم تحويله عبر تكييف العملة إذا لم يكن كذلك.
</Info>

## المفاهيم الأساسية

- **وضعيات التسعير** — المنتج يكون في وضع واحد تماماً في كل مرة، يحدد بواسطة `pricing_mode`:
  - `by_currency`: سعر واحد لكل عملة، بغض النظر عن البلد. الجميع الذين يدفعون بالـ EUR يرون €9.99.
  - `by_country`: سعر خاص ببلد (₹999 في الهند)، حتى عندما تشترك عدة دول في عملة واحدة.
- **مبالغ ثابتة، في أصغر وحدة** — `amount` لقاعدة يكون رقماً صحيحاً في أصغر وحدة للعملة، كما هو حال في أماكن أخرى في API: `99900` هو ₹999.00، `999` هو €9.99. إنه سعر تقوم بتحديده، وليس قيمة محولة.
- **عندما لا تطابق القاعدة** — يحتفظ المنتج بسلوكه الحالي: العملاء في عملتك الأساسية يدفعون السعر الأساسي مباشرة؛ الجميع الآخر يحصل عليه محولاً عبر [تكييف العملة](/features/adaptive-currency).
- **الرسوم مشمولة عندما تتطابق القاعدة** — يدفع العميل **بالضبط** المبلغ الذي تحدده. [تكييف العملة](/features/adaptive-currency#choose-who-bears-the-fee) يتحمل FX الرسوم التي تتحملها أنت (تعتبر ضمن الرسوم لتلك المعاملة) بدلاً من إضافتها إلى الأعلى، لذا يكون سعر يمكنك شحنه محلياً دائماً السعر الذي يتم تحصيله.

## الإدارة عبر API

التسعير المحلي متاح بالكامل عبر API. قم أولاً بتعيين وضع تسعير المنتج، ثم قم بإرفاق القواعد.

### تعيين وضع التسعير

قم بتعيين `pricing_mode` عند إنشاء المنتج (أو تحديث واحد موجود). `null` يعني الأساس فقط، السلوك الحالي.

<CodeGroup>

```typescript theme={null}
import DodoPayments from 'dodopayments';

const client = new DodoPayments({
  bearerToken: process.env.DODO_PAYMENTS_API_KEY,
  environment: 'test_mode',
});

const product = await client.products.update('pdt_premium_plan', {
  pricing_mode: 'by_country',
});
```

```python theme={null}
import os
from dodopayments import DodoPayments

client = DodoPayments(
    bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
    environment="test_mode",
)

product = client.products.update(
    "pdt_premium_plan",
    pricing_mode="by_country",
)
```

```go theme={null}
package main

import (
	"context"
	"os"

	"github.com/dodopayments/dodopayments-go"
	"github.com/dodopayments/dodopayments-go/option"
)

func main() {
	client := dodopayments.NewClient(
		option.WithBearerToken(os.Getenv("DODO_PAYMENTS_API_KEY")),
	)

	_, err := client.Products.Update(
		context.TODO(),
		"pdt_premium_plan",
		dodopayments.ProductUpdateParams{
			PricingMode: dodopayments.F(dodopayments.PricingModeByCountry),
		},
	)
	if err != nil {
		panic(err)
	}
}
```

</CodeGroup>

### إضافة سعر محلي

قم بإرفاق قاعدة للمنتج. في وضع `by_country` `country_code` مطلوب؛ في وضع `by_currency` يجب حذفه.

<CodeGroup>

```typescript theme={null}
// ₹999.00 for customers in India
const localizedPrice = await client.products.localizedPrices.create('pdt_premium_plan', {
  currency: 'INR',
  country_code: 'IN',
  amount: 99900,
});
```

```python theme={null}
# ₹999.00 for customers in India
localized_price = client.products.localized_prices.create(
    "pdt_premium_plan",
    currency="INR",
    country_code="IN",
    amount=99900,
)
```

```go theme={null}
// ₹999.00 for customers in India
localizedPrice, err := client.Products.LocalizedPrices.New(
	context.TODO(),
	"pdt_premium_plan",
	dodopayments.ProductLocalizedPriceNewParams{
		Currency:    dodopayments.F(dodopayments.CurrencyInr),
		CountryCode: dodopayments.F(dodopayments.CountryCodeIn),
		Amount:      dodopayments.F(int64(99900)),
	},
)
```

</CodeGroup>

بالنسبة إلى منتج `by_currency`، استبعد `country_code`. على سبيل المثال، `€9.99` للكل الذين يدفعون بالـ EUR (`currency: 'EUR'`, `amount: 999`).

### قائمة، تحديث، وأرشفة

يمكنك تحديث فقط `amount` لقاعدة، حيث يكون العملة والبلد ثابتين بمجرد أن يتم إنشاؤهما. الأرشفة هي حذف ناعم يوقف المطابقة لكنه يبقى في تاريخك.

<CodeGroup>

```typescript theme={null}
// List all active rules on a product
const rules = await client.products.localizedPrices.list('pdt_premium_plan');

// Change the amount (e.g. end a promo)
await client.products.localizedPrices.update('lcp_india_price', {
  product_id: 'pdt_premium_plan',
  amount: 119900,
});

// Archive a rule
await client.products.localizedPrices.archive('lcp_india_price', {
  product_id: 'pdt_premium_plan',
});
```

## كيف يتم تطبيقه عند الخروج

يتم حل التسعير المحلي لكل سطر في العربة، فقط للمنتجات التي تم تعيين `pricing_mode` عليها. ديدو بايمنتس تقرأ إشارتين من الطلب: **بلد فاتورة** العميل، و **`billing_currency`** اختياري (عند حذفه، يتم اشتقاق عملة من بلد الفاتورة).

- **حسب البلد**: يبحث عن قاعدة تطابق بلد الفاتورة. إذا كانت موجودة، يتم تحصيل المبلغ المحدد في عملة القاعدة.
- **حسب العملة**: يبحث عن قاعدة تطابق عملة العميل (`billing_currency`، أو العملة المشتقة من بلدهم). إذا كانت موجودة، يتم تحصيل المبلغ المحدد في تلك العملة من العميل.
- **لا تطابق، أو لا `pricing_mode`**: ينطبق السعر الأساسي، يتم تحصيله مباشرة عندما تكون عملة العميل مساوية للعملة الأساسية، أو يتم تحويله عبر [تكييف العملة](/features/adaptive-currency).

يتم حل كل سطر من العربة بشكل فردي، لذا يمكنك تخصيص منتج واحد وترك الآخرين على التسعير الأساسي في نفس عملية الشراء. إذا تطابق أي سطر مع قاعدة محلية، يتم تغطية كل المعاملة بالرسوم - شاملة (انظر [المفاهيم الأساسية](#core-concepts)).

## كيفية تطبيق ذلك عند تغيير خطة الاشتراك

تتبع الأسعار المترجمة المشتركين عند انتقالهم بين الخطط. عندما تقوم اشتراكات موجودة [بتغيير الخطة](/features/subscription#subscription-plan-changes) إلى منتج يتضمن `pricing_mode`، يُحدَّد سعر الخطة الجديدة وفق القواعد نفسها المستخدمة في الدفع، مع استخدام بلد الفوترة والعملة المثبتين مسبقًا على الاشتراك:

- **حسب البلد**: تُطبَّق القاعدة المطابقة لبلد فوترة الاشتراك. إذا اختلفت عملة القاعدة عن العملة التي تتم فوترة الاشتراك بها، يُحوَّل مبلغ القاعدة وفق أسعار الصرف الأجنبي المباشرة — تُطبَّق القاعدة ولا يتم تجاهلها.
- **حسب العملة**: تُطبَّق القاعدة المطابقة للعملة التي تتم فوترة العميل بها، ويُحمَّل العميل مبلغ القاعدة كما هو تمامًا.
- **عدم وجود تطابق، أو عدم وجود `pricing_mode`**: يُطبَّق السعر الأساسي للخطة الجديدة، مع تحويله عبر [Adaptive Currency](/features/adaptive-currency) عند الحاجة — وهو نفس الخيار الاحتياطي المستخدم عند الدفع.

ينطبق ذلك في جميع الحالات التي يمكن أن يبدأ فيها تغيير الخطة: [Change Plan API](/api-reference/subscriptions/change-plan)، وتغييرات الخطة ذاتية الخدمة في [Customer Portal](/features/customer-portal)، والتغييرات المجدولة لنهاية فترة الفوترة.

- **المعاينات دقيقة.** يعرض [Preview Change Plan](/api-reference/subscriptions/preview-change-plan) المبلغ المترجم نفسه الذي يفرضه التغيير الفعلي.
- **تحتفظ التجديدات بالسعر المترجم.** بعد التغيير، تُجدَّد الخطة الجديدة بمبلغها المترجم — وتظل شاملة للرسوم — تمامًا مثل اشتراك أُنشئ بهذا السعر.
- **يستخدم التوزيع النسبي المبالغ الفعلية.** عند الترقية، يستند رصيد الوقت غير المستخدم إلى المبلغ الذي دفعه العميل فعليًا للخطة القديمة، بينما تُسعَّر الخطة الجديدة وفق قاعدتها المترجمة.
- **تثبّت التغييرات المجدولة السعر عند جدولتها.** يفرض التغيير المجدول لنهاية فترة الفوترة المبلغ المحسوب وقت الجدولة، حتى إذا عدّلت القاعدة في الفترة الفاصلة.
- **لا تتغير عملة الفوترة أبدًا.** لا يبدّل تغيير الخطة العملة التي تتم تسوية الاشتراك بها؛ بل تُحوَّل القاعدة بعملة أخرى إليها وفق أسعار الصرف الأجنبي.
- **لا تُترجم أسعار الإضافات.** تستخدم أسعار الإضافات في الخطة الجديدة دائمًا تسعيرها الأساسي.

## سلوكيات مهمة

| السلوك | التفاصيل |
| :--- | :--- |
| **المبالغ قبل الضريبة** | المبلغ المترجم هو السعر *قبل* الضريبة. بالنسبة إلى المنتجات غير الشاملة للضريبة، تُضاف الضريبة عند الدفع، لذلك لا يمثل المبلغ المترجم الإجمالي النهائي. راجع [Tax-Inclusive Pricing](/features/tax-inclusive-pricing). |
| **غير متاح لمنتجات Pay What You Want** | لا تنطبق القواعد المترجمة على منتجات [Pay What You Want](/features/pay-what-you-want)، حيث يختار العميل المبلغ. |
| **يختلف حسب العملة عن السعر الأساسي** | يجب أن تستخدم قاعدة `by_currency` عملة مختلفة عن العملة الأساسية للمنتج. |
| **قاعدة واحدة لكل سوق** | يمكن أن يتضمن المنتج قاعدة نشطة واحدة كحد أقصى لكل عملة (حسب العملة) أو لكل بلد (حسب البلد). |
| **جميع أنواع المنتجات** | ينطبق ذلك على المنتجات ذات الشراء لمرة واحدة، والاشتراكات، والمنتجات القائمة على الاستخدام — بما في ذلك عندما يقوم مشترك حالي [بتغيير الخطة](#how-it-applies-on-subscription-plan-changes). |

<Info>
لا تُصدر تغييرات القواعد المترجمة Webhooks خاصة بها. يظهر المبلغ المحدد في الدفعة أو الاشتراك الناتج تمامًا مثل أي سعر آخر.
</Info>

## أفضل الممارسات

- **حافظ على سعر أساسي منطقي.** فهو الخيار الاحتياطي لكل سوق لا تتوفر له قاعدة، مع تحويله عبر Adaptive Currency.
- **قرّب الأسعار إلى أرقام جذابة محليًا.** الهدف من المبلغ الثابت هو الحصول على رقم واضح مثل ₹999 أو €9.99 أو ¥1000، وليس نتيجة لتحويل أسعار الصرف الأجنبي.
- **اختر الوضع المناسب للمهمة.** استخدم `by_country` لتسعير القدرة الشرائية؛ واستخدم `by_currency` عندما يكون سعر واحد لكل منطقة عملة كافيًا.
- **أرشف القواعد بدلًا من إعادة إنشائها للعروض الترويجية.** تؤدي أرشفة القاعدة إلى إعادة السوق إلى السعر الأساسي/التكيفي مع الحفاظ على السجل؛ ويمكنك إعادة إنشائها أو إعادة تسعيرها لاحقًا حسب الحاجة.
- **انتبه إلى بند الضريبة قبل الإعلان عن إجمالي.** بالنسبة إلى المنتجات غير الشاملة للضريبة، يدفع العميل المبلغ المترجم *بالإضافة إلى* الضريبة، لذلك لا تذكره باعتباره السعر النهائي في الإعلانات.
