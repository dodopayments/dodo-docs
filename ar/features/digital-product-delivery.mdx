## نظرة عامة

توصيل المنتجات الرقمية هو نوع الاستحقاق **Digital Files**. تحمّل ملفاتك مرة واحدة إلى استحقاق Digital Files، وتربط الاستحقاق بمنتج، ثم يسلّم Dodo Payments روابط تنزيل موقعة مسبقًا إلى كل عميل دفع عبر البريد الإلكتروني وبوابة العميل.

يدعم الاستحقاق ما يلي:

- **تحميلات الملفات المستضافة**: خزّن الملفات على Dodo Payments وقدّمها عبر روابط موقعة مسبقًا قصيرة الأجل.
- **روابط التنزيل الخارجية**: اربط بالملفات المستضافة على Dropbox أو Google Drive أو S3 أو أي عنوان URL.
- **تعليمات التنزيل**: نص حر يظهر للعميل في صفحة الطلب وفي رسالة التسليم الإلكترونية.

يمكنك دمج الأنواع الثلاثة كلها في استحقاق واحد.

## إعداد توصيل المنتجات الرقمية

<Steps>
<Step title="Open Entitlements">
انتقل إلى **Entitlements** في لوحة معلومات Dodo Payments وانقر على **+** لإنشاء استحقاق جديد.
</Step>

<Step title="Choose Digital Files">
حدّد **Digital Product Delivery** باعتباره التكامل.
</Step>

<Step title="Add files, links, and instructions">
اضبط أي مجموعة من الخيارات التالية:

- **Files**: حمّل ملفًا واحدًا أو أكثر. يعيد كل تحميل `file_id` تتم إضافته إلى الاستحقاق.
- **External URL**: رابط HTTPS يمكن الوصول إليه بشكل عام، ويتم تسليمه إلى جانب الملفات المستضافة.
- **Instructions**: نص حر يظهر للعميل (مثل: "فك الضغط وشغّل setup.sh").

</Frame>
</Step>

<Step title="Save the entitlement">
احفظ التغييرات. أصبح الاستحقاق متاحًا الآن لإرفاقه بأي منتج.
</Step>
</Steps>

## الإرفاق بالمنتجات

## آلية التسليم

يتبع تسليم Digital Files [دورة حياة المنح القياسية](/features/entitlements/introduction#how-grants-work):

| الحدث | السلوك |
|---|---|
| `payment.succeeded` (مرة واحدة) | إصدار منحة. تحتوي المنحة على روابط تنزيل موقعة مسبقًا صالحة لنحو 15 دقيقة؛ ويمكن للعملاء تحديثها بإعادة فتح رابط البريد الإلكتروني أو صفحة بوابة العميل. |
| `subscription.active` | إصدار منحة. تظل الملفات متاحة ما دام الاشتراك نشطًا. |
| `subscription.renewed` | لا عملية. تستمر المنحة نفسها؛ وتُنشأ روابط موقعة مسبقًا جديدة عند كل جلب. |
| `subscription.on_hold` / `cancelled` / `expired` | إلغاء المنحة. لن تُصدر روابط موقعة مسبقًا جديدة. |
| `subscription.plan_changed` | إلغاء المنحة القديمة وإصدار منحة جديدة للخطة الجديدة واستحقاقها. |
| `refund.succeeded` (مرة واحدة) | إلغاء المنحة. |
| الإلغاء اليدوي | الإلغاء باستخدام `revocation_reason: manual`. |

<Warning>
يمنع الإلغاءُ Dodo Payments من إصدار روابط تنزيل جديدة، لكنه **لا** يبطل النسخ التي نزّلها العميل بالفعل. تعامل مع تنزيلات الملفات المستضافة على أنها "تُسلّم بمجرد قراءتها".
</Warning>

## إدارة الملفات برمجيًا

### تحميل ملف إلى استحقاق

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';
import fs from 'node:fs';

const client = new DodoPayments({
  bearerToken: process.env['DODO_PAYMENTS_API_KEY'],
  environment: 'test_mode',
});

await client.entitlements.files.upload('ent_files_abc', {
  file: fs.createReadStream('./pro-bundle.zip'),
  filename: 'pro-bundle.zip',
});
```

```bash cURL theme={null}
curl -X POST "https://test.dodopayments.com/entitlements/ent_files_abc/files" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -F "file=@./pro-bundle.zip" \
  -F "filename=pro-bundle.zip"
```

</CodeGroup>

### سرد المنح وحل روابط التنزيل

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_files_abc', {
  customer_id: 'cus_abc123',
});

for (const grant of grants.items) {
  for (const file of grant.digital_product_delivery.files) {
    console.log(file.filename, file.download_url, `expires in ${file.expires_in}s`);
  }
}
```

### إزالة ملف من استحقاق

```typescript theme={null}
await client.entitlements.files.delete('df_a4f6c1de', { id: 'ent_files_abc' });
```

## اعتبارات مهمة

- **تنتهي صلاحية الروابط الموقعة مسبقًا بسرعة.** روابط التنزيل المعادة في حمولات المنح أو أحداث webhook صالحة لنحو 15 دقيقة. لا تخزّنها؛ أعد جلبها عندما يحتاج العميل إلى التنزيل مرة أخرى.
- **يؤثر تحديث الملفات في عمليات الشراء المستقبلية فقط.** لا يؤدي استبدال ملف أو إزالته إلى تغيير التنزيلات التي أُصدرت سابقًا بأثر رجعي. ولا يزال بإمكان العملاء السابقين إعادة جلب الإصدار الذي كان ساريًا عند إنشاء منحهم.
- **لا تُبطل عمليات رد الأموال النسخ التي تم تنزيلها.** يحتفظ العميل الذي نزّل ملفًا بالفعل بنسخته. بالنسبة إلى المحتوى القابل للإلغاء (الوسائط المقيدة بترخيص، والوصول المحدد زمنيًا)، اقرن Digital Files بـ [License Keys](/features/license-keys) وأجرِ التحقق أثناء التشغيل.
- **للمحتوى الحساس، يُفضّل استخدام عناوين URL خارجية مع المصادقة الخاصة بها.** روابط Dodo Payments الموقعة مسبقًا قصيرة الأجل لكنها غير موثّقة خلال فترة صلاحيتها؛ ويمكن لأي شخص يملك الرابط التنزيل خلال تلك الفترة. يوفر المحتوى المستضاف خارجيًا والمقيّد بحسابات ضمانات أقوى.

## Webhooks

يُطلق تسليم الملفات الرقمية وإلغاؤها أحداث webhook الأربعة المدرجة في [أحداث webhook الخاصة بـ `entitlement_grant.*`](/developer-resources/webhooks/intents/entitlement-grant). بالنسبة إلى منح Digital Files، تتضمن الحمولة كائن `digital_product_delivery` مع قائمة الملفات التي تم حلها (الروابط الموقعة مسبقًا وأسماء الملفات وأحجامها)، و`instructions` الاختياري، و`external_url` الاختياري.

```json theme={null}
"digital_product_delivery": {
  "files": [
    {
      "file_id": "df_a4f6c1de",
      "download_url": "https://files.dodopayments.com/.../pro-bundle.zip?Signature=...",
      "filename": "pro-bundle.zip",
      "content_type": "application/zip",
      "file_size": 18742390,
      "expires_in": 900
    }
  ],
  "instructions": "Unzip and run setup.sh from the project root.",
  "external_url": null
}
```

## توصيل المنتجات الرقمية القديمة

<Note>
تم **ترحيل المنتجات المُعدّة باستخدام كتلة `digital_product_delivery` القديمة على المنتج نفسه تلقائيًا** إلى استحقاق Digital Files. وقد حُفظت الملفات الحالية التي تم تحميلها باستخدام API ملفات المنتج القديم؛ ولا يزال من الممكن تنزيلها، كما تظهر في حمولات المنح مع وسم `source: "legacy"`. يجب إجراء التحديثات المستقبلية (إضافة ملفات أو تغيير التعليمات أو استبدال العنوان URL الخارجي) عن طريق تحرير استحقاق Digital Files الذي تم ترحيله ضمن **Entitlements**.

تستمر تعبئة الحقول القديمة على مستوى المنتج (`digital_product_delivery.external_url` و`digital_product_delivery.instructions`) في استجابات المنتج لتحقيق التوافق مع الإصدارات السابقة، لكن الاستحقاق هو مصدر الحقيقة مستقبلًا.
</Note>

## أفضل الممارسات

- **تعامل مع التنزيلات باعتبارها عملية لمرة واحدة.** سيشارك العملاء الروابط أو يفقدونها، لذا صمّم منتجك على افتراض أن أي شيء ينزّلونه أصبح ملكًا لهم للاحتفاظ به.
- **استخدم التعليمات لتوضيح التوقعات.** بالنسبة إلى الحزم متعددة الملفات، أضف سطر `instructions` يوضح ما يجب تثبيته أولًا أو كيفية دمج الملفات.
- **راقب حد 500 MiB.** يجب استضافة الملفات الأكبر (مجموعات البيانات متعددة الجيجابايت ودورات الفيديو) خارجيًا وربطها عبر `external_url` بدلًا من تحميلها.
- **اجمع بينها وبين License Keys للوصول القابل للإلغاء.** إذا كنت بحاجة إلى إلغاء الوصول إلى الميزات داخل المنتج بعد رد الأموال، فاربط استحقاق Digital Files باستحقاق License Key وتحقق من المفتاح أثناء التشغيل.
- **اختبر مسار تحديث بوابة العميل.** تأكد من قدرة العميل على العودة إلى البوابة بعد أسبوع والحصول على رابط تنزيل صالح. هذا هو مسار الاسترداد الأساسي عند انتهاء صلاحية روابط البريد الإلكتروني.
