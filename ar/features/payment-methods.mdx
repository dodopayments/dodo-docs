## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## تكوين طرق الدفع لكل جلسة دفع

بالإضافة إلى الإعدادات على مستوى الأعمال، يمكنك تقييد الطرق المعروضة لكل جلسة دفع باستخدام `allowed_payment_method_types`:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

### الأنواع المتاحة للطرق

| النوع | الوصف |
| :--- | :---------- |
| `credit` | بطاقات الائتمان (فيزا، ماستركارد، أمريكان إكسبريس، إلخ) |
| `debit` | بطاقات الخصم |
| `apple_pay` | Apple Pay |
| `google_pay` | Google Pay |
| `amazon_pay` | Amazon Pay |
| `cashapp` | Cash App Pay |
| `klarna` | Klarna BNPL |
| `afterpay_clearpay` | Afterpay / Clearpay |
| `upi_collect` | UPI Collect (رمز QR) |
| `ideal` | iDEAL (هولندا) |
| `bancontact_card` | Bancontact (بلجيكا) |
| `eps` | EPS (النمسا) |
| `multibanco` | Multibanco (البرتغال) |
| `revolut_pay` | RevolutPay |
| `billie` | Billie B2B BNPL |
| `pix` | Pix (البرازيل) |
| `crypto` | العملات الرقمية والعملات الثابتة |

<Warning>
دائمًا ما يتم تضمين `credit` و`debit` كخيارات احتياطية. إذا كانت جميع طرق الدفع المحددة غير متاحة للعميل، فسيتم فشل عملية الدفع.
</Warning>

## أفضل الممارسات

<AccordionGroup>
<Accordion title="Match methods to your market">
تضمين طرق الدفع الإقليمية للأسواق المستهدفة. تلتقط iDEAL حوالي 60% من المدفوعات عبر الإنترنت في هولندا؛ UPI يسيطر في الهند. الغياب عن هذه الطرق يؤثر بشكل كبير على التحويل.
</Accordion>

<Accordion title="Always provide card fallbacks">
حتى عند استهداف طرق معينة، قم بتضمين `credit` و`debit` كخيارات احتياطية. ليس لدى جميع العملاء إمكانية الوصول إلى كل طريقة دفع.
</Accordion>

<Accordion title="Consider transaction minimums">
تتطلب طرق BNPL (Klarna، Afterpay) حدًا أدنى يبلغ 50.01 دولارًا. لا تقم بتضمينها للمنتجات ذات القيمة المنخفضة - لن تظهر ببساطة، وهذا أمر جيد.
</Accordion>

<Accordion title="Test across regions and devices">
استخدم وضع الاختبار للتحقق من توفر طرق الدفع لمواقع مختلفة للعملاء، العملات، وأنواع الأجهزة قبل البث المباشر.
</Accordion>
</AccordionGroup>

## استكشاف الأخطاء وإصلاحها

<AccordionGroup>
<Accordion title="Payment method not appearing">
**تحقق من هذه العوامل:**
1. هل تم تضمين الطريقة في `allowed_payment_method_types`؟
2. هل موقع العميل يتطابق مع المنطقة المدعومة للطريقة؟
3. هل العملة المدعومة من قبل الطريقة؟
4. هل مبلغ المعاملة يفي بالحد الأدنى (على سبيل المثال، 50.01 دولارًا لـ BNPL)؟
5. للاشتراكات: هل الطريقة تدعم المدفوعات المتكررة؟

**الحل:** قم بإزالة `allowed_payment_method_types` مؤقتًا لرؤية جميع الطرق المتاحة، ثم حدد المشكلة للتضييق عليها.
</Accordion>

<Accordion title="Unexpected methods appearing">
**الأسباب المحتملة:**
- `allowed_payment_method_types` لا يتم تمريره بشكل صحيح
- تنسيق المعلمات بشكل غير صحيح (يجب أن يكون مصفوفة من السلاسل)

**الحل:** قم بتسجيل حمولة طلب API الخاص بك وتحقق من بنية المعلمات.
</Accordion>

<Accordion title="Regional method not available">
**تحقق:**
- هل عنوان العميل يتطابق مع منطقة الطريقة
- هل يتم تعيين العملة بشكل صحيح (على سبيل المثال، اليورو لـ iDEAL)
- هل تم تمكين العملة المتكيفة إذا كان العميل من دول أخرى

**الحل:** تحقق من رمز بلد عنوان الفاتورة والعملة في طلب API الخاص بك.
</Accordion>

<Accordion title="Indian payment method issues">
تتمتع اشتراكات UPI وRupay بمتطلبات فريدة تشمل تأخيرات معالجة لمدة 48 ساعة وحدود تفويض RBI.

**راجع:** <a href="/features/payment-methods/india">طرق الدفع في الهند</a> للحصول على الإرشادات الكاملة.
</Accordion>
</AccordionGroup>
