## Adaptive Currency

تتيح Adaptive Currency للعملاء الدفع بعملتهم المحلية المفضلة، مما يعزز الثقة ومعدلات التحويل.

### آلية العمل

1. **التفعيل**: فعّل Adaptive Currency من **Settings → Business**
2. **الاختيار**: يمكن للعملاء تبديل العملات مباشرةً في صفحة الدفع
3. **التحويل**: تُحوَّل الأسعار ديناميكيًا باستخدام أسعار صرف العملات الأجنبية الآنية
4. **العرض**: يُعرض المبلغ النهائي المستحق بوضوح قبل الدفع

## حساب الضرائب تلقائيًا

تُحسب الضرائب تلقائيًا استنادًا إلى موقع فوترة العميل، مما يضمن الامتثال لمتطلبات GST وVAT وضريبة المبيعات دون إعداد يدوي.

### آلية حساب الضرائب

<Steps>
<Step title="Location Detection">
  تُطبَّق القواعد الضريبية استنادًا إلى بلد العميل (والمنطقة عند الاقتضاء).
</Step>

<Step title="Dynamic Updates">
  يُحدَّث مبلغ الضريبة تلقائيًا عند:
  - تغيير البلد
  - تحديث العنوان
</Step>

<Step title="Transparent Display">
  يُعرض التفصيل النهائي للضريبة بوضوح قبل الدفع.
</Step>
</Steps>

<Tip>
حساب الضرائب مؤتمت بالكامل. لا يلزم إعداد يدوي للمنتجات الرقمية القياسية ومنتجات SaaS.
</Tip>

## دعم Tax ID للأعمال

بالنسبة إلى الأنشطة التجارية المسجلة، تتيح صفحة الدفع للعملاء إدخال Business Tax ID الخاص بهم (مثل رقم VAT/GST).

### ما يحدث عند إدخال Tax ID

- يتم التحقق من الأهلية الضريبية في الوقت الفعلي
- تُطبَّق الإعفاءات الضريبية أو قواعد الاحتساب العكسي السارية
- يُحدَّث مبلغ الضريبة فورًا في صفحة الدفع

## رموز الخصم

يمكن للعملاء تطبيق رموز الخصم أو الرموز الترويجية التي أنشأتها في لوحة التحكم مباشرةً في صفحة الدفع.

### تجربة الدفع

1. يُدخل العميل رمز الخصم
2. يتم التحقق من الرمز فورًا
3. يُعرض السعر المحدّث ومقدار التوفير بوضوح

<Frame>
  <img src="/images/checkout/c4.png" alt="إدخال رمز الخصم في صفحة الدفع" style={{ maxHeight: '500px', width: '70%' }}/>
</Frame>

### تكامل API

طبّق مسبقًا رمز خصم واحدًا أو أكثر من رموز الخصم المتراكمة، أو فعّل حقل إدخال الخصم:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  discount_codes: ['WELCOME20'], // Pre-apply one or more codes (max 20, applied in order)
  feature_flags: {
    allow_discount_code: true // Show discount input field
  },
  return_url: 'https://yoursite.com/return'
});
```

<Info>
يقبل `discount_codes` مصفوفةً تضم ما يصل إلى 20 رمزًا تُطبَّق بالتسلسل. حقل `discount_code` المفرد مهجور، لكنه لا يزال يعمل — ولا تحتاج عمليات التكامل الحالية إلى التغيير فورًا. انتقل إلى `discount_codes` عندما يناسبك للاستفادة من التراكم وبنية الاستجابة الأكثر شمولًا.
</Info>

## جمع العناوين الذكي

تدعم صفحة الدفع إدخال العنوان بمرونة لإتمام العملية بسرعة أكبر.

### الخيارات المتاحة

| الخيار | الوصف |
|--------|-------------|
| **Google Address Autofill** | اختيار سريع باستخدام الإكمال التلقائي |
| **الإدخال اليدوي** | تحكم كامل لإدخال العناوين بالتفصيل |
| **اختيار البلد** | يحدد منطق الضرائب والامتثال |
| **العنوان المختصر** | جمع البلد فقط (والرمز البريدي عند الحاجة لأغراض الضريبة) — راجع [وضع العنوان المختصر](#minimal-address-mode) |

<Tip>
يوازن جمع العناوين بين السرعة والدقة والتغطية العالمية لزيادة التحويل مع ضمان الامتثال.
</Tip>

### وضع العنوان المختصر

لتحقيق أعلى معدل تحويل، فعّل جمع العنوان المختصر لتقليل العوائق أثناء الدفع. عند ضبط `minimal_address` على `true`، تجمع صفحة الدفع ما يلي فقط:

- **البلد** — مطلوب دائمًا لتحديد الضرائب
- **الرمز البريدي** — في المناطق التي يلزم فيها لحساب ضريبة المبيعات أو VAT أو GST فقط

يتم تخطي جميع حقول العنوان الأخرى (الشارع والمدينة والولاية)، مما يسرّع إتمام الدفع بشكل ملحوظ.

<Frame>
  <img src="/images/changelog/minimal-address.png" alt="وضع العنوان المختصر الذي يعرض حقلي البلد والرمز البريدي فقط في صفحة الدفع" style={{ maxHeight: '500px', width: 'auto' }} />
</Frame>

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  minimal_address: true,
  return_url: 'https://yoursite.com/return'
});
```

<Info>
يظل جمع العنوان الكامل هو الإعداد الافتراضي. فعّل `minimal_address` للمنتجات الرقمية وتدفقات SaaS التي لا تتطلب تفاصيل فوترة كاملة.
</Info>

<Card title="Minimal Address Reference" icon="address-card" href="/developer-resources/checkout-session#request-body">
  راجع المرجع الكامل لمعامل `minimal_address` في دليل Checkout Sessions API.
</Card>

## جمع أرقام الهواتف

تحكم في ظهور حقل رقم الهاتف في صفحة الدفع — وما إذا كان مطلوبًا — باستخدام أعلام ميزات جلسة Checkout.

| العلم | الافتراضي | السلوك |
|------|---------|----------|
| `allow_phone_number_collection` | `true` | يعرض حقل رقم الهاتف في نموذج الدفع |
| `require_phone_number` | `false` | يجعل حقل رقم الهاتف مطلوبًا (يفرض التحقق من النموذج إدخال قيمة غير فارغة) |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_abc', quantity: 1 }],
  feature_flags: {
    allow_phone_number_collection: true,
    require_phone_number: true
  },
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
يتطلب `require_phone_number: true` تفعيل `allow_phone_number_collection: true`. ترفض API الجلسات التي يكون فيها جمع الهاتف معطلًا بينما يكون رقم الهاتف مطلوبًا.
</Warning>

<Tip>
استخدم `require_phone_number` في B2B SaaS والقطاعات الخاضعة للتنظيم، أو في أي تدفق تحتاج فيه إلى قناة اتصال موثقة للدعم أو مراجعة الاحتيال أو الامتثال.
</Tip>

## الحقول المخصصة

اجمع معلومات إضافية من العملاء أثناء الدفع من خلال تعريف حقول نموذج مخصصة. يفيد ذلك في جمع بيانات مثل اسم الشركة وحجم الفريق ومصدر الإحالة أو أي معلومات أخرى خاصة بالعمل.

### أنواع الحقول المتاحة

| النوع | الوصف |
|------|-------------|
| `text` | إدخال نص في سطر واحد |
| `number` | إدخال رقمي |
| `email` | عنوان بريد إلكتروني مع التحقق |
| `url` | URL مع التحقق |
| `date` | منتقي التاريخ |
| `dropdown` | الاختيار من خيارات محددة مسبقًا |
| `boolean` | مفتاح تبديل نعم/لا |

### مثال

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  custom_fields: [
    {
      key: 'company_name',
      label: 'Company Name',
      field_type: 'text',
      required: true
    },
    {
      key: 'team_size',
      label: 'Team Size',
      field_type: 'dropdown',
      required: true,
      options: ['1-10', '11-50', '51-200', '200+']
    }
  ],
  return_url: 'https://yoursite.com/return'
});
```

<Info>
تُضمَّن إجابات العملاء تلقائيًا في حمولات webhook (`payment.succeeded` و`subscription.active`) وفي استجابات API عبر مصفوفة `custom_field_responses`. يمكنك تعريف ما يصل إلى 5 حقول مخصصة لكل جلسة Checkout.
</Info>

<Card title="Custom Fields Guide" icon="input-text" href="/developer-resources/checkout-session#15-collecting-custom-fields">
  تعرّف على المزيد حول إعداد الحقول المخصصة والوصول إلى الإجابات.
</Card>

## الدفع عبر مجموعة المنتجات

تتيح Product Collections تجربة دفع موحدة يمكن للعملاء من خلالها عرض منتجات متعددة ذات صلة واختيارها (مثل خطط Starter وPro وEnterprise) في عملية دفع واحدة.

### آلية العمل

1. **عرض جميع المنتجات**: يرى العملاء كل منتج نشط في المجموعة
2. **تحديد المنتج الأول مسبقًا**: يتم تحديد المنتج الأول في المجموعة تلقائيًا
3. **مقارنة الخيارات**: يمكن للعملاء مقارنة الأسعار والمزايا قبل الاختيار
4. **اختيار واحد**: بعد اختيار المنتج، تستمر عملية الدفع باستخدام التدفق القياسي للدفع

### إنشاء عملية دفع لمجموعة

```typescript
const session = await client.checkoutSessions.create({
  product_collection_id: 'pdc_abc123',
  product_cart: [], // Required: pass an empty array for collection checkout
  return_url: 'https://yoursite.com/return'
});
```

<Warning>
عند استخدام `product_collection_id`، مرّر مصفوفة `product_cart` فارغة. لا يمكن تطبيق رموز الخصم مسبقًا عند إنشاء الجلسة.
</Warning>

## إعداد Checkout Session

تحكم في سلوك صفحة الدفع باستخدام Checkout Sessions API:

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [
    { product_id: 'prod_abc', quantity: 1 }
  ],
  customer: {
    email: 'customer@example.com',
    name: 'Jane Doe'
  },
  billing_currency: 'EUR', // Set specific currency
  discount_codes: ['PROMO10'],
  feature_flags: {
    allow_discount_code: true
  },
  return_url: 'https://yoursite.com/return',
  cancel_url: 'https://yoursite.com/pricing', // Optional: where to redirect on cancel
  metadata: {
    order_ref: 'ORD-12345'
  }
});
```

<Info>
بعد الدفع، يُعاد توجيه العملاء إلى `return_url` الخاص بك، مع إلحاق معاملات query تلقائيًا — بما في ذلك `payment_id` أو `subscription_id` و`status` و`email` و`license_key` (عند الاقتضاء). راجع [دليل Checkout Sessions](/developer-resources/checkout-session#request-body) للحصول على القائمة الكاملة.
</Info>

## تخصيص مظهر صفحة الدفع

خصّص مظهر صفحة الدفع ليتوافق مع علامتك التجارية باستخدام معامل `customization.theme_config` عند إنشاء جلسة Checkout عبر API. اضبط الألوان والخطوط ونصف قطر الحدود ونص الزر لكل من الوضعين الفاتح والداكن.

<Frame>
  <img src="/images/checkout/theme-example.png" alt="صفحة دفع بمظهر مخصص" style={{ maxHeight: '500px', width: 'auto' }} />

<Card title="Design & Theme Customization" icon="palette" href="/features/design">

<Info>
يغطي هذا القسم إعداد المظهر عبر **server-side API** باستخدام `customization.theme_config`. إذا كنت تستخدم **Checkout SDK** (الدفع عبر overlay أو inline)، فراجع قسم تخصيص المظهر في [Overlay Checkout](/developer-resources/overlay-checkout#theme-customization)، الذي يستخدم خصائص camelCase (مثل `bgPrimary` بدلًا من `bg_primary`).
</Info>

### خيارات إعداد المظهر

| الخاصية | الوصف |
|----------|-------------|
| `light` | إعداد الألوان للوضع الفاتح |
| `dark` | إعداد الألوان للوضع الداكن |
| `font_primary_url` | URL للخط الأساسي |
| `font_secondary_url` | URL للخط الثانوي |
| `font_size` | حجم الخط: `xs` و`sm` و`md` و`lg` و`xl` و`2xl` |
| `font_weight` | سُمك الخط: `normal` و`medium` و`bold` و`extraBold` |
| `radius` | نصف قطر حدود عناصر واجهة المستخدم (مثل `4px` و`0.5rem` و`8px`) |
| `pay_button_text` | نص مخصص لزر الدفع (مثل "Complete Purchase" و"Subscribe Now") |

### إعداد الألوان (الوضع الفاتح/الداكن)

يدعم كل وضع (`light` و`dark`) خصائص الألوان التالية:

| الخاصية | الوصف |
|----------|-------------|
| `bg_primary` | لون الخلفية الأساسي |
| `bg_secondary` | لون الخلفية الثانوي |
| `text_primary` | لون النص الأساسي |
| `text_secondary` | لون النص الثانوي |
| `text_placeholder` | لون النص النائب |
| `text_error` | لون نص الخطأ |
| `text_success` | لون نص النجاح |
| `border_primary` | لون الحدود الأساسي |
| `border_secondary` | لون الحدود الثانوي |
| `button_primary` | لون خلفية الزر الأساسي |
| `button_primary_hover` | لون تمرير المؤشر فوق الزر الأساسي |
| `button_secondary` | لون خلفية الزر الثانوي |
| `button_secondary_hover` | لون تمرير المؤشر فوق الزر الثانوي |
| `button_text_primary` | لون نص الزر الأساسي |
| `button_text_secondary` | لون نص الزر الثانوي |
| `input_focus_border` | لون حدود التركيز لحقل الإدخال |

<Info>
تقبل جميع حقول الألوان تنسيقات ألوان CSS القياسية:
- Hex: `#fff` و`#ffffff` و`#ffffffff`
- RGB/RGBA: `rgb(255, 255, 255)` و`rgba(255, 255, 255, 0.5)`
- HSL/HSLA: `hsl(120, 100%, 50%)` و`hsla(120, 100%, 50%, 0.5)`
- الألوان المسماة: `red` و`blue` و`transparent`
</Info>
