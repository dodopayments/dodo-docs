<Info>
مفاتيح التراخيص هي نوع الاستحقاق License Key. أنشئ استحقاق License Key مرة واحدة مع حد التنشيط وتاريخ انتهاء الصلاحية والتعليمات التي تريدها، وأرفقه بأي منتج، وسيتولى Dodo Payments إنشاء مفتاح وتسليمه لكل عملية شراء أو مقعد اشتراك تلقائيًا.
</Info>

## ما هي مفاتيح التراخيص؟

مفاتيح التراخيص هي رموز فريدة تسمح بالوصول إلى منتجك. وهي مناسبة لـ:

- **ترخيص البرامج**: تطبيقات سطح المكتب والإضافات وCLIs
- **عناصر التحكم لكل مقعد**: تحديد عدد عمليات التنشيط لكل مستخدم أو جهاز
- **المنتجات الرقمية**: تقييد الوصول إلى التنزيلات أو التحديثات أو الميزات المميزة

داخل Dodo Payments، تتم إدارة مفاتيح التراخيص من خلال نظام [الاستحقاقات](/features/entitlements/introduction)، ما يعني أن دورة حياة كل مفتاح (الإنشاء والانتهاء والإبطال وإعادة المنح) تُدار بواسطة أحداث الدفع والاشتراك نفسها مثل بقية العناصر التي تسلّمها.

## إنشاء استحقاق License Key

<Steps>
<Step title="Open Entitlements">
انتقل إلى **الاستحقاقات** في لوحة تحكم Dodo Payments وانقر على **+** لإنشاء استحقاق جديد.
</Step>

<Step title="Choose License Key">
حدّد **License Key** باعتباره التكامل. اضبط سلوك كل مفتاح يتم إصداره:

- **Activations Limit**: الحد الأقصى لعمليات التنشيط المتزامنة لكل مفتاح (مثلًا، `1` لمستخدم واحد، و`5` لتراخيص الفرق، أو اتركه فارغًا لعدد غير محدود).
- **Duration**: المدة التي يظل فيها المفتاح صالحًا بعد إصداره (مثلًا، 30 يومًا أو سنة واحدة). بالنسبة إلى المفاتيح الصادرة للاشتراكات، اتركه فارغًا؛ إذ تظل المفاتيح صالحة ما دام الاشتراك نشطًا.
- **Activation Instructions**: التعليمات الموجهة إلى العميل والتي تُرسل مع المفتاح عبر البريد الإلكتروني. أمثلة: `Paste the key in Settings → License` أو `Run: mycli activate <key>`.

## إرفاق الاستحقاق بالمنتجات

افتح منتجًا، ووسّع **Advanced Settings → Entitlements & Credits**، ثم حدّد استحقاق License Key. يمكن لمنتج واحد تسليم مفتاح ترخيص إلى جانب استحقاقات أخرى (الوصول إلى Discord وتنزيلات الملفات والوصول إلى مستودع GitHub وغير ذلك) ضمن عملية الشراء نفسها.

## كيفية إصدار المفاتيح

يتبع إصدار المفاتيح [دورة حياة المنح](/features/entitlements/introduction#how-grants-work) القياسية:

| الحدث | السلوك |
|---|---|
| `payment.succeeded` (مرة واحدة) | إنشاء مفتاح واحد لكل `quantity` تم شراؤه. يراعي انتهاء صلاحية المفتاح مدة الاستحقاق. |
| `subscription.active` | إنشاء مفتاح واحد لكل `quantity` (مقعد) في الاشتراك. لا تنتهي صلاحية المفتاح؛ وترتبط صلاحيته بحالة الاشتراك. |
| `subscription.renewed` | لا إجراء. تستمر المفاتيح الحالية. |
| `subscription.on_hold` | تعطيل المفاتيح. وتُعاد تفعيلها عند رفع تعليق الاشتراك. |
| `subscription.cancelled` / `expired` | تعطيل المفاتيح نهائيًا. |
| `subscription.plan_changed` | تعطيل المفاتيح القديمة وإصدار مفاتيح جديدة للخطة الجديدة. |
| `refund.succeeded` (مرة واحدة) | تعطيل المفاتيح. |
| الإبطال اليدوي عبر API/لوحة التحكم | تعطيل المفاتيح باستخدام `revocation_reason: manual`. ولا تتم إعادة منحها تلقائيًا عند تجديد الاشتراك. |
| تعطيل مفتاح الترخيص مباشرةً | إبطال المنحة باستخدام `revocation_reason: license_key_disabled`. تؤدي إعادة تفعيل المفتاح إلى إعادة تفعيل المنحة تلقائيًا. |

### سلوك الكمية

- **منتجات الاشتراك**: إصدار مفتاح واحد لكل مقعد (`subscriptions.quantity`).
- **المنتجات التي تُشترى مرة واحدة**: إصدار مفتاح واحد لكل عنصر في سطر سلة التسوق (`product_cart.quantity`).
- **المنح اليدوية عبر API**: إصدار مفتاح واحد بالضبط.

### وضع التنفيذ

يحتوي كل استحقاق License Key على `fulfillment_mode` الذي يحدد الجهة التي توفّر المفتاح:

- **`auto`** (الافتراضي): ينشئ Dodo Payments المفتاح ويرسله عبر البريد الإلكتروني تلقائيًا عند الدفع أو بدء الاشتراك. هذا هو السلوك الموضح أعلاه، وينطبق عند حذف `fulfillment_mode`.
- **`manual`**: ينشئ الشراء منحة `Pending` بدون مفتاح، وتوفّر أنت قيمة كل مفتاح بنفسك. راجع [التنفيذ اليدوي](#manual-fulfillment) أدناه.

## التنفيذ اليدوي

بشكل افتراضي، ينشئ Dodo Payments مفتاح ترخيص ويرسله عبر البريد الإلكتروني لحظة إتمام العميل للدفع. باستخدام **التنفيذ اليدوي**، توفّر المفتاح بنفسك: ينشئ الشراء منحة `Pending` بدون مفتاح، ويرسل إليك إشعارًا، وينتظر منك إرسال قيمة المفتاح. استخدمه عندما تأتي المفاتيح من نظامك الخاص، أو من مورّد تابع لجهة خارجية، أو من مجموعة محدودة من الرموز المطبوعة مسبقًا.

<Info>
هل تبحث عن طريقة إنشاء خطوة بخطوة؟ راجع [دليل تكامل التنفيذ اليدوي لمفاتيح التراخيص](/developer-resources/manual-license-key-fulfillment) للاطلاع على شرح شامل يبدأ من إنشاء المنتج وينتهي بتسليم المفتاح.
</Info>

### متى تستخدمه

يُعد التنفيذ التلقائي الخيار الافتراضي المناسب لمعظم حالات ترخيص البرامج. اختر التنفيذ اليدوي عندما يتعذر على Dodo Payments إنشاء المفتاح بنفسه:

- **استخدام مفاتيحك الخاصة**: ينشئ المفتاح تطبيقك أو منتج سطح المكتب أو خادم التراخيص الخاص بك.
- **المورّدون الخارجيون**: تعيد بيع مفاتيح يصدرها مزوّد منبع (مفتاح لعبة أو بيانات اعتماد API أو منصة شريكة).
- **المخزون المحدود**: توزع رموزًا من مجموعة مخصصة مسبقًا وتريد تعيينها واحدًا تلو الآخر.
- **المراجعة البشرية**: تريد مراجعة عملية الشراء قبل إتاحة الوصول.

### تفعيل التنفيذ اليدوي

اضبط `fulfillment_mode: "manual"` في إعداد تكامل استحقاق License Key:

<CodeGroup>

```typescript Node.js theme={null}
const entitlement = await client.entitlements.create({
  name: 'Pro License (Manual)',
  integration_type: 'license_key',
  integration_config: {
    fulfillment_mode: 'manual',
    activations_limit: 5,
    duration_count: 1,
    duration_interval: 'Year',
  },
});
```

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/entitlements \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Pro License (Manual)",
    "integration_type": "license_key",
    "integration_config": {
      "fulfillment_mode": "manual",
      "activations_limit": 5,
      "duration_count": 1,
      "duration_interval": "Year"
    }
  }'
```

</CodeGroup>

<Note>
`fulfillment_mode` متوافق مع الإصدارات السابقة. لا تحتوي الاستحقاقات التي أُنشئت قبل توفر هذا الإعداد على `fulfillment_mode`، وتستمر في العمل باعتبارها `auto`. ولا يؤثر التبديل إلى `manual` إلا في المنح التي تُنشأ **بعد** التغيير؛ أما المفاتيح التي تم تسليمها مسبقًا فلا تتأثر.
</Note>

### العثور على المنح التي تنتظر التنفيذ

عندما يشتري العميل منتجًا في الوضع اليدوي، تُنشأ المنحة بالحالة `Pending` بدون مفتاح، ويتم تشغيل webhook [`entitlement_grant.created`](/developer-resources/webhooks/intents/entitlement-grant) مع `integration_type: "license_key"` و`status: "Pending"`. يمكنك الاستجابة لذلك webhook، أو إجراء استقصاء لنقطة النهاية [List Customer Grants](/api-reference/entitlements/list-customer-grants) باستخدام عاملَي التصفية `integration_type` و`status`:

```typescript theme={null}
const pending = await client.customers.listEntitlementGrants('customer_id', {
  integration_type: 'license_key',
  status: 'Pending',
});
```

### تسليم المفتاح

أرسل المفتاح باستخدام نقطة النهاية [Fulfill License Key Grant](/api-reference/entitlements/fulfill-license-key). تنتقل المنحة إلى `Delivered`، ويُرسل المفتاح إلى العميل تلقائيًا — في رسالة البريد الإلكتروني نفسها التي كان سيتلقاها عند استخدام التنفيذ التلقائي.

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/grants/grant_8VbC6JDZ/license-key \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "key": "PRO-AAAA-BBBB-CCCC-DDDD",
    "activations_limit": 5,
    "expires_at": "2027-05-01T00:00:00Z"
  }'
```

يُعد كل من `activations_limit` و`expires_at` اختياريًا، ويُستخدم إعداد الاستحقاق عند حذفه. يمكن تنفيذ كل منحة مرة واحدة؛ وتؤدي إعادة محاولة تنفيذ منحة نُفذت مسبقًا إلى إرجاع `409` بدلًا من إصدار مفتاح ثانٍ.

<Check>
لا تحتاج إلى إرسال المفتاح عبر البريد الإلكتروني بنفسك — إذ يتم التسليم تلقائيًا عند تنفيذ المنحة. ويختلف ذلك عن [استيراد المفاتيح](#import-existing-license-keys-via-api) عبر `POST /license_keys`، الذي لا يرسل إشعارًا إلى العميل عمدًا.
</Check>

## تنشيط الترخيص والتحقق منه وإلغاء تنشيطه

تُعد نقاط نهاية API الخاصة بالتنشيط والتحقق وإلغاء التنشيط **عامة** ولا تتطلب مفتاح API. استخدمها مباشرةً من برامج سطح المكتب أو CLIs أو العملاء المستندين إلى المتصفح للتحقق من المفاتيح أثناء التشغيل.

<Info>
**نقاط النهاية العامة**: نقاط نهاية تنشيط التراخيص وإلغاء تنشيطها والتحقق منها عامة ولا تتطلب مفتاح API. استدعها مباشرةً من تطبيقات العملاء من دون كشف بيانات اعتماد API الخاصة بك.
</Info>

### تنشيط ترخيص

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';

// No API key needed for public license endpoints
const client = new DodoPayments();

const response = await client.licenses.activate({
  license_key: 'PRO-AAAA-BBBB-CCCC-DDDD',
  name: 'Device Name',
});

console.log(response.id);
```

```python Python theme={null}
client.licenses.activate(
    license_key="PRO-AAAA-BBBB-CCCC-DDDD",
    name="Device Name",
)
```

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/licenses/activate \
  -H "Content-Type: application/json" \
  -d '{
    "license_key": "PRO-AAAA-BBBB-CCCC-DDDD",
    "name": "Device Name"
  }'
```

</CodeGroup>

## إدارة المفاتيح

افتح استحقاق License Key من لوحة التحكم لعرض كل منحة (صف واحد لكل مفتاح عميل) مع تاريخ التسليم وعدد عمليات التنشيط وإجراء للإبطال. تعرض تفاصيل كل منحة مفتاح الترخيص الأساسي وتاريخ انتهاء الصلاحية وعمليات التنشيط المستخدمة وحد التنشيط.

يمكنك أيضًا إدراج المنح برمجيًا:

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_license_key_id', {
  status: 'Delivered',
});

for (const grant of grants.items) {
  console.log(grant.license_key.key, grant.license_key.activations_used);
}
```

## استيراد مفاتيح التراخيص الحالية عبر API

هل لديك مفاتيح تراخيص موجودة في نظام آخر؟ استخدم API [Create License Key](/api-reference/licenses/create-license-key) لاستيرادها إلى Dodo Payments. يتيح لك ذلك نقل المفاتيح الحالية من دون التأثير في عملائك — إذ يستمرون في تنشيط المفاتيح والتحقق منها وإلغاء تنشيطها باستخدام سلاسل المفاتيح نفسها من دون إعادة إصدارها.

<Warning>
لا تؤدي مفاتيح التراخيص التي يتم إنشاؤها أو تحديثها عبر API إلى تشغيل إشعارات بريد إلكتروني للعملاء. وإذا احتجت إلى إخطار العملاء بشأن مفتاح مستورد، فتولَّ ذلك بشكل منفصل في تطبيقك.
</Warning>

```typescript theme={null}
const licenseKey = await client.licenseKeys.create({
  customer_id: 'cus_abc123',
  product_id: 'pdt_456',
  key: 'YOUR-EXISTING-LICENSE-KEY',
  activations_limit: 5,
  expires_at: '2026-12-31T23:59:59Z',
});
```

### كيف تختلف المفاتيح حسب المصدر

| الحقل | مفتاح منشأ تلقائيًا | مفتاح نُفذ يدويًا | مفتاح مستورد |
|-------|--------------------|------------------------|--------------|
| `source` | `"auto"` | `"manual"` | `"import"` |
| المصدر | أنشأه Dodo Payments عند الدفع | [وفّرته أنت](#manual-fulfillment) لمنحة معلقة | أُنشئ/نُقل عبر `POST /license_keys` |
| `payment_id` | يُضبط على عملية الدفع الأصلية | يُستخلص من المنحة أو اشتراكها | `null` (من دون معاملة Dodo Payments) |
| `subscription_id` | يُضبط إذا أُصدر عبر اشتراك | يُضبط إذا جاءت المنحة من اشتراك | `null` ما لم يتم ربطه صراحةً |
| إشعار العميل عبر البريد الإلكتروني | يُرسل عند الإصدار | يُرسل عند التنفيذ | لا يُرسل — تولَّ ذلك بشكل منفصل |

استخدم الحقل `source` في استجابات `GET /license_keys` للتمييز بين المخزون المنقول والمفاتيح المنفذة يدويًا والمفاتيح الصادرة تلقائيًا عند المطابقة أو التدقيق.

<Tip>
هل تنتقل من **Polar.sh** أو **Lemon Squeezy**؟ تعمل [`dodo-migrate` CLI](/migrate-to-dodo) على أتمتة عمليات الاستيراد الجماعي للمنتجات والعملاء والخصومات ومفاتيح التراخيص بأمر واحد، وتربط المعرّفات الخارجية بمعرّفات Dodo تلقائيًا.
</Tip>

## مفاتيح التراخيص في عنوان URL للعودة

عند إتمام العميل عملية شراء لمنتج يتضمن استحقاق License Key، يُضاف المفتاح المُنشأ تلقائيًا إلى `return_url` باعتباره معلمة query. يتيح لك ذلك عرض المفتاح فورًا في صفحة النجاح من دون إجراء استدعاء API إضافي.

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com
```

إذا أنشأت عملية الشراء مفاتيح متعددة (quantity > 1)، فستُفصل بينها بفواصل:

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001,LK-002&email=customer%40example.com
```

بالنسبة إلى الاشتراكات، يُستخدم `subscription_id` بدلًا من `payment_id`:

```text theme={null}
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001&email=customer%40example.com
```

<Tip>
حلّل معلمة `license_key` في صفحة العودة لعرض المفتاح فورًا، وتحسين تجربة ما بعد الشراء.
</Tip>

## Webhooks

يؤدي تسليم مفاتيح التراخيص وإبطالها إلى تشغيل أحداث [`entitlement_grant.*` webhook الأربعة](/developer-resources/webhooks/intents/entitlement-grant). تتضمن حمولة المنحة كائن `license_key` مكتملًا يحتوي على المفتاح وتاريخ انتهاء الصلاحية وعمليات التنشيط المستخدمة والحد.

تستمر أحداث `license_key.*` القديمة (`license_key.created`) في التشغيل لدورة حياة سجل مفتاح الترخيص الأساسي؛ راجع [صفحة حمولة License Key webhook](/developer-resources/webhooks/intents/license-key).

<Tip>
للتكاملات الجديدة، استمع إلى `entitlement_grant.delivered` بدلًا من `license_key.created`. يخبرك حدث الاستحقاق بأن التسليم اكتمل عبر جميع التكاملات الموجودة على المنتج، وليس لمفتاح الترخيص فقط.
</Tip>

## مفاتيح التراخيص القديمة

<Note>
تم **ترحيل المنتجات تلقائيًا** التي أُنشئت باستخدام العلامة `license_key_enabled` الأقدم إلى استحقاق License Key. عملية الترحيل شفافة: تستمر مفاتيح العملاء الحاليين في العمل دون تغيير، وتواصل نقاط النهاية العامة `/licenses/activate` و`/licenses/validate` و`/licenses/deactivate` عملها، كما تواصل نقاط نهاية API `/license_keys/*` القراءة والكتابة في مخزن المفاتيح نفسه.

يبقى قسم لوحة التحكم المستقل **License Keys** متاحًا باعتباره قائمة مسطحة بكل مفتاح تم إصداره، وهو مفيد للتدقيق والبحث. ينبغي إجراء الإعدادات الجديدة (تغيير حدود التنشيط أو المدد أو التعليمات) عبر تعديل استحقاق License Key الذي تم ترحيله ضمن **الاستحقاقات**.
</Note>

## أفضل الممارسات

- **اجعل حدود التنشيط واضحة**: اختر قيمًا افتراضية مناسبة (1 لتطبيقات المستخدم الواحد، و3–5 لتراخيص الفرق) ووثّقها.
- **قدّم تعليمات تنشيط دقيقة**: ينسخ العملاء هذه التعليمات من بريدهم الإلكتروني، لذا فإن المسارات والأوامر الدقيقة تقلل طلبات الدعم.
- **تحقق من المفاتيح من جهة الخادم**: بالنسبة إلى المنتجات المتصلة بالشبكة، تحقّق عبر `/licenses/validate` بدلًا من تخزين التنشيط مؤقتًا محليًا.
- **استخدم webhooks للإبطال**: استمع إلى `entitlement_grant.revoked` لتعطيل الميزات داخل التطبيق فورًا عند إلغاء العميل أو استرداد المبلغ.
- **اختبر الاشتراكات والعمليات التي تُشترى مرة واحدة**: يختلف سلوك مفتاح الترخيص بينهما بشكل طفيف، لذا اختبر كليهما قبل الإطلاق.
