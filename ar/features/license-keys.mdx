<Info>
مفاتيح الترخيص هي نوع تمتع بمفتاح الترخيص. أنشئ تمتعات مفتاح ترخيص مرة واحدة مع الحد الأقصى للتفعيل، الانتهاء، والتعليمات التي تريدها، واربطها بأي منتج، وDodo Payments ستولد وتوزع مفتاحًا لكل عملية شراء أو مقعد اشتراك تلقائيًا.
</Info>

## ما هي مفاتيح الترخيص؟

مفاتيح الترخيص هي رموز فريدة تفوض الوصول إلى منتجك. إنها مثالية لـ:

- **ترخيص البرمجيات**: تطبيقات سطح المكتب، المكونات الإضافية، وواجهات سطر الأوامر
- **التحكم حسب المقعد**: تحديد التفعيلات لكل مستخدم أو جهاز
- **السلع الرقمية**: تأمين التنزيلات، التحديثات، أو الميزات المميزة

داخل Dodo Payments، تدار مفاتيح الترخيص من خلال نظام [التمتعات](/features/entitlements/introduction)، مما يعني أن دورة حياة كل مفتاح (الإنشاء، الانتهاء، الإلغاء، إعادة المنح) تُدار بواسطة نفس أحداث الدفع والاشتراك مثل المكونات الأخرى الخاصة بك.

## كيفية إصدار المفاتيح

إصدار المفاتيح يتبع [دورة حياة المنح](/features/entitlements/introduction#how-grants-work) العادية:

| الحدث | السلوك |
|---|---|
| `payment.succeeded` (مرة واحدة) | توليد مفتاح واحد لكل `quantity` يتم شراؤه. انتهاء صلاحية المفتاح يلتزم بمدة التمتع. |
| `subscription.active` | توليد مفتاح واحد لكل اشتراك `quantity` (مقعد). ليس للمفتاح انتهاء صلاحية؛ الصلاحية مرتبطة بحالة الاشتراك. |
| `subscription.renewed` | لا شيء. تستمر المفاتيح الحالية. |
| `subscription.on_hold` | تعطيل المفاتيح. يُعاد تنشيطها عندما يخرج الاشتراك من الحجز. |
| `subscription.cancelled` / `expired` | تعطيل المفاتيح بشكل دائم. |
| `subscription.plan_changed` | تعطيل المفاتيح القديمة؛ إصدار مفاتيح جديدة للخطة الجديدة. |
| `refund.succeeded` (مرة واحدة) | تعطيل المفاتيح. |
| إلغاء يدوي عبر API/لوحة التحكم | تعطيل المفاتيح مع `revocation_reason: manual`. لا يُعاد منحها تلقائيًا عند تجديد الاشتراك. |
| تعطيل مفتاح الترخيص مباشرة | إبطال المنحة بواسطة `revocation_reason: license_key_disabled`. إعادة تمكين المفتاح تعيد تنشيط المنحة تلقائيًا. |


### سلوك الكمية

- **منتجات الاشتراك** تصدر مفتاحًا واحدًا لكل مقعد (`subscriptions.quantity`).
- **المنتجات لمرة واحدة** تصدر مفتاحًا واحدًا لكل عنصر من سلة التسوق (`product_cart.quantity`).
- **المنح اليدوية عبر API** تصدر مفتاحًا واحدًا بالضبط.


## التفعيل، التحقق، إلغاء التفعيل

نقاط النهاية لتفعيل/التحقق/إلغاء التفعيل في الواجهة البرمجية **عامة** ولا تتطلب مفتاح API. استخدمها مباشرة من برامج سطح المكتب، أو CLI، أو عملاء المتصفح للتحقق من المفاتيح في الوقت الفعلي.

<Info>
**نقاط النهاية العامة**: نقاط النهاية للتفعيل، الإلغاء، والتحقق من الترخيص هي عامة ولا تتطلب مفتاح API. قم باستدعائها مباشرة من تطبيقات العميل الخاصة بك دون كشف اعتماديات API الخاصة بك.
</Info>

### تفعيل الرخصة

<CodeGroup>

```typescript TypeScript theme={null}
import DodoPayments from 'dodopayments';

// No API key needed for public license endpoints
const client = new DodoPayments();

const response = await client.licenses.activate({
  license_key: 'PRO-AAAA-BBBB-CCCC-DDDD',
  name: 'Device Name',
});

console.log(response.id);
```

```python Python theme={null}
client.licenses.activate(
    license_key="PRO-AAAA-BBBB-CCCC-DDDD",
    name="Device Name",
)
```

```bash cURL theme={null}
curl -X POST https://test.dodopayments.com/licenses/activate \
  -H "Content-Type: application/json" \
  -d '{
    "license_key": "PRO-AAAA-BBBB-CCCC-DDDD",
    "name": "Device Name"
  }'
```

</CodeGroup>

<CodeGroup>

</CodeGroup>

## إدارة المفاتيح

افتح تمتع مفتاح الترخيص من لوحة المعلومات الخاصة بك لرؤية كل منحة (صف واحد لكل مفتاح عميل) مع تاريخ التسليم، وعدد التفعيلات، وإجراء الإلغاء. يكشف كل تفاصيل المنحة المفتاح الأساسي، والانتهاء، والتفعيلات المستخدمة، وحدود التفعيلات.

يمكنك أيضًا سرد المنح برمجيًا:

```typescript theme={null}
const grants = await client.entitlements.grants.list('ent_license_key_id', {
  status: 'delivered',
});

for (const grant of grants.items) {
  console.log(grant.license_key.key, grant.license_key.activations_used);
}
```

## استيراد مفاتيح ترخيص موجودة عبر API

هل لديك مفاتيح ترخيص بالفعل في نظام آخر؟ استخدم [API إنشاء مفتاح ترخيص](/api-reference/licenses/create-license-key) لاستيرادها إلى Dodo Payments. يتيح لك ذلك نقل المفاتيح الموجودة دون تعطيل عملائك — يستمرون في التفعيل، والتحقق، وإلغاء التفعيل ضد نفس سلاسل المفاتيح بدون إعادة الإصدار.

{/* LOCKED_PATTERN_4907e9f6f7bдадfbf16d5e6c9d83c4eb5b74af72107b43e */}
مفاتيح الترخيص التي تم إنشاؤها أو تحديثها عبر API لا تؤدي إلى إرسال إشعارات بريدية إلى العملاء. إذا كنت بحاجة إلى إخطار العملاء بشأن مفتاح مستورد، تعامل مع ذلك بشكل منفصل في تطبيقك.
{/* LOCKED_PATTERN_176d815432e7554ac558e8631b2bc397 */}

```typescript theme={null}
const licenseKey = await client.licenseKeys.create({
  customer_id: 'cus_abc123',
  product_id: 'prod_456',
  key: 'YOUR-EXISTING-LICENSE-KEY',
  activations_limit: 5,
  expires_at: '2026-12-31T23:59:59Z',
});
```

### كيفية اختلاف المفاتيح المستوردة عن المفاتيح المنتجة تلقائيًا

| الحقل | مفتاح منتج تلقائيًا | مفتاح مستورد |
|-------|--------------------|--------------|
| `source` | `"auto"` | `"import"` |
| `payment_id` | تعيين حسب الدفع الأصلي | `null` (بدون معاملة Dodo Payments) |
| `subscription_id` | تم تعيينه إذا صدر المفتاح عبر اشتراك | `null` ما لم يتم ربطه صراحة |
| إشعار بريد إلكتروني للعميل | تم إرساله عند الإصدار | لم يُرسل - تعامل مع ذلك بشكل منفصل |


استخدم الحقل `source` على ردود `GET /license_keys` لتمييز المخزون المنقول عن المفاتيح المصدرة عضوياً عند التسوية أو المراجعة.

<Tip>
هل تهاجر من **Polar.sh** أو **Lemon Squeezy**؟ تقوم [CLI `dodo-migrate`](/migrate-to-dodo) تلقائيًا بعمليات استيراد جماعية للمنتجات، والعملاء، والخصم, ومفاتيح الترخيص في أمر واحد وتعيين معرفات خارجية إلى معرفات Dodo تلقائيًا.
</Tip>

## مفاتيح الترخيص في عنوان URL العائد

عندما يكمل العميل شراء منتج يحتوي على تمتع مفتاح ترخيص، يُضاف المفتاح المنشأ تلقائيًا إلى `return_url` الخاص بك كعنصر استعلام. يتيح لك ذلك عرض المفتاح فورًا على صفحة النجاح الخاصة بك دون إجراء مكالمة API إضافية.

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com
```

إذا كان الشراء ينتج مفاتيح متعددة (الكمية > 1)، فسيتم فصلها بواسطة فاصلة:

```text theme={null}
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001,LK-002&email=customer%40example.com
```

للاشتراكات، يستخدم `subscription_id` بدلاً من `payment_id`:

```text theme={null}
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001&email=customer%40example.com
```

<Tip>
حلل عنصر `license_key` على صفحة العودة الخاصة بك لعرض المفتاح فورًا، مما يحسن من تجربة ما بعد الشراء.
</Tip>

## الوصلات الشبكية

إصدار وإلغاء مفتاح الترخيص تثير أربعة [أحداث webhook](/developer-resources/webhooks/intents/entitlement-grant). تتضمن الحمولة منحة مملوءة بـ `license_key` مع المفتاح، الانتهاء، والتفعيلات المستخدمة، والحدود.

تواصل أحداث `license_key.*` (`license_key.created`) القديمة الانتقال لدورة حياة سجل مفتاح الترخيص الأساسي؛ انظر [صفحة حمل نظام الويب لمفتاح الترخيص](/developer-resources/webhooks/intents/license-key).

<Tip>
للتكاملات الجديدة، استمع إلى `entitlement_grant.delivered` بدلاً من `license_key.created`. يخبرك حدث التمتع بأن التسليم قد اكتمل عبر جميع التكاملات على المنتج، وليس فقط مفتاح الترخيص.
</Tip>

## مفاتيح الترخيص القديمة

<Note>
تم **نقل المنتجات** التي تم إنشاؤها باستخدام العلامة القديمة `license_key_enabled` تلقائيًا إلى تمتع بمفتاح ترخيص. التحويل شفاف: تواصل مفاتيح العملاء الحالية العمل دون تغيير، نقاط النهاية العامة `/licenses/activate`، `/licenses/validate`، `/licenses/deactivate` تواصل العمل، ونقاط النهاية API `/license_keys/*` تواصل القراءة والكتابة إلى نفس متجر المفتاح.


لا يزال قسم مفتاح الترخيص المنفصل في لوحة التحكم متاحًا كقائمة مسطحة لكل مفتاح تم إصداره، مفيدة للمراجعة والبحث. يجب إجراء التكوين الجديد (تغيير حدود التفعيل، المدد، أو التعليمات) من خلال تحرير تمتع مفتاح الترخيص المحول تحت **التمتعات**.
</Note>

## أفضل الممارسات

- **احتفظ بوضوح حدود التفعيل**: اختر إعدادات افتراضية معقولة (1 لتطبيقات المستخدم الفردي، و3-5 لتراخيص الفريق) ووثقها.
- **قدم تعليمات تفعيل دقيقة**: يقوم العملاء بلصق هذه التعليمات من بريدهم الإلكتروني، لذا توفر المسارات والأوامر الدقيقة طلبات الدعم.
- **تحقق من المفاتيح على الجانب الخادم**: للمنتجات المتصلة بالشبكة، تحقق عبر `/licenses/validate` بدلاً من تخزين التفعيل محليًا.
- **استخدم الوصلات الشبكية للإلغاء**: استمع إلى `entitlement_grant.revoked` لتعطيل ميزات التطبيق مباشرة عند إلغاء العميل أو استرداده.
- **اختبر مع الاشتراكات والمعاملات لمرة واحدة**: تختلف سلوكيات مفاتيح الترخيص بشكل طفيف بين الاثنين، لذا اختبر كليهما قبل الانطلاق.
