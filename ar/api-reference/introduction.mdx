## إدارة مفاتيح API والمصادقة

<Steps>
<Step title="الوصول إلى مفاتيح API">
انتقل إلى **المطور → مفاتيح API** في لوحة التحكم الخاصة بك لإدارة مفاتيحك.
</Step>

<Step title="إنشاء مفتاح جديد">
اختر **إضافة مفتاح API**، وقدم اسمًا وصفيًا، وقم بتكوين الوصول للكتابة:

- **تمكين الوصول للكتابة** (محدد): أذونات قراءة وكتابة كاملة لجميع عمليات API
- **تمكين الوصول للكتابة** (غير محدد): وصول للقراءة فقط - يمكن فقط جلب البيانات (المدفوعات، الاشتراكات، العملاء، المنتجات). لا يمكن إنشاء أو تعديل الموارد.

<Tip>
قم بإلغاء تحديد "تمكين الوصول للكتابة" للتكاملات في لوحة التحكم، وأدوات التحليل، وأي نظام يحتاج فقط إلى عرض البيانات دون إجراء تغييرات.
</Tip>
</Step>

<Step title="تخزين مفتاحك بأمان">
انسخ المفتاح الذي تم إنشاؤه على الفور وتأكد من تخزينه بأمان.
</Step>

<Step title="المصادقة على طلبات API الخاصة بك">
استخدم مفاتيح API الخاصة بك للمصادقة على جميع الطلبات. طبق تنسيق التفويض التالي:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
لا تكشف أبدًا عن مفاتيح API السرية الخاصة بك في كود جانب العميل أو المستودعات العامة.
</Warning>
</Step>
</Steps>

## حدود المعدل

يستخدم واجهة البرمجة الخاصة بنا نظام تحديد معدل ثنائي النوافذ مع حماية من انفجارات الطلبات. يتم تطبيق الحدود بناءً على طريقة المصادقة الخاصة بك وطبقة الأعمال.

### الحدود الافتراضية (الطبقة 0)

| النافذة | الحد |
|--------|-------|
| في الثانية (انفجار) | 40 طلب |
| في الدقيقة (مستدام) | 240 طلب |

### طبقات الأعمال

تتوفر حدود معدلات أعلى للأعمال التي لديها احتياجات متزايدة من واجهة البرمجة:

| الطبقة | الانفجار (في الثانية) | المستدام (في الدقيقة) |
|------|-------------------|------------------------|
| الطبقة 0 (افتراضية) | 40 | 240 |
| الطبقة 1 | 100 | 1,000 |
| الطبقة 2 | 500 | 5,000 |

<Tip>
اتصل بالدعم لترقية عملك إلى طبقة حد معدل أعلى.
</Tip>

### الطلبات غير المصادق عليها

يتم تحديد الطلبات بدون رؤوس مصادقة صالحة بواسطة عنوان IP:

| النافذة | الحد |
|--------|-------|
| في الثانية (انفجار) | 20 طلب |
| في الدقيقة (مستدام) | 100 طلب |

### رؤوس حد المعدل

راقب استخدامك باستخدام رؤوس الاستجابة هذه:

- `X-RateLimit-Limit` - أقصى عدد من الطلبات المسموح بها
- `X-RateLimit-Remaining` - الطلبات المتبقية في النافذة الحالية
- `X-RateLimit-Reset` - الوقت الذي يتم فيه إعادة تعيين حد المعدل

<Note>
عندما تتجاوز حدود المعدلات، تقوم واجهة البرمجة بإرجاع استجابة `429 Too Many Requests`. نفذ استراتيجية موازنة الانفجار في منطق إعادة المحاولة الخاص بك.
</Note>
