## إدارة مفاتيح API والمصادقة

<Steps>
<Step title="Access API Keys">
انتقل إلى **Developer → API Keys** في لوحة التحكم لإدارة مفاتيحك.
</Step>

<Step title="Generate a New Key">
حدد **Add API Key**، وأدخل اسمًا وصفيًا، واضبط صلاحية الكتابة:

- **Enable write access** (محدد): صلاحيات قراءة وكتابة كاملة لجميع عمليات API
- **Enable write access** (غير محدد): وصول للقراءة فقط - يمكنه جلب البيانات فقط (المدفوعات والاشتراكات والعملاء والمنتجات). ولا يمكنه إنشاء الموارد أو تعديلها.

<Tip>
ألغِ تحديد "Enable write access" لتكاملات لوحة التحكم وأدوات التحليلات وأي نظام يحتاج فقط إلى عرض البيانات دون إجراء تغييرات.
</Tip>
</Step>

<Step title="Store Your Key Securely">
انسخ المفتاح الذي تم إنشاؤه فورًا وتأكد من تخزينه بأمان.
</Step>

<Step title="Authenticate Your API Requests">
استخدم مفاتيح API للمصادقة على جميع الطلبات. طبّق تنسيق التفويض التالي:

```bash 
Authorization: Bearer YOUR_API_KEY
```

<Warning>
لا تكشف أبدًا عن مفاتيح API السرية في التعليمات البرمجية من جانب العميل أو في المستودعات العامة.
</Warning>
</Step>
</Steps>

## حدود المعدل

تستخدم API لدينا نظامًا مزدوج النوافذ للحد من المعدل مع حماية من الاندفاعات. تُطبّق الحدود استنادًا إلى طريقة المصادقة وطبقة نشاطك التجاري.

### الحدود الافتراضية (Tier 0)

| النافذة | الحد |
|--------|-------|
| لكل ثانية (اندفاعي) | 40 طلبًا |
| لكل دقيقة (مستمر) | 240 طلبًا |

### طبقات النشاط التجاري

تتوفر حدود معدل أعلى للأنشطة التجارية التي لديها احتياجات API متزايدة:

| الطبقة | الاندفاع (لكل ثانية) | المستمر (لكل دقيقة) |
|------|-------------------|------------------------|
| Tier 0 (الافتراضية) | 40 | 240 |
| Tier 1 | 100 | 1,000 |
| Tier 2 | 500 | 5,000 |

<Tip>
تواصل مع الدعم لترقية نشاطك التجاري إلى طبقة أعلى لحد المعدل.
</Tip>

### الطلبات غير المصادق عليها

تُحدَّد معدلات الطلبات التي لا تتضمن ترويسات مصادقة صالحة استنادًا إلى عنوان IP:

| النافذة | الحد |
|--------|-------|
| لكل ثانية (اندفاعي) | 20 طلبًا |
| لكل دقيقة (مستمر) | 100 طلب |

### ترويسات حد المعدل

راقب استخدامك باستخدام ترويسات الاستجابة التالية:

- `X-RateLimit-Limit` - الحد الأقصى للطلبات المسموح بها
- `X-RateLimit-Remaining` - الطلبات المتبقية في النافذة الحالية
- `X-RateLimit-Reset` - وقت إعادة ضبط حد المعدل

<Note>
عند تجاوز حدود المعدل، تُرجع API استجابة `429 Too Many Requests`. طبّق التراجع الأسي في منطق إعادة المحاولة.
</Note>
