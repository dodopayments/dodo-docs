Gerencie seus recursos do Dodo Payments, crie sessões de checkout e teste webhooks diretamente do terminal. Construído para desenvolvedores que preferem a linha de comando.

## Instalação

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

### Instalação Manual

1. Baixe a versão mais recente de [GitHub Releases](https://github.com/dodopayments/dodopayments-cli/releases) para o seu sistema
2. Extraia e renomeie o binário para `dodo`
3. Mova para um diretório no seu PATH:

<CodeGroup>

```bash Linux
sudo mv ./dodo /usr/local/bin/
```

```text Windows
move .\dodo C:\Windows\System32\dodo
```

</CodeGroup>

## Autenticação

Antes de usar o CLI, autentique-se com sua chave API:

```bash
dodo login
```

Isso irá:
1. Abrir seu navegador na página de Chaves de API do Dodo Payments
2. Solicitar que você insira sua Chave API
3. Pedir que você selecione o ambiente (**Modo de Teste** ou **Modo Ao Vivo**)
4. Armazenar suas credenciais localmente em `~/.dodopayments/api-key`

<Info>
O CLI suporta armazenar uma chave API por ambiente. Se ambas as chaves do modo de teste e ao vivo estiverem configuradas, você será solicitado a escolher qual ambiente usar na sessão atual.
</Info>

## Uso

A sintaxe geral é:

```bash
dodo ‹category› ‹sub-command›
```

Executar `dodo` sem argumentos exibe todas as categorias disponíveis. Executar `dodo <category>` sem subcomando mostra os subcomandos disponíveis para essa categoria.

### Produtos

Gerencie seu catálogo de produtos.

| Comando | Descrição |
|---------|-------------|
| `dodo products list` | Liste todos os produtos (paginado) |
| `dodo products create` | Abra o painel para criar um produto |
| `dodo products info` | Veja os detalhes de um produto específico |

### Pagamentos

Veja transações de pagamento.

| Comando | Descrição |
|---------|-------------|
| `dodo payments list` | Liste todos os pagamentos (paginado) |
| `dodo payments info` | Obtenha informações sobre um pagamento específico |

### Clientes

Gerencie sua base de clientes.

| Comando | Descrição |
|---------|-------------|
| `dodo customers list` | Liste todos os clientes (paginado) |
| `dodo customers create` | Crie um novo perfil de cliente |
| `dodo customers update` | Atualize os detalhes de um cliente existente |

### Descontos

Gerencie cupons e descontos.

| Comando | Descrição |
|---------|-------------|
| `dodo discounts list` | Liste todos os descontos (paginado) |
| `dodo discounts create` | Crie um novo desconto baseado em porcentagem |
| `dodo discounts delete` | Remova um desconto pelo ID |

### Licenças

Gerencie licenças de software.

| Comando | Descrição |
|---------|-------------|
| `dodo licences list` | Liste todas as chaves de licença (paginado) |

### Complementos

Gerencie complementos de produtos.

| Comando | Descrição |
|---------|-------------|
| `dodo addons list` | Liste todos os complementos (paginado) |
| `dodo addons create` | Abra o painel para criar um complemento |
| `dodo addons info` | Veja os detalhes de um complemento específico |

### Reembolsos

Veja informações sobre reembolsos.

| Comando | Descrição |
|---------|-------------|
| `dodo refund list` | Liste todos os reembolsos (paginado) |
| `dodo refund info` | Veja os detalhes de um reembolso específico |

### Checkout

Crie sessões de checkout.

| Comando | Descrição |
|---------|-------------|
| `dodo checkout new` | Crie uma nova sessão de checkout e obtenha a URL do checkout |

O comando de checkout suporta opções avançadas incluindo coleta mínima de endereço, URL de retorno, exigência de 3D Secure, códigos de desconto e metadados.

## Teste de Webhook

O CLI inclui duas ferramentas poderosas para testar webhooks durante o desenvolvimento: um **ouvinte** que encaminha webhooks de teste ao vivo para seu servidor local, e um **disparador** que envia cargas úteis de webhook fictícias para qualquer endpoint.

### Ouvir Webhooks

Encaminhe webhooks do Dodo Payments diretamente para seu servidor de desenvolvimento local em tempo real.

```bash
dodo wh listen
```

<Steps>
<Step title="Insira sua URL de endpoint local">
  Forneça a URL local onde deseja receber webhooks (por exemplo, `http://localhost:3000/webhook`).
</Step>

<Step title="Configuração automática">
  O CLI cria automaticamente um endpoint de webhook na sua conta do Dodo Payments se um não existir, e então abre uma conexão WebSocket para receber eventos em tempo real.
</Step>

<Step title="Receber e encaminhar">
  Quando um evento de webhook é disparado (de um pagamento de teste, alteração de assinatura, etc.), o CLI o recebe, registra o tipo de evento, e encaminha a solicitação completa com cabeçalhos e corpo para seu endpoint local. A resposta do seu endpoint é registrada e enviada de volta.
</Step>
</Steps>

<Warning>
O ouvinte de webhook só funciona com uma chave API de **modo de teste**. Certifique-se de que você está autenticado com uma chave de modo de teste antes de usar `dodo wh listen`.
</Warning>

<Tip>
O ouvinte preserva os cabeçalhos originais do webhook (`webhook-id`, `webhook-signature`, `webhook-timestamp`) ao encaminhar para seu endpoint local, para que você possa testar sua lógica de verificação de assinatura.
</Tip>

### Disparar Webhooks de Teste

Envie cargas úteis fictícias de webhook para qualquer endpoint para testes rápidos sem precisar criar transações reais.

```bash
dodo wh trigger
```

Isso orienta você por:
1. Definindo uma **URL de endpoint** de destino
2. Opcionalmente configurando **ID da Empresa**, **ID do Produto** e **Metadados**
3. Selecionando um **evento** específico para disparar de um menu interativo
4. Enviando a carga útil fictícia e visualizando a resposta

Após cada evento, você pode selecionar outro evento para disparar ou sair -- facilitando o teste de múltiplos manipuladores de eventos em uma sessão.

<Warning>
A ferramenta de disparo envia cargas úteis fictícias sem assinaturas de webhook. Desative a verificação de assinatura do webhook durante o teste usando `unsafe_unwrap()` em vez de `unwrap()` em seu manipulador de webhook.
</Warning>

### Eventos de Webhook Suportados

| Categoria | Eventos |
|----------|--------|
| **Assinatura** | `subscription.active`, `subscription.updated`, `subscription.on_hold`, `subscription.renewed`, `subscription.plan_changed`, `subscription.cancelled`, `subscription.failed`, `subscription.expired` |
| **Pagamento** | `payment.success`, `payment.failed`, `payment.processing`, `payment.cancelled` |
| **Reembolso** | `refund.success`, `refund.failed` |
| **Disputa** | `dispute.opened`, `dispute.expired`, `dispute.accepted`, `dispute.cancelled`, `dispute.challenged`, `dispute.won`, `dispute.lost` |
| **Licença** | `licence.created` |

### Variáveis de Ambiente

| Variável | Descrição |
|----------|-------------|
| `DODO_WH_TEST_SERVER_URL` | Substituir a URL do servidor de retransmissão de webhook padrão usado por `dodo wh listen` |
