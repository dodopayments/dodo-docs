O Dodo Agent Plugin conecta dois servidores MCP e dezessete skills de integração ao seu agente de programação com IA em uma única instalação. Ele funciona com **Claude Code**, **Codex CLI**, **Cursor**, **VS Code / GitHub Copilot**, **Kiro** e **OpenCode**. O **Gemini CLI** recebe apenas os dois servidores MCP. Os servidores MCP e o CLI de skills funcionam com qualquer cliente compatível com MCP.

O plugin segue a especificação [Agent Plugins 1.0.0](https://agent-plugins.org/specification), portanto clientes com suporte nativo o carregam diretamente da raiz `plugin.json` e `mcp.json`. Clientes anteriores à especificação carregam o mesmo conteúdo por meio de manifestos de compatibilidade gerados.

<Info>
**Três componentes básicos, um plugin.** O Agent Plugin reúne tudo de que você precisa:
- **Servidor MCP de API** — acesso em tempo real a pagamentos, assinaturas, clientes, produtos, reembolsos, licenças e uso. Autentica por OAuth no navegador (não são necessárias chaves locais).
- **Servidor MCP de conhecimento** — pesquisa semântica em toda a documentação do Dodo Payments. Não são necessárias credenciais.
- **Dezessete skills de agente** — guias rápidos que o agente carrega sob demanda para checkout, assinaturas, webhooks, cobrança baseada em uso e em créditos, chaves de licença, catálogo de produtos, descontos, preços localizados, checkout mobile, reembolsos e disputas, gerenciamento de clientes, adaptadores de frameworks, BillingSDK, Better Auth, testes e entrada em produção, além de práticas recomendadas.
</Info>

## Instale o plugin

Escolha seu agente de programação abaixo. Cada instalação adiciona os dois servidores MCP; todos, exceto o Gemini CLI, também adicionam as dezessete skills.

<AccordionGroup>
<Accordion title="Claude Code" defaultOpen>
Instale pelo marketplace:

```bash
claude plugins marketplace add dodopayments/dodo-agent-plugin
claude plugins install dodopayments@dodopayments
```

O servidor MCP de API usa OAuth no navegador por padrão — nenhuma chave é necessária no momento da instalação. Na primeira vez que seu agente chamar uma ferramenta do Dodo, será solicitado que você faça login.

  Código-fonte, opções de configuração e instruções para desenvolvimento local
</Card>
</Accordion>

<Accordion title="Codex CLI">
O Codex instala plugins em duas etapas: registre o marketplace pelo shell e, em seguida, instale o plugin dentro da TUI do Codex.

<Steps>
<Step title="Register the marketplace">

```bash
codex plugin marketplace add dodopayments/dodo-agent-plugin
```

</Step>

<Step title="Install from the Codex TUI">
Abra o Codex e execute o comando de barra `/plugins`:

```bash
codex
```

Depois, digite `/plugins`, alterne para o marketplace **Dodo Payments**, selecione o plugin **dodopayments** e escolha **Install plugin**.
</Step>
</Steps>

Os dois servidores MCP e todas as dezessete skills são registrados automaticamente assim que o plugin é instalado.

<Note>
O Codex CLI não tem um subcomando `codex plugin install` — a instalação do plugin sempre ocorre pelo fluxo `/plugins` dentro da TUI. Consulte a [documentação oficial de plugins do Codex](https://developers.openai.com/codex/plugins).
</Note>

Se você já adicionou o marketplace e o plugin não aparecer em `/plugins`, atualize-o:

```bash
codex plugin marketplace upgrade dodopayments
```

</Accordion>

<Accordion title="Cursor">
Instalação manual — clone o repositório no diretório de plugins local do Cursor:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git ~/.cursor/plugins/local/dodo-agent-plugin
```

Reinicie o Cursor. O plugin carrega as skills de `skills/` e os servidores MCP de `.mcp.json`, conforme declarado em `.cursor-plugin/plugin.json`.

<Info>
Versões recentes do Cursor também reconhecem diretamente o Agent Plugins 1.0.0 e aceitam `.cursor-plugin/marketplace.json` ou `.claude-plugin/marketplace.json` como fonte de marketplace. Este plugin inclui `.claude-plugin/marketplace.json` — use esse caminho. O `.cursor-plugin/plugin.json` gerado é mantido para versões mais antigas.
</Info>

<Warning>
Versões anteriores à 0.5.0 incluíam `skills/` como links simbólicos para um submódulo git, portanto esse clone produzia um plugin com **skills sem funcionamento**. As skills agora são distribuídas como arquivos reais. Se você instalou uma versão anterior, exclua o diretório e faça o clone novamente.
</Warning>
</Accordion>

<Accordion title="OpenCode">
O OpenCode é distribuído via npm. Adicione o plugin ao seu `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"]
}
```

Reinicie o OpenCode. Os dois servidores MCP (`dodopayments-api`, `dodo-knowledge`) são registrados automaticamente pelo hook de configuração do plugin. Nenhum bloco `mcp` manual é necessário.

**As skills precisam de uma linha adicional.** O OpenCode não pesquisa skills nos pacotes instalados, portanto aponte manualmente para o diretório `skills/` do pacote:

```bash
npm install --save-dev @dodopayments/opencode-plugin
```

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "skills": {
    "paths": ["node_modules/@dodopayments/opencode-plugin/skills"]
  }
}
```

As entradas `skills.paths` relativas são resolvidas em relação ao **diretório do projeto**, portanto o pacote precisa existir no `node_modules` desse projeto — o cache de plugins do próprio OpenCode fica em outro local. Um caminho absoluto também funciona e evita a exigência de instalação local.

<Warning>
Um caminho de skills inexistente é ignorado **silenciosamente**. Verifique em vez de presumir:

```bash
opencode run "List every skill available to you by name."
```

Você deverá ver todas as dezessete. Versões anteriores à 0.5.0 documentavam essas skills como descobertas automaticamente — isso não acontecia, então usuários do OpenCode tinham servidores MCP, mas nenhuma skill.
</Warning>
</Accordion>

<Accordion title="VS Code / GitHub Copilot">
Clone o repositório em qualquer local e registre-o:

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

Abra a visualização Chat, acesse **Plugins** e adicione a pasta clonada. Você também pode registrá-la diretamente em `settings.json`:

```json
{
  "chat.pluginLocations": { "~/dodo-agent-plugin": true }
}
```

A chave é um caminho; o valor o habilita. Caminhos absolutos e `~/` também funcionam; um caminho relativo é resolvido em relação a cada pasta do workspace. A configuração é lida em tempo real, portanto uma janela em execução a aplica sem reinicialização. As skills são carregadas de `skills/`, e os dois servidores MCP são carregados de `.mcp.json`.

<Note>
`chat.pluginLocations` é marcado como **experimental** e é uma configuração *restrita*, portanto o workspace precisa ser confiável para que ela seja aplicada. O suporte a agent-plugin em geral é um recurso de pré-visualização governado por `chat.plugins.enabled`, que fica **ativado por padrão** — você só precisa defini-lo se sua organização o desabilitar por política.
</Note>

<Info>
O VS Code não usa o Agent Plugins `$schema` como chave. Seu carregador verifica `.plugin/plugin.json`, depois `.claude-plugin/plugin.json` e, em seguida, uma raiz `plugin.json`; por padrão, usa `.mcp.json` para MCP em vez de `mcp.json`. Como este repositório inclui um `.claude-plugin/plugin.json` gerado, o VS Code o carrega por esse caminho de compatibilidade e obtém a ponte `mcp-remote` em vez dos transportes nativos em `mcp.json`. Tudo funciona — o caminho é diferente.
</Info>
</Accordion>

<Accordion title="Kiro">
O Kiro lê o manifesto do Agent Plugins nativamente e o carrega como um Power.

<Steps>
<Step title="Clone the repository">

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git
```

</Step>

<Step title="Open the Powers panel">
No Kiro, abra o painel Powers — o ícone do Ghosty com o raio.
</Step>

<Step title="Import the folder">
Escolha **Add Custom Power → Import power from a folder**, selecione o diretório clonado (aquele que contém `plugin.json`) e clique em **Install**.
</Step>
</Steps>

As skills são carregadas de `skills/`, os servidores MCP de `mcp.json`, e a apresentação específica do Kiro vem do namespace de extensão `dev.kiro` em `plugin.json`.

<Note>
Para plugins no formato Agent Plugins, o Kiro gerencia os servidores MCP internamente — eles **não** são gravados no `~/.kiro/settings/mcp.json` no nível do usuário, portanto não espere encontrá-los lá. O Kiro também pode instalar um Power diretamente de uma URL do GitHub; consulte a [documentação de instalação do Kiro](https://kiro.dev/docs/powers/installation/).
</Note>
</Accordion>

<Accordion title="Gemini CLI (MCP only)">
O Gemini CLI não tem uma primitiva de agent-skill, portanto **apenas os dois servidores MCP estão disponíveis** — as dezessete skills não estão. `dodo-knowledge` ainda cobre boa parte do que as skills oferecem e permanece atualizado automaticamente.

```bash
git clone https://github.com/dodopayments/dodo-agent-plugin.git \
  ~/.gemini/extensions/dodopayments
```

Reinicie o Gemini CLI. `gemini-extension.json` na raiz do repositório é o manifesto.
</Accordion>
</AccordionGroup>

</Info>

## O que você recebe

Depois que o plugin é instalado, seu agente tem acesso a dois servidores MCP e dezessete skills.

### Servidores MCP

| Servidor | Finalidade | Autenticação |
|--------|---------|------|
| `dodopayments-api` | Acesso à API em tempo real — pagamentos, assinaturas, clientes, produtos, reembolsos, licenças e uso | OAuth (navegador) |
| `dodo-knowledge` | Pesquisa semântica em toda a documentação do Dodo Payments | Nenhuma |

Ambos os servidores usam Streamable HTTP. O `mcp.json` canônico os declara nativamente (`type: "streamable-http"`), que é o formato usado por clientes nativos da especificação, como Codex CLI e Kiro. O manifesto de compatibilidade gerado `.mcp.json` conecta os mesmos dois endpoints por meio de `mcp-remote`, permitindo que também sejam executados em clientes que não conseguem acessar o Streamable HTTP diretamente — Claude Code, VS Code e Cursor pelo clone do git documentado acima, cujo `.cursor-plugin/plugin.json` aponta para `.mcp.json`.

### Skills de agente

| Skill | Descrição |
|-------|-------------|
| `dodo-best-practices` | Configuração do SDK, ambientes, chaves de API e a arquitetura canônica de checkout a webhook |
| `framework-adapters` | Handlers de rota oficiais `@dodopayments/*` para Next.js, Express, Hono, Astro, Remix, SvelteKit, Nuxt, Fastify, TanStack, Bun e Convex |
| `testing-and-go-live` | Modo de teste, métodos de pagamento de teste, testes de webhook e checklist de lançamento em produção |
| `checkout-integration` | Checkout Sessions, links de pagamento e checkout em overlay ou inline |
| `subscription-integration` | Ciclo de vida de assinaturas, períodos de teste, alterações de planos, rateio proporcional e cobranças sob demanda |
| `mobile-checkout` | Checkout no aplicativo para React Native, Flutter, iOS e Android |
| `webhook-integration` | Recebimento e verificação de webhooks usando a especificação Standard Webhooks |
| `credit-based-billing` | Direitos de crédito, saldos, ledger, rollover, excedentes e dedução baseada em medidores |
| `usage-based-billing` | Medidores, ingestão de eventos, agregação e preços por unidade |
| `license-keys` | Ativação e validação de chaves de licença e gerenciamento de instâncias |
| `product-catalog-management` | Produtos, preços, complementos, coleções, imagens e entrega de produtos digitais |
| `discounts-and-promotions` | Códigos de desconto, regras de elegibilidade, combinação e limites por ciclo de assinatura |
| `localized-pricing` | Preços localizados, Adaptive Currency e paridade do poder de compra |
| `customer-management` | Clientes, portal de autoatendimento, métodos de pagamento salvos e carteiras |
| `refunds-and-disputes` | Emissão de reembolsos, tratamento de disputas e chargebacks e reconciliação de acesso |
| `billing-sdk` | Componentes React do BillingSDK para tabelas de preços e interface de cobrança |
| `better-auth-integration` | O plugin `@dodopayments/better-auth` para sincronização de clientes, checkout e acesso ao portal |

As skills são carregadas automaticamente — seu agente escolhe a correta ao detectar uma tarefa relevante. Consulte a [documentação de Agent Skills](/developer-resources/agent-skills) para ver a lista completa e a instalação individual.

### Experimente este prompt primeiro

Depois que o plugin estiver ativo, experimente:

```
Set up Dodo Payments webhook handlers in my Next.js app for payment.succeeded and subscription.active events.
```

Seu agente carregará a skill `webhook-integration`, usará o MCP `dodo-knowledge` para obter os formatos de payload mais recentes e escreverá um handler com verificação de assinatura seguindo a especificação Standard Webhooks.

## Suporte a clientes

### Clientes com instalação do Agent Plugin

Uma instalação conecta os dois servidores MCP, além das skills em cada cliente que tem uma primitiva de skills.

| Agente | Instalação | Skills | Servidores MCP |
|-------|---------|-------:|------------:|
| **Claude Code** | comando do marketplace | 17 | 2 |
| **Codex CLI** | comando do marketplace | 17 | 2 |
| **Cursor** | clone do git | 17 | 2 |
| **VS Code / GitHub Copilot** | clone do git | 17 | 2 |
| **Kiro** | clone do git | 17 | 2 |
| **OpenCode** | npm | 17 | 2 |
| **Gemini CLI** | clone do git | 0 | 2 |

- O **OpenCode** precisa de uma entrada `skills.paths` adicional antes que suas dezessete skills sejam carregadas — consulte a seção de instalação acima.
- O **Gemini CLI** não tem uma primitiva de agent-skill, portanto as skills não estão disponíveis por definição.

### Outros clientes compatíveis com MCP

Estes não têm instalação do Agent Plugin. Configure manualmente os dois servidores MCP e adicione skills pelo Skills CLI quando houver suporte.

| Agente | Servidores MCP | Skills |

| Claude Desktop | [Guia do MCP Server](/developer-resources/mcp-server) | não compatível |
| Windsurf | [Guia do MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |
| Cline / Zed / outros | [Guia do MCP Server](/developer-resources/mcp-server) | [Skills CLI](/developer-resources/agent-skills) |

## Segurança e práticas recomendadas

<Warning>
**Nunca confirme chaves de API de produção no repositório.** Use o [modo de teste](/miscellaneous/test-mode-vs-live-mode) durante o desenvolvimento. O Agent Plugin usa OAuth no navegador por padrão — alterne para chaves de API locais somente se o seu fluxo exigir isso.
</Warning>

- **Use primeiro o modo de teste.** Coloque sua integração em sandbox com chaves `dodo_test_...` antes de entrar em produção. Consulte [Modo de teste versus modo live](/miscellaneous/test-mode-vs-live-mode).
- **OAuth é o padrão.** O Agent Plugin autentica por OAuth no navegador (sem segredos locais). Use o modo com chave de API somente se necessário — consulte a seção Configurar abaixo.
- **Revise o código gerado pelo agente.** Sempre verifique se os handlers de webhook incluem verificação de assinatura seguindo a [especificação Standard Webhooks](https://standardwebhooks.com/).

## Configure com uma chave de API

Por padrão, o Agent Plugin usa o servidor MCP remoto com OAuth no navegador — não são necessárias credenciais locais. Se o seu fluxo exigir uma chave de API local (por exemplo, ambientes de CI ou servidores sem interface), você pode alternar para o modo stdio.

<AccordionGroup>
<Accordion title="Local API key mode — Claude Code">
Abra `/plugins` no Claude Code, selecione **Dodo Payments** e escolha **Configure options**. Preencha:

- `dodo_api_key` — sua chave `dodo_test_...` ou `dodo_live_...`
- `dodo_webhook_key` — seu segredo de assinatura de webhook
- `dodo_environment` — `test_mode` ou `live_mode`

Depois, edite `.mcp.json` para apontar `dodopayments-api` para o servidor stdio local:

```json
{
  "mcpServers": {
    "dodopayments-api": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "dodopayments-mcp@latest"],
      "env": {
        "DODO_PAYMENTS_API_KEY": "${user_config.dodo_api_key}",
        "DODO_PAYMENTS_WEBHOOK_KEY": "${user_config.dodo_webhook_key}",
        "DODO_PAYMENTS_ENVIRONMENT": "${user_config.dodo_environment}"
      }
    }
  }
}
```

Execute `/reload-plugins` para aplicar as alterações à sua sessão atual.
</Accordion>

<Accordion title="Local API key mode — OpenCode">
Declare `dodopayments-api` você mesmo em `opencode.json` — sua entrada substitui o servidor remoto padrão do plugin:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@dodopayments/opencode-plugin"],
  "mcp": {
    "dodopayments-api": {
      "type": "local",
      "command": ["npx", "-y", "dodopayments-mcp@latest"],
      "environment": {
        "DODO_PAYMENTS_API_KEY": "dodo_test_...",
        "DODO_PAYMENTS_WEBHOOK_KEY": "whsec_...",
        "DODO_PAYMENTS_ENVIRONMENT": "test_mode"
      },
      "enabled": true
    }
  }
}
```

Reinicie o OpenCode para aplicar.
</Accordion>
</AccordionGroup>
