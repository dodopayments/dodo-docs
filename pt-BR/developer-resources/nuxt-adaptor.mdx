## Visão geral

<Info>
Este guia explica como integrar o Dodo Payments ao seu aplicativo Nuxt usando o módulo oficial do Nuxt. Você aprenderá a configurar as rotas de API de checkout, portal do cliente e webhook, além de gerenciar variáveis de ambiente com segurança.
</Info>

## Instalação

<Steps>
<Step title="Install the Nuxt module">
Execute o comando a seguir na raiz do projeto:

```bash
npm install @dodopayments/nuxt
```

</Step>
<Step title="Register the module in nuxt.config.ts">
Adicione <code>@dodopayments/nuxt</code> ao seu array <code>modules</code> e configure-o:

```typescript nuxt.config.ts expandable
export default defineNuxtConfig({
  modules: ["@dodopayments/nuxt"],
  devtools: { enabled: true },
  compatibilityDate: "2025-02-25",
  runtimeConfig: {
    private: {
      bearerToken: process.env.NUXT_PRIVATE_BEARER_TOKEN,
      webhookKey: process.env.NUXT_PRIVATE_WEBHOOK_KEY,
      environment: process.env.NUXT_PRIVATE_ENVIRONMENT,
      returnUrl: process.env.NUXT_PRIVATE_RETURNURL
    },
  }
});
```

</Step>
</Steps>

<Warning>
Nunca faça commit do arquivo <code>.env</code> ou de segredos no controle de versão.
</Warning>

## Exemplos de manipuladores de rotas de API

<Info>
Todas as integrações com Dodo Payments no Nuxt são gerenciadas por meio de rotas de servidor no diretório <code>server/routes/api/</code>.
</Info>

<Tab title="Checkout API Route">
<Info>
Use este manipulador para integrar o checkout do Dodo Payments ao seu aplicativo Nuxt. Compatível com fluxos de pagamento estáticos (GET), dinâmicos (POST) e de sessão (POST).
</Info>

## Manipulador de rota de checkout

<Info>
O Dodo Payments é compatível com três tipos de fluxos de pagamento para integrar pagamentos ao seu site; este adaptador é compatível com todos os tipos de fluxos de pagamento.
</Info>

- **Links de pagamento estáticos:** URLs compartilháveis instantaneamente para coleta rápida de pagamentos sem código.
- **Links de pagamento dinâmicos:** gere links de pagamento programaticamente com detalhes personalizados usando a API ou SDKs.
- **Sessões de checkout:** crie experiências de checkout seguras e personalizáveis com carrinhos de produtos e dados do cliente pré-configurados.

</Warning>

### Formato da resposta
O checkout estático retorna uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envie os parâmetros como um corpo JSON em uma solicitação POST.
- Compatível com pagamentos únicos e recorrentes.
- Para obter uma lista completa dos campos compatíveis no corpo da solicitação POST, consulte:
  - [Corpo da solicitação para um produto de pagamento único](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corpo da solicitação para um produto de assinatura](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

<Warning>
O Dynamic Checkout faz proxy dos endpoints `POST /payments` e `POST /subscriptions`, que estão obsoletos. Ele continua funcionando para integrações existentes, mas novas integrações devem usar **Checkout Sessions** abaixo.
</Warning>

### Formato da resposta
O Dynamic Checkout retorna uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
As Checkout Sessions oferecem uma experiência de checkout hospedada e mais segura, que gerencia todo o fluxo de pagamento para compras únicas e assinaturas, com controle total de personalização.

Consulte o [Guia de integração das Checkout Sessions](https://docs.dodopayments.com/developer-resources/checkout-session) para obter mais detalhes e a lista completa de campos compatíveis.

### Formato da resposta
As Checkout Sessions retornam uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Manipulador de rota de Webhook

- **Método:** somente solicitações POST são compatíveis. Outros métodos retornam 405.
- **Verificação da assinatura:** verifica a assinatura do webhook usando <code>webhookKey</code>. Retorna 401 se a verificação falhar.
- **Validação do payload:** validado com Zod. Retorna 400 para payloads inválidos.
- **Tratamento de erros:**
  - 401: assinatura inválida
  - 400: payload inválido
  - 500: erro interno durante a verificação
- **Roteamento de eventos:** chama o manipulador de eventos apropriado com base no tipo do payload.
