## Instalação

<Steps>
<Step title="Install the package">
Execute o comando a seguir na raiz do seu projeto:

```bash
bun add @dodopayments/bun
```

</Step>
<Step title="Set up environment variables">
Crie um arquivo <code>.env</code> na raiz do seu projeto:

```env expandable
DODO_PAYMENTS_API_KEY=your-api-key
DODO_PAYMENTS_WEBHOOK_KEY=your-webhook-secret
DODO_PAYMENTS_ENVIRONMENT="test_mode" or "live_mode"
DODO_PAYMENTS_RETURN_URL=your-return-url
```

<Warning>
Nunca faça commit do arquivo <code>.env</code> ou de secrets no controle de versão.
</Warning>
</Step>
</Steps>

## Exemplos de Route Handler

<Info>
Todos os exemplos pressupõem que você está usando o servidor nativo do Bun com <code>Bun.serve()</code>.
</Info>

<Tabs>
<Tab title="Checkout Handler">
  <Info>
  Use este handler para integrar o checkout do Dodo Payments ao seu servidor Bun. Suporta fluxos de pagamento estático (GET), dinâmico (POST) e de sessão (POST).
  </Info>
  <CodeGroup>

    ```typescript Bun Server Handler expandable
    import { Checkout } from '@dodopayments/bun';

    const staticCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "static"
    });

    const sessionCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "session"
    });

    const dynamicCheckoutHandler = Checkout({
        bearerToken: process.env.DODO_PAYMENTS_API_KEY,
        returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
        environment: process.env.DODO_PAYMENTS_ENVIRONMENT,
        type: "dynamic"
    });

    Bun.serve({
      port: 3000,
      fetch(request) {
        const url = new URL(request.url);
        
        if (url.pathname === "/api/checkout") {
          if (request.method === "GET") {
            return staticCheckoutHandler(request);
          }
          if (request.method === "POST") {
            return sessionCheckoutHandler(request);
            // or return dynamicCheckoutHandler(request);
          }
        }
        
        return new Response("Not Found", { status: 404 });
      },
    });
    ```

  </CodeGroup>
  <CodeGroup>

## Route Handler de Checkout

<Info>
Dodo Payments é compatível com três tipos de fluxos de pagamento para integrar pagamentos ao seu site; este adaptador é compatível com todos os tipos de fluxos de pagamento.
</Info>

- **Links de pagamento estáticos:** URLs que podem ser compartilhadas instantaneamente para uma cobrança rápida de pagamentos sem código.
- **Links de pagamento dinâmicos:** Gere links de pagamento programaticamente com detalhes personalizados usando a API ou SDKs.
- **Checkout Sessions:** Crie experiências de checkout hospedadas, seguras e personalizáveis, com carrinhos de produtos e dados do cliente pré-configurados.

### Formato da resposta
O checkout estático retorna uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Dynamic Checkout (POST)">
- Envie os parâmetros como um corpo JSON em uma solicitação POST.
- Suporta pagamentos únicos e recorrentes.
- Para obter a lista completa de campos compatíveis no corpo do POST, consulte:
  - [Corpo da solicitação para um produto de pagamento único](https://docs.dodopayments.com/api-reference/payments/post-payments)
  - [Corpo da solicitação para um produto de assinatura](https://docs.dodopayments.com/api-reference/subscriptions/post-subscriptions)

### Formato da resposta
O checkout dinâmico retorna uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/..."
}
```

</Accordion>
<Accordion title="Checkout Sessions (POST)">
As Checkout Sessions oferecem uma experiência de checkout hospedada e mais segura, que gerencia o fluxo completo de pagamento para compras únicas e assinaturas, com controle total de personalização.

Consulte o [Guia de integração das Checkout Sessions](https://docs.dodopayments.com/developer-resources/checkout-session) para obter mais detalhes e a lista completa de campos compatíveis.

### Formato da resposta
As Checkout Sessions retornam uma resposta JSON com a URL do checkout:

```json
{
  "checkout_url": "https://checkout.dodopayments.com/session/..."
}
```

</Accordion>

## Route Handler de Customer Portal

O Route Handler de Customer Portal permite integrar perfeitamente o Customer Portal do Dodo Payments ao seu aplicativo de servidor Bun.

### Parâmetros de consulta
<ParamField query="customer_id" type="string" required>
O ID do cliente para a sessão do portal (por exemplo, <code>?customer_id=cus_123</code>).
</ParamField>
<ParamField query="send_email" type="boolean">
Se definido como <code>true</code>, envia um e-mail ao cliente com o link do portal.
</ParamField>

<Warning>
Retorna 400 se <code>customer_id</code> estiver ausente.
</Warning>

## Webhook Route Handler

- **Método:** somente solicitações POST são compatíveis. Outros métodos retornam 405.
- **Verificação de assinatura:** verifica a assinatura do webhook usando <code>webhookKey</code>. Retorna 401 se a verificação falhar.
- **Validação do payload:** validado com Zod. Retorna 400 para payloads inválidos.
- **Tratamento de erros:**
  - 401: assinatura inválida
  - 400: payload inválido
  - 500: erro interno durante a verificação
- **Roteamento de eventos:** chama o handler de eventos apropriado com base no tipo do payload.

import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

  returnUrl: process.env.DODO_PAYMENTS_RETURN_URL,
