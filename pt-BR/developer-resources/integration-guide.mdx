## Prerequisites

To integrate the Dodo Payments API, you'll need:
- A Dodo Payments merchant account
- API Credentials (API key and webhook secret key) from dashboard

## Dashboard Setup

1. Navigate to the [Dodo Payments Dashboard](https://app.dodopayments.com/)

2. Crie um produto (pagamento único ou assinatura). Os produtos de assinatura devem ter preço de pelo menos **\$1** (ou o equivalente na moeda escolhida); valores abaixo desse mínimo não são compatíveis.

4. Generate your API key:
   - Go to Developer > API
   - [Detailed Guide](/api-reference/introduction#api-key-generation)
   - Copy the API key the in env named DODO_PAYMENTS_API_KEY

5. Configure webhooks:
   - Go to Developer > Webhooks
   - Create a webhook URL for payment notifications
   - Copy the webhook secret key in env 

## Integration

### Payment Links

Escolha o caminho de integração mais adequado ao seu caso de uso:
- **Checkout Sessions (recomendado)**: ideal para a maioria das integrações. Crie uma sessão no seu servidor e redirecione os clientes para um checkout seguro e hospedado.
- **Overlay Checkout**: use quando precisar de uma experiência na página que abra o checkout como uma sobreposição modal no seu site.
- **Inline Checkout**: incorpore o checkout diretamente ao layout da sua página para obter experiências de checkout totalmente integradas e personalizadas com a sua marca.
- **Static Payment Links**: URLs sem código, compartilháveis instantaneamente, para coletar pagamentos rapidamente.
- **Dynamic Payment Links**: links criados programaticamente. No entanto, Checkout Sessions são recomendadas e oferecem mais flexibilidade.
- **[Mobile Checkout SDKs](/developer-resources/mobile-integration)**: para aplicativos nativos Android, iOS, React Native e Flutter. Crie a sessão no seu servidor conforme descrito acima e, em seguida, passe `checkout_url` ao SDK.

<Info>
Overlay e Inline Checkout funcionam apenas no navegador — eles incorporam o checkout a uma
página web. Se você estiver desenvolvendo um aplicativo móvel nativo, crie a sessão de checkout no
seu servidor e abra-a usando os
[Mobile Checkout SDKs](/developer-resources/mobile-integration).
</Info>

#### 1. Checkout Sessions

Use Checkout Sessions para criar uma experiência de checkout segura e hospedada para pagamentos únicos ou assinaturas. Você cria uma sessão no seu servidor e, em seguida, redireciona o cliente para `checkout_url`.

<Info>
As sessões de checkout são válidas por 24 horas por padrão. Se você passar <code>confirm=true</code>, as sessões serão válidas por 15 minutos e todos os campos obrigatórios deverão ser fornecidos.
</Info>

<Steps>
<Step title="Create a checkout session">
  Escolha o SDK de sua preferência ou chame a REST API.

  <Tabs>
  <Tab title="Node.js SDK">

  ```javascript
  import DodoPayments from 'dodopayments';

  const client = new DodoPayments({
    bearerToken: process.env.DODO_PAYMENTS_API_KEY,
    environment: 'test_mode', // defaults to 'live_mode'
  });

  const session = await client.checkoutSessions.create({
    product_cart: [{ product_id: 'prod_123', quantity: 1 }],
    customer: { email: 'customer@example.com', name: 'John Doe' },
    return_url: 'https://yourapp.com/checkout/success',
  });
  ```

  </Tab>

  <Tab title="Python SDK">

  ```python

      bearer_token=os.environ.get("DODO_PAYMENTS_API_KEY"),
      environment="test_mode",  # defaults to "live_mode"
  )

  session = client.checkout_sessions.create(
      product_cart=[{"product_id": "prod_123", "quantity": 1}],
      customer={"email": "customer@example.com", "name": "John Doe"},
      return_url="https://yourapp.com/checkout/success",
  )
  ```

</Step>

<Step title="Redirect customer to checkout">
  Após criar a sessão, redirecione para `checkout_url` para iniciar o fluxo hospedado.

<Tip>
Prefira Checkout Sessions para começar a aceitar pagamentos da maneira mais rápida e confiável. Para personalizações avançadas, consulte o <a href="/developer-resources/checkout-session">guia de Checkout Sessions</a> completo e a <a href="/api-reference/checkout-sessions/create">API Reference</a>.

#### 2. Overlay Checkout

Para uma experiência de checkout integrada à página, conheça nossa integração de [Overlay Checkout](/developer-resources/overlay-checkout), que permite aos clientes concluir pagamentos sem sair do seu site.

#### 3. Inline Checkout

Para experiências de checkout totalmente integradas e incorporadas diretamente à sua página, use nossa integração de [Inline Checkout](/developer-resources/inline-checkout). Ela permite criar resumos de pedidos personalizados e ter controle total sobre o layout do checkout, enquanto Dodo Payments gerencia a coleta do pagamento com segurança.

#### 4. Static Payment Links

Static payment links permitem aceitar pagamentos rapidamente compartilhando uma URL simples. Você pode personalizar a experiência de checkout passando query parameters para preencher previamente os dados do cliente, controlar os campos do formulário e adicionar metadados personalizados.

<Steps>
<Step title="Construct your payment link">
  Comece com a URL base e adicione o ID do produto:

  ```text
  https://checkout.dodopayments.com/buy/{productid}
  ```

</Step>
<Step title="Add core parameters">
  Inclua os query parameters essenciais:
  - <ParamField query="quantity" type="integer" default="1">Número de itens a comprar.</ParamField>
  - <ParamField query="redirect_url" type="string" required>URL para redirecionar após a conclusão do pagamento.</ParamField>
  <Note>
  A URL de redirecionamento incluirá os detalhes do pagamento como query parameters, por exemplo:<br/>
  <code>https://example.com/?payment_id=pay_ts2ySpzg07phGeBZqePbH&status=succeeded&email=customer%40example.com</code><br/><br/>
  Se o produto tiver chaves de licença habilitadas, um parâmetro `license_key` também será acrescentado (separado por vírgulas para várias chaves):<br/>
  <code>https://example.com/?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com</code>
  </Note>
</Step>
<Step title="Pre-fill customer information (optional)">
  Adicione campos do cliente ou de cobrança como query parameters para agilizar o checkout.
  <AccordionGroup>
    <Accordion title="Supported Customer Fields">
      - <ParamField query="fullName" type="string">Nome completo do cliente (ignorado se firstName ou lastName for fornecido).</ParamField>
      - <ParamField query="firstName" type="string">Nome do cliente.</ParamField>
      - <ParamField query="lastName" type="string">Sobrenome do cliente.</ParamField>
      - <ParamField query="email" type="string">Endereço de e-mail do cliente.</ParamField>
      - <ParamField query="country" type="string">País do cliente.</ParamField>
      - <ParamField query="addressLine" type="string">Endereço.</ParamField>
      - <ParamField query="city" type="string">Cidade.</ParamField>
      - <ParamField query="state" type="string">Estado ou província.</ParamField>
      - <ParamField query="zipCode" type="string">Código postal/ZIP.</ParamField>
      - <ParamField query="showDiscounts" type="boolean">true ou false</ParamField>
    </Accordion>
  </AccordionGroup>
</Step>
<Step title="Control form fields (optional)">
  <Info>
  Você pode desabilitar campos específicos para torná-los somente leitura para o cliente. Isso é útil quando você já tem os dados do cliente (por exemplo, usuários autenticados).
  </Info>
  Para desabilitar um campo, forneça seu valor e defina a flag <code>disable...</code> correspondente como <code>true</code>:
  <CodeGroup>

  ```text Example
  &email=alice@example.com&disableEmail=true
  ```

  </CodeGroup>
  <Tabs>
    <Tab title="Disable Flags Table">
      | Campo         | Flag de desativação         | Parâmetro obrigatório |
      |---------------|---------------------|-------------------|
      | Nome completo     | `disableFullName`   | `fullName`        |
      | Nome    | `disableFirstName`  | `firstName`       |
      | Sobrenome    | `disableLastName`   | `lastName`        |
      | E-mail         | `disableEmail`      | `email`           |
      | País       | `disableCountry`    | `country`         |
      | Endereço          | `disableAddressLine`| `addressLine`     |
      | Cidade          | `disableCity`       | `city`            |
      | Estado         | `disableState`      | `state`           |
      | Código postal      | `disableZipCode`    | `zipCode`         |
    </Tab>
  </Tabs>
  <Tip>
  Desabilitar campos ajuda a evitar alterações acidentais e garante a consistência dos dados.
  </Tip>
  <Note>
  Definir <code>showDiscounts=false</code> desabilitará e ocultará a seção de descontos no formulário de checkout. Use isso se quiser impedir que os clientes insiram códigos de cupom ou promocionais durante o checkout.
  </Note>

</Step>
<Step title="Add advanced controls (optional)">
  - <ParamField query="paymentCurrency" type="string">Especifica a moeda do pagamento. O padrão é a moeda do país de cobrança.</ParamField>
  - <ParamField query="showCurrencySelector" type="boolean" default="true">Mostra ou oculta o seletor de moeda.</ParamField>
  - <ParamField query="paymentAmount" type="integer">Valor em centavos (somente para preços Pay What You Want).</ParamField>
  - <ParamField query="metadata_*" type="string">Campos de metadados personalizados (por exemplo, <code>metadata_orderId=123</code>).</ParamField>
</Step>
<Step title="Share the link">
  Envie o payment link concluído ao seu cliente. Quando ele acessá-lo, todos os query parameters serão coletados e armazenados com um ID de sessão. A URL será então simplificada para incluir apenas o parâmetro de sessão (por exemplo, <code>?session=sess_1a2b3c4d</code>). As informações armazenadas persistem após atualizações da página e ficam acessíveis durante todo o processo de checkout.
  <Check>
  A experiência de checkout do cliente agora está simplificada e personalizada com base nos seus parâmetros.
  </Check>
</Step>
</Steps>

### Implementando Webhooks

Configure um endpoint de API para receber notificações de pagamento. Veja um exemplo usando Next.js:

```javascript
import { Webhook } from "standardwebhooks";
import { headers } from "next/headers";
import { WebhookPayload } from "@/types/api-types";

const webhook = new Webhook(process.env.DODO_WEBHOOK_KEY!); // Replace with your secret key generated from the Dodo Payments Dashboard

export async function POST(request: Request) {
  const headersList = headers();
  const rawBody = await request.text();

  const webhookHeaders = {
    "webhook-id": headersList.get("webhook-id") || "",
    "webhook-signature": headersList.get("webhook-signature") || "",
    "webhook-timestamp": headersList.get("webhook-timestamp") || "",
  };

  await webhook.verify(rawBody, webhookHeaders);
  const payload = JSON.parse(rawBody) as WebhookPayload;
  
  // Process the payload according to your business logic
}
```

Nossa implementação de webhook segue a especificação dos [Standard Webhooks](https://standardwebhooks.com/). Para obter as definições dos tipos de webhook, consulte nosso [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide).

#### Eventos a serem monitorados

Ative `payload.type` e processe os eventos relevantes para um fluxo de pagamento único. No mínimo, monitore:

| Tipo de evento           | Quando é acionado                                              | O que fazer                                                                 |
| -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `payment.succeeded`  | O pagamento é processado com sucesso.                        | Cumpra o pedido — conceda acesso, disponibilize o produto e envie o recibo. |
| `payment.failed`     | A tentativa de pagamento falha (cartão recusado, erro etc.).       | Notifique o cliente e solicite uma nova tentativa; não cumpra o pedido.                    |
| `payment.processing` | O pagamento foi aceito, mas ainda está sendo processado (métodos assíncronos). | Aguarde `payment.succeeded`/`payment.failed` terminal — ainda não cumpra o pedido. |
| `payment.cancelled`  | O pagamento é cancelado antes da conclusão.                   | Libere qualquer estado reservado e marque o pedido como abandonado.                       |

<Tip>
Sempre **cumpra o pedido com `payment.succeeded` recebido pelo webhook**, não com base no redirecionamento do navegador — o redirecionamento pode ser perdido se o cliente fechar a aba, enquanto o webhook é reenviado até ser confirmado.
</Tip>

Se você vende produtos digitais com chaves de licença, processe também `license_key.created`. Para consultar a lista completa de eventos — incluindo eventos de assinatura, entitlement, crédito, recuperação e cobrança — consulte o [Webhook Event Guide](/developer-resources/webhooks/intents/webhook-events-guide).

Você pode consultar este projeto com uma implementação de demonstração no [GitHub](https://github.com/dodopayments/dodo-checkout-demo) usando Next.js e TypeScript.

Você pode conferir a implementação em produção [aqui](https://atlas.dodopayments.com/).

## Principais informações sobre Checkout e moeda

<Warning>
**Os valores Dynamic (Pay-What-You-Want) estão na moeda base do produto** — não em uma moeda local arbitrária — e a moeda base é limitada a **USD, INR, GBP e EUR**. Para coletar um valor fixo em outra moeda (por exemplo, PHP), você não pode passá-lo diretamente: use **Adaptive Pricing** (converte seu valor base usando o câmbio FX atual) ou **Localized Pricing** (preço fixo por moeda, mas incompatível com Pay-What-You-Want).
</Warning>

<Tip>
**Defina a moeda explicitamente.** Passe `billing_currency` e `billing_address.country` na sessão de checkout. Se omitidos, a moeda e o país serão detectados a partir do IP do cliente (Adaptive Currency) e talvez não correspondam ao que você pretende cobrar.
</Tip>

<Info>
**As sessões de checkout expiram em 24 horas** (15 minutos quando `confirm: true`), e cada `checkout_url` é de **uso único** — gere uma nova sessão para cada cliente e tentativa de pagamento, em vez de reutilizar um link.
</Info>

<Info>
**Compra recorrente com um clique.** Para um cliente recorrente com um método de pagamento salvo, passe `payment_method_id` junto com `confirm: true` para cobrar instantaneamente, ignorando completamente a seleção do método.
</Info>
