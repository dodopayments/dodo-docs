## Alterações de Plano Agendadas

Use o parâmetro `effective_at` para controlar quando a alteração do plano entra em vigor:

| Valor | Comportamento |
|-------|----------|
| `immediately` | Aplique a alteração do plano imediatamente. Este é o padrão. |
| `next_billing_date` | Agende a alteração para a próxima data de cobrança. O cliente mantém acesso ao plano atual até o final do período de faturamento. |

<Info>
Alterações de plano agendadas são ideais para downgrades — os clientes mantêm os benefícios do plano atual até o final do período de faturamento e, em seguida, mudam automaticamente para o novo plano.
</Info>

Para cancelar uma alteração de plano agendada antes que ela entre em vigor, use o endpoint [Cancelar Alteração de Plano Agendada](/api-reference/subscriptions/cancel-change-plan).

## Tratamento de Falha de Pagamento

Use o parâmetro `on_payment_failure` para controlar o que acontece quando o pagamento da alteração do plano falha:

| Valor | Comportamento |
|-------|----------|
| `prevent_change` | Mantenha a assinatura no plano atual até que o pagamento seja bem-sucedido. A alteração do plano permanece pendente. |
| `apply_change` | Aplique a alteração do plano imediatamente, independentemente do resultado do pagamento. Este é o padrão. |

<Info>
Se `on_payment_failure` não for especificado, o comportamento será o padrão configurado em nível de negócios no painel.
</Info>

## Coleta por meio de Payment Link

Defina `collect_via_payment_link` como `true` para enviar o cliente a uma página de checkout hospedada em vez de cobrar o método de pagamento salvo. A resposta então inclui `payment_id`, `payment_link`, `client_secret` e `expires_on` — redirecione o cliente para `payment_link` para concluir o pagamento.

Isso requer:

| Requisito | Motivo |
|-------------|-----|
| A empresa tem o recurso `allow_plan_change_via_payment_link` habilitado | Desabilitado por padrão; ativado em **Configurações → Assinaturas → Coletar pagamentos de alteração de plano por Payment Link**. |
| `effective_at: immediately` | Uma alteração agendada não cobra nada até ser aplicada, portanto ainda não há nada a coletar pelo checkout. |
| O `on_payment_failure` **efetivo** é `prevent_change` | A assinatura deve permanecer no plano atual até que o pagamento do checkout seja concluído com sucesso. Você não precisa enviar o campo — um padrão no nível da empresa de `prevent_change` também atende a esse requisito. |

Uma solicitação que não atende a esses requisitos retorna `422`. Enquanto o link não for pago, a assinatura permanece no plano atual, e uma nova solicitação `change-plan` retorna INLINE_CODE_PLACEHOLDER_30f6f75e725227d_END.

<Info>
Consulte o [Guia de upgrade e downgrade de assinaturas](/developer-resources/subscription-upgrade-downgrade#collecting-payment-via-a-checkout-link) para conhecer o fluxo completo, incluindo como um cliente tenta novamente um pagamento recusado e o que acontece se o link expirar.
</Info>

## Códigos de desconto

Você pode aplicar um ou mais **códigos de desconto empilhados** ao alterar planos, enviando o array `discount_codes` (máximo de 20 entradas, aplicadas na ordem do array). O campo singular `discount_code` está obsoleto, mas continua funcionando para integrações existentes; ele não pode ser combinado com `discount_codes` na mesma solicitação.

| Valor de `discount_codes` | Comportamento |
|------------------------|----------|
| Não fornecido (`null` / omitido) | Os descontos existentes com `preserve_on_plan_change=true` são preservados se forem aplicáveis ao novo produto. |
| `[]` (array vazio) | **Todos** os descontos existentes são removidos da assinatura. |
| `["CODE_A", "CODE_B", ...]` | Substitui todos os descontos existentes por este conjunto empilhado, validado e aplicado na ordem do array. |

<Tip>
Use códigos de desconto durante alterações de plano para oferecer preços promocionais em upgrades ou envie códigos ao migrar clientes para um novo nível de plano.
</Tip>

<Tip>
Use `prevent_change` para upgrades críticos nos quais você deseja garantir o pagamento antes de conceder acesso a recursos premium.
</Tip>
