## Novos Recursos

### 1. **Análises em Nível de Produto**

Agora, cada produto possui seu próprio **painel de análises dedicado**. Navegue até **Produtos > [Selecione um Produto]** para acessar métricas detalhadas específicas desse produto, organizadas em cinco guias:

<Frame>
<img src="/images/product-analytics/overview.png" alt="Análises em Nível de Produto" />
</Frame>

| Guia | O Que Você Recebe |
|-----|-------------|
| **Visão Geral** | Receita total, contagem de pagamentos bem-sucedidos, gráfico de tendências de receita de 30 dias (diário ou acumulado) e uma tabela de transações filtrável |
| **Clientes** | Principais 3 clientes classificados por gasto com uma visão de pódio, além de uma tabela de detalhamento completo de clientes |
| **Retenção** | Taxa de churn de clientes, taxa de churn de receita e um gráfico de tendências de dupla linha para identificar padrões |
| **Inscritos** | Todas as assinaturas para o produto com status, data de início, próxima data de cobrança e valor |
| **MRR** | Gráfico de barras empilhadas da Receita Mensal Recorrente com desagregações de MRR Novo, MRR de Expansão, MRR Churned e MRR Líquido Novo |

Todas as guias suportam um **filtro de data** (padrão para todo o tempo) para que você possa aprofundar em qualquer período de tempo.

<Tip>
Use a guia Retenção para identificar produtos com alto churn precocemente e a guia de MRR para rastrear se a receita de expansão está superando a receita perdida mês a mês.
</Tip>

### 2. **Suporte Verifi RDR no Dodo Payments**

O Dodo Payments agora suporta **Visa Rapid Dispute Resolution (RDR)** com a tecnologia Verifi -- uma ferramenta de prevenção de disputas automatizada que resolve disputas elegíveis da Visa **antes que elas se tornem chargebacks formais**. Quando um titular de cartão inicia uma disputa, o RDR a intercepta e automaticamente emite um reembolso se a transação estiver abaixo do seu limite de USD configurado.

**Por Que Isso Importa**

| Benefício | Impacto |
|---------|--------|
| **Taxa de disputa mais baixa** | Disputas resolvidas pelo RDR não contam para o limite de 0,9% da Visa |
| **Sem taxas de disputa** | Evite taxas não reembolsáveis de $15 a $25 por disputa |
| **Zero sobrecarga operacional** | Sem coleta de evidências ou prazos de resposta |
| **Melhor experiência do cliente** | Titulares de cartão recebem reembolsos instantaneamente |
| **Proteção da conta** | Fique fora do Programa de Monitoramento de Disputas da Visa (VDMP) |

<Warning>
Exceder a taxa de disputa de 0,9% da Visa ou 100 disputas/mês ativa o VDMP, com penalidades crescentes de até $50,000+/mês. O RDR ajuda você a se manter bem abaixo desses limites.
</Warning>

**Como Funciona**

1. O titular do cartão inicia uma disputa com seu banco
2. O RDR intercepta a disputa antes que ela se torne um chargeback formal
3. Se o valor da transação estiver no seu limite ou abaixo, um reembolso é automaticamente emitido
4. A disputa é resolvida instantaneamente e **não conta** contra sua taxa de disputa

<Info>
Transações reembolsadas automaticamente por meio do RDR aparecem como uma **disputa perdida** no seu painel do Dodo Payments. Isso é esperado -- o reembolso foi emitido automaticamente para evitar um chargeback formal.
</Info>

Para habilitar o Verifi RDR na sua conta, entre em contato com **support@dodopayments.com** para configurar seu limite.

Saiba mais: [Documentação Visa RDR](/features/transactions/disputes#visa-rapid-dispute-resolution-rdr)

### 3. **CLI DodoPayments**

Apresentando o novíssimo **CLI DodoPayments** (`dodopayments-cli`) -- gerencie todo seu fluxo de trabalho do Dodo Payments diretamente do terminal. Criado para desenvolvedores que preferem a linha de comando, o CLI permite gerenciar produtos, pagamentos, clientes, descontos, licenças, complementos, reembolsos e até criar sessões de checkout sem sair do seu editor.

**Instalação**

<CodeGroup>

```bash npm (Recommended)
npm install -g dodopayments-cli
```

```bash Bun
bun install -g dodopayments-cli
```

</CodeGroup>

**Comandos Principais**

| Comando | Descrição |
|---------|-------------|
| `dodo login` | Autentica com sua chave API (abre o navegador) |
| `dodo products list` | Lista todos os produtos |
| `dodo payments list` | Lista todos os pagamentos |
| `dodo customers create` | Cria um novo cliente |
| `dodo checkout new` | Cria uma sessão de checkout e obtém a URL |
| `dodo wh listen` | Encaminha webhooks de teste ao vivo para seu servidor local via WebSocket |
| `dodo wh trigger` | Envia cargas de webhooks simuladas para qualquer endpoint |

**Teste de Webhook**

O CLI inclui duas ferramentas poderosas para desenvolvimento:

- **`dodo wh listen`** -- Abre uma conexão WebSocket para encaminhar webhooks de teste em tempo real para seu servidor local, preservando os cabeçalhos originais para testes de verificação de assinatura
- **`dodo wh trigger`** -- Envia cargas de webhooks simuladas interativamente, suportando todos os 22 tipos de eventos em assinaturas, pagamentos, reembolsos, disputas e licenças

<Tip>
O listener de webhook só funciona com uma chave API de **modo de teste**. Certifique-se de que você está logado com uma chave de modo de teste antes de usar `dodo wh listen`.
</Tip>

Saiba mais: [Documentação CLI](/developer-resources/sdks/cli)

### 5. **Atualizar Método de Pagamento no Checkout Inline**

O [checkout inline](/developer-resources/inline-checkout) agora suporta **atualizações de método de pagamento** para assinaturas. Quando um cliente precisa atualizar seu método de pagamento (para uma assinatura ativa ou para reativar uma assinatura em espera), o fluxo de atualização do método de pagamento agora pode ser exibido diretamente dentro do layout da sua página usando checkout inline -- proporcionando uma experiência incorporada e contínua.

**Como Funciona**

1. Chame a API de Atualização do Método de Pagamento para obter um `payment_link`:

```typescript
const response = await client.subscriptions.updatePaymentMethod('sub_123', {
  type: 'new',
  return_url: 'https://example.com/return'
});
```

2. Use o `payment_link` retornado como o `checkoutUrl` no checkout inline:

```typescript
DodoPayments.Checkout.open({
  checkoutUrl: response.payment_link,
  elementId: "dodo-inline-checkout"
});
```

O iframe inline renderiza apenas o formulário de coleta do método de pagamento, permitindo que os clientes insiram novos dados de cartões ou selecionem um método de pagamento salvo sem sair da sua página.

<Tip>
Para assinaturas em espera, o fluxo de atualização do método de pagamento cria automaticamente uma cobrança para os valores devidos restantes. Monitore os webhooks `payment.succeeded` e `subscription.active` para confirmar a reativação.
</Tip>

Saiba mais: [Checkout Inline](/developer-resources/inline-checkout) | [Atualizações de Método de Pagamento de Assinaturas](/features/subscription#update-payment-method-for-active-subscription)

### 6. **Suporte de Pré-preenchimento do CPF para Sessões de Checkout**

Agora você pode **pré-preencher o CPF** (por exemplo, número VAT, número GST) ao criar uma sessão de checkout usando o parâmetro `tax_id`. Isso é ideal para transações B2B onde você já conhece o número de identificação fiscal do cliente. Quando um CPF é pré-preenchido, o campo é preenchido automaticamente e bloqueado no formulário de checkout.

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customer: { customer_id: 'cus_123' },
  billing_address: { country: 'DE' },
  tax_id: 'DE999999999',
  return_url: 'https://yoursite.com/return'
});
```

<Info>
O parâmetro `tax_id` requer um `billing_address` com pelo menos um campo `country`. A elegibilidade para impostos é validada em tempo real, e as regras de reverse-charge são aplicadas automaticamente para transações B2B qualificadas.
</Info>

Use a flag de recurso `allow_customer_editing_tax_id` para controlar se os clientes podem modificar o CPF pré-preenchido, e `allow_tax_id` para alternar a visibilidade do CPF no checkout.

Saiba mais: [Sessões de Checkout - CPF](/developer-resources/checkout-session) | [Pagamentos B2B](/features/b2b-payments)

### 7. **Chave de Licença e E-mail no Redirecionamento da URL de Retorno**

Após a conclusão do checkout por um cliente, o Dodo Payments agora anexa `license_key` e `email` como parâmetros de consulta ao seu `return_url` redirecionar, além dos parâmetros `payment_id`/`subscription_id` e `status` existentes.

**Parâmetros de Consulta Adicionados**

| Parâmetro | Tipo | Condição |
|-----------|------|-----------|
| `payment_id` | `string` | Sempre presente para pagamentos únicos |
| `subscription_id` | `string` | Sempre presente para pagamentos de assinatura |
| `status` | `string` | Sempre presente |
| `license_key` | `string` | Presente se o produto tiver chaves de licença habilitadas (separadas por vírgula para múltiplas) |
| `email` | `string` | Presente se o cliente tiver um e-mail registrado |

**Exemplos de URLs de redirecionamento:**

```text
# One-time payment with license key
https://yoursite.com/return?payment_id=pay_xxx&status=succeeded&license_key=LK-001&email=customer%40example.com

# Subscription with multiple license keys
https://yoursite.com/return?subscription_id=sub_xxx&status=active&license_key=LK-001,LK-002&email=customer%40example.com
```

<Tip>
Use esses parâmetros de consulta para exibir chaves de licença ou enviar um e-mail de confirmação imediatamente na sua página de retorno, sem a necessidade de uma chamada API extra.
</Tip>

Saiba mais: [Sessões de Checkout - URL de Retorno](/developer-resources/checkout-session) | [Chaves de Licença na URL de Retorno](/features/license-keys#license-keys-in-return-url)

### 8. **API de Atualização de E-mail do Cliente**

O endpoint `PATCH /customers/{customer_id}` agora suporta a atualização de endereços de e-mail de clientes programaticamente. Atualize e-mail junto com nome, número de telefone e metadados em uma única chamada API.

```typescript
await client.customers.update('cus_123', {
  email: 'newemail@example.com',
  name: 'Updated Name'
});
```

**Campos Atualizáveis**

| Campo | Tipo | Descrição |
|-------|------|-------------|
| `email` | `string \| null` | Endereço de e-mail do cliente |
| `name` | `string \| null` | Nome de exibição do cliente |
| `phone_number` | `string \| null` | Número de telefone em formato internacional |
| `metadata` | `object \| null` | Pares de chave-valor personalizados |

<Info>
Atualizações de e-mail do cliente também estão disponíveis através do Portal do Cliente (autoatendimento), do painel e do CLI via `dodo customers update`.
</Info>

Saiba mais: [API de Atualização de Cliente](/api-reference/customers/patch-customer) | [Gestão de Clientes](/features/customers)

### 9. **Lançamento do Adaptador Bun**

Apresentando `@dodopayments/bun` -- um adaptador de framework dedicado para o servidor nativo do [Bun](https://bun.sh) (`Bun.serve()`). Integre checkout, portal do cliente e webhooks com Bun em apenas algumas linhas de código.

**Instalação**

```bash
bun add @dodopayments/bun
```

**Configuração Rápida**

```typescript
import { Checkout, CustomerPortal, Webhooks } from "@dodopayments/bun";

Bun.serve({
  routes: {
    "/api/checkout": Checkout({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      returnUrl: process.env.DODO_PAYMENTS_RETURN_URL!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/customer-portal": CustomerPortal({
      bearerToken: process.env.DODO_PAYMENTS_API_KEY!,
      environment: process.env.DODO_PAYMENTS_ENVIRONMENT!,
    }),
    "/api/webhooks": Webhooks({
      webhookKey: process.env.DODO_PAYMENTS_WEBHOOK_KEY!,
      onPaymentSucceeded: async (payload) => {
        console.log("Payment succeeded:", payload.data.payment_id);
      },
      onSubscriptionActive: async (payload) => {
        console.log("Subscription active:", payload.data.subscription_id);
      },
    }),
  },
});
```

O adaptador Bun suporta todos os três fluxos de checkout (estático, dinâmico e baseado em sessão), geração de sessão do portal do cliente e manuseio seguro de webhooks com verificação de assinatura e validação em Zod em 22 tipos de eventos.

</Check>
