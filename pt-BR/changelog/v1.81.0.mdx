## Novos Recursos

### 1. **Suporte a Análise de Terceiros**

Rastreie o comportamento do cliente em toda a Storefront, Checkout e Portal do Cliente com Google Analytics 4, Google Tag Manager e Meta Pixel. Adicione seus IDs de rastreamento em **Configurações → Análise** para começar a coletar eventos de e-commerce.

**Plataformas Suportadas**

| Plataforma               | Formato do ID                           |
|-------------------------|----------------------------------------|
| Google Analytics 4      | `G-XXXXXXXXXX` |
| Google Tag Manager      | `GTM-XXXXXXX` |
| Meta Pixel             | Numérico (10-20 dígitos)               |

**Eventos Rastreados**

Eventos como `purchase`, `add_payment_info`, `view_item`, e `view_item_list` são enviados automaticamente para suas plataformas de análise enquanto os clientes navegam e completam compras.

<Check>
Suportado na Storefront, Checkout hospedado, Checkout em sobreposição/inline e Portal do Cliente.
</Check>

Saiba mais: [Análise de Terceiros](/features/analytics)

### 2. **Personalização do Tema de Checkout**

Personalize a aparência do checkout por meio do parâmetro `customization.theme_config` ao criar sessões de checkout. Configure cores, fontes, raio de borda e texto do botão para os modos claro e escuro.

**Opções de Configuração**

| Propriedade                                 | Descrição                             |
|---------------------------------------------|-------------------------------------|
| `light` / `dark` | Esquemas de cores para cada modo |
| `font_primary_url` | URL da fonte personalizada          |
| `font_size` | `xs`, `sm`, `md`, `lg`, `xl`, `2xl` |
| `radius` | Raio de borda (ex: `8px`) |
| `pay_button_text` | Texto do botão personalizado        |

```typescript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  customization: {
    theme_config: {
      radius: '8px',
      pay_button_text: 'Complete Purchase',
      light: { button_primary: '#0066ff', text_primary: '#1a1a1a' },
      dark: { button_primary: '#3385ff', text_primary: '#ffffff' }
    }
  },
  return_url: 'https://yoursite.com/return'
});
```

Saiba mais: [Personalização do Tema de Checkout](/features/checkout#checkout-theme-customization)

### 3. **Prevenir Mudança de Plano em Caso de Falha no Pagamento**

Novo parâmetro `on_payment_failure` para mudanças de plano de assinatura controla o comportamento quando o pagamento falha.

| Modo                        | Comportamento                                     |
|-----------------------------|-------------------------------------------------|
| `prevent_change` | Manter assinatura no plano atual até o pagamento ser bem-sucedido |
| `apply_change` | Aplicar mudança de plano imediatamente, independentemente do resultado do pagamento (padrão) |

```typescript
await client.subscriptions.changePlan('sub_123', {
  product_id: 'prod_pro',
  proration_billing_mode: 'prorated_immediately',
  on_payment_failure: 'prevent_change'
});
```

<Tip>
Use `prevent_change` para atualizações críticas, onde você deseja garantir o pagamento antes de conceder acesso a recursos premium.
</Tip>

Saiba mais: [Tratando Falhas de Pagamento](/developer-resources/subscription-upgrade-downgrade#handling-payment-failures)

## Atualizações da API

### API do Livro Razão do Saldo

Novo endpoint `GET /balances/ledger` para recuperar as entradas do livro razão da sua conta com filtragem e paginação.

| Parâmetro                                    | Descrição                                   |
|----------------------------------------------|--------------------------------------------|
| `created_at_gte` / `created_at_lte` | Filtrar por intervalo de datas                |
| `event_type` | Filtrar por `payment`, `refund`, `dispute`, `payout`, etc. |
| `currency` | Filtrar por código de moeda                   |
| `reference_object_id` | Filtrar por ID específico de pagamento/reembolso/contestação |

Saiba mais: [API do Livro Razão do Saldo](/api-reference/balance-ledger/list-ledger-entries)

### Resposta de Pagamento: `refund_status`

Adicionado o campo `refund_status` à resposta `GET /payments/{paymentId}` para verificar rapidamente se um pagamento foi reembolsado sem consultar o endpoint de reembolsos separadamente.
