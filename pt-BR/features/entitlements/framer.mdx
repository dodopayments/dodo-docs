<Info>
The Framer entitlement unlocks a Framer template remix link for paying customers. You upload the template to Dodo Payments, attach the entitlement to a product, and customers receive a remix link that lets them clone the template into their own Framer account.
</Info>

## O que é entregue

- Um link único de remix para o modelo do Framer que você enviou.
- O cliente clica no link para remixar o modelo em seu próprio espaço de trabalho no Framer.
- Em caso de cancelamento ou reembolso, o link de remix é invalidado.

Usos comuns incluem modelos de landing page pagos do Framer, kits de portfólio e bibliotecas de componentes.

## Conectar Framer

O Framer é conectado implicitamente na primeira vez que você cria um entitlement de modelo. Não há etapa separada de OAuth.

<Steps>
<Step title="Open Entitlements">
No painel do Dodo Payments, vá para **Entitlements** e clique em **+**.
</Step>

<Step title="Pick Framer">
Escolha **Framer Template** como a integração.
</Step>

<Step title="Grab the remix link from Framer">
Abra seu projeto no Framer. No menu superior à esquerda, vá para **Arquivo → Copiar link de remix**. Isso produz uma URL de remix público que permite a qualquer pessoa clonar o projeto em sua própria conta do Framer — o link que o Dodo Payments compartilhará com clientes pagantes.

</Step>

<Step title="Add the template and create the entitlement">
De volta ao painel do Dodo Payments, escolha o modelo no menu suspenso **Template**. Na primeira vez que você fizer isso para um novo modelo, cole o link de remix que você copiou para registrá-lo. Dê ao entitlement um **nome** e clique em **Criar Entitlement**.

## Fluxo do cliente

1. O cliente conclui o checkout.
2. Dodo Payments cria um `pending` grant e emite um link de remix único associado a esse cliente.
3. O grant transita para `delivered` uma vez que o link de remix é provisionado e o link é incluído no e-mail e no portal do cliente.
4. O cliente clica no link, faz login no Framer e remixa o modelo.
5. Na revogação, o link de remix é invalidado. Cópias já remixadas na conta do Framer do cliente permanecem, já que o Framer não expõe uma maneira de revogá-las.

## Configuração necessária

| Campo | Obrigatório | Descrição |
|---|---|---|
| `framer_template_id` | Sim | O ID do modelo retornado quando você carrega o modelo. |

## Criar via API

<CodeGroup>

```typescript TypeScript theme={null}
const entitlement = await client.entitlements.create({
  name: 'Portfolio Kit',
  integration_type: 'framer',
  integration_config: {
    framer_template_id: 'tmpl_abc123',
  },
});
```

```python Python theme={null}
client.entitlements.create(
    name="Portfolio Kit",
    integration_type="framer",
    integration_config={"framer_template_id": "tmpl_abc123"},
)
```

```go Go theme={null}
client.Entitlements.New(ctx, dodopayments.EntitlementNewParams{
  Name:            dodopayments.F("Portfolio Kit"),
  IntegrationType: dodopayments.F(dodopayments.EntitlementIntegrationTypeFramer),
  IntegrationConfig: dodopayments.F[dodopayments.IntegrationConfigUnionParam](
    dodopayments.IntegrationConfigFramerConfigParam{
      FramerTemplateID: dodopayments.F("tmpl_abc123"),
    },
  ),
})
```

</CodeGroup>

## Webhooks

Veja [`entitlement_grant.*` eventos de webhook](/developer-resources/webhooks/intents/entitlement-grant). Grants do Framer chegam `pending` e transitam para `delivered` uma vez que o link de remix é provisionado.

## Solução de problemas

<AccordionGroup>
<Accordion title="Customer's remix link doesn't work">
O link de remix é de uso único e vinculado ao cliente. Se eles limparam o link antes de remixar, revogue o grant e reemita.
</Accordion>

<Accordion title="Refunded customer still has a remixed copy">
Isso é esperado. O Framer trata um remix como o próprio projeto do cliente uma vez que é clonado; o Dodo Payments invalida o link original, mas não pode excluir cópias na conta do cliente.
</Accordion>
</AccordionGroup>
