## Introdução

Multi-Brand permite que você associe várias marcas, cada uma com seu próprio logotipo, descrição e URL do site, a **um negócio verificado**. Sua conta de pagamento, taxas e KYC permanecem exatamente os mesmos, enquanto cada Produto, Link de Pagamento, Assinatura, Fatura e Transação podem agora ser arquivados sob uma marca específica. Use isso para testar novos nichos, localizar um site ou separar linhas B2B e B2C sem abrir contas comerciais extras.

- **Nome da Marca** (obrigatório): Insira o nome da sua marca.

- **Descrição da Marca** (obrigatório): Descreva sua marca, produtos e o que a torna única.
- **Logotipo da Marca**: Carregue um logotipo para representar a marca no checkout, nas faturas e nos links de pagamento.

## Pontos Adicionais

- **Nenhuma alteração nos payouts:** Todos os fundos, ciclos de payout e taxas continuam fluindo para a carteira no nível da empresa e para a conta bancária do merchant.
- **ID da marca nos webhooks:** Os payloads de pagamento, assinatura, reembolso, disputa, chave de licença, entrada no ledger de créditos, saldo de créditos baixo, concessão de entitlement, tentativa de cobrança e checkout abandonado incluem um `brand_id`, para que você possa atribuí-los a uma marca específica. Quando uma entidade não tem uma marca própria, `brand_id` usa como fallback a marca principal da empresa. Os payloads de payout são no nível da empresa e não contêm um `brand_id`.
- **Suspensões:** Se uma marca for suspensa, apenas seus links de pagamento serão interrompidos. As outras marcas da mesma empresa continuarão realizando transações.
- Nenhuma alteração no Storefront, Invoices, License Keys, Discount Codes, Payout Settings e em quaisquer outros recursos no nível da empresa.

## Arquivando uma marca

Quando uma marca chega ao fim de seu ciclo, arquive-a em vez de deixá-la inativa no painel. O arquivamento desativa a marca e transfere seu catálogo para outra marca da mesma empresa em uma única etapa.

<Warning>
Arquivar uma marca é permanente. Não há como restaurar uma marca arquivada.
</Warning>

### O que acontece quando você arquiva uma marca

Você indica uma **marca de destino** para assumir as operações da marca que está arquivando. O painel sempre solicita uma, e a API a recebe como `move_products_to`. Em uma ação atômica, Dodo Payments:

- Transfere todos os produtos para a marca de destino.
- Transfere todas as assinaturas ativas para a marca de destino, para que as renovações continuem sendo cobradas por ela.
- Transfere todas as coleções de produtos para a marca de destino.
- Arquiva e desativa a marca original.

Seu histórico não é alterado. Os pagamentos, faturas e assinaturas concluídas permanecem associados à marca sob a qual foram criados, mantendo a precisão dos relatórios anteriores.

A marca de destino deve pertencer à mesma empresa e não pode estar arquivada. Sua marca principal é um destino válido, e o ID da marca é o ID da sua empresa. Você pode omitir o destino somente quando a marca não tiver produtos, assinaturas ativas nem coleções de produtos.

<Note>
A marca principal nunca pode ser arquivada. Ela é a marca de fallback da sua empresa, portanto pelo menos uma marca sempre permanece.
</Note>

### Uma marca arquivada é somente leitura

| Ação | Resultado |
|---|---|
| Editar os detalhes da marca | Rejeitado com `BRAND_ARCHIVED` |
| Enviar a marca para verificação | Rejeitado com `BRAND_ARCHIVED` |
| Criar um produto ou uma coleção sob a marca | Rejeitado com `BRAND_ARCHIVED` |
| Criar uma assinatura para um de seus produtos | Rejeitado com `BRAND_ARCHIVED` |

As marcas arquivadas ficam ocultas nos seletores de marcas, portanto não é possível associar novos registros a elas. Elas continuam disponíveis como filtros de analytics, mantendo completos os relatórios por marca referentes ao período em que a marca esteve em operação. Consulte [Analytics](/features/analytics).

### Arquivamento pela API

Chame o endpoint de arquivamento com a marca que está sendo desativada e a marca que assumirá suas operações:

<CodeGroup>

```typescript Node.js
const response = await client.brands.archive('brnd_8dFiAW42v28JzhlVSocjq', {
  move_products_to: 'brnd_pRQ2zXk91mNvBcTgLwHsA',
});

console.log(response.products_moved);
```

```python Python
response = client.brands.archive(
    id="brnd_8dFiAW42v28JzhlVSocjq",
    move_products_to="brnd_pRQ2zXk91mNvBcTgLwHsA",
)
print(response.products_moved)
```

```bash cURL
curl -X POST https://live.dodopayments.com/brands/brnd_8dFiAW42v28JzhlVSocjq/archive \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"move_products_to": "brnd_pRQ2zXk91mNvBcTgLwHsA"}'
```

</CodeGroup>

A resposta informa o que foi transferido, para que você possa confirmar o resultado:

```json
{
  "brand_id": "brnd_8dFiAW42v28JzhlVSocjq",
  "archived_at": "2026-08-17T11:20:05Z",
  "moved_to_brand_id": "brnd_pRQ2zXk91mNvBcTgLwHsA",
  "products_moved": 12,
  "subscriptions_moved": 3,
  "collections_moved": 1
}
```

Para listar as marcas, incluindo as arquivadas, defina `include_archived` no endpoint de listagem. As marcas arquivadas são excluídas por padrão. Cada marca contém um campo `archived_at`, que é `null` enquanto a marca está ativa.

```bash cURL
curl "https://live.dodopayments.com/brands?include_archived=true" \
  -H "Authorization: Bearer $DODO_PAYMENTS_API_KEY"
```

Consulte a referência da API [Archive Brand](/api-reference/brands/archive-brand) para ver o esquema completo da requisição e da resposta, e [Error Codes](/api-reference/error-codes) para consultar os erros retornados por esse endpoint.
