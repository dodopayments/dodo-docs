## Como Funciona

Os métodos de pagamento são apresentados automaticamente aos clientes com base em:

- **Localização do Cliente** — Métodos regionais como iDEAL (Países Baixos) ou UPI (Índia) aparecem apenas para clientes nessas regiões
- **Moeda da Transação** — Métodos de pagamento são filtrados por moedas suportadas
- **Tipo de Dispositivo** — Apple Pay aparece apenas em dispositivos e navegadores Apple compatíveis
- **Tipo de Transação** — Alguns métodos não suportam assinaturas ou têm valores mínimos

<Info>
**Ativação Automática:** Todos os métodos de pagamento são pré-configurados e gerenciados pela Dodo Payments. Não é necessário nenhum ajuste adicional — eles ficam disponíveis assim que sua conta for verificada e o modo produção estiver habilitado.
</Info>

## Configurando Métodos de Pagamento

Por padrão, todas as formas de pagamento elegíveis aparecem automaticamente. Use `allowed_payment_method_types` para restringir quais métodos são exibidos:

<Tab title="Python">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="cURL">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>
</Tabs>

### Tipos de Métodos Disponíveis

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

<Warning>
Inclua sempre `credit` e `debit` como alternativas. Se todos os métodos especificados estiverem indisponíveis para um cliente, o checkout falhará.
</Warning>

## Melhores Práticas

Inclua métodos de pagamento regionais para seus mercados-alvo. O iDEAL captura ~60% dos pagamentos online nos Países Baixos; UPI domina na Índia. Omitir esses métodos prejudica significativamente a conversão.

Mesmo ao direcionar métodos específicos, inclua `credit` e `debit` como alternativas. Nem todos os clientes têm acesso a todas as formas de pagamento.

Métodos BNPL (Klarna, Afterpay) exigem um mínimo de $50,01. Não os inclua para produtos de baixo valor — eles simplesmente não aparecerão, o que é aceitável.

Use o modo de teste para verificar a disponibilidade dos métodos de pagamento em diferentes locais, moedas e tipos de dispositivos dos clientes antes de entrar em operação.

## Solução de Problemas

**Verifique estes fatores:**
1. Método incluído em `allowed_payment_method_types`?
2. Localização do cliente corresponde à região suportada pelo método?
3. Moeda da transação suportada pelo método?
4. O valor da transação atinge o mínimo (por exemplo, $50,01 para BNPL)?
5. Para assinaturas: o método suporta pagamentos recorrentes?

**Solução:** Remova `allowed_payment_method_types` temporariamente para ver todos os métodos elegíveis e depois restrinja o problema.

**Possíveis causas:**
- `allowed_payment_method_types` não está sendo passado corretamente
- Parâmetro formatado incorretamente (deve ser um array de strings)

**Solução:** Registre o payload da sua solicitação API e verifique a estrutura do parâmetro.

**Verifique:**
- O endereço de cobrança do cliente corresponde à região do método
- A moeda está configurada corretamente (por exemplo, EUR para iDEAL)
- Moeda Adaptativa está habilitada se o cliente for internacional

**Solução:** Verifique o código do país do endereço de cobrança e a moeda na sua solicitação API.

Assinaturas UPI e Rupay têm requisitos únicos, incluindo atrasos de processamento de 48 horas e limites de mandato do RBI.
