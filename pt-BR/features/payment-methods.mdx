## How It Works

Payment methods are automatically presented to customers based on:

- **Customer Location** — Regional methods like iDEAL (Netherlands) or UPI (India) only appear for customers in those regions
- **Transaction Currency** — Payment methods are filtered by supported currencies
- **Device Type** — Apple Pay only appears on compatible Apple devices and browsers
- **Transaction Type** — Some methods don't support subscriptions or have minimum amounts

<Info>
**Automatic Activation:** All payment methods are pre-configured and managed by Dodo Payments. No additional setup needed — they become available once your account is verified and live mode is enabled.
</Info>

## Configuração de Método de Pagamento por Checkout

Além das configurações no nível de negócio, você pode restringir os métodos que são exibidos para sessões de checkout individuais usando `allowed_payment_method_types`:

<Tabs>
<Tab title="JavaScript">

```javascript
const session = await client.checkoutSessions.create({
  product_cart: [{ product_id: 'prod_123', quantity: 1 }],
  allowed_payment_method_types: [
    'credit',
    'debit', 
    'apple_pay',
    'google_pay'
  ],
  return_url: 'https://example.com/success'
});
```

</Tab>

<Tab title="Python">

```python
session = client.checkout_sessions.create(
    product_cart=[{"product_id": "prod_123", "quantity": 1}],
    allowed_payment_method_types=[
        "credit",
        "debit",
        "apple_pay", 
        "google_pay"
    ],
    return_url="https://example.com/success"
)
```

</Tab>

<Tab title="cURL">

```bash
curl -X POST https://test.dodopayments.com/checkout-sessions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "product_cart": [{"product_id": "prod_123", "quantity": 1}],
    "allowed_payment_method_types": ["credit", "debit", "apple_pay", "google_pay"],
    "return_url": "https://example.com/success"
  }'
```

</Tab>
</Tabs>

## Melhores Práticas

<AccordionGroup>
<Accordion title="Match methods to your market">
Inclua métodos de pagamento regionais para seus mercados-alvo. O iDEAL captura cerca de 60% dos pagamentos online na Holanda; UPI domina na Índia. Omissão desses métodos prejudica significativamente a conversão.
</Accordion>

<Accordion title="Always provide card fallbacks">
Mesmo ao direcionar métodos específicos, inclua `credit` e `debit` como opções de fallback. Nem todos os clientes têm acesso a todos os métodos de pagamento.
</Accordion>

<Accordion title="Consider transaction minimums">
Métodos BNPL (Klarna, Afterpay) exigem um mínimo de $50,01. Não os inclua para produtos de baixo valor — eles simplesmente não aparecerão, o que está correto.
</Accordion>

<Accordion title="Test across regions and devices">
Use o modo de teste para verificar a disponibilidade de métodos de pagamento para diferentes localizações de clientes, moedas e tipos de dispositivos antes de ativar.
</Accordion>
</AccordionGroup>

## Solução de Problemas

<AccordionGroup>
<Accordion title="Payment method not appearing">
**Verifique estes fatores:**
1. Método incluído em `allowed_payment_method_types`?
2. Localização do cliente corresponde à região suportada pelo método?
3. Moeda da transação suportada pelo método?
4. Quantia da transação atende ao mínimo (por exemplo, $50,01 para BNPL)?
5. Para assinaturas: método suporta pagamentos recorrentes?

**Solução:** Remova temporariamente `allowed_payment_method_types` para ver todos os métodos elegíveis, depois restrinja para identificar o problema.
</Accordion>

<Accordion title="Unexpected methods appearing">
**Causas possíveis:**
- `allowed_payment_method_types` não está sendo passado corretamente
- Parâmetro formatado incorretamente (deve ser um array de strings)

**Solução:** Registre a carga útil da solicitação de sua API e verifique a estrutura do parâmetro.
</Accordion>

<Accordion title="Regional method not available">
**Verifique:**
- Endereço de cobrança do cliente corresponde à região do método
- Moeda está configurada corretamente (por exemplo, EUR para iDEAL)
- Moeda Adaptativa está habilitada se o cliente for internacional

**Solução:** Verifique o código do país do endereço de cobrança e a moeda na sua solicitação de API.
</Accordion>

<Accordion title="Indian payment method issues">
Assinaturas UPI e Rupay têm requisitos únicos, incluindo atrasos de processamento de 48 horas e limites de mandato do RBI.

**Veja:** <a href="/features/payment-methods/india">Métodos de Pagamento na Índia</a> para orientações completas.
</Accordion>
</AccordionGroup>
